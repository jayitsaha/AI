Understanding Open LLMs
▼

What are they? Falcon, MPT, and BLOOM are prominent examples of large language models (LLMs) whose weights, architectures, and often training code are made publicly available under permissive licenses. This contrasts with "closed" models where only API access is provided.

Why are they important? Open models democratize access to powerful AI. They enable researchers to study, reproduce, and build upon state-of-the-art models without needing vast proprietary compute. For companies, they offer a cost-effective way to deploy and fine-tune LLMs, fostering innovation and reducing reliance on a few large providers.

Analogy: Imagine a complex, high-performance racing engine. A "closed" LLM is like being given the car and told you can drive it, but you're not allowed to open the hood, inspect the engine, or modify it. An "open" LLM is like being given the blueprints, all the parts, and assembly instructions — you can understand how it works, fix it, customize it, or even build a better one from scratch.

💡 If you remember one thing

Open LLMs like Falcon, MPT, and BLOOM are not just about releasing weights; they often incorporate significant architectural innovations (e.g., Multi-Query Attention, ALiBi) specifically designed to make training and inference more efficient and scalable, making them practical for a wider range of users.

2
How They Work Internally: Key Innovations
▼

Common Ground: The Decoder-Only Transformer

All three models are based on the decoder-only Transformer architecture, which has become standard for generative LLMs. This means they predict the next token in a sequence, conditioned on all previous tokens. The core building block is the self-attention mechanism, which allows tokens to "look at" and weigh the importance of other tokens in the input sequence.

Architectural Divergence for Efficiency

While sharing the Transformer foundation, these open models introduce specific modifications to improve performance, especially for inference and long context windows:

  • Multi-Query Attention (MQA) / Grouped-Query Attention (GQA): Instead of each attention "head" having its own Key (K) and Value (V) projection matrices (as in standard Multi-Head Attention, MHA), MQA (used by BLOOM and some Falcon versions) shares a single K and V matrix across all heads. GQA (used by Falcon and MPT) generalizes this by sharing K and V across *groups* of heads. This drastically reduces the size of the K/V cache during inference, improving throughput and memory efficiency.
  • ALiBi (Attention with Linear Biases): Used by Falcon, MPT, and BLOOM. Instead of relying on learned positional embeddings (which struggle to extrapolate to sequences longer than those seen during training), ALiBi directly adds a non-learned, linear bias to the attention scores based on the relative distance between query and key tokens. This allows models to handle much longer contexts more robustly.
  • FlashAttention / Fused Kernels: MPT models (from MosaicML) heavily leverage FlashAttention and other fused kernel implementations. These are not architectural changes but highly optimized low-level GPU kernels that dramatically speed up attention computations and reduce GPU memory usage by minimizing data movement between different memory hierarchies.
🔑 Key Property

These innovations primarily target the bottlenecks of LLM deployment: reducing the memory footprint of the K/V cache during inference (MQA/GQA) and improving the model's ability to generalize to longer input sequences (ALiBi). FlashAttention provides an orthogonal speedup by optimizing the underlying compute.

Why It Works — The Math Behind the Innovations
▼

Standard Self-Attention

The core of the Transformer is the scaled dot-product attention. For a sequence of tokens, we project the input into Query (\(Q\)), Key (\(K\)), and Value (\(V\)) matrices. The attention output is:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

In Multi-Head Attention (MHA), this is done independently for \(H\) heads, each with its own \(Q_h, K_h, V_h\) matrices, then concatenated. This means \(H\) separate \(K\) and \(V\) matrices need to be stored in the K/V cache during auto-regressive inference.

Multi-Query Attention (MQA) / Grouped-Query Attention (GQA)

MQA and GQA modify the \(K\) and \(V\) projections. Instead of \(H\) distinct \(K_h, V_h\) pairs, MQA uses just one \(K, V\) pair shared across all heads. GQA uses \(G\) distinct \(K, V\) pairs, where each pair is shared by \(H/G\) heads. The attention calculation itself remains the same, but the underlying \(K, V\) matrices are shared:

$$Q_h \text{ is unique per head } h \in \{1 \dots H\}$$ $$K_g, V_g \text{ are shared across a group of } H/G \text{ heads, for } g \in \{1 \dots G\}$$

This directly reduces the memory footprint for storing the K/V cache from \(O(H \cdot S \cdot d_k)\) to \(O(G \cdot S \cdot d_k)\), where \(S\) is sequence length and \(d_k\) is head dimension. For MQA, \(G=1\), leading to maximum memory savings. For GQA, \(1 < G < H\), offering a trade-off between memory and quality.

ALiBi (Attention with Linear Biases)

ALiBi modifies the attention score calculation by adding a non-learned, fixed bias matrix \(B\) before the softmax. This bias depends only on the relative distance between tokens \(i\) (query) and \(j\) (key):

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}} + B\right)V$$ $$\text{where } B_{i,j} = m \cdot (j-i)$$

Here, \(m\) is a fixed negative slope factor (e.g., \(-0.1\)) that is typically different for each attention head. The bias \(B_{i,j}\) is more negative for tokens further away in the past (\(j

⚠️ Common Pitfall

While MQA/GQA significantly improve inference speed by reducing K/V cache memory, they can sometimes lead to a slight drop in model quality compared to full MHA, especially if the number of KV heads is too small (e.g., MQA, where \(G=1\)). GQA offers a tunable compromise.

When to choose an open model:

  • Cost-effectiveness: Avoids API costs, allows for local deployment.
  • Customization: Full access to weights and architecture for fine-tuning, merging, or architectural modifications.
  • Transparency & Research: Understand internal mechanisms, reproduce results, contribute to the open-source community.
  • Privacy & Security: Keep data on-premises, crucial for sensitive applications.

When to be cautious:

  • Infrastructure & Expertise: Deploying and managing LLMs requires significant compute resources and ML engineering expertise.
  • Bleeding-edge performance: While rapidly catching up, some proprietary models might still hold a lead in specific benchmarks or niche capabilities.
  • Maintenance: Responsible for updates, security patches, and troubleshooting.
💡 Big Picture

The rise of open LLMs has fundamentally shifted the landscape of AI development. Innovations like GQA and ALiBi are critical enablers, making these models not just accessible, but also highly performant and efficient, closing the gap with proprietary alternatives.

Code Trace — Simplified Attention with GQA & ALiBi
▼
import torch
import torch.nn as nn
class CustomAttention(nn.Module):
def __init__(self, embed_dim, num_heads, num_kv_heads=None, alibi_slope=0.0):
super().__init__()
self.num_heads = num_heads
self.num_kv_heads = num_kv_heads if num_kv_heads is not None else num_heads
self.head_dim = embed_dim // num_heads
self.alibi_slope = alibi_slope
assert embed_dim % num_heads == 0, "embed_dim must be divisible by num_heads"
assert num_heads % self.num_kv_heads == 0, "num_heads must be divisible by num_kv_heads"
# Linear projections for Q, K, V
self.q_proj = nn.Linear(embed_dim, embed_dim, bias=False)
self.kv_proj = nn.Linear(embed_dim, self.num_kv_heads * self.head_dim * 2, bias=False)
self.out_proj = nn.Linear(embed_dim, embed_dim, bias=False)
def forward(self, x, mask=None):
batch_size, seq_len, _ = x.shape
# 1. Project Q, K, V
q = self.q_proj(x).view(batch_size, seq_len, self.num_heads, self.head_dim)
kv = self.kv_proj(x).view(batch_size, seq_len, self.num_kv_heads, self.head_dim * 2)
k, v = kv.chunk(2, dim=-1) # Split into K and V
# 2. Duplicate K, V for GQA if num_kv_heads < num_heads
if self.num_kv_heads != self.num_heads:
k = k.repeat_interleave(self.num_heads // self.num_kv_heads, dim=2)
v = v.repeat_interleave(self.num_heads // self.num_kv_heads, dim=2)
# 3. Transpose for batched matmul (batch, heads, seq_len, head_dim)
q = q.transpose(1, 2)
k = k.transpose(1, 2)
v = v.transpose(1, 2)
# 4. Compute attention scores
attn_scores = (q @ k.transpose(-2, -1)) / (self.head_dim ** 0.5)
# 5. Apply ALiBi bias if enabled
if self.alibi_slope > 0:
alibi_bias = self._generate_alibi_bias(seq_len)
attn_scores = attn_scores + alibi_bias.unsqueeze(0).unsqueeze(0)
# 6. Apply causal mask (for decoder-only)
if mask is not None:
attn_scores = attn_scores.masked_fill(mask == 0, float('-inf'))
# 7. Softmax and multiply by V
attn_weights = torch.softmax(attn_scores, dim=-1)
output = (attn_weights @ v).transpose(1, 2).contiguous()
# 8. Concatenate heads and project out
output = output.view(batch_size, seq_len, embed_dim)
return self.out_proj(output)
def _generate_alibi_bias(self, seq_len):
# Simplified ALiBi bias for a single head and batch
# In reality, different heads have different slopes
i = torch.arange(seq_len).unsqueeze(1)
j = torch.arange(seq_len).unsqueeze(0)
relative_distance = j - i
alibi_bias = relative_distance * self.alibi_slope
return alibi_bias
