Understanding PaliGemma
▼

What is it? PaliGemma is a compact "vision-language model" (VLM) — it looks at an image and a text prompt together and produces text back (a caption, an answer, a bounding box, a segmentation mask encoded as tokens). It is built by bolting a vision encoder called SigLIP onto a small language model called Gemma, and training the combination on image+text pairs.

Analogy: Think of SigLIP as a translator who looks at a photo and writes down a paragraph of "visual notes" — but instead of English words, the notes are dense numeric vectors. Gemma is a writer who only reads and writes text. PaliGemma's job is to make the writer fluent in the translator's notation: a small linear "adapter" projects the visual notes into the exact vocabulary space the writer already understands, so the writer can continue the story (answer the question, describe the scene, output coordinates) by reading the image notes as if they were just more words in its prompt.

PaliGemma treats image patches as extra "tokens" prepended to the text prompt, and trains with a prefix-LM mask: full bidirectional attention over the image+prompt ("prefix"), causal attention over the generated answer ("suffix"). $$P(\text{suffix} \mid \text{image}, \text{prefix}) = \prod_{t} P(y_t \mid \text{image}, \text{prefix}, y_{

How It Works Internally
▼

Why This Exists

Before PaliGemma, VLMs like Flamingo or LLaVA typically bolted a vision tower onto a decoder-only LM using cross-attention layers or by inserting visual tokens with a purely causal mask (like a normal GPT). Cross-attention adds architectural complexity and new weights to train from scratch; a fully causal mask forces image patches — which have no inherent left-to-right reading order — to attend only to "earlier" patches, discarding information that should flow freely in every direction. PaliGemma borrows the prefix-LM idea from T5/UL2/PaLI: no new attention layers, just a smarter mask on a standard decoder.

The Three Pieces

1. SigLIP image encoder — a ViT (So400m/14, ~400M params) pretrained with a sigmoid contrastive loss (not softmax-based CLIP loss) on image-text pairs. It turns a 224×224 (or 448/896 for PaliGemma 2) image into a fixed grid of patch embeddings, e.g. 256 tokens at 224px (16×16 patches of size 14).

2. Linear projection — a single trainable linear layer maps SigLIP's output dimension (1152) into Gemma's embedding dimension (2048 for Gemma-2B), so image tokens live in exactly the same vector space as text token embeddings.

3. Gemma decoder — a standard decoder-only transformer (2B/9B/27B for PaliGemma 2) that receives the concatenated sequence [image tokens] + [prefix text] + [suffix text] and predicts the suffix autoregressively.

🔑 Key Property

The mask, not the architecture, is what makes this multimodal. Image tokens are just embeddings sitting at the front of a normal transformer's input sequence — the only new mechanism is that the causal mask is relaxed to full attention over the "prefix" block (image + task prompt) and stays causal only for the "suffix" (the answer being generated).

Why It Works — The Math of the Prefix-LM Mask
▼

Building the Attention Mask

Let the full input sequence have length \(n = n_{img} + n_{pre} + n_{suf}\): \(n_{img}\) image tokens, \(n_{pre}\) prefix text tokens (the task string, e.g. "caption en"), and \(n_{suf}\) suffix text tokens (the target being generated). Define the "input" region \(I = \{1, \dots, n_{img}+n_{pre}\}\) and the "target" region \(T = \{n_{img}+n_{pre}+1,\dots,n\}\). The attention mask \(M \in \{0,1\}^{n\times n}\) used inside every self-attention layer is:

$$M_{ij} = \begin{cases} 1 & \text{if } j \in I \\ 1 & \text{if } i \in T \text{ and } j \le i \\ 0 & \text{otherwise} \end{cases}$$

In words: any query token can see all of the prefix (image + task prompt), regardless of position — that block is fully bidirectional. A suffix query token additionally sees all suffix tokens up to and including itself — that block is causal, exactly like a normal GPT.

Masked Self-Attention

Inside each layer, standard scaled dot-product attention is computed with this mask added as \(-\infty\) before the softmax:

$$\text{Attn}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + (1-M)\cdot(-\infty)\right) V$$

Setting masked logits to \(-\infty\) makes their softmax weight exactly 0, so information never flows backward from an as-yet-ungenerated suffix token into the prefix, and never flows forward across suffix positions — but it flows freely in both directions inside the prefix.

Training Loss — Only on the Suffix

The model is trained with standard next-token cross-entropy, but the loss is masked to the suffix positions only:

$$\mathcal{L} = -\sum_{t \in T} \log P_\theta\big(y_t \mid \text{image}, \text{prefix}, y_{

Prefix tokens (image patches and the task string) never appear as prediction targets — they are pure conditioning context. This is exactly the "span corruption" / prefix-LM objective from T5 and UL2, adapted so the "prefix" is multimodal.

⚠️ Common Misconception

"PaliGemma uses cross-attention like Flamingo." It does not — there are no extra cross-attention layers or gated adapters. Every layer is the same self-attention Gemma already has; only the mask \(M\) changes per position. This keeps the architecture identical to a plain decoder-only LM, so pretrained Gemma weights can be reused directly.

Key Takeaways
▼

PaliGemma vs PaliGemma 2:

DimensionPaliGemmaPaliGemma 2
Decoder LMGemma (2B)Gemma 2 (2B / 9B / 27B)
Resolutions224px only (base ckpt)224 / 448 / 896 px, all released
Vision encoderSigLIP So400m/14SigLIP So400m/14 (same, re-tuned)
Released tasksTransfer-only checkpoints+ Stronger OCR, table structure, long captioning

When this design shines:

  • You want a single small decoder to reuse for many tasks — detection, segmentation, VQA, OCR, captioning — via fine-tuning, not new heads
  • You need bounding boxes / segmentation masks as plain text (PaliGemma emits <loc0104> and <seg012> tokens — coordinates and mask codes as vocabulary)
  • You want to avoid designing and training new cross-attention adapters

Limitations:

  • Fixed, quadratic-in-tokens cost — high resolution (896px → 4096 image tokens) makes the prefix very long and attention expensive
  • A single linear projection is a thin bridge; most of the vision-language alignment work happens during large-scale pretraining, not architecture
  • Requires task-specific fine-tuning ("transfer") for best results — the base pretrained checkpoint is a general-purpose starting point, not a chat assistant
💡 Hierarchy

Causal LM (mask is fully lower-triangular) ⊂ Prefix-LM (mask is lower-triangular only on the suffix, full elsewhere) ⊂ Encoder-decoder (separate full-attention encoder + causal decoder with cross-attention). PaliGemma sits in the middle: it gets the encoder-decoder's "look both ways at the input" behavior with only a decoder's weights and a mask change.

▼
import numpy as np
# Toy sizes: 4 image tokens, 3 prefix-text tokens, 4 suffix tokens
n_img, n_pre, n_suf = 4, 3, 4
n = n_img + n_pre + n_suf
n_prefix = n_img + n_pre # image+text "input" block
# 1. SigLIP encodes the image into n_img patch embeddings
img_feats = siglip_encoder(image) # (n_img, 1152)
img_tokens = linear_projection(img_feats) # (n_img, 2048) == Gemma dim
# 2. Concatenate: [image | prefix text | suffix text]
seq_embeds = concat([img_tokens, prefix_text_embeds, suffix_text_embeds])
# 3. Build the prefix-LM attention mask (1 = can attend)
M = np.zeros((n, n), dtype=bool)
M[:, :n_prefix] = True # everyone sees the whole prefix
causal = np.tril(np.ones((n_suf, n_suf), dtype=bool))
M[n_prefix:, n_prefix:] = causal # suffix is causal w.r.t. itself
# 4. Self-attention with additive mask
scores = (Q @ K.T) / np.sqrt(d_k)
scores = np.where(M, scores, -np.inf)
attn = softmax(scores, axis=-1)
out = attn @ V
# 5. Loss only on suffix positions
logits = lm_head(hidden_states) # (n, vocab)
loss = cross_entropy(logits[n_prefix:-1], targets[n_prefix+1:])
