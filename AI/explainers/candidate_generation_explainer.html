1
Understanding Candidate Generation
▼

What is it? In a modern recommender, showing a ranked feed to a user happens in two stages. Candidate generation (retrieval) narrows a catalog of millions or billions of items down to a few hundred plausible candidates in single-digit milliseconds, using a query embedding (a user, a search string, an item). A heavier ranking model then scores just those candidates. Candidate generation is fundamentally a nearest-neighbor search problem in a high-dimensional embedding space: given a query vector, find the k item vectors closest to it.

Analogy: Imagine looking for a friend's face in a photo album of 10 million photos. Flipping every single page is brute-force search — exact, but hopeless at scale. Approximate Nearest Neighbor (ANN) search instead builds an index ahead of time: a highway system with express lanes that get you to the right neighborhood fast, then local streets to find the exact house (HNSW) — or a library card catalog that sends you straight to the right shelf before you check individual books (FAISS's IVF, ScaNN). You trade a sliver of certainty for orders-of-magnitude more speed.

💡 If you remember one thing

Exact k-NN costs \(O(N \cdot D)\) per query — infeasible past a few hundred thousand items. ANN indexes (HNSW, IVF-PQ, ScaNN) trade a small, tunable amount of recall for a huge drop in latency, typically reaching >95% recall@k in \(O(\log N)\) to \(O(\sqrt{N})\) time via graph traversal or space partitioning.

How ANN Search Works Internally
▼

HNSW — Hierarchical Navigable Small World

HNSW builds a multi-layer graph over the embedding vectors. Every vector lives at layer 0 (the base, dense layer). Each vector is also promoted to higher layers with exponentially decaying probability — so layer 0 has all \(N\) points, layer 1 has roughly \(N/M\), layer 2 has \(N/M^2\), and so on, where \(M\) is the average node degree. Higher layers act as "express lanes": long-range edges that let a query jump across the space quickly. A query starts at a fixed entry point on the topmost layer, greedily walks to whichever neighbor is closest to the query, and once no neighbor improves, drops down one layer and repeats — narrowing in like a coarse-to-fine zoom. At layer 0 it switches to a wider beam search with a candidate-list size \(ef\), collecting the final approximate top-k.

FAISS — IVF + Product Quantization

FAISS's classic recipe partitions the space instead of layering it. An IVF (inverted file) index runs k-means to produce a few thousand centroids (Voronoi cells); each vector is assigned to its nearest cell. At query time, only the nprobe cells nearest the query are scanned — pruning away the rest of the corpus entirely. To shrink memory further, FAISS applies Product Quantization (PQ): each vector is split into \(m\) sub-vectors, and each sub-vector is replaced by the ID of its nearest of \(2^{nbits}\) learned codewords, compressing a 128-dim float32 vector (512 bytes) down to a few dozen bytes.

ScaNN — Anisotropic Vector Quantization

Google's ScaNN improves on plain PQ by noticing that quantization error along the direction of the true nearest-neighbor ranking matters more than error in other directions. Its anisotropic loss biases the quantizer to preserve dot-product ordering rather than minimizing raw reconstruction error, then adds a reorder step that re-scores a small shortlist with exact distances — squeezing out a large recall gain at the same memory budget.

🔑 Key Property

All three systems share the same shape: a cheap index structure (graph or partition) that prunes the search space, plus a tunable knob (\(ef\) for HNSW, \(nprobe\) for IVF, leaves-to-search for ScaNN) that trades recall for latency at query time — no retraining required.

3
Why It Works — The Math
▼

Distance & the Recall Metric

Nearest neighbors are ranked by a similarity function — Euclidean distance, cosine similarity, or (for many RecSys embeddings) the maximum inner product \(q^\top x_i\), which can itself be reduced to a nearest-neighbor problem via a norm-augmenting transform. Quality of an ANN index is measured with recall@k:

$$\text{recall@}k = \frac{|\,\text{ANN top-}k \cap \text{true top-}k\,|}{k}$$

HNSW Layer Assignment

Each point's top layer \(l\) is drawn from an exponential distribution so the graph forms a skip-list-like hierarchy:

$$P(\text{level} \ge l) = \left(\frac{1}{M}\right)^{l}, \qquad l = \lfloor -\ln(u) \cdot m_L \rfloor,\ u \sim \text{Uniform}(0,1)$$

This gives expected query cost \(O(\log N)\): \(O(1)\) hops per (exponentially thinning) layer across \(O(\log N)\) layers, versus \(O(N)\) for brute force.

Product Quantization Compression

Splitting a \(D\)-dim vector into \(m\) sub-vectors, each quantized to one of \(2^{b}\) centroids, needs only \(m \cdot b\) bits per vector instead of \(32D\) bits — e.g. \(D{=}128, m{=}16, b{=}8\) compresses 512 bytes to 16 bytes, a 32x reduction, while distances are approximated via a precomputed lookup table:

$$\hat{d}(q, x) = \sum_{j=1}^{m} d\big(q^{(j)},\, c_{j}(x^{(j)})\big)^2$$
⚠️ Common Pitfall

Recall is not free — it's a knob. Setting \(ef\) or \(nprobe\) too low silently drops true neighbors with no error, no warning — the model just serves slightly worse candidates. Always measure recall@k against an exact brute-force baseline on a held-out sample before shipping an index configuration.

Key Takeaways
▼

When to reach for which index:

  • Brute force / IndexFlat — corpora under ~100K vectors, or when 100% recall is mandatory (e.g. re-ranking a small shortlist).
  • HNSW — best recall/latency trade-off for in-memory corpora up to tens of millions of vectors; no training step, supports incremental inserts, but memory-hungry (stores full vectors + graph edges).
  • FAISS IVF-PQ — billions of vectors on a single machine; needs a training pass to learn centroids/codebooks, and compressed vectors mean lower raw recall unless paired with a re-ranking pass.
  • ScaNN — when squeezing extra recall out of a fixed memory/PQ budget matters most (Google-scale retrieval, matrix-factorization / two-tower embeddings).
  • Production systems often combine them: FAISS's IndexIVFPQ plus an HNSW coarse quantizer, or ANN retrieval followed by exact re-ranking on the shortlist.

Operational considerations:

  • Index build/train time and memory footprint matter as much as query latency at scale.
  • Embeddings drift — re-train / re-index periodically, or use online-insert structures (HNSW) for freshness.
  • Always A/B recall@k against brute force before changing \(ef\) / \(nprobe\) in production.
💡 Hierarchy

Brute force (exact, \(O(N)\)) → IVF (partition, prune cells) → HNSW (graph, prune via hierarchy) → +PQ / ScaNN (compress vectors themselves). Each layer trades a bit more exactness for a lot more scale.
