SARSA: On-Policy TD Control

Learning optimal policies directly from experience using the (S, A, R, S', A') tuple
Foundational Reinforcement Learning O(1) per step
1
Understanding SARSA
▼

What is it? SARSA is an algorithm in Reinforcement Learning (RL) used to learn an optimal policy for an agent navigating an environment. It's a Temporal Difference (TD) control method, meaning it learns from experience without a model of the environment, and it updates its value estimates based on other learned value estimates (bootstrapping). Crucially, SARSA is on-policy: it learns the value of the policy it is currently following.

Analogy: Imagine you're learning to navigate a new city by driving around. Every time you make a turn, you note your current street (State), the turn you just made (Action), the immediate experience (Reward), the new street you're on (Next State), and crucially, the turn you plan to make next from this new street (Next Action). SARSA is like updating your mental map of "how good is this turn from this street" based on this entire sequence of (Street, Turn, Experience, Next Street, Next Turn) you just observed. You're learning the value of *your current driving habits*.

💡 If you remember one thing

SARSA updates the Q-value for a (State, Action) pair based on the reward received and the Q-value of the next action chosen by the *same policy* from the next state. The update rule is: $$Q(S,A) \leftarrow Q(S,A) + \alpha [R + \gamma Q(S',A') - Q(S,A)]$$ This "SARSA tuple" (State, Action, Reward, Next State, Next Action) gives the algorithm its name.

How SARSA Works Internally
▼

The SARSA Algorithm (for a single episode)

SARSA is an iterative algorithm that builds a Q-table (or Q-function approximation) mapping state-action pairs to their expected future rewards. Here's how it generally proceeds for one episode:

  1. Initialize: Start with a Q-table (all zeros or small random values) and an initial state \(S\).
  2. Choose \(A\): Select an action \(A\) for the current state \(S\) using an \(\epsilon\)-greedy policy derived from the current Q-table (e.g., mostly exploit best known actions, sometimes explore randomly).
  3. Execute: Take action \(A\), observe the immediate reward \(R\), and the next state \(S'\).
  4. Choose \(A'\): Select the next action \(A'\) for the next state \(S'\) using the same \(\epsilon\)-greedy policy. This is the "on-policy" step that distinguishes SARSA.
  5. Update Q(S,A): Apply the SARSA update rule: \(Q(S,A) \leftarrow Q(S,A) + \alpha [R + \gamma Q(S',A') - Q(S,A)]\).
  6. Iterate: Set \(S \leftarrow S'\) and \(A \leftarrow A'\), then go back to step 3 (or 2 if \(A'\) was not chosen in step 5, but rather used as the "next action"). Repeat until \(S'\) is a terminal state.

Design Decision: Why "On-Policy"?

The key differentiator for SARSA is its "on-policy" nature. It learns the Q-values for the policy it is currently executing (the \(\epsilon\)-greedy policy used for both \(A\) and \(A'\)). This means if the agent explores a suboptimal path due to \(\epsilon\)-greedy exploration, SARSA will learn the Q-value of that suboptimal path. In contrast, off-policy algorithms like Q-learning estimate the value of the optimal policy independently of the agent's exploration policy.

This makes SARSA generally safer for learning in environments where exploration can lead to catastrophic outcomes (e.g., a robot falling off a cliff). If the \(\epsilon\)-greedy policy occasionally takes the robot near a cliff, SARSA will learn the lower Q-values associated with those risky actions and states, making the learned policy more cautious.

🔑 Key Property

SARSA learns the optimal policy \(\pi^*\) only if the exploration strategy (e.g., \(\epsilon\)-greedy) gradually decays \(\epsilon\) to zero over time (ensuring sufficient exploration initially, then converging to exploitation). If \(\epsilon\) remains high, SARSA will converge to the optimal policy under that level of exploration, which may not be the true optimal policy of the environment.

Why It Works — The Math
▼

The Bellman Equation for Action-Values

The foundation of SARSA (and other TD control methods) is the Bellman equation for action-values, which states that the value of taking an action \(A\) in state \(S\) under a policy \(\pi\) can be expressed recursively:

$$Q^\pi(S,A) = \mathbb{E}[R_{t+1} + \gamma Q^\pi(S_{t+1}, A_{t+1}) \mid S_t=S, A_t=A, A_{t+1} \sim \pi(\cdot|S_{t+1})]$$

This says the expected return from state \(S\) and action \(A\) is the sum of the immediate reward \(R_{t+1}\) and the discounted value (\(\gamma\)) of the next state-action pair \((S_{t+1}, A_{t+1})\), where \(A_{t+1}\) is chosen according to the policy \(\pi\).

The SARSA Update Rule

SARSA uses this Bellman expectation as a target for its updates. Since the true expectation is unknown, SARSA samples it directly from experience. The core of the update is the Temporal Difference (TD) error:

$$\delta_t = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t)$$

This error term represents the difference between the "new estimate" (the sampled return \(R_{t+1} + \gamma Q(S_{t+1}, A_{t+1})\)) and the "old estimate" (the current \(Q(S_t, A_t)\)). The update rule then simply moves the old estimate a fraction (\(\alpha\), the learning rate) of the way towards the new estimate:

$$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \cdot \delta_t$$

This iterative update allows the Q-values to gradually converge to \(Q^\pi(S,A)\) for the policy \(\pi\) being followed, and if \(\pi\) eventually becomes greedy with respect to \(Q\), then \(Q\) will converge to \(Q^*(S,A)\).

⚠️ Common Pitfall

The choice of \(\boldsymbol{A'}\) is critical for SARSA. It must be chosen using the same policy (e.g., \(\epsilon\)-greedy) that generated the previous action \(A\). If \(A'\) were chosen greedily with respect to \(Q(S', \cdot)\) regardless of \(\epsilon\), the algorithm would become Q-learning, which is off-policy and has different convergence properties and behavior, especially in environments with penalties for exploration.

Key Takeaways
▼

When to use SARSA:

  • When learning an optimal policy in environments where the cost of exploration is high (e.g., real-world robotics, safety-critical systems). SARSA's on-policy nature makes it "safer" because it accounts for the actual actions taken, including exploratory ones.
  • When you need to evaluate the performance of a specific, fixed policy, including its exploratory behavior.
  • For continuous state/action spaces when combined with function approximators, as the on-policy nature can sometimes be more stable during training.

When to consider alternatives (e.g., Q-learning):

  • When the environment is safe for extensive exploration, and you want to learn the absolute optimal policy regardless of the exploration strategy. Q-learning is off-policy and can learn the optimal policy more aggressively.
  • When computational efficiency is paramount, and the exploration policy is simple. Q-learning's simpler target calculation (max Q-value) can sometimes be faster.
  • In environments where the optimal policy is known to be deterministic, and exploration is solely for learning.
💡 SARSA vs. Q-learning (The On- vs. Off-Policy Divide)

The fundamental difference lies in the next action: SARSA uses \(Q(S',A')\) where \(A'\) is chosen by the current policy (e.g., \(\epsilon\)-greedy). Q-learning uses \(\max_{a'} Q(S',a')\), which is the value of the greedy action in \(S'\), regardless of what the agent actually does next. This means Q-learning learns the optimal policy directly, while SARSA learns the optimal policy given its exploration strategy.

Code Trace (Python-like Pseudocode)
▼
# Initialize Q-table, learning rate (alpha), discount factor (gamma), exploration rate (epsilon)
Q = initialize_q_table(states, actions)
alpha = 0.1
gamma = 0.9
epsilon = 0.1
for episode in range(num_episodes):
S = environment.reset() # Get initial state
A = choose_action(S, Q, epsilon) # Choose A from S using epsilon-greedy policy
while not S.is_terminal():
S_prime, R = environment.step(A) # Take action A, observe R and S_prime
A_prime = choose_action(S_prime, Q, epsilon) # Choose A_prime from S_prime using epsilon-greedy policy
# Calculate TD Target and TD Error
td_target = R + gamma * Q[S_prime, A_prime]
td_error = td_target - Q[S, A]
# Update Q-value for (S, A)
Q[S, A] = Q[S, A] + alpha * td_error
S = S_prime # Move to next state
A = A_prime # Move to next action
# Helper function for epsilon-greedy action selection
def choose_action(state, Q, epsilon):
if random.uniform(0, 1) < epsilon:
return random.choice(available_actions) # Explore
else:
return argmax_action(Q[state, :]) # Exploit
