Bayesian Optimization: GP Surrogate & TPE

Sample-efficient black-box hyperparameter optimization via probabilistic models
Advanced Classical ML · HPO O(n³) GP fitting
1
Understanding the Concept

What is this? Most hyperparameter tuning runs the model thousands of times with random guesses — extremely wasteful. Bayesian Optimization (BO) instead builds a cheap probabilistic model of the objective (e.g. validation loss), uses it to guess which hyperparameter setting is most promising, evaluates there, updates the model, and repeats. It needs far fewer evaluations to find a good configuration.

Real-World Analogy

You're blindfolded, searching for the coldest spot on an uneven floor. Random search: keep stepping randomly. BO: build a mental map of temperatures you've already measured, reason about where the cold spot probably is, then step there. Each step makes your map better. TPE does the same but asks a different question: "where are my best measurements clustered?" and samples from that cluster.

If You Remember One Thing

BO maintains a surrogate model \(p(y \mid x)\) over the objective, then picks the next point by maximizing an acquisition function (e.g. Expected Improvement) that balances exploitation of known good regions with exploration of uncertain ones. TPE is a specific BO variant that models \(p(x \mid y < y^*)\) and \(p(x \mid y \ge y^*)\) separately and picks \(x\) maximizing \(\ell(x)/g(x)\).

2
How GP-BO Works Internally

A Gaussian Process defines a distribution over functions. Given \(n\) observations \(\mathcal{D} = \{(x_i, y_i)\}\), the GP posterior at any new point \(x_*\) is Gaussian:

$$\mu_*(x_*) = k_{*n}(K_{nn} + \sigma_n^2 I)^{-1}\mathbf{y}$$
$$\sigma^2_*(x_*) = k_{**} - k_{*n}(K_{nn} + \sigma_n^2 I)^{-1}k_{n*}$$

Here \(K_{nn}\) is the \(n \times n\) kernel (covariance) matrix, \(k_{*n}\) is the \(1 \times n\) vector of covariances between \(x_*\) and all observed points, and \(\sigma_n^2\) is observation noise. Fitting costs \(\mathcal{O}(n^3)\) — fine for small budgets but prohibitive beyond ~10 000 evaluations.

The Expected Improvement (EI) acquisition function at a candidate \(x\) is:

$$\text{EI}(x) = (\mu(x) - f^+ - \xi)\,\Phi(Z) + \sigma(x)\,\phi(Z), \quad Z = \frac{\mu(x) - f^+ - \xi}{\sigma(x)}$$

where \(f^+\) is the best observed value, \(\xi\) is an exploration bonus, and \(\Phi, \phi\) are the standard normal CDF and PDF. EI is maximized (analytically in closed form) to select the next \(x\) to evaluate.

Design Decision: Why EI and not UCB?

Upper Confidence Bound (UCB) \(= \mu(x) + \kappa\sigma(x)\) is simpler but requires tuning \(\kappa\). EI has an implicit exploration-exploitation trade-off through \(\sigma(x)\): when uncertainty is high, the second term dominates; when \(\mu(x)\) is high, the first term does. PI (Probability of Improvement) is even simpler but myopic — it ignores magnitude of improvement.

3
How TPE Works — The Density Ratio Trick

TPE (Tree-structured Parzen Estimator, Bergstra et al. 2011) reframes the problem. Instead of modelling \(p(y \mid x)\) directly like a GP does, TPE models two class-conditional densities using Parzen estimators (kernel density estimation):

$$\ell(x) = p(x \mid y < y^*) \qquad g(x) = p(x \mid y \ge y^*)$$

The threshold \(y^*\) is chosen so that the top \(\gamma\) fraction of observed results fall below it (e.g. \(\gamma = 0.25\), so the best 25 % form the "good" set). Then Expected Improvement is proportional to:

$$\text{EI}(x) \propto \frac{\ell(x)}{g(x)}$$

So TPE samples many candidates from \(\ell(x)\) and picks the one with the highest ratio \(\ell/g\). Intuitively: draw from the good-outcome distribution, then reject those that also appear frequently in the bad-outcome distribution.

Why "Tree-Structured"?

Real search spaces often have conditional hyperparameters — e.g. "number of layers in LSTM" only makes sense if "model type = LSTM". TPE models these via a tree-structured graphical model that respects the conditional dependencies, treating each node's density independently given its parent's value. This is exactly how Optuna's internal sampler works.

Kernel choice: For continuous HPs, Gaussian kernels centered at each observed point; for integer/categorical HPs, discrete categorical distributions. Bandwidth is set by Silverman's rule or cross-validation. The result is a mixture of Parzen estimators — cheap to evaluate and sample from.

GP vs TPE — when each wins

GP works best for low-dimensional, continuous search spaces with smooth objectives and budget of 20–200 evaluations. TPE scales better to high-dimensional mixed (continuous + categorical) spaces and handles conditional structure natively — which is why Optuna defaults to TPE and Hyperopt pioneered it.

Decision Guide

Use GP-BO when: the search space is low-dimensional (<20 dims), all continuous, each evaluation is expensive (>10 min), and you need maximum sample efficiency.

Use TPE / Optuna when: the space has categorical or conditional HPs, you want parallelism across many workers, or the budget is medium (50–1000 trials).

Use random search when: the budget is tiny (<20 trials) and you want a reliable baseline — Bergstra & Bengio (2012) showed it beats grid search almost always.

Minimal Code Trace

GP-BO from scratch (NumPy):

# GP posterior mean and variance
def gp_posterior(X_train, y_train, X_test, kernel, noise=1e-6):
K = kernel(X_train, X_train) + noise*np.eye(len(X_train)) # n×n
Ks = kernel(X_train, X_test) # n×m
L = np.linalg.cholesky(K) # Cholesky: O(n³)
alpha = np.linalg.solve(L.T, np.linalg.solve(L, y_train)) # K⁻¹y
mu = Ks.T @ alpha # posterior mean
v = np.linalg.solve(L, Ks)
var = kernel(X_test, X_test) - v.T @ v # posterior variance
return mu, np.sqrt(np.diag(var))
# Expected Improvement
def EI(mu, sigma, f_best, xi=0.01):
Z = (mu - f_best - xi) / (sigma + 1e-9)
return (mu - f_best - xi)*norm.cdf(Z) + sigma*norm.pdf(Z)
# TPE (simplified)
def tpe_sample(obs_x, obs_y, gamma=0.25, n_candidates=24, bw=0.2):
thresh = np.quantile(obs_y, gamma) # y* = 25th percentile
good = obs_x[obs_y < thresh]; bad = obs_x[obs_y >= thresh]
# Sample candidates from good-set KDE (Parzen estimator)
centers = good[np.random.randint(0, len(good), n_candidates)]
cands = centers + np.random.randn(n_candidates) * bw
# Evaluate ℓ/g at each candidate
def kde(x, pts): return np.mean(norm.pdf((x-pts)/bw)/bw, axis=-1)
ratio = kde(cands, good) / (kde(cands, bad) + 1e-9)
return cands[np.argmax(ratio)] # return argmax ℓ/g
Production Gotcha

In Optuna: always set sampler = optuna.samplers.TPESampler(seed=42) for reproducibility. By default Optuna uses random search for the first \(n_{\text{startup\_trials}}\) trials (default 10) before switching to TPE — this warm-up is crucial because TPE's KDE needs enough points to be non-degenerate.
