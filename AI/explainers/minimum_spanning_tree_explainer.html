Understanding MST
▼

What is it? Given a connected, weighted, undirected graph with \(n\) nodes and \(m\) edges, a minimum spanning tree (MST) is a subset of \(n{-}1\) edges that (1) keeps all nodes connected, (2) forms no cycles, and (3) minimizes the total edge weight.

Analogy: You're laying fiber-optic cables to connect 6 cities. Each possible cable segment has a cost. You want every city reachable from every other city, but you want to spend as little as possible — and you never need a redundant cable (a loop). The MST is the cheapest wiring plan.

💡 If you remember one thing

An MST always has exactly \(n-1\) edges for \(n\) nodes. Kruskal sorts all edges globally and picks the cheapest that doesn't create a cycle (tracked with Union-Find). Prim grows a tree one node at a time, always adding the cheapest edge crossing from the tree into the rest of the graph. Both are greedy and both always find an optimal MST.

Connection to clustering: Single-linkage hierarchical clustering is literally the MST — merge clusters via the shortest inter-cluster edge, which is exactly what MST edges encode. Removing the heaviest \(k{-}1\) edges of an MST gives \(k\) clusters.

Historical Context & Motivation
▼

Origins

MST problems arose from electrical network design in the early 20th century. Czech mathematician Otakar Borůvka published the first algorithm in 1926, motivated by connecting Moravian towns to the electricity grid. Jarník (1930) independently discovered what we now call Prim's algorithm. Kruskal rediscovered the sort-and-add approach in 1956 in a seminal 2-page paper in the Proceedings of the American Mathematical Society.

Key Papers

  • Borůvka (1926): First MST algorithm — parallel contraction approach, \(O(E \log V)\)
  • Jarník/Prim (1930/1957): Grow-from-seed approach, rediscovered by Prim in 1957
  • Kruskal (1956): Sort edges globally, add if no cycle; introduced Union-Find implicitly
  • Fredman & Tarjan (1987): Fibonacci heaps give \(O(E + V \log V)\) Prim variant

Core Concepts & Theory
▼

Definitions

Let \(G = (V, E, w)\) be a connected undirected weighted graph with \(|V| = n\) vertices, \(|E| = m\) edges, and weight function \(w: E \to \mathbb{R}\). A spanning tree \(T \subseteq E\) is an acyclic connected subgraph on all \(n\) vertices (so \(|T| = n-1\)). The MST minimizes \(w(T) = \sum_{e \in T} w(e)\).

The Cut Property (fundamental correctness theorem)

🔑 Cut Property

Let \((S, V \setminus S)\) be any cut of \(G\) (a partition of \(V\) into two non-empty sets). Let \(e^* = \arg\min_{e \in \text{cut}(S)} w(e)\) be the unique minimum-weight edge crossing this cut. Then \(e^*\) belongs to every MST.

This is why greedy works: at every step, both Kruskal and Prim add an edge that is the minimum-weight edge crossing some cut.

The Cycle Property (dual perspective)

For any cycle \(C\) in \(G\), the maximum-weight edge of \(C\) (if unique) is NOT in any MST. Kruskal's cycle check directly uses this: it rejects any edge whose endpoints are already connected.

Union-Find (Disjoint Set Union)

Kruskal needs to check and merge connected components efficiently. Union-Find supports two operations: Find(x) — return the representative of \(x\)'s component; Union(x, y) — merge components. With path compression + union by rank, each operation costs \(O(\alpha(n))\) amortized — practically \(O(1)\). The inverse Ackermann function \(\alpha(n) \leq 4\) for all practical \(n\).

$$\alpha(n) = \min\{k : A(k,k) \geq n\} \approx \text{constant for all practical }n$$

Priority Queue in Prim

Prim maintains a min-heap of (weight, vertex, from-vertex) tuples. Each time a vertex joins the tree, its neighbors are pushed. The heap gives the cheapest crossing edge in \(O(\log m)\). With a Fibonacci heap: \(O(E + V \log V)\) total — theoretically optimal but practically slower due to constants.

Why It Works — The Math
▼

Proof of the Cut Property

Suppose \(e^* = (u,v)\) is the unique minimum crossing edge for cut \((S, V \setminus S)\), but \(e^* \notin T\) for some spanning tree \(T\). Since \(T\) is spanning, there must be a path \(P\) in \(T\) from \(u\) to \(v\). This path crosses the cut at least once — let \(f = (a,b)\) be such a crossing edge, \(f \neq e^*\). Then \(T' = T \cup \{e^*\} \setminus \{f\}\) is also a spanning tree (still acyclic and connected). Since \(w(e^*) < w(f)\) (by uniqueness of minimum), \(w(T') < w(T)\) — contradicting optimality of \(T\). Therefore \(e^* \in T\). \(\square\)

Kruskal Complexity

$$T_{\text{Kruskal}} = O(m \log m) + O(m \cdot \alpha(n)) = O(m \log m)$$

Sorting dominates. Since \(m \leq n^2\), \(\log m = O(\log n)\), so this is also \(O(m \log n)\).

Prim Complexity

With a binary min-heap: each of \(m\) edges is pushed once (\(O(\log m)\) per push), each of \(n\) vertices is popped once (\(O(\log m)\) per pop):

$$T_{\text{Prim}} = O((m + n) \log m) = O(m \log n)$$

With a Fibonacci heap, decrease-key is \(O(1)\) amortized: \(T_{\text{Prim-Fib}} = O(m + n \log n)\).

MST as a Matroid

Spanning forests of a graph form a graphic matroid \(\mathcal{M} = (E, \mathcal{I})\) where \(\mathcal{I}\) is the collection of acyclic edge subsets. The MST problem is equivalent to finding a maximum-weight basis of the dual matroid under negated weights. Greedy works on any matroid — this is why both Kruskal and Prim are provably optimal without case analysis.

⚠️ Uniqueness Condition

If all edge weights are distinct, the MST is unique. If weights can repeat, there may be multiple MSTs with the same total weight, but all have the same multiset of edge weights (by the matroid exchange property). The cut/cycle property proofs assume uniqueness for simplicity; with ties, at least one optimal MST contains any minimum-weight cut-crossing edge.

Connection to Single-Linkage Clustering

Build the MST on your data points where \(w(u,v) = d(u,v)\) (Euclidean distance or any metric). The MST encodes the full single-linkage dendrogram: the merge order is exactly the MST edge-weight order. Cutting the \(k-1\) heaviest edges gives \(k\) clusters — the same clusters as running single-linkage hierarchical clustering and cutting the dendrogram at \(k\) groups. Total cost: \(O(n^2 \log n)\) with Prim on a dense graph.

$$\text{single-linkage}(C_i, C_j) = \min_{u \in C_i, v \in C_j} d(u,v) = \text{weight of first MST edge joining } C_i, C_j$$

Code Implementation

Kruskal from Scratch (Python)

def kruskal(n, edges):
"""MST via Kruskal's algorithm.
n: number of vertices (0..n-1)
edges: list of (u, v, weight)
Returns: list of MST edges, total weight
"""
# Step 1: Sort edges by weight — O(m log m)
edges = sorted(edges, key=lambda e: e[2])
# Step 2: Union-Find with path compression + union by rank
parent = list(range(n))
rank = [0] * n
def find(x): # path compression
while parent[x] != x:
parent[x] = parent[parent[x]] # halving
x = parent[x]
return x
def union(x, y): # union by rank
rx, ry = find(x), find(y)
if rx == ry: return False # same component — would create cycle
if rank[rx] < rank[ry]: rx, ry = ry, rx
parent[ry] = rx
if rank[rx] == rank[ry]: rank[rx] += 1
return True
# Step 3: Greedily add edges
mst, total = [], 0
for u, v, w in edges:
if union(u, v): # no cycle → add to MST
mst.append((u, v, w))
total += w
if len(mst) == n - 1: # MST complete (n-1 edges)
break
return mst, total
# Example: 6 nodes, 8 edges → MST weight = 17
edges = [(0,1,4),(0,2,3),(1,2,1),(1,3,2),(2,4,5),(3,4,9),(3,5,7),(4,5,6)]
mst, w = kruskal(6, edges)
print(mst) # [(1,2,1),(1,3,2),(0,2,3),(2,4,5),(4,5,6)]
print(w) # 17

Prim from Scratch (Python)

import heapq
def prim(n, edges, start=0):
"""MST via Prim's algorithm with a binary heap.
n: number of vertices
edges: list of (u, v, weight)
Returns: list of MST edges, total weight
"""
adj = [[] for _ in range(n)]
for u, v, w in edges:
adj[u].append((w, v))
adj[v].append((w, u))
in_mst = set()
heap = [(0, start, -1)] # (weight, node, parent)
mst, total = [], 0
while heap and len(in_mst) < n:
w, u, parent = heapq.heappop(heap)
if u in in_mst:
continue # stale entry — already in MST
in_mst.add(u)
if parent != -1:
mst.append((parent, u, w))
total += w
for nw, v in adj[u]: # explore neighbors
if v not in in_mst:
heapq.heappush(heap, (nw, v, u))
return mst, total
# Same graph → same MST weight = 17
mst, w = prim(6, edges, start=0)
print(mst) # [(0,2,3),(2,1,1),(1,3,2),(2,4,5),(4,5,6)]
print(w) # 17
