Quantization for LLM Inference

Reducing model size and speeding up inference with lower-precision numbers
Intermediate Deep Learning LLMs O(1) extra cost
1
Understanding Quantization
▼

What is it? Quantization in machine learning is the process of converting continuous floating-point numbers (like 32-bit floats, FP32) into discrete, lower-precision integer representations (e.g., 8-bit integers, INT8, or even 4-bit, INT4). For Large Language Models (LLMs), this means representing the vast number of weights and activations with fewer bits, significantly reducing memory footprint and computational cost during inference.

Analogy: Imagine you have a high-resolution photograph (FP32). Quantization is like reducing its color palette to a much smaller set of colors (INT8/INT4). If done well, the image still looks mostly the same, but it takes up much less storage space and can be processed faster. If done poorly, or if the original image has extreme colors, you might lose important detail or introduce noticeable artifacts.

💡 If you remember one thing

Quantization maps a range of floating-point values \([Min, Max]\) to a finite set of integer levels. The core idea is to find a scale factor \(S\) and a zero-point \(Z\) that best approximate this mapping, allowing efficient integer arithmetic and then de-quantizing back to approximate floats when needed.

2
How It Works Internally
▼

The Core Idea: Scale and Zero Point

Every floating-point value \(x\) is converted to a quantized integer \(q\) using a scale factor \(S\) and a zero point \(Z\). The reverse process, de-quantization, reconstructs an approximate floating-point value \(\tilde{x}\) from \(q\). This is the fundamental equation:

$$q = \text{round}\left(\frac{x}{S} + Z\right)$$

And for de-quantization:

$$\tilde{x} = S \cdot (q - Z)$$

The scale \(S\) determines the step size between quantization levels, and the zero point \(Z\) aligns the floating-point zero with an integer value (often 0 or 128 for INT8). The goal is to choose \(S\) and \(Z\) such that quantization error is minimized across the range of values in a tensor.

Symmetric vs. Asymmetric Quantization

There are two main approaches to defining the mapping:

  • Symmetric: The floating-point range is centered around zero, e.g., \([-Max, +Max]\). The integer range is then typically \([-127, +127]\) for INT8, and \(Z\) is implicitly 0. This is simpler but can be suboptimal if the float distribution is not centered at zero.
  • Asymmetric: The floating-point range is defined by its true \([Min, Max]\) values, which can be entirely positive or negative. The integer range is typically \([0, 255]\) for unsigned INT8. This allows better utilization of the full integer range but requires explicitly calculating and storing \(Z\).

Per-Tensor vs. Per-Channel Quantization

Quantization parameters (\(S\) and \(Z\)) can be determined for:

  • Per-tensor: A single \(S\) and \(Z\) are used for all values in an entire weight matrix or activation tensor. This is simpler but can be suboptimal if different parts of the tensor have very different value ranges.
  • Per-channel: \(S\) and \(Z\) are calculated independently for each output channel (or row/column) of a weight matrix. This is more expensive to store but significantly improves accuracy, especially for heterogeneous distributions common in LLMs.
🔑 Key Property

The choice of \(S\) and \(Z\) is crucial. They are determined during a process called calibration, often by analyzing the distribution of values in a small dataset. This ensures that the dynamic range of the original floating-point values is effectively captured by the limited integer levels.

Why It Works — The Math
▼

Deriving Scale and Zero Point

Let \(B\) be the number of bits (e.g., 8 for INT8). The number of unique integer levels is \(2^B\). For signed integers (like INT8 \(\in [-128, 127]\)), the range is \([-2^{B-1}, 2^{B-1}-1]\). For unsigned (like UINT8 \(\in [0, 255]\)), it's \([0, 2^B-1]\).

1. Symmetric Quantization (e.g., INT8 to \([-127, 127]\))

Given a float range \([-Max, +Max]\), we want to map \(Max\) to \(2^{B-1}-1\) (e.g., 127). The scale \(S\) is simply:

$$S = \frac{Max}{2^{B-1}-1}$$

The zero point \(Z\) is typically 0, so \(q = \text{round}(x/S)\).

2. Asymmetric Quantization (e.g., UINT8 to \([0, 255]\))

Given a float range \([Min, Max]\), we map \(Min\) to \(0\) and \(Max\) to \(2^B-1\). The scale \(S\) is:

$$S = \frac{Max - Min}{2^B - 1}$$

The zero point \(Z\) ensures that \(Min\) maps to \(0\): \(0 = \text{round}(Min/S + Z) \implies Z = -\text{round}(Min/S)\). Note that \(Z\) is an integer, so we round. The formula for \(q\) is still \(q = \text{round}(x/S + Z)\).

Quantization Error

The fundamental trade-off is quantization error, \(\epsilon = x - \tilde{x}\). This error is introduced because multiple floating-point values map to the same integer level. The maximum absolute error is \(S/2\). The mean squared error (MSE) is often used as a metric for calibration, trying to find \(S\) and \(Z\) that minimize \(\mathbb{E}[(x - \tilde{x})^2]\).

⚠️ The Outlier Problem

If a tensor has a few very large values (outliers) and many small values, a single global \([Min, Max]\) range will be dominated by the outliers. This makes \(S\) very large, meaning the step size between quantization levels is also large. Consequently, the many small values will all be quantized to very few (or even one) integer levels, leading to significant precision loss and poor model performance. This is why per-channel or more advanced quantization methods (like GPTQ/AWQ that clip outliers) are crucial for LLMs.

Key Takeaways
▼

Benefits of Quantization for LLMs:

  • Reduced Memory: Storing weights (and KV cache) in INT4/INT8 halves/quarters memory usage, allowing larger models or larger batch sizes.
  • Faster Inference: Integer arithmetic is faster on modern hardware (especially specialized tensor cores) and reduces memory bandwidth bottlenecks.
  • Deployment: Enables LLMs to run on resource-constrained devices (edge devices, mobile phones).

Challenges & Advanced Techniques:

  • Accuracy Drop: The primary challenge is minimizing the loss of accuracy. This requires careful calibration, often using a small subset of the training data.
  • Outlier Handling: Large outliers in weight distributions are common. Techniques like clipping, or sophisticated quantization algorithms like GPTQ (General-purpose Quantization) and AWQ (Activation-aware Weight Quantization), are designed to preserve accuracy by intelligently handling these outliers.
  • KV Cache Quantization: For long contexts, the Key-Value (KV) cache can consume significant memory. Quantizing the KV cache (e.g., to INT8) is another crucial optimization for LLM inference efficiency.
💡 The Future is Low-Bit

The trend is towards even lower bit-widths (INT4, INT2, or even 1-bit binary networks). While challenging, these push the boundaries of efficiency. The core principles of scale, zero-point, and calibration remain fundamental, but the methods for minimizing quantization error become increasingly sophisticated.

import numpy as np
def quantize_symmetric(x_float, B=8):
# Determine scaling range based on B bits (e.g., -127 to 127 for B=8)
q_min = -(2**(B-1) - 1)
q_max = (2**(B-1) - 1)
# Find global max absolute value for calibration
abs_max = np.max(np.abs(x_float))
# Calculate scale factor (S)
S = abs_max / q_max
Z = 0 # Zero point is 0 for symmetric
# Quantize: x_float / S + Z, then round and clip to integer range
q_int = np.round(x_float / S + Z)
q_int = np.clip(q_int, q_min, q_max)
return q_int.astype(np.int8), S, Z # Return integer type and params
def quantize_asymmetric(x_float, B=8):
# Determine scaling range for unsigned integers (e.g., 0 to 255 for B=8)
q_min = 0
q_max = (2**B - 1)
# Find global min/max values for calibration
x_min = np.min(x_float)
x_max = np.max(x_float)
# Calculate scale factor (S)
S = (x_max - x_min) / (q_max - q_min)
# Calculate zero point (Z), rounded to nearest integer
Z = np.round(q_min - x_min / S)
Z = np.clip(Z, q_min, q_max) # Clip Z to be within integer range
# Quantize: x_float / S + Z, then round and clip
q_int = np.round(x_float / S + Z)
q_int = np.clip(q_int, q_min, q_max)
return q_int.astype(np.uint8), S, Z # Return integer type and params
def dequantize(q_int, S, Z):
# Dequantize: S * (q_int - Z)
return S * (q_int - Z)
