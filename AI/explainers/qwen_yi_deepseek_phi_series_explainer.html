Qwen, Yi, DeepSeek, Phi-series: Achieving big performance in small packages

1
Understanding Small Efficient Models
▼

What is it? For years, the dominant paradigm in Large Language Models (LLMs) was "bigger is better" — scale up parameters, scale up data, get better performance. However, recent models like Microsoft's Phi-series, Alibaba's Qwen, 01.AI's Yi, and DeepSeek's models have challenged this, demonstrating impressive capabilities (often matching or exceeding much larger models) with significantly fewer parameters. These "small but mighty" LLMs prioritize efficiency through meticulous data curation, architectural innovations, and focused training strategies.

Analogy: Instead of building a massive, sprawling library filled with every book ever written (many of them low-quality or redundant), imagine creating a highly curated, concise, and expertly organized handbook for a specific domain. This handbook might be much smaller, but it contains only the most valuable and relevant information, making it incredibly effective for its intended purpose. Small efficient LLMs are like these handbooks: they are compact but "information-dense."

💡 If you remember one thing

The performance of small efficient models stems from a synergistic combination of high-quality, often synthetically generated training data, coupled with architectural optimizations that enhance parameter utilization. This allows them to "punch above their weight" in terms of performance per parameter or computational cost.

2
How They Work Internally
▼

Data Curation: Quality over Quantity

A hallmark of these models is their obsessive focus on data quality. Rather than simply ingesting vast quantities of raw web data, they employ sophisticated filtering, deduplication, and often, synthetic data generation techniques. For example:

  • Phi-1/Phi-2: Trained on "textbook-quality" data, a mix of filtered web content and synthetically generated data from larger LLMs. This data is designed to be highly didactic and conceptually dense, mimicking educational materials.
  • DeepSeek-Coder: Utilized a massive, high-quality dataset of code, filtered for correctness and diversity, allowing it to excel in programming tasks with fewer parameters.
  • Qwen/Yi: Combine high-quality web data with carefully selected scientific, academic, and code-centric corpora, often with multiple stages of filtering.

The intuition is that a small model has limited capacity; feeding it noisy or redundant data wastes that capacity. Clean, information-rich data allows it to learn more effectively from each parameter.

Architectural Efficiency & Optimizations

While still largely based on the Transformer architecture, these models often incorporate subtle but impactful modifications:

  • Grouped Query Attention (GQA): Used in models like Qwen and Yi, GQA generalizes Multi-Head Attention (MHA) and Multi-Query Attention (MQA). It allows query heads to share key and value projections, reducing memory bandwidth requirements and improving inference speed without significant performance loss, especially for smaller models.
  • SwiGLU Activation: A variant of GLU (Gated Linear Unit) combined with Swish activation, SwiGLU has been shown to improve performance for Transformers, often used in conjunction with larger hidden dimensions to compensate for smaller parameter counts.
  • Optimized Layer Normalization: Different placements or types of normalization (e.g., RMSNorm instead of LayerNorm) can offer minor speedups or stability improvements.
  • Reduced Depth/Width: Carefully balancing the number of layers and the hidden dimension to find the optimal compute-performance trade-off for the target model size.

Design Decision: Why not just use larger models?

The drive for smaller, efficient models is pragmatic. Larger models demand immense computational resources for training and inference, leading to high costs, energy consumption, and latency. Small models offer:

  • Lower Inference Costs: Crucial for deploying LLMs at scale.
  • Faster Inference: Important for real-time applications.
  • Edge & On-Device Deployment: Enabling LLMs on mobile phones, IoT devices, or local machines.
  • Reduced Carbon Footprint: More sustainable AI development.
  • Easier Fine-tuning: Smaller models are faster and cheaper to adapt to specific downstream tasks.
🔑 Key Property

The core principle is to maximize the "utility per parameter." This is achieved by ensuring each parameter sees the most informative data possible and is used in the most computationally efficient way within the network's architecture.

3
Why They Work — The Math & Theory
▼

Revisiting Scaling Laws with Data Quality

Traditional scaling laws (Kaplan et al., 2020; Hoffmann et al., 2022) suggest that performance scales predictably with model size \(N\), dataset size \(D\), and compute \(C\). For example, Chinchilla's optimal scaling suggests that for every increase in model size, the training data should increase proportionally to fully utilize the model's capacity. These laws often take the form:

$$L(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta}$$

where \(L\) is the loss, \(E\) is irreducible error, and \(A, B, \alpha, \beta\) are constants. However, this formula implicitly assumes a uniform "quality" of data. Small efficient models demonstrate that this equation can be dramatically altered by introducing a data quality factor \(Q\).

We can conceptualize an "effective dataset size" \(D_{eff} = Q \cdot D\), where \(Q > 1\) for high-quality data. Then the scaling law becomes:

$$L(N, D, Q) = E + \frac{A}{N^\alpha} + \frac{B}{(Q \cdot D)^\beta}$$

This implies that increasing data quality \(Q\) has a similar effect to increasing raw data quantity \(D\), but potentially more efficiently, allowing smaller \(N\) to achieve lower \(L\). The "textbook quality" hypothesis posits that \(Q\) can be significantly large for curated or synthetic data.

Architectural Impact: Efficient Compute Mapping

Architectural innovations like Grouped Query Attention (GQA) don't change the theoretical capacity of the model in the same way as adding more parameters, but they change the efficiency with which that capacity is utilized during computation. For a Transformer layer, attention involves computing Query (\(Q\)), Key (\(K\)), and Value (\(V\)) matrices. In Multi-Head Attention (MHA), each of \(H\) heads has its own \(Q, K, V\) projections. In GQA, \(G\) groups of heads share \(K, V\) projections, where \(1 \le G \le H\).

The computational cost for \(K, V\) projections is reduced by a factor of \(H/G\). This means for an equivalent number of parameters and theoretical expressivity, GQA reduces memory bandwidth and latency, especially critical during inference. The impact on total FLOPs might be small, but the practical speedup due to memory access patterns is significant. The model thus achieves a higher "effective compute efficiency" per parameter.

⚠️ Not a Universal Solution

While impressive, small efficient models are not a panacea. They often excel in specific domains (e.g., coding, reasoning on structured text) due to their specialized training data. For broad, open-ended generative tasks or complex multi-modal reasoning, larger, more generalist models still tend to hold an advantage due to their sheer capacity for diverse knowledge and nuanced understanding.

Key Takeaways
▼

When to use small efficient models:

  • Resource-constrained environments: Deploying on edge devices, mobile phones, or consumer-grade GPUs with limited VRAM.
  • Specific domain tasks: When fine-tuned for a particular industry or application, their focused training data makes them highly effective and specialized.
  • Cost-sensitive applications: Significantly lower inference costs make them ideal for high-volume deployments.
  • Privacy-sensitive local deployment: Running models entirely on-device eliminates the need to send data to external servers.
  • Faster iteration: Quicker to train, fine-tune, and experiment with due to reduced compute requirements.

When NOT to use small efficient models:

  • General-purpose reasoning: For tasks requiring broad, common-sense knowledge or complex multi-step reasoning across diverse domains, larger models still tend to excel.
  • When raw compute isn't a bottleneck: If you have ample GPU resources, the incremental gains from extreme efficiency might not outweigh the broader capabilities of larger models.
  • When data curation is impossible or too expensive: The performance of these models heavily relies on high-quality data, which can be difficult or costly to acquire/generate.
  • Cutting-edge research: While efficient, they often build on innovations from larger models; for pushing the absolute frontier of capabilities, larger models are still the primary research vehicles.
💡 Big Picture

The success of small efficient LLMs marks a critical shift in the LLM landscape, moving beyond brute-force scaling. They highlight that intelligence in AI is not solely about size, but also about the quality of learning materials and the elegance of the learning machinery. This opens doors for broader accessibility and more sustainable AI development.

Code Trace — Simplified Transformer Block with GQA
▼
import torch
import torch.nn as nn
import torch.nn.functional as F
class SwiGLU(nn.Module):
def forward(self, x):
x, gate = x.chunk(2, dim=-1) # Split input for gated activation
return x * F.silu(gate)
class GroupedQueryAttention(nn.Module):
def __init__(self, dim, n_heads, n_kv_heads):
super().__init__()
self.n_heads = n_heads
self.n_kv_heads = n_kv_heads # Number of Key/Value heads (G in GQA)
self.head_dim = dim // n_heads
self.q_proj = nn.Linear(dim, n_heads * self.head_dim, bias=False)
self.kv_proj = nn.Linear(dim, n_kv_heads * self.head_dim * 2, bias=False) # K and V shared
self.out_proj = nn.Linear(n_heads * self.head_dim, dim, bias=False)
self.kv_groups = n_heads // n_kv_heads # How many query heads share a KV head
def forward(self, x, mask=None):
B, T, C = x.size()
q = self.q_proj(x).view(B, T, self.n_heads, self.head_dim)
kv = self.kv_proj(x).view(B, T, self.n_kv_heads, self.head_dim * 2)
k, v = kv.chunk(2, dim=-1) # Split K and V
# Repeat K and V for each query head in its group
k = k.repeat_interleave(self.kv_groups, dim=2)
v = v.repeat_interleave(self.kv_groups, dim=2)
# Standard attention computation (reshaping for batch matmul)
q = q.transpose(1, 2); k = k.transpose(1, 2); v = v.transpose(1, 2)
attn_scores = (q @ k.transpose(-2, -1)) * (self.head_dim ** -0.5)
if mask is not None: attn_scores = attn_scores.masked_fill(mask == 0, float('-inf'))
attn_weights = F.softmax(attn_scores, dim=-1)
output = (attn_weights @ v).transpose(1, 2).contiguous().view(B, T, C)
return self.out_proj(output)
