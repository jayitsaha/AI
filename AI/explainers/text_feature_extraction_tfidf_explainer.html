Text Feature Extraction: TF-IDF & N-grams

From raw text to sparse numeric vectors — bag-of-words, term frequency weighting, and local order capture
Intermediate Classical ML · Feature Engineering · NLP Sparse Matrices · O(N·D)
1
Understanding the Concept
▾

Machine learning models require numbers, but text is strings. Text feature extraction converts a corpus of documents into a matrix of numbers where each row is a document and each column is a feature derived from vocabulary terms.

The Bag-of-Words (BoW) model treats a document as an unordered set of word counts. It loses word order but captures vocabulary presence and frequency. From raw counts we derive TF-IDF, which down-weights terms that appear in nearly every document (like "the") and up-weights terms that are distinctive to a few documents.

N-grams extend BoW by treating contiguous sequences of \(n\) words as atomic features, recovering some local ordering information. A bigram "not good" captures negation that unigrams would miss entirely.

Key Insight

TF-IDF is the product of two statistics: how often a term appears in this document (TF) times how rare it is across all documents (IDF). Common words have high TF but low IDF; distinctive words have high TF and high IDF — the product isolates signal.

2
How It Works Internally
▾

Step 1 — Tokenization & Vocabulary. The corpus of \(N\) documents is tokenized. Every unique token (or n-gram) becomes a column. With \(V\) unique terms we get a \(N \times V\) document-term matrix (DTM). For a corpus of 10,000 docs and vocabulary of 50,000 terms this is 500 million cells — but 99%+ are zero. We store it as a sparse matrix.

Step 2 — Term Frequency (TF). For document \(d\) and term \(t\), raw TF is just the count \(c_{t,d}\). Sklearn normalises it: \(\text{tf}(t,d) = c_{t,d}\). Some variants use logarithm: \(1 + \log c_{t,d}\).

Step 3 — Inverse Document Frequency (IDF). Let \(\text{df}(t)\) = number of documents containing term \(t\). Sklearn's smooth IDF:

$$\text{idf}(t) = \log\!\left(\frac{N+1}{\text{df}(t)+1}\right) + 1$$

The "+1" smoothing prevents division by zero for unseen terms and adds 1 to the log so that terms appearing in every document still get a non-zero weight.

Step 4 — TF-IDF weight.

$$\text{tfidf}(t,d) = \text{tf}(t,d) \times \text{idf}(t)$$

Step 5 — L2 normalisation. Each document vector is divided by its L2 norm so cosine similarity equals the dot product. This removes document-length bias.

N-gram expansion. Before building the vocabulary, tokenizer emits all contiguous word sequences of length 1 to \(n\). Bigrams double or triple vocabulary size but capture phrases. Range \((1,2)\) = unigrams + bigrams.

Design Decision

Why \(\log\) in IDF and not raw reciprocal \(N/\text{df}\)? The log compresses the dynamic range — a word appearing in 1 doc vs. 10 docs gets a 2× boost, not 10×. This prevents extremely rare typos from dominating over moderately discriminative words.

3
The Math Behind TF-IDF
▾

Let corpus \(\mathcal{D} = \{d_1, \ldots, d_N\}\), vocabulary \(\mathcal{V} = \{t_1, \ldots, t_V\}\). The full document-term matrix \(\mathbf{X} \in \mathbb{R}^{N \times V}\) is defined entry-wise:

$$X_{ij} = \text{tfidf}(t_j, d_i) = c_{t_j, d_i} \cdot \left[\log\!\left(\frac{N+1}{\text{df}(t_j)+1}\right)+1\right]$$

After L2 row-normalisation, the cosine similarity between documents \(i\) and \(k\) is simply:

$$\text{sim}(d_i, d_k) = \tilde{\mathbf{x}}_i \cdot \tilde{\mathbf{x}}_k = \frac{\mathbf{x}_i \cdot \mathbf{x}_k}{\|\mathbf{x}_i\|_2 \|\mathbf{x}_k\|_2}$$

IDF derivation sketch. We want a function \(f(\text{df})\) that is monotone decreasing, equals 0 when \(\text{df}=N\) (ubiquitous term), and grows large when \(\text{df} \ll N\) (rare term). The natural choice is \(\log(N/\text{df})\); adding smoothing constants prevents singularities and ensures non-negativity.

N-gram feature space. With vocabulary of \(V\) unigrams and bigram range \((1,2)\), the combined vocabulary size is at most \(V + V^2\) (in practice far smaller due to sparsity). The DTM remains sparse because each document uses only a tiny fraction of all possible bigrams.

Sparsity Theorem

If a document contains \(L\) tokens, it can activate at most \(L\) distinct unigram columns and \(L-1\) bigram columns, regardless of vocabulary size \(V\). Row sparsity \(\approx L/V\), which is typically \(<0.01\).

From-Scratch Code Trace
▾

NumPy implementation of TF-IDF from scratch. Active line corresponds to current visualization step.

corpus = ["cat sat mat", "dog sat log", "cat log"]
docs = [d.split() for d in corpus] # tokenize
vocab = sorted(set(w for d in docs for w in d)) # build vocab
N = len(docs) # N=3 documents
tf = np.zeros((N, len(vocab)))
for i,doc in enumerate(docs): # fill TF counts
for w in doc: tf[i, vocab.index(w)] += 1
df = (tf > 0).sum(axis=0) # doc frequency
idf = np.log((N+1)/(df+1)) + 1 # smooth IDF
tfidf = tf * idf # TF * IDF
norms = np.linalg.norm(tfidf,axis=1,keepdims=True)
tfidf_norm = tfidf / norms # L2 normalise

When to Use TF-IDF

Use when you have limited compute, need interpretable features, or are doing keyword-heavy retrieval. TF-IDF with bigrams often beats word embeddings on short classification tasks with small datasets. Skip it when semantic paraphrase matters (TF-IDF treats synonyms as unrelated) or when you have GPU budget for transformers.
