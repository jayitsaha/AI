1
Understanding FlashAttention
▼

What is it? FlashAttention is an optimized attention algorithm that significantly speeds up and reduces memory usage for Transformer models, especially on GPUs. It achieves this by being "IO-aware," meaning it minimizes the amount of data transferred between fast (SRAM) and slow (HBM) memory on the GPU.

Why is it needed? Standard attention (like in the original Transformer) involves computing a large attention matrix \\(P = \text{softmax}(QK^\top / \sqrt{d_k})\\) and then \\(O = PV\\). For long sequences of length \\(N\\) and hidden dimension \\(D\\), \\(Q, K, V\\) are \\(N \times D\\) matrices. The attention matrix \\(P\\) is \\(N \times N\\). Storing and moving this \\(N \times N\\) matrix (which can be gigabytes for \\(N=65536\\)) between GPU's High Bandwidth Memory (HBM) and faster but smaller SRAM is a major bottleneck. This is called the memory wall or IO bottleneck.

The Core Idea: Fused Kernels & Tiling. FlashAttention avoids materializing the full \\(N \times N\\) attention matrix in HBM. Instead, it breaks \\(Q, K, V\\) into smaller blocks (tiles), loads these blocks into SRAM, performs the attention computation for those blocks, and accumulates the output, all within SRAM. This "fused kernel" approach drastically reduces HBM reads/writes.

💡 If you remember one thing

FlashAttention re-organizes the standard attention computation to keep intermediate results (like the \\(N \times N\\) attention matrix) in fast on-chip memory (SRAM) as much as possible, minimizing costly transfers to/from slower off-chip memory (HBM). This is achieved through tiling and kernel fusion.

2
How FlashAttention Works Internally
▼

The Memory Hierarchy Problem

GPUs have a memory hierarchy:

  • High Bandwidth Memory (HBM): Large capacity (tens of GBs), but relatively slow access. This is where your model weights and full input/output tensors reside.
  • SRAM (Shared Memory / L1 Cache): Small capacity (tens to hundreds of KBs), but very fast access (100x faster than HBM). Optimal for intermediate computations.
Standard attention often requires reading \\(Q, K, V\\) from HBM, computing \\(QK^\top\\) (an \\(N \times N\\) matrix), writing it to HBM, reading it back for softmax, writing \\(P\\) to HBM, reading \\(P, V\\) for \\(PV\\), and finally writing \\(O\\) to HBM. Many redundant HBM accesses!

The Tiling Strategy

FlashAttention divides the input sequences \\(Q, K, V\\) into smaller blocks (tiles). It then processes these blocks iteratively. For each block of \\(Q\\) (let's call it \\(Q_i\\)), it iterates through all blocks of \\(K\\) (\\(K_j\\)) and \\(V\\) (\\(V_j\\)).

The Two Passes

FlashAttention uses a clever two-pass approach to compute the softmax correctly without materializing the full attention matrix:

  1. First Pass (Forward):
    • For each \\(Q_i\\) block:
    • Iterate through all \\(K_j, V_j\\) blocks.
    • Load \\(Q_i, K_j, V_j\\) into SRAM.
    • Compute a partial attention score \\(S_{ij} = Q_i K_j^\top\\) and a partial softmax \\(P_{ij} = \text{softmax}(S_{ij})\).
    • Compute a partial output \\(O_{ij} = P_{ij} V_j\\).
    • Crucially, it also computes and updates running statistics for the softmax (row-wise maximum \\(m_i\\) and sum of exponentials \\(l_i\\)) for each \\(Q_i\\) block.
    • Accumulate \\(O_{ij}\\) into a running \\(O_i\\) output block.
    • These \\(m_i\\) and \\(l_i\\) are saved to HBM. The full \\(P\\) matrix is never written to HBM.
  2. Second Pass (Backward/Refine):
    • For each \\(Q_i\\) block:
    • Load \\(Q_i\\) and its final \\(m_i, l_i\\) from HBM into SRAM.
    • Iterate through all \\(K_j, V_j\\) blocks again.
    • Load \\(K_j, V_j\\) into SRAM.
    • Recompute \\(S_{ij} = Q_i K_j^\top\\).
    • Apply the global softmax scaling using the final \\(m_i, l_i\\) to get the correct \\(P_{ij}\\).
    • Compute \\(O_{ij} = P_{ij} V_j\\) and accumulate into the final \\(O_i\\).
    • Write the final \\(O_i\\) block to HBM.

This two-pass strategy ensures mathematical equivalence to standard attention while keeping intermediate \\(N \times N\\) matrices out of HBM.

🔑 Key Innovation

The core innovation is the online softmax trick. This allows computing the softmax function incrementally across blocks without needing the full \\(N \times N\\) attention scores matrix at any single point in time. It updates the maximum \\(m_i\\) and sum of exponentials \\(l_i\\) for each row of \\(Q\\) as new \\(K\\) blocks are processed.

3
Why It Works — The Math
▼

Standard Attention Recap

The self-attention mechanism is defined as:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Let \\(S = QK^\top / \sqrt{d_k}\\) be the raw attention scores. The softmax operation is applied row-wise:

$$P_{ij} = \frac{\exp(S_{ij})}{\sum_k \exp(S_{ik})}$$

The problem is that \\(S\\) (and thus \\(P\\)) is an \\(N \times N\\) matrix, which is too large to fit in SRAM for large \\(N\\). FlashAttention computes \\(P\\) and \\(O\\) in blocks, using an online softmax algorithm.

The Online Softmax Trick

Consider computing the \\(i\\)-th row of \\(P\\) and \\(O\\). Let \\(S_i = [S_{i1}, S_{i2}, \dots, S_{iN}]\\) be the \\(i\\)-th row of scores. The softmax for this row is:

$$P_i = \frac{\exp(S_i)}{\sum_k \exp(S_{ik})}$$

FlashAttention computes this incrementally. Suppose we have processed blocks \\(K_1, \dots, K_{j-1}\\) and have current maximum \\(m^{(j-1)}_i\\) and sum of exponentials \\(l^{(j-1)}_i\\). When we process \\(K_j\\), we get new scores \\(S_{ij} = Q_i K_j^\top / \sqrt{d_k}\\). We can update \\(m_i\\) and \\(l_i\\) as follows:

Let \\(m^{(j)}_i = \max(m^{(j-1)}_i, \max(S_{ij}))\\) and \\(l^{(j)}_i = \exp(m^{(j-1)}_i - m^{(j)}_i) l^{(j-1)}_i + \exp(\max(S_{ij}) - m^{(j)}_i) \sum_k \exp(S_{ijk} - \max(S_{ij}))\\). This is a simplified version; the actual update is more robust. The key is that the new maximum \\(m^{(j)}_i\\) and sum \\(l^{(j)}_i\\) allow us to combine previous partial sums with current partial sums correctly. Specifically, for an output block \\(O_i\\) and a new block \\(S_{ij}\\) and \\(V_j\\):

$$\begin{aligned} m_i^{\text{new}} &= \max(m_i^{\text{old}}, \max(S_{ij})) \\ l_i^{\text{new}} &= \exp(m_i^{\text{old}} - m_i^{\text{new}}) l_i^{\text{old}} + \exp(\max(S_{ij}) - m_i^{\text{new}}) \sum_k \exp(S_{ijk} - \max(S_{ij})) \\ O_i^{\text{new}} &= \frac{l_i^{\text{old}}}{l_i^{\text{new}}} \exp(m_i^{\text{old}} - m_i^{\text{new}}) O_i^{\text{old}} + \frac{1}{l_i^{\text{new}}} \exp(\max(S_{ij}) - m_i^{\text{new}}) \left( \text{softmax}(S_{ij}) V_j \right) \end{aligned}$$

This formulation means that \\(O_i\\) can be updated incrementally without ever forming the full \\(N \times N\\) matrix \\(P\\). The first pass computes the final \\(m_i\\) and \\(l_i\\) for each row of \\(Q\\). The second pass uses these final scaling factors to compute the final \\(O_i\\) blocks accurately.

➗ Mathematical Equivalence

The online softmax ensures that the final output \\(O\\) computed by FlashAttention is numerically identical to the output of standard attention, assuming infinite precision. In practice, it's often more numerically stable due to careful handling of large exponents.

Key Takeaways
▼

When to use FlashAttention:

  • Training or inferencing large Transformer models, especially with long sequence lengths (e.g., \\(N > 1024\\)).
  • When attention computation is a bottleneck, consuming significant GPU memory or time.
  • On NVIDIA GPUs with Tensor Cores, where fused operations can leverage specialized hardware.
  • When using exact attention (not sparse or approximate attention).

Benefits:

  • Speed: Up to 2-4x faster than standard attention due to reduced HBM access and better hardware utilization.
  • Memory Efficiency: Reduces HBM usage from \\(O(N^2)\\) to \\(O(N)\\) for intermediate attention matrices, enabling much longer sequence lengths.
  • Exactness: Computes the exact standard attention, unlike many sparse or approximate attention methods.
  • Gradient Computation: The technique also extends efficiently to the backward pass, saving memory and time for gradients.

Limitations:

  • Requires custom CUDA kernels, meaning it's not a simple Python library call (though frameworks like PyTorch integrate it).
  • Optimal performance depends on careful tuning of block sizes and other parameters, which can be hardware-specific.
  • Primarily benefits NVIDIA GPUs with sufficient SRAM and Tensor Core capabilities.
💡 Impact

FlashAttention has been a game-changer for large language models, significantly reducing training costs and enabling research into models with much larger context windows. It highlights the importance of IO-awareness in optimizing deep learning workloads.

Code Trace (Conceptual)
▼

This pseudocode illustrates the core logic of FlashAttention's first pass. The second pass recomputes \\(P\\) using the final \\(m\\) and \\(l\\) to produce the final \\(O\\).

# Assume Q, K, V are NxD matrices in HBM
# B is the block size for sequence dimension
# d_k is the head dimension
output_O = zeros(N, D) # Accumulator for output, in HBM
row_max_m = -infinity(N) # Running max for softmax, in HBM
row_sum_l = zeros(N) # Running sum for softmax, in HBM
# First Pass: Compute running O, m, l
for i_block from 0 to N step B:
Q_block = Q[i_block : i_block+B, :] # Load Q_i from HBM to SRAM
O_i_partial = zeros(B, D) # Partial output for this Q_block, in SRAM
m_i_current = row_max_m[i_block : i_block+B] # Load m_i from HBM to SRAM
l_i_current = row_sum_l[i_block : i_block+B] # Load l_i from HBM to SRAM
for j_block from 0 to N step B:
K_block = K[j_block : j_block+B, :] # Load K_j from HBM to SRAM
V_block = V[j_block : j_block+B, :] # Load V_j from HBM to SRAM
S_ij = Q_block @ K_block.T / sqrt(d_k) # Compute attention scores in SRAM
# Online Softmax Update (fused kernel)
m_ij_new = max(m_i_current, max(S_ij, axis=1)) # New max for rows of Q_block
P_ij = exp(S_ij - m_ij_new.unsqueeze(1)) # Scale scores for stability
l_ij_new = exp(m_i_current - m_ij_new) * l_i_current + sum(P_ij, axis=1) # Update sum
# Update partial output O_i_partial (fused kernel)
O_i_partial = (l_i_current / l_ij_new) * exp(m_i_current - m_ij_new) * O_i_partial + (1 / l_ij_new) * (P_ij @ V_block)
m_i_current = m_ij_new # Update running max
l_i_current = l_ij_new # Update running sum
# K_block, V_block, S_ij, P_ij are discarded from SRAM
output_O[i_block : i_block+B, :] = O_i_partial # Write final O_i_partial to HBM
row_max_m[i_block : i_block+B] = m_i_current # Write final m_i to HBM
row_sum_l[i_block : i_block+B] = l_i_current # Write final l_i to HBM
# (Second Pass, not shown: re-load Q_block, m, l, K_block, V_block, recompute P, O and write final O)
