Collaborative Filtering

User-based CF, item-based CF, and neighborhood methods for recommendation

Understanding Collaborative Filtering
▼

What is it? Collaborative filtering (CF) predicts how much a user will like an item using only the ratings matrix — no descriptions, genres, or features required. The core assumption: people who agreed in the past will agree again, and items that were rated similarly by the same crowd will keep being rated similarly.

Analogy: You ask friends with similar taste what they thought of a movie you haven't seen ("user-based"), or you notice that everyone who loved Inception also loved Interstellar, so if you loved Inception you're probably going to love Interstellar too ("item-based"). Both approaches never look at the movie's plot — they only look at the pattern of ratings.

💡 If you remember one thing

CF fills in a missing entry of the user–item ratings matrix by taking a similarity-weighted average of ratings from a neighborhood — either similar users or similar items: $$\hat{r}_{u,i} = \frac{\sum_{v \in N(u)} \text{sim}(u,v)\, r_{v,i}}{\sum_{v \in N(u)} |\text{sim}(u,v)|}$$

How Neighborhood CF Works Internally
▼

Two Flavors, One Recipe

User-based CF: to predict how user \(u\) will rate item \(i\), find the \(k\) users most similar to \(u\) who have rated \(i\), then blend their ratings, weighted by similarity. Item-based CF: to predict the same rating, find the \(k\) items most similar to \(i\) that user \(u\) has already rated, then blend user \(u\)'s ratings on those items. Both are "neighborhood methods" — they never build an explicit model, they just look up nearby rows or columns of the ratings matrix at prediction time.

Building the Neighborhood

Similarity is computed only over the items (or users) both parties actually rated — the co-rated set. Two common metrics: cosine similarity treats each user/item as a vector and measures the angle between them; Pearson correlation additionally subtracts each party's mean rating first, which corrects for the fact that some raters are simply more generous than others.

$$\text{sim}_{\cos}(u,v) = \frac{\sum_{i \in I_{uv}} r_{u,i}\,r_{v,i}}{\sqrt{\sum_{i \in I_{uv}} r_{u,i}^2}\sqrt{\sum_{i \in I_{uv}} r_{v,i}^2}}$$

Design Decision: User-based vs. Item-based

User-based CF needs to search across all other users at prediction time — expensive and unstable when the user base is huge and constantly churning. Item-based CF exploits the fact that item-item similarities are far more stable over time (a catalog changes slowly compared to a user base), so they can be precomputed offline once and reused for every user. This is why item-based CF (popularized by Amazon) scales better in production.

🔑 Key Property

Neighborhood CF is a lazy, memory-based method — there is no training phase. All the "learning" happens at query time by scanning the ratings matrix. This makes it simple and interpretable ("recommended because users like you rated it highly") but harder to scale than model-based approaches like matrix factorization.

Why It Works — The Math
▼

Similarity Over Co-Rated Items

Let \(I_{uv}\) be the set of items rated by both users \(u\) and \(v\). Cosine similarity over that restricted set is:

$$\text{sim}(u,v) = \frac{\mathbf{r}_u \cdot \mathbf{r}_v}{\lVert \mathbf{r}_u \rVert \, \lVert \mathbf{r}_v \rVert}, \qquad \mathbf{r}_u, \mathbf{r}_v \text{ restricted to } I_{uv}$$

Item-based similarity is the mirror image — replace "users who co-rated items" with "items co-rated by users":

$$\text{sim}(i,j) = \frac{\mathbf{r}_i \cdot \mathbf{r}_j}{\lVert \mathbf{r}_i \rVert \, \lVert \mathbf{r}_j \rVert}, \qquad \mathbf{r}_i, \mathbf{r}_j \text{ restricted to } U_{ij}$$

The Prediction Formula

Once the top-\(k\) neighborhood \(N(u)\) (or \(N(i)\)) is chosen, the missing rating is a similarity-weighted average — neighbors that agree more strongly with the target pull the prediction harder toward their own rating:

$$\hat{r}_{u,i} = \frac{\displaystyle\sum_{v \in N(u)} \text{sim}(u,v)\, r_{v,i}}{\displaystyle\sum_{v \in N(u)} |\text{sim}(u,v)|}$$

Dividing by the sum of absolute similarities (not just the count \(k\)) keeps the prediction on the original rating scale even when similarities are small or negative.

Mean-Centering (Pearson Variant)

Raw cosine similarity is thrown off by rating-scale bias — an optimist who rates everything 4–5 looks "similar" to another optimist even on unrelated taste. Subtracting each user's mean rating \(\bar{r}_u\) before computing similarity and before averaging fixes this:

$$\hat{r}_{u,i} = \bar{r}_u + \frac{\sum_{v \in N(u)} \text{sim}(u,v)\,(r_{v,i} - \bar{r}_v)}{\sum_{v \in N(u)} |\text{sim}(u,v)|}$$
⚠️ Common Pitfall

Sparsity breaks neighborhood CF: if two users share only one or two co-rated items, the "similarity" computed from them is statistically noisy — a single shared 5-star rating can produce a similarity of 1.0 from almost no evidence. Production systems require a minimum co-rated-item threshold (e.g. \(|I_{uv}| \geq 5\)) before trusting a similarity score.

Key Takeaways
▼

When to use neighborhood CF:

  • You have an explicit or implicit ratings matrix and want simple, interpretable recommendations
  • Catalog is relatively stable → precompute item-item similarities offline (item-based)
  • You need "explainable" recommendations ("because you rated X highly")
  • Cold items/users are rare, or you can fall back to popularity/content-based methods for them

When NOT to use (or use with care):

  • Extremely sparse matrices — few co-rated items make similarity estimates unreliable
  • Huge, fast-changing user bases — user-based similarity search doesn't scale well online
  • New users/items with no ratings yet — the classic cold-start problem, unsolved by pure CF
  • When latent structure matters more than raw co-occurrence — matrix factorization (SVD, ALS) usually predicts better at scale
💡 Hierarchy

Neighborhood CF (memory-based, lazy, interpretable) sits alongside model-based CF (matrix factorization, learns latent user/item vectors) and hybrid systems (blend CF with content features to fight cold-start). Modern production recommenders usually combine all three.

Code Trace

import numpy as np
# rows = users, cols = movies, nan = missing rating
R = np.array([
[5, 3, 4, 1, np.nan], # Alice <- predict R[0,4]
[4, np.nan, 5, 1, 4], # Bob
[1, 1, 2, 5, 2], # Carol
[5, 4, 5, np.nan, 5], # Dave
[2, 2, 1, 4, 1], # Eve
[4, 3, 4, 2, 5], # Frank
])
def cosine_sim(a, b):
mask = ~np.isnan(a) & ~np.isnan(b)
a, b = a[mask], b[mask]
return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))
# --- user-based: similarity between Alice (row 0) and everyone else ---
user_sims = [(v, cosine_sim(R[0], R[v])) for v in range(1, 6)]
user_sims.sort(key=lambda t: -t[1])
neighbors = user_sims[:3]
num = sum(s * R[v, 4] for v, s in neighbors)
den = sum(abs(s) for v, s in neighbors)
pred_user_based = num / den
# --- item-based: similarity between Interstellar (col 4) and other movies ---
item_sims = [(j, cosine_sim(R[:, 4], R[:, j])) for j in range(4)]
item_sims.sort(key=lambda t: -t[1])
top_items = item_sims[:3]
num_i = sum(s * R[0, j] for j, s in top_items)
den_i = sum(abs(s) for j, s in top_items)
pred_item_based = num_i / den_i
