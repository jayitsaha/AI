Understanding Tensors
▼

What is a tensor? A tensor is a container for numbers — organised into a specific geometric shape. Just as a spreadsheet holds numbers in rows and columns, a tensor can hold numbers in any number of dimensions. The order (also called rank or degree) of a tensor counts how many indices are needed to pick out a single element.

Analogy: Think of tensors as nested containers: a single egg is a scalar (0-D); a single row in an egg carton is a vector (1-D); a full carton (rows × columns) is a matrix (2-D); a box of cartons (depth × rows × columns) is a 3-D tensor. Every AI model manipulates exactly these nested containers.

Why it matters: Every layer in a neural network is a tensor operation. Image data arrives as a 4-D tensor of shape \((B, H, W, C)\); attention weights are 4-D \((B, \text{heads}, L, L)\); transformer hidden states are 3-D \((B, L, d)\). Fluency with tensor notation is the prerequisite for reading any ML paper.

💡 If you remember one thing

The order of a tensor = the number of indices needed to access one scalar element. A tensor \(\mathcal{T} \in \mathbb{R}^{d_1 \times d_2 \times \cdots \times d_N}\) has order \(N\), and its element at position \((i_1, i_2, \ldots, i_N)\) is written \(\mathcal{T}_{i_1 i_2 \cdots i_N}\).

2
Orders 0 through N — Definitions & Shape
▼

Order 0 — Scalar

A scalar is a single real number: \(a \in \mathbb{R}\). No indices needed. Shape: \((\ )\) (empty tuple). Examples: learning rate \(\alpha = 0.001\), loss value \(\mathcal{L} = 2.37\).

Order 1 — Vector

A vector \(\mathbf{v} \in \mathbb{R}^n\) stores \(n\) numbers in a line. One index: \(v_i\) picks the \(i\)-th element, \(i \in \{1,\ldots,n\}\). Shape: \((n,)\). Examples: word embedding \(\mathbf{e} \in \mathbb{R}^{512}\), bias term \(\mathbf{b} \in \mathbb{R}^{d}\).

Order 2 — Matrix

A matrix \(A \in \mathbb{R}^{m \times n}\) stores \(m \times n\) numbers on a grid. Two indices: \(A_{ij}\) picks row \(i\), column \(j\). Shape: \((m, n)\). Examples: weight matrix \(W \in \mathbb{R}^{d_{\text{out}} \times d_{\text{in}}}\), covariance matrix \(\Sigma \in \mathbb{R}^{d \times d}\).

Order 3 — 3-D Tensor

Three indices: \(\mathcal{T}_{ijk}\). Shape: \((d_1, d_2, d_3)\). Examples: a batch of word embeddings \(\mathcal{T} \in \mathbb{R}^{B \times L \times d}\) where \(B\) is batch size, \(L\) is sequence length, \(d\) is embedding dimension.

Order N — General Tensor

An order-\(N\) tensor \(\mathcal{T} \in \mathbb{R}^{d_1 \times d_2 \times \cdots \times d_N}\) has \(\prod_{k=1}^{N} d_k\) total elements and requires \(N\) indices to access any one of them:

$$\mathcal{T}_{i_1 i_2 \cdots i_N} \in \mathbb{R}, \quad i_k \in \{1, \ldots, d_k\}$$

The total number of elements is \(\prod_{k=1}^{N} d_k\). Memory cost scales multiplicatively — a design reason why very high-order tensors are rare in practice.

🔑 Key Property: Shape and Rank are distinct

Order (number of axes) ≠ Rank in the linear-algebra sense (dimension of column space). A full-rank matrix \(A \in \mathbb{R}^{3\times3}\) has order 2 and matrix rank 3. Confusingly, "rank" is overloaded — in ML frameworks, "rank" often means order. Always check context.

Index Notation, Shapes, and Einstein Summation
▼

Standard Index Notation

Element access uses subscript indices. Convention: lowercase Roman letters (\(i,j,k\)) for indices; uppercase for matrices; calligraphic (\(\mathcal{T}\)) or bold (\(\mathbf{T}\)) for higher-order tensors:

$$a \in \mathbb{R}, \quad v_i \in \mathbb{R}^n, \quad A_{ij} \in \mathbb{R}^{m\times n}, \quad \mathcal{T}_{ijk} \in \mathbb{R}^{p\times q\times r}$$

Einstein Summation Convention

A repeated index implies summation over that index (used in papers and torch.einsum):

$$c_i = A_{ij}\,v_j \quad \equiv \quad c_i = \sum_{j} A_{ij}\,v_j \quad \text{(matrix-vector product)}$$
$$C_{ik} = A_{ij}\,B_{jk} \quad \equiv \quad C_{ik} = \sum_{j} A_{ij}\,B_{jk} \quad \text{(matrix-matrix product)}$$

This generalises: torch.einsum("bij,bjk->bik", A, B) is batched matrix multiplication, automatically summing over the \(j\) axis.

Shape Convention in ML Frameworks

PyTorch / NumPy use 0-based indices and C-contiguous (row-major) layout. A tensor of shape (B, C, H, W) stores batches of images: the last two axes (\(H, W\)) are contiguous in memory.

⚠️ Common Pitfall: Axis Ordering

PyTorch uses channel-first \((B, C, H, W)\); TensorFlow defaults to channel-last \((B, H, W, C)\). Forgetting to permute axes is the source of many cryptic shape errors. Use tensor.permute() or np.transpose() to reorder axes.

Fibre, Slice, and Mode

Fixing all but one index of a tensor gives a fibre (the generalisation of a row/column). Fixing all but two indices gives a slice (a matrix). The axis along which an operation runs is called a mode.

Key Takeaways & ML Applications
▼

Tensor order in real ML systems:

  • 0-D scalar: Loss values, learning rate, single metric readings.
  • 1-D vector: Bias terms, word embeddings, 1-D feature maps, gradient of a scalar loss w.r.t. a vector parameter.
  • 2-D matrix: Weight matrices (\(W \in \mathbb{R}^{d_\text{out}\times d_\text{in}}\)), attention score matrix (\(QK^\top \in \mathbb{R}^{L\times L}\)).
  • 3-D tensor: Batched sequences \((B, L, d)\), RNN hidden states over time, per-head attention.
  • 4-D tensor: Image batches \((B, C, H, W)\), all-heads attention \((B, H, L, L)\).
  • 5-D tensor: Video batches \((B, T, C, H, W)\), where \(T\) is the time dimension.

Contraction & broadcasting: Most DL operations contract (sum over) one or more shared indices. Broadcasting allows axes of size 1 to be implicitly expanded — a powerful shorthand that relies on the same tensor-order algebra.

💡 Hierarchy of Generalisation

Scalar ⊂ Vector ⊂ Matrix ⊂ 3-D Tensor ⊂ … ⊂ N-D Tensor. Each is a special case of the next with extra axes of size 1 squeezed away. The same algebra (contraction, outer product, transposition) generalises uniformly.

Code Trace — Tensor Construction & Indexing in PyTorch
▼
import torch
# Order 0 — Scalar
a = torch.tensor(3.14) # shape: torch.Size([])
print(a.ndim, a.shape) # 0 torch.Size([])
# Order 1 — Vector
v = torch.tensor([1., 2., 3.]) # shape: (3,)
print(v.ndim, v.shape) # 1 torch.Size([3])
print(v[1]) # tensor(2.) — one index
# Order 2 — Matrix
A = torch.arange(6.).reshape(2, 3) # shape: (2, 3)
print(A.ndim, A.shape) # 2 torch.Size([2, 3])
print(A[0, 2]) # tensor(2.) — two indices
# Order 3 — 3-D Tensor (e.g. batched embeddings: B=2, L=4, d=8)
T = torch.randn(2, 4, 8) # shape: (2, 4, 8)
print(T.ndim, T.shape) # 3 torch.Size([2, 4, 8])
print(T[0, 2, 5]) # scalar — three indices
# Order 4 — 4-D Tensor (image batch: B=8, C=3, H=224, W=224)
imgs = torch.randn(8, 3, 224, 224) # shape: (8, 3, 224, 224)
print(imgs.ndim) # 4
print(imgs.numel()) # 8*3*224*224 = 1,204,224
# Einstein summation — matrix multiply via einsum
C = torch.einsum('ij,jk->ik', A, A.T) # (2,3)@(3,2) -> (2,2)
print(C.shape) # torch.Size([2, 2])
