Two answers to "my clusters don't fit in memory / don't fit one density"
Advanced Classical ML Clustering BIRCH: O(n) · OPTICS: O(n log n)
1
Understanding BIRCH & OPTICS
▼

What are they? BIRCH and OPTICS both tackle a weakness of k-means and vanilla DBSCAN: neither scales gracefully to huge streaming data (k-means, hierarchical clustering) nor handles clusters of very different densities (DBSCAN's single ε). BIRCH compresses a huge stream of points into a small in-memory tree of summary statistics in one pass. OPTICS orders points by "reachability" from dense neighborhoods, exposing clusters of any shape and density from a single run.

Analogy: BIRCH is a librarian scanning book requests once, keeping a running tally (count, average position) per pile instead of remembering every book — a new book that doesn't fit any pile's tally starts a new pile. OPTICS is like walking through a crowd, writing down how much of a squeeze it took to reach each person from the last one visited — dense crowds give smooth low readings, walking between two crowds gives a spike. Plot those readings and the crowds (clusters) appear as valleys.

💡 If you remember one thing

BIRCH stores only (N, LinearSum, SquaredSum) per cluster — a tiny additive summary — for single-pass, bounded-memory clustering. OPTICS replaces DBSCAN's one global ε with an ordered reachability-distance plot, so clusters at many densities can be read off at once: $$\text{reach-dist}(p,o) = \max\big(\text{core-dist}(o),\ d(p,o)\big)$$

How They Work Internally
▼

BIRCH: The Clustering Feature (CF)

Every sub-cluster is summarized by a triplet \(CF=(N,\vec{LS},SS)\): count, linear sum of points, sum of squared norms. Centroid, radius and diameter are algebraic functions of the triplet — no raw points needed. Insertion is one top-down pass per point: descend to the nearest leaf CF, test whether merging keeps the radius ≤ threshold \(T\); if yes, merge (an O(d) update); if no, add a new CF entry. A full leaf splits like a B-tree page, propagating updated CFs upward.

OPTICS: Core Distance & Reachability Distance

For a point \(p\), core-dist\((p)\) is the distance to its MinPts-th nearest neighbor within radius \(\varepsilon\) (undefined if fewer than MinPts neighbors exist). OPTICS visits an unprocessed point, appends it to an output order, and — if it's a core point — pushes its ε-neighbors onto a priority queue keyed by reach-dist\((p,o)=\max(\text{core-dist}(o), d(p,o))\). It always expands the closest, densest candidate next, so the output order and its reachability values trace out density-connected regions.

Design Decision: Why floor reach-dist at core-dist(o)?

Flooring makes every point inside a dense core equally reachable at that core's own core-distance, preserving DBSCAN's density-reachability semantics inside a single linear ordering — this is what makes the reachability plot equivalent to running DBSCAN at every ε' ≤ ε simultaneously.

🔑 Key Property

CFs are additive: \(CF_1 \oplus CF_2 = (N_1{+}N_2,\ \vec{LS}_1{+}\vec{LS}_2,\ SS_1{+}SS_2)\) — merging never touches raw data. OPTICS' reachability plot is equivalent to DBSCAN at every ε' ≤ ε in one pass — cut the plot at any height to extract that density's clusters.

3
Why It Works — The Math
▼

CF Algebra

Given \(CF=(N,\vec{LS},SS)\):

$$\vec{x}_0=\frac{\vec{LS}}{N}, \qquad R=\sqrt{\frac{SS}{N}-\left\|\frac{\vec{LS}}{N}\right\|^2}$$

\(R\) (radius) is the average distance of points to the centroid. Two disjoint CFs combine by simple addition — a direct consequence of linearity of the sum:

$$CF_1 \oplus CF_2 = (N_1+N_2,\ \vec{LS}_1+\vec{LS}_2,\ SS_1+SS_2)$$

OPTICS Reachability Distance

$$\text{core-dist}_{\varepsilon,MinPts}(p)=\begin{cases}\text{UNDEFINED} & |N_\varepsilon(p)| < MinPts\\ d_{MinPts}(p) & \text{otherwise}\end{cases}$$
$$\text{reach-dist}_{\varepsilon,MinPts}(p,o)=\max\big(\text{core-dist}(o),\ d(p,o)\big)$$

A contiguous run of low reachability values in the output order is exactly one DBSCAN-style cluster at that density; a spike means the algorithm had to "jump" — either crossing to a different density region or starting a fresh unconnected component.

⚠️ Common Misconception

"OPTICS clusters the data." It does not output labels directly — it outputs an ordering plus reachability values. Extracting flat clusters needs a second step: a fixed cut at height ε', or the ξ-steep-area method. Different cuts can yield materially different clusterings from the very same OPTICS run.

Key Takeaways
▼

When to use BIRCH:

  • Streaming data or datasets too large to fit in memory
  • Cheap pre-clustering step before k-means / GMM on huge n
  • Clusters are roughly spherical / convex

When to use OPTICS:

  • Clusters have genuinely different densities
  • You don't want to commit to a single DBSCAN ε upfront
  • Exploratory analysis where the reachability plot itself is diagnostic
💡 Hierarchy of Ideas

K-Means (spherical, needs k) → DBSCAN (arbitrary shape, single ε) → OPTICS (arbitrary shape, multi-density) → HDBSCAN (stability-based extraction, no ε at all). Separately, BIRCH attacks the orthogonal problem of scale: single-pass, bounded-memory summarization that can feed any of the above.
