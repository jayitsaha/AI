Mish Activation Function

A smooth, non-monotonic, self-regularizing activation for deep neural networks
Intermediate Deep Learning Activation Functions O(1) per neuron
1
Understanding Mish
▼

What is it? Mish is an activation function proposed by Diganta Misra in 2019. It's defined as \(\text{Mish}(x) = x \cdot \tanh(\operatorname{softplus}(x))\). Unlike ReLU (which is piecewise linear) or even Swish (which is smooth but monotonic), Mish is smooth everywhere and non-monotonic. These properties allow for better information flow through deep networks, leading to improved performance and generalization, especially in deep convolutional neural networks.

Analogy: Imagine a car's accelerator pedal. ReLU is like a pedal that's either off (0) or on (linear, positive). Swish is a smoother, slightly more responsive pedal. Mish is like a highly refined, adaptive pedal that not only responds smoothly but can also give a tiny, gentle "nudge" even when you're mostly off the gas, allowing for more nuanced control and preventing the engine from ever fully stalling. This subtle flexibility helps the network learn more robust features.

💡 If you remember one thing

Mish is a smooth, non-monotonic activation function that combines the input \(x\) with a hyperbolic tangent of its softplus. Its non-monotonicity in the negative region helps preserve small negative values, preventing "dead neurons" and improving gradient flow, while its smoothness aids optimization.

How Mish Works Internally
▼

The Mechanism: Softplus + Tanh + Scaling

Mish is constructed from two well-known functions: Softplus and Tanh. Let's break down its components:

  1. Softplus: The first component is \(\operatorname{softplus}(x) = \log(1 + e^x)\). This function is a smooth approximation of the ReLU function, meaning it's always positive and its output ranges from 0 (for very negative \(x\)) to \(x\) (for very positive \(x\)). It ensures that the input to the hyperbolic tangent is always positive.
  2. Hyperbolic Tangent (Tanh): The output of softplus is then passed through the \(\tanh\) function: \(\tanh(\operatorname{softplus}(x))\). The \(\tanh\) function squashes its input to the range \((-1, 1)\). Since \(\operatorname{softplus}(x)\) is always positive, \(\tanh(\operatorname{softplus}(x))\) will always be in the range \((0, 1)\).
  3. Scaling by Input: Finally, this squashed value is multiplied by the original input \(x\): \(\text{Mish}(x) = x \cdot \tanh(\operatorname{softplus}(x))\). This multiplication is key to Mish's unique properties.

Key Properties and Design Decisions

The combination yields several desirable characteristics:

  • Non-monotonicity: Unlike ReLU, Mish allows small negative inputs to result in small positive outputs. This "dip" in the negative region helps preserve information and avoid "dead neurons" that can occur when activations are strictly zero for negative inputs.
  • Smoothness: Mish is smooth everywhere, meaning its derivative is also continuous. This leads to smoother loss landscapes and potentially better optimization, as gradients don't suffer from abrupt changes.
  • Unbounded above: For large positive inputs, Mish grows linearly with \(x\) (since \(\tanh(\operatorname{softplus}(x)) \approx 1\)), preventing saturation in the positive range and allowing for large activation values.
  • Bounded below: Mish has a lower bound (around \(-0.31\)), which helps stabilize training by preventing activations from becoming too negative.

Design Decision: Why Mish over predecessors like Swish? While Swish (\(x \cdot \operatorname{sigmoid}(x)\)) also offers smoothness and a degree of non-monotonicity, Mish's use of \(\tanh(\operatorname{softplus}(x))\) instead of \(\operatorname{sigmoid}(x)\) provides a slightly smoother curve and a more pronounced non-monotonic dip, which empirically has shown to sometimes yield better performance in very deep architectures.

🔑 Key Property

Mish's smoothness ensures a continuous gradient flow, crucial for deep learning optimization. Its non-monotonic nature in the negative region is a form of "self-regularization," allowing some negative information to propagate, which helps prevent over-regularization and the "dying ReLU" problem.

Why It Works — The Math
▼

The Mish Function

The Mish activation function is defined as:

$$\text{Mish}(x) = x \cdot \tanh(\operatorname{softplus}(x))$$

where \(\operatorname{softplus}(x)\) is itself defined as:

$$\operatorname{softplus}(x) = \log(1 + e^x)$$

Substituting the definition of \(\operatorname{softplus}(x)\) into the Mish formula gives the complete expression:

$$\text{Mish}(x) = x \cdot \tanh(\log(1 + e^x))$$

This formulation highlights its dependence on the exponential and logarithmic functions, which contribute to its smoothness and unique shape.

The Derivative of Mish

For backpropagation, the derivative of Mish is essential. Let \(f(x) = \text{Mish}(x)\). Using the product rule, \(f'(x) = g'(x)h(x) + g(x)h'(x)\) where \(g(x) = x\) and \(h(x) = \tanh(\operatorname{softplus}(x))\).

We know \(g'(x) = 1\). For \(h'(x)\), we use the chain rule. Let \(s(x) = \operatorname{softplus}(x)\). Then \(h(x) = \tanh(s(x))\), so \(h'(x) = \operatorname{sech}^2(s(x)) \cdot s'(x)\).

The derivative of \(\operatorname{softplus}(x)\) is \(\operatorname{softplus}'(x) = \frac{e^x}{1+e^x} = \operatorname{sigmoid}(x)\). Therefore:

$$\text{Mish}'(x) = \tanh(\operatorname{softplus}(x)) + x \cdot \operatorname{sech}^2(\operatorname{softplus}(x)) \cdot \operatorname{sigmoid}(x)$$

This derivative is continuous and non-zero across its entire domain, which facilitates gradient flow and avoids the "dying ReLU" problem. The complexity of the derivative (involving multiple exponentials and hyperbolic functions) implies a higher computational cost per neuron compared to simpler activations like ReLU, but this is often offset by improved model performance.

⚠️ Computational Cost

While Mish offers strong empirical benefits, its computational cost per neuron is higher than ReLU or even Swish due to multiple calls to exp(), log(), and tanh(). This can be a factor in latency-critical applications or on hardware without optimized implementations for these transcendental functions.

Key Takeaways
▼

When to use Mish:

  • When training very deep neural networks, especially convolutional architectures (CNNs), where improved information flow and gradient propagation are critical.
  • When seeking marginal performance gains and better generalization over ReLU or Swish, particularly in tasks like image classification or object detection.
  • When the benefits of a smooth, non-monotonic activation (e.g., avoiding dead neurons, smoother loss landscape) outweigh the slight increase in computational cost.

When NOT to use:

  • In resource-constrained environments or latency-critical applications where the increased computational cost of transcendental functions (exp, log, tanh) is prohibitive.
  • For very shallow networks, where the benefits of Mish might be minimal and simpler, faster activations like ReLU would suffice.
  • If the model is already underfitting or struggling with vanishing/exploding gradients due to other architectural issues; Mish is an activation function, not a universal fix for all training problems.
💡 Rule of Thumb

Mish is a powerful activation that often provides a performance edge in complex deep learning models due to its unique combination of smoothness and non-monotonicity. It's a strong candidate for experimentation when traditional activations like ReLU or Swish are not delivering optimal results, especially when computational budget allows.

Code Trace (Python/PyTorch)
▼
import torch
import torch.nn as nn
# --- From scratch implementation ---
def softplus(x):
return torch.log(1 + torch.exp(x))
def mish_forward(x):
return x * torch.tanh(softplus(x))
# Example usage:
x_input = torch.tensor([-5.0, 0.0, 5.0], dtype=torch.float32)
mish_output = mish_forward(x_input)
print(f"Mish output for {x_input.numpy()}: {mish_output.numpy()}")
# Expected: [-0.0003, 0.0000, 4.9999] (approx)
# --- PyTorch's built-in Mish (recommended) ---
class MyMishModel(nn.Module):
def __init__(self):
super().__init__()
self.linear1 = nn.Linear(10, 20)
self.mish = nn.Mish() # Use nn.Mish() for optimized & stable version
self.linear2 = nn.Linear(20, 1)
def forward(self, x):
x = self.linear1(x)
x = self.mish(x)
x = self.linear2(x)
return x
model = MyMishModel()
dummy_input = torch.randn(1, 10)
output = model(dummy_input)
print(f"Model output shape: {output.shape}")
