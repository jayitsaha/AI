Off-Policy Evaluation: Inverse Propensity Scoring (IPS)

Evaluating a new policy using historical data from a different policy
Intermediate Reinforcement Learning Causal Inference O(N) per estimate
1
Understanding Off-Policy Evaluation (OPE) & IPS
▼

What is it? In real-world systems (e.g., recommendation engines, ad placement, clinical trials), we often have a large dataset of user interactions (state, action, reward) collected under an existing "behavior" policy. We want to evaluate a *new* "evaluation" policy without actually deploying it (which can be risky or costly). This is called Off-Policy Evaluation (OPE). Inverse Propensity Scoring (IPS) is a foundational OPE method that re-weights historical data points to make them look like they were sampled from the new policy.

Analogy: Imagine you're running a restaurant and have historical data on what customers ordered based on an old menu (behavior policy). You design a new menu (evaluation policy) and want to predict how much revenue it would generate, without actually printing and using it. You can't just sum up historical orders from the old menu, because the new menu might suggest different dishes! IPS says: "If a customer ordered 'Pasta' on the old menu, but the new menu would have made them *much less likely* to order Pasta, then that 'Pasta' order from history should count for less in your new revenue estimate. Conversely, if the new menu would have made them *more likely* to order Pasta, that historical order counts for more."

💡 If you remember one thing

IPS corrects for selection bias by weighting each historical observation \((s, a, r)\) by the ratio of probabilities: how likely the *new* policy \(\pi_e\) would have taken action \(a\) in state \(s\), divided by how likely the *behavior* policy \(\pi_b\) *actually* took action \(a\) in state \(s\). That is, \(w = \frac{\pi_e(a|s)}{\pi_b(a|s)}\).

2
How IPS Works Internally
▼

The Problem: Biased Estimation

If we simply average the rewards from historical data to estimate the value of a new policy \(\pi_e\), we get a biased estimate. The historical data \(D = \{(s_i, a_i, r_i)\}_{i=1}^N\) was generated by a different policy \(\pi_b\). The actions \(a_i\) observed in the data are not necessarily representative of the actions \(\pi_e\) would take in states \(s_i\). For example, if \(\pi_b\) never takes action A in state S, but \(\pi_e\) *always* takes action A in state S, we have no data to evaluate \(\pi_e\)'s performance in (S, A).

The Solution: Importance Weighting

IPS addresses this by applying an importance weight to each observed reward. For each historical tuple \((s_i, a_i, r_i)\), the weight \(w_i\) is given by the ratio of probabilities:

$$w_i = \frac{\pi_e(a_i|s_i)}{\pi_b(a_i|s_i)}$$

This weight \(w_i\) tells us how much more (or less) likely the observed action \(a_i\) was under the evaluation policy \(\pi_e\) compared to the behavior policy \(\pi_b\). The IPS estimator for the expected reward of \(\pi_e\) is then the weighted average of the rewards:

$$\hat{V}_{IPS}(\pi_e) = \frac{1}{N} \sum_{i=1}^N w_i r_i$$

Often, a self-normalized IPS estimator is used to reduce variance, especially when the number of samples is small or weights are highly variable:

$$\hat{V}_{SNIPS}(\pi_e) = \frac{\sum_{i=1}^N w_i r_i}{\sum_{i=1}^N w_i}$$

This ensures the weights effectively sum to 1, making it a true weighted average.

Design Decision: Why IPS and not direct modeling?

IPS is a model-free method. It doesn't require learning a model of the environment dynamics or rewards. It only needs to know the probabilities \(\pi_b(a|s)\) (which are usually logged with the data) and be able to compute \(\pi_e(a|s)\) for any given state-action pair. This simplicity is a major advantage. Other OPE methods, like Direct Method (DM), require learning a reward function \(\hat{R}(s,a)\) or a value function \(\hat{V}(s)\), which introduces model bias if the learned model is inaccurate.

🔑 Key Property

The IPS estimator is unbiased: \(\mathbb{E}[\hat{V}_{IPS}(\pi_e)] = V(\pi_e)\). This means that, given enough data, the estimate will converge to the true value of the evaluation policy. However, it can suffer from high variance, especially when the importance weights \(\pi_e(a|s) / \pi_b(a|s)\) are very large (i.e., \(\pi_b(a|s)\) is very small for actions that \(\pi_e\) frequently takes).

3
Why It Works — The Unbiasedness Proof
▼

Formal Definition of Expected Return

The true expected return of a policy \(\pi_e\) is defined as the expected reward when actions are sampled according to \(\pi_e\):

$$V(\pi_e) = \mathbb{E}_{s \sim \mathcal{D}, a \sim \pi_e(\cdot|s)}[R(s,a)] = \sum_s P(s) \sum_a \pi_e(a|s) R(s,a)$$

where \(P(s)\) is the probability of observing state \(s\).

Unbiasedness Proof Sketch

We want to show that \(\mathbb{E}_{D}[\hat{V}_{IPS}(\pi_e)] = V(\pi_e)\). Let's consider a single sample \((s,a,r)\) from the historical dataset \(D\), which was generated by \(\pi_b\). The expectation over this sample is:

$$\mathbb{E}_{s \sim \mathcal{D}, a \sim \pi_b(\cdot|s)}\left[\frac{\pi_e(a|s)}{\pi_b(a|s)} R(s,a)\right] = \sum_s P(s) \sum_a \pi_b(a|s) \left[\frac{\pi_e(a|s)}{\pi_b(a|s)} R(s,a)\right]$$

Notice that \(\pi_b(a|s)\) in the numerator and denominator cancel out:

$$ = \sum_s P(s) \sum_a \pi_e(a|s) R(s,a) = V(\pi_e)$$

Since the expectation for a single sample is \(V(\pi_e)\), and \(\hat{V}_{IPS}(\pi_e)\) is an average of \(N\) such independent samples, its expectation is also \(V(\pi_e)\) by linearity of expectation. This proves the unbiasedness of IPS.

Variance of IPS

While unbiased, the variance of IPS can be problematic. The variance of a single importance-weighted reward is:

$$\operatorname{Var}\left(\frac{\pi_e(a|s)}{\pi_b(a|s)} R(s,a)\right) = \mathbb{E}\left[\left(\frac{\pi_e(a|s)}{\pi_b(a|s)}\right)^2 R(s,a)^2\right] - V(\pi_e)^2$$

This term can be very large if \(\pi_b(a|s)\) is small for some \(a\) where \(\pi_e(a|s)\) is large, leading to huge weights. These large weights can dominate the sum, making the estimate unstable. The effective sample size (ESS) is a useful metric: \(\text{ESS} = \left(\sum w_i\right)^2 / \sum w_i^2\). A low ESS indicates high variance.

⚠️ Practical Considerations

IPS requires accurate logging of \(\pi_b(a|s)\). If the logged behavior probabilities are incorrect, the IPS estimator will be biased. Additionally, if an action \(a\) taken in state \(s\) has \(\pi_b(a|s) = 0\) but \(\pi_e(a|s) > 0\), the weight becomes infinite, leading to an undefined estimate. This is known as the "support mismatch" problem.

Key Takeaways
▼

When to use IPS:

  • You need to evaluate a new policy \(\pi_e\) without deploying it, using historical data from \(\pi_b\).
  • The behavior policy \(\pi_b(a|s)\) is known and logged accurately for each observation.
  • The support condition holds: for any \((s,a)\) where \(\pi_e(a|s) > 0\), it must be that \(\pi_b(a|s) > 0\).
  • When model-free methods are preferred due to complexity or risk of model bias.

When NOT to use / be careful:

  • When \(\pi_b(a|s)\) is very small for actions \(\pi_e\) frequently takes (high variance, low ESS).
  • If \(\pi_b(a|s) = 0\) for some \((s,a)\) where \(\pi_e(a|s) > 0\) (support mismatch) — IPS becomes undefined.
  • When the state space is very large and the data is sparse, making \(\pi_b(a|s)\) estimates unreliable.
  • For long-horizon problems (e.g., full trajectories in RL), simple IPS can be extended to handle sequences of actions, but variance issues compound.
💡 Beyond Simple IPS

IPS is a building block. More advanced OPE methods, like Doubly Robust (DR) estimators, combine IPS with a model-based approach (e.g., a learned reward model) to achieve both unbiasedness and lower variance. Marginalized Importance Sampling (MIS) and Direct Method (DM) are other common OPE techniques, each with their own trade-offs between bias and variance.

import numpy as np
# Historical data (s, a, r, pi_b(a|s))
# 'New': 0, 'Returning': 1; 'Ad_A': 0, 'Ad_B': 1
data = [
{'s': 0, 'a': 0, 'r': 1, 'pi_b_a_s': 0.8},
{'s': 0, 'a': 0, 'r': 0, 'pi_b_a_s': 0.8},
{'s': 1, 'a': 1, 'r': 1, 'pi_b_a_s': 0.7},
{'s': 0, 'a': 1, 'r': 0, 'pi_b_a_s': 0.2},
{'s': 1, 'a': 0, 'r': 0, 'pi_b_a_s': 0.3},
{'s': 0, 'a': 0, 'r': 1, 'pi_b_a_s': 0.8},
{'s': 1, 'a': 1, 'r': 0, 'pi_b_a_s': 0.7},
{'s': 0, 'a': 1, 'r': 1, 'pi_b_a_s': 0.2},
{'s': 1, 'a': 0, 'r': 1, 'pi_b_a_s': 0.3},
{'s': 1, 'a': 1, 'r': 0, 'pi_b_a_s': 0.7},
]
# Evaluation policy (pi_e(a|s))
# new_policy_pref_B_new_user: prob of Ad_B for New users
def get_pi_e(s, a, new_policy_pref_B_new_user):
if s == 0: # New User
if a == 0: return 1 - new_policy_pref_B_new_user # Ad_A
else: return new_policy_pref_B_new_user # Ad_B
else: # Returning User
if a == 0: return 0.5 # Ad_A (fixed)
else: return 0.5 # Ad_B (fixed)
# IPS Estimation function
def estimate_ips(data, new_policy_pref_B_new_user):
weighted_rewards = []
ips_weights = []
for record in data:
pi_e_a_s = get_pi_e(record['s'], record['a'], new_policy_pref_B_new_user)
if record['pi_b_a_s'] == 0: # Avoid division by zero (support mismatch)
weight = 0 # Or handle as error/NaN if pi_e_a_s > 0
else:
weight = pi_e_a_s / record['pi_b_a_s']
ips_weights.append(weight)
weighted_rewards.append(weight * record['r'])
sum_weighted_rewards = np.sum(weighted_rewards)
sum_ips_weights = np.sum(ips_weights)
# Self-normalized IPS estimator
if sum_ips_weights == 0:
estimated_value = 0 # Or NaN if all weights are zero
else:
estimated_value = sum_weighted_rewards / sum_ips_weights
# Effective Sample Size (ESS)
squared_weights = np.array(ips_weights)**2
if np.sum(squared_weights) == 0:
ess = 0
else:
ess = sum_ips_weights**2 / np.sum(squared_weights)
return estimated_value, ess, ips_weights, weighted_rewards
