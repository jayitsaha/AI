Understanding Circuits & Superposition
▼

What is it? Mechanistic Interpretability (MI) is the study of reverse-engineering neural networks to understand the specific algorithms and computations they perform. Instead of just observing input-output behavior, MI aims to trace the "circuits" — the specific subnetworks of neurons and weights — that implement particular functions. A key challenge and phenomenon in this field is superposition.

Superposition: This refers to the network's tendency to represent more features than it has neurons (or dimensions) in a given layer. When faced with a bottleneck, the network compresses these features, often making individual neurons "polysemantic" — meaning a single neuron will activate for multiple, seemingly unrelated input features. This is an efficiency trade-off, exploiting the sparsity of features.

Analogy: Imagine a master chef with only two pots (neurons) but needing to cook four distinct dishes (features). If the dishes are rarely needed at the same time (sparse), the chef might use Pot 1 for Dish A and Dish C, and Pot 2 for Dish B and Dish D. Each pot is "polysemantic," handling two dishes. If Dish A and Dish C are needed simultaneously, there's interference. MI is trying to figure out exactly which dishes each pot is assigned to, and how the chef manages the schedule.

💡 If you remember one thing

Superposition is a form of efficient compression where a network encodes many sparse features into fewer neurons. This leads to polysemanticity, where individual neurons respond to multiple distinct input features, making them harder to interpret directly.

2
How Superposition Happens
▼

Feature Representation & Neuron Activation

In a neural network, input features (e.g., "cat ear detector," "dog nose detector") are typically represented as high-dimensional vectors. A hidden layer neuron receives these features through a set of weights. The neuron's activation is a weighted sum of its inputs, followed by a non-linearity:

$$h_j = \sigma\left(\sum_{k=1}^D w_{jk} f_k + b_j\right)$$

where \(f_k\) is the activation of input feature \(k\), \(w_{jk}\) is the weight connecting feature \(k\) to neuron \(j\), \(b_j\) is the bias, and \(\sigma\) is an activation function (e.g., ReLU). Each neuron essentially learns a "preferred direction" or combination of input features it responds to.

The Pressure for Compression

Modern neural networks, especially large language models, learn an enormous number of latent features. However, the number of neurons in a hidden layer is often much smaller than the total number of features the network might want to represent. This creates a bottleneck. If these features are sparse — meaning only a few are active at any given time — the network can efficiently "multiplex" them onto shared neurons.

For example, if feature 'A' and feature 'B' are never active simultaneously, a single neuron can learn to respond to both. Its weights would align with both 'A' and 'B'. If 'A' is active, the neuron fires. If 'B' is active, the neuron fires. If both were active, their signals would interfere, leading to a suboptimal representation.

Design Decision: Why Superposition?

Superposition isn't explicitly designed; it emerges as an optimal compression strategy under certain conditions:

  1. Limited Capacity: The number of neurons \(N\) is less than the number of features \(D\).
  2. Sparsity: Most features are inactive most of the time. This means co-activation of features assigned to the same neuron is rare, minimizing interference.
  3. Optimization Pressure: The network is incentivized to minimize loss and maximize information throughput with limited resources. Superposition is a way to achieve this.

This efficiency comes at the cost of interpretability: a polysemantic neuron is harder to assign a single, clear meaning to.

🔑 Key Property

Superposition is fundamentally a trade-off between network capacity (number of neurons) and the interpretability of individual neurons. Fewer neurons force more polysemanticity; more neurons allow for greater disentanglement.

3
Why It Works — Mathematical Intuition
▼

The Linear Model of Feature Encoding

Consider a simple linear layer where input features \(f \in \mathbb{R}^D\) are mapped to hidden neuron activations \(h \in \mathbb{R}^N\) by a weight matrix \(W \in \mathbb{R}^{N \times D}\) and a bias \(b \in \mathbb{R}^N\):

$$h = Wf + b$$

If we simplify to \(b=0\) and consider a single input feature \(f_k\) (represented as a one-hot vector, i.e., \(f\) has a 1 at index \(k\) and 0 elsewhere), then the activation of neuron \(j\) is simply \(h_j = w_{jk}\) (the \(j\)-th row of \(W\) dotted with \(f_k\)).

The Conditions for Superposition

Superposition arises when \(N < D\). In this scenario, the network must compress the \(D\) input features into an \(N\)-dimensional space. If the features are sparse, meaning that for most inputs, only a few \(f_k\) are non-zero, then the network can learn to encode multiple features into a single neuron. For example, if feature \(f_A\) and \(f_B\) are rarely co-active:

$$\begin{aligned} \text{When } f_A \text{ is active:} & \quad h_j \approx w_{jA} \\ \text{When } f_B \text{ is active:} & \quad h_j \approx w_{jB} \end{aligned}$$

A single neuron \(j\) can have significant weights \(w_{jA}\) and \(w_{jB}\), effectively responding to both features. The "cost" of this compression (interference) is low if \(f_A\) and \(f_B\) are rarely present together in the input.

De-superposition with Sparse Autoencoders (SAEs)

Mechanistic interpretability often uses tools like Sparse Autoencoders (SAEs) to "de-superpose" features. An SAE tries to learn a higher-dimensional, sparse representation of the hidden layer activations. It consists of an encoder \(W_E \in \mathbb{R}^{D_{SAE} \times N}\) and a decoder \(W_D \in \mathbb{R}^{N \times D_{SAE}}\), where \(D_{SAE} > N\). The loss function typically includes a reconstruction term and an L1 sparsity penalty:

$$\mathcal{L}(h, \hat{h}) = \|h - \hat{h}\|^2 + \lambda \sum_{i=1}^{D_{SAE}} |\text{SAE_features}_i|$$

The L1 penalty encourages the SAE to activate only a few of its \(D_{SAE}\) features at a time, pushing it towards a disentangled, interpretable basis where each SAE feature ideally corresponds to a single underlying concept, even if the original \(N\) neurons were polysemantic.

⚠️ Common Pitfall

Assuming one neuron = one concept is a common trap in interpreting neural networks. Due to superposition, a single neuron is often polysemantic, responding to a mixture of features. This is especially true in layers with low capacity relative to the number of concepts the network learns.

Key Takeaways
▼

When to expect superposition:

  • In layers where the number of neurons is significantly less than the number of unique features the network implicitly learns (i.e., \(N \ll D\)).
  • When features are sparse and rarely co-active. This allows the network to "time-share" neurons without much interference.
  • In intermediate layers of large, overparameterized models where efficiency pressures are high.

Implications for interpretability:

  • Polysemanticity: Individual neurons often respond to multiple, seemingly unrelated features. This makes simple "neuron-to-concept" mapping difficult.
  • Circuits are complex: Understanding how a high-level concept is computed requires tracing a "circuit" across multiple polysemantic neurons, rather than finding a single "concept neuron."
  • Need for de-superposition: Tools like Sparse Autoencoders are critical to find a more disentangled basis, making features more interpretable.
💡 The Grand Challenge

Mechanistic interpretability aims to reverse-engineer the "black box." Superposition shows that the internal representations are not always human-interpretable at the neuron level, forcing us to look for higher-level "circuits" or to apply techniques that disentangle these compressed features.

import torch
import torch.nn as nn
# Assume D input features, N hidden neurons
D_INPUT_FEATURES = 128
N_HIDDEN_NEURONS = 32 # Example: N < D, leading to superposition
class SimpleLayer(nn.Module):
def __init__(self, in_features, out_features):
super().__init__()
self.linear = nn.Linear(in_features, out_features)
self.relu = nn.ReLU()
def forward(self, x):
# x: (batch_size, D_INPUT_FEATURES) - raw feature activations
hidden_activations = self.linear(x) # (batch_size, N_HIDDEN_NEURONS)
return self.relu(hidden_activations)
# Initialize layer (weights W are self.linear.weight)
layer = SimpleLayer(D_INPUT_FEATURES, N_HIDDEN_NEURONS)
# To analyze superposition for a specific neuron (e.g., neuron 0):
neuron_idx = 0
# Get the weights connecting all input features to this neuron
weights_to_neuron = layer.linear.weight[neuron_idx, :] # (D_INPUT_FEATURES,)
# Identify which input features strongly activate this neuron
# (e.g., by thresholding or finding top-k values)
strong_features = (weights_to_neuron > 0.5).nonzero(as_tuple=True)[0]
print(f"Neuron {neuron_idx} responds strongly to features: {strong_features}")
# If len(strong_features) > 1, this neuron is polysemantic.
# Conceptual SAE for de-superposition
class SparseAutoencoder(nn.Module):
def __init__(self, n_neurons, d_sae_features):
super().__init__()
self.encoder = nn.Linear(n_neurons, d_sae_features)
self.decoder = nn.Linear(d_sae_features, n_neurons)
self.relu = nn.ReLU()
def forward(self, hidden_acts):
sae_features = self.relu(self.encoder(hidden_acts)) # (batch, D_SAE_FEATURES)
reconstruction = self.decoder(sae_features) # (batch, N_HIDDEN_NEURONS)
return sae_features, reconstruction
