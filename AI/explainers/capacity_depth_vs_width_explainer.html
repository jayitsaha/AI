Understanding Capacity: Depth vs. Width
▼

What is it? "Capacity" is a rough measure of how complicated a function a neural network can represent — how many distinct wiggles, bends, and decision boundaries it can carve into its input space. A network has two knobs to grow capacity: make each layer wider (more neurons per layer) or make the network deeper (more layers stacked in sequence). These two knobs are not interchangeable: depth buys capacity multiplicatively, width buys it additively.

Analogy: Think of folding a sheet of paper. Punch a few holes through it, then unfold — you get a repeating, symmetric pattern of holes, way more than the number of holes you punched. Each extra fold (depth) multiplies the pattern that later folds punch through; adding more hole-punches at the same fold (width) only adds holes one at a time. A deep ReLU network is literally doing this: each layer folds the input space, and later layers stamp the same decision boundary across every fold simultaneously.

💡 If you remember one thing

The number of linear regions a ReLU network can carve grows polynomially with width but exponentially with depth (for fixed total neurons). Depth is what makes capacity cheap.

2
How Depth Multiplies, Width Adds
▼

ReLU Networks Are Piecewise-Linear Functions

A feedforward network with ReLU activations computes a continuous piecewise-linear (PWL) function of its input. Each hidden unit's pre-activation \(z = w^\top x + b\) defines a hyperplane; the ReLU "bends" the function along that hyperplane (\(\max(0,z)\)). The full network partitions the input space \(\mathbb{R}^d\) into convex-ish cells — linear regions — inside which the network is exactly affine. Capacity ≈ how finely this partition can be carved.

Width Alone: An Arrangement of Hyperplanes

A single hidden layer with \(n\) units places \(n\) hyperplanes through the input space. Classic hyperplane-arrangement counting gives an upper bound on regions:

$$R_{\text{shallow}}(n,d) \le \sum_{j=0}^{d}\binom{n}{j}$$

For fixed input dimension \(d\), this is a polynomial in \(n\) of degree \(d\) — quadratic for \(d=2\). Adding a width-\(n\) unit adds at most \(n\) new boundary crossings; it does not multiply what's already there.

Depth: Folding, Not Adding

Now compose layers. Layer 2's hyperplanes are computed on top of layer 1's piecewise-linear output — layer 1 has already folded the input space onto itself several times (like origami), and every hyperplane layer 2 draws gets replicated across every fold simultaneously. This is the "folding" argument behind Montúfar et al.'s (2014) depth-separation result: composing \(L\) layers of width \(n\) multiplies region counts across layers rather than summing them, giving a bound that is exponential in \(L\) instead of polynomial in \(n\).

Design Decision: Why Does This Matter for Real Networks?

If your target function is compositional (edges → textures → parts → objects; characters → words → sentences), a deep network can represent it with a number of neurons that scales polynomially in the desired resolution, while a shallow network needs exponentially many neurons to match it — because a shallow net has to re-derive every combination "by hand" with fresh hyperplanes instead of reusing folds.

🔑 Key Property

Width adds regions linearly/polynomially (an arrangement of hyperplanes). Depth composes piecewise-linear maps, so regions multiply layer-over-layer — the same mechanism that makes function composition \(f_L\circ\cdots\circ f_1\) fundamentally more expressive than a single wide \(f\).

3
Why It Works — The Math
▼

The Montúfar Lower Bound

For a ReLU network with input dimension \(d\), \(L\) hidden layers, and width \(n \ge d\) per layer, the number of linear regions is at least:

$$R_{\text{deep}}(n,d,L) \;\ge\; \left\lfloor \frac{n}{d} \right\rfloor^{\,d(L-1)} \sum_{j=0}^{d}\binom{n}{j}$$

Compare the exponents: the shallow upper bound \(\sum_{j=0}^d \binom{n}{j} = O(n^d)\) is polynomial in the width \(n\). The deep lower bound has a factor \(\lfloor n/d\rfloor^{d(L-1)}\) — the depth \(L\) sits in the exponent. Holding the total neuron budget \(N = nL\) roughly fixed, region count under depth scaling grows exponentially in \(L\) while region count under width-only scaling grows only polynomially in \(N\).

Universal Approximation Doesn't Contradict This

The classical universal approximation theorem (Cybenko 1989; Hornik 1991) says a single hidden layer, given enough width, can approximate any continuous function on a compact domain to arbitrary precision. Depth-separation results don't overturn this — they sharpen it: "enough width" can mean exponentially many neurons for functions that a deep network represents with a polynomial-size architecture (Telgarsky 2016; Eldan & Shamir 2016 exhibit explicit functions needing exponentially wide shallow nets). Universal approximation guarantees existence; depth is what makes the "enough" tractable.

⚠️ Common Misconception

More linear regions is not automatically "better." Region count is an upper bound on raw expressivity, not on generalization or trainability. Many regions may never be touched by real data, may be vanishingly thin, or the extra expressivity may just as easily overfit noise. Very deep narrow networks are also harder to optimize (vanishing/exploding gradients) even when they are more expressive on paper — which is exactly why architectures like ResNets pair depth with residual connections.

Key Takeaways
▼

Prefer depth when:

  • The target function is compositional / hierarchical (vision, language, structured signals)
  • You need parameter-efficient capacity — fewer weights for the same expressivity
  • You can stabilize training (residual connections, normalization) to tame optimization difficulty

Prefer width when:

  • You need a smoother, better-conditioned loss landscape and easier optimization (wide networks approach the NTK / "lazy training" regime)
  • Gradient flow is a bottleneck and you want to avoid vanishing/exploding gradients from many compositions
  • The target function isn't naturally hierarchical, or you need low-latency, highly parallel inference (shallow-wide nets parallelize better per layer)
💡 In Practice

Modern architectures rarely pick a side — they combine both: deep stacks of residual blocks (depth for compositional capacity) each internally reasonably wide (width for optimization stability and per-layer capacity), plus normalization layers that make the depth-induced folding trainable instead of just theoretically expressive.

Code Trace — Counting Linear Regions
▼
import numpy as np
# Build a ReLU MLP: input dim d -> L hidden layers of width n -> 1 output
def build_mlp(d, n, L, seed=0):
rng = np.random.default_rng(seed)
dims = [d] + [n] * L + [1]
layers = []
for i in range(len(dims) - 1):
fan_in = dims[i]
W = rng.normal(0, np.sqrt(2 / fan_in), size=(dims[i+1], dims[i]))
b = rng.normal(0, 0.3, size=dims[i+1])
layers.append((W, b))
return layers
# Forward pass that also returns the ReLU sign-pattern (region fingerprint)
def forward_with_pattern(x, layers):
a, pattern = x, []
for i, (W, b) in enumerate(layers):
z = W @ a + b
is_last = (i == len(layers) - 1)
if not is_last:
pattern.extend((z > 0).astype(int).tolist()) # which units "fired"
a = np.maximum(0, z) # ReLU
else:
a = z # linear output layer
return a[0], tuple(pattern)
# Approximate the number of linear regions by dense grid sampling:
# every distinct sign-pattern observed = one distinct affine piece.
def count_regions(layers, grid=140, lo=-1, hi=1):
xs = np.linspace(lo, hi, grid)
seen = set()
for x1 in xs:
for x2 in xs:
_, pattern = forward_with_pattern(np.array([x1, x2]), layers)
seen.add(pattern)
return len(seen)
# Same neuron budget (12 units), different shape:
shallow = build_mlp(d=2, n=12, L=1) # 1 layer x 12 units
deep = build_mlp(d=2, n=3, L=4) # 4 layers x 3 units
print("shallow regions:", count_regions(shallow))
print("deep regions: ", count_regions(deep)) # typically far more
