Understanding Web Search Ranking
▼

What is it? Web search ranking is the system that turns a few typed words into an ordered list of the ten most useful pages out of tens of billions of candidates, in well under 200 milliseconds. It is not one algorithm — it is a funnel of increasingly expensive, increasingly accurate stages, each one throwing away documents the previous stage could not afford to evaluate.

Analogy: Think of hiring for a job with a million applicants. You would not have the CEO read every resume. First an applicant-tracking system keyword-filters to a few thousand (retrieval). Then a recruiter skims those for obvious fit in a minute each (a cheap first-pass ranker). Only the shortlist gets a deep interview considering experience, references, and culture fit together (an expensive learned ranker). Search engines do the same thing to web pages: cheap filters first, expensive judgment last, applied only to the survivors.

💡 If you remember one thing

Ranking is a cascade: an inverted-index retrieval stage narrows billions of pages to thousands; a cheap lexical ranker (BM25) narrows thousands to hundreds; an expensive learned ranker (LambdaMART or a neural net) combines relevance, freshness, authority, and click signals to pick the final order, optimized directly against a ranking-quality metric called NDCG.

2
How The Pipeline Works Internally
▼

Stage 0 — Query Understanding

The raw query string is lowercased, tokenized, stripped of stopwords, and sometimes expanded with synonyms or spelling corrections. "best running shoes" becomes the term set {best, running, shoes} that the rest of the pipeline operates on.

Stage 1 — Retrieval via the Inverted Index

An inverted index maps every term to a sorted "posting list" of document IDs that contain it. Instead of scanning billions of pages, the engine looks up three short lists (one per query term) and intersects or unions them — this is what takes the candidate pool from tens of billions down to tens of millions, then to a filtered recall set of tens of thousands after removing non-matching language, spam, and duplicate pages.

Stage 2 — L1: A Cheap Lexical Ranker (BM25)

Scoring tens of thousands of candidates with a heavy machine-learned model would be far too slow. Instead, a fast, closed-form formula — BM25 — scores every candidate using only term frequency, document length, and how rare each term is across the corpus. It is cheap enough to run on the entire recall set, but it only sees words, not quality: a page that stuffs the query terms can score deceptively high even if it is spam.

Stage 3 — Feature Extraction & L2: A Learned Ranker

Only the L1 survivors (a few hundred documents) are worth the expense of extracting rich features — BM25-based textual relevance, freshness/recency, authority signals like PageRank, and historical click/dwell-time signals — and running them through a learned model such as LambdaMART (gradient-boosted trees trained with a pairwise/listwise ranking loss) or a neural cross-encoder. This L2 ranker is what actually decides the final order.

Stage 4 — Evaluation with NDCG

Ranking quality is judged with NDCG (Normalized Discounted Cumulative Gain): human raters assign relevance grades to query-document pairs, and NDCG rewards rankings that place highly relevant results near the top, with a logarithmic discount for lower positions. LambdaMART is trained to directly optimize NDCG (or a smooth proxy for it) rather than a generic classification loss.

🔑 Key Property

Every stage exists purely as a cost/accuracy trade-off: the cheaper the stage, the more documents it must handle, and the more mistakes it is allowed to make — as long as the true best answers survive into the next, more discerning stage.

3
Why It Works — The Math
▼

BM25: The L1 Ranking Function

For query \(Q\) with terms \(q_1 \ldots q_n\) and document \(D\) of length \(|D|\), BM25 sums a per-term contribution:

$$\text{BM25}(D,Q) = \sum_{i=1}^{n} \text{IDF}(q_i)\cdot \frac{f(q_i,D)\,(k_1+1)}{f(q_i,D) + k_1\left(1 - b + b\dfrac{|D|}{\text{avgdl}}\right)}$$

where \(f(q_i,D)\) is the term frequency, \(\text{avgdl}\) is the average document length in the corpus, \(k_1\) controls term-frequency saturation (diminishing returns from repeating a word), and \(b\) controls how much document length is penalized. The inverse document frequency term downweights common words:

$$\text{IDF}(q_i) = \ln\!\left(\frac{N - n(q_i) + 0.5}{n(q_i) + 0.5} + 1\right)$$

with \(N\) documents in the corpus and \(n(q_i)\) documents containing \(q_i\). BM25 is entirely lexical — it has no notion of authority, freshness, or user behavior, which is exactly why it is only trusted for L1.

NDCG: Scoring The Final Ranking

Given true relevance grades \(rel_i\) for the documents placed at positions \(i = 1 \ldots k\), the discounted cumulative gain is:

$$\text{DCG}@k = \sum_{i=1}^{k} \frac{rel_i}{\log_2(i+1)}\qquad \text{NDCG}@k = \frac{\text{DCG}@k}{\text{IDCG}@k}$$

\(\text{IDCG}@k\) is the DCG of the ideal ranking (documents sorted by true relevance). NDCG is 1.0 for a perfect ranking and shrinks whenever highly relevant documents are pushed down — the \(\log_2(i+1)\) discount means being wrong near the top hurts far more than being wrong at position 9.

LambdaMART: Optimizing NDCG Directly

NDCG is not differentiable (sorting is discontinuous), so LambdaMART sidesteps this with lambda gradients: for every pair of documents \((i,j)\) where \(i\) is more relevant than \(j\) but ranked below it, it computes a pseudo-gradient proportional to how much swapping them would change NDCG, \(|\Delta\text{NDCG}_{ij}|\), and fits gradient-boosted regression trees to reduce those violations.

⚠️ Common Pitfall

A pure L1/BM25 system is trivially gameable by keyword stuffing — repeat the query terms enough and BM25 score climbs, regardless of actual quality. This is precisely why production ranking never ships on lexical scores alone: the L2 stage folds in authority and behavioral signals that are far harder to fake.

Key Takeaways
▼

Why a funnel instead of one big model:

  • Latency budget is fixed (~100–200ms) but the candidate pool spans billions of pages — you cannot run an expensive model on all of them.
  • Each stage's job is only to keep true positives alive for the next stage, not to get the final order right.
  • Cost grows with model complexity, so complexity is applied only to the shrinking survivor set.

What makes L2 necessary, not optional:

  • Lexical signals (BM25) are gameable by keyword stuffing and blind to page quality.
  • Authority (PageRank-style link analysis) and click/dwell signals correlate with real-world trust and usefulness in ways raw text cannot.
  • Freshness matters differently per query type (news vs. reference content) and can only be weighted correctly by a learned model.
💡 Hierarchy

Retrieval (recall, must not miss) → L1 / BM25 (cheap precision, thousands scored) → L2 / LambdaMART or neural (expensive precision, hundreds scored, features fused) → NDCG is the yardstick that closes the loop and drives what L2 is trained to optimize.

# Web search ranking pipeline (simplified)
def search(query, index, docs):
# 1. Parse and normalize query
terms = tokenize(query.lower())
terms = remove_stopwords(terms)
# 2. Inverted index lookup
postings = [index[t] for t in terms]
# 3. Candidate generation (recall set)
candidates = intersect_or_union(postings)
candidates = apply_filters(candidates, lang="en", safe=True)
# 4. L1: cheap lexical ranker (BM25) over all candidates
l1_scores = {d: bm25(query, d, avgdl, k1=1.5, b=0.75) for d in candidates}
top_k = top_n(l1_scores, k=200)
# 5. Feature extraction for L2 (top_k docs only -- expensive features)
features = {d: extract_features(d, query) for d in top_k}
# relevance, freshness, authority/PageRank, CTR, dwell time, ...
# 6. L2: learned ranker (LambdaMART / neural net)
l2_scores = {d: model.predict(features[d]) for d in top_k}
ranked = sort_by_score(l2_scores, descending=True)
# 7. Offline eval: NDCG against human relevance judgments
ndcg = compute_ndcg(ranked, judgments, k=10)
# 8. Return top 10 for the results page
return ranked[:10]
