Understanding User-Based CF
▼

What is it? User-based collaborative filtering (user-based CF) recommends items to a person by first finding other people with similar taste, then suggesting what those similar people liked. It never looks at what a movie is about — no genres, no actors, no plot summaries. It only looks at the pattern of who rated what.

Analogy: Imagine asking a friend for a movie recommendation. You don't pick a random friend — you pick the friend whose taste has matched yours in the past. If you and that friend both loved the same five movies, you'll probably trust their opinion on a sixth movie you haven't seen. User-based CF automates this at scale: it finds your "taste twins" among thousands of users and lets them vote on what you should watch next.

💡 If you remember one thing

User-based CF has three steps: (1) measure how similar every other user is to the target user using their overlapping ratings, (2) keep only the top-\(k\) most similar "neighbors," and (3) predict a missing rating as a similarity-weighted average of what those neighbors rated that item.

2
How It Works Internally
▼

The Rating Matrix

Everything starts with a sparse user–item matrix \(R\), where \(R_{u,i}\) is the rating user \(u\) gave item \(i\) (or missing if they haven't rated it). For a target user \(a\), the goal is to fill in the blanks in row \(a\) — and then recommend the highest-predicted blanks.

Step 1 — Similarity

For every other user \(u\), compute a similarity score \(sim(a,u)\) using only the items both \(a\) and \(u\) have rated (their co-rated set). Cosine similarity and Pearson correlation are the two classic choices — Pearson additionally subtracts each user's mean rating first, which corrects for users who are simply "generous raters" vs. "harsh raters."

Step 2 — Neighborhood Selection

Sort all users by \(sim(a,u)\) and keep the top-\(k\) (a hyperparameter, typically 10–50 in production, small here for clarity). Everyone outside this neighborhood is discarded — a distant, dissimilar user shouldn't get a vote just because they happened to rate the missing item.

Step 3 — Weighted Prediction

For a missing item \(i\), predict \(a\)'s rating as the neighbors' ratings for \(i\), weighted by how similar each neighbor is to \(a\). A neighbor with similarity 0.99 counts far more than one with similarity 0.6. This is the key design decision: a plain average would treat every neighbor's opinion as equally trustworthy, which throws away exactly the signal similarity was computed to capture.

🔑 Key Property

User-based CF is a memory-based method — there is no trained model, no parameters, no gradient descent. Predictions are computed on-the-fly directly from the raw rating matrix at query time, which makes it simple and fully interpretable, but expensive to serve at scale.

3
Why It Works — The Math
▼

Cosine Similarity

Treating each user's ratings as a vector, cosine similarity measures the angle between two users' rating vectors over their commonly-rated items \(I_{a,u}\):

$$sim(a,u) = \frac{\sum_{i \in I_{a,u}} r_{a,i}\, r_{u,i}}{\sqrt{\sum_{i \in I_{a,u}} r_{a,i}^2}\;\sqrt{\sum_{i \in I_{a,u}} r_{u,i}^2}}$$

This ranges from \(-1\) to \(1\) (or \(0\) to \(1\) for strictly positive ratings) — a score near 1 means the two users tend to rate the same items similarly high or similarly low.

Weighted-Average Prediction

Let \(N_k(a)\) be the top-\(k\) neighbors of \(a\). The predicted rating for item \(i\) is a similarity-weighted average of the neighbors' actual ratings:

$$\hat{r}_{a,i} = \frac{\sum_{u \in N_k(a)} sim(a,u)\cdot r_{u,i}}{\sum_{u \in N_k(a)} |sim(a,u)|}$$

Dividing by the sum of absolute similarities re-normalizes the weights so the prediction stays on the original 1–5 rating scale regardless of how many neighbors contributed or how strong their similarities are.

Mean-Centering (a common refinement)

A more robust variant subtracts each neighbor's average rating \(\bar{r}_u\) before weighting, then adds back the target's average \(\bar{r}_a\):

$$\hat{r}_{a,i} = \bar{r}_a + \frac{\sum_{u \in N_k(a)} sim(a,u)\cdot (r_{u,i} - \bar{r}_u)}{\sum_{u \in N_k(a)} |sim(a,u)|}$$

This corrects for rating scale bias — a neighbor who rates everything 4–5 stars contributes their relative enthusiasm for item \(i\), not their absolute generosity. The interactive walkthrough below uses the simpler un-centered formula for clarity, but production systems almost always mean-center.

⚠️ Common Pitfall

Cosine similarity computed on raw ratings is undefined (division by zero) when two users share no co-rated items — the classic cold-start and sparsity problem. With millions of items and few ratings per user, most user pairs have near-empty overlap, which is exactly why production systems often switch to item-based CF or matrix factorization instead.

Key Takeaways
▼

When to use user-based CF:

  • Small-to-medium user bases where user-user similarity can be recomputed cheaply
  • Domains where "people like you" is a genuinely meaningful and explainable recommendation story
  • Cold-start items (a brand-new movie can still be recommended the moment a handful of similar users rate it — no retraining needed)

When NOT to use:

  • Very large, sparse catalogs — the user-user similarity matrix is \(O(n^2)\) in the number of users and becomes unusable at web scale
  • Cold-start users — a brand-new user with few ratings has no reliable neighbors yet
  • When item catalogs change faster than users rate — item-based CF is far more stable since item-item similarity drifts slowly
💡 Hierarchy

User-based CF and item-based CF are both memory-based neighborhood methods; both are special cases of the broader collaborative filtering family, which also includes model-based approaches like matrix factorization (SVD, ALS) and neural CF. Amazon's classic 2003 paper popularized item-based CF specifically because it scales better than the user-based approach shown here.

Code Trace

import numpy as np
# ratings[u][i] = rating of user u for item i, 0 = unrated
ratings = np.array([
[5, 3, 0, 5, 2, 0, 0], # Alice (target)
[4, 3, 2, 5, 1, 4, 5], # Bob
[1, 5, 5, 1, 5, 5, 1], # Carol
[5, 2, 1, 4, 1, 2, 4], # Dave
[2, 5, 4, 2, 4, 4, 2], # Eve
[4, 4, 3, 4, 3, 3, 3], # Frank
])
def cosine_sim(a, b):
mask = (a > 0) & (b > 0) # co-rated items only
if mask.sum() == 0: return 0.0
a, b = a[mask], b[mask]
return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))
target = 0
sims = [(u, cosine_sim(ratings[target], ratings[u]))
for u in range(len(ratings)) if u != target]
sims.sort(key=lambda t: -t[1])
neighbors = sims[:3] # top-k neighborhood
def predict(item_idx, neighbors):
num = sum(s * ratings[u][item_idx] for u, s in neighbors)
den = sum(abs(s) for _, s in neighbors)
return num / den if den else 0.0
missing = [i for i, r in enumerate(ratings[target]) if r == 0]
preds = {i: predict(i, neighbors) for i in missing}
ranked = sorted(preds.items(), key=lambda kv: -kv[1])
print("Recommend first:", ranked[0]) # highest predicted rating
