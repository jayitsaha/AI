Key-Value Cache for Autoregressive Generation

Optimizing Transformer decoding by caching past Keys and Values
Intermediate Deep Learning Optimization O(L) per token
1
Understanding the Key-Value Cache
▼

What is it? The Key-Value (KV) cache is an optimization technique crucial for efficient autoregressive generation with Transformer models (like LLMs). When a Transformer generates text token by token, each new token needs to attend to all previously generated tokens. Without the KV cache, the model would re-compute the "Key" and "Value" representations for all past tokens at every single step, leading to significant redundant computation. The KV cache simply stores these past Keys and Values, so they only need to be computed once and can be reused.

Analogy: Imagine you're writing a long story. Every new sentence you write needs to "pay attention" to all the previous sentences to maintain coherence.

  • Without KV Cache: For each new sentence, you'd re-read the *entire story from the very beginning* to understand its context. This is very slow as the story gets longer.
  • With KV Cache: You keep a running mental summary of the "key ideas" (Keys) and "important details" (Values) from all sentences you've already written. When you write a new sentence, you only need to process *that new sentence* and then quickly reference your mental summary for context. This is much faster.

💡 If you remember one thing

The core Transformer self-attention mechanism is defined as: $$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$ For autoregressive decoding, the Key (\(K\)) and Value (\(V\)) projections for past tokens don't change. The KV cache stores these, turning a redundant \(O(L^2)\) computation *per token* into an \(O(L)\) lookup and \(O(L)\) attention *per token*, where \(L\) is the current sequence length.

2
How It Works Internally
▼

The Problem: Redundant Computation

In a Transformer decoder, each output token is generated sequentially. To predict the \(t\)-th token, the model processes the entire sequence up to \(t\) tokens: \([x_1, x_2, \dots, x_t]\). For each token in this sequence, the model computes Query (\(Q\)), Key (\(K\)), and Value (\(V\)) matrices by multiplying its embedding with learned weight matrices (\(W_Q, W_K, W_V\)). The self-attention mechanism then uses these to compute an output for each token.

The critical observation is that when generating \(x_{t+1}\), the \(Q, K, V\) values for \([x_1, \dots, x_t]\) are *exactly the same* as they were when generating \(x_t\). Without a KV cache, the model would re-run the linear projections for all previous \(t\) tokens, which is a significant waste of computation.

The Solution: Caching Keys and Values

The KV cache addresses this by storing the \(K\) and \(V\) matrices from previous steps. The process typically has two phases:

  1. Pre-fill Phase (Prompt Processing): When the initial prompt (e.g., "The quick brown fox") is fed into the model, the Keys and Values for all tokens in the prompt are computed once. These are then stored in the KV cache.
  2. Decoding Phase (Token-by-Token Generation): For each subsequent token to be generated (e.g., "jumps", then "over"):
    • Only the Query (\(Q\)) for the *new* token is computed.
    • Only the Key (\(K\)) and Value (\(V\)) for the *new* token are computed.
    • The newly computed \(K\) and \(V\) are concatenated with the existing Keys and Values in the cache.
    • Attention is calculated using the new \(Q\) against the *full, concatenated* Keys and Values.
    • The updated cache (containing all past and current \(K\) and \(V\)) is passed to the next decoding step.

This way, the linear projections for past tokens are never re-computed.

Design Decision: Why not cache Query (Q) too?

The Query (\(Q\)) for the *current* token is fundamentally different from past Queries. It represents "what I'm looking for *now*." Each new token defines a new "query" into the context of all previous tokens (Keys and Values). Therefore, the Query vector for the current token must always be computed fresh. Only Keys and Values, which represent the "content" of past tokens, can be reused.

🔑 Key Property

The KV cache transforms the computational complexity of autoregressive decoding. Without it, generating a sequence of length \(L\) involves \(L\) forward passes, each processing a sequence of length \(t \in [1, L]\), leading to \(O(L^3)\) total operations. With the KV cache, each token generation step is \(O(L)\), leading to a total of \(O(L^2)\) operations for the full sequence. This is a massive speedup for long sequences.

3
Why It Works — The Math
▼

Self-Attention Refresher

Recall that the core of Transformer self-attention involves three matrices: Query (\(Q\)), Key (\(K\)), and Value (\(V\)). These are derived from the input sequence embeddings \(X \in \mathbb{R}^{L \times d_{model}}\) by linear projections:

$$Q = X W_Q, \quad K = X W_K, \quad V = X W_V$$

where \(W_Q, W_K, W_V \in \mathbb{R}^{d_{model} \times d_k}\) are learned weight matrices, and \(d_k\) is the dimension of the keys and queries. The attention output is then:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Autoregressive Decoding Without KV Cache

To generate the \(t\)-th token, the model receives the input sequence \(X_{1:t} = [x_1, \dots, x_t]\). It then computes:

$$Q_{1:t} = X_{1:t} W_Q, \quad K_{1:t} = X_{1:t} W_K, \quad V_{1:t} = X_{1:t} W_V$$

The attention computation for the last token \(x_t\) (i.e., the last row of \(Q_{1:t}\) attending to all rows of \(K_{1:t}\) and \(V_{1:t}\)) yields the context for predicting the next token. This process is repeated for every token, meaning \(W_K\) and \(W_V\) are applied to \(X_{1:t}\) at each step \(t\), redundantly re-computing \(K\) and \(V\) for tokens \(x_1, \dots, x_{t-1}\).

Autoregressive Decoding With KV Cache

Let \(K_{\text{cache}} \in \mathbb{R}^{(t-1) \times d_k}\) and \(V_{\text{cache}} \in \mathbb{R}^{(t-1) \times d_k}\) be the accumulated Keys and Values from tokens \(x_1, \dots, x_{t-1}\). To generate the \(t\)-th token, we receive only the embedding for the current token, \(x_t \in \mathbb{R}^{1 \times d_{model}}\). We then compute:

$$q_t = x_t W_Q, \quad k_t = x_t W_K, \quad v_t = x_t W_V$$

The new \(k_t\) and \(v_t\) are concatenated with the cache to form the full Key and Value matrices for this step:

$$K'_{\text{full}} = \begin{pmatrix} K_{\text{cache}} \\ k_t \end{pmatrix} \in \mathbb{R}^{t \times d_k}, \quad V'_{\text{full}} = \begin{pmatrix} V_{\text{cache}} \\ v_t \end{pmatrix} \in \mathbb{R}^{t \times d_k}$$

Then, attention is computed using the new query \(q_t\) against the full Keys and Values:

$$\text{Attention Output for } x_t = \text{softmax}\left(\frac{q_t (K'_{\text{full}})^\top}{\sqrt{d_k}}\right)V'_{\text{full}}$$

The cache is then updated to \(K'_{\text{full}}\) and \(V'_{\text{full}}\) for the next step. This avoids recomputing \(K_{\text{cache}}\) and \(V_{\text{cache}}\) at each step, saving significant FLOPs.

⚠️ Memory Cost

While the KV cache drastically reduces computation, it comes at a memory cost. The cache for a single layer in a single attention head stores \(2 \times L \times d_k\) floating-point numbers. For a large model with many layers and heads, generating long sequences can result in a KV cache that consumes gigabytes of GPU memory, often becoming the bottleneck for maximum sequence length.

Key Takeaways
▼

When to use the KV cache:

  • Autoregressive Generation: Essential for any task where output is produced token-by-token, such as language generation, speech synthesis, or video prediction.
  • Long Sequences: The computational savings become increasingly significant as sequence length grows, transforming \(O(L^3)\) total operations to \(O(L^2)\).
  • Real-time Inference: Reduces latency for interactive applications by speeding up each decoding step.

When NOT to use or be mindful of:

  • Encoder-only Models: Models like BERT used for classification or feature extraction do not generate sequences autoregressively, so a KV cache is irrelevant.
  • Memory Constraints: For very large models or extremely long sequences, the KV cache can consume significant GPU memory. This can be a bottleneck, sometimes requiring techniques like KV cache quantization or eviction strategies.
  • Non-autoregressive Tasks: If the entire output sequence is generated in parallel (e.g., masked language modeling), the KV cache offers no benefit.
  • Very Short Sequences: For extremely short sequences, the overhead of managing the cache might slightly outweigh the computational savings, though this is rarely a practical concern.
💡 Big Picture

The KV cache is a fundamental optimization that enables the practical deployment of large Transformer models for generative tasks. It directly exploits the causal mask in autoregressive decoding to avoid redundant linear projections, making token-by-token generation feasible at scale. Without it, the computational cost would render most modern LLMs unusable for interactive generation.

Code Trace (Simplified PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
class SelfAttention(nn.Module):
def __init__(self, d_model, d_k):
super().__init__()
self.W_q = nn.Linear(d_model, d_k, bias=False)
self.W_k = nn.Linear(d_model, d_k, bias=False)
self.W_v = nn.Linear(d_model, d_k, bias=False)
self.scale = d_k ** -0.5
def forward(self, x, past_key_value=None, use_cache=False):
# x: (batch_size, seq_len, d_model)
# past_key_value: tuple of (past_keys, past_values), each (batch_size, past_seq_len, d_k)
q = self.W_q(x) # (batch_size, seq_len, d_k)
k = self.W_k(x) # (batch_size, seq_len, d_k)
v = self.W_v(x) # (batch_size, seq_len, d_k)
if past_key_value is not None:
past_k, past_v = past_key_value
k = torch.cat([past_k, k], dim=1) # Concatenate with cached keys
v = torch.cat([past_v, v], dim=1) # Concatenate with cached values
# Only the *last* query token attends to the full K/V for decoding
# (Simplified: assumes seq_len=1 for decoding, or full seq for prefill)
attn_scores = (q @ k.transpose(-2, -1)) * self.scale
attn_weights = torch.softmax(attn_scores, dim=-1)
output = attn_weights @ v
next_key_value = (k, v) if use_cache else None
return output, next_key_value
# --- Example Usage (Autoregressive Decoding) ---
model = SelfAttention(d_model=768, d_k=64)
# 1. Prefill phase (e.g., processing a prompt "The quick brown")
prompt_tokens_embeddings = torch.randn(1, 3, 768) # Batch=1, SeqLen=3
_, past_kv = model(prompt_tokens_embeddings, use_cache=True)
print(f"Past KV shape: {past_kv[0].shape}") # (1, 3, 64)
# 2. Decoding phase (generating next token: "fox")
new_token_embedding = torch.randn(1, 1, 768) # Batch=1, SeqLen=1
output_token_emb, past_kv = model(new_token_embedding, past_key_value=past_kv, use_cache=True)
print(f"Output token embedding shape: {output_token_emb.shape}") # (1, 1, 64)
print(f"Updated Past KV shape: {past_kv[0].shape}") # (1, 4, 64)
# Repeat step 2 for subsequent tokens...
