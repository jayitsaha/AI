Target / Mean Encoding & Leakage Risks

Part III: Classical ML — Feature Encoding

Understanding Target Encoding

Categorical features like City = "London" are strings — most ML models need numbers. Target (mean) encoding replaces each category with the average of the target variable for all training rows that share that category.

Key Concept
If 80% of customers from "London" churned, encode "London" → 0.80. The category's encoding is its conditional target mean: \(\hat{\mu}_c = \mathbb{E}[y \mid X = c]\).

Why bother? One-hot encoding explodes cardinality (1000 cities → 1000 columns). Label encoding is ordinal nonsense. Target encoding produces a single informative number per category — often the strongest predictor in the dataset.

The Catch
Done naively on the full training set, target encoding leaks the target into the features — the model sees, for each row, a feature computed using that row's own label. This inflates training accuracy and causes severe overfitting to rare categories.

Fixes: smoothing toward the global mean, out-of-fold (cross-validated) encoding, and additive noise. The interactive explainer below walks through each numerically.

2
Internal Mechanism

Naive Encoding — step by step

For a binary classification target \(y \in \{0,1\}\) and a categorical feature \(X\):

$$\hat{\mu}_c = \frac{1}{n_c}\sum_{i:\, x_i = c} y_i = \bar{y}_c$$

where \(n_c = |\{i : x_i = c\}|\) is the count of category \(c\).

At inference: every row with \(x = c\) gets the value \(\hat{\mu}_c\) learned from training data.

The Leakage Problem

When computed on the full training set and then used as a feature for the same training rows, the encoding carries information about \(y_i\) directly into \(x_i'\). A row where \(y_i = 1\) nudges \(\hat{\mu}_c\) upward; the model exploits this during training but the signal vanishes at test time.

Leakage Signature
Rare categories (small \(n_c\)) are worst: a single row with \(y=1\) gives \(\hat{\mu}_c=1.0\), and that same row then has feature value 1.0. The model memorises it. Training ROC ≈ 1.0; test ROC ≈ random.

Fix 1 — Additive Smoothing

Regularise toward the global mean \(\bar{y}\) using a smoothing weight \(\lambda \geq 0\):

$$\tilde{\mu}_c = \frac{n_c\,\bar{y}_c + \lambda\,\bar{y}}{n_c + \lambda}$$

When \(n_c \to \infty\), \(\tilde{\mu}_c \to \bar{y}_c\) (trust the data). When \(n_c \to 0\), \(\tilde{\mu}_c \to \bar{y}\) (fall back to global). \(\lambda\) is a hyperparameter tuned by cross-validation.

Fix 2 — Out-of-Fold (OOF) Encoding

Partition training data into \(K\) folds. For each fold \(k\), compute \(\hat{\mu}_c\) using only the other \(K-1\) folds, then assign it to the held-out fold. The target row never contributes to its own encoding.

$$\tilde{x}_i = \hat{\mu}_c^{(-k(i))} = \frac{1}{n_c^{(-k(i))}} \sum_{j \notin \text{fold }k(i),\, x_j=c} y_j$$

Fix 3 — Additive Noise

After computing \(\hat{\mu}_c\), add Gaussian noise: \(\tilde{x}_i = \hat{\mu}_c + \epsilon_i\), where \(\epsilon_i \sim \mathcal{N}(0,\sigma^2)\). This breaks exact memorisation but is strictly inferior to OOF encoding — noise is a blunt instrument. Use only for quick baselines.

3
Mathematical Properties

Bias-Variance of the Naive Estimator

The naive estimator \(\hat{\mu}_c = \bar{y}_c\) is an unbiased estimate of \(\mathbb{E}[y \mid X=c]\) but has high variance for small \(n_c\):

$$\operatorname{Var}(\hat{\mu}_c) = \frac{\sigma^2_c}{n_c}$$

Smoothing introduces bias toward \(\bar{y}\) but dramatically reduces variance — the classic bias-variance trade-off.

Smoothing as Empirical Bayes

Additive smoothing corresponds to placing a Beta prior \(\text{Beta}(\lambda\bar{y},\, \lambda(1-\bar{y}))\) on the per-category rate and using the posterior mean as the encoding:

$$\tilde{\mu}_c = \frac{n_c \bar{y}_c + \lambda \bar{y}}{n_c + \lambda}$$

Larger \(\lambda\) → stronger prior → more shrinkage toward global mean.

Relationship to James-Stein Shrinkage

For many categories simultaneously, the optimal shrinkage estimator (minimising MSE) is exactly of this form. Target encoding with smoothing is an instance of hierarchical partial pooling — a core concept in Bayesian statistics and mixed-effects models.

Optimal \(\lambda\)
The MSE-minimising \(\lambda^\star\) satisfies \(\lambda^\star = \sigma^2_\varepsilon / \sigma^2_\alpha\) where \(\sigma^2_\varepsilon\) is within-category noise variance and \(\sigma^2_\alpha\) is between-category variance. In practice, cross-validate over a grid \(\lambda \in \{1, 5, 10, 20, 50\}\).

Key Takeaways
When to Use Target Encoding
High-cardinality categoricals (cities, zip codes, user IDs, product SKUs) where one-hot would be too sparse. Tree models (XGBoost, LightGBM) benefit most; linear models benefit from the signal but need strong regularisation.
  • Always use OOF encoding or smoothing — never naked mean encoding on the full training set.
  • In scikit-learn, use TargetEncoder (v1.3+) which implements CV encoding internally.
  • Apply the test-set encoding using the global \(\hat{\mu}_c\) fitted on all training rows — no target leakage at inference time.
  • For unseen categories at inference, fall back to global mean \(\bar{y}\).
  • Tune \(\lambda\) (smoothing) as a hyperparameter; typical range: 5–50.
