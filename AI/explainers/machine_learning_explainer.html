Anomaly Detection: Isolation Forest & Autoencoders on Time Series

Detecting outliers using rolling features, isolation depth, and reconstruction error

1
Understanding Anomaly Detection
▼

What is it? Anomaly detection (also called outlier detection) is the task of identifying rare items, events, or observations that deviate significantly from the majority of the data. These "anomalies" often point to critical incidents like fraud, system failures, structural defects, or novel discoveries.

Why is it hard? Anomalies are, by definition, infrequent. This makes them hard to learn from (few positive examples) and easy to miss (swamped by normal data). In time-series data, an anomaly might not be an unusual *value* but an unusual *pattern* or *sequence* of values.

Analogy: Imagine you're a quality control inspector for a factory producing identical widgets. Most widgets are perfect. An anomaly could be a widget with an unusual dent, a strange color, or one that vibrates oddly when tested. An Isolation Forest might quickly spot the dented one because it's so obviously different from the rest. An Autoencoder, having learned the precise blueprint of a perfect widget, would immediately flag the vibrating one because it fails to reconstruct its expected behavior.

💡 If you remember one thing

For time series, individual data points are rarely anomalous in isolation. Instead, we extract rolling features from sliding windows over the time series. These features convert temporal context into static, multivariate descriptions that can then be fed into standard anomaly detection algorithms like Isolation Forest or Autoencoders.

2
How It Works Internally
▼

Rolling Features: Capturing Context

To apply anomaly detection to a univariate time series (e.g., temperature over time), we first transform it. A rolling window of a fixed size slides over the series, and for each window, statistical features are extracted. Common rolling features include:

  • Mean: Average value within the window.
  • Standard Deviation: Volatility/spread within the window.
  • Min/Max: Extreme values within the window.
  • Raw window values: The raw sequence of values within the window, forming a higher-dimensional vector.

Each window thus becomes a multi-dimensional feature vector, and the time series is converted into a sequence of these feature vectors. Anomalies are then detected in this feature space.

Isolation Forest: Anomalies are Easy to Isolate

An Isolation Forest (Liu et al., 2008) is an ensemble of "Isolation Trees" (iTrees). Unlike traditional decision trees that try to *cluster* normal points, iTrees explicitly try to *isolate* anomalies. It works by:

  1. Randomly selecting a feature.
  2. Randomly selecting a split value for that feature, between its min and max.
  3. Recursively partitioning the data until each observation is isolated or a maximum depth is reached.

Anomalies are typically few and far from normal data, so they require fewer random partitions (shorter path lengths) to be isolated. Normal points, being clustered, require many more partitions (longer path lengths).

Autoencoder Reconstruction Error: Learning Normality

An Autoencoder (AE) is a type of neural network trained to reconstruct its own input. It consists of two parts:

  1. Encoder: Maps the input data \(x\) to a lower-dimensional latent representation \(z\).
  2. Decoder: Maps the latent representation \(z\) back to a reconstruction of the input, \(\hat{x}\).

The AE is trained on a dataset of *normal* data. During training, it learns to efficiently compress and decompress the typical patterns. When an anomalous input \(x\) is fed to a trained AE, it struggles to reconstruct it accurately because it has never seen such a pattern before. The discrepancy between the input and its reconstruction is the reconstruction error, which will be significantly higher for anomalies.

🔑 Key Property

Both Isolation Forest and Autoencoders are primarily unsupervised anomaly detection methods. They don't require labeled anomaly examples for training. Instead, Isolation Forest implicitly learns what "normal" looks like by how hard points are to isolate, while Autoencoders explicitly learn to model "normal" data patterns.

3
Why It Works — The Math
▼

Isolation Forest: Anomaly Score

For an Isolation Tree, the path length \(h(x)\) of an observation \(x\) is the number of edges \(x\) traverses from the root to the external node. The anomaly score \(s(x, n)\) for an observation \(x\) in a dataset of \(n\) samples is derived from its average path length \(E[h(x)]\) across an ensemble of \(t\) iTrees:

$$s(x, n) = 2^{-\frac{E[h(x)]}{c(n)}}$$

where \(c(n)\) is the average path length of unsuccessful search in a Binary Search Tree given \(n\) points, which acts as a normalization constant: \(c(n) = 2H(n-1) - (2(n-1)/n)\) (where \(H(k)\) is the harmonic number). A shorter \(E[h(x)]\) (meaning \(x\) is easily isolated) results in a score closer to 1, indicating an anomaly. Scores close to 0.5 indicate normal observations, and scores below 0.5 indicate likely normal observations.

Autoencoder: Reconstruction Error

An Autoencoder minimizes a reconstruction loss function, typically Mean Squared Error (MSE), between its input \(x\) and its output \(\hat{x}\). Given an input vector \(x \in \mathbb{R}^D\), the encoder \(f\) maps it to a latent representation \(z \in \mathbb{R}^d\) (where \(d < D\)), and the decoder \(g\) maps \(z\) back to \(\hat{x} \in \mathbb{R}^D\):

$$z = f(x) \quad \text{and} \quad \hat{x} = g(z)$$

The reconstruction error \(R(x)\) is then:

$$R(x) = \|x - \hat{x}\|^2 = \sum_{j=1}^D (x_j - \hat{x}_j)^2$$

During training, the autoencoder learns to minimize \(R(x)\) for normal data. Anomalous data, which deviates from the learned normal patterns, will naturally have a higher \(R(x)\) because the AE's compressed representation (latent space) and reconstruction capabilities are optimized for normal data distributions.

⚠️ Common Pitfall

The choice of rolling window size is critical. A window that is too small might not capture enough contextual information to identify pattern-based anomalies. A window that is too large might dilute the local anomalous signal by averaging it with too much normal data. Experimentation and domain knowledge are key.

Key Takeaways
▼

When to use Isolation Forest:

  • When you have high-dimensional data, as it scales well and is efficient.
  • When anomalies are expected to be sparse and distinct, easily separable from normal data.
  • Less sensitive to irrelevant features compared to distance-based methods.

When to use Autoencoders:

  • When the "normal" data has complex, non-linear patterns that can be effectively learned by a neural network.
  • When you have abundant normal data for training.
  • Can be powerful for high-dimensional data, learning a compressed latent representation.

When to use both:

  • To gain robustness: different methods may catch different types of anomalies.
  • Combine their scores (e.g., sum, product, or a meta-model) for a more comprehensive anomaly detection system.

When NOT to use / Caveats:

  • Isolation Forest can struggle with dense clusters of anomalies or if normal data is itself very scattered.
  • Autoencoders require careful hyperparameter tuning (architecture, learning rate, regularization) and can be computationally expensive to train. They are also sensitive to noise in the training data (if "normal" data contains anomalies, the AE might learn to reconstruct them).
  • Both methods are sensitive to the quality and representativeness of the "normal" data used for their internal modeling.
💡 Big Picture

The power of these techniques for time series lies in their ability to detect anomalies in a transformed feature space. Rolling features are the bridge that converts the temporal dynamics of a time series into static patterns that these powerful, general-purpose anomaly detectors can understand and act upon.

Code Trace (Python-like Pseudocode)
▼
import numpy as np
from sklearn.ensemble import IsolationForest
from tensorflow.keras.models import Model
from tensorflow.keras.layers import Input, Dense
# 1. Generate synthetic time series data
time_series_length = 200
t = np.arange(time_series_length)
data = 50 + 10 * np.sin(t / 10) + np.random.normal(0, 2, time_series_length)
data[50:55] += 30 # Anomaly 1: Spike
data[120:130] -= 20 # Anomaly 2: Shift
# 2. Extract rolling features
def create_rolling_features(ts_data, window_size):
features = []
for i in range(len(ts_data) - window_size + 1):
window = ts_data[i : i + window_size]
features.append([np.mean(window), np.std(window), np.min(window), np.max(window)])
return np.array(features)
window_size = 5
X_features = create_rolling_features(data, window_size)
# 3. Isolation Forest for anomaly scoring
if_model = IsolationForest(contamination='auto', random_state=42)
if_model.fit(X_features)
if_scores = -if_model.decision_function(X_features) # Higher score = more anomalous
# 4. Autoencoder for anomaly scoring (reconstruction error)
input_dim = X_features.shape[1] # Number of rolling features
encoding_dim = 2 # Latent dimension
input_layer = Input(shape=(input_dim,))
encoder = Dense(encoding_dim, activation='relu')(input_layer)
decoder = Dense(input_dim, activation='linear')(encoder)
autoencoder = Model(inputs=input_layer, outputs=decoder)
autoencoder.compile(optimizer='adam', loss='mse')
# Train AE on normal data (or all data, it learns normal patterns)
autoencoder.fit(X_features, X_features, epochs=50, batch_size=32, verbose=0)
# Get reconstruction error
reconstructions = autoencoder.predict(X_features, verbose=0)
ae_errors = np.mean(np.square(X_features - reconstructions), axis=1)
