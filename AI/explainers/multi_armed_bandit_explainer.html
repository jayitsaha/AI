Understanding Multi-Armed Bandits
▼

What is it? A Multi-Armed Bandit (MAB) problem is a classic reinforcement learning scenario where an agent must choose between multiple "arms" (actions) repeatedly, each yielding a random reward from an unknown distribution. The goal is to maximize the cumulative reward over time. The core challenge is the exploration-exploitation dilemma: should the agent choose the arm that has performed best so far (exploit), or try a less-known arm to see if it's actually better (explore)?

Analogy: Imagine you're in a casino with several slot machines ("one-armed bandits"). Each machine has a different, unknown probability of paying out. You have a limited budget (total pulls). How do you decide which machine to play at each turn to maximize your winnings? If you only play the one that paid out most in the beginning, you might miss out on a truly better machine. If you keep trying new machines, you might waste pulls on bad ones. MAB algorithms provide strategies for this trade-off.

💡 If you remember one thing

MAB is the simplest sequential decision-making problem, focusing purely on the exploration-exploitation trade-off. It's "context-free" — unlike full Reinforcement Learning, there's no state, just a choice of action (arm) and an immediate reward.

How MAB Algorithms Work Internally
▼

The Core Loop

At each time step \(t\):

  1. Select an arm \(a_t\).
  2. Observe a reward \(r_t\) from arm \(a_t\).
  3. Update the statistics (e.g., estimated mean reward, number of pulls) for arm \(a_t\).

The "trick" is in step 1: how to select \(a_t\) to balance finding the best arm (exploration) with pulling the current best arm (exploitation).

Three Popular Strategies

  • ε-greedy: The simplest. With probability \(\varepsilon\) (epsilon), choose an arm randomly (explore). With probability \(1-\varepsilon\), choose the arm with the highest estimated average reward (exploit). A fixed \(\varepsilon\) means you never stop exploring, even after many pulls.
  • Upper Confidence Bound (UCB): More sophisticated. It selects the arm that maximizes an "optimistic" estimate of its true reward. This estimate includes the current average reward plus a bonus term that depends on how uncertain we are about that arm (fewer pulls = larger bonus). This naturally prioritizes less-explored arms.
  • Thompson Sampling: A Bayesian approach. It maintains a probability distribution (a "belief") over the true reward probability for each arm. At each step, it samples a hypothetical true reward probability from each arm's belief distribution, and then pulls the arm with the highest sampled value. This integrates uncertainty directly into the decision-making.
🔑 Key Property

All MAB algorithms aim to minimize regret, which is the difference between the cumulative reward obtained and the cumulative reward that would have been obtained by always choosing the optimal arm. A good algorithm quickly converges to pulling the best arm most of the time.

3
Why It Works — The Math
▼

1. ε-greedy

Let \(Q_a(t)\) be the estimated average reward of arm \(a\) after \(t\) pulls, and \(N_a(t)\) be the number of times arm \(a\) has been pulled. At each step, with probability \(\varepsilon\), choose a random arm. With probability \(1-\varepsilon\), choose arm \(a^*\) where:

$$a^* = \arg\max_a Q_a(t)$$

The estimate \(Q_a(t)\) is simply the sum of rewards received from arm \(a\) divided by \(N_a(t)\). For binary rewards (win/loss): \(Q_a(t) = \frac{\text{Wins}_a}{\text{Pulls}_a}\).

2. Upper Confidence Bound (UCB1)

UCB algorithms select arm \(a_t\) at time \(t\) that maximizes the following score:

$$a_t = \arg\max_a \left[ Q_a(t) + c \sqrt{\frac{\ln t}{N_a(t)}} \right]$$

Here, \(Q_a(t)\) is the average reward. The second term is the "confidence bonus": \(\ln t\) is the natural logarithm of the total number of pulls so far, and \(N_a(t)\) is the number of times arm \(a\) has been pulled. The constant \(c\) (often set to 2) controls the balance between exploration and exploitation. If \(N_a(t) = 0\), that arm is chosen automatically (or given an infinite bonus) to ensure it's explored at least once. The bonus shrinks as \(N_a(t)\) grows, and grows as \(t\) grows, ensuring all arms are explored sufficiently over time.

3. Thompson Sampling (for Bernoulli Rewards)

For each arm \(a\), we maintain a Beta distribution, \(\text{Beta}(\alpha_a, \beta_a)\), which is a conjugate prior for the Bernoulli likelihood. Initially, \(\alpha_a = 1\) and \(\beta_a = 1\) for all arms (representing a uniform prior belief). When arm \(a\) is pulled and yields a reward \(r_a \in \{0, 1\}\):

$$\text{If } r_a = 1: \alpha_a \leftarrow \alpha_a + 1$$ $$\text{If } r_a = 0: \beta_a \leftarrow \beta_a + 1$$

To choose an arm at time \(t\):

  1. For each arm \(a\), sample a probability \(\theta_a \sim \text{Beta}(\alpha_a, \beta_a)\).
  2. Choose the arm \(a^*\) with the highest sampled probability: \(a^* = \arg\max_a \theta_a\).
This means arms with higher \(\alpha_a\) (more wins) or higher uncertainty (wider Beta distribution) are more likely to be sampled as the best, driving exploration naturally.

⚠️ Common Pitfall

Choosing the right hyperparameters is crucial. For ε-greedy, a fixed \(\varepsilon\) can lead to suboptimal long-term regret if it's too high. For UCB, the constant \(c\) can significantly impact performance. For Thompson Sampling, while often robust, the choice of prior can matter with very limited data.

Key Takeaways
▼

When to use MAB algorithms:

  • A/B testing (online optimization): Dynamically allocating traffic to different website designs, ad creatives, or product features to find the best performing one faster.
  • Recommendation systems: Choosing which item to recommend next when user preferences are uncertain and need to be learned.
  • Clinical trials: Allocating patients to different treatment arms to maximize the number of patients receiving the most effective treatment.
  • Hyperparameter tuning: Selecting the best set of hyperparameters for a model when evaluating each set is costly.

When NOT to use MAB (consider full RL or other methods):

  • Contextual Bandits: If the reward distribution depends on external factors (e.g., user demographics, time of day), MAB ignores this context. Use Contextual Bandits.
  • Sequential Decision Making with State: If current actions affect future states or rewards (e.g., navigating a maze, playing chess), MAB is insufficient. Use full Reinforcement Learning.
  • Non-stationary Environments: If the true reward probabilities of arms change over time, standard MAB algorithms might struggle. Use decaying ε-greedy or UCB variants for non-stationary settings.
💡 Big Picture

MAB algorithms are simple yet powerful tools for optimizing sequential choices under uncertainty. They provide a principled way to manage the exploration-exploitation trade-off, a fundamental challenge across many fields from science to business. Understanding MAB is a stepping stone to more complex Reinforcement Learning problems.

import numpy as np
class EpsilonGreedyBandit:
def __init__(self, n_arms, epsilon=0.1):
self.n_arms = n_arms
self.epsilon = epsilon
self.q_estimates = np.zeros(n_arms) # Estimated average rewards
self.n_pulls = np.zeros(n_arms) # Number of times each arm pulled
def choose_arm(self):
if np.random.rand() < self.epsilon:
return np.random.randint(self.n_arms) # Explore: random arm
else:
return np.argmax(self.q_estimates) # Exploit: best estimated arm
def update(self, chosen_arm, reward):
self.n_pulls[chosen_arm] += 1
# Update Q_estimate using incremental average formula
self.q_estimates[chosen_arm] += (reward - self.q_estimates[chosen_arm]) / self.n_pulls[chosen_arm]
class UCBBandit(EpsilonGreedyBandit): # Inherit for common parts
def __init__(self, n_arms, c=2):
super().__init__(n_arms, epsilon=0) # UCB is deterministic
self.c = c
self.total_pulls = 0
def choose_arm(self):
# Ensure all arms are pulled at least once
if 0 in self.n_pulls: return np.argmin(self.n_pulls)
# Calculate UCB scores
ucb_values = self.q_estimates + self.c * np.sqrt(np.log(self.total_pulls) / self.n_pulls)
return np.argmax(ucb_values)
def update(self, chosen_arm, reward):
super().update(chosen_arm, reward)
self.total_pulls += 1
class ThompsonSamplingBandit:
def __init__(self, n_arms):
self.n_arms = n_arms
self.alphas = np.ones(n_arms) # Number of wins + 1 (prior)
self.betas = np.ones(n_arms) # Number of losses + 1 (prior)
def choose_arm(self):
# Sample from Beta distribution for each arm
sampled_thetas = [np.random.beta(self.alphas[i], self.betas[i]) for i in range(self.n_arms)]
return np.argmax(sampled_thetas)
def update(self, chosen_arm, reward):
if reward == 1: self.alphas[chosen_arm] += 1
else: self.betas[chosen_arm] += 1
