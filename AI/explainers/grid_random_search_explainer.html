Grid Search vs Random Search

Bergstra & Bengio (2012) — Why random wins when only a few dimensions matter
Intermediate Classical ML · HPO O(n^d) grid · O(n) random
1
Understanding the Concept
▾

Every machine learning model has hyperparameters — settings you choose before training starts, like learning rate, tree depth, or regularization strength. Getting them right dramatically affects performance, but there's no formula: you have to search.

Grid search enumerates every combination on a fixed lattice: if you try 5 values of parameter A and 5 values of parameter B, you run 25 experiments. Systematic, exhaustive — but exponential: add a third parameter with 5 values and you now run 125 experiments.

Random search simply samples each hyperparameter independently from a specified distribution, running a fixed budget of trials at random locations. It sounds naïve, but Bergstra & Bengio (2012) proved it is almost always better than grid search for the same budget.

💡 The Key Insight

Most hyperparameters don't matter much. In a 6-dimensional search space, if only 2 dimensions are "effective" (i.e., actually change validation loss), grid search wastes most of its trials exploring useless combinations of the irrelevant 4. Random search gets the same coverage of the 2 effective dimensions with far fewer total trials — because each random point projects uniquely onto every axis.

🔑 One-Sentence Summary

Random search dominates grid search whenever the loss function has low effective dimensionality — and in practice, it almost always does.

How Each Strategy Works Internally
▾

Grid Search

You specify a discrete grid: \(\mathcal{G} = \Lambda_1 \times \Lambda_2 \times \cdots \times \Lambda_d\) where \(\Lambda_k = \{\lambda_k^{(1)}, \ldots, \lambda_k^{(m_k)}\}\). Every point in the Cartesian product is evaluated. Total trials: \(\prod_{k=1}^{d} m_k\). With \(d=6\) dimensions and \(m_k=5\) each, this is \(5^6 = 15{,}625\) evaluations — completely infeasible.

Random Search

You specify a distribution \(p_k(\lambda_k)\) per dimension (uniform, log-uniform, categorical). For each trial, sample \(\boldsymbol{\lambda}^{(t)} \sim \prod_{k} p_k(\lambda_k)\) independently. Run exactly \(T\) trials, regardless of \(d\).

📐 The Coverage Argument

For \(T\) random trials in \(d\) dimensions, each axis receives \(T\) distinct marginal values. A \(T\)-point grid has \(T^{1/d}\) values per axis. For \(T=25\), \(d=2\): grid gets 5 per axis; random also gets 25 per axis projections — a 5× advantage per dimension. This is exactly Bergstra & Bengio's Figure 1 result.

The "Effective Dimensionality" Theorem (Informal)

Let \(f: \mathbb{R}^d \to \mathbb{R}\) be the validation loss landscape. Suppose only \(d_e \ll d\) dimensions are "important" (contribute meaningfully to the variance of \(f\)). Grid search allocates its budget uniformly across all \(d\) dimensions, wasting evaluations on the \(d - d_e\) irrelevant ones. Random search, by independently sampling each axis, achieves the same effective coverage of the \(d_e\) important dimensions as a grid search that knew which dimensions mattered.

⚠️ When Grid Search Has an Edge

If all dimensions are equally important AND you have an exact grid budget to fill, grid search is slightly more deterministic. But in practice this never holds: there are always some irrelevant or nearly-irrelevant hyperparameters.

The Mathematics
▾

Setup

Hyperparameter space \(\Lambda = \Lambda_1 \times \cdots \times \Lambda_d \subseteq \mathbb{R}^d\). Objective: minimize validation loss \(\mathcal{L}: \Lambda \to \mathbb{R}\). We have a budget of \(T\) evaluations (model train+eval cycles).

Grid Search Budget

$$|\mathcal{G}| = \prod_{k=1}^{d} m_k \quad \text{(evaluations needed for full grid)}$$

For a balanced grid with \(m_k = m\) values per dimension:

$$|\mathcal{G}| = m^d$$

Exponential in \(d\). With \(T\) budget and \(d\) dimensions, grid search can only afford \(m = T^{1/d}\) values per axis.

Random Search Coverage per Axis

With \(T\) random samples in \(d\) dimensions, the marginal distribution on axis \(k\) has all \(T\) points projected onto it — each with a distinct value (with probability 1 for continuous distributions). So random search effectively has \(T\) "levels" per axis versus grid's \(T^{1/d}\).

$$\text{Unique axis values: Random} = T, \quad \text{Grid} = T^{1/d}$$

Probability of Finding a Good Region

Suppose the top-\(r\) fraction of the search space (by performance) forms a connected region. The probability that at least one of \(T\) random trials lands in this region is:

$$P(\text{hit}) = 1 - (1-r)^T$$

For \(r = 0.05\) (top 5%) and \(T = 60\) trials: \(P = 1 - 0.95^{60} \approx 0.953\). For 95% confidence of hitting the top-5% region, you need only \(T = \lceil \log(0.05)/\log(0.95) \rceil = 59\) trials — independent of \(d\).

$$T \geq \frac{\log \delta}{\log(1 - r)} \quad \text{for success probability } 1-\delta$$

This \(T\) is independent of \(d\): adding more hyperparameters doesn't increase the required budget for random search, whereas grid search requires \(m^d\) evaluations to cover the same fraction.

The Effective Dimensionality Bound

Formally (Bergstra & Bengio 2012), if \(f\) depends on at most \(d_e\) dimensions, then for any \(\epsilon > 0\), random search with \(T = O\!\left(\frac{d_e}{\epsilon^{d_e}}\right)\) trials achieves \(\epsilon\)-optimal performance, matching what an oracle grid search over only the \(d_e\) important dimensions would achieve — regardless of \(d \geq d_e\).

$$T_{\text{random}} = O\!\left(\frac{d_e}{\epsilon^{d_e}}\right) \quad \ll \quad T_{\text{grid}} = O\!\left(\frac{d}{\epsilon^{d}}\right)$$

🎯 Decision Rule

Use grid search when you have ≤2 hyperparameters and want a clean sweep for a paper/report.

Use random search as your default for 3+ hyperparameters and ≥25 trials — it's strictly better in expectation.

Use Bayesian optimization when each trial is very expensive (hours of training) and you can't parallelize.

Python Snippets

# Grid Search (sklearn)
from sklearn.model_selection import GridSearchCV
gs = GridSearchCV(model, param_grid={
'C': [0.01, 0.1, 1, 10, 100], # 5 values
'gamma': [0.001, 0.01, 0.1, 1, 10], # 5 values → 25 trials
}, cv=5)
# Random Search (sklearn)
from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import loguniform
rs = RandomizedSearchCV(model, param_distributions={
'C': loguniform(1e-3, 1e3), # continuous log-uniform
'gamma': loguniform(1e-4, 1e1), # same budget → same 25 trials
'kernel': ['rbf', 'poly'], # extra dim — no extra cost!
'degree': [2, 3, 4, 5], # another dim — still 25 trials
}, n_iter=25, cv=5, random_state=42)

Key Takeaways
▾
✅ Remember These

1. Random search is sample-efficient: \(T\) trials → \(T\) distinct values per axis marginal, regardless of dimension count.

2. Grid search is exponential: adding one dimension multiplies the required budget by \(m\).

3. Bergstra & Bengio's result holds when \(d_e \ll d\) — loss has low effective dimensionality. This is empirically true for nearly all ML models.

4. For truly cheap evaluations and few hyperparameters (e.g., 2), grid search is fine. For 3+, default to random.

5. Both are "embarrassingly parallel" — random search scales perfectly to any compute cluster.
