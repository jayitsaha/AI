1
Understanding BLIP-2
▼

What is it? BLIP-2 connects a huge, already-trained image encoder to a huge, already-trained language model — without touching either one. Both stay frozen (weights untouched, no gradients). The only new piece is a small go-between network called the Q-Former (Querying Transformer) that learns to translate "what's in this image" into a handful of tokens the LLM can read as if they were words.

Analogy: Imagine a brilliant art critic (the frozen vision encoder) who sees every detail of a painting but only speaks "Visual." And a brilliant novelist (the frozen LLM) who can write anything but has never seen a painting and only speaks "English." BLIP-2 hires a translator (the Q-Former) who learns to look at the painting, distill it into a short briefing of exactly 32 index cards, and hand those cards to the novelist as if they were the opening sentences of a story. The critic and novelist never change how they work — only the translator is trained.

One-sentence summary: A lightweight, doubly-attentive transformer with 32 learnable query vectors is trained in two stages to extract the text-relevant visual information a frozen LLM needs, while both the vision encoder and the LLM remain completely frozen.

💡 If you remember one thing

The Q-Former is an information bottleneck by design: however large the image, it is always compressed into a fixed 32 query embeddings before reaching the LLM. Training it (not the giant encoders) is what makes BLIP-2 dramatically cheaper than training a vision-language model from scratch.

2
How the Q-Former Works Internally
▼

The Problem It Solves

Before BLIP-2 (2023), vision-language models like Flamingo either fine-tuned parts of a frozen LLM with adapters, or trained end-to-end multimodal transformers from scratch — both expensive, and both requiring the two modalities to be tightly coupled during training. The modality gap (images live in a continuous pixel/patch space, text lives in a discrete token space) was bridged either by full fine-tuning (costly, risks catastrophic forgetting of the LLM's language ability) or by naively projecting all patch tokens into the LLM (an image can produce 256+ patch tokens — far more expensive per image than a sentence of text, and unstructured).

Architecture: Two Transformers Sharing Self-Attention

The Q-Former consists of two transformer submodules that share the same self-attention layers: an image transformer that interacts with the frozen ViT via cross-attention, and a text transformer that can act as both a text encoder and text decoder. A set of 32 learnable query embeddings (each 768-dim) is the only input to the image side — they are not derived from the image at all; they are trained parameters, like a learned "checklist" of questions to ask any image.

Each Q-Former block: (1) queries self-attend to each other, (2) queries cross-attend into the frozen ViT's patch-grid features every other block, (3) queries pass through a shared feed-forward layer. Text tokens, when present, share the same self-attention layer as the queries — but a attention mask is switched per-objective to control exactly who can see whom.

Design Decision: Why a Fixed 32 Queries and Not All Patch Tokens?

Feeding all ~257 ViT patch tokens (for a 224×224 image with 14×14 patches + CLS) directly into the LLM as a "soft prompt" would be simple, but (a) makes every image cost ~257 LLM context tokens regardless of content, (b) gives the LLM no signal about which visual details matter for the caption/question at hand, and (c) scales poorly to higher resolutions. Forcing the information through 32 trained queries makes the bottleneck the LOCUS of learning: the queries learn to actively extract exactly the visual information that is useful for language, discarding the rest.

🔑 Key Property

The Q-Former is trained in two stages against two different frozen partners — first a frozen image encoder (representation learning), then a frozen LLM (generative learning) — while its own weights and the 32 queries are the only thing ever updated by gradient descent.

Why It Works — The Math
▼

Stage 1 — Vision-Language Representation Learning

Let \(Q \in \mathbb{R}^{32\times d}\) be the query embeddings after passing through the Q-Former, and \(V \in \mathbb{R}^{n\times d}\) the frozen ViT's patch features. Stage 1 jointly optimizes three objectives that all reuse the same shared self-attention stack, distinguished only by the attention mask \(M\):

$$\mathcal{L}_{\text{stage1}} = \mathcal{L}_{\text{ITC}} + \mathcal{L}_{\text{ITM}} + \mathcal{L}_{\text{ITG}}$$

1. Image-Text Contrastive (ITC): queries and text are encoded independently (unimodal mask — queries cannot see text tokens and vice versa). For each of the 32 output query vectors \(q_i\), compute similarity with the text [CLS] embedding \(t\); take the maximum over queries as the image-text similarity, then apply the standard InfoNCE contrastive loss over a batch of size \(N\):

$$s(I,T) = \max_{i \in [1,32]} \; q_i^\top t, \qquad \mathcal{L}_{\text{ITC}} = -\log \frac{\exp(s(I,T)/\tau)}{\sum_{j=1}^N \exp(s(I,T_j)/\tau)}$$

2. Image-Text Matching (ITM): a binary classification — does this image/text pair truly correspond? Uses a bi-directional mask (queries and text tokens freely attend to each other), and each query's output is passed through a 2-class linear head; the 32 per-query logits are averaged:

$$\hat{y} = \sigma\!\left(\frac{1}{32}\sum_{i=1}^{32} w^\top q_i\right), \qquad \mathcal{L}_{\text{ITM}} = -\big[y\log\hat{y} + (1-y)\log(1-\hat{y})\big]$$

3. Image-grounded Text Generation (ITG): generate the caption token-by-token conditioned on the image, using a multimodal causal mask — queries can attend to each other (never to text, so all visual information must be squeezed through the fixed 32 slots) and each text token can attend to all queries plus previous text tokens only:

Because \(V\) comes from a frozen encoder, gradients from all three losses flow only into the Q-Former's parameters and the 32 query embeddings — never into the vision backbone.

Stage 2 — Vision-to-Language Generative Bridging

After stage 1, the 32 query outputs \(Q \in \mathbb{R}^{32\times d}\) (\(d{=}768\)) are known to be text-aligned. Stage 2 discards the ITC/ITM heads and adds a single trainable linear projection \(W_{\text{proj}} \in \mathbb{R}^{d \times d_{\text{LLM}}}\) mapping each query into the frozen LLM's embedding dimension \(d_{\text{LLM}}\) (e.g. 2560–4096):

$$E_{\text{visual}} = Q\,W_{\text{proj}} \in \mathbb{R}^{32 \times d_{\text{LLM}}}$$

These 32 vectors are prepended as a fixed-length "soft visual prompt" to the frozen LLM's input embedding sequence. Training minimizes the LLM's ordinary language-modeling loss (decoder-only, e.g. OPT) or prefix-conditioned denoising loss (encoder-decoder, e.g. FlanT5) on the target caption — but backpropagation stops at the LLM's input embeddings; only \(W_{\text{proj}}\) and the Q-Former are updated:

⚠️ Common Pitfall

Because the LLM is frozen and never sees gradient signal about images during pretraining, stage 2 only works if stage 1 already made the query embeddings linearly close to something language-like. Skipping stage 1 and training stage 2 from scratch converges far worse — the representation-learning stage is what makes the bottleneck useful rather than just small.

Key Takeaways
▼

When BLIP-2's recipe shines:

  • You already have a strong pretrained vision encoder (e.g. CLIP ViT-L/g) and a strong pretrained LLM (e.g. OPT, FlanT5) and want to connect them cheaply
  • Compute budget is limited — BLIP-2 trains ~188M parameters vs. billions for end-to-end multimodal pretraining, and needs far fewer image-text pairs
  • You want a fixed, small, resolution-independent visual token budget (32 tokens) regardless of image size — good for long-context LLMs handling many images
  • Zero-shot image captioning / VQA / instruction-following on images is the target use case

Limitations to know:

  • The 32-query bottleneck can lose fine-grained spatial/detail information — dense tasks like segmentation or precise counting suffer
  • In-context few-shot learning is weaker than Flamingo-style models, because the frozen LLM never sees interleaved image-text training data
  • Quality is capped by the frozen backbones — the Q-Former cannot fix a weak vision encoder or a weak LLM, only bridge good ones
💡 Lineage

CLIP (frozen-ready vision encoder) → BLIP (unified encoder-decoder with ITC+ITM+captioning, but no frozen-LLM bridging) → BLIP-2 (adds the Q-Former as a trainable bridge between frozen encoder and frozen LLM) → InstructBLIP (instruction-tuned Q-Former, extracts instruction-aware visual features) → LLaVA / Flamingo (alternative bridging strategies: simple linear projection of all patch tokens, or gated cross-attention layers inserted into the LLM).

import torch, torch.nn as nn
# --- Frozen backbones (never receive gradients) ---
vit = FrozenViT() # e.g. CLIP/EVA ViT-g, .requires_grad_(False)
llm = FrozenLLM() # e.g. OPT-2.7B / FlanT5-XL, .requires_grad_(False)
# --- Trainable Q-Former ---
queries = nn.Parameter(torch.randn(32, 768)) # the only image-side input
qformer = QFormer(num_layers=12, cross_attn_every=2)
# === STAGE 1: representation learning vs frozen ViT ===
patch_feats = vit(image) # [n_patches, 768], no grad
q_out = qformer(queries, patch_feats, mask='unimodal') # ITC branch
t_out = qformer(text_tokens, mask='unimodal')
loss_itc = contrastive_loss(q_out.max_sim(t_out.cls))
q_out_bi = qformer(queries, patch_feats, text_tokens, mask='bidirectional')
loss_itm = bce_loss(itm_head(q_out_bi.mean(0)), match_label)
q_out_causal = qformer(queries, patch_feats, text_tokens, mask='mm_causal')
loss_itg = cross_entropy(lm_head(q_out_causal.text_part), caption_tokens)
loss_stage1 = loss_itc + loss_itm + loss_itg # backprop -> qformer, queries ONLY
# === STAGE 2: generative bridging into frozen LLM ===
proj = nn.Linear(768, llm.embed_dim) # new trainable bridge
Q = qformer(queries, vit(image), mask='unimodal') # [32, 768], stage-1 weights
visual_prompt = proj(Q) # [32, d_llm] soft prompt
inputs_embeds = torch.cat([visual_prompt, llm.embed(text_prefix)], dim=0)
logits = llm(inputs_embeds=inputs_embeds) # frozen forward pass
loss_stage2 = cross_entropy(logits, target_tokens)
loss_stage2.backward() # gradient flows through llm (no update) into proj & qformer
