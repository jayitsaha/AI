Understanding Similarity Search
▼

What is it? Similarity search, often called Nearest Neighbor (NN) search, is the task of finding data points (vectors) in a dataset that are "most similar" to a given query point. This is fundamental to many modern AI applications: recommending products, finding visually similar images, retrieving relevant documents, or powering semantic search engines. The core idea is to represent items as high-dimensional vectors (embeddings) and then quantify their closeness.

Analogy: Imagine you have a vast music library, and you want to find songs "like" your current favorite track. A similarity search system would represent each song as a vector based on its genre, tempo, instrumentation, and lyrical themes. When you input your favorite song (the query vector), the system calculates how "close" its vector is to every other song's vector in the library. The closest ones are your recommendations. The challenge is doing this efficiently when your library has millions of songs, each with hundreds of dimensions!

💡 If you remember one thing

Similarity search relies on converting items into high-dimensional numerical vectors (embeddings). The "similarity" between these vectors is then measured using specific mathematical metrics (like cosine similarity or L2 distance). For very large datasets, exact search is too slow, so Approximate Nearest Neighbor (ANN) algorithms are used to find "good enough" matches much faster.

2
Core Similarity Metrics
▼

The choice of similarity metric critically defines what "similar" means. Different metrics emphasize different aspects of vector relationships:

1. Cosine Similarity

Measures the cosine of the angle between two vectors. It ranges from -1 (opposite directions) to 1 (same direction), with 0 indicating orthogonality. Cosine similarity is insensitive to vector magnitude; two vectors pointing in the same direction are maximally similar even if one is much longer than the other. This makes it ideal for text embeddings where the "topic" (direction) is more important than the "length" (e.g., word count or frequency).

2. Euclidean (L2) Distance

Measures the straight-line distance between the endpoints of two vectors. It ranges from 0 (identical vectors) to infinity. L2 distance is sensitive to both direction and magnitude. Two vectors pointing in the same direction but with different lengths will have a large L2 distance. It's often used when the absolute difference in feature values is meaningful, such as in geographic coordinates or physical measurements.

3. Inner Product (Dot Product)

Calculated as the sum of the products of corresponding components of two vectors. It ranges from negative infinity to positive infinity. The inner product is high when vectors are both large in magnitude AND point in similar directions. If vectors are normalized (unit length), the inner product is identical to cosine similarity. It's often used in recommendation systems where both preference strength (magnitude) and item alignment (direction) are important.

🔑 Key Relationship

For unit vectors (normalized to length 1), Euclidean distance and Inner Product are directly related to Cosine Similarity. Specifically, if vectors \(A\) and \(B\) are unit vectors, then \(A \cdot B = \text{cos}(\theta)\) and \(d(A,B)^2 = \|A-B\|^2 = \|A\|^2 + \|B\|^2 - 2A \cdot B = 1 + 1 - 2\text{cos}(\theta) = 2 - 2\text{cos}(\theta)\). Thus, for normalized vectors, minimizing L2 distance is equivalent to maximizing cosine similarity.

3
Why It Works — The Math
▼

Mathematical Definitions

Given two \(D\)-dimensional vectors \(A = [A_1, \dots, A_D]\) and \(B = [B_1, \dots, B_D]\):

$$\text{Cosine Similarity}(A, B) = \frac{A \cdot B}{\|A\| \|B\|} = \frac{\sum_{i=1}^D A_i B_i}{\sqrt{\sum_{i=1}^D A_i^2} \sqrt{\sum_{i=1}^D B_i^2}}$$
$$\text{Euclidean (L2) Distance}(A, B) = \|A - B\|_2 = \sqrt{\sum_{i=1}^D (A_i - B_i)^2}$$
$$\text{Inner Product}(A, B) = A \cdot B = \sum_{i=1}^D A_i B_i$$

The Curse of Dimensionality & ANN

In low dimensions (like 2D or 3D), our intuition about distance works well. However, in high-dimensional spaces (common for embeddings, e.g., 768 or 1536 dimensions), the "curse of dimensionality" makes exact nearest neighbor search infeasible. The volume of the space grows exponentially with dimension, making data points sparse. Distances between points tend to become very similar, losing discriminative power. A naive linear scan (comparing the query vector to every single data vector) becomes prohibitively slow for large datasets (\(O(N \cdot D)\) complexity, where \(N\) is dataset size and \(D\) is dimensionality).

This is where Approximate Nearest Neighbor (ANN) algorithms come in. Instead of guaranteeing the absolute closest point, they aim to find a "good enough" nearest neighbor very quickly, often with \(O(D \log N)\) or even \(O(D)\) complexity. They achieve this by structuring the data in ways that allow fast pruning of large parts of the search space.

⚠️ No Free Lunch

ANN algorithms trade off perfect accuracy for speed. There's always a recall-latency trade-off: higher recall (finding more true nearest neighbors) usually means higher latency (slower search). The choice of ANN algorithm and its parameters depends on the specific application's requirements for speed vs. accuracy.

Key Takeaways
▼

Choosing the Right Metric:

  • Cosine Similarity: Best when vector direction (e.g., semantic meaning) is more important than magnitude. Common for text embeddings (BERT, Word2Vec) and image features. Often requires vector normalization.
  • Euclidean (L2) Distance: Best when the absolute difference in feature values, including magnitude, is meaningful. Suitable for physical coordinates, or when all dimensions are equally important and scaled.
  • Inner Product: Best when both direction and magnitude contribute to "relevance." Often used in recommendation systems (e.g., user-item interaction scores) where a strong positive preference (large magnitude) for a similar item (similar direction) is desired.

When to use ANN:

  • Large Datasets: When \(N\) (number of data points) is in the thousands, millions, or billions, exact linear search is too slow.
  • High Dimensionality: When \(D\) (number of dimensions) is in the hundreds or thousands, the curse of dimensionality makes exact search inefficient and even less meaningful.
  • Real-time Requirements: For interactive applications like search and recommendation, latency is critical, making approximation necessary.

ANN Algorithms: HNSW vs. IVF (and friends):

  • IVF (Inverted File Index): A clustering-based approach. Data points are grouped into clusters, and only a few relevant clusters are searched at query time. Fast for very large \(N\), but recall can suffer if clusters are not well-defined or if the true nearest neighbor is in an unsearched cluster.
  • HNSW (Hierarchical Navigable Small World): A graph-based approach. Builds a multi-layer graph where each layer connects points at different "distances." Search starts at a coarse layer and navigates to finer layers. Known for excellent recall-latency trade-offs and is a popular choice for many production systems.
  • Other popular methods include LSH (Locality Sensitive Hashing) for very high dimensions and Product Quantization (PQ) for memory efficiency.
💡 Big Picture

The entire field of similarity search is a masterclass in engineering trade-offs: choosing the right vector representation, the right metric for "similarity", and the right approximate algorithm to balance speed, memory, and accuracy for your specific use case. There's no single "best" solution, only the most appropriate one.

import numpy as np
from sklearn.cluster import MiniBatchKMeans
# Example vectors
query_vec = np.array([0.5, 0.8])
data_vecs = np.array([[0.6, 0.9], [1.2, 0.1], [-0.3, 0.7], [0.5, -0.6]])
# 1. Cosine Similarity
def cosine_similarity(a, b):
dot_product = np.dot(a, b)
norm_a = np.linalg.norm(a)
norm_b = np.linalg.norm(b)
if norm_a == 0 or norm_b == 0: return 0.0
return dot_product / (norm_a * norm_b)
# 2. Euclidean (L2) Distance
def euclidean_distance(a, b):
return np.linalg.norm(a - b)
# 3. Inner Product
def inner_product(a, b):
return np.dot(a, b)
# Calculate for all data vectors
cos_sims = [cosine_similarity(query_vec, dv) for dv in data_vecs]
l2_dists = [euclidean_distance(query_vec, dv) for dv in data_vecs]
inner_prods = [inner_product(query_vec, dv) for dv in data_vecs]
# Approximate Nearest Neighbor (ANN) - IVF conceptual example
def ivf_search_conceptual(query, data, n_clusters=3, n_probe=1):
kmeans = MiniBatchKMeans(n_clusters=n_clusters, random_state=0, n_init=10)
kmeans.fit(data)
# Find nearest centroids to query
centroid_dists = [euclidean_distance(query, c) for c in kmeans.cluster_centers_]
nearest_centroid_indices = np.argsort(centroid_dists)[:n_probe]
# Search only within selected clusters
candidate_indices = []
for idx in nearest_centroid_indices:
cluster_points_indices = np.where(kmeans.labels_ == idx)[0]
candidate_indices.extend(cluster_points_indices)
# Perform exact search on candidates
candidate_data = data[candidate_indices]
if len(candidate_data) == 0: return []
distances = [euclidean_distance(query, cp) for cp in candidate_data]
# Return global indices of top K from candidates
sorted_candidate_local_indices = np.argsort(distances)
return [candidate_indices[i] for i in sorted_candidate_local_indices]
