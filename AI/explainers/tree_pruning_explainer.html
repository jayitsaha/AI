Decision Tree Pruning

Pre-pruning (early stopping) vs. Post-pruning (cost-complexity / minimal cost-complexity)
Intermediate Classical ML Decision Trees O(n · |T|)
1
Understanding Pruning
▼

What is it? A decision tree grown to full depth memorises every training sample — it overfits. Pruning controls complexity. Pre-pruning (early stopping) stops splitting early via constraints like max_depth, min_samples_split, or a minimum information-gain threshold. Post-pruning grows the full tree first, then systematically collapses internal nodes back into leaves using held-out data or cross-validation.

Why two strategies? Pre-pruning is fast and simple but myopic — a split that looks useless now might enable a crucial split two levels down ("horizon effect"). Post-pruning sees the whole tree before deciding what to cut, so it tends to produce better solutions at the cost of growing the full tree first.

If you remember one thing

Cost-complexity pruning solves $$\underset{T \subseteq T_{\max}}{\min}\; R(T) + \alpha |T|$$ where \(R(T)\) is misclassification rate, \(|T|\) is the number of leaves, and \(\alpha \geq 0\) is the complexity penalty. Increasing \(\alpha\) collapses weak subtrees one by one, yielding a nested sequence of trees; cross-validation picks the optimal \(\alpha\).

How Pruning Works Internally
▼

Pre-pruning: Stop-Early Criteria

Before making a split, the learner checks a set of guards. The split is rejected if any guard fires:

  • max_depth: current node depth \(\geq d_{\max}\) — hard depth cap.
  • min_samples_split: fewer than \(m_{\text{split}}\) samples reach this node.
  • min_samples_leaf: the best split would create a child with fewer than \(m_{\text{leaf}}\) samples.
  • min_impurity_decrease: best achievable gain \(\Delta I < \delta\) — a gain threshold. In terms of Gini or entropy: $$\Delta I(s,t) = I(t) - \frac{n_L}{n_t}I(t_L) - \frac{n_R}{n_t}I(t_R) < \delta$$

Pre-pruning is a greedy heuristic: it can stop too early (horizon effect) or too late (if \(\delta\) is poorly calibrated). It is, however, very fast — \(O(n \log n)\) per feature.

Post-pruning: Minimal Cost-Complexity (Breiman et al., 1984)

Grow the full tree \(T_{\max}\) first. For any internal node \(t\), define:

$$\alpha_{\text{eff}}(t) = \frac{R(t) - R(T_t)}{|T_t| - 1}$$

where \(R(t)\) is the error if \(t\) is pruned to a leaf, \(R(T_t)\) is the error of the subtree rooted at \(t\), and \(|T_t|\) is the number of leaves in that subtree. \(\alpha_{\text{eff}}(t)\) is the minimum penalty at which pruning \(t\) becomes preferable to keeping it. The weakest-link rule: always prune the node with the smallest \(\alpha_{\text{eff}}\) first.

This produces a sequence \(T_{\max} = T_0 \supset T_1 \supset \cdots \supset T_{\text{root}}\), and a corresponding sequence \(0 = \alpha_0 \leq \alpha_1 \leq \cdots\). Cross-validation then selects the \(\alpha^*\) that minimises validation error, and the corresponding \(T_k\) is returned.

Key Property: Nested Sequence

For any \(\alpha\), the optimal subtree of \(T_{\max}\) is one of the trees in the finite nested sequence \(\{T_k\}\). Exhaustive search over all subtrees is NP-hard, but the weakest-link algorithm finds the exact answer in \(O(|T_{\max}|^2)\).

3
The Math — Cost-Complexity Derivation
▼

Objective Function

For a penalty \(\alpha \geq 0\) define the cost-complexity criterion for tree \(T\):

$$R_\alpha(T) = R(T) + \alpha |T|$$

where \(R(T) = \frac{1}{n}\sum_{t \in \tilde{T}} n_t \cdot r(t)\), \(\tilde{T}\) is the set of leaves, and \(r(t)\) is the node misclassification rate \(1 - \max_k p(k|t)\). The goal is \(\hat{T}(\alpha) = \arg\min_{T \subseteq T_{\max}} R_\alpha(T)\).

When Is It Worth Pruning Node t?

Compare keeping the subtree \(T_t\) vs. collapsing \(t\) to a leaf:

$$R_\alpha(t) = R(t) + \alpha \quad \leq \quad R_\alpha(T_t) = R(T_t) + \alpha |T_t|$$

Rearranging: pruning is preferred when

$$\alpha \leq \frac{R(t) - R(T_t)}{|T_t| - 1} = \alpha_{\text{eff}}(t)$$

At exactly \(\alpha = \alpha_{\text{eff}}(t)\), the pruned and unpruned versions tie; for \(\alpha > \alpha_{\text{eff}}(t)\), pruning wins strictly.

Weakest-Link Selection

At each step, compute \(\alpha_{\text{eff}}(t)\) for all internal nodes. Prune the node achieving the minimum — the "weakest link." Let \(g_1 = \min_t \alpha_{\text{eff}}(t)\). After pruning those nodes, recompute on the smaller tree to find \(g_2\), and so on. The resulting sequence satisfies \(g_1 \leq g_2 \leq \cdots\) and partitions \([0, \infty)\) into intervals where \(\hat{T}(\alpha)\) is constant.

Numerical Example (Concrete)

Suppose the full tree \(T_{\max}\) has 5 leaves and \(n=20\) samples with total errors \(= 5\), so \(R(T_{\max}) = 0.25\). For a subtree covering leaves \(\{L_4, L_5\}\) (4+4 samples, 3 combined errors if pruned):

$$\alpha_{\text{eff}} = \frac{3/20 - (2+1)/20}{2 - 1} = \frac{0.15 - 0.15}{1} = 0.000$$

This subtree costs nothing to prune — its leaves give identical error to the merged leaf. It is pruned first (at \(\alpha = 0\)). Another subtree covering \(\{L_1, L_2, L_3\}\) gives \(\alpha_{\text{eff}} = 0.075\); pruned second. The full sequence: \(\alpha_0 = 0 \to 5\) leaves, \(\alpha_1 = 0.075 \to 3\) leaves, \(\alpha_2 = 0.100 \to 2\) leaves.

Common Pitfall

\(R(T)\) here uses training error. Relying on training error alone always prefers the full tree (\(\alpha = 0\)). The entire point is to use \(\alpha\) as a surrogate for test complexity, then pick \(\alpha^*\) via cross-validation on a held-out set.

Key Takeaways
▼

Pre-pruning vs. Post-pruning at a glance

  • Pre-pruning: Fast, tunable via intuitive hyperparameters, but suffers from the horizon effect — may miss splits that only become useful deeper in the tree.
  • Post-pruning (CCP): Globally optimal within the nested sequence; CV-driven; default in scikit-learn 0.22+ via ccp_alpha. Costs one full tree build.

Practical rules

  • Start with max_depth=3–5 and min_samples_leaf=5 for quick experiments.
  • For production use DecisionTreeClassifier.cost_complexity_pruning_path() to get \(\alpha\) candidates, then grid-search with CV.
  • In Random Forests, individual trees are intentionally grown deep (no pruning) because bagging handles variance.
Decision Rule

Use pre-pruning when training time is critical (large datasets, real-time refit). Use post-pruning when you want the best single tree and can afford the cost of growing \(T_{\max}\) first. In sklearn, set ccp_alpha to the value from CV.

Code Trace
▼
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import cross_val_score
import numpy as np
# 1. Pre-pruning: constrain at fit time
clf_pre = DecisionTreeClassifier(
max_depth=4, # hard depth cap
min_samples_split=10, # must have ≥10 samples to split
min_samples_leaf=5, # each child must have ≥5 samples
min_impurity_decrease=0.01 # gain threshold δ
)
clf_pre.fit(X_train, y_train)
# 2. Post-pruning: grow full tree then get alpha path
clf_full = DecisionTreeClassifier(random_state=0)
clf_full.fit(X_train, y_train)
path = clf_full.cost_complexity_pruning_path(X_train, y_train)
alphas = path.ccp_alphas # [0, alpha_1, alpha_2, ..., alpha_max]
# 3. CV over alpha sequence
cv_scores = []
for alpha in alphas:
clf = DecisionTreeClassifier(ccp_alpha=alpha, random_state=0)
scores = cross_val_score(clf, X_train, y_train, cv=5)
cv_scores.append(scores.mean())
# 4. Pick best alpha
best_alpha = alphas[np.argmax(cv_scores)]
clf_pruned = DecisionTreeClassifier(ccp_alpha=best_alpha).fit(X_train, y_train)
print(f"Leaves: {clf_pruned.get_n_leaves()}, Test acc: {clf_pruned.score(X_test, y_test):.3f}")
