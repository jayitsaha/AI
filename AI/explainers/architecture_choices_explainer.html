1
Understanding Transformer Architecture Decisions
▼

What are these choices? The Transformer architecture, foundational to modern AI, offers key design knobs: (1) whether to use an encoder-decoder, encoder-only, or decoder-only structure; (2) the number of layers (depth) versus the model dimension (width); and (3) the expansion ratio of the intermediate Feed-Forward Network (FFN) layers. These choices profoundly impact a model's capabilities, computational cost, and memory footprint.

Analogy: Think of designing a complex building. The architecture type (e.g., a single-tower residential, a multi-wing office, or a factory with a single assembly line) dictates its fundamental purpose. The number of floors (layers) and the area per floor (model dimension) determine its overall scale and capacity. The size of utility rooms and internal infrastructure (FFN ratio) affects how efficiently work is processed on each floor. Every decision has trade-offs in cost, construction time, and functionality.

💡 If you remember one thing

Modern large language models (LLMs) are almost exclusively decoder-only. Their performance and efficiency are then primarily tuned by balancing depth (layers) and width (model dimension), and optimizing the FFN expansion ratio — which together define the total parameter count and computational cost.

2
How These Choices Shape a Model
▼

Decoder-Only Dominance for Generative AI

The original Transformer model (Vaswani et al., 2017) had an encoder-decoder structure, ideal for sequence-to-sequence tasks like translation. Encoder-only models (e.g., BERT) are great for understanding existing text (classification, QA). However, for generative tasks like text completion, summarization, and dialogue, decoder-only architectures (e.g., GPT series, Llama) have become dominant. They simplify the architecture by removing the encoder, relying solely on the decoder stack. A key feature is causal masking in self-attention, ensuring that predictions for a token can only attend to previous tokens, making them inherently suitable for autoregressive generation.

Layer Count (Depth) vs. Model Dimension (Width)

These two parameters, \(L\) (number of layers) and \(d_{model}\) (dimension of token embeddings and internal representations), are the primary drivers of model capacity.

  • Depth (L): More layers allow the model to learn more hierarchical and abstract representations. Each layer can build upon the features learned by the previous one, potentially capturing longer-range dependencies and complex semantic structures. However, very deep networks can be harder to train (optimization challenges, though mitigated by residual connections and LayerNorm).
  • Width (\(d_{model}\)): A larger model dimension means each token's representation is richer, carrying more information. Wider networks can process more features in parallel within each layer, potentially leading to a more comprehensive understanding of the input. Wider models often require more memory and computation per layer but can be more efficient at capturing diverse patterns in a single pass.
Scaling laws (e.g., Kaplan et al., 2020) often suggest that increasing both depth and width is beneficial, with specific trade-offs depending on the available compute budget.

FFN Ratio (Intermediate Dimension Expansion)

Within each Transformer block, after the Multi-Head Attention (MHA) sub-layer, there is a Feed-Forward Network (FFN). This FFN typically consists of two linear transformations with a non-linearity (e.g., GELU) in between. The intermediate dimension of this FFN is often a multiple of \(d_{model}\), commonly \(4 \times d_{model}\). This "FFN ratio" (e.g., 4) allows the model to expand the representation locally, perform non-linear transformations, and then project it back to \(d_{model}\). A larger FFN ratio increases the capacity for local feature transformation, but also significantly adds to the parameter count and computational cost of each block.

🔑 Key Property

The choice between depth and width, along with the FFN ratio, is a resource allocation problem. Depth often enables more complex reasoning, while width allows for richer representations. The FFN ratio controls the "processing power" within each block, offering a tunable trade-off between computational intensity and representational flexibility.

Why It Works — Parameter Counts & Cost
▼

Parameter Counting in a Decoder-Only Transformer

Let \(L\) be the number of decoder layers, \(d_{model}\) be the model dimension, \(d_{ff}\) be the FFN intermediate dimension, and \(V\) be the vocabulary size. We assume \(d_{ff} = \text{FFN\_Ratio} \times d_{model}\).

1. Input Embeddings: The token embeddings and often positional embeddings (if learnable) contribute significantly. If positional embeddings are learnable, they add \(S_{max} \times d_{model}\) parameters (where \(S_{max}\) is max sequence length). For simplicity, we'll count only token embeddings here.

$$P_{emb} = V \times d_{model}$$

2. Multi-Head Self-Attention (per block): For each attention head, queries (Q), keys (K), and values (V) are projected from \(d_{model}\) to \(d_k = d_{model} / N_{heads}\). There are \(N_{heads}\) heads. The output of the heads is then concatenated and projected back to \(d_{model}\). This involves 4 linear layers:

  • \(W_Q, W_K, W_V\) (for Q, K, V): \(3 \times d_{model} \times d_{model}\)
  • \(W_O\) (output projection): \(d_{model} \times d_{model}\)
$$P_{MHA\_block} = 4 \times d_{model}^2$$

3. Feed-Forward Network (per block): This consists of two linear layers. The first projects from \(d_{model}\) to \(d_{ff}\), and the second projects from \(d_{ff}\) back to \(d_{model}\).

  • First linear layer: \(d_{model} \times d_{ff}\)
  • Second linear layer: \(d_{ff} \times d_{model}\)
$$P_{FFN\_block} = 2 \times d_{model} \times d_{ff} = 2 \times \text{FFN\_Ratio} \times d_{model}^2$$

4. Layer Normalization (per block): Each block typically has two LayerNorm layers (after MHA, after FFN). Each LayerNorm has two learnable parameters per dimension (gain and bias).

$$P_{LN\_block} = 2 \times (2 \times d_{model}) = 4 \times d_{model}$$

5. Output Layer: A final linear layer projects the last decoder block's output to the vocabulary size for token prediction.

$$P_{output} = d_{model} \times V$$

Total Learnable Parameters: Summing these up:

$$P_{total} = P_{emb} + L \times (P_{MHA\_block} + P_{FFN\_block} + P_{LN\_block}) + P_{output}$$ $$P_{total} = (V \times d_{model}) + L \times (4 d_{model}^2 + 2 \times \text{FFN\_Ratio} \times d_{model}^2 + 4 d_{model}) + (d_{model} \times V)$$

Computational Cost (FLOPs)

The FLOPs (floating point operations) roughly scale quadratically with \(d_{model}\) and linearly with \(L\). For self-attention, it's \(O(S^2 \cdot d_{model})\) where \(S\) is sequence length, and for FFN it's \(O(S \cdot d_{model}^2 \cdot \text{FFN\_Ratio})\). For very long sequences, attention dominates. For shorter sequences and large \(d_{model}\), FFN can dominate. This explains why both depth and width contribute heavily to compute cost.

⚠️ Nuance in Parameter Counting

The actual parameter count can vary slightly based on implementation details (e.g., shared embeddings/output weights, bias terms in linear layers, specific LayerNorm variants). The formulas above provide a strong approximation of the major contributors.

Key Takeaways
▼

When to choose which architecture:

  • Decoder-only: The default for modern LLMs and generative tasks (text generation, chatbots, code completion). Simpler, highly scalable, and naturally autoregressive.
  • Encoder-decoder: Best for sequence-to-sequence tasks where the input and output sequences are distinct (e.g., machine translation, summarization from scratch).
  • Encoder-only: Ideal for understanding and encoding input text for tasks like classification, sentiment analysis, or information retrieval (e.g., BERT-style models).

Balancing Depth (L) vs. Width (\(d_{model}\)):

  • Deeper (more L): Can learn more abstract, hierarchical features; potentially better for complex reasoning and long-range dependencies. Can be harder to optimize.
  • Wider (larger \(d_{model}\)): Richer representations per token; better for capturing diverse patterns. Higher memory footprint and computational cost per layer.
  • Scaling Laws: Empirical evidence suggests that for a fixed compute budget, there's an optimal balance, often favoring wider models for smaller budgets and deeper models for larger budgets, but this is an active area of research. In practice, both are scaled up simultaneously.

FFN Ratio:

  • The standard 4x expansion (e.g., \(d_{ff} = 4 \times d_{model}\)) is a widely adopted heuristic. It offers a good balance between local transformation capacity and computational cost.
  • Deviating from 4x (e.g., 2x or 8x) can be explored, but often requires careful tuning and may not yield significant gains over the standard. It directly impacts the parameter count and FLOPs quadratically with \(d_{model}\).
💡 The Future of Scaling

As models continue to grow, architectural choices become even more critical. Innovations in sparse attention, Mixture-of-Experts (MoE) layers, and alternative FFN structures are all attempts to break the quadratic scaling bottlenecks and find more efficient architectures for the next generation of AI.

import torch.nn as nn
class MultiHeadSelfAttention(nn.Module):
def __init__(self, d_model, num_heads):
super().__init__()
self.q_proj = nn.Linear(d_model, d_model)
self.k_proj = nn.Linear(d_model, d_model)
self.v_proj = nn.Linear(d_model, d_model)
self.out_proj = nn.Linear(d_model, d_model)
# Params: 4 * d_model * d_model
class FeedForward(nn.Module):
def __init__(self, d_model, ffn_ratio):
super().__init__()
d_ff = int(d_model * ffn_ratio)
self.linear1 = nn.Linear(d_model, d_ff)
self.linear2 = nn.Linear(d_ff, d_model)
# Params: 2 * d_model * d_ff = 2 * d_model * (ffn_ratio * d_model)
class DecoderBlock(nn.Module):
def __init__(self, d_model, num_heads, ffn_ratio):
super().__init__()
self.attn = MultiHeadSelfAttention(d_model, num_heads)
self.norm1 = nn.LayerNorm(d_model) # Params: 2 * d_model (weight, bias)
self.ffn = FeedForward(d_model, ffn_ratio)
self.norm2 = nn.LayerNorm(d_model) # Params: 2 * d_model (weight, bias)
# Total block params: 4*d_model^2 + 2*ffn_ratio*d_model^2 + 4*d_model
class DecoderOnlyTransformer(nn.Module):
def __init__(self, vocab_size, d_model, num_layers, num_heads, ffn_ratio):
super().__init__()
self.token_embeddings = nn.Embedding(vocab_size, d_model)
self.pos_embeddings = nn.Embedding(2048, d_model) # Example max_seq_len
self.layers = nn.ModuleList([
DecoderBlock(d_model, num_heads, ffn_ratio) for _ in range(num_layers)
])
self.final_norm = nn.LayerNorm(d_model)
self.lm_head = nn.Linear(d_model, vocab_size) # Output projection
# Total parameters calculation (simplified, excluding biases in linear layers)
# P_emb = vocab_size * d_model + max_seq_len * d_model
# P_block = (4 + 2*ffn_ratio) * d_model^2 + 4*d_model
# P_total = P_emb + num_layers * P_block + 2*d_model (final_norm) + d_model * vocab_size
