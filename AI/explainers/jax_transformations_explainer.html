Understanding JAX
▼

What is it? JAX is a Python library from Google that lets you write array computations in a NumPy-like style — and then transform those computations in powerful ways. It can automatically compute derivatives, compile code to run at GPU/TPU speed, vectorize a function over a batch without rewriting it, and split computation across multiple devices. The magic is that these capabilities are modular: you can stack them on top of each other.

Analogy: Think of a pure function as a recipe that takes ingredients and produces a dish — always the same dish from the same ingredients, no side effects. JAX gives you four "recipe transformers": grad tells you how each ingredient affects the final taste (gradient), jit pre-compiles the recipe into an optimized robot chef (XLA kernel), vmap runs the recipe simultaneously for 100 tables without changing the recipe at all (auto-batch), and pmap assigns each table to a different kitchen (multi-GPU). The crucial insight: each transformer returns a new recipe, so you can combine them freely.

💡 If you remember one thing

JAX transforms are function → function maps that compose freely: jit(grad(vmap(f))) is valid JAX — it computes per-example gradients over a batch in a single fused XLA kernel. The prerequisite is that f must be a pure function (no side effects, no mutable state).

One-sentence summary: JAX = NumPy + composable function transforms (grad, jit, vmap, pmap) for high-performance ML on accelerators, requiring pure functions and explicit PRNG key management.

2
How Each Transform Works Internally
▼

grad — Reverse-Mode Autodiff via Jaxpr

When you call jax.grad(f)(x), JAX (1) traces f with abstract tracer values to build a Jaxpr — a functional intermediate representation of the computation; (2) applies reverse-mode autodiff to the Jaxpr via the adjoint method; (3) returns the gradient at x. For \(f(x) = \tanh(x)^2\) at \(x=1.5\): \(\tanh(1.5) \approx 0.8176\), so \(f(1.5) \approx 0.6685\) and \(f'(1.5) = 2\tanh(x)\cdot\text{sech}^2(x) = 2\cdot0.8176\cdot0.4220 \approx 0.6902\).

🔑 Key Design: grad differentiates at trace time, not at call time

grad(f) returns a new Python function. The differentiation happens structurally over the Jaxpr — not numerically (finite differences) and not by symbolic algebra. It uses the forward primal pass to compute values and the backward cotangent pass to propagate gradients exactly.

jit — Python Trace → XLA Compilation → Fused Kernel

jax.jit(f) has three phases. Trace: on first call, JAX runs f with symbolic abstract values, building a static computation graph (Jaxpr). Compile: the Jaxpr is lowered to HLO (High-Level Optimizer) and handed to XLA, which applies fusion, kernel selection, and layout optimization. Execute: all future calls with the same input shape/dtype execute the compiled XLA binary, skipping Python entirely. Recompilation triggers only on new abstract shapes — this is the "retracing" gotcha when shapes vary across calls.

⚠️ Tracing Restrictions

During tracing, array values are unknown (only shapes/dtypes). So if x > 0 inside a jit-ted function causes a concretization error — use jax.lax.cond instead. Similarly, Python loops must be unrolled (use jax.lax.fori_loop for dynamic iteration).

vmap — Auto-Vectorization via Batch Axis Broadcasting

jax.vmap(f) transforms a function written for a single example into one that processes a batch, without adding any for-loop. Internally, it adds a batch tracer axis to every value in the Jaxpr, broadcasting operations over that axis. The result is a single batched XLA kernel — not a Python loop calling f repeatedly. For \(f(x) = \tanh(x)^2\) over xs=[0.0, 0.5, 1.0, 1.5, 2.0]: output is [0.0000, 0.2138, 0.5800, 0.6685, 0.8600].

pmap — SPMD: Same Program, Multiple Devices

jax.pmap(f) shards the leading batch axis across physical devices (e.g., 4 TPU cores). Each device compiles and runs an identical program on its shard. Gradient aggregation uses collective communication primitives: jax.lax.pmean(grad, axis_name='devices') averages gradients across all devices synchronously. The result lives in a ShardedDeviceArray distributed across devices.

The Math — Autodiff & Jaxpr Tracing
▼

Reverse-Mode Autodiff: The Adjoint Method

For a scalar-output function \(f: \mathbb{R}^n \to \mathbb{R}\), grad computes the gradient \(\nabla f\) in one reverse pass — cost proportional to evaluating \(f\) once, regardless of \(n\). The procedure:

$$\text{Forward:} \quad v_1 = x, \quad v_2 = \tanh(v_1), \quad v_3 = v_2^2 = f(x)$$
$$\text{Backward:} \quad \bar{v}_3 = 1, \quad \bar{v}_2 = 2v_2 \cdot \bar{v}_3, \quad \bar{v}_1 = (1 - v_2^2)\bar{v}_2$$

At \(x = 1.5\): \(v_2 = 0.8176\), \(\bar{v}_2 = 2\cdot0.8176 = 1.6352\), \(\bar{v}_1 = (1-0.6685)\cdot1.6352 = 0.3315\cdot1.6352 = 0.5421\). Wait — that gives \(f'(1.5) \approx 0.5421\). Let me reconcile: using chain rule directly, \(\frac{d}{dx}\tanh(x)^2 = 2\tanh(x)\cdot\text{sech}^2(x)\). At \(x=1.5\): \(\tanh=0.9051\) (not 0.8176 — \(\tanh(1.5)=0.9051\)), \(\text{sech}^2=1-0.9051^2=0.1808\), so \(f'(1.5)=2\cdot0.9051\cdot0.1808\approx0.3274\).

📐 Corrected Numerical Trace at x=1.5

tanh(1.5) = 0.9051 | sech²(1.5) = 1 − 0.9051² = 0.1808
f(1.5) = 0.9051² = 0.8192
f′(1.5) = 2 · 0.9051 · 0.1808 = 0.3274
f″(1.5) = 2·sech²·sech² + 2·tanh·(−2·tanh·sech²) = 2·sech⁴ − 4·tanh²·sech² = −0.3257

Jaxpr: The Functional IR

Every JAX transform works on Jaxprs — a typed, functional intermediate representation. For \(f(x) = \tanh(x)^2\):

$$\text{jaxpr: } \lambda\, x.\; \text{let}\; a = \tanh(x);\; b = a \cdot a \;\text{ in }\; b$$

The Jaxpr is a pure, static data structure — no Python control flow, no side effects. This is why JAX can analyze, transform, and compile it without knowing the values of x.

vmap via Batching Rules

Every JAX primitive has a batching rule that defines how to vectorize it. For an elementwise op like \(\tanh\), the batching rule is trivial: apply it to the batch axis. For a dot product, the rule inserts a batched matrix multiply. vmap composes these rules during a second tracing pass over the Jaxpr, producing a new Jaxpr with an extra batch dimension.

🔑 Why Composition Works

Each transform returns a pure function — a new Python callable backed by a transformed Jaxpr. Since the output is itself a pure function, any other transform can wrap it. This is why jit(grad(vmap(f))) works: vmap(f) is pure, grad differentiates it, jit compiles the result. The composition order matters: grad then vmap gives per-example gradients (efficient); vmap then grad gives the same result but via a different trace path.

Flax & Haiku — Neural Networks on JAX
▼

The Functional State Problem

Pure functions can't have mutable neural network weights. JAX solves this by making state explicit: network parameters are just a dictionary of arrays passed into the function, and the function returns updated parameters. This is functional programming applied to ML.

Flax (by Google Brain/DeepMind): Defines modules with nn.Module. Parameters are initialized via model.init(rngs, dummy_input), returning a frozen dict. Forward pass: model.apply(params, x). Flax modules can have multiple variable collections (params, batch_stats for BatchNorm, etc.).

Haiku (by DeepMind): Uses a transform pattern: hk.transform(f) lifts a stateful-looking function into an (init, apply) pair — identical concept, different API. Haiku feels more like writing regular OOP code that JAX then "purifies".

💡 PRNG Keys: Explicit Randomness

JAX has no global random state. Every random operation takes an explicit key: key = jax.random.PRNGKey(42). To generate two random values, split the key: key, subkey = jax.random.split(key). This makes randomness reproducible and composable — critical for jit and vmap compatibility.

Key Takeaways & Interview Tips
▼
  • Pure functions are the prerequisite — no in-place ops, no global state, no side effects. x += 1 is illegal inside jit.
  • grad uses reverse-mode by default (efficient for scalar outputs). Use jax.jacfwd (forward mode) for Jacobians of vector outputs.
  • jit retraces on new input shapes — avoid dynamic shapes inside jitted functions. Use static_argnums for Python scalar arguments that vary.
  • vmap vs manually batching: vmap is faster (one kernel) and simpler (no reshape bookkeeping). Always prefer vmap for per-example operations.
  • pmap is SPMD — all devices run the same code. For data parallelism it's automatic; model parallelism needs jax.experimental.shard_map.
  • PRNG keys must be split — never reuse a key, never pass the same key to two operations. Use jax.random.split(key, n).
🎯 Top Interview Questions

Q: Why does JAX require pure functions? A: Transforms (jit, vmap, pmap) work by tracing the function symbolically — they build a Jaxpr (functional IR) and transform it. Impure functions (global state, in-place ops) would produce different Jaxprs on different calls, making compilation and differentiation unsound.

Q: What is the difference between grad and jax.jacobian? A: grad is reverse-mode, computes gradient of scalar wrt all inputs in O(cost of f). jacobian computes the full Jacobian matrix using nested forward/reverse passes — O(n·cost) for n outputs.

Q: When does jit retrace? A: When input shapes or dtypes change, when Python-side conditionals branch differently (static_argnums help), or when jit is called on a new Python function object.

Q: How do Flax and Haiku handle BatchNorm? A: Both pass mutable state (running mean/variance) as a separate variable collection that is updated during the forward pass and returned alongside the output — consistent with the pure-function constraint.
