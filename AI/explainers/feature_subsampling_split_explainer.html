Feature Subsampling at Each Split (max_features)

How sampling \(m < p\) features per node decorrelates trees and reduces ensemble variance
Intermediate Random Forest Classical ML m = √p (classifier) Variance Reduction
1
Understanding Feature Subsampling
▼

What is it? In a standard Decision Tree, every split considers all \(p\) features and picks the best one. In a Random Forest, each split node randomly draws only \(m < p\) candidate features and selects the best split among those \(m\) — then discards the rest. This happens independently at every node, every tree.

Analogy: Imagine building a panel of expert reviewers, where each reviewer must give an opinion using only a randomly chosen subset of the evidence files. No single reviewer dominates because strong evidence is sometimes absent from their subset. Yet the panel collectively sees all evidence and aggregates to a balanced verdict — free from one persuasive document always winning.

💡 If you remember one thing

Feature subsampling stops a single dominant feature from appearing at the root of every tree. Without it, all trees look nearly identical (correlated), and averaging correlated trees barely reduces variance. With \(m = \sqrt{p}\), trees diverge enough that their errors cancel, slashing ensemble variance without much bias cost.

Default values: scikit-learn uses \(m = \sqrt{p}\) for classifiers and \(m = p/3\) (rounded) for regressors. These are empirically derived heuristics that work well across many datasets.

2
Why Tree Correlation Kills Variance Reduction
▼

The Variance-Bias Decomposition of a Bagged Ensemble

For a Random Forest with \(B\) trees, each tree \(h_b\) has variance \(\sigma^2\) and pairwise correlation \(\rho\) with any other tree (assuming identically distributed trees). The ensemble mean \(\hat{f} = \frac{1}{B}\sum_b h_b\) has variance:

$$\operatorname{Var}(\hat{f}) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2$$

As \(B \to \infty\), the second term vanishes, leaving a variance floor of \(\rho\,\sigma^2\). If \(\rho\) is large (highly correlated trees), you can use thousands of trees and still be stuck near the full single-tree variance. Decorrelation — reducing \(\rho\) — is what unlocks genuine variance reduction.

🔑 Key Insight

Bagging alone (bootstrap row sampling) reduces variance by a factor of roughly \(1/B\) when trees are uncorrelated. But trees grown on bootstrap samples of the same full feature set will still split on the same dominant feature at the root — \(\rho\) stays high. Feature subsampling attacks \(\rho\) directly: the dominant feature is simply absent from some splits, forcing those trees down different paths.

Effect on Bias

Restricting to \(m\) features at each split increases individual tree bias slightly — the selected subset might miss the globally optimal feature. But since \(m\) features are re-drawn at every node (not once per tree), each tree can still use every feature somewhere; bias increase is mild. The net variance–bias trade-off strongly favors smaller \(m\) until \(m\) becomes so small that trees become too weak.

3
Mathematical Analysis
▼

Gini Impurity at a Node

At each node, for each candidate feature \(j \in S_m\) (the sampled subset), we find the threshold \(t_j\) that minimises the weighted Gini impurity of the split:

$$\Delta G(j, t) = G(\text{parent}) - \frac{n_L}{n}\,G(\text{left}) - \frac{n_R}{n}\,G(\text{right})$$

where \(G(\mathcal{S}) = \sum_{k=1}^K p_k(1-p_k)\) is the Gini impurity of a set \(\mathcal{S}\) and \(p_k\) is the proportion of class \(k\). The winning feature and threshold maximise \(\Delta G\) over the \(m\) candidates.

Correlation Model

Consider a setting with one strong feature (say feature 1 accounts for 80% of mutual information with the label) and \(p-1\) weak features. Under full-feature splits, feature 1 is chosen at nearly every root — trees are nearly identical. Under \(m\)-feature subsampling, feature 1 is present at a node with probability \(m/p\). The expected correlation between two trees becomes approximately:

$$\rho \approx \left(\frac{m}{p}\right)^d$$

where \(d\) is the dominant depth at which the strong feature normally appears. For root splits (\(d=1\)) and \(m=\sqrt{p}\): \(\rho \approx 1/\sqrt{p}\), shrinking correlation to essentially zero for large \(p\).

Optimal m — Breiman's Empirical Result

Breiman (2001) showed via simulation that \(m = \lfloor\sqrt{p}\rfloor\) minimises test error across a wide range of datasets for classification. For regression, the slightly larger \(m = \lfloor p/3 \rfloor\) is preferred because regression targets are continuous and benefit from more feature diversity per split (the signal is distributed across features more smoothly).

$$m_{\text{class}} = \lfloor\sqrt{p}\rfloor \qquad m_{\text{reg}} = \left\lfloor\frac{p}{3}\right\rfloor$$
⚠️ Common Pitfall

When \(p\) is very small (e.g., \(p = 4\)), \(m = 2\) may be too restrictive. When \(p\) is very large (e.g., sparse text, \(p = 50\,000\)), even \(\sqrt{p} \approx 224\) features per split may keep correlation low — in practice you may use even smaller \(m\) and gain further speed. Always tune \(m\) as a hyperparameter when \(p\) is unusual.

5
Practical Guidance & Hyperparameter Tuning
▼

Tuning max_features in scikit-learn

The max_features parameter accepts integers (exact count), floats (fraction of p), or strings: "sqrt", "log2", "auto" (deprecated alias for sqrt). Common grid to search: [1, "log2", "sqrt", 0.5, 1.0] in increasing correlation order.

📐 m vs ρ trade-off

As \(m\) increases from 1 to \(p\): individual tree accuracy increases (lower bias), but inter-tree correlation \(\rho\) rises (higher variance floor). The ensemble variance \(\rho\sigma^2 + (1-\rho)\sigma^2/B\) is minimised at an interior \(m^*\) that balances both. For typical tabular data this coincides with \(\sqrt{p}\).

Feature Importance Implications

Because each node only sees \(m\) features, importance scores (mean decrease in impurity, MDI) are computed over partial subsets. This makes MDI scores more reliable than in single trees — the dominant feature can only accumulate importance across nodes where it was actually sampled, preventing it from monopolising all credit.

When to deviate from defaults

Increase m when: many features are noisy/irrelevant (strong features need more chances to appear), or data is very small and you need lower-bias trees. Decrease m when: you have very many correlated features, you want faster training, or you suspect the forest is overfitting due to near-identical trees.

6
Interview Q&A
▼

Q: Why does Random Forest use feature subsampling at splits, not just bootstrap sampling of rows?

Bootstrap sampling alone reduces variance by \(1/B\) for uncorrelated trees, but trees trained on different bootstrap samples of the same features tend to use the same dominant feature at the root — keeping inter-tree correlation high. Feature subsampling directly reduces this correlation by preventing any single feature from dominating every split, breaking the bottleneck that limits variance reduction.

Q: What is the variance formula for a random forest ensemble and what does it imply?

For \(B\) identically distributed trees with pairwise correlation \(\rho\) and per-tree variance \(\sigma^2\): \(\operatorname{Var}(\hat{f}) = \rho\sigma^2 + (1-\rho)\sigma^2/B\). As \(B\to\infty\) the second term vanishes, leaving a floor of \(\rho\sigma^2\). This shows that adding more trees only helps if \(\rho\) is small — hence decorrelation via feature subsampling is essential.

Q: Why is m = √p the default for classification but p/3 for regression?

Breiman's empirical tuning found that classification targets benefit from stronger decorrelation (the dominant class-boundary feature is very influential), so a smaller \(m\) makes a bigger relative difference. For regression, the signal is spread more smoothly across features, so a somewhat larger candidate set allows trees to fit continuous targets better without over-correlating.

Q: Does reducing m hurt individual tree accuracy?

Yes, slightly — each tree's bias increases because the globally best feature may not be in the sampled subset at a given node. However, since the \(m\) features are re-sampled independently at every node, the tree can still use all features deeper down; the bias increase is far outweighed by the variance reduction achieved through decorrelation across the ensemble.
