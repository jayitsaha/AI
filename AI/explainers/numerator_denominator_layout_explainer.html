1
Understanding the Confusion
▼

When you differentiate a scalar with respect to a vector, or a vector with respect to another vector, you get a matrix — but which orientation? Should the result be a row vector or column vector? Should the Jacobian have the output variable indexing rows or columns? Two competing conventions answer this differently, and textbooks silently pick one without telling you.

The Core Confusion

The numerator layout and denominator layout give results that differ by a transpose. They are both self-consistent — but mixing them mid-derivation produces wrong answers. Every major ML framework, textbook, and paper silently picks one. Knowing which convention is in use lets you read any matrix-calculus result correctly.

Analogy: Think of "latitude/longitude" vs "longitude/latitude" — both locate the same point on Earth, but if you mix the conventions (reading a lat/lon coordinate as if it were lon/lat), you end up in the wrong ocean. Matrix calculus layout conventions are exactly this kind of silent ordering choice.

If you remember one thing

Numerator layout: \(\frac{\partial(\mathbf{A}\mathbf{x})}{\partial \mathbf{x}} = \mathbf{A}\).   Denominator layout: \(\frac{\partial(\mathbf{A}\mathbf{x})}{\partial \mathbf{x}} = \mathbf{A}^\top\).   They differ by a transpose — pick one and stick to it.

2
The Two Conventions Defined Precisely
▼

Let \(\mathbf{y} \in \mathbb{R}^m\) be a function of \(\mathbf{x} \in \mathbb{R}^n\). The derivative \(\frac{\partial \mathbf{y}}{\partial \mathbf{x}}\) contains all partial derivatives \(\frac{\partial y_i}{\partial x_j}\) — but the question is how to arrange them into a matrix.

Numerator Layout (aka Jacobian formulation)

The numerator variable (\(\mathbf{y}\)) indexes the rows; the denominator variable (\(\mathbf{x}\)) indexes the columns. Result shape: \(m \times n\).

$$\left[\frac{\partial \mathbf{y}}{\partial \mathbf{x}}\right]_{\text{num}} = \begin{bmatrix} \frac{\partial y_1}{\partial x_1} & \frac{\partial y_1}{\partial x_2} & \cdots & \frac{\partial y_1}{\partial x_n} \\ \frac{\partial y_2}{\partial x_1} & \frac{\partial y_2}{\partial x_2} & \cdots & \frac{\partial y_2}{\partial x_n} \\ \vdots & \vdots & \ddots & \vdots \\ \frac{\partial y_m}{\partial x_1} & \frac{\partial y_m}{\partial x_2} & \cdots & \frac{\partial y_m}{\partial x_n} \end{bmatrix} \in \mathbb{R}^{m \times n}$$

Denominator Layout (aka Hessian formulation / "numerator is transposed")

The denominator variable (\(\mathbf{x}\)) indexes the rows; the numerator variable (\(\mathbf{y}\)) indexes the columns. Result shape: \(n \times m\) — the transpose of numerator layout.

$$\left[\frac{\partial \mathbf{y}}{\partial \mathbf{x}}\right]_{\text{den}} = \left[\frac{\partial \mathbf{y}}{\partial \mathbf{x}}\right]_{\text{num}}^{\!\top} \in \mathbb{R}^{n \times m}$$
Name Confusion Warning

Wikipedia and some sources use "numerator layout" to mean the Jacobian (\(m \times n\)) and "denominator layout" for its transpose (\(n \times m\)). Other sources flip the names entirely or call them "row-vector convention" vs "column-vector convention." Always verify which convention a reference uses by checking one concrete formula before trusting its notation.

Scalar-by-Vector: The Gradient

For a scalar \(f(\mathbf{x})\) where \(\mathbf{x} \in \mathbb{R}^n\):

  • Numerator layout: \(\nabla_{\mathbf{x}} f = \frac{\partial f}{\partial \mathbf{x}} \in \mathbb{R}^{1 \times n}\) — a row vector
  • Denominator layout: \(\nabla_{\mathbf{x}} f = \frac{\partial f}{\partial \mathbf{x}} \in \mathbb{R}^{n \times 1}\) — a column vector

In most ML textbooks and PyTorch, gradients are column vectors (denominator layout for gradients, but numerator layout for Jacobians — the field is inconsistent, which is exactly the problem).

Chain Rule — Watch the Order

In numerator layout, the chain rule \(\frac{\partial \mathbf{z}}{\partial \mathbf{x}} = \frac{\partial \mathbf{z}}{\partial \mathbf{y}} \cdot \frac{\partial \mathbf{y}}{\partial \mathbf{x}}\) preserves matrix-multiply order naturally (Jacobians multiply left-to-right). In denominator layout the order reverses: \(\frac{\partial \mathbf{z}}{\partial \mathbf{x}} = \frac{\partial \mathbf{y}}{\partial \mathbf{x}} \cdot \frac{\partial \mathbf{z}}{\partial \mathbf{y}}\). If you mix conventions mid-chain, dimensions will silently misalign.

Key Takeaways & Practical Advice
▼
Practical Rule

Most ML textbooks (Bishop, Goodfellow "Deep Learning") use denominator layout for gradients (column vectors) but are inconsistent with Jacobians. Wikipedia's matrix calculus page uses numerator layout. Magnus & Neudecker (the rigorous reference) use denominator layout. Always check the first concrete example in a source to determine its convention.

  • Numerator layout makes the chain rule read left-to-right: \(\mathbf{J}_{z/x} = \mathbf{J}_{z/y}\,\mathbf{J}_{y/x}\). Natural for forward-mode autodiff.
  • Denominator layout makes gradients column vectors (matching the shape of the input), which is why PyTorch and most optimization algorithms use it for parameter gradients.
  • Transpose bridge: Convert any formula from one convention to the other by transposing the result. If you see a formula that "doesn't match" what you expect, try transposing it.
  • Dimension check: Always verify that matrix multiply dimensions are consistent. A shape mismatch is often a convention error, not a mathematical error.
Common Bug in Backprop Derivations

When deriving backprop by hand, mixing conventions mid-chain gives a result that is the transpose of the correct gradient. If your weight update moves in the wrong direction (increasing loss instead of decreasing it), first check for a transposition error from a convention mismatch before suspecting a sign error.

Code: Verify Both Conventions with NumPy
▼

The following code demonstrates both conventions and shows they differ by a transpose:

import numpy as np # Define A and x A = np.array([[2, 1], [3, 4]], dtype=float) x = np.array([1.0, 2.0]) # y = Ax y = A @ x # [4., 11.] # Jacobian entries: dy_i/dx_j = A[i,j] # Numerator layout: rows = output (y), cols = input (x) J_numerator = A # [[2, 1], [3, 4]] # Denominator layout: rows = input (x), cols = output (y) J_denominator = A.T # [[2, 3], [1, 4]] print("Numerator layout d(Ax)/dx:", J_numerator) print("Denominator layout d(Ax)/dx:", J_denominator) print("Relationship:", np.allclose(J_numerator, J_denominator.T)) # True # Scalar case: f(x) = a^T x a = np.array([1.0, 2.0, 3.0]) x3 = np.array([0.5, 1.0, 1.5]) # Numerator layout: gradient is row vector (1×n) grad_numerator = a.reshape(1, -1) # [[1., 2., 3.]] # Denominator layout: gradient is column vector (n×1) grad_denominator = a.reshape(-1, 1) # [[1.], [2.], [3.]] # Verify quadratic: f(x) = x^T A x, grad (denominator) = (A + A^T) x A_sym = np.array([[1,2],[2,3]], dtype=float) x2 = np.array([1.0, 2.0]) grad_quad_den = (A_sym + A_sym.T) @ x2 # = 2*A_sym @ x2 = [10., 16.] grad_quad_num = grad_quad_den.reshape(1,-1) # row vector for numerator layout
