Understanding K-Medoids
▼

What is it? K-Medoids is a clustering algorithm — it groups data points into \(k\) clusters. The key difference from K-Means: each cluster's "center" must be an actual data point (called a medoid), not an abstract average. A medoid is the point in a cluster that minimizes the total distance to all other points in its cluster.

Analogy: Imagine selecting \(k\) representatives from a large population — the representatives must come from the population itself, not be invented. K-Means invents a "mythical average person" that may not exist. K-Medoids insists the representative is a real person. If your population includes Bill Gates, he would massively distort a K-Means mean — but K-Medoids would still pick typical members of each income group as representatives.

PAM (Partitioning Around Medoids) is the classic algorithm for solving K-Medoids. It has two phases: BUILD (greedy initialization: select \(k\) good starting medoids one by one) and SWAP (iteratively try swapping each medoid with every non-medoid to see if total dissimilarity decreases).

💡 If you remember one thing

K-Medoids minimizes \(\sum_{i=1}^{n} \min_{j \in M} d(x_i, x_j)\) where \(M\) is the set of medoid indices — and every medoid must be one of your actual data points. This makes it robust to outliers and usable with any distance metric, including non-Euclidean ones.

PAM Algorithm — Internals
▼

Phase 1: BUILD — Greedy Initialization

PAM builds an initial set of \(k\) medoids greedily. For the first medoid, it picks the data point with the smallest sum of distances to all other points — this is the dataset's "geometric median". For each subsequent medoid, it picks the point that maximally reduces the total assignment cost:

$$m_1 = \underset{j}{\operatorname{argmin}} \sum_{i=1}^{n} d(x_i, x_j)$$
$$m_2 = \underset{j \notin M}{\operatorname{argmin}} \; T(M \cup \{j\}), \quad T(M) = \sum_{i=1}^{n} \min_{m \in M} d(x_i, x_m)$$

This greedy step is key: BUILD runs in \(O(kn^2)\) time and typically produces a good starting point that dramatically reduces the number of SWAP iterations needed.

Phase 2: SWAP — Iterative Improvement

Once BUILD gives us \(k\) medoids, SWAP tries all \(k \times (n-k)\) possible exchanges of (current medoid \(m\), non-medoid candidate \(c\)). For each pair, compute the new total cost if \(m\) is replaced by \(c\). Accept the swap that gives the largest cost reduction. Repeat until no improving swap exists.

$$\Delta(m \to c) = T(M \setminus \{m\} \cup \{c\}) - T(M)$$
$$\text{If } \min_{m, c} \Delta(m \to c) < 0 \text{, swap } m^* \leftarrow c^* \text{ and repeat}$$

Each full SWAP iteration costs \(O(k \cdot (n-k) \cdot n)\). PAM converges to a local minimum of total dissimilarity — not necessarily the global minimum, but empirically good.

🔑 Why Medoids Beat Means for Outliers

A K-Means centroid is the arithmetic mean — one extreme outlier shifts it far from the true cluster center. A medoid is the most central actual data point — an outlier can only become a medoid if it is genuinely representative, which it never is. The outlier still gets assigned to a cluster, but it cannot corrupt the representative.

⚠️ Scalability Trade-off

PAM is \(O(k(n-k)^2)\) per iteration — feasible for \(n \le 1{,}000\). For large datasets use CLARA (samples sub-sets and runs PAM on each) or CLARANS (random-neighbor SWAP variant). Exact PAM is prohibitive above \(n \approx 3{,}000\).

3
Why It Works — The Math
▼

Objective Function

K-Medoids solves the combinatorial optimization problem: given \(n\) points and a pairwise dissimilarity function \(d(\cdot,\cdot)\) (which need not be Euclidean — can be any valid distance or even a dissimilarity satisfying \(d \ge 0\)), find a subset \(M \subset \{1,\ldots,n\}\) with \(|M|=k\) that minimizes total within-cluster dissimilarity:

$$T(M) = \sum_{i=1}^{n} \min_{j \in M} d(x_i, x_j)$$

This is equivalent to assigning each point to its nearest medoid and summing the assignment distances. The search space is \(\binom{n}{k}\) possible subsets — combinatorially explosive, so PAM uses local search.

SWAP Correctness

PAM's SWAP step is a form of coordinate descent on \(T(M)\), where each "coordinate" is one medoid's identity. Since \(T(M) \ge 0\) and is strictly decreasing after each accepted swap, PAM provably converges. However, because the search is local, it may reach a local minimum rather than the global optimum.

$$T(M^{(t+1)}) < T(M^{(t)}) \quad \Rightarrow \quad \text{convergence in finite iterations}$$

Robustness to Outliers — Formal Argument

Suppose one point \(x_o\) is a severe outlier: \(d(x_o, x_i) \gg 0\) for all \(i \neq o\). In K-Means, the centroid of the cluster containing \(x_o\) shifts by \(\frac{d_o}{n_c}\) where \(n_c\) is the cluster size. In K-Medoids, the only effect is that \(x_o\) contributes \(d(x_o, m_c)\) to the total cost \(T\) — the medoid \(m_c\) itself does not move unless replacing it with \(x_o\) reduces \(T\), which it won't (since \(x_o\) is far from all points in the cluster).

📐 Connection to L1 vs L2

The medoid is the sample analogue of the geometric median (minimizer of sum of distances, i.e., \(L_1\) norm). The centroid (K-Means) minimizes sum of squared distances (\(L_2\) norm). Squaring distances makes the centroid hypersensitive to large deviations — analogous to why L1 regression is more robust than L2 to outliers.

Key Takeaways & When to Use
▼

Use K-Medoids / PAM when:

  • Your data has outliers that would corrupt K-Means centroids
  • Your distance metric is non-Euclidean (e.g., edit distance on strings, DTW on time series, graph distance)
  • Cluster representatives must be interpretable real examples (e.g., selecting a "prototype customer" from actual customers)
  • Data is categorical or mixed-type (using Gower distance)
  • Dataset is small enough (\(n \lesssim 1{,}000\)) for PAM, or use CLARA/CLARANS for larger data

Do not use when:

  • Dataset is very large — PAM is \(O(k(n-k)^2)\) per iteration, too slow for \(n > 3{,}000\)
  • Data is truly Gaussian and outlier-free — K-Means is faster and equally good
  • Clusters are highly non-convex — consider DBSCAN or spectral clustering instead
💡 Hierarchy of Clustering Robustness

K-Means (fast, sensitive to outliers, Euclidean only) → K-Medoids/PAM (moderate speed, robust to outliers, any metric) → DBSCAN (no \(k\) needed, finds arbitrary shapes, robust) → Spectral Clustering (arbitrary manifolds, expensive). Choose based on dataset size, outlier prevalence, and whether clusters are convex.

K-Means Centroid

Mean of cluster members. Does not exist in dataset. Pulled by outliers. Only valid for Euclidean distance. Fast: O(nki).

K-Medoids Medoid

Most central real data point. Outlier-resistant. Works with any distance. Interpretable. Slower: O(k(n−k)² per iter).

Code Trace — PAM from Scratch
▼
import numpy as np
def pam(X, k, dist=None, max_iter=100):
"""PAM (Partitioning Around Medoids) — BUILD + SWAP."""
if dist is None:
dist = lambda a, b: np.sqrt(np.sum((a-b)**2)) # Euclidean
n = len(X)
# Pre-compute full distance matrix O(n²)
D = np.array([[dist(X[i], X[j]) for j in range(n)] for i in range(n)])
def total_cost(medoids):
return sum(D[i, medoids].min() for i in range(n))
# ── BUILD Phase ──────────────────────────────────────
# Pick m1: minimize sum of all distances (geometric median)
m1 = int(D.sum(axis=1).argmin())
medoids = [m1]
# Greedily add remaining medoids
for _ in range(k - 1):
best, nxt = float('inf'), -1
for c in range(n):
if c in medoids: continue
cost = total_cost(medoids + [c])
if cost < best: best, nxt = cost, c
medoids.append(nxt)
# ── SWAP Phase ───────────────────────────────────────
for _ in range(max_iter):
best_delta, best_swap = 0, None
cur_cost = total_cost(medoids)
for m in medoids: # each current medoid
for c in range(n): # each non-medoid candidate
if c in medoids: continue
new_m = [x for x in medoids if x != m] + [c]
delta = total_cost(new_m) - cur_cost
if delta < best_delta: # improving swap?
best_delta, best_swap = delta, (m, c)
if best_swap is None: break # converged
old_m, new_c = best_swap
medoids = [x for x in medoids if x != old_m] + [new_c]
labels = np.array([medoids[D[i, medoids].argmin()] for i in range(n)])
return medoids, labels
