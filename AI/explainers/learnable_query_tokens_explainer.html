Understanding Learnable Query Tokens
▼

What is it? A vision encoder can turn one image into hundreds of feature vectors, and a video into thousands (many frames × many patches each). Feeding all of that directly into a language model is expensive and the amount varies per input. A Perceiver Resampler fixes this: it keeps a small, fixed number of "query" vectors that are themselves learned parameters (not derived from the input). These queries cross-attend to however many visual features exist and always emit the same fixed number of output tokens.

Analogy: Picture a court stenographer with exactly 64 index cards. Whether the hearing lasts five minutes or five hours, they must summarize everything onto those same 64 cards — no more, no fewer. The cards themselves (the questions the stenographer has learned to ask: "what happened, who said it, when") are fixed and reusable; only what gets written on them changes based on the testimony (the input).

One-sentence summary: A set of learned latent vectors act as queries in cross-attention over variable-length inputs, always producing a constant-size output — the mechanism behind Flamingo's Perceiver Resampler, DETR's object queries, and BLIP-2's Q-Former.

💡 If you remember one thing

The queries are trained weights, not a function of the current input. That's what makes the output length constant: $$\text{latents}_{out} \in \mathbb{R}^{N\times d} \;\; \text{regardless of } M = |\text{visual tokens}|$$

How the Perceiver Resampler Works Internally
▼

The Setup

A vision encoder (e.g. a frozen NFNet or CLIP ViT) turns each of \(T\) frames into \(S\) spatial patch embeddings, giving \(M = T\times S\) feature vectors \(X \in \mathbb{R}^{M\times d}\) — a learned temporal embedding is added per-frame so the model knows frame order. \(M\) grows with the number of images/frames; it is never constant across examples.

The Fixed Latent Array

A small learned latent array \(L \in \mathbb{R}^{N\times d}\) (Flamingo uses \(N=64\)) is initialized randomly and updated purely by backpropagation — it is a nn.Parameter, exactly like a weight matrix, shared across all inputs. It supplies the queries \(Q = L W_q\) for cross-attention.

Keys/Values: Concatenate Features WITH the Latents

Flamingo's specific twist on Perceiver: keys and values are computed not just from \(X\) but from \(\text{concat}(X, L)\). So \(K = V = \text{concat}(X, L) W_{kv} \in \mathbb{R}^{(M+N)\times d}\). This "residual latent" trick lets each layer's latents directly attend to their own previous state alongside fresh visual evidence, which the Flamingo ablations found improved sample efficiency over attending to \(X\) alone.

Numerical Trace (toy example, \(d=3\))

Suppose \(T=2\) frames, \(S=2\) patches ⇒ \(M=4\) image tokens, and \(N=2\) latents. One query \(q_1=[1,0,1]\) computes raw scores against 6 keys (4 image + 2 latent) via \(q_1\cdot k_j/\sqrt3\); softmax turns e.g. raw scores \([1.4,0.2,-0.6,0.9,2.1,0.3]\) into weights \([0.19,0.06,0.03,0.12,0.55,0.05]\) — here the query puts 55% of its attention onto the second latent (itself/its neighbor) and the rest spread over image patches. The output for that query is the weight-averaged sum of the 6 value vectors — still a single \(d\)-dim vector, no matter how large \(M\) grows.

🔑 Design Decision: Why fixed queries, not mean/max pooling?

Mean/max pooling is fixed-size too, but it cannot learn what to look for — every input dimension contributes with a rule (average, or the max) fixed in advance. Learned queries let the model discover, through gradient descent, which combinations of visual evidence (faces, text, motion) are worth extracting, and different query slots can specialize in different aspects.

3
Why It Works — The Math
▼

Cross-Attention With Fixed Query Count

Let \(X\in\mathbb{R}^{M\times d}\) be the (variable-length) visual features and \(L\in\mathbb{R}^{N\times d}\) the learned latents. One resampler layer computes:

$$Q = LW_q,\quad K=V=\text{concat}(X,L)W_{kv},\quad \text{Attn}(Q,K,V)=\operatorname{softmax}\!\Big(\frac{QK^\top}{\sqrt{d}}\Big)V$$

The output has shape \(N\times d\) — determined entirely by \(Q\)'s row count, which is \(N\) by construction. \(M\) only ever appears as the column-count contribution to \(K,V\), so however large \(M\) is, the output shape is untouched. A residual + FFN block (with its own residual) then refines \(L \leftarrow L + \text{FFN}(L + \text{Attn})\), and this is stacked for \(l=1,\dots,L_{depth}\) layers (Flamingo uses 6).

Complexity: Linear, not Quadratic, in Input Size

Full self-attention over all tokens costs \(O((M+N)^2 d)\). Because only \(N\) rows ever act as queries, the resampler costs \(O(N(M+N)d)\) — linear in \(M\). For a long video, \(M\) can be in the tens of thousands; with \(N=64\ll M\), this is the difference between a tractable model and an intractable one.

$$\text{Self-attn: } O\big((M+N)^2 d\big) \qquad \text{Resampler: } O\big(N(M+N)d\big),\quad N \ll M$$

Downstream Use: Gated Cross-Attention

The final \(N\) output tokens are used as \(K,V\) inside GATED XATTN-DENSE blocks spliced between the frozen LLM's layers. Each gate applies \(\tanh(\alpha)\) with \(\alpha\) initialized to \(0\), so at the start of training the inserted block is the identity function — the pretrained language model's behavior is exactly preserved until training nudges \(\alpha\) away from zero. This lets a frozen, already-capable LLM be conditioned on vision without destabilizing its language modeling.

⚠️ Common Pitfall

More latents is not automatically better. Too few (\(N\) small) creates an information bottleneck — fine detail gets averaged away. Too many increases compute roughly linearly and can slow convergence with no accuracy gain past the point where \(N\) already covers the "concepts per image" the LLM actually needs. Flamingo settled on \(N=64\) empirically.

When to use:

  • Bridging a frozen vision encoder to a frozen LLM when the number of images/frames varies per example (Flamingo)
  • Detection/segmentation where you want a fixed number of "slots" for objects regardless of scene complexity (DETR)
  • Any modality-compression bottleneck where downstream compute must not scale with raw input size

When NOT to use: single fixed-size images with no efficiency constraint — direct patch tokens into a cross-attention layer may retain more detail. Also skip it if you need to reconstruct the exact input (resampling is lossy compression).

💡 Hierarchy

Pooling (fixed, not learned) ⊂ Learnable query tokens (fixed, learned) ⊂ Full cross/self-attention (variable, learned). Learnable queries occupy the sweet spot: trainable selectivity at constant compute.

Code Trace

import torch, torch.nn as nn, torch.nn.functional as F
class PerceiverResampler(nn.Module):
def __init__(self, dim=512, depth=6, num_latents=64, heads=8):
super().__init__()
# The fixed, LEARNED latent array -- an nn.Parameter, not input-derived
self.latents = nn.Parameter(torch.randn(num_latents, dim) * 0.02)
self.layers = nn.ModuleList([
nn.ModuleDict(dict(
attn=CrossAttention(dim, heads),
ffn=nn.Sequential(nn.LayerNorm(dim), nn.Linear(dim, 4*dim),
nn.GELU(), nn.Linear(4*dim, dim)),
)) for _ in range(depth)])
self.norm = nn.LayerNorm(dim)
def forward(self, x):
# x: (batch, T*S, dim) -- variable-length visual features (M = T*S)
b = x.shape[0]
latents = self.latents.unsqueeze(0).expand(b, -1, -1) # (b, N, dim)
for layer in self.layers:
kv_input = torch.cat([x, latents], dim=1) # concat features + latents
latents = latents + layer['attn'](q=latents, kv=kv_input)
latents = latents + layer['ffn'](latents)
return self.norm(latents) # (b, N, dim) -- ALWAYS N, regardless of input M
class CrossAttention(nn.Module):
def __init__(self, dim, heads):
super().__init__()
self.scale = (dim // heads) ** -0.5
self.to_q = nn.Linear(dim, dim, bias=False)
self.to_kv = nn.Linear(dim, dim * 2, bias=False)
self.to_out = nn.Linear(dim, dim, bias=False)
self.heads = heads
def forward(self, q, kv):
Q = self.to_q(q) # (b, N, dim)
K, V = self.to_kv(kv).chunk(2, dim=-1) # (b, M+N, dim) each
scores = torch.einsum('bnd,bmd->bnm', Q, K) * self.scale
attn = scores.softmax(dim=-1) # (b, N, M+N)
out = torch.einsum('bnm,bmd->bnd', attn, V) # (b, N, dim)
return self.to_out(out)
# Usage: bridging a frozen vision encoder to a frozen LLM (Flamingo-style)
resampler = PerceiverResampler(dim=1024, depth=6, num_latents=64)
vision_feats = vision_encoder(video_frames) # (b, T*S, 1024), T*S varies!
tokens = resampler(vision_feats) # (b, 64, 1024) -- FIXED size
lm_logits = frozen_lm(text_ids, cross_kv=tokens) # gated cross-attn, tanh(alpha=0) init
