Understanding Edward2
▼

What is it? Edward2 is a probabilistic programming language (PPL) built on TensorFlow. It allows you to express statistical models with random variables directly within a TensorFlow computation graph. This enables the seamless integration of deep learning architectures with Bayesian inference methods, leading to models that can quantify their uncertainty, not just make point predictions.

Analogy: Imagine building a LEGO castle. Standard TensorFlow (or Keras) gives you deterministic bricks: walls, towers, roofs. You assemble them into a fixed design. Edward2, however, gives you "probabilistic bricks": a wall might be a "Normal distribution of wall types," or a tower's height might be a "Categorical distribution of heights." You still build a castle, but now its components can be sampled from distributions, allowing you to explore many possible castle designs and understand the uncertainty in your construction choices.

💡 If you remember one thing

Edward2 leverages TensorFlow's auto-differentiation and graph capabilities to treat random variables as first-class citizens. This means you can define model parameters (like neural network weights) as probability distributions instead of fixed values, then use powerful inference algorithms to learn these distributions from data.

2
How Edward2 Works Internally
▼

Random Variables as Tensors

At its core, Edward2 represents random variables (RVs) as special TensorFlow objects that encapsulate a probability distribution. When you call an Edward2 RV, it returns a sample from its distribution. This allows you to build models where, for instance, a neural network's weights are sampled from a distribution rather than being fixed scalar values.

$$W \sim \mathcal{N}(\mu_W, \sigma_W^2) \quad \text{becomes in Edward2: } W = \text{ed.Normal}(\text{loc}=\mu_W, \text{scale}=\sigma_W)$$

This is crucial because it transforms a deterministic computation graph into a stochastic one. Each forward pass of the network might use different sampled weights, leading to a distribution of outputs rather than a single point prediction.

Integration with TensorFlow and Keras

Edward2 is designed to be a thin wrapper around TensorFlow Probability (TFP) distributions and Keras layers. This means you can use familiar `tf.keras.layers` like `Dense` or `Conv2D`, but instead of their weights being simple `tf.Variable`s, you can replace them with Edward2 random variables. For example, a `Dense` layer's kernel could be an `ed.Normal` distribution.

This deep integration is key to its power: you get the flexibility of probabilistic modeling without sacrificing the performance and scalability of TensorFlow for deep learning. It's not a separate framework but an extension of the existing ecosystem.

Inference: From Prior to Posterior

The goal of probabilistic modeling is typically to infer the posterior distribution of parameters given data: \(P(\text{parameters} | \text{data})\). Edward2 facilitates this by providing tools for various inference algorithms, such as Markov Chain Monte Carlo (MCMC) methods (e.g., Hamiltonian Monte Carlo) and Variational Inference (VI). These algorithms iteratively refine the distributions of your random variables, moving them from an initial "prior belief" to a "posterior belief" that reflects the observed data.

🔑 Key Property

Edward2 enables Bayesian Deep Learning by making it easy to define deep neural networks with probabilistic weights and activations. This allows models to express their uncertainty about predictions, which is critical in high-stakes applications where knowing "how sure" a model is matters as much as the prediction itself.

3
Why It Works — The Bayesian Foundation
▼

The Bayesian Inference Loop

At the heart of Edward2's utility is Bayes' Theorem, which formally describes how to update our beliefs about a hypothesis (the model parameters \(\theta\)) given new evidence (the data \(D\)).

$$P(\theta | D) = \frac{P(D | \theta) P(\theta)}{P(D)}$$

Here, \(P(\theta)\) is the prior distribution (our initial belief about \(\theta\) before seeing any data), \(P(D | \theta)\) is the likelihood (how probable the data \(D\) is given specific parameters \(\theta\)), and \(P(\theta | D)\) is the posterior distribution (our updated belief about \(\theta\) after observing \(D\)). The term \(P(D)\) is the marginal likelihood, a normalizing constant often intractable to compute directly.

From Fixed Weights to Distributions

In a traditional neural network, weights are point estimates. In a Bayesian Neural Network (BNN) defined with Edward2, each weight \(w_{ij}\) (from input \(i\) to neuron \(j\)) is treated as a random variable with its own distribution. For simplicity, often a Normal distribution is chosen:

$$w_{ij} \sim \mathcal{N}(\mu_{ij}, \sigma_{ij}^2)$$

The "training" process then becomes finding the posterior distributions \(P(\mu_{ij}, \sigma_{ij}^2 | D)\) for all weights. This is typically done by defining a *surrogate* or *variational* distribution \(q(\theta)\) (e.g., a simple Normal distribution for each weight) and iteratively adjusting its parameters (mean and variance) to best approximate the true posterior \(P(\theta | D)\). This is Variational Inference, where we minimize the Kullback-Leibler (KL) divergence between \(q(\theta)\) and \(P(\theta | D)\):

$$\text{KL}(q(\theta) || P(\theta | D)) = \mathbb{E}_{q(\theta)}[\log q(\theta)] - \mathbb{E}_{q(\theta)}[\log P(D | \theta)] - \mathbb{E}_{q(\theta)}[\log P(\theta)] + \log P(D)$$

Edward2's integration with TensorFlow allows the gradients for optimizing these variational parameters (e.g., \(\mu_{ij}, \sigma_{ij}\)) to be computed automatically, making complex Bayesian models tractable.

⚠️ Computational Cost

While powerful, Bayesian methods (including those using Edward2) often incur a higher computational cost than their deterministic counterparts. Sampling from distributions during training and inference, as well as optimizing for entire distributions rather than point estimates, can be more resource-intensive. This trade-off is often justified by the valuable uncertainty quantification provided.

Key Takeaways
▼

When to use Edward2:

  • You need to quantify uncertainty in your model's predictions or parameters (e.g., medical diagnosis, financial forecasting).
  • Your model parameters (e.g., neural network weights) could benefit from being treated as distributions rather than point estimates, allowing for richer representations.
  • You want to incorporate prior knowledge into your deep learning models, guiding the learning process.
  • You are building hybrid models that combine traditional statistical components (e.g., Gaussian Processes) with deep learning architectures.
  • You are working with small datasets where overfitting is a major concern, and Bayesian methods can provide regularization.

When to consider alternatives:

  • Computational efficiency is the absolute top priority, and the added cost of Bayesian inference is prohibitive.
  • Your problem is well-suited for deterministic models, and point predictions are sufficient without uncertainty estimates.
  • You are working with extremely large models or datasets where the scalability of full Bayesian inference becomes a bottleneck (though approximations like VI help).
  • You prefer other probabilistic programming frameworks (e.g., Pyro, Stan) or simpler methods for uncertainty (e.g., Monte Carlo Dropout).
💡 Edward2's Niche

Edward2 excels at bridging the gap between deep learning and probabilistic modeling. It allows practitioners to build complex, uncertainty-aware models using the familiar TensorFlow ecosystem, making advanced Bayesian techniques more accessible for deep learning researchers and engineers.

Code Trace — Bayesian Linear Regression with Edward2
▼
import tensorflow as tf
import tensorflow_probability as tfp
import edward2 as ed
import numpy as np
tfd = tfp.distributions
# 1. Generate synthetic data
TRUE_W = 2.0
TRUE_B = 1.0
NUM_EXAMPLES = 15
X = tf.cast(tf.linspace(-5.0, 5.0, NUM_EXAMPLES), tf.float32)
Y = TRUE_W * X + TRUE_B + tf.random.normal(shape=[NUM_EXAMPLES], stddev=0.5)
# 2. Define the Bayesian Linear Regression Model
def bayesian_linear_model(features):
# Prior distributions for weight 'w' and bias 'b'
w = ed.Normal(loc=0., scale=5., name="w")
b = ed.Normal(loc=0., scale=5., name="b")
# Linear prediction (deterministic part)
mean_output = w * features + b
# Likelihood: observed Y is Normal around mean_output
# The observation noise (scale) can also be a random variable
y_pred = ed.Normal(loc=mean_output, scale=0.5, name="y_pred")
return y_pred
# 3. Define variational posterior distributions (q(w), q(b))
# These will approximate the true posterior P(w,b | X,Y)
def variational_model(features):
# q(w) is a Normal distribution with learnable loc and scale
qw_loc = tf.Variable(0., name="qw_loc")
qw_scale = tfp.util.TransformedVariable(tf.Variable(-2., name="qw_scale_unconstrained"), tfp.bijectors.Softplus())
qw = ed.Normal(loc=qw_loc, scale=qw_scale, name="w")
# q(b) is a Normal distribution with learnable loc and scale
qb_loc = tf.Variable(0., name="qb_loc")
qb_scale = tfp.util.TransformedVariable(tf.Variable(-2., name="qb_scale_unconstrained"), tfp.bijectors.Softplus())
qb = ed.Normal(loc=qb_loc, scale=qb_scale, name="b")
mean_output = qw * features + qb
y_pred = ed.Normal(loc=mean_output, scale=0.5, name="y_pred")
return y_pred
# 4. Perform Variational Inference
log_joint = ed.make_log_joint_fn(bayesian_linear_model)
def target_log_prob(qw, qb):
return log_joint(features=X, w=qw, b=qb, y_pred=Y)
# Build the surrogate posterior (q_model)
q_model = variational_model(features=X)
# Define the loss (Negative Evidence Lower Bound - ELBO)
kl_divergence_function = ed.make_log_joint_fn(variational_model)
elbo = tfp.vi.monte_carlo_csiszar_f_divergence(
f=tfp.vi.kl_reverse,
target_log_prob=target_log_prob,
surrogate_posterior=q_model,
num_draws=10)
loss = -elbo
# 5. Optimize the variational parameters
optimizer = tf.optimizers.Adam(learning_rate=0.01)
@tf.function
def train_step():
with tf.GradientTape() as tape:
loss_value = loss()
gradients = tape.gradient(loss_value, q_model.trainable_variables)
optimizer.apply_gradients(zip(gradients, q_model.trainable_variables))
return loss_value
