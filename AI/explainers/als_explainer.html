Alternating Least Squares (ALS)

Parallelizable matrix factorization for implicit feedback recommenders
Intermediate Recommender Systems Matrix Factorization O(k²·n) per row, parallel
1
Understanding ALS
▼

What is it? ALS is a way to factorize a giant user-item matrix (like "who clicked/watched/bought what") into two small matrices of latent factors — one row per user, one row per item — so that the dot product of a user's row and an item's row predicts how much that user likes that item. The trick that makes it fast at Netflix/Spotify scale: instead of solving for users and items simultaneously (non-convex, hard), ALS alternates — freeze the items, solve exactly for every user; freeze the users, solve exactly for every item; repeat.

Analogy: Imagine seating guests at round tables to maximize how much they enjoy their tablemates, but you can only move one side at a time. First you fix which tables exist and optimally reassign every guest to the best table (an easy, independent decision per guest). Then you fix the guest assignments and optimally redesign every table's theme to suit its guests. Alternate a few times and both sides converge to a good arrangement — and because each guest's reassignment doesn't depend on any other guest's, you can do them all in parallel.

💡 If you remember one thing

Fixing one factor matrix turns the whole problem into independent, closed-form ridge regressions — one per user (or per item). That's what makes each half-step exact, convex, and embarrassingly parallel across users/items: $$x_u = (Y^\top C_u Y + \lambda I)^{-1} Y^\top C_u p_u$$

How ALS Works Internally
▼

Implicit Feedback: No Ratings, Just Signal

With explicit ratings (1–5 stars) you'd factorize the rating matrix directly. Implicit feedback (clicks, watch time, purchase counts) has no "dislike" signal — a 0 might mean "hates it" or "never saw it." Hu, Koren & Volinsky (2008) reframed this: build a binary preference matrix \(p_{ui} = 1\) if any interaction was observed, else 0, and a confidence matrix \(c_{ui} = 1 + \alpha r_{ui}\) where \(r_{ui}\) is the raw interaction count. More interactions ⇒ more confidence that the preference is real — but we never claim absolute certainty.

The Alternating Update

The factor matrices are \(X \in \mathbb{R}^{n_u \times k}\) (users) and \(Y \in \mathbb{R}^{n_i \times k}\) (items), predicting \(\hat p_{ui} = x_u^\top y_i\). Jointly optimizing \(X\) and \(Y\) is non-convex (it's a bilinear form), but with \(Y\) fixed, the loss is a plain weighted ridge regression in \(x_u\) — strictly convex, unique global minimum, closed form. Symmetric for \(Y\) with \(X\) fixed. ALS just ping-pongs between these two convex subproblems.

Design Decision: Why Alternate Instead of Joint SGD?

Stochastic Gradient Descent (SGD) also factorizes matrices, but it processes one interaction at a time and needs careful learning-rate tuning. ALS's closed-form per-row solve (1) handles the full, dense confidence-weighted objective exactly (implicit feedback treats every unobserved pair as a negative with low confidence — that's a dense \(n_u \times n_i\) sum SGD can't easily subsample), and (2) each row update is fully independent of every other row in the same matrix, so it maps perfectly onto a MapReduce/Spark cluster: shard users across machines, broadcast \(Y\), solve all \(x_u\) with zero cross-machine communication.

🔑 Key Property

Every ALS half-step never increases the loss — each row solve is an exact minimizer of a convex quadratic given the other matrix. The joint loss is monotonically non-increasing across the whole alternating sequence, though the joint problem itself is non-convex (many local optima depending on initialization).

Why It Works — The Math
▼

The Objective

For implicit feedback (Hu, Koren, Volinsky 2008), minimize:

$$L(X,Y) = \sum_{u,i} c_{ui}\left(p_{ui} - x_u^\top y_i\right)^2 \;+\; \lambda\left(\sum_u \|x_u\|^2 + \sum_i \|y_i\|^2\right)$$

This is bilinear in \((X,Y)\) jointly — non-convex. But hold \(Y\) fixed and look only at the terms involving one user \(u\):

$$L_u(x_u) = \sum_i c_{ui}(p_{ui} - x_u^\top y_i)^2 + \lambda \|x_u\|^2$$

This is a strictly convex quadratic in \(x_u\) (a weighted ridge regression). Setting the gradient to zero:

$$\frac{\partial L_u}{\partial x_u} = -2Y^\top C_u p_u + 2(Y^\top C_u Y + \lambda I)x_u = 0$$

Solving gives the closed-form update, where \(C_u = \text{diag}(c_{u1},\dots,c_{un_i})\) is the diagonal confidence matrix for user \(u\):

$$x_u = (Y^\top C_u Y + \lambda I)^{-1} Y^\top C_u p_u$$

By symmetry, fixing \(X\) gives \(y_i = (X^\top C_i X + \lambda I)^{-1} X^\top C_i p_i\). Because \(\lambda I \succ 0\), the matrix being inverted is always positive-definite — the inverse always exists, no degenerate cases.

Why It's Parallelizable

Notice \(x_u\)'s formula only touches row \(u\) of the data and the (shared, read-only) matrix \(Y\). No \(x_{u'}\) for \(u' \neq u\) appears anywhere. So all \(n_u\) row-solves are data-parallel: broadcast \(Y\) (small: \(n_i \times k\)) to every worker, each worker solves a \(k \times k\) linear system per user it owns. Cost per row is \(O(n_i k^2 + k^3)\), fully independent — this is exactly why ALS (unlike SGD-based factorization) scales cleanly on Spark/MapReduce clusters with millions of users.

⚠️ Common Pitfall

ALS finds the global optimum of each half-step, but the overall joint objective is non-convex — different random initializations of \(X,Y\) can converge to different local optima. It's also sensitive to \(\alpha\) (confidence scaling) and \(\lambda\) (regularization); too little \(\lambda\) overfits to popular items, too much \(\alpha\) lets a handful of power users dominate the loss.

Key Takeaways
▼

When to use ALS:

  • Implicit feedback at large scale (clicks, views, purchases, watch time)
  • You have a distributed compute cluster (Spark MLlib's ALS is built exactly for this)
  • You want an exact, deterministic per-step solve rather than tuning SGD learning rates
  • Cold-start-adjacent settings where you periodically retrain in batch

When NOT to use:

  • Very large \(k\) (factor dimension) — solving \(k \times k\) systems per row gets costly, and SGD/coordinate descent variants scale better
  • Streaming, single-example updates — ALS is a batch algorithm; use online matrix factorization or neural retrieval instead
  • Rich side-features (text, images) you want to fuse into the model — ALS is a pure collaborative-filtering factorization
💡 Hierarchy

OLS (one closed-form solve) → Weighted Ridge Regression (one closed-form solve, per-row confidence weights) → ALS (alternate the same weighted ridge solve across two coupled matrices until the joint loss stops improving).

# R: raw interaction counts (n_users x n_items)
alpha, lam, k = 8.0, 0.3, 2
C = 1 + alpha * R # confidence
P = (R > 0).astype(float) # binary preference
X = init_small_random(n_users, k)

for iteration in range(n_iters):
# ---- fix Y, solve every user row IN PARALLEL ----
for u in range(n_users): # <- distribute across workers
Cu = np.diag(C[u])
A = Y.T @ Cu @ Y + lam * np.eye(k)
b = Y.T @ Cu @ P[u]
X[u] = np.linalg.solve(A, b)
# ---- fix X, solve every item row IN PARALLEL ----
for i in range(n_items): # <- distribute across workers
Ci = np.diag(C[:, i])
A = X.T @ Ci @ X + lam * np.eye(k)
b = X.T @ Ci @ P[:, i]
Y[i] = np.linalg.solve(A, b)
