AdaGrad: Per-Parameter Learning Rates

Adaptive Gradient Algorithm — accumulates squared gradients to scale each parameter's step size individually
Intermediate Optimization Calculus & Optimization O(d) memory
1
Understanding AdaGrad
▼

Plain SGD updates every parameter by the same global learning rate \(\eta\): it doesn't know which features show up rarely and which appear in every batch. In sparse data — NLP vocabularies, recommendation systems, bag-of-words — frequent words dominate gradients and quickly push their parameters far, while rare-word parameters barely move at all.

AdaGrad's core idea: give each parameter its own effective learning rate, automatically tuned by how much that parameter has been updated historically. Parameters that receive large or frequent gradients get a smaller step; parameters with small or infrequent gradients get a larger step. The algorithm does this without any manual per-parameter tuning.

Key Insight

AdaGrad divides each gradient by \(\sqrt{G_t + \varepsilon}\) where \(G_t = \sum_{\tau=1}^{t} g_\tau^2\) is the sum of squared historical gradients for that coordinate. Frequent coordinates accumulate large \(G_t\), shrinking their steps. Rare coordinates keep small \(G_t\), preserving large steps. The learning rate adapts itself from the gradient history.

Analogy: Imagine you're adjusting dials on a mixing board. Some dials (frequent features) get touched constantly — so you make each turn smaller to avoid overcorrecting. Others (rare features) are rarely touched, so when you finally reach one, you turn it boldly. AdaGrad is the mixing board that automatically learns how sensitive each dial is.

One-Sentence Summary

AdaGrad accumulates the squared gradient for each parameter and uses the square root of this accumulation to shrink step sizes for frequently-updated parameters while keeping step sizes large for rarely-updated ones.

Historical Context & Motivation
▼

The Problem with a Single Learning Rate

Before AdaGrad, standard SGD applied the same scalar learning rate \(\eta\) to all parameters equally: \(\theta_{t+1} = \theta_t - \eta g_t\). In dense, homogeneous data this works fine. But in natural language processing and recommender systems, features are wildly imbalanced: the word "the" appears millions of times per epoch while the word "serendipitous" might appear once. SGD's uniform step means frequent-feature parameters overshoot while rare-feature parameters never move enough. Practitioners had to hand-tune separate learning rates or use heuristics — both expensive and brittle.

The Breakthrough (2011)

Duchi, Hazan, and Singer introduced AdaGrad in "Adaptive Subgradient Methods for Online Learning and Stochastic Optimization" (JMLR 2011). The core insight: use the diagonal of the outer-product sum of gradients as a preconditioner. Instead of SGD's fixed \(\eta\), divide each coordinate's gradient by the root-mean-square of its past gradients. No hyperparameter tuning per coordinate — the geometry of the loss surface informs the step size automatically.

Key Paper

Duchi, Hazan & Singer (2011) — "Adaptive Subgradient Methods for Online Learning and Stochastic Optimization." JMLR 12. First algorithm to automatically per-adapt learning rates from gradient history. Regret bound: \(O(\sqrt{T})\) for convex problems.

Evolution Timeline

  • Before 2011: SGD, SGD+momentum — one global \(\eta\), manual tuning
  • 2011: AdaGrad — diagonal adaptive preconditioning, accumulates all history
  • 2012: RMSProp (Hinton, unpublished) — fixes vanishing LR with exponential moving average
  • 2014: Adam — combines RMSProp's EMA variance with momentum on gradients
  • 2016+: AdaDelta, AMSGrad, AdaBound — further refinements addressing Adam's convergence issues
AdaGrad's Fatal Flaw

Because \(G_t = \sum_{\tau=1}^{t} g_\tau^2\) grows monotonically and without bound, the effective learning rate \(\eta / \sqrt{G_t}\) decays toward zero. For non-convex deep networks trained over many epochs, learning effectively stops. RMSProp and Adam address this by replacing the full sum with an exponential moving average, so old gradients decay away.

The Mathematics of AdaGrad
▼

Full AdaGrad Update Rule

Let \(\theta \in \mathbb{R}^d\) be the parameter vector, \(g_t = \nabla_\theta \mathcal{L}(\theta_{t-1})\) the gradient at step \(t\), and \(\eta\) the global learning rate. Define:

$$G_t = \sum_{\tau=1}^{t} g_\tau \odot g_\tau = \sum_{\tau=1}^{t} g_\tau^2 \quad \in \mathbb{R}^d$$

where \(\odot\) denotes element-wise multiplication. The update for coordinate \(i\) is:

$$\theta_{t+1}^{(i)} = \theta_t^{(i)} - \frac{\eta}{\sqrt{G_t^{(i)} + \varepsilon}} \cdot g_t^{(i)}$$

where \(\varepsilon \approx 10^{-8}\) prevents division by zero. In matrix form (with diagonal matrix \(\text{diag}(G_t)^{1/2}\)):

$$\theta_{t+1} = \theta_t - \eta \cdot \text{diag}(G_t + \varepsilon \mathbf{1})^{-1/2} \cdot g_t$$

Why This is a Preconditioner

AdaGrad approximates the diagonal of the Fisher information matrix. The full Newton step uses \(H^{-1} g_t\) (the inverse Hessian times gradient). Computing the full Hessian is \(O(d^2)\). AdaGrad uses only the diagonal \(\text{diag}(G_t / t)^{-1/2}\) as a cheap \(O(d)\) preconditioner that adapts from data without computing second derivatives.

Effective Learning Rate & Decay Rate

The effective learning rate at step \(t\) for coordinate \(i\) is:

$$\eta_t^{(i)} = \frac{\eta}{\sqrt{G_t^{(i)} + \varepsilon}}$$

If coordinate \(i\) receives a constant gradient magnitude \(|g^{(i)}| = c\) every step, then \(G_t^{(i)} = c^2 t\) and:

$$\eta_t^{(i)} = \frac{\eta}{\sqrt{c^2 t + \varepsilon}} \approx \frac{\eta}{c\sqrt{t}}$$

The effective LR decays at rate \(O(1/\sqrt{t})\) for dense features — exactly the classical SGD convergence rate. For sparse features that fire \(k \ll t\) times, \(G_t^{(i)} = c^2 k\), so \(\eta_t^{(i)} \approx \eta/(c\sqrt{k})\) — much larger.

Regret Bound

For convex functions, AdaGrad achieves the following cumulative regret bound over \(T\) rounds:

$$R(T) = \sum_{t=1}^{T} \left[\mathcal{L}(\theta_t) - \mathcal{L}(\theta^*)\right] \leq \frac{1}{2\eta} \|\theta_1 - \theta^*\|^2 \cdot \text{tr}\!\left(\sqrt{G_T}\right)$$

For sparse problems where most coordinates have \(G_T^{(i)} \approx 0\), \(\text{tr}(\sqrt{G_T}) \ll d\sqrt{T}\), giving a much tighter bound than SGD's \(O(d\sqrt{T})\). This is the formal guarantee behind AdaGrad's advantage on sparse data.

Numerical Trace (Step 1)

Parameters: \(\theta = [1.0,\; 1.0]\), \(\eta = 0.5\), \(\varepsilon = 10^{-8}\). Gradient \(g_1 = [1.0,\; 2.0]\).

\(G_1 = [1^2,\; 2^2] = [1.0,\; 4.0]\)

\(\theta_2^{(1)} = 1.0 - 0.5/({\sqrt{1.0}+\varepsilon}) \cdot 1.0 = 0.5\)

\(\theta_2^{(2)} = 1.0 - 0.5/({\sqrt{4.0}+\varepsilon}) \cdot 2.0 = 1.0 - 0.5 = 0.5\)

Despite \(g^{(2)}\) being 2× larger, both parameters moved exactly 0.5 — AdaGrad automatically compensated.

Common Misconception

AdaGrad is not computing a running mean of squared gradients — it's computing a running sum. This is what causes the LR to go to zero. RMSProp replaces the sum with an exponential moving average: \(v_t = \beta v_{t-1} + (1-\beta) g_t^2\), bounding \(v_t\) and preventing the LR from vanishing.

AdaGrad vs Other Optimizers
▼

Comparison Table

All optimizers below use the same base update \(\theta \leftarrow \theta - \tilde{\eta} \cdot g_t\) but differ in how they compute \(\tilde{\eta}\):

Optimizer State per param LR decay Sparse data Deep nets
SGD None Manual schedule Poor Good (with tuning)
AdaGrad G_t (sum) Monotone → 0 Excellent Poor
RMSProp v_t (EMA) Bounded Good Good
Adam m_t + v_t Bounded Good Excellent
AdaDelta v_t + Δθ_t Bounded Good OK
When to Use AdaGrad

Use AdaGrad when: training shallow models on sparse data (NLP bag-of-words, tabular with many rare categories, word2vec skip-gram). Its convergence guarantee for convex functions is tight for sparse problems.

Avoid AdaGrad when: training deep neural networks over multiple epochs — the monotone LR decay stalls learning. Use Adam or RMSProp instead.

Code: From Scratch & Production
▼

From Scratch (NumPy)

import numpy as np
class AdaGrad:
def __init__(self, eta=0.01, eps=1e-8):
self.eta = eta # global learning rate
self.eps = eps # numerical stability floor
self.G = None # accumulated squared gradients per coordinate
def step(self, theta, grad):
if self.G is None:
self.G = np.zeros_like(theta) # lazy init, same shape as params
self.G += grad ** 2 # accumulate squared gradient (NEVER decays)
eff_lr = self.eta / (np.sqrt(self.G) + self.eps) # per-coord effective LR
theta = theta - eff_lr * grad # parameter update
return theta
# Usage example
opt = AdaGrad(eta=0.5)
theta = np.array([1.0, 1.0])
for t, grad in enumerate([[1.,2.],[0.,1.5],[2.,2.5],[0.,1.],[1.5,2.]]):
theta = opt.step(theta, np.array(grad))
print(f"t={t+1} G={opt.G} eff_lr={opt.eta/(np.sqrt(opt.G)+opt.eps)}")

Production Usage (PyTorch)

import torch, torch.optim as optim
model = MyModel()
# lr=0.01 typical; lr_decay adds optional schedule on top
optimizer = optim.Adagrad(
model.parameters(),
lr=0.01, # global η
eps=1e-10, # numerical floor (PyTorch default)
weight_decay=0, # L2 added BEFORE the adaptive scale
initial_accumulator_value=0, # G_0 — set > 0 to avoid huge first step
)
# ⚠️ Gotcha: AdaGrad state is NOT reset between epoch boundaries.
# If you checkpoint and resume, the G tensor must be saved too.
torch.save({'model': model.state_dict(),
'optimizer': optimizer.state_dict()}, 'ckpt.pt')
Interview Tip

Q: Why does AdaGrad use \(\sqrt{G_t}\) and not \(G_t\) directly? — Dimensional analysis: \(g_t\) has units of loss/parameter. \(G_t\) has units of (loss/param)². Dividing by \(\sqrt{G_t}\) restores units to loss/param, making the update scale to the natural scale of the gradient. Dividing by \(G_t\) itself would make the step dimensionally inconsistent and decay the LR far too aggressively (as \(1/G_t\) vs \(1/\sqrt{G_t}\)).
