Understanding Graph Representations
▼

What is it? A graph is a collection of nodes (or vertices) and edges (or links) connecting them. Graph representations are different ways to store this node and edge information in computer memory. The choice of representation profoundly impacts the efficiency (time and space complexity) of graph algorithms like Breadth-First Search (BFS), Depth-First Search (DFS), or finding shortest paths.

Analogy: Imagine you have a social network. How do you store who is friends with whom?

  1. You could use a giant spreadsheet where rows and columns are people, and a "✓" marks a friendship (Adjacency Matrix).
  2. Or, for each person, you could keep a list of their friends (Adjacency List).
  3. Or, you could just have one long list of every single friendship in the network (Edge List).
Each method has its strengths and weaknesses depending on what questions you ask most often (e.g., "Is Alice friends with Bob?" vs. "Who are all of Alice's friends?").

💡 If you remember one thing

The three primary graph representations — Adjacency Matrix, Adjacency List, and Edge List — offer fundamental trade-offs between space complexity (how much memory is used) and time complexity (how fast operations like checking for an edge or finding neighbors are). The "best" choice depends on the graph's characteristics (dense vs. sparse, directed vs. undirected, weighted vs. unweighted) and the operations most frequently performed.

How Each Representation Works
▼

1. Adjacency Matrix

This method uses a square 2D array (matrix) where both rows and columns represent nodes. For a graph with \(V\) nodes, the matrix will be \(V \times V\).

  • For an unweighted graph, an entry \(A_{ij} = 1\) if there's an edge from node \(i\) to node \(j\), and \(0\) otherwise.
  • For a weighted graph, \(A_{ij}\) stores the weight of the edge from \(i\) to \(j\), and typically \(0\) or \(\infty\) (infinity) if no edge exists.
  • For an undirected graph, the matrix is symmetric (\(A_{ij} = A_{ji}\)).

2. Adjacency List

This is an array (or hash map) where each index (or key) corresponds to a node. At each index, there's a list (or linked list, or dynamic array) containing all the neighbors of that node.

  • For an unweighted graph, the list for node \(i\) simply contains the nodes \(j\) to which \(i\) has an outgoing edge.
  • For a weighted graph, the list for node \(i\) contains pairs of \((j, w_{ij})\), where \(j\) is a neighbor and \(w_{ij}\) is the weight of the edge \(i \to j\).
  • For an undirected graph, if there's an edge between \(i\) and \(j\), then \(j\) will be in \(i\)'s list, AND \(i\) will be in \(j\)'s list.

3. Edge List

This is the simplest representation: just a list of all the edges in the graph. Each edge is represented as a tuple or object.

  • For an unweighted graph, each entry is a pair \((u, v)\) indicating an edge from \(u\) to \(v\).
  • For a weighted graph, each entry is a triplet \((u, v, w_{uv})\) indicating an edge from \(u\) to \(v\) with weight \(w_{uv}\).
  • For an undirected graph, an edge between \(u\) and \(v\) is typically stored only once, e.g., \((u, v)\) assuming \(u < v\), or simply \((u, v)\) and handled symmetrically by algorithms.

🔑 Key Properties

The choice of representation is a classic space-time trade-off. Adjacency Matrix is fast for checking if an edge exists (\(O(1)\)) but slow to find all neighbors in a sparse graph (\(O(V)\)). Adjacency List is efficient for sparse graphs and iterating neighbors (\(O(\text{deg}(v))\)) but slower for edge existence checks. Edge List is space-efficient for very sparse graphs but slow for most queries.

3
Why It Works — Complexity Analysis
▼

Let \(V\) be the number of vertices (nodes) and \(E\) be the number of edges. Typically, \(E\) can range from \(O(V)\) (for sparse graphs like trees) to \(O(V^2)\) (for dense graphs like complete graphs).

Adjacency Matrix

Definition: For an unweighted graph, the matrix \(A\) is defined as:

$$A_{ij} = \begin{cases} 1 & \text{if } (i,j) \in E \\ 0 & \text{otherwise} \end{cases}$$
For a weighted graph, \(A_{ij}\) stores the weight \(w_{ij}\) if \((i,j) \in E\), and a sentinel value (e.g., \(0\) or \(\infty\)) otherwise.
  • Space Complexity: \(O(V^2)\). This is because it always requires a \(V \times V\) matrix, regardless of how many edges exist.
  • Time Complexity:
    • Check if an edge \((i,j)\) exists: \(O(1)\) (direct lookup).
    • Find all neighbors of node \(i\): \(O(V)\) (must scan the entire row \(i\)).
    • Add/Remove an edge: \(O(1)\).

Adjacency List

Definition: An array \(Adj\) where each \(Adj[i]\) is a list of vertices \(j\) such that \((i,j) \in E\). For weighted graphs, \(Adj[i]\) stores pairs \((j, w_{ij})\).

$$Adj[i] = \{j \mid (i,j) \in E\} \quad \text{or} \quad \{(j, w_{ij}) \mid (i,j) \in E\}$$
  • Space Complexity: \(O(V+E)\). There are \(V\) lists, and each edge is stored once (for directed graphs) or twice (for undirected graphs, once in each direction).
  • Time Complexity:
    • Check if an edge \((i,j)\) exists: \(O(\text{deg}(i))\) (must scan \(i\)'s list).
    • Find all neighbors of node \(i\): \(O(\text{deg}(i))\) (iterate \(i\)'s list).
    • Add an edge: \(O(1)\) (append to list). Remove an edge: \(O(\text{deg}(i))\).

Edge List

Definition: A collection \(L\) of tuples, each representing an edge. For unweighted graphs, \((u,v)\); for weighted, \((u,v,w_{uv})\).

$$L = \{(u,v) \mid (u,v) \in E\} \quad \text{or} \quad \{(u,v,w_{uv}) \mid (u,v) \in E\}$$
  • Space Complexity: \(O(E)\). It stores exactly one entry per edge.
  • Time Complexity:
    • Check if an edge \((i,j)\) exists: \(O(E)\) (must scan the entire list).
    • Find all neighbors of node \(i\): \(O(E)\) (must scan the entire list).
    • Add an edge: \(O(1)\) (append to list). Remove an edge: \(O(E)\).

⚠️ When to be careful

For a sparse graph (few edges, \(E \ll V^2\)), an Adjacency Matrix wastes a lot of space. For a dense graph (many edges, \(E \approx V^2\)), an Adjacency List can have longer lists to scan for edge checks. Edge Lists are generally inefficient for graph traversal algorithms (BFS/DFS) as finding neighbors is slow, but excellent for algorithms that iterate all edges (e.g., Kruskal's MST algorithm).

Key Takeaways
▼
Representation Space Complexity Edge Check \( (u,v) \) Iterate Neighbors of \(u\) Best For
Adjacency Matrix \(O(V^2)\) \(O(1)\) \(O(V)\) Dense graphs, frequent edge existence checks.
Adjacency List \(O(V+E)\) \(O(\text{deg}(u))\) \(O(\text{deg}(u))\) Sparse graphs, BFS/DFS, iterating neighbors.
Edge List \(O(E)\) \(O(E)\) Very sparse graphs, algorithms that sort edges (Kruskal's).

When to use each:

  • Adjacency Matrix: Ideal for graphs where the number of edges \(E\) is close to \(V^2\) (dense graphs), or when you frequently need to check for the existence of an edge between any two nodes.
  • Adjacency List: Best for sparse graphs (\(E \ll V^2\)), as it uses significantly less memory. It's also very efficient for algorithms that need to find all neighbors of a given node (like BFS or DFS).
  • Edge List: Simple to implement and memory-efficient for extremely sparse graphs. It's particularly useful for algorithms that primarily iterate over all edges, such as Kruskal's algorithm for Minimum Spanning Trees, where edges are often sorted by weight.

When NOT to use:

  • Adjacency Matrix: Avoid for very sparse graphs with many nodes, as it wastes a lot of memory storing mostly zeros.
  • Adjacency List: Can be less efficient than an Adjacency Matrix for checking edge existence in very dense graphs, as it requires scanning a list.
  • Edge List: Not suitable for algorithms that frequently need to find neighbors of a node or check for edge existence, as these operations require iterating through the entire list of edges.
💡 General Rule

For most real-world graphs (especially large ones like social networks or the internet), which tend to be sparse, the Adjacency List is the most common and efficient choice. However, always consider the specific operations your algorithm will perform most often.

Code Trace (Python)
▼
# Example Graph: 4 nodes (0, 1, 2, 3)
NODES = 4
# --- Adjacency Matrix ---
# Initialize with 0s (no edges) or inf (no path for weighted)
adj_matrix = [[0] * NODES for _ in range(NODES)]
def add_edge_matrix(u, v, weight=1, directed=True):
adj_matrix[u][v] = weight
if not directed:
adj_matrix[v][u] = weight
add_edge_matrix(0, 1, 2) # 0 -> 1, weight 2
add_edge_matrix(0, 2, 5) # 0 -> 2, weight 5
# --- Adjacency List ---
# Initialize with empty lists for each node
adj_list = [[] for _ in range(NODES)]
def add_edge_list(u, v, weight=1, directed=True):
adj_list[u].append((v, weight)) # Store (neighbor, weight)
if not directed:
adj_list[v].append((u, weight))
add_edge_list(1, 2, 1) # 1 -> 2, weight 1
add_edge_list(2, 3, 3) # 2 -> 3, weight 3
# --- Edge List ---
# Initialize as an empty list of edges
edge_list = []
def add_edge_edge_list(u, v, weight=1, directed=True):
edge_list.append((u, v, weight)) # Store (source, dest, weight)
if not directed:
edge_list.append((v, u, weight)) # For undirected, add reverse too for simplicity
add_edge_edge_list(3, 1, 4) # 3 -> 1, weight 4
# --- Common operations ---
# Check if edge (0, 1) exists (weighted)
is_connected_matrix = adj_matrix[0][1] > 0
is_connected_list = any(v == 1 for v, w in adj_list[0])
is_connected_edge = any(u == 0 and v == 1 for u, v, w in edge_list)
# Get neighbors of node 0
neighbors_matrix = [i for i, val in enumerate(adj_matrix[0]) if val > 0]
neighbors_list = [v for v, w in adj_list[0]]
neighbors_edge = [e[1] for e in edge_list if e[0] == 0]
