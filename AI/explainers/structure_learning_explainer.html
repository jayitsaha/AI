1
Understanding Structure Learning
▼

What is it? A Bayesian network is a directed acyclic graph (DAG) where each node is a variable and each edge means "directly influences." Usually a human draws this graph. Structure learning discovers the graph automatically from data: which variables are conditionally independent of which others, once you already know a few of them?

Analogy: You're handed spreadsheets of patient records with no explanation of how the columns relate, and you want to reconstruct the doctor's mental flowchart. There are two ways to detective-work this out: score every candidate flowchart and keep the best one (score-based), or test pairs of symptoms for independence and erase arrows that don't hold up once you control for other variables (constraint-based).

💡 If you remember one thing

Score-based search asks "which graph makes the data most likely, penalized for complexity?" and searches with hill climbing. Constraint-based search asks "which edges survive after I control for every other variable?" and builds the graph from a sequence of conditional-independence tests (the PC algorithm). Both target the same object — the true DAG's Markov equivalence class — but fail differently on finite data.

2
How the Two Families Work Internally
▼

Score-Based: Hill Climbing over BIC

The joint distribution factorizes as \(P(X_1,\dots,X_n)=\prod_i P(X_i \mid \mathrm{Pa}(X_i))\), so any decomposable score — like BIC — is a sum of per-node terms. Hill climbing starts from an empty (or random) DAG and repeatedly applies the single local move (add-edge, remove-edge, reverse-edge) that most increases the total score, rejecting any move that creates a cycle, until no move improves the score.

$$\mathrm{BIC}(G,D)=\sum_{i=1}^n\Big[\ell_i(\hat\theta_i;D)-\tfrac{k_i}{2}\log N\Big]$$

Because only the child node's local term changes when you add/remove/reverse one edge, each candidate move can be scored in time proportional to that one node's data — not the whole network. This decomposability is what makes greedy search fast enough to run per-step.

Constraint-Based: The PC Algorithm

PC never scores a graph. It starts from the complete undirected graph (assume everything might be dependent) and, for growing conditioning-set size \(\ell=0,1,2,\dots\), tests every adjacent pair \((X,Y)\) for \(X\perp\!\!\!\perp Y \mid S\) for subsets \(S\) of size \(\ell\). Any pair found conditionally independent has its edge deleted, and the conditioning set \(S\) is remembered as \(\mathrm{Sep}(X,Y)\). Once no more edges can be removed, PC orients v-structures — unshielded triples \(X-Z-Y\) where \(Z \notin \mathrm{Sep}(X,Y)\) become colliders \(X\rightarrow Z \leftarrow Y\) — then propagates further orientations with Meek's rules.

Design Decision: Why does PC start conditioning-set size at 0?

Real-world graphs are usually sparse (few true parents per node), so most false edges are killed early and cheaply with small conditioning sets. The algorithm only pays the exponential cost of large conditioning sets for the few nodes with genuinely large neighborhoods — a huge saving over testing every subset up front.

🔑 Key Property

Two DAGs are Markov equivalent — indistinguishable from observational data — iff they share the same skeleton and the same v-structures (Verma & Pearl, 1990). This is why constraint-based search naturally outputs a CPDAG (some edges left undirected) rather than a single DAG.

3
Why It Works — The Math
▼

Deriving BIC from the Marginal Likelihood

A Laplace approximation to the log marginal likelihood \(\log P(D\mid G)\) around the MLE \(\hat\theta\) gives:

$$\log P(D\mid G) \approx \log P(D\mid G,\hat\theta) - \frac{|\theta|}{2}\log N + O(1)$$

Dropping the constant \(O(1)\) term yields the BIC score used to compare candidate DAGs. Because the log-likelihood factorizes over the DAG's local conditional distributions, the score is a sum over nodes — and if two DAGs \(G,G'\) differ only in node \(i\)'s parent set:

$$\mathrm{BIC}(G')-\mathrm{BIC}(G)=\big[\ell_i(G')-\ell_i(G)\big]-\frac{k_i(G')-k_i(G)}{2}\log N$$

Only node \(i\)'s local term needs recomputation — this is exactly why hill climbing can cheaply evaluate every candidate edge addition/removal/reversal at every step.

The Conditional Independence Test (G² / χ²)

PC tests \(H_0: X\perp Y \mid S{=}s\) for discrete variables using the log-likelihood-ratio statistic, pooled across every stratum of \(S\):

$$G^2 = 2\sum_{x,y} O_{xy}\log\frac{O_{xy}}{E_{xy}}, \qquad E_{xy}=\frac{O_{x\cdot}\,O_{\cdot y}}{O_{\cdot\cdot}}$$

which is asymptotically \(\chi^2\)-distributed with \((|X|-1)(|Y|-1)\) degrees of freedom (summed across strata) under \(H_0\). A large p-value (fails to reject \(H_0\)) means the edge is deleted.

📐 Formula Box — Verma-Pearl Equivalence

\(G_1 \sim_{\text{Markov}} G_2 \iff \mathrm{skeleton}(G_1)=\mathrm{skeleton}(G_2)\) and \(\mathrm{v\text{-}structures}(G_1)=\mathrm{v\text{-}structures}(G_2)\). This theorem is the mathematical reason observational data can only pin down a CPDAG.

⚠️ Common Misconception

"A learned DAG shows causal direction." Not from observational data alone. Without interventions or extra distributional assumptions (non-Gaussian/non-linear noise, as in LiNGAM), both families can only identify the graph up to Markov equivalence — a directed edge outside a v-structure is one arbitrary, consistent choice, not proof of causality.

Key Takeaways
▼

When to use score-based (hill climbing):

  • Small-to-medium variable count, need one usable DAG immediately for inference
  • You have a sensible prior for BDeu's equivalent sample size, or trust BIC's consistency
  • You want to inject domain knowledge as edge black-lists / white-lists to prune search

When to use constraint-based (PC):

  • Large, sparse graphs where most true parent sets are small
  • You want statistically interpretable edge deletions (p-values) rather than a black-box score
  • A partially-oriented CPDAG is an acceptable (or preferred, more honest) output
💡 Hierarchy

Both families target the same object: the true DAG's Markov equivalence class. Hill climbing commits to one representative DAG in that class (sometimes the wrong local optimum); PC returns the whole equivalence class as a CPDAG, honestly leaving unidentifiable edges undirected. Hybrid methods like MMHC use PC-style tests to build a candidate neighborhood, then score-based search to pick and orient edges — combining the speed of testing with the single-DAG output of scoring.

Code Trace — Hill Climbing Loop
▼
def local_bic(data, child, parents, N):
ch = data[child]
if not parents:
p1 = clip(ch.mean(), 1e-9, 1-1e-9)
ll = sum(ch*log(p1) + (1-ch)*log(1-p1))
return ll - 0.5 * 1 * log(N)
# ...else sum log-lik over each parent-value combo
k = 2 ** len(parents) # binary parents
return ll - 0.5 * k * log(N)
def hill_climb(data, nodes, N):
dag = {n: [] for n in nodes}
score = sum(local_bic(data, n, [], N) for n in nodes)
while True:
best_gain, best_move = 0.0, None
for child in nodes:
for parent in nodes:
if parent == child or parent in dag[child]: continue
trial_parents = dag[child] + [parent]
if creates_cycle(dag, child, parent): continue
gain = local_bic(data, child, trial_parents, N) \
- local_bic(data, child, dag[child], N)
if gain > best_gain: best_gain, best_move = gain, (parent, child)
if best_move is None: break # local optimum
p, c = best_move; dag[c].append(p); score += best_gain
return dag, score
