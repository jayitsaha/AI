Training, Validation & Test Sets

Why and how to split your data — the foundation of honest ML evaluation
Foundational Classical ML Model Evaluation Must Know Leakage Risk
1
Understanding the Concept
▾

Before a model can be trusted in the real world, it must be evaluated on data it has never seen. The problem: if you test a model on the same data you trained it on, it will look far better than it actually is — like grading your own exam using the answer key you studied.

💡 The Core Idea

We divide the dataset into three non-overlapping buckets. The training set teaches the model. The validation set guides decisions about model architecture and hyperparameters. The test set is a time capsule — sealed until the very end — that reports the true, unbiased performance.

Analogy. Imagine you're studying for a maths exam. The training set is your practice problems — you work through them repeatedly. The validation set is a mock exam your teacher gives you to see which topics need more revision (tuning). The test set is the real exam, sat only once. If you looked at the real exam questions while studying, your grade would be meaningless — that's data leakage.

🔑 Key Property

The test set must be touched exactly once. Any decision made after seeing test-set results (re-training, threshold tuning, feature engineering) invalidates it as an unbiased estimator.

Stratification

A random split on imbalanced data can produce a validation set with zero positive examples. Stratified splitting preserves the class distribution in every subset.

∑ The Guarantee

If class \(k\) has proportion \(p_k\) in the full dataset \(D\), stratified splitting ensures each subset \(S\) satisfies \(\hat{p}_k(S) \approx p_k\). Formally, each subset is drawn by sampling independently within each stratum.

In sklearn: train_test_split(X, y, stratify=y)

Data Leakage — The Silent Killer

🚨 Leakage = Inflated Scores

Leakage occurs when information from the validation or test set (labels, statistics, future data) bleeds into the training pipeline. The model exploits a shortcut that won't exist at deployment. Reported accuracy can be 10–40% higher than real-world performance.

Common leakage patterns:

  • Fitting a scaler/imputer on the full dataset, then splitting
  • Feature engineering that looks at future rows (time series)
  • Using a feature that is a proxy for the label
  • Running multiple test-set evaluations then picking the best

Fix: Always fit preprocessing inside the training fold only. Use Pipeline in sklearn to enforce this automatically.

The Math — Bias–Variance of the Estimator
▾

Let \(\hat{e}\) be the test-set error estimate and \(e^*\) the true generalisation error. The quality of the split determines how close \(\hat{e}\) is to \(e^*\).

$$\mathbb{E}[(\hat{e} - e^*)^2] = \underbrace{\text{Bias}^2(\hat{e})}_{\text{optimism if test polluted}} + \underbrace{\text{Var}(\hat{e})}_{\text{small test set = high variance}}$$

The variance term decreases with test-set size \(n_\text{test}\):

$$\operatorname{Var}(\hat{e}) \approx \frac{e^*(1 - e^*)}{n_\text{test}}$$

This is a binomial variance under the normal approximation. A 95% confidence interval for the true error is:

$$\hat{e} \pm 1.96\sqrt{\frac{\hat{e}(1-\hat{e})}{n_\text{test}}}$$
∑ Implication

With \(n_\text{test}=100\) and \(\hat{e}=0.2\), the CI is \(\pm 7.8\%\). With \(n_\text{test}=10{,}000\), it narrows to \(\pm 0.78\%\). This is why reporting model accuracy on a 100-sample test set without a confidence interval is misleading.

When the test set is peeked at multiple times (say \(k\) comparisons), the effective false positive rate inflates. By Bonferroni correction, the true significance level becomes \(\alpha_\text{eff} = k \cdot \alpha\). This is why the test set is sacred: it is a single-use instrument.

Key Takeaways & Related Topics
▾
  • Three-way split is the foundation of all model selection and evaluation in ML.
  • The test set is a one-shot instrument — any reuse inflates the false positive rate and invalidates results.
  • Stratification is mandatory for class imbalance; otherwise validation metrics are unreliable.
  • All preprocessing must be fit on train only — use sklearn Pipeline to enforce this.
  • Larger test sets produce narrower confidence intervals and more trustworthy error estimates.
  • For small datasets, replace the fixed split with k-fold cross-validation (inner loop for tuning, outer loop for evaluation = nested CV).
