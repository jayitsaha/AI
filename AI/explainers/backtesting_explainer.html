1
Understanding Backtesting
▼

What is it? Backtesting is how you find out whether a model that predicts the future (stock returns, demand, weather) would actually have worked, by replaying it against history in the correct chronological order. Unlike ordinary cross-validation, you are never allowed to train on data that comes after the period you are testing on — that would be like grading a student's exam using the answer key from a future test.

Analogy: Think of a flight simulator used to certify pilots. You never let the trainee "peek" at how the flight actually ended before they practice the landing — that would make every landing look perfect and tell you nothing. Backtesting is the same discipline applied to models: at every point in simulated time, the model only sees what would have really been available at that moment.

💡 If you remember one thing

Ordinary k-fold cross-validation shuffles data randomly, which silently lets the model "see the future." Backtesting schemes — expanding window, sliding window, and purged CV — all preserve time order and additionally remove any samples whose information could leak across the train/test boundary.

2
How It Works Internally
▼

Three Walk-Forward Schemes

Expanding window (a.k.a. anchored walk-forward): the training set always starts at time 0 and keeps growing, fold after fold, while the test window slides forward by a fixed step. Every fold uses strictly more history than the last — nothing is ever thrown away.

Sliding window (a.k.a. rolling window): the training set has a fixed size and slides forward together with the test window, always dropping the oldest observations. This keeps the model reactive to regime changes but caps how much history it can learn from.

Purged cross-validation: even with time order respected, leakage can still creep in through the back door — if a feature at time \(t\) is built from a rolling window of the previous \(L\) observations (e.g. a moving average) or a label looks \(H\) steps into the future, then train samples adjacent to the test fold overlap with it informationally. Purged CV removes a purge zone of width \(L\) before the test fold and an embargo zone of width \(H\) after it, deleting exactly the samples that share information with the test set.

🔑 Key Property

All three schemes evaluate the model on a sequence of out-of-sample folds and average the per-fold error into one backtest score. The differences are only in which observations are allowed into the training set for each fold — anchored, rolling, or purged.

Design Decision: Why not just shuffle and use k-fold?

Standard k-fold CV assumes samples are i.i.d. Time series violate this: observations are autocorrelated, and features/labels routinely span multiple time steps. Shuffling would place a training point from "next Tuesday" right next to a test point from "this Monday," letting the model implicitly learn from information that would not have existed yet. This is called lookahead bias, and it is the single most common reason backtests look great on paper and fail in production.

3
Why It Works — The Math
▼

Fold Error and the Backtest Score

For fold \(k\) with test set \(T_k\) and a model trained only on the allowed training set \(D_k\), the fold error is:

$$s_k = \frac{1}{|T_k|}\sum_{t \in T_k} \ell\big(y_t, \hat{y}_t\big), \qquad \hat{y}_t = f_{\theta}(x_t \mid D_k)$$

The overall backtest score averages across the \(K\) folds:

$$\text{BacktestScore} = \frac{1}{K}\sum_{k=1}^{K} s_k$$

The Purge and Embargo Condition

Let features use a lookback of \(L\) steps and labels use a horizon of \(H\) steps. A training index \(i\) is contaminated if it falls within reach of the test window \([t_0, t_1)\):

$$D_k = \Big\{\, i : i \notin [t_0 - L,\ t_1 + H) \,\Big\}$$

The interval \([t_0-L, t_0)\) is the purge zone (removes train points whose forward-looking labels reach into the test set), and \([t_1, t_1+H)\) is the embargo zone (removes train points whose backward-looking features would reuse test information right after it). Both are excluded from \(D_k\) — never used for training or evaluation.

⚠️ Common Pitfall

Even a "time-ordered" split without purging can leak. If a feature is a 5-day moving average, the training sample immediately before the test fold already contains values that were computed using data points that overlap the test period's neighborhood in autocorrelation. Purging removes exactly the width of the longest lookback/label horizon in your pipeline — not an arbitrary buffer.

Key Takeaways
▼

When to use each scheme:

  • Expanding window — stable, slowly-evolving processes where more history always helps (e.g. macro forecasting).
  • Sliding window — regime-shifting or non-stationary processes where old data goes stale (e.g. short-term trading signals).
  • Purged CV (+ embargo) — whenever features/labels span multiple time steps, especially in finance (De Prado's triple-barrier labels, rolling technical indicators).

When NOT to use plain k-fold on time series: if there is any autocorrelation, rolling features, or forward-looking labels — random shuffling will leak and inflate your validation score, making a useless model look production-ready.

💡 Hierarchy

Shuffled k-fold (breaks time order) ⊂ Walk-forward (respects order, expanding or sliding) ⊂ Purged + embargoed walk-forward (respects order AND removes information overlap). Each step removes one more source of leakage.

import numpy as np
def expanding_folds(n, n_folds, test_size):
step = test_size
for k in range(n_folds):
test_start = (k + 2) * step
train_idx = np.arange(0, test_start) # anchored at 0
test_idx = np.arange(test_start, test_start + step)
yield train_idx, test_idx
def sliding_folds(n, n_folds, train_size, test_size):
for k in range(n_folds):
train_start = k * test_size + 2
train_idx = np.arange(train_start, train_start + train_size) # fixed size
test_idx = np.arange(train_start + train_size, train_start + train_size + test_size)
yield train_idx, test_idx
def purged_folds(n, test_windows, purge, embargo):
for (t0, t1) in test_windows:
purge_zone = np.arange(max(0, t0 - purge), t0) # drop before test
embargo_zone = np.arange(t1, min(n, t1 + embargo)) # drop after test
train_idx = np.setdiff1d(np.arange(n), np.r_[purge_zone, np.arange(t0, t1), embargo_zone])
test_idx = np.arange(t0, t1)
yield train_idx, test_idx
def backtest_score(y, folds):
fold_errors = []
for train_idx, test_idx in folds:
baseline = y[train_idx].mean() # naive forecast
mae = np.abs(y[test_idx] - baseline).mean()
fold_errors.append(mae)
return np.mean(fold_errors), fold_errors
