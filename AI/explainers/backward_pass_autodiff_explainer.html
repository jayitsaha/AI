Backward Pass: Chain Rule & Reverse-Mode Automatic Differentiation

How one backward sweep through a computation graph produces every parameter's gradient
Intermediate Deep Learning Optimization O(1) extra passes
1
Understanding the Backward Pass
▼

What is it? Training a network means nudging millions of weights so a single loss number goes down. The backward pass is the algorithm that computes exactly how much every weight should move — all of them, simultaneously — in roughly the cost of one extra forward pass.

Analogy: A company's profit depends on a long chain of departments, each affecting the next. If profit drops, you don't guess how much each of 10,000 employees contributed. Instead you trace blame backward: each department multiplies its own "local blame factor" by however much blame already arrived from downstream, and passes the product further back. That is exactly what the backward pass does — automatically, exactly, for every operation in a computation graph.

💡 If you remember one thing

The backward pass walks the computation graph once, from output to inputs, in reverse topological order. At each node it multiplies the gradient arriving from downstream by a cheap local derivative, and accumulates (sums) contributions whenever a node feeds more than one consumer: $$\bar v = \sum_{u\,\in\,\text{children}(v)} \bar u \cdot \frac{\partial u}{\partial v}$$

2
How It Works Internally
▼

Two Passes Over One Graph

The forward pass evaluates the function bottom-up, visiting each node only after all of its inputs are known, and caches every intermediate value (the "primal" values) because the backward pass will need them. The backward pass then re-visits every node in the exact reverse of that order, starting from the output.

The Local Rule at Every Node

Every primitive operation (add, multiply, matmul, sin, ReLU, …) ships with a local vector-Jacobian product (VJP) rule. Given the upstream gradient \(\bar u = \partial L/\partial u\) for an op \(u = g(v)\), the rule returns \(\bar v = \bar u \cdot \partial u/\partial v\) — never the full Jacobian, only the product of it with the incoming gradient. That is what keeps reverse-mode cheap even when \(v\) and \(u\) are huge tensors.

Fan-Out Means Accumulation

If a node feeds two or more consumers (like x or a in the graph on the right), each consumer sends back its own contribution, and those contributions are summed, not overwritten. A node's gradient is only final once every one of its consumers has already propagated.

🔑 Key Property

Reverse topological order guarantees correctness: by the time a node is visited, every consumer that depends on it has already sent back its complete contribution — so summing them at that moment yields the node's true, final gradient.

⚙️ Design Decision

Why a dynamic "define-by-run" tape (PyTorch, JAX) instead of a static pre-compiled graph (early TensorFlow 1.x)? Rebuilding the graph every forward call trades away some whole-graph optimization opportunity in exchange for native Python control flow, easy debugging, and variable-shape inputs.

3
Why It Works — The Math
▼

The Multivariable Chain Rule on a DAG

For a scalar loss \(L\) and any node \(v\), the total derivative sums over every consumer \(u\) of \(v\):

$$\bar v = \frac{\partial L}{\partial v} = \sum_{u\,\in\,\text{children}(v)} \bar u \cdot \frac{\partial u}{\partial v}$$

Reverse-mode AD evaluates this recursion once per node, in reverse topological order — producing \(\bar v\) for every node, including all \(n\) parameters, in a single backward sweep.

Reverse-Mode vs Forward-Mode Cost

For \(f:\mathbb{R}^n \to \mathbb{R}^m\), let \(c\) be the cost of one forward evaluation:

$$\text{forward-mode} \approx O(n)\cdot c \qquad\qquad \text{reverse-mode} \approx O(m)\cdot c$$

Forward-mode propagates one input direction per pass (needs \(n\) passes for all Jacobian columns); reverse-mode propagates one output direction per pass (needs only \(m\)). Deep nets have \(n\) = millions of parameters but \(m=1\) (a scalar loss) — so reverse-mode gets every gradient in about one backward pass.

Proof Sketch (Induction on Topological Order)

Base case: the output's own gradient is trivially \(\bar L = 1\). Inductive step: assume every consumer of \(v\) already holds its final, fully-accumulated gradient — true because topological order processes all of \(v\)'s consumers strictly before \(v\). Then the sum \(\bar v=\sum_u \bar u\,\partial u/\partial v\) is complete the instant \(v\) is visited. By induction this holds for every node down to the leaves.

⚠️ Common Misconception

"The backward pass reverses/inverts the forward operations." False — it never inverts a function. It propagates derivative values (VJPs) through each op's local Jacobian transpose, which is perfectly well-defined even for non-invertible ops like ReLU, max-pooling, or a sum-reduction.

Key Takeaways
▼

When the backward pass (reverse-mode AD) wins:

  • Many inputs, one scalar output — exactly the shape of a neural-network training loop (millions of parameters, one loss).
  • You need exact gradients, not finite-difference approximations.
  • The computation graph has shared sub-expressions worth reusing (avoids symbolic "expression swell").

When to prefer something else:

  • Few inputs, many outputs (e.g. the full Jacobian of a low-dimensional function) → forward-mode AD is cheaper.
  • Sanity-checking a hand-written gradient → finite differences (gradient checking), never for training itself.
  • Need a Hessian-vector product → combine forward-over-reverse mode.
💡 The One-Line Summary

One backward sweep, reverse topological order, local VJP at every node, sum at every fan-out — and you get exact gradients for every parameter at roughly the cost of one extra forward pass.

class Value:
def __init__(self, data, parents=()):
self.data = data
self.grad = 0.0 # accumulated dL/d(self)
self._parents = parents
self._backward = lambda: None
def __mul__(self, other):
out = Value(self.data * other.data, (self, other))
def _backward():
self.grad += out.grad * other.data # local deriv = other
other.grad += out.grad * self.data # local deriv = self
out._backward = _backward
return out
def __add__(self, other):
out = Value(self.data + other.data, (self, other))
def _backward():
self.grad += out.grad * 1.0 # local deriv = 1
other.grad += out.grad * 1.0 # local deriv = 1
out._backward = _backward
return out

topo, seen = [], set()
def build(v): # DFS post-order
if v not in seen:
seen.add(v)
for p in v._parents: build(p)
topo.append(v)
build(self)
self.grad = 1.0 # seed
for node in reversed(topo): # REVERSE topo order
node._backward() # accumulate (+=) into parents
