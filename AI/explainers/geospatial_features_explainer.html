Understanding Geospatial Features
▼

What is it? Raw latitude and longitude pairs \((lat, lon)\) are often poor features for machine learning models. They represent points on a sphere, not a flat Cartesian plane, meaning simple Euclidean distance is misleading. Also, they don't inherently capture concepts like "nearby," "within the same neighborhood," or "belonging to a dense region." Geospatial feature engineering transforms these raw coordinates into more meaningful, model-friendly representations that capture distance, proximity, and spatial relationships.

Analogy: Imagine trying to predict house prices using only street numbers. It's hard because "100 Main St" and "101 Main St" are close, but "100 Elm St" might be far, even if "100" is also a small number. Geospatial features are like adding "distance to downtown," "neighborhood ID," or "population density within 1km" — information that actually helps predict value, rather than just raw numbers.

💡 If you remember one thing

Geospatial features address the non-Euclidean nature of Earth's surface and the need to encode spatial relationships. Haversine distance measures accurate "as-the-crow-flies" distance, geohashing provides hierarchical spatial indexing, and spatial clustering identifies natural groupings of points.

How These Techniques Work Internally
▼

Haversine Distance: Great-Circle Measurement

The Haversine formula calculates the "great-circle" distance between two points on a sphere (like Earth) given their latitudes and longitudes. Unlike Euclidean distance, which treats coordinates as a flat grid, Haversine accounts for the curvature of the Earth. It's crucial when distances are significant (e.g., across cities or countries) or when precise routing/travel time is important. It's often used directly as a feature (e.g., distance from a point to a city center) or as a metric within spatial algorithms.

Geohashing: Hierarchical Spatial Grid Encoding

Geohashing converts a latitude and longitude pair into a short alphanumeric string. This string represents a rectangular cell on a grid covering the Earth. The key properties are: (1) Hierarchy: longer geohashes represent smaller, more precise cells; shorter geohashes represent larger, coarser cells. (2) Spatial Locality: points that are spatially close tend to have geohashes with long common prefixes. This makes geohashes excellent for efficient spatial indexing, searching for nearby points, or creating categorical features like "neighborhood ID" at different granularities.

Spatial Clustering: Discovering Natural Groupings

Spatial clustering algorithms group geographically proximate points into clusters. Unlike general clustering, spatial clustering often uses distance metrics appropriate for geographic data (like Haversine). Common algorithms include DBSCAN (Density-Based Spatial Clustering of Applications with Noise), which finds clusters of arbitrary shapes based on density, or variations of K-Means that incorporate geographic distance. Output features can include the cluster ID for each point, or the distance from each point to its cluster's centroid, capturing local density and regional patterns.

Design Decision: Why these over raw lat/lon?

Raw \((lat, lon)\) coordinates have several issues: (1) Non-Euclidean: A degree of latitude is roughly constant, but a degree of longitude shrinks towards the poles. (2) Circular Nature: Longitude wraps around at \(\pm 180^\circ\), and latitude at \(\pm 90^\circ\), which linear models struggle with. (3) Lack of Context: They don't inherently tell a model about proximity or density. These techniques transform raw coordinates into features that are either distance-aware, spatially indexed, or contextually grouped, making them much more informative for ML models.

🔑 Key Property

Each method addresses a different aspect of spatial information: Haversine provides accurate pairwise distances, Geohashing creates discrete, hierarchical spatial bins, and Spatial Clustering identifies emergent regional patterns. Together, they form a powerful toolkit for enriching location data.

3
Why It Works — The Math
▼

Haversine Formula Derivation

The Haversine formula is derived from spherical trigonometry. Given two points \((lat_1, lon_1)\) and \((lat_2, lon_2)\) on a sphere with radius \(R\), the distance \(d\) is calculated as:

$$a = \sin^2\left(\frac{\Delta lat}{2}\right) + \cos(lat_1) \cos(lat_2) \sin^2\left(\frac{\Delta lon}{2}\right)$$
$$c = 2 \cdot \operatorname{atan2}(\sqrt{a}, \sqrt{1-a})$$
$$d = R \cdot c$$

Where \(\Delta lat = lat_2 - lat_1\), \(\Delta lon = lon_2 - lon_1\), and all latitudes/longitudes must be in radians. \(a\) is the square of half the central angle between the points, \(c\) is the central angle itself, and \(R\) is Earth's radius (approx. 6371 km). This formula is numerically stable for small distances, unlike some other spherical distance formulas.

Geohashing: Interleaving Bits

Geohashing works by recursively dividing the Earth into smaller and smaller cells. The process involves:

  1. Bisecting the longitude range \([-180, 180]\) and assigning a bit (0 or 1) based on which half the point falls into.
  2. Bisecting the latitude range \([-90, 90]\) and assigning a bit.
  3. Alternating between longitude and latitude bisections, generating a sequence of bits.
  4. Interleaving these bits (e.g., \(lon\_bit_1 lat\_bit_1 lon\_bit_2 lat\_bit_2 \dots\)).
  5. Encoding the resulting binary string into a base-32 alphanumeric string (using characters 0-9 and a-z, excluding a few to avoid ambiguity).

For example, a precision of 1 character corresponds to 5 bits, a precision of 2 characters to 10 bits, and so on. This bit interleaving ensures that nearby locations tend to share longer prefixes.

Spatial Clustering: Density-Based Grouping (DBSCAN)

DBSCAN groups points that are closely packed together, marking as outliers points that lie alone in low-density regions. It requires two parameters: \(\epsilon\) (epsilon), which defines the maximum distance between two samples for one to be considered as in the neighborhood of the other, and \(min\_samples\), the number of samples in a neighborhood for a point to be considered as a core point. The algorithm iteratively expands clusters from core points by finding all density-reachable points using the defined distance metric (e.g., Haversine).

⚠️ Common Pitfall

Geohashing suffers from "border effects" — two points very close to each other but on opposite sides of a geohash cell boundary will have entirely different geohashes, losing spatial locality. This can be mitigated by querying neighboring geohash cells or using multiple geohash resolutions as features. Similarly, spatial clustering results are highly sensitive to the choice of \(\epsilon\) and \(min\_samples\).

Key Takeaways
▼

When to use these geospatial features:

  • Haversine Distance: When the "as-the-crow-flies" distance between two points on Earth is a critical feature, especially for large distances (e.g., logistics, travel time prediction, radius searches).
  • Geohashing: For efficient spatial indexing, querying nearby points, or creating categorical "neighborhood" features at various granularities. Useful for grouping events or finding points within a specific area.
  • Spatial Clustering: To discover natural groupings or dense regions in your data. Features derived from clusters (e.g., cluster ID, distance to cluster centroid, cluster density) can capture important local context for models like fraud detection, demand forecasting, or urban planning.

When NOT to use / be cautious:

  • Small-scale problems: For very small areas (e.g., within a few city blocks), Euclidean distance might be a sufficient and computationally cheaper approximation.
  • Computational cost: Calculating Haversine for all pairs in a large dataset is \(O(N^2)\). Geohash indexing is faster (\(O(N)\) or \(O(N \log N)\)) but has border issues. Clustering can be computationally intensive, especially for large datasets or complex algorithms.
  • Interpretability: While powerful, engineered features can sometimes be less directly interpretable than raw coordinates.
💡 Rule of Thumb

Always consider the scale of your problem and the nature of spatial relationships you want to capture. For global or regional scale, Haversine and Geohashing are essential. For local density and patterns, spatial clustering adds rich context. Often, a combination of these features yields the best model performance.

import numpy as np
from math import radians, sin, cos, sqrt, atan2
import geohash as gh # pip install geohash
from sklearn.cluster import DBSCAN # pip install scikit-learn
EARTH_RADIUS_KM = 6371
def haversine_distance(lat1, lon1, lat2, lon2):
"""Calculates great-circle distance between two points in km."""
lat1, lon1, lat2, lon2 = map(radians, [lat1, lon1, lat2, lon2])
dlat = lat2 - lat1
dlon = lon2 - lon1
a = sin(dlat / 2)**2 + cos(lat1) * cos(lat2) * sin(dlon / 2)**2
c = 2 * atan2(sqrt(a), sqrt(1 - a))
return EARTH_RADIUS_KM * c
def get_geohash(lat, lon, precision=6):
"""Encodes lat/lon into a geohash string."""
return gh.encode(lat, lon, precision)
def spatial_dbscan(points_df, eps_km, min_samples=2):
"""Performs DBSCAN clustering using Haversine distance."""
# DBSCAN requires a distance matrix or a custom metric function
# For efficiency with many points, usually use a BallTree or similar
coords = points_df[['latitude', 'longitude']].values
db = DBSCAN(eps=eps_km, min_samples=min_samples, metric=haversine_distance, n_jobs=-1)
clusters = db.fit_predict(coords)
points_df['cluster_id'] = clusters
return points_df
