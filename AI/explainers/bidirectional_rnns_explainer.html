Bidirectional RNNs

Reading a sequence forwards AND backwards, in parallel, to see the whole context
Intermediate Sequence Models NLP O(n) · two passes
1
Understanding Bidirectional RNNs
▼

What is it? A standard (unidirectional) RNN reads a sentence left to right — at word 3, it only knows words 1 and 2. That's fine for generating text, but terrible for understanding text, where the meaning of a word often depends on what comes after it too. A Bidirectional RNN (BiRNN) runs two independent RNNs over the same sequence — one forward (→), one backward (←) — and glues their hidden states together at every position.

Analogy: Imagine reading a mystery novel one page at a time versus being handed the whole book. If you only read forward, "he" on page 50 is ambiguous until page 80 reveals who "he" is. A bidirectional reader skims the whole book first, then annotates page 50 knowing both what happened before and after. That's exactly what concatenating forward and backward hidden states gives each token.

💡 If you remember one thing

Each output token's representation is the concatenation of a forward hidden state (all context to the left) and a backward hidden state (all context to the right): $$h_t = [\overrightarrow{h}_t \, ; \, \overleftarrow{h}_t]$$ giving every position full past and future context — at the cost of needing the entire sequence up front (no streaming generation).

2
How It Works Internally
▼

Two RNNs, Same Input, Opposite Directions

Given an input sequence \(x_1, x_2, \dots, x_n\) (word embeddings), a BiRNN instantiates two separate recurrent layers with independent weights:

  • Forward RNN \((\overrightarrow{W}_x, \overrightarrow{W}_h, \overrightarrow{b})\): processes \(x_1 \to x_2 \to \dots \to x_n\), producing \(\overrightarrow{h}_1, \dots, \overrightarrow{h}_n\).
  • Backward RNN \((\overleftarrow{W}_x, \overleftarrow{W}_h, \overleftarrow{b})\): processes \(x_n \to x_{n-1} \to \dots \to x_1\), producing \(\overleftarrow{h}_n, \dots, \overleftarrow{h}_1\).

Both passes are computed independently — the backward pass does not wait for the forward pass to finish, they can run in parallel (two separate matrix chains). Only after both finish do we combine them per position: \(h_t = [\overrightarrow{h}_t \,;\, \overleftarrow{h}_t]\), a vector twice the width of a single hidden state.

Numerical Trace (2-dim hidden states)

For the sentence "Elon Musk founded SpaceX today", the forward pass sweeps left→right computing \(\overrightarrow{h}_1 \dots \overrightarrow{h}_5\) using only past tokens. The backward pass sweeps right→left computing \(\overleftarrow{h}_5 \dots \overleftarrow{h}_1\) using only future tokens. At token 3 ("founded"), \(\overrightarrow{h}_3\) has absorbed "Elon Musk" and \(\overleftarrow{h}_3\) has absorbed "SpaceX today" — concatenating them gives "founded" a representation aware of both the subject and the object, which is exactly the context an NER tagger needs to label "founded" correctly. Design Decision: Why Two Separate RNNs Instead of One?

You could imagine feeding the network a reversed copy of the sequence and hoping one RNN "figures it out" — but a single set of weights can't specialize in reading both directions well. Two independent weight sets let each RNN specialize (forward captures "what led here", backward captures "what follows"), and concatenation is a cheap, differentiable way to fuse them without forcing one representation to do two jobs.

🔑 Key Property

A BiRNN requires the entire input sequence to be available before computing any output (the backward pass needs the last token first). This makes it perfect for tagging/encoding tasks (NER, POS tagging, encoder side of seq2seq) but unusable for autoregressive generation, where future tokens don't exist yet.

3
Why It Works — The Math
▼

The Two Recurrences

The forward recurrence, run for \(t = 1 \dots n\):

$$\overrightarrow{h}_t = \tanh\!\left(\overrightarrow{W}_x x_t + \overrightarrow{W}_h \overrightarrow{h}_{t-1} + \overrightarrow{b}\right), \qquad \overrightarrow{h}_0 = \mathbf{0}$$

The backward recurrence, run for \(t = n \dots 1\):

$$\overleftarrow{h}_t = \tanh\!\left(\overleftarrow{W}_x x_t + \overleftarrow{W}_h \overleftarrow{h}_{t+1} + \overleftarrow{b}\right), \qquad \overleftarrow{h}_{n+1} = \mathbf{0}$$

The per-token output used by downstream layers (e.g. a softmax tagger) is the concatenation:

$$h_t = \left[\overrightarrow{h}_t \, ; \, \overleftarrow{h}_t\right], \qquad \hat{y}_t = \operatorname{softmax}(W_o h_t + b_o)$$

Gradient Flow

Backpropagation Through Time (BPTT) is applied to each direction separately. Gradients w.r.t. \(\overrightarrow{W}_h\) flow backward through the forward chain (from \(t=n\) down to \(t=1\)), and gradients w.r.t. \(\overleftarrow{W}_h\) flow backward through the backward chain (from \(t=1\) up to \(t=n\), i.e. against its own forward-computation order). The two gradient chains never interact except through the shared loss at the concatenation point — each direction's weights only receive gradient through its own half of \(h_t\).

⚠️ Common Misconception

Bidirectionality does not mean information flows both directions within a single RNN cell — it means two entirely separate RNNs (separate weights, separate hidden state chains) are run and their outputs are merged afterward. It also does not fix vanishing gradients over long sequences (each direction is still a standard RNN chain, hence BiLSTM/BiGRU are far more common in practice than vanilla BiRNN).

Key Takeaways
▼
Unidirectional RNNBidirectional RNN
Context per tokenPast onlyPast + future
Needs full sequence upfrontNoYes
Good for generationYes (autoregressive)No
Good for tagging/encodingWeakerYes (NER, POS, encoders)
Hidden state width\(d\)\(2d\) (concatenated)

Use it when: the whole input is known before you need an answer — sequence labeling (NER, POS tagging), sentiment/classification encoders, the encoder half of seq2seq/machine translation, speech recognition over a full utterance.

Don't use it when: you're generating text token-by-token (language modeling, chat completion) — there's no "future" to read yet, so causal/unidirectional (or masked, as in GPT) models are required.

💡 Where This Leads

BiLSTM/BiGRU (swap the vanilla RNN cell for LSTM/GRU to fight vanishing gradients) dominated NLP tagging from ~2015-2018. Today, bidirectional self-attention (BERT's encoder) achieves the same "see everything at once" property without any sequential recurrence — but the core idea, fusing left and right context per token, is identical in spirit.

def rnn_cell(x, h_prev, Wx, Wh, b):
return np.tanh(Wx @ x + Wh @ h_prev + b)
# ── FORWARD PASS: left -> right ──
h_fwd = [np.zeros(d)]
for t in range(n):
h_fwd.append(rnn_cell(x[t], h_fwd[-1], Wxf, Whf, bf))
h_fwd = h_fwd[1:] # h_fwd[t] = forward state at token t
# ── BACKWARD PASS: right -> left ──
h_bwd = [np.zeros(d)]
for t in reversed(range(n)):
h_bwd.append(rnn_cell(x[t], h_bwd[-1], Wxb, Whb, bb))
h_bwd = list(reversed(h_bwd[1:])) # re-align to token order
# ── CONCATENATE per token: full past + future context ──
h = [np.concatenate([h_fwd[t], h_bwd[t]]) for t in range(n)]
