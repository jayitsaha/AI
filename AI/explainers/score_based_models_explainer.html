Understanding Score-based Models
▼

What is it? Score-based generative models, also known as diffusion models, learn to generate new data (like images) by reversing a process of gradual noise addition. Instead of directly learning the data distribution \(p(x)\), they learn its score function, \(\nabla_x \log p(x)\), which tells you the direction of steepest increase in log-probability. Once learned, this score function can guide a noisy input back towards the data distribution using an iterative process called Langevin dynamics.

Analogy: Imagine you're blindfolded in a hilly landscape, trying to find the highest peaks (data points). You can't see the peaks, but you can always feel the slope beneath your feet. The score function is like this "slope detector" — it tells you which way is uphill towards higher probability. Langevin dynamics is the process of taking small steps uphill, adding a bit of random jostling to avoid getting stuck in local optima, until you find a peak.

💡 If you remember one thing

Score-based models learn the gradient of the log-probability density function, \(\nabla_x \log p(x)\). This "score" vector field guides noisy samples towards regions of high data likelihood through a process called Langevin dynamics, effectively "denoising" pure noise into data.

2
How It Works Internally
▼

The Core Idea: Score Matching + Langevin Dynamics

The fundamental challenge is that directly estimating \(\nabla_x \log p(x)\) from discrete data samples is hard. Score-based models overcome this with two key components:

  1. Score Matching: A technique to train a neural network \(s_\theta(x)\) to approximate \(\nabla_x \log p(x)\) without needing explicit density values \(p(x)\). Instead, it minimizes a loss function related to the Fisher divergence between \(s_\theta(x)\) and \(\nabla_x \log p(x)\). A common variant is Denoising Score Matching, where the network is trained to predict the noise added to a data point.
  2. Langevin Dynamics: An iterative sampling algorithm that, given a score function \(s_\theta(x)\), can generate samples from \(p(x)\). It starts from a random noise sample and iteratively refines it by taking steps in the direction of the score function, plus some additional random noise.

The Problem: Low-Density Regions

When \(p(x)\) is very low (far from any data points), \(\nabla_x \log p(x)\) is ill-defined or hard to estimate reliably. A network trained via score matching might produce inaccurate score estimates in these regions. This poses a problem for Langevin dynamics, which often starts from pure noise, far from any data.

The Solution: Noise-Conditional Score Networks (NCSN)

To address the low-density problem, NCSN (Yang & Song, 2019) introduces a series of noise scales \(\sigma_1 < \sigma_2 < \dots < \sigma_L\). Instead of learning a single score function, it learns a noise-conditional score network \(s_\theta(x, \sigma)\) that approximates \(\nabla_x \log p_\sigma(x)\), where \(p_\sigma(x)\) is the data distribution corrupted by Gaussian noise with standard deviation \(\sigma\). By training on increasingly noisy versions of the data, the model learns to estimate scores even in regions far from the original data manifold.

During sampling, NCSN employs an annealed Langevin dynamics procedure. It starts with a pure noise sample and the largest noise scale \(\sigma_L\), performing several Langevin steps. Then, it gradually reduces the noise scale to \(\sigma_{L-1}\), then \(\sigma_{L-2}\), and so on, performing Langevin steps at each noise level. This annealing process effectively "walks" the sample from pure noise down to the clean data distribution, guided by the appropriate score function at each noise level.

🔑 Key Property

The magic of score-based models lies in a two-stage process: training a neural network \(s_\theta(x)\) to approximate the score function \(\nabla_x \log p(x)\) via score matching, and then sampling from \(p(x)\) using the learned \(s_\theta(x)\) via Langevin dynamics. NCSN extends this by learning a score for multiple noise levels to improve sample quality.

3
Why It Works — The Math
▼

1. The Score Function

The score function of a probability density \(p(x)\) is defined as the gradient of its logarithm:

$$\mathbf{s}(x) = \nabla_x \log p(x) = \frac{\nabla_x p(x)}{p(x)}$$

This vector field points in the direction of steepest increase in log-probability density.

2. Score Matching Loss

To train a model \(s_\theta(x)\) to approximate \(\mathbf{s}(x)\), we minimize the Fisher divergence between \(s_\theta(x)\) and \(\mathbf{s}(x)\). This is equivalent to minimizing the score matching objective:

$$L(\theta) = \mathbb{E}_{p_{data}(x)} \left[ \frac{1}{2} \| s_\theta(x) - \nabla_x \log p(x) \|^2 \right]$$

Directly computing \(\nabla_x \log p(x)\) is intractable. However, minimizing \(L(\theta)\) can be done using an alternative objective derived via integration by parts, which avoids computing \(\nabla_x \log p(x)\):

$$L(\theta) = \mathbb{E}_{p_{data}(x)} \left[ \text{Tr}(\nabla_x s_\theta(x)) + \frac{1}{2} \|s_\theta(x)\|^2 \right]$$

This still requires computing the Jacobian trace, which can be computationally expensive. A more practical alternative is Denoising Score Matching, which involves adding Gaussian noise to data points:

$$L_{DSM}(\theta) = \mathbb{E}_{p_{data}(x)} \mathbb{E}_{\tilde{x} \sim \mathcal{N}(x, \sigma^2 I)} \left[ \frac{1}{2} \| s_\theta(\tilde{x}) - \nabla_{\tilde{x}} \log p(\tilde{x} | x) \|^2 \right]$$

Here, \(\nabla_{\tilde{x}} \log p(\tilde{x} | x) = -(\tilde{x}-x)/\sigma^2\), which is simple to compute. The network \(s_\theta(\tilde{x})\) is trained to predict the scaled noise that transforms \(\tilde{x}\) back to \(x\).

3. Langevin Dynamics for Sampling

Given the true score function \(\mathbf{s}(x)\), we can sample from \(p(x)\) using the following iterative update rule:

$$x_{t+1} = x_t + \epsilon \mathbf{s}(x_t) + \sqrt{2\epsilon} \mathbf{z}_t, \quad \mathbf{z}_t \sim \mathcal{N}(0, I)$$

where \(\epsilon\) is a small step size and \(\mathbf{z}_t\) is Gaussian noise. As \(t \to \infty\) and \(\epsilon \to 0\), \(x_t\) converges to a sample from \(p(x)\). In practice, we use the learned score network \(s_\theta(x)\).

⚠️ Common Pitfall

The score function \(\nabla_x \log p(x)\) is only well-defined where \(p(x) > 0\). In regions where data is sparse or non-existent, the score function can be noisy or misleading. This is precisely why Noise-Conditional Score Networks (NCSN) train on noisy versions of the data, effectively "smoothing out" these low-density regions and providing well-behaved score estimates everywhere.

Key Takeaways
▼

When to use Score-based Models:

  • High-quality Generative Tasks: Excellent for generating realistic images, audio, and other complex data types. State-of-the-art in many benchmarks.
  • Flexible Sampling: Langevin dynamics allows for flexible sampling, including conditional generation (e.g., inpainting, super-resolution) by modifying the score function.
  • Density Estimation (Implicit): While not explicitly estimating \(p(x)\), they provide a powerful way to sample from it, which is often sufficient for many applications.

When to be cautious:

  • Computational Cost: Sampling typically requires many (hundreds to thousands) iterative steps, making inference slower than one-shot generative models like GANs or VAEs.
  • Training Stability: Training the score network can be sensitive to hyperparameter choices, especially the noise schedules and step sizes.
  • Mode Coverage: While generally good at covering modes, very sharp or isolated modes can still be challenging without careful noise scheduling.
💡 Big Picture: Connection to Diffusion Models

Score-based models, especially NCSN and its successor Score-based Generative Models (SGM), are essentially equivalent to Denoising Diffusion Probabilistic Models (DDPMs). Both approaches learn to reverse a diffusion process by estimating gradients of log-likelihoods, differing mainly in their mathematical formulation (continuous-time SDEs vs. discrete-time Markov chains) but sharing the same core principle of iterative denoising guided by learned scores.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
import numpy as np
# Assume s_theta is a neural network that outputs a vector of the same shape as x
# s_theta(x, sigma) takes input x and a noise level sigma
def train_ncsn(data_loader, s_theta, optimizer, noise_scales, num_epochs):
s_theta.train()
for epoch in range(num_epochs):
for x_data in data_loader:
sigma = np.random.choice(noise_scales) # Sample a noise level
z = torch.randn_like(x_data) # Sample Gaussian noise
x_noisy = x_data + sigma * z # Corrupt data
# Denoising Score Matching Loss: s_theta should predict -z/sigma
# which is proportional to - (x_noisy - x_data) / sigma^2
# or more precisely, - (x_noisy - x_data) / sigma^2 = - (sigma * z) / sigma^2 = -z/sigma
target_score = -z / sigma
predicted_score = s_theta(x_noisy, sigma)
loss = torch.mean(torch.square(predicted_score - target_score))
optimizer.zero_grad()
loss.backward()
optimizer.step()
def annealed_langevin_sampling(s_theta, shape, noise_scales, num_steps_per_scale, epsilon_factor):
s_theta.eval()
x = torch.randn(shape) * noise_scales[0] # Start from pure noise (largest sigma)
for sigma in noise_scales: # Iterate from largest to smallest sigma
epsilon = epsilon_factor * sigma**2 # Step size dependent on noise level
for _ in range(num_steps_per_scale):
with torch.no_grad():
score = s_theta(x, sigma)
x = x + epsilon * score + torch.sqrt(2 * epsilon) * torch.randn_like(x)
return x
