Understanding Graph Features
▼

What is it? In Graph Neural Networks (GNNs), data isn't just a grid (images) or a sequence (text) but a collection of interconnected entities. To make sense of this structure, we need to describe the properties of individual entities (nodes), their relationships (edges), and the overall network (graph). These descriptions are called features, and they come in three main flavors: node-level, edge-level, and graph-level.

Analogy: Imagine a social network. Each person is a node. Their attributes like age, income, or profession are node features. The friendships between them are edges. The strength or duration of a friendship could be an edge feature. Finally, properties of the entire network, like the average age of all members, the total number of friendships, or the network's density, are graph-level features. GNNs learn to process these features to make predictions.

💡 If you remember one thing

Features are numerical representations of properties. Node features describe individual entities (e.g., a person's age). Edge features describe relationships (e.g., friendship strength). Graph-level features describe the entire network (e.g., network diameter). GNNs combine these to learn complex patterns.

2
How Features Are Represented Internally
▼

Vector Representations

In machine learning, features are typically represented as numerical vectors. For a graph with \(N\) nodes and \(M\) edges, we might have:

  • Node features: A matrix \(X \in \mathbb{R}^{N \times d_v}\), where each row \(x_v \in \mathbb{R}^{d_v}\) is a feature vector for node \(v\). \(d_v\) is the dimensionality of node features.
  • Edge features: A matrix \(E \in \mathbb{R}^{M \times d_e}\), where each row \(e_{uv} \in \mathbb{R}^{d_e}\) is a feature vector for the edge between nodes \(u\) and \(v\). \(d_e\) is the dimensionality of edge features. If edges are undirected, \(e_{uv} = e_{vu}\).
  • Graph-level features: A single vector \(h_G \in \mathbb{R}^{d_G}\) describing properties of the entire graph. \(d_G\) is the dimensionality of graph features.

These vectors can contain anything from simple counts (e.g., node degree) to complex embeddings (e.g., word embeddings for text labels on nodes).

Design Decision: Why Use Features at Different Levels?

The hierarchical nature of graph features allows GNNs to capture information at multiple scales. Node features are local, edge features describe pairwise interactions, and graph-level features provide a global context. A GNN typically learns to iteratively aggregate information from neighbors (using node and edge features) to enrich each node's representation, eventually pooling these enriched node representations to form a graph-level representation for tasks like graph classification.

For example, in a molecular graph:

  • Node features: Atomic number, charge, hybridization state for each atom.
  • Edge features: Bond type (single, double, triple), bond length for each chemical bond.
  • Graph-level features: Total number of atoms, molecular weight, presence of specific functional groups.
🔑 Key Property

The choice of features is crucial and domain-specific. Good features encode relevant domain knowledge, helping the GNN learn more efficiently. Poor or irrelevant features can confuse the model, leading to suboptimal performance.

How GNNs Process Features
▼

Message Passing Paradigm

Most GNNs operate on a "message passing" paradigm, where node features are iteratively updated by aggregating information from their neighbors. This process inherently combines node and edge features:

$$h_v^{(k)} = \operatorname{UPDATE}^{(k)}\left(h_v^{(k-1)}, \operatorname{AGGREGATE}^{(k)}\left(\{ (h_u^{(k-1)}, e_{uv}) \mid u \in \mathcal{N}(v) \}\right)\right)$$

Here, \(h_v^{(k)}\) is the feature vector for node \(v\) at layer \(k\), and \(\mathcal{N}(v)\) are its neighbors. The \(\operatorname{AGGREGATE}\) function combines features from neighbors \(u\) and their connecting edge features \(e_{uv}\). A common aggregation is a weighted sum:

For example, a simple readout could be the sum of all final node embeddings: \(h_G = \sum_{v \in \mathcal{V}} h_v^{(K)}\). This vector \(h_G\) is then used for graph-level prediction tasks.

⚠️ Common Pitfall

Many early GNNs ignored edge features, implicitly treating all edges as identical. This is a severe limitation for domains like chemistry or knowledge graphs where edge types/weights are critical. Always consider if your problem domain has meaningful edge attributes that should be incorporated into the message passing process.

Key Takeaways
▼

When to use which feature type:

  • Node features: Almost always necessary. They describe the intrinsic properties of individual entities. Without them, nodes are indistinguishable except by their position in the graph.
  • Edge features: Essential when relationships are not uniform. If bond types in molecules, trust levels in social networks, or traffic flow capacities in road networks are important, edge features are indispensable. Ignoring them can severely limit model expressivity.
  • Graph-level features: Useful as initial graph-level representations (e.g., global context for node-level tasks) or as targets for graph classification/regression tasks. They provide a summary of the entire graph's characteristics.

Impact on GNN performance:

  • Richness: More informative features (e.g., using chemical properties for atoms instead of just arbitrary IDs) generally lead to better learning.
  • Domain knowledge: Incorporating domain-specific features is often more effective than relying purely on learned embeddings from raw data.
  • Scalability: High-dimensional features can increase memory and computational costs, especially for large graphs. Feature engineering often involves balancing informativeness with computational efficiency.
💡 Feature Engineering in Graphs

Just as in traditional ML, feature engineering is critical for GNNs. For graph data, this means not only selecting good attributes for nodes and edges but also considering how to extract meaningful graph-level properties or even structural features (like centrality measures, clustering coefficients) that can be added as node-level features.

Code Trace (PyTorch Geometric Style)
▼
import torch
from torch_geometric.data import Data
# 1. Node Features (x)
# Each row is a node's feature vector. Here, 4 nodes, 2 features each.
# e.g., Node A: [1.0, 0.5], Node B: [2.0, 0.8], etc.
node_features = torch.tensor([
[1.0, 0.5], # Node A features
[2.0, 0.8], # Node B features
[1.5, 0.3], # Node C features
[2.5, 0.9] # Node D features
], dtype=torch.float)
# 2. Edge Index (adjacency list)
# A list of (source, target) pairs for directed edges.
# (0->1, 1->2, 2->3, 3->0)
edge_index = torch.tensor([
[0, 1, 2, 3], # Source nodes
[1, 2, 3, 0] # Target nodes
], dtype=torch.long)
# 3. Edge Features (edge_attr)
# Each row corresponds to an edge in edge_index. Here, 4 edges, 1 feature each.
# e.g., Edge 0->1: [0.7], Edge 1->2: [0.3], etc.
edge_features = torch.tensor([
[0.7], # Edge 0->1 weight
[0.3], # Edge 1->2 weight
[0.9], # Edge 2->3 weight
[0.5] # Edge 3->0 weight
], dtype=torch.float)
# 4. Graph-level Features (y or global_x)
# A single feature vector for the entire graph (e.g., a target label).
graph_label = torch.tensor([0], dtype=torch.long) # e.g., graph belongs to class 0
# Create a PyG Data object
data = Data(x=node_features, edge_index=edge_index, edge_attr=edge_features, y=graph_label)
print(data)
