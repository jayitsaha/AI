Understanding Parameter Learning
▼

What is it? A Bayesian network's joint distribution factors into small local tables — one Conditional Probability Table (CPT) per node, indexed by its parents' values. "Parameter learning" means filling in the numbers of those tables from observed data. MLE fills each cell with a simple relative frequency: count how often something happened, divide by how often it could have happened. MAP does the same counting, but adds a handful of "imaginary" pseudo-observations first (a Dirichlet prior), so a table cell never collapses to an extreme, unsupported value.

Analogy: You ask 3 friends whether they carried an umbrella every time it rained. All 3 say yes. MLE concludes "100% of people always carry an umbrella in the rain" — reckless, given 3 data points. MAP starts from a mild assumption ("people are roughly 50/50 on this") and blends it with the 3 opinions, landing near 80% instead of a brittle 100%. Ask 1000 more friends and both methods converge — enough data eventually overwhelms the starting assumption.

💡 If you remember one thing

\(\hat\theta_{\text{MLE}} = N(x,\mathrm{pa})/N(\mathrm{pa})\) is just counting. \(\hat\theta_{\text{MAP}} = (N(x,\mathrm{pa})+\alpha-1)/(N(\mathrm{pa})+\alpha_0-K)\) is counting with fake extra observations mixed in — exactly what "Laplace smoothing" is doing under the hood.

How It Works Internally
▼

Why Counting Is Enough

A Bayesian network factorizes as \(P(X_1,\dots,X_n) = \prod_i P(X_i \mid \mathrm{Pa}(X_i);\theta_i)\). Because every CPT parameter appears inside exactly ONE multiplicative factor, the log-likelihood of a full dataset is a SUM of independent terms — one per (node, parent-configuration) pair. Maximizing a sum of independent terms, each under its own simplex constraint (a CPT row must sum to 1), decomposes into thousands of tiny, closed-form problems. No gradient descent needed for fully-observed data.

The Two Estimators

MLE: scan the data once, accumulate counts \(N(x,\mathrm{pa})\), normalize each row. MAP: same scan, but add Dirichlet pseudo-counts \(\alpha_k - 1\) to each cell before normalizing — the posterior is again Dirichlet because the Dirichlet is conjugate to the categorical likelihood.

Design Decision: Why Dirichlet, not Gaussian?

The Dirichlet is CONJUGATE to the multinomial/categorical likelihood — the posterior stays Dirichlet, giving closed-form MAP and posterior-mean formulas. A non-conjugate prior would force numerical integration or MCMC for what is otherwise a trivial estimation problem.

🔑 Key Property

Parameter independence — the assumption that CPT rows are a priori independent of each other — is exactly what licenses splitting one giant estimation problem into many tiny counting problems.

Why It Works — The Math
▼

MLE via Lagrange Multipliers

Fix one CPT row. Maximize \(\sum_k N_k \log\theta_k\) subject to \(\sum_k \theta_k = 1\):

$$\mathcal{L}(\theta,\lambda) = \sum_k N_k \log\theta_k + \lambda\Big(1-\sum_k\theta_k\Big) \;\Rightarrow\; \theta_k = \frac{N_k}{\lambda} \;\Rightarrow\; \hat\theta_k^{\text{MLE}} = \frac{N_k}{N}$$

MAP via Dirichlet Conjugacy

With prior \(\theta \sim \mathrm{Dir}(\alpha_1,\dots,\alpha_K)\), \(p(\theta)\propto\prod_k\theta_k^{\alpha_k-1}\), Bayes' rule gives:

$$p(\theta\mid D) \propto \prod_k \theta_k^{N_k}\cdot\prod_k\theta_k^{\alpha_k-1} = \prod_k \theta_k^{N_k+\alpha_k-1} \;\Rightarrow\; \theta\mid D \sim \mathrm{Dir}(N_1{+}\alpha_1,\dots,N_K{+}\alpha_K)$$

The same Lagrangian trick, with \(N_k\) replaced by \(N_k+\alpha_k-1\), gives the MAP mode:

$$\hat\theta_k^{\text{MAP}} = \frac{N_k+\alpha_k-1}{N+\alpha_0-K}, \qquad \bar\theta_k = \frac{N_k+\alpha_k}{N+\alpha_0}\ \text{(posterior mean)}$$

For a binary CPT cell with Beta\((\alpha,\beta)\) prior: \(\hat\theta^{\text{MAP}} = (N_1+\alpha-1)/(N_1+N_0+\alpha+\beta-2)\).

⚠️ Common Pitfall

\(\mathrm{Beta}(\alpha{=}2,\beta{=}2)\) gives +1 pseudo-count per category (since the formula uses \(\alpha-1\)), NOT +2 — this off-by-one is the most common bug when hand-coding Laplace smoothing.

Key Takeaways
▼

When to use MLE: large datasets where every parent configuration is well represented — the prior's influence vanishes anyway, so plain counting is simplest.

When to use MAP: small or sparse datasets, high-cardinality parent sets, or whenever a zero probability would be catastrophic downstream (it regularizes exactly like Laplace smoothing).

  • MLE = raw counts. MAP = counts + pseudo-counts (prior). Posterior mean = Bayes-optimal average over the whole posterior, not just its peak.
  • As data grows, MLE and MAP provably converge — the prior's influence shrinks like \(O(1/N)\).
  • Zero counts make MLE undefined or degenerate; MAP with any \(\alpha_k>1\) never hits exactly 0 or 1.
💡 Big Picture

Because a Bayesian network's likelihood factorizes along the DAG, parameter learning with fully-observed data is always closed-form counting — the hard optimization machinery (gradient descent, EM) only shows up once data is missing or CPDs are compactly parametrized instead of tabular.
