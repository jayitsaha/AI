Viterbi Algorithm (Decoding)

Finding the most likely sequence of hidden states in a Hidden Markov Model
Foundational Classical ML Sequence Models O(T · N²)
1
Understanding the Viterbi Algorithm
▼

What is it? The Viterbi algorithm is a dynamic programming algorithm for finding the most likely sequence of hidden states (called the Viterbi path) that results in a sequence of observed events, especially within the framework of a Hidden Markov Model (HMM). Think of it as finding the "best explanation" for what you've seen, when the underlying causes are hidden.

Analogy: Imagine you're a detective trying to figure out the weather (hidden states: 'Hot', 'Cold') over several days, but you can only observe indirect evidence (observations: 'Dry', 'Damp', 'Soggy'). You know how likely each weather state is to start, how likely it is to transition from one state to another, and how likely each weather state is to produce each type of observation. Viterbi helps you piece together the most probable sequence of weather states that explains the observations you actually collected.

💡 If you remember one thing

Viterbi is a dynamic programming algorithm. It builds up the solution by remembering the best (most probable) path to each state at each time step, rather than re-calculating from scratch. This avoids exponential complexity and guarantees finding the globally optimal path.

2
How Viterbi Works Internally
▼

The Hidden Markov Model (HMM) Components

To use Viterbi, you need a pre-defined HMM, which consists of:

  • Hidden States (S): The unobservable states (e.g., 'Hot', 'Cold').
  • Observations (O): The observable events (e.g., 'Dry', 'Damp', 'Soggy').
  • Initial Probabilities (\(\pi\)): The probability of starting in each hidden state.
  • Transition Probabilities (A): The probability of moving from one hidden state to another.
  • Emission Probabilities (B): The probability of observing a particular event from a particular hidden state.

Given an observed sequence \(O = (o_1, o_2, \dots, o_T)\), Viterbi finds the hidden state sequence \(S = (s_1, s_2, \dots, s_T)\) that maximizes \(P(S, O)\).

The Four Steps of Viterbi

The algorithm proceeds in four main phases:

  1. Initialization: For the first time step (\(t=1\)), calculate the probability of being in each hidden state, given the first observation. This is simply the initial probability of the state multiplied by the emission probability of the first observation from that state.
  2. Recursion (Forward Pass): For each subsequent time step (\(t=2, \dots, T\)) and for each hidden state \(j\), calculate the maximum probability of reaching state \(j\) at time \(t\). This involves considering all possible previous states \(i\) at time \(t-1\), multiplying their maximum path probability by the transition probability from \(i\) to \(j\), and then by the emission probability of the current observation from state \(j\). Crucially, it stores not just this max probability, but also which previous state \(i\) led to it (the "backpointer").
  3. Termination: After computing probabilities for all states at all time steps, find the state at the final time step (\(t=T\)) that has the highest maximum path probability. This is the end of the most likely hidden state sequence.
  4. Path Backtracking: Starting from the final state identified in the termination step, follow the stored backpointers backwards through time, from \(t=T\) down to \(t=1\). This reconstructs the entire most likely sequence of hidden states.
🔑 Key Property

The Viterbi algorithm's efficiency comes from the "optimal substructure" property of dynamic programming. To find the best path to state \(j\) at time \(t\), you only need to know the best paths to all states at time \(t-1\), not the full history. This prevents re-evaluating exponentially many paths.

3
Why It Works — The Math
▼

Defining the Viterbi Variables

Let \(N\) be the number of hidden states, and \(T\) be the length of the observation sequence. We define two key variables:

  • \(\delta_t(j)\): The maximum probability of any single path ending in state \(j\) at time \(t\), having generated the first \(t\) observations \((o_1, \dots, o_t)\).
  • \(\psi_t(j)\): The state that maximizes \(\delta_{t-1}(i) \cdot a_{ij}\), i.e., the predecessor state of \(j\) on the most probable path to \(j\) at time \(t\). This is our "backpointer."

1. Initialization (\(t=1\))

For each state \(j \in \{1, \dots, N\}\):

$$\delta_1(j) = \pi_j \cdot b_j(o_1)$$ $$\psi_1(j) = 0 \quad \text{(no predecessor)}$$

Here, \(\pi_j\) is the initial probability of state \(j\), and \(b_j(o_1)\) is the emission probability of observing \(o_1\) from state \(j\).

2. Recursion (\(t=2, \dots, T\))

For each time step \(t\) and each state \(j \in \{1, \dots, N\}\):

$$\delta_t(j) = \max_{i \in \{1, \dots, N\}} (\delta_{t-1}(i) \cdot a_{ij}) \cdot b_j(o_t)$$ $$\psi_t(j) = \arg\max_{i \in \{1, \dots, N\}} (\delta_{t-1}(i) \cdot a_{ij})$$

Where \(a_{ij}\) is the transition probability from state \(i\) to state \(j\), and \(b_j(o_t)\) is the emission probability of observing \(o_t\) from state \(j\).

3. Termination (\(t=T\))

The maximum probability of the entire observation sequence and its corresponding final state are:

$$P^* = \max_{j \in \{1, \dots, N\}} \delta_T(j)$$ $$s_T^* = \arg\max_{j \in \{1, \dots, N\}} \delta_T(j)$$

4. Path Backtracking (\(t=T-1, \dots, 1\))

The most likely hidden state sequence \(S^* = (s_1^*, s_2^*, \dots, s_T^*)\) is found by tracing back:

$$s_t^* = \psi_{t+1}(s_{t+1}^*)$$

The time complexity is \(O(T \cdot N^2)\) because for each of \(T\) time steps, we iterate through \(N\) states, and for each state, we compare \(N\) previous states.

⚠️ Numerical Stability with Log-Probabilities

When \(T\) is large, the probabilities \(\delta_t(j)\) can become extremely small, leading to floating-point underflow. To prevent this, Viterbi is often implemented using log-probabilities, converting multiplications to additions: \(\log(P_1 \cdot P_2) = \log P_1 + \log P_2\). The \(\max\) operation remains the same.

Key Takeaways
▼

When to use Viterbi:

  • Speech Recognition: Deciphering the most likely sequence of words (hidden states) given an acoustic signal (observations).
  • Part-of-Speech Tagging: Determining the most probable sequence of grammatical tags (hidden states) for a sentence (observations).
  • Bioinformatics: Finding the most likely gene sequence or protein structure (hidden states) given experimental data (observations).
  • Error Correction: Decoding the most probable original message (hidden states) from a noisy received signal (observations) in communication systems.
  • Any problem where you have a sequence of observations and want to infer the most probable underlying sequence of unobserved states.

Limitations of Viterbi:

  • Requires a pre-trained HMM (all initial, transition, and emission probabilities must be known). Learning these parameters from data requires other algorithms (e.g., Expectation-Maximization / Baum-Welch).
  • Assumes the Markov property (next state depends only on current state) and observation independence (current observation depends only on current state). Real-world systems often violate these assumptions.
  • Only finds the single most likely path, not the probability of the observation sequence itself (which is solved by the Forward algorithm) or the posterior probability of individual states (solved by the Forward-Backward algorithm).
💡 Viterbi vs. Forward Algorithm

While both use dynamic programming, Viterbi calculates the maximum probability over paths to find the single most likely hidden state sequence. The Forward algorithm calculates the sum of probabilities over all possible paths to find the total probability of an observation sequence, without recovering a specific path.

Code Trace (Python)
▼
import numpy as np
def viterbi(obs, states, start_p, trans_p, emit_p):
# obs: sequence of observations (e.g., ['Dry', 'Damp', 'Dry'])
# states: list of hidden states (e.g., ['Hot', 'Cold'])
# start_p: initial probabilities (dict)
# trans_p: transition probabilities (dict of dicts)
# emit_p: emission probabilities (dict of dicts)
V = [{}] # Viterbi probability table
path = {} # Backpointer table
# 1. Initialization (t=0)
for y in states:
V[0][y] = start_p[y] * emit_p[y][obs[0]]
path[y] = [y]
# 2. Recursion (t=1 to T-1)
for t in range(1, len(obs)):
V.append({})
new_path = {}
for y in states: # Current state y
(prob, state) = max((V[t-1][y0] * trans_p[y0][y] * emit_p[y][obs[t]], y0)
for y0 in states) # Previous state y0
V[t][y] = prob
new_path[y] = path[state] + [y] # Store backpointer path
path = new_path
# 3. Termination (t=T-1, last observation)
(prob, state) = max((V[len(obs) - 1][y], y) for y in states)
# 4. Path Backtracking is implicitly done by `path` table
return (prob, path[state])
# Example Usage (same as interactive demo)
states = ['Hot', 'Cold']
observations = ['Dry', 'Damp', 'Dry']
start_probability = {'Hot': 0.8, 'Cold': 0.2}
transition_probability = {
'Hot': {'Hot': 0.7, 'Cold': 0.3},
'Cold': {'Hot': 0.4, 'Cold': 0.6}
}
emission_probability = {
'Hot': {'Dry': 0.6, 'Damp': 0.3, 'Soggy': 0.1},
'Cold': {'Dry': 0.1, 'Damp': 0.4, 'Soggy': 0.5}
}
result_prob, result_path = viterbi(observations, states,
start_probability, transition_probability,
emission_probability)
print(f"Most likely path: {result_path}") # ['Hot', 'Hot', 'Hot']
print(f"Path probability: {result_prob:.4f}") # 0.02016
