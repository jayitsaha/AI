Patch Embedding & Masked Tokens (MAE)

Converting images to sequences for Transformers, and self-supervised pre-training by reconstruction
Foundational Intermediate Computer Vision Deep Learning
1
Understanding Patch Embedding and MAE
▼

What is it? Vision Transformers (ViTs) adapt the Transformer architecture, originally designed for text, to image data. Since Transformers process sequences of tokens, images must first be converted into such a sequence. This is done via patch embedding: an image is divided into fixed-size, non-overlapping patches, each flattened into a vector and then linearly projected into a high-dimensional embedding space, much like words are embedded in NLP. Crucially, learnable positional embeddings are added to these patch embeddings to retain spatial information.

Masked Autoencoders (MAE) build on this by introducing a powerful self-supervised pre-training objective. During training, a large portion of the image patches (e.g., 75%) are randomly masked out. The ViT encoder then processes only the *visible* patches. A lightweight decoder is then tasked with reconstructing the original pixel values of the *masked* patches. This forces the model to learn rich, semantic representations of images by understanding context and filling in missing information.

Analogy: Imagine an image as a long sentence. Patch embedding is like a "visual tokenizer" that breaks the image into "visual words" (patches) and then translates each visual word into a numerical vector that a Transformer can understand. Masked tokens (MAE) is like playing a game of "visual fill-in-the-blanks": you hide most of the image, show only a few scattered pieces, and ask the model to guess what the hidden parts looked like. To do this well, the model must learn deep visual understanding.

💡 If you remember one thing

Patch embedding is the core mechanism that allows Transformers to process images by converting them into sequences of fixed-size vectors. MAE is a highly effective self-supervised pre-training strategy that leverages this patch-based representation by reconstructing masked image regions, leading to powerful and efficient vision models.

2
How It Works Internally
▼

The Patch Embedding Pipeline

  1. Image to Patches: An input image of size \((H, W, C)\) (Height, Width, Channels) is divided into a grid of non-overlapping square patches of size \((P, P, C)\). For example, a \(224 \times 224\) image with \(16 \times 16\) patches yields \((224/16) \times (224/16) = 14 \times 14 = 196\) patches.
  2. Flattening: Each individual patch \((P, P, C)\) is flattened into a 1D vector of size \(P \cdot P \cdot C\). For a \(16 \times 16\) patch with 3 channels, this is a vector of \(16 \cdot 16 \cdot 3 = 768\) elements.
  3. Linear Projection: Each flattened patch vector is then projected into a target embedding dimension \(D\) (e.g., 768 or 1024) using a learnable linear transformation. This is typically implemented as a convolutional layer with kernel size and stride equal to the patch size, effectively performing the flattening and projection in one step. The output is a sequence of \(N\) patch embeddings, where \(N = (H/P) \cdot (W/P)\).
  4. Positional Encoding: To retain the spatial information lost during flattening, learnable positional embeddings (one for each patch position) are added to the patch embeddings. These embeddings allow the Transformer to understand where each patch originated in the original image.
  5. Class Token (Optional): For classification tasks, a special learnable `[CLS]` token embedding is often prepended to the sequence of patch embeddings. The Transformer's output corresponding to this `[CLS]` token is then used for downstream classification.

The final output is a sequence of \(N+1\) (if using `[CLS]` token) \(D\)-dimensional vectors, ready to be fed into a standard Transformer encoder.

Masked Autoencoder (MAE) Pre-training

MAE introduces sparsity and a reconstruction task:

  • Masking Strategy: A very high proportion of patches (e.g., 75%) are randomly sampled and "masked out." Unlike NLP's `[MASK]` token, MAE often *removes* these patches entirely from the encoder input, making the input sequence much shorter.
  • Encoder Input: The Transformer encoder only processes the remaining *visible* (unmasked) patches. This makes the encoder very efficient.
  • Decoder Input: The decoder receives the encoder's output for the visible patches, along with *learnable mask tokens* for the positions of the masked patches. Crucially, positional embeddings are added to *all* tokens (visible and masked) to inform the decoder of their original locations.
  • Reconstruction Target: The decoder's task is to reconstruct the *original pixel values* of the masked patches. The loss (typically Mean Squared Error) is computed only over these reconstructed masked patches. This forces the model to learn a rich understanding of image structure and context.
🔑 Key Property

The patch embedding process converts a 2D image into a 1D sequence, enabling Transformer architectures to be applied to vision. MAE's high masking ratio and reconstruction-only-on-masked-patches objective creates a powerful self-supervision signal, making the encoder learn robust representations while being computationally efficient.

3
Why It Works — The Math
▼

Patch Embedding Formalism

Given an input image \(X \in \mathbb{R}^{H \times W \times C}\) and a patch size \(P\), we first divide \(X\) into \(N = (H/P) \times (W/P)\) non-overlapping patches. Each patch \(x_{i,j}\) (at grid position \((i,j)\)) has dimensions \(\mathbb{R}^{P \times P \times C}\). This patch is then flattened into a 1D vector \(x'_{i,j} \in \mathbb{R}^{P^2 C}\).

The linear projection maps this flattened vector to an embedding of dimension \(D\):

$$e_{i,j} = x'_{i,j} W_{proj} + b_{proj}$$

where \(W_{proj} \in \mathbb{R}^{P^2 C \times D}\) is the learnable projection matrix and \(b_{proj} \in \mathbb{R}^D\) is the bias. To retain spatial information, a learnable positional embedding \(p_{i,j} \in \mathbb{R}^D\) is added:

$$z_{i,j} = e_{i,j} + p_{i,j}$$

These \(z_{i,j}\) vectors, along with an optional `[CLS]` token, form the input sequence to the Transformer encoder.

Masked Autoencoder (MAE) Objective

For MAE, we randomly select a subset of patches \(\mathcal{M}\) (masked patches) and \(\mathcal{V}\) (visible patches), where \(\mathcal{M} \cup \mathcal{V}\) covers all patches. The encoder only receives the visible patches:

$$Z_{\mathcal{V}} = \text{Encoder}(\{z_{i,j} \mid (i,j) \in \mathcal{V}\})$$

The decoder then takes \(Z_{\mathcal{V}}\), plus learnable mask tokens for positions in \(\mathcal{M}\), each combined with its respective positional embedding \(p_{i,j}\). The objective is to reconstruct the original pixel values \(x_{i,j}\) for the masked patches, typically using Mean Squared Error (MSE) loss:

$$L_{\text{MAE}} = \sum_{(i,j) \in \mathcal{M}} \| \text{DecoderOutput}_{(i,j)} - x_{i,j}^{\text{original pixels}} \|_2^2$$

This objective forces the encoder to learn robust, non-local representations, as it cannot rely on local pixel correlations to reconstruct large masked regions. The high masking ratio encourages learning global context and strong semantic features.

➗ Connection to NLP

This process is directly analogous to NLP's `Word2Vec` or `BERT` masking. Just as BERT predicts masked words using surrounding context, MAE predicts masked image patches using surrounding visual context. The key difference is that MAE reconstructs raw pixel values, not a discrete token ID, and uses a much higher masking ratio due to the inherent redundancy in image data.

Key Takeaways
▼

When to use Patch Embedding & MAE:

  • Vision Transformers (ViTs): Essential for any Transformer-based architecture applied to images.
  • Self-supervised Pre-training: MAE is a highly effective method for pre-training large vision models on vast amounts of unlabeled image data, often outperforming supervised pre-training on ImageNet.
  • Computational Efficiency: MAE's high masking ratio means the encoder processes a significantly smaller sequence, leading to faster pre-training, especially for large models.
  • Scalability: Enables the scaling laws observed in NLP Transformers to be applied to computer vision.

Considerations & Limitations:

  • Patch Size Choice: Smaller patches lead to longer sequences (higher computational cost) but potentially finer-grained representations. Larger patches reduce sequence length but might lose fine details.
  • Positional Encodings: Crucial for maintaining spatial awareness. Learnable positional embeddings are common.
  • Reconstruction Target: Reconstructing raw pixels is simple but might not be the most semantically rich target. Other MAE variants explore reconstructing features or discrete visual tokens.
  • Fine-tuning: After MAE pre-training, the decoder is typically discarded, and the encoder is fine-tuned on downstream tasks with a classification head.
🔑 Broader Impact

Patch embedding and MAE represent a paradigm shift in computer vision, moving away from CNN-centric architectures towards Transformer-based models. This approach not only achieves state-of-the-art results but also highlights the power of self-supervised learning, enabling models to learn from raw data without costly human annotations.

Code Trace (PyTorch-like Snippet)
▼
import torch
import torch.nn as nn
import numpy as np
# --- Configuration ---
IMAGE_SIZE = 32
PATCH_SIZE = 8
IN_CHANNELS = 3
EMBED_DIM = 768 # D
MASK_RATIO = 0.75
num_patches = (IMAGE_SIZE // PATCH_SIZE) ** 2
patch_dim = IN_CHANNELS * PATCH_SIZE * PATCH_SIZE
# --- 1. Patch Embedding Layer ---
# This Conv2d acts as both patch extraction and linear projection
patch_embed_layer = nn.Conv2d(
IN_CHANNELS, EMBED_DIM,
kernel_size=PATCH_SIZE, stride=PATCH_SIZE
)
# --- 2. Positional Embeddings ---
# Learnable embeddings for each patch position + optional CLS token
pos_embed = nn.Parameter(torch.randn(1, num_patches + 1, EMBED_DIM)) # +1 for CLS
cls_token = nn.Parameter(torch.randn(1, 1, EMBED_DIM))
# --- Forward Pass (simplified) ---
# Input: (B, C, H, W) e.g., (1, 3, 32, 32)
x = torch.randn(1, IN_CHANNELS, IMAGE_SIZE, IMAGE_SIZE)
# Step A: Apply patch embedding (Conv2d)
# Output: (B, EMBED_DIM, num_patches_h, num_patches_w)
x = patch_embed_layer(x)
# Step B: Flatten spatial dimensions to get sequence of patches
# Output: (B, EMBED_DIM, num_patches) -> (B, num_patches, EMBED_DIM)
x = x.flatten(2).transpose(1, 2)
# Step C: Prepend CLS token and add positional embeddings
x = torch.cat((cls_token, x), dim=1) # (B, num_patches+1, EMBED_DIM)
x = x + pos_embed
# --- MAE Masking (during training) ---
# We assume x now contains embeddings for [CLS, patch1, ..., patchN]
# MAE typically masks patches *before* adding CLS token and pos_embed to encoder
# Here, we'll simplify and show masking on the full sequence for conceptual clarity.
num_unmasked = int(num_patches * (1 - MASK_RATIO))
noise = torch.rand(num_patches) # Random noise for masking
ids_shuffle = torch.argsort(noise) # Shuffle patch indices
ids_restore = torch.argsort(ids_shuffle) # To restore original order later
ids_visible = ids_shuffle[:num_unmasked] # Indices of visible patches
ids_masked = ids_shuffle[num_unmasked:] # Indices of masked patches
# Encoder input (excluding CLS token for simplicity in masking)
x_patches = x[:, 1:, :] # (B, num_patches, EMBED_DIM)
x_visible = x_patches[:, ids_visible, :] # Only visible patches go to encoder
# For decoder, we need all positional embeddings + encoder output + mask tokens
# (Simplified: assume encoder_output is just x_visible for demo)
mask_tokens = nn.Parameter(torch.randn(1, 1, EMBED_DIM)) # Learnable mask token
mask_tokens_repeated = mask_tokens.repeat(1, len(ids_masked), 1)
# Combine encoder output and mask tokens, then add positional embeddings
# This forms the full sequence for the decoder to process
decoder_input = torch.cat([x_visible, mask_tokens_repeated], dim=1)
# Add positional embeddings for all patches (visible + masked)
decoder_pos_embed = pos_embed[:, 1:, :][:, ids_restore, :] # restore order
decoder_input = decoder_input + decoder_pos_embed
# ... Decoder processes decoder_input ...
# ... and outputs reconstructed pixel values for masked patches.
