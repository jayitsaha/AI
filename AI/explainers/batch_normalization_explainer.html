Understanding Batch Normalization
▼

What is it? As data flows through a deep network, the distribution of each layer's inputs keeps shifting during training — earlier layers change, so later layers constantly have to re-adapt to a moving target. Batch Normalization (BN) takes the activations for one feature across an entire mini-batch, re-centers them to mean 0 and re-scales them to variance 1, then applies a small learnable rescale-and-shift so the layer can still represent whatever distribution is actually useful.

Analogy: Picture a teacher grading exams from five different classes, each with a wildly different difficulty. Instead of comparing raw scores, the teacher curves every class to the same mean and spread (a z-score) before comparing students. BN does this per mini-batch, per feature — then adds a dial (\(\gamma\)) and a knob (\(\beta\)) that let the network decide how much of the original "difficulty" to restore if that turns out to be useful.

💡 If you remember one thing

BN standardizes each feature over the batch, then re-introduces flexibility with a learnable affine transform:

$$y_i = \gamma \cdot \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}} + \beta$$

How BatchNorm Works Internally
▼

Where It Sits

BN is inserted between a linear/convolutional layer and its activation function: Linear → BatchNorm → ReLU. For a fully-connected layer it normalizes each of the \(D\) output features independently; for a convolutional layer it normalizes each channel independently, pooling statistics over the batch and the spatial dimensions (N×H×W samples per channel).

The Forward Pass, With Real Numbers

Take one feature's pre-activations across a mini-batch of \(m=8\) samples: \(x = [2.1,\,4.8,\,1.3,\,6.2,\,3.5,\,5.9,\,0.8,\,4.4]\).

  1. Batch mean: \(\mu_B = \frac{1}{8}\sum x_i = 3.625\)
  2. Batch variance: \(\sigma_B^2 = \frac{1}{8}\sum (x_i-\mu_B)^2 \approx 3.689\)
  3. Normalize: \(\hat{x}_i = (x_i-\mu_B)/\sqrt{\sigma_B^2+\epsilon} \approx -0.79,\,0.61,\,-1.21,\ldots\) — now mean ≈ 0, variance ≈ 1
  4. Scale & shift: \(y_i = \gamma\hat{x}_i + \beta\) — if \(\gamma=1,\beta=0\) this is identity-normalized; the network learns better values during training

The exact live numbers for this batch are computed and shown in the interactive walkthrough below — nothing here is hard-coded ahead of time.

Design Decision: Why Normalize Over the Batch (Not Over Features)?

Normalizing across the batch dimension assumes samples in a batch are drawn i.i.d. from the same distribution — reasonable for i.i.d. training data with a large-enough batch. The alternative (normalize across the feature dimension for a single sample) is LayerNorm, which drops the batch-size dependency entirely — critical for RNNs/Transformers where sequence batches are irregular.

Design Decision: Why the Learnable γ, β?

Forcing every layer's output to mean 0, variance 1 could hurt expressiveness — e.g. a sigmoid saturates less usefully near 0. The affine transform \(\gamma,\beta\) restores full representational power: with \(\gamma=\sqrt{\sigma_B^2+\epsilon}\) and \(\beta=\mu_B\), BN can exactly reconstruct the identity mapping. So BN never strictly reduces what the network can express — it only makes the *optimization landscape* better behaved (see Card 3).

🔑 Key Property

BN computes batch statistics during training but freezes to running (exponential moving average) statistics at inference — this is exactly why model.eval() matters in PyTorch: it switches BatchNorm layers from batch stats to the accumulated running stats.

Why It Works — The Math
▼

Forward Pass

For a mini-batch \(\mathcal{B} = \{x_1,\ldots,x_m\}\) of one feature:

$$\mu_B = \frac{1}{m}\sum_{i=1}^m x_i \qquad \sigma_B^2 = \frac{1}{m}\sum_{i=1}^m (x_i-\mu_B)^2$$
$$\hat{x}_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2+\epsilon}} \qquad y_i = \gamma\hat{x}_i + \beta \equiv \text{BN}_{\gamma,\beta}(x_i)$$

Backward Pass (Gradient Flow)

\(\gamma,\beta\) are ordinary learnable parameters trained by backprop; the trickier part is that \(\mu_B\) and \(\sigma_B^2\) are themselves functions of every \(x_i\) in the batch, so gradients must flow through them too:

$$\frac{\partial \mathcal{L}}{\partial \gamma} = \sum_i \frac{\partial \mathcal{L}}{\partial y_i}\hat{x}_i \qquad \frac{\partial \mathcal{L}}{\partial \beta} = \sum_i \frac{\partial \mathcal{L}}{\partial y_i}$$
$$\frac{\partial \mathcal{L}}{\partial x_i} = \frac{1}{m\sqrt{\sigma_B^2+\epsilon}}\Big[m\,\frac{\partial \mathcal{L}}{\partial \hat{x}_i} - \sum_j \frac{\partial \mathcal{L}}{\partial \hat{x}_j} - \hat{x}_i\sum_j \frac{\partial \mathcal{L}}{\partial \hat{x}_j}\hat{x}_j\Big]$$

The key consequence: every sample's gradient depends on every other sample in the batch — this is precisely why tiny batches make BN noisy and why BN behaves differently in train vs. eval mode.

Inference: Running Statistics

During training, BN also accumulates population estimates via an exponential moving average (momentum \(\alpha\), PyTorch default \(0.1\)):

$$\mu_{\text{run}} \leftarrow (1-\alpha)\,\mu_{\text{run}} + \alpha\,\mu_B \qquad \sigma^2_{\text{run}} \leftarrow (1-\alpha)\,\sigma^2_{\text{run}} + \alpha\,\sigma_B^2$$

At inference, batch statistics are replaced entirely by \((\mu_{\text{run}}, \sigma^2_{\text{run}})\) — so a single test sample can still be normalized meaningfully, and outputs no longer depend on which other samples happen to be in the batch.

⚠️ The "Internal Covariate Shift" Misconception

The original paper (Ioffe & Szegedy, 2015) claimed BN works by reducing "internal covariate shift" — the layer-to-layer drift of activation distributions. Santurkar et al. (2018, "How Does Batch Normalization Help Optimization?") showed experimentally that BN barely reduces covariate shift, and that even injecting covariate shift after BN doesn't hurt training. The real mechanism: BN makes the loss landscape smoother — the loss changes more predictably (Lipschitz gradients, more predictable curvature) along the gradient direction — which lets you safely use higher learning rates and converge faster.

Key Takeaways
▼

When to use BatchNorm:

  • CNNs for images with a reasonably large batch size (≥ 16-32 per device)
  • You want to use higher learning rates and converge faster
  • Deep feed-forward / conv nets where the same feature statistics genuinely repeat across the batch

When NOT to use it:

  • RNNs / Transformers with variable-length sequences — batch statistics are unstable → use LayerNorm
  • Very small batch sizes (≤ 4), e.g. object detection / segmentation with high-res images → use GroupNorm
  • Online / streaming inference with batch size 1 during training → BN statistics degenerate (variance → 0)

Code Trace — From Scratch (NumPy)
▼
import numpy as np
class BatchNorm:
def __init__(self, dim, eps=1e-5, momentum=0.1):
self.gamma = np.ones(dim); self.beta = np.zeros(dim)
self.running_mean = np.zeros(dim)
self.running_var = np.ones(dim)
self.eps, self.momentum = eps, momentum
def forward(self, x, training=True):
if training:
mu = x.mean(axis=0) # batch mean per feature
var = x.var(axis=0) # batch variance per feature
self.running_mean = (1-self.momentum)*self.running_mean + self.momentum*mu
self.running_var = (1-self.momentum)*self.running_var + self.momentum*var
else:
mu, var = self.running_mean, self.running_var # frozen stats
x_hat = (x - mu) / np.sqrt(var + self.eps)
return self.gamma * x_hat + self.beta

Production Usage (PyTorch)

bn = torch.nn.BatchNorm2d(num_features=64) # per-channel for conv nets
model.train() # BN uses live batch statistics
model.eval() # BN switches to running_mean / running_var — no batch dependency
# ⚠️ Gotcha: forgetting model.eval() at inference silently uses batch stats,
# which is nondeterministic and depends on the eval batch composition.
