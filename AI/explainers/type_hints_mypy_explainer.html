Understanding Type Hints & mypy
▼

What is it? Python is dynamically typed — you never declare what type a variable holds, and errors like passing a string where an integer is expected only blow up at runtime. Type hints (PEP 484, Python 3.5+) let you annotate your code with type information. mypy is a static analyser that reads those annotations and flags type mismatches before you run a single line — turning Python into a partially typed language.

Analogy: Think of type hints as the labels on jars in a kitchen ("FLOUR", "SUGAR", "SALT"). They don't enforce anything while the jars sit on the shelf, but if a recipe instruction says "add 1 cup FLOUR" and you reach for the jar labelled "SALT", a careful sous-chef (mypy) catches it before the dish is ruined. Python itself doesn't stop you, but mypy does — and it checks the whole kitchen in milliseconds.

💡 If you remember one thing

Type hints are zero-cost at runtime — Python ignores them. mypy reads them statically (like a compiler), walking every call site and variable assignment, and reports incompatible types as errors before execution. The type lattice: \(\texttt{Any}\) escapes all checks, \(\texttt{Optional[T]} = \texttt{Union[T, None]}\), generics via \(\texttt{TypeVar}\), and structural typing via \(\texttt{Protocol}\).

How mypy Works Internally
▼

The Type Lattice

mypy operates over a type lattice — a partial order on types where "higher" means "more general". At the top sits object (every Python object); special position goes to Any which is both top and bottom (it opts out of checking). Subtype relationships flow upward:

The key subtype rule: if \(A \leq B\) (A is a subtype of B), then wherever B is expected you can safely pass an A. bool is a subtype of int; int is not a subtype of str.

The Five Key Type Constructors

  • Optional[T] — shorthand for Union[T, None]. A function returning Optional[str] might return a string or None. mypy forces you to handle both branches.
  • Union[A, B] — the value is A or B. Narrowing (isinstance checks) refines the type inside a branch.
  • Any — the escape hatch. Compatible with every type in both directions. Use sparingly — it silences mypy for everything that flows through it.
  • TypeVar — generic type parameter. T = TypeVar('T') lets you write def identity(x: T) -> T — the return type equals the input type, precisely.
  • Protocol — structural ("duck") typing. A class satisfies a Protocol if it has the required methods/attributes, without needing to explicitly subclass. This is how mypy handles Python's duck-typed idioms.

Covariance & Contravariance

For generic containers, the subtype relationship of the container depends on how it's used. A List[int] is NOT a List[object] (mutable containers are invariant — you could append a non-int). But a Sequence[int] IS a Sequence[object] because Sequence is read-only (covariant). Callable[[object], str] IS a subtype of Callable[[int], str] (contravariant in arguments — accepting a broader type is safe).

$$\frac{A \leq B}{\texttt{List}[A] \not\leq \texttt{List}[B]} \quad \frac{A \leq B}{\texttt{Sequence}[A] \leq \texttt{Sequence}[B]} \quad \frac{B \leq A}{\texttt{Callable}[[A], R] \leq \texttt{Callable}[[B], R]}$$
🔑 Key Property

mypy performs type inference — you don't need to annotate every variable. It infers types from assignments and propagates them. Annotations are most critical at function boundaries (parameters and return types), which are the contracts between modules.

3
Why It Works — Type Theory
▼

Subtype Soundness

The Liskov Substitution Principle (LSP) formalises when substitution is safe. For types \(S\) and \(T\), \(S \leq T\) (S is a subtype of T) if and only if any program property provable about objects of type T still holds for objects of type S. mypy enforces a variant of this for function overriding.

$$S \leq T \iff \forall\, P \text{ (property)}: P(t) \Rightarrow P(s) \quad \text{for all } t:T,\, s:S$$

The Subsumption Rule

The core typing rule that makes assignment safe: if expression \(e\) has type \(S\) and \(S \leq T\), then \(e\) may be used where type \(T\) is expected.

$$\frac{\Gamma \vdash e : S \quad S \leq T}{\Gamma \vdash e : T} \quad \text{(Subsumption)}$$

TypeVar Bounds and Constraints

TypeVars can be bounded: T = TypeVar('T', bound=Comparable) means T must be a subtype of Comparable. Constrained TypeVars enumerate valid substitutions exactly: AnyStr = TypeVar('AnyStr', str, bytes) means T is either str or bytes, never a mix.

$$T_{\text{bound}=B}: \quad \forall\, A.\ (T \mapsto A) \Rightarrow A \leq B$$
⚠️ Common Misconception

Any is NOT the same as object. object is the top type — you can only call methods that all objects share. Any is an escape hatch that is simultaneously a subtype AND supertype of every type — it disables checking entirely for anything it touches.

Key Takeaways & When to Use
▼

When to use type hints + mypy

  • Library code — public APIs benefit most; callers get IDE completion and early error detection.
  • Large codebases — refactoring becomes safe; mypy tells you every call site affected by a signature change.
  • Team projects — annotations are living documentation that can't drift out of sync with the code.

When to be careful

  • Heavy metaprogramming / decorators — mypy sometimes needs hints (overload, ParamSpec, TypeGuard) to understand dynamic patterns.
  • Third-party libraries without stubs — use types-<package> from typeshed, or write stubs yourself.
  • --ignore-missing-imports is a crutch — prefer installing stub packages.
💡 Practical Quick-Start
# Install
pip install mypy

# Run on a single file
mypy my_module.py

# Strict mode (enable all checks)
mypy --strict my_module.py

# pyproject.toml config
[tool.mypy]
python_version = "3.12"
strict = true
ignore_missing_imports = false
