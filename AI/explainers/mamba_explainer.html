Mamba: Selective State-Space Models

Linear-time sequence modeling via input-dependent (selective) SSMs and a hardware-aware parallel scan
Intermediate Deep Learning Sequence Models O(L) time · O(1) inference/step
1
Understanding Mamba
▼

What is it? Mamba (Gu & Dao, 2023) is a sequence model built from a selective state-space model (SSM). It replaces the quadratic self-attention of Transformers with a recurrence that runs in linear time in the sequence length \(L\), while — unlike earlier linear-time SSMs such as S4 — letting its parameters change per time step based on the current input. That single change (selectivity) is what lets a fundamentally recurrent, "compress everything into a fixed-size state" model match Transformer-quality language modeling.

Analogy: Picture a person taking notes while listening to a long lecture, using a notebook of fixed size (not a full transcript). A non-selective note-taker uses the same fixed rule every sentence: "average 5% of the new sentence into my running summary." A selective note-taker instead decides, sentence by sentence, how much to write down and how much to erase — leaning in and writing fast for "the exam will cover chapter 4," and ignoring filler like "um, anyway." Mamba is that selective note-taker, and it computes each decision from the content of the current input itself.

💡 If you remember one thing

Mamba turns the SSM's transition parameters \(\mathbf{B}, \mathbf{C}, \Delta\) into functions of the input instead of fixed weights. This gives the recurrence content-aware "remember / forget" gating like attention or LSTMs, but the recurrence itself still costs only \(O(L)\) — not \(O(L^2)\) — because there is no all-pairs comparison, just a running state that gets selectively updated at each step.

2
How Mamba Works Internally
▼

The base state-space recurrence

Every SSM — including S4 and Mamba — maintains a hidden state \(h_t \in \mathbb{R}^N\) that is updated at every time step and read out to produce the output:

  • State update: \(h_t = \mathbf{A} h_{t-1} + \mathbf{B} x_t\)
  • Output: \(y_t = \mathbf{C} h_t\)

In classic linear time-invariant (LTI) SSMs like S4, \(\mathbf{A}, \mathbf{B}, \mathbf{C}\) are fixed matrices learned once during training and reused at every position, for every input. Because the recurrence is linear and time-invariant, it can be unrolled into a single long convolution and computed with an FFT — great for hardware, but the model literally cannot change how it treats a token based on what that token is.

Selectivity: making B, C, Δ input-dependent (S6)

Mamba's core mechanism, called S6 (Selective Structured State Space Sequence model), makes the discretization step \(\Delta_t\), the input matrix \(\mathbf{B}_t\), and the output matrix \(\mathbf{C}_t\) all linear projections of the current input \(x_t\):

  • \(\Delta_t = \text{softplus}(\text{Linear}(x_t))\) — controls how much this step matters (a large \(\Delta_t\) resets/refreshes the state toward \(x_t\); a small \(\Delta_t\) nearly freezes it, ignoring \(x_t\)).
  • \(\mathbf{B}_t = \text{Linear}(x_t)\) — controls how much of \(x_t\) is written into the state.
  • \(\mathbf{C}_t = \text{Linear}(x_t)\) — controls how the state is read out at this step.

Because \(\Delta_t\) also modulates the discretized \(\bar{\mathbf{A}}_t = \exp(\Delta_t \mathbf{A})\), the model effectively learns a per-token, per-channel "gate" that decides whether to remember old context or overwrite it with new content — exactly the ability an LTI SSM lacks, and the reason S4 struggles on tasks like Selective-Copy that require content-based reasoning.

The price: no more global convolution

The parallel training trick for LTI SSMs relies on the recurrence being time-invariant, so it can be re-expressed as convolving the input with one fixed kernel \(\bar{K}=(\mathbf{C}\bar{\mathbf{B}}, \mathbf{C}\bar{\mathbf{A}}\bar{\mathbf{B}}, \dots)\) — a single FFT gives \(O(L \log L)\) training. Once \(\bar{\mathbf{A}}_t, \bar{\mathbf{B}}_t, \mathbf{C}_t\) vary with \(t\), the kernel is different at every position, the convolution view breaks, and naively you are back to a slow sequential loop over \(L\) steps.

🔑 Key Property

Selectivity buys content-aware memory but destroys the global-convolution shortcut that made S4 fast. Mamba's second contribution — the hardware-aware parallel scan (Card 3) — is what wins that speed back without giving up selectivity.

3
Why It Works — Parallel Scan & the Hardware-Aware Algorithm
▼

Discretization

A continuous-time SSM \(\dot h(t)=\mathbf{A}h(t)+\mathbf{B}x(t)\) is discretized with step size \(\Delta\) (zero-order hold) into the recurrence used at inference:

$$\bar{\mathbf{A}}_t = \exp(\Delta_t \mathbf{A}), \qquad \bar{\mathbf{B}}_t = (\Delta_t \mathbf{A})^{-1}(\exp(\Delta_t \mathbf{A}) - I)\cdot \Delta_t \mathbf{B}_t$$ $$h_t = \bar{\mathbf{A}}_t h_{t-1} + \bar{\mathbf{B}}_t x_t, \qquad y_t = \mathbf{C}_t h_t$$

Because every \(\bar{\mathbf{A}}_t,\bar{\mathbf{B}}_t,\mathbf{C}_t\) now differs per step, this is a genuinely time-varying linear recurrence — no fixed convolution kernel exists. The recurrence is still associative, though: a sequential scan computing \(h_t\) one step at a time is equivalent to a parallel (prefix) scan that combines pairs of "state transition" operators in a binary-tree pattern, \(O(\log L)\) sequential depth instead of \(O(L)\).

The hardware-aware algorithm

Running that scan naively in PyTorch would still be slow, because it materializes the full \((B, L, D, N)\) state tensor in slow GPU HBM at every step. Mamba's implementation instead:

  1. Kernel fusion: the discretization, scan, and output projection are fused into one custom CUDA kernel, so intermediate states never leave fast on-chip SRAM.
  2. Parallel scan: the associative combination above is computed with a work-efficient parallel scan across the sequence dimension, using GPU threads instead of a Python for-loop.
  3. Recomputation: instead of storing all intermediate states for the backward pass (which would blow up memory), the forward states are recomputed during the backward pass — trading extra FLOPs (which are cheap and parallel) for HBM I/O (which is the real bottleneck).

The net effect: Mamba trains and runs at speeds close to a plain convolution, while its FLOP count and, crucially, its memory scale linearly — \(O(L)\) — rather than the \(O(L^2)\) time and memory of self-attention.

$$\text{Attention: } O(L^2 d) \text{ time}, \ O(L^2) \text{ memory} \qquad\text{vs.}\qquad \text{Mamba: } O(L d N) \text{ time}, \ O(L d N) \text{ memory}$$
⚠️ Practical Implication

The parallel scan and kernel fusion are not optional engineering polish — without them, selectivity would make Mamba slower than a Transformer at moderate lengths despite its better asymptotics. The "hardware-aware" part of the paper's title is doing real work: it's what converts a good idea (input-dependent SSM) into a practical one.

Key Takeaways & Comparisons

When Mamba shines:

  • Very long sequences (genomics, audio waveforms, long documents) where attention's \(O(L^2)\) time and memory become the bottleneck.
  • Fast autoregressive generation: inference is a constant-time state update per token, with no growing KV cache to store or read.
  • Content-selective tasks (e.g. Selective-Copy, induction heads) that plain LTI SSMs like S4 provably cannot solve, because S4's fixed \(\mathbf{B},\mathbf{C}\) can't decide what to keep based on content.

Where Transformers still have an edge:

  • Tasks needing precise, easily-inspectable pairwise token interactions (explicit attention maps).
  • Short sequences, where \(O(L^2)\) is not actually large and attention's extra expressivity per FLOP can win.
  • Massive parallel training throughput on very short contexts, where the constant factors of a custom scan kernel matter less.
💡 Hierarchy

LTI SSM / S4 (fixed \(\mathbf{A},\mathbf{B},\mathbf{C}\), fast global convolution, no content selectivity) → Mamba / S6 (input-dependent \(\Delta,\mathbf{B},\mathbf{C}\), no more convolution, recovered via a hardware-aware parallel scan, linear time and memory) → Attention (fully content-dependent, no fixed-size state, quadratic time and memory).

Code Trace (Conceptual PyTorch-like)
▼
class MambaBlock(nn.Module):
def __init__(self, d_model, d_state, d_conv=4, expand=2):
d_inner = expand * d_model
self.in_proj = nn.Linear(d_model, 2 * d_inner) # splits into x, gate z
self.conv1d = nn.Conv1d(d_inner, d_inner, d_conv, groups=d_inner, padding=d_conv-1)
self.x_proj = nn.Linear(d_inner, d_state * 2 + 1) # -> (B_t, C_t, Delta_t)
self.A_log = nn.Parameter(torch.log(torch.arange(1, d_state+1).float().repeat(d_inner,1)))
self.out_proj = nn.Linear(d_inner, d_model)
def forward(self, x): # x: (B, L, d_model)
x_and_z = self.in_proj(x)
x_in, z = x_and_z.chunk(2, dim=-1) # z is the gating branch
x_in = silu(self.conv1d(x_in.transpose(1,2))[..., :x.size(1)].transpose(1,2))
# --- selectivity: B_t, C_t, Delta_t all depend on x_in ---
delta_bc = self.x_proj(x_in)
delta, B, C = delta_bc.split([1, d_state, d_state], dim=-1)
delta = softplus(delta) # (B, L, d_inner)
A = -torch.exp(self.A_log) # (d_inner, d_state), fixed
# --- hardware-aware selective scan (fused CUDA kernel in practice) ---
A_bar = torch.exp(delta.unsqueeze(-1) * A) # per-step, per-channel
B_bar = delta.unsqueeze(-1) * B.unsqueeze(2)
h = torch.zeros(x.size(0), d_inner, d_state)
ys = []
for t in range(x.size(1)): # replaced by parallel scan in the real kernel
h = A_bar[:, t] * h + B_bar[:, t] * x_in[:, t].unsqueeze(-1)
ys.append((C[:, t].unsqueeze(1) * h).sum(-1))
y = torch.stack(ys, dim=1)
y = y * silu(z) # gated residual branch
return self.out_proj(y)
