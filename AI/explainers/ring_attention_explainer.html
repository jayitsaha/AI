Ring Attention

Scaling Attention to Very Long Sequences with Distributed Memory
Technique LLMs Distributed ML Memory Optimization
1
Understanding Ring Attention
▼

What is it? Ring Attention is a memory-efficient technique that enables Transformer models to process extremely long sequences, far beyond what a single GPU's memory can handle. It achieves this by distributing the computation and memory of the attention mechanism across multiple devices (e.g., GPUs) in a "ring" topology.

The Problem: Standard self-attention requires computing an \(L \times L\) attention matrix (where \(L\) is sequence length), which has a memory complexity of \(O(L^2)\). For very long sequences (e.g., millions of tokens), this quickly exceeds the memory capacity of even the largest GPUs, making it a major bottleneck for context window expansion in Large Language Models (LLMs).

Analogy: Imagine a team of chefs (GPUs) preparing a very long recipe (sequence of tokens). Instead of one chef trying to memorize the entire recipe (full \(L \times L\) attention matrix), they divide the recipe into smaller sections. Each chef is responsible for a section. To ensure everyone knows what's happening, they pass their current section of ingredients (Key and Value chunks) around in a circle, continuously updating their understanding based on what others are working on. This way, no single chef needs to hold the entire recipe in their head at once, but everyone still contributes to the complete dish.

💡 If you remember one thing

Ring Attention is a memory optimization for distributed training. It allows each device to compute its portion of the attention output by iteratively processing different chunks of Keys and Values, which are passed around in a ring, without ever needing to store the full \(L \times L\) attention matrix or the entire K/V sequence on a single device.

2
How Ring Attention Works
▼

Chunking the Sequence

First, the input sequence of total length \(L\) is divided into \(N\) equal-sized chunks, where \(N\) is the number of available devices. Each device \(i\) is assigned a chunk of Query (\(Q_i\)), Key (\(K_i\)), and Value (\(V_i\)) matrices, each of length \(L/N\).

In standard attention, each \(Q\) token attends to all \(K\) tokens. This means \(Q_i\) needs to attend to \(K_1, K_2, \dots, K_N\). The challenge is how to do this efficiently without any device having to store all \(K\) and \(V\) chunks simultaneously.

The Ring Communication Pattern

Ring Attention leverages a simple but effective communication pattern: a "ring" of devices. Imagine devices \(D_0, D_1, \dots, D_{N-1}\) connected in a circle, where \(D_i\) can send data to \(D_{(i+1) \pmod N}\) and receive from \(D_{(i-1) \pmod N}\).

The process unfolds in \(N\) steps (or "rounds"):

  1. Initialization: Each device \(D_i\) holds its local \(Q_i, K_i, V_i\). It also initializes an empty accumulator for the attention scores and outputs.
  2. Local Computation: In the first round, each \(D_i\) computes attention scores for its \(Q_i\) against its own \(K_i\) (and corresponding \(V_i\)). This is a partial attention sum.
  3. Ring Passing: After local computation, each device \(D_i\) passes its \(K_i\) and \(V_i\) chunks to the next device in the ring, \(D_{(i+1) \pmod N}\). Simultaneously, it receives \(K_{(i-1) \pmod N}\) and \(V_{(i-1) \pmod N}\) from the previous device.
  4. Accumulation: In subsequent rounds, each \(D_i\) computes attention scores for its \(Q_i\) against the received \(K\) chunk (and corresponding \(V\)). These new scores are added to the accumulated total.
  5. Iteration: Steps 3 and 4 repeat \(N-1\) times, until each \(K_j, V_j\) chunk has visited every device and contributed to every \(Q_i\)'s attention calculation.

By the end of \(N\) rounds, each device \(D_i\) has accumulated all necessary partial attention scores and can compute its final attention output chunk for \(Q_i\). Crucially, no device ever needs to store all \(K\) and \(V\) chunks at once; it only needs its own \(Q\) and the currently received \(K/V\) chunk.

🔑 Key Idea: Memory vs. Communication

Ring Attention trades increased communication overhead (passing K/V chunks) for vastly reduced memory requirements per device. The memory footprint for K/V on any single device becomes \(O(L/N \cdot d_k)\) instead of \(O(L \cdot d_k)\), allowing for much larger total sequence lengths \(L\).

3
Why It Works — The Math
▼

Standard Self-Attention

The core self-attention mechanism for a sequence of length \(L\) with embedding dimension \(d_{model}\) and key dimension \(d_k\) is given by:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Here, \(Q\) is \(L \times d_k\), \(K\) is \(L \times d_k\), and \(V\) is \(L \times d_{model}\). The term \(QK^\top\) results in an \(L \times L\) matrix of attention scores. This matrix, along with the full \(K\) and \(V\) matrices, is the primary source of the \(O(L^2)\) memory bottleneck.

Decomposition for Ring Attention

Let's denote the full sequence as \(X = [x_1, \dots, x_L]\). We partition \(X\) into \(N\) chunks, \(X_0, \dots, X_{N-1}\), each of length \(L/N\). Consequently, \(Q, K, V\) are also partitioned into chunks \(Q_i, K_i, V_i\), each of shape \((L/N) \times d_k\) (or \((L/N) \times d_{model}\) for \(V_i\)).

The full attention score matrix \(S = QK^\top\) can be written as a block matrix:

$$S = \begin{pmatrix} Q_0 \\ Q_1 \\ \vdots \\ Q_{N-1} \end{pmatrix} \begin{pmatrix} K_0^\top & K_1^\top & \dots & K_{N-1}^\top \end{pmatrix} = \begin{pmatrix} Q_0 K_0^\top & Q_0 K_1^\top & \dots & Q_0 K_{N-1}^\top \\ Q_1 K_0^\top & Q_1 K_1^\top & \dots & Q_1 K_{N-1}^\top \\ \vdots & \vdots & \ddots & \vdots \\ Q_{N-1} K_0^\top & Q_{N-1} K_1^\top & \dots & Q_{N-1} K_{N-1}^\top \end{pmatrix}$$

Each block \(S_{ij} = Q_i K_j^\top\) is an \((L/N) \times (L/N)\) matrix. The attention output for the \(i\)-th query chunk, \(O_i\), is then:

$$O_i = \text{softmax}\left(\frac{[S_{i0}, S_{i1}, \dots, S_{i,N-1}]}{\sqrt{d_k}}\right) \begin{pmatrix} V_0 \\ V_1 \\ \vdots \\ V_{N-1} \end{pmatrix}$$

The key insight is that the softmax operation is applied over the entire row of blocks \([S_{i0}, S_{i1}, \dots, S_{i,N-1}]\). This means that to compute the \(i\)-th output chunk \(O_i\), device \(D_i\) needs access to all \(K_j\) and \(V_j\) chunks. Ring Attention enables this by having each \(D_i\) compute its row of blocks iteratively. In each round \(r\), device \(D_i\) computes \(S_{i, (i-r) \pmod N}\) and accumulates it. After \(N\) rounds, \(D_i\) has all the \(S_{ij}\) blocks it needs to form its part of the full attention score matrix, apply softmax, and multiply by the corresponding \(V_j\) chunks (which also circulate).

⚠️ Communication Cost

While Ring Attention significantly reduces memory, it introduces substantial communication costs. In each of the \(N\) rounds, every device must send and receive \(K\) and \(V\) chunks. This can be a bottleneck for very large \(N\) or slow interconnects. The total communication volume is \(N \times (\text{size of } K_i + \text{size of } V_i)\) per attention layer.

Key Takeaways
▼

When to use Ring Attention:

  • When training or inferring with extremely long sequences (e.g., hundreds of thousands to millions of tokens) that exceed single-device memory.
  • In distributed training environments where multiple GPUs are available and connected via a high-bandwidth interconnect (e.g., NVLink, InfiniBand).
  • As a component of larger sequence parallelism strategies, allowing context windows to scale linearly with the number of devices.

Benefits:

  • Massive Context Window Expansion: Enables processing sequences far beyond \(O(L^2)\) memory limits.
  • Memory Efficiency: Each device's memory footprint for K/V caches is reduced from \(O(L \cdot d_k)\) to \(O(L/N \cdot d_k)\).
  • Scalability: The context window length can scale linearly with the number of devices \(N\).

Limitations & Trade-offs:

  • Communication Overhead: Requires significant data transfer between devices in each attention layer, which can be a bottleneck if interconnects are slow.
  • Latency: The sequential nature of the ring pass can introduce latency, as each device must wait for chunks from its predecessor.
  • Synchronization: All devices must synchronize at each step of the ring pass, potentially leading to idle time if devices have imbalanced workloads.
💡 Broader Context

Ring Attention is often combined with other techniques like FlashAttention (for compute efficiency within a chunk) and sequence parallelism (for distributing the model's layers or entire sequence across devices) to achieve state-of-the-art performance for very large models and long contexts.

Code Trace (Pseudocode)
▼

This pseudocode illustrates the core logic of Ring Attention for a single attention head. In a real implementation, this would be integrated into a Transformer layer, often with optimizations like FlashAttention for the local computations.

import torch
import torch.distributed as dist
# Assume a distributed environment is initialized
rank = dist.get_rank() # Current device's index (0 to N-1)
world_size = dist.get_world_size() # Total number of devices (N)
# Input: local_Q, local_K, local_V are chunks on current device
# local_Q: (chunk_len, head_dim)
# local_K: (chunk_len, head_dim)
# local_V: (chunk_len, head_dim)
# Initialize accumulated attention scores and output
accumulated_logits = torch.zeros_like(local_Q @ local_K.transpose(-2, -1)) # (chunk_len, chunk_len)
accumulated_output = torch.zeros_like(local_Q) # (chunk_len, head_dim)
# Ring Attention Loop
current_K = local_K
current_V = local_V
for i in range(world_size):
# 1. Compute partial attention with current K, V
partial_logits = local_Q @ current_K.transpose(-2, -1)
# For simplicity, assume softmax and V-multiplication are done later
accumulated_logits += partial_logits
# 2. Pass K, V to the next device in the ring
if i < world_size - 1: # Don't pass on the last iteration
next_rank = (rank + 1) % world_size
prev_rank = (rank - 1 + world_size) % world_size
# Create buffers for send/recv
send_K = current_K.clone()
send_V = current_V.clone()
recv_K = torch.empty_like(current_K)
recv_V = torch.empty_like(current_V)
# Asynchronous send/recv for K and V
req_send_K = dist.isend(send_K, next_rank)
req_send_V = dist.isend(send_V, next_rank)
req_recv_K = dist.irecv(recv_K, prev_rank)
req_recv_V = dist.irecv(recv_V, prev_rank)
# Wait for communication to complete
req_send_K.wait(); req_send_V.wait()
req_recv_K.wait(); req_recv_V.wait()
current_K = recv_K
current_V = recv_V
# After loop, apply softmax and multiply by V chunks (simplified)
# In reality, softmax is applied over the concatenated full logits
# and then multiplied by the corresponding V chunks.
# This pseudocode focuses on the accumulation of QK^T.
# The full softmax and V-multiplication also needs to be distributed.
final_output_chunk = accumulated_logits # Placeholder for final calculation
print(f"Device {rank}: Final output chunk computed.")
