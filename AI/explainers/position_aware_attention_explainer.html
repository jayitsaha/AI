Position-Aware Attention for Sequential Recommendation

Why self-attention over a purchase/click history needs positional encodings to know item order
Foundational Sequential Recommendation Self-Attention O(n²·d)
1
Understanding Position-Aware Attention
▼

What is it? Sequential recommenders (SASRec, BERT4Rec, and their descendants) treat a user's interaction history — the items they viewed, clicked, or purchased in order — as a sequence, and use self-attention to decide which past items matter most for predicting the next one. The problem: raw self-attention has no built-in sense of order. Given a bag of item embeddings, \(\text{softmax}(QK^\top/\sqrt d)V\) produces the exact same set of outputs no matter what order you feed the items in — it only reshuffles which output goes with which input. That is a disaster for recommendation, where "phone → case → charger" is a completely different signal than "charger → case → phone."

Analogy: Imagine handing someone a shuffled deck of receipt photos and asking "what will this customer buy next?" Without timestamps, they can group receipts by similarity (electronics vs. groceries) but can't tell what was bought most recently or spot a repeating weekly pattern. A positional encoding is like stamping each receipt with a date — now the same content carries a sense of sequence, recency, and rhythm.

💡 If you remember one thing

Positional encodings inject a signal that depends only on where an item sits in the sequence, added to (or fused with) the item's content embedding before attention is computed: $$x_i^{pos} = x_i + PE_i, \qquad \text{Attn}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt d}\right)V$$ This turns a permutation-invariant set model into an order-aware sequence model.

2
How It Works Internally
▼

The Permutation-Invariance Problem

Self-attention computes each output as a weighted average of value vectors, with weights from \(QK^\top\). If you permute the input rows by some permutation \(\pi\), the attention scores and outputs permute identically — the model is equivariant to reordering, not sensitive to it. Two users with identical items but opposite chronological order look indistinguishable to a content-only attention layer.

Fix 1: Absolute Positional Encodings

Vaswani et al.'s sinusoidal scheme assigns each position \(pos\) a fixed vector using sine/cosine at different frequencies per dimension \(i\):

$$PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d}}\right), \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d}}\right)$$

Original SASRec instead uses a learned position embedding table (one trainable vector per slot 1..L), functionally the same idea: a position-only vector added to the item embedding.

Fix 2: Causal Masking

Sequential recommendation is autoregressive: predicting the item after position \(i\) must only look at items \(1..i\), never the future. Before softmax, scores for \(j>i\) are set to \(-\infty\) so they vanish after normalization — combined with position info, this produces attention that is naturally recency-biased.

Fix 3: Relative Positional Encoding

Absolute encodings tie meaning to a fixed slot number. Relative schemes (Transformer-XL, T5-style bias, rotary embeddings) instead encode the offset \(i-j\) between two items directly into the attention score, so "2 purchases ago" means the same thing whether it's early or late in a long history — better generalization to variable-length sequences.

🔑 Key Property

The dot product \((x_i+PE_i)\cdot(x_j+PE_j)\) expands into content·content + content·position + position·content + position·position terms — the network can learn to weight pure recency (position·position) independently of what the items actually are.

3
Why It Works — The Math
▼

Query/Key Projections With Position Fused In

Given position-augmented input \(x_i^{pos}=x_i+PE_i\), project with learned matrices \(W_Q,W_K\in\mathbb{R}^{d\times d}\):

$$q_i = x_i^{pos}W_Q, \qquad k_j = x_j^{pos}W_K, \qquad \text{score}(i,j)=\frac{q_i\cdot k_j}{\sqrt d}$$

Causal Softmax

$$\alpha_{ij}=\frac{\exp(\text{score}(i,j))}{\sum_{j'\le i}\exp(\text{score}(i,j'))}, \qquad \text{score}(i,j)=-\infty \text{ for } j>i$$

Relative Position Bias (T5 / Transformer-XL style)

Instead of (or in addition to) adding \(PE_i\) to the input, add a learned scalar bias keyed only by the offset:

$$\text{score}_{rel}(i,j) = \frac{q_i\cdot k_j}{\sqrt d} + b(i-j)$$

Because \(b\) depends only on \(i-j\), the same relative pattern (e.g. "the immediately preceding item usually matters most") transfers across sequences of any length and any absolute starting position — sinusoidal/learned absolute PE does not have this shift-invariance.

⚠️ Common Pitfall

Learned absolute position embeddings are capped at the trained max sequence length \(L\); a user with a longer history than seen in training has no valid position slot. Sinusoidal PE extrapolates a bit better mathematically but its dot-product structure still degrades far outside the trained range. Relative encodings and rotary embeddings (RoPE) are the standard fixes when history length varies a lot.

Key Takeaways
▼

When position-aware attention matters:

  • Sequential/session-based recommendation (SASRec, BERT4Rec, GRU4Rec-successors using attention)
  • Any transformer over ordered items where recency or rhythm carries signal (clickstreams, playlists, browsing paths)
  • Long user histories where relative recency generalizes better than absolute slot number

Choosing an encoding scheme:

SchemeCapturesGeneralizes to unseen lengths?
None (content only)What the items areN/A — order-blind
Sinusoidal absolute PEFixed slot numberPartially
Learned absolute PEFixed slot numberNo — capped at trained \(L\)
Relative bias / RoPEOffset \(i-j\) between itemsYes
💡 Hierarchy

Set model (no position) ⊂ sequence model (absolute PE, fixed \(L\)) ⊂ relative/rotary model (offset-aware, length-generalizing). Each step adds structure the raw attention formula does not provide on its own — and each is layered on top of, not a replacement for, the causal mask that keeps recommendation autoregressive.

import numpy as np
# 6-item history, d=4 content embeddings (learned in practice)
X = item_embedding_table[history_ids] # (N=6, d=4)
# --- content-only attention: order-blind ---
Q = X @ Wq; K = X @ Wk
scores = Q @ K.T / np.sqrt(d)
attn = softmax(scores, axis=-1) # same weights if X rows permuted
# --- sinusoidal positional encoding ---
def sinusoidal_pe(pos, d):
i = np.arange(d)
angle = pos / np.power(10000, 2*(i//2)/d)
pe = np.where(i % 2 == 0, np.sin(angle), np.cos(angle))
return pe
PE = np.stack([sinusoidal_pe(p, d) for p in range(N)])
X_pos = X + PE # fuse content + position
# --- causal (autoregressive) position-aware attention ---
Qp = X_pos @ Wq; Kp = X_pos @ Wk
scores = Qp @ Kp.T / np.sqrt(d)
mask = np.triu(np.ones((N, N)), k=1).astype(bool)
scores[mask] = -np.inf # block future items
attn_pos = softmax(scores, axis=-1)
# --- relative position bias variant ---
rel_bias = -alpha * np.abs(np.arange(N)[:,None] - np.arange(N)[None,:])
scores_rel = (Q @ K.T)/np.sqrt(d) + rel_bias
scores_rel[mask] = -np.inf
attn_rel = softmax(scores_rel, axis=-1)
