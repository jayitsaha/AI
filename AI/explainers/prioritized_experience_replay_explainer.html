Prioritized Experience Replay (PER)

Sampling important experiences more often for faster, more stable Reinforcement Learning
Intermediate Reinforcement Learning O(log N) sample/update
1
Understanding Prioritized Experience Replay
▼

What is it? In Reinforcement Learning, agents collect (state, action, reward, next_state) tuples and store them in an "experience replay buffer." Standard replay samples these experiences uniformly at random. Prioritized Experience Replay (PER) samples "important" experiences more frequently, where importance is typically measured by the magnitude of the Temporal Difference (TD) error.

Analogy: Imagine studying for an exam. Uniform sampling means reviewing every page of your textbook with equal frequency. Prioritized replay is like focusing more of your study time on the concepts you struggled with most on practice tests (high TD error) or the new material you just learned. This way, you learn faster and more efficiently by addressing your biggest knowledge gaps first.

💡 If you remember one thing

PER samples transitions with high TD error more often. High TD error means the agent's current prediction (\(Q(s,a)\)) is far from its target (\(r + \gamma \max_{a'} Q(s',a')\)), indicating a "surprising" or "informative" event that the agent should learn from more. This significantly speeds up learning for many RL algorithms like DQN.

2
How PER Works Internally
▼

The Core Idea: TD-error as Priority

When an agent interacts with its environment, it collects a stream of (state, action, reward, next_state) tuples. For Q-learning algorithms, the TD error \(\delta\) for a transition \((s_t, a_t, r_t, s_{t+1})\) is defined as:

$$\delta_t = r_t + \gamma \max_{a'} Q(s_{t+1}, a'; \theta^-) - Q(s_t, a_t; \theta)$$

where \(\theta\) are the current network weights and \(\theta^-\) are the target network weights. A large absolute TD error \(|\delta_t|\) means the agent's current value estimate for \((s_t, a_t)\) is significantly different from what it "should" be, according to the Bellman equation. These "surprising" transitions are more informative for learning.

The PER Algorithm: Store, Sample, Update

  1. Store: When a new experience \((s,a,r,s')\) is observed, it's added to the replay buffer. It's assigned a high initial priority (often the maximum priority seen so far) to ensure it's sampled at least once.
  2. Sample: Instead of uniform sampling, experiences are sampled with a probability proportional to their priority. This is typically done using a SumTree or similar data structure for efficient \(O(\log N)\) sampling.
  3. Update: After an experience is sampled and used for a learning step (e.g., updating the Q-network), its priority is updated to the magnitude of the *new* TD error computed with the *updated* network weights.

Importance Sampling (IS) Weights for Bias Correction

Prioritized sampling introduces bias: the distribution of sampled experiences no longer matches the distribution of experiences generated by the agent's policy. To correct this, Importance Sampling (IS) weights are used during the gradient update:

$$w_i = \left( \frac{1}{N \cdot P(i)} \right)^\beta$$

where \(N\) is the buffer size, \(P(i)\) is the sampling probability of experience \(i\), and \(\beta\) is a hyperparameter that controls how much bias correction is applied (typically annealed from a small value to 1 over training). These weights are applied to the gradients during backpropagation, effectively down-weighting the contribution of frequently sampled experiences and up-weighting rarely sampled ones.

🔑 Key Property

PER uses two hyperparameters: \(\alpha\) (alpha) and \(\beta\) (beta). \(\alpha \in [0,1]\) determines how much prioritization influences sampling (0 = uniform, 1 = full priority). \(\beta \in [0,1]\) determines how much importance sampling correction is applied (0 = no correction, 1 = full correction). Both are crucial for balancing sampling efficiency with avoiding bias.

3
Why It Works — The Math
▼

Priority Function

The priority \(p_i\) of an experience \(i\) is typically defined based on its absolute TD error \(|\delta_i|\). To ensure all experiences have a chance to be sampled (especially new ones with unknown TD error), a small positive constant \(\epsilon\) is added:

$$p_i = |\delta_i| + \epsilon$$

This is called the "proportional prioritization" scheme. An alternative is "rank-based prioritization," where \(p_i = 1 / \text{rank}(i)\), with rank determined by \(|\delta_i|\). Proportional prioritization is more common due to its direct link to the TD error magnitude.

Sampling Probability

The probability of sampling experience \(i\) is given by a power of its priority, normalized by the sum of priorities of all experiences in the buffer. The exponent \(\alpha\) controls the degree of prioritization:

$$P(i) = \frac{p_i^\alpha}{\sum_k p_k^\alpha}$$

If \(\alpha = 0\), then \(p_i^\alpha = 1\) for all \(i\), and \(P(i) = 1/\sum_k 1 = 1/N\), which reverts to uniform sampling. As \(\alpha \to 1\), sampling becomes strongly biased towards high-TD-error experiences.

Importance Sampling (IS) Weights

When we use a stochastic gradient descent update for a loss function \(L(\theta)\), the expectation of the gradient is taken over the data distribution. If we sample from a biased distribution \(Q\) instead of the true distribution \(P\), we need to correct for this. For an unbiased estimate of \(\mathbb{E}_{x \sim P}[\nabla L(x)]\), we use:

$$\mathbb{E}_{x \sim P}[\nabla L(x)] = \mathbb{E}_{x \sim Q}\left[ \frac{P(x)}{Q(x)} \nabla L(x) \right]$$

In PER, \(P(x)\) is the uniform distribution (\(1/N\)) and \(Q(x)\) is \(P(i)\) (defined above). So the IS weight is \(w_i = \frac{1/N}{P(i)}\). To further control the correction, a hyperparameter \(\beta\) is introduced, and the weights are often normalized by \(\max_k w_k\) for stability:

$$w_i = \left( \frac{1}{N \cdot P(i)} \right)^\beta \quad \text{and then } w_i \leftarrow w_i / \max_k w_k$$

The \(\max_k w_k\) normalization ensures that IS weights are never greater than 1, preventing large updates from rare experiences, which can lead to instability. The \(\beta\) parameter is typically annealed from an initial value (e.g., 0.4) to 1.0 over training, gradually increasing the bias correction as learning progresses.

⚠️ Common Pitfall

Forgetting to update the priority of a sampled experience after a learning step is a critical error. The priority must reflect the current TD error with the latest network weights. If priorities become stale, the agent might repeatedly sample experiences that are no longer informative, or miss new, high-TD-error experiences.

Key Takeaways
▼

When to use PER:

  • When training Deep Q-Networks (DQNs) or other off-policy value-based RL algorithms.
  • In environments where rewards are sparse or events are rare but critical (e.g., reaching a goal state).
  • To accelerate learning and improve sample efficiency, especially in complex environments.
  • When you have a large replay buffer and want to make the most of stored experiences.

When NOT to use / be cautious:

  • On-policy algorithms (like Policy Gradients, PPO, A2C) where the data distribution must strictly match the current policy. PER introduces off-policy data bias.
  • If the TD error is not a good indicator of importance (e.g., if the reward function is pathological or the value function is highly unstable).
  • With very small replay buffers, as the benefits of prioritization might be limited, and the overhead might not be worth it.
  • If computational overhead is a major concern: PER's sampling (SumTree) is \(O(\log N)\) vs. \(O(1)\) for uniform, and IS weights add computation.
💡 Big Picture

PER is a crucial ingredient for many state-of-the-art deep RL agents, offering a significant boost in performance and stability by intelligently re-using past data. It highlights the importance of data management in complex learning systems.

Code Trace (Python - Simplified PER Buffer)

import numpy as np
class SumTree: # A binary tree structure for efficient sampling and update
def __init__(self, capacity):
self.capacity = capacity
self.tree = np.zeros(2 * capacity - 1) # Stores priorities (leaf nodes) and sums
self.data = np.zeros(capacity, dtype=object) # Stores experiences
self.data_ptr = 0
def add(self, priority, data):
tree_idx = self.data_ptr + self.capacity - 1
self.data[self.data_ptr] = data
self.update(tree_idx, priority) # Update leaf node and its parents
self.data_ptr = (self.data_ptr + 1) % self.capacity
def update(self, tree_idx, priority):
change = priority - self.tree[tree_idx]
self.tree[tree_idx] = priority
while tree_idx != 0: # Propagate change up to root
tree_idx = (tree_idx - 1) // 2
self.tree[tree_idx] += change
def get_leaf(self, v): # Sample a leaf proportional to its priority
parent_idx = 0
while True:
left_child_idx = 2 * parent_idx + 1
right_child_idx = left_child_idx + 1
if left_child_idx >= len(self.tree): # Reached leaf node
leaf_idx = parent_idx
break
else: # Traverse down the tree
if v <= self.tree[left_child_idx]:
parent_idx = left_child_idx
else:
v -= self.tree[left_child_idx]
parent_idx = right_child_idx
data_idx = leaf_idx - self.capacity + 1
return leaf_idx, self.tree[leaf_idx], self.data[data_idx]
@property
def total_priority(self): return self.tree[0] # Root contains sum of all priorities
class PrioritizedReplayBuffer:
def __init__(self, capacity, alpha=0.6, beta=0.4, epsilon=0.01):
self.sum_tree = SumTree(capacity)
self.capacity = capacity
self.alpha = alpha
self.beta = beta
self.epsilon = epsilon
self.max_priority = 1.0 # Initial max priority for new experiences
def add(self, experience):
self.sum_tree.add(self.max_priority, experience)
def sample(self, batch_size):
batch = []
indices = []
weights = []
total_priority = self.sum_tree.total_priority
segment = total_priority / batch_size
for i in range(batch_size):
a = segment * i
b = segment * (i + 1)
v = np.random.uniform(a, b) # Sample uniformly within segments
idx, priority, data = self.sum_tree.get_leaf(v)
sampling_prob = priority / total_priority
weight = (self.capacity * sampling_prob)**(-self.beta)
batch.append(data)
indices.append(idx)
weights.append(weight)
max_weight = max(weights) if weights else 1.0
weights = np.array(weights) / max_weight # Normalize IS weights
return indices, batch, weights
def update_priorities(self, indices, td_errors):
for idx, td_error in zip(indices, td_errors):
priority = (np.abs(td_error) + self.epsilon)**self.alpha
self.sum_tree.update(idx, priority)
self.max_priority = max(self.max_priority, priority)
