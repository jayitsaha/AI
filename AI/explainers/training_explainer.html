Training implicit generative models and density estimators without an intractable partition function

1
Understanding Implicit Density Estimation
▼

What is it? Many powerful generative models, like Energy-Based Models (EBMs) or certain types of implicit generative models, define a probability distribution \(p(x;\theta)\) where the normalization constant (the "partition function") is intractable to compute. This makes standard maximum likelihood training (which requires computing this constant) impossible. Contrastive Divergence (CD), Score Matching (SM), and Noise Contrastive Estimation (NCE) are three fundamental techniques to train such models by approximating the necessary gradients or loss functions without ever explicitly calculating the intractable partition function.

Analogy: Imagine you're trying to describe the typical shape of a "cat." You have many real cat pictures (positive examples). If you were to explicitly define "cat-ness" (a probability distribution), you'd need to compare it against all possible images (the partition function). Instead, these methods offer shortcuts:

  • CD: "Show me a real cat, and show me something that *almost* looks like a cat but isn't quite right. I'll learn to push my definition towards the real cat and away from the almost-cat."
  • SM: "I'll try to make the direction of 'cat-ness' (the gradient of my log-probability) match the direction of 'real cat-ness' everywhere, without worrying about the absolute 'cat-ness' score."
  • NCE: "I'll play a game where I'm shown a real cat or a random, clearly non-cat image. I'll learn to tell the difference, and in doing so, I'll implicitly learn what a cat is."
💡 If you remember one thing

CD, SM, and NCE are all ingenious ways to train generative models or density estimators when the normalization constant (partition function) of the model's probability distribution is intractable. They achieve this by either approximating the gradient of the log-likelihood or by constructing an alternative, tractable objective function.

2
How These Methods Work Internally
▼

The Intractable Partition Function Problem

Many generative models define an unnormalized probability distribution \( \tilde{p}(x;\theta) = e^{-E(x;\theta)} \), where \(E(x;\theta)\) is an "energy function" parameterized by \(\theta\). The true probability density is \(p(x;\theta) = \frac{\tilde{p}(x;\theta)}{Z(\theta)}\), where \(Z(\theta) = \int \tilde{p}(x;\theta) dx = \int e^{-E(x;\theta)} dx\) is the partition function. For complex, high-dimensional data, this integral is almost always intractable, preventing direct maximum likelihood optimization.

Contrastive Divergence (CD)

CD (Hinton, 2002) approximates the gradient of the log-likelihood by sampling. The core idea is to increase the energy of samples from the model's current distribution while decreasing the energy of true data samples. This "pushes" the model distribution away from regions it currently finds probable but are not data, and "pulls" it towards the data. It uses a short Markov Chain Monte Carlo (MCMC) chain (e.g., Gibbs sampling or Langevin dynamics) to get "negative" samples \(x'\) from the model's current distribution, starting from data samples \(x\). Instead of running the chain to equilibrium (which is intractable), CD-k runs it for only \(k\) steps. This makes the gradient biased but often effective.

Score Matching (SM)

Score Matching (Hyvärinen, 2005) bypasses the partition function by matching the gradients of the log-density (the "score function") instead of the densities themselves. The score function \(\nabla_x \log p(x;\theta)\) is invariant to the partition function (since \(\nabla_x \log Z(\theta) = 0\)). The objective minimizes the squared difference between the model's score and the data's score. A clever trick allows the objective to be computed without needing the data's score (which is unknown) or the model's partition function, but it requires computing second-order derivatives of the log-likelihood with respect to \(x\).

Noise Contrastive Estimation (NCE)

NCE (Gutmann & Hyvärinen, 2010) reframes the density estimation problem as a binary classification task. It trains a classifier to distinguish between samples from the true data distribution \(p_{data}(x)\) and samples from a chosen "noise" distribution \(p_{noise}(x)\). The output of this classifier is directly related to the ratio \(p(x;\theta)/p_{noise}(x)\). By optimizing this binary classification loss, the model implicitly learns to match \(p_{data}(x)\) with \(p(x;\theta)\). The noise distribution \(p_{noise}(x)\) must be chosen carefully: it should be easy to sample from and evaluate, and ideally cover the data space.

🔑 Key Property

All three methods operate on the principle of indirect inference. They either approximate the intractable expectation in the log-likelihood gradient (CD), leverage properties of derivatives that cancel out the partition function (SM), or transform the problem into a tractable auxiliary task (NCE).

3
Why It Works — The Math
▼

Energy-Based Model Log-Likelihood Gradient

For an EBM with \(p(x;\theta) = \frac{e^{-E(x;\theta)}}{Z(\theta)}\), the gradient of the log-likelihood with respect to parameters \(\theta\) is:

$$\nabla_\theta \log p(x;\theta) = -\nabla_\theta E(x;\theta) - \nabla_\theta \log Z(\theta)$$

Using the identity \(\nabla_\theta \log Z(\theta) = \mathbb{E}_{p(x';\theta)}[\nabla_\theta \log \tilde{p}(x';\theta)] = -\mathbb{E}_{p(x';\theta)}[\nabla_\theta E(x';\theta)]\), we get the crucial "positive-negative" gradient form:

$$\nabla_\theta \log p(x;\theta) = \underbrace{-\nabla_\theta E(x;\theta)}_{\text{Positive Phase}} + \underbrace{\mathbb{E}_{p(x';\theta)}[\nabla_\theta E(x';\theta)]}_{\text{Negative Phase}}$$

The positive phase pulls the model towards data \(x\), decreasing their energy. The negative phase pushes the model away from samples \(x'\) drawn from its own distribution, increasing their energy. The intractability lies in computing the expectation \(\mathbb{E}_{p(x';\theta)}[\dots]\).

Contrastive Divergence (CD-k) Approximation

CD-k approximates the expectation by replacing \(\mathbb{E}_{p(x';\theta)}[\dots]\) with an average over \(x_k\) samples obtained by running \(k\) steps of an MCMC chain (e.g., Langevin dynamics) initialized at data points \(x_0 \sim p_{data}(x)\):

$$\nabla_\theta \log p(x;\theta) \approx -\nabla_\theta E(x;\theta) + \nabla_\theta E(x_k;\theta)$$

Where \(x_k \sim \text{MCMC-k}(x_0, \theta)\). This is a biased estimator, but computationally feasible. It aims to push up the probability of data samples and push down the probability of "confabulated" samples after a short MCMC walk.

Score Matching Objective

The score matching objective is defined as minimizing the Fisher divergence between the model's score and the data's score. For a distribution \(p(x)\), its score is \(\nabla_x \log p(x)\). The objective function is:

$$\mathcal{J}_{SM}(\theta) = \frac{1}{2} \mathbb{E}_{p_{data}(x)}\left[ \left\| \nabla_x \log p(x;\theta) - \nabla_x \log p_{data}(x) \right\|^2 \right]$$

Through integration by parts, this can be transformed into a tractable form that does not depend on \(p_{data}(x)\) or \(Z(\theta)\), but requires second derivatives of the model's log-density:

$$\mathcal{J}_{SM}(\theta) = \mathbb{E}_{p_{data}(x)}\left[ \operatorname{tr}\left(\nabla_x^2 \log p(x;\theta)\right) + \frac{1}{2} \left\| \nabla_x \log p(x;\theta) \right\|^2 \right]$$

Minimizing this objective forces the model's score function to match the data's score function.

Noise Contrastive Estimation (NCE) Loss

NCE frames the problem as learning a binary classifier \(D(x)\) to distinguish data \(x \sim p_{data}(x)\) from noise \(x \sim p_{noise}(x)\). The optimal classifier for this task is \(D^*(x) = \frac{p_{data}(x)}{p_{data}(x) + k \cdot p_{noise}(x)}\) (where \(k\) is the ratio of noise to data samples). NCE trains a model \(p(x;\theta)\) such that \(D(x) = \sigma(\log p(x;\theta) - \log p_{noise}(x))\). The binary cross-entropy loss is:

$$\mathcal{J}_{NCE}(\theta) = \mathbb{E}_{p_{data}(x)}\left[ \log \sigma(s(x)) \right] + \mathbb{E}_{p_{noise}(x)}\left[ \log (1 - \sigma(s(x))) \right]$$

where \(s(x) = \log p(x;\theta) - \log p_{noise}(x)\). By minimizing this, \(p(x;\theta)\) is implicitly optimized to approximate \(p_{data}(x)\).

⚠️ Common Pitfall

Each method has its challenges: CD-k's MCMC chains might not mix well or be too slow; Score Matching requires second derivatives which can be computationally intensive; NCE's performance is sensitive to the choice of the noise distribution \(p_{noise}(x)\) and the noise-to-data ratio \(k\).

Key Takeaways
▼
MethodCore IdeaProsCons
Contrastive Divergence (CD-k)Approximate EBM log-likelihood gradient using short MCMC chains.Conceptually simple, widely applicable to EBMs.Biased gradient, MCMC chains might not mix well, choice of \(k\) is heuristic.
Score Matching (SM)Match gradients of log-density; bypass partition function via integration by parts.Unbiased gradient (if second derivatives are exact), no sampling required.Requires second-order derivatives, computationally expensive for high-D inputs.

When to use these methods:

  • When training generative models (like EBMs) or density estimators where the partition function \(Z(\theta)\) is intractable.
  • When direct maximum likelihood estimation is computationally infeasible due to the normalization constant.
  • For implicit generative models that don't directly define a likelihood but can generate samples (e.g., GANs are related to NCE).

When NOT to use:

  • For models where the likelihood (and thus \(Z(\theta)\)) is tractable (e.g., simple Gaussians, normalizing flows, VAEs with tractable decoders).
  • When computational resources are extremely limited for methods requiring MCMC or second derivatives.
  • If exact likelihood values are required for downstream tasks (these methods provide density estimation, but not necessarily exact likelihoods).
💡 Big Picture

These techniques represent a powerful paradigm shift in generative modeling: instead of trying to explicitly compute and maximize a likelihood that's often intractable, we find clever proxies that allow us to learn good models without ever touching the normalization constant. They are foundational to many modern implicit generative models.

Code Trace (Conceptual PyTorch)
▼
import torch
import torch.nn as nn
import torch.optim as optim
# Assume EnergyModel(x) outputs E(x)
# and data_loader provides batches of x_data
# --- Contrastive Divergence (CD-k) ---
def train_cd(model, data_loader, optimizer, k_steps=1):
for x_data in data_loader:
# Positive phase: decrease energy of data samples
energy_pos = model(x_data).mean()
# Negative phase: MCMC samples (e.g., Langevin dynamics)
x_neg = x_data.clone().detach().requires_grad_(True)
for _ in range(k_steps):
neg_energy = model(x_neg).sum()
grad_neg_energy = torch.autograd.grad(neg_energy, x_neg)[0]
x_neg = x_neg - 0.1 * grad_neg_energy + 0.01 * torch.randn_like(x_neg) # Langevin
x_neg = x_neg.detach().requires_grad_(True) # detach for next step
energy_neg = model(x_neg).mean()
# CD loss: (positive_energy - negative_energy)
loss = energy_pos - energy_neg
optimizer.zero_grad()
loss.backward()
optimizer.step()
# --- Score Matching (simplified for 1D Gaussian model) ---
# For a Gaussian N(mu, sigma^2), log p(x) = -0.5*(x-mu)^2/sigma^2 - log(sigma) - 0.5*log(2pi)
# score = d/dx log p(x) = -(x-mu)/sigma^2
# d/dx score = -1/sigma^2 (trace of Hessian in 1D)
def train_sm(model_mu, model_sigma, data_loader, optimizer):
for x_data in data_loader:
x_data.requires_grad_(True) # need gradients w.r.t. input x
log_p_x = -0.5 * ((x_data - model_mu)**2 / model_sigma**2) - torch.log(model_sigma)
score = torch.autograd.grad(log_p_x.sum(), x_data, create_graph=True)[0]
# Simplified SM loss: -trace(Hessian) - 0.5 * ||score||^2
# Here, trace(Hessian) is d/dx score, which is -1/sigma^2 for Gaussian
sm_loss = (1 / model_sigma**2) + 0.5 * (score**2).mean()
optimizer.zero_grad()
sm_loss.backward()
optimizer.step()
# --- Noise Contrastive Estimation (NCE) ---
# Assume model_log_p(x) outputs log p(x) (unnormalized)
# Assume noise_sampler() generates x_noise, noise_log_p(x) outputs log p_noise(x)
# Assume D is a binary classifier: D(x) -> log(p(real)/p(fake))
def train_nce(model_log_p, noise_sampler, noise_log_p, data_loader, optimizer):
for x_data in data_loader:
x_noise = noise_sampler(x_data.shape[0])
# Compute scores for data and noise
s_data = model_log_p(x_data) - noise_log_p(x_data)
s_noise = model_log_p(x_noise) - noise_log_p(x_noise)
# NCE loss (binary cross-entropy)
loss_data = -torch.log(torch.sigmoid(s_data)).mean()
loss_noise = -torch.log(1 - torch.sigmoid(s_noise)).mean()
loss = loss_data + loss_noise
optimizer.zero_grad()
loss.backward()
optimizer.step()
