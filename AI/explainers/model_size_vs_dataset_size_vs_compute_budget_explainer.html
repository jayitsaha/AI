The scaling laws of deep learning: finding the optimal balance for a given compute budget

1
Understanding Scaling Laws
▼

What is it? Scaling laws describe how a model's performance (usually measured by validation loss) changes as you increase three key resources: model size (\(N\), number of parameters), dataset size (\(D\), number of training tokens/examples), and compute budget (\(C\), total FLOPs spent during training). These laws reveal that for a given compute budget, there's often an optimal balance between making a model larger and training it on more data.

Analogy: Imagine you're building a custom racing car (your model). You have a fixed budget of money (compute). You can spend it on a bigger engine (more parameters) or more fuel for practice laps (more training data). Historically, people often focused on just buying the biggest engine. Scaling laws tell us that for a given total budget, there's an optimal mix: a moderately large engine with plenty of fuel for practice might win more races than an enormous engine that runs out of fuel after two laps.

💡 If you remember one thing

For large language models (LLMs), recent scaling laws (e.g., Chinchilla) suggest that for a fixed compute budget, models have often been undertrained. The optimal strategy is to train smaller models on significantly more data than previously thought, leading to better performance for the same FLOPs.

2
From Intuition to Empirical Laws
▼

The Traditional View vs. Modern Findings

For years, a common heuristic in deep learning was "bigger models are better." Researchers would often scale up model sizes (\(N\)) while keeping dataset sizes (\(D\)) relatively constant or growing them linearly. This led to models like GPT-3, which was trained on ~300 billion tokens with 175 billion parameters. This strategy was effective up to a point, but it implicitly assumed that model capacity was the primary bottleneck.

However, systematic studies (like Kaplan et al. 2020, Hoffmann et al. 2022 a.k.a. Chinchilla) revealed that the relationship is more nuanced. They trained hundreds of models across wide ranges of \(N\) and \(D\) and observed the resulting loss. The key insight was that for a fixed compute budget (\(C\)), there's an optimal allocation of resources between model size and data size. Simply increasing \(N\) without proportionally increasing \(D\) leads to diminishing returns, as the model quickly exhausts the useful information in the dataset.

The "Compute-Optimal" Frontier

The concept of "compute-optimal" training emerges from these studies. For a given total FLOPs, one can explore different combinations of \(N\) and \(D\) that consume that compute. For example, a very large model trained on a small dataset might perform worse than a moderately sized model trained for many more steps on a much larger dataset, even if both consume the same total FLOPs. The scaling laws provide a mathematical framework to predict this optimal trade-off.

Specifically, for transformer-based language models, the Chinchilla paper found that for optimal training, both model size and dataset size should scale proportionally with compute budget, such that the number of training tokens \(D\) should be roughly 20 times the number of model parameters \(N\) (i.e., \(20N\) tokens). This implies that many prior large models were significantly undertrained on data.

🔑 Key Property

Scaling laws are empirical observations derived from extensive experimentation, not theoretical derivations from first principles. They describe emergent properties of deep learning systems and provide practical guidance for efficient resource allocation during large-scale model pre-training.

3
Why It Works — The Scaling Law Equations
▼

The Loss Function and Compute Relationship

The core of scaling laws lies in two empirical relationships. First, the total compute budget \(C\) (in FLOPs) for training a transformer model is approximately proportional to the product of its parameters \(N\) and the number of training tokens \(D\):

$$C \approx 6ND$$

Here, \(N\) is in billions of parameters, and \(D\) is in billions of tokens. The factor of 6 comes from the forward and backward passes of a transformer layer (roughly 2 FLOPs per parameter per token, times 3 for forward, backward, and optimizer update; plus some overheads). This formula defines the constraint: for a fixed \(C\), as \(N\) increases, \(D\) must decrease, and vice-versa.

Second, the achievable validation loss \(L\) can be modeled as a function of \(N\) and \(D\). A common form, derived from observing many training runs, is:

$$L(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta}$$

Where \(E\) is an irreducible minimum loss (e.g., due to noise in the data or inherent task difficulty), and \(A, B, \alpha, \beta\) are positive constants determined empirically. Typically, \(\alpha\) and \(\beta\) are found to be similar (e.g., around 0.07-0.08). This equation shows that loss decreases as \(N\) or \(D\) increase, but with diminishing returns (due to the exponents \(\alpha, \beta < 1\)).

Finding the Compute-Optimal Configuration

To find the optimal \(N\) and \(D\) for a fixed \(C\), we substitute \(D = C / (6N)\) into the loss equation:

$$L(N, C) = E + \frac{A}{N^\alpha} + \frac{B}{\left(\frac{C}{6N}\right)^\beta} = E + A N^{-\alpha} + B \left(\frac{C}{6}\right)^{-\beta} N^\beta$$

To minimize \(L(N, C)\) with respect to \(N\) (for a fixed \(C\)), we take the derivative with respect to \(N\) and set it to zero. This yields an optimal \(N\) proportional to \(C^{\frac{\alpha}{\alpha+\beta}}\) and an optimal \(D\) proportional to \(C^{\frac{\beta}{\alpha+\beta}}\). If \(\alpha \approx \beta\), then \(N\) and \(D\) scale roughly equally with \(C\), implying that for optimal training, both model size and dataset size should grow proportionally to the compute budget.

⚠️ Common Pitfall

These scaling laws are specific to pre-training large language models (transformers) on general text corpora. They might not directly apply to fine-tuning, other model architectures (e.g., CNNs for vision), or tasks where data is inherently very limited. The constants \(A, B, \alpha, \beta\) are also empirical and can vary slightly between studies or specific model families.

Key Takeaways
▼

When to apply scaling laws:

  • When pre-training large transformer models (especially LLMs) from scratch.
  • When you have a fixed compute budget and want to maximize performance.
  • When designing new model architectures or training strategies for foundation models.

Implications and considerations:

  • Data is more important than previously thought: The Chinchilla paper showed that for a given compute budget, models were often too large and undertrained. Scaling up data proportionally to compute is crucial.
  • Efficiency: Scaling laws help avoid wasting compute by training models that are either too large for their data or too small to benefit from more data.
  • Beyond pre-training: While primarily for pre-training, the principles (resource allocation, diminishing returns) can inform other stages like fine-tuning, though specific formulas may differ.
  • Data quality: These laws typically assume high-quality data. The benefit of scaling data might diminish if additional data is noisy or redundant.
💡 The "Chinchilla" Finding

The optimal training recipe for a given compute budget is to roughly double the training dataset size for every doubling of model parameters. This leads to a ratio where the number of training tokens (\(D\)) is approximately 20 times the number of non-embedding parameters (\(N\)). This means many previous large models were significantly undertrained.

Code Trace — Scaling Law Simulation
▼
import numpy as np
# Scaling law constants (illustrative, based on Chinchilla/Kaplan)
E = 0.05 # Irreducible loss
A = 400 # N-scaling constant
alpha = 0.07 # N-scaling exponent
B = 3e10 # D-scaling constant (D in tokens)
beta = 0.07 # D-scaling exponent
C_FACTOR = 6 # FLOPs per parameter per token
def calculate_loss(N_params, D_tokens):
"""Calculate loss given N (parameters) and D (tokens)."""
if N_params <= 0 or D_tokens <= 0: return np.inf
loss = E + A / (N_params**alpha) + B / (D_tokens**beta)
return loss
def find_optimal_nd(compute_budget):
"""Find optimal N and D for a given compute budget C."""
# C = C_FACTOR * N * D => D = C / (C_FACTOR * N)
# Substitute into loss: L(N) = E + A*N^-alpha + B*(C/(C_FACTOR*N))^-beta
# L(N) = E + A*N^-alpha + B*(C_FACTOR/C)^beta * N^beta
# Analytical solution for optimal N by setting dL/dN = 0:
# -alpha * A * N^(-alpha-1) + beta * B * (C_FACTOR/C)^beta * N^(beta-1) = 0
# alpha * A * N^(-alpha-1) = beta * B * (C_FACTOR/C)^beta * N^(beta-1)
# N^(alpha+beta) = (alpha * A) / (beta * B * (C_FACTOR/C)^beta)
# N_optimal = ((alpha * A) / (beta * B))^(1/(alpha+beta)) * (C/C_FACTOR)^(beta/(alpha+beta))
N_optimal = ((alpha * A) / (beta * B))**(1/(alpha+beta)) * \
(compute_budget / C_FACTOR)**(beta/(alpha+beta))
D_optimal = compute_budget / (C_FACTOR * N_optimal)
return N_optimal, D_optimal
# Example usage:
compute_target = 1e21 # 1 ZettaFLOP
N_opt, D_opt = find_optimal_nd(compute_target)
loss_opt = calculate_loss(N_opt, D_opt)
print(f"For C={compute_target:.0e} FLOPs:")
print(f" Optimal Model Size (N): {N_opt/1e9:.2f} Billion parameters")
print(f" Optimal Dataset Size (D): {D_opt/1e12:.2f} Trillion tokens")
print(f" Minimum Loss (L): {loss_opt:.4f}")
