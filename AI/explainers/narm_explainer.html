Foundational Deep Learning Recommender Systems O(L·d) attention
1
Understanding NARM
▼

What is it? NARM (Neural Attentive Recommendation Machine) is a deep learning model designed for sequential recommendation, particularly in session-based scenarios (e.g., e-commerce browsing sessions). It uses a Gated Recurrent Unit (GRU) to encode the sequence of items a user has interacted with, then applies a novel attention mechanism to capture both the user's general interest within the session (global attention) and their current intent (local attention). This allows it to predict the next item a user is likely to interact with.

Analogy: Imagine you're helping a friend shop online. They've added several items to their cart (the sequence) and are currently looking at a specific item. You want to suggest the *next* item. NARM does this by considering two things: (1) all items they've looked at so far, weighted by how similar they are to the *last* item added (global intent, like "they're clearly into gadgets now"), and (2) all items they've looked at, weighted by how relevant they are to their *current browsing state* (local intent, like "they just looked at a phone, so maybe a case?"). NARM combines these two insights to make a smart suggestion.

💡 If you remember one thing

NARM combines a GRU to model sequential dependencies with a dual attention mechanism. One attention component captures global session intent (querying all past items with the *last* item in the sequence), and another captures local/current intent (querying all past items with the *current GRU hidden state*). These are combined for a robust session representation.

How NARM Works Internally
▼

The Core Components

NARM processes a sequence of items \(x_1, x_2, \dots, x_L\) (each represented by its embedding) to predict the next item. It consists of three main parts:

  1. Session Encoder (GRU): A GRU processes the sequence of item embeddings. At each time step \(t\), it takes the current item embedding \(x_t\) and the previous hidden state \(h_{t-1}\) to produce a new hidden state \(h_t\). This sequence of hidden states \(\{h_1, \dots, h_L\}\) implicitly captures the sequential dependencies and user's evolving preferences.
  2. Dual Attention Mechanism: This is where NARM shines. Instead of just using the last GRU hidden state \(h_L\) as the session representation, NARM computes two context vectors:
    • Global Attention: Uses the embedding of the *last item* in the session, \(x_L\), as a query to attend over all previous item embeddings \(\{x_1, \dots, x_L\}\). This aims to capture the user's overall interest or the main theme of the session.
    • Local Attention: Uses the *current GRU hidden state*, \(h_L\), as a query to attend over all previous item embeddings \(\{x_1, \dots, x_L\}\). This focuses on the user's immediate intent or what they are looking for *right now*.
  3. Session Representation and Prediction: The final GRU hidden state \(h_L\) and the two attention-derived context vectors (global and local) are concatenated and passed through a linear layer to form the ultimate session representation \(s_L\). This \(s_L\) is then used to predict scores for all possible next items, typically via a softmax over item embeddings.

Design Decision: Why Two Attentions?

A single attention mechanism, if queried by \(h_L\), might overemphasize the most recent items (local bias), potentially missing broader session themes. If queried by \(x_L\), it might miss the subtle sequential patterns captured by the GRU. By combining both, NARM aims to get the best of both worlds: the precise sequential modeling of the GRU for local context, and the explicit attention over *all* items for global context, leading to more robust recommendations that are less susceptible to noise or short-term distractions in the session.

🔑 Key Property

The global attention mechanism uses the last item embedding \(x_L\) as its query, while the local attention mechanism uses the final GRU hidden state \(h_L\) as its query. Both attend over the sequence of item embeddings \(\{x_1, \dots, x_L\}\) to produce context vectors, which are then combined with \(h_L\) itself.

Why It Works — The Math
▼

1. GRU-based Session Encoding

Given a sequence of item embeddings \((x_1, x_2, \dots, x_L)\), the GRU computes hidden states \((h_1, h_2, \dots, h_L)\):

$$h_t = \text{GRU}(x_t, h_{t-1})$$

The final hidden state \(h_L\) summarizes the entire sequence up to the last item.

2. Dual Attention Mechanism

NARM computes two context vectors. Let \(X = [x_1, \dots, x_L]\) be the matrix of item embeddings in the session.

Global Attention: The query is the last item embedding \(x_L\). It computes attention scores \(\alpha_t\) for each item \(x_t\) in the session, then a weighted sum:

$$\alpha_t = \mathbf{v}_1^\top \text{tanh}(\mathbf{W}_1 x_t + \mathbf{U}_1 x_L) \\ c_{global} = \sum_{t=1}^L \text{softmax}(\alpha_t) \cdot x_t$$

Here, \(\mathbf{v}_1, \mathbf{W}_1, \mathbf{U}_1\) are learnable parameters. The softmax ensures weights sum to 1.

Local Attention: The query is the final GRU hidden state \(h_L\). It computes attention scores \(\beta_t\) for each item \(x_t\), then a weighted sum:

$$\beta_t = \mathbf{v}_2^\top \text{tanh}(\mathbf{W}_2 x_t + \mathbf{U}_2 h_L) \\ c_{local} = \sum_{t=1}^L \text{softmax}(\beta_t) \cdot x_t$$

Similarly, \(\mathbf{v}_2, \mathbf{W}_2, \mathbf{U}_2\) are learnable parameters.

3. Combined Session Representation and Prediction

The final session representation \(s_L\) combines the GRU's last hidden state \(h_L\), the global context \(c_{global}\), and the local context \(c_{local}\). The original NARM paper concatenates \(h_L\) with a combination of attention contexts. A common simplified form (as used in many implementations) concatenates them directly:

$$\hat{y}_j = \text{softmax}(s_L^\top \mathbf{E}_j)$$

Where \(\mathbf{E}_j\) is the embedding of item \(j\). The model is trained using cross-entropy loss against the true next item.

⚠️ Computational Cost

The attention mechanism requires computing scores for *every item* in the session for *every prediction*. For long sessions or very large item vocabularies, this can become computationally intensive. Efficient implementation of the item embedding lookup and attention calculation is crucial for scalability.

Key Takeaways
▼

When to use NARM:

  • Session-based recommendation: When user interactions are naturally grouped into short, distinct sessions (e.g., website visits, shopping carts).
  • Sequential patterns are important: When the order of items matters for predicting the next interaction.
  • Capturing evolving intent: When user preferences change within a session, and both overall session context and immediate intent are valuable.
  • Relatively short sessions: The attention mechanism's complexity scales with session length, making it more practical for shorter sequences.

When NOT to use:

  • Long-term preferences only: If you're only interested in static, long-term user preferences, simpler models might suffice or be more efficient.
  • Cold start problem: NARM relies heavily on item embeddings and session history; it struggles with new users or items without sufficient interaction data.
  • Extremely long sessions: The quadratic complexity of attention (or linear-with-length if implemented with tricks) can be prohibitive for sessions with hundreds or thousands of items.
  • Very large item vocabularies: The final prediction step involves scoring against all item embeddings, which can be slow for millions of items without sampling or approximation.
💡 NARM's Strength

NARM's core innovation is its ability to explicitly model two distinct aspects of user intent within a session: a global preference derived from the overall session context (using the last item as query) and a local preference reflecting the immediate next step (using the current GRU state as query). This dual focus leads to more nuanced and effective recommendations than models relying on a single summary vector.

Code Trace (Simplified PyTorch-like)
▼
import torch
import torch.nn as nn
class NARM(nn.Module):
def __init__(self, num_items, embed_dim, hidden_size):
super().__init__()
self.item_embedding = nn.Embedding(num_items, embed_dim)
self.gru = nn.GRU(embed_dim, hidden_size, batch_first=True)
# Global attention parameters
self.W1 = nn.Linear(embed_dim, hidden_size, bias=False)
self.U1 = nn.Linear(embed_dim, hidden_size, bias=False)
self.v1 = nn.Linear(hidden_size, 1, bias=False)
# Local attention parameters
self.W2 = nn.Linear(embed_dim, hidden_size, bias=False)
self.U2 = nn.Linear(hidden_size, hidden_size, bias=False)
self.v2 = nn.Linear(hidden_size, 1, bias=False)
# Combined session representation linear layer
self.Ws = nn.Linear(hidden_size * 3, hidden_size) # h_L, c_global, c_local
def forward(self, session_ids): # session_ids: (batch_size, seq_len)
item_embs = self.item_embedding(session_ids) # (batch_size, seq_len, embed_dim)
seq_len = item_embs.size(1)
# 1. GRU Session Encoding
gru_out, h_L = self.gru(item_embs) # gru_out: (bs, sl, hs), h_L: (1, bs, hs)
h_L = h_L.squeeze(0) # (batch_size, hidden_size)
# 2. Dual Attention Mechanism
# Global Attention (query = last item embedding)
last_item_emb = item_embs[:, -1, :] # (batch_size, embed_dim)
global_scores = self.v1(torch.tanh(self.W1(item_embs) + self.U1(last_item_emb).unsqueeze(1)))
global_weights = torch.softmax(global_scores, dim=1) # (batch_size, seq_len, 1)
c_global = torch.sum(global_weights * item_embs, dim=1) # (batch_size, embed_dim)
# Local Attention (query = final GRU hidden state)
local_scores = self.v2(torch.tanh(self.W2(item_embs) + self.U2(h_L).unsqueeze(1)))
local_weights = torch.softmax(local_scores, dim=1) # (batch_size, seq_len, 1)
c_local = torch.sum(local_weights * item_embs, dim=1) # (batch_size, embed_dim)
# 3. Combined Session Representation
combined_session_vec = torch.cat([h_L, c_global, c_local], dim=1)
s_L = torch.tanh(self.Ws(combined_session_vec)) # (batch_size, hidden_size)
# Prediction (dot product with all item embeddings)
all_item_embs = self.item_embedding.weight # (num_items, embed_dim)
scores = torch.matmul(s_L, all_item_embs.transpose(0, 1)) # (bs, num_items)
return scores
