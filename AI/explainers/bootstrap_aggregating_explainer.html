Understanding Bootstrap Aggregating
▼

What is it? Bagging (Bootstrap Aggregating) is a technique for reducing the variance of a learning algorithm by training many copies of the model on different random subsamples of the training data, then averaging their predictions. Instead of trusting one potentially overfit model, you build a democracy of models that cancel each other's mistakes.

Analogy: Imagine you're forecasting tomorrow's weather. Instead of asking one expert meteorologist, you ask 50 meteorologists — each given a slightly different historical dataset (some data repeated, some omitted). You average their forecasts. The idiosyncratic quirks of each expert cancel out; what remains is a more stable, lower-variance prediction. Each individual model might be wiggly and overfitted; the average is smooth.

Why it helps: A single high-variance model (like an unpruned decision tree) memorizes noise in its training set — it varies dramatically with small data changes. The key insight is that if models are at least somewhat independent (low correlation \(\rho\)), averaging them dramatically reduces variance. The irreducible floor is \(\rho\sigma^2\) — correlation limits the gain.

💡 If you remember one thing

Bagging trains \(B\) models on bootstrap resamples and averages their outputs. Variance drops from \(\sigma^2\) (single model) toward the floor \(\rho\sigma^2 + (1-\rho)\frac{\sigma^2}{B}\), where \(\rho\) is the pairwise prediction correlation. Works best for high-variance, low-bias learners like unpruned trees.

How Bagging Works — Step by Step
▼

The Bootstrap Resample

Given training data \(\mathcal{D} = \{(x_1, y_1), \ldots, (x_n, y_n)\}\) of size \(n\), a bootstrap sample \(\mathcal{D}^{(b)}\) is drawn by sampling \(n\) points with replacement from \(\mathcal{D}\). On average, each bootstrap sample contains about \(63.2\%\) of unique original points (since the probability of any single point being excluded is \((1 - 1/n)^n \to e^{-1} \approx 0.368\)). The remaining \(\approx 36.8\%\) are the out-of-bag (OOB) points — free validation data!

The Bagging Algorithm

  1. For \(b = 1, \ldots, B\): draw bootstrap sample \(\mathcal{D}^{(b)}\) from \(\mathcal{D}\).
  2. Train a base learner \(\hat{f}^{(b)}\) on \(\mathcal{D}^{(b)}\).
  3. For regression: aggregate as average: \(\hat{f}_{bag}(x) = \frac{1}{B}\sum_{b=1}^{B}\hat{f}^{(b)}(x)\)
  4. For classification: aggregate by majority vote: \(\hat{y}_{bag}(x) = \text{mode}\{\hat{y}^{(b)}(x)\}_{b=1}^{B}\)
$$\hat{f}_{\text{bag}}(x) = \frac{1}{B}\sum_{b=1}^{B} \hat{f}^{(b)}(x)$$

Why Trees Are the Canonical Base Learner

Bagging works best for high-variance, low-bias learners. Unpruned decision trees fit training data exactly (zero training error), but vary wildly across different datasets — exactly the profile that benefits from averaging. Linear regression, by contrast, has low variance and little to gain from bagging.

🔑 Key Design Decision

Bootstrap resampling (vs. splitting data into B disjoint sets) is critical. Disjoint sets of size \(n/B\) would give each model only a fraction of the data, increasing bias. Bootstrap samples of size \(n\) keep each model's bias the same as training on the full set, while introducing the diversity needed for variance reduction.

Out-of-Bag Error — Free Cross-Validation

Since each point \((x_i, y_i)\) is excluded from roughly \(1/3\) of the bootstrap samples, we can predict on it using only those trees where it was OOB. Averaging these predictions gives the OOB error estimate — equivalent to leave-one-out cross-validation, at zero extra computational cost.

3
The Variance Decomposition — Why It Works
▼

Variance of an Average

Let \(\hat{f}^{(1)}, \ldots, \hat{f}^{(B)}\) be the predictions of \(B\) bagged models at a fixed test point \(x\). Assume each has variance \(\sigma^2\) and pairwise correlation \(\rho\) (the same \(\rho\) for all pairs — a simplifying assumption). The variance of the ensemble average is:

$$\text{Var}\!\left(\hat{f}_{\text{bag}}\right) = \text{Var}\!\left(\frac{1}{B}\sum_{b=1}^{B}\hat{f}^{(b)}\right) = \frac{1}{B^2}\left[B\sigma^2 + B(B-1)\rho\sigma^2\right]$$

Simplifying:

$$\text{Var}\!\left(\hat{f}_{\text{bag}}\right) = \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$$

This is the central formula. Two terms:

  • \(\rho\sigma^2\) — the irreducible floor: even with \(B \to \infty\), variance can't go below this. It's driven entirely by the correlation between trees.
  • \(\frac{(1-\rho)\sigma^2}{B}\) — the reducible term: goes to 0 as \(B \to \infty\).
$$\lim_{B \to \infty} \text{Var}\!\left(\hat{f}_{\text{bag}}\right) = \rho\sigma^2$$

Numerical Example

Say each tree has \(\sigma^2 = 1.0\). With \(\rho = 0.3\) (low correlation, achieved by random feature subsets in Random Forests):

  • \(B=1\): \(\text{Var} = 1.000\)
  • \(B=5\): \(\text{Var} = 0.3 + 0.7/5 = 0.440\)  (56% reduction)
  • \(B=25\): \(\text{Var} = 0.3 + 0.7/25 = 0.328\)  (67% reduction)
  • \(B \to \infty\): \(\text{Var} \to 0.300\)  (70% reduction floor)

With \(\rho = 0.9\) (high correlation, plain bagging of trees on same features):

  • \(B=25\): \(\text{Var} = 0.9 + 0.1/25 = 0.904\) — only 9.6% reduction. High correlation kills the gain.
⚠️ Critical Insight

Correlation \(\rho\) is the limiting factor. Adding more trees (larger \(B\)) only helps the \((1-\rho)/B\) term. The floor \(\rho\sigma^2\) is untouched. Random Forests explicitly reduce \(\rho\) by considering only a random subset of features at each split — turning bagging's moderate gain into a dramatic one.

Bias is Unchanged

Since each bootstrap sample has the same size \(n\) as the original dataset, the expected tree is essentially the same as if trained on \(\mathcal{D}\). Therefore \(\mathbb{E}[\hat{f}_{\text{bag}}(x)] \approx \mathbb{E}[\hat{f}^{(b)}(x)]\) — bagging does not reduce bias. It is a pure variance-reduction technique. Using a high-bias base learner (e.g., a stump) with bagging wastes computation: bias remains high, and variance was already low.

Implementation — From Scratch & Production
▼

From Scratch (NumPy + pure Python)

import numpy as np
from collections import Counter
class BaggingClassifier:
"""Bootstrap Aggregating for classification, from scratch."""
def __init__(self, base_learner_cls, B=100, **learner_kwargs):
self.base_learner_cls = base_learner_cls # e.g. DecisionTreeClassifier
self.B = B # number of bootstrap samples
self.learner_kwargs = learner_kwargs
self.models_ = []
self.oob_indices_ = [] # out-of-bag indices per tree
def fit(self, X, y):
n = len(X)
self.models_ = []
self.oob_indices_ = []
for b in range(self.B):
# Step 1: draw bootstrap sample (n points w/ replacement)
idx = np.random.choice(n, n, replace=True)
oob = np.setdiff1d(np.arange(n), idx) # ~36.8% excluded
X_b, y_b = X[idx], y[idx]
# Step 2: train base learner on this bootstrap sample
model = self.base_learner_cls(**self.learner_kwargs)
model.fit(X_b, y_b)
self.models_.append(model)
self.oob_indices_.append(oob)
return self
def predict(self, X):
# Step 3: majority vote across all B models
votes = np.array([m.predict(X) for m in self.models_]) # (B, n_test)
return np.apply_along_axis(
lambda col: Counter(col).most_common(1)[0][0], 0, votes
)
def oob_score(self, X, y):
"""Out-of-bag accuracy: free cross-validation estimate."""
n = len(X)
oob_preds = [[] for _ in range(n)]
for model, oob in zip(self.models_, self.oob_indices_):
if len(oob) == 0: continue
preds = model.predict(X[oob])
for i, p in zip(oob, preds):
oob_preds[i].append(p)
correct = sum(
Counter(oob_preds[i]).most_common(1)[0][0] == y[i]
for i in range(n) if oob_preds[i]
)
valid = sum(1 for i in range(n) if oob_preds[i])
return correct / valid

Production Usage (scikit-learn)

from sklearn.ensemble import BaggingClassifier, BaggingRegressor
from sklearn.tree import DecisionTreeClassifier
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
X, y = make_classification(n_samples=1000, n_features=20, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)
bag = BaggingClassifier(
estimator=DecisionTreeClassifier(max_depth=None), # unpruned: high variance
n_estimators=100, # B — more is better up to diminishing returns
max_samples=1.0, # fraction of training set per bootstrap (1.0 = n samples)
max_features=1.0, # fraction of features per tree (1.0 = all features)
bootstrap=True, # sample with replacement (False = pasting)
oob_score=True, # compute OOB accuracy for free
n_jobs=-1, # parallel training across all CPU cores
random_state=42,
)
bag.fit(X_train, y_train)
print(f"Test accuracy : {bag.score(X_test, y_test):.3f}")
print(f"OOB accuracy : {bag.oob_score_:.3f}") # free validation, no test leak
# ⚠️ Gotcha 1: oob_score=True requires bootstrap=True (needs held-out OOB set)
# ⚠️ Gotcha 2: BaggingClassifier is NOT the same as RandomForestClassifier.
# RandomForest reduces CORRELATION between trees by random feature subsets
# at each split — a crucial extra step that dramatically lowers the ρσ² floor.

Key Takeaways & When to Use Bagging
▼

When to use bagging:

  • Base learner has high variance and low bias (e.g., unpruned decision trees)
  • You want a free model validation estimate (OOB score)
  • Parallelizable training is important (each tree trains independently)
  • You have enough data that each bootstrap sample is representative

When NOT to use:

  • Base learner already has low variance (e.g., linear regression, shallow trees) — bias stays fixed, little variance gain
  • Data is too small — bootstrap samples won't be representative; high OOB pessimism bias
  • You need interpretability — an ensemble of 100 trees is not explainable
  • Boosting is more appropriate — if bias is the main problem, boosting beats bagging
🌲 Bagging → Random Forest

Random Forest = Bagging + random feature subsets at each split. The extra randomization reduces \(\rho\) from ~0.7–0.9 (plain bagging of trees) to ~0.3–0.5 (RF), pushing the variance floor down dramatically. RF is almost always preferred over plain bagging when using decision trees.

Related topics: Random Forests (extend bagging with feature subsampling), Boosting (sequential bias reduction vs. parallel variance reduction), Stacking (train a meta-learner to combine base model outputs), Bias-Variance Tradeoff (the fundamental tension bagging exploits).
