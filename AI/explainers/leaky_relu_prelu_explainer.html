Leaky ReLU & Parametric ReLU (PReLU)

Curing the dying-ReLU problem with a small — or learnable — negative-side slope
Intermediate Deep Learning Activation Functions O(1) per unit
1
Understanding the Concept
▼

What is it? A plain ReLU neuron, \(f(x)=\max(0,x)\), outputs exactly zero AND has exactly zero gradient for any negative input. If a neuron's inputs are negative across the whole training set, it stops learning forever — a "dead" neuron. Leaky ReLU and PReLU fix this by letting a small negative signal leak through instead of clamping to zero.

Analogy: Picture a one-way check valve on a pipe. Plain ReLU is a valve that slams fully shut the instant pressure reverses — a stuck valve stays stuck forever. Leaky ReLU is the same valve with a permanent hairline crack: a trickle always gets through, so it can never fully seize. PReLU is a smart valve that learns, from experience, exactly how wide that crack should be for each pipe (channel) in the system.

💡 If you remember one thing

Both variants replace ReLU's negative-side \(f(x)=0\) with \(f(x)=\alpha x\). Leaky ReLU fixes \(\alpha\) (e.g. 0.01); PReLU learns \(\alpha\) via backprop, one value per channel: $$f(x_i)=\max(0,x_i)+a_i\min(0,x_i)$$

How It Works Internally
▼

Forward Pass

For a pre-activation \(z=[-2.0,\ 3.0,\ -0.5,\ 1.5]\): plain ReLU gives \([0,\ 3.0,\ 0,\ 1.5]\) — both negatives clamp to 0. Leaky ReLU (\(\alpha=0.01\)) gives \([-0.02,\ 3.0,\ -0.005,\ 1.5]\). PReLU initialized at \(a_c=0.25\) (He et al.'s recommended init) gives \([-0.5,\ 3.0,\ -0.125,\ 1.5]\) — a much larger, data-adaptive leak.

Backward Pass — Where It Really Matters

With upstream gradient \(\partial L/\partial f = [0.8,\ -0.3,\ 0.6,\ -0.1]\): ReLU zeroes the gradient at both negative positions — \([0,\ -0.3,\ 0,\ -0.1]\) — those upstream weights get NO update from this path. Leaky ReLU passes \([0.008,\ -0.3,\ 0.006,\ -0.1]\): small but alive. PReLU passes \([0.2,\ -0.3,\ 0.15,\ -0.1]\): a much stronger signal, because \(a_c=0.25 \gg 0.01\).

The Extra Step Unique to PReLU

PReLU also back-propagates a gradient into \(a_c\) itself: $$\frac{\partial L}{\partial a_c}=\sum_{x_i<0}\frac{\partial L}{\partial f(x_i)}\cdot x_i = (0.8)(-2.0)+(0.6)(-0.5)=-1.9$$ A single SGD step with \(lr=0.1\) gives \(a_c \leftarrow 0.25-0.1(-1.9)=0.44\) — the channel just learned to leak more.

🔑 Design Decision: Why per-channel, not per-weight or global?

Per-weight would roughly double a layer's parameter count for little gain. A single global scalar has too little capacity — every filter shares one behavior. Per-channel (He et al.'s choice) costs only one extra float per channel yet lets each filter independently decide how "ReLU-like" vs. "linear-like" it should be.

3
Why It Works — The Math
▼

Unified Formulation

Both variants collapse into one compact expression:

$$f(x_i) = \max(0,x_i) + a_i\min(0,x_i)$$

which is plain ReLU when \(a_i=0\), Leaky ReLU when \(a_i=\alpha\) is fixed, and PReLU when \(a_i\) is a free trainable parameter.

Gradient Through the Unit

$$\frac{\partial f(x_i)}{\partial x_i}=\begin{cases}1 & x_i>0\\ a_i & x_i\leq 0\end{cases} \qquad \frac{\partial f(x_i)}{\partial a_i}=\min(0,x_i)$$

By the chain rule, the loss gradient w.r.t. the slope, summed over every position sharing that channel's parameter:

$$\frac{\partial E}{\partial a_i}=\sum_{x_i}\frac{\partial E}{\partial f(x_i)}\cdot\min(0,x_i)$$

Updated with momentum \(\mu\) and learning rate \(\varepsilon\), without weight decay:

$$\Delta a_i \leftarrow \mu\Delta a_i + \varepsilon\frac{\partial E}{\partial a_i}, \qquad a_i \leftarrow a_i + \Delta a_i$$
⚠️ Common Pitfall

L2 weight decay pulls every parameter toward 0 — for \(a_i\), that means toward plain ReLU, the very failure mode PReLU exists to avoid. He et al. deliberately exclude \(a_i\) from weight decay. Also: nothing constrains \(a_i \in [0,1]\) — it can in principle drift negative (non-monotonic) or above 1.

Key Takeaways
▼

When to use which:

  • Seeing dead filters and want a zero-parameter, zero-complexity fix → Leaky ReLU
  • Training a CNN from scratch and chasing top-line accuracy, can afford excluding a few params from weight decay → PReLU
  • Building a Transformer → neither; use GELU / Swish instead (smooth, non-monotonic near 0)
  • Tiny dataset, worried about overfitting the extra PReLU parameters → stick with fixed Leaky ReLU or plain ReLU + careful init
💡 The One Invariant

Both variants guarantee \(f'(x)\neq 0\) for every \(x\neq 0\). That is the entire mechanism by which they prevent permanently dead neurons — no matter how small or how learned the slope is, it is never exactly zero.

Code Trace
▼
import numpy as np
z = np.array([-2.0, 3.0, -0.5, 1.5])
upstream = np.array([0.8, -0.3, 0.6, -0.1]) # dL/df from next layer
# --- ReLU ---
relu_out = np.maximum(0, z) # [0, 3.0, 0, 1.5]
relu_grad = np.where(z > 0, 1.0, 0.0) # [0, 1, 0, 1] -> dead at negatives
# --- Leaky ReLU (alpha fixed) ---
alpha = 0.01
leaky_out = np.where(z > 0, z, alpha * z)
leaky_grad = np.where(z > 0, 1.0, alpha) # [0.01, 1, 0.01, 1] -> always alive
# --- PReLU (a_c learnable) ---
a_c = 0.25 # He et al. recommended init
prelu_out = np.maximum(0, z) + a_c * np.minimum(0, z)
prelu_grad = np.where(z > 0, 1.0, a_c)
# gradient into z through PReLU
dL_dz = upstream * prelu_grad
# gradient into the slope a_c itself (sum over negative positions)
d_ac = np.sum(upstream * np.minimum(0, z)) # -1.9
# SGD update (no weight decay on a_c!)
lr = 0.1
a_c = a_c - lr * d_ac # 0.25 -> 0.44
