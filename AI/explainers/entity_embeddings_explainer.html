Entity Embeddings for Deep Learning

Mapping categorical variables to learned dense vectors — geometry one-hot can never capture
Intermediate Feature Encoding Classical ML O(C·d) lookup
1
Understanding the Concept
▼

Imagine you're teaching a neural network about days of the week. You could give Monday the code [1,0,0,0,0,0,0], Tuesday [0,1,0,0,0,0,0], and so on. This is called one-hot encoding. But it has a problem: to the network, Monday and Tuesday are just as different as Monday and Sunday — there is no notion of "nearby" or "similar." And if you have 50,000 zip codes, each gets a vector of length 50,000. That's enormous.

Entity embeddings solve this by replacing each category with a short, dense vector of real numbers — say length 4 or 16 — and letting the neural network learn those numbers during training. By the end of training, days with similar sales patterns end up with similar vectors. Monday and Tuesday might be close together; weekends far from weekdays. The geometry of the embedding space captures real structure in the data.

💡 Analogy

Think of a star map. Instead of labeling each star "star #1", "star #2" (one-hot), we place each star at GPS coordinates (ra, dec, distance). Stars in the same constellation cluster together. Embeddings do the same for categories — they give each one a location in a learned semantic space.

Key Concept

An embedding table \(E \in \mathbb{R}^{C \times d}\) stores one row per category. Row lookup \(E[c]\) is the forward pass. The entries are free parameters trained jointly with the rest of the network via backpropagation.

If you remember one thing: one-hot says "each category is its own isolated island." Embeddings say "let the data teach us how close or far each island is from every other."

2
How It Works Internally
▼

Architecture

The embedding layer is the first building block when handling categorical data in a neural network. Given a categorical feature with \(C\) unique values and an embedding dimension \(d\):

$$E \in \mathbb{R}^{C \times d}, \quad \text{initialized randomly, e.g., } E_{c,j} \sim \mathcal{N}(0, 1)$$

For input category \(c \in \{0, 1, \ldots, C-1\}\), the forward pass is a single row lookup:

$$\mathbf{e}_c = E[c] \in \mathbb{R}^d$$

This is mathematically equivalent to a matrix multiplication with a one-hot vector \(\mathbf{o}_c\):

$$\mathbf{e}_c = \mathbf{o}_c^\top E, \quad \mathbf{o}_c \in \{0,1\}^C, \; \|\mathbf{o}_c\|_1 = 1$$

but implemented as an O(d) table lookup, not O(C·d) matrix multiply.

End-to-End Training

The embedding weights are ordinary parameters — they receive gradients via backpropagation from the task loss. If the model learns that "Monday" and "Tuesday" both precede high-order days, their rows in \(E\) get pushed closer in \(\mathbb{R}^d\). No manual feature engineering is needed. The geometry emerges from supervision.

⚠ Design Choice: Embedding Dimension d

A common heuristic is \(d \approx \lceil C^{0.25} \rceil\) or \(d = \min(50, \lfloor C/2 \rfloor)\). Too small: information loss. Too large: the model memorizes noise. Empirically, even \(d=4\) for days-of-week carries rich geometry.

Multi-Feature Concatenation

When a record has several categorical features (e.g., day-of-week, store ID, product category), each gets its own embedding table. The resulting vectors are concatenated before the MLP:

$$\mathbf{h} = [\mathbf{e}^{(1)};\; \mathbf{e}^{(2)};\; \ldots;\; \mathbf{e}^{(K)};\; \mathbf{x}_{cont}]$$

where \(\mathbf{x}_{cont}\) is the vector of continuous features.

3
The Math — Gradients & Geometry
▼

Gradient Flow Through the Embedding Table

Let \(L\) be the task loss and \(\mathbf{e}_c = E[c]\) the selected embedding. The gradient of \(L\) w.r.t. row \(c\) of \(E\) is:

$$\frac{\partial L}{\partial E[c]} = \frac{\partial L}{\partial \mathbf{e}_c}$$

Crucially, only row \(c\) receives a non-zero gradient for a given training example — all other rows get zero gradient. This is sparse gradient updates: efficient, but means rare categories update infrequently.

Cosine Similarity as a Geometry Probe

After training, the "closeness" of two categories \(a\) and \(b\) can be measured by:

$$\text{sim}(a, b) = \frac{\mathbf{e}_a \cdot \mathbf{e}_b}{\|\mathbf{e}_a\|_2 \; \|\mathbf{e}_b\|_2} \in [-1, 1]$$

Guo & Berkhahn (2016) showed that for a retail dataset, the learned store embeddings placed geographically nearby stores close together in \(\mathbb{R}^{10}\) — a property the model was never told about explicitly.

Euclidean Distance and Analogy

Word2Vec popularized vector arithmetic: king − man + woman ≈ queen. The same arithmetic works for entity embeddings:

$$E[\text{Friday}] - E[\text{Weekday}] + E[\text{Weekend}] \approx E[\text{Saturday}]$$
Key Formula

Full model with embedding: \(\hat{y} = f_\theta\bigl([E[c^{(1)}];\ldots;E[c^{(K)}];\mathbf{x}_{cont}]\bigr)\), where \(f_\theta\) is an MLP and all parameters (including \(E\)) are updated by \(\theta \leftarrow \theta - \eta \nabla_\theta L\).

⚠ Common Misconception

Entity embeddings are NOT the same as label encoding (mapping category → integer). Label encoding implies an ordinal relationship (e.g., Monday=1 < Tuesday=2). Embeddings make no such assumption — they learn whatever geometry the task demands.

From-Scratch Code Trace
▼

Each highlighted line corresponds to the current visualization step. Click through the steps above to follow along.

import numpy as np
import torch, torch.nn as nn
# ── Step 1: Define embedding table ──────────────────
C, d = 7, 4 # 7 days, 4-dim embedding
emb = nn.Embedding(num_embeddings=C, embedding_dim=d)
# Weights shape: (7, 4) — one row per day
# ── Step 2: Forward pass (lookup) ───────────────────
idx = torch.tensor([0]) # Monday = index 0
e_mon = emb(idx) # shape: (1, 4)
# ── Step 3: Combine with MLP ────────────────────────
mlp = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 1))
y_hat = mlp(e_mon) # final prediction
# ── Step 4: Backprop — only row 0 gets updated ─────
loss = nn.MSELoss()(y_hat, torch.tensor([[1.2]]))
loss.backward()
# emb.weight.grad[0] != 0 ; emb.weight.grad[1:] == 0
# ── Step 5: After training — inspect geometry ───────
W = emb.weight.detach().numpy() # (7, 4) learned table
from numpy.linalg import norm
sim = W @ W[0] / (norm(W, axis=1) * norm(W[0]))
# sim[1] high → Tue similar to Mon in learned space

When to use Entity Embeddings

Use when: (1) a categorical feature has > ~10 unique values, (2) you're training a deep neural network, (3) you suspect categories have latent structure (days cluster as weekdays/weekends, stores cluster by region). Avoid for binary or 3-class features — one-hot is sufficient there.

Key papers: Guo & Berkhahn, "Entity Embeddings of Categorical Variables" (arXiv 2016) — first systematic study on tabular data; Cheng et al., "Wide & Deep Learning for Recommender Systems" (RecSys 2016) — embeddings + linear model; He et al., NCF (WWW 2017) — neural CF with item/user embeddings.
