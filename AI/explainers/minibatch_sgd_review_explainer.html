Mini-batch SGD: Batch Size Trade-offs

The practical middle ground between full-batch gradient descent and pure SGD — where noise, speed, and hardware efficiency collide.

Foundational Optimization Training Dynamics Must Know
1
Understanding the Concept
▼

Training a neural network means repeatedly asking: "How should I nudge every parameter to make the model less wrong?" The answer comes from the gradient of the loss. But computing that gradient exactly requires scanning your entire dataset — which could be millions of images. That's expensive.

There are three strategies, arranged by how many examples you look at per update:

  • Full-Batch Gradient Descent (GD): use all N examples to estimate the gradient exactly. Slow per step; perfectly smooth path to the minimum.
  • Stochastic Gradient Descent (SGD, B=1): use one random example per step. Very fast iterations but extremely noisy gradient estimates — the path bounces all over.
  • Mini-batch SGD (B = 32 … 512): use a random subset of B examples. This is the practical sweet spot used in almost every real-world deep learning training run.
💡 If You Remember One Thing

Mini-batch SGD is the universal default because it reduces gradient variance by a factor of \(B\) compared to pure SGD, while keeping each update far cheaper than full-batch GD. The noise that remains is not only tolerable — it often helps generalization.

Analogy: Imagine you're a chef trying to perfect a recipe. Full-batch GD = taste every dish before adjusting (perfect info, parallelism waste). Pure SGD = adjust after every single bite (reactive and jerky). Mini-batch = taste a random table of 32 dishes and adjust — fast, good signal, still affordable.

2
How It Works Internally
▼

At each training step, mini-batch SGD performs three actions:

  1. Sample a random mini-batch \(\mathcal{B} = \{(x_1,y_1),\ldots,(x_B,y_B)\}\) uniformly from the training set.
  2. Compute the mini-batch gradient: the average loss gradient over those \(B\) examples.
  3. Update parameters by stepping in the negative gradient direction, scaled by learning rate \(\eta\).
$$\theta_{t+1} = \theta_t - \eta \cdot \frac{1}{B} \sum_{i \in \mathcal{B}} \nabla_\theta \ell(f_\theta(x_i), y_i)$$

Why the Gradient is Unbiased

The mini-batch gradient is an unbiased estimator of the true gradient:

$$\mathbb{E}_{\mathcal{B}}\!\left[\frac{1}{B}\sum_{i \in \mathcal{B}} \nabla \ell_i\right] = \frac{1}{N}\sum_{i=1}^N \nabla \ell_i = \nabla L(\theta)$$

Each random mini-batch points on average in the correct direction. The stochasticity is pure variance, not bias — which is why convergence is still guaranteed (under standard conditions).

The Variance and Why It Scales as 1/B

Let \(\sigma^2\) be the per-sample gradient variance. Averaging over \(B\) i.i.d. samples reduces variance by \(B\) (standard statistics):

$$\operatorname{Var}\!\left[\hat{g}_{\mathcal{B}}\right] = \frac{\sigma^2}{B}$$

At \(B=1\) you get pure noise \(\sigma^2\). At \(B=N\) you get zero variance (full gradient). Mini-batch gives you the \(1/\!\sqrt{B}\) noise-reduction of averaging without paying the cost of the full dataset.

Key Invariant

The gradient estimator is unbiased for any \(B\). The only thing \(B\) controls is the variance of that estimate. Larger batch = lower variance = smoother path = potentially larger safe learning rate.

Numerical Trace (B=4, loss = MSE on a mini-batch)

Suppose \(\theta = 2.0\), true gradient \(= 4.0\), per-sample gradients \([3.8, 4.2, 3.9, 4.1]\):

  • Mini-batch mean: \(\hat{g} = (3.8+4.2+3.9+4.1)/4 = 4.0\) → exact this time
  • Update: \(\theta \leftarrow 2.0 - 0.1 \times 4.0 = 1.6\)
  • Per-sample variance: \(\approx 0.025\)   →   \(\operatorname{Var}[\hat{g}] = 0.025/4 = 0.00625\)
⚠ Common Confusion

People say "SGD is noisy and GD is stable." True — but some noise helps. The noise from small batches acts as implicit regularization, allowing the optimizer to escape sharp minima and find flatter, more generalizable ones (Keskar et al., 2017).

3
The Math: Variance ∝ 1/B
▼

Let the true loss be \(L(\theta) = \frac{1}{N}\sum_{i=1}^N \ell_i(\theta)\). Denote the per-sample gradients \(g_i = \nabla_\theta \ell_i(\theta)\) and define:

  • True gradient: \(\mu = \frac{1}{N}\sum_{i=1}^N g_i\)
  • Per-sample variance: \(\sigma^2 = \frac{1}{N}\sum_{i=1}^N \|g_i - \mu\|^2\)

A mini-batch of size \(B\) drawn uniformly without replacement gives the estimator:

$$\hat{g}_{\mathcal{B}} = \frac{1}{B}\sum_{i \in \mathcal{B}} g_i$$

Bias and Variance

Bias: \(\mathbb{E}[\hat{g}_{\mathcal{B}}] = \mu\) (zero bias — see Card 2).

Variance of the estimator (sampling without replacement from a finite population):

$$\operatorname{Var}[\hat{g}_{\mathcal{B}}] = \frac{\sigma^2}{B} \cdot \left(1 - \frac{B}{N}\right)$$

For large \(N \gg B\), the finite-population correction \((1 - B/N) \approx 1\), so the dominant term is simply \(\sigma^2/B\). This is the key formula:

$$\operatorname{Var}[\hat{g}_{\mathcal{B}}] \approx \frac{\sigma^2}{B} \qquad (B \ll N)$$
Gradient Noise Scales as \(1/\!\sqrt{B}\)

The standard deviation (noise magnitude) of the gradient estimate is \(\sigma/\!\sqrt{B}\). Doubling the batch size halves the gradient noise in standard deviation terms. This is exactly the same relationship as the standard error of the mean.

Convergence Rate

For a convex loss with Lipschitz-smooth gradient (constant \(L\)), SGD with batch size \(B\) and step size \(\eta = \mathcal{O}(1/\!\sqrt{T})\) converges after \(T\) steps as:

$$\mathbb{E}[L(\theta_T)] - L^* \leq \mathcal{O}\!\left(\frac{\sigma}{\sqrt{BT}}\right)$$

Increasing \(B\) by factor \(k\) keeps the same convergence bound with \(T/k\) iterations (i.e., \(k\times\) fewer passes through data), provided the learning rate is scaled appropriately.

The Linear Scaling Rule

Goyal et al. (2017) showed empirically that for large-batch training:

$$\eta_{\text{large}} = \eta_{\text{base}} \times \frac{B_{\text{large}}}{B_{\text{base}}}$$

This "linear scaling rule" keeps the effective update magnitude constant as batch size grows. For very large batches a warmup schedule is needed as abrupt large learning rates destabilize early training.

⚠ Large Batch Generalization Gap

Very large batches (B > ~8192 for ImageNet) often find sharper minima and generalize worse than small-batch training, even at matched training loss. The noise from small batches acts as implicit regularization. This is the "generalization gap" and is an active research area.

Hardware Efficiency & LR Scaling
▼

Hardware efficiency is just as important as statistical efficiency. Modern GPUs/TPUs are massively parallel: they process a batch of B examples at nearly the same wall-clock time as a single example, up to a saturation point.

Throughput vs. Batch Size

  • B=1 (pure SGD): near-zero GPU utilization. The forward pass of one sample uses <1% of CUDA cores. Most hardware cycles wasted.
  • B=32–256: GPU utilization climbs sharply. Memory bandwidth and compute are both exercised. Throughput (samples/second) rises nearly linearly with B in this range.
  • B>1024: GPU memory saturates. Throughput plateaus or grows sub-linearly. You're now paying for memory bandwidth, not compute.
💡 The Practical Sweet Spot

For most convolutional and transformer models, B = 32–512 saturates GPU compute while keeping per-sample noise low enough for stable training. The exact optimum depends on model size, GPU memory, and dataset size.

Learning Rate Scaling Options

RuleFormulaWorks when
Linear scaling (Goyal 2017)\(\eta \propto B\)Large B, same #epochs, ResNet-style
Square-root scaling\(\eta \propto \sqrt{B}\)Convex loss, constant #steps
No scaling\(\eta = \text{const}\)Small batches (B<64) where noise dominates

In practice, most practitioners start with the linear rule plus a warmup of 5–10 epochs, then monitor validation loss curves to decide if further adjustment is needed.

Gradient Accumulation (for large effective B)

When GPU VRAM is limited, you can simulate a larger effective batch by accumulating gradients over \(k\) forward passes before each parameter update. Effective batch size = \(k \times B_{\text{per\,step}}\). This is mathematically identical to using the larger batch (since gradient averages commute with addition).

Decision Rule

Start with B = 256 (or the largest power-of-2 that fits GPU memory). If training is unstable, halve B and halve \(\eta\) (or use \(\eta \propto \sqrt{B}\) scaling). If training is slow and stable, double B and apply linear scaling rule. Always monitor validation performance, not just training loss.

  • Mini-batch SGD is the de facto standard optimizer substrate for deep learning
  • Variance \(\propto 1/B\) means doubling batch halves gradient noise (std dev halved by \(\sqrt{2}\))
  • Hardware efficiency plateaus: sweet spot is usually B = 32–512
  • Large-batch training requires careful LR scaling + warmup to avoid generalization gap
  • The noise from small batches is a feature, not a bug — it provides implicit regularization
