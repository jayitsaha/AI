Scalable Hierarchical Clustering (CF-Tree) · Density-Based Reachability Ordering

1
Understanding the Algorithms

BIRCH — Balanced Iterative Reducing & Clustering using Hierarchies

Imagine a census bureau counting households in a city. Instead of listing every individual, they keep a compact summary per block (count, address centroid, spread). BIRCH does exactly this: it builds a CF-Tree (Clustering Feature Tree) in a single linear pass over data. Each leaf holds a Clustering Feature (CF) triple — (N, LS, SS) — from which means and variances can be reconstructed without storing raw points.

Key insight — BIRCH
A clustering feature \((N, \mathbf{LS}, SS)\) is a sufficient statistic for a spherical micro-cluster: centroid = \(\mathbf{LS}/N\), radius² = \(SS/N - \|\mathbf{LS}/N\|^2\).

OPTICS — Ordering Points To Identify the Clustering Structure

Think of hiking a hilly landscape and recording your altitude along a path chosen to always descend as little as possible. OPTICS produces an ordered list of points with reachability distances — a 1-D plot whose valleys reveal clusters. Unlike DBSCAN (fixed \(\varepsilon\)), OPTICS exposes the multi-density structure in one shot.

Key insight — OPTICS
The reachability plot (reachability distance vs. order index) encodes the full cluster hierarchy: each valley = one dense cluster; deeper valley = denser cluster.
One-sentence summary
BIRCH: build a CF-Tree of micro-clusters in one pass → apply any flat clustering (e.g., k-means) to the tree leaves.
OPTICS: order all points by reachability distance → read off clusters as valleys in the reachability plot, no fixed \(\varepsilon\) needed.

How They Work Internally

BIRCH — CF-Tree construction

  • Clustering Feature (CF): For a set of \(N\) points \(\{x_i\}\):
    $$CF = \Bigl(N,\;\mathbf{LS}=\sum_{i=1}^N x_i,\;SS=\sum_{i=1}^N \|x_i\|^2\Bigr)$$
    CFs are additive: \(CF_1 + CF_2 = (N_1+N_2,\;\mathbf{LS}_1+\mathbf{LS}_2,\;SS_1+SS_2)\).
  • Tree structure: B-tree–like. Each non-leaf node stores CFs of its children; each leaf stores micro-cluster CFs.
  • Insertion: New point \(x\) → find closest leaf CF → if adding \(x\) keeps radius ≤ \(T\) (threshold), absorb it; else create new leaf (split if full).
  • Phase 2: Optional re-scan to remove outliers. Phase 3: Run global clustering (k-means) on leaf CFs. Phase 4 (optional): reassign raw points.
Centroid & Radius from CF
\(\bar{x} = \mathbf{LS}/N\)
$$R = \sqrt{\frac{SS}{N} - \left\|\frac{\mathbf{LS}}{N}\right\|^2}$$

OPTICS — Reachability ordering

Two key distances (MinPts = minimum neighborhood size):

  • Core distance of \(p\): distance to its MinPts-th nearest neighbor (or undefined if \(|N_\varepsilon(p)| < \text{MinPts}\)):
    $$\text{core-dist}(p) = d_{(MinPts)}(p)$$
  • Reachability distance of \(q\) w.r.t. \(p\):
    $$\text{reach-dist}(q, p) = \max\bigl(\text{core-dist}(p),\; d(p,q)\bigr)$$

Algorithm (BFS-like with priority queue):

  1. Start with any unvisited point \(p\); mark visited; add \(N_\varepsilon(p)\) to priority queue ordered by reachability-dist.
  2. Pop smallest-reachability point \(q\); emit \((q, \text{reach-dist}(q))\) to ordered list.
  3. If \(q\) is a core point, update priority queue for \(q\)'s unvisited neighbors.
  4. Repeat until queue empty; restart with next unvisited point (new "valley" = new cluster).
Common confusion
OPTICS does not output cluster labels directly — you extract clusters from the reachability plot using a cut threshold \(\xi\) (steep drops) or a fixed \(\varepsilon'\).
3
Mathematical Properties

BIRCH — Complexity

  • Time: \(O(n)\) single-pass tree build (each insertion \(O(\log B \cdot d)\), \(B\) = branching factor). Global k-means on \(L\) leaves: \(O(L \cdot k \cdot d \cdot \text{iter})\), \(L \ll n\).
  • Memory: CF-Tree fits in RAM even when \(n\) doesn't. Tree rebuilds with larger \(T\) if memory exceeded.
  • Diameter-based threshold: Alternatively use diameter \(D = \sqrt{2 \cdot SS/N - 2\|\mathbf{LS}/N\|^2}\) instead of radius.
BIRCH Intra-cluster distance measures
Radius: \(R = \sqrt{SS/N - \|\mathbf{LS}/N\|^2}\)
Diameter: \(D = \sqrt{2SS/N - 2\|\mathbf{LS}/N\|^2} = R\sqrt{2}\)
Average inter-cluster dist (used for merging):
\(D_0 = \sqrt{\frac{\|\mathbf{LS}_1/N_1 - \mathbf{LS}_2/N_2\|^2}{1}}\)

OPTICS — Complexity

  • Time: \(O(n^2)\) naive; \(O(n \log n)\) with spatial index (k-d tree / ball tree) for \(\varepsilon\)-neighborhood queries.
  • Correctness guarantee: OPTICS is a superset of DBSCAN — for any \(\varepsilon' \leq \varepsilon_{\text{max}}\), applying a horizontal cut at \(\varepsilon'\) yields the same clusters as DBSCAN(\(\varepsilon'\), MinPts).
  • MinPts effect: Larger MinPts → smoother reachability plot, merges adjacent small clusters.
Cluster extraction (ξ-method)
A cluster starts at a steep downward "step": \(\frac{\text{reach}[i-1] - \text{reach}[i]}{\text{reach}[i-1]} \geq \xi\)
A cluster ends at a steep upward step (or end of ordering).
Typical \(\xi \in [0.01, 0.1]\).

Decision Rule
Use BIRCH when: data is too large for RAM, clusters are roughly spherical, you need a fast single-pass algorithm, or you'll apply k-means afterwards.

Use OPTICS when: clusters have wildly different densities, you want to explore structure before committing to \(\varepsilon\), or you need a principled noise label.
Common pitfalls
BIRCH: Threshold \(T\) controls granularity — too large merges distinct clusters into one CF entry; too small creates a huge tree. Assumes spherical micro-clusters; fails on elongated shapes.
OPTICS: MinPts controls smoothness but cluster extraction still needs \(\xi\) or \(\varepsilon'\). In very high dimensions, all distances become similar (curse of dimensionality) → reachability plot flattens.

Key Takeaways
  • BIRCH: \((N, \mathbf{LS}, SS)\) CF triples are sufficient statistics — additive, constant-memory summaries enabling scalable clustering.
  • OPTICS: Reachability distance \(= \max(\text{core-dist}(p), d(p,q))\) — generalises DBSCAN to all density thresholds simultaneously.
  • BIRCH → scalability. OPTICS → density robustness. Neither replaces the other.
  • In practice: use BIRCH as a pre-processing step to reduce \(n\), then apply OPTICS on the leaf centroids for density-aware final clustering.
Interview must-know
Q: "How is OPTICS different from DBSCAN?" → OPTICS produces a complete ordered list encoding cluster structure at all \(\varepsilon' \leq \varepsilon_{\max}\); DBSCAN outputs labels for a single \(\varepsilon\). OPTICS strictly subsumes DBSCAN.

Q: "Why can BIRCH scale to millions of points?" → The CF-Tree stores only summary statistics \((N, \mathbf{LS}, SS)\) per micro-cluster, not raw points. Memory is proportional to the number of micro-clusters (\(L\)), not \(n\).
