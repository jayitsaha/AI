Fully Convolutional Network (FCN)

Replacing Fully Connected layers with Convolutional layers for arbitrary input sizes
Foundational Deep Learning Computer Vision Architecture
1
Understanding FCNs
▼

What is it? A Fully Convolutional Network (FCN) is a type of neural network where all layers are convolutional layers (including pooling and upsampling layers), and crucially, there are no fully connected (FC) layers. This architecture allows FCNs to take input images of arbitrary size and produce an output map of corresponding spatial dimensions, making them ideal for tasks like semantic segmentation where each pixel needs a class prediction.

Analogy: Imagine you have a magnifying glass that can only focus on a fixed-size area of a photograph. A traditional CNN with FC layers is like that: it needs to crop or resize every photo to a specific size before it can analyze it. An FCN, however, is like a special magnifying glass that can adapt its focus and coverage to any size of photo, allowing you to examine the entire image, pixel by pixel, no matter how large or small, without distortion or loss of context.

💡 If you remember one thing

FCNs replace traditional fully connected (FC) classification layers with 1x1 convolutional layers. This seemingly simple trick transforms a fixed-input-size classifier into a network capable of dense, pixel-wise prediction on images of arbitrary spatial dimensions.

2
How FCNs Work Internally
▼

The Problem with Traditional CNNs

Most early successful CNNs (like AlexNet, VGG, ResNet) for image classification ended with one or more fully connected (FC) layers. These layers take a fixed-size input vector (e.g., a flattened feature map) and produce a fixed-size output vector (e.g., class scores). This means the entire network, from input to output, requires a fixed input image size (e.g., 224x224 pixels). If you want to process a larger image, you have to crop or resize it, losing information or distorting scale.

The FCN Solution: Convolutionalizing FC Layers

The core idea of an FCN (Long et al., 2015) is that a fully connected layer can be reinterpreted as a convolutional layer. Specifically, an FC layer that connects a \(H \times W \times C\) feature map (after flattening) to \(K\) output neurons is mathematically equivalent to a \(1 \times 1\) convolutional layer with \(C\) input channels, \(K\) output channels, and a kernel size of \(H \times W\). This "convolutionalization" allows the network to maintain spatial information throughout, even in the "classification" part.

When FC layers are replaced by convolutional layers, the network becomes "fully convolutional." This means it can accept any input image size. A larger input image will simply result in a larger output feature map at the end of the convolutionalized classification layers.

Dense Prediction via Upsampling

For tasks like semantic segmentation, we need a prediction for every pixel. The output of the convolutionalized network is typically a much smaller feature map (e.g., 1/32nd the size of the input image) with many channels (e.g., 21 classes). To get a pixel-wise prediction, this coarse output needs to be upsampled back to the original input resolution. This is achieved using:

  • Transposed convolutions (Deconvolutions): These are learnable upsampling layers that effectively reverse the downsampling operations of pooling layers.
  • Bilinear interpolation: A simpler, non-learnable upsampling method.
  • "Skip connections": FCNs often combine (via summation or concatenation) coarse, deep layer outputs with finer, shallower layer outputs to capture both semantic information and precise localization.
🔑 Key Property

The core insight is that convolutional layers are inherently translation-equivariant. By removing FC layers, an FCN leverages this property to produce an output map where each "pixel" in the output corresponds to a receptive field in the input, irrespective of the input image's overall dimensions.

3
Why It Works — The Math
▼

FC Layer as a Convolution

Consider a fully connected layer with \(I\) input neurons and \(O\) output neurons. Its operation is: \(y = Wx + b\), where \(W\) is an \(O \times I\) weight matrix and \(x\) is an \(I \times 1\) input vector. If \(x\) comes from flattening a feature map of size \(h \times w \times c\), then \(I = h \cdot w \cdot c\).

This can be re-expressed as a convolutional layer. Imagine the input feature map as a tensor of shape \((1, h, w, c)\). An FC layer mapping this to \(O\) output neurons can be seen as a convolutional layer with:

  • Input channels: \(c\)
  • Output channels: \(O\)
  • Kernel size: \((h, w)\)
  • Stride: \((1, 1)\) (or \((h, w)\) if you want a \(1 \times 1\) output)
  • Padding: \((0, 0)\)

If the kernel size is set to the exact spatial dimensions of the input feature map \((h, w)\), and the stride is \((1, 1)\), the output feature map will have dimensions \((1, 1, O)\). This is precisely what an FC layer does: it reduces a spatial input to a single spatial location, but with \(O\) channels (the output neurons).

$$ \text{FC}(x) = Wx + b $$ $$ \text{where } x \in \mathbb{R}^{h \cdot w \cdot c}, W \in \mathbb{R}^{O \times (h \cdot w \cdot c)} $$ $$ \text{is equivalent to } \text{Conv}(x', \text{kernel_size}=(h,w), \text{in_channels}=c, \text{out_channels}=O) $$ $$ \text{where } x' \in \mathbb{R}^{1 \times h \times w \times c} $$

The weights of the FC layer \(W\) are simply reshaped into the convolutional kernel. For example, if the last conv layer outputs a \(7 \times 7 \times 512\) feature map, an FC layer connecting it to 4096 neurons can be replaced by a convolutional layer with \(512\) input channels, \(4096\) output channels, and a \(7 \times 7\) kernel. This layer will produce a \(1 \times 1 \times 4096\) feature map.

Upsampling with Transposed Convolutions

Transposed convolutions (often called "deconvolutions" or "fractionally-strided convolutions") perform the reverse operation of a convolution, mapping a small input feature map to a larger output feature map. For an input feature map of size \((H_{in}, W_{in})\), a transposed convolution with kernel size \(K\), stride \(S\), and padding \(P\) produces an output of size \((H_{out}, W_{out})\):

$$ H_{out} = (H_{in} - 1)S - 2P + K $$ $$ W_{out} = (W_{in} - 1)S - 2P + K $$

For example, a transposed convolution with \(K=4, S=2, P=1\) will double the spatial dimensions of the input. This allows the FCN to upsample its coarse predictions to the original image resolution for pixel-wise segmentation.

⚠️ Common Misconception

"Deconvolution" is a misnomer. Transposed convolution is not the inverse of convolution in the mathematical sense. It's a learnable upsampling operation that uses convolution-like kernels, but it doesn't recover the exact input of a prior convolution. This can sometimes lead to artifacts like "checkerboard patterns" in the output if not designed carefully.

Key Takeaways
▼

When to use FCNs:

  • Semantic Segmentation: The primary use case, where every pixel needs to be classified (e.g., identifying objects, background, sky in an image).
  • Arbitrary Input Sizes: When your dataset contains images of varying resolutions, or you need to process very large images without resizing.
  • Dense Prediction Tasks: Any task that requires an output with spatial dimensions corresponding to the input, such as depth estimation, super-resolution, or image-to-image translation.
  • Foundation for Advanced Architectures: FCNs laid the groundwork for many modern segmentation models like U-Net, DeepLab, and Mask R-CNN.

When NOT to use:

  • Simple Image Classification: For tasks that only need a single class label per image, traditional CNNs with FC layers are often simpler and sufficient.
  • Very Small, Fixed-Size Images: If all your inputs are already a uniform, small size, the benefits of FCNs (arbitrary input) are less critical.
  • Computational Cost Concerns: Upsampling can be computationally intensive, especially for very high-resolution outputs.
💡 Hierarchy

FCNs represent a fundamental shift from image-level classification to pixel-level understanding. They are the direct ancestors of encoder-decoder architectures (like U-Net) and dilated convolution networks (like DeepLab), all of which build upon the principle of preserving and recovering spatial information for dense prediction.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
# --- 1. Traditional CNN with FC layers (fixed input size) ---
class ClassicCNN(nn.Module):
def __init__(self, num_classes=10):
super().__init__()
self.features = nn.Sequential(
nn.Conv2d(3, 16, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2, 2), # Output: H/2 x W/2 x 16
nn.Conv2d(16, 32, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2, 2), # Output: H/4 x W/4 x 32
nn.Conv2d(32, 64, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2, 2) # Output: H/8 x W/8 x 64
)
# Assuming 224x224 input -> 28x28x64 feature map
self.classifier = nn.Sequential(
nn.Linear(28 * 28 * 64, 1024), nn.ReLU(), # FC layer 1
nn.Linear(1024, num_classes) # FC layer 2
)
def forward(self, x):
x = self.features(x)
x = torch.flatten(x, 1) # Flatten for FC layers
x = self.classifier(x)
return x
# --- 2. FCN: Replacing FC layers with Conv layers ---
class FCN(nn.Module):
def __init__(self, num_classes=21): # For segmentation, often more classes
super().__init__()
self.features = nn.Sequential(
nn.Conv2d(3, 16, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2, 2),
nn.Conv2d(16, 32, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2, 2),
nn.Conv2d(32, 64, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2, 2)
)
# Replace FC layers with Conv2d layers (1x1 kernel for "classification")
self.classifier_conv = nn.Sequential(
nn.Conv2d(64, 1024, kernel_size=1), nn.ReLU(), # FC1 as 1x1 conv
nn.Conv2d(1024, num_classes, kernel_size=1) # FC2 as 1x1 conv (output for each pixel)
)
# Upsampling layer for dense prediction
# Example: if downsampling factor is 8, upsample by 8 (e.g., ConvTranspose with stride 8)
self.upsample = nn.ConvTranspose2d(num_classes, num_classes, kernel_size=16, stride=8, padding=4)
def forward(self, x):
x_features = self.features(x) # Output: H/8 x W/8 x 64
x_scores = self.classifier_conv(x_features) # Output: H/8 x W/8 x num_classes
# Upsample to original input size (or desired output size)
output = self.upsample(x_scores)
return output
