Understanding Gradient Descent
▼

What is it? Gradient descent is the workhorse algorithm for minimizing a function \(f(\theta)\) — finding the parameter values \(\theta\) where \(f\) is smallest. Every deep learning optimizer at its core is a variant of this single idea.

Analogy: Imagine you are blindfolded on a hilly terrain and want to reach the valley floor. You can only feel the slope under your feet (the gradient). At each step you move in the direction that goes downhill — opposite the steepest ascent. The step size \(\eta\) (learning rate) controls how far you stride. Too small: you shuffle slowly but safely. Too large: you overshoot, bouncing up the other side and possibly ending up higher than you started. Just right: you converge efficiently to the bottom.

If you remember one thing

The update rule is $$\theta_{k+1} = \theta_k - \eta \nabla f(\theta_k)$$ where \(\eta > 0\) is the learning rate (step size) and \(\nabla f(\theta_k)\) is the gradient at the current point. Subtract the gradient to go downhill. Everything else in optimization is a refinement of this idea.

Why This Exists — Historical Context
▼

Origins

Gradient descent was introduced by Augustin-Louis Cauchy in 1847 ("Méthode générale pour la résolution des systèmes d'équations simultanées") and later popularized for machine learning by Robbins & Monro (1951) with stochastic variants. The modern backpropagation + gradient descent combo was codified by Rumelhart, Hinton & Williams (1986), enabling neural network training at scale.

The Problem It Solves

In ML we need to minimize a loss \(f(\theta)\) — a function that can have millions of parameters. Closed-form solutions (like the OLS normal equations) require matrix inversions that are \(\mathcal{O}(n^3)\) and don't apply to nonlinear models. Gradient descent side-steps this by using only first-order information (gradients) in a local update, making it applicable to arbitrarily complex, nonlinear losses.

Key paper

Cauchy (1847). Comptes rendus — first formulation of steepest descent. Rumelhart, Hinton, Williams (1986). "Learning representations by back-propagating errors," Nature — married GD with backprop to train neural nets. Robbins & Monro (1951). "A stochastic approximation method" — introduced stochastic variant (SGD).

Evolution Timeline

Cauchy GD (1847) → SGD / Robbins-Monro (1951) → Backprop+GD for NNs (1986) → Momentum / Nesterov (1983/1983) → RMSProp (Hinton, 2012) → Adam (Kingma & Ba, 2014) → Lion, Sophia, … (2023+).

Why It Works — The Math
▼

The Update Rule

Given a differentiable objective \(f:\mathbb{R}^d \to \mathbb{R}\), gradient descent iterates:

$$\theta_{k+1} = \theta_k - \eta \,\nabla f(\theta_k)$$

where \(\eta > 0\) is the learning rate (step size) and \(\nabla f(\theta_k) \in \mathbb{R}^d\) is the gradient at the current iterate.

Why the negative gradient?

By the first-order Taylor expansion, for small \(\eta\):

$$f(\theta_k - \eta \nabla f) \approx f(\theta_k) - \eta \|\nabla f(\theta_k)\|^2 \;\leq\; f(\theta_k)$$

so each step strictly decreases \(f\) (provided \(\|\nabla f\| \neq 0\) and \(\eta\) is small enough). The negative gradient is the direction of steepest descent in Euclidean space.

Step-Size Regimes (L-smooth functions)

For an \(L\)-smooth function (\(\|\nabla f(x) - \nabla f(y)\| \leq L\|x-y\|\)), the descent lemma gives:

$$f(\theta_{k+1}) \leq f(\theta_k) - \eta\!\left(1 - \frac{\eta L}{2}\right)\|\nabla f(\theta_k)\|^2$$
  • Too small (\(\eta \ll 1/L\)): RHS decreases but very slowly. Many iterations to converge.
  • Too large (\(\eta > 2/L\)): The quadratic term dominates; \(f\) increases — divergence.
  • Goldilocks (\(\eta \leq 1/L\)): Guaranteed decrease each step. Optimal: \(\eta^* = 2/(\mu + L)\).

Convergence Rates

Convergence guarantees

Convex, \(L\)-smooth: \(\displaystyle f(\theta_k) - f^* \leq \frac{L\|\theta_0 - \theta^*\|^2}{2k}\) — rate \(\mathcal{O}(1/k)\).
\(\mu\)-strongly convex, \(L\)-smooth: \(\displaystyle \|\theta_k - \theta^*\|^2 \leq \left(1 - \frac{\mu}{L}\right)^k \|\theta_0 - \theta^*\|^2\) — linear (geometric) rate.
Condition number: \(\kappa = L/\mu\). Large \(\kappa\) = ill-conditioned = slow convergence.

For our demo function \(f(\theta) = \tfrac{1}{2}(\theta_0^2 + 4\theta_1^2)\): Hessian \(H = \mathrm{diag}(1, 4)\), so \(\mu = 1\), \(L = 4\), \(\kappa = 4\). Optimal step \(\eta^* = 2/(1+4) = 0.4\), convergence rate \(\rho = (L-\mu)/(L+\mu) = 0.6\) per step.

Common pitfall

The threshold for divergence is \(\eta > 2/L\), not \(\eta > 1/L\). With \(\eta \in (1/L, 2/L)\) GD still converges but exhibits zig-zagging. Many practitioners confuse the stability bound with the optimal step size — they differ by a factor of 2.

Key Takeaways
▼

Learning rate summary

  • Too small (\(\eta \ll 1/L\)): Converges but slowly — \(\mathcal{O}(1/k)\) for convex, linear for strongly convex but with large constant.
  • Optimal (\(\eta = 2/(\mu+L)\)): Fastest linear convergence; rate \((\kappa-1)/(\kappa+1)\) per step.
  • Zig-zag (\(\eta \in (1/L, 2/L)\)): Convergent but bounces across the valley — can be fixed by momentum.
  • Divergence (\(\eta > 2/L\)): Loss grows exponentially — reduce \(\eta\) immediately.

In practice

  • Use a learning rate scheduler (warm-up + cosine/linear decay) — constant \(\eta\) is rarely optimal throughout training.
  • Monitor the loss; a sudden spike means \(\eta\) is too large.
  • Mini-batch SGD introduces gradient noise which acts as implicit regularization but makes \(L\) effectively larger (requiring smaller \(\eta\)).
  • Adaptive methods (Adam, RMSProp) automatically rescale \(\eta\) per-parameter using second-moment estimates.
Hierarchy of optimizers

GD (full batch, exact gradient) ⊂ SGD (mini-batch) ⊂ Momentum / Nesterov (accelerated) ⊂ Adam / RMSProp (adaptive). Each builds on the core update \(\theta \leftarrow \theta - \eta g\), adding corrections for variance, curvature, or past gradients.

Code Trace
▼

Gradient descent from scratch in NumPy on the demo function, then using PyTorch's optimizer API. Lines highlighted in green as the algorithm steps.

import numpy as np
# f(t) = 0.5*(t0^2 + 4*t1^2) — mu=1, L=4, kappa=4
def f(theta): return 0.5 * (theta[0]**2 + 4*theta[1]**2)
def grad_f(theta): return np.array([theta[0], 4*theta[1]])
theta = np.array([3.0, 2.0]) # starting point
eta = 0.40 # optimal: 2/(mu+L) = 2/5
n_steps = 15
for k in range(n_steps):
g = grad_f(theta) # compute gradient
theta = theta - eta * g # UPDATE RULE
if k % 3 == 0:
print(f"k={k:2d} f={f(theta):.6f}")
# PyTorch production usage
import torch, torch.optim as optim
theta_t = torch.tensor([3.0, 2.0], requires_grad=True)
optimizer = optim.SGD([theta_t], lr=0.40) # vanilla GD (full batch)
for k in range(n_steps):
optimizer.zero_grad() # clear accumulated grads
loss = 0.5*(theta_t[0]**2 + 4*theta_t[1]**2)
loss.backward() # autograd computes grad
optimizer.step() # theta -= lr * grad
