Hardswish & Hardtanh

Piecewise-linear, mobile-friendly stand-ins for Swish and Tanh
Intermediate Deep Learning Mobile / Quantization O(1) — no exp()
1
Understanding Hardswish & Hardtanh
▼

What is it? When a neural network runs on a phone, every operation costs battery and latency. Smooth activation functions like Swish (\(x\cdot\sigma(x)\)) and Tanh need an exponential to compute — expensive, and awkward to represent in 8-bit fixed-point math. Hardswish and Hardtanh replace those smooth curves with a few straight-line segments that look almost identical but only need comparisons, clamps, and one multiply.

Analogy: Think of tracing a winding mountain road (the smooth curve) versus paving a road out of three straight segments that hug the same general shape (the piecewise-linear version). The straight-segment road is far cheaper to build and drive on a low-power chip, and for almost every trip the ride feels the same — you only notice a slightly sharper turn at the two joints.

💡 If you remember one thing

$$\operatorname{Hardswish}(x) = x\cdot\frac{\operatorname{ReLU6}(x+3)}{6} \qquad \operatorname{Hardtanh}(x) = \operatorname{clip}(x,-1,1)$$ Both are built entirely from compare/clamp/multiply — zero exponentials — which is the whole reason they exist: speed and exact int8 quantization on mobile hardware.

How It Works Internally
▼

The Building Block: ReLU6

\(\operatorname{ReLU6}(x) = \min(\max(x,0),6)\) — a ReLU capped at 6, already implemented efficiently on every mobile runtime because MobileNetV1/V2 use it directly. Bounding the output keeps the dynamic range small, which matters a lot for fixed-point (int8) quantization.

Hard Sigmoid: Reusing ReLU6

Shift and rescale ReLU6 to build a piecewise-linear stand-in for sigmoid: \(\operatorname{HardSigmoid}(x) = \operatorname{ReLU6}(x+3)/6\). Sigmoid's non-saturated range is roughly \([-3,3]\) — shifting by 3 centers that window exactly on ReLU6's \([0,6]\) domain, and dividing by 6 rescales the output into \([0,1]\), just like sigmoid.

Hardswish: Gate x by Its Own Hard Sigmoid

\(\operatorname{Hardswish}(x) = x \cdot \operatorname{HardSigmoid}(x)\) — exactly mirrors Swish's \(x\cdot\sigma(x)\) gating shape, but built from three cheap ALU ops: clamp, scale, multiply.

Hardtanh: A Direct Clamp

\(\operatorname{Hardtanh}(x)=\operatorname{clip}(x,-1,1)\) has no gating multiply at all — it's the simplest possible saturating nonlinearity, used since BinaryConnect (2015) as a cheap Tanh substitute and as the standard straight-through-estimator gradient for quantized/binarized training.

🔑 Key Property

Every stage — clamp, scale, multiply — is exactly representable in low-bit fixed-point arithmetic. No lookup table, no polynomial fit, no precision loss beyond the quantization grid itself.

Why It Works — The Math
▼

Piecewise Definition

$$\operatorname{Hardswish}(x) = \begin{cases} 0 & x \le -3 \\ \dfrac{x(x+3)}{6} & -3 < x < 3 \\ x & x \ge 3 \end{cases}$$

Gradient, Piece by Piece

$$\frac{d}{dx}\operatorname{Hardswish}(x) = \begin{cases} 0 & x \le -3 \\ \dfrac{2x+3}{6} & -3 < x < 3 \\ 1 & x \ge 3 \end{cases}$$

The value is continuous at \(x=-3\) (both pieces give 0) and at \(x=3\) (both give 3) — but the slope is not: at \(x=-3\) the left derivative is 0 while the right derivative is \(\tfrac{2(-3)+3}{6}=-0.5\). These are genuine kinks, exactly like ReLU's kink at 0.

Matching Swish's Slope at the Origin

Swish's exact derivative is \(\sigma(x) + x\sigma(x)(1-\sigma(x))\), which equals 0.5 at \(x=0\) — identical to Hardswish's middle-piece slope \(\tfrac{2(0)+3}{6}=0.5\) at the same point. The piecewise-linear fit was constructed to match Swish exactly where most pre-activations concentrate early in training.

Hardtanh Gradient

$$\frac{d}{dx}\operatorname{Hardtanh}(x) = \begin{cases} 1 & -1 < x < 1 \\ 0 & \text{otherwise} \end{cases}$$

This constant-1-or-0 gradient is exactly what's used as a straight-through estimator when backpropagating through a true (non-differentiable) binarization or rounding step.

⚠️ Common Pitfall

"Hardswish is just ReLU6" is false — ReLU6 alone can never be negative, but \(\operatorname{Hardswish}(-1.5) = -0.375\). The multiply by \(x\) is what creates the small negative dip that mirrors Swish's non-monotonicity.

Key Takeaways
▼

When to use:

  • Deploying to mobile/edge NPUs, DSPs, or microcontrollers where latency and power matter
  • Quantizing a model to int8 and wanting exact, table-free activation quantization
  • Building or fine-tuning MobileNetV3 / EfficientNet-Lite style backbones
  • Quantization-aware training, where Hardtanh's clean gradient is a natural straight-through estimator

When NOT to use:

  • Training large, accuracy-critical models on ample server compute — GELU/Swish's smoothness usually wins by a fraction of a percent
  • Transformers almost universally prefer GELU over Hardswish
💡 Hierarchy

ReLU6 (atomic clamp) → HardSigmoid (shifted/rescaled ReLU6) → Hardswish (x · HardSigmoid). Hardtanh is a direct clamp with no gating step. All are piecewise-linear approximations chosen so the whole network stays exactly quantizable and hardware-cheap.

Code Trace
▼
import numpy as np
def relu6(x):
return np.clip(x, 0.0, 6.0)
def hard_sigmoid(x):
return relu6(x + 3.0) / 6.0
def hardswish(x):
return x * hard_sigmoid(x)
def hardswish_grad(x):
if x <= -3: return 0.0
if x >= 3: return 1.0
return (2*x + 3) / 6.0
def hardtanh(x, lo=-1.0, hi=1.0):
return np.clip(x, lo, hi)
def hardtanh_grad(x, lo=-1.0, hi=1.0):
return 1.0 if lo < x < hi else 0.0
# torch.nn.Hardswish() / torch.nn.Hardtanh()
# are the production drop-in equivalents.
