Understanding Hardswish & Hardtanh
▼

What are they? Hardswish and Hardtanh are activation functions designed for neural networks, specifically optimized for deployment on resource-constrained devices like mobile phones or embedded systems. They are piecewise linear approximations of the more computationally expensive Swish and Tanh functions, respectively.

Why use them? Traditional activation functions like sigmoid, tanh, and swish involve exponential calculations (e.g., \(e^x\)), which are floating-point intensive and slow on mobile processors or specialized hardware without dedicated `exp` units. Hardswish and Hardtanh replace these operations with simpler arithmetic (additions, multiplications, clamping) that are much faster and more power-efficient.

Analogy: Imagine you need to draw a smooth curve. A professional designer might use a flexible "French curve" (like `tanh` or `swish`). But if you're building a quick prototype and only have a ruler, you might approximate that curve with a few straight line segments (like `Hardtanh` or `Hardswish`). The approximation isn't perfect, but it's much faster to draw and often "good enough" for the task at hand, especially if you're drawing thousands of them a second.

💡 If you remember one thing

Hardswish and Hardtanh are engineered compromises: they trade a tiny, often imperceptible, drop in model accuracy for significant gains in inference speed and power efficiency on mobile and edge devices. They achieve this by replacing expensive non-linear operations (like `exp` or `tanh`) with simple, hardware-friendly piecewise linear functions.

How Hardswish & Hardtanh Work Internally
▼

Hardtanh: A Simple Clip

The `tanh` (hyperbolic tangent) function squashes its input to the range \((-1, 1)\) with a smooth S-shape. Hardtanh, on the other hand, is a straightforward clipping operation:

  • If \(x < -1\), output \(-1\).
  • If \(x > 1\), output \(1\).
  • Otherwise (if \(-1 \le x \le 1\)), output \(x\).

This is simply clamp(x, -1, 1). It perfectly matches `tanh(x)` for inputs close to zero, but beyond \(\pm 1\), it becomes a flat line instead of smoothly approaching the asymptote.

Hardswish: Approximating Sigmoid with ReLU6

The Swish activation function is defined as \(x \cdot \text{sigmoid}(x)\). The computational bottleneck here is the `sigmoid` function, which involves an exponential: \(\text{sigmoid}(x) = 1 / (1 + e^{-x})\). Hardswish replaces this expensive `sigmoid` with a piecewise linear approximation derived from `ReLU6`:

$$\text{Hardswish}(x) = x \cdot \frac{\text{ReLU6}(x+3)}{6}$$

Here, `ReLU6` is defined as \(\text{ReLU6}(x) = \min(\max(0, x), 6)\). So, \(\text{ReLU6}(x+3)\) effectively clamps the input \(x+3\) between 0 and 6. When divided by 6, the term \(\frac{\text{ReLU6}(x+3)}{6}\) serves as a fast, piecewise linear approximation of the `sigmoid` function.

Design Decision: Why ReLU6?

`ReLU6` is a variant of ReLU that clamps activations at 6. It was originally introduced in early mobile-optimized architectures (like MobileNetV1) because it provided robustness for low-precision (e.g., FP16 or INT8) inference and could be efficiently implemented on hardware that supported 8-bit quantization. By leveraging `ReLU6` in Hardswish, developers gain the benefits of a well-understood, hardware-accelerated operation for the sigmoid approximation, further boosting performance on mobile platforms.

🔑 Key Property

Both Hardtanh and Hardswish preserve the general shape and desirable properties (like non-monotonicity for Hardswish near zero, or zero-centered output for Hardtanh) of their smooth counterparts. The key difference lies in replacing transcendental functions (like `exp` or `tanh`) with sequences of basic arithmetic operations (`add`, `mul`, `min`, `max`, `div`), making them significantly faster on mobile-grade hardware.

3
Why It Works — The Math
▼

Hardtanh: Piecewise Linear Clipping

The hyperbolic tangent function is defined as \(\tanh(x) = \frac{e^x - e^{-x}}{e^x + e^{-x}}\). Hardtanh directly approximates this by clipping:

$$ \text{Hardtanh}(x) = \begin{cases} -1 & \text{if } x < -1 \\ x & \text{if } -1 \le x \le 1 \\ 1 & \text{if } x > 1 \end{cases} $$

This function is computationally trivial, involving only two comparisons and potentially one assignment. It has a sharp, non-differentiable point at \(x = \pm 1\), unlike the smooth `tanh` function. However, for most practical purposes in deep learning, this sharp transition is acceptable, as gradients are typically handled by subgradient methods.

Hardswish: The Sigmoid Approximation

The standard Swish function is \( \text{Swish}(x) = x \cdot \text{sigmoid}(x) \). Hardswish replaces the `sigmoid` part with a piecewise linear approximation. Let's analyze the approximation: \(\text{approx\_sigmoid}(x) = \frac{\text{ReLU6}(x+3)}{6}\).

Recall that \(\text{ReLU6}(z) = \min(\max(0, z), 6)\). Substituting \(z = x+3\):

$$ \text{ReLU6}(x+3) = \begin{cases} 0 & \text{if } x+3 < 0 \implies x < -3 \\ x+3 & \text{if } 0 \le x+3 \le 6 \implies -3 \le x \le 3 \\ 6 & \text{if } x+3 > 6 \implies x > 3 \end{cases} $$

Therefore, the Hardswish activation function is explicitly piecewise linear:

$$ \text{Hardswish}(x) = \begin{cases} 0 & \text{if } x < -3 \\ x \cdot \frac{x+3}{6} & \text{if } -3 \le x \le 3 \\ x & \text{if } x > 3 \end{cases} $$

This approximation of `sigmoid` by `ReLU6(x+3)/6` is remarkably accurate over the most important range of inputs, especially around \(x=0\), while completely avoiding the expensive exponential operations. The resulting Hardswish function retains the non-monotonic behavior for negative inputs that is characteristic of Swish, which has been shown to be beneficial in deep networks.

⚠️ Common Misconception

While highly efficient, Hardswish and Hardtanh are not universally superior. Their piecewise linear nature introduces sharp corners (non-differentiable points) that can sometimes lead to minor training instabilities or slightly reduced model expressiveness compared to their smooth counterparts. The choice is a practical engineering trade-off, not a pure theoretical improvement.

Key Takeaways
▼

When to use Hardswish / Hardtanh:

  • Mobile and Edge Devices: Their primary use case. If you're deploying models on smartphones, IoT devices, or other platforms with limited computational resources and power budgets, these activations are excellent choices.
  • Latency-Sensitive Applications: Where every millisecond of inference time counts.
  • Quantized Models: Their piecewise linear nature often makes them more robust and easier to quantize (e.g., to INT8) without significant accuracy loss.
  • MobileNetV3: Hardswish was specifically introduced and heavily used in MobileNetV3, demonstrating its effectiveness in state-of-the-art mobile architectures.

When NOT to use:

  • High-Performance Computing (HPC) / Cloud GPUs: If you have abundant computational resources (e.g., powerful GPUs in the cloud), the minor speedup from Hardswish/Hardtanh might not justify any potential (though often negligible) accuracy trade-off.
  • When Exact Differentiability is Critical: For certain theoretical analyses or specific optimization algorithms that require smoothly differentiable functions everywhere, the sharp corners of Hardswish/Hardtanh might be problematic.
  • Early Research/Prototyping: Unless you are specifically targeting mobile deployment from the outset, starting with standard activations like ReLU, Leaky ReLU, or Swish is often simpler.
💡 Practical Wisdom

The "Hard" activations are a testament to the engineering ingenuity in deep learning. They highlight that sometimes, a computationally simpler, slightly less accurate approximation can be vastly more valuable in real-world deployment than a theoretically perfect but resource-heavy alternative. Always consider your target hardware and performance metrics.

Code Trace (PyTorch-style from scratch)
▼
import torch
def hardtanh(x):
return torch.clamp(x, min=-1.0, max=1.0)
def relu6(x):
return torch.clamp(x, min=0.0, max=6.0)
def hardswish(x):
# Equivalent to x * torch.min(torch.max(torch.tensor(0.0), x + 3.0), torch.tensor(6.0)) / 6.0
return x * relu6(x + 3.0) / 6.0
# For comparison (not used in Hard activations):
def tanh(x):
return torch.tanh(x)
def sigmoid(x):
return torch.sigmoid(x)
def swish(x):
return x * sigmoid(x)
# Example usage:
input_tensor = torch.tensor([-5.0, -1.0, 0.0, 1.0, 5.0])
print(f"Input: {input_tensor}")
print(f"Hardtanh: {hardtanh(input_tensor)}")
print(f"Hardswish: {hardswish(input_tensor)}")
