MADDPG: Multi-Agent Deep Deterministic Policy Gradient

Centralized Training, Decentralized Execution for cooperative & competitive environments
Intermediate Reinforcement Learning Multi-Agent Systems O(N³) per step
1
Understanding MADDPG
▼

What is it? MADDPG (Multi-Agent Deep Deterministic Policy Gradient) is an extension of the DDPG algorithm designed for environments with multiple interacting agents. It tackles the non-stationarity problem inherent in multi-agent reinforcement learning (MARL) by employing a "Centralized Training, Decentralized Execution" (CTDE) paradigm. This means during training, agents can share information and observe the full state, but during execution, they act independently based only on their local observations.

Why is MARL Hard? In a multi-agent setting, each agent's optimal policy depends not only on the environment but also on the policies of all other agents. If other agents are learning simultaneously, the environment becomes non-stationary from any single agent's perspective, violating a core assumption of many single-agent RL algorithms like Q-learning or standard DDPG. MADDPG addresses this by giving critics access to more information during training.

Analogy: Imagine a soccer team. During practice (training), the coach (centralized critic) sees all players' positions, intended moves, and the ball's trajectory, and can give feedback to each player (actor) based on the entire team's performance. During a game (execution), each player (actor) must make decisions quickly based only on what they can see from their own perspective, without explicit knowledge of every teammate's exact plan. MADDPG allows for this rich, global feedback during training to produce robust individual players for decentralized play.

💡 If you remember one thing

MADDPG's core idea is Centralized Training, Decentralized Execution (CTDE). Each agent's *actor* (policy) learns from its local observation, but its *critic* (value function) gets to see the observations and actions of *all* agents during training to stabilize learning. At test time, only the local actors are used.

2
How MADDPG Works Internally
▼

Architecture: Per-Agent Actor-Critic Pairs

Each of the \(N\) agents in MADDPG has its own actor network \(\mu_i\) and critic network \(Q_i\). These networks are typically neural networks:

  • Actor \(\mu_i(o_i)\): A policy network for agent \(i\) that takes its local observation \(o_i\) as input and outputs a deterministic action \(a_i\). During execution, this is the only part of the agent used.
  • Critic \(Q_i(x, a_1, \dots, a_N)\): A Q-network for agent \(i\) that takes the joint observation \(x\) (concatenation of all agents' observations) and the joint action \((a_1, \dots, a_N)\) (actions of all agents) as input, and outputs an estimated Q-value for agent \(i\). This expanded input for the critic is the "centralized training" part.

Each agent also maintains a set of target networks (\(\mu'_i\) and \(Q'_i\)) for stability, similar to DDPG. These are slow-moving copies of the main networks, used to compute target Q-values.

Training Loop: The CTDE Advantage

The training process for each agent \(i\) involves:

  1. Experience Collection: Agents execute actions in the environment (using their current policies \(\mu_i(o_i)\)). The collective experience \((x, a_1, \dots, a_N, r_1, \dots, r_N, x')\) is stored in a shared replay buffer. Here, \(x\) is the *joint state* (all observations combined), and \(r_i\) is agent \(i\)'s individual reward.
  2. Batch Sampling: A batch of experiences is sampled from the replay buffer.
  3. Critic Update: For each agent \(i\), its critic \(Q_i\) is updated to minimize the temporal difference (TD) error. The target Q-value \(y_i\) is computed using the target critic \(Q'_i\) and target actors \(\mu'_j\) of all agents. This is where the centralized information comes in: \(y_i = r_i + \gamma Q'_i(x', a'_1, \dots, a'_N)\), where \(a'_j = \mu'_j(o'_j)\).
  4. Actor Update: For each agent \(i\), its actor \(\mu_i\) is updated using the policy gradient theorem. The gradient is taken with respect to the agent's own action, but using its critic's centralized knowledge: \(\nabla_{\theta_i} J \approx \mathbb{E}_{x, o_i, a_i \sim \mathcal{D}}[\nabla_{a_i} Q_i(x, a_1, \dots, a_N)|_{a_i=\mu_i(o_i)} \nabla_{\theta_i} \mu_i(o_i)]\).
  5. Target Network Update: The target networks are softly updated towards the main networks: \(\theta'_i \leftarrow \tau \theta_i + (1-\tau)\theta'_i\).

Design Decision: Why Joint Observation for Critic, but Local for Actor?

The critic needs to understand the impact of *all* agents' actions on the value function to provide a stable learning signal. If a critic only saw its local observation, it wouldn't know if a low reward was due to its own bad action or another agent's interference. By seeing everything, it can accurately assess the global situation. The actor, however, must learn to act based *only* on its local view because during real-world execution, it won't have access to other agents' internal states or intentions.

🔑 Key Property

By leveraging the full state information during training, MADDPG effectively handles the non-stationarity problem that plagues traditional MARL. Each agent's critic can distinguish between changes in the environment due to other agents' evolving policies and changes due to its own actions, leading to more stable and robust learning.

Why It Works — The Math
▼

The Critic Loss Function

For each agent \(i\), the critic \(Q_i\) is trained to minimize the mean squared TD error, just like in DDPG, but with a multi-agent target. We collect a tuple \((x, a_1, \dots, a_N, r_1, \dots, r_N, x')\) from the replay buffer, where \(x\) is the joint observation and \(a_j\) are actions from the current policies \(\mu_j\).

The target \(y_i\) for agent \(i\) is calculated using the target networks of all agents:

$$y_i = r_i + \gamma Q'_i(x', \mu'_1(o'_1), \dots, \mu'_N(o'_N))$$

The critic loss for agent \(i\) is then:

$$L(Q_i) = \mathbb{E}_{x,a,r,x' \sim \mathcal{D}} \left[ \left( Q_i(x, a_1, \dots, a_N) - y_i \right)^2 \right]$

This loss explicitly incorporates the actions of all agents, making the critic aware of the full context. The target actions \(a'_j\) are determined by the target policies \(\mu'_j\), ensuring stability.

The Actor Policy Gradient

Each agent \(i\)'s actor \(\mu_i\) is updated using the deterministic policy gradient. The key is that the gradient is computed with respect to agent \(i\)'s actions, but leveraging the joint information available to its critic \(Q_i\). The objective for agent \(i\) is to maximize its expected return:

$$J(\theta_i) = \mathbb{E}_{x, o_i \sim \mathcal{D}} \left[ Q_i(x, a_1, \dots, a_N)|_{a_i=\mu_i(o_i)} \right]$$

The policy gradient for agent \(i\) is then:

$$\nabla_{\theta_i} J(\theta_i) = \mathbb{E}_{x, o_i \sim \mathcal{D}} \left[ \nabla_{a_i} Q_i(x, a_1, \dots, a_N)|_{a_i=\mu_i(o_i)} \cdot \nabla_{\theta_i} \mu_i(o_i) \right]$$

Here, the \(\nabla_{a_i} Q_i\) term is computed using the full joint state and actions, while \(\nabla_{\theta_i} \mu_i\) only depends on agent \(i\)'s local observation. This allows the actor to learn an optimal policy for decentralized execution while benefiting from the centralized training information.

⚠️ Common Pitfall

MADDPG's critics require joint actions as input. If the action space is continuous (as in DDPG), this is straightforward. If it's discrete, one common approach is to use a Gumbel-Softmax trick to get differentiable "soft" actions from discrete policies, allowing the critic to handle them. Directly passing one-hot discrete actions can sometimes work but might lead to sparse gradients for the critic.

Key Takeaways
▼

When to use MADDPG:

  • Cooperative Multi-Agent Tasks: Where agents need to coordinate to achieve a common goal (e.g., team games, synchronized movement).
  • Competitive Multi-Agent Tasks: Where agents compete against each other (e.g., predator-prey, adversarial games). MADDPG can learn robust policies against co-adapting opponents.
  • Mixed Cooperative-Competitive Tasks: Environments with elements of both, as long as the joint observations are feasible for critics.
  • Continuous Action Spaces: Inherits DDPG's ability to handle continuous actions directly.

When NOT to use / Limitations:

  • Very Large Number of Agents: The centralized critic's input grows with the number of agents and their observation/action spaces, potentially making it intractable for many agents.
  • Decentralized Training Required: If agents cannot share *any* information during training (e.g., privacy concerns, communication bandwidth limits), MADDPG's CTDE paradigm is not applicable.
  • Discrete Action Spaces without Gumbel-Softmax: While possible, direct application can be tricky without careful handling of discrete actions for the critic.
  • High-Dimensional Observations: Joint observations can become very large, requiring complex critic architectures.
💡 Broader Impact

MADDPG laid foundational groundwork for many subsequent multi-agent RL algorithms that utilize the CTDE paradigm. Its success demonstrated that breaking the single-agent non-stationarity assumption via centralized information during training is a powerful approach for complex MARL problems, influencing fields from robotics to game AI.

Code Trace (Simplified PyTorch Structure)
▼
import torch
import torch.nn as nn
import torch.optim as optim
# --- Agent Networks ---
class Actor(nn.Module):
def __init__(self, obs_dim, action_dim):
super().__init__()
self.net = nn.Sequential(
nn.Linear(obs_dim, 64), nn.ReLU(),
nn.Linear(64, 64), nn.ReLU(),
nn.Linear(64, action_dim), nn.Tanh() # actions in [-1, 1]
)
def forward(self, obs): return self.net(obs)
class Critic(nn.Module):
# Critic takes joint observation (x) and joint actions (a_all)
def __init__(self, joint_obs_dim, joint_action_dim):
super().__init__()
self.net = nn.Sequential(
nn.Linear(joint_obs_dim + joint_action_dim, 128), nn.ReLU(),
nn.Linear(128, 128), nn.ReLU(),
nn.Linear(128, 1) # Q-value output
)
def forward(self, joint_obs, joint_actions):
return self.net(torch.cat([joint_obs, joint_actions], dim=-1))
# --- MADDPG Agent Class (simplified) ---
class MADDPGAgent:
def __init__(self, agent_idx, obs_dim, action_dim, num_agents, gamma=0.95, tau=0.01):
self.agent_idx = agent_idx
self.gamma = gamma; self.tau = tau
self.actor = Actor(obs_dim, action_dim)
self.critic = Critic(num_agents * obs_dim, num_agents * action_dim)
self.target_actor = Actor(obs_dim, action_dim)
self.target_critic = Critic(num_agents * obs_dim, num_agents * action_dim)
# Copy parameters to target networks
self.target_actor.load_state_dict(self.actor.state_dict())
self.target_critic.load_state_dict(self.critic.state_dict())
self.actor_optimizer = optim.Adam(self.actor.parameters(), lr=1e-4)
self.critic_optimizer = optim.Adam(self.critic.parameters(), lr=1e-3)
def act(self, obs): # Decentralized execution
obs_tensor = torch.tensor(obs, dtype=torch.float32).unsqueeze(0)
return self.actor(obs_tensor).squeeze(0).detach().numpy()
def update_critic(self, batch, all_agents_target_actors, obs_dim):
# batch contains: joint_obs, joint_actions, rewards, next_joint_obs
joint_obs, joint_actions, rewards, next_joint_obs = batch
# Compute target actions for all agents from their target actors
next_actions = [target_actor(next_joint_obs[:, i*obs_dim:(i+1)*obs_dim])
for i, target_actor in enumerate(all_agents_target_actors)]
next_actions = torch.cat(next_actions, dim=-1)
# Compute target Q-value for this agent (centralized)
target_q = rewards[:, self.agent_idx] + self.gamma * \
self.target_critic(next_joint_obs, next_actions).squeeze(1)
current_q = self.critic(joint_obs, joint_actions).squeeze(1)
critic_loss = nn.MSELoss()(current_q, target_q.detach())
self.critic_optimizer.zero_grad()
critic_loss.backward()
self.critic_optimizer.step()
def update_actor(self, batch, all_agents_actors, obs_dim):
joint_obs, _, _, _ = batch
# Get current actions from all agents' actors (including this agent's)
current_actions = [actor(joint_obs[:, i*obs_dim:(i+1)*obs_dim])
for i, actor in enumerate(all_agents_actors)]
current_actions = torch.cat(current_actions, dim=-1)
# Policy gradient: maximize Q for this agent's action (centralized critic)
actor_loss = -self.critic(joint_obs, current_actions).mean()
self.actor_optimizer.zero_grad()
actor_loss.backward()
self.actor_optimizer.step()
def soft_update_target_networks(self):
for target_param, param in zip(self.target_critic.parameters(), self.critic.parameters()):
target_param.data.copy_(self.tau * param.data + (1.0 - self.tau) * target_param.data)
for target_param, param in zip(self.target_actor.parameters(), self.actor.parameters()):
target_param.data.copy_(self.tau * param.data + (1.0 - self.tau) * target_param.data)
