Compressing neural networks by removing redundant weights for faster inference

1
Understanding Pruning
▼

What is it? Pruning is a technique to reduce the size and computational cost of neural networks by removing redundant weights or neurons, typically after or during training. The goal is to achieve a sparse network that performs comparably to its dense counterpart but requires fewer parameters and floating-point operations (FLOPs), making it faster and more memory-efficient for deployment on resource-constrained devices.

Analogy: Imagine a sculptor starting with a huge block of marble (a dense, over-parameterized neural network). Instead of carving from scratch, they meticulously identify and chip away only the excess material that doesn't contribute to the final form, or even detracts from it (pruning weights). The result is a lighter, more elegant sculpture (a sparse network) that retains all its artistic value (accuracy) but is far more efficient to display and transport (inference).

💡 If you remember one thing

Pruning transforms a dense neural network into a sparse one by setting a fraction of its weights to zero. This process is usually performed iteratively (train, prune, retrain) to recover accuracy, and the choice of which weights to remove is crucial. Magnitude pruning is the simplest heuristic, while gradient-based methods offer a more principled approach.

2
How Pruning Works Internally
▼

The Pruning Mask

At its core, pruning involves creating a binary mask \(M\) for each weight tensor \(W\). This mask has the same shape as \(W\), with \(M_{ij} = 1\) if the weight \(W_{ij}\) is kept, and \(M_{ij} = 0\) if it's pruned (set to zero). During inference, the pruned weights are simply skipped, leading to computational savings. During training (if retraining is done), the mask ensures that the pruned weights remain zero.

Magnitude Pruning: The Simplest Heuristic

The most straightforward approach is to prune weights with the smallest absolute values. The intuition is that weights with very small magnitudes contribute little to the network's output and can be removed with minimal impact. This method is surprisingly effective and forms the basis of many pruning strategies, including those inspired by the "Lottery Ticket Hypothesis" (Frankle & Carbin, 2019).

Gradient-Based Pruning: A More Principled Approach

Instead of just looking at the weight's value, gradient-based methods consider how much a weight contributes to the loss. A common approach is to use a first-order Taylor expansion to estimate the change in loss if a weight \(w_i\) were removed (set to zero). This leads to a "saliency score" that quantifies the importance of each weight, often related to the product of the weight and its gradient.

Design Decision: Why Not Train Sparse from Scratch?

While ideally one might train sparse networks directly, it's empirically much harder to optimize. Starting with a dense, over-parameterized model and then pruning it often yields better results. This is because dense training allows the network to explore a wider solution space and find a good initial configuration, from which pruning can then identify the truly essential connections.

🔑 Key Property

Pruning is typically an iterative process: (1) train a dense model, (2) prune a fraction of weights, (3) retrain the sparse model to recover accuracy. This cycle can be repeated multiple times, gradually increasing sparsity. The weights are not physically removed, but rather masked to zero, with the underlying memory often remaining allocated unless specialized sparse hardware is used.

3
Why It Works — The Math
▼

Magnitude Pruning: Thresholding Absolute Values

For magnitude pruning, the criterion is simple: identify weights \(w_i\) whose absolute value falls below a certain threshold \(\tau\). If \(\left|w_i\right| < \tau\), then \(w_i\) is pruned. The threshold \(\tau\) is usually determined by a target sparsity level (e.g., prune the smallest 50% of weights), rather than an absolute value.

$$M_{ij} = \begin{cases} 1 & \text{if } |W_{ij}| \ge \tau \\ 0 & \text{if } |W_{ij}| < \tau \end{cases}$$

This method assumes that small weights are less important. While a heuristic, it often works well in practice, especially when combined with iterative retraining.

Gradient-Based Pruning: Taylor Expansion for Saliency

More advanced pruning methods aim to remove weights that cause the least increase in the loss function \(L\). We can estimate this change using a first-order Taylor expansion around the current weights \(W\). If we set a weight \(w_i\) to zero, the change \(\Delta w_i = -w_i\). The approximate change in loss \(\Delta L\) is then:

$$\Delta L \approx \sum_{i} \frac{\partial L}{\partial w_i} \Delta w_i = \sum_{i} \left(\frac{\partial L}{\partial w_i}\right) (-w_i)$$

To prune a single weight \(w_k\), we consider its individual contribution to \(\Delta L\). The "saliency score" or "importance score" for \(w_k\) is then defined as the absolute value of this contribution:

$$S_k = \left| \frac{\partial L}{\partial w_k} \cdot w_k \right|$$

Weights with the smallest \(S_k\) are considered least important because their removal would lead to the smallest increase in loss. This technique is related to "Optimal Brain Damage" (LeCun et al., 1990) and "Optimal Brain Surgeon" (Hassibi et al., 1993), which use second-order information (Hessian) for a more accurate but computationally expensive estimate.

⚠️ Common Pitfall

The gradient \(\partial L / \partial w_k\) must be computed after the model has been trained for at least some time, often at the end of a training epoch. Using gradients from an untrained or poorly trained model will yield meaningless saliency scores. Also, ensure the gradients are "fresh" and correspond to the current weights, not stale ones.

Key Takeaways
▼

When to use pruning:

  • Model Deployment: For deploying large models on edge devices (mobile, IoT) with limited memory and computational power.
  • Inference Cost: To reduce inference latency and energy consumption in data centers.
  • Research: To understand neural network redundancy and explore the "Lottery Ticket Hypothesis" (finding sparse subnetworks that train to full accuracy).
  • Combined with Quantization: Pruning is often paired with quantization (reducing the bit-width of weights) for maximum model compression.

When NOT to use pruning:

  • Underfitting Models: If your model is already struggling to learn the task, pruning will likely degrade performance further.
  • Very Small Models: For models that are already minimally parameterized, the overhead of managing sparsity might outweigh the benefits.
  • Accuracy is Paramount: While pruning aims for minimal accuracy loss, it's not always zero. If every fraction of a percent accuracy is critical, pruning might be avoided or used very cautiously.
  • No Sparse Hardware: Without hardware (e.g., specialized ASICs or GPUs with sparse tensor cores) that can efficiently skip zero weights, the computational speedup from pruning might be limited, though memory savings still apply.
💡 Big Picture

Pruning is a powerful tool for model compression, but it's not a magic bullet. It requires careful experimentation with pruning percentages, methods, and retraining schedules. The choice between magnitude and gradient-based pruning often comes down to a trade-off between simplicity and theoretical rigor, with both capable of achieving significant sparsity with minimal accuracy degradation.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn.utils.prune as prune
# Assume 'model' is a trained PyTorch nn.Module
# and 'dataloader' provides training data
# --- Magnitude Pruning ---
# Prune 50% of connections in linear layers by magnitude
for name, module in model.named_modules():
if isinstance(module, torch.nn.Linear):
prune.l1_unstructured(module, name="weight", amount=0.5)
# --- Gradient-Based Pruning (simplified pseudo-code) ---
# 1. Compute gradients for saliency scores
model.zero_grad()
output = model(next(iter(dataloader))[0]) # Forward pass on a batch
loss = loss_fn(output, next(iter(dataloader))[1])
loss.backward() # Compute gradients
# 2. Calculate saliency scores |w * grad(L,w)|
saliency_scores = {}
for name, param in model.named_parameters():
if "weight" in name and param.grad is not None:
saliency_scores[name] = torch.abs(param * param.grad)
# 3. Determine threshold and apply pruning mask
all_saliencies = torch.cat([s.flatten() for s in saliency_scores.values()])
threshold = torch.topk(all_saliencies, int(len(all_saliencies) * 0.5), largest=False).values[-1]
for name, module in model.named_modules():
if isinstance(module, torch.nn.Linear):
# Create a custom mask based on saliency_scores
mask = (saliency_scores[name + ".weight"] >= threshold).float()
prune.custom_from_mask(module, name="weight", mask=mask)
# --- Retrain the pruned model ---
# After pruning, resume training to recover accuracy.
# The 'prune.remove_reparameterization' makes pruned weights permanent.
for name, module in model.named_modules():
if isinstance(module, torch.nn.Linear):
prune.remove_reparameterization(module, "weight")
