XGBoost: Weighted Quantile Sketch & Histogram-Based Splits

How XGBoost proposes candidate split points in O(#bins) instead of O(#samples)
Advanced Classical ML · Boosting O(#bins · depth · trees) Must Know
1
Understanding the Concept
›

XGBoost builds an ensemble of decision trees, one at a time, where each tree fits the residual errors left by the previous trees. To build each tree, XGBoost needs to find the best place to split the data at every node — i.e., which feature threshold maximises the reduction in the loss.

The naive approach checks every unique value in the data as a candidate split: if you have 10 million rows, that's up to 10 million split points per feature per node — impossibly slow. XGBoost solves this with two interlocking techniques:

  1. Weighted Quantile Sketch — compress the full data distribution into a small set of candidate split points weighted by second-order gradients (hessians). Each candidate represents a "bucket" of equal hessian weight, so no important region is under-sampled.
  2. Histogram-Based Split Finding — pre-aggregate all gradient statistics into discrete bins, then evaluate only those bins. Split evaluation becomes O(#bins) not O(#samples).
Key Insight

The hessian \(h_i\) is the curvature of the loss at sample \(i\). It measures how "confident" the model is about that sample. Weighting quantile buckets by \(h_i\) ensures that uncertain samples (high curvature) get finer resolution in split candidates, exactly where it matters most.

2
How It Works Internally
›

At each boosting round, XGBoost computes first-order (\(g_i\)) and second-order (\(h_i\)) gradient statistics for every sample. The Weighted Quantile Sketch algorithm then finds quantile boundaries of the weighted empirical CDF, where the weight of sample \(i\) with feature value \(x_i\) is its hessian \(h_i\).

Formally, define the rank function for feature \(k\):

$$r_k(z) = \frac{1}{\sum_{(x,h)\in\mathcal{D}_k} h} \sum_{\substack{(x,h)\in\mathcal{D}_k \\ x < z}} h$$

This is the fraction of total hessian mass whose feature value is below \(z\). XGBoost selects candidate split points \(\{s_{k,1}, \ldots, s_{k,l}\}\) such that:

$$|r_k(s_{k,j}) - r_k(s_{k,j+1})| < \epsilon$$

where \(\epsilon\) is the approximation factor. This guarantees roughly \(1/\epsilon\) candidate splits per feature — completely independent of dataset size.

Histogram Binning

After candidate splits are fixed, XGBoost builds a gradient histogram: for each bin \(b\), accumulate \(G_b = \sum_{i \in b} g_i\) and \(H_b = \sum_{i \in b} h_i\). The gain of splitting at any boundary is then computed directly from \(G_b, H_b\) — no need to touch individual samples again.

The exact gain formula for splitting node \(t\) into left \(L\) and right \(R\) children is:

$$\text{Gain} = \frac{1}{2}\left[\frac{G_L^2}{H_L+\lambda} + \frac{G_R^2}{H_R+\lambda} - \frac{(G_L+G_R)^2}{H_L+H_R+\lambda}\right] - \gamma$$

where \(\lambda\) is the L2 leaf-weight regulariser and \(\gamma\) is the minimum gain threshold (pruning). This is evaluated once per bin boundary — O(#bins) — not once per sample.

3
Why It Works: The Math
›

XGBoost frames tree construction as minimising a second-order Taylor expansion of the loss. For round \(t\), the objective for a single tree \(f_t\) is:

$$\tilde{\mathcal{L}}^{(t)} = \sum_{i=1}^n \left[ g_i f_t(x_i) + \frac{1}{2} h_i f_t(x_i)^2 \right] + \Omega(f_t)$$

where \(\Omega(f_t) = \gamma T + \frac{\lambda}{2}\sum_{j=1}^T w_j^2\). For a fixed tree structure, the optimal leaf weight in leaf \(j\) is:

$$w_j^* = -\frac{G_j}{H_j + \lambda}, \quad G_j = \sum_{i \in I_j} g_i,\; H_j = \sum_{i \in I_j} h_i$$

And the optimal objective value (score of the tree structure) is:

$$\tilde{\mathcal{L}}^* = -\frac{1}{2}\sum_{j=1}^T \frac{G_j^2}{H_j+\lambda} + \gamma T$$
Why Hessians as Weights

The error committed by approximating the optimal leaf weight with binned statistics is proportional to \(h_i\). Weighting bins by \(h_i\) distributes approximation error uniformly across all samples — it is the minimax optimal weighting under the second-order loss expansion.

Common Misconception

People assume the sketch uses uniform quantiles of feature values. It uses hessian-weighted quantiles. For MSE loss, \(h_i = 1\) always, so they coincide — but for logistic loss or custom losses, hessians vary and the difference is significant.

Key Takeaways & When to Use
›
Summary
  • Weighted quantile sketch → O(1/ε) candidate splits per feature, independent of N
  • Hessian weighting ensures finer resolution where curvature (uncertainty) is highest
  • Histogram aggregation reduces split evaluation from O(N) to O(#bins) per node
  • The gain formula directly follows from the optimal leaf-weight closed form
  • ε ≈ 0.1–0.3 in practice; LightGBM extends with leaf-wise growth and GOSS

Use when: tabular data with millions of rows, needing fast training without sacrificing split quality. The approximation is controlled by ε — smaller ε = more candidates = closer to exact but slower.

Related topics: Gradient Boosting (GBDT), LightGBM (GOSS + EFB), CatBoost (ordered boosting), Decision Tree construction, Second-order optimisation.

Code Trace: From-Scratch Implementation
›

Minimal NumPy implementation of the weighted quantile sketch + histogram gain computation:

import numpy as np
def weighted_quantile_sketch(x, h, eps=0.1):
"""Propose split candidates via hessian-weighted quantiles."""
order = np.argsort(x) # sort by feature value
x_s, h_s = x[order], h[order] # sorted feature + hessian
H_total = h_s.sum() # total hessian mass
cum_h = np.cumsum(h_s) / H_total # weighted CDF
candidates = []
prev_rank = 0.0
for i, (xi, ri) in enumerate(zip(x_s, cum_h)):
if ri - prev_rank >= eps: # bucket boundary exceeded
candidates.append(xi) # propose this value as split point
prev_rank = ri
return np.array(candidates)
def histogram_gain(g, h, splits, x, lam=1.0):
"""Evaluate split gain for each candidate via histograms."""
best_gain, best_split = -np.inf, None
G_tot, H_tot = g.sum(), h.sum()
for s in splits:
mask = x <= s # left bin mask
G_L, H_L = g[mask].sum(), h[mask].sum()
G_R = G_tot - G_L; H_R = H_tot - H_L
gain = 0.5*(G_L**2/(H_L+lam) + G_R**2/(H_R+lam)
- (G_tot)**2/(H_tot+lam))
if gain > best_gain:
best_gain, best_split = gain, s
return best_split, best_gain
