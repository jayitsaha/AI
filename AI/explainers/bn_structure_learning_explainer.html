What is Structure Learning?

A Bayesian network is a directed acyclic graph (DAG) where nodes are random variables and edges encode conditional dependencies. Structure learning is the inverse problem: given a dataset of observations, discover which DAG best explains the data.

Think of it as detective work — you observe symptoms in many patients, and you want to reconstruct the causal web linking genes → proteins → diseases, without being told the network in advance.

💡 Core Insight

Two families of algorithms approach this from opposite directions: score-based methods assign a quality score to each candidate DAG and search for the best-scoring one; constraint-based methods run statistical independence tests to prune and orient edges. Both are provably NP-hard in general.

Why it's hard

The space of DAGs over \(d\) nodes grows super-exponentially: roughly \(2^{d^2/2}\) graphs. Exact search is feasible only for \(d \lesssim 20\). Greedy heuristics and independence-test oracles dominate practical use.

2
Score-Based: Searching DAG Space

Define a scoring function \(S(G, \mathcal{D})\) that measures how well DAG \(G\) fits dataset \(\mathcal{D}\). Common choices:

$$\text{BIC}(G, \mathcal{D}) = \log P(\mathcal{D} \mid \hat{\theta}_G) - \frac{d_G}{2}\log N$$

where \(d_G\) is the number of free parameters (penalizes complexity) and \(N\) is the number of samples. The BDeu score is a Bayesian marginal likelihood under a Dirichlet prior — both decompose node-by-node, enabling local search.

🔑 Decomposability

Both BIC and BDeu decompose: \(S(G,\mathcal{D}) = \sum_{i=1}^d s(X_i, \text{Pa}(X_i), \mathcal{D})\). This lets Greedy Equivalence Search (GES) score local edge additions/removals independently — only recompute the touched node's local score.

GES Algorithm (2 phases)

  • Forward phase: Start from the empty graph. Greedily add edges that increase \(S\) most until no single addition helps.
  • Backward phase: Greedily remove edges that increase \(S\) until no single deletion helps.
⚠️ NP-Hardness

Finding the globally optimal DAG under BIC is NP-hard (Chickering 1996). GES finds the Markov-equivalent optimal DAG in the large-sample limit (Chickering 2002), but can be trapped in local optima at finite \(N\).

3
Constraint-Based: The PC Algorithm

The PC algorithm (Peter-Clark, Spirtes et al. 1993) leverages the Markov property: \(X\) and \(Y\) are d-separated by set \(Z\) in \(G\) if and only if \(X \perp\!\!\!\perp Y \mid Z\) in the true distribution.

Phase 1 — Skeleton Discovery (undirected)

  1. Start with the complete undirected graph.
  2. For \(|S|=0,1,2,\ldots\): for each adjacent pair \((X,Y)\), test \(X \perp\!\!\!\perp Y \mid S\) for all \(S \subseteq \text{Adj}(X)\setminus\{Y\}\) with \(|S|=k\). If independence found, remove edge and record sepset\((X,Y) = S\).
  3. Halt when no conditioning set of size \(k\) separates any adjacent pair.

Phase 2 — V-structure Orientation

For each unshielded triple \(X - Z - Y\) (where \(X\) and \(Y\) are not adjacent): if \(Z \notin\) sepset\((X,Y)\), orient as \(X \to Z \leftarrow Y\) (a collider). Then apply Meek's orientation rules to propagate additional orientations without introducing new v-structures or cycles.

$$\chi^2 \text{ test (discrete):} \quad T = N \sum_{x,y,z} \frac{(\hat{P}(x,y,z) - \hat{P}(x|z)\hat{P}(y|z)\hat{P}(z))^2}{\hat{P}(x|z)\hat{P}(y|z)\hat{P}(z)}$$
$$\text{Fisher Z (Gaussian):} \quad Z_{xy.S} = \frac{1}{2}\ln\frac{1+\hat{\rho}_{xy.S}}{1-\hat{\rho}_{xy.S}}, \quad \sqrt{N-|S|-3}\,Z_{xy.S} \sim \mathcal{N}(0,1)$$
Key Guarantee

Under faithfulness and with a perfect (oracle) independence test, PC recovers the Markov equivalence class (CPDAG) of the true DAG in polynomial time — \(O(d^{|\text{max-degree}|+1})\) tests in the worst case.

🎯 Decision Rule

Use score-based (GES / hill-climbing) when you have continuous/Gaussian data or want a single best DAG quickly. Use constraint-based (PC / FCI) when you have abundant data, the graph is sparse, and you suspect latent confounders (FCI). Hybrid methods (e.g., MMHC) run PC first to restrict the search space, then score-based search — best of both worlds.

Why NP-Hard?

The number of DAGs over \(d\) nodes follows the OEIS sequence A003024 — it grows faster than \(2^{d(d-1)/2}\). Exhaustive search is infeasible beyond \(d \approx 20\). Score-based exact algorithms (DP over subsets) run in \(O(2^d \cdot d)\) — practical only for \(d \lesssim 25\). PC is polynomial but in the number of CI tests per adjacency, which itself can be exponential in max degree.
