Incremental PCA for Large Datasets

Online subspace estimation — update principal components one mini-batch at a time, bounded memory
Intermediate Unsupervised Learning Dimensionality Reduction O(d²k) per batch
1
Understanding Incremental PCA
▼

What is it? Ordinary PCA loads the entire dataset into RAM, builds a covariance matrix, and decomposes it. With millions of rows or streaming data that never ends, that is simply impossible. Incremental PCA (IPCA) solves this by processing one small mini-batch at a time, updating the principal component estimate after each batch, and discarding the raw data. Memory usage stays constant no matter how many samples arrive.

Analogy: Imagine you are trying to find the longest axis of a cloud of points, but the points arrive one boxcar at a time on a conveyor belt — you cannot see all of them at once. After each boxcar you update your best guess for the main axis, then let the data roll away. After enough boxcars your guess converges to the same axis you would have found if you had seen everything at once.

💡 If you remember one thing

IPCA uses a rank-\(k\) incremental SVD: after each mini-batch \(X_t\), it stacks the current component sketch \(U_t S_t\) with the new centered data, runs a cheap thin SVD on that tall-but-narrow matrix, and extracts the updated top-\(k\) components. Memory is \(O(dk)\), not \(O(nd)\).

2
How Incremental PCA Works Internally
▼

The Core Update Step

Let \(n_t\) be samples seen so far, with running mean \(\mu_t\) and component matrix \(U_t \in \mathbb{R}^{d \times k}\) (orthonormal columns) weighted by singular values \(S_t\). A new batch \(X_b \in \mathbb{R}^{b \times d}\) arrives.

Step 1 — Update the mean. The global mean is a weighted average of old mean and batch mean \(\bar{x}_b\):

$$\mu_{t+1} = \frac{n_t \mu_t + b\,\bar{x}_b}{n_t + b}$$

Step 2 — Centre the batch and correct for mean shift. Two correction vectors must be included: the mean-shift correction \(\sqrt{\frac{n_t b}{n_t+b}}(\bar{x}_b - \mu_t)\), and the centred batch rows \(X_b - \bar{x}_b\mathbf{1}^\top\).

Step 3 — Build the augmented matrix. Stack the old sketch with the new data:

$$M = \begin{bmatrix} S_t U_t^\top \\ X_b - \bar{x}_b \mathbf{1}^\top \\ \sqrt{\tfrac{n_t b}{n_t+b}}(\bar{x}_b - \mu_t)^\top \end{bmatrix} \in \mathbb{R}^{(k+b+1)\times d}$$

Step 4 — Thin SVD. Compute \(M = U' S' V'^\top\) and keep only the top \(k\) components: \(U_{t+1} \leftarrow V'[:,:k]\), \(S_{t+1} \leftarrow S'[:k]\). The matrix \(M\) is \((k+b+1) \times d\) — when \(k \ll d\) and \(b \ll n\), this SVD is cheap.

🔑 Key Property — Bounded Memory

The algorithm stores only \(U_t \in \mathbb{R}^{d\times k}\), \(S_t \in \mathbb{R}^k\), and \(\mu_t \in \mathbb{R}^d\). No matter how many samples \(n \to \infty\), memory remains \(O(dk)\). The cost per batch is \(O(b d k)\) for centering plus \(O((k+b)^2 d)\) for the thin SVD.

Why the Mean Correction Term?

If the running mean drifts when a new batch arrives, the old sketch \(U_t S_t\) was computed relative to the old mean. The correction term \(\sqrt{\frac{n_t b}{n_t+b}}(\bar{x}_b-\mu_t)\) exactly compensates so the combined covariance estimate stays consistent — without it the estimated components would be biased toward the old centre.

⚠️ Batch Size Trade-off

Very small batches (\(b=1\)) are memory-optimal but the thin SVD on a \((k+2)\times d\) matrix is still \(O(k^2 d)\) per sample — slower per sample than full PCA for modest \(n\). The sklearn default is \(b = k\), balancing update cost and approximation quality. Larger batches converge faster and give better intermediate estimates.

3
Why It Converges — The Math
▼

Exact Equivalence After All Data

Let the full data matrix be \(X \in \mathbb{R}^{n \times d}\) with centred version \(\tilde{X}\). Batch PCA finds the rank-\(k\) truncated SVD of \(\tilde{X} = U_k \Sigma_k V_k^\top\). IPCA maintains an implicit sketch \(A_t\) such that \(A_t^\top A_t\) equals the empirical covariance \(\sum_{i=1}^{n_t}(x_i - \mu_t)(x_i-\mu_t)^\top\) at every step. Therefore:

$$A_n^\top A_n = \tilde{X}^\top \tilde{X} \quad \Rightarrow \quad \text{IPCA eigenvectors} \xrightarrow{n\to\infty} \text{exact PCA eigenvectors}$$

Subspace Error Bound (Ross et al. 2008)

Let \(\hat{V}_k\) be the IPCA subspace after \(n\) samples and \(V_k^*\) be the true top-\(k\) subspace. The reconstruction error satisfies:

$$\|\tilde{X} - \tilde{X}\hat{V}_k\hat{V}_k^\top\|_F^2 = \|\tilde{X} - \tilde{X}V_k^*(V_k^*)^\top\|_F^2$$

This is an exact equality, not an approximation — the IPCA algorithm is algebraically equivalent to full PCA on the seen data. The approximation arises only if one truncates the sketch rank below \(k\).

Online Mean Consistency

The running mean update \(\mu_{t+1} = \frac{n_t \mu_t + b \bar{x}_b}{n_t+b}\) is the Welford/Chan formula for numerically stable online mean, and satisfies:

$$\mu_n = \frac{1}{n}\sum_{i=1}^n x_i \quad \text{(exact, no accumulation error)}$$
📐 Algorithm Invariant

At every step \(t\), the stored sketch satisfies \(U_t S_t^2 U_t^\top = \sum_{i=1}^{n_t}(x_i-\mu_t)(x_i-\mu_t)^\top\). The algorithm maintains this invariant exactly via the augmented SVD update.

Key Takeaways & When to Use
▼

Use IPCA when: your dataset does not fit in RAM, data arrives as a stream, or you need a sliding-window PCA over time. Use standard PCA when all data fits in memory and you can afford the full SVD — it is slightly more numerically stable and there is no hyperparameter to tune.

The algorithm is algebraically exact: given the same data, IPCA and full PCA produce the same components (within floating-point tolerance). The only approximation is in intermediate steps before all data is seen.

💡 Practical Rule of Thumb

Set batch size \(b \geq k\) (number of components wanted). Smaller batches converge more slowly and produce noisier intermediate estimates. sklearn's IncrementalPCA defaults to batch_size = 5 * n_features when no batch size is given, which is very conservative — try \(b = 10k\) for faster convergence.

From-Scratch & Production Code
▼

Minimal NumPy Implementation

import numpy as np
from numpy.linalg import svd
class IncrementalPCA:
def __init__(self, n_components=2):
self.k = n_components
self.n = 0 # total samples seen
self.mean_ = None # running mean
self.components_ = None # (k, d) orthonormal rows
self.singular_values_ = None
def partial_fit(self, X):
n_b, d = X.shape
x_mean = X.mean(axis=0)
if self.n == 0:
# First batch: bootstrap directly
self.mean_ = x_mean
Xc = X - x_mean
_, S, Vt = svd(Xc, full_matrices=False)
self.components_ = Vt[:self.k]
self.singular_values_ = S[:self.k]
self.n = n_b
return
# Mean-shift correction vector
w = np.sqrt(n_b * self.n / (n_b + self.n))
correction = w * (x_mean - self.mean_)
# Update running mean
self.mean_ = (self.n * self.mean_ + n_b * x_mean) / (self.n + n_b)
# Centre the new batch around batch mean
Xc = X - x_mean
# Build augmented matrix: sketch + new data + correction
sketch = self.components_ * self.singular_values_[:, None] # (k,d)
M = np.vstack([sketch, Xc, correction[None, :]]) # (k+b+1, d)
_, S, Vt = svd(M, full_matrices=False)
self.components_ = Vt[:self.k]
self.singular_values_ = S[:self.k]
self.n += n_b
def transform(self, X):
return (X - self.mean_) @ self.components_.T
