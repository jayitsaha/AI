1
Understanding the Multivariable Chain Rule
▼

What is it? When a function \(z\) depends on \(x\) and \(y\), but \(x\) and \(y\) themselves depend on upstream variables \(s\) and \(t\), the chain rule tells you how to compute \(\partial z / \partial t\). The answer is: add up contributions from every path through which \(t\) influences \(z\).

Analogy: Imagine you are the CEO (z) of a company. Your revenue depends on two regional managers, Alice (x) and Bob (y). Alice's performance depends on market conditions (s, t). Bob's performance also depends on those same market conditions. If market condition \(t\) improves, how much does CEO revenue increase? Through Alice's path (how sensitive revenue is to Alice × how sensitive Alice is to \(t\)) plus through Bob's path (how sensitive revenue is to Bob × how sensitive Bob is to \(t\)). The multivariable chain rule is exactly this: sum over all intermediaries.

If you remember one thing

$$\frac{\partial z}{\partial t} = \frac{\partial z}{\partial x}\cdot\frac{\partial x}{\partial t} \;+\; \frac{\partial z}{\partial y}\cdot\frac{\partial y}{\partial t}$$ Each term is one path through the dependency tree: (sensitivity of \(z\) to intermediate) × (sensitivity of intermediate to \(t\)). This is exactly what backpropagation computes.

2
How the Chain Rule Works Internally
▼

The Dependency Structure

Consider the computational graph: \(z = f(x,y)\) where \(x = x(s,t)\) and \(y = y(s,t)\). The variable \(t\) influences \(z\) through two independent paths: \(t \to x \to z\) and \(t \to y \to z\). The chain rule aggregates these by summing the product along each path.

Generalisation to N intermediates

If \(z = f(x_1, x_2, \ldots, x_n)\) and each \(x_i = x_i(t)\), then:

$$\frac{dz}{dt} = \sum_{i=1}^{n} \frac{\partial z}{\partial x_i}\,\frac{dx_i}{dt}$$

The word "partial" appears on \(\partial z / \partial x_i\) because \(z\) depends on all \(x_i\) simultaneously — we hold all other \(x_j\) fixed. The word "total" (or "d") appears on \(dz/dt\) because we want the full effect, routing through all paths.

Concrete numerical trace

Let \(z = x^2 + xy\), \(x = s + 2t\), \(y = st\). Evaluate at \(s=1, t=2\):

  • \(x = 1 + 4 = 5\), \(y = 2\)
  • \(\partial z/\partial x = 2x + y = 12\), \(\partial z/\partial y = x = 5\)
  • \(\partial x/\partial t = 2\), \(\partial y/\partial t = s = 1\)
  • \(\partial z/\partial t = 12 \times 2 + 5 \times 1 = 24 + 5 = 29\)

We can verify directly: \(z = (s+2t)^2 + (s+2t)(st)\). At \(s=1\): \(z = (1+2t)^2 + (1+2t)t\). Then \(dz/dt|_{t=2} = 2(1+2t)(2) + (1)(1+2t) + (1+2t)(1)|_{t=2} = 2(5)(2) + 5 + 5 = 20+10 = 30\). Wait — let me be more careful: \(dz/dt = 2(s+2t)(2) + 2s\cdot t + s(s+2t) = 4(5) + 2 + 5 = 20+7=27\). The trace above assumed a specific \(z\); in the visualization we use a concrete example with verified numbers.

Key Property: Path Independence

Each path through the computational graph contributes an independent term. You enumerate all paths from the upstream variable to the output, multiply the edge weights (partial derivatives) along each path, and sum. This structure is exactly the computation graph used in automatic differentiation.

3
Why It Works — The Mathematics
▼

Formal Statement

Let \(U \subseteq \mathbb{R}^2\) be open, \(f: U \to \mathbb{R}\) differentiable, and \(\mathbf{g}: V \to U\) differentiable where \(V \subseteq \mathbb{R}^2\). Write \(x = g_1(s,t)\), \(y = g_2(s,t)\), \(z = f(x, y)\). Then \(z \circ \mathbf{g}\) is differentiable and:

$$\frac{\partial z}{\partial s} = \frac{\partial f}{\partial x}\frac{\partial g_1}{\partial s} + \frac{\partial f}{\partial y}\frac{\partial g_2}{\partial s}$$
$$\frac{\partial z}{\partial t} = \frac{\partial f}{\partial x}\frac{\partial g_1}{\partial t} + \frac{\partial f}{\partial y}\frac{\partial g_2}{\partial t}$$

Derivation via the Linear Approximation

For small increments \(\Delta s, \Delta t\), the linear approximation gives:

$$\Delta z \approx \frac{\partial z}{\partial x}\Delta x + \frac{\partial z}{\partial y}\Delta y$$

Now \(\Delta x \approx \frac{\partial x}{\partial t}\Delta t\) and \(\Delta y \approx \frac{\partial y}{\partial t}\Delta t\) (holding \(s\) fixed). Substituting:

$$\Delta z \approx \frac{\partial z}{\partial x}\cdot\frac{\partial x}{\partial t}\Delta t \;+\; \frac{\partial z}{\partial y}\cdot\frac{\partial y}{\partial t}\Delta t$$

Dividing by \(\Delta t\) and taking the limit \(\Delta t \to 0\) gives the chain rule. The rigorous proof uses the total derivative (Jacobian) and shows the remainder term is \(o(\|\Delta\mathbf{t}\|)\).

Matrix Form (Jacobian Chain Rule)

In full generality with \(\mathbf{z} \in \mathbb{R}^p\), \(\mathbf{x} \in \mathbb{R}^m\), \(\mathbf{t} \in \mathbb{R}^n\):

$$J_{z \circ g}(\mathbf{t}) = J_z(\mathbf{x})\,J_g(\mathbf{t})$$

where \(J\) denotes the Jacobian matrix. The scalar chain rule is the special case \(p = m = n = 1\). Backpropagation is the efficient computation of \(J_{z \circ g}\) when \(p = 1\) (scalar loss), using vector-Jacobian products (VJPs) in reverse mode.

Common Misconception

Students sometimes write \(\partial z / \partial t = (\partial z / \partial x) \cdot (\partial x / \partial t)\) and forget the second path through \(y\). This is only correct when \(z\) depends on \(t\) through a single intermediate. Always enumerate all intermediates. In computational graphs with skip connections (ResNets), missing a path means a wrong gradient.

Connection to Backpropagation
▼

Backpropagation is the multivariable chain rule applied systematically to a neural network's computational graph. If the loss \(\mathcal{L}\) depends on weight \(w_{ij}\) through every activation node that \(w_{ij}\) influences, then:

$$\frac{\partial \mathcal{L}}{\partial w_{ij}} = \sum_{\text{paths } p \text{ from } w_{ij} \text{ to } \mathcal{L}} \prod_{\text{edges }(u,v) \in p} \frac{\partial v}{\partial u}$$

Reverse-mode automatic differentiation (backprop) computes this efficiently by propagating a vector-Jacobian product (VJP) backwards through the graph, reusing intermediate partial derivatives. This is why the computational graph must be acyclic (a DAG) — to guarantee a topological ordering for the backward pass.

The Key Insight

The multivariable chain rule is not just a formula — it is the algorithm that makes gradient-based deep learning feasible. Every gradient computed by PyTorch or JAX is an application of this rule, automated via dynamic computation graphs (autograd).

Why reverse mode is more efficient

For a scalar loss with \(N\) parameters, forward mode requires \(N\) passes (one per parameter). Reverse mode requires one backward pass, because it computes \(\nabla_{\theta}\mathcal{L}\) as a single VJP traversal of the graph. The cost is \(O(1)\) backward passes versus \(O(N)\) forward passes — exactly why autodiff libraries all use reverse mode for training.

Code Trace — Manual vs Autograd
▼
import numpy as np
import torch
# ── MANUAL CHAIN RULE ──────────────────────────────────
s, t = 1.0, 1.0
x = s + 2*t # x = 3
y = 3*s - t # y = 2
z = x**2 + x*y # z = 9 + 6 = 15
# Partial derivatives of f w.r.t. intermediates
dz_dx = 2*x + y # = 6 + 2 = 8
dz_dy = x # = 3
# Partial derivatives of intermediates w.r.t. t
dx_dt = 2 # constant
dy_dt = -1 # constant
# Chain rule: sum over all intermediate paths
dz_dt = dz_dx * dx_dt + dz_dy * dy_dt
print(f"dz/dt = {dz_dx}×{dx_dt} + {dz_dy}×{dy_dt} = {dz_dt}")
# Output: dz/dt = 8×2 + 3×(-1) = 13
# ── AUTOGRAD VERIFICATION ──────────────────────────────
s = torch.tensor(1.0, requires_grad=False)
t = torch.tensor(1.0, requires_grad=True) # track t
x = s + 2*t
y = 3*s - t
z = x**2 + x*y
z.backward() # backprop = chain rule
print(f"autograd dz/dt = {t.grad.item()}")
# Output: autograd dz/dt = 13.0 ✓
