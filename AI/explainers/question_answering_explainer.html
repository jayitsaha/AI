Understanding Question Answering
▼

What is Question Answering (QA)? QA systems aim to automatically answer questions posed in natural language. Unlike traditional search engines that return a list of documents, QA systems strive to provide direct, concise answers.

There are several paradigms:

  • Extractive QA: The system finds and extracts a span of text directly from a given context (e.g., a document or paragraph) that answers the question. It's like finding the exact sentence or phrase.
  • Generative QA: The system generates a free-form answer in natural language, which may or may not be a direct copy of text from a source document. This allows for more nuanced and synthesized responses.
  • Open-Domain QA: The system can answer questions across a vast collection of documents (e.g., Wikipedia, the entire web) without being given a specific context upfront. This contrasts with Closed-Domain QA, where the context is limited to a small, predefined set of documents.
💡 Key Distinction

Extractive QA is about finding an answer within a text. Generative QA is about creating an answer. Open-Domain QA adds the challenge of finding the relevant text first from a large corpus.

2
How Each QA Type Works
▼

Extractive QA (SQuAD-style)

Models like BERT or RoBERTa are fine-tuned for extractive QA. Given a question and a context paragraph, the model predicts a "start" token and an "end" token within the context. The text span between these two tokens is the answer. This is typically framed as two token classification tasks (one for start, one for end).

Generative QA

Generative models, often based on sequence-to-sequence (seq2seq) architectures (e.g., T5, BART, or larger LLMs), take the question and optionally a context as input and generate the answer word by word. These models are trained to produce coherent and grammatically correct sentences, even synthesizing information if needed.

Open-Domain QA (Retriever-Reader)

This is a two-stage pipeline designed to handle questions without a pre-specified context:

  1. Retriever: Given a natural language query, this component searches a large corpus of documents (e.g., Wikipedia) and retrieves a small set of documents or passages most relevant to the query. This is often done using dense vector embeddings (e.g., DPR - Dense Passage Retriever) where query and document embeddings are compared for similarity.
  2. Reader: The retrieved documents (or passages) are then passed as context to a powerful QA model (either extractive or generative), along with the original question. This reader model then extracts or generates the final answer from the provided relevant contexts.
🔑 Key Component: Context

For both extractive and generative QA, the quality and relevance of the context provided to the model are paramount. Open-domain QA's retriever stage is crucial for providing this high-quality context.

3
The Underlying Math & Mechanisms
▼

Extractive QA: Span Prediction Loss

For extractive QA, a model like BERT outputs a probability distribution over all tokens in the context for being the start of the answer span, and another distribution for being the end. The training objective minimizes the negative log-likelihood (cross-entropy) for the true start and end tokens:

$$L_{ext} = -\frac{1}{N} \sum_{i=1}^N \left[ \log P(s_i | Q_i, C_i) + \log P(e_i | Q_i, C_i) \right]$$

Where \(N\) is the number of examples, \(s_i\) and \(e_i\) are the true start and end token indices for question \(Q_i\) and context \(C_i\).

Generative QA: Sequence Generation Loss

Generative QA models are typically trained with a standard language modeling objective, predicting the next token in the answer sequence given the previous tokens, the question, and context. This is also a form of cross-entropy loss:

$$L_{gen} = -\frac{1}{T} \sum_{t=1}^T \log P(y_t | y_{

Here, \(T\) is the length of the target answer sequence, and \(y_t\) is the \(t\)-th token in the true answer. The model learns to generate the most probable next token given the history.

Retriever: Embedding Similarity

Dense retrievers embed both the query and all passages in the corpus into a high-dimensional vector space. Relevance is then determined by the similarity between these embeddings, often using dot product or cosine similarity. The training objective for the retriever aims to maximize the similarity between a query's embedding and its relevant passages' embeddings, while minimizing similarity with irrelevant ones.

$$Score(Q, D) = E_Q(Q) \cdot E_D(D)$$

Where \(E_Q(Q)\) is the embedding of the query and \(E_D(D)\) is the embedding of a document/passage. A common loss function is a contrastive loss or triplet loss, pushing relevant pairs closer and irrelevant pairs further apart.

⚠️ Challenges

Generative models can hallucinate (make up facts). Extractive models are limited to the context, unable to answer if the information isn't present. Open-domain systems critically depend on the retriever's ability to find relevant documents; a poor retrieval can lead to a poor or no answer.

Key Takeaways & Use Cases
▼

When to use each type:

  • Extractive QA: Best when answers are guaranteed to be direct spans in provided text and factual accuracy is paramount (e.g., legal documents, medical guidelines, SQuAD-like datasets).
  • Generative QA: Ideal for conversational agents, summarization, or when answers require synthesis, rephrasing, or information not directly present as a single span (e.g., chatbots, creative writing, complex reasoning).
  • Open-Domain QA: For general knowledge questions, large enterprise knowledge bases, or when the relevant document is unknown (e.g., search engines, virtual assistants, RAG systems).

Pros and Cons:

  • Extractive: High accuracy on known contexts, easy to verify answers (traceable). Limited to context, cannot synthesize.
  • Generative: Flexible, natural language output, can synthesize. Prone to hallucination, harder to verify, computationally intensive.
  • Open-Domain: Handles vast knowledge, flexible. Performance heavily relies on retriever quality, more complex pipeline.
💡 Hybrid Approaches (RAG)

Many modern systems combine a retriever with a generative reader, often called Retrieval-Augmented Generation (RAG). This leverages the strengths of both: the retriever grounds the generation in factual documents, reducing hallucination, while the generative model provides flexible, natural answers.

import numpy as np
from transformers import AutoTokenizer, AutoModelForQuestionAnswering
from sentence_transformers import SentenceTransformer
# 1. Initialize Models
retriever_model = SentenceTransformer('multi-qa-mpnet-base-dot-v1')
reader_tokenizer = AutoTokenizer.from_pretrained('deepset/roberta-base-squad2')
reader_model = AutoModelForQuestionAnswering.from_pretrained('deepset/roberta-base-squad2')
# 2. Document Corpus (pre-indexed in reality)
documents = [
"The first iPhone was unveiled by Steve Jobs on January 9, 2007, and released in the United States on June 29, 2007. It combined a mobile phone, an iPod, and an internet communications device.",
"Apple Inc. is an American multinational technology company headquartered in Cupertino, California. It designs, develops, and sells consumer electronics, computer software, and online services.",
"The iPhone 3G, the second generation of iPhone, was introduced on June 9, 2008, at the WWDC 2008. It added 3G networking and GPS.",
"Steve Jobs was an American businessman, inventor, and investor best known for co-founding Apple Inc. with Steve Wozniak and Ronald Wayne."
]
doc_embeddings = retriever_model.encode(documents, convert_to_tensor=True)
# 3. User Query
question = "When was the first iPhone released?"
# 4. Retriever Stage

# 5. Reader Stage (for each retrieved context)
