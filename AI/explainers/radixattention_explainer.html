RadixAttention

An efficient attention mechanism for long sequences using radix-based grouping
Intermediate Deep Learning Transformers O(L²/K) complexity
1
Understanding RadixAttention
▼

What is it? RadixAttention is an efficient variant of the self-attention mechanism, designed to reduce the computational cost and memory footprint when processing very long input sequences. Standard self-attention has a quadratic complexity with respect to sequence length (\(O(L^2)\)), making it prohibitive for sequences beyond a few thousand tokens. RadixAttention addresses this by partitioning the input sequence into smaller "radix groups" and performing attention locally within these groups, then combining their outputs.

Analogy: Imagine you have a very long list of names, and for each name, you need to find out how similar it is to every other name on the list. Doing this for every single pair is very time-consuming. RadixAttention is like saying: "Let's split this huge list into 4 smaller sub-lists. Within each sub-list, we'll find similarities (local attention). Then, we'll combine the insights from all four sub-lists to get a final understanding of the whole list." This significantly speeds up the process by avoiding comparisons between names that are very far apart in the original list, while still capturing relevant local relationships.

💡 If you remember one thing

RadixAttention decomposes the standard attention computation into \(K\) independent local attention operations, each on a subsequence of length \(L/K\). This reduces the quadratic \(O(L^2)\) complexity to \(O(L^2/K)\), enabling processing of much longer sequences with manageable computational resources.

2
How RadixAttention Works Internally
▼

The Core Mechanism: Divide and Conquer

RadixAttention operates in three main steps:

  1. Input Partitioning: Given an input sequence of length \(L\) (e.g., a sequence of tokens or features), it is first divided into \(K\) non-overlapping sub-sequences, or "radix groups." Each group therefore has a length of \(L/K\).
  2. Local Attention: Standard self-attention is then applied independently within each of these \(K\) groups. This means that each token in a group can only attend to other tokens within its own group. This is where the significant computational savings come from, as the attention matrices are much smaller.
  3. Output Combination: The outputs from each of the \(K\) local attention operations are concatenated back together to form a single output sequence of length \(L\). This combined output then proceeds to subsequent layers in the transformer block.

This approach maintains a local receptive field for attention, similar to how convolutional layers operate, but with the dynamic weighting of attention. It assumes that most relevant contextual information for a token lies within its local neighborhood, which is often a valid assumption for many tasks.

Design Decision: Trade-offs Between Locality and Globality

The choice of \(K\) (number of radix groups) is a crucial design decision. A larger \(K\) leads to smaller groups, thus greater computational efficiency and memory savings, but it also restricts the receptive field of attention. If \(K=1\), RadixAttention reverts to standard full self-attention. If \(K=L\), each group has length 1, and attention is effectively disabled (each token only attends to itself). The optimal \(K\) depends on the task and the desired balance between efficiency and the need for long-range dependencies. For many natural language tasks, a substantial portion of relevant context is local, making RadixAttention a viable alternative to full attention.

🔑 Key Property

RadixAttention is a form of restricted attention. It sacrifices global attention (where every token can attend to every other token) for computational efficiency, by enforcing a block-diagonal attention mask implicitly through partitioning. This makes it particularly suitable for very long sequences where full global attention is computationally infeasible.

3
Why It Works — The Math
▼

Computational Complexity of Standard Self-Attention

Standard self-attention computes attention scores between all pairs of \(L\) tokens. If \(Q, K, V\) are matrices of shape \((L, d_k)\), the core operation is the matrix multiplication \(Q K^\top\), which results in an \((L, L)\) attention score matrix. Computing this matrix takes \(O(L^2 d_k)\) operations. The subsequent multiplication with \(V\) is \(O(L d_k^2)\). Thus, the dominant term for computational complexity is:

$$\text{Complexity}_{\text{Vanilla}} = O(L^2 d_k)$$

where \(d_k\) is the dimension of keys/queries. This quadratic dependency on \(L\) is the bottleneck for long sequences.

Computational Complexity of RadixAttention

In RadixAttention, the input sequence of length \(L\) is divided into \(K\) groups, each of length \(L' = L/K\). Attention is computed independently within each group. For a single group, the attention computation involves matrices of shape \((L', d_k)\), leading to a complexity of \(O((L')^2 d_k)\).

Since there are \(K\) such independent groups, the total computational complexity for all local attention operations is \(K\) times the complexity of a single group:

$$\text{Complexity}_{\text{Radix}} = K \cdot O((L/K)^2 d_k) = K \cdot O(L^2/K^2 \cdot d_k) = O(L^2/K \cdot d_k)$$

Comparing the two, RadixAttention reduces the quadratic dependency on \(L\) by a factor of \(K\). For example, if \(K=4\), the computation is roughly 4 times faster. This allows for significantly longer sequences to be processed efficiently.

🧮 Example: L=64, K=4

Vanilla attention: \(L^2 = 64^2 = 4096\). RadixAttention: \(L^2/K = 64^2/4 = 4096/4 = 1024\). This is a 4x reduction. The computational savings scale linearly with the number of groups \(K\).

⚠️ Limitations and Considerations

While efficient, RadixAttention inherently limits a token's receptive field. Information flow between tokens in different groups is lost in a single attention layer. To recover some global context, multiple RadixAttention layers might be needed, or it can be combined with other mechanisms (e.g., cross-attention between group summaries, or a global attention head on top of local outputs).

Key Takeaways
▼

When to use RadixAttention:

  • When processing very long sequences (e.g., thousands or tens of thousands of tokens) where standard self-attention's \(O(L^2)\) complexity is prohibitive due to memory or computation constraints.
  • In tasks where local context is predominantly important, such as many natural language processing tasks (e.g., text summarization, machine translation, where adjacent words have strong dependencies).
  • As a building block in hierarchical attention mechanisms, where local RadixAttention layers can be combined with other forms of attention (e.g., sparse attention, global pooling) to gradually build up global context.

When NOT to use / be cautious:

  • For short sequences where the \(O(L^2)\) cost is already manageable. The overhead of partitioning and combining might outweigh the benefits.
  • In tasks where long-range dependencies are absolutely critical and cannot be effectively captured by stacking multiple local attention layers or other global mechanisms.
  • If the computational gains from reducing \(L^2\) to \(L^2/K\) are not significant enough (e.g., if \(K\) is very small, or \(d_k\) is very large and becomes the dominant factor).
💡 Big Picture

RadixAttention is one of many strategies (alongside sparse attention, axial attention, linear attention, etc.) to make transformers scale to longer sequences. It offers a simple, interpretable way to trade off global context for computational efficiency, making it a valuable tool in the efficient transformer toolkit.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
class RadixAttention(nn.Module):
def __init__(self, embed_dim, num_heads, radix_groups):
super().__init__()
self.num_heads = num_heads
self.radix_groups = radix_groups # K
self.head_dim = embed_dim // num_heads
self.scale = self.head_dim ** -0.5
self.qkv = nn.Linear(embed_dim, embed_dim * 3)
self.proj = nn.Linear(embed_dim, embed_dim)
def forward(self, x):
B, L, C = x.shape # Batch, Sequence Length, Embedding Dim
assert L % self.radix_groups == 0, "Sequence length L must be divisible by radix_groups K"
group_len = L // self.radix_groups # L' = L/K
# 1. Generate QKV and split into heads
qkv = self.qkv(x).reshape(B, L, 3, self.num_heads, self.head_dim)
qkv = qkv.permute(2, 0, 3, 1, 4) # 3, B, num_heads, L, head_dim
q, k, v = qkv[0], qkv[1], qkv[2] # B, num_heads, L, head_dim
# 2. Partition into radix groups
# Reshape to (B, num_heads, K, L/K, head_dim)
q_groups = q.reshape(B, self.num_heads, self.radix_groups, group_len, self.head_dim)
k_groups = k.reshape(B, self.num_heads, self.radix_groups, group_len, self.head_dim)
v_groups = v.reshape(B, self.num_heads, self.radix_groups, group_len, self.head_dim)
# 3. Perform local attention within each group
# (B, num_heads, K, L/K, head_dim) @ (B, num_heads, K, head_dim, L/K)
attn_scores = (q_groups @ k_groups.transpose(-2, -1)) * self.scale
attn_probs = attn_scores.softmax(dim=-1)
# (B, num_heads, K, L/K, L/K) @ (B, num_heads, K, L/K, head_dim)
local_out = attn_probs @ v_groups
# 4. Combine outputs from radix groups
out = local_out.reshape(B, self.num_heads, L, self.head_dim)
out = out.transpose(1, 2).reshape(B, L, C) # Concat heads, then groups
return self.proj(out)
