1
Understanding MPC
▼

What is it? Model Predictive Control picks the current action by solving an optimization problem: "given where I am right now, and a model of how the system behaves, what sequence of controls over the next few seconds minimizes cost while staying within limits?" It solves that finite-horizon problem, applies only the very first control from the answer, measures the new state, and solves the whole problem again. This "solve, act once, re-solve" loop is called a receding horizon.

Analogy: Think of driving in fog with headlights that only reach 50 meters. You plan the best path you can see for those 50 meters, steer for the next instant, then look again — because the road (or a pedestrian) may have changed. You never commit blindly to the whole 50-meter plan; you only trust the first sliver of it and keep re-planning as new information arrives.

💡 If you remember one thing

MPC repeatedly solves $$\min_{u_0,\dots,u_{N-1}} \; \sum_{k=0}^{N-1}\Big[\|x_k-x_{ref}\|^2_Q+\|u_k\|^2_R\Big]+\|x_N-x_{ref}\|^2_{Q_f}\quad\text{s.t. } x_{k+1}=f(x_k,u_k),\; u_{min}\le u_k\le u_max$$ then applies only \(u_0^\ast\) and re-solves next step from the newly measured state. This is what separates it from classic feedback control laws that are computed once and never revisited online.

2
How MPC Works Internally
▼

The Receding-Horizon Loop

Every control cycle repeats four steps: (1) measure/estimate the current state \(x_t\); (2) using a model of the system, predict how the state evolves over the next \(N\) steps for candidate control sequences; (3) optimize that sequence to minimize a cost while respecting constraints; (4) apply only the first control \(u_0^\ast\), throw the rest of the plan away, and move to \(t+1\). Discarding the tail of the plan is what makes MPC a feedback controller rather than an open-loop planner — every step gets a fresh measurement to correct for disturbances and model error.

The Role of the Model

The predictions used inside the optimization come entirely from a dynamics model \(x_{k+1}=f(x_k,u_k)\). If the model is linear, \(x_{k+1}=Ax_k+Bu_k\), and the cost is quadratic with linear (box) constraints, the whole problem is a convex Quadratic Program (QP) — this is Linear MPC, solvable fast and reliably every cycle. If \(f\) is nonlinear (robot arms, vehicle dynamics at the limits of friction, aircraft), the problem becomes a nonconvex Nonlinear Program (NLP), solved with SQP, interior-point methods, or iLQR — this is Nonlinear MPC (NMPC). Either way: a bad model produces confidently wrong predictions, so the accuracy of \(f\) bounds how good MPC can ever be, no matter how well the optimizer solves the problem.

Cost: Tracking Error + Control Effort

The stage cost trades off two things: how far predicted states drift from the reference (\(\|x_k-x_{ref}\|^2_Q\)) against how hard the controller pushes (\(\|u_k\|^2_R\)). A terminal cost \(\|x_N-x_{ref}\|^2_{Q_f}\) on the last predicted state discourages the plan from ending in a bad position just outside the visible horizon.

Constraints: What LQR Cannot Do

Actuators saturate (a motor cannot output infinite torque) and states have physical or safety limits (temperature, speed, position). MPC bakes \(u_{min}\le u_k\le u_{max}\) and optionally \(x_{min}\le x_k\le x_{max}\) directly into the optimization at every step, so the returned plan is guaranteed feasible. Classic linear feedback controllers like LQR have no notion of constraints — they must be clamped after the fact, which the controller does not "know" about.

🔑 Prediction Horizon vs Control Horizon

The prediction horizon \(N_p\) is how far ahead the model simulates. The control horizon \(N_c \le N_p\) is how many free control moves the optimizer searches over — after \(N_c\), the control is often held constant to shrink the number of decision variables while still predicting far enough ahead to judge consequences.

3
Why It Works — The Math
▼

The Finite-Horizon Optimal Control Problem

At time \(t\), with measured state \(x_t\), MPC solves:

$$\min_{u_0,\ldots,u_{N-1}} J = \sum_{k=0}^{N-1}\Big[(x_k-x_{ref})^\top Q (x_k-x_{ref}) + u_k^\top R\, u_k\Big] + (x_N-x_{ref})^\top Q_f (x_N-x_{ref})$$

subject to \(x_0=x_t\), \(x_{k+1}=Ax_k+Bu_k\), and \(u_{min}\le u_k\le u_{max}\). With linear dynamics and this quadratic cost, \(J\) is convex in \(U=(u_0,\ldots,u_{N-1})\) and the box constraints keep the feasible set convex — a QP, globally solvable every cycle.

Solving It: Adjoint / Costate Gradient

Our live demo below solves this QP from scratch with projected gradient descent. Differentiating the Lagrangian gives a backward costate recursion, exactly Pontryagin's discrete minimum principle applied to a quadratic problem:

$$\lambda_N = 2Q_f(x_N-x_{ref}), \qquad \lambda_k = 2Q(x_k-x_{ref}) + A^\top \lambda_{k+1}, \qquad \frac{\partial J}{\partial u_k} = 2Ru_k + B^\top \lambda_{k+1}$$

Each iteration rolls the dynamics forward to get \(x_0,\ldots,x_N\), sweeps the costate backward to get every gradient, then takes a projected step \(u_k \leftarrow \text{clip}(u_k - \alpha\,\partial J/\partial u_k,\, u_{min}, u_{max})\). Repeated to convergence, this recovers the constrained optimum — the same object a commercial QP solver (active-set or interior-point) would return, just via a simpler first-order method.

📐 The Unconstrained Special Case

Drop the bounds on \(u_k\) and this exact problem has a closed form: a backward Riccati recursion producing a time-varying gain \(K_k\) with \(u_k^\ast=-K_k(x_k-x_{ref})\). That closed form is finite-horizon LQR. So: unconstrained MPC over a finite horizon reduces to LQR — MPC is LQR's constrained, receding-horizon generalization, not a different theory.

⚠️ Stability Is Not Automatic

A short horizon only "sees" a little way ahead, so the optimizer can be myopic — happily accepting a plan that looks cheap over \(N\) steps but is heading toward trouble beyond the horizon. Formal stability guarantees for MPC typically require a horizon long enough, or a terminal cost/terminal constraint set built from a known Lyapunov function, so the receding-horizon policy behaves like a genuine infinite-horizon controller near the target.

Key Takeaways
▼

Linear MPC vs Nonlinear MPC:

  • Linear MPC: linear model + quadratic cost + box constraints → convex QP every cycle. Fast, reliable, globally optimal per step. Dominant in process control, HVAC, and many robotics/vehicle path-tracking loops.
  • Nonlinear MPC (NMPC): nonlinear dynamics or cost → nonconvex NLP, solved iteratively (SQP, interior-point, iLQR/DDP). Handles more realistic physics (legged robots, aggressive vehicle maneuvers, aerospace) at higher compute cost and without a global-optimality guarantee.

MPC vs LQR — the core distinction the task asked about:

LQRMPC
HorizonInfinite (or fixed, computed once offline)Finite, re-solved online every step
ConstraintsNone built in — clamped ad hoc after the factExplicit \(u_{min}\le u\le u_{max}\), \(x_{min}\le x\le x_{max}\) inside the optimization
Online costOne matrix multiply \(u=-Kx\)Solve a QP/NLP every step
Special case—Unconstrained, infinite-horizon MPC ≡ LQR

MPC is best summarized as "LQR that is constrained and continuously re-planned." When there are no active constraints and the horizon is long enough, the two coincide.

💡 Why re-planning matters even with a perfect model

Re-solving from the freshly measured state every cycle gives MPC implicit feedback against disturbances and small model errors — even though each individual solve assumes the model is exact. An open-loop plan computed once and played back blindly has no such correction.

def dynamics(x, u, dt=0.2):
p, v = x
return [p + v*dt, v + u*dt] # x_{k+1} = A x_k + B u_k
def cost(X, U, x_ref, Q, R, Qf):
J = sum(Q*(X[k][0]-x_ref)**2 + R*U[k]**2 for k in range(len(U)))
J += Qf*(X[-1][0]-x_ref)**2 # terminal cost
return J
def mpc_solve(x0, N, u_min, u_max, iters=150, lr=0.03):
U = [0.0]*N
for _ in range(iters):
X = rollout(x0, U) # forward pass through the model
lam = terminal_costate(X[N]) # backward costate (adjoint)
for k in reversed(range(N)):
grad_k = 2*R*U[k] + B.T @ lam
lam = stage_costate(X[k]) + A.T @ lam
U[k] = clip(U[k] - lr*grad_k, u_min, u_max) # constraint!
return U, rollout(x0, U)
# ---- receding-horizon loop, run every control cycle ----
x = x_measured
while True:
U_star, X_pred = mpc_solve(x, N=8, u_min=-1.2, u_max=1.2)
apply(U_star[0]) # ONLY the first control is used
x = measure_new_state() # everything after is discarded
