CornerNet: Corner-Based Object Detection

An anchor-free approach to object detection by finding paired keypoints
Foundational Deep Learning Computer Vision O(H*W feature map)
1
Understanding CornerNet
▼

What is it? CornerNet (Law & Deng, 2018) revolutionized object detection by proposing an "anchor-free" and "keypoint-based" paradigm. Instead of predicting bounding boxes directly or using predefined anchor boxes, it detects objects by finding a pair of keypoints: the top-left corner and the bottom-right corner of each bounding box. It then groups these detected corner pairs into final bounding boxes.

Analogy: Imagine you're trying to describe a rectangular object to someone without using the word "rectangle" or "box." You might say, "It starts at this point here (top-left) and ends at that point there (bottom-right)." CornerNet does exactly this. It trains a neural network to become an expert at finding these two specific points. If it finds a top-left point and a bottom-right point that seem to belong to the same object, it draws a box between them.

💡 If you remember one thing

CornerNet redefines object detection as a keypoint detection and grouping problem. It leverages a powerful backbone (like Hourglass) to simultaneously predict two heatmaps (one for top-left corners, one for bottom-right), along with "embedding" vectors to help match corners belonging to the same object. This avoids the complex design of anchor boxes and their hyper-parameters.

2
How CornerNet Works Internally
▼

The Architecture: Hourglass Backbone

CornerNet typically employs a stacked Hourglass Network as its backbone. The Hourglass architecture is particularly well-suited for keypoint detection because it repeatedly downsamples and upsamples features, combining multi-scale information to capture both local and global cues, which is crucial for precisely locating small corners in a large image.

Corner Heatmaps and Offsets

The backbone's output is fed into two parallel prediction branches: one for top-left corners and one for bottom-right corners. Each branch predicts:

  • Heatmap: A probability map (one per object class) where high values indicate a high likelihood of a corner being present at that pixel location. During training, ground truth heatmaps are generated using a 2D Gaussian kernel centered at the true corner, allowing nearby pixels to contribute to the loss.
  • Offsets: Since the feature maps are downsampled (e.g., by a factor of 4), a corner detected at integer coordinates \((x, y)\) on the feature map corresponds to a region \((nx, ny)\) to \((n(x+1), n(y+1))\) in the input image. To precisely localize the corner, small sub-pixel offsets \(( \delta_x, \delta_y )\) are predicted for each corner. The actual corner location in the input image is then \((nx + \delta_x, ny + \delta_y)\).

Associative Embeddings for Grouping

This is the core innovation for pairing corners. For each potential corner detected on the heatmaps, the network also predicts a small embedding vector. The key idea is that a top-left corner and a bottom-right corner belonging to the same object should have very similar embedding vectors, while corners from different objects should have distinct embeddings. This allows the network to "associate" two corners together.

Grouping and Bounding Box Formation

After predicting heatmaps, offsets, and embeddings:

  1. Peak Detection: Non-maximum suppression (NMS) is applied to the heatmaps to find local peaks, which are considered candidate corners.
  2. Offset Correction: The predicted offsets are applied to refine the candidate corner locations.
  3. Corner Pairing: For every detected top-left corner and every detected bottom-right corner (of the same class), their embedding vectors are compared. If the distance between their embeddings is below a certain threshold, they are considered a potential pair for a bounding box.
  4. Final NMS: Candidate bounding boxes are formed from these pairs. A final NMS step is applied to these boxes, usually based on their average corner scores, to produce the final set of non-overlapping detections.
🔑 Key Property

CornerNet's strength lies in its ability to implicitly learn object scales and aspect ratios through corner pairing, completely eliminating the need for manually designed anchor boxes. This simplifies the detection pipeline and reduces hyperparameter tuning related to anchors.

3
Why It Works — The Math
▼

1. Corner Heatmap Loss (Modified Focal Loss)

The heatmap prediction is crucial. Instead of a binary cross-entropy, CornerNet uses a variant of Focal Loss to handle the extreme class imbalance (most pixels are not corners). It also introduces a "penalty reduction" term for false positives that are far from any ground truth corner. Ground truth heatmaps \(Y_{cij}\) are 2D Gaussians centered at true corners, ensuring nearby pixels contribute to the loss.

$$L_{hm} = -\frac{1}{N} \sum_{c=1}^C \sum_{i=1}^H \sum_{j=1}^W \begin{cases} (1 - p_{cij})^\alpha \log(p_{cij}) & \text{if } Y_{cij}=1 \\ (1 - Y_{cij})^\beta (p_{cij})^\alpha \log(1 - p_{cij}) & \text{otherwise} \end{cases}$$

Here, \(p_{cij}\) is the predicted confidence for class \(c\) at location \((i,j)\), \(N\) is the number of objects, and \(\alpha, \beta\) are hyperparameters. The second case (for \(Y_{cij} \neq 1\)) is the key: false positives far from a true corner are down-weighted by \((1 - Y_{cij})^\beta\), where \(Y_{cij}\) is the Gaussian value at that location. This focuses training on "hard" negative examples close to ground truth corners.

2. Associative Embedding Loss

This loss function encourages embeddings of corners from the same object to be close, and embeddings of corners from different objects to be far apart. It consists of two parts: a "pull" loss and a "push" loss.

$$L_{pull} = \frac{1}{N} \sum_{k=1}^N \left[ (e_{t_k} - e_k)^2 + (e_{b_k} - e_k)^2 \right]$$

The pull loss minimizes the distance between the top-left embedding \(e_{t_k}\) and a "mean" embedding \(e_k\) (which is the average of \(e_{t_k}\) and \(e_{b_k}\)) for the \(k\)-th object, and similarly for the bottom-right embedding \(e_{b_k}\). This pulls the embeddings of paired corners together.

$$L_{push} = \frac{1}{N} \sum_{k=1}^N \sum_{j \neq k} \left[ \max(0, \Delta - |e_k - e_j|)^2 \right]$$

The push loss maximizes the distance between the mean embeddings of different objects \(k\) and \(j\), up to a margin \(\Delta\). This pushes embeddings of unpaired corners away from each other. In practice, \(e_k\) is typically just \(e_{t_k}\) and \(e_j\) is \(e_{b_j}\) for simplified implementation, comparing all TL-BR pairs.

3. Offset Loss

The offset prediction loss is a simple L1 loss:

$$L_{off} = \frac{1}{N} \sum_{k=1}^N \left[ \left| o_{t_k} - \left( \frac{x_{t_k}}{n} - \lfloor \frac{x_{t_k}}{n} \rfloor \right) \right| + \left| o_{b_k} - \left( \frac{x_{b_k}}{n} - \lfloor \frac{x_{b_k}}{n} \rfloor \right) \right| \right]$$

This loss ensures that the predicted offsets \(o_{t_k}, o_{b_k}\) accurately refine the corner coordinates from the downsampled feature map grid to the original image resolution. \(n\) is the downsampling factor (e.g., 4), and \(x_{t_k}\) (or \(x_{b_k}\)) is the ground truth original coordinate.

The total loss for CornerNet is a weighted sum of these components: \(L = L_{hm} + \alpha L_{pull} + \beta L_{push} + \gamma L_{off}\).

Key Takeaways
▼

Strengths of CornerNet:

  • Anchor-Free: Eliminates the need for hand-crafted anchor boxes, which are sensitive to dataset statistics and require careful tuning. This simplifies the pipeline.
  • Efficient for Small Objects: By focusing on keypoints, CornerNet can be very effective at detecting small objects, as keypoint detection is often more robust at fine scales than direct bounding box regression.
  • Implicit Scale/Aspect Ratio Learning: The network learns to group corners, implicitly inferring object dimensions rather than relying on predefined box ratios.
  • Strong Backbone Leverage: Benefits greatly from powerful feature extractors like Hourglass networks, which excel at dense keypoint prediction.

Limitations of CornerNet:

  • Grouping Challenge: The associative embedding mechanism can be prone to false positives (incorrect pairings) or false negatives (missing true pairings), especially in crowded scenes.
  • Corner Definition: Objects without clear, sharp corners (e.g., a circular object) might be harder for CornerNet to detect reliably.
  • Occlusion Sensitivity: If a corner is heavily occluded, the network might fail to detect it, leading to a missed object.
  • Computational Cost: Hourglass networks are computationally intensive, making CornerNet slower than some single-stage detectors.
💡 Evolution

CornerNet paved the way for many subsequent anchor-free object detectors (e.g., CenterNet, ExtremeNet, FCOS). Its core idea of detecting keypoints and then forming boxes from them has proven to be a powerful alternative to anchor-based methods, influencing the design of modern detection architectures.

Code Trace (Simplified PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
import torch.nn.functional as F
# Simplified CornerNet Head (after Hourglass backbone)
class CornerNetHead(nn.Module):
def __init__(self, num_classes, in_channels):
super().__init__()
# Top-Left branch
self.tl_heatmap = nn.Conv2d(in_channels, num_classes, 1)
self.tl_embedding = nn.Conv2d(in_channels, 1, 1) # 1D embedding per pixel
self.tl_offset = nn.Conv2d(in_channels, 2, 1) # (dx, dy) offset
# Bottom-Right branch (similar structure)
self.br_heatmap = nn.Conv2d(in_channels, num_classes, 1)
self.br_embedding = nn.Conv2d(in_channels, 1, 1)
self.br_offset = nn.Conv2d(in_channels, 2, 1)
def forward(self, features):
tl_hm = torch.sigmoid(self.tl_heatmap(features))
tl_emb = self.tl_embedding(features)
tl_off = self.tl_offset(features)
br_hm = torch.sigmoid(self.br_heatmap(features))
br_emb = self.br_embedding(features)
br_off = self.br_offset(features)
return tl_hm, tl_emb, tl_off, br_hm, br_emb, br_off
# Simplified Inference (after getting predictions)
def group_and_decode_boxes(tl_hm, tl_emb, tl_off, br_hm, br_emb, br_off,
score_thresh=0.1, emb_thresh=0.5, downsample_factor=4):
# 1. Extract peaks from heatmaps (simplified NMS)
# In real CornerNet, this involves 3x3 max pooling and thresholding
tl_peaks = (tl_hm > score_thresh).nonzero(as_tuple=True) # (class, y, x)
br_peaks = (br_hm > score_thresh).nonzero(as_tuple=True)
final_boxes = []
for tl_idx in range(len(tl_peaks[0])):
tl_c, tl_y, tl_x = tl_peaks[0][tl_idx], tl_peaks[1][tl_idx], tl_peaks[2][tl_idx]
tl_e = tl_emb[0, 0, tl_y, tl_x] # assuming batch=1, emb_dim=1
tl_ox = tl_off[0, 0, tl_y, tl_x]
tl_oy = tl_off[0, 1, tl_y, tl_x]
# Refine TL coords to original image scale
x1 = (tl_x + tl_ox) * downsample_factor
y1 = (tl_y + tl_oy) * downsample_factor
for br_idx in range(len(br_peaks[0])):
br_c, br_y, br_x = br_peaks[0][br_idx], br_peaks[1][br_idx], br_peaks[2][br_idx]
# Only consider same class and valid geometry (br_x > tl_x, br_y > tl_y)
if tl_c != br_c or br_x <= tl_x or br_y <= tl_y: continue
br_e = br_emb[0, 0, br_y, br_x]
br_ox = br_off[0, 0, br_y, br_x]
br_oy = br_off[0, 1, br_y, br_x]
x2 = (br_x + br_ox) * downsample_factor
y2 = (br_y + br_oy) * downsample_factor
# 2. Compare embeddings
if torch.abs(tl_e - br_e) < emb_thresh:
# 3. Combine scores and add to final list
score = (tl_hm[0, tl_c, tl_y, tl_x] + br_hm[0, br_c, br_y, br_x]) / 2
final_boxes.append({'box': [x1, y1, x2, y2], 'score': score, 'class': tl_c})
# 4. Apply final NMS (not shown here for brevity)
return final_boxes
