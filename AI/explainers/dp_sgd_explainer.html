DP-SGD: Training with Privacy Guarantees

Differentially private stochastic gradient descent: clipping gradients and adding noise
Intermediate Privacy Deep Learning O(N) per step
1
Understanding DP-SGD
▼

What is it? DP-SGD (Differentially Private Stochastic Gradient Descent) is a modification of the standard SGD algorithm that provides a mathematical guarantee of privacy for individual training data points. It ensures that the trained model's parameters reveal very little about any single person's data, protecting against membership inference attacks and other privacy breaches.

Analogy: Imagine a group of chefs (the model) learning to bake a cake (the task) from individual recipes (data points). Standard SGD lets each chef taste a recipe and adjust their technique. If one chef has a very unique, secret ingredient, the final cake might subtly hint at that ingredient. DP-SGD is like making sure each chef only gives feedback that's capped in intensity (gradient clipping) and then mixing all the feedback with a bit of random noise before adjusting the master recipe. This way, no single secret ingredient can be easily reverse-engineered from the final cake.

💡 If you remember one thing

DP-SGD protects privacy by two main mechanisms during gradient computation: clipping individual gradients to a maximum L2 norm (to limit influence) and adding Gaussian noise to the aggregated gradients (to obscure individual contributions). This ensures that adding or removing a single data point from the training set has a negligible effect on the final model, quantified by the privacy budget \((\epsilon, \delta)\).

How DP-SGD Works Internally
▼

The Standard SGD Update

In standard SGD, for each batch of data, we compute the gradient of the loss with respect to the model parameters \(\nabla L(w)\), and update the weights as \(w_{t+1} = w_t - \eta \nabla L(w_t)\). The batch gradient is typically an average of individual gradients: \(\nabla L(w) = \frac{1}{N} \sum_{i=1}^N \nabla L_i(w)\).

The DP-SGD Modifications

DP-SGD modifies this process in three key ways, applied per mini-batch:

  1. Compute per-example gradients: Instead of a single batch gradient, compute \(\nabla L_i(w)\) for each individual data point \(x_i\) in the mini-batch.
  2. Clip individual gradients: For each \(\nabla L_i(w)\), if its L2 norm \(\|\nabla L_i(w)\|_2\) exceeds a predefined clipping threshold \(C\), scale it down so its norm is exactly \(C\). This limits the maximum influence any single example can have.
  3. Average and add noise: Sum the clipped gradients, then add Gaussian noise with scale \(\sigma C\) to this sum. Finally, divide by the batch size \(N\) to get the noisy average gradient, which is then used for the weight update.

This process guarantees that the model update is almost indistinguishable whether a specific data point was included or excluded from the training set, thus providing differential privacy.

Design Decision: Why Clip *Before* Noise?

Clipping is crucial because differential privacy requires bounding the "sensitivity" of the query (in this case, the gradient computation). If individual gradients could be arbitrarily large, the noise required to mask them would also have to be arbitrarily large, making the training ineffective. Clipping sets an upper bound on the influence of any single example, allowing a fixed amount of noise to provide meaningful privacy guarantees.

🔑 Key Property

The privacy budget \((\epsilon, \delta)\) in DP-SGD is not fixed per step, but accumulates over the entire training process. Lower noise \(\sigma\) or smaller clipping threshold \(C\) (relative to gradient magnitudes) generally lead to a tighter privacy budget (smaller \(\epsilon\)), but can hurt model utility. There's a fundamental trade-off between privacy and accuracy.

Why It Works — The Math
▼

The DP-SGD Update Rule

For each training step \(t\), given current weights \(w_t\) and a mini-batch of \(N\) examples \(B = \{x_1, \dots, x_N\}\):

  1. Individual Gradients: Compute \(\nabla L_i(w_t)\) for each \(x_i \in B\).
  2. Clipping: For each \(i\), define the clipped gradient \(\tilde{g}_i\) as:
    $$\tilde{g}_i = \frac{\nabla L_i(w_t)}{\max\left(1, \frac{\|\nabla L_i(w_t)\|_2}{C}\right)}$$
    This ensures that \(\|\tilde{g}_i\|_2 \le C\).
  3. Noise Addition and Averaging: Compute the noisy average gradient \(\hat{g}_t\):
    $$\hat{g}_t = \frac{1}{N} \left( \sum_{i=1}^N \tilde{g}_i + \mathcal{N}(0, \sigma^2 C^2 I) \right)$$
    Here, \(\mathcal{N}(0, \sigma^2 C^2 I)\) represents a Gaussian noise vector where each dimension is drawn independently from \(\mathcal{N}(0, \sigma^2 C^2)\). Note that the noise scale is proportional to \(C\).
  4. Weight Update: Update the model weights:
    $$w_{t+1} = w_t - \eta \hat{g}_t$$
    where \(\eta\) is the learning rate.

Privacy Accounting (\(\epsilon, \delta\))

The privacy guarantee is typically expressed using \(( \epsilon, \delta ) \)-differential privacy. For DP-SGD, the total \(\epsilon\) and \(\delta\) after \(T\) steps are usually computed using a composition theorem, often with advanced techniques like Rényi Differential Privacy (RDP) accounting. The key parameters influencing privacy are:

  • Noise Multiplier \(\sigma\): Higher \(\sigma\) means more noise, leading to smaller \(\epsilon\) (better privacy).
  • Clipping Threshold \(C\): Defines the maximum sensitivity of gradients.
  • Sampling Probability \(q\): The fraction of data points sampled in each mini-batch (\(q = N / |\text{Dataset}|\)). Smaller batches (smaller \(q\)) generally offer better privacy.
  • Number of Epochs/Steps \(T\): Privacy budget accumulates with more steps.
⚠️ Common Pitfall

Choosing the right hyperparameters (\(C\), \(\sigma\), \(\eta\)) for DP-SGD is notoriously difficult. A high \(\sigma\) (more noise) improves privacy but often dramatically reduces model accuracy. A low \(C\) (aggressive clipping) also improves privacy but can distort gradients and slow down convergence. Finding the optimal balance for a given task and privacy budget often requires extensive tuning and understanding of the data's gradient distribution.

Key Takeaways
▼

When to use DP-SGD:

  • When training on sensitive user data (e.g., medical records, financial data, personal communications) where strong privacy guarantees are legally or ethically required.
  • When the risk of membership inference attacks or reconstruction attacks on the training data is a concern.
  • In federated learning settings where models are trained on decentralized user data, to protect individual client contributions.

When NOT to use / Challenges:

  • When model accuracy is paramount and a slight drop in performance is unacceptable. DP-SGD almost always introduces some utility cost.
  • For very small datasets, as the noise can easily overwhelm the signal.
  • When computational resources are extremely limited, as per-example gradient computation and clipping add overhead.
  • When fine-tuning pre-trained models, as the privacy budget can quickly accumulate, and it's unclear how much privacy is truly gained for the fine-tuning data if the base model was not privately trained.
💡 The Privacy-Utility Trade-off

DP-SGD offers a powerful privacy guarantee, but it comes at a cost. The parameters \(C\) and \(\sigma\) directly control this trade-off: increasing \(\sigma\) (more noise) or decreasing \(C\) (more aggressive clipping) improves privacy (smaller \(\epsilon\)) but typically reduces the model's utility (accuracy/performance). The art of using DP-SGD lies in carefully balancing these factors to achieve an acceptable level of privacy without rendering the model useless.

import torch.nn as nn
from opacus.accountants import RDPAccountant # For privacy accounting
# Hyperparameters for DP-SGD
clip_norm = 1.0 # C: L2 clipping threshold
noise_multiplier = 0.5 # σ: Noise scale
learning_rate = 0.1 # η
batch_size = 64
num_epochs = 10
model = nn.Linear(input_dim, output_dim)
optimizer = torch.optim.SGD(model.parameters(), lr=learning_rate)
criterion = nn.BCEWithLogitsLoss(reduction='none') # important: no reduction for per-example gradients
accountant = RDPAccountant()
for epoch in range(num_epochs):
for i, (data, target) in enumerate(dataloader):
optimizer.zero_grad()
# 1. Compute per-example gradients
logits = model(data)
losses = criterion(logits, target) # (batch_size,) tensor of individual losses
per_sample_gradients = []
for loss in losses:
loss.backward(retain_graph=True) # Compute gradient for each loss
flat_grad = torch.cat([p.grad.flatten() for p in model.parameters()])
per_sample_gradients.append(flat_grad)
model.zero_grad() # Clear for next sample's gradient
per_sample_gradients = torch.stack(per_sample_gradients) # (batch_size, grad_dim)
# 2. Clip individual gradients
l2_norms = per_sample_gradients.norm(2, dim=1, keepdim=True)
clipping_factor = torch.min(torch.ones_like(l2_norms), clip_norm / l2_norms)
clipped_gradients = per_sample_gradients * clipping_factor
# 3. Aggregate and add Gaussian noise
sum_clipped_gradients = clipped_gradients.sum(dim=0)
noise = torch.randn_like(sum_clipped_gradients) * noise_multiplier * clip_norm
noisy_gradient = (sum_clipped_gradients + noise) / batch_size
# 4. Apply noisy gradient to model parameters
# Manually set gradients for optimizer step (or use a custom DP optimizer)
start_idx = 0
for p in model.parameters():
param_grad_len = p.numel()
p.grad = noisy_gradient[start_idx : start_idx + param_grad_len].reshape(p.shape)
start_idx += param_grad_len
optimizer.step()
