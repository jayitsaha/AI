Understanding Pretext Tasks
▼

What are they? Pretext tasks are a core component of self-supervised learning (SSL). Instead of relying on human-annotated labels (which are expensive and scarce), SSL algorithms create artificial "pretext" labels directly from the unlabeled data itself. A neural network is then trained to solve this pretext task. The key idea is that to solve these tasks, the network must learn rich, semantically meaningful visual representations, which can then be transferred to downstream tasks (like classification or object detection) with far fewer labeled examples.

Analogy: Imagine you want to teach a child about the world, but you don't have time to label every object. Instead, you give them a series of games: "Here's a picture, tell me if it's upside down," or "Here are scrambled pieces of a photo, put them back together." To solve these games, the child implicitly learns about objects, shapes, and spatial relationships. The games (pretext tasks) aren't the final goal, but they're a powerful way to acquire general knowledge (visual features) that can later be applied to specific problems.

💡 If you remember one thing

Pretext tasks leverage the inherent structure of unlabeled data to generate free supervisory signals. The true "output" is not the solution to the pretext task itself, but the powerful feature encoder learned in the process, which can then be fine-tuned for real-world tasks.

2
How It Works: Common Pretext Tasks
▼

The general workflow for a pretext task involves: (1) taking an unlabeled input (e.g., an image), (2) applying a transformation to it, and (3) defining a "pretext label" based on that transformation. A neural network (typically a standard encoder like ResNet) is trained to predict this pretext label. After training, the final prediction head is discarded, and the trained encoder is used as a feature extractor.

Rotation Prediction (Gidaris et al., 2018)

An image is rotated by 0°, 90°, 180°, or 270°. The network's task is to predict which of these four rotations was applied. To succeed, the model must learn to recognize objects and their canonical orientations (e.g., a car typically has wheels at the bottom, not the side). This forces the encoder to learn strong object-centric features.

Jigsaw Puzzle (Noroozi & Favaro, 2016)

An image is divided into a grid of \(N \times N\) patches (e.g., \(3 \times 3\)). These patches are then randomly shuffled and presented to the network. The task is to predict the original permutation of the patches. This requires the model to understand spatial context, object parts, and how they fit together, leading to robust local and global feature learning.

Colorization (Zhang et al., 2016)

A color image is converted to grayscale. The network is then tasked with predicting the original color values (e.g., in the Lab color space, or by classifying into quantized color bins) for each pixel. To accurately colorize, the model must infer the semantic content of regions (e.g., grass is green, sky is blue, faces are skin-toned), thereby learning high-level object and scene understanding.

Inpainting (Pathak et al., 2016)

A rectangular region of an image is masked out (e.g., filled with a constant color or noise). The network's goal is to reconstruct the missing pixels in the masked region. This forces the model to learn about contextual relationships and to generate plausible visual content based on surrounding information, fostering a strong understanding of object completion and scene structure.

🔑 Key Property

The common thread is that solving these tasks requires semantic understanding of the image, even though no human-provided semantic labels were used for training. This "implicit" learning makes the extracted features highly effective for a wide range of downstream tasks.

3
Why It Works: Mathematical Formulation
▼

The core idea behind pretext tasks is to define a loss function that encourages the neural network's encoder \(f_\theta\) to learn useful features. Let \(x\) be an unlabeled image, \(T(\cdot)\) be a transformation function, and \(P(\cdot)\) be a function that extracts the pretext label from the transformed image. The general objective is:

$$\min_\theta \mathbb{E}_{x \sim \mathcal{D}} [ L(f_\theta(T(x)), P(x)) ]$$

where \(L\) is a suitable loss function (e.g., cross-entropy for classification, L2 for regression).

Rotation Prediction Loss

For rotation prediction, the input image \(x\) is transformed by one of four rotations \(R_j \in \{0^\circ, 90^\circ, 180^\circ, 270^\circ\}\). The pretext label is the index \(j\) corresponding to the applied rotation. The model outputs a probability distribution over the four classes, and we use cross-entropy loss:

$$L_{rot} = -\frac{1}{B} \sum_{i=1}^{B} \sum_{j=0}^{3} \mathbb{I}(R_j(x_i))_j \log \sigma(f_\theta(R_j(x_i)))_j$$

Here, \(B\) is the batch size, \(\mathbb{I}(R_j(x_i))_j\) is 1 if rotation \(j\) was applied (0 otherwise), and \(\sigma(\cdot)\) is the softmax function over the model's output logits for the four rotation classes.

Jigsaw Puzzle Loss

For jigsaw, the image is divided into \(N \times N\) patches, which are then shuffled according to one of \(K\) predefined permutations \(\pi_k\). The model's task is to predict the index \(k\) of the permutation used. With a fixed set of \(K\) permutations, this also becomes a multi-class classification problem:

$$L_{jig} = -\frac{1}{B} \sum_{i=1}^{B} \sum_{k=1}^{K} \mathbb{I}(\pi_k(x_i))_k \log \sigma(f_\theta(\pi_k(x_i)))_k$$

The design choice for \(K\) is important; too many permutations make the task too hard (random guess), too few make it too easy (trivial features).

Inpainting Loss

For inpainting, a mask \(M\) is applied to the image, and the model \(\hat{x} = f_\theta(x \odot (1-M))\) attempts to reconstruct the original image \(x\). The loss is typically an L1 or L2 distance between the reconstructed masked region and the true masked region, sometimes combined with a perceptual loss:

$$L_{inpainting} = \| M \odot (\hat{x} - x) \|_1 + \lambda L_{perc}(\hat{x}, x)$$

The mask \(M\) is a binary matrix (1 for masked pixels, 0 otherwise), and \(L_{perc}\) measures the difference in high-level features extracted by another (pre-trained) network.

⚠️ Common Pitfall

The primary goal is learning transferable features, not achieving high accuracy on the pretext task itself. A model that perfectly solves a trivial pretext task might learn poor features, while one that struggles with a challenging pretext task might learn very robust features. Task difficulty and careful design are crucial.

Key Takeaways
▼

When to use pretext tasks:

  • Limited Labeled Data: When human annotation is expensive or scarce (e.g., medical imaging, specialized scientific datasets). Pretraining provides a strong initialization.
  • Domain Adaptation: To adapt a model to a new domain where labeled data is sparse but unlabeled data is abundant. The model can learn domain-specific features without cross-domain label shifts.
  • Robust Feature Learning: Pretext tasks often lead to more robust and generalizable features compared to supervised pretraining, especially if the pretext task encourages diverse forms of understanding (e.g., combining spatial and semantic tasks).
  • Computational Efficiency: Once a strong feature extractor is learned, fine-tuning for downstream tasks can be much faster and require less compute than training from scratch.

When NOT to use:

  • Abundant Labeled Data: If you have a massive, well-curated labeled dataset for your target task (e.g., ImageNet for classification), supervised pretraining might be simpler and more effective.
  • Simple Tasks: For very simple downstream tasks that don't require complex visual understanding, the overhead of pretext task training might not be justified.
  • Computational Constraints: Training a model on pretext tasks can still be computationally intensive, requiring large datasets and significant GPU time, although less than a full supervised training from scratch on diverse tasks.
💡 Big Picture: Relation to Contrastive Learning

Pretext tasks are a specific form of self-supervised learning. Another major branch is contrastive learning (e.g., SimCLR, MoCo), which learns representations by pulling "positive pairs" (different augmented views of the same image) closer in embedding space, and pushing "negative pairs" (views of different images) further apart. While pretext tasks often rely on explicit classification/regression, contrastive methods learn implicitly through similarity metrics. Both aim to learn powerful, transferable encoders from unlabeled data.

self.backbone.fc = nn.Identity() # Remove original FC layer

return self.backbone(x)

features = self.encoder(x)
return self.classifier(features)
