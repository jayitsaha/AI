1
Understanding BLIP
▼

What is it? BLIP is a vision-language model that learns to understand and generate captions for images by training on hundreds of millions of image-text pairs scraped from the web. The catch: web alt-text is notoriously noisy (mismatched, generic, or irrelevant). BLIP's big idea, CapFilt (Captioning and Filtering), is to use the model itself to clean its own training data — a captioner writes better synthetic captions, and a filter throws out the pairs (real or synthetic) that don't actually match.

Analogy: Imagine hiring an intern to sort a warehouse of mislabeled photos. Instead of a human relabeling millions of items, you train one clerk to write a plausible new label for every photo (the captioner), and a second clerk to reject any label — old or new — that doesn't match the picture (the filter). The warehouse gets cleaner every cycle, and both clerks were trained using only a small, trusted, human-labeled sample to begin with.

💡 If you remember one thing

BLIP is one shared multimodal transformer (MED) trained jointly with three losses — Image-Text Contrastive (ITC), Image-Text Matching (ITM), and Language Modeling (LM) — and bootstraps its own training data via CapFilt: a fine-tuned decoder generates synthetic captions, a fine-tuned encoder filters out noisy pairs, and the model is retrained on the resulting cleaner dataset.

How BLIP Works Internally — MED Architecture
▼

The Mixture of Encoder-Decoder (MED)

BLIP's backbone is a single multimodal transformer that can operate in four functional modes, sharing most of its parameters across them:

  • Unimodal image encoder — a ViT that splits the image into patches and produces a sequence of image embeddings; a [CLS] token summarizes the whole image.
  • Unimodal text encoder — a BERT-style encoder that produces a text embedding via its own [CLS] token, trained with ITC.
  • Image-grounded text encoder — the same text transformer, but with a cross-attention layer inserted between self-attention and the feed-forward block, so every text token can attend to image patch embeddings. Trained with ITM (a binary match/no-match classifier on the output [Encode] token).
  • Image-grounded text decoder — replaces bidirectional self-attention with causal self-attention so the model can only see past tokens, and is trained with LM (autoregressive next-token prediction, i.e., captioning).

Only the self-attention layers differ across the last three text modes; the cross-attention and feed-forward layers are shared. This lets ONE set of weights serve as text encoder, image-grounded encoder, and image-grounded decoder just by swapping the attention mask and, for ITM, adding the cross-attention branch.

Information Flow Per Training Batch

Every image-text pair flows through the network up to three times per step: once through image+text encoders (ITC), once through the image-grounded encoder with cross-attention (ITM), and once through the image-grounded decoder (LM). Gradients from all three losses are summed and backpropagated jointly.

Design Decision: Why Three Losses Instead of One?

ITC alone (like CLIP) aligns global embeddings but has no fine-grained cross-modal fusion — it can't tell you why an image and caption match, only whether their vectors are close. ITM adds token-level fusion via cross-attention so the model learns fine-grained alignment, but is a discriminative task (no generation). LM gives the model the ability to generate captions, which is exactly the capability CapFilt needs for its captioner. Together they cover retrieval (ITC), verification (ITM), and generation (LM) — and, crucially, ITM's hard-negative mining reuses ITC's similarity scores for free.

🔑 Key Property

The captioner used in CapFilt is just the image-grounded text decoder (LM-trained), and the filter is just the image-grounded text encoder (ITM-trained) — CapFilt requires no new architecture, only fine-tuning the two existing MED sub-modules on a small set of human-annotated pairs (e.g. COCO).

Why It Works — The Math of ITC, ITM, LM & CapFilt
▼

Image-Text Contrastive Loss (ITC)

Let \(v\) be the normalized image [CLS] embedding and \(t\) the normalized text [CLS] embedding, with similarity \(s(v,t) = v^\top t\). For a batch of \(N\) pairs, ITC is a symmetric InfoNCE loss over image-to-text and text-to-image directions:

$$\mathcal{L}_{ITC} = -\frac{1}{2}\mathbb{E}\Big[\log\frac{\exp(s(v,t^+)/\tau)}{\sum_{k=1}^N \exp(s(v,t_k)/\tau)} + \log\frac{\exp(s(v^+,t)/\tau)}{\sum_{k=1}^N \exp(s(v_k,t)/\tau)}\Big]$$

where \(\tau\) is a learned temperature and \(t^+, v^+\) denote the matched partner. BLIP follows ALBEF and maintains momentum-updated encoders plus a queue of negatives to enlarge \(N\) beyond the batch size, and applies momentum distillation to soften labels for noisy web pairs.

Image-Text Matching Loss (ITM)

ITM is binary classification: given the fused [Encode] token from the image-grounded text encoder, a linear head predicts \(p_{match}\in[0,1]\):

$$\mathcal{L}_{ITM} = \mathbb{E}\big[y\log p_{match} + (1-y)\log(1-p_{match})\big], \quad p_{match}=\sigma(w^\top h_{[\text{Encode}]}+b)$$

Hard negative mining: rather than sampling negatives uniformly (which are trivially easy), BLIP samples in-batch negatives with probability proportional to their ITC similarity — high-similarity-but-wrong pairs are the hardest and most informative for ITM.

CapFilt: Bootstrapping the Dataset

Let \(D = \{(I_w, T_w)\}\) be noisy web pairs and \(D_h\) a small human-annotated set (e.g. COCO). CapFilt proceeds as:

$$\text{Captioner, Filter} \leftarrow \text{fine-tune MED}(D_h) \quad\text{(LM for captioner, ITC+ITM for filter)}$$
$$T_s = \text{Captioner}(I_w), \qquad \text{keep } (I,T) \text{ iff } \text{Filter}(I,T) > \gamma$$

The filter is applied to both the original web text \(T_w\) and the synthetic caption \(T_s\), independently. The bootstrapped dataset is \(D' = D_h \cup \{(I_w,T_w): \text{kept}\} \cup \{(I_w,T_s): \text{kept}\}\) — a new MED is then pre-trained from scratch on \(D'\).

⚠️ Common Pitfall

CapFilt is not a one-shot cleanup: without diverse sampling, both captioner and filter inherit the same biases (since they're fine-tuned from the same MED checkpoint), which can produce a captioner that "hallucinates" plausible-sounding but generic captions that pass the filter. BLIP mitigates this with nucleus sampling for caption generation (introducing diversity) rather than greedy/beam decoding.

Key Takeaways
▼

When BLIP / CapFilt shines:

  • Pre-training on large-scale, noisy web-scraped image-text corpora (LAION, CC12M-style data)
  • Downstream image-text retrieval (ITC+ITM re-ranking), image captioning (LM decoder), and VQA (image-grounded encoder)
  • Any pipeline where synthetic caption generation + verification can substitute for expensive human annotation

Limitations:

  • Captioner and filter share pre-training biases — bootstrapping amplifies rather than corrects systematic errors
  • Three forward passes per batch (ITC, ITM, LM) triples compute versus a single-objective model like CLIP
  • CapFilt is only run once or twice in practice; iterating further shows diminishing or even negative returns
💡 Lineage

CLIP (ITC only, no generation) → ALBEF (ITC + ITM with cross-attention fusion, momentum distillation) → BLIP (adds LM decoder + CapFilt data bootstrapping) → BLIP-2 (freezes image encoder + LLM, adds a lightweight Q-Former bridge for compute efficiency).

Code Trace — CapFilt Bootstrapping Loop
▼
# Stage 0: pre-train MED on noisy web pairs D (ITC + ITM + LM)
med = MixtureEncoderDecoder()
med.pretrain(D_web, losses=[ITC, ITM, LM])
# Stage 1: fine-tune captioner (decoder, LM) & filter (encoder, ITC+ITM)
captioner = copy(med.decoder).finetune(D_human, loss=LM)
filter_m = copy(med.encoder).finetune(D_human, loss=[ITC, ITM])
# Stage 2: generate synthetic captions for every web image
for (I_w, T_w) in D_web:
T_s = captioner.generate(I_w, sampling='nucleus')
# Stage 3: filter BOTH original and synthetic captions
keep_web = filter_m.itm_score(I_w, T_w) > gamma
keep_syn = filter_m.itm_score(I_w, T_s) > gamma
# Stage 4: assemble bootstrapped dataset D'
D_prime = D_human.copy()
if keep_web: D_prime.add((I_w, T_w))
if keep_syn: D_prime.add((I_w, T_s))
# Stage 5: re-initialize and pre-train a fresh MED on D'
blip = MixtureEncoderDecoder()
blip.pretrain(D_prime, losses=[ITC, ITM, LM]) # final BLIP model
