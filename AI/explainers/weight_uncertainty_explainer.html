Understanding Weight Uncertainty
▼

What is it? A standard neural network learns one number per weight — a single point estimate found by gradient descent. A Bayesian neural network (BNN) instead learns a distribution over every weight: a mean and a spread that say "this weight is probably around here, but I'm not 100% sure." Before seeing any data, every weight starts with a broad prior \(p(w) = \mathcal{N}(0,\sigma_0^2)\). After seeing data, Bayes' rule turns that prior into a narrower posterior \(p(w\mid \mathcal{D})\) that is consistent with what was observed.

Analogy: Imagine guessing a friend's arrival time before they've texted you anything — you might say "somewhere between noon and 6pm," a wide guess (the prior). Once they text "on the highway, 20 minutes out," your estimate narrows sharply around 12:20-12:40 (the posterior). A BNN does this for every single weight, using the training data as the "text message."

💡 If you remember one thing

A BNN replaces point weights \(w\) with distributions \(q_\theta(w)\). Predictions become an ensemble: sample many weight configurations, run the network forward for each, and the spread of the resulting outputs is the model's uncertainty. That spread grows wherever the training data doesn't cover — this is epistemic uncertainty, uncertainty from lack of knowledge rather than sensor noise.

2
How Posterior Inference Works Internally
▼

The Problem with a Point Estimate

Ordinary backprop finds a single \(\hat{w} = \arg\max_w \log p(\mathcal{D}\mid w) + \log p(w)\) (a MAP estimate). This is fast, but it throws away everything about how confident we should be. Two very different weight vectors might fit the training data equally well yet disagree wildly far from it — a point estimate can't tell you that. This matters most exactly where it's most dangerous: inputs unlike anything the model has seen.

The Bayesian Fix: Keep the Whole Distribution

Bayes' rule gives the exact posterior over weights:

$$p(w \mid \mathcal{D}) = \frac{p(\mathcal{D}\mid w)\, p(w)}{p(\mathcal{D})} = \frac{p(\mathcal{D}\mid w)\, p(w)}{\int p(\mathcal{D}\mid w')\,p(w')\,dw'}$$

The catch: for any network with a hidden layer and nonlinearity, that integral in the denominator (the evidence) is intractable — there is no closed form. This is the central obstacle of Bayesian deep learning.

Design Decision: Variational Approximation

Bayes by Backprop (Blundell et al., 2015) sidesteps the intractable integral by picking a tractable family \(q_\theta(w) = \mathcal{N}(w; \mu, \sigma^2)\) — one Gaussian per weight, each with its own learnable mean \(\mu\) and standard deviation \(\sigma\) — and pushing \(q_\theta\) as close as possible to the true posterior by minimizing their KL divergence. This turns an intractable integration problem into a tractable optimization problem solvable with ordinary gradient descent, doubling the parameter count (\(\mu,\sigma\) per weight) but keeping the training loop familiar.

🔑 Key Property

Minimizing \(\mathrm{KL}(q_\theta(w) \,\|\, p(w\mid\mathcal{D}))\) is equivalent to maximizing the Evidence Lower Bound (ELBO), which needs only the prior, the likelihood, and \(q_\theta\) — never the intractable evidence \(p(\mathcal{D})\).

3
Why It Works — The Math
▼

The ELBO Objective

Bayes by Backprop minimizes the variational free energy — the negative ELBO — over the variational parameters \(\theta=(\mu,\sigma)\):

$$\mathcal{F}(\theta) = \underbrace{\mathrm{KL}\big[q_\theta(w)\,\|\,p(w)\big]}_{\text{complexity cost}} \;-\; \underbrace{\mathbb{E}_{q_\theta(w)}\big[\log p(\mathcal{D}\mid w)\big]}_{\text{data-fit / likelihood cost}}$$

The first term pulls the posterior back toward the prior (regularization — "don't over-claim confidence"); the second term pulls it toward whatever explains the training data (fit). Their tug-of-war is exactly what makes the posterior narrow near data and stay wide elsewhere.

The Reparameterization Trick

You cannot backprop through a stochastic sampling node \(w \sim \mathcal{N}(\mu,\sigma^2)\) directly. The trick: rewrite the sample as a deterministic, differentiable function of a noise variable:

$$w = \mu + \sigma \odot \varepsilon, \qquad \varepsilon \sim \mathcal{N}(0, I)$$

Now \(\varepsilon\) carries all the randomness (no gradient needed through it), while \(\mu\) and \(\sigma = \log(1+e^{\rho})\) (a softplus parameterization keeping \(\sigma>0\)) are ordinary differentiable parameters. Gradients of the loss w.r.t. \(\mu\) and \(\sigma\) flow through exactly like any other backprop computation — hence "Bayes by Backprop."

Monte Carlo ELBO Estimate

In practice the expectation is approximated with a handful of samples (often just one per minibatch):

$$\mathcal{F}(\theta) \approx \sum_{i=1}^{n} \Big[\log q_\theta(w^{(i)}) - \log p(w^{(i)}) - \log p(\mathcal{D}\mid w^{(i)})\Big], \quad w^{(i)} = \mu + \sigma\odot\varepsilon^{(i)}$$
⚠️ Common Pitfall

A too-narrow variational posterior (\(\sigma \to 0\)) collapses back to a point estimate and loses all uncertainty — it will look confident and be wrong far from data. A too-wide prior makes the KL term negligible and the network barely regularized. Both the prior variance and the KL weight (often annealed) must be tuned; this is why plain Bayes by Backprop needs care, and why alternatives (MC Dropout, deep ensembles, Laplace approximation) remain popular cheaper proxies for weight uncertainty.

Key Takeaways
▼

When weight uncertainty matters:

  • Safety-critical decisions (medical diagnosis, autonomous driving) where "I don't know" must be distinguishable from a confident wrong answer
  • Active learning / Bayesian optimization — query points where epistemic uncertainty is highest
  • Small or sparse data regimes where overfitting point estimates is a real risk
  • Out-of-distribution detection — predictive variance spikes on unfamiliar inputs

When a plain point-estimate network is fine:

  • Abundant i.i.d. training data covering the deployment distribution well
  • Latency-critical inference where sampling many forward passes is too costly
  • Only aleatoric (irreducible data noise) uncertainty is needed — a single heteroscedastic output head often suffices
💡 Hierarchy

MAP point estimate (\(\sigma\to 0\), no uncertainty) ⊂ MC Dropout / Deep Ensembles (cheap approximate posteriors) ⊂ Bayes by Backprop (explicit variational \(q_\theta(w)\) per weight) ⊂ full MCMC posterior (exact but extremely expensive). Each level trades computational cost for a more faithful picture of what the network doesn't know.

import torch, torch.nn as nn
class BayesianLinear(nn.Module):
def __init__(self, in_f, out_f, prior_std=1.0):
super().__init__()
self.mu = nn.Parameter(torch.zeros(out_f, in_f))
self.rho = nn.Parameter(torch.full((out_f, in_f), -3.0)) # sigma = softplus(rho)
self.prior_std = prior_std
def forward(self, x):
sigma = torch.log1p(torch.exp(self.rho)) # softplus > 0
eps = torch.randn_like(self.mu) # reparameterization
w = self.mu + sigma * eps # w = mu + sigma * eps
self.kl = kl_divergence_to_prior(self.mu, sigma, self.prior_std)
return x @ w.T
def kl_divergence_to_prior(mu, sigma, prior_std):
# KL[N(mu,sigma^2) || N(0, prior_std^2)], closed form, summed over weights
return (torch.log(prior_std / sigma) +
(sigma**2 + mu**2) / (2 * prior_std**2) - 0.5).sum()
