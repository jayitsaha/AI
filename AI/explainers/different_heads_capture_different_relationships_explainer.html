Multi-Head Attention

Different heads capture different relationships in Transformer models

1
Understanding Multi-Head Attention
▼

What is it? In a Transformer model, the attention mechanism allows each word (token) in a sequence to "look at" and weigh the importance of other words. Multi-Head Attention takes this a step further: instead of one attention mechanism, it uses several, each focusing on different aspects of the input. Think of it as having multiple "lenses" or "specialists" simultaneously analyzing the same data.

Analogy: Imagine a team of experts reviewing a document. One expert might focus on grammatical structure, another on identifying key entities (people, places), and a third on understanding the overall sentiment. Each expert forms their own "summary" based on their focus. Multi-Head Attention works similarly: each "head" learns to attend to different parts of the input sequence, capturing diverse relationships.

💡 If you remember one thing

Multi-Head Attention allows a model to jointly attend to information from different representation subspaces at different positions. It's like parallel processing of attention, enabling the model to capture a richer, more nuanced understanding of the input sequence.

2
How Multi-Head Attention Works
▼

The Single Head Foundation: Scaled Dot-Product Attention

Before multi-head, let's recall single-head attention. For each token, we generate three vectors: a Query (\(Q\)), a Key (\(K\)), and a Value (\(V\)). The attention score between a query token and all other key tokens is computed via a dot product, scaled by \(\sqrt{d_k}\) (the dimension of the key vectors), and then passed through a softmax function to get weights. These weights are then applied to the value vectors to produce a context vector for the query token.

Splitting into Multiple Heads

Multi-Head Attention doesn't just run one attention mechanism. Instead, the input \(Q, K, V\) matrices are linearly projected \(h\) times (where \(h\) is the number of heads) into different, lower-dimensional subspaces. Each of these \(h\) sets of projected \(Q, K, V\) then goes through its own independent scaled dot-product attention calculation. This means each head learns its own set of projection matrices and thus focuses on different aspects of the input.

Concatenation and Final Projection

After each head computes its own context vector for every query token, these \(h\) context vectors are concatenated back together. This combined vector, which now contains information from all \(h\) "perspectives," is then passed through a final linear projection layer. This projection transforms the concatenated output into the desired output dimension, allowing it to be integrated into the rest of the Transformer block.

🔑 Key Property

Each attention head operates in parallel, learning distinct linear transformations of the input. This parallelization allows the model to capture a richer variety of relationships—e.g., one head might identify syntactic dependencies, while another captures semantic similarities—without interfering with each other's focus.

3
Why It Works — The Math
▼

Single Head Attention

For a given input sequence (represented as a matrix \(X\)), we first project it into Query (\(Q\)), Key (\(K\)), and Value (\(V\)) matrices using learned weight matrices \(W^Q, W^K, W^V\):

$$Q = XW^Q, \quad K = XW^K, \quad V = XW^V$$

Then, the scaled dot-product attention function computes the output for a single head:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Here, \(d_k\) is the dimension of the key vectors, used for scaling to prevent vanishing gradients during softmax.

Multi-Head Attention

Multi-Head Attention combines \(h\) such attention layers. For each head \(i \in \{1, \dots, h\}\):

$$\text{head}_i = \text{Attention}(XW^Q_i, XW^K_i, XW^V_i)$$

where \(W^Q_i, W^K_i, W^V_i\) are the projection matrices for the \(i\)-th head. These matrices project the input \(X\) into a lower-dimensional space, typically \(d_{model}/h\). Finally, the outputs from all heads are concatenated and linearly transformed:

$$\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \dots, \text{head}_h)W^O$$

Here, \(W^O\) is a final output projection matrix. This structure allows the model to learn different projection spaces for each head, enabling them to focus on different types of relationships within the input sequence.

⚠️ Computational Cost

While powerful, the attention mechanism, particularly the \(QK^\top\) dot product, has a quadratic time complexity with respect to the sequence length (\(O(N^2)\)). This can be a bottleneck for very long sequences, leading to research into more efficient attention mechanisms.

Key Takeaways
▼

Benefits of Multi-Head Attention:

  • Diverse Relationships: Each head can specialize in capturing different types of relationships (e.g., syntactic, semantic, long-range dependencies).
  • Increased Representational Capacity: By performing multiple attention calculations in parallel, the model can attend to information from different representation subspaces.
  • Robustness: Having multiple heads can make the model more robust to noise or ambiguities in the input.
  • Parallelization: The independent computation of each head allows for efficient parallel processing, which is crucial for training large Transformer models.

When to use Multi-Head Attention:

  • Almost universally in modern Transformer architectures (e.g., BERT, GPT, T5) for tasks like machine translation, text summarization, question answering, and image recognition.
  • Any sequence processing task where capturing complex, varied dependencies between elements is important.

When NOT to use:

  • Extremely resource-constrained environments where the added computational cost of multiple heads is prohibitive.
  • Very simple sequence tasks where a simpler model (e.g., RNN, CNN) might suffice with less overhead.
💡 Analogy to Convolutional Filters

Multi-Head Attention can be thought of as analogous to multiple filters in a Convolutional Neural Network (CNN). Just as different filters learn to detect different features (edges, textures, shapes) in an image, different attention heads learn to detect different types of relationships in a sequence.

Code Trace (Conceptual)
▼
import torch
import torch.nn as nn
class MultiHeadSelfAttention(nn.Module):
def __init__(self, d_model, num_heads):
super().__init__()
self.d_model = d_model # Embedding dimension
self.num_heads = num_heads
self.head_dim = d_model // num_heads # Dimension per head
# Linear layers for Q, K, V projections for ALL heads
self.wq = nn.Linear(d_model, d_model)
self.wk = nn.Linear(d_model, d_model)
self.wv = nn.Linear(d_model, d_model)
self.fc_out = nn.Linear(d_model, d_model) # Final output projection
def forward(self, x):
batch_size, seq_len, embed_dim = x.shape
# 1. Project input for Q, K, V for all heads combined
Q = self.wq(x) # (batch_size, seq_len, d_model)
K = self.wk(x) # (batch_size, seq_len, d_model)
V = self.wv(x) # (batch_size, seq_len, d_model)
# 2. Reshape to (batch_size, num_heads, seq_len, head_dim)
Q = Q.view(batch_size, seq_len, self.num_heads, self.head_dim).transpose(1, 2)
K = K.view(batch_size, seq_len, self.num_heads, self.head_dim).transpose(1, 2)
V = V.view(batch_size, seq_len, self.num_heads, self.head_dim).transpose(1, 2)
# 3. Compute Scaled Dot-Product Attention for each head in parallel
# (batch_size, num_heads, seq_len, seq_len)
attention_scores = (Q @ K.transpose(-2, -1)) / (self.head_dim**0.5)
attention_weights = torch.softmax(attention_scores, dim=-1)
# (batch_size, num_heads, seq_len, head_dim)
weighted_values = attention_weights @ V
# 4. Concatenate heads and apply final linear layer
# Reshape back to (batch_size, seq_len, d_model)
concat_heads = weighted_values.transpose(1, 2).contiguous().view(batch_size, seq_len, embed_dim)
output = self.fc_out(concat_heads)
return output
