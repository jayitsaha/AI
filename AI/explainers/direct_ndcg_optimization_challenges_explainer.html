Understanding NDCG
▼

What is it? Normalized Discounted Cumulative Gain (NDCG) is a popular metric for evaluating the quality of ranked lists, especially in search engines, recommendation systems, and information retrieval. It measures how well a ranking algorithm places highly relevant items at the top of a list, giving more weight to items appearing earlier.

Intuition: Imagine you're a librarian organizing books on a shelf. The most popular and relevant books should be on the easiest-to-reach top shelf. Less relevant books can be on lower shelves. NDCG quantifies how good your "shelf organization" is: it rewards you for putting the most relevant books at the very top, and penalizes you more if highly relevant books are buried deep down. The "discount" part means that a relevant book at rank 1 is much more valuable than the same book at rank 10.

💡 If you remember one thing

NDCG is a list-wise metric that cares about two things: (1) the relevance of items, and (2) their position in the ranked list, with a logarithmic penalty for lower positions. It's often the "true north" for ranking system evaluation.

2
How NDCG Works & Its Optimization Challenges
▼

Components of NDCG

NDCG is built from two main parts:

  • Gain: This is a measure of how useful an item is. For a binary relevance (relevant/not relevant), it's often \(1\). For graded relevance (e.g., 0-5 stars), it's typically \(2^{\text{relevance score}} - 1\).
  • Discount: Items appearing lower in the list are less useful. This is usually a logarithmic decay, like \(1/\log_2(\text{rank}+1)\).

These combine into Discounted Cumulative Gain (DCG), which is the sum of discounted gains for a given ranked list. To normalize, DCG is divided by Ideal DCG (IDCG), which is the maximum possible DCG achievable by ranking items in perfect order of their true relevance. This normalization ensures NDCG is always between 0 and 1.

The Core Challenge: Non-Differentiability

The problem for direct optimization arises because the entire process of computing DCG (and thus NDCG) involves a critical, non-differentiable step:

  1. Sorting by Predicted Scores: A ranking model outputs a continuous score for each item. To form a ranked list, these scores must be sorted. The act of sorting is a discrete, non-differentiable operation. A tiny change in a predicted score might not change its rank at all, or it might cause a sudden, discontinuous jump in rank if it crosses another item's score.
  2. Discrete Ranks: The rank \(i\) in the discount factor \(\log_2(i+1)\) is an integer. Even though \(\log_2(x)\) is a smooth function, its input (\(i+1\)) jumps discretely, making the overall term non-differentiable with respect to continuous predicted scores.
  3. Fixed Relevance Scores: The ground truth relevance scores (\(rel_i\)) are typically fixed integers, not continuous outputs of the model. The gain term \(2^{rel_i}-1\) is thus a constant for a given item, not a function we can differentiate with respect to model parameters.

Since gradient-based optimization (the bedrock of deep learning) requires continuous, differentiable functions, directly optimizing a model to maximize NDCG is not straightforward.

🔑 Key Property

The fundamental issue is the permutation operation (sorting). Any small change in a model's continuous predicted scores can lead to a discrete, abrupt change in the item's rank, making the gradient of NDCG with respect to those scores undefined or zero almost everywhere.

3
Why It's Non-Differentiable — The Math
▼

Formal Definitions

Let \(rel_j\) be the true relevance score for item \(j\), and \(s_j\) be the predicted score from our model for item \(j\). To compute DCG, we first sort items by \(s_j\) to get a ranked list. Let \(k\) be the length of the list (or cutoff rank). The gain for an item at rank \(i\) in the *predicted* list is \(G_i = 2^{rel_i} - 1\).

$$\text{DCG}_k = \sum_{i=1}^k \frac{G_i}{\log_2(i+1)}$$

The Ideal DCG (IDCG) is computed by sorting items by their *true* relevance scores \(rel_j\) to get the optimal permutation. Let \(G_{\text{ideal}_i}\) be the gain of the item at rank \(i\) in this ideal list:

$$\text{IDCG}_k = \sum_{i=1}^k \frac{G_{\text{ideal}_i}}{\log_2(i+1)}$$

Finally, NDCG is the normalized ratio:

$$\text{NDCG}_k = \frac{\text{DCG}_k}{\text{IDCG}_k}$$

The Gradient Problem

Consider the derivative of NDCG with respect to a single predicted score \(s_j\). The term \(G_i / \log_2(i+1)\) depends on the rank \(i\). This rank \(i\) is a function of the predicted scores \(s_1, \dots, s_N\): \(i = \text{rank}(s_j, \{s_1, \dots, s_N\})\).

The function \(\text{rank}(\cdot)\) is a step function. For example, if we have scores \([s_1, s_2, s_3]\) and \(s_1\) is the highest, its rank is 1. If \(s_1\) decreases but remains above \(s_2\), its rank is still 1. The derivative with respect to \(s_1\) is 0. However, if \(s_1\) drops just below \(s_2\), its rank suddenly jumps from 1 to 2. At this exact point of transition, the derivative is undefined.

Mathematically, the derivative \(\frac{\partial \text{NDCG}_k}{\partial s_j}\) is zero almost everywhere (when small changes in \(s_j\) don't change its rank) and undefined at the points where \(s_j\) becomes equal to another item's score, causing a rank swap. This makes standard backpropagation impossible.

⚠️ Common Misconception

"The discount factor \(\log_2(i+1)\) is smooth, so NDCG should be differentiable." While \(\log_2(x)\) is smooth, the *input* to it, \(i+1\), is the discrete rank. The non-differentiability stems from the discrete nature of ranks determined by sorting, not from the discount function itself.

Key Takeaways
▼

When to use (or approximate) direct NDCG optimization:

  • When the final evaluation metric is precisely NDCG, and you need to optimize as close to it as possible.
  • In reinforcement learning settings, where NDCG can be treated as a reward signal for a ranking "policy."
  • When using differentiable approximations to sorting (e.g., Gumbel-Softmax) or gradient estimation techniques.

When NOT to use direct NDCG optimization (and what to use instead):

  • For standard neural network training with backpropagation. Direct optimization is simply not feasible due to non-differentiability.
  • Instead, use Proxy Losses:
    • Pointwise: Treat each item independently (e.g., predict relevance score, optimize MSE or cross-entropy against true relevance). Simple, but ignores rank order.
    • Pairwise: Compare pairs of items (e.g., optimize a loss that ensures a more relevant item gets a higher score than a less relevant one). Examples: RankNet, LambdaRank.
    • Listwise: Consider the entire list at once. These are often designed to be differentiable approximations of NDCG or other ranking metrics. Examples: ListNet, ListMLE, LambdaMART (a tree-based method that uses LambdaRank gradients).
💡 Big Picture

Most practical ranking systems optimize a differentiable proxy loss (pointwise, pairwise, or listwise) that correlates well with NDCG, rather than directly optimizing NDCG itself. This allows for efficient training with gradient descent while still aiming for high ranking quality.

Code Trace (Python / NumPy)
▼
import numpy as np
def calculate_dcg(relevances, k):
dcg = 0.0
for i in range(k):
gain = 2**relevances[i] - 1
discount = np.log2(i + 2) # i+1 for 0-indexed rank, +1 for log base 2
dcg += gain / discount
return dcg
def calculate_ndcg(true_relevances, predicted_scores, k=None):
if k is None: k = len(true_relevances)
# Step 1: Sort items by predicted scores to get current ranking
# This is the non-differentiable step!
ranked_indices = np.argsort(predicted_scores)[::-1] # descending scores
current_relevances = true_relevances[ranked_indices]
# Step 2: Calculate DCG for the current ranking
dcg = calculate_dcg(current_relevances, k)
# Step 3: Calculate IDCG (Ideal DCG)
ideal_relevances = np.sort(true_relevances)[::-1] # descending true rel
idcg = calculate_dcg(ideal_relevances, k)
if idcg == 0: return 0.0 # Handle case where no relevant items exist
return dcg / idcg
# Example usage:
true_rel = np.array([3, 0, 4, 1, 2]) # Item A-E true relevances
pred_scores = np.array([0.9, 0.2, 0.7, 0.5, 0.8]) # Item A-E predicted scores
ndcg_at_5 = calculate_ndcg(true_rel, pred_scores, k=5)
print(f"NDCG@5: {ndcg_at_5:.4f}")
# Demonstrating non-differentiability:
# Small perturbation to item C's score (originally 0.7)
pred_scores_p1 = np.array([0.9, 0.2, 0.701, 0.5, 0.8]) # +0.001
ndcg_p1 = calculate_ndcg(true_rel, pred_scores_p1, k=5)
print(f"NDCG@5 (+0.001): {ndcg_p1:.4f} (No change, gradient = 0)")
pred_scores_p2 = np.array([0.9, 0.2, 0.801, 0.5, 0.8]) # Crosses 0.8 threshold
ndcg_p2 = calculate_ndcg(true_rel, pred_scores_p2, k=5)
print(f"NDCG@5 (+0.101): {ndcg_p2:.4f} (Discrete jump, gradient undefined)")
