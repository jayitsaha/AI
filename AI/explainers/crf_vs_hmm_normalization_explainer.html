CRF vs HMM: Global Normalization

How normalizing once over the whole sequence — instead of once per step — kills the label-bias problem
Advanced NLP / Sequence Labeling Graphical Models O(T·S²) inference
1
Understanding CRF vs HMM
▼

What is it? Both HMMs and CRFs label sequences — e.g. tag every word in a sentence with a part of speech. HMMs are generative: they model \(P(x,y)\) using local, per-step normalized distributions. CRFs are discriminative: they model \(P(y\mid x)\) directly, but normalize only once, over entire label sequences, via a global partition function \(Z(x)\).

Analogy: Local normalization is like a relay runner forced to hand the baton to someone on their leg of the race, even if every nearby teammate is a bad fit — the runner must commit full confidence regardless of quality. Global normalization is like scoring the entire relay only after watching the whole race, so no single leg is ever unfairly forced to look confident.

💡 If you remember one thing

Local normalization forces probability mass to sum to 1 at every step, regardless of how weak the evidence is. CRFs normalize to 1 only once, over complete label sequences: $$P(y\mid x) = \frac{1}{Z(x)}\exp\Big(\sum_t\sum_k \lambda_k f_k(y_{t-1},y_t,x,t)\Big)$$ so weak local evidence can still lose to a globally stronger competing path.

2
How It Works Internally — The Label Bias Problem
▼

Why MEMMs (Locally-Normalized Discriminative Models) Break

Maximum Entropy Markov Models model \(P(y_t \mid y_{t-1}, x_t)\) directly, normalized locally at every step: \(\sum_{y_t} P(y_t\mid y_{t-1},x_t) = 1\), for any \(x_t\). If a state \(y_{t-1}\) happens to have only one reachable successor, that conditional is forced to equal exactly 1 no matter how weak the evidence — the observation is mathematically erased at that step. This is the label bias problem (McCallum, Freitag & Pereira, 2000).

Why HMMs Don't Suffer the Same Way

HMMs factorize \(P(x,y)=\prod_t P(y_t\mid y_{t-1})P(x_t\mid y_t)\). The transition factor never conditions on \(x\) at all, so there's no observation evidence to erase — but this generative independence assumption also means HMMs can't use rich, overlapping features of \(x\).

The CRF Fix: Normalize Once, Globally

A linear-chain CRF keeps MEMM's rich features but replaces the per-step normalizer with a single global partition function \(Z(x)\) that sums over every complete label sequence. Local potentials \(\psi_t(y_{t-1},y_t,x)\) are never required to sum to 1 — they stay honest, unnormalized numbers until the very last step, where they compete jointly against every other full path.

🔑 Key Property

Because \(Z(x)\) depends on the full set of competing label sequences — not any single state's out-degree — a locally weak edge can still lose to a globally stronger competing path. This structurally forbids label bias.

3
Why It Works — The Math
▼

Three Factorizations, Side by Side

HMM (local, generative):

$$P(x,y) = P(y_1)\prod_{t=2}^{T} P(y_t\mid y_{t-1})\prod_{t=1}^{T} P(x_t\mid y_t)$$

MEMM (local, discriminative — label bias lives here):

$$P(y\mid x) = \prod_{t=1}^{T} \frac{\exp\big(\sum_k \lambda_k f_k(y_{t-1},y_t,x_t)\big)}{Z_t(y_{t-1},x_t)}$$

CRF (global, discriminative):

$$P(y\mid x) = \frac{1}{Z(x)}\exp\Big(\sum_{t}\sum_k \lambda_k f_k(y_{t-1},y_t,x,t)\Big),\quad Z(x)=\sum_{y'}\exp\Big(\sum_t\sum_k \lambda_k f_k(y'_{t-1},y'_t,x,t)\Big)$$

Training Gradient (Observed − Expected Counts)

The CRF log-likelihood \(\mathcal{L}(\lambda)=\sum_t\sum_k \lambda_k f_k(\cdot) - \log Z(x)\) is concave, with gradient:

$$\frac{\partial \mathcal{L}}{\partial \lambda_k} = \sum_t f_k(y_{t-1},y_t,x,t) \;-\; \mathbb{E}_{P(y\mid x)}\Big[\sum_t f_k(y_{t-1},y_t,x,t)\Big]$$

The expectation is computed via forward-backward: \(Z(x)=\sum_j \alpha_T(j)\), where \(\alpha_t(j)=\sum_i \alpha_{t-1}(i)\,\psi_t(i,j,x)\) — the same dynamic-programming machinery as the HMM forward algorithm, just applied to unnormalized potentials.

⚠️ Common Misconception

"CRF training is just HMM training but discriminative." False — HMM's MLE is closed-form (count and normalize). CRF training has no closed form because \(\log Z(x)\) is a nonlinear function of every \(\lambda_k\); it needs iterative convex optimization (L-BFGS/SGD), even though the objective is guaranteed concave.

🎯 Decision

Use an HMM when you need a lightweight generative model or must sample sequences. Use a CRF (or a neural encoder + CRF layer, e.g. BiLSTM-CRF) whenever you need accurate discriminative sequence labeling with rich features — CRF strictly dominates MEMM for this.

6
Key Takeaways
▼

Label bias is a structural consequence of requiring every step's conditional distribution to sum to 1 on its own. No amount of extra features fixes it — only removing the per-step normalization requirement does.

CRFs achieve this by scoring complete label sequences with unnormalized potentials and dividing by a single global partition function \(Z(x)\), computed efficiently with the same forward-algorithm dynamic programming used in HMMs.

In practice: BiLSTM/Transformer encoders supply rich per-position features, and a CRF output layer supplies label-bias-free, globally-consistent structured prediction — the combination standard in modern NER and POS tagging.
