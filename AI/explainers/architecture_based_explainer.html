Understanding PNN & PackNet
▼

What is it? When a neural network learns a new task, it often "forgets" how to perform previously learned tasks. This is called catastrophic forgetting. Progressive Neural Networks (PNNs) and PackNet are two architectural strategies to combat this problem in continual learning (also known as lifelong learning or incremental learning).

PNN Analogy: Imagine a master chef (Task 1) who is an expert at French cuisine. When they need to learn Italian cuisine (Task 2), instead of trying to retrain their French skills, they hire a new chef (Column 2) who specializes in Italian. This new chef can ask the French chef for advice (lateral connections) but never changes the French chef's recipes. For Japanese cuisine (Task 3), they hire yet another chef, who can consult both previous chefs. Old skills are perfectly preserved.

PackNet Analogy: The same master chef (Task 1) learns French cuisine. To learn Italian (Task 2), they go through their French recipe book and cross out all the "unimportant" ingredients or steps (prune weights). They then use the remaining blank spaces in their memory to learn Italian. For Japanese (Task 3), they cross out more unimportant parts of both French and Italian, making space for Japanese. The chef's overall "brain size" stays roughly the same, but different parts are dedicated to different skills.

💡 If you remember one thing

Both PNNs and PackNet address catastrophic forgetting by explicitly managing the network's architecture or parameter space. PNNs expand the network by adding new, frozen columns for each task. PackNet partitions the existing network by pruning weights after each task to "pack" new tasks into the remaining capacity.

2
How They Work Internally
▼

The Problem: Catastrophic Forgetting

Standard neural networks are designed to learn a single task. When sequentially trained on new tasks, the weights optimized for previous tasks are often overwritten during the optimization for the current task. This leads to a sharp drop in performance on old tasks, as the network effectively "forgets" them.

Progressive Neural Networks (PNNs)

PNNs (Rusu et al., 2016) tackle this by growing the network architecture. For each new task \(k\):

  1. A new "column" (a full copy of the base network's layers) is added to the architecture.
  2. All parameters in previously trained columns (for tasks \(1, \dots, k-1\)) are frozen and remain unchanged.
  3. The new column receives input from the current task's data. Crucially, it also receives output from lateral connections from all preceding columns at every layer. These lateral connections are trainable.
  4. Only the parameters of the new column and its lateral connections are trained on task \(k\).

This guarantees zero catastrophic forgetting because old task parameters are never modified. However, the network size grows linearly with the number of tasks, making it memory and computationally expensive for many tasks.

PackNet

PackNet (Mallya & Lazebnik, 2018) takes a different approach, aiming for a more compact network. For each new task \(k\):

  1. The entire network (or a portion of it) is trained on task \(k\).
  2. After training, a portion of the network's weights are identified as "unimportant" (e.g., based on magnitude or sensitivity). These unimportant weights are pruned (set to zero) and then frozen. They are considered "packed" for task \(k\).
  3. For the next task \(k+1\), only the remaining, unpruned weights are available for training. The pruned weights remain frozen at zero (or their packed value).

This method allows for a fixed or slowly growing network size, as new tasks are "packed" into the unused capacity of the existing network. It's more memory efficient than PNNs but relies heavily on an effective pruning strategy to avoid some degree of forgetting or capacity limitations.

🔑 Key Property

Both methods ensure that knowledge from previous tasks is preserved by preventing new task learning from directly overwriting critical parameters. PNNs achieve this via architectural expansion and parameter freezing, while PackNet achieves it through parameter partitioning via pruning and freezing.

Why They Work — The Math
▼

PNN: Leveraging Lateral Connections

The core idea of PNNs is to allow new columns to adapt to previous representations without altering them. For a hidden layer \(j\) in column \(k\), its activation \(h_k^{(j)}\) is computed as:

$$h_k^{(j)} = f_j\left(W_k^{(j)}a_{k}^{(j-1)} + \sum_{i=1}^{k-1} U_{k,i}^{(j)}a_{i}^{(j-1)} + \sum_{i=1}^{k-1} V_{k,i}^{(j)}h_{i}^{(j)}\right)$$

Here, \(f_j\) is the activation function for layer \(j\), \(W_k^{(j)}\) are the weights for the current column \(k\) at layer \(j\), and \(a_k^{(j-1)}\) is the activation from the previous layer within the current column. The crucial terms are the lateral connections:

  • \(U_{k,i}^{(j)}\) are weights connecting the output of layer \(j-1\) from column \(i\) (\(a_i^{(j-1)}\)) to layer \(j\) of column \(k\).
  • \(V_{k,i}^{(j)}\) are weights connecting the output of layer \(j\) from column \(i\) (\(h_i^{(j)}\)) to layer \(j\) of column \(k\).

Only \(W_k^{(j)}\), \(U_{k,i}^{(j)}\), and \(V_{k,i}^{(j)}\) are trained for task \(k\). All \(W_i^{(j)}\) for \(i < k\) and their associated lateral weights are frozen. This structural isolation guarantees no forgetting.

PackNet: Masking and Re-training

PackNet relies on iterative magnitude-based pruning. After training task \(k\), a binary mask \(M_k\) is learned for the network weights \(W\). For a specific weight \(W_{ij}\), the mask element \(M_{k,ij}\) is typically:

$$M_{k,ij} = \begin{cases} 1 & \text{if } |W_{ij}| \ge \tau_k \\ 0 & \text{if } |W_{ij}| < \tau_k \end{cases}$$

where \(\tau_k\) is a threshold chosen to prune a certain percentage of weights. The "packed" weights for task \(k\) are then \(W \odot M_k\). For task \(k+1\), the network is trained only on the weights where \(M_{k,ij}=0\). This means the new weights \(W'_{ij}\) are learned for the "unpacked" portion of the network:

⚠️ Common Pitfall

PNNs, while robust against forgetting, suffer from significant parameter growth. For \(T\) tasks, a PNN with \(L\) layers and \(P\) parameters per layer grows to \(T \times P + T \times (T-1)/2 \times L \times P_{lateral}\) parameters. PackNet's performance is highly sensitive to the pruning strategy and the chosen percentage. Too much pruning can lead to insufficient capacity for new tasks or even some implicit forgetting.

Key Takeaways
▼

When to use PNNs:

  • When strict, provable prevention of catastrophic forgetting is paramount.
  • When the number of tasks is relatively small, or computational/memory resources are abundant.
  • As a strong baseline for continual learning, demonstrating the power of architectural expansion.

When to use PackNet:

  • When memory and computational efficiency are critical, and a fixed or slowly growing architecture is desired.
  • When a slight compromise on absolute forgetting (due to pruning strategy) is acceptable for resource gains.
  • As a method for parameter-efficient continual learning, especially in resource-constrained environments.

When NOT to use these methods:

  • For single-task learning, where standard networks are simpler and more efficient.
  • When task boundaries are ill-defined or tasks are highly interleaved, as both methods assume distinct sequential tasks.
  • PNNs are impractical for very large numbers of tasks due to linear resource scaling.
  • PackNet can be sensitive to hyperparameter tuning (pruning threshold, percentage) and might still suffer from capacity limitations or partial forgetting if not carefully managed.
💡 Big Picture

Both PNNs and PackNet represent different philosophies within architecture-based continual learning: PNNs prioritize perfect knowledge retention through expansion, while PackNet prioritizes parameter efficiency through intelligent reuse and partitioning. The choice depends on the specific resource constraints and forgetting tolerance of the application.

import torch
import torch.nn as nn
import torch.nn.utils.prune as prune
# --- Progressive Neural Network (PNN) ---
class PNNColumn(nn.Module):
def __init__(self, input_dim, hidden_dims, prev_columns_outputs):
super().__init__()
self.layers = nn.ModuleList()
self.lateral_connections = nn.ModuleList()
# Example: two hidden layers
dims = [input_dim] + hidden_dims
for i in range(len(dims) - 1):
current_layer = nn.Linear(dims[i], dims[i+1])
self.layers.append(current_layer)
# Lateral connections from previous columns to this layer
lateral_in_dim = sum(out_dim for out_dim in prev_columns_outputs[i])
if lateral_in_dim > 0:
self.lateral_connections.append(nn.Linear(lateral_in_dim, dims[i+1]))
else: self.lateral_connections.append(None)
def forward(self, x, prev_column_activations):
activations = [x]
for i, layer in enumerate(self.layers):
h = layer(activations[-1])
if self.lateral_connections[i] and prev_column_activations[i]:
lateral_input = torch.cat(prev_column_activations[i], dim=1)
h += self.lateral_connections[i](lateral_input)
activations.append(torch.relu(h)) # Store activations for next column
return activations[-1], activations[1:] # Return final output and hidden acts

# --- PackNet ---
class PackNetModel(nn.Module):
def __init__(self, input_dim, hidden_dims, output_dim):
super().__init__()
self.fc1 = nn.Linear(input_dim, hidden_dims[0])
self.fc2 = nn.Linear(hidden_dims[0], hidden_dims[1])
self.fc3 = nn.Linear(hidden_dims[1], output_dim)
self.masks = {} # Stores pruning masks for each task
def forward(self, x):
x = torch.relu(self.fc1(x))
x = torch.relu(self.fc2(x))
return self.fc3(x)
def prune_and_pack(self, task_id, prune_ratio):
# Example: Prune fc1 and fc2 based on magnitude
prune.global_unstructured(
(self.fc1, 'weight'), (self.fc2, 'weight'), (self.fc3, 'weight'),
pruning_method=prune.L1Unstructured,
amount=prune_ratio,
)
# Store the current state of masks (prune.remove makes them permanent)
self.masks[task_id] = {
'fc1_mask': self.fc1.weight_mask,
'fc2_mask': self.fc2.weight_mask,
'fc3_mask': self.fc3.weight_mask,
}
prune.remove(self.fc1, 'weight') # Make pruning permanent
prune.remove(self.fc2, 'weight')
prune.remove(self.fc3, 'weight')
def set_trainable_for_task(self, task_id):
# Freeze weights used by previous tasks, unfreeze remaining
for name, module in self.named_modules():
if isinstance(module, nn.Linear):
mask_name = f"{name}_mask"
current_mask = torch.ones_like(module.weight)
for prev_task_id in range(1, task_id):
if prev_task_id in self.masks and mask_name in self.masks[prev_task_id]:
current_mask *= self.masks[prev_task_id][mask_name] # Combine masks
module.weight.requires_grad = (current_mask == 0).any() # Train only unmasked
