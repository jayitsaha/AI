1
Understanding the Traditional ASR Pipeline
▼

What is it? Before end-to-end neural networks (CTC, RNN-T, Whisper) took over, automatic speech recognition (ASR) was built as a pipeline of separately-trained statistical models glued together by a search algorithm. Raw audio becomes a stream of feature vectors; an acoustic model scores how well those vectors match phoneme sounds; a pronunciation lexicon spells words out as phoneme sequences; a language model scores which word sequences are plausible English; and a decoder searches through all of this to find the single most probable sentence.

Analogy: Imagine transcribing a mumbled voicemail. You don't just listen to isolated sounds — you use two kinds of evidence at once: "what did that noise actually sound like?" (acoustic evidence) and "what would a person plausibly say here?" (linguistic expectation). Someone who says something that sounds like "the cat sat" is far more believable than "the bat sad," even if the noisy audio is ambiguous between them. The decoder is the part of your brain that weighs both kinds of evidence simultaneously and picks the best overall story.

💡 If you remember one thing

The entire pipeline is one application of Bayes' rule: $$\hat{W} = \arg\max_{W} P(W \mid X) = \arg\max_{W} \frac{P(X\mid W)\,P(W)}{P(X)} = \arg\max_{W} P(X\mid W)\,P(W)$$ The acoustic model supplies \(P(X\mid W)\), the language model supplies \(P(W)\), and the decoder performs the \(\arg\max\) search over an astronomically large space of word sequences.

2
How the Pipeline Works Internally
▼

Stage 1 — Feature Extraction

Raw audio is chopped into overlapping ~25ms frames (10ms stride). Each frame is converted to a compact feature vector — classically MFCCs (Mel-Frequency Cepstral Coefficients): compute a spectrum, warp it onto the perceptual Mel scale, take the log of the filterbank energies, then apply a Discrete Cosine Transform (DCT) to decorrelate the bands into a handful of coefficients per frame. The audio becomes a sequence of vectors \(X = x_1, x_2, \dots, x_T\).

Stage 2 — Acoustic Model \(P(X\mid W)\)

Each word is expanded (via the lexicon) into a sequence of context-dependent phoneme states, modeled as a left-to-right Hidden Markov Model (HMM). Classically, each state's emission distribution \(b_j(x_t)\) was a Gaussian Mixture Model (GMM) over the feature vector — later replaced by a DNN that outputs state posteriors (the "hybrid HMM-DNN" system). Either way, the acoustic model answers: "how likely is this stretch of audio, given that this phoneme state produced it?"

Stage 3 — Pronunciation Lexicon

A dictionary mapping words to phoneme sequences, e.g. cat → K AE T. This is the bridge between the acoustic model's phoneme-level world and the language model's word-level world. Homophones and multiple pronunciations simply add extra paths through the lexicon.

Stage 4 — Language Model \(P(W)\)

Classically an n-gram model estimated by counting word sequences in a large text corpus: \(P(w_i \mid w_{i-1}) \approx \frac{\text{count}(w_{i-1}, w_i)}{\text{count}(w_{i-1})}\) (with smoothing for unseen pairs). This encodes which word sequences "sound like English," independent of audio.

Stage 5 — The Decoder

All the above are compiled into weighted finite-state transducers (WFSTs) — H (HMM topology), C (context-dependency), L (lexicon), G (grammar/LM) — composed into one giant search graph \(HCLG = H \circ C \circ L \circ G\), then determinized and minimized to remove redundancy. The decoder then runs the Viterbi algorithm (with beam-search pruning to stay tractable) over this graph to find the single best path — the recognized transcript.

🔑 Key Design Decision: Why Separate Models?

Splitting acoustics from language lets each be trained on wildly different, abundant data: the acoustic model needs transcribed speech; the language model just needs text (billions of words, no audio required). This modularity was the whole point before end-to-end models made joint training with huge paired datasets practical.

3
Why It Works — The Math
▼

The Noisy Channel Model

ASR is framed as a noisy channel: a speaker "encodes" a word sequence \(W\) into acoustics \(X\) through a noisy vocal-tract-and-microphone channel. Recognition inverts the channel via Bayes' rule:

$$\hat{W} = \arg\max_W P(W \mid X) = \arg\max_W P(X \mid W)\,P(W)$$

In practice the two terms live on very different scales, so a language model weight \(\lambda\) and word insertion penalty are introduced:

$$\hat{W} = \arg\max_W \Big[\log P(X\mid W) + \lambda \log P(W)\Big]$$

HMM Emission & Transition Structure

Each phoneme state \(j\) has a self-loop probability \(a_{jj}\) (to model variable duration) and a forward transition \(a_{j,j+1}\), plus an emission density \(b_j(x_t)\) — a Gaussian (or GMM / DNN posterior) over the acoustic feature at time \(t\):

$$b_j(x_t) = \mathcal{N}(x_t; \mu_j, \Sigma_j) = \frac{1}{\sqrt{(2\pi)^d|\Sigma_j|}}\exp\!\Big(-\tfrac12 (x_t-\mu_j)^\top \Sigma_j^{-1}(x_t-\mu_j)\Big)$$

The Viterbi Recursion

Finding the best state sequence is a dynamic program. Define \(\delta_t(j)\) as the probability of the best path ending in state \(j\) at time \(t\):

$$\delta_t(j) = \Big[\max_i\, \delta_{t-1}(i)\,a_{ij}\Big]\, b_j(x_t), \qquad \psi_t(j) = \arg\max_i\, \delta_{t-1}(i)\,a_{ij}$$

In log-domain (used in practice to avoid underflow), products become sums:

$$\log\delta_t(j) = \max_i\Big[\log\delta_{t-1}(i) + \log a_{ij}\Big] + \log b_j(x_t)$$

The backpointers \(\psi_t(j)\) let the decoder backtrace from the best final state to recover the optimal state — and hence word — sequence. Because the full search space is exponential in vocabulary size, real decoders use beam pruning: at each frame, only hypotheses within a score threshold of the best are kept alive.

⚠️ Common Pitfall

Beam pruning trades optimality for speed — a narrow beam can prune away the true best path ("search error"), which is a different failure mode from a model error. Practitioners must tune the beam width and LM weight \(\lambda\) jointly; too small a beam causes search errors, too large a beam is intractably slow.

5
Key Takeaways
▼

Why the traditional pipeline mattered:

  • Modularity: acoustic and language models train independently on very different, abundant data sources
  • Interpretability: every stage (features, phoneme scores, LM scores, search) can be inspected and debugged separately
  • Domain adaptation: swap in a new language model for a new domain without retouching the acoustic model
  • The WFST framework (\(HCLG\)) elegantly unifies HMM topology, context, lexicon, and grammar into one searchable graph

Why it was eventually replaced:

  • Each component is optimized separately (not end-to-end) — errors compound, and no component "knows" about downstream loss
  • Hand-built pronunciation lexicons don't scale to open-vocabulary, code-switched, or noisy real-world speech
  • End-to-end models (CTC, RNN-Transducer, attention-based encoder-decoders, Whisper) fold acoustic + lexicon + language modeling into one jointly-trained network, given enough paired audio-text data
💡 Enduring Ideas

Even modern end-to-end ASR systems still shallow-fuse an external neural language model at decode time using the same \(\log P(X\mid W) + \lambda \log P(W)\) formula, and still run beam search as the decoder. The Bayes decomposition and Viterbi-style search never went away — only how \(P(X\mid W)\) is computed changed.

# 1. Feature extraction (simplified MFCC)
frames = frame_signal(audio, frame_len=25ms, stride=10ms)
features = [dct(log_mel_energies(f)) for f in frames] # X = x_1..x_T
# 2. Acoustic model: P(x_t | phoneme state j)
def log_b(x_t, state):
mu, var = gmm_params[state]
return gaussian_logpdf(x_t, mu, var) # or DNN log-posterior
# 3. Pronunciation lexicon
lexicon = {"cat": ["K","AE","T"], "cap": ["K","AE","P"], "bat": ["B","AE","T"]}
# 4. Language model: n-gram counts -> smoothed probabilities
P_lm = (count[prev, word] + 1) / (count[prev] + vocab_size)
# 5. Bayes combination (log-linear)
score(W) = sum(log_b(x_t, state_t) for t, state_t in alignment(W)) \
+ lm_weight * log(P_lm(W | prev_word))
# 6. Build HCLG = H o C o L o G, then determinize + minimize
HCLG = compose(H, C, L, G); HCLG = determinize(minimize(HCLG))
# 7. Viterbi decoding with beam pruning
delta[0][j] = log_b(x[0], j) if j == start else -inf
for t in range(1, T):
for j in states:
delta[t][j] = max(delta[t-1][i] + log_a[i][j] for i in prevs(j)) + log_b(x[t], j)
prune(delta[t], beam_width) # drop hypotheses far below the max
# 8. Backtrace the winning path -> transcript
best_final = argmax(delta[T-1])
transcript = backtrace(psi, best_final)
