1
Understanding Neural Vocoders
▼

What is it? Text-to-speech systems (Tacotron, FastSpeech, VITS' acoustic half, etc.) don't output audio directly — they output a mel-spectrogram: a coarse, compressed picture of how loud each of ~80 frequency bands is, once every ~10 ms. That picture has no phase information and is far too low-resolution to play through a speaker. A vocoder is the neural network whose only job is to invert that picture back into a real waveform — tens of thousands of individual pressure samples per second — so it sounds like natural speech instead of a buzz.

Analogy: Imagine an artist is handed a low-resolution, blurry color sketch (the mel-spectrogram — just "how much energy in this pitch band, right now") and asked to paint a photorealistic canvas (the waveform) with millions of individual brush-strokes (audio samples). WaveNet paints one brush-stroke at a time, looking at literally every stroke painted so far before placing the next one — incredibly faithful, but painfully slow. HiFi-GAN paints the entire canvas in one motion, then shows it to an art critic (a discriminator) who points out anything that looks fake; over thousands of rounds of critique the one-shot painter learns to fool the critic completely — just as fast as a single brush stroke, but for the whole canvas.

💡 If you remember one thing

Mel → waveform is a ~100–300× upsampling problem. WaveNet solves it with an autoregressive chain rule (exact but sequential); HiFi-GAN solves it with a fully convolutional generator trained adversarially (approximate but fully parallel — hundreds of times faster than real-time).

How It Works Internally
▼

WaveNet — Dilated Causal Convolutions, Sample by Sample

WaveNet (van den Oord et al., 2016) models the waveform as a chain: \(p(x) = \prod_{t=1}^{T} p(x_t \mid x_1, \dots, x_{t-1}, c_t)\), where \(c_t\) is the mel-conditioning vector at time \(t\) (the mel frame is upsampled — repeated/transposed-convolved — to the audio sample rate so every sample has a conditioning vector). Each layer is a causal convolution (it can never see the future) with dilation that doubles every layer: 1, 2, 4, 8, 16, … A causal conv with dilation \(d\) skips \(d{-}1\) samples between taps, so stacking \(L\) layers gives a receptive field that grows as \(2^L\) instead of just \(L\) — exponential context from only linear depth. Every node also passes through a gated activation unit borrowed from PixelCNN: \(z = \tanh(W_f * x + V_f * c) \odot \sigma(W_g * x + V_g * c)\). At generation time the network predicts a softmax over 256 μ-law-quantized amplitude levels, samples one value, feeds it back as input, and repeats — one full forward pass per audio sample.

HiFi-GAN — Transposed-Conv Upsampling + Multi-Receptive-Field Fusion

HiFi-GAN (Kong et al., 2020) throws away the autoregressive loop entirely. The generator is a stack of transposed convolutions that progressively upsample the mel frame in time (e.g. strides 8, 8, 2, 2 multiply to the hop length, 256), turning one mel frame into 256 waveform samples in a handful of parallel conv layers. After each upsampling stage, a Multi-Receptive-Field Fusion (MRF) block runs several parallel residual convolution branches with different kernel sizes and dilation rates (e.g. kernel 3/dilation 1, kernel 7/dilation 3, kernel 11/dilation 5) over the same signal and sums their outputs — capturing short buzzy pitch-periods and long formant structure simultaneously. Two discriminators supply the training signal: a Multi-Period Discriminator (MPD) reshapes the 1-D waveform into 2-D grids at several prime periods (2, 3, 5, 7, 11) to catch periodicity artifacts, and a Multi-Scale Discriminator (MSD) looks at the raw waveform plus ×2 and ×4 downsampled versions to catch structure at multiple time-scales.

🔑 Design Decision

Why dilated convolutions instead of an RNN for WaveNet? Convolutions can be trained in parallel across an entire ground-truth sequence (teacher forcing), even though generation must still be sequential — an RNN's recurrence is sequential in both training and inference. Why adversarial + parallel for HiFi-GAN instead of another autoregressive model? A GAN's discriminator directly optimizes for perceptual realism rather than per-sample likelihood, and removing the sequential loop makes inference 100–300× faster than real time on a GPU.

HiFi-GAN: Adversarial + Feature-Matching + Mel Losses

Pure adversarial training is unstable and slow to converge for audio, so HiFi-GAN's generator loss combines three terms:

$$\mathcal{L}_G = \mathcal{L}_{adv}(G;D) + \lambda_{fm}\,\mathcal{L}_{FM}(G,D) + \lambda_{mel}\,\mathcal{L}_{mel}(G)$$

where \(\mathcal{L}_{adv}\) is a least-squares GAN loss, \(\mathcal{L}_{FM}\) is an L1 distance between the discriminators' intermediate feature maps on real vs. generated audio (stabilizes training, sharpens texture), and \(\mathcal{L}_{mel} = \lVert \text{Mel}(x) - \text{Mel}(\hat{x}) \rVert_1\) directly anchors the generated waveform's mel-spectrogram to the ground truth (\(\lambda_{fm}{=}2\), \(\lambda_{mel}{=}45\) in the original paper) — this single term is why HiFi-GAN converges in hours instead of the weeks earlier audio GANs needed.

⚠️ Common Pitfall

WaveNet's 256-level μ-law quantization introduces its own quantization noise floor — more layers/receptive-field does not fix this. And HiFi-GAN's speed comes at a cost: without the mel-loss anchor, adversarial-only training on raw waveforms is notoriously prone to mode collapse and metallic/buzzy artifacts, especially on unseen speakers or singing voice.

Key Takeaways
▼

When to use WaveNet-style autoregressive vocoders:

  • Offline / batch synthesis where latency doesn't matter and top fidelity does (audiobooks, dubbing masters)
  • As a "teacher" model to distill into a fast parallel student (e.g. Parallel WaveNet / IAF distillation, ClariNet)

When to use HiFi-GAN-style parallel GAN vocoders:

  • Real-time / on-device / streaming TTS (assistants, accessibility, live dubbing)
  • Any production system where you need >1 utterance/second/GPU throughput

When NOT to reach for either: if you only need coarse, non-critical audio, simpler Griffin-Lim phase reconstruction from the mel-spectrogram (no neural network at all) is free and "good enough" for prototyping.

💡 Lineage

WaveNet (2016, autoregressive, slow, exact likelihood) → WaveRNN / Parallel WaveNet (distillation for speed) → WaveGlow / Flow-based (parallel, invertible) → HiFi-GAN / MelGAN / UnivNet / BigVGAN (GAN-based, parallel, now the production default) → VITS / end-to-end (vocoder fused directly into the TTS model, trained jointly).

import numpy as np
# --- WaveNet: dilated causal conv stack, gated activation, autoregressive ---
def cond_scalar(mel, cond_weights):
return float(np.dot(mel, cond_weights)) # upsampled local conditioning
def generate_wavenet(mel, dilations, weights, N):
c = cond_scalar(mel, weights['cond'])
x = np.zeros(N)
for t in range(N): # sequential: 1 forward pass / sample
h = x.copy()
for l, d in enumerate(dilations): # dilation doubles each layer
prev, past = h[t], h[t-d] if t-d >= 0 else 0.0
filt = np.tanh(weights['af'][l]*prev + weights['bf'][l]*past + weights['c'][l]*c)
gate = 1/(1+np.exp(-(weights['ag'][l]*prev + weights['bg'][l]*past + weights['c'][l]*c)))
h[t] = filt*gate + 0.3*prev # gated activation + residual
x[t] = np.tanh(h[t]) # sample x_t, feed back for x_(t+1)
return x

for i, w in enumerate(kernel):
j = k*stride + i
if j < len(out): out[j] += v*w
