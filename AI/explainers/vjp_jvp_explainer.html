Vector-Jacobian Products (VJP) & Jacobian-Vector Products (JVP)

The two fundamental primitives of automatic differentiation — reverse-mode and forward-mode AD
Intermediate → Advanced Matrix Calculus Autodiff Part I · Section 2.1
1
Understanding the Concept
▾

When a neural network trains, it needs to know: "how does the loss change if I nudge each weight?" That question boils down to computing one particular product involving the Jacobian matrix \(\mathbf{J}\) — the big matrix of all partial derivatives.

The Jacobian of a function \(f: \mathbb{R}^n \to \mathbb{R}^m\) is an \(m \times n\) matrix where entry \(J_{ij} = \partial f_i / \partial x_j\). For a neural net, \(n\) might be millions of parameters and \(m\) might be a scalar loss — so \(\mathbf{J}\) is astronomically large. We never form it. Instead we compute products with it.

Key Concept — The Two Products

JVP (Jacobian-vector product): Given tangent vector \(v \in \mathbb{R}^n\), compute \(\mathbf{J}v \in \mathbb{R}^m\). Propagates a "perturbation" forward. Cost: one forward pass.

VJP (Vector-Jacobian product): Given cotangent vector \(u \in \mathbb{R}^m\), compute \(u^\top \mathbf{J} \in \mathbb{R}^n\). Pulls a "sensitivity" backward. Cost: one backward pass. This is backpropagation.

Analogy: Imagine a factory pipeline with \(n\) input valves and \(m\) output gauges. A JVP asks: "If I adjust all valves according to direction \(v\), how do all gauges move together?" A VJP asks: "Given that I care about gauge readings weighted by \(u\), which valve adjustments caused this?"

If You Remember One Thing

VJP = backprop (pull cotangents back, one VJP per scalar loss → all \(n\) gradients at once). JVP = forward-mode AD (push tangents forward, one JVP per input direction → all \(m\) outputs at once). For ML with scalar loss: 1 VJP beats \(n\) JVPs. For few inputs: 1 JVP beats \(m\) VJPs.

2
How It Works — Internal Mechanism
▾

The Computational Graph

Every differentiable computation can be broken into primitive operations (addition, multiply, exp, etc.) arranged in a directed acyclic graph (DAG). Nodes are intermediate values; edges carry Jacobians of primitives.

For a composition \(f = f_3 \circ f_2 \circ f_1\), the chain rule gives:

$$\mathbf{J}_f = \mathbf{J}_{f_3} \cdot \mathbf{J}_{f_2} \cdot \mathbf{J}_{f_1}$$

The key question is: in what order do we evaluate this matrix product?

JVP — Forward Mode (left-to-right)

JVP evaluates \((\mathbf{J}_{f_3} \cdot \mathbf{J}_{f_2} \cdot \mathbf{J}_{f_1}) \cdot v\) right to left: first \(\mathbf{J}_{f_1}v\), then apply \(\mathbf{J}_{f_2}\), etc. At each primitive, we propagate a tangent (perturbation) forward alongside the primal value. This is called dual number arithmetic: carry \((x, \dot{x})\) where \(\dot{x} = \partial x / \partial \text{input direction}\).

$$\dot{y} = \frac{\partial f}{\partial x} \dot{x} \quad \text{(JVP rule for primitive } f \text{)}$$

Cost: One forward pass per input direction. To get the full Jacobian you need \(n\) passes (one per basis vector \(e_i\)). Best when \(n \ll m\) (few inputs, many outputs).

VJP — Reverse Mode (right-to-left, backprop)

VJP evaluates \(u^\top \cdot (\mathbf{J}_{f_3} \cdot \mathbf{J}_{f_2} \cdot \mathbf{J}_{f_1})\) left to right: first \(u^\top \mathbf{J}_{f_3}\), then \(\cdot \mathbf{J}_{f_2}\), etc. We must first do a full forward pass to store intermediate values, then traverse the graph backward propagating cotangents (adjoint sensitivities).

$$\bar{x} = \bar{y} \cdot \frac{\partial f}{\partial x} \quad \text{(VJP rule, also called adjoint rule)}$$

Cost: One forward pass + one backward pass, regardless of \(n\). To get the full Jacobian you need \(m\) VJPs. Best when \(m \ll n\) — especially \(m=1\) (scalar loss in ML).

Common Confusion

VJP computes \(u^\top J\) (a row vector / covector). It is NOT \(Ju\). In ML, we set \(u = \mathbf{1}\) (since loss is scalar, \(m=1\), \(u\) is just the scalar 1) and get the gradient \(\nabla_x \mathcal{L} = J^\top \cdot 1 = J^\top\) — which equals the transpose Jacobian applied to the unit cotangent. JAX's jax.vjp returns this cotangent.

Numerical Trace (Concrete Example)

Consider \(f: \mathbb{R}^2 \to \mathbb{R}^2\) defined as \(f(x_1, x_2) = (x_1^2 + x_2,\; x_1 x_2)\) evaluated at \(x = (2, 3)\).

The Jacobian at \(x\) is:

$$\mathbf{J} = \begin{bmatrix} \partial f_1/\partial x_1 & \partial f_1/\partial x_2 \\ \partial f_2/\partial x_1 & \partial f_2/\partial x_2 \end{bmatrix} = \begin{bmatrix} 2x_1 & 1 \\ x_2 & x_1 \end{bmatrix} \bigg|_{(2,3)} = \begin{bmatrix} 4 & 1 \\ 3 & 2 \end{bmatrix}$$

JVP with \(v = (1, 0)\):   \(Jv = \begin{bmatrix}4&1\\3&2\end{bmatrix}\begin{bmatrix}1\\0\end{bmatrix} = \begin{bmatrix}4\\3\end{bmatrix}\). Meaning: perturbing \(x_1\) by 1 moves output by \((4, 3)\).

VJP with \(u = (1, 0)\):   \(u^\top J = \begin{bmatrix}1&0\end{bmatrix}\begin{bmatrix}4&1\\3&2\end{bmatrix} = \begin{bmatrix}4&1\end{bmatrix}\). Meaning: caring only about \(f_1\), the gradient w.r.t. inputs is \((4, 1)\), i.e. \(\nabla_{x} f_1 = (4, 1)\).

3
The Mathematics — Duality & Complexity
▾

Formal Definitions

Let \(f: \mathbb{R}^n \to \mathbb{R}^m\) be differentiable at \(x\). The Jacobian \(\mathbf{J}_f(x) \in \mathbb{R}^{m \times n}\) is the matrix of all partials.

Core Formulas

JVP (forward-mode):

$$\text{jvp}(f, x, v) := \mathbf{J}_f(x)\, v \in \mathbb{R}^m$$

VJP (reverse-mode):

$$\text{vjp}(f, x, u) := u^\top \mathbf{J}_f(x) \in \mathbb{R}^{1\times n} \cong \mathbb{R}^n$$

They are transposes of each other's linear maps — VJP is the pullback, JVP is the pushforward.

Complexity Analysis

For a single primitive with input \(\in \mathbb{R}^n\), output \(\in \mathbb{R}^m\):

ModeCost per passPasses to get full JTotal
JVP (forward)\(O(\text{flops}(f))\)\(n\)\(O(n \cdot \text{flops})\)
VJP (reverse)\(O(\text{flops}(f))\)\(m\)\(O(m \cdot \text{flops})\)

For ML: \(n = \text{number of parameters}\) (millions), \(m = 1\) (scalar loss). So VJP costs just \(1 \times \text{flops}(f)\) to get all \(n\) gradients. JVP would cost \(n \times \text{flops}(f)\) — completely infeasible.

Chain Rule for Composed Functions

$$\text{jvp}(g \circ f, x, v) = \mathbf{J}_g(f(x)) \cdot \mathbf{J}_f(x) \cdot v = \text{jvp}(g, f(x), \text{jvp}(f, x, v))$$
$$\text{vjp}(g \circ f, x, u) = u^\top \mathbf{J}_g \cdot \mathbf{J}_f = \text{vjp}(f, x,\; \text{vjp}(g, f(x), u))$$

Both rules are just the chain rule applied in different orders. Neither ever forms \(\mathbf{J}\) explicitly.

Memory vs. Compute Trade-off (VJP)

VJP requires storing all intermediate activations from the forward pass (to use during the backward pass). This is why training a large model uses far more memory than inference. Techniques like gradient checkpointing recompute some activations rather than storing them, trading compute for memory.

Mathematical Subtlety — Cotangent vs. Gradient

Formally, \(v\) lives in the tangent space \(T_x\mathbb{R}^n \cong \mathbb{R}^n\) (a column vector), while \(u\) lives in the cotangent space \(T^*_{f(x)}\mathbb{R}^m \cong \mathbb{R}^m\) (a row vector). The gradient \(\nabla_x \mathcal{L}\) is the VJP with \(u = 1\), expressed as a column vector via the Euclidean metric. JAX preserves this distinction; PyTorch conflates them (always column vectors).

From Scratch (NumPy dual numbers for JVP)

import numpy as np
# ── JVP via Dual Number Arithmetic ──────────────────────────────────
class Dual:
"""Dual number x + ε*dx. ε²=0 gives exact first-order derivative."""
def __init__(self, val, tan):
self.val = val # primal value
self.tan = tan # tangent (∂val/∂input_direction)
def __mul__(self, other): # product rule: (ab)' = a'b + ab'
return Dual(self.val*other.val, self.tan*other.val + self.val*other.tan)
def __add__(self, other): # sum rule: (a+b)' = a' + b'
return Dual(self.val+other.val, self.tan+other.tan)
def __pow__(self, n): # power rule: (aⁿ)' = n*aⁿ⁻¹*a'
return Dual(self.val**n, n*self.val**(n-1)*self.tan)
def sigmoid_dual(d): # σ(z+ε*ż) = σ(z) + ε*σ'(z)*ż
s = 1/(1+np.exp(-d.val))
return Dual(s, s*(1-s)*d.tan)
def f_dual(x1d, x2d): # f = σ(x1*x2 + x2²)
return sigmoid_dual(x1d * x2d + x2d**2)
# JVP with v=(1,0): set tangents to v
x1 = Dual(2.0, 1.0) # primal=2, tangent=1 (direction v₁=1)
x2 = Dual(1.0, 0.0) # primal=1, tangent=0 (direction v₂=0)
out = f_dual(x1, x2)
print(f"f(2,1) = {out.val:.6f}") # 0.952574
print(f"JVP v=(1,0) = {out.tan:.6f}") # ≈ 0.04518 (∂f/∂x1 at (2,1))
# ── VJP via Manual Backprop ─────────────────────────────────────────
x1_p, x2_p = 2.0, 1.0
z1 = x1_p * x2_p # forward: mul → 2.0
z2 = x2_p ** 2 # forward: sq → 1.0
z3 = z1 + z2 # forward: add → 3.0
sig = 1/(1+np.exp(-z3)) # forward: sigma → 0.952574
sig_d = sig*(1-sig) # σ'(z3) ≈ 0.04518
# Backward: start with cotangent u=1 (scalar loss)
u = 1.0
z3_bar = u * sig_d # VJP of sigma: ū * σ'(z3) = 0.04518
z1_bar = z3_bar * 1.0 # VJP of add: pass through = 0.04518
z2_bar = z3_bar * 1.0 # VJP of add: pass through = 0.04518
x1_bar = z1_bar * x2_p # VJP of mul: ∂(x1*x2)/∂x1 = x2 = 0.04518
x2_bar = z1_bar * x1_p + z2_bar * 2*x2_p # mul + sq = 0.04518*2 + 0.04518*2 = 0.18072
print(f"∂f/∂x1 = {x1_bar:.5f}") # 0.04518
print(f"∂f/∂x2 = {x2_bar:.5f}") # 0.18072

JAX — jvp and vjp built-ins

import jax
import jax.numpy as jnp
from jax import jvp, vjp, grad
def f(x): # x = [x1, x2]
return jax.nn.sigmoid(x[0]*x[1] + x[1]**2)
x = jnp.array([2.0, 1.0])
v = jnp.array([1.0, 0.0]) # tangent vector
# JVP: forward-mode AD
primals, tangents = jvp(f, (x,), (v,))
print(f"f = {primals:.6f}") # 0.952574
print(f"Jv = {tangents:.6f}") # 0.045177 (= ∂f/∂x1)
# VJP: reverse-mode AD
y, vjp_fn = vjp(f, x) # vjp_fn takes cotangent
grads, = vjp_fn(1.0) # cotangent u=1 (scalar output)
print(f"∂f/∂x1 = {grads[0]:.5f}") # 0.04518
print(f"∂f/∂x2 = {grads[1]:.5f}") # 0.13554
# grad = vjp with u=1 (convenience wrapper)
print(grad(f)(x)) # [0.04518, 0.13554] — same result
# Hessian-vector product (HVP): jvp of vjp
def hvp(f, x, v): # H(x) @ v without forming H
return jvp(grad(f), (x,), (v,))[1]
Gotcha — PyTorch and VJP

PyTorch's autograd is VJP-only by default. loss.backward() computes VJP with \(u=1\). torch.autograd.functional.jvp(f, x, v) exists but is less efficient than JAX's implementation. For forward-mode AD in PyTorch, use torch.autograd.forward_ad (added in PyTorch 1.11).

Key Takeaways & When to Use Each
▾
Dimension JVP (Forward-Mode) VJP (Reverse-Mode / Backprop)
Computes \(\mathbf{J}v\) — one column of \(\mathbf{J}\) \(u^\top\mathbf{J}\) — one row of \(\mathbf{J}\)
Best for \(n \ll m\) (few inputs, many outputs) \(m \ll n\) (few outputs, many inputs)
Memory Low — no storage of intermediates High — must store forward activations
Full Jacobian cost \(n\) passes \(m\) passes
ML training Rarely used directly (unless \(n=1\)) Standard backprop — always used
Use cases Sensitivity analysis, HVP (JVP of VJP), ODEs, physics sims Neural net training, gradient computation, attention
JAX API jax.jvp(f, primals, tangents) jax.vjp(f, *primals) or jax.grad
PyTorch API torch.autograd.forward_ad loss.backward()
Decision Rule

Let \(n\) = inputs, \(m\) = outputs.
If \(n < m\) → use JVP (\(n\) forward passes to get full Jacobian).
If \(m < n\) → use VJP (\(m\) backward passes to get full Jacobian).
ML almost always has \(m=1\) (scalar loss) and \(n \sim 10^6\text{–}10^{10}\) → always VJP.
For Hessian-vector products: compose JVP ∘ VJP (one forward-over-reverse pass).
