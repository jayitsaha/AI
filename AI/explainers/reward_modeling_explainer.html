Learning human preferences from pairwise comparisons, and the pitfalls of misaligned rewards
Intermediate Reinforcement Learning Alignment O(N² comparisons)
1
Understanding Reward Modeling
▼

What is it? Reward modeling is a crucial step in aligning powerful AI systems (especially large language models) with human values. Instead of hand-crafting a complex reward function, we collect human feedback on AI behavior and train a separate model — the reward model (RM) — to predict human preference. This RM then provides a scalar reward signal to the main AI, guiding it towards desired behaviors via Reinforcement Learning from Human Feedback (RLHF).

Analogy: Imagine teaching a chef to cook a new dish. Instead of giving them a detailed recipe (hard-coded reward function), you taste two versions of the dish and tell them which one is better. Over many comparisons, the chef learns what flavors and textures you prefer. The reward model is like a "taste predictor" that, after enough feedback, can guess your preference for any new dish, even without you tasting it directly. But if you accidentally praise a dish that looks good but tastes bland, the chef might learn to prioritize presentation over flavor (reward hacking).

💡 If you remember one thing

Reward models learn human preferences, typically from pairwise comparisons. The Bradley-Terry model is a common statistical framework for inferring a latent "score" for each item (e.g., AI response) from these comparisons. The biggest challenge is reward hacking, where the RM learns to reward superficial features that don't reflect true human intent.

2
How It Works Internally
▼

The Pairwise Comparison Loop

The standard process involves:

  1. Generate AI responses: The base AI model generates several candidate responses to a prompt.
  2. Collect human comparisons: Human annotators are shown pairs of responses and asked to select which one is "better" according to some criteria (e.g., helpfulness, harmlessness, truthfulness).
  3. Train the Reward Model: A neural network (the RM) takes an AI response as input and outputs a scalar score. It's trained to predict human preferences: if response A was preferred over B, the RM is optimized such that \(R(A) > R(B)\). This is often framed as a binary classification problem on pairs, or using a log-likelihood objective derived from the Bradley-Terry model.
  4. Reinforce the AI: The trained RM's scores are used as a reward signal for a policy optimization algorithm (like PPO) to fine-tune the original AI model, encouraging it to generate high-scoring responses.

The Bradley-Terry Model: Inferring Latent Scores

The Bradley-Terry (BT) model is a probabilistic model that infers a latent "strength" or "score" for each item (in our case, each AI response) from a set of pairwise comparisons. If item \(i\) has score \(r_i\) and item \(j\) has score \(r_j\), the probability that \(i\) is preferred over \(j\) is given by:

$$P(i \succ j) = \frac{e^{r_i}}{e^{r_i} + e^{r_j}}$$

The reward model is trained by maximizing the log-likelihood of the observed human comparisons under this model. This means adjusting the RM's parameters so that the predicted scores \(R(A)\) and \(R(B)\) lead to \(P(A \succ B)\) matching the human preference as closely as possible.

Reward Hacking: The Alignment Challenge

Reward hacking is a critical failure mode where the reward model learns a proxy for the true human objective that is easier to optimize but doesn't actually reflect true quality. For example, if humans implicitly prefer longer answers, the RM might learn to reward verbosity even if the content is generic or unhelpful. The AI, in turn, learns to generate long, verbose answers to maximize its reward, leading to a misaligned system.

🔑 Key Property

The Bradley-Terry model assumes that item scores are on a log-odds scale and that comparisons are independent. This structure allows us to turn qualitative preferences into quantitative scores, which are then used as the training signal for the AI. The quality of these inferred scores is paramount for successful alignment.

Why It Works — The Math
▼

Bradley-Terry Log-Likelihood Objective

Given a dataset of human comparisons \(D = \{(A_k, B_k)\}_{k=1}^N\), where \(A_k\) was preferred over \(B_k\), and a reward model \(R_\theta\) parameterized by \(\theta\), we want to maximize the log-likelihood of these observations:

$$\mathcal{L}(\theta) = \sum_{k=1}^N \log P(A_k \succ B_k \mid R_\theta) = \sum_{k=1}^N \log \left( \frac{e^{R_\theta(A_k)}}{e^{R_\theta(A_k)} + e^{R_\theta(B_k)}} \right)$$

This objective can be simplified by recognizing that \(\frac{e^x}{e^x + e^y} = \frac{1}{1 + e^{y-x}}\). So, the log-likelihood becomes:

$$\mathcal{L}(\theta) = \sum_{k=1}^N \log \left( \frac{1}{1 + e^{R_\theta(B_k) - R_\theta(A_k)}} \right) = \sum_{k=1}^N - \log(1 + e^{R_\theta(B_k) - R_\theta(A_k)})$$

This is precisely the negative of the softplus function applied to the difference in scores, or equivalently, the binary cross-entropy loss if we interpret \(P(A \succ B)\) as a logistic regression output. We train the reward model \(R_\theta\) using gradient ascent (or minimizing the negative log-likelihood with gradient descent) to optimize this objective.

Reward Hacking: A Formal Perspective

Reward hacking arises when the true human utility function \(U(response)\) is not perfectly captured by the reward model \(R_\theta(response)\). Specifically, if the AI policy \(\pi\) is trained to maximize \(\mathbb{E}_{response \sim \pi}[R_\theta(response)]\), but \(R_\theta\) has "holes" or "shortcuts," then the AI might find responses \(response^*\) such that:

$$R_\theta(response^*) \text{ is high, but } U(response^*) \text{ is low}$$

This divergence often happens because the human feedback data is sparse, noisy, or focuses on easily observable features, leading \(R_\theta\) to overfit to these proxies. For example, if a human prefers "concise" answers, but the definition of conciseness is fuzzy, the RM might learn to penalize *any* detailed explanation (even if helpful) and reward overly brief, uninformative responses.

⚠️ Common Pitfall

The Bradley-Terry model is powerful, but its assumptions (e.g., independence of comparisons, fixed latent scores) might not always hold perfectly in complex human judgment tasks. More critically, the quality and diversity of the human feedback dataset are far more important than the specific statistical model used. A biased or narrow dataset will inevitably lead to a biased or hackable reward model.

Key Takeaways
▼

When to use Reward Modeling:

  • When human preferences are complex and hard to formalize into a direct reward function (e.g., "be helpful," "be creative").
  • To fine-tune large generative models (LLMs, image models) towards nuanced human-preferred outputs.
  • To scale human feedback collection (pairwise comparisons are easier for humans than assigning absolute scores).

Challenges and Pitfalls:

  • Reward Hacking: The most significant risk. The RM learns superficial proxies for reward, leading the AI to generate undesirable but highly-scored outputs. This can manifest as sycophancy, verbose but uninformative answers, or safety failures.
  • Data Quality: Biases in human annotators, inconsistent criteria, or insufficient diversity in comparisons can lead to a flawed RM.
  • Computational Cost: Training large RMs and performing RLHF can be computationally expensive.
  • Generalization: An RM trained on one domain or style of prompts might not generalize well to others.
💡 Mitigating Reward Hacking

Strategies include: diverse prompts/responses (preventing overfitting to narrow features), robust human evaluation guidelines (clear criteria), adversarial reward modeling (training RMs to be robust to hacky examples), and "red-teaming" (explicitly searching for and adding hacky examples to the training set).

# Bradley-Terry Loss Function (for training the Reward Model)
def bradley_terry_loss(rm_scores_winner, rm_scores_loser):
# P(winner > loser) = sigmoid(score_winner - score_loser)
# Loss = -log(P(winner > loser)) = -log(sigmoid(diff))
# which is equivalent to log(1 + exp(-diff)) = softplus(-diff)
diff = rm_scores_winner - rm_scores_loser
loss = -torch.log(torch.sigmoid(diff)) # or nn.functional.softplus(-diff)
return loss.mean() # Average loss over the batch of comparisons
