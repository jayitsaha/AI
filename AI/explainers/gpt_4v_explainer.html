Understanding GPT-4V
▼

What is it? GPT-4V ("V" for Vision) is OpenAI's multimodal extension of GPT-4: the same conversational model, now able to accept images alongside text and reason about both in one turn. Released to ChatGPT and the API in 2023, it can read a screenshot, describe a photo, extract numbers from a chart, debug a diagram, or transcribe handwriting — then discuss what it saw using ordinary language. Critically, GPT-4V is closed-source: OpenAI has not published its weights, training data, or exact architecture. Everything below is assembled from three kinds of public evidence — (a) the official GPT-4V System Card and GPT-4 Technical Report, (b) OpenAI's documented API pricing formula for image tokens (one of the only hard architectural facts released), and (c) the broader published literature on multimodal LLMs (CLIP, Flamingo, LLaVA, PaLI, Qwen-VL) that plausibly share GPT-4V's design pattern. Claims from source (c) are explicitly flagged as speculative throughout.

Analogy: Think of GPT-4 as a brilliant essayist who has only ever "heard" the world described in words. GPT-4V hands that essayist a pair of glasses. The essayist's reasoning ability doesn't change — what changes is that a new sense (pixels) gets translated into the same internal vocabulary (tokens) the essayist already knows how to think in. Once translated, thinking about a photograph is, mechanically, no different from thinking about a paragraph.

💡 If you remember one thing

GPT-4V turns pixels into tokens that live in the same embedding space as words, then lets one Transformer decoder read both streams together. One of the few facts OpenAI has confirmed publicly is the token cost of an image: $$\text{tokens}_{\text{image}} = 85 + 170 \times n_{\text{tiles}}, \qquad n_{\text{tiles}} = \left\lceil \frac{W}{512} \right\rceil \times \left\lceil \frac{H}{512} \right\rceil$$ This single documented formula is the clearest public window into how GPT-4V actually consumes an image.

How GPT-4V Likely Works Internally
▼

The Base Model (confirmed)

GPT-4V is built on GPT-4, a decoder-only Transformer language model trained to predict the next token. OpenAI has disclosed neither parameter count nor whether it uses a dense or mixture-of-experts architecture; independent reporting suggests a very large model trained on a mixture of text-only and image-text corpora, with vision capability added via additional multimodal training rather than a wholly separate model.

The Vision Front-End (speculative, by analogy to published multimodal LLMs)

The pattern below is not confirmed by OpenAI — it is the design shared by essentially every published multimodal LLM (LLaVA, Flamingo, PaLI, Qwen-VL, InstructBLIP), and is the most parsimonious explanation for GPT-4V's documented behavior:

  1. Preprocess (confirmed by API docs): the image is capped at 2048×2048, its shortest side scaled to 768px, then sliced into 512×512 tiles.
  2. Vision encoder (speculative): a ViT-style encoder — plausibly CLIP-like, contrastively pretrained on image-text pairs — turns each tile into a grid of patch embeddings.
  3. Projector (speculative): a learned linear layer or small cross-attention "resampler" maps each patch embedding from the vision encoder's dimension into the LLM's token-embedding dimension, so a patch now "looks like" a word embedding to the Transformer.
  4. Fusion (speculative mechanism, confirmed effect): projected image tokens are spliced into the input sequence at the position where the image appeared in the conversation. The same decoder-only Transformer that processes text now self-attends across both modalities in one pass.
  5. Generation (confirmed effect): the model decodes an answer autoregressively, attending back to whichever image tokens are relevant — this is the mechanism that produces answers "grounded" in specific image regions.

Design Decision: Why Tokens, Not a Separate Pathway?

Once pixels become vectors living in the same space as word embeddings, no bespoke multimodal architecture is needed — the same self-attention and next-token objective that explains text understanding also explains image understanding. This is GPT-4's core recipe ("just predict the next token") extended to a new input alphabet, rather than a fundamentally new model.

🔑 Public vs. Speculative

Confirmed: image token pricing formula, that vision was added via extra training, and the documented refusal categories in the System Card. Speculative: the exact vision encoder, the projector type (linear vs. resampler), and whether fusion is full token concatenation (LLaVA-style) or gated cross-attention layers (Flamingo-style). OpenAI has not disclosed which.

Why It Works — The Math
▼

Patchify and Embed

Each tile is sliced into non-overlapping \(k\times k\) patches, giving \((512/k)^2\) patches per tile. Each patch is flattened to a vector and linearly projected with an added position embedding:

$$e_i = W_e \cdot \text{vec}(\text{patch}_i) + p_i$$

A standard Vision Transformer block then lets patches attend to each other within a tile, producing contextualized patch embeddings \(e_i'\).

Project into the LLM's Space

A projector \(W_{\text{proj}}\) (optionally a cross-attention "resampler" that also compresses many patches into fewer latent tokens) maps each patch embedding into the LLM's token dimension:

$$h_i = W_{\text{proj}}\, e_i' \in \mathbb{R}^{d_{\text{LLM}}}$$

The fused sequence interleaves these image tokens with ordinary text token embeddings:

$$T = [\,t_1^{\text{text}}, \dots, \texttt{}, h_1, \dots, h_M, \texttt{}, \dots, t_k^{\text{text}}\,]$$

Grounding = Ordinary Attention, Extended

The decoder's self-attention is unchanged by the presence of images — it is still

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V$$

applied jointly across text and image tokens. A text query token (e.g. "car") can attend more strongly to the image-token keys whose content resembles "car" — this is literally what produces a "grounded" answer: no separate localization module is required, just attention weights \(\alpha_{ij} = \text{softmax}(q_i \cdot k_j)\) that happen to concentrate mass on the relevant patches.

⚠️ Common Misconception

GPT-4V does not run a separate OCR engine or object detector by default. Its text-reading and object-localization abilities are emergent from next-token prediction over massive image-text training data — not a hard-coded symbolic vision module. This is exactly why it can misread dense small text, miscount objects, or hallucinate details: what looks like symbolic perception is actually statistical pattern completion, with all the same failure modes as text generation.

Key Takeaways
▼

Demonstrated capabilities:

  • Reading dense text, handwriting, and screenshots (emergent OCR)
  • Chart, table, and diagram question-answering
  • Multi-image comparison and reasoning across a sequence of photos
  • Visual reasoning: geometry problems, puzzles, spatial layout questions
  • Code and markup generation from a UI screenshot or whiteboard sketch
  • Rough grounding — referring to "the object in the top-left" with reasonable accuracy

Known limitations:

  • Unreliable precise counting of objects in a scene
  • Weak at exact bounding-box / pixel-level spatial coordinates
  • Can hallucinate objects or text that are not actually present
  • Sensitive to tiling artifacts and image resolution/compression
  • Not suitable as the sole reader for high-stakes small print (legal, medical) without verification

Documented safety behaviors (from the GPT-4V System Card):

  • Refuses to identify or speculate about the identity of private individuals in photos
  • Avoids diagnosing medical images — offers general information with a disclaimer instead
  • Refuses to solve CAPTCHAs
  • Declines to make character, emotion, or personality judgments about identifiable people from images ("physiognomy" refusal)
  • Extra caution around images that could assist weapons-making or self-harm
💡 Hierarchy

GPT-4 (text-only Transformer) ⊂ GPT-4V (adds a vision front-end feeding the same token stream) ⊂ later natively multimodal / "omni" models (audio + video absorbed the same way). Each generalizes by folding a new modality into the same "predict the next token" backbone rather than building a new architecture per sense.

from PIL import Image
import numpy as np
# 1. Resize + tile (documented OpenAI API rule)
img = Image.open("photo.jpg") # e.g. 1024x768
img = scale_shortest_side(img, 768) # cap long side at 2048
tiles = split_into_tiles(img, size=512) # ceil(W/512) * ceil(H/512)
n_tiles = len(tiles)
image_tokens = 85 + 170 * n_tiles # documented billing formula
# 2. Vision encoder (speculative: CLIP-style ViT)
patch_embeds = [vision_encoder(t) for t in tiles] # (n_patches, 1024)
# 3. Projector into the LLM's embedding space (speculative)
img_tokens = [projector(p) for p in patch_embeds] # (n_patches, 4096)
# 4. Fuse into one token sequence for the decoder
text_tokens = tokenizer.encode(prompt)
sequence = [BOS] + text_tokens[:split] + img_tokens + text_tokens[split:]
# 5. Autoregressive, grounded generation
answer = gpt4_decoder.generate(sequence, max_new_tokens=200)
print(answer) # "The sign says STOP; the car is orange."
