Understanding WGAN
▼

What is it? Generative Adversarial Networks (GANs) are powerful models for learning data distributions. However, standard GANs are notoriously unstable to train, often suffering from vanishing gradients (which stall learning) or mode collapse (where the generator only produces a limited variety of outputs). Wasserstein GANs (WGANs) address these issues by replacing the Jensen-Shannon divergence loss with the Wasserstein-1 distance (also known as Earth Mover's Distance).

Analogy: Imagine two piles of dirt (our probability distributions) and you want to transform one into the other. The Earth Mover's Distance is the minimum "cost" of moving all the dirt from one pile to match the other, where cost is defined as the amount of dirt times the distance moved. A small wiggle in one pile might lead to a huge change in Jensen-Shannon divergence (if the piles separate), but only a tiny change in Earth Mover's Distance. This smoother metric provides more stable gradients.

💡 If you remember one thing

WGAN fundamentally changes the GAN's objective function to use the Wasserstein distance, which is a much smoother metric between distributions than Jensen-Shannon divergence. To make this work, the discriminator (now called the "critic") must be a K-Lipschitz function, which WGAN enforces via simple (but problematic) weight clipping.

How WGAN Works Internally
▼

The Problem with Original GANs

Standard GANs minimize the Jensen-Shannon (JS) divergence between the real data distribution (\(p_{data}\)) and the generator's distribution (\(p_g\)). When these two distributions are non-overlapping (which is common, especially in high-dimensional spaces or early in training), the JS divergence is a constant \(\log(2)\). This provides no useful gradient signal to the generator, causing vanishing gradients and stalled learning. It also makes the discriminator's job too easy, leading to overly confident predictions.

Wasserstein Distance: A Smoother Metric

The Wasserstein-1 distance (or Earth Mover's Distance) measures the minimum cost of transforming one distribution into another. Unlike JS divergence, it provides a meaningful, continuous gradient even when distributions are far apart or non-overlapping. This continuous gradient allows the generator to learn effectively even when it's producing very poor samples.

The K-Lipschitz Constraint

The mathematical formulation of Wasserstein distance (via Kantorovich-Rubinstein duality) requires the critic function \(D(x)\) to be K-Lipschitz. A function \(f\) is K-Lipschitz if \(\|f(x_1) - f(x_2)\| \le K \|x_1 - x_2\|\) for all \(x_1, x_2\). Intuitively, this means the function's slope (or gradient magnitude) cannot exceed \(K\) anywhere. For WGAN, we typically choose \(K=1\), so the critic must be 1-Lipschitz.

Enforcing Lipschitz: Weight Clipping

The original WGAN paper proposed a simple, albeit heuristic, method to enforce the Lipschitz constraint: weight clipping. After each gradient update, all weights in the critic network are clipped to a small, fixed range, e.g., \([-c, c]\). The idea is that if weights are bounded, then the gradients of the critic (its slopes) will also be bounded, thus making it approximately Lipschitz. While simple, this method has significant drawbacks, as we'll explore.

Architectural Changes

Unlike a standard GAN discriminator, the WGAN critic does not output a probability (it's not a classifier). Therefore, its final activation function should *not* be a sigmoid. It simply outputs a raw score, which represents the "value" of the input according to the critic. The loss functions for both generator and critic are also simplified, removing the \(\log\) terms.

🔑 Key Property

The WGAN critic is not a classifier but a regressor that estimates the Wasserstein distance. Its output is a raw score, not a probability. The Lipschitz constraint is crucial for the mathematical validity of the Wasserstein objective, and weight clipping is the WGAN's (imperfect) way of enforcing it.

3
Why It Works — The Math
▼

Original GAN Objective (Minimax)

The standard GAN trains a generator \(G\) and a discriminator \(D\) via a minimax game aiming to minimize the Jensen-Shannon divergence:

$$ \min_G \max_D V(D, G) = \mathbb{E}_{x \sim p_{data}(x)}[\log D(x)] + \mathbb{E}_{z \sim p_z(z)}[\log(1 - D(G(z)))] $$

Here, \(D(x)\) is the probability that \(x\) came from real data, and \(G(z)\) is a generated sample from noise \(z\). The discriminator tries to maximize this, while the generator tries to minimize it.

Wasserstein-1 Distance (Earth Mover's Distance)

The Wasserstein-1 distance between two distributions \(p_{data}\) and \(p_g\) is defined as:

$$ W(p_{data}, p_g) = \inf_{\gamma \in \Pi(p_{data}, p_g)} \mathbb{E}_{(x,y) \sim \gamma}[\|x-y\|] $$

where \(\Pi(p_{data}, p_g)\) is the set of all joint distributions \(\gamma(x,y)\) whose marginals are \(p_{data}\) and \(p_g\). This definition is hard to compute directly.

Kantorovich-Rubinstein Duality & WGAN Objective

Fortunately, the Wasserstein-1 distance has a dual form (Kantorovich-Rubinstein Duality) that is tractable for neural networks:

$$ W(p_{data}, p_g) = \sup_{\|f\|_L \le 1} \left( \mathbb{E}_{x \sim p_{data}(x)}[f(x)] - \mathbb{E}_{z \sim p_z(z)}[f(G(z))] \right) $$

Here, \(f\) is any 1-Lipschitz function. The WGAN uses its critic \(D\) to approximate this \(f\). So, the WGAN objective becomes:

$$ \min_G \max_D \left( \mathbb{E}_{x \sim p_{data}(x)}[D(x)] - \mathbb{E}_{z \sim p_z(z)}[D(G(z))] \right) $$

subject to the constraint that \(D\) is 1-Lipschitz. The critic \(D\) is trained to maximize this quantity (to estimate \(W\)), and the generator \(G\) is trained to minimize it (to reduce \(W\)).

Weight Clipping to Enforce Lipschitz

To enforce the 1-Lipschitz constraint on \(D\), WGAN applies a simple clipping operation to the critic's weights after each update:

$$ w \leftarrow \text{clip}(w, -c, c) $$

where \(c\) is a small positive constant (e.g., 0.01). The intuition is that if all weights are bounded, the function's gradients will also be bounded, thus making the function approximately Lipschitz. However, this is a very strong and often suboptimal way to enforce the constraint.

⚠️ Common Pitfall

While weight clipping is simple, it can severely restrict the critic's capacity, forcing it to learn a very simple function. This can lead to vanishing gradients or suboptimal solutions if the clipping value \(c\) is too small. If \(c\) is too large, the critic might become too powerful, leading to unstable training. WGAN-GP (Gradient Penalty) is a more robust alternative to enforce the Lipschitz constraint.

Key Takeaways
▼

When to use WGAN:

  • When training standard GANs is highly unstable, leading to vanishing gradients or mode collapse.
  • When you need a more robust and smooth loss function for generative models.
  • For applications where the quality of generated samples is paramount, and training stability is a bottleneck.

When NOT to use (or use with caution):

  • If you are strictly using the original WGAN with weight clipping — WGAN-GP (Gradient Penalty) is almost always preferred due to its superior stability and performance.
  • For very simple datasets where standard GANs already train well and quickly.
  • If the computational overhead of training the critic more frequently (a common WGAN practice) is prohibitive.
💡 Big Picture

WGAN was a pivotal moment in GAN research, providing a theoretical foundation and practical improvements for stable training. While its original weight clipping method has been largely superseded by WGAN-GP, the core idea of using Wasserstein distance and a Lipschitz critic remains fundamental to many state-of-the-art generative models.

import torch.nn as nn
# Critic (Discriminator) Network
class Critic(nn.Module):
def __init__(self, input_dim):
super().__init__()
self.main = nn.Sequential(
nn.Linear(input_dim, 64),
nn.ReLU(),
nn.Linear(64, 1) # No sigmoid, outputs raw score
)
def forward(self, x):
return self.main(x)
# Generator Network
class Generator(nn.Module):
def __init__(self, latent_dim, output_dim):
super().__init__()
self.main = nn.Sequential(
nn.Linear(latent_dim, 64),
nn.ReLU(),
nn.Linear(64, output_dim)
)
def forward(self, z):
return self.main(z)
