Homomorphic Encryption

Perform computations on encrypted data without ever decrypting it
Intermediate Cryptography Privacy O(poly(λ, N))
1
Understanding Homomorphic Encryption
▼

What is it? Homomorphic encryption (HE) is a form of encryption that allows computations to be performed on ciphertext, generating an encrypted result which, when decrypted, matches the result of operations performed on the plaintext. In simpler terms, you can process sensitive data in the cloud without ever exposing it in an unencrypted form.

Analogy: Imagine you have a magical pair of gloves and a locked box. You can put sensitive documents (plaintext) into the box. Then, without ever opening the box or taking off your gloves, you can manipulate the documents inside (perform computations). When you're done, you hand the box to someone else, who opens it with their own key and sees the result of your manipulations, but never saw the original documents or the intermediate steps. Homomorphic encryption is like those gloves and that box: data stays encrypted, computations happen, and only the owner can unlock the final result.

💡 If you remember one thing

Homomorphic encryption enables privacy-preserving computation: a third party (e.g., a cloud server) can perform arbitrary operations (like addition or multiplication) on your encrypted data, and the result remains encrypted. Only you can decrypt the final result to reveal the computed plaintext.

2
How It Works Internally
▼

The Homomorphic Property

The core idea of HE is that an operation on encrypted values \(E(m_1)\) and \(E(m_2)\) yields an encrypted result \(E(m_1 \circ m_2)\), where \(\circ\) is some plaintext operation. For example, an additively homomorphic scheme might allow \(E(m_1) \cdot E(m_2) = E(m_1 + m_2)\). Notice the ciphertext operation (multiplication) maps to a different plaintext operation (addition).

Types of Homomorphic Encryption

  • Partially Homomorphic Encryption (PHE): Supports one type of operation (e.g., only addition, or only multiplication) an unlimited number of times. Examples include RSA (multiplicative) and Paillier (additive).
  • Somewhat Homomorphic Encryption (SHE): Supports both addition and multiplication, but only for a limited number of operations before the ciphertext becomes too "noisy" to decrypt correctly.
  • Fully Homomorphic Encryption (FHE): The holy grail. Supports both addition and multiplication an unlimited number of times. This allows for arbitrary computations. The first FHE scheme was proposed by Craig Gentry in 2009.

The Challenge: Noise Accumulation

Most practical HE schemes (especially SHE and FHE) are based on lattice problems. When you perform operations on ciphertexts, a small amount of "noise" is added to the encrypted data. This noise is crucial for security, making it hard for attackers to distinguish between valid ciphertexts and random data. However, with each homomorphic operation, the noise grows. If the noise level exceeds a certain threshold, the ciphertext becomes undecryptable, and the original plaintext is lost.

The Solution: Bootstrapping

Gentry's breakthrough for FHE was the concept of bootstrapping. This is a clever technique where a noisy ciphertext is "refreshed" into a new, less noisy ciphertext that encrypts the same plaintext. Crucially, this refreshing process itself is performed homomorphically (i.e., on the encrypted data), without ever decrypting the data. By repeatedly bootstrapping, FHE schemes can perform an unlimited number of operations.

🔑 Key Property

The "noise" in HE schemes is a security feature, but also their Achilles' heel. Managing this noise (especially through bootstrapping for FHE) is the primary challenge and source of computational overhead.

Why It Works — A Simplified Paillier Scheme
▼

Paillier Encryption (Additive Homomorphism)

We'll use a simplified version of the Paillier cryptosystem to illustrate additive homomorphism. Let \(N\) be a large prime (for simplicity, we'll use a small prime for the demo). Key generation involves choosing two large primes, \(p\) and \(q\), and setting \(N = pq\). We also need a generator \(g\) and a random number \(r\).

The core operations are:

1. Key Generation: Alice chooses a prime \(N\) (e.g., 7). She computes \(\lambda = N-1\) and \(\mu = (L(g^\lambda \pmod{N^2}))^{-1} \pmod N\), where \(L(x) = (x-1)/N\). The Public Key is \((N, g)\) and the Private Key is \((\lambda, \mu)\).

2. Encryption of a plaintext \(m \in [0, N-1]\): Alice chooses a random \(r \in [1, N-1]\) and computes the ciphertext \(C\):

$$C = g^m \cdot r^N \pmod{N^2}$$

3. Decryption of a ciphertext \(C\): Alice uses her private key to recover the plaintext \(m\):

$$m = L(C^\lambda \pmod{N^2}) \cdot \mu \pmod N$$

The Homomorphic Property (Addition)

The magic happens when two ciphertexts \(C_1 = E(m_1)\) and \(C_2 = E(m_2)\) are multiplied. Let \(C_1 = g^{m_1} r_1^N \pmod{N^2}\) and \(C_2 = g^{m_2} r_2^N \pmod{N^2}\). Their product is:

$$C_{sum} = C_1 \cdot C_2 \pmod{N^2} = (g^{m_1} r_1^N) \cdot (g^{m_2} r_2^N) \pmod{N^2}$$

Rearranging the terms, we get:

$$C_{sum} = g^{m_1+m_2} \cdot (r_1 r_2)^N \pmod{N^2}$$

This result is exactly in the form of an encryption of \(m_1+m_2\), with a new random factor \((r_1 r_2)\). Thus, multiplying ciphertexts homomorphically adds their underlying plaintexts. This is the fundamental property that allows computations on encrypted data.

⚠️ Practical Limitations

While mathematically elegant, Paillier is only additively homomorphic (you can only add plaintexts). FHE schemes, which allow both addition and multiplication, are far more complex, computationally intensive (many orders of magnitude slower than plaintext operations), and introduce the noise management challenges discussed in Card 2.

Key Takeaways
▼

When to use Homomorphic Encryption:

  • Privacy-preserving machine learning: Train models on encrypted data, or make predictions on encrypted inputs without revealing the data to the model owner.
  • Secure cloud computing: Delegate computation of sensitive data (e.g., financial records, medical data) to untrusted cloud servers.
  • Secure voting systems: Tally encrypted votes without revealing individual choices.
  • Confidential blockchain transactions: Perform computations on encrypted transaction amounts.

When NOT to use:

  • High-performance computing: HE operations are significantly slower and require more memory than plaintext operations, often by orders of magnitude.
  • Simple data processing without privacy concerns: The overhead is not justified for non-sensitive data or when other privacy techniques (like secure multi-party computation or differential privacy) are more suitable.
  • General-purpose computing where real-time interaction is critical: The latency introduced by HE can be prohibitive.
💡 Big Picture

Homomorphic encryption is a powerful theoretical tool becoming increasingly practical. While PHE schemes are relatively mature, FHE remains a cutting-edge field with ongoing research focused on improving efficiency and reducing the computational cost of bootstrapping, paving the way for wider adoption in privacy-critical applications.

Code Trace (Simplified Paillier Logic)
▼
import math
# Helper for L-function in Paillier: L(x) = (x - 1) // N
def L(x, N):
return (x - 1) // N
# Modular inverse: a^-1 mod m
def mod_inv(a, m):
# Extended Euclidean algorithm for gcd(a, m) = 1
m0, x0, x1 = m, 0, 1
while a > 1:
q = a // m0
m0, a = a % m0, m0
x0, x1 = x1 - q * x0, x0
return x1 + m if x1 < 0 else x1
class PaillierCipher:
def __init__(self, N, g, r): # N, g for public key; r for encryption randomness
self.N = N
self.N_squared = N * N
self.g = g
self.r = r # Fixed for demo, usually random per encryption
# Private key components: lambda, mu
self.lam = N # Simplified for N prime, should be LCM of p-1,q-1
# mu = (L(g^lam mod N_squared))^-1 mod N
g_lam_mod_N_squared = pow(self.g, self.lam, self.N_squared)
self.mu = mod_inv(L(g_lam_mod_N_squared, self.N), self.N)
def encrypt(self, m):
# C = g^m * r^N mod N^2
return (pow(self.g, m, self.N_squared) * pow(self.r, self.N, self.N_squared)) % self.N_squared
def decrypt(self, c):
# m = L(C^lam mod N_squared) * mu mod N
c_lam_mod_N_squared = pow(c, self.lam, self.N_squared)
return (L(c_lam_mod_N_squared, self.N) * self.mu) % self.N
# Homomorphic addition: E(m1) * E(m2) = E(m1+m2)
def add_ciphertexts(self, c1, c2):
return (c1 * c2) % self.N_squared
# --- Demo Usage (matches explainer values) ---
N_val, g_val, r_val = 7, 8, 2
paillier = PaillierCipher(N_val, g_val, r_val)
m1 = 2
m2 = 3
c1 = paillier.encrypt(m1) # Expected: 9
c2 = paillier.encrypt(m2) # Expected: 23
c_sum = paillier.add_ciphertexts(c1, c2) # Expected: 11
decrypted_sum = paillier.decrypt(c_sum) # Expected: 5
print(f"m1={m1}, m2={m2}")
print(f"c1={c1}, c2={c2}")
print(f"c_sum={c_sum}")
print(f"decrypted_sum={decrypted_sum}") # Should be m1+m2
