1
Understanding Set Theory
▼

What is it? A set is simply a collection of distinct objects. No repetitions, no order — just membership. Every branch of mathematics (and much of computer science) is built on this deceptively simple idea. Set theory is the language in which all mathematical structures are written.

Analogy: Think of a set as a bag with no duplicates and no concept of "position." A bag containing {apple, banana, cherry} is identical to a bag containing {cherry, apple, banana}. You can only ask "is X in the bag?" not "what is item #2?"

💡 If you remember one thing

A set is defined entirely by its members (the Axiom of Extensionality): \(A = B \iff \forall x\,(x \in A \leftrightarrow x \in B)\). The three fundamental operations — union \(A \cup B\), intersection \(A \cap B\), and complement \(A^c\) — satisfy the same laws as Boolean logic.

Core Set Operations

Given sets \(A\) and \(B\) within a universe \(U\):

  • Union: \(A \cup B = \{x \mid x \in A \text{ or } x \in B\}\) — everything in either set
  • Intersection: \(A \cap B = \{x \mid x \in A \text{ and } x \in B\}\) — only what both share
  • Difference: \(A \setminus B = \{x \mid x \in A \text{ and } x \notin B\}\) — in A but not B
  • Complement: \(A^c = U \setminus A = \{x \in U \mid x \notin A\}\) — everything in U not in A
  • Cartesian Product: \(A \times B = \{(a,b) \mid a \in A,\, b \in B\}\) — all ordered pairs

Key Laws (De Morgan & Distributivity)

$$\overline{A \cup B} = \overline{A} \cap \overline{B} \qquad \overline{A \cap B} = \overline{A} \cup \overline{B}$$
$$A \cap (B \cup C) = (A \cap B) \cup (A \cap C)$$

These are identical to Boolean algebra laws — not a coincidence. Set membership is a proposition, and proposition logic is set theory in disguise.

🔑 Cardinality & Power Sets

The cardinality \(|A|\) is the number of elements. For a finite set \(A\), the power set \(\mathcal{P}(A)\) — the set of all subsets — has \(|\mathcal{P}(A)| = 2^{|A|}\). For \(A = \{1,2,3\}\), \(|\mathcal{P}(A)| = 8\). Inclusion-Exclusion: \(|A \cup B| = |A| + |B| - |A \cap B|\).

Relations on Sets
▼

A binary relation \(R\) on a set \(S\) is a subset of \(S \times S\). We write \(a\,R\,b\) to mean \((a,b) \in R\). Relations capture how elements of a set are "connected" to each other.

The Four Key Properties

  • Reflexive: \(\forall a \in S,\; (a,a) \in R\) — every element relates to itself (e.g., "≤" on numbers)
  • Symmetric: \(\forall a,b \in S,\; (a,b) \in R \Rightarrow (b,a) \in R\) — if a relates to b then b relates to a (e.g., "is sibling of")
  • Antisymmetric: \((a,b)\in R \wedge (b,a)\in R \Rightarrow a=b\) — the only symmetric pairs are self-loops (e.g., "≤")
  • Transitive: \((a,b)\in R \wedge (b,c)\in R \Rightarrow (a,c)\in R\) — connectivity chains close (e.g., "ancestor of")
🔑 Equivalence Relations & Partitions

A relation that is reflexive + symmetric + transitive is an equivalence relation (written \(\sim\)). Every equivalence relation on \(S\) partitions \(S\) into disjoint equivalence classes \([a] = \{b \in S \mid a \sim b\}\). Example: congruence modulo \(n\): \(a \equiv b \pmod{n}\) iff \(n \mid (a-b)\). This partitions \(\mathbb{Z}\) into \(n\) classes.

Partial and Total Orders

A partial order is reflexive, antisymmetric, and transitive — like subset inclusion \(\subseteq\). Not every pair needs to be comparable. A total order additionally requires that every pair is comparable: \(\forall a,b:\; a \leq b\) or \(b \leq a\). The real numbers under "≤" form a total order; subsets under "⊆" form only a partial order.

⚠️ Common Confusion

Symmetric and antisymmetric are NOT opposites. A relation can be both (only self-loops remain), or neither (e.g., the "parent of" relation). Reflexivity is about self-pairs \((a,a)\); symmetry is about reversibility of pairs \((a,b)/(b,a)\). Check each property independently.

Composition of Relations

Given relations \(R \subseteq A \times B\) and \(S \subseteq B \times C\), their composition is \(S \circ R = \{(a,c) \mid \exists b:\; (a,b) \in R \wedge (b,c) \in S\}\). The transitive closure \(R^+\) adds all pairs reachable by chains: \(R^+ = R \cup R^2 \cup R^3 \cup \cdots\). This is exactly what graph reachability computes.

Functions: Injective, Surjective, Bijective
▼

A function \(f: A \to B\) is a special relation where each element of the domain \(A\) maps to exactly one element of the codomain \(B\). The range (image) is \(f(A) = \{f(a) \mid a \in A\} \subseteq B\).

$$f: A \to B \text{ is a function} \iff \forall a \in A,\; \exists! b \in B:\; (a,b) \in f$$

Three Critical Properties

  • Injective (one-to-one): \(f(a_1) = f(a_2) \Rightarrow a_1 = a_2\) — different inputs give different outputs. No two arrows land on the same point. Equivalently, \(|f^{-1}(\{b\})| \leq 1\) for all \(b\).
  • Surjective (onto): \(\forall b \in B,\; \exists a \in A:\; f(a) = b\) — every codomain element is hit. The range equals the codomain: \(f(A) = B\).
  • Bijective (one-to-one correspondence): Both injective AND surjective. Every \(b\) has exactly one preimage. Bijections have inverses: \(f^{-1}: B \to A\) is itself a bijection.
📐 Cardinality Test

For finite sets: if \(f: A \to B\) is injective, then \(|A| \leq |B|\). If surjective, then \(|A| \geq |B|\). If bijective, \(|A| = |B|\). For infinite sets, bijection is the definition of equal cardinality — this is how Cantor proved that \(|\mathbb{Z}| = |\mathbb{Q}|\) but \(|\mathbb{R}| > |\mathbb{Z}|\).

Composition & Inverse

Given \(f: A \to B\) and \(g: B \to C\), the composition is \((g \circ f)(a) = g(f(a)): A \to C\). Composition of injections is injective; composition of surjections is surjective; composition of bijections is bijective. A function \(f\) has an inverse \(f^{-1}\) if and only if it is bijective.

Why This Matters in CS/ML

  • Hash functions: aim to be surjective onto bucket space, but collisions make them non-injective
  • Encoding/decoding: a codec must be bijective — lossless compression is a bijection between representations
  • Embeddings: \(f: \text{words} \to \mathbb{R}^d\) — usually not injective in theory but approximately so in practice
  • Invertible networks (normalizing flows): explicitly require bijections so the change-of-variables formula applies
💡 The Pigeonhole Principle

If \(|A| > |B|\), then no function \(f: A \to B\) can be injective — at least two inputs must share the same output. This simple observation drives collision proofs, birthday paradox calculations, and complexity lower bounds.

Key Takeaways
▼

Sets

  • Defined by membership alone — extensionality axiom
  • Operations: union, intersection, difference, complement, Cartesian product
  • De Morgan's laws connect complement to union/intersection
  • Inclusion-Exclusion: \(|A \cup B| = |A|+|B|-|A\cap B|\)

Relations

  • A relation \(R \subseteq A \times B\) is a set of ordered pairs
  • Equivalence = reflexive + symmetric + transitive → partitions the set into classes
  • Partial order = reflexive + antisymmetric + transitive (e.g., ⊆, ≤)

Functions

  • Injective: no two inputs share an output — necessary for left-invertibility
  • Surjective: every codomain element is reached — necessary for right-invertibility
  • Bijective: perfect pairing — the only functions with two-sided inverses
💡 The Hierarchy

Bijection ⊂ Injection ⊂ Function and Bijection ⊂ Surjection ⊂ Function. Every function is a relation; every relation is a set of pairs; every set is built from the empty set \(\varnothing\). This nesting is the foundation of all rigorous mathematics.

inter = A & B # {3,4}

# ── RELATIONS ──
S = {1, 2, 3}
R = {(1,1),(2,2),(3,3),(1,2),(2,1)} # equivalence relation
def is_reflexive(S, R): return all((a,a) in R for a in S)
def is_symmetric(R): return all((b,a) in R for (a,b) in R)
def is_transitive(R): return all((a,c) in R for (a,b) in R for (b2,c) in R if b==b2)
def is_equivalence(S, R): return is_reflexive(S,R) and is_symmetric(R) and is_transitive(R)
print(is_equivalence(S, R)) # True
# Equivalence classes
def eq_classes(S, R):
classes, seen = [], set()
for a in S:
if a not in seen:
cls = frozenset(b for b in S if (a,b) in R)
classes.append(cls); seen |= cls
return classes # [{1,2}, {3}]
# ── FUNCTIONS ──
def is_injective(f): return len(set(f.values())) == len(f)
def is_surjective(f, codomain): return set(f.values()) == codomain
def is_bijective(f, codomain): return is_injective(f) and is_surjective(f, codomain)

f_neither = {'a':1,'b':1,'c':3} # not injective, not surjective onto {1,2,3}
