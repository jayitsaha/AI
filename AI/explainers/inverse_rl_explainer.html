1
Understanding Inverse RL
▼

What is it? In standard Reinforcement Learning (RL), you define a reward function \(R(s,a)\) and an agent learns a policy \(\pi(s)\) to maximize cumulative rewards. Inverse RL flips this: you observe an "expert" agent's demonstrations (trajectories \(\tau\)), and your goal is to infer the underlying reward function \(R(s,a)\) that best explains why the expert acted the way it did. Once you have \(R\), you can use it to train your own (potentially better) agent.

Analogy: Imagine watching someone cook a meal. You see their actions (chopping, stirring, adding spices) and the final dish. In regular RL, you'd tell the chef "maximize deliciousness, minimize mess." In Inverse RL, you don't know the recipe (reward function). You just watch them cook and try to figure out what they value: "Ah, they added basil, so basil must be good. They avoided burning the onions, so burning onions must be bad." You then try to write down a recipe that, if followed, would produce exactly what you observed.

💡 If you remember one thing

IRL aims to find a reward function \(R\) such that the expert's observed behavior is (near-)optimal with respect to \(R\). This is often framed as finding \(R\) whose optimal policy matches the expert's feature expectations.

2
How Inverse RL Works Internally
▼

The Core Idea: Feature Expectation Matching

Most practical IRL algorithms (like Apprenticeship Learning, Abbeel & Ng, 2004) assume the reward function can be expressed as a linear combination of features: \(R(s) = w \cdot \phi(s)\), where \(\phi(s)\) is a vector of features describing state \(s\), and \(w\) is a vector of unknown weights. The goal is to find \(w\). The key insight is that an optimal policy will accumulate high total feature values. So, if we find a reward function \(R\) such that its optimal policy \(\pi_R\) has feature expectations \(\mathbb{E}_{\pi_R}[\sum_t \phi(s_t)]\) that match the expert's feature expectations \(\mathbb{E}_{\pi_E}[\sum_t \phi(s_t)]\), then \(\pi_R\) is a good approximation of \(\pi_E\).

The Iterative Algorithm

A common approach is iterative:

  1. Initialize a random reward weight vector \(w\).
  2. Solve RL: Use standard RL (e.g., Value Iteration) to find the optimal policy \(\pi_R\) for the current reward function \(R(s) = w \cdot \phi(s)\).
  3. Compute Feature Expectations: Calculate the feature expectations \(\mu_R = \mathbb{E}_{\pi_R}[\sum_t \phi(s_t)]\) under the current policy \(\pi_R\).
  4. Compare & Update: Compare \(\mu_R\) with the expert's feature expectations \(\mu_E\). Update \(w\) to reduce the discrepancy between \(\mu_R\) and \(\mu_E\). For example, if \(\mu_R\) has too much "lava avoidance" compared to \(\mu_E\), we might make the "lava" feature less negative in \(w\).
  5. Repeat until \(w\) converges or \(\mu_R\) closely matches \(\mu_E\).
This process is essentially a search in the space of reward functions, guided by how well the resulting policies mimic the expert's observed feature usage.

Design Decision: Why Feature Expectations?

Directly matching expert trajectories can be brittle due to stochasticity or sub-optimality. Feature expectations provide a robust, summary statistic of behavior. They capture the "kind" of states an agent visits and actions it takes, rather than the exact sequence. This allows for generalization and robustness to minor deviations in expert demonstrations. It's often easier to match the *overall style* of behavior than every single step.

🔑 Key Property

The problem of finding a reward function \(R\) is ill-posed: many different \(R\) can induce the same optimal policy. IRL algorithms often add regularization (e.g., Maximum Entropy IRL) or aim for a robust solution within this ambiguity.

3
Why It Works — The Math
▼

The Reward Function Parameterization

We assume the reward function \(R(s)\) (for simplicity, state-dependent only) can be parameterized linearly by a set of features \(\phi(s) \in \mathbb{R}^k\):

$$R(s) = w^\top \phi(s)$$

where \(w \in \mathbb{R}^k\) is the vector of unknown weights we want to learn. The expert provides a set of demonstrations \(\mathcal{D}_E = \{\tau_1, \dots, \tau_m\}\), where each trajectory \(\tau = (s_0, s_1, \dots, s_T)\) is a sequence of states (and actions, if applicable).

Feature Expectation Matching Objective

The core idea is to find \(w\) such that the feature expectations of the optimal policy for \(R(s)\) match those of the expert. Let \(\mu_E\) be the expert's average feature expectations:

$$\mu_E = \mathbb{E}_{\tau \sim \mathcal{D}_E} \left[ \sum_{t=0}^T \gamma^t \phi(s_t) \right]$$

And let \(\mu_R(w)\) be the feature expectations of the optimal policy \(\pi_R\) derived from the reward function \(R(s) = w^\top \phi(s)\). We want to minimize the difference between these two:

$$\min_w \| \mu_E - \mu_R(w) \|_2^2$$

This is a non-convex optimization problem because \(\mu_R(w)\) is a complex function of \(w\) (it involves solving an MDP). Practical algorithms often use gradient-based methods or approximations. A common update rule (e.g., in Maximum Causal Entropy IRL) is to adjust \(w\) in the direction of the difference between expert and current policy feature expectations:

$$w \leftarrow w + \alpha (\mu_E - \mu_R(w))$$

where \(\alpha\) is a learning rate. This pushes the reward weights \(w\) to favor features that the expert visits more than the current policy does, and penalize features that the current policy visits more than the expert.

⚠️ Common Pitfall

IRL is computationally intensive. Each iteration requires solving a full RL problem (e.g., Value Iteration) to get \(\pi_R\) and then computing its feature expectations. For large state spaces, this can be prohibitively slow. Approximate methods (e.g., using neural networks for \(\phi\) and \(R\), or sampling for \(\mu_R\)) are often necessary.

Key Takeaways
▼

When to use Inverse RL:

  • When defining a reward function manually is hard (e.g., complex robotic tasks, human preferences).
  • To transfer skills from human demonstrations to an autonomous agent.
  • To understand expert behavior by uncovering their underlying motivations.
  • When the environment changes, and you need a robust reward function to re-optimize a policy.

Limitations and challenges:

  • Ambiguity: Multiple reward functions can explain the same expert behavior. Additional assumptions (e.g., maximum entropy) are often needed.
  • Expert Suboptimality: IRL assumes the expert is optimal. If demonstrations are noisy or suboptimal, the learned reward function might be flawed.
  • Feature Engineering: The quality of the learned reward depends heavily on the chosen features \(\phi(s)\). Poor features can lead to poor reward functions.
  • Computational Cost: Iteratively solving an MDP can be very expensive for large state/action spaces.
💡 IRL vs. Imitation Learning

Imitation Learning (IL) directly learns a policy \(\pi(s)\) from expert demonstrations, mapping states to actions. It's often simpler but struggles with compounding errors (out-of-distribution states). IRL learns the reward function \(R(s)\) first, then uses standard RL to derive a policy. This is more robust to environment changes and can generalize better, but is more complex.
