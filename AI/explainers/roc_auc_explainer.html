1
Understanding the Concept

What is this? A binary classifier doesn't just output "yes" or "no" — it outputs a score (a number between 0 and 1). You pick a threshold to convert that score into a label. The ROC curve shows how the quality of that split changes as you sweep the threshold from 0 to 1. The AUC (area under that curve) summarizes it in one number.

Analogy: the security scanner. Imagine airport security scanning bags. Sensitivity tells you: "of all bags with dangerous items, how many did we catch?" (True Positive Rate). False Alarm Rate tells you: "of all safe bags, how many did we falsely flag?" (False Positive Rate). If you crank sensitivity to 100%, you flag every single bag — but now your false alarm rate is also 100%. The ROC curve traces every possible operating point of this trade-off.

💡 If you remember one thing

AUC = the probability that a randomly chosen positive example gets a higher model score than a randomly chosen negative example. A random classifier has AUC = 0.5; a perfect one has AUC = 1.0.

Key terms: TPR (sensitivity/recall) = TP/(TP+FN). FPR (fall-out) = FP/(FP+TN). The ROC curve plots TPR on the y-axis vs FPR on the x-axis as threshold decreases from 1 to 0.

2
How It Works Internally

The algorithm is exactly this:

1. Sort all examples by predicted score (descending). 2. For each unique threshold value (i.e., each score in the dataset, plus ∞ and −∞), compute TPR and FPR. 3. Plot each (FPR, TPR) point. 4. Connect the dots. The area under the resulting curve is the AUC.

🔑 The Wilcoxon-Mann-Whitney statistic

AUC equals the probability \(\text{AUC} = P(\hat{s}_{+} > \hat{s}_{-})\) where \(\hat{s}_{+}\) is the score of a random positive and \(\hat{s}_{-}\) of a random negative. This is the Wilcoxon-Mann-Whitney U statistic normalized by the product of class sizes.

Efficient implementation: sklearn uses a merge-sort-based algorithm — sort by descending score (\(O(n \log n)\)), then sweep left-to-right accumulating TP and FP counts. The trapezoidal rule computes the area in \(O(n)\) after sorting.

⚠️ Common Mistake

AUC is threshold-independent — it evaluates the ranking quality of the model, not any particular operating point. Don't pick your deployment threshold by maximizing AUC; use the ROC curve to find the threshold that meets your business constraint (e.g., max FPR ≤ 5%).

Design decisions: Why FPR and not precision on the x-axis? Because FPR is invariant to class imbalance changes — adding more negatives doesn't change FPR at a fixed threshold. This is why ROC is preferred when class prevalence may shift, but Precision-Recall is preferred when imbalance is severe and you care only about positives.

3
The Math

Given a dataset with \(P\) positives and \(N\) negatives, and a threshold \(t\):

$$\text{TPR}(t) = \frac{\text{TP}(t)}{P}, \qquad \text{FPR}(t) = \frac{\text{FP}(t)}{N}$$

The ROC curve is the parametric curve \(\bigl(\text{FPR}(t),\, \text{TPR}(t)\bigr)\) as \(t\) decreases from \(+\infty\) to \(-\infty\).

AUC via trapezoidal rule: Let the curve have points \((x_0, y_0), (x_1, y_1), \ldots, (x_k, y_k)\) sorted by ascending FPR. Then:

$$\text{AUC} = \sum_{i=1}^{k} (x_i - x_{i-1}) \cdot \frac{y_i + y_{i-1}}{2}$$

Probabilistic interpretation (proof sketch): Let \(f\) be the classifier score function. For uniform draws \(X_+ \sim P\) and \(X_- \sim N\):

$$\text{AUC} = \int_0^1 \text{TPR}(\text{FPR}^{-1}(u))\, du = P\!\left(f(X_+) > f(X_-)\right)$$

This follows from a change of variable from threshold \(t\) to FPR \(u\). The integrand at each FPR value \(u\) is exactly the fraction of positives scored above the threshold that gives FPR = \(u\).

Multi-class AUC (OvR macro-average): For \(C\) classes, train \(C\) binary classifiers. Compute AUC for class \(c\) by treating class \(c\) as positive and all others as negative:

$$\text{AUC}_{\text{macro}} = \frac{1}{C} \sum_{c=1}^{C} \text{AUC}_c$$
📐 Partial AUC (pAUC)

When only low FPR matters (e.g., medical screening), compute pAUC over FPR ∈ [0, \(\alpha\)] and normalize by \(\alpha\): \(\text{pAUC}_\alpha = \frac{1}{\alpha}\int_0^\alpha \text{TPR}(u)\,du\).

⚠️ OvR vs OvO

OvR (One-vs-Rest) is simpler but can be biased if classes are imbalanced. OvO (One-vs-One) trains \(\binom{C}{2}\) classifiers and averages pairwise AUC — less biased but expensive. sklearn's roc_auc_score(multi_class='ovo') is the Hand-Till generalization, which equals the average of all pairwise AUC values.

🎯 Decision Rules

Use AUC-ROC when: class prevalence may shift at deployment, or you want threshold-free ranking evaluation.
Use AUC-PR when: positives are rare (fraud, cancer) and you must minimize false negatives without inflating false positives.
Use partial AUC when: a specific FPR operating region matters (e.g., FPR ≤ 10% for screening).
