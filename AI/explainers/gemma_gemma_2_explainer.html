Understanding Gemma
▼

What is it? Gemma is a family of lightweight, open-weight language models developed by Google DeepMind, built on the same research lineage as the Gemini models. They are decoder-only transformers designed for text generation, summarization, reasoning, and code tasks, available in sizes from 2B to 27B parameters.

Analogy: Think of Gemma 1 as a single expert translator who reads one reference dictionary at a time (Multi-Query Attention). Gemma 2 upgrades to a small team of translators sharing a few dictionaries among them (Grouped-Query Attention) -- still fast, but with richer understanding because each sub-team specializes while sharing common references.

Key Insight

Gemma 2 achieves performance competitive with models 2-3x its size by combining Grouped-Query Attention (GQA), sliding window + global attention alternation, RMSNorm applied both pre- and post-layer (dual normalization), and soft-capping of logits for training stability. These are surgical architectural changes -- no fundamental paradigm shift, yet they yield outsized gains.

2
Gemma 1 vs Gemma 2 Architecture
▼

Shared Foundation

Both Gemma 1 and 2 are decoder-only transformer stacks using RoPE (Rotary Position Embeddings) for relative position encoding, GeGLU activation in the feed-forward network (replacing standard ReLU/GELU), and RMSNorm instead of LayerNorm. The vocabulary uses a SentencePiece tokenizer with 256K tokens.

Key Differences in Gemma 2

1. Grouped-Query Attention (GQA): Gemma 1 uses Multi-Query Attention (MQA) where all query heads share a single KV head. Gemma 2 uses GQA with multiple KV groups, balancing inference speed and model quality. For the 9B model, 16 query heads share 8 KV heads (ratio 2:1); for 27B, 32 query heads share 16 KV heads.

2. Sliding Window + Global Attention: Gemma 2 alternates between local sliding-window attention (4096-token window) on odd layers and full global attention on even layers, reducing the quadratic cost of full attention while preserving long-range reasoning.

3. Post-Norm + Pre-Norm (Dual RMSNorm): Gemma 1 applies RMSNorm only before each sub-layer (pre-norm). Gemma 2 adds a second RMSNorm after each sub-layer too, which empirically stabilizes training at scale.

4. Logit Soft-Capping: Attention logits are capped at 50.0 and final logits at 30.0 using \(\text{cap} \cdot \tanh(x / \text{cap})\), preventing extreme values from destabilizing training.

Attention Mechanisms: MQA vs GQA
▼

Standard Multi-Head Attention (MHA) computes \(h\) independent attention heads, each with its own Query, Key, and Value projections of dimension \(d_k = d_{\text{model}} / h\):

$$\text{Attn}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Multi-Query Attention (Gemma 1)

MQA uses \(h\) query heads but only one shared Key and Value head. This dramatically reduces the KV cache size from \(O(h \cdot d_k)\) to \(O(d_k)\) per token per layer, enabling faster autoregressive inference. Each query head \(Q_i\) attends against the same \(K\) and \(V\):

$$\text{head}_i = \text{softmax}\!\left(\frac{Q_i K^\top}{\sqrt{d_k}}\right)V, \quad K, V \text{ shared across all } i$$

Grouped-Query Attention (Gemma 2)

GQA partitions the \(h\) query heads into \(g\) groups, each group sharing one KV head. With \(g = h\), GQA degenerates to MHA; with \(g = 1\), it becomes MQA. Gemma 2 uses \(g = h/2\) (two query heads per KV head), striking a balance between capacity and efficiency:

$$\text{head}_i = \text{softmax}\!\left(\frac{Q_i K_{g(i)}^\top}{\sqrt{d_k}}\right)V_{g(i)}, \quad g(i) = \lfloor i \cdot g / h \rfloor$$

GeGLU Activation

The FFN in both Gemma versions uses the Gated Linear Unit variant with GELU gating:

$$\text{GeGLU}(x) = \text{GELU}(xW_1) \odot (xW_2)$$

where \(W_1, W_2 \in \mathbb{R}^{d_{\text{model}} \times d_{\text{ff}}}\) and \(\odot\) is element-wise multiplication. This adds a multiplicative gate that helps the network learn which features to pass through.

KV Cache Comparison

For a sequence of length \(L\) with \(n\) layers:
MHA: \(2 \cdot n \cdot L \cdot h \cdot d_k\) parameters in cache
MQA: \(2 \cdot n \cdot L \cdot d_k\) (factor \(h\) reduction)
GQA (g groups): \(2 \cdot n \cdot L \cdot g \cdot d_k\) (factor \(h/g\) reduction)

Model Variants & Parameter Counts
▼

Each Gemma variant is fully specified by its hidden dimension \(d\), number of layers \(L\), query heads \(h\), KV heads \(h_{\text{kv}}}\), and FFN intermediate dimension \(d_{\text{ff}}}\). The parameter budget is dominated by: embeddings (\(V \times d\)), attention projections (\(L \times (d \times d + 2 \times d \times d_k \times h_{\text{kv}})\)), and FFN weights (\(L \times 2 \times d \times d_{\text{ff}}}\) for GeGLU's dual projection, plus the output projection).

Design Trade-off

Gemma 2 9B has more layers (42 vs 28) but a wider FFN than Gemma 1 7B. The philosophy shifted from "fewer, wider layers" to "more, narrower layers with better attention" -- distributing capacity across depth rather than width, aided by the stabilizing effect of dual RMSNorm.

5
Key Takeaways
▼

When to choose Gemma 2 over Gemma 1: Always, if your hardware supports it. Gemma 2 strictly dominates Gemma 1 on quality benchmarks at similar parameter counts while maintaining comparable inference throughput thanks to GQA's KV cache efficiency.

GQA vs MQA: MQA is maximally aggressive on cache compression but sacrifices representational capacity. GQA recovers most of MHA's quality while keeping 50-75% of MQA's speed advantage. The sweet spot for production serving is GQA with a 2:1 query-to-KV ratio.

Sliding window attention: By alternating local (4096-token) and global layers, Gemma 2 ensures every token can reach any other token within 2 layers, while individual layers only pay quadratic cost over the window size. This is similar to Mistral's approach.

Key Concept

Gemma 2's improvements are composable engineering: each change (GQA, dual-norm, soft-capping, sliding window) is individually well-understood, but their combination yields a model family that punches far above its weight class, proving that architecture refinement matters as much as scale.
