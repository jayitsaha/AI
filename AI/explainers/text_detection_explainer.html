1
Understanding Text Detection
▼

What is it? Text detection is the task of localizing text instances in natural scene images or documents by predicting their bounding boxes or polygons. It's the crucial first step in any Optical Character Recognition (OCR) pipeline, acting as a "where's the text?" stage before OCR attempts to "what does it say?"

Analogy: Imagine you're trying to read all the sticky notes scattered across a very cluttered desk. Text detection is like drawing a perfect box around each individual sticky note, no matter its size, angle, or whether it's curved. Once you have those boxes, OCR is the process of then reading the actual handwriting on each note. Without good detection, OCR is impossible.

The core challenge lies in the immense variability of text in the wild: arbitrary orientations, diverse scales, varying aspect ratios, different fonts, colors, and complex backgrounds. Early methods often struggled with non-horizontal or curved text.

💡 If you remember one thing

Text detection models output geometric primitives (axis-aligned rectangles, rotated boxes, or arbitrary polygons) that precisely localize text instances in an image. They are typically fully convolutional networks that predict pixel-level maps which are then post-processed into final detections.

2
How Text Detection Works Internally
▼

Modern text detection models typically use a Fully Convolutional Network (FCN) backbone (like ResNet or VGG) combined with a Feature Pyramid Network (FPN) to handle text at multiple scales. The key difference between models lies in their output representation and the post-processing steps.

EAST (Efficient and Accurate Scene Text Detector)

EAST (Zhou et al., 2017) is a single-stage, end-to-end text detector designed for speed. It directly predicts word or text line regions from the full image. Its outputs are:

  • Score Map: A pixel-level binary classification map indicating the probability of a pixel belonging to a text region.
  • Geometry Map: For each text pixel, it predicts the distances to the four boundaries of its bounding box (top, right, bottom, left) and the orientation angle of the box. This forms a Rotated Bounding Box (RBOX).

Post-processing involves non-maximum suppression (NMS) on the predicted RBOXes to merge overlapping detections into final, distinct rotated rectangles. EAST is fast and accurate for quadrilateral text, but struggles with highly curved text.

CRAFT (Character Region Awareness for Text)

CRAFT (Baek et al., 2019) focuses on detecting individual characters and then linking them to form words/lines. This character-level approach makes it highly robust to arbitrary text shapes, including curved text. Its outputs are:

  • Character Region Score Map: A heatmap indicating the likelihood of a pixel being part of a character.
  • Affinity Score Map: A heatmap indicating the likelihood of two adjacent characters being part of the same text instance.

Post-processing uses a watershed algorithm or Breadth-First Search (BFS) to group character regions into word/line instances based on the affinity map, generating precise polygonal detections.

DBNet (Differentiable Binarization Network)

DBNet (Liao et al., 2020) introduces "differentiable binarization," allowing the binarization process (converting probability maps to binary text regions) to be integrated into the network and optimized end-to-end. This leads to sharper boundaries and more accurate polygon generation. Its outputs are:

  • Probability Map: Similar to EAST's score map, indicating text likelihood.
  • Threshold Map: A pixel-level map predicting an adaptive threshold for binarization, instead of using a fixed global threshold.

The probability map is binarized using the adaptive threshold map, creating tight text regions. Post-processing then uses a polygon approximation algorithm (e.g., Vatti clipping) to convert these binary regions into precise polygonal bounding boxes.

🔑 Key Property

The evolution of text detection models shows a trend from directly regressing fixed-shape bounding boxes (EAST) to predicting pixel-level maps that encode more granular information (character regions, affinities, adaptive thresholds) for more flexible and accurate polygonal text localization (CRAFT, DBNet).

3
Why It Works — The Math
▼

The core of these models' success lies in their loss functions, which guide the neural network to learn the desired pixel-level predictions.

EAST Loss Function

EAST combines a pixel-level classification loss with a geometry regression loss:

$$L_{EAST} = L_{cls} + \lambda_g L_{geo}$$

Where \(L_{cls}\) is typically a Focal Loss or Binary Cross-Entropy (BCE) on the score map, penalizing incorrect text/non-text pixel classification. \(L_{geo}\) is a combination of AABB (axis-aligned bounding box) IoU loss and rotation angle loss for the RBOX parameters. \(\lambda_g\) is a weighting factor.

The IoU loss is crucial for accurate box regression, as it directly optimizes the overlap between predicted and ground-truth boxes, which is more robust than simple L1/L2 regression on box coordinates.

CRAFT Loss Function

CRAFT's loss is simpler, focusing on accurate prediction of the two score maps:

$$L_{CRAFT} = L_{char} + L_{aff}$$

Both \(L_{char}\) and \(L_{aff}\) are typically Mean Squared Error (MSE) or BCE losses, comparing the predicted character region and affinity maps against their respective ground truth heatmaps. The ground truth maps are generated by applying Gaussian kernels to character and affinity regions in the original image.

DBNet Loss Function

DBNet's loss is more intricate, incorporating the differentiable binarization aspect. It has three main components:

$$L_{DBNet} = \alpha L_{prob} + \beta L_{thresh} + \gamma L_{bin}$$

Here, \(L_{prob}\) is a BCE loss on the probability map, \(L_{thresh}\) is an L1 loss on the threshold map (only for pixels inside text regions), and \(L_{bin}\) is a "binarization loss" (also L1) that directly supervises the binarized probability map. ⚠️ Common Pitfall

Despite the end-to-end learning, post-processing steps (NMS, watershed, polygon approximation) remain critical for all these models. Their performance can be highly sensitive to the choice and hyper-parameters of these post-processing algorithms. A perfect pixel-level prediction can still yield poor boxes if post-processing is sub-optimal.

Key Takeaways
▼

Choosing the right text detection model depends on your specific application's needs regarding speed, accuracy, and the complexity of text layouts you expect to encounter.

ModelOutput RepresentationProsCons
EASTScore Map + RBOX Geometry MapFast, good for horizontal/rotated rectangles, single-stage.Struggles with highly curved text, fixed quadrilateral output.
CRAFTCharacter Region Map + Affinity MapExcellent for curved/arbitrary shapes, character-level precision.Slower due to complex post-processing (watershed/BFS).
DBNetProbability Map + Adaptive Threshold MapFast & Accurate, robust for complex shapes, precise polygonal output due to differentiable binarization.Slightly more complex loss/architecture than EAST.

When to use which model:

  • EAST: For applications where speed is paramount and text is mostly linear (e.g., real-time video processing, simple document layouts).
  • CRAFT: When high accuracy on arbitrary-shaped or curved text is critical, and you can tolerate slightly slower inference (e.g., artistic text, complex scene text).
  • DBNet: A strong all-rounder, offering a good balance of speed and accuracy for most challenging real-world scenarios, including curved text and tight polygon requirements. It's often the go-to choice for state-of-the-art performance.

When NOT to use:

  • Text detection is not a substitute for OCR. These models only locate, not read.
  • For extremely dense or overlapping text, all models may struggle, requiring additional context or specialized techniques.
  • If text is extremely small or low-contrast, a more robust backbone or specialized pre-processing might be needed.
💡 Evolution of Design

The progression from EAST to CRAFT and DBNet reflects a move from direct bounding box regression to more sophisticated pixel-level segmentation strategies. This allows for more flexible text representations (polygons vs. fixed rectangles) and better handling of complex text geometries, ultimately improving the robustness of OCR systems.

Code Trace (Pseudocode)
▼

Below is simplified pseudocode illustrating the core output heads and loss computation for each model. In practice, these would be implemented using deep learning frameworks like PyTorch or TensorFlow, leveraging optimized layers and loss functions.

import torch
import torch.nn.functional as F
# --- EAST Model (Simplified Output Head) ---
class EASTHead(torch.nn.Module):
def __init__(self):
super().__init__()
self.score_map_conv = torch.nn.Conv2d(64, 1, kernel_size=1) # Text/No-Text
self.geometry_map_conv = torch.nn.Conv2d(64, 5, kernel_size=1) # 4 offsets + 1 angle
def forward(self, features): # features from FPN
score_map = torch.sigmoid(self.score_map_conv(features))
geometry_map = self.geometry_map_conv(features) # distances (d1,d2,d3,d4) + angle
return score_map, geometry_map
# --- CRAFT Model (Simplified Output Head) ---
class CRAFTHead(torch.nn.Module):
def __init__(self):
super().__init__()
self.char_region_conv = torch.nn.Conv2d(64, 1, kernel_size=1)
self.affinity_region_conv = torch.nn.Conv2d(64, 1, kernel_size=1)
def forward(self, features):
char_map = torch.sigmoid(self.char_region_conv(features))
affinity_map = torch.sigmoid(self.affinity_region_conv(features))
return char_map, affinity_map
# --- DBNet Model (Simplified Output Head & Differentiable Binarization) ---
class DBNetHead(torch.nn.Module):
def __init__(self):
super().__init__()
self.prob_map_conv = torch.nn.Conv2d(64, 1, kernel_size=1)
self.thresh_map_conv = torch.nn.Conv2d(64, 1, kernel_size=1)
self.k = 50 # binarization factor
def forward(self, features):
prob_map = torch.sigmoid(self.prob_map_conv(features))
thresh_map = torch.sigmoid(self.thresh_map_conv(features)) # range [0,1]
# Differentiable Binarization:
binarized_map = prob_map / (1.0 + torch.exp(-self.k * (prob_map - thresh_map)))
return prob_map, thresh_map, binarized_map
# --- Example Loss Calculation (DBNet) ---
def dbnet_loss(pred_prob, pred_thresh, pred_bin, gt_prob, gt_thresh, gt_mask):
# L_prob: BCE loss on probability map
loss_prob = F.binary_cross_entropy(pred_prob, gt_prob, reduction='none')
loss_prob = (loss_prob * gt_mask).mean() # apply mask for text regions
# L_thresh: L1 loss on threshold map (only for text regions)
loss_thresh = F.l1_loss(pred_thresh, gt_thresh, reduction='none')
loss_thresh = (loss_thresh * gt_mask).mean()
# L_bin: L1 loss on binarized map (adaptive thresholding effect)
loss_bin = F.l1_loss(pred_bin, gt_prob, reduction='none')
loss_bin = (loss_bin * gt_mask).mean()
# Combined loss with weighting factors
alpha, beta, gamma = 1.0, 10.0, 1.0 # typical weights
total_loss = alpha * loss_prob + beta * loss_thresh + gamma * loss_bin
return total_loss
