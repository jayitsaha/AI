Understanding SciPy
▼

SciPy (Scientific Python) is the workhorse of numerical computing in Python. Where NumPy gives you arrays, SciPy gives you algorithms: solvers, transforms, interpolation routines, and spatial data structures — all implemented in Fortran, C, and Cython so they run at near-native speed while you write pure Python.

The Big Picture

SciPy is not one thing — it is a curated collection of sub-modules, each wrapping decades of battle-tested numerical libraries (LAPACK, ARPACK, FFTPACK, MINPACK, FITPACK, QHull). You pick the sub-module for your problem domain.

The five sub-modules covered here

Sub-moduleWhat it solvesKey class / function
scipy.sparseStore huge matrices with mostly zeros, run sparse linear algebracsr_matrix, spsolve
scipy.optimizeFind minima of functions, solve equations, least-squares fitminimize, curve_fit

Key Insight

Each sub-module solves a different class of mathematical problem. When you encounter a new scientific computing task, the first question is: which sub-module owns this? The answer is almost always "one of the above."

Sparse Matrices: CSR, CSC, COO
▼

A sparse matrix has the vast majority of its entries equal to zero. Storing every zero wastes enormous memory. A 10 000 × 10 000 dense float64 matrix needs 0.8 GB. At 1 % fill the same matrix as CSR takes only 12 MB — a 66× saving.

Three canonical storage formats

COO (Coordinate format) — the simplest: store three arrays (row, col, data), one entry per nonzero. Easy to construct; not efficient for arithmetic.

$$A_{\text{COO}}: \quad \text{data} = [v_1, v_2, \ldots, v_{\text{nnz}}], \quad \text{row} = [r_1,\ldots,r_{\text{nnz}}], \quad \text{col} = [c_1,\ldots,c_{\text{nnz}}]$$

CSR (Compressed Sparse Row) — the workhorse format for row-slicing and matrix-vector products. Three arrays:

  • data — nonzero values in row-major order (length = nnz)
  • indices — column index of each nonzero (length = nnz)
  • indptr — pointers: data[indptr[i]:indptr[i+1]] are row \(i\)'s values (length = nrows + 1)
$$\text{Row } i \text{ nonzeros}: \quad \text{data}[\text{indptr}[i]:\text{indptr}[i+1]], \quad \text{cols: indices}[\text{indptr}[i]:\text{indptr}[i+1]]$$

Numerical trace — 4 × 4 matrix:

Consider the matrix with nonzeros at positions (0,0)=5, (1,2)=8, (2,1)=3, (3,3)=6:

data:5836
indices:0213
indptr:01234

Row 0: data[0:1]=[5] at col 0. Row 1: data[1:2]=[8] at col 2. Row 2: data[2:3]=[3] at col 1. Row 3: data[3:4]=[6] at col 3.

CSC (Compressed Sparse Column) — mirror of CSR, but columns are compressed. Preferred for column slicing and direct solvers (like UMFPACK used inside spsolve).

Common Pitfall

Building a CSR matrix by repeatedly setting individual elements is slow (O(nnz) insertion per element). Always assemble in COO first — collect all (row, col, data) triples — then convert once: csr = coo.tocsr(). Duplicate (i, j) entries are summed, which is exactly what FEM assembly needs.

Sparse linear algebra

Once in CSR/CSC, SciPy can solve \(Ax = b\) with scipy.sparse.linalg.spsolve (direct, via SuperLU) or iterative methods (cg, gmres, bicgstab) for very large systems. The matrix-vector product \(y = Ax\) skips all zero entries, costing \(O(\text{nnz})\) instead of \(O(n^2)\).

$$y_i = \sum_{j \in \text{nonzeros of row } i} A_{ij} \, x_j \quad \Rightarrow \quad O(\text{nnz}) \text{ vs } O(n^2)$$

Optimization, Interpolation & Signal Processing
▼

scipy.optimize.minimize

minimize(fun, x0, method='BFGS') finds a local minimum of a scalar function. The BFGS method (Broyden–Fletcher–Goldfarb–Shanno) is a quasi-Newton method: it builds a low-rank approximation \(H_k \approx \nabla^2 f\) from past gradients without ever computing the full Hessian.

$$x_{k+1} = x_k - H_k^{-1} \nabla f(x_k), \quad H_{k+1} = H_k + \frac{y_k y_k^\top}{y_k^\top s_k} - \frac{H_k s_k s_k^\top H_k}{s_k^\top H_k s_k}$$

where \(s_k = x_{k+1}-x_k\) (step) and \(y_k = \nabla f(x_{k+1}) - \nabla f(x_k)\) (gradient change).

Numerical trace on Rosenbrock \(f(x,y) = (1-x)^2 + 100(y-x^2)^2\) starting at \((-1, 1.5)\):

Step 0:x=[-1.000, 1.500], f=29.000
Step 1:x=[-1.154, 1.422], f=5.460
Step 3:x=[-0.890, 0.760], f=3.679
Step 34:x=[1.000, 1.000], f=2.06e-11 ✓
Available Methods

'Nelder-Mead' — gradient-free simplex, robust but slow. 'L-BFGS-B' — limited-memory BFGS with box constraints, gold standard for large ML problems. 'SLSQP' — equality + inequality constraints. 'trust-constr' — nonlinear constraints, 2nd-order accurate.

scipy.interpolate — CubicSpline

Given \(n\) sample points \((x_i, y_i)\), interpolation constructs a function \(s(x)\) that passes exactly through each point. CubicSpline builds a piecewise cubic polynomial \(s_i(x)\) on each interval \([x_i, x_{i+1}]\), enforcing continuity of \(s\), \(s'\), and \(s''\) at each interior knot — giving a smooth, "natural" spline.

$$s_i(x) = a_i + b_i(x - x_i) + c_i(x-x_i)^2 + d_i(x-x_i)^3, \quad x \in [x_i, x_{i+1}]$$

Trace: interpolating \(\sin(x)\) at \(x \in \{0,1,2,3,4\}\). At \(x=0.5\): spline gives 0.5016, true sin(0.5)=0.4794. At \(x=1.5\): spline gives 0.9880, true sin(1.5)=0.9975. Error is typically \(O(h^4)\) where \(h\) is the knot spacing.

scipy.signal — Butterworth filter

A Butterworth filter has maximally flat magnitude in the passband. Design with butter(N, Wn) to get IIR coefficients \((b, a)\), then apply with filtfilt (zero-phase, forward + backward pass) or lfilter (causal, one-pass).

$$|H(j\omega)|^2 = \frac{1}{1 + \left(\frac{\omega}{\omega_c}\right)^{2N}} \quad \xrightarrow{N=4,\,\omega_c=0.1\pi} \quad \text{-3 dB at 10\% Nyquist}$$

Trace: signal = sin(2π·5t) + 0.5·sin(2π·50t). After 4th-order lowpass (cutoff = 10% Nyquist), the 50 Hz component is attenuated from ±0.5 to nearly zero. b-coefficients ≈ [4.17e-4, 1.67e-3, 2.50e-3, 1.67e-3, 4.17e-4]. The filter range shrinks from ±1.49 to ±1.00, isolating the 5 Hz tone.

filtfilt vs lfilter

filtfilt applies the filter twice (forward + backward), achieving zero phase shift but requiring the entire signal. lfilter is causal (usable in real-time) but introduces group delay. For offline analysis (EEG, audio mastering) always prefer filtfilt.

Key Takeaways & When to Use
▼

Module decision guide

ProblemModuleWhy not dense/loops?
Matrix with ≥ 90% zeros (FEM, graphs)scipy.sparseDense wastes memory; matrix-vec product is O(nnz) not O(n²)
Minimize a differentiable functionscipy.optimize.minimizeHand-written gradient descent ignores Hessian curvature; BFGS converges in far fewer steps
Smooth curve through measured datascipy.interpolateLinear interpolation gives kinks; splines give C² continuity
Remove noise or extract frequency contentscipy.signalManual FFT masking loses phase info; IIR/FIR filters are better-designed
k-nearest-neighbour queries in any dimscipy.spatial.KDTreeBrute-force is O(n·d); KD-tree is O(log n·d) for balanced trees
When KDTree Breaks Down

KD-tree query time degrades to \(O(n)\) in high dimensions (the "curse of dimensionality" — all points become equally far). The rule of thumb is: KD-trees are effective when \(d \lesssim 20\). For larger \(d\), use approximate methods (FAISS, HNSW) or ball trees.

Interoperability

  • SciPy sparse matrices interoperate with NumPy dense arrays; just call .toarray() or np.asarray().
  • scipy.optimize.minimize accepts any callable — including PyTorch/TF functions with manual gradient extraction.
  • KDTree accepts any NumPy float array; cKDTree (C implementation) is ~2–5× faster for large datasets.

KD-tree nearest neighbours

from scipy.spatial import KDTree
import numpy as np
# 9 points on a 3×3 grid
pts = np.mgrid[0:3, 0:3].reshape(2,-1).T.astype(float)
tree = KDTree(pts)
q = np.array([0.6, 0.6]) # query point
dists, idx = tree.query(q, k=3) # 3 nearest
# dists ≈ [0.5657, 0.7211, 0.7211]
# idx = [4, 1, 3] → pts [1,1], [1,0], [0,1]
# Ball query: all points within radius 1.0
neighbours = tree.query_ball_point(q, r=1.0)
