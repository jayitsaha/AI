Understanding Model Averaging & SLERP
▼

What is it? Model averaging is an ensemble technique where you combine the parameters (weights and biases) of multiple trained models (or different checkpoints of the same model during training) into a single, potentially stronger model. Simple linear interpolation (LERP) might average these weights directly, but this can lead to undesirable results if the models are "far" apart or if the magnitude of the weight vector is important. Spherical Linear Interpolation (SLERP) is a method to smoothly interpolate between two vectors on the surface of a hypersphere, preserving their magnitude and following the shortest angular path.

Analogy: Imagine you have two different shades of blue paint. If you linearly interpolate them (LERP), you just mix them directly, getting a shade somewhere in between. Now imagine you're navigating between two cities on a globe. If you draw a straight line on a flat map (LERP), that path might be longer or pass through unexpected terrain. But if you follow a "great circle" route on the globe's surface (SLERP), you get the shortest, most natural path. For model weights, the "surface of the globe" represents models with similar overall "strength" or "magnitude," and the "great circle" ensures a smooth transition between their "styles" or "features."

💡 If you remember one thing

SLERP is crucial when the direction of a parameter vector (e.g., a latent code, or a layer's weights) is more meaningful than its absolute Cartesian coordinates, and when maintaining a constant norm (magnitude) during interpolation is important. It ensures the interpolated model's overall "strength" doesn't fluctuate wildly, which can happen with simple linear averaging.

How SLERP Works Internally
▼

Simple Averaging (LERP) and its Limitations

Given two weight vectors \(w_0\) and \(w_1\), linear interpolation (LERP) simply computes \(w_t = (1-t)w_0 + t w_1\) for \(t \in [0,1]\). This is straightforward and often works surprisingly well for model checkpoints that are close in parameter space. However, LERP has two main drawbacks for model parameters:

  1. Norm changes: The magnitude (L2 norm) of \(w_t\) is not guaranteed to be constant, or even monotonic. It can dip significantly in the middle, creating "weaker" models.
  2. Suboptimal path: LERP takes a straight line in the high-dimensional parameter space. This path might pass through regions that correspond to very poor model performance, even if \(w_0\) and \(w_1\) are both good. This is especially true for highly non-linear models where the "loss landscape" is complex.

The SLERP Solution: Spherical Interpolation

SLERP addresses these issues by treating the vectors as points on a hypersphere. It interpolates along the shortest arc connecting them. This requires the vectors to be normalized (or their norms handled explicitly). The core idea is to use the angle between the vectors, \(\theta\), to define the interpolation. The interpolation coefficients are then trigonometric functions of \(\theta\) and \(t\).

For model averaging, weights are often high-dimensional vectors. While we can't easily visualize a hypersphere, the principle holds: SLERP ensures that the "effective magnitude" of the combined model remains constant, and that the interpolation path stays on a manifold where model properties (like overall strength or feature balance) are preserved.

Design Decision: Why normalize vectors for SLERP?

The standard SLERP formula assumes unit vectors. If your vectors are not normalized, you typically normalize them first, perform SLERP, and then scale the result by an appropriate magnitude (e.g., the average of the initial norms, or the norm of one of the endpoints). This ensures the "direction" is interpolated correctly on the sphere, and the "magnitude" is then applied. This is why SLERP is particularly useful for latent space interpolation in generative models, where latent codes are often implicitly or explicitly normalized.

🔑 Key Property

SLERP is essentially a weighted sum of two vectors, but the weights are non-linear functions of the angle between them and the interpolation parameter \(t\). This non-linearity ensures a smooth, constant-norm path along the surface of a sphere, making it ideal for interpolating directions or relative proportions rather than absolute values.

Why It Works — The Math
▼

The SLERP Formula

Given two vectors \(v_0\) and \(v_1\), and an interpolation parameter \(t \in [0, 1]\), the SLERP formula for an interpolated vector \(v_t\) is:

$$ \text{SLERP}(v_0, v_1, t) = \frac{\sin((1-t)\theta)}{\sin(\theta)}v_0 + \frac{\sin(t\theta)}{\sin(\theta)}v_1 $$

where \(\theta\) is the angle between \(v_0\) and \(v_1\), calculated using the dot product:

$$ \theta = \arccos\left(\frac{v_0 \cdot v_1}{\|v_0\|\|v_1\|}\right) $$

For numerical stability, if \(\theta\) is very small (vectors are nearly parallel), a linear interpolation (LERP) can be used as an approximation: \(\text{SLERP} \approx (1-t)v_0 + tv_1\). If \(\theta = \pi\) (vectors are anti-parallel), SLERP is undefined or requires a choice of direction for the arc.

Derivation Intuition

Consider two unit vectors \(v_0\) and \(v_1\) in a 2D plane. We want to find a vector \(v_t\) that makes an angle of \(t\theta\) with \(v_0\) (and \((1-t)\theta\) with \(v_1\)). We can express \(v_t\) as a linear combination of \(v_0\) and a vector perpendicular to \(v_0\) in the plane spanned by \(v_0\) and \(v_1\). A common choice for this perpendicular component is \(v_1 - (v_1 \cdot v_0)v_0\), which is \(v_1\) projected onto the plane orthogonal to \(v_0\). However, the standard derivation uses a more symmetric approach by projecting \(v_t\) onto \(v_0\) and \(v_1\). The coefficients \(\frac{\sin((1-t)\theta)}{\sin(\theta)}\) and \(\frac{\sin(t\theta)}{\sin(\theta)}\) naturally arise from expressing \(v_t\) in terms of \(v_0\) and \(v_1\) using the sine rule in the triangle formed by \(v_0, v_1, v_t\) and the origin, scaled by their magnitudes.

Specifically, if \(v_0\) and \(v_1\) are unit vectors, then the interpolated vector \(v_t\) will also be a unit vector, as shown by:

$$ \| \text{SLERP}(v_0, v_1, t) \|^2 = \left(\frac{\sin((1-t)\theta)}{\sin(\theta)}\right)^2 \|v_0\|^2 + \left(\frac{\sin(t\theta)}{\sin(\theta)}\right)^2 \|v_1\|^2 + 2 \frac{\sin((1-t)\theta)\sin(t\theta)}{\sin^2(\theta)} (v_0 \cdot v_1) = 1 $$

This property of preserving the norm is a key advantage over LERP when dealing with normalized vectors.

⚠️ Common Pitfall

SLERP can become numerically unstable or behave unexpectedly when the angle \(\theta\) between \(v_0\) and \(v_1\) approaches \(0\) (vectors are nearly identical) or \(\pi\) (vectors are nearly opposite). For \(\theta \approx 0\), LERP is a good fallback. For \(\theta \approx \pi\), the "shortest path" on the sphere becomes ambiguous, as there are many great circle paths between anti-parallel vectors. In practice, if \(\theta\) is very close to \(\pi\), SLERP might produce a vector with a very small norm or flip direction unpredictably.

Key Takeaways
▼

When to use SLERP (or model averaging in general):

  • Ensembling: Averaging weights of multiple models (trained with different random seeds or on different data splits) can improve robustness and generalization.
  • Checkpoint averaging: Averaging weights from different training checkpoints (e.g., from the end of an epoch) can sometimes yield better models than the last checkpoint, especially in noisy loss landscapes.
  • Latent space interpolation: In generative models (VAEs, GANs), SLERP is excellent for smoothly interpolating between latent codes to generate a continuous sequence of outputs (e.g., morphing one face into another), as latent codes are often implicitly normalized.
  • Interpolating "styles" or "features": When you want to smoothly blend between two distinct characteristics encoded in parameter vectors, and you want to maintain a consistent "intensity" or "magnitude" of that characteristic.

When NOT to use / be cautious:

  • Mismatched architectures: Model averaging (LERP or SLERP) is only meaningful if the models have identical architectures and corresponding parameters.
  • Unstructured parameter spaces: If the parameter space is truly Euclidean and magnitude is linearly meaningful (e.g., simple linear regression coefficients), LERP might be sufficient or even preferred.
  • Anti-parallel vectors: If \(v_0\) and \(v_1\) are nearly opposite (\(\theta \approx \pi\)), SLERP can be numerically unstable and its interpretation ambiguous.
  • Computational cost: For very large models, loading multiple checkpoints and performing element-wise SLERP can be memory and computationally intensive.
💡 Big Picture

Model averaging, especially with SLERP, is a powerful trick to leverage the diversity of multiple models or latent codes. It's a fundamental tool in the ML engineer's toolkit for improving model quality and for exploring complex generative spaces, particularly when working with high-dimensional vectors where simple linear paths can be misleading.

Code Trace (NumPy Implementation)
▼
import numpy as np
def normalize_vector(v):
norm = np.linalg.norm(v)
return v / norm if norm > 1e-6 else v # avoid division by zero
def lerp(v0, v1, t):
"""Linear interpolation between v0 and v1."""
return (1 - t) * v0 + t * v1
def slerp(v0, v1, t, v0_norm=None, v1_norm=None):
"""Spherical Linear Interpolation between v0 and v1."""
if v0_norm is None: v0_norm = np.linalg.norm(v0)
if v1_norm is None: v1_norm = np.linalg.norm(v1)
# Normalize vectors to unit length
u0 = v0 / v0_norm
u1 = v1 / v1_norm
# Compute the angle between them
dot = np.dot(u0, u1)
dot = np.clip(dot, -1.0, 1.0) # Clip to avoid numerical errors for arccos
theta = np.arccos(dot)
# Handle edge cases
if theta < 1e-6: # Vectors are nearly parallel, fall back to LERP
return lerp(v0, v1, t)
if theta > np.pi - 1e-6: # Vectors are nearly anti-parallel
# This case is ambiguous for SLERP, simply return v0 or v1 based on t
return v0 if t < 0.5 else v1
# SLERP formula
return (np.sin((1 - t) * theta) / np.sin(theta)) * v0 + \
(np.sin(t * theta) / np.sin(theta)) * v1
