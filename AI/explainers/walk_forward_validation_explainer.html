Walk-Forward Validation

Time-Series Cross-Validation — train on the past, validate on the next block, never peek at the future.
Intermediate Classical ML Model Selection Important in Interviews
1
Understanding the Concept

What is this? Standard k-fold cross-validation shuffles your data and randomly assigns rows to folds. That works perfectly for, say, predicting house prices — the rows are independent. But time-series data is ordered: Monday's stock price influences Tuesday's. If you shuffle, you let the model peek at the future during training, making your error estimates wildly optimistic. Walk-forward validation solves this by respecting the arrow of time.

The recipe: Always train on past data only, then validate on the very next block of unseen future data. Roll that window forward and repeat. Each fold mirrors how you'd actually deploy the model — only historical information is available at inference time.

💡 If you remember one thing

Never shuffle time-series data before splitting. Walk-forward validation is the correct CV strategy when observations are temporally dependent — it produces honest out-of-sample estimates that match real deployment conditions.

Real-world analogy: Imagine you're a weather forecaster. You train on January–March data, then predict April. Next iteration: train on January–April, predict May. You never "train on June and then predict March" — the past is fixed, the future is always unknown. That's walk-forward validation.

Two flavours:

  • Expanding window — each fold adds the new validation block to the training set. Training size grows: 1→1+2→1+2+3… Prefers more data, can be slow.
  • Sliding window — training window has a fixed size; it shifts forward dropping old data. Controls for concept drift and keeps training cost constant.
2
How It Works Internally

Given a time series of \(T\) observations indexed \(t = 1, 2, \ldots, T\), choose an initial training size \(n_0\) and a step/horizon \(h\) (how many future steps each validation fold covers). The procedure produces \(K = \lfloor (T - n_0) / h \rfloor\) folds.

Expanding window (grow the train set):

Fold \(k\) uses training indices \(\{1, \ldots, n_0 + (k-1)h\}\) and validation indices \(\{n_0 + (k-1)h + 1, \ldots, n_0 + kh\}\). The total training size at fold \(k\) is \(n_0 + (k-1)h\).

Sliding window (fixed train size \(W\)):

Fold \(k\) uses training indices \(\{1 + (k-1)h, \ldots, n_0 + (k-1)h\}\) and validation indices \(\{n_0 + (k-1)h + 1, \ldots, n_0 + kh\}\). Training always covers exactly \(W = n_0\) points.

Key Invariant

Every training fold index is strictly less than every validation fold index. The data timeline is never violated. This is the core guarantee walk-forward provides.

Aggregating error: Compute a metric (MAE, RMSE, MAPE…) on each fold's validation block, then average across folds — optionally weighting recent folds more heavily. This gives a temporally honest estimate of production performance.

⚠️ Common Mistake

Using sklearn.model_selection.KFold on time-series data. It shuffles indices, guaranteeing future leakage. Always use TimeSeriesSplit or implement walk-forward manually.

3
The Math Behind It

Let \(\{y_t\}_{t=1}^T\) be a time series. Define initial window \(n_0\), horizon \(h\), and number of folds \(K\).

Expanding window fold indices:

$$\mathcal{T}_k = \{1,\ldots, n_0 + (k-1)h\}, \quad \mathcal{V}_k = \{n_0 + (k-1)h + 1,\ldots, n_0 + kh\}$$

Sliding window fold indices (window size \(W\)):

$$\mathcal{T}_k = \{1+(k-1)h, \ldots, W + (k-1)h\}, \quad \mathcal{V}_k = \{W + (k-1)h + 1,\ldots, W + kh\}$$

Aggregate CV error (uniform weights):

$$\widehat{\text{Err}} = \frac{1}{K}\sum_{k=1}^{K} \frac{1}{|\mathcal{V}_k|} \sum_{t \in \mathcal{V}_k} \ell\!\left(y_t,\; \hat{y}_t^{(k)}\right)$$

where \(\hat{y}_t^{(k)}\) is the model trained on \(\mathcal{T}_k\) and \(\ell\) is the chosen loss (e.g. squared error, absolute error).

Number of folds:

$$K = \left\lfloor \frac{T - n_0}{h} \right\rfloor$$
Key Property — Temporal Non-Overlap

For all valid \(k\): \(\max(\mathcal{T}_k) < \min(\mathcal{V}_k)\). The model never sees any validation observation during its training phase. This ensures unbiased estimation under temporal dependence.

Practical example with numbers: \(T=20\), \(n_0=10\), \(h=2\).
\(K = \lfloor(20-10)/2\rfloor = 5\) folds.
Fold 1: Train \(\{1..10\}\), Val \(\{11,12\}\).
Fold 2: Train \(\{1..12\}\) (expanding) or \(\{3..12\}\) (sliding \(W=10\)), Val \(\{13,14\}\).
…and so on until Fold 5: Val \(\{19,20\}\).

Code: From Scratch & Production

From Scratch — NumPy

python
import numpy as np
def walk_forward_split(n, n_init, h, mode='expanding', W=None):
"""Yield (train_idx, val_idx) pairs for walk-forward CV.
Args:
n : total number of timesteps
n_init : initial training size
h : validation horizon per fold
mode : 'expanding' or 'sliding'
W : sliding window size (only for mode='sliding')
"""
if mode == 'sliding' and W is None:
W = n_init
k = 0
while True:
val_end = n_init + (k + 1) * h # exclusive end of val
if val_end > n:
break # no more data for val
val_start = n_init + k * h # inclusive start of val
if mode == 'expanding':
train_start = 0
else: # sliding
train_start = max(0, val_start - W)
train_idx = np.arange(train_start, val_start)
val_idx = np.arange(val_start, val_end)
# KEY INVARIANT: all train < all val
assert train_idx.max() < val_idx.min(), "Future leakage!"
yield train_idx, val_idx
k += 1
# Usage
y = np.sin(np.linspace(0, 4*np.pi, 60)) + np.random.randn(60)*0.1
scores = []
for train_idx, val_idx in walk_forward_split(60, n_init=30, h=5):
# Fit a trivial mean model (replace with your model)
pred = np.full(len(val_idx), y[train_idx].mean())
rmse = np.sqrt(np.mean((y[val_idx] - pred)**2))
scores.append(rmse)
print(f"Mean RMSE: {np.mean(scores):.4f} ± {np.std(scores):.4f}")

Key Takeaways & Comparisons
Dimension k-Fold CV Walk-Forward (Expanding) Walk-Forward (Sliding)
Data ordering respected? No — shuffles Yes Yes
Future leakage? Yes None None
Training set size Fixed fraction Grows with each fold Fixed (window size)
Handles concept drift? No Partially (diluted by old data) Yes (drops stale data)
Compute cost Low Increases per fold Constant per fold
Use when i.i.d. tabular data Stationary time series; more data → better Non-stationary; fixed compute budget
Decision Guide

Series is stationary & longer history helps? → Expanding window.
Series drifts over time (non-stationary)? → Sliding window.
Data is i.i.d.? → Standard k-fold is fine.
Lag features included? → Add a gap to prevent indirect leakage.
