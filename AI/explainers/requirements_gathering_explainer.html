1
Understanding Key ML System Requirements
▼

What is it? Building a successful Machine Learning system isn't just about model accuracy. It requires carefully defining and balancing a suite of operational and ethical requirements. Four core metrics often come into play: latency (how fast), throughput (how much), accuracy (how good), and fairness (how equitable).

Analogy: Imagine building a self-driving car.

  • Latency: How quickly the car reacts to a sudden obstacle. A delay of even milliseconds can be catastrophic.
  • Throughput: How many sensor readings and decisions the car can process per second. Too low, and it might miss critical information.
  • Accuracy: How correctly it identifies pedestrians versus lampposts, or stop signs versus billboards.
  • Fairness: Does it perform equally well for all road conditions, lighting, and pedestrian types? Is it equally safe for all demographics of passengers or bystanders?
These metrics often pull in different directions: a faster car might be less accurate, a fairer car might require more processing.

💡 If you remember one thing

These four metrics — latency, throughput, accuracy, and fairness — are fundamental to any production ML system. They are almost always in tension, requiring engineering and product teams to make explicit trade-offs based on the use case's priorities.

2
How Each Metric Manifests in a System
▼

Latency: The Time Per Request

Latency measures the delay between a request being sent to the system and the system producing a response. It's typically measured in milliseconds (ms) or seconds (s). Low latency is crucial for interactive applications (e.g., search engines, real-time bidding, user interfaces). High latency leads to poor user experience, timeouts, and cascading failures in distributed systems.

Throughput: The Volume of Work

Throughput (often called QPS - Queries Per Second, or RPS - Requests Per Second) measures the number of requests a system can handle within a given time frame. High throughput is essential for batch processing, large-scale data ingestion, and systems serving many concurrent users. Optimizing for throughput often involves parallelization, batching, and efficient resource utilization.

Accuracy: The Quality of Predictions

Accuracy (or more generally, predictive performance metrics like F1-score, AUC, RMSE) measures how well the ML model's predictions match the ground truth. This is the metric most ML practitioners are familiar with. A highly accurate model is useless if it's too slow or unfair. Conversely, a fast model is useless if its predictions are consistently wrong.

Fairness: The Equity of Outcomes

Fairness refers to the idea that an ML system should not disproportionately harm or benefit certain groups of people. This can manifest as equal accuracy across demographic groups (e.g., gender, race), equal false positive rates, or equal opportunity. Achieving fairness often involves careful data collection, bias detection, and algorithmic interventions, which can sometimes come at the cost of overall accuracy or system complexity.

Design Decision: Why Not Just Maximize All Four?

These metrics are often fundamentally at odds.

  • Increasing model complexity for higher accuracy typically increases latency.
  • Batching requests to improve throughput can increase average latency for individual requests.
  • Implementing fairness constraints might require re-weighting data or adjusting decision thresholds, which can reduce overall accuracy or introduce more computation.
  • Throwing more hardware at latency/throughput problems increases cost.
The "right" balance depends entirely on the business context, user expectations, and ethical considerations.

🔑 Key Property

Defining explicit Service Level Objectives (SLOs) for latency and throughput, alongside clear target metrics for accuracy and fairness, is a critical first step in ML system design. These SLOs guide architectural choices and model development.

3
Quantifying the Trade-offs
▼

Defining the Metrics

Mathematically, these metrics can be defined:

Latency (\(L\)): The time taken for a single request to complete. Often reported as a percentile (e.g., P99 latency is the latency experienced by 99% of requests).

$$L = \text{Time}(\text{response}) - \text{Time}(\text{request})$$

Throughput (\(T\)): The number of requests processed per unit time.

$$T = \frac{\text{Number of Requests}}{\text{Total Time}}$$

Accuracy (\(A\)): For binary classification, overall accuracy is:

$$A = \frac{\text{True Positives} + \text{True Negatives}}{\text{Total Samples}}$$

Fairness (\(F\)): There are many definitions. One common approach is Demographic Parity, where the positive prediction rate should be equal across protected groups \(G_1, G_2\). Let \(\hat{Y}=1\) be a positive prediction:

$$P(\hat{Y}=1 \mid G_1) = P(\hat{Y}=1 \mid G_2)$$

Another is Equalized Odds, requiring equal true positive rates and false positive rates across groups. The "best" fairness metric is application-dependent.

The Trade-off Space

Optimizing for one metric often means accepting a degradation in another. For example, a more complex model might increase accuracy but also latency. A higher confidence threshold for predictions might increase precision (a component of accuracy) but reduce recall, potentially impacting fairness for groups where predictions are inherently less confident.

A common way to visualize this is through Pareto fronts, where points on the front represent optimal trade-offs: you cannot improve one metric without worsening another. The goal is to choose a point on this front that best aligns with business objectives.

⚠️ The "No Free Lunch" Principle

There is no single "perfect" ML system that maximizes all metrics simultaneously. Every design decision, from model architecture to deployment strategy, involves implicit or explicit compromises between these competing requirements. Understanding these trade-offs upfront is crucial to avoid costly re-engineering later.

Key Takeaways
▼

When to prioritize each metric:

  • Latency: Critical for real-time user-facing applications (e.g., search, online gaming, self-driving cars, real-time bidding). Users expect instant feedback.
  • Throughput: Essential for batch processing, large-scale data analytics, and systems with high concurrent load (e.g., ad serving, large language model inference for many users).
  • Accuracy: Always important, but its exact definition and trade-offs vary. For medical diagnosis, high precision (few false positives) might be paramount. For fraud detection, high recall (few false negatives) might be key.
  • Fairness: Increasingly critical for systems impacting human lives (e.g., loan applications, hiring, criminal justice, healthcare). Ethical and regulatory compliance often demand explicit fairness considerations.

Common Trade-offs:

  • Accuracy vs. Latency: More complex models (higher accuracy) often mean longer inference times (higher latency).
  • Throughput vs. Latency: Batching requests can increase overall throughput but might increase the average latency for individual requests.
  • Fairness vs. Accuracy: Explicitly mitigating bias to achieve fairness for one group might sometimes lead to a slight decrease in overall accuracy or accuracy for another group.
  • All vs. Cost: Throwing more compute resources at the problem can improve all metrics, but at a higher operational cost.
💡 The Art of ML System Design

The process of defining, measuring, and balancing these requirements is an iterative art. It involves deep understanding of the problem domain, user needs, business goals, and ethical implications. There's no one-size-fits-all solution; every system requires its own unique balance.

Code Trace: Simplified Metric Calculation
▼
import time
import random
from collections import deque
class MLSystem:
def __init__(self, model_complexity_ms=50, num_workers=4, confidence_threshold=0.7, fairness_priority=0):
self.model_complexity_ms = model_complexity_ms
self.num_workers = num_workers
self.confidence_threshold = confidence_threshold
self.fairness_priority = fairness_priority
self.request_queue = deque()
self.completed_requests = []
self.processing_workers = [None] * num_workers # (request, start_time, expected_finish_time)
self.sim_time = 0
def generate_request(self, current_time):
group = 'A' if random.random() < 0.6 else 'B' # Group A is slightly more common
true_label = 1 if random.random() < 0.7 else 0 # True positive rate bias for Group A
if group == 'B': true_label = 1 if random.random() < 0.5 else 0 # Group B harder to predict positively
self.request_queue.append({'id': len(self.completed_requests) + len(self.request_queue),
'arrival_time': current_time, 'group': group, 'true_label': true_label})
def process_step(self, delta_time):
self.sim_time += delta_time
# Dispatch requests to idle workers
for i in range(self.num_workers):
if self.processing_workers[i] is None and self.request_queue:
req = self.request_queue.popleft()
process_duration = self.model_complexity_ms / 1000.0 # Convert ms to seconds
self.processing_workers[i] = (req, self.sim_time, self.sim_time + process_duration)
# Complete requests
for i in range(self.num_workers):
if self.processing_workers[i] and self.sim_time >= self.processing_workers[i][2]:
req, start_time, _ = self.processing_workers[i]
latency = self.sim_time - req['arrival_time']
# Simulate model prediction based on complexity, threshold, fairness
confidence = random.random() * 0.4 + 0.5 # Base confidence 0.5-0.9
if req['group'] == 'B': confidence -= (0.1 - (self.fairness_priority/100 * 0.1)) # Group B bias
predicted_label = 1 if confidence >= self.confidence_threshold else 0
is_correct = (predicted_label == req['true_label'])
self.completed_requests.append({
'id': req['id'], 'group': req['group'], 'true_label': req['true_label'],
'predicted_label': predicted_label, 'is_correct': is_correct,
'latency': latency, 'completion_time': self.sim_time
})
self.processing_workers[i] = None
def calculate_metrics(completed_requests, time_window=10):
if not completed_requests: return {'latency': 0, 'throughput': 0, 'accuracy': 0, 'fairness': 0}
current_time = completed_requests[-1]['completion_time']
recent_requests = [r for r in completed_requests if r['completion_time'] >= current_time - time_window]
avg_latency = sum(r['latency'] for r in recent_requests) / len(recent_requests) if recent_requests else 0
throughput = len(recent_requests) / time_window
accuracy = sum(1 for r in recent_requests if r['is_correct']) / len(recent_requests) if recent_requests else 0
# Fairness: Difference in accuracy between groups A and B
group_a_reqs = [r for r in recent_requests if r['group'] == 'A']
group_b_reqs = [r for r in recent_requests if r['group'] == 'B']
acc_a = sum(1 for r in group_a_reqs if r['is_correct']) / len(group_a_reqs) if group_a_reqs else 0
acc_b = sum(1 for r in group_b_reqs if r['is_correct']) / len(group_b_reqs) if group_b_reqs else 0
fairness_score = abs(acc_a - acc_b) # Lower is better
return {'latency': avg_latency, 'throughput': throughput, 'accuracy': accuracy, 'fairness': fairness_score}
