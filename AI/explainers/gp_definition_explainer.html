Understanding Gaussian Processes
▼

What is it? A Gaussian Process (GP) is a probability distribution — but instead of putting probability mass on numbers or vectors, it puts probability mass on entire functions. Formally, we write \(f(x) \sim \mathcal{GP}(m(x), k(x,x'))\), meaning: for any finite collection of input points \(x_1,\dots,x_n\), the corresponding function values \((f(x_1),\dots,f(x_n))\) are jointly Gaussian, with mean vector \(m_i = m(x_i)\) and covariance matrix \(K_{ij} = k(x_i,x_j)\).

Analogy: Imagine you don't know a temperature curve over a day, but you're fairly sure it's smooth — 2pm won't be wildly different from 1:59pm. A GP encodes exactly this belief: it is a "distribution over curves" where the two knobs are (1) where you expect the curve to sit on average (the mean function), and (2) how strongly nearby points influence each other (the covariance/kernel function). Draw a sample, and you get one concrete, plausible curve; draw many, and you see the whole family of curves consistent with your beliefs.

💡 If you remember one thing

A GP is completely determined by two functions: $$f(x) \sim \mathcal{GP}\big(m(x),\, k(x,x')\big)$$ The mean function \(m(x)=\mathbb{E}[f(x)]\) says what value you expect at each \(x\). The kernel \(k(x,x')=\operatorname{Cov}(f(x),f(x'))\) says how correlated any two outputs are — and that correlation structure is what makes sampled functions smooth instead of noisy.

2
How a GP Works Internally
▼

The Mean Function

\(m(x) = \mathbb{E}[f(x)]\) is your prior guess for \(f\) before seeing any data. In practice it is very often set to \(m(x)=0\) — not because we think the function is literally zero, but because the kernel already carries all the interesting structure, and any nonzero trend can be added back later (or absorbed by centering the data). More expressive choices — a linear function, a low-degree polynomial — are used when domain knowledge suggests a baseline trend.

The Covariance (Kernel) Function

\(k(x,x') = \operatorname{Cov}(f(x), f(x'))\) is the real engine of a GP. It must be a valid positive semi-definite function (Mercer's condition) so that every covariance matrix \(K\) it produces is a legitimate covariance matrix. The most common choice, used throughout this explainer, is the RBF / squared-exponential kernel:

$$k(x,x') = \sigma_f^2 \exp\!\left(-\frac{(x-x')^2}{2\ell^2}\right)$$

Two hyperparameters control its shape: the amplitude \(\sigma_f\) (how large the typical function swing is) and the lengthscale \(\ell\) (how far apart two inputs can be before they stop influencing each other). Because \(k\) depends only on \(x-x'\), this particular kernel is stationary — the correlation structure looks the same everywhere along the input axis.

Design Decision: Why a Covariance Function at All?

A finite Gaussian vector needs an \(n\times n\) covariance matrix. A GP needs to work for any \(n\) and any set of query points — including points nobody picked yet. The kernel function is the trick that generates a consistent covariance matrix on demand for whatever finite set of points you evaluate, which is exactly the Kolmogorov extension idea: define pairwise covariances everywhere, and every finite marginal falls out automatically and consistently.

🔑 Key Property

A GP is consistent under marginalization: if you already have the joint distribution over \(f(x_1),\dots,f(x_n)\) and you add a new point \(x_{n+1}\), the distribution over the first \(n\) values doesn't change — you've simply enlarged the same underlying multivariate Gaussian, using the same \(m\) and \(k\).

3
Why It Works — The Math
▼

From Kernel to Covariance Matrix

Pick any grid \(x_1,\dots,x_n\). Evaluate the kernel on every pair to build \(K \in \mathbb{R}^{n\times n}\), \(K_{ij}=k(x_i,x_j)\), and the mean vector \(\mu_i = m(x_i)\). The GP prior says:

$$\big(f(x_1),\dots,f(x_n)\big) \sim \mathcal{N}(\mu, K)$$

This is just an ordinary multivariate Gaussian — everything you know about Gaussians (marginals, conditionals, linear transforms) applies directly, which is why conditioning a GP on observed data (Gaussian Process Regression) reduces to closed-form linear algebra.

Sampling via Cholesky Factorization

To draw \(f \sim \mathcal{N}(\mu,K)\) we need a matrix square root of \(K\). Because \(K\) is symmetric positive semi-definite, it admits a Cholesky factorization \(K = LL^\top\) with \(L\) lower-triangular. Then:

$$z \sim \mathcal{N}(0, I), \qquad f = \mu + Lz \;\; \Longrightarrow \;\; f \sim \mathcal{N}(\mu, LL^\top) = \mathcal{N}(\mu, K)$$

Verification: \(\operatorname{Cov}(Lz) = L\operatorname{Cov}(z)L^\top = LIL^\top = LL^\top = K\). This is exactly the same trick used to sample any correlated multivariate Gaussian, and it is what the interactive walkthrough below computes, live, in JavaScript.

Marginal Variance and Confidence Bands

The variance of \(f\) at a single point is just the diagonal of \(K\): \(\operatorname{Var}[f(x)] = k(x,x)\). For the RBF kernel, \(k(x,x)=\sigma_f^2\) for every \(x\) — constant, because the kernel is stationary. That constant variance is what lets us draw a single, uniform \(m(x) \pm 2\sigma_f\) band that (approximately) contains 95% of the prior's probability mass at every \(x\).

⚠️ Common Pitfall

Not every function is a valid kernel — it must be symmetric, \(k(x,x')=k(x',x)\), and positive semi-definite for every finite set of points. Using an invalid "kernel" can produce a \(K\) with negative eigenvalues, and Cholesky will fail (or produce nonsense) because no real covariance matrix could ever look like that.

5
Key Takeaways
▼

What to remember:

  • A GP prior is just \(\mathcal{GP}(m,k)\) — pick a mean function (usually 0) and a kernel (usually RBF, Matérn, or a sum/product of kernels).
  • The kernel's hyperparameters (\(\ell\), \(\sigma_f\)) directly control the smoothness and amplitude of sampled functions — small \(\ell\) → wiggly, large \(\ell\) → smooth.
  • Sampling reduces to Cholesky factorization of the covariance matrix: \(f = m + Lz\).
  • The diagonal of \(K\), \(k(x,x)\), gives the pointwise variance and the ±2σ uncertainty band.

When NOT to use a plain RBF prior:

  • Data has periodicity — use a periodic kernel instead.
  • Function is not smooth (rough, jagged) — use a Matérn kernel with low smoothness parameter \(\nu\).
  • \(n\) is very large — exact GP inference is \(O(n^3)\); use sparse/inducing-point approximations.
💡 Why this matters

Everything in Gaussian Process regression — predictions, uncertainty estimates, hyperparameter learning via marginal likelihood — is built on top of exactly this object: a mean function and a kernel function defining a joint Gaussian over any finite set of points. Master this definition, and GP regression is "just" conditioning a big multivariate Gaussian.

Code Trace
▼
import numpy as np
# Mean function: m(x) = 0 for every x
def mean_fn(x): return np.zeros_like(x)
# Covariance (RBF / squared-exponential) kernel
def rbf_kernel(x1, x2, ell=1.0, amp=1.0):
d2 = (x1[:, None] - x2[None, :]) ** 2
return amp**2 * np.exp(-0.5 * d2 / ell**2)
# Build covariance matrix K on a grid of points
xs = np.linspace(-5, 5, 36)
K = rbf_kernel(xs, xs, ell=1.0, amp=1.0) + 1e-6 * np.eye(len(xs))
mu = mean_fn(xs)
# Cholesky factorization: K = L L^T
L = np.linalg.cholesky(K)
# Sample functions from the GP prior
z = np.random.randn(len(xs))
f_sample = mu + L @ z # one draw from GP(m, k)
# Pointwise variance -> 2-sigma confidence band
var = np.diag(K) # = sigma_f^2 everywhere
lower, upper = mu - 2*np.sqrt(var), mu + 2*np.sqrt(var)
