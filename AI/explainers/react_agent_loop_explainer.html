ReAct Agent Loop: Thought → Action → Observation

Empowering LLMs with dynamic reasoning and tool use
Foundational Deep Learning LLMs Agentic AI
1
Understanding ReAct
▼

What is it? ReAct (Reasoning + Acting) is a powerful prompting technique for Large Language Models (LLMs) that enables them to perform complex tasks by interleaving natural language thoughts, actions (tool use), and observations (tool results). This structured interaction allows LLMs to dynamically reason, plan, and adapt their behavior based on real-time feedback from the environment, moving beyond simple text generation to become more capable agents.

Analogy: Imagine a detective solving a complex case. Their process isn't just one long monologue; it's an iterative cycle:

  • Thought: "Based on the evidence, the next logical step is to check the suspect's alibi."
  • Action: "I will call the witness 'Ms. Scarlet' and ask about the suspect's whereabouts on Tuesday evening." (This involves using a "phone" tool.)
  • Observation: "Ms. Scarlet confirms the suspect was at the library, not the mansion." (This is the result from the "phone" tool.)

The detective then uses this new observation to refine their next thought and action, continually progressing towards solving the case. ReAct applies this same iterative, evidence-driven loop to LLMs.

💡 If you remember one thing

ReAct combines the explicit reasoning steps of Chain-of-Thought (CoT) prompting with the ability to execute external tools. This synergy allows LLMs to overcome limitations like outdated knowledge or lack of computational power, making them more robust and capable in complex, dynamic environments.

2
How ReAct Works Internally
▼

The Core Mechanism: Thought, Action, Observation

At its heart, ReAct guides the LLM to generate a sequence of tokens that strictly alternates between three types of output:

  1. Thought: The LLM articulates its internal reasoning process. This might involve planning the next step, breaking down the problem, reflecting on previous observations, or identifying potential tools to use. This step is crucial for transparency and helps the LLM maintain a coherent problem-solving trajectory.
  2. Action: The LLM specifies an external tool to use and its arguments. This is typically a structured output, like Search[query] or Calculator[expression]. The agent then executes this action by calling the corresponding external function or API.
  3. Observation: The result returned by the external tool after executing the action. This observation is then fed back into the LLM's context, becoming part of the ongoing conversation history.

This cycle of Thought, Action, and Observation repeats until the LLM determines it has sufficient information to generate a Final Answer token, which signals the completion of the task.

Design Decision: Why Explicit 'Thought' Steps?

The explicit 'Thought' component is a key innovation. While it adds verbosity, it provides several benefits:

  • Improved Performance: Forces the LLM to articulate its reasoning, which often leads to better planning, reduced hallucination, and more logical problem-solving.
  • Enhanced Debuggability: Makes the agent's decision-making process transparent, allowing developers to understand why certain actions were taken and diagnose failures.
  • Adaptability and Recovery: Enables the agent to reflect on unexpected or erroneous observations, formulate new strategies, and recover from mistakes, making the system more robust.
🔑 Key Property

ReAct transforms LLMs from stateless text generators into stateful agents capable of dynamic interaction with their environment. Each step in the loop updates the agent's "mental state" (its context window), allowing it to build on previous steps and adapt its strategy over time.

3
Why It Works — The Formalism
▼

Mathematical Representation (Simplified)

We can conceptualize the ReAct agent's operation within a Markov Decision Process (MDP) framework, though the LLM's internal state is far richer than a typical MDP state. Let \(P\) be the initial prompt or task. At each step \(t\), the agent's context (or history) is \(H_t\), which includes \(P\) and all previous \((T_k, A_k, O_k)\) triplets. The LLM acts as a policy \(\pi_{LLM}\) that generates the next token given the current context:

$$token_t \sim \pi_{LLM}(token | H_t)$$

The ReAct loop proceeds as follows:

  1. Thought Generation: The LLM generates a thought \(T_t\). This is a sequence of tokens that is appended to the history: \(H_t \leftarrow H_t \cup \{ \text{"Thought: "} T_t \}\).
  2. Action Generation: Based on the updated history, the LLM generates an action \(A_t\). This action is typically a structured call to an external tool, e.g., ToolName[arg1, arg2]. The action is also appended to the history: \(H_t \leftarrow H_t \cup \{ \text{"Action: "} A_t \}\).
  3. Observation: The external tool is executed, yielding an observation \(O_t\). This is an environmental response, not generated by the LLM itself. It is appended to the history: \(H_t \leftarrow H_t \cup \{ \text{"Observation: "} O_t \}\).

This iterative process continues. The objective (implicitly optimized during pre-training and fine-tuning, and explicitly during reinforcement learning from human feedback) is to maximize the probability of reaching a successful Final Answer state:

$$\max_{\pi_{LLM}} \mathbb{E}_{H_0 \sim P, (T_k, A_k, O_k) \sim \pi_{LLM}, \text{Tool}} [\text{Reward}(\text{Final Answer} \mid H_t)]$$

where \(\text{Reward}(\cdot)\) is 1 for a correct final answer and 0 otherwise. The prompt engineering aspect of ReAct provides few-shot examples that effectively guide \(\pi_{LLM}\) to adopt the desired (Thought, Action, Observation) structure.

The Role of Prompting and Fine-tuning

ReAct's effectiveness heavily relies on the LLM's ability to understand the desired prompt format. This is often achieved through:

  • Few-shot Prompting: Providing several examples of successful (Thought, Action, Observation) trajectories in the prompt. This teaches the LLM the desired pattern and how to use the available tools.
  • Fine-tuning: Explicitly fine-tuning the LLM on datasets that demonstrate the ReAct pattern, often using human-curated or synthetic trajectories.
⚠️ Common Pitfall

ReAct's success is not guaranteed. If the LLM generates an invalid action (e.g., calls a non-existent tool, provides incorrect arguments), the observation will likely be an error message. The LLM must then be robust enough to parse this error and generate a new thought to recover. Without good tools, clear examples, and a capable base LLM, ReAct agents can easily fall into infinite loops or produce nonsensical output.

Key Takeaways
▼

When to use ReAct:

  • Complex, Multi-step Tasks: Ideal for problems that require breaking down into sub-problems, such as travel planning, data analysis, or debugging code.
  • Tasks Requiring External Information: When the LLM's internal knowledge is insufficient or outdated, and it needs to query databases, search the web, or access real-time data.
  • Tasks Requiring Computation: For numerical calculations, symbolic manipulation, or any task best handled by a dedicated computational tool (e.g., a calculator or code interpreter).
  • Transparency and Debuggability: When understanding the agent's decision-making process is critical for development, auditing, or user trust.

When NOT to use:

  • Simple, Single-Turn Questions: For straightforward queries that an LLM can answer directly, the overhead of the ReAct loop is unnecessary.
  • Highly Constrained, Deterministic Tasks: If a task can be solved by a direct, single function call without any reasoning or adaptation, a simpler approach is often more efficient.
  • Unreliable or Slow Tools: If the external tools are prone to errors, timeouts, or significant latency, the ReAct loop can become inefficient, costly, or lead to poor user experience.
  • Limited LLM Capability: If the base LLM lacks strong reasoning abilities or struggles to follow instructions, ReAct may not yield good results, as it relies on the LLM to drive the loop effectively.
💡 Big Picture

ReAct is a foundational pattern for building general-purpose LLM agents that can operate autonomously in complex environments. It represents a significant step towards more intelligent and capable AI systems by integrating reasoning, planning, and tool-use into a cohesive, iterative framework. Its success hinges on careful tool design, robust prompt engineering, and a capable underlying LLM.

import re
# --- Simulated LLM and Tools ---
class MockLLM:
def generate(self, prompt_history):
# In a real system, this calls the LLM API.
# Here, we simulate responses based on keywords in history.
if "capital of France" in prompt_history and "Thought" not in prompt_history:
return "I need to find the capital of France first."
if "capital of France" in prompt_history and "Thought" in prompt_history and "Action" not in prompt_history:
return "Search[capital of France]"
if "Paris is the capital" in prompt_history and "population of Paris" not in prompt_history:
return "Now that I know the capital, I need to find its population."
if "population of Paris" in prompt_history and "Action" not in prompt_history:
return "Search[population of Paris]"
if "Paris population: 2.14 million" in prompt_history:
return "Final Answer: The capital of France is Paris, and its current population is approximately 2.14 million."
return "I am unsure how to proceed."
class Tools:
def Search(self, query):
if "capital of France" in query:
return "Paris is the capital of France."
if "population of Paris" in query:
return "Paris population: 2.14 million (2023)."
return "No relevant search results found."
# --- ReAct Agent Loop Implementation ---
def react_agent_loop(llm, tools_instance, initial_prompt, max_steps=10):
history = [f"Question: {initial_prompt}"]
for step_num in range(max_steps):
# 1. Generate Thought
current_context = "\n".join(history) + "\nThought:"
thought = llm.generate(current_context)
history.append(f"Thought: {thought}")
# 2. Generate Action
current_context = "\n".join(history) + "\nAction:"
action_str = llm.generate(current_context)
history.append(f"Action: {action_str}")
if action_str.startswith("Final Answer:"):
return action_str.replace("Final Answer:", "").strip()
# Parse action and execute tool
match = re.match(r"(\w+)\[(.*?)\]", action_str)
if match:
tool_name, tool_args = match.groups()
if hasattr(tools_instance, tool_name):
observation = getattr(tools_instance, tool_name)(tool_args)
else:
observation = f"Error: Unknown tool '{tool_name}'"
else:
observation = f"Error: Invalid action format: '{action_str}'"
# 3. Add Observation
history.append(f"Observation: {observation}")
return "Max steps reached without a final answer."
