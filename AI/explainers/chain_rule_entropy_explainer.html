Understanding the Chain Rule of Entropy
▼

What is it? The chain rule of entropy says that the total uncertainty in a collection of random variables can always be broken down into a sum of conditional uncertainties — each variable's uncertainty given everything we already know about the preceding ones.

Analogy: Imagine guessing all the words in a sentence one at a time. Before you hear any word, guessing the first one is hard (high uncertainty). Once you know the first word, guessing the second is a bit easier (less uncertainty). By the time you've heard five words, guessing the sixth is easier still. The chain rule says: the total surprise in the whole sentence equals the sum of the surprise at each word, given all previous words.

Formally, for random variables \(X_1, X_2, \ldots, X_n\):

$$H(X_1, X_2, \ldots, X_n) = \sum_{i=1}^{n} H(X_i \mid X_1, X_2, \ldots, X_{i-1})$$

where \(H(X_1 \mid ) \triangleq H(X_1)\) by convention (nothing is conditioned on for the first term).

If you remember one thing

Joint entropy equals the sum of conditional entropies added one variable at a time. This is exact — no approximation. It is the information-theoretic analog of the chain rule of probability: \(P(X_1,\ldots,X_n)=\prod_i P(X_i|X_1,\ldots,X_{i-1})\). GPT and all autoregressive language models maximize the log-likelihood of exactly this decomposition.

2
How It Works Internally
▼

From Probability to Entropy via Logarithms

Entropy for a single variable is \(H(X) = -\sum_x P(X{=}x)\log_2 P(X{=}x)\). The chain rule of entropy flows directly from the chain rule of probability. Because \(\log P(X_1,\ldots,X_n) = \sum_i \log P(X_i | X_1,\ldots,X_{i-1})\), taking expectations of both sides gives the entropy identity immediately.

Conditional Entropy — Defined Precisely

The conditional entropy of \(X_i\) given \(X_1,\ldots,X_{i-1}\) is the expected entropy of \(X_i\) after observing the conditioning variables:

$$H(X_i \mid X_1,\ldots,X_{i-1}) = \sum_{x_1,\ldots,x_{i-1}} P(x_1,\ldots,x_{i-1}) \cdot H(X_i \mid X_1{=}x_1,\ldots,X_{i-1}{=}x_{i-1})$$

Conditioning can only reduce or maintain entropy, never increase it: \(H(X_i | \text{past}) \leq H(X_i)\). Equality holds iff \(X_i\) is independent of the past — i.e., no information about \(X_i\) is contained in \(X_1,\ldots,X_{i-1}\).

Connection to Language Modeling

An autoregressive language model (GPT, LLaMA, etc.) parameterizes each factor \(P_\theta(x_i | x_1,\ldots,x_{i-1})\) with a neural network. The cross-entropy training loss it minimizes is exactly an empirical estimate of \(H(X_1,\ldots,X_n)\) measured in nats (using \(\ln\) instead of \(\log_2\)). Perplexity is \(2^{H}\), the exponentiated average bits per token.

Key Property — No Approximation

The chain rule is an exact identity, not an approximation. Unlike many factorizations in ML (mean-field VI, naïve Bayes), this one holds for every joint distribution, regardless of dependencies. The order of variables can be changed, but different orders give different (all valid) decompositions, each summing to the same joint entropy.

3
Why It Works — The Math
▼

Proof for Two Variables

Start from the chain rule of probability: \(P(X_1, X_2) = P(X_1) \cdot P(X_2 \mid X_1)\). Take \(-\log\) of both sides:

$$-\log P(X_1, X_2) = -\log P(X_1) - \log P(X_2 \mid X_1)$$

Take expectations under \(P(X_1, X_2)\) on both sides:

$$H(X_1, X_2) = H(X_1) + H(X_2 \mid X_1)$$

This works because \(\mathbb{E}_{P(X_1,X_2)}[-\log P(X_2|X_1)] = H(X_2|X_1)\) by definition of conditional entropy.

Extension to n Variables (Induction)

By induction on \(n\): assume \(H(X_1,\ldots,X_{n-1}) = \sum_{i=1}^{n-1} H(X_i|X_1,\ldots,X_{i-1})\). Then:

$$H(X_1,\ldots,X_n) = H(X_1,\ldots,X_{n-1}) + H(X_n \mid X_1,\ldots,X_{n-1})$$

Substituting the inductive hypothesis completes the proof.

Numerical Verification (3-variable example)

With the concrete example used in the visualization below — binary \(X_1, X_2, X_3\) with specific conditional distributions:

$$H(X_1) = 1.0000 \text{ bits}, \quad H(X_2|X_1) = 0.8016 \text{ bits}, \quad H(X_3|X_1,X_2) = 0.8589 \text{ bits}$$
$$H(X_1,X_2,X_3) = 2.6605 \text{ bits} \;=\; 1.0000 + 0.8016 + 0.8589 \checkmark$$
Common Misconception

The chain rule does NOT say that different orderings give different totals — the joint entropy \(H(X_1,\ldots,X_n)\) is unique (it's a property of the joint distribution). Different orderings give different sequences of conditionals, but each sequence sums to the same value. Only the intermediate terms change across orderings.

Key Takeaways & Applications
▼

Why this matters for ML:

  • Language models: GPT/LLaMA train on the cross-entropy of exactly this factorization — one conditional per token
  • Data compression: The chain rule says the minimum average code length for \((X_1,\ldots,X_n)\) equals the sum of conditional entropies — motivates arithmetic coding with context models
  • Feature selection: If adding feature \(X_i\) reduces \(H(Y|X_1,\ldots,X_i)\) significantly, it is informative about \(Y\)
  • Mutual information: \(I(X;Y) = H(X) - H(X|Y)\); the chain rule underlies multivariate MI and conditional MI

When conditioning helps most:

  • Strong dependencies between variables — conditioning can dramatically reduce entropy
  • Later terms in the sequence: \(H(X_n|X_1,\ldots,X_{n-1}) \leq \cdots \leq H(X_2|X_1) \leq H(X_1)\) when the process is predictable
Connection to Autoregressive Models

The cross-entropy loss for a language model with parameters \(\theta\) on sequence \((x_1,\ldots,x_n)\) is: \(-\frac{1}{n}\sum_{i=1}^n \log P_\theta(x_i | x_1,\ldots,x_{i-1})\). This is an empirical estimate of \(H(X_1,\ldots,X_n)/n\) bits per token — exactly the chain rule, one term at a time.

Code Trace

import numpy as np
from scipy.stats import entropy
# Binary variables: P(X1=0)=0.5, P(X1=1)=0.5
p_x1 = np.array([0.5, 0.5]) # marginal of X1
H_X1 = entropy(p_x1, base=2) # H(X1) = 1.0 bit
# Conditional table P(X2 | X1) [rows=X1, cols=X2]
p_x2_given_x1 = np.array([[0.7, 0.3], # P(X2|X1=0)
[0.2, 0.8]]) # P(X2|X1=1)
H_X2_X1 = np.dot(p_x1, # H(X2|X1)
[entropy(row, base=2) for row in p_x2_given_x1])
# Marginal of X2 (for computing X3's conditional)
p_x2 = p_x1 @ p_x2_given_x1 # [0.45, 0.55]
# P(X3 | X2) — X3 depends only on X2 (Markov)
p_x3_given_x2 = np.array([[0.8, 0.2], # P(X3|X2=0)
[0.4, 0.6]]) # P(X3|X2=1)
H_X3_X1X2 = np.dot(p_x2, # H(X3|X1,X2) = H(X3|X2)
[entropy(row, base=2) for row in p_x3_given_x2])
# Chain rule: H(X1,X2,X3) = H(X1) + H(X2|X1) + H(X3|X1,X2)
H_joint = H_X1 + H_X2_X1 + H_X3_X1X2 # 2.6605 bits
# Verify via direct joint computation
p_joint = np.outer(p_x1, p_x2_given_x1) # shape (2,2)
p_joint3 = np.einsum('ij,jk->ijk', p_joint, p_x3_given_x2)
H_direct = entropy(p_joint3.ravel(), base=2)
assert abs(H_joint - H_direct) < 1e-10 # exact equality
