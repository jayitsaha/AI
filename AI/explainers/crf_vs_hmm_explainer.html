CRF vs HMM: Global Normalization

Understanding the fundamental difference in probability modeling for sequence labeling
Foundational NLP Machine Learning O(T S²) (inference)
1
Understanding HMMs and CRFs
▼

What are they? Hidden Markov Models (HMMs) and Conditional Random Fields (CRFs) are powerful statistical models for sequence labeling tasks, such as Part-of-Speech (POS) tagging, Named Entity Recognition (NER), or speech recognition. They assign a sequence of hidden states (labels) to a sequence of observed inputs (e.g., words).

The Core Difference: Normalization Scope. This is the single most important distinction. HMMs are generative models that define a joint probability distribution \(P(X, Y)\) over observation sequences \(X\) and label sequences \(Y\). They normalize probabilities locally at each step. CRFs, on the other hand, are discriminative models that directly define the conditional probability \(P(Y|X)\) of a label sequence given an observation sequence. Crucially, CRFs normalize globally over all possible label sequences for a given observation.

Analogy: Local vs. Global Optimism. Imagine a team trying to predict the weather for the next week. An HMM forecaster would predict each day's weather by only considering yesterday's weather and the immediate observations (e.g., clouds today). They normalize their probabilities for *each day* independently. A CRF forecaster would look at the entire week's observations (satellite images, pressure systems, etc.) and evaluate all possible week-long weather patterns, then normalize the probability of each *entire week-long sequence*. The CRF can see the bigger picture, ensuring the most coherent overall forecast wins, even if individual days look slightly less probable in isolation.

💡 If you remember one thing

HMMs normalize locally at each step (emission and transition probabilities sum to 1). CRFs normalize globally over all possible label sequences for a given observation sequence. This global view makes CRFs more robust and avoids the "label bias problem."

2
How They Work Internally
▼

Hidden Markov Models (HMMs)

HMMs model the process of generating both the hidden states and the observations. They are defined by:

  • Initial State Probabilities: \(P(y_1)\) for the first hidden state.
  • Transition Probabilities: \(P(y_i | y_{i-1})\) for moving from one hidden state to the next. These sum to 1 for each \(y_{i-1}\): \(\sum_{y_i} P(y_i | y_{i-1}) = 1\).
  • Emission Probabilities: \(P(x_i | y_i)\) for observing \(x_i\) given hidden state \(y_i\). These sum to 1 for each \(y_i\): \(\sum_{x_i} P(x_i | y_i) = 1\).

To find the probability of a sequence of states and observations \(P(Y, X)\), HMMs multiply these local probabilities along a path. Because of the local normalization, an HMM might assign high probability to a state that has few outgoing transitions (a "low entropy" state), even if those few transitions lead to overall unlikely paths. This is the root of the "label bias problem."

Conditional Random Fields (CRFs)

CRFs directly model the conditional probability \(P(Y|X)\). Instead of probabilities, CRFs use feature functions and weights:

  • Feature Functions: \(f_k(y_{i-1}, y_i, x, i)\) are arbitrary functions that capture characteristics of the input \(x\) at position \(i\), previous state \(y_{i-1}\), and current state \(y_i\). These can be overlapping and non-independent.
  • Weights: \(\lambda_k\) are real-valued parameters learned for each feature function.
  • Potentials: The score for a particular state transition \((y_{i-1} \to y_i)\) is an exponential of a weighted sum of features: \(\exp\left(\sum_k \lambda_k f_k(y_{i-1}, y_i, x, i)\right)\). These individual potentials are NOT probabilities and do NOT sum to 1 locally.

The key is that CRFs compute a score for an entire label sequence \(Y\) given \(X\), then normalize this score by summing over the scores of all possible label sequences for that \(X\). This global normalization ensures that the probabilities are well-behaved and avoids the label bias problem, as the model explicitly compares the likelihood of one full path against all others.

🔑 Key Property

CRFs can incorporate rich, overlapping, global features of the observation sequence \(X\) when determining the likelihood of a label sequence \(Y\), something HMMs cannot easily do due to their strong independence assumptions and local normalization.

3
Why It Works — The Math
▼

HMM Joint Probability

For an HMM, the joint probability of an observation sequence \(X = (x_1, \dots, x_T)\) and a state sequence \(Y = (y_1, \dots, y_T)\) is given by:

$$P(Y, X) = P(y_1) \cdot \prod_{i=2}^T P(y_i | y_{i-1}) \cdot \prod_{i=1}^T P(x_i | y_i)$$

Here, \(P(y_i | y_{i-1})\) is a transition probability and \(P(x_i | y_i)\) is an emission probability. Both are normalized such that \(\sum_{y_i} P(y_i | y_{i-1}) = 1\) for all \(y_{i-1}\) and \(\sum_{x_i} P(x_i | y_i) = 1\) for all \(y_i\). This local normalization is efficient for computation but can lead to the label bias problem.

CRF Conditional Probability

For a CRF, the conditional probability of a state sequence \(Y\) given an observation sequence \(X\) is:

$$P(Y|X) = \frac{1}{Z(X)} \exp\left(\sum_{k=1}^K \lambda_k F_k(Y, X)\right)$$

where \(F_k(Y, X) = \sum_{i=1}^T f_k(y_{i-1}, y_i, x, i)\) is a global feature function (sum of local feature functions \(f_k\)) and \(\lambda_k\) are learned weights. The crucial term is the global normalization constant \(Z(X)\):

$$Z(X) = \sum_{Y'} \exp\left(\sum_{k=1}^K \lambda_k F_k(Y', X)\right)$$

This \(Z(X)\) sums over the scores of all possible label sequences \(Y'\) for the given input \(X\). This summation is computationally intensive but ensures that the probabilities \(P(Y|X)\) are properly normalized over the entire output space, directly addressing the label bias problem. The sum over all paths is typically computed using dynamic programming (a variant of the forward-backward algorithm).

⚠️ The Label Bias Problem (HMMs)

In HMMs, states with fewer outgoing transitions (e.g., a state that mostly transitions to itself) have their "probability mass" concentrated on those few transitions. This can artificially inflate the probability of paths involving such states, regardless of the overall sequence's true likelihood. CRFs avoid this because the normalization constant \(Z(X)\) considers all paths, effectively penalizing paths that are locally strong but globally weak.

Key Takeaways
▼

When to use HMMs:

  • When computational efficiency is paramount, especially for very long sequences or many states.
  • When the generative story of the data is useful (e.g., for data simulation or understanding underlying processes).
  • When strong independence assumptions (Markov property, output independence) are reasonable for the problem.
  • When you have limited training data, as HMMs tend to require less data than CRFs due to simpler parameterization.

When to use CRFs:

  • For most modern sequence labeling tasks (POS tagging, NER, chunking) where accuracy is critical.
  • When you need to incorporate rich, overlapping, and non-independent features from the observation sequence.
  • When avoiding the "label bias problem" is important, ensuring that globally optimal paths are preferred.
  • When modeling conditional probability \(P(Y|X)\) directly is desired, without modeling \(P(X)\) (which is often complex and irrelevant for discrimination).
💡 Summary

HMMs are simple, generative, and locally normalized. CRFs are powerful, discriminative, and globally normalized. While HMMs are a good conceptual stepping stone, CRFs generally offer superior performance for sequence labeling by handling complex, interdependent features and avoiding label bias.

Code Trace (Python/Numpy)
▼
import numpy as np
# --- Shared Data ---
states = ['N', 'V']
observations = ['The', 'dog', 'barks']
state_map = {'N': 0, 'V': 1}
obs_map = {'The': 0, 'dog': 1, 'barks': 2}
# --- HMM Calculations ---
# Initial probabilities P(y1)
pi = np.array([0.5, 0.5]) # P('N'), P('V')
# Transition probabilities P(yi | yi-1)
# to N to V
# from N [[0.6, 0.4],
# from V [0.3, 0.7]]
A = np.array([[0.6, 0.4], [0.3, 0.7]])
# Emission probabilities P(xi | yi)
# The dog barks
# from N [[0.8, 0.7, 0.1],
# from V [0.1, 0.2, 0.9]]
B = np.array([[0.8, 0.7, 0.1], [0.1, 0.2, 0.9]])
def hmm_path_prob(y_seq, x_seq, pi, A, B):
prob = pi[state_map[y_seq[0]]] * B[state_map[y_seq[0]], obs_map[x_seq[0]]]
for i in range(1, len(x_seq)):
prev_s = state_map[y_seq[i-1]]
curr_s = state_map[y_seq[i]]
obs_idx = obs_map[x_seq[i]]
prob *= A[prev_s, curr_s] * B[curr_s, obs_idx]
return prob
# --- CRF Calculations ---
# Feature functions (simplified for illustration)
# f_obs(state, observation_idx)
# f_trans(prev_state, curr_state)
# Example weights (learned parameters)
weights = {
'obs_N_The': 1.5, 'obs_N_dog': 1.2, 'obs_N_barks': -1.0,
'obs_V_The': -1.0, 'obs_V_dog': -0.8, 'obs_V_barks': 1.8,
'trans_N_N': 0.8, 'trans_N_V': 0.5,
'trans_V_N': 0.2, 'trans_V_V': 1.0,
'initial_N': 0.0, 'initial_V': 0.0 # No strong initial bias
}
def crf_path_score(y_seq, x_seq, weights):
score = weights[f'initial_{y_seq[0]}']
score += weights[f'obs_{y_seq[0]}_{x_seq[0]}']
for i in range(1, len(x_seq)):
score += weights[f'trans_{y_seq[i-1]}_{y_seq[i]}']
score += weights[f'obs_{y_seq[i]}_{x_seq[i]}']
return score
# To get P(Y|X) for CRF, you'd need to compute Z(X)
# This involves summing exp(score) for ALL possible y_seq,
# typically via a Forward-Backward algorithm (omitted for brevity).
# Example usage:
y_path_NNV = ['N', 'N', 'V']
y_path_NVV = ['N', 'V', 'V']
hmm_prob_NNV = hmm_path_prob(y_path_NNV, observations, pi, A, B)
crf_score_NNV = crf_path_score(y_path_NNV, observations, weights)
print(f"HMM P(NNV, X): {hmm_prob_NNV:.6f}")
print(f"CRF Score(NNV, X): {crf_score_NNV:.2f}")
