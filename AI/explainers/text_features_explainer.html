1
Understanding Text Features
▼

What are they? Text features are numerical representations derived from raw text, making it understandable to machine learning models. Since ML algorithms operate on numbers, converting unstructured text into structured numerical vectors is a crucial first step in any NLP pipeline, from spam detection to sentiment analysis.

Analogy: Imagine you want to describe a fruit. You could say "it's red, round, and sweet" (these are features). For text, instead of "red" or "round," we extract properties like "contains the word 'great' 5 times" (Bag-of-Words), or "is 150 words long" (text length), or "is easy to read" (readability score). Each of these becomes a number that an algorithm can process.

💡 If you remember one thing

The core challenge in NLP is bridging the gap between human language and machine-readable data. Text features are the numerical "language" that allows models to learn patterns in documents, classify them, or predict outcomes based on their content.

2
How Text Features Are Constructed
▼

The Preprocessing Pipeline

Before extracting most features, text undergoes a series of preprocessing steps to standardize it and reduce noise:

  • Tokenization: Breaking text into smaller units (words, subwords, characters).
  • Lowercasing: Converting all text to lowercase to treat "The" and "the" as the same token.
  • Stopword Removal: Eliminating common, less informative words (e.g., "a", "is", "the") that add little semantic value.
  • Stemming/Lemmatization: Reducing words to their root form (e.g., "running" → "run", "better" → "good") to unify different inflections of the same word.

Common Feature Types

Once preprocessed, various numerical representations can be derived:

  • Bag-of-Words (BoW): A simple count of how many times each word from a predefined vocabulary appears in a document. It ignores word order.
  • TF-IDF: Extends BoW by weighting words. It considers both how frequently a word appears in a document (Term Frequency, TF) and how unique or rare it is across the entire corpus (Inverse Document Frequency, IDF).
  • N-grams (Word & Character): Sequences of N adjacent words or characters. These capture local context and word order that BoW misses.
  • Text Length: Simple metrics like total word count, character count, or sentence count.
  • Readability Scores: Metrics (e.g., Flesch-Kincaid) that estimate the difficulty of a text based on factors like sentence length and syllable count.
🔑 Key Property

The choice of text features and preprocessing steps is highly dependent on the specific NLP task. For example, sentiment analysis often benefits from retaining negations (so 'not good' isn't just 'good'), while topic modeling might benefit from aggressive stopword removal and stemming.

3
Why It Works — The Math Behind TF-IDF
▼

Term Frequency (TF)

Term Frequency measures how often a term \(t\) appears in a document \(d\). A common normalization is to divide by the total number of terms in the document to prevent longer documents from having higher TF values by default:

$$\text{TF}(t, d) = \frac{\text{count}(t \text{ in } d)}{\sum_{t' \in d} \text{count}(t' \text{ in } d)}$$

This gives the proportion of term \(t\) in document \(d\). Other variations exist, like logarithmic scaling or binary presence.

Inverse Document Frequency (IDF)

Inverse Document Frequency measures how important a term is by downweighting terms that appear frequently across many documents in a corpus \(D\). If a term appears in almost every document, it's likely not very informative (e.g., "the").

$$\text{IDF}(t, D) = \log\left(\frac{N}{\text{DF}(t, D) + 1}\right)$$

Here, \(N\) is the total number of documents in the corpus, and \(\text{DF}(t, D)\) is the number of documents in \(D\) that contain term \(t\). The \(+1\) in the denominator is a smoothing term to prevent division by zero for terms not in the corpus, and the \(\log\) scales the value. A higher IDF means the term is rarer and thus more informative.

TF-IDF Score

The TF-IDF score for a term \(t\) in a document \(d\) within a corpus \(D\) is simply the product of its TF and IDF values:

$$\text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \text{IDF}(t, D)$$

This combined score reflects both the local importance of a term within a document and its global rarity across the entire corpus. Documents can then be represented as vectors where each dimension corresponds to a term in the vocabulary, and its value is the term's TF-IDF score.

⚠️ Common Pitfall

TF-IDF is highly sensitive to the quality and size of your corpus. If your corpus is too small or not representative of the domain, IDF values can be misleading. For very large corpora or streaming data, IDF might be pre-computed or estimated incrementally.

Key Takeaways
▼

When to use specific features:

  • Bag-of-Words (BoW): Simple, fast baseline for classification (spam, sentiment). Good when word order is less critical.
  • TF-IDF: Excellent for document similarity, search relevance, and topic modeling. Highlights important words in a document relative to a corpus.
  • N-grams (Word): Improves BoW by capturing short phrases ("not good"). Useful when word order or collocations are important for meaning.
  • N-grams (Character): Robust to misspellings, handles out-of-vocabulary words, and useful for languages without clear word boundaries. Good for text classification or language identification.
  • Text Length: Can be a strong signal for tasks like spam detection (short spam vs. long emails), article quality, or genre classification.
  • Readability Scores: Useful for predicting target audience, educational level, or content complexity (e.g., news article vs. academic paper).

When to be cautious or use alternatives:

  • High Dimensionality: BoW and N-grams create very sparse, high-dimensional vectors, which can be computationally expensive and prone to the "curse of dimensionality."
  • Loss of Context: BoW completely ignores word order and semantic relationships. "Dog bites man" is the same as "Man bites dog."
  • Out-of-Vocabulary (OOV) Words: BoW and TF-IDF struggle with words not seen during training.
  • Deep Learning Embeddings: For more complex tasks requiring semantic understanding and context, modern deep learning methods (Word2Vec, BERT, GPT embeddings) often outperform traditional features, as they learn dense, lower-dimensional representations that capture meaning.
💡 Feature Engineering is Key

While advanced embeddings are powerful, traditional text features remain highly relevant. They are interpretable, computationally efficient, and often serve as strong baselines or complementary features in hybrid models. Understanding their strengths and weaknesses is fundamental to applied NLP.

import re
from collections import Counter
import math
# --- 1. Preprocessing ---
def preprocess_text(text, remove_stopwords=False, apply_stemming=False):
tokens = re.findall(r'\b\w+\b', text.lower())
if remove_stopwords:
stopwords = {'the', 'a', 'is', 'over', 'past', 'and', 'for', 'in'} # example list
tokens = [t for t in tokens if t not in stopwords]
if apply_stemming:
tokens = [stem(t) for t in tokens] # simplified stemmer
return tokens
def stem(word): # Basic example, not a full NLP stemmer
if word.endswith('s'): return word[:-1]
if word.endswith('ing'): return word[:-3]
return word
# --- 2. Feature Extraction ---
def bag_of_words(tokens):
return Counter(tokens) # Returns {word: count}
def calculate_tfidf(doc_tokens, corpus_docs_tokens):
tf_scores = {}
total_words_in_doc = len(doc_tokens)
for term, count in Counter(doc_tokens).items():
tf_scores[term] = count / total_words_in_doc
idf_scores = {}
N = len(corpus_docs_tokens)
all_unique_terms = set(term for doc in corpus_docs_tokens for term in doc)
for term in all_unique_terms:
df = sum(1 for doc in corpus_docs_tokens if term in doc)
idf_scores[term] = math.log(N / (df + 1))
tfidf_vector = {term: tf_scores.get(term, 0) * idf_scores.get(term, 0)
for term in all_unique_terms}
return tfidf_vector
def get_ngrams(tokens, n, type='word'):
if type == 'word':
return Counter(tuple(tokens[i:i+n]) for i in range(len(tokens) - n + 1))
elif type == 'char':
text = "".join(tokens) # join words for char n-grams
return Counter(text[i:i+n] for i in range(len(text) - n + 1))
def flesch_kincaid_grade(text):
sentences = re.split(r'[.!?]', text)
sentences = [s.strip() for s in sentences if s.strip()]
words = preprocess_text(text)
syllables = sum(count_syllables(w) for w in words)
word_count = len(words)
sentence_count = len(sentences)
if word_count == 0 or sentence_count == 0: return 0.0
score = 0.39 * (word_count / sentence_count) + 11.8 * (syllables / word_count) - 15.59
return max(0, score)
def count_syllables(word): # Heuristic for English
word = word.lower()
count = 0
vowels = "aeiouy"
if len(word) == 0: return 0
if word[0] in vowels: count += 1
for i in range(1, len(word)):
if word[i] in vowels and word[i-1] not in vowels: count += 1
if word.endswith("e"): count -= 1
if word.endswith("le") and len(word) > 2 and word[-3] not in vowels: count += 1
return max(1, count)
