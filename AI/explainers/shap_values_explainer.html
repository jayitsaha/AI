1
Understanding SHAP Values
▼

What is it? SHAP (SHapley Additive exPlanations) is a unified framework to explain the output of any machine learning model. For a single prediction, SHAP values tell us how much each feature contributed to pushing the model's output from a baseline (e.g., the average prediction) to the current prediction. It's rooted in cooperative game theory, ensuring a "fair" distribution of the prediction among features.

Analogy: Imagine a team of developers collaborating on a complex software project. At the end, the project is a huge success. How do you fairly credit each developer for their contribution to the final success? You can't just count lines of code. Instead, you consider what value each developer added *in every possible sub-team they could have been part of*. That average marginal contribution is their "Shapley value" — a fair way to attribute success. SHAP applies this exact logic to features in a machine learning model.

💡 If you remember one thing

SHAP values explain a prediction by treating each feature as a "player" in a "game" where the prediction is the "payout". Each feature's SHAP value is its average marginal contribution to the prediction across all possible coalitions of features. This ensures the explanations are consistent and locally accurate.

2
How SHAP Works Internally
▼

The Core Idea: Shapley Values from Game Theory

The original Shapley value (Shapley, 1953) is a concept from cooperative game theory that fairly distributes the total gains (or losses) among players in a coalition. For machine learning, the "players" are the input features, and the "game" is the prediction task. The "payout" is the model's output for a specific instance.

A feature's Shapley value is calculated by considering its contribution to the prediction when added to *every possible subset* of other features. This marginal contribution is then averaged across all these subsets, weighted by the number of permutations where that specific subset occurs. This ensures that the sum of all feature contributions equals the difference between the model's output and the expected baseline output.

The Computational Challenge: Exponential Complexity

For a model with \(M\) features, there are \(2^M\) possible subsets of features. Calculating the exact Shapley value for a single feature requires evaluating the model \(2^{M-1}\) times (once for each subset with the feature, and once for each without). Since there are \(M\) features, the total computational cost is \(M \cdot 2^{M-1}\) model evaluations. This is computationally prohibitive for most real-world models with many features.

Approximation Methods: KernelSHAP, TreeSHAP, DeepSHAP

To overcome the computational bottleneck, various approximation methods have been developed, each tailored to different model types:

  • KernelSHAP: Model-agnostic. It approximates Shapley values by training a weighted linear regression model on a simplified input space. It samples feature coalitions and weights them according to the Shapley kernel.
  • TreeSHAP: Optimized for tree-based models (decision trees, random forests, gradient boosting machines). It leverages the tree structure to compute exact Shapley values in polynomial time (instead of exponential), typically \(O(TD^2)\) or \(O(TLD)\) where \(T\) is the number of trees, \(D\) is max depth, \(L\) is max leaves.
  • DeepSHAP: Optimized for deep learning models. It uses a backpropagation-like approach to approximate SHAP values by attributing contributions through the network layers. It's often faster than KernelSHAP for deep models but is also an approximation.
🔑 Key Property: Additive Feature Attribution

SHAP values are "additive" in the sense that the sum of all feature contributions (\(\phi_i\)) plus a baseline value (\(\phi_0\)) equals the model's prediction for the instance. This property, \(f(x) = \phi_0 + \sum_{i=1}^M \phi_i\), makes SHAP explanations intuitive and directly links feature contributions to the final output.

3
Why It Works — The Math
▼

Formal Definition of Shapley Values

For a model \(f\) and an instance \(x\), we want to explain the prediction \(f(x)\). Let \(F\) be the set of all \(M\) features. The Shapley value \(\phi_i(f, x)\) for feature \(i\) is given by:

$$\phi_i(f, x) = \sum_{S \subseteq F \setminus \{i\}} \frac{|S|!(|F|-|S|-1)!}{|F|!} (f_x(S \cup \{i\}) - f_x(S))$$

Here, \(S\) is a subset of features not including \(i\), \(|S|\) is its size, and \(f_x(S)\) is the model's prediction using only the features in set \(S\), with features not in \(S\) "integrated out" (typically by replacing them with values from a background dataset). The term \(f_x(S \cup \{i\}) - f_x(S)\) represents the marginal contribution of feature \(i\) when added to the coalition \(S\).

The Additive Feature Attribution Property

A key property of SHAP values is that they form an additive explanation model, meaning the original model \(f(x)\) can be expressed as a sum of feature effects:

$$f(x) = \phi_0 + \sum_{i=1}^M \phi_i$$

where \(\phi_0 = \mathbb{E}[f(X)]\) is the expected output of the model (the baseline prediction over a background dataset), and \(\phi_i\) is the SHAP value for feature \(i\). This structure is what makes SHAP a "unified" framework, as it connects local explanations to a simple linear model.

Desirable Properties of Shapley Values

The Shapley value is the *only* solution concept that satisfies these four properties:

  1. Efficiency: The sum of the feature contributions equals the difference between the actual prediction and the baseline prediction: \(\sum_{i=1}^M \phi_i = f(x) - \mathbb{E}[f(X)]\).
  2. Symmetry: If two features contribute equally to all possible coalitions, they get the same SHAP value.
  3. Dummy: A feature that never changes the prediction (its marginal contribution is always zero) gets a SHAP value of zero.
  4. Additivity: For a game that is a sum of two independent games, the Shapley values are also additive.

These properties ensure that SHAP values provide a unique and fair attribution of the prediction to each feature.

⚠️ Common Pitfall: Feature Correlation

When features are highly correlated, the "integrating out" process (replacing features with background values) can involve evaluating the model on unrealistic or out-of-distribution feature combinations. This can lead to misleading SHAP values, as the model's behavior on such synthetic inputs might not reflect its real-world decision-making process.

Key Takeaways
▼

When to use SHAP values:

  • For local interpretability: explaining *why* a model made a specific prediction for a single instance.
  • To understand global feature importance: aggregating SHAP values across many instances can reveal which features are most important overall.
  • When you need consistent and fair attribution: The game-theoretic foundation ensures properties like efficiency and symmetry.
  • For model-agnostic explanations: KernelSHAP can explain any black-box model.
  • For tree-based models: TreeSHAP offers fast and exact SHAP value computation.

When NOT to use / be cautious:

  • High computational cost: Exact Shapley values are \(O(M!)\), and even approximations like KernelSHAP can be slow for many features or large datasets.
  • Feature correlation: As noted, SHAP's reliance on "integrating out" features can lead to issues with highly correlated inputs.
  • Background dataset choice: The choice of the background dataset (for \(\mathbb{E}[f(X)]\) and marginalization) significantly impacts SHAP values. A non-representative background can yield misleading explanations.
  • Interpretation pitfalls: While SHAP values quantify contribution, they don't imply causation.
💡 Big Picture

SHAP provides a powerful, theoretically grounded framework for model interpretability. By framing explanation as a fair allocation problem from game theory, it offers a consistent way to understand feature contributions, bridging the gap between complex model predictions and human understanding.

Code Trace (Python - `shap` library)
▼
import shap
import numpy as np
from sklearn.ensemble import RandomForestRegressor
# 1. Train a simple model
X, y = shap.datasets.boston() # Example dataset
model = RandomForestRegressor(max_depth=6, random_state=0)
model.fit(X, y)
# 2. Choose an instance to explain
instance_to_explain = X.iloc[[0]]
print(f"Model prediction: {model.predict(instance_to_explain)[0]:.2f}")
# 3. Create a SHAP explainer (e.g., TreeExplainer for tree models)
# A background dataset is needed for E[f(X)] and marginalization
explainer = shap.TreeExplainer(model, data=X) # 'data' is the background
# 4. Compute SHAP values for the instance
shap_values = explainer.shap_values(instance_to_explain)
# 5. Visualize the explanation (e.g., force plot)
# shap.initjs() # For JS visualizations in notebooks
# shap.force_plot(explainer.expected_value, shap_values[0], instance_to_explain)
# Verify additive property (sum of SHAP values + base = prediction)
base_value = explainer.expected_value
sum_shap = np.sum(shap_values[0])
reconstructed_prediction = base_value + sum_shap
print(f"Baseline (E[f(X)]): {base_value:.2f}")
print(f"Sum of SHAP values: {sum_shap:.2f}")
print(f"Reconstructed prediction: {reconstructed_prediction:.2f}")
# This should be very close to model.predict(instance_to_explain)
