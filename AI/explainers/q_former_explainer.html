Q-Former (Querying Transformer)

BLIP-2's lightweight bridge between a frozen vision encoder and a frozen LLM
Advanced Multimodal Vision-Language 32 learned tokens
1
Understanding the Q-Former
▼

What is it? Large vision-language models want to reuse two expensive, already-trained pieces: a frozen image encoder (e.g. CLIP ViT-g/14) and a frozen LLM (e.g. OPT or FlanT5). Neither was trained to talk to the other. The Q-Former (Querying Transformer) is a small, lightweight transformer — about 188M parameters — inserted between them that learns to extract exactly the visual information the LLM needs, and packages it as a fixed, tiny set of "vision tokens."

Analogy: Imagine a translator who doesn't speak every word of a foreign lecture, but has learned to ask 32 very good, very specific questions ("what's the main subject?", "what color is it?", "what's happening in the background?") and boils a 20-minute lecture down to 32 crisp answer-cards. Those 32 cards are then handed to a novelist (the frozen LLM) who writes a story using only what's on the cards. The translator's questions are the learnable queries; the answer-cards are the compressed visual tokens.

💡 If you remember one thing

The Q-Former replaces "feed the LLM hundreds of raw image patch embeddings" with "feed the LLM a fixed set of \(K{=}32\) learned query embeddings that have already cross-attended to the image." This makes the vision-to-language bridge resolution-independent, parameter-efficient, and trainable without ever touching the frozen encoder or frozen LLM weights.

2
How the Q-Former Works Internally
▼

Two Transformer Sub-modules, One Shared Self-Attention

The Q-Former has two sub-modules that share the same self-attention layers: an image transformer and a text transformer, both initialized from BERT-base. A set of \(K=32\) learnable query embeddings (each 768-dim, so a \(32\times768\) matrix) is the only new input — it is a trainable parameter, not derived from any image or text.

Inside Each of the \(N{=}12\) Blocks

Each block runs: (1) self-attention among the queries (and jointly with text tokens, depending on the objective's attention mask), (2) a cross-attention layer inserted every other block where queries act as Q and the frozen image encoder's patch feature grid acts as K/V, and (3) a shared feed-forward layer. Only the queries, self-attention, cross-attention, and FFN weights are trainable — the image encoder and, in Stage 2, the LLM are completely frozen.

Design Decision: Why Queries, Not a Pooling Layer?

A simple mean-pool or a linear projection of all patch tokens would produce one fixed vector, losing spatial/semantic diversity. Cross-attention lets each of the 32 queries specialize — one might learn to track "salient object identity," another "spatial layout," another "text-in-image" — and because attention weights are computed at inference time from the actual image, the extraction adapts to whatever the image contains, unlike a fixed pooling function.

🔑 Key Property

The number of output vision tokens is always exactly \(K\) (32 in BLIP-2), regardless of image resolution or patch count. A \(224\times224\) image (257 ViT tokens) and a \(364\times364\) image (677 ViT tokens) both compress down to the same 32 query outputs — the Q-Former is a learned, content-adaptive bottleneck.

3
Why It Works — Objectives & Attention Masking
▼

Cross-Attention: The Core Operation

Let \(Q \in \mathbb{R}^{32\times d}\) be the query embeddings and \(Z \in \mathbb{R}^{P\times d}\) be the frozen encoder's \(P\) patch features. Cross-attention computes:

$$\text{CrossAttn}(Q,Z) = \operatorname{softmax}\!\left(\frac{(QW_Q)(ZW_K)^\top}{\sqrt{d_k}}\right)(ZW_V)$$

Each query row attends over all \(P\) patches and returns a weighted mixture — the entire image is visible to every query, but each query learns its own weighting.

Stage 1: Three Objectives, Three Attention Masks

Stage 1 trains the Q-Former jointly with a frozen image encoder using three losses on the same forward pass, distinguished only by the self-attention mask applied to the shared transformer:

$$\mathcal{L}_{\text{Stage 1}} = \mathcal{L}_{\text{ITC}} + \mathcal{L}_{\text{ITM}} + \mathcal{L}_{\text{ITG}}$$

ITC (Image-Text Contrastive): unimodal mask — queries and text cannot see each other. Align the query output closest to the text \([CLS]\) embedding via InfoNCE with in-batch negatives:

$$\mathcal{L}_{\text{ITC}} = -\log\frac{\exp(\max_i \, \text{sim}(q_i, t)/\tau)}{\sum_{j} \exp(\max_i \, \text{sim}(q_i, t_j)/\tau)}$$

ITM (Image-Text Matching): bidirectional mask — queries and text fully attend to each other. A binary classifier on each query's output (averaged) predicts match/no-match, trained with hard negative mining.

ITG (Image-grounded Text Generation): causal (multimodal-causal) mask — text tokens attend to all queries plus previous text tokens only, forcing the model to route all image information through the queries to generate captions autoregressively.

⚠️ Common Pitfall

Because ITC, ITM, and ITG share one set of weights but need different information flow, the mask is the entire mechanism — get it wrong (e.g. let ITC's queries see the text) and the contrastive objective trivially leaks the answer, collapsing representation learning.

Stage 2: Bridging to the Frozen LLM

A linear projection \(W_{\text{proj}} \in \mathbb{R}^{768 \times d_{\text{llm}}}\) maps the 32 query outputs to the LLM's embedding dimension. These become soft prompt tokens prepended to the text embedding sequence; the frozen LLM then generates conditioned on them with its ordinary language-modeling loss — no gradient ever touches the LLM or the image encoder, only \(W_{\text{proj}}\) and the Q-Former.

5
Key Takeaways
▼

When Q-Former shines:

  • Bridging any frozen pretrained image encoder to any frozen pretrained LLM cheaply (BLIP-2 trains ~188M params vs. billions for the encoder+LLM)
  • Fixed-length visual context regardless of image resolution — keeps LLM prompt length constant and predictable
  • Strong zero-shot image captioning / VQA by inheriting the LLM's language ability untouched

When NOT to reach for it:

  • Tasks needing fine-grained pixel-level grounding (segmentation) — 32 tokens lose spatial resolution
  • End-to-end fine-tuning is affordable — a fully fine-tuned encoder+LLM (e.g. LLaVA's simple MLP projector + full fine-tune) can outperform a frozen bridge given enough compute
  • Extremely long or high-resolution image sequences where 32 tokens per frame becomes the bottleneck (video needs one Q-Former pass per frame)
💡 Lineage

BLIP (2022, one encoder-decoder, no frozen LLM) → BLIP-2 (2023, Q-Former bridges frozen encoder + frozen LLM) → InstructBLIP (instruction-aware Q-Former, text instruction fed into the query cross-attention) → simpler MLP-projector approaches like LLaVA trade the learned bottleneck for a fully fine-tuned, higher-token-count connection.
