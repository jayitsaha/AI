Understanding Word2Vec
▼

What is it? Word2Vec turns each word in a vocabulary into a dense vector of a few hundred numbers, learned purely by reading massive amounts of text and noticing which words tend to appear near each other. No dictionary, no grammar rules — just co-occurrence statistics compressed into geometry.

Analogy: Imagine placing every word in a city, one address per word, so that words used in similar situations end up as neighbours. "Coffee" lives near "tea" and "espresso"; "king" lives near "queen" and "monarch". Word2Vec is the algorithm that assigns those addresses by repeatedly nudging words closer to their neighbours in text and further from random strangers.

💡 If you remember one thing

Word2Vec is not one model — it's a training objective (predict context from center, or center from context) paired with a softmax approximation (negative sampling or hierarchical softmax) that makes training on millions of words tractable. The famous by-product is that vector arithmetic captures meaning: $$\vec{v}_{king} - \vec{v}_{man} + \vec{v}_{woman} \approx \vec{v}_{queen}$$

How Word2Vec Works Internally
▼

Two Mirror-Image Architectures

Skip-gram takes one center word and tries to predict each of its neighbouring context words independently: \(P(w_{context} \mid w_{center})\). CBOW (Continuous Bag-of-Words) does the reverse: it averages the context vectors and predicts the single center word: \(P(w_{center} \mid \text{avg}(w_{context}))\). Skip-gram creates more training pairs per sentence and tends to represent rare words better; CBOW trains faster and smooths over noise, favoring frequent words.

Two Embedding Matrices, Not One

Every word actually has two learned vectors: an input (center) vector \(v_w\), looked up when the word is the center, and an output (context) vector \(u_w\), used when scoring the word as a candidate context/prediction. The final embedding released to downstream users is usually just \(v_w\), or the average of both.

Why a Plain Softmax Doesn't Scale

Scoring a context word requires \(P(w_o \mid w_c) = \dfrac{\exp(u_{w_o}^\top v_{w_c})}{\sum_{w \in V}\exp(u_w^\top v_{w_c})}\). That denominator sums over the entire vocabulary — for a 1-million-word vocabulary, that's 1 million dot products per training pair. Mikolov et al. (2013) fixed this with two tricks, both covered in the walkthrough below: negative sampling, which turns the |V|-way classification into a handful of binary classifications, and hierarchical softmax, which arranges the vocabulary as a binary tree so scoring one word costs \(O(\log|V|)\) instead of \(O(|V|)\).

🔑 Design Decision: Why Two Separate Approximations?

Negative sampling is simpler, faster per-step, and empirically best for frequent words with large corpora (the setting Word2Vec was built for). Hierarchical softmax updates every internal node on a word's tree path every step, which helps rare words see more gradient signal — useful on smaller corpora. Production Word2Vec (and its descendants like fastText) default to negative sampling.

3
Why It Works — The Math
▼

The Skip-gram Objective

For a corpus of \(T\) words and window size \(m\), skip-gram maximizes the average log-probability of context words given the center word:

$$J(\theta) = \frac{1}{T}\sum_{t=1}^{T}\sum_{-m \le j \le m,\, j \ne 0} \log P(w_{t+j} \mid w_t)$$

Negative Sampling: Turning Softmax into Logistic Regression

Instead of normalizing over all of \(V\), negative sampling replaces the softmax with \(k\) binary logistic decisions: "is \(w_o\) really the context of \(w_c\)?" (label 1) vs. "is a randomly drawn \(w_i \sim P_n(w)\) the context of \(w_c\)?" (label 0, for \(i=1,\dots,k\)):

$$\log \sigma(u_{w_o}^\top v_{w_c}) + \sum_{i=1}^{k} \mathbb{E}_{w_i \sim P_n(w)}\left[\log \sigma(-u_{w_i}^\top v_{w_c})\right]$$

where \(\sigma(x)=1/(1+e^{-x})\) and the noise distribution is the unigram frequency raised to the \(3/4\) power, \(P_n(w) \propto \text{count}(w)^{3/4}\), which over-samples rare words relative to raw frequency. The gradient with respect to \(v_{w_c}\) only touches \(k+1\) output vectors instead of \(|V|\):

$$\frac{\partial J_{neg}}{\partial v_{w_c}} = (\sigma(u_{w_o}^\top v_{w_c}) - 1)\,u_{w_o} + \sum_{i=1}^{k}\sigma(u_{w_i}^\top v_{w_c})\,u_{w_i}$$

Hierarchical Softmax: Turning Softmax into a Binary Tree Walk

Build a binary tree (typically Huffman-coded by frequency) with all \(|V|\) words as leaves. Every internal node \(n\) owns its own parameter vector \(w_n\). The probability of reaching leaf word \(w\) is the product of binary sigmoid decisions along the unique root-to-leaf path \(n_1, \dots, n_L\):

$$P(w \mid w_c) = \prod_{i=1}^{L-1} \sigma\big(\,[\![ n_{i+1} = \text{right child of } n_i ]\!] \cdot w_{n_i}^\top v_{w_c}\,\big)$$

Because the tree has depth \(O(\log|V|)\), computing (and backpropagating through) this product costs \(O(\log|V|)\) instead of \(O(|V|)\), and — crucially — the probabilities across all leaves still sum exactly to 1, unlike negative sampling which only approximates the softmax.

⚠️ Common Pitfall

Negative sampling does not compute a valid probability distribution over the vocabulary — it only trains vectors so that true pairs score high and random pairs score low. Don't try to read \(P(w_o\mid w_c)\) off a negative-sampling model's raw sigmoid outputs and expect them to sum to 1 across \(V\); only hierarchical (or full) softmax gives you that guarantee.

Key Takeaways
▼

When to reach for Word2Vec-style embeddings:

  • You need fast, static word vectors for a downstream classical ML pipeline (feature engineering, similarity search, clustering)
  • You have a large monolingual corpus but limited compute — training is far cheaper than a transformer language model
  • Interpretability of the analogy structure (\(a - b + c \approx d\)) is useful for debugging or demos

When NOT to use it:

  • You need context-sensitive meaning ("bank" the river vs. the institution) — use contextual embeddings from a transformer (BERT, GPT) instead
  • Your vocabulary has heavy out-of-vocabulary risk (typos, rare morphology) — prefer subword methods like fastText or BPE-based transformer tokenizers
  • You need the model itself to reason over sequences, not just represent isolated words
💡 Lineage

One-hot encoding (no semantics) → Word2Vec / GloVe (static dense semantics) → fastText (adds subword robustness) → ELMo/BERT/GPT (contextual, one vector per token-in-context). Negative sampling itself lives on beyond NLP — it's the backbone of modern recommender-system and graph-embedding training (e.g. node2vec).

Code Trace
▼
import numpy as np
# Skip-gram with negative sampling, one training step
def sigmoid(x): return 1.0 / (1.0 + np.exp(-x))
# V: input (center) matrix, U: output (context) matrix -- both (|vocab|, dim)
def train_pair(center_idx, context_idx, neg_idxs, V, U, lr=0.05):
v_c = V[center_idx] # (dim,) center embedding
u_o = U[context_idx] # (dim,) true context vector
# positive pair: push sigmoid(u_o . v_c) toward 1
score_pos = sigmoid(np.dot(u_o, v_c))
grad_v = (score_pos - 1.0) * u_o
U[context_idx] -= lr * (score_pos - 1.0) * v_c
# negative pairs: push sigmoid(u_neg . v_c) toward 0
for neg_idx in neg_idxs:
u_neg = U[neg_idx]
score_neg = sigmoid(np.dot(u_neg, v_c))
grad_v += score_neg * u_neg
U[neg_idx] -= lr * score_neg * v_c
V[center_idx] -= lr * grad_v # one combined update to v_c
return V, U
# Hierarchical softmax: probability of one word = product of node sigmoids
def hsoftmax_prob(v_c, path_nodes, path_dirs, node_vectors):
prob = 1.0
for node, went_right in zip(path_nodes, path_dirs):
w_n = node_vectors[node]
s = sigmoid(np.dot(w_n, v_c))
prob *= s if went_right else (1.0 - s)
return prob # O(log|V|) instead of O(|V|)
