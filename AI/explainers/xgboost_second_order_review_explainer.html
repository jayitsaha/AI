XGBoost: Second-Order Gradients

Regularization · Column Subsampling · Sparsity-Aware Split Finding — Part III Classical ML (Review)
Advanced Classical ML · Boosting Must Know

The Core Idea
▼

XGBoost is a gradient-boosted tree ensemble that fits one new decision tree per round, each tree correcting the residual errors of all previous trees. What makes it special — and why it dominated Kaggle competitions from 2014 onward — is a single brilliant design choice: use second-order Taylor expansion of the loss to guide every split and leaf value.

💡 The One Insight

Ordinary gradient boosting only uses the gradient \(g_i = \partial \ell / \partial \hat{y}_i\) to decide how to correct errors. XGBoost additionally uses the Hessian \(h_i = \partial^2 \ell / \partial \hat{y}_i^2\) — the curvature of the loss — which gives it a Newton-step update instead of a first-order gradient step. The Hessian acts as a natural per-sample learning rate that down-weights uncertain predictions.

Real-world analogy: Imagine you're navigating a hilly landscape in fog and want to reach the valley. A first-order method (gradient) tells you which direction slopes downhill. A second-order method (gradient + curvature) additionally tells you how steeply the slope curves ahead — so you know whether you can take a big safe step or should be cautious near a cliff edge. XGBoost uses the curvature (Hessian) to take an optimal Newton step at every leaf.

🔑 Four Innovations
  • Second-order objective: Taylor expand loss → closed-form optimal leaf weights and split gain
  • Regularization: \(L_2\) penalty \(\lambda\) on leaf weights + \(\gamma\) per-leaf complexity penalty
  • Column subsampling: randomly subsample features per tree/level/node (like Random Forest)
  • Sparsity-aware: learn a default branch direction for missing/zero values — no imputation needed

The Mathematics
▼

Taylor Objective

At boosting round \(t\), the ensemble prediction is \(\hat{y}_i^{(t)} = \hat{y}_i^{(t-1)} + f_t(x_i)\). XGBoost approximates the per-sample loss contribution via second-order Taylor expansion around the current prediction:

$$\mathcal{L}^{(t)} \approx \sum_{i=1}^n \left[ g_i f_t(x_i) + \tfrac{1}{2} h_i f_t(x_i)^2 \right] + \Omega(f_t)$$

where \(g_i = \partial_{\hat{y}} \ell(y_i, \hat{y}_i^{(t-1)})\) and \(h_i = \partial^2_{\hat{y}} \ell(y_i, \hat{y}_i^{(t-1)})\). The regularization term is:

$$\Omega(f_t) = \gamma T + \tfrac{1}{2}\lambda \sum_{j=1}^T w_j^2$$

with \(T\) = number of leaves, \(w_j\) = leaf weight (score), \(\gamma\) = min-split-gain threshold, \(\lambda\) = L2 leaf-weight penalty.

Optimal Leaf Weight

Within a leaf \(j\) containing instance set \(I_j\), the objective becomes a simple quadratic in \(w_j\). Taking derivative and setting to zero:

$$w_j^* = -\frac{G_j}{H_j + \lambda}, \quad G_j = \sum_{i \in I_j} g_i,\quad H_j = \sum_{i \in I_j} h_i$$

Split Gain

For a candidate split partitioning leaf \(j\) into left \(L\) and right \(R\), the gain in objective (higher = better) is:

$$\text{Gain} = \frac{1}{2}\left[\frac{G_L^2}{H_L+\lambda} + \frac{G_R^2}{H_R+\lambda} - \frac{(G_L+G_R)^2}{H_L+H_R+\lambda}\right] - \gamma$$

A split is accepted only when Gain > 0. The \(-\gamma\) term ensures the gain must overcome the per-leaf complexity cost. This is the exact same formula for any differentiable loss — MSE, log-loss, or custom.

📐 Optimal Tree Score

Substituting \(w_j^*\) back gives the tree's best achievable objective value (used to compare tree structures):

$$\mathcal{L}^*_{\text{tree}} = -\frac{1}{2}\sum_{j=1}^T \frac{G_j^2}{H_j + \lambda} + \gamma T$$
⚠️ Common Misconception

The Hessian \(h_i\) is always non-negative for convex losses (squared error: \(h_i = 2\); logistic: \(h_i = \hat{p}_i(1-\hat{p}_i)\)). It cannot be zero unless \(\hat{p} \in \{0,1\}\), so the denominator \(H_j + \lambda\) is always safely positive (with \(\lambda > 0\)).

Column Subsampling

At tree construction time, XGBoost randomly samples a fraction \(\text{colsample\_bytree} \in (0,1]\) of features before evaluating splits. This decorrelates trees (à la Random Forest), reduces overfitting, and speeds up split finding significantly.

Sparsity-Aware Split Finding

Many real datasets have missing or zero values. Rather than imputing, XGBoost learns a default direction per node: during tree learning, samples with missing feature values are sent both left and right separately; whichever direction yields higher gain wins, and that direction is stored. At inference, missing values automatically follow the learned default branch.

Top Interview Questions

Q1 (Easy): Why does XGBoost use second-order gradients?
A: First-order boosting (gradient descent) uses only the slope of the loss — it picks a step direction but not an optimal step size. The Hessian gives the curvature, enabling a Newton-step update \(w^* = -G/(H+\lambda)\) that is the closed-form optimal leaf weight. This converges faster and adapts to the loss shape automatically.

Q2 (Medium): What does \(\lambda\) do in XGBoost?
A: \(\lambda\) adds an L2 penalty on each leaf weight in the objective. It appears in both the optimal weight formula \(w^* = -G/(H+\lambda)\) — shrinking leaf values toward zero — and in the split gain denominator, making splits harder to achieve. It controls model complexity similarly to ridge regression's regularization.

Q3 (Medium): What is \(\gamma\) and how does it prune trees?
A: \(\gamma\) is the minimum gain required for a split to be accepted. It appears as \(-\gamma\) in the gain formula, so a split only happens if the gain in objective exceeds \(\gamma\). Higher \(\gamma\) → fewer splits → shallower, more regularized trees. It is equivalent to post-pruning: XGBoost first grows max-depth trees then prunes splits with Gain < \(\gamma\).

Q4 (Hard): How does sparsity-aware split finding work for missing values?
A: During tree construction, for each split candidate, samples with a missing feature value are tried in both left and right branches separately. The direction that yields higher gain is recorded as the "default direction" for that node. At inference, any missing value automatically routes to that default branch. This learns optimal imputation directions for free, without any preprocessing.

Q5 (Hard): Show why \(H_j\) (Hessian sum) acts as a sample-count proxy in MSE.
A: For squared loss \(\ell = \tfrac{1}{2}(y-\hat{y})^2\), \(h_i = \partial^2 \ell / \partial \hat{y}^2 = 1\) for every sample. So \(H_j = |I_j|\). The optimal leaf weight becomes \(w^* = -G_j/(|I_j| + \lambda)\), which is the negative mean gradient (i.e., mean residual) in that leaf — exactly the tree fitted on residuals in standard GBDT. The Hessian unifies diverse losses under one formula.

🚩 Red Flags (Wrong Answers)
  • "XGBoost uses random forests" — No. It is sequential boosting, not bagging. Column subsampling is an option, not the core algorithm.
  • "The Hessian is always 1" — Only for MSE. For log-loss, \(h_i = \hat{p}(1-\hat{p})\) which varies per sample.
  • "Missing values are imputed to 0 or mean" — No. The default direction is learned during training.

Key Takeaways
▼
  • Taylor objective: approximate \(\mathcal{L}^{(t)}\) using \(g_i\) (gradient) and \(h_i\) (Hessian) per sample.
  • Optimal leaf weight: \(w_j^* = -G_j/(H_j+\lambda)\) — Newton step, shrunk by \(\lambda\).
  • Split gain formula: \(\tfrac{1}{2}\left[\tfrac{G_L^2}{H_L+\lambda}+\tfrac{G_R^2}{H_R+\lambda}-\tfrac{(G_L+G_R)^2}{H_L+H_R+\lambda}\right]-\gamma\)
  • Column subsampling decorrelates trees and speeds up training without hurting accuracy (often improves it).
  • Sparsity-aware: default direction is learned, not imputed — critical for real-world sparse/missing data.
💡 The Unified View

The split gain formula, optimal weight, and tree score are all derived from a single quadratic approximation to the loss. Change the loss function (swap MSE → log-loss → any custom loss), re-compute \(g_i\) and \(h_i\) — everything else stays identical. This is what makes XGBoost a general-purpose boosting framework.
