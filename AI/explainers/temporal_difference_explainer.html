Understanding Temporal Difference (TD) Learning
▼

What is it? Temporal Difference (TD) learning is a core concept in Reinforcement Learning. It's a method for estimating the value function \(V(s)\) (the expected total future reward from a state \(s\)) without needing a model of the environment's dynamics, and without waiting until the end of an episode (unlike Monte Carlo methods). TD learning "bootstraps" — it updates its estimate for a state \(S_t\) based on the reward received \(R_{t+1}\) and its *own current estimate* of the value of the next state \(V(S_{t+1})\).

Analogy: Imagine you're trying to predict your commute time. A Monte Carlo approach would be to wait until you arrive at work, record the total time, and update your prediction for the starting point. A TD approach would be to drive for a few minutes, note how long that segment took, then look at your current location and *your existing prediction* for how long the rest of the trip from there will take. You then update your original starting point prediction based on the actual segment time PLUS your prediction for the rest of the journey.

💡 If you remember one thing

TD learning blends Monte Carlo (learning from actual outcomes) with Dynamic Programming (learning from other learned values). Its most basic form, TD(0), updates a state's value \(V(S_t)\) using a "TD target" that combines the immediate reward \(R_{t+1}\) and the discounted value of the next state \(V(S_{t+1})\):
$$\Delta V(S_t) = \alpha [R_{t+1} + \gamma V(S_{t+1}) - V(S_t)]$$

How It Works Internally
▼

TD(0): The Simplest Update

The core of TD(0) is the TD error, \(\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\). This measures the difference between the current estimate \(V(S_t)\) and a "better" bootstrapped estimate, \(R_{t+1} + \gamma V(S_{t+1})\). The update rule is simply to move \(V(S_t)\) a fraction \(\alpha\) (learning rate) of the way towards this target:

$$V(S_t) \leftarrow V(S_t) + \alpha \delta_t$$

This update happens after every single step \(S_t \to S_{t+1}\) and \(R_{t+1}\). If \(S_{t+1}\) is a terminal state, \(V(S_{t+1})\) is taken to be 0.

TD(λ): Blending N-Step Returns with Eligibility Traces

TD(0) looks one step ahead. Monte Carlo looks all the way to the end of the episode. TD(λ) generalizes this by looking anywhere in between. It combines multiple "n-step returns," where an n-step return includes \(n\) actual rewards and then bootstraps from \(V(S_{t+n})\). The parameter \(\lambda \in [0,1]\) controls the blend:

  • If \(\lambda = 0\), it's pure TD(0) (one-step lookahead).
  • If \(\lambda = 1\), it's closer to Monte Carlo (full lookahead, but still bootstrapping from \(V(S_{t+n})\) if the episode ends early).

To implement this efficiently, TD(λ) uses eligibility traces, denoted \(E(s)\). An eligibility trace for a state \(s\) is a temporary numerical record of how recently and frequently that state has been visited. When a TD error \(\delta_t\) occurs, it's not just used to update \(V(S_t)\); it's propagated back to *all* states \(s\) in proportion to their eligibility trace \(E_t(s)\) at that moment. Traces decay over time by \(\gamma \lambda\).

Design Decision: Why TD vs. Monte Carlo?

Monte Carlo methods require waiting until an entire episode finishes to calculate the total return. This can be slow or impossible in continuing tasks. TD learning, being an online method, can learn from partial episodes and has lower variance in its updates because \(V(S_{t+1})\) is usually a less noisy estimate than a full Monte Carlo return. However, Monte Carlo is unbiased, while TD introduces bias by bootstrapping from potentially inaccurate value estimates.

🔑 Key Property

Eligibility traces provide a way to assign credit (or blame) for a TD error \(\delta_t\) to past states. When \(\delta_t\) occurs, all states \(s\) get updated by \(\alpha \delta_t E_t(s)\). The trace \(E_t(s)\) acts as a memory, decaying by \(\gamma \lambda\) at each step, ensuring more recent and relevant states are updated more strongly.

Why It Works — The Math
▼

TD(0) Update Derivation

TD(0) can be seen as performing a kind of stochastic gradient descent on the mean squared error between the estimated value function and the true value function. The objective is to minimize the squared TD error:

$$L(V) = \mathbb{E}[(R_{t+1} + \gamma V(S_{t+1}) - V(S_t))^2]$$

Taking the derivative with respect to \(V(S_t)\) (and ignoring the expectation for a single sample update):

$$\frac{\partial L}{\partial V(S_t)} = 2 (R_{t+1} + \gamma V(S_{t+1}) - V(S_t)) \cdot (-1)$$

So, a gradient descent step \(V(S_t) \leftarrow V(S_t) - \alpha \frac{\partial L}{\partial V(S_t)}\) becomes:

$$V(S_t) \leftarrow V(S_t) + \alpha (R_{t+1} + \gamma V(S_{t+1}) - V(S_t))$$

This is precisely the TD(0) update rule, where \(\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\) is the TD error.

Eligibility Traces and TD(λ) Updates

For TD(λ), we track an eligibility trace \(E_t(s)\) for each state \(s\). When a state \(S_t\) is visited, its trace is incremented, and all traces decay by \(\gamma \lambda\):

$$E_t(s) = \gamma \lambda E_{t-1}(s) + \mathbb{1}(S_t=s)$$

Here, \(\mathbb{1}(S_t=s)\) is 1 if \(S_t=s\) and 0 otherwise. The TD error \(\delta_t\) is still calculated as in TD(0). However, this error is then used to update *all* states \(s\) in the environment, weighted by their current eligibility trace:

$$V(s) \leftarrow V(s) + \alpha \delta_t E_t(s) \quad \text{for all } s$$

This effectively propagates the single-step TD error back along the path taken, with states further back receiving a smaller update due to the decay factor \(\gamma \lambda\). This combines the low variance of TD(0) with the ability to learn from multi-step returns, much like Monte Carlo methods.

⚠️ Common Pitfall

Choosing \(\lambda\) is crucial. A \(\lambda\) near 0 means updates are very local (TD(0)-like), relying heavily on immediate bootstrapping. A \(\lambda\) near 1 means updates extend far back in time (Monte Carlo-like), propagating errors over many steps. While TD(λ) converges to \(V^\pi\) for any \(\lambda \in [0,1]\) in tabular settings, the optimal \(\lambda\) for fastest learning depends on the specific task and how rewards are structured.

Key Takeaways
▼

When to use TD learning:

  • Online learning: TD methods can learn from every single experience step, without waiting for episode completion. This is critical for continuous tasks or tasks with very long episodes.
  • Model-free control: Like Monte Carlo, TD does not require a model of the environment's dynamics (transition probabilities and rewards).
  • Lower variance updates: By bootstrapping from an already learned value function, TD updates often have lower variance than Monte Carlo updates, which rely on potentially noisy full returns.
  • Credit assignment: Eligibility traces (in TD(λ)) provide an elegant way to distribute a single TD error back to multiple preceding states, balancing between immediate (TD(0)) and long-term (Monte Carlo-like) credit assignment.

When to be cautious or use alternatives:

  • Bias: Bootstrapping introduces bias, as the target itself is an estimate. If the value function is inaccurate, this bias can propagate. Monte Carlo methods are unbiased.
  • Function approximation: In large state spaces, tabular TD methods are impractical. Combining TD with function approximation (e.g., neural networks) introduces its own set of challenges, particularly with off-policy learning.
  • Exploration vs. Exploitation: As with all RL algorithms, balancing exploration (finding new paths) and exploitation (using known good paths) is crucial and not directly handled by TD updates alone.
💡 Hierarchy

TD(0) is the fundamental one-step TD algorithm. TD(λ) is a generalization that smoothly interpolates between TD(0) (\(\lambda=0\)) and Monte Carlo-like updates (\(\lambda=1\)) by using eligibility traces. All are model-free methods that learn value functions, forming the backbone of many advanced RL algorithms like Q-learning and SARSA.

Code Trace (Python-like Pseudocode)
▼
import numpy as np
# Initialize value function V(s) and eligibility traces E(s)
V = np.zeros(num_states)
E = np.zeros(num_states)
# Hyperparameters
alpha = 0.1 # Learning rate
gamma = 0.99 # Discount factor
lambda_ = 0.8 # Trace decay parameter
# For each episode:
E.fill(0) # Reset eligibility traces at start of episode
state = env.reset() # Get initial state S_0
while not env.is_terminal(state):
action = policy(state) # Choose action A_t based on policy
next_state, reward, done = env.step(action) # Take action, get R_{t+1}, S_{t+1}
# Calculate TD Error (delta_t)
td_target = reward + gamma * V[next_state] * (1 - done) # V[terminal]=0
td_error = td_target - V[state]
# Update eligibility trace for current state
E[state] += 1
# Update value function for all states and decay traces
for s in range(num_states):
V[s] += alpha * td_error * E[s]
E[s] *= gamma * lambda_ # Decay trace
state = next_state
# After episode, V contains updated value estimates
