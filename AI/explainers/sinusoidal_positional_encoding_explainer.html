Giving order to an attention mechanism that otherwise can't tell "dog bites man" from "man bites dog"
Foundational Transformers NLP O(1) per position — no training
1
Understanding Sinusoidal Positional Encoding
▼

What is it? Self-attention looks at a whole sentence at once and computes a weighted average over all the other tokens. That averaging operation doesn't care about order — feed it "the cat sat" or "sat the cat" and, without extra help, it produces the exact same output for each token. Sinusoidal positional encoding fixes this by adding a unique vector to every token's embedding that encodes where it sits in the sequence, built entirely out of sine and cosine waves of different frequencies.

Analogy: Picture a clock with many hands, each spinning at its own speed — one hand sweeps around every 6 steps, another takes 20, another takes thousands. Reading the position of every hand together gives each moment in time a unique "fingerprint," and because two clock readings taken \(k\) ticks apart are related by a fixed rotation, comparing two fingerprints tells you their distance without ever reading a clock face out loud as a number.

One-sentence summary: Sinusoidal positional encoding stamps each sequence position with a fixed vector of sine/cosine values at geometrically spaced frequencies, added directly to the token embedding before it enters the first attention layer.

💡 If you remember one thing

$$PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d}}\right) \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d}}\right)$$ Even dimensions get a sine, odd dimensions get a cosine of the same angle — that pairing is what makes relative positions linearly computable later.

How It Works Internally
▼

Where it sits in the architecture

Right after the token embedding lookup, and before the first encoder/decoder block, the positional encoding vector \(PE_{pos} \in \mathbb{R}^d\) is added elementwise (not concatenated) to the token embedding: \(z_{pos} = \text{Embed}(x_{pos}) + PE_{pos}\). Because it's a sum, the model must learn to "read off" position from the same coordinates it uses for word meaning — this works because \(PE\) values are bounded in \([-1,1]\) and occupy a structured, low-dimensional manifold the network can linearly separate out.

Constructing the frequencies

For each dimension pair \((2i, 2i+1)\), define an angular frequency \(\omega_i = 1/10000^{2i/d}\). The wavelength of that pair is \(2\pi/\omega_i = 2\pi \cdot 10000^{2i/d}\), which grows geometrically from \(2\pi \approx 6.3\) steps (at \(i=0\)) up to roughly \(10000 \cdot 2\pi \approx 62{,}832\) steps (at \(i = d/2 - 1\)). Low-\(i\) dimensions oscillate fast and encode fine-grained local position; high-\(i\) dimensions barely move across any realistic sequence and act like a slow-varying, almost-constant offset — together they form a multi-resolution code, exactly like the many-handed clock.

Numerical trace (\(d=16\), position 3, pair \(i=2\))

\(\omega_2 = 1/10000^{4/16} = 1/10000^{0.25} = 1/10 = 0.1\). Angle \(=\; pos \cdot \omega_2 = 3 \times 0.1 = 0.3\) rad. So \(PE_{(3,4)} = \sin(0.3) = 0.2955\) and \(PE_{(3,5)} = \cos(0.3) = 0.9553\). Every other position, dimension pair follows the identical recipe — nothing is learned, nothing is randomly initialized.

🔑 Design decision: why sine/cosine and not just the raw integer position?

Feeding raw \(pos\) (0, 1, 2, …) directly would produce unbounded values that swamp the embedding and generalize terribly to unseen lengths. Sinusoids stay in \([-1,1]\) for any position, are defined at sequence lengths never seen during training (pure extrapolation), and — critically — the sin/cos pairing turns "shift by \(k\) positions" into an exact 2D rotation, a linear operation a single attention head can learn to exploit.

3
Why It Works — The Math
▼

The relative-position property

Fix a dimension pair \(i\) with frequency \(\omega_i\), and let \(\theta = pos \cdot \omega_i\), \(\phi = k \cdot \omega_i\). The angle-sum identities give:

$$\sin(\theta+\phi)=\sin\theta\cos\phi+\cos\theta\sin\phi \qquad \cos(\theta+\phi)=\cos\theta\cos\phi-\sin\theta\sin\phi$$

Written as a 2×2 matrix acting on the pair \([\sin\theta,\ \cos\theta]^\top\):

$$\begin{bmatrix}\sin(\theta+\phi)\\ \cos(\theta+\phi)\end{bmatrix} = \underbrace{\begin{bmatrix}\cos\phi & \sin\phi\\ -\sin\phi & \cos\phi\end{bmatrix}}_{R(\phi)\ \text{(rotation matrix)}} \begin{bmatrix}\sin\theta\\ \cos\theta\end{bmatrix}$$

So \(PE_{pos+k}\) is a fixed linear (rotation) transform of \(PE_{pos}\) — the matrix \(R(\phi)\) depends only on the offset \(k\), never on the absolute position \(pos\). This is the property that lets a learned linear projection inside attention (query/key weight matrices) compute relative offsets, even though \(PE\) itself is a fixed, non-trainable table.

Proof sketch that it's a genuine rotation

\(R(\phi)\) has determinant \(\cos^2\phi+\sin^2\phi=1\) and \(R(\phi)^\top R(\phi)=I\), so it's an orthogonal, orientation-preserving map — literally a 2D rotation by angle \(\phi\) around the origin. Rotations compose: \(R(\phi_1)R(\phi_2)=R(\phi_1+\phi_2)\), matching the intuition that shifting by \(k_1\) then \(k_2\) positions is the same as shifting by \(k_1+k_2\).

Similarity decays (roughly) with distance

The dot product \(PE_{pos}\cdot PE_{pos+k}=\sum_i \big(\sin\theta_i\sin(\theta_i{+}k\omega_i)+\cos\theta_i\cos(\theta_i{+}k\omega_i)\big)=\sum_i \cos(k\,\omega_i)\) depends only on \(k\), not on \(pos\) — and because it's a sum of cosines at geometrically spaced frequencies, it behaves like a damped, quasi-periodic function of \(|k|\), giving the model an implicit (not strictly monotonic) sense of "nearby vs. far away."

⚠️ Common misconception

Positional encoding does not tell the network "this is token #7" as a decodable label. \(PE\) is never inverted back to an integer. What matters is purely the geometric relationship between two encodings — the rotation structure — which downstream linear layers can exploit to reason about relative offsets.

Key Takeaways
▼

When it's the right tool:

  • You want zero extra trainable parameters for position
  • You need the model to (at least partially) generalize to sequence lengths longer than any seen in training
  • You want a deterministic, reproducible position signal (useful for analysis/debugging)

When something else wins:

  • Learned absolute position embeddings (BERT, GPT-2) are simpler to implement and, with enough data, match or beat sinusoidal PE within the trained length range — but cannot extrapolate past the max trained position at all.
  • Relative position biases (T5, ALiBi) and RoPE (rotary position embedding, used in LLaMA/GPT-NeoX/Qwen) bake the relative-offset rotation directly into the attention dot product instead of adding a vector to the embedding — empirically more robust for long-context and length extrapolation.
💡 The throughline to modern LLMs

RoPE is the sinusoidal idea taken to its logical conclusion: instead of adding \(\sin/\cos\) vectors to the embedding, it directly rotates the query and key vectors by the same position-dependent angle before the dot product. The 2017 rotation-matrix identity you just derived is exactly the mechanism RoPE exploits — sinusoidal PE and RoPE are two implementations of one underlying geometric insight.

import numpy as np
def sinusoidal_positional_encoding(n_pos, d_model, base=10000):
"Build the (n_pos, d_model) PE matrix from the original Transformer."
pe = np.zeros((n_pos, d_model))
position = np.arange(n_pos)[:, None] # shape (n_pos, 1)
i = np.arange(0, d_model, 2) # 0, 2, 4, ... (pair index * 2)
div_term = 1.0 / (base ** (i / d_model)) # omega_i for each pair
angles = position * div_term # shape (n_pos, d_model/2)
pe[:, 0::2] = np.sin(angles) # even dims: sine
pe[:, 1::2] = np.cos(angles) # odd dims: cosine
return pe
PE = sinusoidal_positional_encoding(n_pos=48, d_model=16)
print(PE[3, 4], PE[3, 5]) # -> 0.2955 0.9553 (matches worked example)
# Relative-position property: PE[pos+k] recoverable via a fixed rotation of PE[pos]
def rotation_matrix(k, i_pair, d_model, base=10000):
phi = k / (base ** (2 * i_pair / d_model))
return np.array([[np.cos(phi), np.sin(phi)], [-np.sin(phi), np.cos(phi)]])
