Understanding Newton's Method
▼

What is it? Gradient descent moves downhill one step at a time, ignoring the shape of the terrain. Newton's method is smarter: it fits a bowl-shaped (quadratic) model to the function at your current location, then jumps directly to the bottom of that bowl. On a pure quadratic, it reaches the minimum in exactly one step, regardless of starting point.

Analogy: Imagine you're lost in a hilly landscape at night. Gradient descent says "walk downhill." Newton's method says "measure the slope AND the curvature of the hill in every direction, build a precise map of the local terrain, and leap to the predicted lowest point." On gentle rolling hills the map is accurate and you land exactly at the bottom. On jagged cliffs the local map can be wrong — and Newton's method can fail.

The Hessian is the matrix of second derivatives — the \(n \times n\) table of "how curved is \(f\) in every pair of directions?" It encodes local curvature exactly as the gradient encodes local slope. The Newton step is \(\mathbf{d} = -H^{-1}\nabla f\), a gradient rescaled by the inverse curvature.

If you remember one thing

Newton's method replaces the gradient step \(-\alpha \nabla f\) with \(-H^{-1}\nabla f\). The Hessian \(H\) corrects for elongated loss surfaces, turning zig-zagging into a straight shot. The cost is O(n²) storage and O(n³) solve — catastrophic for neural networks with millions of parameters.

2
How Newton's Method Works Internally
▼

The Local Quadratic Model

At the current iterate \(\mathbf{x}_k\), Taylor-expand \(f\) to second order:

$$f(\mathbf{x}_k + \mathbf{d}) \approx f(\mathbf{x}_k) + \nabla f(\mathbf{x}_k)^\top \mathbf{d} + \tfrac{1}{2}\mathbf{d}^\top H(\mathbf{x}_k)\,\mathbf{d} \quad =: m_k(\mathbf{d})$$

This quadratic model \(m_k\) is exact for quadratic functions and a good local approximation for smooth \(f\). Newton's method minimizes \(m_k\) exactly — set its gradient to zero:

$$\nabla_d\, m_k = \nabla f + H\mathbf{d} = 0 \quad\Longrightarrow\quad \mathbf{d}^* = -H^{-1}\nabla f$$

The next iterate is \(\mathbf{x}_{k+1} = \mathbf{x}_k - H^{-1}\nabla f(\mathbf{x}_k)\).

The Hessian as Local Curvature

The Hessian \(H_{ij} = \frac{\partial^2 f}{\partial x_i \partial x_j}\) measures how steeply the slope changes in direction \(j\) as you move in direction \(i\). On an elongated bowl like \(f = x^2 + 10y^2\), the Hessian is \(\text{diag}(2, 20)\). The \(y\) direction is 10× more curved — gradient descent with a fixed step must be tiny to avoid overshooting in \(y\), causing the famous zig-zag. Newton's step scales each direction by the reciprocal curvature: \(d_x = -g_x/2\), \(d_y = -g_y/20\), landing precisely at the minimum.

Key Property: Affine Invariance

Newton's method is affine-invariant: it takes the same number of steps on \(f(\mathbf{x})\) and on \(f(A\mathbf{x})\) for any invertible \(A\). Gradient descent is not; it is sensitive to the conditioning of \(H\) — high condition number causes slow convergence and zig-zagging.

Quadratic Convergence

Near a strict local minimum \(\mathbf{x}^*\), Newton's method converges quadratically: \(\|\mathbf{x}_{k+1} - \mathbf{x}^*\| \leq C\|\mathbf{x}_k - \mathbf{x}^*\|^2\). In practice, errors square at each step: if you're 0.1 away, the next step is ≈0.01, then ≈0.0001. That is, digit-doubling convergence — typically 5–10 iterations from a reasonable start.

Warning: Region of Convergence

Quadratic convergence only holds near the minimum. Far away, the quadratic model may be inaccurate and Newton's method can diverge. In practice this is fixed with damped Newton (line search on the Newton direction) or trust-region methods that limit the step size.

3
Why It Works — The Math
▼

Derivation from the Quadratic Model

For a twice-differentiable \(f:\mathbb{R}^n \to \mathbb{R}\), the second-order Taylor expansion around \(\mathbf{x}_k\) is:

$$m_k(\mathbf{d}) = f(\mathbf{x}_k) + \mathbf{g}_k^\top \mathbf{d} + \tfrac{1}{2}\mathbf{d}^\top H_k \mathbf{d}$$

where \(\mathbf{g}_k = \nabla f(\mathbf{x}_k)\) and \(H_k = \nabla^2 f(\mathbf{x}_k)\). Differentiating w.r.t. \(\mathbf{d}\) and setting to zero:

$$\frac{\partial m_k}{\partial \mathbf{d}} = \mathbf{g}_k + H_k \mathbf{d} = \mathbf{0} \implies \mathbf{d}^* = -H_k^{-1}\mathbf{g}_k$$

This is valid only if \(H_k \succ 0\) (positive definite). If \(H_k\) has negative eigenvalues, \(m_k\) is not bounded below — the pure Newton step may ascend. The fix is to use \(H_k + \lambda I\) (Levenberg-Marquardt regularization) or projected-gradient methods.

Quadratic Convergence — Proof Sketch

Let \(\mathbf{e}_k = \mathbf{x}_k - \mathbf{x}^*\). At the optimum, \(\nabla f(\mathbf{x}^*) = 0\), so by Taylor:

$$\nabla f(\mathbf{x}_k) = H(\mathbf{x}^*)\mathbf{e}_k + O(\|\mathbf{e}_k\|^2)$$

The Newton update gives:

$$\mathbf{e}_{k+1} = \mathbf{x}_{k+1} - \mathbf{x}^* = \mathbf{e}_k - H_k^{-1}\nabla f(\mathbf{x}_k) = O(\|\mathbf{e}_k\|^2)$$

The quadratic term in the Taylor expansion of \(\nabla f\) (evaluated at \(\mathbf{x}_k\), not \(\mathbf{x}^*\)) is what drives quadratic convergence — the error at step \(k+1\) is proportional to the square of the error at step \(k\).

O(n²) and O(n³) Costs

For \(n\) parameters, the Hessian is an \(n \times n\) matrix requiring \(O(n^2)\) storage and \(O(n^2)\) operations to compute (via second-order backprop or finite differences). Solving the Newton system \(H\mathbf{d} = -\mathbf{g}\) via Cholesky factorization costs \(O(n^3)\). For a neural network with \(n = 10^8\) parameters, storing the Hessian alone requires \(10^{16}\) floats — roughly 80 petabytes. This is the fundamental barrier to using exact Newton's method in deep learning.

Scaling Costs at a Glance

Gradient: \(O(n)\) compute, \(O(n)\) storage
Hessian: \(O(n^2)\) compute, \(O(n^2)\) storage
Newton solve: \(O(n^3)\) via Cholesky
For \(n=10^6\): Hessian = \(4\text{ TB}\), solve ≈ intractable
For \(n=10^8\) (ResNet-50): \(4 \times 10^{16}\) bytes — physically impossible

Key Takeaways & Practical Implications
▼

When Newton's Method Is Used

  • Small-scale optimization (n ≤ ~10,000): scipy.optimize, R's optim — exact Newton feasible
  • Logistic/linear regression: Iteratively Reweighted Least Squares (IRLS) is Newton's method on the log-likelihood
  • Physics simulations & robotics: Newton-Raphson for solving nonlinear equations
  • Quasi-Newton methods (L-BFGS): Approximate \(H^{-1}\) with low-rank updates — used in many classical ML packages

Why Deep Learning Uses SGD/Adam Instead

  • O(n²) storage is infeasible: GPT-3 has 175B params → Hessian would be 245 zettabytes
  • O(n³) solve: Even if stored, factorization would take geological time
  • Stochastic gradients: Mini-batch loss has noisy Hessians — exact Newton on noise is counterproductive
  • Non-convexity: Deep nets have saddle points; Newton can move towards them (negative curvature)
The Bridge: Quasi-Newton and K-FAC

L-BFGS approximates \(H^{-1}\) using the last \(m\) gradient differences — only \(O(mn)\) storage. K-FAC (Kronecker-Factored Approximate Curvature) approximates the Fisher information matrix using Kronecker products, making second-order optimization tractable for moderate-sized networks. These are the bridges between Newton's theory and practical deep learning.

Code Trace — Newton vs Gradient Descent
▼

Exact Newton on \(f(x,y)=x^2+10y^2\) reaches the minimum in 1 step. Gradient descent (α=0.09) zig-zags for 20+ iterations.

import numpy as np
# Elongated bowl: f(x,y) = x^2 + 10*y^2
def f(x): return x[0]**2 + 10*x[1]**2
def grad_f(x): return np.array([2*x[0], 20*x[1]])
def hessian_f(): return np.array([[2., 0.], [0., 20.]]) # constant for quadratic
x0 = np.array([3.0, 1.5]) # starting point
H = hessian_f() # [[2, 0], [0, 20]]
g = grad_f(x0) # [6, 30]
# === NEWTON'S METHOD ===
d_newton = -np.linalg.solve(H, g) # solve Hd = -g => d = [-3, -1.5]
x1_newton = x0 + d_newton # [0, 0] — exact minimum in ONE step!
print(f"Newton step 1: {x1_newton}, f = {f(x1_newton):.6f}") # f = 0.000000
# === GRADIENT DESCENT (lr=0.09) ===
alpha = 0.09
x_gd = x0.copy()
for step in range(20):
x_gd -= alpha * grad_f(x_gd) # zig-zags in y direction
if step < 5:
print(f"GD step {step+1}: ({x_gd[0]:.3f}, {x_gd[1]:.3f}), f = {f(x_gd):.4f}")
# GD step 1: (2.460, -1.200), f = 20.4516
# GD step 2: (2.017, 0.960), f = 13.2851 ← flips sign!
# GD step 3: (1.654, -0.768), f = 8.6343 ← still zig-zagging
# === PRODUCTION: scipy ===
from scipy.optimize import minimize
res = minimize(f, x0, method='Newton-CG', jac=grad_f,
options={'xtol': 1e-8, 'disp': True})
print(res.x) # [~0, ~0]
# For ML: use L-BFGS (approximate inverse Hessian)
res_bfgs = minimize(f, x0, method='L-BFGS-B', jac=grad_f)
print(res_bfgs.x) # very fast, no full Hessian needed
