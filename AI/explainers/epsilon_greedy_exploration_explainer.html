Epsilon-Greedy Exploration

Balancing exploration and exploitation in Multi-Armed Bandits
Foundational Reinforcement Learning O(K) per step
1
Understanding Epsilon-Greedy
▼

What is it? Epsilon-greedy is a simple yet effective strategy for solving the "exploration-exploitation dilemma," most famously in Multi-Armed Bandit (MAB) problems. At each step, with a small probability \(\epsilon\) (epsilon), the agent chooses a random action (exploration). With probability \(1-\epsilon\), it chooses the action that currently has the highest estimated value (exploitation).

Analogy: Imagine you're at a new restaurant with 5 dishes on the menu. You want to find your favorite. Pure exploitation means you pick the dish you *think* is best after your first bite, and never try anything else. Pure exploration means you randomly pick a dish every time, never settling on a favorite. Epsilon-greedy says: "Most of the time (e.g., 90%), I'll order what I think is my favorite. But 10% of the time, I'll randomly try something new to see if there's an even better option I haven't discovered yet."

💡 If you remember one thing

Epsilon-greedy ensures that every action is tried infinitely often in the limit, preventing the agent from getting stuck on suboptimal choices forever. The parameter \(\epsilon\) directly controls the trade-off: higher \(\epsilon\) means more exploration, lower \(\epsilon\) means more exploitation.

How It Works Internally
▼

The Multi-Armed Bandit Problem

In a MAB problem, an agent faces \(K\) "arms" (actions). Each arm \(a\) provides a reward drawn from an unknown probability distribution with a true mean value \(Q^*(a)\). The goal is to maximize the total reward over a sequence of pulls.

The agent maintains an estimate \(Q_t(a)\) for the true value of each arm \(a\) at time step \(t\), usually by taking the sample average of rewards received so far for that arm. It also keeps track of how many times each arm \(N_t(a)\) has been pulled.

The Epsilon-Greedy Algorithm

At each time step \(t\):

  1. Generate a random number between 0 and 1.
  2. If this number is less than \(\epsilon\):
    • Choose an action \(a\) uniformly at random from all \(K\) available actions (exploration).
  3. Else (with probability \(1-\epsilon\)):
    • Choose the action \(a^* = \arg\max_{a'} Q_t(a')\), i.e., the arm with the highest current estimated value (exploitation). Ties are broken arbitrarily.
  4. Pull the chosen arm \(a\), observe the reward \(r\).
  5. Update the count \(N_t(a) \leftarrow N_t(a) + 1\).
  6. Update the estimated value \(Q_t(a)\) using the new reward \(r\). The common way is an incremental average: \(Q_{new}(a) = Q_{old}(a) + \frac{1}{N_t(a)}(r - Q_{old}(a))\).

Design Decision: Fixed vs. Decaying Epsilon

A fixed \(\epsilon\) ensures continued exploration, which is good for non-stationary environments where optimal actions might change. However, in stationary environments (like classic MAB), it means the agent will always explore even when it has a very good estimate of the optimal action, leading to suboptimal long-term reward. Often, \(\epsilon\) is decayed over time (e.g., linearly or exponentially) to favor exploration early on and exploitation later, allowing the policy to converge to the optimal action.

🔑 Key Property

The exploration probability \(\epsilon\) is applied to the *entire* set of actions, not just the non-greedy ones. This means that even the greedy action has a small chance of being picked as part of the \(\epsilon\)-fraction of random choices.

3
Why It Works — The Math
▼

Action-Value Estimation

The most common way to estimate the value of an action is the sample-average method. If action \(a\) has been chosen \(N_t(a)\) times up to time \(t\), yielding rewards \(r_1, r_2, \dots, r_{N_t(a)}\), its estimated value is:

$$Q_t(a) = \frac{\sum_{i=1}^{N_t(a)} r_i}{N_t(a)}$$

This can be updated incrementally without storing all past rewards. When a new reward \(r\) is observed for action \(a\) at step \(k\), the new estimate \(Q_{k+1}(a)\) is:

$$Q_{k+1}(a) = Q_k(a) + \frac{1}{N_k(a)}(r - Q_k(a))$$

This formula is efficient and keeps the estimate as a true average.

Probability of Choosing an Action

Let \(A_t\) be the action chosen at time \(t\), and \(K\) be the total number of actions. Let \(a^*\) be the greedy action (the one with the highest estimated value). The probability of choosing any action \(a\) under an \(\epsilon\)-greedy policy is:

$$P(A_t = a) = \begin{cases} \frac{\epsilon}{K} + (1-\epsilon) & \text{if } a = \arg\max_{a'} Q_t(a') \\ \frac{\epsilon}{K} & \text{if } a \neq \arg\max_{a'} Q_t(a') \end{cases}$$

This shows that the greedy action gets the largest share of probability \(1-\epsilon\) plus its share of the random exploration, while all other actions get an equal (small) share of \(\epsilon/K\).

⚠️ Common Pitfall

Epsilon-greedy can be slow to converge to the optimal policy if the rewards are very noisy or if the suboptimal actions have values very close to the optimal one. It also doesn't prioritize "promising" but unproven actions; it treats all non-greedy actions equally during exploration. More sophisticated methods like UCB (Upper Confidence Bound) address this by favoring actions with high uncertainty.

Key Takeaways
▼

When to use Epsilon-Greedy:

  • As a simple, robust baseline for reinforcement learning problems, especially in Multi-Armed Bandits.
  • When computational resources are limited, as it's very efficient per step.
  • In stationary environments, often with a decaying \(\epsilon\) schedule.
  • In non-stationary environments, with a fixed (small) \(\epsilon\) to adapt to changes.

When NOT to use / Alternatives:

  • In problems with very sparse or delayed rewards, where initial estimates are unreliable for a long time.
  • When more intelligent exploration is needed, e.g., prioritizing actions that are uncertain but potentially high-value (see UCB).
  • In very high-dimensional action spaces, where random exploration (\(\epsilon\)-greedy) becomes impractical (too many actions to sufficiently explore).
  • When safety is critical, as random exploration might lead to very bad outcomes.
💡 Big Picture

Epsilon-greedy is the fundamental building block of exploration strategies. While simple, it illustrates the core trade-off and provides a solid foundation before moving to more advanced techniques like Upper Confidence Bound (UCB), Thompson Sampling, or strategies based on intrinsic motivation.

Code Trace (Python-like Pseudocode)
▼
import numpy as np
class EpsilonGreedyAgent:
def __init__(self, num_arms, epsilon):
self.num_arms = num_arms
self.epsilon = epsilon
self.q_estimates = np.zeros(num_arms) # Estimated value for each arm
self.n_pulls = np.zeros(num_arms) # Number of times each arm pulled
def choose_action(self):
if np.random.rand() < self.epsilon:
action = np.random.randint(self.num_arms) # Explore: choose randomly
self.last_choice_type = "explore"
else:
action = np.argmax(self.q_estimates) # Exploit: choose best current estimate
self.last_choice_type = "exploit"
return action
def update_estimates(self, action, reward):
self.n_pulls[action] += 1
alpha = 1.0 / self.n_pulls[action] # Learning rate (1/N for sample average)
self.q_estimates[action] += alpha * (reward - self.q_estimates[action])
