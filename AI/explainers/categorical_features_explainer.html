Understanding Categorical Features & Encodings
▼

What are categorical features? Categorical features represent types or groups of data, rather than numerical quantities. Examples include "City" (New York, London, Paris), "Product Category" (Electronics, Clothing, Books), or "Day of Week" (Monday, Tuesday, ...). They can be:

  • Nominal: No inherent order (e.g., City, Product Category).
  • Ordinal: Have a meaningful order (e.g., 'Small', 'Medium', 'Large' or 'Good', 'Better', 'Best').

Why encode them? Most machine learning algorithms (linear models, tree-based models, neural networks) operate on numerical input. They cannot directly process text labels like "New York" or "Electronics". Encoding converts these categories into a numerical format that models can understand.

The challenge: The choice of encoding significantly impacts model performance. A poor encoding can introduce spurious relationships (e.g., implying an order where none exists) or lose valuable information, leading to suboptimal models. For example, treating "Red" as 1, "Green" as 2, and "Blue" as 3 implies that Green is "between" Red and Blue, and that the difference between Red and Green is the same as between Green and Blue — which is usually false for nominal categories.

💡 If you remember one thing

Categorical encoding is the process of translating non-numerical labels into numerical values. The goal is to represent the categories in a way that allows the machine learning model to effectively learn from them, without introducing misleading relationships or losing critical information about their distinctness or relationships to the target variable.

2
How Different Encodings Work
▼

Basic Encodings

  • Label Encoding: Assigns a unique integer to each category (e.g., New York=0, London=1, Paris=2). Simple, but implies an arbitrary ordinal relationship which can confuse models if the feature is nominal.
  • Ordinal Encoding: Similar to Label Encoding, but the integers are assigned based on a predefined, meaningful order (e.g., Small=0, Medium=1, Large=2). Appropriate for ordinal features.
  • One-Hot Encoding: Creates a new binary column for each unique category. For a given observation, the column corresponding to its category gets a 1, and all others get 0. This avoids implying order but can lead to high dimensionality ("curse of dimensionality") for features with many unique categories (high cardinality).
  • Binary Encoding: A compromise for high cardinality. It first maps each category to an integer, then converts these integers into binary code. Each bit position in the binary code then becomes a new column. This reduces the number of new columns compared to one-hot encoding (e.g., 100 categories need 7 binary columns instead of 100 one-hot columns).
  • Frequency Encoding: Replaces each category with its frequency (count) or proportion in the dataset. This captures information about how common or rare a category is, potentially revealing predictive patterns (e.g., rare cities behave differently).

Target-Based Encodings (Supervised)

These methods use the relationship between the categorical feature and the target variable to create numerical representations. They are powerful but carry a risk of data leakage and overfitting.

  • Target (Mean) Encoding: Replaces each category with the average (mean) of the target variable for all observations belonging to that category. For example, replace 'New York' with the average 'Purchase Amount' for all 'New York' transactions. This directly injects target information but can easily overfit to noise in the training data, especially for rare categories. Smoothing (mixing with global mean) is often used to mitigate this.
  • Leave-One-Out (LOO) Encoding: A variant of Target Encoding that addresses data leakage. For each observation, the category is replaced by the mean target of all *other* observations in that same category, excluding the current row. This prevents the target value of the current row from influencing its own encoding.
  • CatBoost Encoding: Another robust target-based encoding, primarily designed for tree-based models. It uses an ordered approach: for each observation, the encoding is computed using only the target values of observations that appeared *before* it in a random permutation of the dataset, combined with a prior. This further reduces leakage and is less prone to overfitting than simple mean encoding.

Learned Embeddings

  • Entity Embeddings: Instead of a fixed, hand-crafted mapping, each category is assigned a dense, low-dimensional vector (an "embedding") that is learned as part of a neural network model. Similar to word embeddings in NLP, these vectors capture semantic relationships between categories in a learned latent space. They are highly flexible and can capture complex patterns but require a neural network architecture and sufficient data to train effectively.
🔑 Key Property

The fundamental trade-off in categorical encoding is between simplicity/safety (Label, One-Hot) and predictive power/risk (Target-based, Embeddings). Simpler methods are less prone to overfitting but may lose information; more complex methods can capture richer patterns but require careful handling to avoid data leakage and instability.

3
Why It Works — The Math & Pitfalls
▼

One-Hot Encoding

For a categorical feature \(X\) with \(C\) unique categories, One-Hot Encoding transforms it into \(C\) binary features \(X_1, X_2, \dots, X_C\). For an observation \(i\) belonging to category \(c\):

$$X_{i,j} = \begin{cases} 1 & \text{if category of } i \text{ is } j \\ 0 & \text{otherwise} \end{cases}$$

This is mathematically sound for nominal data as it imposes no spurious order. However, for linear models, one column is often dropped (e.g., \(C-1\) columns) to avoid multicollinearity (the "dummy variable trap"), as the last column's value is perfectly predictable from the others.

Frequency Encoding

For each category \(c\), replace it with its frequency or proportion in the dataset:

$$E_{freq}(c) = \frac{\text{Count}(c)}{\sum_{k=1}^C \text{Count}(k)}$$

This method implicitly captures information about category prevalence. If categories with similar frequencies also have similar target values, this encoding can be very effective. It is also robust to high cardinality as it only adds one numerical feature.

Target (Mean) Encoding with Smoothing

The basic target encoding for a category \(c\) is the mean of the target variable \(Y\) for all instances where \(X=c\):

$$E_{target}(c) = \frac{\sum_{i: X_i=c} Y_i}{\text{Count}(c)}$$

To prevent overfitting, especially for categories with few observations, smoothing is applied. This blends the category's mean with the global mean of the target:

$$E_{smoothed}(c) = \frac{\text{Count}(c) \cdot E_{target}(c) + \text{min\_samples\_leaf} \cdot \text{GlobalMean}(Y)}{\text{Count}(c) + \text{min\_samples\_leaf}}$$

Here, \(\text{min\_samples\_leaf}\) is a hyperparameter (e.g., 1 to 100) that controls the strength of smoothing. A larger value means more weight is given to the global mean, especially for small categories.

Leave-One-Out Encoding

To prevent data leakage, for each observation \(i\) with category \(c\), the encoding is calculated using the mean of the target from all *other* observations in the same category:

$$E_{LOO}(c, i) = \frac{\sum_{j \neq i, X_j=c} Y_j}{\text{Count}(c) - 1}$$

This ensures that the target value of the current row does not directly influence its own encoded feature value, making it safer for models that are sensitive to leakage (e.g., linear models, neural networks). If \(\text{Count}(c) - 1 = 0\), a fallback (e.g., global mean) is used.

⚠️ Common Pitfall: Data Leakage

Target-based encodings (Mean, LOO, CatBoost) are highly susceptible to data leakage if not implemented carefully. If the encoding is calculated on the entire dataset (including validation/test sets), the model implicitly "sees" the target values of future data. Always compute target-based encodings ONLY on the training split and apply the learned mapping to validation/test sets, or use cross-validation folds to compute encodings.

General Best Practices:

  • Always use cross-validation: Especially for target-based encodings, compute encodings within each fold on the training data of that fold, then apply to the validation data. This mimics real-world deployment and prevents leakage.
  • Handle unseen categories: New categories in test data (not present in training) need a strategy: assign global mean (for target encodings), a default value, or a special 'unknown' category.
  • Consider cardinality: Low-cardinality features (e.g., <10 unique values) often work well with One-Hot. High-cardinality features may benefit from Binary, Frequency, or Target-based encodings, or Embeddings.
  • Model choice matters: Tree-based models can handle Label/Ordinal encoding better than linear models because they don't assume linear relationships between feature values. Linear models and neural networks generally prefer One-Hot or Target-based encodings.
💡 No Silver Bullet

There is no single "best" encoding method. The optimal choice is highly dependent on the dataset's characteristics (cardinality, nominal vs. ordinal), the nature of the target variable, and the specific machine learning model being used. Experimentation and careful validation are key.

Code Trace (Python)
▼
import pandas as pd
from sklearn.preprocessing import LabelEncoder, OneHotEncoder
from category_encoders import BinaryEncoder, TargetEncoder, CatBoostEncoder
import numpy as np
# Sample Data
data = pd.DataFrame({
'City': ['New York', 'London', 'Paris', 'New York', 'London',
'Paris', 'New York', 'London', 'Paris', 'New York'],
'Purchase': [150, 50, 200, 30, 70, 40, 180, 20, 60, 160]
})
X = data[['City']]; y = data['Purchase']
# 1. Label Encoding
le = LabelEncoder()
data['City_LabelEncoded'] = le.fit_transform(X['City'])
print("Label Encoded:\n", data[['City', 'City_LabelEncoded']].head())
# 2. One-Hot Encoding
ohe = OneHotEncoder(handle_unknown='ignore', sparse_output=False)
city_ohe = ohe.fit_transform(X[['City']])
ohe_df = pd.DataFrame(city_ohe, columns=ohe.get_feature_names_out(['City']))
print("\nOne-Hot Encoded:\n", ohe_df.head())
# 3. Binary Encoding
be = BinaryEncoder(cols=['City'])
city_binary = be.fit_transform(X)
print("\nBinary Encoded:\n", city_binary.head())
# 4. Frequency Encoding
freq_map = X['City'].value_counts(normalize=True).to_dict()
data['City_FreqEncoded'] = X['City'].map(freq_map)
print("\nFrequency Encoded:\n", data[['City', 'City_FreqEncoded']].head())
# 5. Target (Mean) Encoding with smoothing
te = TargetEncoder(cols=['City'], smoothing=1.0) # smoothing factor
data['City_TargetEncoded'] = te.fit_transform(X, y)
print("\nTarget Encoded:\n", data[['City', 'City_TargetEncoded']].head())
# 6. Leave-One-Out Encoding
loo_encoder = TargetEncoder(cols=['City'], return_df=True, smoothing=0, min_samples_leaf=1)
# To simulate LOO, fit on full data, then transform using a loop or specific method
data['City_LOOEncoded'] = loo_encoder.fit_transform(X, y) # This is a simplified example, actual LOO needs cross-validation
print("\nLeave-One-Out Encoded (simplified):\n", data[['City', 'City_LOOEncoded']].head())
# 7. CatBoost Encoding
cbe = CatBoostEncoder(cols=['City'])
data['City_CatBoostEncoded'] = cbe.fit_transform(X, y)
print("\nCatBoost Encoded:\n", data[['City', 'City_CatBoostEncoded']].head())
