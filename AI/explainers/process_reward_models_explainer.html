Understanding PRM vs ORM
▼

What are they? In Reinforcement Learning from Human Feedback (RLHF), a Reward Model (RM) learns to predict human preferences, guiding a large language model (LLM) towards generating better responses. The core distinction lies in what gets rewarded:

  • Outcome Reward Models (ORM): Assign a single reward based on the final output or overall outcome of a generated response. This is the simpler, more common approach.
  • Process Reward Models (PRM): Assign rewards based on the intermediate steps or the reasoning process demonstrated within a generated response. This requires finer-grained human feedback.

Analogy: Imagine a student solving a complex math problem. An ORM is like a teacher who only grades the final answer. If the answer is correct, full marks; if wrong, zero, regardless of the steps. A PRM is like a teacher who checks each step of the student's work. Even if the final answer is wrong, a student showing correct reasoning in intermediate steps can still earn partial credit, and conversely, a correct final answer achieved through flawed logic would be penalized.

💡 If you remember one thing

PRM aims to align LLMs not just on what to say, but how to reason. By rewarding good intermediate steps, PRM encourages models to generate interpretable, verifiable, and robust chain-of-thought reasoning, even for complex, multi-step tasks.

How They Work Internally
▼

Outcome Reward Models (ORM)

ORM training is straightforward. Humans are shown a complete LLM response (or a pair of responses) and asked to give an overall preference score or ranking. The RM is then trained to predict these holistic scores. This approach is efficient for data collection as it requires only one label per full response, making it suitable for tasks where the final result is the primary concern.

  • Input to RM: The full generated text sequence.
  • Output from RM: A single scalar reward score.
  • Human Feedback: Overall preference or quality rating for the complete output.
  • Pros: Simpler to implement, cheaper data collection.
  • Cons: Can be susceptible to "lucky" or "deceptive" answers, provides less specific feedback for complex reasoning errors.

Process Reward Models (PRM)

PRM training is more involved. Humans are presented with an LLM's response broken down into its constituent reasoning steps (e.g., a chain-of-thought). They then provide a preference or quality rating for each individual step. The PRM is typically trained as a sequence model, predicting a reward for each step in the sequence.

  • Input to RM: The sequence of intermediate steps.
  • Output from RM: A sequence of scalar reward scores, one per step.
  • Human Feedback: Granular quality ratings for each intermediate step.
  • Pros: Encourages robust reasoning, improves interpretability, better for complex, multi-step tasks.
  • Cons: Significantly more expensive and time-consuming for data collection, requires careful task decomposition and human annotator training.

Design Decision: Why the Complexity for PRM?

The added complexity and cost of PRM data collection are justified by its potential to overcome limitations of ORMs. For tasks like mathematical reasoning, scientific problem-solving, or code generation, a correct final answer might hide flawed or non-generalizable reasoning. An ORM would reward this, potentially reinforcing bad habits. A PRM, by scrutinizing each step, ensures that the model learns the *correct process*, leading to more reliable and trustworthy AI systems.

🔑 Key Property

PRM provides denser and more localized supervision. Instead of a single sparse signal at the end, it offers a rich gradient signal at every decision point, enabling more efficient learning of complex, compositional behaviors.

3
Why It Works — The Math
▼

Outcome Reward Model (ORM) Loss

For an ORM, given a set of \(N\) generated responses (outcomes) \(O = \{o_1, \dots, o_N\}\), each with a human-assigned reward label \(y_k \in [0,1]\) (or a binary preference), the reward model \(\mathcal{R}_{ORM}\) predicts a single scalar reward \(\hat{r}_k = \mathcal{R}_{ORM}(o_k)\). The loss function (e.g., binary cross-entropy for a preference task) is standard:

$$ L_{ORM} = - \frac{1}{N} \sum_{k=1}^N \left[ y_k \log(\hat{r}_k) + (1-y_k) \log(1-\hat{r}_k) \right] $$

Here, \(y_k\) is typically 1 for a preferred response and 0 for a dispreferred one. The gradient signal is global to the entire response \(o_k\).

Process Reward Model (PRM) Loss

For a PRM, each response \(o_k\) is decomposed into \(M_k\) intermediate steps \(S_{k} = \{s_{k,1}, \dots, s_{k,M_k}\}\). A human provides a label \(y_{k,i} \in [0,1]\) for each step \(s_{k,i}\). The PRM \(\mathcal{R}_{PRM}\) predicts a reward \(\hat{r}_{k,i} = \mathcal{R}_{PRM}(s_{k,i})\) for each step. The total loss is the sum over all steps and all responses:

$$ L_{PRM} = - \frac{1}{\sum M_k} \sum_{k=1}^N \sum_{i=1}^{M_k} \left[ y_{k,i} \log(\hat{r}_{k,i}) + (1-y_{k,i}) \log(1-\hat{r}_{k,i}) \right] $$

This loss function provides a much denser gradient signal. When a mistake is made at step \(s_{k,i}\), the PRM receives a direct penalty for that specific step, allowing the underlying LLM to learn to correct that particular reasoning error more efficiently.

The Denser Gradient Signal

Consider the gradient with respect to the parameters \(\theta\) of the reward model for a single step \(s_{k,i}\) in PRM:

$$ \frac{\partial L_{PRM}}{\partial \theta} = - \frac{1}{\sum M_k} \sum_{k=1}^N \sum_{i=1}^{M_k} \left[ \frac{y_{k,i}}{\hat{r}_{k,i}} - \frac{1-y_{k,i}}{1-\hat{r}_{k,i}} \right] \frac{\partial \hat{r}_{k,i}}{\partial \theta} $$

This shows that each step's reward prediction directly contributes to the gradient. In contrast, for ORM, the gradient for any part of the response is filtered through the single final reward prediction. This localized feedback in PRM allows for more precise updates, preventing "credit assignment" problems where it's unclear which part of a long response led to a good or bad outcome.

⚠️ Common Pitfall

The quality of PRM depends critically on the granularity and consistency of human step-by-step feedback. If human annotators struggle to consistently evaluate intermediate steps, or if the decomposition into steps is arbitrary, PRM can introduce noise and bias, potentially hindering alignment rather than improving it.

Key Takeaways
▼

When to choose Process Reward Models (PRM):

  • Complex Reasoning Tasks: Problems requiring multiple logical steps (e.g., math, science, multi-turn dialogue, code generation).
  • Safety-Critical Applications: Where the reasoning process itself must be trustworthy and verifiable, not just the final answer.
  • Interpretability is Key: When understanding *how* an LLM arrives at an answer is as important as the answer itself.
  • Preventing Deception: To avoid models learning to "hack" the reward system by producing correct outcomes via flawed or non-generalizable internal processes.

When to choose Outcome Reward Models (ORM):

  • Simple, Single-Step Tasks: Where the quality is easily judged by the final output.
  • Limited Annotation Budget: When the cost of granular, step-by-step human feedback is prohibitive.
  • Low-Stakes Applications: Where occasional flawed reasoning that still yields a correct result is acceptable.
  • Early-Stage Prototyping: ORMs are a good starting point due to their simplicity.
💡 Big Picture

PRM represents a significant step towards building more robust, transparent, and genuinely intelligent AI systems by moving beyond mere outcome prediction to aligning the underlying cognitive process. It is a key direction for advanced LLM alignment research.

Code Trace (Python/PyTorch)
▼
import torch
import torch.nn as nn
# Assume a simple text encoder for brevity
class TextEncoder(nn.Module):
def __init__(self, vocab_size, emb_dim, hidden_dim):
super().__init__()
self.embedding = nn.Embedding(vocab_size, emb_dim)
self.lstm = nn.LSTM(emb_dim, hidden_dim, batch_first=True)
self.linear = nn.Linear(hidden_dim, 1) # Output a single score
def forward(self, text_ids):
embedded = self.embedding(text_ids)
_, (hidden, _) = self.lstm(embedded)
return torch.sigmoid(self.linear(hidden.squeeze(0))) # Reward in [0,1]
# --- Outcome Reward Model (ORM) ---
class ORM(nn.Module):
def __init__(self, vocab_size, emb_dim, hidden_dim):
super().__init__()
self.encoder = TextEncoder(vocab_size, emb_dim, hidden_dim)
def forward(self, full_response_text_ids):
return self.encoder(full_response_text_ids) # Single reward for full text
# --- Process Reward Model (PRM) ---
class PRM(nn.Module):
def __init__(self, vocab_size, emb_dim, hidden_dim):
super().__init__()
self.encoder = TextEncoder(vocab_size, emb_dim, hidden_dim) # Same encoder
def forward(self, step_texts_ids):
# step_texts_ids is a list of tensors, each for a step's text
rewards = [self.encoder(step_id) for step_id in step_texts_ids]
return torch.cat(rewards, dim=0) # Returns a tensor of rewards, one per step
# --- Example Usage & Loss Calculation ---
vocab_size, emb_dim, hidden_dim = 10000, 128, 256
criterion = nn.BCELoss() # Binary Cross-Entropy Loss
# ORM training example
orm_model = ORM(vocab_size, emb_dim, hidden_dim)
full_response_input = torch.randint(0, vocab_size, (1, 50)) # Batch 1, len 50
human_orm_label = torch.tensor([0.9]).float() # High quality outcome
predicted_orm_reward = orm_model(full_response_input)
loss_orm = criterion(predicted_orm_reward, human_orm_label)
# loss_orm.backward() # Backprop through the whole response
# PRM training example
prm_model = PRM(vocab_size, emb_dim, hidden_dim)
step_inputs = [
torch.randint(0, vocab_size, (1, 10)), # Step 1 text
torch.randint(0, vocab_size, (1, 15)), # Step 2 text
torch.randint(0, vocab_size, (1, 20)), # Step 3 text
torch.randint(0, vocab_size, (1, 12)), # Step 4 text
torch.randint(0, vocab_size, (1, 8)) # Step 5 text
]
human_prm_labels = torch.tensor([0.9, 0.8, 0.2, 0.7, 0.9]).float() # Step-wise labels
predicted_prm_rewards = prm_model(step_inputs)
loss_prm = criterion(predicted_prm_rewards.squeeze(), human_prm_labels)
# loss_prm.backward() # Backprop with granular gradients
