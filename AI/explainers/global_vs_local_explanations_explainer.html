Global vs Local Explanations

Understanding how a model behaves overall vs. why a single prediction was made
Intermediate XAI Interpretability Varies by method
1
Understanding Global vs Local Explanations
▼

What are they? As machine learning models become more complex ("black boxes"), understanding their decisions is crucial. Global explanations tell us how the model behaves *on average* across the entire dataset. They answer questions like "Which features are generally most important?" or "How does the model typically respond to changes in feature X?" In contrast, local explanations focus on *why a single prediction was made* for a specific input instance. They answer "Why did the model predict class A for *this* particular input?"

Analogy: Imagine a large company. A global explanation is like the CEO's annual report: it describes overall revenue drivers, market trends, and average employee performance. It gives a high-level view of how the company works. A local explanation, however, is like a manager explaining why a specific employee received a particular bonus this year: it details their individual performance, specific projects, and contributions. Both are valuable, but they serve different purposes and provide different levels of detail.

💡 If you remember one thing

The core distinction between global and local explanations is their scope. Global methods provide insights into the model's overall behavior and decision-making patterns, while local methods focus on dissecting individual predictions for specific data points.

2
How They Work Internally
▼

Global Explanation Methods

These techniques aim to summarize the model's behavior over its entire input space. They are useful for understanding the model's biases, debugging, and gaining general trust.

  • Feature Importance: Ranks features by their overall impact on model predictions. Methods include Permutation Importance (measuring prediction error increase when a feature is shuffled) and Mean Decrease Impurity (for tree-based models).
  • Partial Dependence Plots (PDPs): Show the marginal effect of one or two features on the predicted outcome of a model, averaging over the values of all other features.
  • Accumulated Local Effects (ALE) Plots: Similar to PDPs but more robust to correlated features, showing how features influence the prediction on average.
  • Model Coefficients: For linear models, coefficients directly indicate feature importance and direction of effect.

Local Explanation Methods

These methods explain individual predictions, providing transparency and accountability for specific decisions. They are crucial for high-stakes applications like medical diagnosis or loan approvals.

  • LIME (Local Interpretable Model-agnostic Explanations): Approximates the black-box model locally around a specific instance with an interpretable model (e.g., linear regression), explaining its prediction.
  • SHAP (SHapley Additive exPlanations): Based on Shapley values from game theory, SHAP attributes each feature's contribution to a prediction by considering all possible feature coalitions.
  • Individual Conditional Expectation (ICE) Plots: Show the prediction for a single instance as a function of a feature of interest, keeping all other features fixed.
  • Counterfactual Explanations: Identify the smallest change to an instance's features that would change its prediction to a desired outcome.
🔑 Key Property

Many advanced explanation methods are model-agnostic, meaning they can be applied to any black-box model without needing access to its internal structure. This flexibility is a major advantage, especially for complex deep learning models. LIME and SHAP are prime examples of model-agnostic techniques.

3
Why They Work — The Math
▼

Global: Permutation Feature Importance

Permutation Importance (Breiman, 2001) quantifies the importance of a feature by measuring how much the model's prediction error increases when the feature's values are randomly shuffled. A larger increase implies a more important feature. For a feature \(j\), the importance is:

$$ \text{Importance}_j = \mathbb{E}_{\pi_j} [L(f(X), y) - L(f(X_{\text{perm}_j}), y)] $$

Here, \(L\) is the loss function (e.g., accuracy, MSE), \(f\) is the trained model, \(X\) is the original dataset, \(y\) are the true labels, and \(X_{\text{perm}_j}\) is the dataset where feature \(j\) has been randomly permuted. The expectation \(\mathbb{E}_{\pi_j}\) is taken over multiple permutations to ensure robustness.

Local: LIME (Local Interpretable Model-agnostic Explanations)

LIME (Ribeiro et al., 2016) explains a single prediction by approximating the black-box model \(f\) with a simple, interpretable model \(g\) (e.g., linear regression, decision tree) in the vicinity of the instance \(x\) to be explained. The objective function for LIME is:

$$ \xi(x) = \arg\min_{g \in G} L(f, g, \pi_x) + \Omega(g) $$

Where \(G\) is the class of interpretable models (e.g., linear models), \(\Omega(g)\) is a regularization term for the complexity of \(g\), and \(L(f, g, \pi_x)\) is the fidelity loss, measuring how well \(g\) approximates \(f\) in the neighborhood defined by \(\pi_x\). The fidelity loss is typically a weighted squared error:

$$ L(f, g, \pi_x) = \sum_{z \in Z} \pi_x(z) (f(z) - g(z))^2 $$

Here, \(Z\) is a set of perturbed samples around \(x\), and \(\pi_x(z)\) is a proximity measure (e.g., exponential kernel) indicating how close \(z\) is to \(x\). The coefficients of the locally fitted model \(g\) then serve as the local feature importances.

⚠️ Common Pitfall

Local explanations like LIME rely on the assumption that the black-box model is locally linear (or simple enough to be approximated by \(g\)). If the model's behavior is highly complex and non-linear even within a small neighborhood, the interpretable surrogate \(g\) might not accurately reflect the black-box model's reasoning, leading to misleading explanations.

Key Takeaways
▼

When to use Global Explanations:

  • Model Debugging: Identify if the model relies on spurious correlations or exhibits unwanted biases across the dataset.
  • High-Level Understanding: Gain an overall intuition of which features drive the model's decisions.
  • Feature Engineering: Inform which features might be more valuable to collect or engineer further.
  • Regulatory Compliance: Demonstrate general fairness or adherence to guidelines across broad populations.

When to use Local Explanations:

  • Individual Trust: Justify a specific prediction to an affected individual (e.g., why a loan was denied).
  • Counterfactual Analysis: Answer "What if?" questions for a particular instance (e.g., "What would I need to change to get a loan approval?").
  • Debugging Specific Cases: Understand why an unusual or erroneous prediction occurred for a single input.
  • Adversarial Attacks: Analyze the sensitivity of a single prediction to small input perturbations.
💡 Complementary Views

Global and local explanations are not mutually exclusive; rather, they offer complementary perspectives. Global insights can guide general model improvements, while local explanations provide the granular detail needed for trust, accountability, and targeted interventions on individual predictions.

Code Trace (Simplified Python)
▼
import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.metrics import accuracy_score
# Assume `model` is your trained black-box classifier
# Assume `X_train, y_train` are your dataset
# --- Global Explanation: Permutation Importance ---
def global_permutation_importance(model, X, y):
baseline_preds = model.predict(X)
baseline_score = accuracy_score(y, baseline_preds)
importances = []
for i in range(X.shape[1]): # Iterate over features
X_permuted = X.copy()
np.random.shuffle(X_permuted[:, i]) # Permute feature i
permuted_preds = model.predict(X_permuted)
permuted_score = accuracy_score(y, permuted_preds)
importances.append(baseline_score - permuted_score)
return np.array(importances)
# --- Local Explanation: Simplified LIME-like approach ---
def local_explanation_lime(model, instance_x, num_perturb=1000, noise=0.1):
# Generate perturbed samples around instance_x
perturbed_X = instance_x + np.random.normal(0, noise, size=(num_perturb, len(instance_x)))
perturbed_y_model = model.predict_proba(perturbed_X)[:, 1] # Prob of class 1
# Calculate weights based on proximity (e.g., Gaussian kernel)
distances = np.linalg.norm(perturbed_X - instance_x, axis=1)
weights = np.exp(-distances**2 / (noise**2 * 0.25)) # Kernel width related to noise
# Fit a weighted linear model
local_model = LinearRegression()
local_model.fit(perturbed_X, perturbed_y_model, sample_weight=weights)
return local_model.coef_ # Coefficients are local feature importances
