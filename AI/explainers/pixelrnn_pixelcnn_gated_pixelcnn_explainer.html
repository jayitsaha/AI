Understanding Autoregressive Image Models
▼

What are they? PixelRNN, PixelCNN, and Gated PixelCNN are generative models designed to produce realistic images by predicting one pixel at a time, conditioned on all previously generated pixels. This autoregressive approach gives them a strong theoretical foundation for modeling complex data distributions, as the joint probability of an image \(P(x)\) can be factorized into a product of conditional probabilities:

$$P(x) = \prod_{i=1}^{N^2} P(x_i | x_1, \dots, x_{i-1})$$

where \(x_i\) is the \(i\)-th pixel in a predefined scan order (typically raster scan: left-to-right, top-to-bottom). Each pixel's value (e.g., RGB channels) is also predicted sequentially (e.g., R then G then B).

Analogy: Imagine writing a book one letter at a time. An autoregressive model is like a very smart author who, for each new letter, considers all the letters (and words, sentences, paragraphs) written so far to decide what comes next. Each pixel is a "letter," and the model learns the "grammar" of images. The challenge is efficiently capturing long-range dependencies across the image without breaking the strict causality rule.

💡 If you remember one thing

These models predict pixels sequentially, ensuring that each prediction only uses information from "past" pixels according to a fixed scanline order. This strict causality is enforced by either recurrent connections (PixelRNN) or specialized masked convolutions (PixelCNN/Gated PixelCNN).

2
From RNNs to Masked Convolutions
▼

PixelRNN: Recurrent Connections for Causality

The original PixelRNN (van den Oord et al., 2016) uses Long Short-Term Memory (LSTM) networks to model the dependencies. It employs two types of LSTMs:

  • Row LSTM: Processes each row from left to right, capturing horizontal dependencies.
  • Diagonal BiLSTM: Processes pixels along diagonals, capturing dependencies from the upper-left region.

While powerful, the sequential nature of LSTMs means that generating an entire image is very slow (each pixel must be generated one after another, and within each pixel, each channel sequentially). Training is also slower than parallelizable convolutional networks.

PixelCNN: The Power of Masked Convolutions

To overcome the speed limitations of RNNs while maintaining autoregressive causality, PixelCNN (also van den Oord et al., 2016) introduced masked convolutions. Instead of LSTMs, it uses standard convolutional layers, but with a special trick:

A convolutional filter is modified with a binary mask that zeroes out weights corresponding to "future" pixels. This ensures that the prediction for pixel \(x_{i,j}\) only depends on pixels \(x_{k,l}\) where \(k < i\), or \(k = i\) and \(l < j\).

Two types of masks are crucial:

  • Type A Mask: Applied to the first convolutional layer. It only allows the filter to see pixels strictly above or to the left of the current pixel. The center pixel (the one being predicted) is entirely masked out.
  • Type B Mask: Applied to subsequent convolutional layers. It allows the filter to see pixels strictly above or to the left, and also the channels of the current pixel that have already been predicted (e.g., if predicting green, it can see red).

PixelCNN trains much faster than PixelRNN due to the parallel nature of convolutions, but generation remains sequential (one pixel at a time).

🔑 Key Property

The core innovation of PixelCNN is replacing slow recurrent connections with fast, parallelizable convolutions, while preserving the strict autoregressive property through carefully designed causal masks on the convolutional filters.

3
Gated PixelCNN: Addressing Limitations
▼

The "Blind Spot" Problem in Basic PixelCNN

A major limitation of the original PixelCNN with square masks is its "blind spot." Due to the fixed shape of the masked convolutional kernel, its receptive field is often restricted to a rectangular area, missing some pixels that are causally "past" but fall outside this shape. For example, a 3x3 mask centered on the current pixel cannot see the pixel directly above-right, limiting the model's ability to capture certain dependencies.

Gated PixelCNN: Improved Expressivity and Context

Gated PixelCNN (van den Oord et al., 2016, a follow-up to PixelCNN) addresses these issues with two main improvements:

  1. Gating Mechanism: Inspired by LSTMs and GRUs, each convolutional layer incorporates a gating mechanism to control the flow of information. This allows the model to selectively propagate relevant features and learn more complex dependencies. A typical gated activation for a feature map \(h\) might look like:

    $$\mathbf{h} = \tanh(W_k \ast \mathbf{x}) \odot \sigma(W_f \ast \mathbf{x})$$

    where \(W_k\) and \(W_f\) are convolutional filters for the "key" and "forget" (or "input" and "gate") paths, \(\ast\) denotes convolution, \(\odot\) is element-wise product, \(\tanh\) is the activation function, and \(\sigma\) is the sigmoid activation. This allows for richer interactions than simple ReLU activations.

  2. Two-Stream (Vertical and Horizontal) Architecture: To eliminate the blind spot and provide a more complete receptive field, Gated PixelCNN uses two separate stacks of masked convolutional layers:
    • Vertical Stack: Processes information from pixels above the current row. It uses masks that only allow connections to pixels in rows above the current one.
    • Horizontal Stack: Processes information from pixels in the current row, from left to right. Crucially, it takes input from both its own previous horizontal pixels AND the output of the vertical stack (which provides context from above).

The output of the vertical stack is passed as input to the horizontal stack, allowing the horizontal stack to have a full causal receptive field that extends upwards and to the left, without any blind spots. This significantly improves the quality of generated images.

➕ Gated PixelCNN Update (simplified)

For a horizontal feature map \(h^H_{ij}\) and vertical feature map \(h^V_{ij}\) at pixel \((i,j)\) and layer \(l\): $$h^V_{ij, l} = \tanh(W_{V,k} \ast h^V_{ij, l-1}) \odot \sigma(W_{V,f} \ast h^V_{ij, l-1})$$ $$h^H_{ij, l} = \tanh(W_{H,k} \ast h^H_{ij, l-1} + W_{H,v} \ast h^V_{ij, l}) \odot \sigma(W_{H,f} \ast h^H_{ij, l-1} + W_{H,g} \ast h^V_{ij, l})$$ The horizontal stack (second equation) takes inputs from both previous horizontal features and from the vertical stack, enabling a richer context.

Key Takeaways
▼

When to use (or study) these models:

  • When you need a pixel-perfect density model for image generation, where the joint probability distribution \(P(x)\) is explicitly modeled.
  • As a foundational understanding for more advanced autoregressive models (e.g., WaveNet for audio, or later transformer-based autoregressive image models like DALL-E 1/2).
  • For tasks requiring exact likelihood calculation (e.g., anomaly detection by low likelihood).

Limitations and Evolution:

  • Slow Generation: All these models generate pixels one by one, making them slow for high-resolution images. This is a fundamental trade-off of autoregressive models.
  • Conditional Generation: While the base models generate unconditionally, they can be extended to conditional generation (e.g., generating an image given a class label or text prompt) by conditioning each pixel prediction on the additional input.
  • Alternatives: Modern generative models like GANs (Generative Adversarial Networks) and VAEs (Variational Autoencoders) offer faster generation but typically don't model the exact likelihood. Diffusion models, while also slow during sampling, have recently achieved state-of-the-art image quality.
💡 Big Picture

PixelRNN/CNNs established the power of autoregressive modeling for images, demonstrating how strict causality and carefully designed architectures (like masked convolutions and gating) can achieve high-fidelity generation. They laid groundwork for many subsequent generative models, even as faster alternatives emerged for practical applications.

Code Trace (Masked Convolution)
▼
import torch
import torch.nn as nn
class MaskedConv2d(nn.Conv2d):
def __init__(self, mask_type, *args, **kwargs):
super().__init__(*args, **kwargs)
self.mask_type = mask_type
self.register_buffer('mask', self.weight.data.clone())
_, _, h, w = self.weight.size()
self.mask.fill_(1)
# Mask out future pixels (bottom-right half of kernel)
self.mask[:, :, h // 2, w // 2 + 1:] = 0 # Right half of center row
self.mask[:, :, h // 2 + 1:, :] = 0 # Rows below center row
# Type A mask: additionally mask out the center pixel itself
if mask_type == 'A':
self.mask[:, :, h // 2, w // 2] = 0 # Center pixel
def forward(self, x):
self.weight.data *= self.mask # Apply mask to weights
return super().forward(x)
