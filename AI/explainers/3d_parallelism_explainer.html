3D Parallelism: DP + TP + PP

Data, Tensor, and Pipeline Parallelism for scaling massive models across many GPUs
Intermediate Deep Learning Distributed Training O(N_GPUs) speed & memory
1
Understanding 3D Parallelism
▼

What is it? Training large language models (LLMs) or other foundation models with billions to trillions of parameters requires distributing the model and data across hundreds or thousands of GPUs. "3D Parallelism" refers to the synergistic combination of three orthogonal techniques: Data Parallelism (DP), Tensor Parallelism (TP), and Pipeline Parallelism (PP). Each addresses a different bottleneck in model scaling: DP scales the batch size, TP scales the model's width (hidden dimension), and PP scales the model's depth (number of layers).

Analogy: Imagine building a skyscraper (your model) with a huge team of workers (GPUs).

  • Data Parallelism (DP): You have many identical construction crews, each building a separate, smaller section of the same floor plan (processing a slice of the data batch). They all report back to a central foreman (gradient aggregation) to ensure consistency.
  • Tensor Parallelism (TP): A single floor (a model layer, like a large linear transformation) is too big for one crew. So, you split the tasks for that single floor across multiple specialized teams (e.g., one team builds the west half, another the east half). They have to coordinate closely to complete their shared floor.
  • Pipeline Parallelism (PP): You can't wait for floor 1 to be 100% finished before starting floor 2. Different crews work simultaneously on different floors (layers) of the skyscraper. Crew A builds floor 1, passes it to Crew B who builds floor 2, and so on. This creates an assembly line effect.
3D parallelism is when you do all three at once: multiple construction sites (DP), each with floors split among specialized teams (TP), and multiple floors being built simultaneously (PP).

💡 If you remember one thing

DP replicates the model and splits the data batch. TP splits individual layers (e.g., large matrix multiplies) across GPUs. PP splits the model's layers sequentially across GPUs. The combination allows extreme scaling by distributing all three dimensions: batch size, layer width, and model depth.

2
How Each Parallelism Works Internally
▼

Data Parallelism (DP)

DP is the most common form of distributed training. The full model is replicated on \(N_{dp}\) GPUs. The input mini-batch is split into \(N_{dp}\) sub-batches, with each GPU processing one sub-batch.

  • Forward Pass: Each GPU computes its forward pass independently.
  • Backward Pass: Each GPU computes gradients for its replica.
  • Synchronization: Gradients from all GPUs are averaged (typically via an all-reduce operation) to get the global gradient. This average gradient is then used to update the model weights on all GPUs, ensuring they remain synchronized.
  • Memory: Each GPU stores a full copy of the model weights and optimizer states. Activations are proportional to the local sub-batch size.
  • Communication: High for gradients (one all-reduce per parameter group).
A variant, Fully Sharded Data Parallel (FSDP), shards the model weights, gradients, and optimizer states across DP ranks, significantly reducing memory per GPU, making it a powerful component of 3D parallelism.

Tensor Parallelism (TP)

TP, sometimes called intra-layer model parallelism, shards individual model layers (e.g., large linear layers or attention mechanisms) across \(N_{tp}\) GPUs. This is crucial when a single layer's parameters or intermediate activations are too large to fit on one GPU.

  • Example: A linear layer \(Y = XW + B\), where \(W\) is a huge matrix.
    • If \(W\) is split column-wise (\(W = [W_0, W_1, \dots, W_{N_{tp}-1}]\)), each GPU \(k\) computes \(Y_k = X W_k\). The final \(Y\) is formed by concatenating \(Y_k\)s. This requires replicating \(X\) on all TP GPUs and an all-gather for the output.
    • If \(W\) is split row-wise (\(W = [W_0^\top, \dots, W_{N_{tp}-1}^\top]^\top\)), each GPU \(k\) takes a shard of the input \(X_k\) and computes \(Z_k = X_k W_k\). The final \(Y = \sum Z_k\) requires an all-reduce.
  • Memory: Each GPU stores only a shard of the layer's weights.
  • Communication: High for activations and gradients within each layer (e.g., all-gather or all-reduce operations).

Pipeline Parallelism (PP)

PP, or inter-layer model parallelism, partitions the model's layers sequentially across \(N_{pp}\) GPUs, forming a pipeline. Each GPU (stage) is responsible for a subset of the model's layers.

  • Forward Pass: GPU0 processes its layers, passes activations to GPU1, which processes its layers and passes to GPU2, and so on.
  • Backward Pass: Gradients flow backward through the pipeline.
  • Problem: Pipeline Bubble: GPUs can be idle waiting for activations from the previous stage or gradients from the next stage.
  • Solution: Microbatching: The input mini-batch is divided into smaller "microbatches." Multiple microbatches are processed in sequence, allowing different stages to work on different microbatches concurrently, filling the pipeline and reducing idle time.
  • Memory: Each GPU stores only the weights for its assigned layers. Activations for multiple microbatches must be stored for the backward pass.
  • Communication: Point-to-point communication (send/receive) between adjacent pipeline stages.
🔑 Key Property

These three methods are largely orthogonal. DP distributes the *batch dimension*, TP distributes the *hidden dimension* (within a layer), and PP distributes the *layer dimension* (model depth). Combining them allows for a true "3D" distribution of the model and computation across a large cluster of GPUs.

3
Why It Works — The Combined Math
▼

Data Parallelism (DP) Gradient Aggregation

For \(N_{dp}\) data parallel replicas, each computing a local gradient \(g_k\) for its sub-batch, the effective gradient for the weight update is the average across all replicas. This ensures that the global gradient direction is preserved, just as if a single GPU processed the full batch:

$$g_{global} = \frac{1}{N_{dp}} \sum_{k=0}^{N_{dp}-1} g_k$$

This is typically implemented via an all-reduce collective communication operation, which sums the gradients across all GPUs and then divides by \(N_{dp}\), making the global gradient available on all GPUs.

Tensor Parallelism (TP) for a Linear Layer

Consider a linear layer \(Y = XW + B\), where \(X \in \mathbb{R}^{B \times D_{in}}\), \(W \in \mathbb{R}^{D_{in} \times D_{out}}\), and \(Y \in \mathbb{R}^{B \times D_{out}}\). With \(N_{tp}\) tensor parallel GPUs, we can split \(W\) column-wise. Each GPU \(k\) receives \(W_k \in \mathbb{R}^{D_{in} \times D_{out}/N_{tp}}\) and computes a partial output \(Y_k\):

$$W = [W_0 | W_1 | \dots | W_{N_{tp}-1}]$$ $$Y_k = X W_k + B_k \quad \text{on GPU } k$$

Here, \(X\) is replicated on all TP GPUs, and \(B_k\) is the corresponding bias shard. The final output \(Y\) is then formed by concatenating these partial outputs across GPUs. This requires an all-gather operation for \(Y\) (or its gradients in backward pass) to make the full \(Y\) available for the next layer. The crucial aspect is that the communication is *within* a layer, distributing the computation of a single large matrix multiplication.

⚠️ Communication Overheads

While parallelism scales computation and memory, it introduces communication overheads. DP requires frequent all-reduce for gradients. TP requires all-gather/all-reduce for activations/gradients within layers. PP requires point-to-point communication between pipeline stages. The efficiency of 3D parallelism heavily depends on the GPU interconnect bandwidth (e.g., NVLink) and network topology.

Key Takeaways
▼

When to use 3D Parallelism:

  • Massive Models: When a model's parameters or intermediate activations exceed the memory capacity of a single GPU (or even a single node).
  • Faster Training: To reduce the time it takes to train models that would otherwise take weeks or months.
  • Larger Batch Sizes: DP allows scaling the effective batch size, which can be crucial for convergence and generalization in some tasks.
  • Resource Optimization: To efficiently utilize large GPU clusters, balancing computation, memory, and communication across different hardware configurations.

Trade-offs and Considerations:

  • Communication Overhead: Each parallelism strategy introduces communication. The overall efficiency depends heavily on the speed of inter-GPU communication (NVLink, InfiniBand) and network topology. DP involves large gradient all-reduces. TP involves frequent intra-layer all-gather/all-reduce. PP involves point-to-point transfers and pipeline bubbles.
  • Complexity: Implementing and debugging 3D parallelism is significantly more complex than single-GPU training. Frameworks like PyTorch FSDP, DeepSpeed, and Megatron-LM abstract much of this complexity.
  • Pipeline Bubbles (PP): Idle time in PP stages can be a major source of inefficiency. Microbatching helps, but finding the optimal microbatch size is critical.
  • Memory vs. Compute: DP primarily scales compute (batch size), while TP and PP primarily scale memory (model size). The optimal balance between DP, TP, and PP depends on the specific model architecture, total GPU count, and hardware constraints.
💡 The Future of Scaling

As models continue to grow, 3D parallelism (often combined with techniques like activation checkpointing, CPU offloading, and expert parallelism) becomes indispensable. It's the engineering backbone enabling the next generation of AI capabilities.
