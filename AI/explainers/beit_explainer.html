BEiT: BERT Pre-Training of Image Transformers

Masked image modeling — predict discrete visual tokens, not raw pixels
Advanced Self-Supervised Learning Vision Transformers Two-Stage Pretraining
1
Understanding BEiT
▼

What is it? BEiT takes BERT's masked-language-modeling trick — hide some words, make the model guess them — and ports it to images. But images don't have "words." So BEiT first converts each image patch into a discrete visual token (an integer ID from a fixed vocabulary of ~8,192 codes) using a separately-trained tokenizer. Then it masks some patches and trains a Vision Transformer to predict the missing tokens' IDs, exactly like BERT predicts missing word IDs.

Analogy: Imagine a jigsaw puzzle where every piece has been stamped with a tiny catalog number from a parts bin of 8,192 possible shapes. You cover 40% of the pieces with blank tiles. The model's job isn't to repaint the missing pieces pixel-by-pixel — it's to look at the visible pieces and correctly guess the catalog number stamped on each hidden one.

💡 If you remember one thing

BEiT reframes image pretraining as a classification problem (predict 1-of-8192 token IDs) instead of a regression problem (predict raw pixel values) — this avoids wasting model capacity on high-frequency pixel noise and pushes the encoder toward semantic representations.

2
How BEiT Works Internally
▼

Stage 0: Train the Visual Tokenizer (dVAE)

Before any masking happens, BEiT needs a way to turn patches into discrete symbols. It trains a discrete Variational Autoencoder (dVAE), borrowed from DALL·E: an encoder maps each 16×16 pixel patch to one of \(|V|=8192\) codebook entries, and a decoder reconstructs the image from the chosen codes. This tokenizer is trained once, then frozen — during BEiT pretraining it acts purely as a fixed "ground truth" labeler.

Stage 1: Patchify + Mask

A 224×224 image is split into a 14×14 grid of 196 non-overlapping 16×16 patches — the same patchification used by ViT. Roughly 40% of patches (about 75 of 196) are replaced with a shared, learnable [MASK] embedding, chosen via blockwise masking: instead of picking patches uniformly at random, BEiT repeatedly carves out random rectangular blocks until the target ratio is hit. This forces the model to reason about larger missing regions, not just isolated pixels a neighbor could trivially interpolate.

Stage 2: Encode + Predict

The corrupted patch sequence (visible patch embeddings + mask embeddings + position embeddings) is fed through a standard ViT encoder. Self-attention lets every masked position gather context from all visible patches. A linear "MIM head" on top of each masked position's final hidden state outputs a softmax distribution over the 8,192 codebook entries — the model is graded against the true token ID that the frozen dVAE assigned to that patch back in Stage 0.

🔑 Design Decision: Tokens, not Pixels

Predicting raw pixels (as later MAE does) forces the model to spend capacity on low-level texture and noise. Predicting a discrete semantic token — closer in spirit to BERT's word IDs — encourages high-level, abstract representations, at the cost of needing an extra pretraining stage to build the tokenizer.

3
Why It Works — The Math
▼

The Masked Image Modeling Objective

Let \(x\) be an image split into patches \(\{x_i\}_{i=1}^N\), let \(z_i = \operatorname{dVAE}_{\text{enc}}(x_i) \in \{1,\dots,|V|\}\) be the ground-truth visual token for patch \(i\), and let \(\mathcal{M} \subset \{1,\dots,N\}\) be the randomly masked index set. BEiT maximizes the log-likelihood of the true tokens at masked positions given the corrupted image \(x^{\mathcal{M}}\):

$$\max_{\theta} \; \mathbb{E}_{x}\Big[\sum_{i \in \mathcal{M}} \log p_\theta\big(z_i \mid x^{\mathcal{M}}\big)\Big]$$

which is trained as a per-position cross-entropy loss (identical in form to BERT's masked-token loss):

$$\mathcal{L}_{\text{MIM}} = -\frac{1}{|\mathcal{M}|}\sum_{i \in \mathcal{M}} \log p_\theta(z_i \mid x^{\mathcal{M}})$$

Connection to a Variational Lower Bound

The full BEiT objective (tokenizer + encoder) can be viewed as maximizing an evidence lower bound (ELBO) on the log-likelihood of the original image given the masked one, with the dVAE providing a discrete latent \(z\):

$$\log p(x \mid \tilde{x}) \;\ge\; \underbrace{\mathbb{E}_{z \sim q_\phi(z|x)}\big[\log p_\psi(x \mid z)\big]}_{\text{dVAE reconstruction (stage 0)}} \;-\; \underbrace{D_{\mathrm{KL}}\big(q_\phi(z|x)\,\|\,p_\theta(z \mid \tilde{x})\big)}_{\approx \text{ MIM objective (stage 1)}}$$

Because the tokenizer's posterior \(q_\phi(z|x)\) is frozen and made near-one-hot (via Gumbel-softmax annealing during dVAE training), minimizing the KL term reduces to maximizing \(\log p_\theta(z \mid \tilde x)\) — exactly the cross-entropy loss above.

⚠️ Common Misconception

BEiT is not reconstructing images. The MIM head never outputs pixels — it outputs a probability distribution over 8,192 discrete classes per masked patch. The visible pixels are only used as context; the loss only ever touches token IDs.

5
Key Takeaways
▼

When BEiT-style pretraining shines:

  • Large unlabeled image corpora where a strong ViT backbone is needed for downstream fine-tuning (classification, detection, segmentation)
  • Settings where semantic, high-level representations matter more than pixel-perfect texture
  • As the conceptual bridge that proved BERT-style masked modeling transfers to vision

Limitations:

  • Requires a separate, costly dVAE tokenizer training stage before MIM pretraining can begin
  • Tokenizer quality caps representation quality — a noisy codebook gives noisy training targets
  • Later methods (MAE, SimMIM) showed you can skip the tokenizer entirely and still match or beat BEiT
💡 Historical Significance

BEiT (2021) was the first to show masked-token prediction — not just masked-pixel regression or contrastive learning — works for images, directly inspiring MAE, SimMIM, and BEiT v2 (which replaced the pixel-based dVAE targets with semantic features distilled from CLIP).

🎯 Decision Guide

Use BEiT when you specifically want BERT-style discrete-token pretraining or need BEiT v2's semantic (CLIP-distilled) targets. Use MAE when compute efficiency matters most — dropping masked tokens from the encoder makes it ~3-4× faster to pretrain at equal quality. Use SimMIM for a simpler pixel-regression recipe with minimal tuning.
