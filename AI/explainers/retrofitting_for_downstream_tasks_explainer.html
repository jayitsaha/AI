Retrofitting Word Embeddings

Injecting lexical/semantic knowledge (WordNet, PPDB, FrameNet) into pretrained vectors — after the fact
Intermediate NLP Word Embeddings O(k·E) per pass
1
Understanding Retrofitting
▼

What is it? Word2Vec, GloVe, and similar models learn embeddings purely from word co-occurrence in raw text — words that appear near each other end up nearby in vector space. That's powerful, but it's an imperfect proxy for meaning: "good" and "bad" occur in nearly identical contexts ("the food was ___"), so distributional models often place antonyms close together. Retrofitting is a lightweight post-processing step that nudges a pretrained embedding space using an external semantic lexicon (WordNet synonyms, PPDB paraphrases, FrameNet relations) — without retraining the model.

Analogy: Imagine a seating chart at a huge conference generated purely from "who talks to whom" chatter (co-occurrence). It's roughly right, but some people who should be seated together (synonyms, close relatives in meaning) ended up scattered because they rarely happened to chat. Retrofitting is a facilitator who, holding the master guest list of "these people are family" (the lexicon), gently walks around and slides family members' chairs closer together — while still respecting each person's rough original neighborhood, since the co-occurrence signal isn't worthless, just noisy.

Summary: Retrofitting takes vectors you already trained and a graph of known semantic relations, then solves a small convex optimization that pulls connected words together while keeping every word anchored near its original vector.

💡 If you remember one thing

Retrofitting is graph-based label propagation applied to embeddings: each vector becomes a weighted average of (1) its own original distributional vector and (2) its neighbors' vectors in a hand-built semantic graph — iterated to convergence. $$q_i^{(t+1)} = \frac{\alpha_i \hat q_i + \sum_{j:(i,j)\in E}\beta_{ij}\, q_j^{(t)}}{\alpha_i + \sum_{j:(i,j)\in E}\beta_{ij}}$$

How Retrofitting Works Internally
▼

Inputs

Retrofitting (Faruqui et al., 2015) needs two things: (1) a matrix of pretrained vectors \(\hat Q = \{\hat q_1,\dots,\hat q_n\}\) from any embedding method, and (2) an ontology graph \(\Omega = (V, E)\) where an edge \((i,j)\) means "word \(i\) and word \(j\) are semantically related" — typically WordNet synsets, PPDB paraphrase pairs, or FrameNet frame members. The output \(Q = \{q_1,\dots,q_n\}\) lives in the same vector space and dimensionality as \(\hat Q\), so it's a drop-in replacement.

The Update Rule (Jacobi Iteration)

Retrofitting has no closed-form global solution for the whole graph at once, so it uses a fast iterative scheme. On each pass, every node's new vector is computed as a weighted average: pull weight \(\alpha_i\) toward its own original vector \(\hat q_i\), plus pull weight \(\beta_{ij}\) toward each graph neighbor's current vector \(q_j\). In the standard setting \(\alpha_i = 1\) and \(\beta_{ij} = 1/\deg(i)\), so the neighbor pull-strengths sum to exactly 1 — the update becomes literally "average of my original vector and my neighbors' current average," recomputed every round. Typically 10 iterations is enough to converge (the objective is strictly convex per node given fixed neighbors).

Design Decision: Why post-hoc graph smoothing, not joint training?

An alternative is baking the lexicon into training itself (e.g. adding synonym constraints to the Word2Vec loss). That works, but it's slow (retrain from scratch per lexicon), and couples you to one embedding algorithm. Retrofitting instead treats the pretrained vectors as a black box: it works identically whether \(\hat Q\) came from Word2Vec, GloVe, fastText, or even the input layer of a neural LM — you only need the vectors and a graph, and one pass converges in seconds even for vocabularies with hundreds of thousands of words, since each update touches only a node's local neighborhood.

Numerical Trace

Say "happy" starts at \(\hat q = (-2, 3)\) and its only lexicon neighbor "glad" currently sits at \((1,3)\), with \(\alpha=1,\ \beta=1\) (single neighbor, so \(\beta_{ij}=1/\deg(i)=1\)). One update: \(q_{\text{happy}} = \frac{1\cdot(-2,3) + 1\cdot(1,3)}{1+1} = (-0.5, 3)\). "happy" moved 1.5 units toward "glad" while staying anchored — exactly the interactive walkthrough below, but on all 8 words and 7 edges simultaneously, iterated to convergence.

🔑 Key Property

Retrofitting is algorithm-agnostic and lexicon-agnostic: it's a graph-Laplacian-style smoothing operator applied on top of any embedding, using any relational resource — swap WordNet for a domain-specific taxonomy (e.g. medical ontologies) and the same update rule injects that domain's semantic knowledge.

Why It Works — The Math
▼

The Objective

Retrofitting minimizes a per-word sum of two quadratic penalties: distance from the original vector, and distance from each graph neighbor's vector.

$$\Psi(Q) = \sum_{i=1}^{n} \left[\, \alpha_i \lVert q_i - \hat q_i \rVert^2 \;+\; \sum_{j:(i,j)\in E} \beta_{ij} \lVert q_i - q_j \rVert^2 \,\right]$$

This is exactly a graph-Laplacian regularized least-squares problem — the same mathematical family as label propagation in semi-supervised learning. \(\alpha_i\) controls how strongly word \(i\) trusts its distributional vector; \(\beta_{ij}\) controls how strongly the edge \((i,j)\) enforces agreement.

Deriving the Update Rule

\(\Psi\) is convex in each \(q_i\) individually (holding all other \(q_j\) fixed), so take the partial derivative and set it to zero:

$$\frac{\partial \Psi}{\partial q_i} = 2\alpha_i(q_i - \hat q_i) + 2\sum_{j:(i,j)\in E}\beta_{ij}(q_i - q_j) = 0$$

Collecting terms in \(q_i\):

$$q_i\Big(\alpha_i + \sum_{j}\beta_{ij}\Big) = \alpha_i \hat q_i + \sum_{j}\beta_{ij} q_j \;\;\implies\;\; q_i = \frac{\alpha_i \hat q_i + \sum_{j:(i,j)\in E}\beta_{ij}\, q_j}{\alpha_i + \sum_{j:(i,j)\in E}\beta_{ij}}$$

Because the right-hand side depends on other \(q_j\)'s (which are also being updated), there's no single closed form for the whole graph — instead we treat this as a fixed-point equation and iterate it (Jacobi-style: use the previous round's \(q_j\) values) until vectors stop moving. Each per-node problem is strictly convex, and the overall system is a linear system \(Aq=b\) with \(A\) diagonally dominant, so the Jacobi iteration is guaranteed to converge.

Convergence & Complexity

Faruqui et al. show 10 iterations suffice empirically. Each pass costs \(O(|E|\cdot d)\) — linear in the number of lexicon edges times embedding dimension — since only connected words are touched; words with no lexicon entry stay exactly at \(\hat q_i\).

⚠️ Common Pitfall

Retrofitting only helps words that appear in the lexicon graph — rare or domain-specific words absent from WordNet/PPDB are left completely untouched, so out-of-vocabulary-for-the-lexicon words see zero improvement. Also, if \(\beta_{ij}\) is set too large relative to \(\alpha_i\), the anchor term is overwhelmed and clustered words can collapse toward each other, discarding useful distributional information the original training captured.

Key Takeaways
▼

When to use retrofitting:

  • You already have pretrained embeddings (Word2Vec/GloVe/fastText) and can't afford to retrain
  • You have a curated relational resource — WordNet, PPDB, FrameNet, a medical/legal ontology — for your domain
  • Downstream tasks are sensitive to fine-grained lexical semantics: word similarity, synonym detection, sentiment lexicon expansion, QA

When NOT to use:

  • Your vocabulary has little overlap with any available lexicon (e.g. heavy slang, code-switched text, niche jargon)
  • You're already using contextual embeddings (BERT-style) where "one vector per word" doesn't apply the same way — retrofitting was designed for static embeddings
  • You need the absolute state of the art on word similarity — later work (e.g. counter-fitting, ATTRACT-REPEL) extends retrofitting with explicit antonym-repulsion terms and outperforms it
💡 Downstream Impact

Faruqui et al. (2015) showed retrofitted vectors improve word-similarity correlation (WS-353, MEN, SimLex-999) and downstream tasks like sentiment analysis and syntactic dependency parsing — all with a training-free, few-second post-processing step applied after any embedding algorithm finishes.

import numpy as np
from collections import defaultdict
# Q_hat: dict word -> pretrained vector (e.g. from GloVe)
# lexicon: dict word -> set of related words (from WordNet/PPDB)
def retrofit(Q_hat, lexicon, n_iter=10, alpha=1.0):
Q = {w: v.copy() for w, v in Q_hat.items()} # init at distributional vectors
for it in range(n_iter): # Jacobi sweeps
for word in Q_hat:
neighbors = lexicon.get(word, set()) & Q_hat.keys()
deg = len(neighbors)
if deg == 0:
continue # untouched: no lexicon entry
beta = 1.0 / deg # beta_ij = 1/deg(i), sums to 1
neighbor_sum = sum(Q[n] for n in neighbors) * beta
Q[word] = (alpha * Q_hat[word] + neighbor_sum) / (alpha + 1.0)
return Q
# --- usage ---
lexicon = defaultdict(set)
for syn_pair in wordnet_synonym_pairs:
w1, w2 = syn_pair
lexicon[w1].add(w2); lexicon[w2].add(w1) # undirected graph
Q_retrofitted = retrofit(glove_vectors, lexicon, n_iter=10, alpha=1.0)
