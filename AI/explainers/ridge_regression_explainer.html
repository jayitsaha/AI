1
Understanding Ridge Regression
▼

What is it? Ordinary Least Squares (OLS) finds coefficients that minimise prediction error with no constraints. When predictors are correlated or there are more features than samples, OLS coefficients can explode to very large values — fitting noise rather than signal. Ridge regression adds a penalty proportional to the squared magnitude of the coefficients, forcing them to stay small and well-behaved.

Analogy: Imagine you are fitting a map route between two cities. OLS lets you take wild detours to hit every data point perfectly. Ridge says: "Every extra kilometre of detour costs you. Find the route that balances fit quality against total distance travelled." Larger penalty \(\lambda\) means shorter permitted detours — smoother, more conservative paths.

💡 If you remember one thing

Ridge adds \(\lambda\|\beta\|_2^2\) to the OLS objective, giving the closed-form solution $$\hat{\beta}_\text{ridge} = (X^\top X + \lambda I)^{-1} X^\top y$$ Coefficients shrink smoothly toward zero as \(\lambda\) grows, but never reach exactly zero. This is the fundamental difference from Lasso (L1).

Prerequisites: Linear regression, matrix algebra (inverse, transpose), bias-variance tradeoff concept, eigenvalue decomposition basics.

2
How Ridge Works — Geometry and Mechanics
▼

The Regularised Objective

Ridge solves the penalised least-squares problem:

$$\hat{\beta}_\text{ridge} = \underset{\beta}{\operatorname{argmin}} \underbrace{\|y - X\beta\|_2^2}_{\text{RSS — fit}} + \lambda \underbrace{\|\beta\|_2^2}_{\text{L2 penalty}}$$

The parameter \(\lambda \geq 0\) controls the strength of regularisation. When \(\lambda = 0\) we recover OLS; as \(\lambda \to \infty\) all coefficients are driven to zero.

Constrained Interpretation (Lagrangian)

By duality, Ridge is equivalent to a constrained optimisation: minimise RSS subject to \(\|\beta\|_2^2 \leq t(\lambda)\). Geometrically, the L2 constraint is a sphere (ball) in coefficient space. The loss function \(\|y - X\beta\|_2^2\) has ellipsoidal level-sets (contours). Ridge finds where the smallest loss ellipse first touches the sphere — the unique tangent point. Because the ball is smooth and round, this contact point is almost never at a coordinate axis, so no coefficient is exactly zero.

🔑 Key Property: L2 Ball is Smooth

The L2 ball has no corners. The L1 ball (Lasso) has corners at axis-aligned points, so it naturally produces exact zeros. Ridge shrinks all coefficients proportionally, Lasso performs variable selection. Neither is universally better — Lasso for sparsity, Ridge for correlated predictors.

Closed-Form Solution via Calculus

Expanding the objective and differentiating with respect to \(\beta\):

$$\nabla_\beta \left[\|y - X\beta\|_2^2 + \lambda\|\beta\|_2^2\right] = -2X^\top(y - X\beta) + 2\lambda\beta = 0$$

Rearranging the normal equations:

$$(X^\top X + \lambda I)\hat{\beta}_\text{ridge} = X^\top y$$
$$\hat{\beta}_\text{ridge} = (X^\top X + \lambda I)^{-1} X^\top y$$

Adding \(\lambda I\) to \(X^\top X\) is crucial: it guarantees the matrix is strictly positive definite (eigenvalues all \(\geq \lambda > 0\)), making the inverse well-defined even when \(X^\top X\) is singular or near-singular due to multicollinearity.

SVD Interpretation: Differential Shrinkage

Let \(X = U\Sigma V^\top\) be the SVD. The ridge solution is:

$$\hat{\beta}_\text{ridge} = \sum_{j=1}^p \frac{d_j^2}{d_j^2 + \lambda}\, \frac{u_j^\top y}{d_j}\, v_j$$

where \(d_j\) are the singular values. Each principal component is shrunk by a factor \(d_j^2/(d_j^2+\lambda)\). Small singular values (near-collinear directions) are shrunk most aggressively, while large singular values (well-determined directions) are shrunk least. This is how Ridge controls multicollinearity.

In our numerical example with singular values \(d_1 = 7.92, d_2 = 2.19\), at \(\lambda = 2\): shrinkage factors are \(0.969\) and \(0.705\) — the near-collinear direction (small \(d_2\)) is shrunk 4× more than the dominant direction.

⚠️ Intercept Centering

In practice, the intercept is never penalised. Always centre \(y\) and standardise columns of \(X\) before fitting; the intercept is estimated as \(\hat{\beta}_0 = \bar{y}\). sklearn's Ridge does this automatically when fit_intercept=True.

Bias-Variance Tradeoff — The Math
▼

Bias of the Ridge Estimator

Under the true model \(y = X\beta^* + \varepsilon\), \(\varepsilon \sim (0, \sigma^2 I)\):

$$\mathbb{E}[\hat{\beta}_\text{ridge}] = (X^\top X + \lambda I)^{-1} X^\top X\, \beta^*$$

Unless \(\lambda = 0\), this is not \(\beta^*\), so Ridge is biased. The bias vector is:

$$\text{Bias}(\hat{\beta}_\text{ridge}) = -\lambda(X^\top X + \lambda I)^{-1}\beta^*$$

Bias grows linearly with \(\lambda\). As \(\lambda \to 0\), bias \(\to 0\). As \(\lambda \to \infty\), the estimator collapses to \(\hat{\beta} \to 0\), maximum bias equal to \(\|\beta^*\|_2\).

Variance of the Ridge Estimator

$$\operatorname{Var}(\hat{\beta}_\text{ridge}) = \sigma^2 (X^\top X + \lambda I)^{-1} X^\top X (X^\top X + \lambda I)^{-1}$$

Because the eigenvalues of \((X^\top X + \lambda I)^{-1}\) are \(1/(d_j^2 + \lambda)\), which decrease as \(\lambda\) grows, the variance decreases monotonically with \(\lambda\). When \(X^\top X\) has tiny eigenvalues (multicollinearity), OLS variance is enormous; Ridge brings it under control at the cost of introducing bias.

Mean Squared Error Decomposition

$$\text{MSE}(\hat{\beta}_\text{ridge}) = \underbrace{\|\text{Bias}\|^2}_{\uparrow \text{ with } \lambda} + \underbrace{\operatorname{tr}(\text{Var})}_{\downarrow \text{ with } \lambda}$$

There exists an optimal \(\lambda^* > 0\) that minimises the total MSE whenever \(X^\top X\) is not full rank or is ill-conditioned. This is the formal justification for Ridge: a small amount of bias can substantially reduce variance, lowering total error.

📐 The Ridge Trace

A ridge trace plots each \(\hat{\beta}_j(\lambda)\) against \(\log \lambda\). All coefficients shrink toward zero as \(\lambda\) grows. The point where the curves "stabilise" (stop changing rapidly) is often a good choice of \(\lambda\). Formally, select \(\lambda\) by cross-validation or by the GCV criterion.

Degrees of Freedom

Ridge reduces the effective degrees of freedom compared to OLS. The hat matrix (projection onto predictions) is \(H_\lambda = X(X^\top X + \lambda I)^{-1}X^\top\), and the effective degrees of freedom are:

$$\text{df}(\lambda) = \operatorname{tr}(H_\lambda) = \sum_{j=1}^p \frac{d_j^2}{d_j^2 + \lambda} \leq p$$

When \(\lambda = 0\), \(\text{df} = p\) (full OLS). As \(\lambda \to \infty\), \(\text{df} \to 0\).

🚨 No Feature Selection

Ridge never sets any coefficient exactly to zero. All \(p\) predictors remain in the model. If you need automatic feature selection, use Lasso (\(\|\beta\|_1\) penalty) or Elastic Net. Ridge is best when you believe most predictors are relevant but may be correlated.

Key Takeaways
▼

When to use Ridge

  • Multicollinear predictors (correlated features), where OLS coefficients are unstable
  • High-dimensional settings (\(p\) close to or exceeding \(n\)) — Ridge keeps the problem invertible
  • You believe most features are relevant (ridge shrinks all, Lasso zeros many)
  • You need a numerically stable closed-form solution with fast training

When NOT to use Ridge

  • You need automatic feature selection — use Lasso or Elastic Net instead
  • Errors have a known non-identity covariance (use GLS or WLS)
  • The model is misspecified (adding \(\lambda I\) does not fix structural issues)
MethodPenaltyZeros?Best when
OLSNone—n ≫ p, no multicollinearity

💡 Practical Rule

Always choose \(\lambda\) via cross-validation. In sklearn, use RidgeCV(alphas=np.logspace(-3,3,100)) — it fits efficiently using the SVD and selects \(\lambda\) by leave-one-out CV in \(O(pn^2)\) time without re-fitting.

Code Trace
▼
import numpy as np
from sklearn.linear_model import Ridge, RidgeCV
# ── From Scratch ──────────────────────────────────────
def ridge_fit(X, y, lam):
"""Closed-form: β̂ = (X'X + λI)⁻¹ X'y"""
n, p = X.shape
A = X.T @ X + lam * np.eye(p) # Add λI to X'X
b = X.T @ y # Right-hand side
return np.linalg.solve(A, b) # More stable than explicit inverse
# ── SVD-based (numerically preferred) ─────────────────
def ridge_svd(X, y, lam):
U, s, Vt = np.linalg.svd(X, full_matrices=False)
d = s**2 / (s**2 + lam) # Shrinkage factors
return Vt.T @ np.diag(d/s) @ U.T @ y
# ── Bias-variance example ─────────────────────────────
np.random.seed(42)
n, p = 20, 3
X = np.random.randn(n, p)
X[:,1] = 0.8*X[:,0] + 0.6*X[:,1] # Introduce collinearity
y = X @ [3.0, -2.0, 1.5] + 0.5 * np.random.randn(n)
# Ridge trace: sweep λ
lambdas = np.logspace(-2, 3, 200)
traces = np.array([ridge_fit(X, y, lam) for lam in lambdas])
print(f'OLS: {ridge_fit(X, y, 0.0001)}')
print(f'Ridge(1): {ridge_fit(X, y, 1.0)}')
print(f'Ridge(10):{ridge_fit(X, y, 10.0)}')
# ── Production: sklearn with CV ───────────────────────
clf = RidgeCV(alphas=np.logspace(-3, 3, 100), cv=5)
clf.fit(X, y)
print(f'Best alpha: {clf.alpha_:.4f}')
print(f'Coefficients: {clf.coef_}')
# ⚠️ Note: sklearn calls lambda "alpha"
