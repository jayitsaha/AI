SigLIP: Sigmoid Loss for Language-Image Pretraining

A simple, effective alternative to contrastive loss for vision-language models
Intermediate Deep Learning Vision-Language O(N) loss cost
1
Understanding SigLIP
▼

What is it? SigLIP (Sigmoid Loss for Language-Image Pretraining) is an alternative training objective for learning joint image and text embeddings, similar to CLIP. While CLIP uses a contrastive (InfoNCE) loss that compares positive pairs against a batch of negatives, SigLIP uses a simple sigmoid cross-entropy loss that treats each (image, text) pair independently. This means it doesn't rely on in-batch negatives or require careful temperature tuning, leading to a more robust and scalable training process.

Analogy: Imagine you're grading essays (text) based on how well they describe a picture (image).
CLIP-style: You take one picture and one essay, then compare that essay's quality to all other essays in the stack for that picture. Then you do the same for all other pictures against that one essay. It's a ranking game: "This essay is better for *this* picture than *those* other essays are."
SigLIP-style: You take one picture and one essay. You simply ask: "Does this essay describe this picture well? Yes/No." You score each pair independently, without comparing it to other pairs in the batch. It's a binary prediction for each pair: "Is this a good match?"

💡 If you remember one thing

SigLIP replaces the global softmax normalization of contrastive loss with independent sigmoid activations for each (image, text) similarity score. This simplifies training by eliminating batch-size dependencies and the need for a temperature parameter, while maintaining competitive performance.

2
How It Works Internally
▼

Contrastive Loss (CLIP-style)

In CLIP, given a batch of \(N\) (image, text) pairs \((I_i, T_i)\), we compute a similarity matrix \(S \in \mathbb{R}^{N \times N}\) where \(S_{ij} = \operatorname{sim}(I_i, T_j)\). The goal is to maximize \(S_{ii}\) (positive pairs) and minimize \(S_{ij}\) for \(i \neq j\) (negative pairs). This is achieved using InfoNCE loss, which is a symmetric cross-entropy over softmax probabilities:

$$L_{\text{CLIP}} = -\frac{1}{N} \sum_{i=1}^N \left[ \log \frac{e^{S_{ii}/\tau}}{\sum_{k=1}^N e^{S_{ik}/\tau}} + \log \frac{e^{S_{ii}/\tau}}{\sum_{k=1}^N e^{S_{ki}/\tau}} \right]$$

Here, \(\tau\) is a learnable temperature parameter. The denominators \(\sum e^{S_{ik}/\tau}\) and \(\sum e^{S_{ki}/\tau}\) aggregate information from all other samples in the batch, acting as "in-batch negatives." A high similarity with a negative pair (a "hard negative") can drastically reduce the probability of the positive pair.

Sigmoid Loss (SigLIP-style)

SigLIP also computes the similarity matrix \(S\). However, instead of a global softmax, it applies a sigmoid function to each similarity score independently. For each pair \((I_i, T_j)\), we define a binary label \(y_{ij}\) where \(y_{ij}=1\) for positive pairs (\(i=j\)) and \(y_{ij}=0\) for negative pairs (\(i \neq j\)). The loss for a single pair is then:

$$L_{ij} = - \left[ y_{ij} \log \sigma(S_{ij}) + (1-y_{ij}) \log (1-\sigma(S_{ij})) \right]$$

The total loss is simply the sum (or average) over all pairs in the batch, including both positive and negative pairs. This decouples the learning of each pair's score, making it robust to batch size and removing the need for a temperature parameter.

Advantages and Considerations

  • No Batch Size Dependency: Unlike InfoNCE, where the quality of negatives depends on batch size, SigLIP's loss is computed per pair, making it more stable across different batch sizes.
  • No Temperature Parameter: The sigmoid function inherently provides a "squashing" effect, obviating the need for a learnable temperature \(\tau\).
  • Robust to Hard Negatives: A hard negative (high \(S_{ij}\) for \(i \neq j\)) increases its own loss term, but does not directly "pull down" the positive probabilities of other pairs via a shared denominator.
  • Explicit Negative Sampling: While in-batch negatives are implicitly handled by \(y_{ij}=0\) for \(i \neq j\), SigLIP can benefit from additional explicit negative sampling strategies if desired, to ensure a diverse set of challenging negatives.
🔑 Key Property

SigLIP's core idea is to replace the relative ranking objective (softmax-based) with an absolute scoring objective (sigmoid-based). Each pair's match quality is judged on its own merits, rather than in competition with other pairs in the current batch.

3
Why It Works — The Math
▼

Contrastive Loss (InfoNCE) Gradients

Consider the gradient of the InfoNCE loss with respect to a positive similarity \(S_{ii}\) and a negative similarity \(S_{ij}\) (for a fixed image \(I_i\), varying text embeddings \(T_j\)). The gradient for \(S_{ii}\) is roughly \(\frac{\partial L}{\partial S_{ii}} = P(T_i|I_i) - 1\), and for \(S_{ij}\) it's \(\frac{\partial L}{\partial S_{ij}} = P(T_j|I_i)\). This means InfoNCE creates a "push-pull" dynamic:

$$\frac{\partial L}{\partial S_{ii}} = \frac{e^{S_{ii}/\tau}}{\sum_{k} e^{S_{ik}/\tau}} - 1 \quad \text{and} \quad \frac{\partial L}{\partial S_{ij}} = \frac{e^{S_{ij}/\tau}}{\sum_{k} e^{S_{ik}/\tau}}$$

The positive similarity \(S_{ii}\) is pushed up (gradient \(<0\)) while all negative similarities \(S_{ik}\) are pushed down (gradient \(>0\)). Crucially, these gradients are coupled through the sum in the denominator: improving one negative's score (e.g., \(S_{ik}\)) affects the gradients of *all* other similarities in that row/column.

Sigmoid Loss Gradients

For sigmoid cross-entropy, the gradient with respect to any similarity \(S_{ij}\) is simply the difference between the predicted probability and the true label:

$$\frac{\partial L_{ij}}{\partial S_{ij}} = \sigma(S_{ij}) - y_{ij}$$

If \((I_i, T_j)\) is a positive pair (\(y_{ij}=1\)), the gradient is \(\sigma(S_{ij}) - 1\), which is negative, pushing \(S_{ij}\) up towards a high score. If it's a negative pair (\(y_{ij}=0\)), the gradient is \(\sigma(S_{ij})\), which is positive, pushing \(S_{ij}\) down towards a low score. The key difference:

$$\frac{\partial L_{\text{SigLIP}}}{\partial S_{ij}} = \sum_{k,l} (\sigma(S_{kl}) - y_{kl}) \cdot \frac{\partial S_{kl}}{\partial S_{ij}} = \sigma(S_{ij}) - y_{ij}$$

Each gradient \(\frac{\partial L}{\partial S_{ij}}\) depends *only* on \(S_{ij}\) and its label \(y_{ij}\), not on any other similarities in the batch. This means the learning for each pair is independent. A hard negative \(S_{ij}\) (high score for \(y_{ij}=0\)) will incur a large loss and a strong gradient to push it down, but it won't distort the gradients for other positive pairs.

⚠️ Sampling & Scaling Considerations

While SigLIP simplifies the loss, it still relies on good data. If the dataset's "negative" examples are too easy, the model might not learn to distinguish fine-grained differences. Additionally, SigLIP often uses a fixed scaling factor (e.g., 20) for the similarity scores, \(S_{ij} = \alpha \cdot \operatorname{sim}(I_i, T_j)\), to ensure the sigmoid operates in a useful range. This is akin to a fixed temperature, but applied to the inputs of the sigmoid directly.

Key Takeaways
▼

When to choose SigLIP:

  • When training large-scale vision-language models where batch size can vary or be limited (e.g., due to memory constraints).
  • If you want to avoid tuning a temperature parameter (\(\tau\)) or managing its interaction with optimization.
  • To simplify the loss landscape and potentially improve training stability, especially when dealing with ambiguous or noisy negative samples.
  • As a strong baseline that is conceptually simpler and often performs comparably to InfoNCE-based methods.

When CLIP (InfoNCE) might be preferred:

  • If the dataset naturally benefits from explicit ranking and competitive learning among in-batch samples.
  • For specific tasks where a strong "push-pull" dynamic is empirically found to be more effective.
  • When fine-tuning existing CLIP models, as maintaining the original loss might be beneficial.
💡 Big Picture

SigLIP demonstrates that a simpler, decoupled loss function can achieve state-of-the-art performance in vision-language pretraining. It highlights a recurring theme in ML: sometimes, reducing complexity and making assumptions about independence can lead to more robust and scalable systems, even if the underlying problem is inherently about relationships.

Code Trace (PyTorch-style)
▼
import torch
import torch.nn.functional as F
# Assume image_embeds (N, D) and text_embeds (N, D)
# N is batch size, D is embedding dimension
# We assume (image_embeds[i], text_embeds[i]) are positive pairs
def calculate_similarities(image_embeds, text_embeds, scale_factor=None):
# Normalize embeddings to unit length
image_embeds = F.normalize(image_embeds, p=2, dim=1)
text_embeds = F.normalize(text_embeds, p=2, dim=1)
# Compute cosine similarities (dot product for normalized vectors)
similarity_matrix = torch.matmul(image_embeds, text_embeds.T)
if scale_factor is not None:
similarity_matrix = similarity_matrix * scale_factor
return similarity_matrix
def clip_loss(similarity_matrix, temperature):
N = similarity_matrix.shape[0]
# Image-to-text loss
i2t_logits = similarity_matrix / temperature
i2t_labels = torch.arange(N, device=i2t_logits.device)
loss_i = F.cross_entropy(i2t_logits, i2t_labels)
# Text-to-image loss
t2i_logits = similarity_matrix.T / temperature
t2i_labels = torch.arange(N, device=t2i_logits.device)
loss_t = F.cross_entropy(t2i_logits, t2i_labels)
return (loss_i + loss_t) / 2
def siglip_loss(similarity_matrix):
# Create labels: 1 for positives (diagonal), 0 for negatives
labels = torch.eye(similarity_matrix.shape[0], device=similarity_matrix.device)
# Sigmoid cross-entropy loss applied to each element
loss = F.binary_cross_entropy_with_logits(similarity_matrix, labels)
return loss
