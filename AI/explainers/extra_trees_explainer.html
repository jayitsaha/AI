Push randomization beyond Random Forests — random thresholds, no bootstrap, faster training
Intermediate Classical ML Ensemble Methods O(n·p) per split
1
Understanding Extra-Trees
▼

What is it? Extra-Trees (Extremely Randomized Trees) is an ensemble learning algorithm that builds many decision trees, but with a twist: instead of searching for the best threshold to split on, it picks a random threshold. This extra dose of randomness makes the trees more decorrelated than Random Forest, which typically leads to lower variance at the cost of a small increase in bias.

Analogy: Imagine hiring 100 consultants to estimate house prices. In Random Forest, each consultant sees a random subset of houses and, for each feature (e.g., area), carefully searches for the most predictive cutoff (e.g., "houses above 2,400 sq ft tend to cost more"). In Extra-Trees, each consultant still sees a random subset of features, but picks the cutoff blindly at random (e.g., "I'll split at 1,850 sq ft — I didn't even check if it's optimal"). Individually, each Extra-Trees consultant is sloppier — but because they all use different random cuts, their predictions are far less correlated. When you average 100 uncorrelated guesses, the noise cancels out even better than with RF.

💡 If you remember one thing

Extra-Trees randomizes BOTH the feature subset (like RF) AND the split threshold (unlike RF). This makes trees more decorrelated → lower variance → often better generalization. It's also faster: no threshold search means \(O(n \cdot K)\) per node instead of \(O(n \cdot K \log n)\).

2
How Extra-Trees Works Internally
▼

The Three Key Differences from Random Forest

Extra-Trees (Geurts et al., 2006) differs from Random Forest in two algorithmic choices and one optional one:

  1. Random thresholds (mandatory): For each candidate feature, RF searches all \(n-1\) possible midpoint thresholds and picks the one minimizing Gini/entropy. Extra-Trees draws ONE random threshold uniformly from the feature's observed range \([\min(x_j), \max(x_j)]\) and uses it directly.
  2. No bootstrap sampling (default): RF trains each tree on a bootstrap sample (≈63.2% unique points). Extra-Trees uses the entire training set for each tree by default. This reduces bias but means the decorrelation comes entirely from the random thresholds.
  3. Feature subsampling (shared with RF): Both sample \(K\) features at each node (\(K = \sqrt{p}\) for classification, \(K = p/3\) for regression by default).

Each tree in the ensemble gets different random thresholds → highly decorrelated predictions → averaging them cancels noise effectively.

🔑 Key Invariant

The best split threshold is selected from \(K\) randomly generated candidate (feature, threshold) pairs. The pair with the highest Gini gain among the \(K\) random candidates wins — still greedy among the random candidates, just not over all possible thresholds.

3
The Math: Gini, Variance Reduction & Decorrelation
▼

Split Criterion

For a node with sample set \(S\), the Gini impurity is:

$$G(S) = \sum_{c=1}^{C} p_c (1 - p_c) = 1 - \sum_{c=1}^{C} p_c^2$$

where \(p_c = |S_c| / |S|\) is the fraction of class \(c\). The Gini gain of threshold \(t\) on feature \(j\) is:

$$\Delta G(j, t) = G(S) - \frac{|S_L|}{|S|} G(S_L) - \frac{|S_R|}{|S|} G(S_R)$$

where \(S_L = \{x \in S : x_j \le t\}\) and \(S_R = S \setminus S_L\).

Extra-Trees Split Rule

At each node, Extra-Trees draws \(K\) random (feature, threshold) pairs. For each candidate feature \(j_k\), the threshold \(t_k\) is drawn uniformly:

$$t_k \sim \mathcal{U}\!\left(\min_{x \in S} x_{j_k},\ \max_{x \in S} x_{j_k}\right)$$

The split with highest \(\Delta G(j_k, t_k)\) among the \(K\) candidates is selected:

$$(j^*, t^*) = \underset{k=1,\ldots,K}{\operatorname{argmax}}\ \Delta G(j_k, t_k)$$

Why Random Thresholds Reduce Variance

Consider the ensemble prediction \(\hat{f}(x) = \frac{1}{B} \sum_{b=1}^{B} h_b(x)\). The MSE of the ensemble decomposes as:

$$\operatorname{MSE} = \operatorname{Bias}^2 + \operatorname{Variance} = \operatorname{Bias}^2 + \frac{\rho \sigma^2 + (1-\rho)\sigma^2}{B}$$

More precisely, if each tree has variance \(\sigma^2\) and pairwise correlation \(\rho\):

$$\operatorname{Var}[\hat{f}] = \rho \sigma^2 + \frac{1 - \rho}{B} \sigma^2$$

As \(B \to \infty\), this approaches \(\rho \sigma^2\). Extra-Trees lowers \(\rho\) by injecting random thresholds, at the cost of slightly raising \(\sigma^2\) (each tree is a worse fit). If the reduction in \(\rho\) dominates, total variance falls.

📐 Bias-Variance Tradeoff

Extra-Trees vs RF: Extra-Trees has lower inter-tree correlation \(\rho\) (random thresholds) but higher per-tree variance \(\sigma^2\) (suboptimal splits). No bootstrap → slightly lower bias than RF (all data used). Net result: typically comparable or better generalization at faster training speed.

⚠️ Common Misconception

Extra-Trees does NOT just pick any random split. It still evaluates \(K\) (feature, threshold) pairs and picks the best among those candidates using Gini/MSE. With \(K = p\) (all features, random thresholds), you still have greedy selection over random proposals — this is what "extremely randomized" means, not "completely random".

From Scratch — Extra-Trees Split in NumPy

import numpy as np
def gini_impurity(y):
"""Gini = 1 - sum(p_c^2). Returns 0 for pure node."""
if len(y) == 0: return 0.0
_, counts = np.unique(y, return_counts=True)
p = counts / len(y)
return 1.0 - np.sum(p ** 2)
def extra_trees_split(X, y, K=None):
"""Find best (feature, threshold) pair using ET's random-threshold rule."""
n, p = X.shape
if K is None: K = max(1, int(np.sqrt(p))) # default for classification
parent_gini = gini_impurity(y)
best_gain, best_feat, best_thresh = -np.inf, None, None
# Sample K random features WITHOUT replacement
features = np.random.choice(p, size=K, replace=False)
for j in features:
x_j = X[:, j]
lo, hi = x_j.min(), x_j.max()
if lo == hi: continue # constant feature, skip
# KEY DIFFERENCE: draw ONE random threshold in [min, max]
t = np.random.uniform(lo, hi) # ← ET's randomness
# RF would do: for t in sorted(unique midpoints): ...search all...
left_mask = x_j <= t
y_left, y_right = y[left_mask], y[~left_mask]
gain = parent_gini - (len(y_left)/n)*gini_impurity(y_left) \
- (len(y_right)/n)*gini_impurity(y_right)
if gain > best_gain:
best_gain, best_feat, best_thresh = gain, j, t
return best_feat, best_thresh, best_gain

Production Usage — scikit-learn ExtraTreesClassifier

from sklearn.ensemble import ExtraTreesClassifier, RandomForestClassifier
from sklearn.datasets import make_classification
from sklearn.model_selection import cross_val_score
import numpy as np
X, y = make_classification(n_samples=1000, n_features=20, random_state=42)
et = ExtraTreesClassifier(
n_estimators=100, # number of trees
max_features='sqrt', # K = sqrt(p) features per split
bootstrap=False, # ← no bootstrap (ET default)
max_depth=None, # grow fully by default
min_samples_split=2, # stop splitting < 2 samples
n_jobs=-1, # use all CPU cores
random_state=42,
)
rf = RandomForestClassifier(n_estimators=100, random_state=42, n_jobs=-1)
et_scores = cross_val_score(et, X, y, cv=5)
rf_scores = cross_val_score(rf, X, y, cv=5)
print(f"ET: {et_scores.mean():.4f} ± {et_scores.std():.4f}")
print(f"RF: {rf_scores.mean():.4f} ± {rf_scores.std():.4f}")
# ⚠️ Gotcha: bootstrap=True is NOT the default for ET (unlike RF)
# ⚠️ Gotcha: ET can be faster than RF but may need more trees for same accuracy
# Feature importance is available, but MORE biased toward high-cardinality features
print(et.feature_importances_)
⚠️ Key Gotchas

1. bootstrap=False by default: Unlike RF, ET uses the full training set for each tree. This is a feature, not a bug — but it means no out-of-bag (OOB) error estimate is available unless you set bootstrap=True.
2. Noisy features hurt ET more: Random thresholds are sampled from the feature's observed range. If a feature is pure noise, ET will still occasionally find a "lucky" random threshold that looks informative — increasing the feature's apparent importance.
3. Not always better: If the dataset has very smooth, regular decision boundaries (e.g., linear separability), RF's optimal thresholds beat ET's random ones. ET shines in high-noise, high-dimensional settings.

🎯 Decision Guide

Use Extra-Trees when: You have high-dimensional data with many features, training speed matters, the data is noisy (random thresholds are less overfit to noise), or you're using it as a fast feature-importance screen before a heavier model.

Prefer Random Forest when: You need OOB error estimates, the decision boundary is regular (optimal thresholds help), or interpretability via partial dependence matters.

Prefer Gradient Boosting (XGBoost/LightGBM) when: You need maximum accuracy on tabular data and training time is less of a concern.
