FID, IS, KID, Precision/Recall, LPIPS — measuring the quality and diversity of generative models
Intermediate Deep Learning Generative AI O(N) to O(N²)
1
Understanding GAN Evaluation
▼

What is it? Generative Adversarial Networks (GANs) are powerful models that learn to create new data (e.g., images) that mimic a training distribution. But how do we know if a GAN is "good"? Visual inspection is subjective and unreliable. GAN evaluation metrics provide objective, quantitative ways to measure two key aspects:

  • Fidelity (or Quality): How realistic are the generated samples? Do they look like real data?
  • Diversity (or Coverage): Does the GAN generate a wide variety of samples, covering all modes of the real data distribution, or does it suffer from "mode collapse" (generating only a limited subset)?

Analogy: Imagine a master art forger. Fidelity is how well their forged paintings pass for originals (are they realistic?). Diversity is whether they can forge paintings in *all* styles and subjects of the original artist, or if they only stick to one type of painting (mode collapse). GAN evaluation metrics are the art critics' tools to objectively score the forger's skill.

💡 If you remember one thing

Most modern GAN metrics operate not on raw pixels, but on high-level feature embeddings (e.g., from an Inception v3 network pre-trained on ImageNet). This is because feature space distances correlate better with human perception and are more robust than pixel-level comparisons.

2
How Key Metrics Work Internally
▼

All metrics start by extracting feature vectors for a large set of real images (\(X_r\)) and generated images (\(X_g\)) using a pre-trained deep network (the "feature extractor," commonly Inception v3). Let these feature sets be \(\mathcal{F}_r\) and \(\mathcal{F}_g\).

Fréchet Inception Distance (FID)

FID models the distribution of features \(\mathcal{F}_r\) and \(\mathcal{F}_g\) as multivariate Gaussians. It then calculates the Fréchet distance (or Wasserstein-2 distance) between these two Gaussians. A lower FID score indicates better quality and diversity, as it implies the generated distribution is closer to the real one.

Inception Score (IS)

IS measures two things: (1) how "clear" (recognizable) are the generated images, and (2) how "diverse" are they. It uses a pre-trained Inception classifier to predict class labels for generated images. High clarity means low entropy in \(p(y|x)\) (a generated image \(x\) clearly belongs to one class \(y\)). High diversity means high entropy in \(p(y)\) (the marginal distribution of predicted classes is uniform across many classes). These two are combined into a single score.

Kernel Inception Distance (KID)

KID is similar to FID but uses a polynomial kernel to compare the two feature distributions. Instead of assuming Gaussianity, it computes the Maximum Mean Discrepancy (MMD) between \(\mathcal{F}_r\) and \(\mathcal{F}_g\). KID is often considered more robust than FID, especially with small sample sizes, as it is less sensitive to outliers and can provide a more stable estimate of similarity.

Precision and Recall for GANs

These metrics adapt the classic classification concepts. They define "real" and "generated" feature manifolds (or regions) and measure:

  • Precision: What percentage of generated samples are "real-like" (i.e., fall into the real feature manifold)? High precision means good fidelity.
  • Recall: What percentage of the real feature manifold is covered by generated samples? High recall means good diversity (no mode collapse).

Unlike FID/IS/KID, Precision and Recall are separate scores, offering a clearer picture of the fidelity-diversity trade-off.

Learned Perceptual Image Patch Similarity (LPIPS)

LPIPS is a perceptual distance metric used to quantify how similar two images are, according to a deep neural network (often a pre-trained VGG or AlexNet). Unlike the other metrics which compare distributions, LPIPS is primarily a per-image metric. It's used to measure diversity by computing the average pairwise LPIPS distance between generated images, or to assess image reconstruction quality. A lower LPIPS means images are perceptually more similar.

🔑 Key Property

All these metrics are proxy measures. They don't directly tell you if a human finds an image beautiful or useful. Instead, they quantify similarity/diversity in a learned feature space, which has been shown to correlate well with human judgment for many tasks.

3
Why It Works — The Math Behind The Metrics
▼

Fréchet Inception Distance (FID)

If we model the \(d\)-dimensional Inception features of real images (\(X_r\)) as a Gaussian \(\mathcal{N}(\mu_r, \Sigma_r)\) and generated images (\(X_g\)) as \(\mathcal{N}(\mu_g, \Sigma_g)\), the FID score is:

$$FID = \|\mu_r - \mu_g\|_2^2 + \text{Tr}(\Sigma_r + \Sigma_g - 2(\Sigma_r \Sigma_g)^{1/2})$$

The first term, \(\|\mu_r - \mu_g\|_2^2\), measures the squared Euclidean distance between the means of the feature distributions. This captures fidelity (how close the average generated image is to the average real image). The second term, involving the trace and matrix square root, accounts for the covariance structure, reflecting both fidelity and diversity (how similar are the shapes and orientations of the distributions).

Inception Score (IS)

The Inception Score is defined using the conditional class probability \(p(y|x)\) (from a pre-trained Inception classifier for a generated image \(x\)) and the marginal class probability \(p(y)\) (averaged over all generated images):

$$IS = \exp\left(\mathbb{E}_{x \sim X_g} \left[ D_{KL}(p(y|x) \,||\, p(y)) \right]\right)$$

Here, \(D_{KL}\) is the Kullback-Leibler divergence. A high IS implies two things: (1) for each generated image \(x\), \(p(y|x)\) has low entropy (it strongly predicts a single class, indicating clarity/quality), and (2) \(p(y)\) has high entropy (the generated images span many classes, indicating diversity). The exponential makes the score more interpretable.

Precision and Recall for GANs

These metrics rely on defining "manifolds" or neighborhoods in feature space. Let \(M_r\) be the manifold of real features and \(M_g\) be the manifold of generated features. Precision and Recall are then defined based on how samples from one distribution fall into the manifold of the other:

$$Precision = \frac{\text{Number of } x_g \in \mathcal{F}_g \text{ that are in } M_r}{\text{Total number of } x_g \in \mathcal{F}_g}$$ $$Recall = \frac{\text{Number of } x_r \in \mathcal{F}_r \text{ that are covered by } M_g}{\text{Total number of } x_r \in \mathcal{F}_r}$$

In practice, \(M_r\) and \(M_g\) are often approximated by taking the \(k\)-nearest neighbors of each feature vector and forming a "ball" around it. High precision means generated samples are realistic; high recall means the GAN covers the full variety of real samples, avoiding mode collapse.

⚠️ Metric Limitations

No single metric is perfect. FID can be sensitive to sample size. IS doesn't directly compare to real data. All metrics rely on the quality of the feature extractor (Inception v3), which might not generalize perfectly to all datasets or human perception. It's best practice to use a combination of metrics.

When to use which metric:

  • FID/KID: Your primary go-to for overall GAN performance. Use KID if sample sizes are small.
  • IS: Useful for quick checks of generated image quality and diversity, especially during early development.
  • Precision/Recall: When you need to disentangle fidelity from diversity, or diagnose mode collapse vs. poor quality.
  • LPIPS: For fine-grained perceptual comparison, e.g., in image-to-image translation or assessing diversity by pairwise distances.

General advice:

  • Always report multiple metrics.
  • Ensure sufficient sample sizes (e.g., 10k+ images for FID).
  • Use consistent feature extractors and implementations for fair comparison.
💡 The Future

New generative models (like Diffusion Models) often achieve much better scores than GANs on these metrics. However, the underlying principles of comparing feature distributions for fidelity and diversity remain essential for evaluating any generative model.

import numpy as np
from scipy.linalg import sqrtm
from sklearn.metrics.pairwise import polynomial_kernel
from scipy.stats import entropy
from sklearn.neighbors import NearestNeighbors
# Assume 'feature_extractor' is an InceptionV3 model
# X_real: N_r x D features, X_gen: N_g x D features
def calculate_fid(X_real, X_gen):
mu_real, sigma_real = np.mean(X_real, axis=0), np.cov(X_real, rowvar=False)
mu_gen, sigma_gen = np.mean(X_gen, axis=0), np.cov(X_gen, rowvar=False)
# Squared Euclidean distance between means
ssdiff = np.sum((mu_real - mu_gen)**2)
# Trace term: Tr(Sigma_r + Sigma_g - 2 * sqrtm(Sigma_r @ Sigma_g))
covmean = sqrtm(sigma_real @ sigma_gen)
if np.iscomplexobj(covmean): # Handle potential complex results
covmean = covmean.real
fid = ssdiff + np.trace(sigma_real + sigma_gen - 2 * covmean)
return fid
def calculate_is(X_gen, inception_model):
# inception_model outputs p(y|x) for each generated image x
# This is a simplified conceptual example; real IS needs raw images
p_y_given_x = inception_model.predict_proba(X_gen) # N_g x C
p_y = np.mean(p_y_given_x, axis=0) # C
kl_divergences = []
for i in range(X_gen.shape[0]):
kl_divergences.append(entropy(p_y_given_x[i], p_y))
is_score = np.exp(np.mean(kl_divergences))
return is_score
def calculate_kid(X_real, X_gen, degree=3, gamma=None, coef0=1):
# MMD^2 estimate with polynomial kernel
K_rr = polynomial_kernel(X_real, X_real, degree=degree, gamma=gamma, coef0=coef0)
K_gg = polynomial_kernel(X_gen, X_gen, degree=degree, gamma=gamma, coef0=coef0)
K_rg = polynomial_kernel(X_real, X_gen, degree=degree, gamma=gamma, coef0=coef0)
m = X_real.shape[0]; n = X_gen.shape[0]
kid = (np.sum(K_rr) - m) / (m * (m-1)) + \
(np.sum(K_gg) - n) / (n * (n-1)) - \
2 * np.sum(K_rg) / (m * n)
return kid
def calculate_precision_recall(X_real, X_gen, k_nn=3):
# For Precision: how many generated samples are 'real-like'?
nn_real = NearestNeighbors(n_neighbors=k_nn, algorithm='kd_tree').fit(X_real)
distances_gen_to_real, _ = nn_real.kneighbors(X_gen)
# Threshold: if average distance to k-NN is below a percentile of real distances
# Simplified: check if any real point is within 'epsilon' of gen point
# More robust: use a density estimation or manifold approximation
# This is a conceptual example for visualization
precision = np.mean(np.min(distances_gen_to_real, axis=1) < 0.5) # Simplified threshold
# For Recall: how many real samples are 'covered' by generated samples?
nn_gen = NearestNeighbors(n_neighbors=k_nn, algorithm='kd_tree').fit(X_gen)
distances_real_to_gen, _ = nn_gen.kneighbors(X_real)
recall = np.mean(np.min(distances_real_to_gen, axis=1) < 0.5) # Simplified threshold
return precision, recall
