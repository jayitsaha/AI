Understanding Matrix Factorization
▼

What is it? Basic matrix factorization is the core idea behind classic collaborative-filtering recommenders (think early Netflix Prize systems). You start with a huge, mostly-empty ratings matrix \(R\) — rows are users, columns are items, and most cells are unobserved because no user rates most items. The trick is to assume this matrix has low-rank structure: every user's taste and every item's character can be summarized by just a handful of numbers, called latent factors.

Analogy: Imagine describing a movie not by its title but by scores like "how much sci-fi," "how much romance," "how dark the tone is." Now describe a viewer the same way: "how much they like sci-fi," "how much they like romance," "how much they like dark tone." A viewer's predicted rating for a movie is just how well those two little profiles line up — computed with a dot product. Matrix factorization learns those hidden profiles directly from the ratings, without anyone ever labeling "sci-fi" or "romance" by hand.

💡 If you remember one thing

We factor the \(n\times m\) ratings matrix into two skinny matrices whose product approximates it: $$R \approx \hat R = PQ^\top, \qquad P\in\mathbb{R}^{n\times k},\; Q\in\mathbb{R}^{m\times k}$$ Each user gets a row of \(P\) (their latent taste vector), each item gets a row of \(Q\) (its latent trait vector), and \(k \ll n,m\) is a small number of factors. A single predicted rating is just \(\hat r_{ui} = p_u \cdot q_i^\top\).

How It Works Internally
▼

From a Sparse Matrix to Two Dense, Skinny Ones

\(R\) has \(n\) users and \(m\) items, but only a small known set \(\mathcal{K}\) of (user, item) pairs actually have ratings — everything else is "?". Instead of trying to fill in \(R\) directly, we posit two much smaller matrices: \(P\) (\(n \times k\)) holding one latent vector per user, and \(Q\) (\(m \times k\)) holding one latent vector per item, with \(k\) typically 2–200 (we'll use \(k=2\) so it's plottable). Both start as small random numbers.

Predicting a Rating: One Dot Product

To predict how user \(u\) would rate item \(i\), we take the dot product of their two latent vectors: $$\hat r_{ui} = p_u \cdot q_i^\top = \sum_{f=1}^{k} p_{uf}\,q_{if}$$ This is a multiply-accumulate over \(k\) terms — cheap, and exactly the operation a GPU does billions of times per second in a matmul.

Reconstructing Everything at Once

Doing that dot product for every user against every item simultaneously is nothing more than a matrix multiply: \(\hat R = PQ^\top\). Because \(P\) and \(Q\) are low-rank, \(\hat R\) is automatically a smooth, fully-dense approximation of \(R\) — including entries \(R\) never observed. Those newly-filled cells are exactly the recommendations.

🔑 Key Property

\(P\) and \(Q\) are learned jointly by fitting only the known ratings — nothing about genres, actors, or demographics is ever given to the model. Any structure in \(\hat R\) (e.g. two users clustering near each other) emerges purely from co-occurring rating patterns. This is why it's called "collaborative" filtering.

Why It Works — The Math
▼

The Regularized Objective

We only know the truth on \(\mathcal{K}\), so we minimize squared error there — plus an L2 penalty on the factors to avoid overfitting to the (often very few) ratings each user or item has:

$$J(P,Q) = \sum_{(u,i)\in\mathcal K}\big(r_{ui} - p_u q_i^\top\big)^2 \;+\; \lambda\Big(\sum_u \lVert p_u\rVert^2 + \sum_i \lVert q_i\rVert^2\Big)$$

This is not convex jointly in \((P,Q)\) — swapping \(P \to PT\), \(Q \to Q(T^{-1})^\top\) for any invertible \(T\) leaves \(\hat R\) unchanged, and the surface has many equally-good local minima. But it is convex in \(P\) alone (with \(Q\) fixed) and vice versa, which is exactly what makes it tractable.

Gradient Descent (SGD) Update Rule

Differentiate the squared-error term for one observed cell \((u,i)\) with error \(e_{ui}=r_{ui}-p_uq_i^\top\):

$$\frac{\partial e_{ui}^2}{\partial p_{uf}} = -2e_{ui}q_{if} + 2\lambda p_{uf} \;\;\Rightarrow\;\; p_{uf} \leftarrow p_{uf} + \eta\big(e_{ui}q_{if} - \lambda p_{uf}\big)$$

and symmetrically \(q_{if} \leftarrow q_{if} + \eta(e_{ui}p_{uf} - \lambda q_{if})\). Sweep over every known cell repeatedly (an epoch) and the loss decreases monotonically on average — this is exactly what the interactive walkthrough below computes live.

⚠️ Common Pitfall

Because the objective is non-convex, initialization and learning rate matter — a bad start can land in a poor local minimum. Also beware cold start: a brand-new user or item with zero known ratings has no gradient signal at all, so its factor vector never moves from its random initialization.

Key Takeaways
▼

When to use basic matrix factorization:

  • Large, sparse user-item interaction matrices (ratings, clicks, purchases)
  • You want compact, dense embeddings for users and items, not just a filled-in matrix
  • You need fast inference — once trained, a prediction is one dot product
  • As a strong, simple baseline before reaching for deep or hybrid recommenders

Limitations:

  • Cold start — new users/items with no ratings get no useful factors
  • Non-convex objective — sensitive to initialization, needs regularization tuning
  • Ignores side information (text, images, timestamps) unless extended (e.g. with biases, implicit feedback, or side-feature terms)
  • Static factors — doesn't capture that taste changes over time without extensions
💡 Hierarchy

SVD (exact, needs a fully-observed or mean-imputed matrix) → Basic MF via SGD/ALS (handles missing entries directly, this page) → Regularized MF with biases (adds per-user/item offsets) → Neural / deep MF (replaces the dot product with a learned similarity function). Each step relaxes an assumption of the previous one.

Code Trace
▼
import numpy as np
# Ratings matrix, NaN = unknown
R = np.array([[5, 3, np.nan, 1],
[4, np.nan, np.nan, 1],
[1, 1, np.nan, 5],
[np.nan, np.nan, 5, 4]])
mask = ~np.isnan(R)
# k latent factors, small random init
k = 2
rng = np.random.default_rng(42)
P = rng.random((4, k)) * 0.5 + 0.1 # users
Q = rng.random((4, k)) * 0.5 + 0.1 # items
# Predict one rating: dot product
r_hat_U1_I3 = P[0] @ Q[2]
# Reconstruct the full matrix
R_hat = P @ Q.T
# Training loop: SGD with L2 regularization
lr, reg, epochs = 0.05, 0.05, 300
for epoch in range(epochs):
for u, i in zip(*np.where(mask)):
err = R[u, i] - P[u] @ Q[i]
P[u] += lr * (err * Q[i] - reg * P[u])
Q[i] += lr * (err * P[u] - reg * Q[i])
R_hat = P @ Q.T
# Recommend: argmax(R_hat) among each user's unrated items
