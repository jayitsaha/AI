Gram Matrices & the Kernel Trick

From inner products to implicit feature maps — the algebraic heart of SVMs and kernel methods
Intermediate Linear Algebra Classical ML O(n²) kernel matrix
1
Understanding the Concept
▼

What is it? A Gram matrix records every pairwise inner product between a set of vectors: entry \(G_{ij} = \langle x_i, x_j \rangle\). It encodes the geometric relationships — angles, projections, and distances — of the entire dataset in a single \(n \times n\) matrix. The kernel trick generalises this: instead of computing inner products in the original space, you compute a kernel function \(K(x_i, x_j)\) that implicitly computes \(\langle \phi(x_i), \phi(x_j) \rangle\) in a (possibly infinite-dimensional) feature space, without ever computing \(\phi\).

Analogy: Imagine you want to know how similar every pair of songs in a playlist is. One way: convert each song to a 10 000-dimensional audio fingerprint vector, then compute dot products — expensive. The kernel way: use a similarity function (e.g., shared chord progressions) that gives the same answer as the dot product of those fingerprints, but runs 100× faster without constructing the fingerprints at all. That similarity function is the kernel.

Why does it matter? Many algorithms (SVMs, Gaussian processes, PCA, ridge regression) only ever need pairwise similarities, never individual \(\phi(x)\). Swapping the inner product for a kernel function instantly upgrades these algorithms to handle non-linear boundaries, text, graphs, and sequences — all without changing the algorithm's code.

💡 If you remember one thing

The Gram matrix \(G_{ij} = \langle x_i, x_j \rangle\) is always positive semi-definite (PSD). Every valid kernel function \(K(x_i,x_j)\) must produce a PSD matrix — this is Mercer's condition, and it guarantees the kernel corresponds to a real inner product in some feature space.

2
How It Works Internally
▼

Step 1 — Build the Gram Matrix

Given data \(X = [x_1, \ldots, x_n]^\top \in \mathbb{R}^{n \times d}\), the Gram matrix is:

$$G = X X^\top \in \mathbb{R}^{n \times n}, \qquad G_{ij} = x_i^\top x_j$$

The diagonal \(G_{ii} = \|x_i\|^2\) (squared norm), and off-diagonals measure cosine similarity up to normalisation. \(G\) is symmetric (\(G_{ij}=G_{ji}\)) and PSD: for any vector \(v\), \(v^\top G v = \|Xv^\top v\|^2 \ge 0\) — wait, more precisely \(v^\top G v = v^\top X X^\top v = \|X^\top v\|^2 \ge 0\).

Step 2 — The Kernel Substitution

Now suppose we want to work in a feature space defined by a map \(\phi : \mathbb{R}^d \to \mathcal{H}\). The kernelised Gram matrix is:

$$K_{ij} = K(x_i, x_j) = \langle \phi(x_i), \phi(x_j) \rangle_{\mathcal{H}}$$

Popular kernels and their implicit \(\phi\):

  • Linear: \(K(x,z)=x^\top z\) — \(\phi\) is the identity, \(\mathcal{H}=\mathbb{R}^d\)
  • Polynomial (degree \(p\)): \(K(x,z)=(x^\top z+c)^p\) — \(\phi\) maps to all monomials up to degree \(p\)
  • RBF / Gaussian: \(K(x,z)=\exp\!\left(-\tfrac{\|x-z\|^2}{2\sigma^2}\right)\) — \(\phi\) maps to an infinite-dimensional space; never compute \(\phi\) directly

Design Decision: Why Not Just Compute \(\phi\) Explicitly?

For the RBF kernel, \(\phi\) lives in an infinite-dimensional Hilbert space — it literally cannot be stored. For polynomial kernels, \(\phi\) grows as \(\binom{d+p}{p}\) features, which can be millions even for modest \(d\) and \(p\). The kernel trick replaces an intractable vector computation with a single scalar function evaluation.

🔑 Mercer's Theorem

A symmetric function \(K(x,z)\) is a valid kernel (corresponds to an inner product in some Hilbert space) if and only if the kernel matrix \(K \in \mathbb{R}^{n \times n}\) is positive semi-definite for every finite set of points. This is the Mercer condition: \(\sum_{i,j} c_i c_j K(x_i, x_j) \ge 0\) for all \(c \in \mathbb{R}^n\).

3
Why It Works — The Math
▼

PSD Proof for Gram Matrices

Let \(X \in \mathbb{R}^{n \times d}\) and \(G = XX^\top\). For any \(v \in \mathbb{R}^n\):

$$v^\top G v = v^\top X X^\top v = (X^\top v)^\top (X^\top v) = \|X^\top v\|^2 \ge 0$$

So \(G \succeq 0\) (PSD). Eigenvalues of \(G\) are the squared singular values of \(X\), all \(\ge 0\).

Kernel SVM Dual — Where the Kernel Matrix Appears

The SVM primal minimises \(\frac{1}{2}\|w\|^2\) subject to \(y_i(w^\top x_i + b) \ge 1\). Taking the Lagrangian dual, the weight vector satisfies \(w = \sum_i \alpha_i y_i x_i\), and the prediction for a new point \(x\) becomes:

$$f(x) = \operatorname{sign}\!\left(\sum_{i=1}^n \alpha_i y_i \langle x_i, x \rangle + b\right)$$

Replacing \(\langle x_i, x \rangle\) with \(K(x_i, x)\) gives a non-linear decision boundary in \(\mathcal{H}\) that is still linear in the dual — and we only ever need kernel evaluations, never \(\phi(x)\) explicitly.

RBF Kernel Expansion (Taylor)

$$\exp\!\left(-\frac{\|x-z\|^2}{2\sigma^2}\right) = \exp\!\left(-\frac{\|x\|^2}{2\sigma^2}\right)\exp\!\left(-\frac{\|z\|^2}{2\sigma^2}\right) \sum_{k=0}^{\infty} \frac{(x^\top z)^k}{\sigma^{2k} k!}$$

This shows the RBF kernel is an infinite sum of polynomial kernels — confirming its \(\phi\) is infinite-dimensional.

⚠️ Common Misconception

The kernel trick does not require \(\phi\) to be finite-dimensional, but it does require the kernel matrix \(K\) to be PSD. If \(K\) is not PSD (e.g., the sigmoid kernel \(\tanh(\alpha x^\top z + c)\) for some parameters), the algorithm may fail to converge or give incorrect results.

Key Takeaways
▼

When to use kernel methods: When your data is not linearly separable in the original space, and you cannot afford to explicitly expand features. Kernels shine with small-to-medium datasets (\(n \lesssim 10^4\)) where the \(O(n^2)\) kernel matrix is manageable.

When NOT to use: Large-scale data (\(n > 10^5\)) — the \(n \times n\) kernel matrix becomes intractable (memory and compute). Use approximate methods (Random Fourier Features, Nyström approximation) or neural networks instead.

💡 The Core Insight

The kernel trick is a duality between feature space and function space. Any algorithm that can be expressed purely in terms of inner products can be kernelised. This includes: SVMs, kernel PCA, kernel ridge regression, Gaussian processes, and spectral clustering.

From-Scratch Implementation
▼

Gram Matrix & Kernel SVM (NumPy)

The code below builds the Gram matrix, verifies PSD, and applies kernel SVM — all from scratch with full comments.

import numpy as np
from numpy.linalg import eigh
# ── 1. Gram Matrix ────────────────────────────────────────────
def gram_matrix(X):
"""G_ij = <xi, xj> for xi, xj in X. G = X @ X^T."""
return X @ X.T # shape (n, n)
def is_psd(M, tol=1e-8):
"""Check PSD via minimum eigenvalue (must be >= -tol)."""
eigvals = eigh(M)[0] # sorted ascending
return eigvals[0] >= -tol
# ── 2. Kernels ────────────────────────────────────────────────
def linear_kernel(X, Z=None):
Z = X if Z is None else Z
return X @ Z.T # same as Gram
def poly_kernel(X, Z=None, degree=2, c=1.0):
Z = X if Z is None else Z
return (X @ Z.T + c) ** degree
def rbf_kernel(X, Z=None, sigma=1.0):
"""K(xi, xj) = exp(-||xi-xj||^2 / (2*sigma^2))
Implemented via: ||xi-xj||^2 = ||xi||^2 + ||xj||^2 - 2*xi·xj
"""
Z = X if Z is None else Z
# Efficient vectorised squared-distance computation
sq_X = np.sum(X**2, axis=1, keepdims=True) # (n,1)
sq_Z = np.sum(Z**2, axis=1, keepdims=True).T # (1,m)
dist2 = sq_X + sq_Z - 2 * (X @ Z.T) # (n,m)
return np.exp(-dist2 / (2 * sigma**2))
# ── 3. Quick PSD Verification ──────────────────────────────────
rng = np.random.default_rng(42)
X = rng.standard_normal((8, 2))
for name, K in [("Gram", gram_matrix(X)),
("RBF", rbf_kernel(X)),
("Poly", poly_kernel(X))]:
ev = eigh(K)[0]
print(f"{name}: min_eigval={ev[0]:.6f}, PSD={ev[0]>=-1e-8}")
# Gram: min_eigval=0.000000, PSD=True
# RBF: min_eigval=0.000001, PSD=True
# Poly: min_eigval=0.023184, PSD=True
