Relative Positional Encoding

Shaw, Uszkoreit & Vaswani (2018) — encoding position as a pairwise offset, not an absolute address
Foundational Transformers Attention O(n²·d) with clipping
1
Understanding Relative Positional Encoding
▼

What is it? Self-attention has no built-in sense of word order — it treats a sequence as a bag of vectors unless you tell it where each token sits. The original Transformer did this by adding a fixed sinusoidal vector for each absolute position (position 5, position 12, ...) to the token embedding. Shaw et al. (2018) asked a sharper question: for attention, what actually matters isn't "I am at position 12" — it's "the word I'm attending to is 3 positions to my left." They moved position information out of the input embeddings and directly into the attention computation as a relative offset between the query and key.

Analogy: Imagine reading a sentence with your finger on one word, and instead of memorizing "I am the 12th letter typed," you only ever ask "is this other word one step back, two steps forward, or far away?" Two words separated by 2 tokens generate the exact same relative signal whether they appear at the start of a short sentence or in the middle of a long paragraph — the model reuses the same learned representation for "offset = 2" everywhere.

💡 If you remember one thing

Relative positional encoding injects a learned vector \(a_{ij}\) that depends only on the clipped distance \(\text{clip}(j-i,\,k)\) directly into the attention key/value computation — never into the token embeddings — so the same offset is represented identically no matter where it occurs in the sequence.

2
How It Works Internally
▼

Two edits to standard self-attention

Standard scaled dot-product attention computes a score \(e_{ij} = \frac{(x_iW^Q)(x_jW^K)^\top}{\sqrt{d_z}}\) between query position \(i\) and key position \(j\). Shaw et al. add a relative position representation to both the key term and the value term used at position \(j\), indexed by the clipped offset:

$$r = \text{clip}(j - i,\, k) = \max(-k,\, \min(k,\, j-i))$$

The offset \(r\) is looked up in two small learned tables, \(w^K\) and \(w^V\), each with only \(2k+1\) entries (one per possible clipped distance from \(-k\) to \(+k\)). This gives two new terms, \(a^K_{ij}=w^K_r\) and \(a^V_{ij}=w^V_r\), which are added directly into the attention math:

$$e_{ij} = \frac{x_iW^Q\,(x_jW^K + a^K_{ij})^\top}{\sqrt{d_z}} \qquad z_i = \sum_j \alpha_{ij}\,(x_jW^V + a^V_{ij})$$

Why clip the distance?

Sequences can be arbitrarily long, but two tokens 50 apart behave, for most language, about the same as two tokens 60 apart — both are just "far away." Clipping bounds the table to \(2k+1\) vectors instead of one per possible offset, which (a) caps the parameter count, (b) lets the model generalize to sequence lengths never seen during training, since every offset beyond \(\pm k\) collapses onto the same boundary vector, and (c) keeps memory bounded even though attention itself is still \(O(n^2)\) in pairs.

Design decision: why not just extend the sinusoidal table?

Absolute sinusoidal encodings are added once, at the input layer, and diffuse through every subsequent layer only indirectly via the learned projections. Shaw et al.'s scheme instead injects position information fresh at every attention head, every layer, directly where distance is actually used — a much more direct and reusable signal, at the cost of a small amount of extra compute per layer (an efficient implementation reduces this to two extra matrix multiplications, not a full new tensor).

🔑 Key Property

The representation of "3 tokens to the right" is identical everywhere in the sequence — this is translation invariance. It is the structural reason relative encodings often extrapolate to longer sequences better than absolute sinusoidal or learned-absolute schemes.

3
Why It Works — The Math
▼

Efficient computation

Naively, computing \(a^K_{ij}\) for every pair \((i,j)\) needs an \(n \times n \times d_z\) tensor. Shaw et al. show the key-side term can be computed with a reshape trick: expand \(x_i W^Q\) to shape \((n, d_z)\), and the relative embedding table to shape \((n, n, d_z)\) only implicitly, using a batched matmul that costs \(O(n^2 d_z)\) — the same asymptotic order as ordinary attention, not an extra factor of \(n\).

$$e_{ij} = \frac{x_iW^Q (x_jW^K)^\top}{\sqrt{d_z}} + \frac{x_iW^Q (a^K_{ij})^\top}{\sqrt{d_z}}$$

The first term is the familiar content-content score. The second term is a content-position score: how much does query \(i\)'s projected vector align with the learned "offset \(r\)" vector, independent of what token is actually at \(j\)? Softmax over \(j\) combines both signals into the attention weights \(\alpha_{ij}\).

Proof sketch: translation invariance

Take any sequence and shift every token by a constant \(c\) (i.e., attend from position \(i+c\) to \(j+c\) instead of \(i\) to \(j\)). Because \(r = \text{clip}((j+c)-(i+c), k) = \text{clip}(j-i, k)\), the shift cancels exactly — the relative term \(a^K_{ij}\) is unchanged. Absolute encodings have no such guarantee: shifting the sequence changes every absolute position vector used, so the network must re-learn the same pattern at every offset within the training range.

⚠️ Common Pitfall

Clipping is a double-edged sword: it enables length generalization, but it also means the model is literally blind to any distinction between "40 tokens away" and "4000 tokens away" once both exceed \(k\) — both map to the exact same boundary vector \(w^K_{k}\). Choosing \(k\) too small throws away genuinely useful long-range distance information.

Key Takeaways
▼

When it shines:

  • Tasks where the pattern "N tokens apart" should mean the same thing regardless of absolute position (most of language)
  • Sequences whose length at inference exceeds anything seen during training — clipping bounds the representation space
  • Architectures where you want position signal reinforced at every layer, not just injected once at the input

What replaced or extended it: Transformer-XL generalized this to streaming/segment-level memory; T5 simplified the relative bias to a single learned scalar per bucketed distance per head; RoPE (rotary embeddings) achieves relative-position behavior by rotating query/key vectors instead of adding learned offset vectors — favored in most modern LLMs (LLaMA, GPT-NeoX) for its efficiency; ALiBi replaces learned tables with a fixed linear penalty on distance, requiring zero extra parameters.

💡 Lineage

Absolute sinusoidal/learned (2017) → Shaw et al. relative (2018, this page) → Transformer-XL / T5 relative bias (2019) → RoPE / ALiBi (2021+). Each generation keeps the core idea — position should modulate attention, not just the input — while trading parameter count, extrapolation quality, and compute cost differently.

Code Trace

import numpy as np
# n tokens, d_z head dim, clip window k
def clip_dist(i, j, k):
return max(-k, min(k, j - i)) # relative offset, clipped
# learned tables: one row per offset in [-k, k]
wK = np.random.randn(2*k+1, d_z) * 0.1
wV = np.random.randn(2*k+1, d_z) * 0.1
def rel_attention(X, WQ, WK, WV, wK, wV, k):
n, d = X.shape
Q, K, V = X @ WQ, X @ WK, X @ WV # (n, d_z) each
scores = np.zeros((n, n))
for i in range(n):
for j in range(n):
r = clip_dist(i, j, k) + k # shift to table index
aK = wK[r] # relative key embedding
scores[i, j] = Q[i] @ (K[j] + aK) / np.sqrt(d)
alpha = softmax(scores, axis=-1) # attention weights
Z = np.zeros((n, d))
for i in range(n):
for j in range(n):
r = clip_dist(i, j, k) + k
aV = wV[r] # relative value embedding
Z[i] += alpha[i, j] * (V[j] + aV)
return Z, alpha
