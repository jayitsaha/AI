Understanding Weighted Averaging
▼

What is it? When multiple models make predictions, you can combine them by taking a weighted average: \(\hat{y} = w_1 f_1(x) + w_2 f_2(x) + \cdots + w_K f_K(x)\), where each weight \(w_i \geq 0\) and \(\sum_i w_i = 1\). Rather than trusting all models equally, you let the more accurate models contribute more to the final answer.

Analogy: Imagine asking three weather forecasters for tomorrow's temperature. The first has been right 90% of the time, the second 70%, and the third only 40%. Instead of averaging their answers equally, a weighted ensemble gives 9 votes to the first, 4 votes to the second, and only 1 to the third. The final prediction leans heavily on the expert, giving a more accurate result than any simple average.

If you remember one thing

Weighted averaging is \(\hat{y} = \sum_{i=1}^K w_i f_i(x)\) with \(\sum w_i = 1\), \(w_i \geq 0\). The optimal weights minimize ensemble error and satisfy \(w^* \propto C^{-1}\mathbf{1}\), where \(C\) is the error-covariance matrix of the individual models. A well-tuned ensemble beats the best single model.

How Weighted Averaging Works Internally
▼

Three Weight Schemes

1. Equal weights (uniform): \(w_i = 1/K\) for all \(i\). Simple but ignores that models differ in quality. Often a strong baseline because individual errors tend to cancel.

2. Inverse-error weights: Set \(w_i \propto 1/\text{MSE}_i\) where \(\text{MSE}_i\) is model \(i\)'s validation error. Renormalize so they sum to 1. Strong, simple heuristic that requires no optimization — just divide and normalize.

3. Optimized weights (Stacking-lite): Treat the weights \(\mathbf{w} = (w_1, \ldots, w_K)\) as parameters and solve the constrained optimization problem:

$$\mathbf{w}^* = \underset{\mathbf{w}}{\operatorname{argmin}} \; \mathbb{E}\!\left[(y - \textstyle\sum_i w_i f_i(x))^2\right] \quad \text{s.t.} \; \sum_i w_i = 1,\; w_i \geq 0$$

This is a constrained quadratic program and can be solved exactly with a small validation set using scipy or quadratic programming.

Why a Constrained Sum?

Requiring \(\sum w_i = 1\) ensures the ensemble makes predictions in the same range as the individual models (it is a convex combination). Requiring \(w_i \geq 0\) prevents one model from being used to "cancel out" another's errors in an unstable way. Relaxing these constraints can give lower training error but often overfits to the validation set.

Key Property: Bias-Variance Trade-off

If the individual models have uncorrelated errors, averaging \(K\) of them reduces variance by a factor of \(K\). With optimal weighting, further variance reduction is possible by concentrating weight on the most accurate models. This is why ensembles consistently outperform their constituent members.

3
The Math — Optimal Weights & the Error-Covariance Matrix
▼

Setting Up the Optimization

Let \(\varepsilon_i = y - f_i(x)\) be model \(i\)'s error. The ensemble error is:

$$\varepsilon_{\text{ens}} = y - \sum_{i=1}^K w_i f_i(x) = \sum_{i=1}^K w_i \varepsilon_i$$

The expected squared ensemble error (MSE) is:

$$\mathbb{E}[\varepsilon_{\text{ens}}^2] = \mathbf{w}^\top C \mathbf{w}$$

where \(C_{ij} = \mathbb{E}[\varepsilon_i \varepsilon_j]\) is the error-covariance matrix. The diagonal entries \(C_{ii} = \text{MSE}_i\) are the individual model errors; the off-diagonal entries \(C_{ij}\) measure how much two models' errors co-vary (if they fail together, combining them helps less).

Closed-Form Optimal Weights (Unconstrained)

Minimizing \(\mathbf{w}^\top C \mathbf{w}\) subject to \(\mathbf{1}^\top \mathbf{w} = 1\) (but allowing negative weights) via Lagrange multipliers:

$$\mathbf{w}^* = \frac{C^{-1}\mathbf{1}}{\mathbf{1}^\top C^{-1}\mathbf{1}}$$

This is the minimum-variance portfolio from Markowitz portfolio theory applied to ML models. In practice, non-negativity constraints are added (negative weights are unstable), turning it into a quadratic program.

Why Inverse-Error Weights Work Well

When models' errors are uncorrelated (\(C\) is diagonal with entries \(\text{MSE}_i\)), then \(C^{-1}\) is also diagonal with entries \(1/\text{MSE}_i\), and the optimal weights reduce exactly to:

$$w_i^* = \frac{1/\text{MSE}_i}{\sum_j 1/\text{MSE}_j}$$

This is precisely the inverse-error heuristic. When errors are correlated, the full \(C^{-1}\) formula gives further gains.

Common Pitfall: Overfitting Weights to Validation

Optimizing weights on the same data used to train the models inflates ensemble performance. Always use a held-out validation set (or cross-validated out-of-fold predictions) to estimate weights. With few validation samples and many models, even the weight optimization can overfit — regularize by adding a small ridge penalty or by constraining to equal weights when the validation set is small.

Key Takeaways
▼

When to use weighted averaging:

  • You have 2–20 trained models with different architectures or hyperparameters
  • A held-out validation set is available to calibrate weights
  • Models have uncorrelated error patterns (diverse errors → more cancellation)
  • Inference latency budget allows running all models

When NOT to use:

  • All models are nearly identical — averaging won't help and wastes compute
  • Validation set is tiny relative to number of models — weight overfit is likely
  • Models are strongly correlated in their errors — equal weighting is safer
Hierarchy of Ensemble Methods

Equal avg (\(w_i = 1/K\)) ⊂ Inv-error avg (\(w_i \propto 1/\text{MSE}_i\)) ⊂ Opt. weighted avg (\(\mathbf{w}^* = C^{-1}\mathbf{1}/\mathbf{1}^\top C^{-1}\mathbf{1}\)) ⊂ Stacking (learns a meta-model). Each generalizes by making fewer assumptions about the weight structure.

Code Trace

import numpy as np
from scipy.optimize import minimize
# Validation targets and model predictions
y_true = np.array([1.0, 2.5, 3.0, 5.0, 4.0])
fA = np.array([1.1, 2.4, 3.1, 4.8, 4.1]) # MSE = 0.0160
fB = np.array([1.3, 2.2, 3.3, 4.6, 4.3]) # MSE = 0.1040
fC = np.array([0.5, 1.8, 3.8, 5.6, 3.5]) # MSE = 0.3980
# Scheme 1: Equal weights
w_equal = np.array([1/3, 1/3, 1/3])
ens_eq = w_equal @ np.vstack([fA, fB, fC])
mse_eq = np.mean((y_true - ens_eq)**2) # 0.0593
# Scheme 2: Inverse-MSE weights
mses = np.array([0.0160, 0.1040, 0.3980])
inv = 1 / mses
w_inv = inv / inv.sum() # [0.8375, 0.1288, 0.0337]
ens_inv = w_inv @ np.vstack([fA, fB, fC])
mse_inv = np.mean((y_true - ens_inv)**2) # 0.0211
# Scheme 3: Optimized weights (constrained QP)
def ensemble_mse(w):
ens = w[0]*fA + w[1]*fB + w[2]*fC
return np.mean((y_true - ens)**2)
constraints = [{'type': 'eq', 'fun': lambda w: w.sum() - 1}]
bounds = [(0, 1)] * 3
result = minimize(ensemble_mse, w_inv, constraints=constraints, bounds=bounds)
w_opt = result.x # [0.9321, 0.0000, 0.0679]
mse_opt = ensemble_mse(w_opt) # 0.0140 < best model (0.0160)
print(f"Equal MSE: {mse_eq:.4f}")
print(f"Inv-MSE MSE: {mse_inv:.4f}")
print(f"Optimal MSE: {mse_opt:.4f}") # Beats best single model!
