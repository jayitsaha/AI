Index notation that makes tensor operations compact, unambiguous, and computable
Intermediate Linear Algebra Tensors Foundational for ML
1
Understanding Einstein Summation
▼

What is it? When you multiply matrices, you repeat a lot of \(\sum\) symbols. Einstein summation is a shorthand rule: whenever an index appears exactly twice in a term, sum over it automatically. Drop the \(\sum\) and let the repeated index signal the summation.

Analogy: Imagine filling out a tax form where any line that appears in both "income" and "deductions" automatically cancels out without you writing "minus". Einstein summation is exactly that convention — the repeated position is the rule, not explicit addition signs.

One-sentence summary: An index that appears once is a free index (shapes the output); an index that appears twice is a dummy (contracted/summed over and disappears).

If you remember one thing

Repeated index = sum. In \(c_i = A_{ij} b_j\), the index \(j\) appears on both \(A\) and \(b\), so we sum over all values of \(j\): \(c_i = \sum_j A_{ij} b_j\). This IS matrix-vector multiplication — written without the \(\Sigma\).

2
The Three Rules & Common Operations
▼

Rule 1 — Free index: shapes the output

An index appearing exactly once in a term is a free index. It ranges over its dimension and appears in the output. Example: \(c_i\) — the \(i\) is free, so the output is a vector indexed by \(i\).

Rule 2 — Dummy (repeated) index: summed over, vanishes

An index appearing exactly twice is a dummy index (Einstein called it "contraction"). It gets summed over and does NOT appear in the output. Example: \(A_{ij}B_{jk}\) — \(j\) is dummy (contracted), output is indexed by \(i, k\).

Rule 3 — No index may appear more than twice

An index appearing three or more times is ambiguous and violates the convention. Rename one occurrence with a fresh letter.

Mapping to operations

$$\text{dot product:}\quad s = a_i b_i \equiv \sum_i a_i b_i$$
$$\text{matrix–vector:}\quad c_i = A_{ij} b_j \equiv \sum_j A_{ij} b_j$$
$$\text{matrix–matrix:}\quad C_{ik} = A_{ij} B_{jk} \equiv \sum_j A_{ij} B_{jk}$$
$$\text{outer product:}\quad C_{ij} = a_i b_j \quad (\text{no repeated index, no sum})$$
$$\text{trace:}\quad s = A_{ii} \equiv \sum_i A_{ii}$$
Key Property — Output shape is determined by free indices

Count the free indices to read off the output shape. \(C_{ik} = A_{ij}B_{jk}\): two free indices \(i,k\) → output is a matrix. \(s = a_i b_i\): zero free indices → output is a scalar.

Common Pitfall

The convention was born in differential geometry with a covariant/contravariant distinction (lower/upper indices). In ML and numpy, we usually ignore this distinction and treat all indices equivalently. Don't confuse raising/lowering indices from physics with array dimensions in code.

4
numpy.einsum — Production Code
▼

numpy.einsum takes an index string and arrays, and returns the contraction. The string directly encodes the Einstein summation rule: left of -> are input index labels; right is the output index.

import numpy as np
A = np.array([[1, 2], [3, 4], [5, 6]]) # shape (3,2) — i,j
B = np.array([[7, 8, 9], [10, 11, 12]]) # shape (2,3) — j,k
# --- Core Operations ---
# dot product of vectors (s = a_i b_i)
s = np.einsum('i,i->', np.array([1,2,3]), np.array([4,5,6])) # 32
# matrix-vector multiply (c_i = A_ij b_j)
b = np.array([1, 2])
c = np.einsum('ij,j->i', A, b) # [5, 11, 17]
# matrix-matrix multiply (C_ik = A_ij B_jk)
C = np.einsum('ij,jk->ik', A, B) # equivalent to A @ B
# outer product (C_ij = a_i b_j) — NO repeated index
outer = np.einsum('i,j->ij', np.array([1,2,3]), np.array([4,5,6]))
# trace (s = A_ii)
sq = np.array([[1,2],[3,4]])
tr = np.einsum('ii->', sq) # 5
# transpose (B_ji = A_ij) — free indices reorder
AT = np.einsum('ij->ji', A) # shape (2,3)
# batch matrix multiply (C_bik = A_bij B_bjk)
Abatch = np.random.randn(8, 3, 2) # 8 matrices of shape 3×2
Bbatch = np.random.randn(8, 2, 4) # 8 matrices of shape 2×4
Cbatch = np.einsum('bij,bjk->bik', Abatch, Bbatch) # (8,3,4)
# --- ML-specific: attention scores ---
# Q: (batch, heads, seq, d_k) K: (batch, heads, seq, d_k)
# scores_bhij = sum_d Q_bhid K_bhjd (d is the dummy index)
Q = np.random.randn(2, 8, 10, 64) # batch=2, heads=8, seq=10, d_k=64
K = np.random.randn(2, 8, 10, 64)
scores = np.einsum('bhid,bhjd->bhij', Q, K) # shape (2, 8, 10, 10)
# Performance tip: use optimize=True for long chains (finds best contraction order)
result = np.einsum('ij,jk,kl->il', A, B[:,:2], np.eye(2), optimize=True)
Why einsum over @ or np.dot?

For tensors with 4+ dimensions (batch × heads × seq × d_k in Transformers), einsum eliminates the need for reshaping, transposing, and broadcasting boilerplate. One einsum call replaces 5 lines of numpy gymnastics — and it's often faster because numpy can choose optimal contraction order.

5
Deeper: Contraction Order, Kronecker Delta, Levi-Civita
▼

Contraction order matters for complexity

For a chain \(A_{ij}B_{jk}C_{kl}\) with dimensions \(d_1 \times d_2\), \(d_2 \times d_3\), \(d_3 \times d_4\), the cost depends on which pair you contract first:

$$\text{(AB)C:}\quad O(d_1 d_2 d_3 + d_1 d_3 d_4)$$
$$\text{A(BC):}\quad O(d_2 d_3 d_4 + d_1 d_2 d_4)$$

numpy's optimize=True uses dynamic programming to find the cheapest order — critical for deep learning where tensors have many dimensions.

Kronecker delta \(\delta_{ij}\)

The identity matrix element \(\delta_{ij} = 1\) if \(i=j\), else \(0\). In Einstein notation: contracting with \(\delta\) selects / renames indices.

$$A_{ij}\delta_{jk} = A_{ik} \quad \text{(multiplying by identity = rename } j \to k\text{)}$$
$$\delta_{ii} = n \quad \text{(trace of identity = dimension)}$$

Levi-Civita symbol \(\varepsilon_{ijk}\)

The totally antisymmetric tensor: \(\varepsilon_{ijk} = +1\) if \((i,j,k)\) is an even permutation of \((1,2,3)\), \(-1\) for odd, \(0\) if any index repeats. Cross product in 3D:

$$(\mathbf{a} \times \mathbf{b})_i = \varepsilon_{ijk} a_j b_k$$

The contraction identity \(\varepsilon_{ijk}\varepsilon_{ilm} = \delta_{jl}\delta_{km} - \delta_{jm}\delta_{kl}\) powers the vector triple-product identity — a three-line proof replaces pages of component algebra.

Application in deep learning

The Transformer self-attention score computation:

$$\text{score}_{bhij} = \frac{1}{\sqrt{d_k}} \sum_d Q_{bhid} K_{bhjd}$$

is written as np.einsum('bhid,bhjd->bhij', Q, K) / sqrt(d_k). The dummy index \(d\) is the head dimension contracted over; \(b,h,i,j\) are all free, shaping the \((\text{batch}\times\text{heads}\times\text{seq}\times\text{seq})\) output.

General Tensor Contraction

A contraction of tensors \(T^{i_1\ldots i_r}{}_{j_1\ldots j_s}\) and \(S^{k_1\ldots k_p}{}_{l_1\ldots l_q}\) over a shared index pair produces a new tensor whose rank is \((r+p-1)+(s+q-1)\). Every repeated contraction reduces rank by 2; reaching rank 0 gives a scalar.

6
Interview Q&A
▼

Q1 (Easy): What does a repeated index mean in Einstein notation?

A: It signals summation over all values of that index. The index is called a dummy or contracted index and disappears from the output. A non-repeated index is free and determines the shape of the result.

Q2 (Medium): Write the Transformer attention score computation in Einstein notation.

A: \(\text{score}_{bhij} = Q_{bhid} K_{bhjd}\) where \(d\) is the dummy index (head depth dimension). In numpy: 'bhid,bhjd->bhij'. The \(/\sqrt{d_k}\) scaling is applied after.

Follow-up trap: "Why not transpose K and use @?" — For 4D tensors the transpose is K.transpose(0,1,3,2) and you'd still need a loop or matmul broadcasting. einsum is cleaner and exposes the index structure explicitly.

Q3 (Hard): Explain why contraction order matters and how numpy handles it.

A: Matrix multiplication is associative but NOT computationally equivalent in cost. For \(A(n\!\times\!m)\), \(B(m\!\times\!p)\), \(C(p\!\times\!q)\): left-to-right costs \(O(nmp + npq)\); right-to-left costs \(O(mpq + nmq)\). These differ by up to a factor of \(m/q\) or \(p/n\). numpy's optimize=True uses DP to find the minimum. PyTorch's torch.einsum has similar optimizations.

Q4 (Hard): What is the connection between Einstein summation and the trace?

A: The trace is the contraction of a rank-2 tensor with itself on both indices: \(\text{tr}(A) = A_{ii} = \delta_{ij}A_{ij}\). More generally, the Frobenius norm squared is \(\|A\|_F^2 = A_{ij}A_{ij}\) — contract all indices with themselves. These are special cases of full contraction to a scalar.

Red Flag Answer

"Einstein summation is just syntactic sugar for loops." — Partially true for correctness, but misses the point: it enables the computer to choose optimal BLAS routines and contraction orders, and it communicates mathematical intent precisely without array-shape ambiguity.
