Early Fusion: Concatenation at Input Level

Combining multiple modalities by concatenating their raw or lightly-encoded feature vectors before a shared model
Foundational Multimodal ML Feature Engineering O(d₁+d₂) input Fusion Strategy
1
Understanding Early Fusion
▼

What is it? In multimodal learning, we often have data from multiple sources — for instance, an image and a text description, or audio and video frames, or tabular clinical measurements alongside a radiology scan. Early fusion is the simplest strategy: concatenate all modality feature vectors into one long vector at the very beginning, then feed this combined vector into a single shared model (e.g., an MLP or a transformer encoder).

Analogy: Imagine you're a doctor diagnosing a patient. You have a lab report (numerical values) and a written symptom description (text). Early fusion is like printing both onto a single sheet of paper and reading them together from the start. The doctor's brain (the model) sees everything at once and can immediately notice cross-modal patterns — "high glucose AND the patient mentioned excessive thirst." The model never has to "merge" separate conclusions; it reasons jointly from the outset.

Contrast with late fusion: Late fusion processes each modality independently through its own model, then combines the outputs (predictions or embeddings) at the end. Early fusion is simpler, cheaper (one model instead of many), and allows the model to capture cross-modal interactions at every layer. But it requires that all modalities are always present and that their feature spaces are compatible for concatenation.

💡 If you remember one thing

Early fusion = concatenate first, learn jointly. Given modality vectors \(\mathbf{x}_1 \in \mathbb{R}^{d_1}\) and \(\mathbf{x}_2 \in \mathbb{R}^{d_2}\), form \(\mathbf{z} = [\mathbf{x}_1 \| \mathbf{x}_2] \in \mathbb{R}^{d_1+d_2}\), then pass \(\mathbf{z}\) through a single model \(f_\theta\). Every parameter in \(f_\theta\) can attend to features from both modalities simultaneously.

2
How Early Fusion Works Internally
▼

Step 1 — Feature Extraction per Modality

Each modality is first converted into a fixed-length feature vector. For images, this might be pixel values, HOG features, or the output of a pretrained CNN backbone. For text, it could be a bag-of-words vector, TF-IDF, or a sentence embedding. For audio, MFCCs or spectral features. These per-modality encoders can be simple (raw features) or complex (deep pretrained networks) — the key is that they output a real-valued vector of fixed dimension.

Step 2 — Concatenation

The feature vectors from all modalities are concatenated along the feature dimension. If modality 1 produces \(\mathbf{x}_1 \in \mathbb{R}^{d_1}\) and modality 2 produces \(\mathbf{x}_2 \in \mathbb{R}^{d_2}\), the fused input is \(\mathbf{z} = [\mathbf{x}_1 \| \mathbf{x}_2] \in \mathbb{R}^{d_1+d_2}\). With \(M\) modalities: \(\mathbf{z} \in \mathbb{R}^{\sum_{m=1}^M d_m}\). This is a zero-overhead operation — no parameters, no learning, just memory layout.

Step 3 — Shared Model Processes the Fused Vector

The concatenated vector \(\mathbf{z}\) is fed into a single model — typically an MLP with several hidden layers, or a transformer. The first linear layer of this model has weight matrix \(W \in \mathbb{R}^{h \times (d_1+d_2)}\), which can be partitioned as \(W = [W_1 \| W_2]\) where \(W_1 \in \mathbb{R}^{h \times d_1}\) and \(W_2 \in \mathbb{R}^{h \times d_2}\). Each hidden unit computes a weighted sum over features from BOTH modalities simultaneously, enabling cross-modal interaction from the very first layer.

Design Decisions

Normalization before concatenation: If modalities have very different scales (pixel values 0–255 vs. text embeddings in [-1,1]), it's critical to normalize each modality's features to comparable ranges before concatenation. Otherwise the model's first layer will be dominated by the high-magnitude modality.

Dimensionality balance: If \(d_1 \gg d_2\), the first layer is heavily biased toward modality 1 by sheer parameter count. One fix: project each modality to a common dimension \(d\) before concatenating, giving \(\mathbf{z} \in \mathbb{R}^{Md}\).

🔑 Key Property: Cross-Modal Interaction from Layer 1

Unlike late fusion (where modalities are processed in separate silos until the very end), early fusion allows the model to learn interactions like "if feature 3 from modality 1 is high AND feature 7 from modality 2 is low, activate this hidden unit." This is the primary advantage: joint representation learning from the first layer onward.

3
The Math — Why It Works
▼

Formal Setup

Let there be \(M\) modalities. Modality \(m\) has raw input \(u_m\) which is encoded (possibly by a pretrained encoder \(\phi_m\)) into a feature vector:

$$\mathbf{x}_m = \phi_m(u_m) \in \mathbb{R}^{d_m}, \quad m = 1, \ldots, M$$

Early fusion concatenates these into a single fused representation:

$$\mathbf{z} = \mathbf{x}_1 \| \mathbf{x}_2 \| \cdots \| \mathbf{x}_M \in \mathbb{R}^{D}, \quad D = \sum_{m=1}^M d_m$$

A shared model \(f_\theta : \mathbb{R}^D \to \mathcal{Y}\) (e.g., an \(L\)-layer MLP) then maps \(\mathbf{z}\) to the output. For a two-layer MLP with ReLU:

$$\hat{y} = W_2 \,\sigma\!\left(W_1 \mathbf{z} + \mathbf{b}_1\right) + \mathbf{b}_2$$

where \(W_1 \in \mathbb{R}^{h \times D}\), \(W_2 \in \mathbb{R}^{|\mathcal{Y}| \times h}\), and \(\sigma\) is ReLU. The key insight is that \(W_1\) can be partitioned column-wise:

$$W_1 \mathbf{z} = \underbrace{W_1^{(1)} \mathbf{x}_1}_{\text{from modality 1}} + \underbrace{W_1^{(2)} \mathbf{x}_2}_{\text{from modality 2}} + \cdots + \underbrace{W_1^{(M)} \mathbf{x}_M}_{\text{from modality } M}$$

Each hidden unit is a sum of contributions from all modalities. After the nonlinearity \(\sigma\), the second layer \(W_2\) can combine units that were activated by cross-modal patterns. This is why early fusion enables cross-modal interaction: the nonlinearity creates multiplicative-like coupling between modalities even though the concatenation itself is linear.

Information-Theoretic View

Let \(Y\) be the target. The mutual information captured by the fused representation is at least as large as that of any single modality:

$$I(\mathbf{z}; Y) \geq \max_m I(\mathbf{x}_m; Y)$$

because \(\mathbf{z}\) contains all the information in every \(\mathbf{x}_m\). In practice, the model may not exploit all of it, but the upper bound on representational capacity is maximized at the input stage.

Parameter Count

The first layer has \(h \cdot D + h = h(D+1)\) parameters. For \(M\) modalities each of dimension \(d\), \(D = Md\), so the first layer grows linearly in \(M\). This is manageable for moderate \(M\) and \(d\), but can become expensive for very high-dimensional modalities (e.g., raw image pixels).

⚠️ Common Pitfall: Missing Modalities

Early fusion requires ALL modalities to be present at inference time. If modality 2 is missing, you cannot form \(\mathbf{z}\) without imputation or masking. Late fusion is more robust to missing modalities. Early fusion is best when all modalities are reliably available.

Key Takeaways
▼

When to use early fusion:

  • All modalities are always available at inference time (no missing data)
  • You want the model to learn cross-modal interactions from the very first layer
  • Modality feature dimensions are moderate (not raw high-res images × many modalities)
  • You have limited compute budget — one model is cheaper than M separate models
  • The modalities are tightly coupled and their joint patterns are informative (e.g., text + audio prosody for emotion)

When NOT to use early fusion:

  • Modalities are sometimes missing at test time — use late fusion or masked early fusion
  • Modalities have very different temporal resolutions (e.g., 1 Hz tabular vs. 16 kHz audio) — alignment is needed first
  • One modality is extremely high-dimensional (e.g., raw 224×224 images = 150K dims) — the concatenated input becomes unwieldy
  • You want to pretrain modality-specific encoders separately, then combine — intermediate fusion is more natural
💡 Fusion Hierarchy

Early fusion (concatenate inputs) → Intermediate fusion (concatenate hidden representations) → Late fusion (combine output predictions). Early fusion maximizes cross-modal interaction but requires all modalities. Late fusion maximizes modality independence but loses cross-modal patterns. Intermediate fusion is a compromise.

📐 Complexity Comparison

Early fusion: 1 model with input dim \(D = \sum d_m\), first-layer params \(= h \cdot D\). Late fusion: M models each with input dim \(d_m\), total first-layer params \(= h \cdot \sum d_m = h \cdot D\). Same parameter count in the first layer — but early fusion has one set of subsequent layers while late fusion has M sets. Early fusion is more parameter-efficient overall.

Code Trace

import torch
import torch.nn as nn
# ── Modality-specific encoders (lightweight) ──
class TextEncoder(nn.Module):
def __init__(self, vocab_size, d1=64):
super().__init__()
self.embed = nn.EmbeddingBag(vocab_size, d1, mode='mean')
def forward(self, x): return self.embed(x) # → (B, d1)
class AudioEncoder(nn.Module):
def __init__(self, n_mfcc=40, d2=32):
super().__init__()
self.fc = nn.Linear(n_mfcc, d2)
def forward(self, x): return torch.relu(self.fc(x)) # → (B, d2)
class TabularEncoder(nn.Module):
def __init__(self, n_features, d3=16):
super().__init__()
self.bn = nn.BatchNorm1d(n_features) # normalize scales!
self.fc = nn.Linear(n_features, d3)
def forward(self, x): return torch.relu(self.fc(self.bn(x))) # → (B, d3)
# ── Early Fusion Model ──
class EarlyFusionModel(nn.Module):
def __init__(self, d1=64, d2=32, d3=16, h=128, n_classes=3):
super().__init__()
self.text_enc = TextEncoder(vocab_size=10000, d1=d1)
self.audio_enc = AudioEncoder(n_mfcc=40, d2=d2)
self.tab_enc = TabularEncoder(n_features=8, d3=d3)
D = d1 + d2 + d3 # fused dimension
# Shared MLP processes the concatenated vector
self.shared = nn.Sequential(
nn.Linear(D, h), # W1 ∈ R^{h × D}
nn.ReLU(),
nn.Dropout(0.3),
nn.Linear(h, h // 2),
nn.ReLU(),
nn.Linear(h // 2, n_classes)
)
def forward(self, text, audio, tabular):
x1 = self.text_enc(text) # (B, d1)
x2 = self.audio_enc(audio) # (B, d2)
x3 = self.tab_enc(tabular) # (B, d3)
z = torch.cat([x1, x2, x3], dim=-1) # (B, D) ← EARLY FUSION
return self.shared(z) # (B, n_classes)
# Usage
model = EarlyFusionModel(d1=64, d2=32, d3=16, h=128, n_classes=3)
logits = model(text_tokens, audio_mfcc, tab_features)
