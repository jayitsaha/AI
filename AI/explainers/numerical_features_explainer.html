1
Understanding Numerical Features
▼

What is it? Numerical features are the backbone of many machine learning models. However, raw numerical data often isn't directly suitable for algorithms. Features might have vastly different scales (e.g., age vs. income), highly skewed distributions (e.g., website visits), or non-linear relationships with the target variable. Feature engineering involves transforming these raw numbers into a format that helps models learn more effectively and generalize better.

Analogy: Think of numerical features as raw ingredients for a complex recipe. Some ingredients (like salt) might need precise scaling. Others (like onions) might need chopping (binning) or blending (power transforms). And sometimes, combining ingredients (like oil and vinegar for a dressing) creates a new, more potent flavor (interaction features). Applying these transformations correctly is crucial for the final dish (model performance) to be excellent.

💡 If you remember one thing

The goal of numerical feature engineering is to make data more amenable to machine learning algorithms. This often means putting features on a comparable scale, normalizing their distributions, or explicitly encoding non-linear and interactive relationships that a simple linear model might otherwise miss.

2
How It Works Internally
▼

Scaling: Putting Features on a Comparable Range

Many ML algorithms (e.g., SVMs, k-NN, neural networks, linear regression with regularization) are sensitive to feature scales. Scaling ensures that no single feature dominates the learning process purely due to its magnitude.

  • StandardScaler (Z-score normalization): Transforms data to have a mean of 0 and a standard deviation of 1. It's suitable for algorithms that assume Gaussian distributed data.
  • MinMaxScaler: Scales features to a fixed range, usually [0, 1]. Useful for algorithms that are sensitive to the magnitude of feature values, like neural networks or image processing.
  • RobustScaler: Scales features using the median and interquartile range (IQR). This method is robust to outliers, as it does not use the mean or standard deviation, which are heavily influenced by extreme values.
  • MaxAbsScaler: Scales each feature by its maximum absolute value. It maps the data into the range [-1, 1] and is particularly useful for sparse data, as it doesn't shift or center the data.

Power Transforms: Normalizing Distributions

Many statistical models assume that input features are normally distributed. Power transforms aim to transform skewed data into a more Gaussian-like shape.

  • Log Transform: Applies \(\log(x)\) (typically natural log or \(\log_{10}\)). Effective for heavily right-skewed positive data, compressing large values and expanding small ones.
  • Box-Cox Transform: A family of power transforms that includes the log transform as a special case. It requires input data to be strictly positive and finds an optimal \(\lambda\) parameter that minimizes the skewness of the transformed data.
  • Yeo-Johnson Transform: A generalization of Box-Cox that can handle zero and negative values. Like Box-Cox, it finds an optimal \(\lambda\) to make the data more Gaussian.

Binning (Discretization): Capturing Non-linearities and Handling Outliers

Binning converts continuous numerical features into categorical ones by dividing the range of values into discrete intervals (bins). This can help capture non-linear relationships, reduce the impact of outliers, and make models more robust to small fluctuations.

  • Equal-width binning: Divides the range of the feature into bins of equal size.
  • Equal-frequency (quantile) binning: Divides the feature into bins such that each bin contains roughly the same number of observations.

Polynomial Features: Modeling Non-linear Relationships

Linear models can only capture linear relationships. By creating polynomial features (e.g., \(x^2, x^3\)), we can enable linear models to fit non-linear patterns in the data.

Interaction Features: Capturing Feature Dependencies

Interaction features are combinations of two or more features (e.g., \(x_1 \cdot x_2\)). They allow models to capture synergistic or antagonistic effects between features that would otherwise be treated independently. For example, the effect of age on income might depend on education level.

🔑 Key Property

These transformations are typically applied after splitting data into training and test sets to prevent data leakage. The `fit` step (calculating mean/std, min/max, lambda, bin edges) should only use the training data, and then `transform` is applied to both training and test sets.

3
Why It Works — The Math
▼

Scaling Formulas

Each scaling method employs a distinct mathematical operation:

$$\begin{aligned} \text{StandardScaler: } & z_i = \frac{x_i - \mu}{\sigma} \\ \text{MinMaxScaler: } & x'_i = \frac{x_i - \min(x)}{\max(x) - \min(x)} \\ \text{MaxAbsScaler: } & x'_i = \frac{x_i}{\max(|x|)} \end{aligned}$$

For RobustScaler, \(\mu\) is replaced by the median and \(\sigma\) by the Interquartile Range (IQR), which is the difference between the 75th and 25th percentiles.

Power Transforms

Power transforms aim to stabilize variance and make data more Gaussian. The Box-Cox transform for \(x > 0\) is defined as:

$$x'(\lambda) = \begin{cases} \frac{x^\lambda - 1}{\lambda} & \text{if } \lambda \neq 0 \\ \log(x) & \text{if } \lambda = 0 \end{cases}$$

The optimal \(\lambda\) is typically found by maximizing the log-likelihood function of the transformed data. The Yeo-Johnson transform extends this to handle non-positive values, with a piecewise function for \(x \ge 0\) and \(x < 0\).

Polynomial and Interaction Features

Given \(D\) original features \((x_1, x_2, \dots, x_D)\), polynomial features of degree \(k\) generate all combinations of these features up to that degree. For two features \(x_1, x_2\) and degree 2, the new feature set includes:

$$(1, x_1, x_2, x_1^2, x_2^2, x_1x_2)$$

The term \(x_1x_2\) is an interaction feature. These transformations allow linear models to fit decision boundaries that are non-linear in the original feature space. For example, a linear decision boundary in the \((x_1, x_2, x_1^2, x_2^2)\) space corresponds to a quadratic curve in the original \((x_1, x_2)\) space.

⚠️ Common Pitfall

Over-engineering features, especially with high-degree polynomial or many interaction terms, can lead to overfitting. The model might learn the training data's noise rather than its underlying patterns. Always validate on a held-out set and use regularization techniques (like L1/L2) if necessary.

Key Takeaways
▼

When to use these techniques:

  • Scaling: Almost always for distance-based algorithms (k-NN, SVMs), gradient-based optimizers (neural networks, logistic regression with regularization), or PCA. Choose RobustScaler for outlier-prone data.
  • Power Transforms: When features are heavily skewed and you need to approximate a Gaussian distribution (e.g., for linear models, Gaussian Naive Bayes, or statistical tests). Log transform is a good first attempt for positive skewed data.
  • Binning: To handle outliers, capture non-linear relationships, or when a model benefits from categorical inputs (e.g., decision trees, boosting algorithms). Quantile binning is good for creating balanced bins.
  • Polynomial/Interaction Features: When you suspect non-linear relationships or dependencies between features that a simple linear model cannot capture. Useful for making linear models more flexible.

When NOT to use or be cautious:

  • Scaling: Tree-based models (Decision Trees, Random Forests, Gradient Boosting) are generally insensitive to feature scales.
  • Power Transforms: Can make interpretation harder. If data contains zeros or negatives, ensure the transform (e.g., Box-Cox) can handle it, or use Yeo-Johnson.
  • Binning: Can lead to information loss (e.g., if bin boundaries are chosen poorly). Can also make models more sensitive to small changes near bin edges.
  • Polynomial/Interaction Features: High-degree polynomials or too many interaction terms can lead to a "curse of dimensionality," making models prone to overfitting and harder to interpret. Use sparingly and with strong domain knowledge.
💡 Big Picture

Effective numerical feature engineering is a blend of statistical understanding, domain knowledge, and iterative experimentation. It's not a one-size-fits-all process; the best approach depends heavily on the data, the chosen model, and the problem at hand.

Code Trace (Python / Scikit-learn)
▼
import numpy as np
from sklearn.preprocessing import StandardScaler, MinMaxScaler, RobustScaler, MaxAbsScaler
from sklearn.preprocessing import PowerTransformer, QuantileTransformer, PolynomialFeatures
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
# Assume X is a 2D numpy array of shape (n_samples, n_features)
# and y is a 1D numpy array of labels
X = np.array([[10, 2], [20, 5], [1, 1], [100, 10], [5, 3]])
y = np.array([0, 1, 0, 1, 0])
# 1. Scaling
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X) # X_scaled will have mean 0, std 1
scaler = MinMaxScaler()
X_minmax = scaler.fit_transform(X) # X_minmax will be in [0, 1]
# 2. Power Transforms (e.g., Yeo-Johnson)
pt = PowerTransformer(method='yeo-johnson')
X_transformed = pt.fit_transform(X) # X_transformed will be more Gaussian
# 3. Binning (Quantile Discretization)
qt = QuantileTransformer(n_quantiles=5, output_distribution='uniform')
X_binned = qt.fit_transform(X) # Each feature mapped to [0,1] with uniform density
# 4. Polynomial Features & Interactions
poly = PolynomialFeatures(degree=2, include_bias=False)
X_poly = poly.fit_transform(X) # e.g., for X=[x1,x2] -> [x1,x2,x1^2,x2^2,x1*x2]
print(f"Original X shape: {X.shape}, Poly X shape: {X_poly.shape}")
# Example Pipeline: Scaling + Polynomial + Logistic Regression
pipeline = Pipeline([
('scaler', StandardScaler()),
('poly', PolynomialFeatures(degree=2, include_bias=False)),
('logreg', LogisticRegression())
])
pipeline.fit(X, y)
print(f"Pipeline score: {pipeline.score(X, y)}")
