Intermediate Deep Learning Generative AI O(n) generation, O(n) detection
1
Understanding Watermarking LLM Outputs
▼

What is it? Watermarking for Large Language Models (LLMs) is a technique to embed a subtle, detectable signal into the text generated by an LLM. This signal is imperceptible to humans but can be statistically identified by a detector, allowing us to determine if a given piece of text likely originated from a specific LLM, even if it has been partially edited or truncated.

Analogy: Imagine a master weaver who, when creating a fabric, subtly biases the choice of thread color at certain points. Individually, these choices are hard to spot, but over a large piece of cloth, a specific pattern emerges that only the weaver knows how to detect. This pattern doesn't ruin the fabric's appearance but proves its origin. LLM watermarking is similar: it subtly biases token choices during generation to create a statistical "fingerprint."

💡 If you remember one thing

LLM watermarking works by slightly increasing the probability of "green-listed" tokens (and decreasing "red-listed" ones) at each generation step. The green/red list for a token is determined by a cryptographic hash of the *previous* token, making the pattern context-dependent and hard to remove without destroying the text's coherence. The detection process then statistically checks for an over-abundance of green tokens.

2
How It Works Internally
▼

The Mechanism: Bias and Detect

The core idea of watermarking (Kirchenbauer et al., 2023) revolves around modifying the token sampling process and then statistically verifying the presence of that modification:

  1. Vocabulary Partition: At each generation step, given the previously generated token, the model's entire vocabulary is pseudo-randomly partitioned into two disjoint sets: a "green list" and a "red list." This partition is deterministic, based on a secret key and the hash of the previous token ID.
  2. Logit Bias: Before sampling the next token, the logits (raw scores) for tokens in the "green list" are increased by a small constant value (\(\delta\)), while logits for "red list" tokens might be decreased or left untouched. This subtly shifts the probability distribution.
  3. Sampling: The next token is then sampled from this biased probability distribution. This means the generated text will, on average, contain more green-listed tokens than unwatermarked text would.
  4. Detection: To detect a watermark in a given text, the same green/red list partitioning process is re-applied to each token based on its predecessor. The number of green-listed tokens is counted. If this count is significantly higher than what would be expected from random text (or text generated by an unwatermarked model), the text is flagged as watermarked.

The use of the previous token to determine the current green/red list is crucial: it makes the watermark's pattern context-dependent, spreading it throughout the text and making it robust to local edits or truncations.

Design Decision: Why Context-Dependent Green/Red Lists?

A simple, fixed green/red list for the entire generation would be too easy to detect and remove. If an adversary knew the fixed green list, they could simply rephrase sentences to avoid those tokens. By making the green/red partition depend on the *previous* token, the pattern becomes dynamic and distributed. An editor would need to know the secret key and the partitioning algorithm to effectively remove the watermark, which is computationally infeasible without destroying the text's meaning.

🔑 Key Property

The watermark is statistical and soft. It does not force every token to be green, nor does it guarantee a perfect green/red alternation. Instead, it subtly shifts the *overall proportion* of green tokens in the generated text, making it statistically distinguishable from unwatermarked text while maintaining high text quality and coherence.

3
Why It Works — The Math
▼

Watermark Generation: Biasing Logits

Let \(z \in \mathbb{R}^{|V|}\) be the raw logits for the next token, where \(|V|\) is the vocabulary size. Let \(t_{prev}\) be the ID of the previously generated token. A pseudo-random function \(h(\cdot, \text{key})\) generates a seed, which is then used to partition the vocabulary \(V\) into a green list \(V_G\) and a red list \(V_R\), such that \(V_G \cup V_R = V\) and \(V_G \cap V_R = \emptyset\). We define an indicator function \(\mathbb{I}(i \in V_G)\) which is 1 if token \(i\) is in the green list, 0 otherwise.

The logits are then biased:

$$z'_i = z_i + \delta \cdot \mathbb{I}(i \in V_G)$$

where \(\delta > 0\) is the bias strength. The probabilities \(p'\) are computed using the softmax function on these biased logits:

$$p'_i = \frac{e^{z'_i}}{\sum_{j=1}^{|V|} e^{z'_j}}$$

The next token is sampled from this distribution \(p'\). This process is repeated for each token, with the green/red list dynamically changing based on the preceding token.

Watermark Detection: Statistical Significance

Given a generated text \(x = (x_1, x_2, \dots, x_L)\) of length \(L\), we iterate through it (starting from \(x_2\), using \(x_1\) as the initial previous token). For each token \(x_k\), we re-create the green/red list based on \(x_{k-1}\) and count if \(x_k\) falls into its corresponding green list. Let \(C_G\) be the total count of green tokens in the text.

Under the null hypothesis (\(H_0\)) that the text is unwatermarked and tokens are chosen randomly with respect to the green/red list (i.e., the original model's probabilities are uniformly distributed across the lists, or the text is human-generated), the expected number of green tokens is \(\mu_0 = L_{eff} \cdot \rho_G\), where \(L_{eff}\) is the number of tokens checked (typically \(L-1\)) and \(\rho_G = |V_G|/|V|\) is the expected proportion of green tokens. The variance is \(\sigma_0^2 = L_{eff} \cdot \rho_G \cdot (1 - \rho_G)\).

We can then compute a Z-score to assess the statistical significance:

$$Z = \frac{C_G - \mu_0}{\sigma_0}$$

A high \(Z\)-score (e.g., \(Z > 4\)) indicates that the observed number of green tokens is highly unlikely under the null hypothesis, suggesting the text is watermarked.

⚠️ Common Pitfall

Watermarks are not perfectly robust to adversarial attacks or heavy editing. Aggressive paraphrasing, summarization, or translation can dilute or destroy the statistical signal. The watermark is designed to detect *original* LLM output, not to survive arbitrary transformations. The strength of the watermark (\(\delta\)) is a trade-off: higher \(\delta\) means easier detection but potentially lower text quality/diversity.

Key Takeaways
▼

When to use watermarking:

  • To detect content generated by your specific LLM, for example, to identify misuse or attribute origin.
  • To discourage malicious use of LLMs (e.g., generating fake news, spam) by making the source detectable.
  • In scenarios where proving the origin of text is important for trust and accountability.
  • When you need a lightweight, statistical signal that doesn't significantly degrade text quality.

When NOT to use:

  • If perfect, unremovable attribution is required (no current watermark is truly unremovable).
  • For sensitive applications where any slight degradation in text quality or diversity is unacceptable.
  • If the generated text is expected to undergo heavy human editing, paraphrasing, or translation, which can erase the watermark.
  • With very short outputs, where the statistical signal might not be strong enough for reliable detection.
💡 Trade-offs

LLM watermarking involves a fundamental trade-off between detectability (how easy it is to find the watermark), quality/diversity (how much the watermark affects the generated text), and robustness (how well it survives transformations). The bias strength \(\delta\) and green list ratio \(\rho_G\) are key hyperparameters to tune for these trade-offs.

Code Trace (Python-like Pseudocode)
▼
import numpy as np
import hashlib
VOCAB_SIZE = 10000
WATERMARK_SEED = 12345 # Secret key for partitioning
def get_green_red_lists(prev_token_id, green_ratio=0.5):
# Deterministically generate a seed for RNG based on prev_token_id and secret key
combined_seed = WATERMARK_SEED + prev_token_id
rng = np.random.RandomState(combined_seed)
# Shuffle vocabulary indices and split based on green_ratio
shuffled_vocab = rng.permutation(VOCAB_SIZE)
num_green = int(VOCAB_SIZE * green_ratio)
green_list = set(shuffled_vocab[:num_green])
red_list = set(shuffled_vocab[num_green:])
return green_list, red_list
def watermark_logits(logits, prev_token_id, delta, green_ratio):
green_list, _ = get_green_red_lists(prev_token_id, green_ratio)
biased_logits = np.copy(logits)
for token_id in green_list:
if token_id < len(biased_logits): # Ensure token_id is within current logits length
biased_logits[token_id] += delta
return biased_logits
def softmax(x):
e_x = np.exp(x - np.max(x)) # Subtract max for numerical stability
return e_x / e_x.sum()
def detect_watermark(generated_text_ids, green_ratio):
if len(generated_text_ids) < 2: return 0.0 # Need at least 2 tokens for detection
green_token_count = 0
effective_length = len(generated_text_ids) - 1
for i in range(1, len(generated_text_ids)):
prev_token_id = generated_text_ids[i-1]
current_token_id = generated_text_ids[i]
green_list, _ = get_green_red_lists(prev_token_id, green_ratio)
if current_token_id in green_list:
green_token_count += 1
# Calculate Z-score
expected_green = effective_length * green_ratio
std_dev_green = np.sqrt(effective_length * green_ratio * (1 - green_ratio))
if std_dev_green == 0: return 0.0
z_score = (green_token_count - expected_green) / std_dev_green
return z_score
