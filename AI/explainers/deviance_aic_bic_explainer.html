Trading goodness-of-fit against complexity to find the best generalizing model
Intermediate Classical ML Stats GLM / Regression
1
Understanding the Criteria
▼

What is this? When fitting statistical models you face a dilemma: a more complex model always fits the training data better, but it may fit future data worse. Deviance, AIC, and BIC are principled scorecards that penalize complexity so you can objectively compare models of different sizes and pick the one that generalizes best.

Analogy: Imagine you are hiring a consultant. A generalist charges little but may not solve your specific problem. A hyper-specialist knows everything about your exact case, but costs a fortune and won't apply anywhere else. AIC and BIC are the cost-benefit calculators that help you decide how much specialization is actually worth paying for.

💡 If you remember one thing

AIC = \(-2\ell + 2k\) and BIC = \(-2\ell + k\ln n\). Both reward log-likelihood \(\ell\) (fit) and punish the number of free parameters \(k\) (complexity). BIC imposes a heavier penalty that grows with sample size \(n\), making it prefer simpler models as you collect more data. Always pick the model with the lowest AIC or BIC.

🔑 Deviance

Deviance measures how much worse a candidate model is compared to the saturated model (one with a parameter for every observation, i.e., a perfect fit): $$D = 2\bigl(\ell_{\text{saturated}} - \ell_{\text{model}}\bigr)$$ A deviance of 0 means perfect fit. Larger deviance = worse fit. AIC and BIC build on \(-2\ell\) (equivalent to deviance up to a constant), adding the complexity penalty.

2
How Deviance, AIC & BIC Work Internally
▼

Deviance as a GLM Goodness-of-Fit Statistic

In a Generalized Linear Model (GLM), we maximize a log-likelihood \(\ell(\hat{\theta}; y)\) over model parameters. The saturated model sets \(\hat{\theta}_i = y_i\) for every observation — it achieves the maximum possible log-likelihood \(\ell_{\text{sat}}\). The null model fits only an intercept. Any model you actually want to use lies in between.

$$D(\text{model}) = 2\bigl[\ell(\hat{\theta}_{\text{sat}}; y) - \ell(\hat{\theta}_{\text{model}}; y)\bigr] \geq 0$$

For a Poisson GLM with observed counts \(y_i\) and fitted means \(\hat{\mu}_i\), the deviance simplifies to:

$$D_{\text{Poisson}} = 2\sum_{i=1}^n \left[ y_i \ln\!\left(\frac{y_i}{\hat{\mu}_i}\right) - (y_i - \hat{\mu}_i) \right]$$

For a Gaussian (normal) GLM (i.e., OLS regression), deviance equals the residual sum of squares \(\text{RSS}/\hat{\sigma}^2\) — so the familiar RSS-based model comparison is a special case of deviance.

AIC — Akaike Information Criterion

Derived from information theory (Kullback-Leibler divergence minimization), AIC estimates the expected predictive performance of the model on new data from the same process:

$$\text{AIC} = -2\ell(\hat{\theta}) + 2k$$

where \(k\) is the number of estimated parameters. AIC penalizes complexity lightly — the penalty \(2k\) does not depend on sample size \(n\). AIC tends to pick models that are good for prediction.

BIC — Bayesian Information Criterion

Derived as an approximation to the log marginal likelihood (evidence) under a Bayesian model comparison framework:

$$\text{BIC} = -2\ell(\hat{\theta}) + k\ln n$$

Because \(\ln n\) grows with sample size, BIC applies an increasingly heavy penalty as \(n\) increases. For \(n \geq 8\) we have \(\ln n > 2\), so BIC penalizes more than AIC and tends to prefer simpler, more interpretable models. BIC is also asymptotically consistent: as \(n \to \infty\) it selects the true model (if it is in the candidate set).

⚠️ The Trade-off

Lower = better for both AIC and BIC. As model complexity increases, \(-2\ell\) decreases (better fit) but the penalty increases. The criterion achieves its minimum at the sweet spot — the point where adding more parameters stops being worth the cost.

3
Why They Work — The Math
▼

AIC Derivation (Information-Theoretic)

Let the true data-generating process have density \(g(y)\). We want to approximate \(g\) with a parametric family \(f(y;\theta)\). The KL divergence is:

$$D_{\mathrm{KL}}(g \| f_\theta) = \int g(y)\ln\frac{g(y)}{f(y;\theta)}\,dy = \mathrm{const} - \mathbb{E}_g[\ln f(y;\theta)]$$

We want to minimise \(D_{\mathrm{KL}}\), which means maximising \(\mathbb{E}_g[\ln f]\). The natural estimator is the training log-likelihood \(\ell(\hat\theta)\). But \(\hat\theta\) is fitted to training data, so \(\ell(\hat\theta)\) is an optimistic estimate of expected log-likelihood on new data. Akaike (1974) showed that the bias correction is exactly \(k\) parameters:

$$\mathbb{E}[\ell_{\text{new}}(\hat\theta)] \approx \ell(\hat\theta) - k \implies \text{AIC} = -2\ell(\hat\theta) + 2k$$

BIC Derivation (Bayesian)

Under a Bayesian model comparison, the posterior probability of model \(M\) is proportional to the marginal likelihood (evidence) \(p(y \mid M)\). By Laplace approximation:

$$\ln p(y \mid M) \approx \ell(\hat\theta) - \frac{k}{2}\ln n + \text{const}$$

Multiplying by \(-2\) gives BIC. Schwarz (1978) showed this approximation becomes exact as \(n \to \infty\), making BIC a consistent model selector.

AICc — Corrected AIC for Small Samples

When \(n/k\) is small (rule of thumb: \(n/k < 40\)), AIC underpenalizes. The correction is:

$$\text{AICc} = \text{AIC} + \frac{2k(k+1)}{n - k - 1}$$

As \(n \to \infty\), AICc \(\to\) AIC, so AICc is always preferred over AIC in practice.

📐 Key Formula Summary

\(\text{Deviance} = 2(\ell_{\text{sat}} - \ell_{\text{model}})\)
\(\text{AIC} = -2\ell + 2k\)
\(\text{BIC} = -2\ell + k\ln n\)
\(\text{AICc} = -2\ell + 2k + \frac{2k(k+1)}{n-k-1}\)
\(\Delta\text{AIC}_i = \text{AIC}_i - \min_j \text{AIC}_j\) (models with \(\Delta < 2\) have strong support)

Key Takeaways & When to Use
▼

Decision Guide

  • Use AIC when your goal is prediction accuracy and you are willing to risk slight model complexity.
  • Use BIC when you want to identify the true generating model (model identification) or interpretability matters.
  • Use AICc when \(n/k < 40\) — always prefer AICc over AIC in small samples.
  • Use deviance to compare nested GLMs: the deviance difference \(\Delta D \sim \chi^2(\Delta k)\) under \(H_0\) that the simpler model is correct (likelihood ratio test).

When NOT to use:

  • Comparing non-nested models with different response transformations (the log-likelihood is not comparable).
  • Very large \(k\) relative to \(n\) — consider cross-validation instead.
  • When the true model is not in your candidate set — all criteria will just pick the best available approximation.
💡 BIC vs AIC in Practice

For \(n=20\), \(\ln 20 \approx 3.0\), so BIC's per-parameter penalty is 3 vs AIC's 2. For \(n=1000\), \(\ln 1000 \approx 6.9\). This is why BIC increasingly prefers simpler models as datasets grow — it incorporates the Bayesian idea that with more evidence you can be more confident in the simpler explanation.

Code Trace — Polynomial Model Selection
▼
import numpy as np
from scipy import stats
# 20 noisy observations from true cubic model
np.random.seed(42)
n = 20
x = np.linspace(-2, 2, n)
y = 0.5 + 1.2*x - 0.8*x**2 + 0.3*x**3 + np.random.normal(0, 0.5, n)
results = []
for degree in range(1, 9):
# Design matrix: [1, x, x^2, ..., x^degree]
X = np.column_stack([x**i for i in range(degree+1)])
beta, _, _, _ = np.linalg.lstsq(X, y, rcond=None)
y_hat = X @ beta
# MLE log-likelihood for Gaussian errors
rss = np.sum((y - y_hat)**2)
sigma2_mle = rss / n # MLE variance estimate
loglik = (-n/2) * np.log(2*np.pi*sigma2_mle) - rss/(2*sigma2_mle)
k = degree + 1 + 1 # beta coefficients + sigma^2
aic = -2*loglik + 2*k
bic = -2*loglik + k * np.log(n)
results.append({'degree': degree, 'aic': aic, 'bic': bic})
best_aic = min(results, key=lambda r: r['aic'])
best_bic = min(results, key=lambda r: r['bic'])
print(f"Best AIC: degree {best_aic['degree']}") # → degree 3
print(f"Best BIC: degree {best_bic['degree']}") # → degree 3
