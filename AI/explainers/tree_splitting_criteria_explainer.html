Decision Tree Splitting Criteria

How a tree picks the best split — Gini impurity, entropy, gain ratio, and variance reduction
Intermediate Classical ML Decision Trees O(n log n) per feature
1
Understanding Splitting Criteria
▼

What is a splitting criterion? A decision tree learns by recursively dividing data into groups. At each step, it must choose one feature and one threshold — a "split" — that best separates the data. A splitting criterion is the mathematical scorecard that measures how good a candidate split is.

Analogy: Imagine sorting a bag of mixed red and blue marbles into two smaller bags. A perfect split puts all reds in one bag and all blues in the other — you can tell exactly which colour any marble is just by knowing which bag it came from. A bad split leaves both bags equally mixed. The splitting criteria are mathematical ways to measure how "pure" each resulting bag is.

Four criteria covered here:

  • Gini impurity — probability of misclassifying a randomly drawn sample using the node's class distribution
  • Entropy / Information Gain — reduction in uncertainty (bits) achieved by the split
  • Gain Ratio — information gain normalized by the intrinsic information of the split (fixes C4.5's multi-value bias)
  • Variance Reduction — for regression trees: drop in output variance achieved by the split
If you remember one thing

Every criterion measures impurity — how mixed the class labels are in a node. The best split is the one that most reduces impurity after dividing the parent node into children. Gini and entropy nearly always agree on the best split; the difference is mainly in edge cases and computation speed.

2
How Each Criterion Works Internally
▼

Gini Impurity

For a node containing \(n\) samples across \(K\) classes, let \(p_k\) be the fraction of samples belonging to class \(k\). Gini impurity is:

$$G = 1 - \sum_{k=1}^{K} p_k^2$$

\(G = 0\) when the node is pure (one class). \(G = 0.5\) (binary) or \(G = 1 - 1/K\) (multi-class) at maximum impurity. The gain from a split into left child \(L\) and right child \(R\) is:

$$\Delta G = G_{\text{parent}} - \frac{n_L}{n} G_L - \frac{n_R}{n} G_R$$

Entropy and Information Gain

Shannon entropy measures uncertainty in the node's class distribution:

$$H = -\sum_{k=1}^{K} p_k \log_2 p_k$$

\(H = 0\) for a pure node; \(H = \log_2 K\) at maximum uncertainty. Information gain (IG) is the reduction in entropy:

$$\text{IG} = H_{\text{parent}} - \frac{n_L}{n} H_L - \frac{n_R}{n} H_R$$

Gain Ratio (C4.5)

A feature with many unique values (e.g., a customer ID) trivially maximizes IG by creating one leaf per sample. C4.5's gain ratio penalizes this by dividing IG by the "split information" — the entropy of the split itself:

$$\text{SplitInfo} = -\sum_{i \in \{L,R\}} \frac{n_i}{n} \log_2 \frac{n_i}{n}$$
$$\text{GainRatio} = \frac{\text{IG}}{\text{SplitInfo}}$$

A highly unbalanced split (e.g., 1 vs 999 samples) has low SplitInfo, so a mediocre IG is not over-rewarded.

Variance Reduction (Regression Trees)

For regression, the node "impurity" is the variance of the target values \(y\). The reduction is:

$$\text{VR} = \text{Var}(y_{\text{parent}}) - \frac{n_L}{n}\,\text{Var}(y_L) - \frac{n_R}{n}\,\text{Var}(y_R)$$
Key design decision: why Gini over entropy?

sklearn defaults to Gini because it avoids the \(\log_2\) computation — faster on large datasets. Entropy penalizes near-pure nodes more heavily (steeper near \(p=0,1\)). In practice, the trees they produce are nearly identical. Gain ratio (C4.5) is preferred when features have very different numbers of distinct values.

3
Why It Works — The Math
▼

Gini Impurity: Probabilistic Interpretation

Draw a random sample from the node and label it using the node's class distribution. Draw a second random sample independently. Gini impurity equals the probability they belong to different classes:

$$G = \Pr(\text{mislabel}) = 1 - \sum_k p_k^2 = \sum_{j \neq k} p_j p_k$$

Entropy: Connection to Information Theory

Shannon's entropy \(H(X) = -\sum_k p_k \log_2 p_k\) measures the expected number of bits needed to encode the class label of a random sample from this node. A pure node (\(p_k=1\) for one class) needs 0 bits — no uncertainty. A balanced binary node needs 1 bit. Information gain IG is the mutual information \(I(X; S)\) between the class label \(X\) and the binary split indicator \(S\).

Numerical Trace — Worked Example

Parent: 10 samples, 6 positive, 4 negative. Split: Left=6 samples (5+,1−), Right=4 samples (1+,3−).

$$G_{\text{parent}} = 1 - (0.6^2 + 0.4^2) = 1 - 0.52 = 0.48$$
$$G_L = 1 - \left(\tfrac{5}{6}\right)^2 - \left(\tfrac{1}{6}\right)^2 = 1 - 0.6944 = 0.3056$$
$$G_R = 1 - (0.25^2 + 0.75^2) = 1 - 0.625 = 0.375$$
$$\Delta G = 0.48 - \tfrac{6}{10}(0.3056) - \tfrac{4}{10}(0.375) = 0.48 - 0.1833 - 0.15 = 0.1467$$

Entropy version: \(H_{\text{parent}} = 0.9710\), \(H_L = 0.6500\), \(H_R = 0.8113\), \(\text{IG} = 0.2564\).

Common Pitfall: Multi-Value Feature Bias

A feature with \(n\) unique values can create \(n\) pure children — trivially maximizing IG. Gain ratio corrects this by penalizing high \(\text{SplitInfo}\). Without this correction, ID3 greedily selects unique-value features and produces useless trees.

Comparison & Key Takeaways
▼
CriterionFormulaRangeTaskUsed inBias
Gini\(1-\sum p_k^2\)[0, 0.5]ClassificationCART, sklearnFavours larger partitions
Entropy / IG\(-\sum p_k\log_2 p_k\)[0, log₂K]ClassificationID3Favours high-value-count features
Gain RatioIG / SplitInfo[0, 1]ClassificationC4.5Corrects multi-value bias

When to use each

  • Gini: default choice for classification — fast (no log) and performs nearly identically to entropy
  • Entropy / IG: when interpretability as "bits of information" matters; slightly more expensive
  • Gain Ratio: when features have highly unequal cardinality (e.g., mixing continuous and categorical)
  • Variance Reduction: only for regression targets; use mean absolute deviation if outliers are a concern
Bottom line

Gini and entropy produce near-identical trees in practice. The real split decisions in production (random forests, gradient boosting) matter far more than which impurity measure you choose. Gain ratio matters most in single-tree C4.5-style classifiers with heterogeneous features.

Code Trace — From Scratch
▼
import numpy as np
from math import log2
def gini(y): # y: array of class labels
n = len(y)
if n == 0: return 0.0
classes, counts = np.unique(y, return_counts=True)
probs = counts / n
return 1.0 - np.sum(probs ** 2) # G = 1 - Σ pₖ²
def entropy(y):
n = len(y)
if n == 0: return 0.0
_, counts = np.unique(y, return_counts=True)
probs = counts / n
return -np.sum(p * log2(p) for p in probs if p > 0)
def best_split(X, y, criterion='gini'):
impurity_fn = gini if criterion == 'gini' else entropy
parent_imp = impurity_fn(y)
best_gain, best_thresh = -1, None
thresholds = np.unique(X) # candidate thresholds
for t in thresholds:
left = y[X <= t]
right = y[X > t]
n_L, n_R, n = len(left), len(right), len(y)
gain = parent_imp - (n_L/n)*impurity_fn(left) - (n_R/n)*impurity_fn(right)
if gain > best_gain:
best_gain, best_thresh = gain, t
return best_thresh, best_gain
def gain_ratio(X, y):
thresh, ig = best_split(X, y, 'entropy')
n = len(y)
mask = X <= thresh
n_L, n_R = mask.sum(), (~mask).sum()
split_info = entropy(np.array([0]*n_L + [1]*n_R)) # H of split
return thresh, ig / split_info if split_info > 0 else 0
def variance_reduction(X, y_reg):
parent_var = np.var(y_reg)
best_vr, best_thresh = -1, None
for t in np.unique(X):
L, R = y_reg[X <= t], y_reg[X > t]
n_L, n_R, n = len(L), len(R), len(y_reg)
vr = parent_var - (n_L/n)*np.var(L) - (n_R/n)*np.var(R)
if vr > best_vr: best_vr, best_thresh = vr, t
return best_thresh, best_vr
