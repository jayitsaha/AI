R-CNN: Regions with CNN Features

How a three-stage pipeline — selective search, CNN feature extraction, and per-class SVMs — turned object detection into a solvable problem
Advanced Computer Vision · Object Detection ~2000 region props/image

Understanding the Concept
▾

What is this? R-CNN answers the question "what objects are in this image, and exactly where?" Instead of scanning the entire image at every possible box size and position (impossibly slow), it first guesses a couple thousand plausible boxes, then asks a neural network to describe each one, then asks a simple classifier to name what's inside.

Analogy: Imagine sorting mail in a huge warehouse. Instead of inspecting every square inch of the floor, someone first walks around and points at ~2000 "probably-a-package" shaped blobs (selective search). For each blob, a photographer takes one standardized photo (CNN feature extraction — always the same 227×227 framing). Then a panel of specialists — one for "electronics," one for "clothing," one for "books" — each independently scores the photo (SVMs). Whoever scores highest wins, and any specialist that finds two near-identical photos of the same package throws away the worse one (NMS).

One-sentence summary: R-CNN turns object detection into region proposal + CNN feature extraction + per-class SVM classification + box refinement, run independently as four separate stages.

If you remember one thing
R-CNN's contribution wasn't a clever detector — it was proving that features from an ImageNet-pretrained CNN, transplanted onto arbitrary image regions, crush every hand-engineered feature (HOG, SIFT) that came before, even though CNNs were never designed for localization.

How It Works Internally
▾

The Problem & What Came Before

Pre-2014 detectors (Deformable Parts Models, sliding-window HOG+SVM) hand-crafted features and slid a fixed-size window across every scale and location of the image — expensive, and the features (gradients, edges) hit a performance ceiling on PASCAL VOC around 33–35% mAP. Meanwhile AlexNet (2012) had just shown CNNs crush hand-crafted features on classification. The question was whether that gain transfers to localization, where you also need a box, not just a label.

The Four Stages

  • 1. Region proposals (Selective Search): over-segment the image into ~small superpixels (Felzenszwalb-Huttenlocher graph segmentation), then greedily merge visually similar neighboring regions (by color, texture, size, fill) across many scales. Every intermediate merged region becomes a candidate box — roughly ~2000 proposals per image, with high recall on real object boundaries at a fraction of the cost of sliding windows.
  • 2. Warping: each proposal's box (any aspect ratio) is cropped, a small context margin (16px) added, then anisotropically warped to a fixed 227×227 square — because the CNN's fully-connected layers demand a fixed input size.
  • 3. CNN feature extraction: the warped patch is forward-passed through an AlexNet-style CNN (5 conv layers + 2 FC layers), pretrained on ImageNet classification and then fine-tuned on the detection dataset with an extra (N+1)-way softmax. Only the fc7 activations — a 4096-dim vector — are kept as the region's feature descriptor for the next stage.
  • 4. Classification & refinement: a separate linear SVM per class (trained after the CNN, not jointly) scores each 4096-d feature vector. Greedy non-max suppression per class removes duplicate boxes covering the same object. Finally a class-specific linear regressor nudges each surviving box's (x, y, w, h) toward the ground truth.

Why Four Separate Stages? (Design Decision)

Training one end-to-end network for both localization and classification in 2014 was numerically unstable at this scale, so Girshick et al. decoupled it: fine-tune the CNN with softmax (good gradient signal, cheap), then freeze it and train SVMs on cached features (SVMs handle the specific positive/negative mining regime — tight IoU>0.5 positives, hard-negative mining — better than softmax at the time). This modularity is exactly what later Fast/Faster R-CNN eliminated by making everything differentiable end-to-end.

Failure mode
Because every one of the ~2000 regions is fed through the CNN independently, R-CNN needs ~2000 forward passes per image — roughly 47 seconds/image on a GPU in the original paper. This redundant computation (the same pixels get re-convolved dozens of times across overlapping proposals) is precisely the bottleneck Fast R-CNN fixed with a single shared conv pass plus RoI pooling.

Why It Works — The Math
▾

SVM Scoring

For a region with CNN feature vector \(x \in \mathbb{R}^{4096}\), each class \(c\) has a learned weight vector \(w_c\) and bias \(b_c\). The decision score is a simple linear function:

$$s_c(x) = w_c^\top x + b_c$$

The predicted class is \(\hat{c} = \underset{c}{\operatorname{argmax}}\; s_c(x)\). Each per-class SVM is trained with hinge loss against the standard soft-margin objective:

$$\min_{w_c,b_c} \tfrac{1}{2}\|w_c\|^2 + C\sum_i \max(0,\, 1 - y_i(w_c^\top x_i + b_c))$$

where \(y_i \in \{-1,+1\}\). Crucially, positives are boxes with IoU > 0.5 with ground truth and negatives are mined hard — background regions the current classifier scores confidently high for, added iteratively (hard-negative mining), which is what let SVMs outperform the CNN's own softmax at the time.

Intersection over Union (IoU) & Non-Max Suppression

Overlap between two boxes \(A\) and \(B\) is measured with:

$$\text{IoU}(A,B) = \frac{|A \cap B|}{|A \cup B|}$$

Greedy NMS: sort boxes of a class by SVM score descending; keep the top box; discard every remaining box with \(\text{IoU} > \tau\) against it (typically \(\tau \approx 0.3\)–\(0.5\)); repeat on what's left.

Bounding-Box Regression

A proposal box \(P=(P_x,P_y,P_w,P_h)\) is refined toward ground truth \(G\) by predicting scale-invariant offsets from pooled conv-5 features \(\phi(P)\) via a linear model \(d_\star(P) = w_\star^\top \phi(P)\):

$$\hat{G}_x = P_w\, d_x(P) + P_x \qquad \hat{G}_y = P_h\, d_y(P) + P_y$$
$$\hat{G}_w = P_w \exp(d_w(P)) \qquad \hat{G}_h = P_h \exp(d_h(P))$$

The \(\exp\) on width/height guarantees the regressed box always has positive size; the \(x,y\) offsets are scaled by the proposal's own width/height so the regression is invariant to the proposal's scale and position.

Key invariant
Every regression target is defined relative to the proposal box itself, not in absolute pixels — this is why the same regressor generalizes across boxes of wildly different sizes.
Common misconception
"SVMs classify raw pixels." They don't — they classify the CNN's fc7 embedding of the warped region. The SVM boundary is linear in feature space, but because the CNN feature map is a highly nonlinear function of pixels, the effective decision boundary in pixel space is complex.

Key Takeaways
▾
  • R-CNN = selective search (region proposals) → warp to 227×227 → CNN fc7 features (4096-d) → per-class linear SVM → greedy NMS → bounding-box regression.
  • The big idea that survived: transfer learning — pretrain a CNN on ImageNet classification, then fine-tune/reuse its features for a completely different task (localization) with far less labeled data than training from scratch.
  • The big idea that got replaced: running the CNN 2000 times per image. Fast R-CNN runs it once and pools per-region features from a shared conv map; Faster R-CNN replaces selective search with a learned Region Proposal Network; both make the whole pipeline end-to-end differentiable.
  • Use R-CNN today only to understand the lineage of modern detectors — for production, use Faster R-CNN, YOLO, or DETR-family models.
