Computer Vision · Transformer Architecture

Vision Transformer (ViT)

Split an image into fixed-size patches, embed them like word tokens, prepend a learnable [CLS] token, add positional encodings, and let a standard Transformer encoder do the rest — no convolutions required.

Advanced Computer Vision Transformers O(N² · d)
1
Understanding the Concept
▼

What is it? A Vision Transformer treats an image exactly like a sentence. It chops the image into a grid of small square patches (say 16×16 pixels), flattens each patch into a vector, and linearly projects it into an embedding — precisely how a word becomes a token embedding in NLP. A learnable [CLS] token is glued to the front of the sequence, positional embeddings are added so the model knows where each patch sat in the image, and the whole sequence is fed through a standard Transformer encoder (the same block used in BERT/GPT). After the last layer, the [CLS] token's final vector is passed through a small MLP head to produce class probabilities.

Analogy: Imagine cutting a photograph into a 4×4 grid of tiles, laying the tiles in a row, and asking 16 people (the patches) to have a group discussion (self-attention) about what's in the picture, while one extra "moderator" person ([CLS]) listens to everyone and forms the final verdict. Nobody looks only at their neighboring tile — every tile can directly "talk" to every other tile, no matter how far apart they are.

One-sentence summary: ViT reframes image classification as a sequence-modeling problem — patches are tokens, and a vanilla Transformer encoder finds long-range visual relationships that convolutions build up only gradually.

💡 If you remember one thing

ViT has almost no image-specific inductive bias — no convolutions, no locality prior baked into the architecture. It must learn spatial structure from data (or positional embeddings), which is why it needs large-scale pretraining (JFT-300M / ImageNet-21k) to beat CNNs.

2
How It Works Internally
▼

Given an image \(x \in \mathbb{R}^{H \times W \times C}\), ViT reshapes it into \(N = HW/P^2\) flattened patches \(x_p \in \mathbb{R}^{N \times (P^2 C)}\), where \(P\) is the patch side length (typically 16). Each flattened patch is linearly projected by a shared, learnable matrix \(E\) into a \(D\)-dimensional patch embedding — this single linear layer is the entire "vision" front-end; everything after it is generic sequence modeling.

  1. Patchify: slice the image into a regular non-overlapping grid of \(P \times P\) patches.
  2. Linear projection: flatten each patch and multiply by \(E \in \mathbb{R}^{(P^2C) \times D}\) to get patch embeddings \(x_p^i E\).
  3. Prepend [CLS]: a single learnable embedding \(x_{\text{class}}\) is placed at position 0 — its final-layer output is what gets classified.
  4. Add position embeddings: a learnable (or sinusoidal) vector \(E_{pos}\) is added per position so order/location information survives, since self-attention itself is permutation-invariant.
  5. Transformer encoder × L: alternating Multi-Head Self-Attention (MSA) and MLP blocks, each wrapped in LayerNorm + residual connections, exactly as in the original Transformer encoder.
  6. Classification head: the final [CLS] representation \(z_L^0\) is fed to a small MLP (one hidden layer at pretraining time, a single linear layer at fine-tuning time) to produce class logits.

Design decision — why [CLS] and not global-average-pool? ViT borrows the BERT convention: a dedicated token that attends to (and is attended to by) every patch lets the model learn an adaptive, content-dependent summary, rather than a fixed unweighted average. In practice both work almost identically well once you tune the learning rate — but [CLS] keeps the architecture a drop-in match for NLP Transformers.

⚠️ Common misconception

ViT is not "attention applied to raw pixels." Attention operates over the ~196 patch tokens (for a 224×224 image with 16×16 patches), not over the 50,176 individual pixels — that's what makes the \(O(N^2)\) self-attention cost tractable at all.

3
Why It Works — The Math
▼

The embedded sequence entering the encoder is:

$$z_0 = [\,x_{\text{class}};\; x_p^1 E;\; x_p^2 E;\; \dots ;\; x_p^N E\,] + E_{pos}$$

Each encoder layer applies Multi-Head Self-Attention. For a single head, queries/keys/values are linear projections of the token embeddings, and attention is scaled dot-product:

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

followed by residual MLP blocks:

$$z_\ell' = \text{MSA}(\text{LN}(z_{\ell-1})) + z_{\ell-1} \qquad z_\ell = \text{MLP}(\text{LN}(z_\ell')) + z_\ell'$$

The \(\sqrt{d_k}\) scaling exists because as head dimension \(d_k\) grows, raw dot products grow in variance ($\propto d_k$), pushing softmax into saturated, near-zero-gradient regions — dividing by \(\sqrt{d_k}\) keeps the pre-softmax variance close to 1.

Why it works despite no convolutional prior: self-attention gives every patch a direct, \(O(1)\)-hop path to every other patch (versus a CNN's receptive field, which grows only linearly with depth). With enough data, the model learns spatial locality and translation structure empirically — visualizing learned attention shows heads that behave like local convolutional filters in early layers and heads that attend globally in later layers.

📐 Key invariant

Self-attention is permutation-equivariant: shuffle the input tokens and the outputs shuffle identically. That's exactly why position embeddings \(E_{pos}\) are mandatory — without them, ViT literally cannot distinguish a patch at the top-left from one at the bottom-right.

5
Key Takeaways
▼
  • ViT = patchify → linear embed → prepend [CLS] → add positions → Transformer encoder → classify from [CLS]. No convolutions anywhere.
  • Self-attention gives every patch a direct connection to every other patch — great for long-range context, at \(O(N^2)\) cost in the number of patches.
  • With little data, ViT underperforms CNNs (ResNet) because it lacks translation-equivariance and locality priors. With enough pretraining data (JFT-300M scale), it matches or beats them.
  • Patch size \(P\) trades off sequence length vs. granularity: smaller \(P\) → more tokens → finer detail but quadratically more attention compute.
  • Use ViT when you have large pretraining corpora or can fine-tune from a strong checkpoint (e.g. ViT-B/16, DINOv2). Prefer CNNs / hybrid architectures for small, from-scratch datasets.

Code Trace — Patch Embedding + Attention (from scratch)
▼

A minimal, from-scratch PyTorch sketch of the two pieces that make ViT what it is: the patchify+linear-projection front end, and a single self-attention block.

import torch, torch.nn as nn
class PatchEmbed(nn.Module):
def __init__(self, img_size=224, patch=16, in_ch=3, dim=768):
super().__init__()
self.n_patches = (img_size // patch) ** 2
# a stride-P, kernel-P conv == "flatten patch + linear project"
self.proj = nn.Conv2d(in_ch, dim, kernel_size=patch, stride=patch)
def forward(self, x): # x: (B, 3, H, W)
x = self.proj(x) # (B, D, H/P, W/P)
return x.flatten(2).transpose(1, 2) # (B, N, D) patch tokens
class SelfAttention(nn.Module):
def __init__(self, dim, heads=1):
super().__init__()
self.scale = (dim // heads) ** -0.5
self.qkv = nn.Linear(dim, dim * 3)
self.out = nn.Linear(dim, dim)
def forward(self, z): # z: (B, N+1, D) incl. [CLS]
q, k, v = self.qkv(z).chunk(3, dim=-1)
attn = (q @ k.transpose(-2, -1)) * self.scale
attn = attn.softmax(dim=-1) # weights sum to 1 per row
return self.out(attn @ v) # weighted sum of values
# cls token + learnable position embeddings, prepended/added before
# the sequence enters L stacked (SelfAttention -> MLP) encoder blocks.
💡 Implementation trick

The patchify + flatten + linear-project step is implemented as a single Conv2d with kernel size = stride = patch size — mathematically identical to slicing patches and multiplying by a shared weight matrix \(E\), but reuses fast conv kernels.
