1
Understanding the Problem
▼

What is it? CLIP learns to match images with their captions by pulling matching pairs together and pushing mismatched pairs apart in a shared embedding space. It works beautifully, but it is starving for data: OpenAI's CLIP needed 400 million image-text pairs to reach its reported accuracy, because each pair gives the model exactly one gradient signal — "this image goes with this caption." DeCLIP, SLIP, and the compendium's "YCLIP" synthesis are a family of methods that ask: what if we squeezed extra, free supervision out of the same pairs instead of collecting more of them?

Analogy: Imagine studying for an exam using only flashcards that pair a photo with one caption — one fact learned per card. SLIP is like also noticing that two crops of the same photo should look similar to each other. DeCLIP goes further: it also notices near-duplicate flashcards in the deck (nearest-neighbour supervision) and studies augmented versions of both the photo and the caption. YCLIP, as used here, is the natural end-point — add a "senior self" (a slowly-updated momentum teacher) that quizzes a "student" version of the same network, distilling everything the other signals learned.

💡 If you remember one thing

Vanilla CLIP extracts exactly one supervisory signal per pair: \(\mathcal{L}_{CLIP}\). SLIP, DeCLIP, and YCLIP add free auxiliary signals — intra-modal self-supervision, multi-view cross-modal contrast, nearest-neighbour mining, and self-distillation — that come from the same pairs, so the model needs far fewer of them to reach the same accuracy. DeCLIP reports matching CLIP-ResNet50's 60.4% zero-shot ImageNet accuracy using 7.1× less data.

How Each Variant Works Internally
▼

SLIP — SimCLR meets Language-Image Pretraining (Mu et al., ECCV 2022)

SLIP simply runs a second, independent head next to CLIP's image tower and applies the SimCLR self-supervised loss to two randomly augmented crops of the same image, in addition to the ordinary CLIP cross-modal loss. The text tower is untouched. This is the cheapest possible add-on: one extra forward pass on augmented images, one extra NT-Xent loss term, added with weight \(\lambda\).

DeCLIP — "Supervision Exists Everywhere" (Li et al., 2021, arXiv:2110.05208)

DeCLIP stacks three auxiliary signals on top of CLIP: (1) Self-Supervision (SS) within each modality — a SimSiam-style predictor for images and a contrastive objective over augmented sentences for text; (2) Multi-View Supervision (MVS) — every augmented image view is also contrasted against every augmented text view, turning one pair into up to four cross-modal comparisons for free; (3) Nearest-Neighbour Supervision (NNS) — a FIFO memory queue of past text embeddings (MoCo-style) is searched for the caption nearest to the current image, and that neighbour is added as an extra soft positive, recovering the fact that many different captions can correctly describe similar images.

YCLIP — the self-distillation synthesis

This compendium entry uses "YCLIP" as the label for the natural next step along the same trajectory rather than one single canonical paper: take DeCLIP's full recipe and add a momentum teacher (an EMA copy of the network, BYOL/DINO-style) that distils both the image and text student branches. Visualised as a computation graph, the two self-supervised branches (image, text) are the upper arms of a "Y" that merge into one shared, teacher-guided cross-modal trunk — hence the name. Treat its numbers below as illustrative of where stacking these ideas leads, not a literal reproduction of a single paper's benchmark.

🔑 Key Property

Every added signal is self-supervised or mined from the existing batch — no new labels, no new images, no new captions are collected. Data efficiency comes from extracting more gradient directions per pair, not from better data.

Why It Works — The Math
▼

Base CLIP Loss (Symmetric InfoNCE)

For a batch of \(N\) pairs with L2-normalised image embeddings \(v_i\) and text embeddings \(t_i\), temperature \(\tau\):

$$\mathcal{L}_{CLIP} = -\frac{1}{2N}\sum_{i=1}^{N}\left[\log\frac{\exp(v_i^\top t_i/\tau)}{\sum_{j=1}^{N}\exp(v_i^\top t_j/\tau)} + \log\frac{\exp(t_i^\top v_i/\tau)}{\sum_{j=1}^{N}\exp(t_i^\top v_j/\tau)}\right]$$

SLIP adds one term

$$\mathcal{L}_{SLIP} = \mathcal{L}_{CLIP} + \lambda\,\mathcal{L}_{SimCLR}\!\left(v_i^{(1)}, v_i^{(2)}\right)$$

DeCLIP composes four

$$\mathcal{L}_{DeCLIP} = \underbrace{\textstyle\sum_{a,b\in\{1,2\}}\mathcal{L}_{CLIP}\!\left(v^{(a)}, t^{(b)}\right)}_{\text{multi-view (MVS)}} \;+\; \lambda_1\underbrace{\mathcal{L}_{SS}^{img}}_{\text{SimSiam}} \;+\; \lambda_2\underbrace{\mathcal{L}_{SS}^{txt}}_{\text{aug-contrast}} \;+\; \lambda_3\underbrace{\mathcal{L}_{NNS}}_{\text{queue-mined positive}}$$

YCLIP adds a distillation term

$$\mathcal{L}_{YCLIP} = \mathcal{L}_{DeCLIP} + \lambda_4\,\mathcal{L}_{distill}\!\left(f_\theta(v,t),\, f_{\bar\theta}(v,t)\right), \qquad \bar\theta \leftarrow m\bar\theta + (1-m)\theta$$

where \(f_{\bar\theta}\) is a momentum ("teacher") copy of the student network \(f_\theta\), updated by exponential moving average with momentum \(m\) — the standard BYOL/DINO/MoCo recipe repurposed across both modalities at once.

⚠️ Common Pitfall

Stacking auxiliary losses is not free: every \(\lambda_i\) must be tuned, MVS and NNS roughly double-to-quadruple the forward-pass cost per step, and a poorly-mined nearest neighbour can inject a false positive that hurts more than it helps. Data efficiency is traded for compute efficiency per step — DeCLIP needs fewer pairs but more FLOPs per pair than vanilla CLIP.

Key Takeaways
▼

Use these ideas when:

  • You have a fixed, small-to-medium image-text corpus (web-scale scraping is off the table)
  • Compute per step is less scarce than raw paired data (MVS/NNS/distillation add FLOPs, not pairs)
  • You want better linear-probe / zero-shot transfer without collecting more labels

Skip them when:

  • You already have hundreds of millions of clean pairs — vanilla CLIP's simplicity wins
  • Training throughput is the bottleneck, not data — extra forward passes slow every step down
  • Your text side is very short/noisy (alt-text) — text self-supervision and NNS mine less signal
💡 Hierarchy

CLIP (1 signal) ⊂ SLIP (+ image SS) ⊂ DeCLIP (+ text SS, + multi-view, + nearest-neighbour) ⊂ YCLIP (+ momentum self-distillation). Each layer adds a free auxiliary loss mined from the same batch, monotonically trading extra compute-per-step for fewer required pairs.

import torch, torch.nn.functional as F
def clip_loss(v, t, tau):
v, t = F.normalize(v, dim=-1), F.normalize(t, dim=-1)
logits = v @ t.T / tau
labels = torch.arange(len(v), device=v.device)
return (F.cross_entropy(logits, labels) +
F.cross_entropy(logits.T, labels)) / 2
def simclr_loss(z1, z2, tau):
z = F.normalize(torch.cat([z1, z2]), dim=-1)
sim = z @ z.T / tau
return nt_xent(sim) # standard SimCLR NT-Xent
def declip_step(img, txt, img_aug, txt_aug, queue, encode_i, encode_t):
v = encode_i(img)
v1, v2 = encode_i(img_aug[0]), encode_i(img_aug[1]) # 2 views
t = encode_t(txt)
t1, t2 = encode_t(txt_aug[0]), encode_t(txt_aug[1]) # 2 views
L_clip = clip_loss(v, t, tau)
L_mvs = clip_loss(v1, t1, tau) + clip_loss(v2, t2, tau) # MVS
L_ss = simsiam_loss(v1, v2) + simclr_loss(t1, t2, tau) # intra-modal SS
nn_txt = nearest_neighbor(v, queue) # NNS lookup
L_nns = clip_loss(v, nn_txt, tau)
queue.enqueue(t.detach()) # FIFO update
return L_clip + L_mvs + LAMBDA1 * L_ss + LAMBDA2 * L_nns
def yclip_step(student, teacher, batch, queue):
loss = declip_step(*batch, queue, student.enc_i, student.enc_t)
with torch.no_grad(): # EMA teacher
teacher_out = teacher(batch) # the 'Y' merge
loss += LAMBDA3 * distill_loss(student(batch), teacher_out)
ema_update(teacher, student, momentum=0.999)
