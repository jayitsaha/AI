Contextual Embeddings (ELMo)

The same word gets a different vector depending on what surrounds it
Intermediate NLP Representation Learning biLSTM · O(n)
1
Understanding Contextual Embeddings
▼

What is it? Older embedding methods like Word2Vec and GloVe assign every word exactly one fixed vector, no matter how it's used. The word "bank" gets the same coordinates in "I deposited cash at the bank" and "We sat by the river bank" — even though the two mean completely different things. ELMo (Embeddings from Language Models, 2018) fixes this by generating a fresh vector for every word occurrence, computed from the entire sentence around it.

Analogy: A static embedding is like a dictionary entry — one fixed definition, looked up by spelling alone. A contextual embedding is like asking a friend who just read the whole sentence what the word means here. Same spelling, different meaning, different answer — because the friend (a bidirectional LSTM language model) actually read the surrounding words before answering.

💡 If you remember one thing

ELMo runs a deep bidirectional LSTM language model over the sentence, then represents each word as a learned weighted combination of that model's internal layers — not a lookup-table row. The vector for "bank" is literally a function of every other word in the sentence.

2
How ELMo Works Internally
▼

Step 1 — Context-independent token layer

Each token first gets a "layer 0" vector \(x_k\) from a character-level CNN (so ELMo can handle rare/unseen words via subword structure). This layer is identical for "bank" no matter the sentence — it only knows the spelling.

Step 2 — A deep bidirectional LSTM language model

\(x_k\) is fed into a multi-layer biLSTM trained as a language model: a forward LSTM predicts the next word left-to-right, a separate backward LSTM predicts the previous word right-to-left. At every layer \(j\) and position \(k\), the forward hidden state \(\overrightarrow{h}_{k,j}\) has "read" every word to the left, and the backward hidden state \(\overleftarrow{h}_{k,j}\) has "read" every word to the right. Concatenating them, \(h_{k,j} = [\overrightarrow{h}_{k,j}; \overleftarrow{h}_{k,j}]\), gives a representation of "bank" that depends on both directions of context — money-words on the left, or river-words on the right, both leave a fingerprint.

Step 3 — Stack multiple biLSTM layers

ELMo uses 2 stacked biLSTM layers (plus residual connections). Higher layers tend to capture more abstract, semantic/contextual distinctions (word sense), while lower layers capture more syntactic ones (POS, local structure) — this was empirically verified by probing tasks in the original paper.

Step 4 — Learned layer-weighting (the key trick)

Instead of just taking the top layer's output (as most stacked-RNN models did before), ELMo collapses all layers — token layer + every biLSTM layer — into one task-specific vector using softmax-normalized learned scalar weights \(s_j\) and a scale \(\gamma\):

$$\text{ELMo}_k^{task} = \gamma^{task}\sum_{j=0}^{L} s_j^{task}\, h_{k,j}$$

Because \(s_j\) are learned per downstream task, a POS tagger can lean on lower (syntactic) layers while a coreference model can lean on higher (semantic) layers — the same frozen biLM serves many tasks.

🔑 Key Property

Every ELMo vector is a function of the entire input sentence, not just the token's spelling. Change one word anywhere in the sentence and every other word's vector can shift — this is impossible for Word2Vec/GloVe.

3
Why It Works — The Math
▼

The biLM training objective

The forward and backward LSTMs are each trained to maximize the log-likelihood of the sequence in their respective direction, sharing the token layer and softmax weights:

$$\sum_{k=1}^{N}\Big[\log p(t_k \mid t_1,\dots,t_{k-1}) + \log p(t_k \mid t_{k+1},\dots,t_N)\Big]$$

This is pure self-supervision — no labels needed, just raw text — so the biLM can be pretrained on huge corpora, then frozen and reused.

Inside one LSTM cell (what actually produces context-sensitivity)

At each position \(k\) the recurrence mixes the new input \(x_k\) with everything the hidden state has already accumulated, \(h_{k-1}\):

$$\begin{aligned} i_k &= \sigma(W_i x_k + U_i h_{k-1} + b_i) \quad f_k = \sigma(W_f x_k + U_f h_{k-1} + b_f) \\ o_k &= \sigma(W_o x_k + U_o h_{k-1} + b_o) \quad g_k = \tanh(W_g x_k + U_g h_{k-1} + b_g) \\ c_k &= f_k \odot c_{k-1} + i_k \odot g_k \qquad\quad h_k = o_k \odot \tanh(c_k) \end{aligned}$$

Because \(h_{k-1}\) is itself a function of \(x_1,\dots,x_{k-1}\), \(h_k\) recursively encodes the whole prefix. Run the same recurrence backward over the reversed sentence and you get a symmetric encoding of the whole suffix. Two different sentences sharing a word will produce two different prefixes/suffixes at that word — hence two different hidden states, even with identical LSTM weights and an identical starting token vector \(x_k\).

Layer mixing as weighted least-squares in feature space

The \(s_j\) are the softmax of unconstrained "raw" scores \(a_j\): \(s_j = \dfrac{\exp(a_j)}{\sum_{l}\exp(a_l)}\), guaranteeing \(\sum_j s_j = 1, s_j \ge 0\) — a convex combination of layers. \(\gamma\) is a free scalar that rescales the whole vector, important because the biLM's internal layer norms don't necessarily match the scale a downstream model expects.

⚠️ Common Misconception

"ELMo is a single vector per word, like Word2Vec, just bigger." False — ELMo produces a function \(f(\text{sentence}, \text{position}) \to \mathbb{R}^d\). There is no fixed lookup table; a word not seen during biLM pretraining can still get a sensible vector through the character-CNN token layer.

Key Takeaways
▼

When contextual embeddings help most:

  • Polysemous words — "bank", "bass", "cell", "spring" — where sense depends entirely on context
  • Downstream tasks with limited labeled data (NER, SRL, coreference, QA) — ELMo added ~2-4 F1 points across the board in 2018
  • Domains with rich local syntax the char-CNN + biLSTM can exploit (rare/misspelled words, morphology)

When NOT to reach for ELMo specifically:

  • Today, Transformer-based contextual encoders (BERT, RoBERTa) dominate — they model context with self-attention instead of recurrence, giving better long-range dependencies and full parallelism during training
  • If you need bidirectional context AND causal generation in one model, decoder-only Transformers (GPT-family) with causal attention are the modern default, not biLSTMs
  • Extremely latency-sensitive serving where even a small frozen LSTM forward pass is too slow — static embeddings or distilled models may be preferable
💡 Lineage

Word2Vec/GloVe (context-free) → ELMo (context-dependent via biLSTM + layer-weighting) → BERT/GPT (context-dependent via Transformer self-attention, often fine-tuned end-to-end rather than used as frozen features). ELMo's big conceptual contribution — that different network depths capture different linguistic phenomena, and a task should learn how to mix them — carries straight through to modern "probing" and layer-wise analysis of Transformers.

# --- LSTM cell: real recurrence, not a lookup table ---
def sigmoid(z): return 1 / (1 + np.exp(-z))
def lstm_step(x, h_prev, c_prev, W, U, b):
i = sigmoid(W['i']@x + U['i']@h_prev + b['i'])
f = sigmoid(W['f']@x + U['f']@h_prev + b['f'])
o = sigmoid(W['o']@x + U['o']@h_prev + b['o'])
g = np.tanh(W['g']@x + U['g']@h_prev + b['g'])
c = f * c_prev + i * g
h = o * np.tanh(c)
return h, c
