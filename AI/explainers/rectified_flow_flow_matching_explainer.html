Understanding Rectified Flow
▼

What is it? Rectified Flow (RF), often used with a training method called Flow Matching (FM), is a generative modeling technique that learns to transform a simple noise distribution (e.g., Gaussian) into a complex data distribution (e.g., images) by moving points along straight-line trajectories. Unlike diffusion models which often involve complex, noisy paths, RF aims for the simplest possible path: a straight line.

Analogy: Imagine you have a scattered pile of sand (noise) and you want to arrange it into a specific sculpture (data). Diffusion models might involve a complex, meandering process of adding and removing sand, sometimes getting messy. Rectified Flow is like having a perfect, invisible conveyor belt for each grain of sand, moving it directly from its initial random spot to its final position in the sculpture via the shortest possible straight line. The goal is to learn the "direction" each grain needs to move at any given moment to achieve this straight-line transformation.

💡 If you remember one thing

Rectified Flow learns a vector field \(\mathbf{v}(\mathbf{x}, t)\) that governs a continuous-time ordinary differential equation (ODE) \(\frac{d\mathbf{x}}{dt} = \mathbf{v}(\mathbf{x}, t)\). The "rectified" part means it explicitly trains to make the trajectories from noise \(\mathbf{x}_0\) to data \(\mathbf{x}_1\) as close to straight lines as possible, i.e., \(\mathbf{v}(\mathbf{x}(t), t) \approx \mathbf{x}_1 - \mathbf{x}_0\).

How Flow Matching Works Internally
▼

The Continuous Flow Perspective

Rectified Flow models the transformation from a simple source distribution \(p_0(\mathbf{x})\) (e.g., standard Gaussian noise) to a complex target data distribution \(p_1(\mathbf{x})\) as a continuous flow governed by an ODE: \(\frac{d\mathbf{x}}{dt} = \mathbf{v}(\mathbf{x}, t)\). Here, \(\mathbf{x}(t)\) represents a point evolving over time \(t \in [0, 1]\), and \(\mathbf{v}(\mathbf{x}, t)\) is a vector field that dictates its velocity.

The Coupling and Straight Trajectories

The core idea of Rectified Flow is to establish a "coupling" between points in the source and target distributions. For each noise sample \(\mathbf{x}_0 \sim p_0(\mathbf{x})\), there's a corresponding data sample \(\mathbf{x}_1 \sim p_1(\mathbf{x})\). The ideal, "rectified" trajectory between these two points is a straight line: \(\mathbf{x}(t) = (1-t)\mathbf{x}_0 + t\mathbf{x}_1\). The velocity vector field for such a straight line is simply \(\mathbf{v}(\mathbf{x}(t), t) = \mathbf{x}_1 - \mathbf{x}_0\).

Training with Flow Matching

Since we don't know the optimal coupling \((x_0, x_1)\) for all points, Flow Matching provides a way to train a neural network, \(\mathbf{u}_\theta(\mathbf{x}, t)\), to approximate this ideal vector field. Instead of directly learning the coupling, it samples \(\mathbf{x}_0 \sim p_0(\mathbf{x})\) and \(\mathbf{x}_1 \sim p_1(\mathbf{x})\) independently, then constructs an intermediate point \(\mathbf{x}_t = (1-t)\mathbf{x}_0 + t\mathbf{x}_1\) and a target vector \(\mathbf{v}_t = \mathbf{x}_1 - \mathbf{x}_0\). The network is then trained to predict this target vector at \(\mathbf{x}_t\).

Design Decision: Why Straight Lines?

Straight-line trajectories are desirable for two main reasons:

  1. Efficient Sampling: If the learned flow is truly rectified, it can be integrated with very few steps (even one step) using simple ODE solvers like Euler's method, leading to much faster generation compared to diffusion models that require many steps.
  2. Stable Training: The target vector field \(\mathbf{v}(\mathbf{x}(t), t) = \mathbf{x}_1 - \mathbf{x}_0\) is well-defined and easy to compute, making the training objective stable and effective.

🔑 Key Property

Flow Matching trains a neural network \(\mathbf{u}_\theta(\mathbf{x}, t)\) by minimizing the expected squared difference between its prediction and a simple target vector field. Critically, this target is derived from straight-line paths between independently sampled noise \(\mathbf{x}_0\) and data \(\mathbf{x}_1\).

3
Why It Works — The Math
▼

The ODE and Target Flow

The core idea is to find a vector field \(\mathbf{v}(\mathbf{x}, t)\) that transports samples from \(p_0(\mathbf{x})\) to \(p_1(\mathbf{x})\) via an ODE:

$$\frac{d\mathbf{x}}{dt} = \mathbf{v}(\mathbf{x}, t)$$

For a given pair of coupled points \((\mathbf{x}_0, \mathbf{x}_1)\), the straight-line path is defined as:

$$\mathbf{x}(t) = (1-t)\mathbf{x}_0 + t\mathbf{x}_1$$

Differentiating this path with respect to \(t\) gives the ideal velocity vector field for this specific trajectory:

$$\mathbf{v}_{\text{target}}(\mathbf{x}(t), t) = \frac{d}{dt}((1-t)\mathbf{x}_0 + t\mathbf{x}_1) = \mathbf{x}_1 - \mathbf{x}_0$$

This means that at any point \(\mathbf{x}(t)\) along a straight-line path at time \(t\), the velocity vector should simply be the difference between the end point and the start point of that specific trajectory.

The Flow Matching Objective

The goal is to train a neural network \(\mathbf{u}_\theta(\mathbf{x}, t)\) to approximate this target vector field. The Flow Matching objective minimizes the expected squared L2 distance between the network's prediction and the target field:

$$\mathcal{L}(\theta) = \mathbb{E}_{t \sim \mathcal{U}(0,1), \mathbf{x}_0 \sim p_0, \mathbf{x}_1 \sim p_1} \left[ \left\| \mathbf{u}_\theta((1-t)\mathbf{x}_0 + t\mathbf{x}_1, t) - (\mathbf{x}_1 - \mathbf{x}_0) \right\|^2 \right]$$

Here, \(t\) is uniformly sampled between 0 and 1, and \(\mathbf{x}_0\) and \(\mathbf{x}_1\) are independently sampled from their respective distributions. Crucially, the expectation is taken over the "marginal path distribution" \(p_t(\mathbf{x})\) where \(\mathbf{x} = (1-t)\mathbf{x}_0 + t\mathbf{x}_1\). The optimal \(\mathbf{u}_\theta\) for this objective is the conditional expectation \(\mathbb{E}[\mathbf{x}_1 - \mathbf{x}_0 \mid \mathbf{x}(t) = \mathbf{x}]\). If the conditional expectation is close to \(\mathbf{x}_1 - \mathbf{x}_0\), the resulting trajectories will be close to straight lines.

⚠️ Relationship to Optimal Transport

The straight-line paths \(\mathbf{x}(t) = (1-t)\mathbf{x}_0 + t\mathbf{x}_1\) are known as deterministic interpolations. While Flow Matching doesn't explicitly solve for the optimal transport (OT) coupling between \(p_0\) and \(p_1\), it often learns a flow that approximates it, especially when the initial noise \(\mathbf{x}_0\) and data \(\mathbf{x}_1\) are sampled independently. The "rectified" aspect refers to making the paths as straight as possible, which is a property of optimal transport maps for quadratic cost.

Key Takeaways
▼

When to use Rectified Flow / Flow Matching:

  • When you need highly efficient sampling for generative models (e.g., real-time image generation).
  • As an alternative to diffusion models, especially when the straight-line property is beneficial for interpretability or stability.
  • For applications where the underlying transformation can be well-approximated by simple, non-crossing trajectories.
  • If you are working with optimal transport theory and want a practical method to learn transport maps.

When to be cautious:

  • For extremely complex data distributions where a simple straight-line interpolation might struggle to capture intricate local structures without a very powerful neural network.
  • When the "coupling" between noise and data is highly non-trivial and cannot be easily represented by independent sampling and linear interpolation.
  • If the computational cost of training (which involves sampling from \(p_0\), \(p_1\), and \(t\) for each step) becomes a bottleneck, although this is often offset by faster inference.
💡 Broader Impact

Rectified Flow and Flow Matching represent a powerful paradigm in generative AI, bridging concepts from optimal transport, continuous normalizing flows, and ODE-based modeling. They offer a compelling alternative to diffusion models by prioritizing deterministic, direct transformations, leading to faster and often more stable generation. This approach is particularly promising for high-dimensional data like images and video.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
# Assume a simple MLP for the vector field u_theta(x, t)
class VectorField(nn.Module):
def __init__(self, input_dim, hidden_dim, output_dim):
super().__init__()
self.net = nn.Sequential(
nn.Linear(input_dim + 1, hidden_dim), # x and t as input
nn.ReLU(),
nn.Linear(hidden_dim, hidden_dim),
nn.ReLU(),
nn.Linear(hidden_dim, output_dim)
)
def forward(self, x, t):
# Concatenate x and t for the network input
return self.net(torch.cat([x, t.unsqueeze(-1)], dim=-1))
# --- Training Loop (Flow Matching) ---
model = VectorField(input_dim=2, hidden_dim=64, output_dim=2)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
num_epochs = 10000
for epoch in range(num_epochs):
optimizer.zero_grad()
# 1. Sample x0 from noise distribution p0
x0 = torch.randn(128, 2) # e.g., standard Gaussian
# 2. Sample x1 from data distribution p1
# (Assume p1_sampler is a function that returns data samples)
x1 = p1_sampler(128)
# 3. Sample time t uniformly from [0, 1]
t = torch.rand(128)
# 4. Compute interpolated point x_t and target vector v_t
x_t = (1 - t).unsqueeze(-1) * x0 + t.unsqueeze(-1) * x1
v_t = x1 - x0
# 5. Predict vector field u_theta at (x_t, t)
u_pred = model(x_t, t)
# 6. Compute MSE loss and update weights
loss = torch.mean((u_pred - v_t)**2)
loss.backward()
optimizer.step()
# --- Inference / Generation (ODE Solver) ---
def generate_samples(model, num_samples, timesteps=100):
x = torch.randn(num_samples, 2) # Start from noise
dt = 1.0 / timesteps
for i in range(timesteps):
t = torch.full((num_samples,), i * dt)
with torch.no_grad():
v_pred = model(x, t)
x = x + v_pred * dt # Euler integration step
return x
