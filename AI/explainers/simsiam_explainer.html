SimSiam: Collapse Prevention Without Negatives

Self-supervised learning with Siamese networks, avoiding trivial solutions without negative pairs
Foundational Deep Learning Self-Supervised O(1) extra cost

Understanding SimSiam
▼

What is it? SimSiam (Simple Siamese) is a self-supervised learning method that trains a neural network to learn robust visual representations without explicit labels. Unlike other contrastive learning methods (e.g., SimCLR, MoCo) which rely on "negative pairs" (dissimilar images) to push embeddings apart, SimSiam works solely with "positive pairs" (two augmented views of the *same* image). Its surprising trick is an asymmetric design involving a "predictor" network and a "stop-gradient" operation, which together prevent the model from collapsing to a trivial solution (e.g., outputting constant embeddings for all inputs).

Analogy: Imagine two students studying the same complex textbook. Each student reads it and produces their own unique set of notes (data augmentations). Now, they exchange notes. Student A tries to predict what Student B's notes would look like, given their own notes. Student B does the same for Student A. The key twist: when Student A makes their prediction, they treat Student B's notes as a fixed, unchanging target. Student B, in turn, treats Student A's notes as a fixed target for their own prediction. This creates a dynamic, asymmetric chase where neither student can simply copy the other's notes to "win," forcing them to learn deep, robust understanding of the textbook's content to make accurate predictions.

💡 If you remember one thing

SimSiam prevents collapse (where the network outputs identical, uninformative embeddings for all inputs) using a simple yet ingenious design: a predictor MLP on one branch and a stop-gradient operation on the other branch's target. This asymmetric mechanism creates a dynamic equilibrium that avoids the need for explicit negative samples.

How SimSiam Works Internally
▼

The Architecture

SimSiam consists of two identical encoder networks \(f\) (typically a ResNet), and a smaller predictor MLP \(h\). During training, for each input image \(x\), two augmented views \(x_1\) and \(x_2\) are generated using standard data augmentation techniques (e.g., random cropping, color jittering, Gaussian blur).

The core process for a single image \(x\):

  1. Generate two augmented views: \(x_1 = t_1(x)\) and \(x_2 = t_2(x)\).
  2. Pass each view through the shared encoder: \(z_1 = f(x_1)\) and \(z_2 = f(x_2)\). These are the "representation" vectors.
  3. Apply the predictor to one representation: \(p_1 = h(z_1)\). This is the "prediction" vector for the first branch.
  4. Similarly, apply the predictor to the other representation: \(p_2 = h(z_2)\). This is the "prediction" vector for the second branch.

The Loss Function & Stop-Gradient

The objective is to minimize the negative cosine similarity between the predictions and the representations from the *other* branch. Crucially, a stop-gradient operation is applied to the target representation:

$$L = - \frac{1}{2} \left[ \cos(p_1, \text{stopgrad}(z_2)) + \cos(p_2, \text{stopgrad}(z_1)) \right]$$

The \(\text{stopgrad}(\cdot)\) operation means that gradients from that term do not flow through the specified variable. Specifically:

  • For the term \(\cos(p_1, \text{stopgrad}(z_2))\), gradients only update \(p_1\) (and thus \(h\) and \(f\) for \(x_1\)). \(z_2\) is treated as a constant target.
  • For the term \(\cos(p_2, \text{stopgrad}(z_1))\), gradients only update \(p_2\) (and thus \(h\) and \(f\) for \(x_2\)). \(z_1\) is treated as a constant target.

Design Decision: Why No Negatives?

Traditional contrastive learning methods use negative samples to explicitly push embeddings of dissimilar images apart, preventing collapse. SimSiam demonstrates that this can be avoided. The stop-gradient mechanism, coupled with the predictor, creates an implicit dynamic where the predictor is forced to learn a useful transformation to match a target that is itself evolving (but not directly by the current gradient flow). This asymmetry prevents the trivial solution where all embeddings become identical.

🔑 Key Property

The stop-gradient operation ensures that the target representation for one branch's prediction is treated as a fixed "moving target." This creates an asymmetric learning dynamic where the predictor branch actively chases a representation that is only updated by the *other* branch's encoder, preventing trivial collapse without the need for negative samples.

Why It Works — The Math
▼

Loss Function Formalism

Let \(z_i = f(t_i(x))\) be the output of the encoder for augmented view \(x_i\), and \(p_i = h(z_i)\) be the output of the predictor. The loss for a single pair \((x_1, x_2)\) is defined as:

$$L(x_1, x_2) = - \frac{1}{2} \left[ \left( \frac{p_1}{\|p_1\|_2} \cdot \frac{\text{stopgrad}(z_2)}{\|\text{stopgrad}(z_2)\|_2} \right) + \left( \frac{p_2}{\|p_2\|_2} \cdot \frac{\text{stopgrad}(z_1)}{\|\text{stopgrad}(z_1)\|_2} \right) \right]$$

Each term is a negative cosine similarity, which encourages \(p_i\) to be aligned with \(z_j\). The loss is symmetric across the two views.

Gradient Flow and Collapse Prevention

Consider the first term, \(L_1 = - \frac{p_1}{\|p_1\|_2} \cdot \frac{\text{stopgrad}(z_2)}{\|\text{stopgrad}(z_2)\|_2}\). When computing gradients with respect to the parameters of \(f\) and \(h\):

$$\frac{\partial L_1}{\partial f(x_1)} \quad \text{and} \quad \frac{\partial L_1}{\partial h}$$

These gradients flow through \(p_1 = h(f(x_1))\) to update the parameters of \(h\) and the encoder \(f\) for \(x_1\). Critically, because of \(\text{stopgrad}(z_2)\), there is no gradient flow from \(L_1\) to \(z_2\), and thus no update to \(f\) for \(x_2\).

Similarly, for the second term \(L_2 = - \frac{p_2}{\|p_2\|_2} \cdot \frac{\text{stopgrad}(z_1)}{\|\text{stopgrad}(z_1)\|_2}\), gradients flow through \(p_2 = h(f(x_2))\) to update \(h\) and \(f\) for \(x_2\), but not to \(f\) for \(x_1\).

This asymmetry prevents collapse. If there were no stop-gradient, \(p_1\) would pull \(z_2\) towards itself, and \(p_2\) would pull \(z_1\) towards itself. Since \(p_1\) is a function of \(z_1\) and \(p_2\) is a function of \(z_2\), this would create a positive feedback loop: \(z_1\) and \(z_2\) would both be pulled towards a common, arbitrary point to minimize similarity, leading to trivial embeddings. With stop-gradient, \(p_1\) tries to match a fixed \(z_2\), and \(p_2\) tries to match a fixed \(z_1\). This creates a cycle where the targets are always slightly "behind" the predictors, forcing the network to learn meaningful features to consistently predict these moving targets.

⚠️ Common Pitfall

SimSiam's collapse prevention relies on a delicate balance. While the stop-gradient is essential, factors like the predictor's architecture (e.g., a multi-layer MLP with BatchNorm), the learning rate, and the choice of optimizer can still influence stability. Too simple a predictor or too high a learning rate can still lead to collapse, even with stop-gradient enabled.

Key Takeaways
▼

When to use SimSiam:

  • For self-supervised pretraining of vision models (e.g., ResNets on ImageNet) to learn general-purpose visual features.
  • When computational resources or architectural complexity make explicit negative sampling (requiring large memory banks or large batch sizes) impractical.
  • As a simple baseline for exploring new self-supervised learning ideas due to its minimal components and elegant collapse prevention.

When NOT to use:

  • If explicit contrastive signals (e.g., pushing specific non-matching examples far apart) are critical for your downstream task.
  • For very small datasets or models where the implicit regularization might not be sufficient, or where the risk of collapse is higher.
  • If you need extremely fine-grained control over the embedding space, as SimSiam's mechanism is more implicit than explicit contrastive methods.
💡 Big Picture

SimSiam's success highlights that the common intuition that "negative samples are essential for self-supervised learning" is not universally true. Its asymmetric design with a predictor and stop-gradient provides an alternative, simpler path to effective representation learning, pushing the boundaries of what's possible in non-contrastive methods.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
import torch.nn.functional as F
class SimSiam(nn.Module):
def __init__(self, backbone, dim=2048, pred_dim=512):
super().__init__()
self.backbone = backbone # e.g., ResNet50
# Projection MLP (f): output dim 'dim'
self.projector = nn.Sequential(
nn.Linear(backbone.output_dim, dim, bias=False),
nn.BatchNorm1d(dim), nn.ReLU(inplace=True),
nn.Linear(dim, dim, bias=False),
nn.BatchNorm1d(dim), nn.ReLU(inplace=True),
nn.Linear(dim, dim, bias=False),
nn.BatchNorm1d(dim, affine=False) # No affine in last BN
)
# Prediction MLP (h): output dim 'dim', hidden dim 'pred_dim'
self.predictor = nn.Sequential(
nn.Linear(dim, pred_dim, bias=False),
nn.BatchNorm1d(pred_dim), nn.ReLU(inplace=True),
nn.Linear(pred_dim, dim)
)
def forward(self, x1, x2):
# Encode x1 and x2
z1 = self.projector(self.backbone(x1)) # z1 = f(x1)
z2 = self.projector(self.backbone(x2)) # z2 = f(x2)
# Predict from z1 and z2
p1 = self.predictor(z1) # p1 = h(z1)
p2 = self.predictor(z2) # p2 = h(z2)
# Loss computation
# Cosine similarity loss, with stop-gradient applied to targets
loss = -(F.cosine_similarity(p1, z2.detach(), dim=-1).mean() + \
F.cosine_similarity(p2, z1.detach(), dim=-1).mean()) * 0.5
return loss
# Note: .detach() in PyTorch is equivalent to stop-gradient.
