1
Understanding A/B Testing
▼

What is it? An A/B test (randomized controlled experiment) is the gold standard for measuring the causal effect of a product change. You split users randomly into two groups — control (A, sees the old version) and variant (B, sees the new version) — collect a metric (e.g., click-through rate), then use statistics to decide whether any observed difference is real or just random noise.

Analogy: Imagine a chef testing two soup recipes. She gives bowl A to 500 diners and bowl B to another 500, chosen at random. After counting ratings, she uses statistics to decide whether bowl B is genuinely tastier, or whether the difference could have happened by chance even if the recipes are identical.

If you remember one thing

Every A/B test requires fixing three numbers before collecting data: significance level \(\alpha\) (tolerable false-positive rate), statistical power \(1{-}\beta\) (tolerable false-negative rate), and minimum detectable effect \(\delta\). From these three, the required sample size follows deterministically.

Sample Size Formula (Two-Proportion z-test)

For binary outcomes with baseline rate \(p_1\) and alternative \(p_2 = p_1 + \delta\), the sample size per arm is:

$$n = \frac{(z_{\alpha/2} + z_{\beta})^2\,[p_1(1-p_1) + p_2(1-p_2)]}{\delta^2}$$

Example: \(p_1=0.10\), \(p_2=0.12\), \(\alpha=0.05\), power \(=0.80\). Then \(z_{\alpha/2}=1.960\), \(z_\beta=0.842\), \(\delta=0.02\), giving \(n \approx 3{,}839\) per arm (7,678 total). Smaller \(\delta\) or larger power quadratically inflates \(n\).

Key property: Type I vs Type II errors

Type I error (\(\alpha\)): You declare a winner when there is none (false positive). Controlled by the significance threshold \(z_{\alpha/2}\).
Type II error (\(\beta\)): You miss a real effect (false negative). Controlled by power \(1-\beta\). Industry standard: \(\alpha=0.05\), power \(=0.80\).

The Peeking Problem & Sequential Testing
▼

The peeking problem: The natural urge is to check results daily and stop as soon as \(p < 0.05\). This is catastrophic. Each interim check is an additional chance to observe a false-positive fluctuation. Five equally-spaced looks at \(z=1.96\) inflate the true false-positive rate from \(5\%\) to about 14% — nearly triple.

Peeking inflates Type I error

Simulation (200,000 trials, \(n=1{,}000\) per arm, 5 equally-spaced looks at fixed \(z=1.96\)): measured family-wise \(\alpha = 0.1410\) vs nominal 0.05. The first look alone is innocent; the ability to stop early on any of K looks is what inflates error.

Fix 1 — O'Brien-Fleming Alpha-Spending

Spend the \(\alpha\) budget across looks using an alpha-spending function \(\alpha(t)\) where \(t = n_\text{so far}/n_\text{final}\) is information fraction. The O'Brien-Fleming function is conservative early (very high boundary) and spends most alpha only at the final look:

$$z_k^{\text{OBF}} = z_\infty \cdot \sqrt{\frac{K}{k}}, \quad k = 1,\ldots,K$$

For \(K=5\) equal looks and overall \(\alpha=0.05\), the boundaries are \(z_1=4.562\), \(z_2=3.226\), \(z_3=2.634\), \(z_4=2.281\), \(z_5=2.040\). You almost never stop early (which is the point — guarding against noise).

Fix 2 — Always-Valid p-values (AVPI / mSPRT)

The mixture Sequential Probability Ratio Test (mSPRT) produces a test statistic that is a martingale under the null, so it can be monitored continuously without inflating \(\alpha\). The p-value at any time \(t\) satisfies \(P(p_t \leq \alpha \text{ for any } t \mid H_0) \leq \alpha\). Deployed at Netflix and Optimizely for continuous monitoring.

Intuition for always-valid p-values

A classical p-value at time \(t\) treats \(t\) as fixed. An always-valid p-value builds in the randomness of when you look — it accounts for every possible stopping time simultaneously via an optional-stopping theorem for e-values.

Multi-Armed Bandits: Explore vs. Exploit
▼

A/B testing is pure explore: you commit to 50/50 traffic split until the experiment ends, even if one arm is clearly better and costing you revenue. Multi-Armed Bandits (MABs) solve the explore-exploit trade-off: allocate more traffic to better-performing arms adaptively, while still gathering enough data to learn.

Thompson Sampling (Bayesian)

For binary rewards, maintain a Beta posterior for each arm's true conversion rate \(p_k\). At each round, sample \(\tilde{p}_k \sim \text{Beta}(\alpha_k, \beta_k)\) and pull the arm with the highest sample:

$$\alpha_k \leftarrow \alpha_k + r_k, \quad \beta_k \leftarrow \beta_k + (1 - r_k)$$

where \(r_k \in \{0,1\}\) is the reward. Thompson sampling is asymptotically optimal (Lai-Robbins lower bound) and empirically excellent. Starting from a \(\text{Beta}(60,40)\) vs \(\text{Beta}(40,60)\) prior, a single draw correctly picks arm A with probability \(\approx 99.8\%\).

UCB1 (Frequentist)

Upper Confidence Bound selects the arm with the highest optimistic estimate:

$$\text{UCB}_k(t) = \hat{\mu}_k + \sqrt{\frac{2 \ln t}{n_k}}$$

where \(\hat{\mu}_k\) is the empirical mean reward, \(t\) is total pulls so far, and \(n_k\) is pulls of arm \(k\). The bonus term forces exploration of under-sampled arms; it shrinks as \(n_k\) grows. UCB1 achieves \(\mathcal{O}(\sqrt{K T \ln T})\) cumulative regret.

Regret: the cost of uncertainty

Regret \(R_T = \sum_{t=1}^T (\mu^* - \mu_{a_t})\) measures total reward lost vs always picking the best arm. MABs minimize regret; A/B tests ignore it (both arms treated equally). For large-traffic products, regret savings are significant.

When to use bandits vs A/B tests

Bandits shine when: (a) the experiment runs for a long time, (b) traffic is high, (c) you need real-time adaptation. A/B tests remain preferable when: (a) you need rigorous causal inference with controlled error rates, (b) non-stationarity could confound adaptive allocation, (c) regulatory or legal requirements demand pre-specified sample sizes.

Key Takeaways
▼

The A/B testing pipeline:

  • Fix \(\alpha\), power \((1-\beta)\), and MDE \(\delta\) before collecting data — never after
  • Compute required \(n\) per arm; only analyze once (or use pre-specified interim looks)
  • Use two-sided tests unless you have strong directional priors
  • Never peek and stop early without an alpha-spending plan

Sequential testing options:

  • O'Brien-Fleming: strict early boundaries, most alpha near the end — best for clinical trials
  • Pocock: equal boundary at each look — easier to explain, less powerful at final look
  • mSPRT / always-valid p-values: true continuous monitoring — best for tech industry

Bandit choice:

  • Thompson Sampling: principled Bayesian, naturally handles uncertainty, excellent empirically
  • UCB1: frequentist, theoretically clean \(\mathcal{O}(\sqrt{T})\) regret bound
  • \(\varepsilon\)-greedy: simple but wastes fixed \(\varepsilon\) fraction on random exploration forever
Hierarchy of experimentation methods

A/B test (fixed horizon) ⊂ A/B + alpha-spending (sequential) ⊂ Bandits (adaptive). Each relaxes constraints — more flexibility comes with more assumptions to track.

import math, scipy.stats as st, numpy as np
# ── 1. Sample size (two-proportion z-test) ──
p1, p2, alpha, power = 0.10, 0.12, 0.05, 0.80
z_a = st.norm.ppf(1 - alpha/2) # 1.960
z_b = st.norm.ppf(power) # 0.842
delta = p2 - p1 # 0.02
n = (z_a + z_b)**2 * (p1*(1-p1) + p2*(1-p2)) / delta**2
n_per_arm = math.ceil(n) # 3839
# ── 2. O'Brien-Fleming boundaries ──
K = 5; z_obf = 2.040 # overall z for 5 looks, alpha=0.05
for k in range(1, K+1):
z_k = z_obf * math.sqrt(K / k) # boundary at look k
# z_1=4.562, z_2=3.226, z_3=2.634, z_4=2.281, z_5=2.040
# ── 3. Thompson Sampling (Beta-Binomial) ──
alpha_k = np.ones(2); beta_k = np.ones(2) # uninformative prior
true_p = [0.10, 0.12] # true conversion rates
for _ in range(1000):
samples = np.random.beta(alpha_k, beta_k)
arm = np.argmax(samples) # pull best sampled arm
reward = int(np.random.rand() < true_p[arm])
alpha_k[arm] += reward; beta_k[arm] += 1 - reward
# ── 4. UCB1 ──
mu_hat = np.zeros(2); n_pulls = np.ones(2)
for t in range(3, 1001):
ucb = mu_hat + np.sqrt(2 * math.log(t) / n_pulls)
arm = np.argmax(ucb) # optimistic arm selection
reward = int(np.random.rand() < true_p[arm])
n_pulls[arm] += 1
mu_hat[arm] += (reward - mu_hat[arm]) / n_pulls[arm]
