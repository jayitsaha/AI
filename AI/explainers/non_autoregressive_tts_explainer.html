Understanding Non-Autoregressive TTS
▼

What is it? Text-to-speech (TTS) converts text into a mel-spectrogram (a time-frequency picture of speech), which a vocoder turns into audio. Early neural TTS (Tacotron 2) generated that spectrogram one frame at a time, each frame conditioned on the one before it — autoregressive (AR) generation. Non-autoregressive (NAR) models like FastSpeech, FastSpeech 2, and VITS instead decide up front how long each sound should last, stretch the text representation to the full audio length in one step, and then decode every frame simultaneously.

Analogy: AR generation is like reading a sentence aloud where you must finish word N before your brain even starts planning word N+1 — strictly serial, and if you stumble on one word, everything after it is thrown off. NAR generation is like a printing press: you first measure exactly how much space each word needs on the page (duration prediction), lay out the whole page (length regulation), and then stamp every word onto the paper in one press (parallel decoding).

💡 If you remember one thing

A duration predictor plus a length regulator convert "generate frame-by-frame" into "generate all frames at once." This removes the \(O(T)\) sequential dependency chain that makes autoregressive TTS slow (one decoder step per output frame) and fragile (attention can skip or repeat words). FastSpeech 2 adds explicit pitch/energy control; VITS goes further and fuses the whole pipeline — including the vocoder — into a single end-to-end model.

How It Works Internally
▼

FastSpeech: Duration Predictor + Length Regulator

A Feed-Forward Transformer (FFT) encoder turns \(N\) input phonemes into hidden vectors \(H=(h_1,\dots,h_N)\). A lightweight duration predictor (two Conv1D + ReLU + LayerNorm + Dropout blocks, then a linear layer) reads \(H\) and outputs a predicted duration \(\hat d_i\) — how many mel frames phoneme \(i\) should occupy. The length regulator then repeats each \(h_i\) exactly \(\hat d_i\) times, producing a frame-level sequence of length \(T=\sum_i \hat d_i\). A mirror-image FFT decoder consumes this frame-level sequence and produces all \(T\) mel frames in one parallel forward pass — no frame depends on a previously generated frame.

Because ground-truth per-phoneme durations aren't directly observable, FastSpeech (v1) trained an autoregressive Tacotron2 teacher first, extracted "hard" durations from its attention alignments, and trained the student on the teacher's distilled mel outputs (sequence-level knowledge distillation) to sidestep the one-to-many problem — the same text can be spoken with many valid prosodies, which confuses direct parallel regression.

FastSpeech 2: Ground Truth Targets + Variance Adaptor

FastSpeech 2 removes the teacher entirely. Durations come from an external forced aligner (e.g. Montreal Forced Aligner) run on real audio; pitch (F0) and energy are extracted directly from the ground-truth waveform, frame-averaged per phoneme, and fed back into the model through a Variance Adaptor — stacked duration, pitch, and energy predictors whose outputs are embedded and added directly onto the hidden sequence before decoding. Training on real spectrograms (not a blurry teacher-averaged target) removes the distillation information loss and gives explicit, controllable knobs over rhythm, pitch, and loudness at inference time.

VITS: One Model, Text to Waveform

VITS discards the two-stage "acoustic model + separate vocoder" pipeline altogether. It is a conditional variational autoencoder: a posterior encoder reads the linear spectrogram (training only) into a latent \(z\); a normalizing-flow-based prior is conditioned on text; a stochastic duration predictor (itself a flow) samples durations instead of regressing a single point estimate; a Monotonic Alignment Search (MAS) — a dynamic-programming Viterbi-style search — finds the best phoneme-to-latent alignment during training without any external aligner; and a HiFi-GAN-style decoder converts \(z\) directly into a raw waveform, trained adversarially against a discriminator. Everything is optimized jointly end-to-end.

🔑 Key Design Decision

Why is length regulation necessary at all? Mel frames are emitted every ~10–12.5ms while phonemes last ~50–300ms — the frame timescale vastly outnumbers the phoneme timescale. You must expand the compact phoneme representation up to the frame timescale before a non-recurrent decoder can produce a frame-aligned output; the length regulator is the mechanism that performs this expansion without any recurrence.

Why It Works — The Math
▼

Duration Predictor Loss

Durations are trained in the log domain for numerical stability (durations range from ~1 to 100+ frames, and log-space keeps the regression well-scaled):

$$\mathcal{L}_{dur} = \operatorname{MSE}\big(\log(d),\ \log(\hat d)\big)$$

Length Regulator

Given hidden states \(H=(h_1,\dots,h_N)\), durations \(D=(d_1,\dots,d_N)\), and an inference-time speed control \(\alpha\) (values \(>1\) slow speech down, \(<1\) speed it up — a control impossible to apply cleanly in AR models):

$$\operatorname{LR}(H,D,\alpha)=\big[\underbrace{h_1,\dots,h_1}_{\alpha d_1},\ \underbrace{h_2,\dots,h_2}_{\alpha d_2},\ \dots,\ \underbrace{h_N,\dots,h_N}_{\alpha d_N}\big],\quad T=\textstyle\sum_i \alpha d_i$$

Variance Adaptor (FastSpeech 2)

Pitch and energy predictors output per-frame scalars \(p_i, e_i\) which are quantized and embedded, then added onto the expanded hidden sequence:

$$h_i' = h_i + E_{pitch}(p_i) + E_{energy}(e_i)$$

VITS: Conditional VAE Evidence Lower Bound

VITS maximizes a lower bound on the conditional data likelihood \(\log p_\theta(x\mid c)\), where \(c\) is the text condition:

$$\log p_\theta(x\mid c) \ge \mathbb{E}_{q_\phi(z\mid x)}\big[\log p_\theta(x\mid z)\big] - D_{KL}\big(q_\phi(z\mid x)\,\|\,p_\theta(z\mid c)\big)$$

The prior \(p_\theta(z\mid c)\) is not a simple Gaussian — it is transformed by a normalizing flow \(f\): \(z = f(z')\) with \(z' \sim \mathcal{N}(\mu_\theta(c),\sigma_\theta(c))\), letting the prior match the complex, multi-modal posterior induced by real speech. An LSGAN-style adversarial loss further sharpens the generated waveform:

$$\mathcal{L}_{adv}(D) = \mathbb{E}\big[(D(y)-1)^2\big] + \mathbb{E}\big[D(G(z))^2\big]$$
⚠️ Common Pitfall

A deterministic duration/pitch/energy regressor trained with MSE learns the conditional mean of a one-to-many distribution — this is exactly what makes naive parallel TTS sound flat/over-smoothed. FastSpeech 2's ground-truth variance targets reduce (but don't eliminate) this; VITS's stochastic, flow-based duration predictor samples from the full distribution instead of collapsing to its mean, which is why it captures more natural prosodic diversity.

Key Takeaways
▼

When to use which:

  • FastSpeech — when you already have (or can distill) a working AR teacher and want a fast, robust student without extra prosody control.
  • FastSpeech 2 — when you have forced-aligned durations + F0/energy extraction available and want explicit, controllable prosody with no teacher model needed.
  • VITS — when you want the best naturalness/diversity from a single jointly-trained model and can afford heavier GAN+flow training, and don't need a separately swappable vocoder.

When NOT to use NAR: if you need extremely fine-grained, real-time-streaming, token-by-token controllability that the duration/pitch/energy abstraction can't express — though modern flow- and diffusion-based NAR TTS increasingly closes this gap.

💡 Hierarchy

Tacotron2 (AR, one frame at a time) → FastSpeech (NAR, teacher-distilled) → FastSpeech 2 (NAR, ground-truth variance adaptor, no teacher) → VITS (NAR, single end-to-end conditional-VAE + flow + GAN, text straight to waveform). Each step removes a limitation of the previous one — sequential latency, then distillation loss, then the two-stage acoustic-model/vocoder split.

import torch, torch.nn as nn
# --- Duration Predictor (FastSpeech / FastSpeech2) ---
class DurationPredictor(nn.Module):
def __init__(self, d_model, kernel=3, dropout=0.5):
super().__init__()
self.conv1 = nn.Conv1d(d_model, d_model, kernel, padding=1)
self.conv2 = nn.Conv1d(d_model, d_model, kernel, padding=1)
self.ln1, self.ln2 = nn.LayerNorm(d_model), nn.LayerNorm(d_model)
self.drop = nn.Dropout(dropout)
self.linear = nn.Linear(d_model, 1)
def forward(self, h): # h: (B, N, d_model)
x = torch.relu(self.conv1(h.transpose(1,2))).transpose(1,2)
x = self.drop(self.ln1(x))
x = torch.relu(self.conv2(x.transpose(1,2))).transpose(1,2)
x = self.drop(self.ln2(x))
log_d_hat = self.linear(x).squeeze(-1) # (B, N) predicted log-duration
return log_d_hat
# --- Length Regulator: expand phonemes to frame-level ---
def length_regulate(h, durations, alpha=1.0):
# h: (N, d_model), durations: (N,) integer frame counts
out = []
for i, d in enumerate(durations):
n_frames = max(1, round(int(d) * alpha))
out.append(h[i:i+1].expand(n_frames, -1)) # repeat h_i, d_i times
return torch.cat(out, dim=0) # (T, d_model), T = sum(durations)
# --- VITS: Monotonic Alignment Search (DP recurrence, training only) ---
def monotonic_alignment_search(log_probs):
# log_probs[t, s] = log N(z_t; mu_s, sigma_s) — likelihood of latent frame t
# under phoneme s's prior. Find monotonic, non-skipping path maximizing sum.
T, S = log_probs.shape
Q = torch.full((T, S), -1e9)
Q[0, 0] = log_probs[0, 0]
for t in range(1, T):
for s in range(S):
stay = Q[t-1, s]
advance = Q[t-1, s-1] if s > 0 else -1e9
Q[t, s] = max(stay, advance) + log_probs[t, s] # Viterbi-style DP
return backtrack(Q) # -> hard alignment / durations per phoneme
