Understanding Transformer Initialization
▼

What is it? Initialization is the choice of starting values for a network's weights before any training happens. For a shallow network, a good starting point (Xavier/He) just needs each layer to roughly preserve the variance of its input. But transformers are stacks of dozens or hundreds of residual blocks: \(x_l = x_{l-1} + \text{Sublayer}_l(x_{l-1})\). Every block adds a new chunk of signal on top of the running total, so even a "perfectly reasonable" per-layer variance compounds across depth into an explosion — unless initialization is made depth-aware.

Analogy: Imagine 96 people each adding a coin toss's worth of noise onto a running sum. One coin toss is harmless. Ninety-six of them, all added at full strength, and the running sum swings wildly. Transformer initialization asks: how much should the 96th voice be turned down so the final sum doesn't drown out the signal? The answer depends on how many voices are in the room — i.e., on depth \(N\).

💡 If you remember one thing

Standard Xavier/He initialization keeps a single layer's output variance matched to its input. It says nothing about residual accumulation. Transformer-specific recipes (GPT-2 scaled init, T-Fixup, DeepNorm, μP) add a depth-dependent factor — typically \(1/\sqrt{2N}\) or similar — to the output-projection weights of every sublayer so the residual stream's variance stays roughly constant no matter how deep the network gets.

How It Works Internally
▼

Three Places Transformers Need Special Init

1. Token embeddings. The original Transformer (Vaswani et al., 2017) multiplies token embeddings by \(\sqrt{d_{model}}\) before adding sinusoidal positional encodings, so the embedding magnitude matches the \(O(1)\) scale of the positional signal rather than being drowned out by it.

2. Attention logits. Query-key dot products \(q \cdot k\) grow with head dimension \(d_k\) — summing \(d_k\) roughly-unit-variance products gives logit variance \(\approx d_k\). Left unscaled, softmax saturates into a near one-hot distribution at initialization, killing gradient flow. The fix is the now-famous \(1/\sqrt{d_k}\) scaling inside attention: \(\text{softmax}(QK^\top / \sqrt{d_k})\).

3. Residual output projections. This is the deep one. Every attention block and every MLP block ends by adding its output back onto the residual stream. If each sublayer's output-projection weights use plain Xavier/He (or a fixed small std like GPT-2's 0.02), each sublayer injects roughly unit variance into the stream, and variance accumulates linearly with depth. GPT-2 (Radford et al., 2019) fixed this by scaling the residual-branch output weights (attention output projection and the MLP's second linear layer) by \(1/\sqrt{2N}\), where \(N\) is the number of transformer blocks (the factor of 2 counts attention + MLP as two additive sublayers per block).

Design Decision: Why Scale the Output Projection, Not Everything?

Only the last matrix in each sublayer — the one whose output lands directly on the residual highway — needs shrinking. Internal weights (Q/K/V projections, the MLP's first layer) can keep standard-scale init because their outputs are consumed internally, not added to the residual stream. This keeps gradients healthy inside each sublayer while still controlling the residual accumulation.

🔑 Key Property

Depth-aware init makes the initial forward pass behave as if the network were shallow: residual-stream variance at the final layer stays within a small constant factor of the embedding variance, regardless of how many blocks \(N\) are stacked. This is what makes training 48-, 96-, even 1000-layer (DeepNet) transformers stable without extensive warm-up or learning-rate tricks.

3
Why It Works — The Math
▼

Variance Recursion of the Residual Stream

Model the residual stream after \(l\) sublayers as \(x_l = x_{l-1} + f_l(x_{l-1})\), where \(f_l\) is an attention or MLP sublayer with independent, zero-mean output at initialization. Assuming each sublayer output has variance \(\sigma_f^2\) uncorrelated with \(x_{l-1}\):

$$\operatorname{Var}(x_l) = \operatorname{Var}(x_{l-1}) + \sigma_f^2 \implies \operatorname{Var}(x_l) = \operatorname{Var}(x_0) + l\,\sigma_f^2$$

With standard Xavier/He init, each sublayer is built to satisfy \(\operatorname{Var}(f_l(x)) \approx \operatorname{Var}(x) \approx 1\) in isolation (that's what Xavier/He optimizes for!). Substituting \(\sigma_f^2 = 1\) gives linear variance growth: \(\operatorname{Var}(x_l) \approx 1 + l\). For a 24-block model with \(2N=48\) sublayers, that's a variance of 49 at the output — a ~7× blow-up in standard deviation.

The Scaled-Init Derivation

Now scale every residual-branch output weight matrix by a constant \(\gamma\). Since output variance scales quadratically with weight scale, \(\sigma_f^2 \to \gamma^2\). Choosing \(\gamma = 1/\sqrt{2N}\):

$$\operatorname{Var}(x_l) \approx 1 + \frac{l}{2N} \quad\Longrightarrow\quad \operatorname{Var}(x_{2N}) \approx 1 + 1 = 2$$

The variance at the final sublayer is bounded by a constant (≈2×) independent of \(N\) — depth no longer matters. This is exactly the GPT-2 / nanoGPT recipe: std = 0.02 / sqrt(2 * n_layer) applied to the attention output projection and the MLP's down-projection.

⚠️ Common Pitfall

This analysis ignores LayerNorm. In a Pre-LN transformer (LN inside each sublayer, residual stream itself unnormalized), the variance-growth argument above applies directly and depth-aware scaling matters a lot. In a Post-LN transformer (LN after the residual add), the stream is renormalized every block, which hides the growth during the forward pass but can still leave gradients exploding/vanishing at initialization — this is precisely why Post-LN transformers historically needed careful learning-rate warm-up to train at all (Xiong et al., 2020).

Key Takeaways
▼

What to do in practice:

  • Scale attention-output and MLP-down-projection weights by \(1/\sqrt{2N}\) (GPT-2/nanoGPT recipe) so residual variance stays bounded across depth.
  • Always divide attention logits by \(\sqrt{d_k}\) — this is not optional, it prevents softmax saturation at step 0.
  • If using sinusoidal positional encodings, scale embeddings by \(\sqrt{d_{model}}\) to match magnitudes.
  • For very deep models (100+ layers), consider DeepNorm or T-Fixup, which derive closed-form \(\alpha\) (residual up-scale) and \(\beta\) (init down-scale) as functions of \(N\) to guarantee bounded updates at any depth.
  • Pre-LN architectures need depth-aware init the most; Post-LN hides the symptom but not the underlying instability.
💡 Hierarchy

Xavier/He (single-layer variance preservation) ⊂ GPT-2 scaled init (adds \(1/\sqrt{2N}\) depth correction) ⊂ DeepNorm / T-Fixup (jointly tune residual coefficients and init scale as closed-form functions of depth, enabling 1000+ layer transformers without warm-up).

import torch, torch.nn as nn, math
class Block(nn.Module):
def __init__(self, d_model, n_heads):
super().__init__()
self.qkv = nn.Linear(d_model, 3 * d_model)
self.attn_out = nn.Linear(d_model, d_model) # residual branch
self.mlp_in = nn.Linear(d_model, 4 * d_model)
self.mlp_out = nn.Linear(4 * d_model, d_model) # residual branch
self.d_k = d_model // n_heads
def attn(self, x):
q, k, v = self.qkv(x).chunk(3, dim=-1)
scores = q @ k.transpose(-2,-1) / math.sqrt(self.d_k) # 1/sqrt(d_k) scaling
return self.attn_out(scores.softmax(-1) @ v)
def forward(self, x):
x = x + self.attn(x)
x = x + self.mlp_out(torch.relu(self.mlp_in(x)))
return x
# GPT-2 style depth-aware initialization
def init_weights(model, n_layer, std=0.02):
for name, p in model.named_parameters():
if 'weight' in name and p.dim() == 2:
nn.init.normal_(p, mean=0.0, std=std)
if name.endswith('attn_out.weight') or name.endswith('mlp_out.weight'):
# scale residual-branch output projections by 1/sqrt(2N)
p.data.mul_(1.0 / math.sqrt(2 * n_layer))
# Embedding scale to match positional encoding magnitude
emb_scale = math.sqrt(d_model) # multiply token embeddings before adding pos-enc
