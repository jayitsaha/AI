Knowledge Graph Embeddings: TransE, DistMult, RotatE

Representing entities and relations as vectors for link prediction and knowledge graph completion

Understanding Knowledge Graph Embeddings (KGEs)
▼

What are they? Knowledge Graphs (KGs) represent facts as triples \((h, r, t)\) where \(h\) is a head entity, \(r\) is a relation, and \(t\) is a tail entity (e.g., (Paris, hasCapital, France)). KGEs embed these entities and relations into continuous vector spaces (e.g., \(\mathbb{R}^d\) or \(\mathbb{C}^d\)). The goal is to learn representations such that the vector operations corresponding to a true triple result in a "plausible" configuration, while false triples are "implausible."

Analogy: Imagine a map where cities are points, and relations like "isNorthOf" or "isCapitalOf" are specific vectors or transformations. If New York is a point, and "isNorthOf" is a vector pointing north, then (New York + isNorthOf) should land near a city like Boston. KGEs try to learn these "directions" and "locations" automatically from existing facts, so they can predict missing facts or detect incorrect ones.

💡 If you remember one thing

KGE models define a scoring function \(f(h, r, t)\) that measures the plausibility of a triple \((h, r, t)\) based on their learned embeddings \(\mathbf{h}, \mathbf{r}, \mathbf{t}\). During training, this function is minimized for true triples and maximized for false triples (negative samples).

2
How Different KGE Models Work
▼

The Core Idea: Structural Assumptions

Different KGE models propose different ways to combine \(\mathbf{h}, \mathbf{r}, \mathbf{t}\) into a score, each making a specific structural assumption about how relations behave in the embedding space:

  • TransE (Translational Embeddings): Assumes relations are simply translations between entities. For a true triple \((h, r, t)\), it expects \(\mathbf{h} + \mathbf{r} \approx \mathbf{t}\). This is a very intuitive and popular baseline.
  • DistMult (Diagonal Matrix Multiplication): Models relations as diagonal matrices. For \((h, r, t)\), it expects \(\mathbf{h}^\top \text{diag}(\mathbf{r}) \mathbf{t}\) to be high. This simplifies to an element-wise product followed by a dot product: \(\sum_i \mathbf{h}_i \mathbf{r}_i \mathbf{t}_i\). It's good for symmetric relations.
  • ComplEx (Complex Embeddings): Extends DistMult to complex numbers. Entities and relations are embedded in \(\mathbb{C}^d\). The scoring function is \(\operatorname{Re}(\mathbf{h}^\top \mathbf{r} \overline{\mathbf{t}})\). This allows modeling anti-symmetric relations (e.g., "isTallerThan") which DistMult struggles with.
  • RotatE (Rotation Embeddings): Views relations as rotations in complex vector space. For a true triple, it expects \(\mathbf{h} \circ \mathbf{r} \approx \mathbf{t}\), where \(\circ\) denotes element-wise complex multiplication and \(\mathbf{r}\) has unit-modulus components representing rotation angles. This is powerful for modeling various relation patterns, including symmetric, anti-symmetric, and inversion.
  • TransR (Relation-specific Translation): An extension of TransE that projects entities into a relation-specific space before performing the translation. This allows different relations to operate in different "contexts" or subspaces.

Training Objective: Margin-based Ranking Loss

Most KGE models are trained using a margin-based ranking loss. For a true triple \((h, r, t)\) and a corrupted (false) triple \((h', r', t')\), the loss aims to ensure that the score of the true triple is significantly lower than the score of the false triple:

$$\mathcal{L} = \sum_{(h,r,t) \in S_{train}} \sum_{(h',r',t') \in S'_{neg}} \max(0, f(h,r,t) - f(h',r',t') + \gamma)$$

Here, \(\gamma\) is a margin hyperparameter, and \(S'_{neg}\) are negative samples (e.g., replacing \(h\) with a random entity \(h'\) to get \((h', r, t)\)).

🔑 Key Property

The choice of KGE model fundamentally depends on the types of relations present in the knowledge graph. TransE is simple but struggles with 1-to-N, N-to-1, and N-to-N relations. DistMult handles symmetric relations well. ComplEx and RotatE are more expressive, handling symmetric, anti-symmetric, and inversion relations by leveraging complex number properties.

3
The Math Behind the Models
▼

TransE: Translational Embeddings

The core idea is that the relation vector \(\mathbf{r}\) acts as a translation from \(\mathbf{h}\) to \(\mathbf{t}\). The scoring function measures the distance between \(\mathbf{h} + \mathbf{r}\) and \(\mathbf{t}\):

$$f_{TransE}(\mathbf{h}, \mathbf{r}, \mathbf{t}) = ||\mathbf{h} + \mathbf{r} - \mathbf{t}||_{L_1/L_2}$$

Typically, either L1 or L2 norm is used. Constraints: \(\|\mathbf{h}\|_2 = 1\), \(\|\mathbf{t}\|_2 = 1\), \(\|\mathbf{r}\|_2 = 1\). These unit-norm constraints prevent the model from trivially minimizing scores by making all embeddings zero or extremely large.

DistMult: Diagonal Bilinear Model

DistMult models relations as diagonal matrices. If \(\mathbf{M}_r\) is a diagonal matrix, its entries can be represented by a vector \(\mathbf{r}\) where \(\mathbf{M}_r = \text{diag}(\mathbf{r})\). The scoring function is a bilinear form:

$$f_{DistMult}(\mathbf{h}, \mathbf{r}, \mathbf{t}) = \mathbf{h}^\top \text{diag}(\mathbf{r}) \mathbf{t} = \sum_{i=1}^d \mathbf{h}_i \mathbf{r}_i \mathbf{t}_i$$

This formulation is simple and efficient, but it is inherently limited to modeling symmetric relations (i.e., if \((h,r,t)\) is true, then \((t,r,h)\) tends to also be true) because \(f(\mathbf{h}, \mathbf{r}, \mathbf{t}) = f(\mathbf{t}, \mathbf{r}, \mathbf{h})\).

RotatE: Rotation in Complex Vector Space

RotatE embeds entities and relations in \(\mathbb{C}^d\). For each dimension \(k\), entity embeddings are \(\mathbf{h}_k, \mathbf{t}_k \in \mathbb{C}\), and relation embeddings are \(\mathbf{r}_k \in \mathbb{C}\) with \(|\mathbf{r}_k|=1\). The relation \(\mathbf{r}\) is a rotation operator. The scoring function is:

$$f_{RotatE}(\mathbf{h}, \mathbf{r}, \mathbf{t}) = ||\mathbf{h} \circ \mathbf{r} - \mathbf{t}||_{L_1/L_2}$$

where \(\circ\) denotes element-wise complex multiplication. Each component \(\mathbf{r}_k\) can be written as \(e^{i\theta_k}\), representing a rotation by angle \(\theta_k\). This allows RotatE to model various relation patterns:

  • Symmetry: \(\mathbf{r}_k = e^{i0} = 1\) or \(\mathbf{r}_k = e^{i\pi} = -1\).
  • Anti-symmetry: If \(\mathbf{r}\) maps \(\mathbf{h}\) to \(\mathbf{t}\), then \(\overline{\mathbf{r}}\) maps \(\mathbf{t}\) to \(\mathbf{h}\).
  • Inversion: If \(\mathbf{r}\) maps \(\mathbf{h}\) to \(\mathbf{t}\), then \(\mathbf{r}^{-1}\) maps \(\mathbf{t}\) to \(\mathbf{h}\). RotatE naturally models this with \(\mathbf{r}^{-1} = \overline{\mathbf{r}}\).
🧮 Complex Numbers Refresher

A complex number \(z = x + iy\) can be represented as a 2D vector \((x,y)\). Multiplication by \(e^{i\theta} = \cos\theta + i\sin\theta\) corresponds to a rotation by angle \(\theta\) in the complex plane. RotatE applies this idea element-wise across the embedding dimensions.

Key Takeaways
▼

When to use which KGE model:

  • TransE: A strong baseline, computationally efficient. Best for KGs with many 1-to-1 relations. Struggles with complex relation patterns (1-to-N, N-to-1, N-to-N, symmetric/anti-symmetric relations) because it assumes a single translation vector.
  • DistMult: Good for KGs with many symmetric relations (e.g., "isSimilarTo"). More expressive than TransE for these cases. Cannot model anti-symmetric relations.
  • ComplEx: Generalizes DistMult to complex embeddings, enabling the modeling of anti-symmetric relations (e.g., "isTallerThan"). Generally more powerful than TransE and DistMult for diverse KGs.
  • RotatE: Highly expressive, capable of modeling symmetric, anti-symmetric, and inversion relations through rotations in complex space. Often achieves state-of-the-art results on benchmark datasets, especially for multi-relational graphs.
  • TransR: Addresses TransE's limitations by introducing relation-specific projection matrices, allowing entities to have different representations for different relations. More complex and computationally intensive than TransE.

General considerations for KGEs:

  • Negative Sampling: Crucial for training. Generating good negative samples (false triples) is an active area of research.
  • Hyperparameter Tuning: Embedding dimension, learning rate, margin \(\gamma\), and regularization are critical.
  • Scalability: Training on very large KGs (millions of entities and relations) requires distributed training and efficient sampling strategies.
💡 Big Picture

KGEs transform the symbolic, discrete world of knowledge graphs into a continuous, numeric space where vector arithmetic can reveal hidden patterns, predict missing links, and power reasoning tasks. The choice of model reflects a hypothesis about the underlying geometry of relations.

Code Trace (Python / PyTorch-like)
▼
import torch
import torch.nn.functional as F
class KGEModel(torch.nn.Module):
def __init__(self, num_entities, num_relations, dim, model_name="TransE"):
super().__init__()
self.dim = dim
self.model_name = model_name
self.entity_emb = torch.nn.Embedding(num_entities, dim)
self.relation_emb = torch.nn.Embedding(num_relations, dim)
torch.nn.init.xavier_uniform_(self.entity_emb.weight)
torch.nn.init.xavier_uniform_(self.relation_emb.weight)
def score_triple(self, h_idx, r_idx, t_idx):
h = self.entity_emb(h_idx)
r = self.relation_emb(r_idx)
t = self.entity_emb(t_idx)
if self.model_name == "TransE":
h = F.normalize(h, p=2, dim=-1) # unit norm constraints
t = F.normalize(t, p=2, dim=-1)
return torch.norm(h + r - t, p=1, dim=-1) # L1 distance
elif self.model_name == "DistMult":
return torch.sum(h * r * t, dim=-1)
elif self.model_name == "RotatE":
# Assuming complex embeddings, dim is 2*real_dim
h_re, h_im = h.chunk(2, dim=-1)
r_re, r_im = r.chunk(2, dim=-1)
t_re, t_im = t.chunk(2, dim=-1)
# Normalize relation to unit modulus (rotation)
r_norm = torch.sqrt(r_re**2 + r_im**2)
r_re = r_re / r_norm
r_im = r_im / r_norm
# Complex multiplication: (a+bi)(c+di) = (ac-bd) + (ad+bc)i
pred_t_re = h_re * r_re - h_im * r_im
pred_t_im = h_re * r_im + h_im * r_re
pred_t = torch.cat([pred_t_re, pred_t_im], dim=-1)
true_t = torch.cat([t_re, t_im], dim=-1)
return torch.norm(pred_t - true_t, p=1, dim=-1)
else:
raise ValueError("Unknown model_name")
# Example usage:
num_entities = 100
num_relations = 50
embedding_dim = 256 # For RotatE, this would be 2*128 complex dimensions
model = KGEModel(num_entities, num_relations, embedding_dim, model_name="TransE")
h_idx, r_idx, t_idx = torch.tensor([0]), torch.tensor([1]), torch.tensor([2])
score = model.score_triple(h_idx, r_idx, t_idx)
print(f"TransE score: {score.item()}")
