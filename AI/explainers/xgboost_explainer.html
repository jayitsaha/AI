Understanding XGBoost
▼

What is it? XGBoost is a decision-tree ensemble algorithm that builds trees one at a time, where each new tree corrects the mistakes of the previous ones. Unlike vanilla gradient boosting, XGBoost uses a mathematically precise 2nd-order Taylor expansion of the loss and adds an explicit regularization penalty on tree complexity — making it simultaneously faster, more accurate, and harder to overfit than its predecessors.

Analogy: Imagine a student retaking an exam. Round 1: guess everything. Round 2: focus only on the questions you got wrong. Round 3: focus on the questions from round 2 you still got wrong. Each round, you're fitting residuals. XGBoost does this mathematically — but instead of re-examining raw mistakes, it reads the curvature of the error surface at each point (hessians), letting it take smarter, bigger steps without overshooting.

💡 If you remember one thing

XGBoost uses second-order gradients (hessians \(h_i\)) in both the split-gain formula and the optimal leaf weight \(w^* = -G/(H+\lambda)\). The \(\lambda\) in the denominator is explicit L2 regularization. Together they make splits more stable and robust than plain gradient boosting, which only uses first-order gradients.

How XGBoost Works Internally
▼

Boosting Loop Overview

XGBoost maintains an ensemble prediction \(\hat{y}_i = \sum_{k=1}^K f_k(x_i)\) where each \(f_k\) is a CART tree. At each round \(t\), it adds the tree \(f_t\) that minimises the regularised objective:

$$\mathcal{L}^{(t)} = \sum_{i=1}^n \left[ g_i f_t(x_i) + \tfrac{1}{2} h_i f_t(x_i)^2 \right] + \Omega(f_t)$$

where \(g_i = \partial_{\hat{y}^{(t-1)}} \ell(y_i, \hat{y}^{(t-1)})\) (first-order gradient) and \(h_i = \partial^2_{\hat{y}^{(t-1)}} \ell(y_i, \hat{y}^{(t-1)})\) (second-order Hessian), and the complexity term \(\Omega(f) = \gamma T + \frac{\lambda}{2}\|w\|^2\) penalises the number of leaves \(T\) and the squared leaf weights.

Column Subsampling (colsample_bytree / colsample_bylevel)

Before building each tree (or even each split), XGBoost randomly samples a fraction of features. This performs a role similar to Random Forest's feature bagging — it decorrelates trees and reduces overfitting. Unlike Random Forest (which only does bagging), XGBoost also uses gradient information to choose the best split among the sampled features.

Approximate (Histogram-Based) Splits

Exact greedy split search requires sorting every feature — \(O(n)\) per feature per level. For large datasets, XGBoost uses the weighted quantile sketch: the feature values are binned into candidate split points using hessian sums as weights. This reduces the search from \(O(n)\) to \(O(B)\) candidate bins, where \(B \ll n\).

🔑 Key Architectural Property

XGBoost maintains a column-block data structure: features are sorted once and stored in compressed sparse column (CSC) format. At each split scan the block is streamed through cache-friendly memory — this is the "cache-aware" design that gives XGBoost its practical speed advantage over naive implementations.

The Math — Taylor Objective & Split Gain
▼

Second-Order Taylor Expansion of the Objective

For a loss \(\ell(y_i, \hat{y}_i)\), second-order Taylor expansion around the current prediction \(\hat{y}_i^{(t-1)}\) yields:

$$\mathcal{L}^{(t)} \approx \sum_{i=1}^n \left[ \ell(y_i, \hat{y}^{(t-1)}) + g_i f_t(x_i) + \tfrac{1}{2} h_i f_t(x_i)^2 \right] + \Omega(f_t)$$

The constant \(\ell(y_i, \hat{y}^{(t-1)})\) is dropped for optimisation. Let \(I_j = \{i : q(x_i) = j\}\) be the set of samples in leaf \(j\). Substituting leaf weights \(w_j\) for \(f_t\):

$$\mathcal{L}^{(t)} = \sum_{j=1}^T \left[ G_j w_j + \tfrac{1}{2}(H_j + \lambda) w_j^2 \right] + \gamma T$$

where \(G_j = \sum_{i \in I_j} g_i\) and \(H_j = \sum_{i \in I_j} h_i\). This is a quadratic in \(w_j\) — minimised analytically:

$$w_j^* = -\frac{G_j}{H_j + \lambda}, \qquad \mathcal{L}^{(t)}_{\min} = -\frac{1}{2}\sum_{j=1}^T \frac{G_j^2}{H_j + \lambda} + \gamma T$$

Split Gain Formula

For a candidate split that partitions \(I\) into \(I_L\) (left) and \(I_R\) (right), the reduction in loss is:

$$\text{Gain} = \frac{1}{2}\left[\frac{G_L^2}{H_L+\lambda} + \frac{G_R^2}{H_R+\lambda} - \frac{G^2}{H+\lambda}\right] - \gamma$$

The \(-\gamma\) ensures we only split if the gain exceeds the complexity cost. This is XGBoost's pre-pruning strategy: if no split gives positive gain, the node remains a leaf.

⚠️ Common Misconception

XGBoost is not the same as random forest or plain gradient boosting. Random forests build trees independently (bagging). Gradient boosting uses only first-order gradients. XGBoost's use of second-order gradients (hessians) gives it Newton-Raphson style convergence — it approximates the curvature of the loss landscape rather than just its slope, leading to faster convergence per tree.

Sparsity-Aware & Cache-Aware Architecture
▼

Sparsity-Aware Split Algorithm

Real-world datasets often have missing values or one-hot-encoded sparse features. XGBoost handles these natively without imputation. For each feature split, the algorithm tries routing all missing-value samples both left and right, picking the direction that maximises split gain. This learned default direction is stored in the tree node and applied at inference time.

Formally, for a split at threshold \(s\) on feature \(k\), XGBoost computes:

$$\text{Gain}_{\text{left-default}} = \frac{1}{2}\left[\frac{(G_L + G_{\text{miss}})^2}{H_L+H_{\text{miss}}+\lambda} + \frac{G_R^2}{H_R+\lambda} - \frac{G_{\text{total}}^2}{H_{\text{total}}+\lambda}\right] - \gamma$$
$$\text{Gain}_{\text{right-default}} = \frac{1}{2}\left[\frac{G_L^2}{H_L+\lambda} + \frac{(G_R+G_{\text{miss}})^2}{H_R+H_{\text{miss}}+\lambda} - \frac{G_{\text{total}}^2}{H_{\text{total}}+\lambda}\right] - \gamma$$

The direction yielding higher gain is chosen as the default. This gives XGBoost O(n) complexity on sparse data — only non-missing values are visited during split enumeration.

Cache-Aware Block Structure

XGBoost stores training data in in-memory compressed column blocks. Each block contains a feature's sorted values alongside the sample indices — pre-sorted once during training setup. This enables sequential memory access during split scanning, maximising CPU cache utilisation. For datasets that don't fit in memory, XGBoost uses a block-compression scheme with out-of-core computation and thread-parallel column sorting.

🔑 Why XGBoost Wins in Practice

Three engineering breakthroughs combined with mathematical rigour:

1. Sparsity-aware: handles NaN and sparse features in O(non-zero) time. 2. Cache-aware blocks: eliminates random memory access during split scans. 3. Approximate splits: histogram binning turns O(n) scans into O(B) scans without losing much accuracy. Together these make XGBoost 10-100× faster than naive gradient boosting implementations.

🎯 Decision Guide

Use XGBoost when: tabular classification/regression with mixed features; data has sparse or missing values; interpretability via SHAP is needed; competition setting where accuracy is paramount.

Use LightGBM when: dataset is very large (millions of rows) and speed is critical; memory is constrained; leaf-wise growth suits the data distribution.

Avoid both when: data is images/audio/text (use deep learning); dataset is tiny (≤1000 rows, linear models may generalise better).

Key Hyperparameters to Know

n_estimators: number of trees K (more trees → lower bias, potential overfit). max_depth: tree depth (3–6 typical). learning_rate (η): shrinkage per tree (lower η + more trees = better). lambda (λ): L2 leaf weight regularisation. alpha (α): L1 leaf weight regularisation. subsample: row subsampling ratio. colsample_bytree: feature subsampling per tree. min_child_weight: minimum \(H_j\) (hessian sum) in a leaf — prevents splitting on low-confidence regions.
