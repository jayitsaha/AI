Understanding Learned Positional Embeddings
▼

What is it? Self-attention computes a weighted average of value vectors using content-based similarity (queries dotted with keys). Nothing about that computation looks at where a token sits in the sequence — shuffle the input rows and the output rows shuffle identically. So before the first attention layer runs, models like BERT and GPT add a second vector to every token: one that depends only on the token's position, not its identity. This second vector is not computed from a formula — it is a matrix of trainable numbers, one row per position, learned by gradient descent exactly like every other weight in the network.

Analogy: Imagine handing numbered stickers to people standing in a line before a photographer (attention) studies the group. The photographer only recognizes faces (content), never queue position. The sticker's exact "look" — its color, font, size — isn't fixed by any rule; a stylist (backprop) redesigns all the stickers over many rehearsals until the numbering actually helps the photographer describe the group correctly ("the person after #3 is short").

Summary: Learned positional embeddings add a trainable vector \(P[\text{pos}]\), indexed by absolute position, to each token embedding — so position becomes part of the content itself, learned end-to-end rather than hand-derived.

💡 If you remember one thing

A learned positional embedding is just nn.Embedding(max_len, d_model) indexed by position id \(0, 1, \dots, n-1\), added elementwise to the token embedding. Because it is trained, not derived, it has no defined value past max_len — the single biggest practical limitation versus fixed sinusoidal encodings.

How It Works Internally
▼

The Two Tables

Every token-based model already has a token embedding matrix \(T_{\text{emb}} \in \mathbb{R}^{|V| \times d}\), indexed by vocabulary id. A learned-positional-embedding model adds a second, completely separate matrix \(P \in \mathbb{R}^{L_{\max} \times d}\), indexed by absolute position \(0, \dots, L_{\max}-1\). BERT-base uses \(L_{\max}=512\), GPT-2 uses \(L_{\max}=1024\), GPT-3 uses \(L_{\max}=2048\) — fixed at model-construction time and baked into the checkpoint.

The Forward Pass

Given input token ids \(w_1,\dots,w_n\): (1) gather rows \(T_{\text{emb}}[w_i]\) — the token embeddings; (2) build position ids \([0,1,\dots,n-1]\) and gather rows \(P[i]\) — a pure O(n) index lookup, no matrix multiplication at all; (3) sum elementwise: \(X_i = T_{\text{emb}}[w_i] + P[i]\) (BERT also adds a segment embedding here). \(X\) is what enters the first transformer block.

Design Decision: Why Add Instead of Concatenate?

Concatenating would grow the dimensionality and force every downstream weight matrix to carry extra width just to route two independent signals. Addition instead lets content and position live in superposition inside the same \(d\)-dimensional space — the learned \(W_Q, W_K, W_V\) projections in every attention head can then implicitly carve out sub-directions that behave like "content features" or "positional features," discovered by training rather than architected by hand.

Backpropagation Only Touches Rows That Were Used

\(P\) is a parameter matrix, and the lookup is a gather/index-select. Its backward pass is a scatter-add: the gradient reaching row \(p\) is the sum of gradients from every sequence position, in every example of the batch, whose position id equals \(p\). This is a sparse update — a row for a position that never appears during training (e.g. position 900 if all training sequences are shorter than 512) never receives a gradient signal and stays at its random initialization forever.

🔑 Key Property

Learned positional embeddings are ordinary trainable parameters, not a mathematical function of position. That single fact explains both their strength (task/data-adapted representations) and their fundamental weakness (a hard, un-crossable max_position_embeddings wall).

3
Why It's Needed — The Math
▼

Self-Attention Is Permutation-Equivariant

Let \(X \in \mathbb{R}^{n\times d}\) be a sequence of embeddings and let \(\Pi\) be any \(n\times n\) permutation matrix. Self-attention computes:

$$\text{Attn}(X) = \text{softmax}\!\left(\frac{(XW_Q)(XW_K)^\top}{\sqrt{d_k}}\right) XW_V$$

Substituting \(\Pi X\) for \(X\) shows \(\text{Attn}(\Pi X) = \Pi \cdot \text{Attn}(X)\) — permuting the input rows just permutes the output rows identically; the actual numeric content of each output row is unchanged. Attention alone therefore treats a sentence as a bag of tokens. Positional embeddings are the mechanism that breaks this symmetry by making \(X\) itself depend on order:

$$X_i = \text{TokEmb}(w_i) + P[i], \qquad i = 0, 1, \dots, n-1$$

The Gradient Update for the Position Table

Since \(P[p,:]\) is a raw parameter row selected by a gather operation, its gradient is a plain sum-pool over every occurrence of position \(p\) in the batch:

$$\frac{\partial \mathcal{L}}{\partial P[p,:]} = \sum_{(b,i)\,:\,\text{pos}_i^{(b)} = p} \frac{\partial \mathcal{L}}{\partial X_i^{(b)}}, \qquad P[p,:] \leftarrow P[p,:] - \eta \frac{\partial \mathcal{L}}{\partial P[p,:]}$$

Nothing in this update rule ties \(P[p,:]\) to \(P[p+1,:]\) — they are updated completely independently. Any smoothness you observe between neighboring rows after training (Card 4, Step 8) is emergent: it happens only because language modeling objectives make nearby positions behave similarly, not because the architecture enforces it.

⚠️ Common Misconception

"Positional embeddings encode geometric distance by design." They don't — nothing forces \(P[5]\) to be closer to \(P[6]\) than to \(P[500]\). Distance-awareness is learned, not guaranteed, and it vanishes entirely for positions outside the training range. Fixed sinusoidal encodings (original Transformer) guarantee smoothness and extrapolation by construction; relative schemes like RoPE and ALiBi later restored that guarantee while keeping the flexibility of being baked directly into the attention score.

Key Takeaways
▼

When to use learned absolute embeddings:

  • Fixed, known maximum context length (BERT: 512, GPT-2: 1024, GPT-3: 2048 tokens)
  • Abundant training data at that length, so every position row gets many gradient updates
  • You want the simplest possible mechanism — one extra embedding table, one elementwise add

When NOT to use:

  • You need to run inference on sequences longer than training length — rows past max_position_embeddings are literally undefined
  • Long-context or streaming applications — prefer relative schemes (RoPE, ALiBi, T5 relative bias) that extrapolate
  • Very low-resource training — rarely-seen high positions stay near their random initialization
💡 The Positional Encoding Family Tree

Fixed sinusoidal (Vaswani et al., 2017 — smooth, extrapolates, not learned) → Learned absolute (BERT, GPT-2/3 — flexible, data-adapted, hard length cap) → Relative / rotary (T5 bias, RoPE in LLaMA/GPT-NeoX, ALiBi — baked into the attention score itself, combining learned flexibility with extrapolation). Each generation traded one property for another; none dominates on every axis.

import numpy as np
# --- From scratch: forward pass ---
d_model, max_len, vocab = 4, 8, 30000
tok_emb = np.random.randn(vocab, d_model) * 0.02
pos_emb = np.random.randn(max_len, d_model) * 0.02 # LEARNED table
def embed(token_ids):
n = len(token_ids)
if n > max_len:
raise ValueError(f"sequence length {n} exceeds max_len {max_len}")
T = tok_emb[token_ids] # gather rows, shape (n, d_model)
pos_ids = np.arange(n) # [0, 1, ..., n-1]
P = pos_emb[pos_ids] # gather rows, shape (n, d_model)
return T + P # elementwise sum
# --- From scratch: gradient (scatter-add) ---
def pos_emb_backward(pos_ids, grad_X, pos_emb_grad):
for i, p in enumerate(pos_ids):
pos_emb_grad[p] += grad_X[i] # only used rows get gradient
# --- Production usage: PyTorch ---
import torch, torch.nn as nn
class LearnedPositionalEmbedding(nn.Module):
def __init__(self, max_len, d_model):
super().__init__()
self.pos_emb = nn.Embedding(max_len, d_model) # trainable table
def forward(self, x): # x: (B, n, d_model)
n = x.size(1)
pos_ids = torch.arange(n, device=x.device)
return x + self.pos_emb(pos_ids) # broadcast add
# ⚠️ Gotcha: truncate or bucket positions >= max_len — never index past the table
