Padding Mask (in Attention)

Stopping <PAD> tokens from leaking into softmax attention
Foundational NLP / Transformers Self-Attention O(n²) mask
1
Understanding the Padding Mask
▼

What is it? Transformers process sequences in fixed-size batches, but real sentences have different lengths. To stack them into one tensor, shorter sequences get filler <PAD> tokens appended until every sequence in the batch matches the longest one. The padding mask is a binary flag — 1 for a real token, 0 for a pad token — that tells self-attention "never let any query look at a pad position."

Analogy: Imagine a classroom survey where every student must submit a 5-question form, but some students only had 3 real questions to answer — the rest are blank filler lines. When you tally the results, you obviously ignore the blank lines; counting them would corrupt the average. The padding mask is exactly that "ignore the blank lines" rule, enforced automatically inside the attention computation.

Where it matters: Padding masks appear in encoder self-attention (BERT, encoder of T5), decoder cross-attention (looking at a padded encoder output), and are combined with the causal mask in decoder self-attention (GPT-style, decoder of T5/Transformer).

💡 If you remember one thing

Before softmax, every attention score pointing at a padded key is overwritten with \(-\infty\) (in practice a large negative number). Softmax of \(-\infty\) is exactly 0, so pad positions contribute nothing to the output — with zero risk of a NaN or divide-by-zero, unlike zeroing the weights after softmax.

2
How the Padding Mask Works Internally
▼

Step 1 — Build the mask from real lengths

For each sequence in the batch, the data loader knows the true length \(\ell\) (before padding). The mask is simply \(m_j = 1\) if position \(j < \ell\), else \(m_j = 0\). Shape: \((B, L_k)\) where \(B\) is batch size and \(L_k\) is the padded sequence length.

Step 2 — Broadcast into the attention score tensor

Raw attention scores have shape \((B, H, L_q, L_k)\) — batch, heads, query positions, key positions. The mask is reshaped to \((B, 1, 1, L_k)\) so it broadcasts over every head and every query row. Every column \(j\) with \(m_j = 0\) gets suppressed for all queries in that sequence — padding never depends on which query is asking.

Step 3 — Apply before softmax, not after

The mask is applied as scores.masked_fill(mask == 0, -1e9) — an additive/replacement operation performed before the softmax, never after. This is the single most important design decision in this whole topic.

🔑 Design decision — why not just zero the weights after softmax?

If you instead computed softmax first and zeroed the pad columns afterward, the remaining weights would no longer sum to 1 — you'd need a second renormalization pass, and the pad logits would still have distorted the max-subtraction and denominator used for numerical stability. Masking with \(-\infty\) before softmax makes the pad terms vanish from the sum automatically, in a single fused, numerically stable pass.

Padding mask vs. causal mask

A causal mask blocks position \(i\) from seeing future position \(j > i\) — it depends on the query/key pair \((i,j)\) and encodes word order. A padding mask blocks position \(j\) purely because it's filler content — it depends only on \(j\) and is identical for every query row. In decoder self-attention, both masks are combined with a logical AND before the single softmax call.

3
Why It Works — The Math
▼

Standard scaled dot-product attention

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V$$

where \(M\) is the additive mask matrix. For a purely padding mask (row-independent), $$M_{ij} = \begin{cases} 0 & \text{if } m_j = 1 \text{ (real key)} \\ -\infty & \text{if } m_j = 0 \text{ (pad key)} \end{cases}$$

Why softmax sends it to exactly zero

Row \(i\) of the softmax is $$\alpha_{ij} = \frac{\exp(s_{ij} + M_{ij})}{\sum_{k=1}^{L_k} \exp(s_{ik} + M_{ik})}.$$ For a masked column, \(\exp(s_{ij} - \infty) = \exp(-\infty) = 0\) exactly, so \(\alpha_{ij} = 0\) and that term also vanishes from the denominator — the remaining real-token weights are automatically renormalized to sum to 1 over just the valid keys.

Numerical stability in practice

True \(-\infty\) combined with the max-subtraction trick used for stable softmax, \(\exp(s_{ij} - \max_k s_{ik})\), is safe as long as at least one key in the row is unmasked. Frameworks use a large finite sentinel (e.g. \(-10^9\) or the dtype's minimum) instead of literal \(-\infty\) to avoid NaN arithmetic (\(-\infty - (-\infty)\)) when an entire row happens to be masked.

⚠️ Common pitfall — the fully-masked row

If every key in a row is masked (can happen for a pad query row, or a pad key row combined with causal masking on the very first pad position), every entry becomes the same sentinel value, softmax outputs a uniform distribution over garbage keys instead of \(\tfrac{0}{0}\), and the row's output is later discarded anyway via the padding mask applied to the loss. This is why frameworks use a large finite number, not literal -inf — it avoids a hard NaN crash.

Key Takeaways
▼

When it's needed:

  • Any batch with sequences of different lengths (almost always, outside of single-example inference)
  • Encoder self-attention, decoder cross-attention over a padded encoder output, and decoder self-attention (combined with causal mask)
  • Pooling / loss computation also needs the same mask, so pad positions don't skew the sentence embedding or the loss average

When you can skip it:

  • Batch size of 1 with no padding, or all sequences already truncated/bucketed to identical length
  • Packed-sequence formats that concatenate variable-length examples without padding (still need a mask/boundary indicator of some kind — you don't get a free lunch)
💡 Mental model

Padding mask = "irrelevant, not sequential." Causal mask = "not yet available." Both are additive \(-\infty\) masks applied to the same score matrix before one softmax call — they compose with a logical AND, not two separate softmaxes.

Code Trace
▼
import torch, torch.nn.functional as F
# lengths: true (unpadded) length of each sequence in the batch
lengths = torch.tensor([3, 5, 2]) # batch of 3, L_max = 5
L_max = 5
positions = torch.arange(L_max)[None, :] # (1, L_max)
pad_mask = positions < lengths[:, None] # (B, L_max) bool, True = real
# scores: (B, H, L_q, L_k) raw Q K^T / sqrt(d_k)
scores = (Q @ K.transpose(-2, -1)) / (d_k ** 0.5)
# broadcast pad_mask to (B, 1, 1, L_k) and fill BEFORE softmax
key_mask = pad_mask[:, None, None, :]
scores = scores.masked_fill(~key_mask, float('-inf'))
# decoder self-attention: AND with the causal mask
causal = torch.tril(torch.ones(L_max, L_max, dtype=torch.bool))
scores = scores.masked_fill(~causal, float('-inf'))
weights = F.softmax(scores, dim=-1) # pad columns are exactly 0
output = weights @ V
# In PyTorch's built-in op, pass the mask directly:
out = F.scaled_dot_product_attention(Q, K, V, attn_mask=key_mask & causal)
