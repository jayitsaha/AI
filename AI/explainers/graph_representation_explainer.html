Understanding Graph Representation
▼

What is it? A graph is just a set of things (nodes, also called vertices) and a set of connections between pairs of them (edges). To make a computer reason about a graph, we need to turn that picture of circles-and-lines into numbers — matrices. The adjacency matrix \(A\) records which nodes are connected, and the degree matrix \(D\) records how many connections each node has.

Analogy: Think of a group chat with 5 friends. The "nodes" are the friends. An "edge" exists between two friends if they've ever DMed each other directly. The adjacency matrix is literally a 5×5 spreadsheet: row A, column B has a 1 if A and B have DMed, otherwise 0. The degree matrix just counts, for each friend, how many other friends they've DMed in total — their "popularity" in this tiny social network.

💡 If you remember one thing

The adjacency matrix \(A\) is the graph's "who's connected to whom" table, and the degree matrix \(D\) is just the row sums of \(A\) placed on a diagonal: $$D_{ii} = \sum_{j} A_{ij}, \qquad D_{ij}=0 \text{ for } i \ne j$$ Together they're the raw ingredients for almost every graph algorithm — including Graph Neural Networks.

How the Representation Works Internally
▼

From Picture to Matrix

Formally, a graph is a pair \(G=(V,E)\): a vertex set \(V\) with \(|V|=n\) nodes, and an edge set \(E \subseteq V \times V\). To store \(E\) as a matrix, we index nodes \(0,\dots,n-1\) and build \(A \in \{0,1\}^{n\times n}\) where \(A_{ij}=1\) if an edge connects node \(i\) and node \(j\), else \(0\). For an undirected graph (friendship is mutual), every edge sets two cells at once — \(A_{ij}\) and \(A_{ji}\) — so \(A\) is always symmetric: \(A = A^\top\). For a directed graph (e.g. "follows" on social media), only \(A_{ij}\) is set and the matrix need not be symmetric.

Degree = Row Sum

The degree of a node is simply how many edges touch it. Reading across row \(i\) of \(A\) and adding up the 1s gives exactly that count. Stack those counts on the diagonal of an otherwise-empty \(n\times n\) matrix and you get the degree matrix \(D\) — a compact summary of "how busy" each node is, with zero information about which nodes it connects to (that detail lives in \(A\)).

Design Decision: Why a Matrix and Not Just a List?

The obvious alternative is an adjacency list — for each node, store a list of its neighbors. Lists use \(O(V+E)\) memory (great for sparse graphs) but checking "are nodes 3 and 7 connected?" requires scanning a list. The adjacency matrix uses \(O(V^2)\) memory regardless of how many edges exist, but that same question becomes an \(O(1)\) array lookup: A[3][7]. Matrices also unlock linear-algebra machinery (eigenvalues, matrix powers, spectral methods) that lists don't support directly — which is exactly why Graph Neural Networks and spectral clustering are built on top of \(A\) and \(D\), not on adjacency lists.

🔑 Key Property

For an undirected, unweighted graph, the adjacency matrix is always symmetric with a zero diagonal (no self-loops), and the sum of all its entries equals \(2|E|\) — every edge is counted exactly twice, once from each endpoint.

Why It Works — The Math
▼

Defining the Objects Precisely

Let \(G=(V,E)\), \(|V|=n\). The adjacency matrix \(A \in \mathbb{R}^{n\times n}\) is defined entrywise:

$$A_{ij} = \begin{cases} 1 & \text{if } (i,j) \in E \\ 0 & \text{otherwise} \end{cases}$$

The degree matrix \(D\) is diagonal, built from the row sums of \(A\):

$$D = \operatorname{diag}(d_1,\dots,d_n), \qquad d_i = \sum_{j=1}^{n} A_{ij}$$

From these two objects we can define the (combinatorial) graph Laplacian, the single most important derived matrix in spectral graph theory:

$$L = D - A$$

Every row of \(L\) sums to zero by construction (the diagonal \(d_i\) exactly cancels the \(-1\)'s contributed by its \(d_i\) neighbors). This means the all-ones vector \(\mathbf{1}\) is always an eigenvector of \(L\) with eigenvalue \(0\): \(L\mathbf{1}=0\). More generally, \(L\) is symmetric positive semi-definite, and the multiplicity of its zero eigenvalue equals the number of connected components of \(G\) — the basis of spectral clustering.

⚠️ Common Pitfall

Don't confuse the adjacency matrix's row sum (degree) with a probability. To turn \(A\) into a random-walk transition matrix you need \(D^{-1}A\) (row-normalized), and the normalized Laplacian used in most GNN layers is \(L_{\text{sym}} = I - D^{-1/2}AD^{-1/2}\) — the extra \(D^{-1/2}\) terms rescale each node by \(1/\sqrt{\text{degree}}\) so high-degree "hub" nodes don't dominate.

Key Takeaways
▼

When to use the adjacency matrix:

  • Dense graphs, or when you need \(O(1)\) "are these connected?" queries
  • Feeding a graph into linear-algebra-based methods: spectral clustering, GNN message passing, PageRank
  • Small-to-medium graphs where \(O(V^2)\) memory is affordable

When NOT to use it:

  • Very large, sparse graphs (e.g. the web graph, social networks) — an adjacency list uses \(O(V+E)\) instead of \(O(V^2)\)
  • Graphs that change size dynamically and often — lists resize more cheaply
💡 Extensions

Weighted graphs: replace the 1s in \(A\) with real-valued edge weights. Directed graphs: drop the symmetry requirement — \(A_{ij}\) and \(A_{ji}\) become independent. Self-loops: add a nonzero diagonal to \(A\) (common in GNNs, e.g. \(A + I\), so a node's own features are included when aggregating).

Code Trace
▼
import numpy as np
nodes = ['A', 'B', 'C', 'D', 'E']
edges = [(0,1), (0,2), (1,2), (1,3), (2,4), (3,4)]
n = len(nodes)
# Build the adjacency matrix, one edge at a time
A = np.zeros((n, n), dtype=int)
for i, j in edges:
A[i, j] = 1
A[j, i] = 1 # undirected -> symmetric
# Degree matrix: diagonal of row sums of A
degrees = A.sum(axis=1)
D = np.diag(degrees)
# Row i of A gives node i's neighbors directly
neighbors_of_C = np.nonzero(A[2])[0]
# Graph Laplacian
L = D - A
print("A:\n", A)
print("D:\n", D)
print("L:\n", L)
