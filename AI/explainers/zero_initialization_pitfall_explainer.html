Zero Initialization Pitfall

Why setting every weight in a layer to zero — or to any identical value — permanently breaks its ability to learn distinct features.
Foundational Deep Learning · Weight Initialization Symmetry Breaking Common Bug
1
Understanding the Concept
▾

What is this? Weight initialization sets the starting value of every trainable parameter before training begins. If you initialize every weight in a layer to the exact same number — most commonly zero — every neuron in that layer computes the exact same function of the input, forever. Training runs, the loss even goes down, but the layer never learns more than what a single neuron could learn.

Real-world analogy. Imagine assigning two students identical notes, identical homework, and identical exam answers on day one, then giving both of them the exact same feedback after every test. They will remain indistinguishable no matter how many semesters pass — not because they're incapable, but because nothing ever pushed them to specialize. A hidden layer with equal weights is a classroom of clones: same inputs in, same corrections out, same outputs forever.

One-sentence summary: zero (or any equal) initialization makes every neuron in a layer permutation-identical, and since gradient descent applies identical updates to identical neurons, that redundancy never breaks — collapsing an n-neuron layer into the representational power of one.

💡 If you remember one thing

It's not that zero weights cause zero gradients — the gradients can be perfectly healthy and nonzero. The real failure is that every neuron receives the identical gradient, so symmetry is never broken and the neurons never differentiate.

2
How It Works Internally
▾

Forward pass. With all weights in a layer set equal, every neuron computes the same pre-activation from the same input, so every neuron's output activation is also identical. Two neurons, one signal, duplicated.

Backward pass. Backpropagation computes each neuron's gradient via the chain rule: an upstream signal (how much the loss cares about this neuron's output) multiplied by a local derivative (how much this neuron's output changes with its own weight). Because both neurons feed the same downstream computation and have identical activations, both factors are identical across the two neurons. The result: \(\partial L/\partial w_1 = \partial L/\partial w_2\), exactly, at every step.

The update. Vanilla gradient descent then applies w ← w − η·∇w to both neurons. Equal starting value plus equal update equals equal result. Repeat this for a thousand epochs and the two neurons are still bit-for-bit mirrors — they have permutation symmetry that nothing in plain gradient descent can break.

Design decision: why doesn't more training fix it?

Because "more training" just means "more identical steps applied to identical values." The only way out is to inject asymmetry into the starting point (or into the forward/backward computation itself) — which is exactly what random initialization does: independent random draws mean no two neurons start equal, so their gradients immediately diverge and stay distinct.

This is a distinct failure mode from vanishing/exploding gradients or dead ReLUs — those are about gradient magnitude; the zero-init pitfall is about gradient redundancy across neurons in the same layer. Note also that biases are part of the same symmetry: if weights are randomized but every neuron in a layer shares identical biases and identical weight rows, the collapse still happens — the fix must break symmetry in the full parameter set feeding each neuron.

3
Why It Works — The Math
▾

Consider a hidden layer of \(n\) neurons sharing input \(x\), with neuron \(i\) computing \(h_i = \sigma(w_i x)\), feeding a loss \(L\) through some shared downstream computation. Gradient descent updates each weight independently:

$$w_i^{(t+1)} = w_i^{(t)} - \eta\,\frac{\partial L}{\partial w_i}\bigg|_t, \qquad \frac{\partial L}{\partial w_i} = \underbrace{\frac{\partial L}{\partial h_i}}_{\text{upstream signal}} \cdot \underbrace{\frac{\partial h_i}{\partial w_i}}_{\text{local derivative}}$$
Key Property (Symmetry Invariant)

Claim. If \(w_1^{(0)} = w_2^{(0)} = \cdots = w_n^{(0)}\), then \(w_1^{(t)} = w_2^{(t)} = \cdots = w_n^{(t)}\) for every training step \(t \ge 0\) under vanilla (stochastic) gradient descent.

Proof (induction on \(t\)). Base case \(t=0\): true by hypothesis. Inductive step: assume \(w_i^{(t)}=w_j^{(t)}=w^{(t)}\) for all \(i,j\). Since \(h_i^{(t)}=\sigma(w_i^{(t)} x)\) depends only on the shared \(x\) and the (equal) weight, \(h_i^{(t)} = h_j^{(t)}\). Every downstream quantity — the layer's contribution to \(y\), hence \(L\) — is therefore an identical function of each neuron, so \(\partial L/\partial w_i|_t = \partial L/\partial w_j|_t\). Applying the identical update rule to equal quantities gives \(w_i^{(t+1)} = w_j^{(t+1)}\). \(\blacksquare\)

The proof never assumes the gradient is zero — only that it is the same for every neuron sharing the initial value. That is the whole mechanism of the pitfall.

⚠️ Common Misconception

"Zero-init is bad because it makes the gradients zero, so nothing updates." This is false in general — as the visualization below shows, gradients under zero-init can be large and nonzero, and the weights move every step. The real bug is that they move together, forever, so an \(n\)-neuron layer trains as if it were one neuron copy-pasted \(n\) times.

Key Takeaways
▾
  • Never initialize all weights in a layer to the same value — zero is the most common accidental case, but any tied constant fails identically.
  • Random init breaks symmetry by construction. Schemes like Xavier/Glorot (\(\text{Var}(w)=1/n_{in}\)) and He/Kaiming (\(\text{Var}(w)=2/n_{in}\)) draw each weight independently from the same distribution — but each draw is a different number, so no two neurons start identical.
  • Biases can safely start at zero — because the weight matrix already differs per neuron, the pre-activations differ even with shared bias, so symmetry is already broken upstream.
  • This is why every major framework defaults to kaiming_uniform_ / glorot_uniform instead of zeros_ for weight tensors.
  • Related topics: Xavier/Glorot initialization, He initialization, vanishing/exploding gradients, dead ReLU units, LeCun initialization.

Code Trace — Zero vs. Random Init
▾

Same two-neuron network the visualization above runs, in NumPy. Note the two highlighted lines: with W = np.zeros(...) the weight rows stay identical after every update; with W = np.random.randn(...) they immediately diverge.

import numpy as np
def train(W, x=1.0, target=1.0, lr=0.8, steps=6):
# W has shape (2,) — one weight per hidden neuron, output weights fixed at 0.5
for t in range(steps):
h = np.tanh(W * x) # forward: pre-activation -> tanh
y = 0.5 * (h[0] + h[1]) # output = average of hidden units
loss = 0.5 * (y - target) ** 2
dL_dy = (y - target)
dL_dh = dL_dy * 0.5 # SAME for both neurons (shared output path)
grad = dL_dh * x * (1 - h ** 2) # <-- differs only if h[0] != h[1]
W = W - lr * grad
return W
w_zero = train(np.zeros(2)) # -> [w, w] ALWAYS equal, every epoch, forever
w_rand = train(np.array([0.6, -0.4])) # -> [a, b] with a != b, features diverge
Gotcha

This bug hides well: loss curves for zero-init networks often still go down (because the collapsed "single effective neuron" can still fit part of the data), so training doesn't crash or obviously fail — the model just silently underperforms relative to its declared capacity.
