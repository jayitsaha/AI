Anomaly Detection Framing

One-Class vs. Binary Classification: Choosing the right problem setup
Intermediate Machine Learning Classification Problem Setup
1
Understanding Anomaly Detection Framing
▼

What is it? Anomaly detection is the task of identifying unusual patterns or data points that deviate significantly from the expected norm. "Framing" refers to how we define and set up this problem for a machine learning model. This setup choice is critical, as it dictates the available data, suitable algorithms, and ultimately, what kinds of anomalies can be found.

Analogy: Imagine you're a quality control inspector. If you're looking for counterfeit coins, you might only have examples of *genuine* coins to study. Anything that doesn't look like a genuine coin is suspicious. This is a "one-class" problem. But if you're looking for specific types of manufacturing defects, and you have many examples of both "good" products and products with "known defect X", then you're doing a "binary classification" problem: is it good, or does it have defect X?

💡 If you remember one thing

The core of anomaly detection framing is deciding whether you're learning a model of "normality" (one-class approach, good for novel anomalies) or learning to distinguish between "normal" and "known anomaly types" (binary classification approach, good for specific, recurring anomalies).

2
Two Main Framings & Their Mechanics
▼

1. One-Class Anomaly Detection (Unsupervised / Semi-supervised)

In this framing, the model is trained exclusively on data assumed to be "normal." The objective is to learn a compact representation or boundary that encapsulates the characteristics of normal data. Anything that falls outside this learned boundary, or has a low probability under the learned normal distribution, is flagged as an anomaly.

  • Training Data: Only (or predominantly) normal instances. Any anomalies present are treated as noise or assumed to be very rare.
  • Goal: Model the "normal" class. Anomalies are implicitly defined as "everything else."
  • Detection: Calculate an anomaly score (e.g., distance from boundary, reconstruction error, density estimate). High scores indicate anomalies.
  • Algorithms: One-Class SVM, Isolation Forest, Autoencoders (reconstruction error), Gaussian Mixture Models (low likelihood).
  • Use Cases: Detecting novel fraud patterns, identifying new types of network intrusions, monitoring system health for unforeseen failures.

2. Binary Classification Anomaly Detection (Supervised)

When labeled examples of both normal and anomalous data are available, the problem can be framed as a standard binary classification task. The model learns to distinguish between the two classes directly.

  • Training Data: Labeled instances of both normal and anomalous data.
  • Goal: Learn a decision boundary that separates normal from anomaly classes.
  • Detection: Standard classifier prediction (e.g., "normal" or "anomaly").
  • Challenges:
    • Extreme Class Imbalance: Anomalies are often rare, leading to a large skew in class distribution (e.g., 99.9% normal, 0.1% anomaly).
    • Novelty Detection: The model can only learn to detect anomaly types present in the training data. Truly novel anomalies (unseen during training) may be misclassified as normal.
  • Algorithms: Logistic Regression, SVM, Neural Networks, Gradient Boosting (often with techniques for imbalance like `class_weight` or resampling).
  • Use Cases: Identifying known types of manufacturing defects, detecting specific medical conditions, flagging known types of fraudulent transactions.
🔑 Key Trade-off

The fundamental trade-off in anomaly detection framing is between the ability to detect novel, unknown anomaly types (favored by one-class methods) versus the ability to precisely identify known, recurring anomaly types (favored by supervised binary classification).

3
Why It Works — Mathematical Formulations
▼

One-Class SVM (OCSVM) Objective

One-Class SVM (Schölkopf et al., 2001) is a prime example of a one-class approach. It finds a hyperplane that separates the normal data points from the origin in a high-dimensional feature space, maximizing the margin. The goal is to enclose the normal data in a small region.

$$\min_{w, b, \rho, \xi} \frac{1}{2}\|w\|^2 + \frac{1}{\nu n}\sum_{i=1}^n \xi_i - \rho$$ $$\text{subject to } (w \cdot \phi(x_i)) \ge \rho - \xi_i \quad \text{and } \xi_i \ge 0, \quad \text{for } i=1, \dots, n$$

Here, \(w\) is the normal vector to the hyperplane, \(b\) is the bias (often implicitly handled by \(\rho\)), \(\phi(x_i)\) is the feature mapping (often a kernel trick), \(\xi_i\) are slack variables for points that fall inside the boundary (tolerating some "normal" points being outside), and \(\nu \in (0,1]\) is a hyperparameter controlling the trade-off between maximizing the margin and minimizing the number of slack variables (i.e., the fraction of outliers). The decision function for a new point \(x\) is \(f(x) = \operatorname{sign}(w \cdot \phi(x) - \rho)\).

Binary Classification (e.g., Logistic Regression) Objective

For binary classification, the objective is to minimize a loss function that penalizes misclassifications. For Logistic Regression, this is the binary cross-entropy loss:

$$\min_{w, b} -\frac{1}{n}\sum_{i=1}^n [y_i \log(\hat{p}_i) + (1-y_i)\log(1-\hat{p}_i)]$$ $$\text{where } \hat{p}_i = \sigma(w \cdot x_i + b) = \frac{1}{1 + e^{-(w \cdot x_i + b)}}$$

Here, \(y_i \in \{0, 1\}\) are the true labels (0 for normal, 1 for anomaly), and \(\hat{p}_i\) is the predicted probability that \(x_i\) is an anomaly. The model directly learns to map features to a probability of being anomalous.

Addressing Class Imbalance in Binary Classification

When the anomaly class is very rare, the standard cross-entropy loss can lead to models that simply predict "normal" for almost all instances, achieving high accuracy but failing to detect anomalies. Techniques to mitigate this include:

  • Class Weighting: Modify the loss function to give more weight to errors on the minority (anomaly) class. For example, assign a weight \(W_1\) to anomaly class errors and \(W_0\) to normal class errors, where \(W_1 > W_0\). In `scikit-learn`, this is often handled by `class_weight='balanced'`, which sets weights inversely proportional to class frequencies: \(W_k = n / (2 \cdot n_k)\).
  • Resampling: Oversample the minority class (e.g., SMOTE) or undersample the majority class.
  • Adjusting Thresholds: Instead of using 0.5 as a decision threshold, choose a threshold that optimizes for a metric like F1-score or Precision-Recall AUC, which are more appropriate for imbalanced data.
⚠️ Common Pitfall

Applying standard binary classifiers directly to severely imbalanced anomaly detection problems (e.g., 1:1000 ratio) without specific handling for imbalance is a common mistake. Such models often become "lazy" and learn to predict the majority class almost exclusively, resulting in near-zero recall for anomalies.

Key Takeaways
▼

When to choose One-Class Anomaly Detection:

  • Limited Labeled Anomalies: You have plenty of "normal" data but few or no labeled examples of anomalies for training.
  • Novelty Detection is Key: You anticipate that new, unforeseen types of anomalies will emerge, and you need to detect them even if they don't resemble past anomalies.
  • Anomaly Definition: Your definition of an anomaly is broad: "anything that is not normal."
  • Domain Expertise: It's easier for domain experts to define "normal" behavior than to enumerate all possible "anomalous" behaviors.

When to choose Binary Classification Anomaly Detection:

  • Sufficient Labeled Anomalies: You have a good number of labeled examples for both normal and known anomaly types.
  • Known Anomaly Types: The anomalies you care about are well-defined, recurring, and resemble past observed anomalies.
  • High Specificity Needed: You need to precisely identify specific types of anomalies, rather than just flagging general "weirdness."
  • Cost of Errors: The costs associated with False Positives and False Negatives are well-understood, and you need to optimize for specific metrics (e.g., high recall for critical anomalies).
💡 Rule of Thumb

The choice of anomaly detection framing is not a technical detail but a fundamental strategic decision. It depends entirely on the nature of your data, the characteristics of the anomalies you expect, and the operational goals of your detection system.

Code Trace — Scikit-learn Implementations
▼
import numpy as np
from sklearn.svm import OneClassSVM
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
# 1. Generate synthetic data (simplified for brevity)
rng = np.random.RandomState(42)
X_normal = 0.3 * rng.randn(100, 2) + np.array([0, 0]) # Majority class
X_known_anom = 0.2 * rng.randn(10, 2) + np.array([2, 2]) # Minority, labeled anomaly
X_novel_anom = 0.2 * rng.randn(5, 2) + np.array([-2, -2]) # Minority, unlabeled anomaly
# Combine for visualization/evaluation, keep track of types
X_all = np.vstack([X_normal, X_known_anom, X_novel_anom])
y_true = np.array([0]*len(X_normal) + [1]*len(X_known_anom) + [1]*len(X_novel_anom))
# 2. One-Class Anomaly Detection (training only on normal data)
scaler_oc = StandardScaler().fit(X_normal)
X_normal_scaled = scaler_oc.transform(X_normal)
ocsvm = OneClassSVM(kernel="rbf", gamma="auto", nu=0.1).fit(X_normal_scaled)
# Predict on all data (scaled by same scaler)
X_all_scaled_oc = scaler_oc.transform(X_all)
ocsvm_preds = ocsvm.predict(X_all_scaled_oc) # -1 for anomalies, 1 for normal
# 3. Binary Classification Anomaly Detection (training on normal + known anomalies)
X_train_binary = np.vstack([X_normal, X_known_anom])
y_train_binary = np.array([0]*len(X_normal) + [1]*len(X_known_anom))
scaler_bc = StandardScaler().fit(X_train_binary)
X_train_binary_scaled = scaler_bc.transform(X_train_binary)
X_all_scaled_bc = scaler_bc.transform(X_all)
# Naive Logistic Regression
lr_naive = LogisticRegression(solver='liblinear').fit(X_train_binary_scaled, y_train_binary)
lr_naive_preds = lr_naive.predict(X_all_scaled_bc)
# Balanced Logistic Regression (imbalance handling)
lr_balanced = LogisticRegression(solver='liblinear', class_weight='balanced').fit(X_train_binary_scaled, y_train_binary)
lr_balanced_preds = lr_balanced.predict(X_all_scaled_bc)
