What Are Weight Tensors?
▾

In deep learning, a tensor is a multi-dimensional array of numbers. A weight tensor is any learnable tensor — updated by gradient descent — that defines what a layer does. Every matrix multiply, convolution, and attention operation is ultimately a contraction (a generalised dot-product) between an input activation tensor and a weight tensor.

Key Concept

The shape of a weight tensor encodes the exact transformation the layer performs. Reading a layer's weight shape is sufficient to compute its parameter count, memory footprint, and arithmetic intensity — no code needed.

Why shape notation matters: PyTorch / NumPy uses row-major (C-contiguous) storage — the last axis varies fastest in memory. So a weight of shape \((64, 3, 7, 7)\) stores all 147 numbers of each filter contiguously, then moves to the next filter. This dictates cache behaviour, which matters for GPU throughput.

Analogy

Think of a weight tensor as a filing cabinet. A linear layer has 2 drawers labelled out and in. A Conv2d has 4 drawers: output channel, input channel, kernel row, kernel col. An attention score matrix adds a batch drawer and a heads drawer. The total number of individual papers in the cabinet is the parameter count.

Prerequisites: matrix multiplication, dot products, basic Python/NumPy indexing. Knowing what a neural network forward pass does conceptually is sufficient.

General Parameter Count Formula

For any weight tensor of shape \((d_1, d_2, \ldots, d_k)\):

$$\text{params} = \prod_{i=1}^{k} d_i$$

Add \(d_1\) for the bias vector of the output dimension (one scalar per output unit).

Common Mistake

People count biases as "free" but they are full parameters with gradients. For a Conv2d with 256 output channels the bias adds 256 parameters — negligible vs 147 K weights, but not zero.

The Math: Contraction, Layout & Gradient Flow
▾

Linear layer forward pass. Given input \(x \in \mathbb{R}^{N \times d_{in}}\) and weight \(W \in \mathbb{R}^{d_{out} \times d_{in}}\):

$$y = x W^\top + b \qquad y \in \mathbb{R}^{N \times d_{out}}$$

This is an \(N \times d_{in}\) by \(d_{in} \times d_{out}\) matrix product — a tensor contraction over the shared \(d_{in}\) axis. MACs = \(N \cdot d_{out} \cdot d_{in}\).

Conv2d forward pass. With input \(x \in \mathbb{R}^{N \times C_{in} \times H \times W}\) and weight \(W \in \mathbb{R}^{C_{out} \times C_{in} \times k_H \times k_W}\):

$$y[n, c_{out}, h, w] = \sum_{c=1}^{C_{in}} \sum_{i=1}^{k_H} \sum_{j=1}^{k_W} W[c_{out}, c, i, j] \cdot x[n, c,\, hs+i,\, ws+j] + b[c_{out}]$$

Output shape: \(\bigl(N,\; C_{out},\; \lfloor(H + 2p - k_H)/s\rfloor + 1,\; \lfloor(W + 2p - k_W)/s\rfloor + 1\bigr)\). For ResNet stem (224×224, stride=2, pad=3, k=7): output = \((N, 64, 112, 112)\). MACs per image = \(C_{out} \cdot H_{out} \cdot W_{out} \cdot C_{in} \cdot k_H \cdot k_W = 64 \times 112 \times 112 \times 147 \approx 118\text{ M}\).

Scaled dot-product attention. Projections: \(Q = X W_Q,\; K = X W_K,\; V = X W_V\) where \(W_Q, W_K, W_V \in \mathbb{R}^{d_{model} \times d_{head}}\). Attention for one head:

$$\text{Attn}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_{head}}}\right) V$$

\(QK^\top \in \mathbb{R}^{seq \times seq}\) — this is the \((B, h, seq, seq)\) tensor you see on step 4 of the visualisation. The \(1/\sqrt{d_{head}}\) scaling prevents the dot products from growing in magnitude and pushing softmax into its near-zero gradient region.

Gradient flow through weight tensors. By the chain rule, the gradient w.r.t. a linear weight \(W\) is:

$$\frac{\partial \mathcal{L}}{\partial W} = \frac{\partial \mathcal{L}}{\partial y} \cdot x \qquad \in \mathbb{R}^{d_{out} \times d_{in}}$$

Same shape as \(W\) — the optimizer step subtracts a scaled version of this. For Conv2d the gradient is a cross-correlation of the input with the upstream gradient.

Memory Warning — Activation Checkpointing

Backpropagation requires all intermediate activation tensors \(y = f(Wx)\) to be retained in GPU memory during the forward pass so gradients can be computed during the backward pass. A single batch's activations can dwarf the weight tensors themselves (e.g., 12.3 MB for (4,64,112,112) vs 36.8 KB for the Conv2d weight). Gradient checkpointing re-computes activations on the fly to trade compute for memory.

Memory Layout, Practical Gotchas & Key Takeaways
▾

Memory layout (NCHW vs NHWC). PyTorch defaults to NCHW (channels-first). TensorFlow defaults to NHWC (channels-last). A Conv2d weight \((C_{out}, C_{in}, k_H, k_W)\) is always stored channel-first regardless. cuDNN uses Winograd or implicit-GEMM algorithms that require the weight to be in a specific packed layout internally — PyTorch handles this automatically when you move a tensor to CUDA.

Strides — What really controls layout

A PyTorch tensor's memory layout is determined by its strides: a tuple of integers giving the step (in elements) to advance along each axis. A contiguous \((64,3,7,7)\) tensor has strides (147, 49, 7, 1) — reading element [0,1,2,3] requires advancing 0×147 + 1×49 + 2×7 + 3×1 = 66 elements from the base pointer. tensor.contiguous() forces a copy into standard row-major order.

Key Takeaways
  • Weight tensor shape = exact transformation spec; param count = product of all dimensions.
  • Conv2d params are surprisingly small (9 K for a 7×7 filter) because weights are shared across all spatial positions — the activation map is vastly larger.
  • Attention score matrices grow as \(O(\text{seq}^2)\) — 512 tokens already takes 12.6 MB per batch per layer.
  • Embedding tables often dominate parameter count in LLMs (e.g., 38.6 M out of GPT-2's 117 M total).
  • Use sum(p.numel() for p in model.parameters()) to count all parameters in any PyTorch model.
