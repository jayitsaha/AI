Sharpness-Aware Minimization (SAM)

Find flat minima that generalize — by simultaneously seeking the worst-case perturbation within an ε-ball
Advanced Optimization Generalization 2× gradient cost
1
Understanding SAM
▼

What is it? When you train a neural network, gradient descent finds a point where the loss is low — but there are many such points. Some sit in sharp valleys: narrow pits where the loss shoots up the moment you move slightly in any direction. Others sit in flat basins: wide, gentle bowls where the loss stays low across a broad region. Sharpness-Aware Minimization (SAM) is an optimizer that deliberately steers training toward flat minima, which generalize far better to unseen data.

Analogy: Imagine two mountain valleys filled with snow. In the sharp valley, the snow only reaches the bottom of a thin crevice — miss by a metre and you're on bare rock. In the flat valley, snow covers a huge bowl — you can land anywhere in the basin and be fine. When a new test example comes in (like a slightly different landing spot), the flat valley is forgiving; the sharp valley is catastrophic. SAM finds the flat valley.

The two-step idea: At each training step, SAM (1) ascends in gradient direction by ρ to find the worst-case perturbation within an ε-ball, then (2) descends using the gradient evaluated at that perturbed point. This double-pass ensures the update direction simultaneously reduces the loss and reduces its sensitivity to weight perturbations.

💡 If you remember one thing

SAM solves $$\min_w \max_{\|\varepsilon\|\leq\rho} L(w+\varepsilon)$$ The inner max finds the worst-case perturbation; the outer min finds weights that are good even in the worst case — guaranteeing a flat minimum.

2
The Two-Step Algorithm
▼

Step 1 — Ascent: Find the Worst-Case Perturbation

At current weights \(w\), SAM solves the inner maximization problem. To first order, the loss increase from a perturbation ε is \(L(w+\varepsilon) \approx L(w) + \varepsilon^\top \nabla_w L(w)\). Maximizing this over \(\|\varepsilon\| \leq \rho\) using Cauchy-Schwarz gives the closed-form solution:

$$\hat{\varepsilon}(w) = \rho \cdot \frac{\nabla_w L(w)}{\|\nabla_w L(w)\|_2}$$

This is simply: take a step of size exactly ρ in the gradient direction. The gradient points toward the steepest ascent, so the boundary of the ρ-ball in that direction is the worst-case perturbation. One forward + backward pass computes \(\nabla_w L(w)\) and then \(\hat\varepsilon\).

Step 2 — Descent: Update Using the Perturbed Gradient

Having found \(w + \hat\varepsilon\), SAM computes a fresh gradient at the perturbed point: \(\nabla_w L(w + \hat\varepsilon)\). This is the second forward + backward pass. The weight update then uses standard SGD (or Adam) applied to this gradient:

$$w_{t+1} = w_t - \eta \cdot \nabla_w L(w_t + \hat{\varepsilon}(w_t))$$

Crucially, the update modifies \(w_t\), not \(w_t + \hat\varepsilon\). The perturbed point is used only to compute a better gradient direction — one that accounts for sharpness.

Why This Finds Flat Minima

In a sharp valley, the gradient at \(w + \hat\varepsilon\) is large (steep walls → steep gradients), so SAM's update is large and pushes weights away. In a flat basin, the gradient at \(w + \hat\varepsilon\) is small (gentle slope), so SAM's update is gentle — the optimiser stays. This creates a natural sharpness penalty without any explicit regularization term.

🔑 Key Property

SAM costs exactly 2× the gradient computation per step (two forward+backward passes), but the memory overhead is minimal — only the gradient \(\hat\varepsilon\) is stored between passes. In practice this doubles wall-clock time but consistently improves generalization by 1–3% on benchmark tasks.

⚠️ Common Misconception

SAM does not evaluate the loss at \(w + \hat\varepsilon\) — only the gradient. The weights are always updated from \(w_t\). Also, SAM is not a regularization term added to the loss; it changes the optimization trajectory, not the objective.

3
Mathematical Derivation
▼

The SAM Objective

SAM redefines what it means to find a good minimum. Instead of minimising the training loss \(L(w)\), SAM minimises the worst-case loss within an ε-ball of radius ρ:

$$\min_w \; \underbrace{\max_{\|\varepsilon\|_2 \leq \rho} L(w + \varepsilon)}_{\text{SAM objective}} \quad + \; \lambda \|w\|^2$$

Solving the Inner Maximization

The inner problem \(\max_{\|\varepsilon\| \leq \rho} L(w+\varepsilon)\) is generally hard (non-convex). SAM approximates it via a first-order Taylor expansion around \(w\):

$$L(w+\varepsilon) \approx L(w) + \varepsilon^\top \nabla_w L(w)$$

Now maximize over \(\varepsilon\) subject to \(\|\varepsilon\|_2 \leq \rho\). This is a linear program on a ball — the maximum is attained at the boundary in the gradient direction. By Cauchy-Schwarz:

$$\varepsilon^\top \nabla_w L(w) \leq \|\varepsilon\|_2 \cdot \|\nabla_w L(w)\|_2 \leq \rho \cdot \|\nabla_w L(w)\|_2$$

Equality holds when \(\varepsilon\) is parallel to \(\nabla_w L(w)\), so:

$$\hat{\varepsilon}(w) = \rho \cdot \frac{\nabla_w L(w)}{\|\nabla_w L(w)\|_2}$$

Gradient of the SAM Objective

To update \(w\), we need the gradient of \(\max_\varepsilon L(w+\varepsilon)\) with respect to \(w\). By Danskin's theorem, the gradient of the maximum with respect to the outer variable equals the gradient evaluated at the maximizer:

$$\nabla_w \left[\max_{\|\varepsilon\|\leq\rho} L(w+\varepsilon)\right] = \nabla_w L(w+\varepsilon)\big|_{\varepsilon = \hat\varepsilon(w)}$$

In practice, SAM ignores the second-order term \(\frac{\partial \hat\varepsilon}{\partial w}\) (expensive Hessian-vector product), leaving:

$$\nabla_w^{\text{SAM}} \approx \nabla_w L(w + \hat\varepsilon(w))$$

Numerical Trace (Sharp Minimum, 1-D)

Let \(L(w) = 20w^2\) (sharp), \(w = 0.8\), \(\rho = 0.5\), \(\eta = 0.01\):

  • \(\nabla_w L(w) = 40w = 40 \times 0.8 = 32\)
  • \(\|\nabla_w L(w)\| = 32\), so \(\hat\varepsilon = 0.5 \times \frac{32}{32} = +0.5\)
  • \(w + \hat\varepsilon = 0.8 + 0.5 = 1.3\)
  • \(\nabla_w L(w + \hat\varepsilon) = 40 \times 1.3 = 52\)  ← gradient at perturbed point
  • \(w' = w - \eta \times 52 = 0.8 - 0.01 \times 52 = 0.28\)

For the flat minimum \(L(w) = 1.5w^2\) at the same \(w=0.8\):

  • \(\nabla_w L(w) = 3 \times 0.8 = 2.4\), \(\hat\varepsilon = +0.5\)
  • \(\nabla_w L(w + \hat\varepsilon) = 3 \times 1.3 = 3.9\)
  • \(w' = 0.8 - 0.01 \times 3.9 = 0.761\)  ← much smaller step

The sharp minimum incurs a worst-case loss increase of \(20(1.3)^2 - 20(0.8)^2 = 21.0\); the flat minimum only \(1.5(1.3)^2 - 1.5(0.8)^2 = 1.575\) — a 13× difference. SAM's effective gradient magnitude (52 vs 3.9) naturally disfavours the sharp landscape.

📐 Generalization Bound (PAC-Bayes, Foret et al. 2021)

With high probability over training set \(S\) of size \(n\), for any perturbation radius ρ:

$$L_{\text{test}}(w) \leq \max_{\|\varepsilon\|\leq\rho} L_{\text{train}}(w+\varepsilon) + O\!\left(\sqrt{\frac{h(w,\rho)}{n}}\right)$$

where \(h(w,\rho)\) is a complexity measure that is small when the ρ-neighborhood has uniformly low loss — exactly what SAM achieves.

Variants, Trade-offs & When to Use SAM
▼

Key Variants

  • ESAM (Efficient SAM): Computes the perturbation on a random subset of parameters → ~1.2× cost instead of 2×, with comparable generalization gains.
  • LookSAM: Reuses the gradient from prior steps for the ascent, amortizing cost across iterations.
  • ASAM (Adaptive SAM): Replaces the ℓ₂-ball with an adaptive norm \(\|T^{-1}\varepsilon\|\leq\rho\) where T is a diagonal matrix of parameter scales, making ρ scale-invariant.
  • m-SAM (m-sharpness): Computes sharpness per micro-batch rather than the full batch, finding sharper sharpness estimates that correlate better with generalization.

When to Use SAM

  • Training vision models (ResNet, ViT) where generalization on small/medium datasets matters.
  • Fine-tuning large models where overfitting is a concern.
  • Scenarios where data augmentation alone is insufficient.
  • When you have budget for ~2× training time (each step requires two gradient computations).

When NOT to Use SAM

  • Compute-critical applications where 2× gradient cost is prohibitive.
  • Very large models (GPT-scale) — ESAM or other efficient variants are needed.
  • Convex problems — the sharpness penalty provides no benefit when every minimum is global.
⚠️ Hyperparameter Sensitivity

The neighbourhood radius ρ is the critical hyperparameter. Typical values: ρ=0.05 for ResNet/ImageNet, ρ=0.1 for ViT. Too large → over-regularization (underfitting); too small → no benefit over SGD. Always tune ρ via validation performance.

From-Scratch Implementation
▼

A minimal, from-scratch SAM implementation in PyTorch. Note the two-pass structure and the restore step:

import torch
import torch.nn as nn
class SAM(torch.optim.Optimizer):
"""Sharpness-Aware Minimization (Foret et al., ICLR 2021)."""
def __init__(self, params, base_optimizer, rho=0.05, **kwargs):
defaults = dict(rho=rho, **kwargs)
super().__init__(params, defaults)
self.base_optimizer = base_optimizer(self.param_groups, **kwargs)
self.param_groups = self.base_optimizer.param_groups
@torch.no_grad()
def first_step(self, zero_grad=False):
"""Ascent: perturb w → w + ε̂, storing original w."""
grad_norm = self._grad_norm() # ||∇L(w)||
for group in self.param_groups:
scale = group["rho"] / (grad_norm + 1e-12)
for p in group["params"]:
if p.grad is None: continue
# Store original weights
self.state[p]["old_p"] = p.data.clone()
# Perturb: p ← p + rho * grad / ||grad||
e_w = p.grad * scale
p.add_(e_w) # in-place perturb
if zero_grad: self.zero_grad()
@torch.no_grad()
def second_step(self, zero_grad=False):
"""Descent: restore w, then apply base optimizer update."""
for group in self.param_groups:
for p in group["params"]:
if p.grad is None: continue
p.data = self.state[p]["old_p"] # restore w
self.base_optimizer.step() # update w using ∇L(w+ε̂)
if zero_grad: self.zero_grad()
def _grad_norm(self):
norms = [p.grad.norm(2) for g in self.param_groups
for p in g["params"] if p.grad is not None]
return torch.stack(norms).norm(2)
# ── Training loop ────────────────────────────────────────────
optimizer = SAM(model.parameters(), torch.optim.SGD, rho=0.05,
lr=0.1, momentum=0.9, weight_decay=5e-4)
for x, y in loader:
# Pass 1: compute gradient at w
loss = criterion(model(x), y)
loss.backward()
optimizer.first_step(zero_grad=True) # perturb weights
# Pass 2: compute gradient at w + ε̂
criterion(model(x), y).backward()
optimizer.second_step(zero_grad=True) # restore + update
💡 Key Implementation Note

The first_step stores original weights, perturbs them, then clears gradients. The second_step restores the original weights, then applies the base optimizer using the gradients computed at the perturbed point. The data pipeline must be deterministic between passes (same batch = same data augmentation), otherwise the gradient at \(w+\hat\varepsilon\) is computed for a different mini-batch, breaking the sharpness guarantee.
