Bias-Variance Decomposition of MSE
Why every model's error splits into three unavoidable parts — and why you can't escape the tradeoff
Advanced Classical ML Model Selection Part III · Model Selection
1
Understanding the Concept

What is this? When you train a machine learning model, it makes errors. The bias-variance decomposition proves that the expected squared error of any predictor can be broken into exactly three parts: a part from being systematically wrong (bias), a part from being overly sensitive to the particular training data used (variance), and a part that is fundamentally unpredictable (irreducible noise).

Key Identity
$$\mathbb{E}\!\left[(y - \hat{f}(x))^2\right] \;=\; \underbrace{\left(\mathbb{E}[\hat{f}(x)] - f(x)\right)^2}_{\text{Bias}^2} \;+\; \underbrace{\mathbb{E}\!\left[\left(\hat{f}(x) - \mathbb{E}[\hat{f}(x)]\right)^2\right]}_{\text{Variance}} \;+\; \underbrace{\sigma^2_\varepsilon}_{\text{Irreducible Noise}}$$

Analogy. Picture a dart board. Bias is how far the average landing point is from the bullseye — systematic aim error. Variance is how spread out the darts are around that average — consistency error. Irreducible noise is the wobble in the air you can never control, no matter how skilled you are.

💡 If You Remember One Thing

A high-capacity model (deep polynomial, deep net) drives bias toward zero but explodes variance. A low-capacity model (constant, linear) has high bias but low variance. Optimal model complexity lives in the U-shaped valley where bias² + variance is minimised. Irreducible noise is the floor you cannot cross.

2
The Full Derivation (No Steps Skipped)

The true data-generating process is \(y = f(x) + \varepsilon\) where \(\varepsilon \sim \mathcal{N}(0,\sigma^2_\varepsilon)\) and \(f(x)\) is the unknowable true function. We train predictor \(\hat{f}\) on a dataset \(\mathcal{D}\) drawn from the joint distribution. The expectation below is over both \(\mathcal{D}\) and \(\varepsilon\).

Step-by-step algebraic proof

Step 1. Expand MSE by adding and subtracting \(\mathbb{E}_\mathcal{D}[\hat{f}(x)]\) inside the square:

$$\text{MSE} = \mathbb{E}\!\left[\left(y - \hat{f}(x)\right)^2\right] = \mathbb{E}\!\left[\left(f(x)+\varepsilon - \hat{f}(x)\right)^2\right]$$

Step 2. Let \(\bar{f} = \mathbb{E}_\mathcal{D}[\hat{f}(x)]\). Add and subtract \(\bar{f}\):

$$= \mathbb{E}\!\left[\left((f(x) - \bar{f}) + (\bar{f} - \hat{f}(x)) + \varepsilon\right)^2\right]$$

Step 3. Expand the square. Cross terms involving \(\varepsilon\) vanish because \(\mathbb{E}[\varepsilon]=0\) and noise is independent of \(\hat{f}\). The cross term \((f(x)-\bar{f})(\bar{f}-\hat{f}(x))\) vanishes because \(f(x)-\bar{f}\) is a constant w.r.t. \(\mathcal{D}\) expectation and \(\mathbb{E}_\mathcal{D}[\bar{f}-\hat{f}(x)]=0\) by definition of \(\bar{f}\).

Step 4. What remains:

$$\text{MSE} = \underbrace{(f(x)-\bar{f})^2}_{\text{Bias}^2} \;+\; \underbrace{\mathbb{E}_\mathcal{D}\!\left[(\hat{f}(x)-\bar{f})^2\right]}_{\text{Variance}} \;+\; \underbrace{\sigma^2_\varepsilon}_{\text{Irreducible}}$$
⚠️ Common Misconception

The decomposition holds for any fixed test point \(x\) — not across test points. Bias and variance are both functions of \(x\). "Total bias²" and "total variance" are averages of these over the input distribution \(p(x)\).

Numerical trace at a single point

True function: \(f(x_0)=3.0\), noise: \(\sigma_\varepsilon=0.5\). Trained on five dataset draws, predictions are: 2.1, 2.4, 2.2, 2.8, 2.5.

  • \(\bar{f}(x_0) = (2.1+2.4+2.2+2.8+2.5)/5 = 2.4\)
  • Bias² \(= (3.0-2.4)^2 = 0.36\)
  • Variance \(= \frac{1}{5}\sum(\hat{f}_i - 2.4)^2 = \frac{(0.09+0+0.04+0.16+0.01)}{5} = 0.06\)
  • Irreducible noise \(= \sigma^2_\varepsilon = 0.25\)
  • Expected MSE \(= 0.36 + 0.06 + 0.25 = 0.67\)
3
Model Complexity & the U-Shaped Tradeoff

As model complexity (polynomial degree, tree depth, network width…) increases:

  • Bias² decreases monotonically — a richer model can approximate \(f(x)\) more closely.
  • Variance increases — a richer model is more sensitive to which training points happen to appear; slight data changes cause large prediction swings.
  • Irreducible noise stays constant — it is a property of the data, not the model.

Total expected test error = bias² + variance + \(\sigma^2_\varepsilon\) traces out a U-shape as a function of complexity. The optimal point is the minimum of that U-curve — neither underfitting nor overfitting.

📐 Practical Rates (Polynomial Regression)

For degree-\(d\) polynomial fit to \(n\) samples: Bias² \(\propto d^{-2s}\) (where \(s\) = smoothness of \(f\)), Variance \(\propto d/n\). Optimal degree balances the two: \(d^* \propto n^{1/(2s+1)}\). This is the classic bias-variance optimal bandwidth / complexity rate from non-parametric statistics.

Regularisation interpretation

Ridge regression adds \(\lambda\|\beta\|^2\) to the loss, which shrinks coefficients — this intentionally increases bias but can dramatically reduce variance, often lowering total MSE. The optimal \(\lambda\) is chosen by cross-validation, which implicitly optimises the bias-variance tradeoff.

From-Scratch NumPy Implementation

The code below empirically estimates bias², variance, and irreducible noise for polynomial regression of varying degree.

# Bias-variance decomposition via Monte Carlo simulation
import numpy as np

# True function + noise parameters
def f_true(x): return np.sin(2 * np.pi * x)   # unknowable ground truth
SIGMA = 0.3        # std of irreducible noise ε ~ N(0, σ²)
N_TRAIN = 20       # training set size
N_TRIALS = 500     # number of dataset draws (D_1, D_2, ..., D_500)
X_TEST = np.linspace(0, 1, 100)  # fixed test points

def generate_data(n):
    x = np.random.uniform(0, 1, n)
    y = f_true(x) + np.random.normal(0, SIGMA, n)  # y = f(x) + ε
    return x, y

def fit_predict(x_train, y_train, degree, x_test):
    """Fit degree-d polynomial, return predictions at x_test."""
    coefs = np.polyfit(x_train, y_train, degree)  # least squares
    return np.polyval(coefs, x_test)

def bias_variance_decomposition(degree, n_trials=N_TRIALS):
    preds = np.zeros((n_trials, len(X_TEST)))

    for t in range(n_trials):
        x_tr, y_tr = generate_data(N_TRAIN)
        preds[t] = fit_predict(x_tr, y_tr, degree, X_TEST)

    f_bar = np.mean(preds, axis=0)          # E_D[f_hat(x)] per test point
    bias_sq = np.mean((f_bar - f_true(X_TEST))**2)   # avg over x
    variance  = np.mean(np.var(preds, axis=0))         # avg over x
    irreducible = SIGMA**2                             # σ²_ε, constant
    total = bias_sq + variance + irreducible
    return bias_sq, variance, irreducible, total

# Run for degrees 0..12
degrees = list(range(13))
results = [bias_variance_decomposition(d) for d in degrees]
bias_sq, variance, noise, total = zip(*results)

# Output for degree 5 (often near-optimal here):
# Bias²=0.011  Variance=0.032  Noise=0.09  Total≈0.133

Key Takeaways & When to Apply
RegimeSymptomFix
High Bias (underfitting)Train ≈ Test error, both highIncrease capacity, add features, reduce regularisation
High Variance (overfitting)Train ≪ Test errorMore data, regularise, ensemble, reduce features
Irreducible noise floorTest error stalls even with perfect modelBetter data (cleaner labels, higher signal/noise ratio)
💡 Connection to Cross-Validation

K-fold CV estimates total expected test error (bias²+variance+noise). Hyperparameter search via CV implicitly navigates the U-curve to find the complexity sweet spot. It does NOT separate bias from variance — you need repeated train/test splits for that (bootstrap bias-variance estimators).
