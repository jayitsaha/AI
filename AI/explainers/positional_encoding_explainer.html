Sinusoidal, learned, relative (RPE), and RoPE — how transformers know word order
Foundational Transformers NLP O(1) per position
1
Understanding Positional Encoding
▼

What is it? Self-attention computes each output as a weighted sum of value vectors, where the weights come from dot products between queries and keys. That computation is permutation-invariant: if you shuffle the input tokens (and shuffle the outputs to match), attention produces exactly the same set of results. Nothing in the raw mechanism tells the model that "dog bites man" differs from "man bites dog." Positional encoding is the extra signal injected into (or applied to) the token representations so the model can tell tokens apart by their position in the sequence.

Analogy: Imagine dumping a recipe's ingredients on a counter with no step numbers — flour, eggs, oven, whisk — attention can relate any item to any other, but has no idea what came first. Positional encoding is like stamping each ingredient with a step number: "1. flour, 2. eggs, 3. whisk, 4. oven." Now the same set of items carries an order.

💡 If you remember one thing

Attention is a set operation over tokens — order-blind by default. Every positional encoding scheme is just a different way of telling \(\text{Attention}(Q,K,V)\) which token came before which, either by editing the embeddings (sinusoidal, learned), by editing the attention score directly (relative PE), or by editing the query/key vectors themselves as a function of position (RoPE).

2
How It Works Internally
▼

1. Sinusoidal PE (Vaswani et al., 2017 — the original Transformer)

For position \(pos\) and channel index \(i\), a fixed vector of sines and cosines at geometrically decreasing frequencies is added to the token embedding: \(x_{pos} = e_{pos} + PE_{pos}\). Even channels use \(\sin\), odd channels use \(\cos\), and the wavelengths form a geometric progression from \(2\pi\) up to \(10000\cdot2\pi\). Low-index channels oscillate fast (encode fine-grained local position); high-index channels oscillate slowly (encode coarse, long-range position) — together the vector acts like a "positional fingerprint" that's unique-ish per position and never needs training.

2. Learned Absolute PE (BERT, GPT-2/3)

Instead of a formula, allocate a trainable embedding table of shape \([\text{max\_len}, d_{model}]\) and add row \(pos\) to token \(pos\)'s embedding — exactly like a word-embedding lookup, but indexed by position instead of vocabulary id. The model learns whatever positional structure is useful from data. Simpler to implement, but capped at \(\text{max\_len}\): the model has literally never seen position 600 if it trained on \(\text{max\_len}=512\), so it cannot extrapolate to longer sequences.

3. Relative PE / RPE (Shaw et al. 2018; Transformer-XL; T5)

Instead of encoding "where am I in absolute terms," inject "how far apart are token \(i\) and token \(j\)" directly into the attention computation — typically as a learned bias added to the raw \(QK^\top\) logits, indexed by the clipped offset \(i-j\) (T5 buckets distances into ranges). No positional vector is ever added to the embeddings; position only ever appears as a pairwise offset. This generalizes better to unseen lengths because "5 tokens back" means the same thing at position 10 or position 10,000.

4. Rotary Position Embedding — RoPE (Su et al., 2021)

RoPE encodes position by rotating the query and key vectors rather than adding anything. Split \(q\) and \(k\) into 2D pairs of channels; rotate the pair belonging to position \(m\) by angle \(m\theta\) using a standard 2D rotation matrix. Because rotating \(q\) by \(m\theta\) and \(k\) by \(n\theta\) and then taking their dot product leaves only the angle difference \((n-m)\theta\) in the result, the attention score becomes a function of the relative position \(n-m\) automatically — with no extra parameters and no lookup table. This is why RoPE dominates modern LLMs (LLaMA, GPT-NeoX, PaLM, Mistral, Qwen).

🔑 Key Property

Rotation matrices compose by subtracting angles: \(R(m\theta)^\top R(n\theta) = R((n-m)\theta)\). That single fact is why RoPE's dot product depends only on \(n-m\), never on \(m\) and \(n\) individually — relative position "falls out" of ordinary trigonometry, with no learned relative-position table required.

3
Why It Works — The Math
▼

Sinusoidal PE — the formula

$$PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right) \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

where \(i \in \{0,\dots,d_{model}/2-1\}\) indexes the frequency pair. Define \(\theta_i = 10000^{-2i/d_{model}}\); channel pair \(i\) rotates at angular frequency \(\theta_i\).

Sinusoidal PE encodes relative offsets linearly

Using the angle-addition identities \(\sin(a+b)=\sin a\cos b+\cos a\sin b\) and \(\cos(a+b)=\cos a\cos b-\sin a\sin b\), for any fixed offset \(k\):

$$\begin{bmatrix}PE_{(pos+k,2i)}\\PE_{(pos+k,2i+1)}\end{bmatrix} = \begin{bmatrix}\cos(k\theta_i) & \sin(k\theta_i)\\-\sin(k\theta_i) & \cos(k\theta_i)\end{bmatrix}\begin{bmatrix}PE_{(pos,2i)}\\PE_{(pos,2i+1)}\end{bmatrix}$$

\(PE_{pos+k}\) is a fixed linear transform of \(PE_{pos}\), independent of \(pos\) itself — in principle this lets a linear layer learn to attend by relative offset even though the encodings were built from absolute positions.

RoPE — rotating instead of adding

For a 2D channel pair, define the rotation matrix \(R(\phi) = \begin{bmatrix}\cos\phi & -\sin\phi\\ \sin\phi & \cos\phi\end{bmatrix}\). RoPE applies \(f_q(x_m, m) = R(m\theta)\,W_q x_m\) at position \(m\) and \(f_k(x_n, n) = R(n\theta)\,W_k x_n\) at position \(n\). The attention logit is their dot product:

$$\langle f_q(x_m,m),\, f_k(x_n,n)\rangle = (W_qx_m)^\top R(m\theta)^\top R(n\theta)\,(W_kx_n) = (W_qx_m)^\top R\big((n-m)\theta\big)\,(W_kx_n)$$

using the rotation-composition identity \(R(m\theta)^\top R(n\theta) = R((n-m)\theta)\) (rotating "back" by \(m\theta\) then forward by \(n\theta\) nets a rotation of \((n-m)\theta\)). The score depends only on content (\(x_m,x_n\)) and the relative distance \(n-m\) — never on absolute \(m\) or \(n\).

⚠️ Common Misconception

"RoPE adds a positional vector like sinusoidal PE." It does not — RoPE never touches the embedding. It multiplies \(q\) and \(k\) by position-dependent rotation matrices at attention time, after the \(W_q, W_k\) projections. That multiplicative structure (vs. additive) is exactly what makes the relative-position identity above hold.

💡 Decision Rule

Building a modern long-context LLM today → use RoPE (multiplicative, relative, extrapolation-friendly, cheap). Need a quick, simple baseline or fixed short context → sinusoidal or learned absolute are fine. Need explicit control over how far tokens can "see" each other (e.g. long documents, translation) → relative PE gives the most direct handle on distance.

Code Trace — Sinusoidal PE & RoPE from Scratch
▼
import numpy as np
# ---- Sinusoidal PE (Vaswani et al. 2017) ----
def sinusoidal_pe(seq_len, d_model, base=10000.0):
pos = np.arange(seq_len)[:, None] # (seq_len, 1)
i = np.arange(d_model // 2)[None, :] # (1, d_model/2)
theta = 1.0 / base ** (2 * i / d_model) # geometric frequencies
angles = pos * theta # (seq_len, d_model/2)
pe = np.zeros((seq_len, d_model))
pe[:, 0::2] = np.sin(angles) # even channels
pe[:, 1::2] = np.cos(angles) # odd channels
return pe
# ---- RoPE (Su et al. 2021) ----
def rotate_half(x):
x1, x2 = x[..., 0::2], x[..., 1::2]
return np.stack([-x2, x1], axis=-1).reshape(x.shape)
def apply_rope(x, pos, base=10000.0):
d = x.shape[-1]
i = np.arange(d // 2)
theta = 1.0 / base ** (2 * i / d)
angles = pos * theta # angle per channel pair
cos = np.repeat(np.cos(angles), 2)
sin = np.repeat(np.sin(angles), 2)
return x * cos + rotate_half(x) * sin # 2D rotation per pair
# q at position m, k at position n -> score depends only on (n - m)
q_rot = apply_rope(q, m)
k_rot = apply_rope(k, n)
score = q_rot @ k_rot # f(content, n - m) only
