Understanding Fine-Tuning
▼

What is it? BERT is pretrained once on enormous unlabeled text (masked-language-modeling + next-sentence prediction) to learn general-purpose language representations. Fine-tuning takes that pretrained encoder, bolts a small new "head" onto it, and continues training — this time on a small labeled dataset for a specific job like sentiment classification, named-entity recognition, or question answering.

Analogy: Think of pretraining as sending someone through years of general schooling — they learn grammar, facts, reasoning. Fine-tuning is a focused week of on-the-job training for one specific role. You don't re-teach them the alphabet; you just adjust their existing knowledge slightly and add a small new skill (the task head) on top.

💡 If you remember one thing

Fine-tuning reuses ALL of BERT's pretrained weights as initialization, adds a small randomly-initialized task-specific head, and updates everything jointly with a tiny learning rate — so the general language knowledge is preserved while a task-specific decision boundary is learned: $$\theta^* = \underset{\theta = (\theta_{BERT}, \theta_{head})}{\operatorname{argmin}} \; \mathbb{E}_{(x,y)\sim \mathcal{D}_{task}}\big[\mathcal{L}(f_\theta(x), y)\big]$$

How Fine-Tuning Works Internally
▼

Step 1 — Tokenize & Attach the Head

The raw input is split into WordPiece tokens, wrapped with \([CLS]\) and \([SEP]\), converted to IDs, and summed with position and segment embeddings. A new head — e.g. a single linear layer \(W_{head} \in \mathbb{R}^{C \times H}\) for classification — is attached to the pooled \([CLS]\) representation. This head starts from random weights; everything else starts from the pretrained checkpoint.

Step 2 — Forward Pass Through Frozen-ish Encoder Layers

Each of BERT's \(L\) transformer blocks runs multi-head self-attention (tokens attend to each other, building contextual meaning) followed by a feed-forward sublayer, each wrapped in a residual connection + LayerNorm. Unlike training from scratch, these layers already encode syntax and semantics — fine-tuning only needs to nudge them toward the new task.

Step 3 — Task Head, Loss, and Discriminative Learning Rates

The final \([CLS]\) vector \(h_{CLS}^{(L)}\) is passed through the head to get logits, then a softmax + cross-entropy loss compares predictions to the true label. Gradients flow backward through the whole stack. Critically, most practitioners use layer-wise (discriminative) learning rates: the new head gets the full learning rate, while each encoder layer going deeper (further from the output) gets a progressively smaller one, \(lr_\ell = lr_{top}\cdot \xi^{(L-\ell)}\) for decay \(\xi < 1\) — because lower layers already encode general-purpose features that should barely move.

🔑 Key Property

Fine-tuning is not training a new model — it is a small, low-magnitude perturbation of an already-good parameter initialization. The pretrained weights place \(\theta_0\) near a good basin; fine-tuning with a tiny learning rate (typically \(1\text{e-}5\) to \(5\text{e-}5\)) and few epochs (2–4) just walks a short distance within that basin toward the task-specific optimum.

Design Decision: Full Fine-Tuning vs. Feature Extraction vs. PEFT

You could instead freeze BERT entirely and only train the head ("feature extraction") — faster and cheaper, but strictly less accurate since the representations can't adapt. Full fine-tuning updates every parameter for best accuracy at the cost of storing a full copy of BERT per task. Parameter-efficient methods (LoRA, adapters, prompt-tuning) sit in between: freeze BERT, inject a small number of trainable parameters, and get near-full-fine-tuning accuracy at a fraction of the storage/compute cost.

Why It Works — The Math
▼

Forward Pass, Layer by Layer

For token embeddings \(X^{(0)} \in \mathbb{R}^{n\times H}\), each encoder layer \(\ell\) computes self-attention with query/key/value projections \(Q=X^{(\ell-1)}W_Q,\;K=X^{(\ell-1)}W_K,\;V=X^{(\ell-1)}W_V\):

$$\text{Attn}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V,\qquad X^{(\ell)} = \text{LN}\big(X^{(\ell-1)} + \text{Attn}(Q,K,V)\big)$$

followed by a position-wise feed-forward sublayer with residual connection: \(X^{(\ell)} = \text{LN}\big(X^{(\ell)} + \text{FFN}(X^{(\ell)})\big)\). After \(L\) layers, the pooled \([CLS]\) vector \(h = X^{(L)}_{[CLS]}\) feeds the task head: \(z = W_{head}\,h + b_{head}\), \(\hat{p} = \text{softmax}(z)\).

The Fine-Tuning Objective and Its Gradient

Cross-entropy loss for a true class \(y\):

$$\mathcal{L} = -\log \hat{p}_y = -\log\frac{e^{z_y}}{\sum_c e^{z_c}}$$

The gradient at the logits has the clean form \(\frac{\partial \mathcal{L}}{\partial z} = \hat{p} - \mathbf{1}_y\) (predicted probabilities minus the one-hot label). This backpropagates through the head into \(h\), then through every encoder layer via the chain rule, each layer's Jacobian multiplying in — this is exactly standard backprop, just starting from an already-informative \(\theta_0\) instead of random noise.

Discriminative Learning Rate Update Rule

$$\theta_\ell \leftarrow \theta_\ell - lr_\ell \cdot \nabla_{\theta_\ell}\mathcal{L}, \qquad lr_\ell = lr_{top}\cdot \xi^{\,(L-\ell)}$$

With \(\xi \approx 0.8\)–\(0.95\), layer \(L\) (closest to the head) trains at the full rate while layer \(1\) trains at a much smaller effective rate — this is a first-order approximation to "only adapt what needs adapting," and empirically reduces catastrophic forgetting of pretrained knowledge.

⚠️ Common Pitfall

Using the same learning rate you'd use for training from scratch (e.g. \(1\text{e-}3\)) destroys the pretrained weights within a few steps — this is called catastrophic forgetting. Fine-tuning learning rates are typically 10–100× smaller than pretraining rates, and warmup + linear decay schedules are used to avoid early large, destructive updates.

Key Takeaways
▼

When to fine-tune BERT (fully):

  • You have a labeled dataset of at least a few hundred to a few thousand examples
  • The task is close to BERT's pretraining distribution (natural language, not code/DNA/etc.)
  • You can afford to store/serve one full model copy per task
  • Maximum accuracy matters more than training/storage cost

When NOT to fully fine-tune:

  • Extremely small datasets (<100 examples) — prefer feature extraction or few-shot prompting a larger LLM
  • Many tasks sharing one deployed model — prefer LoRA/adapters (one small delta per task, one shared backbone)
  • Very limited compute/memory — full fine-tuning needs gradients + optimizer states for ~110M+ parameters
💡 Hierarchy

Feature extraction (freeze BERT, train head only) ⊂ Full fine-tuning (train everything, small LR) ⊂ Parameter-efficient fine-tuning (LoRA/adapters: freeze BERT, train a few new low-rank parameters). Each trades off adaptability against compute/storage cost differently — full fine-tuning maximizes accuracy, PEFT maximizes efficiency.

Code Trace
▼
from transformers import BertTokenizer, BertForSequenceClassification
from torch.optim import AdamW
# 1. Load pretrained weights + attach a NEW classification head
tok = BertTokenizer.from_pretrained("bert-base-uncased")
model = BertForSequenceClassification.from_pretrained(
"bert-base-uncased", num_labels=2) # head is randomly init'd
# 2. Tokenize with [CLS]/[SEP], build batch
batch = tok(["this movie was great"], return_tensors="pt", padding=True)
labels = torch.tensor([1]) # 1 = positive
# 3. Discriminative learning rates: head >> top layers >> bottom layers
def llrd_param_groups(model, lr_top=5e-5, decay=0.8):
groups, layers = [], model.bert.encoder.layer
groups.append({"params": model.classifier.parameters(), "lr": lr_top})
for i, layer in enumerate(reversed(layers)):
groups.append({"params": layer.parameters(), "lr": lr_top * decay**i})
return groups
optimizer = AdamW(llrd_param_groups(model))
# 4. Forward + loss + backward + step
out = model(**batch, labels=labels) # cross-entropy computed internally
out.loss.backward()
optimizer.step()
optimizer.zero_grad()
print(f"loss: {out.loss.item():.4f}")
