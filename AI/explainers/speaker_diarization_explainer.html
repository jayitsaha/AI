Understanding Speaker Diarization
▼

What is it? Speaker diarization answers the question "who spoke when?" in an audio recording, without necessarily knowing what was said or who the speakers are by name. It partitions a recording's timeline into segments and labels each with an anonymous speaker identity (Speaker 1, Speaker 2, ...), including moments where two people talk over each other.

Analogy: Imagine muting a meeting recording's words but keeping a colored highlighter mark over the timeline every time a different voice takes over — blue for one voice, green for another. Diarization is an algorithm that draws those highlighter marks automatically, purely from acoustic voice characteristics (pitch, timbre, cadence), not content.

There are two dominant families of approach, both explored interactively below: clustering-based pipelines (Voice Activity Detection → segmentation → speaker embeddings → clustering) which are modular and mature but assume one speaker per instant, and EEND (End-to-End Neural Diarization) which treats diarization as a single multi-label sequence-tagging network that natively predicts overlapping speech.

💡 If you remember one thing

Clustering-based diarization is discriminative in embedding space: it turns audio chunks into fixed-length speaker-embedding vectors (x-vectors/d-vectors) and groups similar ones. EEND is discriminative in time: it directly outputs, for every frame and every speaker slot, a probability "is speaker \(s\) active at time \(t\)?" — which is what lets it handle overlap.

How It Works Internally
▼

The Clustering-Based Pipeline

1. Voice Activity Detection (VAD) finds which regions of the waveform contain speech at all (vs. silence/noise). 2. Segmentation chops the detected speech into short, roughly uniform windows (~1–2s), since speaker embeddings are most reliable on short, single-speaker chunks. 3. Embedding extraction runs a pretrained network (a d-vector LSTM or an x-vector/ECAPA-TDNN) over each window to produce a fixed-length vector that encodes voice identity, largely invariant to what was said. 4. Clustering — Agglomerative Hierarchical Clustering (AHC) or spectral clustering — groups the embeddings into \(k\) speaker clusters, where \(k\) may be known or estimated (e.g. via eigengap on the affinity matrix). 5. The cluster label of each window is painted back onto the timeline to reconstruct "who spoke when."

Why AHC specifically?

AHC starts with every window as its own singleton cluster and greedily merges the two closest clusters, using a linkage rule (single/average/complete) to define cluster-to-cluster distance, until only \(k\) clusters remain (or a distance threshold is crossed). It needs no initial guess of \(k\) or cluster centers (unlike k-means), and produces a full dendrogram, so you can inspect merges at any granularity — useful because the "true" number of speakers is often unknown in real audio.

The EEND Alternative

EEND (Fujita et al., 2019) reframes diarization as multi-label frame classification: a shared encoder (BLSTM, self-attention, or Conformer) reads the raw acoustic features once and outputs, per frame, one activity probability per speaker slot via independent sigmoids — not a softmax — so multiple slots can be "active" simultaneously, natively modeling overlapping speech. Because speaker identity has no canonical order, training uses Permutation-Invariant Training (PIT): the loss is computed against every possible assignment of ground-truth speakers to output slots, and the cheapest permutation is backpropagated.

🔑 Key Design Decision

Clustering pipelines are modular (swap VAD, embedding extractor, or clustering algorithm independently) and scale gracefully to long recordings, but structurally cannot assign two speakers to one instant. EEND is a single trainable network that handles overlap for free, but its output speaker-count is bounded by the number of output slots the network was built/trained for (extensions like EEND-EDA relax this).

3
Why It Works — The Math
▼

Average-Linkage Distance (AHC)

Given clusters \(C_i, C_j\) of speaker embeddings, average linkage defines their distance as the mean pairwise distance between members:

$$d(C_i, C_j) = \frac{1}{|C_i||C_j|}\sum_{x \in C_i}\sum_{y \in C_j} \|x - y\|_2 \quad\text{(or } 1-\cos(x,y)\text{ for cosine embeddings)}$$

After a merge, the Lance–Williams recurrence updates distances to the new cluster without recomputing from scratch:

$$d(C_i \cup C_j, C_k) = \frac{|C_i|}{|C_i|+|C_j|}\,d(C_i,C_k) \;+\; \frac{|C_j|}{|C_i|+|C_j|}\,d(C_j,C_k)$$

Permutation-Invariant Training (EEND)

For \(T\) frames and \(S\) speaker slots, with reference labels \(y \in \{0,1\}^{T\times S}\) and predicted probabilities \(\hat y\), PIT minimizes binary cross-entropy over the best label-to-slot assignment \(\phi\):

$$\mathcal{L}_{PIT} = \min_{\phi \in \operatorname{Perm}(S)} \frac{1}{TS}\sum_{t=1}^{T}\sum_{s=1}^{S} \operatorname{BCE}\big(y_{t,\phi(s)},\, \hat y_{t,s}\big)$$

This is exactly why the clustering pipeline in the walkthrough below must run a matching permutation search itself, when scoring against ground truth — cluster IDs are arbitrary labels, so evaluation must find the optimal one-to-one mapping to reference speakers before counting errors.

Diarization Error Rate (DER)

DER is the standard metric, decomposed per short time frame into missed speech, false alarm, and speaker confusion, normalized by total reference speaker-time (which double-counts overlapped speech, since two speakers are simultaneously "correct" there):

$$\text{DER} = \frac{\text{False Alarm} + \text{Missed Speech} + \text{Speaker Confusion}}{\text{Total reference speaker-time}}$$

Per frame \(t\), with \(N_{ref}(t)\) and \(N_{hyp}(t)\) speakers active in reference/hypothesis and \(N_{correct}(t)\) the size of their optimal-permutation intersection:

$$\text{Miss}(t)=\max(0, N_{ref}\!-\!N_{hyp}) \quad \text{FA}(t)=\max(0, N_{hyp}\!-\!N_{ref}) \quad \text{Conf}(t)=\min(N_{ref},N_{hyp})-N_{correct}$$
⚠️ Common Pitfall

A clustering-based system with perfect clustering can still have a nonzero DER floor, because it structurally outputs at most one speaker label per window — any true overlapping speech is guaranteed "missed" for the silent-on-paper speaker. This is not a clustering failure; it is an architectural ceiling that only overlap-aware models like EEND (or overlap-detection add-ons) can lift.

Key Takeaways
▼

When to use clustering-based diarization:

  • Long recordings (calls, meetings, broadcasts) where a modular, swappable pipeline is valuable
  • Number of speakers is unknown — AHC's dendrogram lets you cut at any \(k\), or estimate it
  • Overlap is rare or tolerable in the application (e.g. rough call analytics)

When to use EEND / overlap-aware neural diarization:

  • Natural, spontaneous conversation with frequent overlapping speech (meetings, interviews)
  • You can train (or fine-tune) on domain-matched, labeled multi-speaker audio
  • You need a single differentiable model integrable end-to-end with other neural components
💡 The Modern Hybrid

Production systems increasingly combine both: EEND-vector-clustering (EEND-VC) runs a local EEND on short chunks to natively resolve overlaps, then uses clustering across chunks (exactly like the pipeline above) to scale speaker identity consistently to arbitrarily long recordings — getting overlap-awareness and unbounded speaker counts.

Z = linkage(embeddings, method="average", metric="cosine")
labels = fcluster(Z, t=k_speakers, criterion="maxclust")
# 5. Paint labels back onto the timeline
hypothesis = [(w.start, w.end, labels[i]) for i, w in enumerate(windows)]
# --- EEND: single forward pass, multi-label sigmoid per speaker ---
probs = eend_model(waveform) # shape (T, S), independent sigmoids
active = probs > 0.5 # multiple speakers can be True at once
# --- Scoring: permutation-invariant DER ---
def der(ref, hyp, dt=0.01):
miss = fa = conf = ref_time = 0.0
for t in frames(dt):
r, h = active_speakers(ref, t), active_speakers(hyp, t)
correct = best_permutation_overlap(r, h)
miss += max(0, len(r) - len(h)) * dt
fa += max(0, len(h) - len(r)) * dt
conf += (min(len(r), len(h)) - correct) * dt
ref_time += len(r) * dt
return (miss + fa + conf) / ref_time
