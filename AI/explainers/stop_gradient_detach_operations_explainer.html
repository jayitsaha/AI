Stop-Gradient / .detach()

Treating a tensor as a constant during backpropagation
Intermediate Deep Learning Autograd O(1) graph edit
1
Understanding Stop-Gradient
▼

What is it? Every tensor produced by a differentiable operation remembers how it was computed, so backpropagation can walk backwards through that history and compute gradients. .detach() (a.k.a. stop_gradient in JAX/TensorFlow) severs that memory: it returns a new tensor with the same values, but with no link back to the graph that produced it. The forward computation still uses the value normally — only the backward pass treats it as a constant, so gradients flowing backward simply stop there and never reach whatever created it.

Analogy: Imagine a relay race where each runner (operation) hands off a baton (tensor) and also a walkie-talkie so instructions can be shouted back to earlier runners ("run faster!" = gradient signal). .detach() is handing off just the baton and cutting the walkie-talkie wire. The next runner still gets a perfectly good baton to keep racing forward — but no instruction ever reaches the runners before the cut.

💡 If you remember one thing

.detach() changes nothing about the forward values — it only prunes an edge in the autograd graph, so \(\frac{\partial L}{\partial (\text{detached input})}\) is never computed for what's upstream of it. It's a graph-surgery operation, not a numerical one.

2
How It Works Internally
▼

Autograd as a DAG

Frameworks like PyTorch build a directed acyclic graph (DAG) dynamically during the forward pass. Every non-leaf tensor stores a grad_fn pointing to the operation that created it and its input tensors. Calling .backward() on a scalar loss traverses this DAG in reverse topological order, applying the chain rule at every node: \(\bar{x} = \bar{y}\cdot \frac{\partial y}{\partial x}\), where \(\bar{v}\) denotes \(\partial L/\partial v\).

What .detach() actually does

Given \(y = f(x)\), y_d = y.detach() creates a new tensor sharing the exact same underlying storage as y, but with requires_grad=False and grad_fn=None. It behaves as a graph leaf — as far as autograd is concerned, y_d "fell from the sky" with no history. Anything computed downstream from y_d can still require gradients (e.g., if it's combined with another tensor that does), but the chain rule simply has no path back through y_d into x.

Design decision: why a graph cut, not a zero gradient?

An alternative would be to let gradients flow but multiply them by zero at that node — this is exactly what the common straight-through trick does NOT do; instead frameworks give you an explicit, cheap, allocation-free graph edit. Cutting the graph is O(1) (just drop a pointer) and composes safely: a detached tensor can be reattached to a fresh differentiable computation, mixed with gradient-carrying tensors, or fed into entirely separate optimizers — none of which a "multiply by zero" gradient hook could do as cleanly, since that still walks (and pays for) the pruned subgraph.

🔑 Key Property

Detach is identity in the forward pass, zero (absent) in the backward pass: \(y_d = y\) numerically, but \(\frac{\partial y_d}{\partial x} \) is undefined/never traversed — it is as if \(y_d\) were an independent constant, not a function of \(x\).

3
Why It Works — The Math
▼

Formalizing stop-gradient

Define the stop-gradient operator \(\operatorname{sg}[\cdot]\) mathematically as the identity function whose Jacobian is defined to be the zero operator, regardless of what's inside:

$$\operatorname{sg}[x] \triangleq x \qquad \text{but} \qquad \frac{\partial\, \operatorname{sg}[x]}{\partial x} \triangleq 0$$

This is not a mathematical identity in the usual calculus sense (it violates \(\frac{d}{dx}x = 1\)) — it's a programming-language primitive injected into the chain rule. For a composed loss \(L = h(\operatorname{sg}[g(x)])\), ordinary chain rule would give \(\frac{\partial L}{\partial x} = h'(\cdot) g'(x)\), but with stop-gradient:

$$\frac{\partial L}{\partial x} = h'(\cdot)\cdot \frac{\partial\, \operatorname{sg}[g(x)]}{\partial x} = h'(\cdot) \cdot 0 = 0$$

The straight-through estimator (STE)

A clever use of this rule lets you get a custom backward function for a non-differentiable forward op like rounding. Define:

$$x_{hard} = x + \operatorname{sg}[\,\operatorname{round}(x) - x\,]$$

Forward value: \(x_{hard} = x + (\operatorname{round}(x)-x) = \operatorname{round}(x)\) exactly. Backward: since the second term's gradient is forced to 0, \(\frac{\partial x_{hard}}{\partial x} = 1 + 0 = 1\) — gradients pass through as if rounding were the identity function, even though the forward pass truly rounded.

⚠️ Common Misconception

".detach() makes a tensor a leaf, so it stops gradients from flowing into it." Correct — but people often forget it also stops gradients from flowing through it to everything upstream. If a feeds both a detached branch and a differentiable branch, only the differentiable branch contributes to \(\partial L/\partial a\); the detached branch contributes exactly zero, not "half credit."

Key Takeaways
▼

When to reach for .detach() / stop-gradient:

  • Target networks (DQN, DDPG, SAC): freeze the bootstrapped TD target so the network isn't chasing a moving, gradient-coupled target — stabilizes training.
  • EMA teacher / self-distillation (BYOL, SimSiam, DINO, mean-teacher): stop-gradient on the teacher branch is what prevents representational collapse — the asymmetry is the whole trick, not an optimization detail.
  • VAE reparameterization contrast: the noise sample \(\epsilon\) itself is a non-differentiable constant (implicitly "detached") — reparameterization exists precisely to route gradients around a sampling step you can't differentiate through.
  • Straight-through estimators: quantization, VQ-VAE codebook lookup, binary/discrete activations — forward is hard/discrete, backward pretends it was the identity.
  • GAN discriminator updates: detach the generator's fake batch before feeding it to D, so D's loss doesn't needlessly build/traverse a graph back into G.
  • Feature extraction / frozen backbones: detach (or requires_grad=False) a pretrained encoder to save memory and compute when only fine-tuning a head.

When NOT to use it: if you actually want gradient signal to reach earlier layers (e.g., end-to-end fine-tuning), detaching there silently zeroes those gradients — a notoriously quiet bug, since the forward pass looks completely normal and loss still decreases (just not the way you think).

💡 Mental Model

.detach() doesn't change what is computed — only who is blamed for the loss. It reroutes credit assignment, which is exactly why it's the tool of choice whenever you want one branch of a computation to act as a fixed, ground-truth-like reference for another.

import torch, torch.nn.functional as F
# ── 1. Plain graph, no detach ──
x = torch.tensor(2.0, requires_grad=True)
a = x ** 2 # a = 4.0
b = 3 * a # b = 12.0
L = (b - 10) ** 2 # L = 4.0
L.backward()
print(x.grad) # -> 48.0
# ── 2. Detach a: gradient never reaches x ──
x = torch.tensor(2.0, requires_grad=True)
a = x ** 2
a_det = a.detach() # cut the graph here
b = 3 * a_det
L = (b - 10) ** 2
L.backward()
print(x.grad) # -> None (never touched)
# ── 3. Straight-through estimator ──
def ste_round(x):
return x + (torch.round(x) - x).detach()
