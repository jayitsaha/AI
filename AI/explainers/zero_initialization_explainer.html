Zero Initialization & Symmetry Breaking

Why setting every weight to the same constant permanently ties neurons together — and why randomness is what lets a network specialize.
Foundational Deep Learning Fundamentals Weight Initialization Failure Mode
1
Understanding the Concept
▾

What is this? When you build a neural network, every weight needs a starting value before training begins. It seems tidy to start everything at zero — no bias toward any feature, a clean slate. It turns out this "clean slate" is a trap: if every neuron in a layer starts identical, they receive identical input, produce identical output, and receive identical gradients during backpropagation. They update by the exact same amount, forever. A layer of 512 neurons initialized this way behaves like a layer of one neuron, copy-pasted 512 times.

Real-world analogy. Imagine hiring 10 identical clones for a team, giving them the exact same instructions, the exact same desk, and the exact same feedback after every task. Because they're indistinguishable and treated indistinguishably, they will make the exact same decisions forever — you've paid for 10 employees but you get the output of 1. To get a team that actually specializes (one person good at design, another at debugging), you need to start them out a little different and let their experiences diverge. Random initialization is that "little different."

💡 If you remember one thing
Zero (or any constant) initialization doesn't fail because the numbers are small — it fails because it makes every neuron in a layer mathematically indistinguishable to the optimizer. Identical inputs + identical weights → identical outputs → identical gradients → identical updates, forever. This is called the symmetry problem, and only breaking the initial symmetry (usually via randomness) lets neurons specialize.

One-sentence summary: Constant initialization is a fixed point of gradient descent for within-layer symmetry — it never breaks on its own, so every neuron in the layer collapses to computing the same function.

2
How It Works Internally — Why Symmetry Never Breaks
▾

Consider a hidden layer with two neurons, both fed the same input vector \(x\), with weight rows \(w_1\) and \(w_2\) and biases \(b_1, b_2\). If the network is initialized so that \(w_1 = w_2\) and \(b_1 = b_2\) (the zero-init case is the special instance where both equal the zero vector), trace what happens on the very first forward pass:

Forward pass — neurons become twins

  • Pre-activations: \(z_1 = w_1 \cdot x + b_1\) and \(z_2 = w_2 \cdot x + b_2\). Since \(w_1=w_2, b_1=b_2\), we get \(z_1 = z_2\) exactly.
  • Activations: \(a_1 = \sigma(z_1)\), \(a_2 = \sigma(z_2)\). Since \(z_1=z_2\), \(a_1 = a_2\) — any downstream computation that reads from this layer sees two copies of the same number instead of two independent features.

Backward pass — neurons receive twin gradients

  • The upstream gradient signal each neuron receives, \(\partial L/\partial a_1\) and \(\partial L/\partial a_2\), is a function of the downstream weights connecting each neuron to the loss. If those downstream weights are also tied by the same symmetric initialization, \(\partial L/\partial a_1 = \partial L/\partial a_2\) too.
  • Chaining back through the identical activation derivative \(\sigma'(z_1)=\sigma'(z_2)\), the gradient w.r.t. each neuron's own weights, \(\partial L/\partial w_1\) and \(\partial L/\partial w_2\), comes out identical — not just similar, bit-for-bit equal (up to floating point).

Update step — the twins stay twins

Gradient descent applies \(w_i \leftarrow w_i - \eta \, \partial L/\partial w_i\). Since the gradients are identical and the starting weights were identical, the updated weights are identical again. Nothing in the update rule depends on a neuron's identity or index — only on shared input and shared gradient. This is an inductive argument: if the layer is symmetric before a step, it is symmetric after the step, for every step, forever. No amount of training data or training time fixes it.

⚠️ Design decision: why can't the optimizer "notice" and fix this?
Gradient descent has no mechanism to distinguish neurons except through the numbers flowing through them. If two neurons are mathematically indistinguishable functions of the input, no loss landscape, no number of epochs, and no amount of data will ever produce different gradients for them. The fix has to happen before training starts — at initialization — because that is the only place symmetry can be broken.

This is exactly why the fix is random initialization: drawing each weight independently (e.g. from \(\mathcal{N}(0, \sigma^2)\), Xavier/Glorot, or He initialization) makes \(w_1 \neq w_2\) with probability 1. That tiny initial difference propagates through the forward pass (different \(z_1 \neq z_2\)), the backward pass (different gradients), and every subsequent update — the neurons drift apart and each is free to specialize in a different feature.

Why It Works — The Symmetry Invariant, Formally
▾

Claim. Let a fully-connected layer have weight matrix \(W \in \mathbb{R}^{m \times n}\) and bias \(b \in \mathbb{R}^m\). If two rows \(i, j\) satisfy \(W_{i,:} = W_{j,:}\) and \(b_i = b_j\) at initialization, and every path from neurons \(i, j\) to the loss is symmetric (e.g. all-constant init), then \(W_{i,:} = W_{j,:}\) and \(b_i = b_j\) after every subsequent gradient-descent step.

$$z_i = W_{i,:}\,x + b_i, \qquad a_i = \sigma(z_i)$$

Proof sketch (induction on training step \(t\)).

Base case (t = 0): By hypothesis \(W_{i,:}^{(0)} = W_{j,:}^{(0)}\), \(b_i^{(0)} = b_j^{(0)}\).

Inductive step: Assume \(W_{i,:}^{(t)} = W_{j,:}^{(t)}\), \(b_i^{(t)} = b_j^{(t)}\). Since both neurons read the same input \(x\):

$$z_i^{(t)} = z_j^{(t)} \;\Rightarrow\; a_i^{(t)} = a_j^{(t)} \;\Rightarrow\; \sigma'(z_i^{(t)}) = \sigma'(z_j^{(t)})$$

The gradient reaching each neuron via backprop is \(\delta_i = \frac{\partial L}{\partial a_i}\sigma'(z_i)\). By the symmetric-downstream-path assumption, \(\frac{\partial L}{\partial a_i^{(t)}} = \frac{\partial L}{\partial a_j^{(t)}}\), so \(\delta_i^{(t)} = \delta_j^{(t)}\). The weight gradient is \(\nabla_{W_{i,:}} L = \delta_i \, x^\top\), so:

$$\nabla_{W_{i,:}} L^{(t)} = \nabla_{W_{j,:}} L^{(t)}, \qquad \nabla_{b_i} L^{(t)} = \nabla_{b_j} L^{(t)}$$

Applying the same update rule \(W_{i,:}^{(t+1)} = W_{i,:}^{(t)} - \eta\, \nabla_{W_{i,:}} L^{(t)}\) to both rows preserves equality: \(W_{i,:}^{(t+1)} = W_{j,:}^{(t+1)}\). ∎

The quantity \(\lVert W_{i,:} - W_{j,:} \rVert\) — the "symmetry gap" between two neurons — is therefore a genuine invariant: it starts at 0 under constant init and is a fixed point of the entire training dynamics (Adam, momentum, weight decay — anything driven purely by gradients of a differentiable loss preserves it). Random initialization instead sets \(\lVert W_{i,:}^{(0)} - W_{j,:}^{(0)} \rVert > 0\) almost surely, and this gap generically grows under training as neurons chase different parts of the loss landscape.

⚠️ Common misconception
"Zero initialization fails because zero gradients kill learning (vanishing gradients)." That's a different, unrelated problem. The symmetry failure happens even when gradients are large and nonzero — as the constant-init trace in the walkthrough below shows, weights do move every step. They just move in perfect lockstep, so the layer's expressive capacity collapses to a single effective neuron regardless of layer width.
🔑 Key property
Symmetry between two neurons is preserved by every gradient step, never broken by it. Breaking symmetry is a job that only the initialization can do — hence "symmetry breaking" describes what random init achieves, not what training achieves.

Key Takeaways
▾
  • Constant init ⇒ permanent symmetry. Any two neurons that start identical (same weights, same bias, symmetric downstream connections) stay identical forever — proven by induction on the gradient-descent update rule itself.
  • It isn't about the number zero. Initializing every weight to 0.3, or 5, or −1 fails for exactly the same reason. Zero is just the most tempting constant to pick.
  • The fix lives at initialization, not in training. No optimizer, learning rate schedule, or number of epochs can break symmetry once training starts — randomness (Xavier/Glorot, He, LeCun, or plain Gaussian) must inject it up front.
  • This is layer-local. Symmetry only matters within a layer (between neurons that share the exact same inputs and the exact same downstream path). Different layers can safely use the same initialization scheme without colliding.
  • Biases can be zero — weights cannot. It's standard practice to initialize biases to 0 while weights are randomized, because the weights (not the biases) are what determines whether two neurons compute the same function of the input.
💡 When this matters most
Fully-connected and convolutional layers are the classic failure case. It's less of a concern for a single-neuron output layer (nothing to be symmetric with) and irrelevant for layers with no shared trainable weights (e.g. some normalization layers) — but any layer with ≥2 units sharing an input is at risk.

Code — Proving It From Scratch
▾

The snippet below is exactly what powers the visualization above — a 2-input → 2-hidden(tanh) → 1-output(linear) network trained with plain gradient descent, run once with constant init and once with random init.

import numpy as np def forward(w, b, v, c, x): z = w @ x + b # pre-activations, shape (2,) a = np.tanh(z) # activations, shape (2,) y_pred = v @ a + c # scalar output return z, a, y_pred def backward(w, b, v, c, x, y_true, z, a, y_pred): dL_dy = y_pred - y_true # dL/dy_pred dv = dL_dy * a # dL/dv (shape 2,) dc = dL_dy da = dL_dy * v # dL/da (shape 2,) dz = da * (1 - a**2) # dL/dz, tanh' = 1 - tanh^2 dw = np.outer(dz, x) # dL/dw (shape 2,2) db = dz return dw, db, dv, dc # --- Constant ("zero-like") init: every weight = 0.3 --- w = np.full((2, 2), 0.3); b = np.full(2, 0.3) v = np.full(2, 0.3); c = 0.3 x, y_true, lr = np.array([1.0, 0.5]), 1.0, 0.5 for step in range(5): z, a, y_pred = forward(w, b, v, c, x) dw, db, dv, dc = backward(w, b, v, c, x, y_true, z, a, y_pred) w -= lr * dw; b -= lr * db; v -= lr * dv; c -= lr * dc gap = np.linalg.norm(w[0] - w[1]) # ALWAYS 0.0 — rows never separate print(step, "row0 == row1:", np.allclose(w[0], w[1]), "gap:", gap) # --- Random init breaks the tie --- rng = np.random.default_rng(0) w = rng.normal(0, 0.5, (2, 2)); b = rng.normal(0, 0.3, 2) v = rng.normal(0, 0.5, 2); c = 0.0 for step in range(5): z, a, y_pred = forward(w, b, v, c, x) dw, db, dv, dc = backward(w, b, v, c, x, y_true, z, a, y_pred) w -= lr * dw; b -= lr * db; v -= lr * dv; c -= lr * dc gap = np.linalg.norm(w[0] - w[1]) # grows step over step print(step, "gap:", gap)
⚠️ Gotcha in real frameworks
PyTorch's default nn.Linear init and Keras' glorot_uniform already randomize weights, so you won't hit this by accident with defaults. It bites when someone "simplifies" a from-scratch implementation, initializes via torch.zeros(...) for debugging and forgets to switch back, or zero-initializes weights (not just biases) in a custom layer.
