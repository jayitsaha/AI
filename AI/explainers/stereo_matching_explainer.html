Stereo Matching

Estimating depth from two images using parallax and correspondence
Foundational Computer Vision 3D Reconstruction O(WHD)
1
Understanding Stereo Matching
▼

What is it? Stereo matching is a core computer vision task that aims to reconstruct the 3D geometry of a scene from two or more 2D images taken from slightly different viewpoints. By finding corresponding points in these images and measuring their relative shift (called disparity), we can infer the depth of objects in the scene, much like how our own two eyes perceive depth.

Analogy: Hold your finger up in front of your face and close one eye, then the other. Your finger appears to "jump" relative to the background. This apparent shift is parallax. Objects closer to you jump more than objects further away. Stereo matching mimics this: two cameras act as "eyes," capturing images. The algorithm then identifies the same point in both images and calculates how much it shifted. This shift, the disparity, directly tells us how far away that point is.

💡 If you remember one thing

Stereo matching works by finding corresponding points in two images (left and right) and calculating their horizontal pixel difference, known as disparity. This disparity is inversely proportional to the object's depth: larger disparity means closer, smaller disparity means further away.

2
How Stereo Matching Works Internally
▼

The process of stereo matching typically involves a pipeline of several stages to compute a dense disparity map (a map where each pixel has an estimated disparity value):

1. Image Rectification

Before matching, the left and right images are geometrically transformed so that they appear as if they were captured by two cameras with parallel optical axes and perfectly aligned image planes. This crucial step simplifies the search for corresponding points from a 2D search (anywhere in the other image) to a 1D search along the same horizontal scanline (the epipolar constraint).

2. Correspondence Cost Computation

For each pixel in the left image, the algorithm searches along its corresponding epipolar line in the right image to find the best match. "Best match" is determined by a cost function that quantifies the similarity between a small window (patch) around the left pixel and a candidate window in the right image. Common cost functions include Sum of Absolute Differences (SAD) or Sum of Squared Differences (SSD).

3. Cost Aggregation

Raw correspondence costs can be noisy and ambiguous, especially in textureless regions. Cost aggregation smooths the cost function over a larger neighborhood to make it more robust. This helps to enforce local consistency and reduce the impact of noise, often producing smoother disparity maps.

4. Disparity Computation/Optimization

After aggregating costs, the disparity for each pixel is determined by selecting the candidate disparity that yields the minimum aggregated cost. A simple approach is Winner-Take-All (WTA), where the disparity with the lowest cost is chosen. More advanced methods use global optimization techniques like dynamic programming or graph cuts to enforce global smoothness constraints across the entire image.

5. Disparity Refinement

The initial disparity map can contain errors (e.g., sub-pixel inaccuracies, holes due to occlusions, or mismatches in repetitive textures). Refinement steps include sub-pixel interpolation, hole filling, and left-right consistency checks (matching right-to-left and comparing results) to improve accuracy and completeness.

🔑 Key Simplification: Epipolar Geometry

After rectification, the 3D world is projected onto the image planes such that any point \\(P\\) in the left image \\((x_L, y_L)\\) will have its corresponding point \\(P'\\) in the right image on the same horizontal scanline \\((x_R, y_R)\\), where \\(y_L = y_R\\). This reduces the search for correspondence from 2D to 1D, making the problem tractable.

3
Why It Works — The Math
▼

Disparity and Depth Relationship

The fundamental principle behind stereo matching is triangulation. Given two cameras separated by a baseline \\(B\\), with a known focal length \\(f\\), a 3D point \\(P=(X,Y,Z)\\) projects to \\((x_L, y_L)\\) in the left image and \\((x_R, y_R)\\) in the right image. After rectification, \\(y_L = y_R\\). The disparity \\(d\\) is defined as the horizontal difference: \\(d = x_L - x_R\\).

Using similar triangles, we can derive the relationship between depth \\(Z\\) and disparity \\(d\\):

$$\frac{Z-f}{Z} = \frac{x_L}{X} = \frac{x_R}{X-B}$$

From this, we can solve for \\(Z\\):

$$Z = \frac{f \cdot B}{d}$$

This equation shows that depth \\(Z\\) is inversely proportional to disparity \\(d\\). A larger disparity (points appearing further apart in the two images) means the object is closer to the cameras, while a smaller disparity means it's further away.

Correspondence Cost Functions

To find the best match, we compare image patches. Let \\(I_L(x,y)\\) and \\(I_R(x,y)\\) be the intensity (or color) values at pixel \\((x,y)\\) in the left and right images, respectively. For a pixel \\((x_L, y_L)\\) in the left image, we search for \\((x_R, y_R)\\) in the right image, where \\(y_R = y_L\\) and \\(x_R = x_L - d\\). We compare a window \\(W_L\\) centered at \\((x_L, y_L)\\) with a window \\(W_R\\) centered at \\((x_R, y_R)\\).

Two common cost functions are:

  1. Sum of Absolute Differences (SAD):
    2. $$C_{SAD}(x_L, y_L, d) = \sum_{(i,j) \in W} |I_L(x_L+i, y_L+j) - I_R(x_L-d+i, y_L+j)|$$
  2. Sum of Squared Differences (SSD):
    3. $$C_{SSD}(x_L, y_L, d) = \sum_{(i,j) \in W} (I_L(x_L+i, y_L+j) - I_R(x_L-d+i, y_L+j))^2$$

Here, \\(W\\) denotes the window around the pixel, and \\((i,j)\\) are offsets within that window. The goal is to find the disparity \\(d\\) that minimizes this cost function for each \\((x_L, y_L)\\).

⚠️ Assumptions and Limitations

The depth formula \\(Z = \frac{f \cdot B}{d}\\) assumes ideal pinhole cameras, perfect calibration, and rectification. In practice, errors in these assumptions, along with issues like textureless regions, occlusions, and illumination variations, can significantly degrade the quality of the disparity map.

Key Takeaways
▼

When to use Stereo Matching:

  • Autonomous Driving: Real-time depth perception for obstacle detection, lane keeping, and navigation.
  • Robotics: Environment mapping, object manipulation, collision avoidance for mobile robots.
  • 3D Reconstruction: Creating 3D models of scenes or objects from multiple images.
  • Augmented Reality/Virtual Reality: Understanding the real-world scene geometry for seamless overlay.
  • Metrology: High-precision measurement in industrial applications.

Advantages:

  • Passive Sensing: Does not emit light or signals, making it suitable for various environments.
  • Dense Depth Maps: Can produce a disparity (and thus depth) value for almost every pixel.
  • Cost-Effective: Compared to active sensors like LiDAR, stereo cameras are relatively inexpensive.

Limitations and Challenges:

  • Textureless Regions: Areas with uniform color lack sufficient features for matching, leading to unreliable disparity.
  • Occlusions: Parts of the scene visible in one image but not the other cannot be matched, creating "holes" in the disparity map.
  • Repetitive Patterns: Ambiguity in matching identical patterns can lead to false correspondences.
  • Illumination Changes: Differences in lighting between the two cameras can affect cost calculations.
  • Computational Cost: Dense stereo matching can be computationally intensive, especially for high-resolution images and large disparity ranges.
💡 Modern Approaches

While traditional block-matching methods form the foundation, modern stereo matching often leverages deep learning. Convolutional Neural Networks (CNNs) are used to learn sophisticated feature descriptors, compute robust correspondence costs, and even directly predict disparity maps, often outperforming classical methods, particularly in challenging scenarios.

Code Trace (Simplified Block Matching)
▼
import numpy as np
def sad_cost(patch_L, patch_R):
# Sum of Absolute Differences for two patches
return np.sum(np.abs(patch_L - patch_R))
def ssd_cost(patch_L, patch_R):
# Sum of Squared Differences for two patches
return np.sum((patch_L - patch_R)**2)
def compute_disparity_map(img_L, img_R, max_disparity, window_size, cost_fn):
H, W = img_L.shape
disparity_map = np.zeros_like(img_L, dtype=float)
half_window = window_size // 2
for y in range(H):
for x_L in range(W):
# Define left image patch
x_L_start = max(0, x_L - half_window)
x_L_end = min(W, x_L + half_window + 1)
patch_L = img_L[y, x_L_start:x_L_end]
min_cost = float('inf')
best_disparity = 0
# Search along epipolar line (same row y) in right image
for d in range(max_disparity + 1): # Disparity from 0 to max_disparity
x_R = x_L - d
if x_R < 0 or x_R - half_window < 0 or x_R + half_window + 1 > W:
continue # Skip if right patch goes out of bounds
x_R_start = x_R - half_window
x_R_end = x_R + half_window + 1
patch_R = img_R[y, x_R_start:x_R_end]
# Ensure patches have same length for comparison
if len(patch_L) != len(patch_R):
continue
cost = cost_fn(patch_L, patch_R)
if cost < min_cost:
min_cost = cost
best_disparity = d
disparity_map[y, x_L] = best_disparity
return disparity_map
# Example Usage (1D scanline)
left_scanline = np.array([10, 10, 10, 50, 50, 50, 50, 50, 10, 10, 10])
right_scanline = np.array([10, 10, 10, 10, 10, 50, 50, 50, 50, 50, 10, 10, 10])
# Reshape to 2D for compute_disparity_map (H=1)
img_L = left_scanline.reshape(1, -1)
img_R = right_scanline.reshape(1, -1)
# Compute disparity map
disparity = compute_disparity_map(img_L, img_R,
max_disparity=5, window_size=3, cost_fn=sad_cost)
print("Disparity Map:", disparity[0])
