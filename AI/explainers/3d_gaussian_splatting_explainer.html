Understanding 3D Gaussian Splatting
▼

What is it? 3D Gaussian Splatting (3DGS) is a novel neural rendering technique that reconstructs 3D scenes from a set of multi-view images and renders them at extremely high quality and real-time frame rates. Unlike traditional 3D models (meshes, voxels) or implicit neural representations (like NeRF), 3DGS explicitly represents a scene as a collection of millions of 3D Gaussians.

Analogy: Imagine you want to recreate a detailed scene, like a bustling market square, from many photographs. Instead of painstakingly modeling every fruit stand, cobblestone, and person, 3DGS approaches it like painting with fuzzy, transparent, colored paint splotches. Each "splotch" is a 3D Gaussian: it has a position, a size, an orientation, a color, and an opacity. When you look at the scene from any angle, these millions of splotches are projected onto your view, sorted by depth, and blended together to form a seamless, photo-realistic image, all in milliseconds.

💡 If you remember one thing

3D Gaussian Splatting achieves state-of-the-art visual quality and real-time rendering speeds by combining an explicit, optimizable 3D representation (millions of Gaussians) with differentiable, GPU-accelerated rasterization. This allows direct optimization against image pixels while leveraging efficient graphics pipelines.

How 3DGS Works Internally
▼

The Gaussian Representation

Each 3D Gaussian is a primitive described by several learnable parameters:

  • 3D Position (\(\boldsymbol{\mu} \in \mathbb{R}^3\)): The center of the Gaussian.
  • 3D Covariance Matrix (\(\boldsymbol{\Sigma} \in \mathbb{R}^{3 \times 3}\)): Defines the Gaussian's anisotropic (stretched/squashed) shape and orientation. This is typically stored as a scale vector and a quaternion for rotation, then converted to \(\boldsymbol{\Sigma}\).
  • Color (Spherical Harmonics): Instead of a single RGB color, 3DGS uses spherical harmonics (SH) coefficients. This allows the Gaussian's color to vary depending on the viewing direction, capturing complex lighting effects (e.g., reflections, specularity).
  • Opacity (\(\alpha \in [0,1]\)): A scalar value determining how transparent or opaque the Gaussian is.

The Optimization Loop

3DGS optimizes these parameters using a standard gradient descent loop:

  1. Initialization: The process typically starts by initializing Gaussians at the 3D points reconstructed by a Structure-from-Motion (SfM) algorithm (e.g., COLMAP).
  2. Render Image: For each training iteration, a view is randomly sampled, and an image is rendered from that camera's perspective using the current set of Gaussians.
  3. Compute Loss: The rendered image is compared to the ground-truth training image for that view using a loss function (e.g., L1 loss plus SSIM).
  4. Backpropagation: Gradients are computed and backpropagated through the differentiable rendering process to update the parameters (\(\boldsymbol{\mu}, \boldsymbol{\Sigma}\), SH coefficients, \(\alpha\)) of all contributing Gaussians.
  5. Adaptive Density Control: Crucially, 3DGS dynamically manages the number and distribution of Gaussians. In regions with high reconstruction error, new Gaussians are "densified" (cloned or split). Gaussians that are too transparent or too large are "pruned" (removed or shrunk). This allows the model to adaptively allocate capacity where needed.

Differentiable Rendering & Fast Rasterization

The core of 3DGS's speed and differentiability lies in its rendering pipeline:

  • Projection: Each 3D Gaussian is projected onto the 2D image plane, becoming a 2D ellipse with its own 2D covariance, color, and opacity.
  • Sorting: These projected 2D ellipses are sorted by their depth relative to the camera. This is critical for correct alpha blending.
  • Alpha Blending: The sorted Gaussians are then blended from back-to-front (or front-to-back) to accumulate color at each pixel. This process is fully differentiable, allowing gradients to flow back to the Gaussian parameters.
  • GPU Acceleration: This entire rasterization process is highly parallelizable and implemented efficiently on GPUs, leveraging existing graphics primitives for speed.
🔑 Key Property

The explicit representation allows for direct, efficient GPU rasterization, bypassing the need for ray-marching or complex sampling strategies common in implicit neural renderers. This is the primary reason for its real-time performance.

Why It Works — The Math
▼

3D Gaussian Definition

A 3D Gaussian function at a point \(\mathbf{x}\) with mean \(\boldsymbol{\mu}\) and covariance \(\boldsymbol{\Sigma}\) is given by:

$$N(\mathbf{x} | \boldsymbol{\mu}, \boldsymbol{\Sigma}) = \frac{1}{\sqrt{(2\pi)^3 \det(\boldsymbol{\Sigma})}} \exp\left(-\frac{1}{2}(\mathbf{x} - \boldsymbol{\mu})^\top \boldsymbol{\Sigma}^{-1} (\mathbf{x} - \boldsymbol{\mu})\right)$$

In 3DGS, we don't directly evaluate this density. Instead, the Gaussian parameters (\(\boldsymbol{\mu}\), \(\boldsymbol{\Sigma}\)) define the shape and position of the "splat." The color and opacity are separate learned attributes.

Projection to 2D

To render, each 3D Gaussian must be projected onto the 2D image plane. The 3D mean \(\boldsymbol{\mu}\) is projected to a 2D pixel coordinate \(\mathbf{p} = (u,v)\) using the camera's view (\(V\)) and projection (\(P\)) matrices. The 3D covariance \(\boldsymbol{\Sigma}\) is transformed into a 2D covariance \(\boldsymbol{\Sigma}'\) on the image plane:

$$\boldsymbol{\Sigma}' = J W \boldsymbol{\Sigma} W^\top J^\top$$

Here, \(W\) is the 3D world-to-camera transformation (view matrix), and \(J\) is the Jacobian of the affine approximation of the perspective projection at the Gaussian's mean. This formula correctly accounts for how the 3D shape appears deformed when viewed through a camera, including perspective effects.

Differentiable Alpha Blending

Once projected, the 2D Gaussians are sorted by their depth (distance from the camera). For each pixel, the final color \(C\) is accumulated by blending Gaussians from back-to-front. The blending formula for a sequence of sorted Gaussians is:

$$C = \sum_{i \in \text{sorted}} c_i \alpha_i \prod_{j=1}^{i-1} (1-\alpha_j)$$

where \(c_i\) is the color of Gaussian \(i\) (derived from its SH coefficients and view direction), and \(\alpha_i\) is its effective opacity. This opacity is a combination of the learned scalar opacity and the 2D Gaussian density evaluated at the pixel. This entire process is differentiable, allowing gradients to flow back to all Gaussian parameters.

⚠️ Practical Considerations

While powerful, 3DGS models can be very large, containing tens of millions of Gaussians. This leads to high memory consumption (several GBs for a single scene) and can make scene editing or integration into existing 3D pipelines challenging. Future work often focuses on compressing these representations.

Key Takeaways
▼

When to use 3D Gaussian Splatting:

  • Real-time novel view synthesis: If your primary goal is to render new views of a captured scene at very high frame rates (e.g., for AR/VR, gaming, virtual tours).
  • High visual fidelity: When photo-realistic quality is paramount, surpassing many traditional 3D reconstruction methods.
  • Faster training: Significantly faster to optimize than implicit neural representations like NeRF, often training in minutes to hours instead of days.
  • Large-scale scene capture: Its adaptive density allows it to represent complex scenes efficiently.

When NOT to use 3D Gaussian Splatting:

  • Scene editing: The explicit Gaussian representation is not intuitive for direct 3D manipulation or editing (e.g., moving objects, changing geometry).
  • Highly reflective surfaces: While spherical harmonics help, very complex light transport (e.g., mirrors) can still be challenging.
  • Very sparse input views: Like most neural rendering methods, it performs best with dense multi-view image captures.
  • Memory-constrained environments: The large number of Gaussians can lead to substantial memory usage, making it unsuitable for very low-end devices without further compression.
💡 One-Line Summary

3D Gaussian Splatting is a powerful explicit neural representation that trades traditional 3D model interpretability for unparalleled real-time rendering speed and quality, by directly optimizing millions of view-dependent 3D Gaussians.

class Gaussian3D:
def __init__(self, position, scale, rotation, color_sh, opacity):
self.pos = torch.tensor(position, requires_grad=True) # (x,y,z)
self.scale = torch.tensor(scale, requires_grad=True) # (sx,sy,sz)
self.rot = torch.tensor(rotation, requires_grad=True) # (qx,qy,qz,qw)
self.color_sh = torch.tensor(color_sh, requires_grad=True) # Spherical Harmonics coeffs
self.opacity = torch.tensor(opacity, requires_grad=True) # Scalar alpha

S = torch.diag(self.scale**2)
R = quaternion_to_rotation_matrix(self.rot)
return R @ S @ R.T

mean_3d_cam = (view_matrix @ to_homogeneous(gaussian.pos))[:3]

def rasterize_gaussians(gaussians_2d, image_width, image_height):
# 1. Sort Gaussians by depth (back-to-front)
sorted_gaussians = sorted(gaussians_2d, key=lambda g: g['depth'])
# 2. Initialize empty image buffer
rendered_image = torch.zeros((image_height, image_width, 3))
alpha_map = torch.zeros((image_height, image_width, 1))
# 3. Iterate over sorted Gaussians and blend
for g in sorted_gaussians:
# For each pixel covered by g, calculate its contribution
pixel_coords = get_pixels_in_ellipse_bbox(g['mean_2d'], g['Sigma_2d'])
for px, py in pixel_coords:
# Calculate alpha_i based on learned opacity and 2D Gaussian density
effective_alpha = g['opacity'] * evaluate_2d_gaussian(px, py, g['mean_2d'], g['Sigma_2d'])
# Alpha blending formula: C = c_i * alpha_i + C_prev * (1 - alpha_i)
# This is simplified. Actual formula accumulates over previous layers.
# The paper uses a specific GPU rasterizer that handles this efficiently.
old_color = rendered_image[py, px]
old_alpha = alpha_map[py, px]
new_alpha = effective_alpha + old_alpha * (1 - effective_alpha)
rendered_image[py, px] = (g['color'] * effective_alpha + old_color * old_alpha * (1 - effective_alpha)) / (new_alpha + 1e-6)
alpha_map[py, px] = new_alpha
return rendered_image
