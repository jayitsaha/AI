Decision Trees: Continuous Features, Missing Values & Multi-Output

How CART and C4.5 handle real-valued attributes, missing data, and simultaneous prediction of multiple targets
Intermediate Classical ML Decision Trees O(n log n) per split
1
Understanding the Three Extensions
▼

What is this? A decision tree splits data by asking yes/no questions. The original ID3 algorithm only handled categorical features (e.g., "Color = Red?"). Real-world data is mostly continuous (height, temperature, price), often has missing values, and sometimes requires predicting multiple outputs at once. CART (Breiman 1984) and C4.5 (Quinlan 1993) introduced principled solutions to all three problems.

Analogy: Think of a doctor doing triage. They check continuous vitals (temperature ≤ 38.5°C?), handle missing readings by using correlated measurements or estimated probabilities, and simultaneously predict both diagnosis and treatment plan from the same examination — one tree, multiple outputs.

💡 If you remember one thing

Continuous features: sort, test \(n{-}1\) midpoints, pick best. Missing values: CART routes via surrogate splits on correlated features; C4.5 sends fractional weights to both branches. Multi-output: one tree, impurity summed across all outputs.

2
Continuous Features — Threshold Search
▼

The Core Algorithm

ID3 picked splits by information gain on categorical features. But how do you split on "height" or "temperature" — a feature that takes a thousand distinct values? CART's answer: exhaustively search all candidate thresholds.

Step 1 — Sort. Given \(n\) training samples with feature values \(x_1, x_2, \ldots, x_n\), sort them: \(x_{(1)} \le x_{(2)} \le \cdots \le x_{(n)}\). This is \(O(n \log n)\) and only needs to happen once per feature at each node.

Step 2 — Candidate thresholds. There are at most \(n-1\) candidate split points — the midpoints between adjacent distinct values:

$$t_k = \frac{x_{(k)} + x_{(k+1)}}{2}, \quad k = 1, \ldots, n-1$$

Only midpoints between samples with different labels can improve impurity (C4.5 optimization: skip equal-label adjacent pairs).

Step 3 — Evaluate each threshold. For each \(t_k\), partition into left (\(x \le t_k\)) and right (\(x > t_k\)) subsets. Compute weighted impurity:

$$\text{Gain}(t_k) = I(\text{parent}) - \frac{n_L}{n}\,I(L_k) - \frac{n_R}{n}\,I(R_k)$$

where \(I\) is Gini impurity (CART) or entropy (C4.5), and \(n_L, n_R\) are left/right counts.

Step 4 — Pick best. Select \(t^* = \arg\max_{k} \text{Gain}(t_k)\).

🔑 Key Property — Why O(n log n) not O(n²)

After sorting once (\(O(n \log n)\)), you can update left/right class counts incrementally as the threshold slides from left to right — each threshold evaluation is \(O(1)\). Total: \(O(n \log n)\) per feature, \(O(pn \log n)\) per node for \(p\) features.

⚠️ C4.5 Gain Ratio Correction

Continuous features generate more thresholds than categorical ones, biasing raw Information Gain toward continuous attributes. C4.5 divides by the split information \(- \sum_k \frac{n_k}{n} \log \frac{n_k}{n}\) to compute Gain Ratio, penalizing high-arity splits.

Missing Values — Surrogates & Fractional Routing
▼

Real datasets are rarely complete. Two major strategies exist: C4.5 fractional routing and CART surrogate splits. They differ in philosophy — C4.5 distributes the sample probabilistically, CART finds a backup split question.

Strategy 1: C4.5 Fractional Routing

When sample \(x_i\) has a missing value for the split feature, C4.5 routes it to both branches simultaneously with fractional weight proportional to each branch's training set size:

$$w_L = \frac{n_L}{n_L + n_R}, \quad w_R = \frac{n_R}{n_L + n_R}$$

In our example above, 3 samples go left, 4 go right, so \(w_L = 3/7 \approx 0.429\), \(w_R = 4/7 \approx 0.571\). A missing-value sample contributes weight 0.429 to the left leaf and 0.571 to the right leaf. At prediction time, the leaf probabilities are blended proportionally.

Strategy 2: CART Surrogate Splits

CART takes a harder approach: find a surrogate split on a correlated feature that mimics the primary split as closely as possible. The surrogate is ranked by predictive association — the fraction of training samples it routes identically to the primary split:

$$\text{Association}(s, s^*) = \frac{\min(P_L, P_L^s) + \min(P_R, P_R^s)}{\text{max possible}}$$

where \(P_L, P_R\) are the primary split's left/right fractions and \(P_L^s, P_R^s\) are the surrogate's. A list of surrogates is stored at each node; when the primary feature is missing, the best available surrogate routes the sample.

💡 CART vs C4.5 Missing Strategy

CART surrogates give hard routing decisions and work at both train and test time. C4.5 fractional weights propagate probability mass to multiple leaves — computationally clean but produces soft predictions at leaves. In practice, sklearn's CART uses the primary split's majority direction as default fallback when no surrogate is trained (faster, slightly less accurate).

🚨 Common Misconception

Mean/mode imputation before tree training changes the training distribution — it artificially concentrates mass near the mean and can shift split thresholds. Decision trees are one of the few algorithms that can handle missing values natively without imputation.

Multi-Output Trees — Shared Structure
▼

A multi-output tree predicts a vector of targets \(\mathbf{y} = (y_1, y_2, \ldots, y_K)\) from a single shared tree structure. Instead of optimizing impurity for one output, the split criterion sums (or averages) impurity across all outputs.

Summed Impurity Criterion

For a candidate split, the gain is computed as:

$$\text{Gain}_{\text{multi}} = \sum_{k=1}^{K} \left[ I_k(\text{parent}) - \frac{n_L}{n} I_k(L) - \frac{n_R}{n} I_k(R) \right]$$

Each \(I_k\) is the appropriate impurity for output \(k\): Gini impurity for classification targets, variance for regression targets. Outputs can be mixed types.

The split at \(x \le 2.5\) maximally separates both outputs simultaneously — the tree learns one shared boundary that works for regression and classification together.

Leaf Prediction in Multi-Output Trees

Each leaf stores a vector of predictions: means for regression outputs, class probability distributions for classification outputs. A single traversal of the tree produces all predictions at once.

🔑 When Multi-Output Trees Are Better Than Separate Trees

If outputs are correlated, a single tree can find splits that jointly reduce impurity across all outputs — learning the correlation for free. Separate trees ignore this structure. Multi-output trees also require fitting only one model, saving memory and inference time. However, if outputs are uncorrelated, joint optimization may hurt each individual output's quality.

sklearn Implementation Note

from sklearn.tree import DecisionTreeClassifier, DecisionTreeRegressor
from sklearn.tree import DecisionTreeClassifier
# Multi-output: pass 2D y matrix (n_samples, n_outputs)
import numpy as np
X = np.array([[1],[2],[3],[4],[5],[6]])
y = np.column_stack([[0,0,1,1,1,1], [0,0,0,1,1,1]]) # 2 classification outputs
clf = DecisionTreeClassifier(random_state=42)
clf.fit(X, y) # automatically detects multi-output
clf.predict([[2.5]]) # returns array of shape (1, 2) — one pred per output

Key Takeaways & When to Use
▼

Quick Reference

FeatureAlgorithmMechanismComplexity
Continuous splitCART / C4.5Sort + midpoint searchO(n log n) per feature
Missing (train)C4.5Fractional weight routingO(1) overhead per sample
Missing (train+test)CARTSurrogate splitsO(n log n) per surrogate
Multi-outputCART (sklearn)Summed impurity across K outputsO(pn log n · K) per node

When to Use

  • Continuous threshold search: always — all modern trees do this automatically.
  • CART surrogates: when data has structured missingness patterns and you need reliable routing at inference time. Preferred in clinical/sensor data.
  • C4.5 fractional routing: when missingness is light and you prefer a probabilistic treatment. Also useful when you need soft predictions from leaves.
  • Multi-output trees: when targets are correlated (e.g., predicting both height and weight, or multiple disease scores from the same features). Saves compute vs training K separate trees.
⚠️ Gotcha — Missing Values in sklearn

sklearn's DecisionTreeClassifier prior to version 1.4 did NOT support missing values natively — it raised an error. From sklearn 1.4+, CART supports missing values using the majority-direction fallback (not full surrogate lists). Always check your sklearn version before assuming native missing support.
