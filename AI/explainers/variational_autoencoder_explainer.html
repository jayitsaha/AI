1
Understanding VAEs
▼

What is it? A Variational Autoencoder is a generative model that learns to compress data into a compact, structured "latent space" and then reconstruct it. Unlike a plain autoencoder, a VAE forces the latent space to follow a known probability distribution (typically a Gaussian), which means you can sample new points from that space and decode them into realistic new data.

Analogy: Imagine you have a huge library of face photos. A VAE learns a "recipe card" for each face: instead of storing millions of pixels, it distills each face down to a handful of numbers (latent variables) like "how much does this person smile" or "hair length." The recipe is slightly fuzzy on purpose — so if you pick any recipe card at random, the kitchen (decoder) can still cook up a plausible face.

If you remember one thing

A VAE encodes inputs not as single points but as probability distributions in latent space. It optimizes the Evidence Lower Bound (ELBO): $$\mathcal{L} = \mathbb{E}_{q(z|x)}[\log p(x|z)] - D_{KL}(q(z|x) \| p(z))$$ balancing reconstruction quality against latent-space regularity.

2
How the VAE Works Internally
▼

Encoder: Input to Distribution

The encoder network takes input \(x\) and outputs two vectors: a mean \(\mu\) and a log-variance \(\log \sigma^2\). These parameterize a diagonal Gaussian \(q_\phi(z|x) = \mathcal{N}(\mu, \text{diag}(\sigma^2))\) in the latent space. Crucially, the encoder does not produce a single point — it produces a cloud of uncertainty.

Reparameterization Trick

We cannot backpropagate gradients through a random sampling operation. The trick: instead of sampling \(z \sim \mathcal{N}(\mu, \sigma^2)\) directly, we sample \(\varepsilon \sim \mathcal{N}(0, I)\) and compute \(z = \mu + \sigma \odot \varepsilon\). This moves the randomness outside the computational graph while producing the same distribution, making the model end-to-end differentiable.

Decoder: Latent to Reconstruction

The decoder takes a latent sample \(z\) and produces a reconstructed output \(\hat{x}\). It models \(p_\theta(x|z)\) — the likelihood of the data given the latent code. For images, this is often a Bernoulli or Gaussian distribution over pixel values.

Key Design Decision

Why not just use a plain autoencoder? Without the KL term forcing latent codes toward \(\mathcal{N}(0, I)\), the latent space has "holes" — regions where decoded outputs are garbage. The VAE's probabilistic constraint ensures a smooth, interpolable latent space suitable for generation.

3
ELBO, KL Divergence & the Loss
▼

We want to maximize the log-evidence \(\log p(x)\), but it is intractable because it requires marginalizing over all \(z\). Instead, we derive the Evidence Lower Bound (ELBO):

$$\log p(x) \geq \underbrace{\mathbb{E}_{q(z|x)}[\log p(x|z)]}_{\text{Reconstruction}} - \underbrace{D_{KL}(q(z|x) \| p(z))}_{\text{Regularization}} = \mathcal{L}(\theta, \phi; x)$$

The reconstruction term encourages the decoder to faithfully reconstruct the input from sampled \(z\). The KL divergence term penalizes the encoder for producing posteriors that deviate from the prior \(p(z) = \mathcal{N}(0, I)\).

Closed-Form KL for Gaussians

When both the posterior \(q(z|x) = \mathcal{N}(\mu, \sigma^2)\) and prior \(p(z) = \mathcal{N}(0, 1)\) are Gaussian, the KL divergence has a closed-form solution per dimension \(j\):

$$D_{KL} = -\frac{1}{2}\sum_{j=1}^{d}\left(1 + \log\sigma_j^2 - \mu_j^2 - \sigma_j^2\right)$$
Posterior Collapse

When the KL term dominates (e.g., with a strong \(\beta > 1\) weight or a powerful decoder), the encoder may learn to set \(q(z|x) \approx p(z)\) for all inputs — collapsing every posterior to the prior. The latent codes carry no information, and the decoder ignores \(z\) entirely. This is called posterior collapse and is a major failure mode of VAEs.

Code: VAE Forward Pass
▼
import torch, torch.nn as nn
class VAE(nn.Module):
def __init__(self, in_dim=784, h=400, z=20):
super().__init__()
self.enc = nn.Linear(in_dim, h) # encoder hidden
self.fc_mu = nn.Linear(h, z) # mean head
self.fc_lv = nn.Linear(h, z) # log-var head
self.dec1 = nn.Linear(z, h) # decoder hidden
self.dec2 = nn.Linear(h, in_dim) # reconstruction
def encode(self, x):
h = torch.relu(self.enc(x))
return self.fc_mu(h), self.fc_lv(h) # mu, log_var
def reparameterize(self, mu, log_var):
std = torch.exp(0.5 * log_var) # sigma
eps = torch.randn_like(std) # eps ~ N(0,I)
return mu + std * eps # z = mu + s*e
def decode(self, z):
h = torch.relu(self.dec1(z))
return torch.sigmoid(self.dec2(h)) # pixel probs
def forward(self, x):
mu, lv = self.encode(x) # Step 1
z = self.reparameterize(mu, lv) # Step 2
return self.decode(z), mu, lv # Step 3
Loss Function

The total loss (negated ELBO) combines binary cross-entropy reconstruction with the analytic KL: $$\mathcal{L} = -\sum_i\left[x_i\log\hat{x}_i + (1-x_i)\log(1-\hat{x}_i)\right] + \frac{\beta}{2}\sum_{j=1}^{d}\left(\mu_j^2 + \sigma_j^2 - \log\sigma_j^2 - 1\right)$$

5
Key Takeaways
▼

When to use VAEs: When you need a structured, continuous latent space for generation, interpolation, or representation learning. VAEs excel at disentangled representations and uncertainty-aware encoding. They produce smoother latent spaces than GANs, though with blurrier outputs.

When NOT to use: If you need photorealistic image generation (use Diffusion Models or GANs). If you need discrete latent variables (consider VQ-VAE). If reconstruction sharpness is critical and generation is not needed (use a plain autoencoder).

Variants & Successors

beta-VAE weights the KL term by \(\beta\) to encourage disentanglement. VQ-VAE replaces the continuous latent with a discrete codebook. NVAE scales VAEs to high-res images with hierarchical latent spaces. Diffusion Models can be seen as hierarchical VAEs with thousands of latent steps.
