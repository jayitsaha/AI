1
Understanding FCOS
▼

What is it? FCOS (Fully Convolutional One-Stage Object Detector) is a modern object detection architecture that eliminates the need for predefined "anchor boxes." Instead, it directly predicts bounding boxes and class scores for each pixel location on a feature map, treating object detection as a per-pixel dense prediction task, much like semantic segmentation.

Why anchor-free? Traditional detectors like Faster R-CNN or YOLO rely on a set of predefined anchor boxes with various scales and aspect ratios. This introduces several challenges:

  • Hyperparameter tuning: The number, scales, and aspect ratios of anchors are critical hyperparameters that need careful tuning for different datasets.
  • Complex matching: Determining which ground-truth box an anchor should predict (anchor matching) is a non-trivial heuristic.
  • Computational overhead: Generating and processing thousands of anchors per image adds complexity.
FCOS simplifies the pipeline by removing this anchor-box mechanism entirely.

Analogy: Imagine you're trying to find specific items in a cluttered room. An anchor-based approach is like having a collection of pre-sized boxes (anchors) and trying to fit them over every possible location, then adjusting the best-fitting ones. FCOS, on the other hand, is like walking over every square inch of the floor and asking, "Am I standing on the center of an item? If so, what item is it, and how far are its edges from me?" This direct, per-location approach is both simpler and more intuitive.

💡 If you remember one thing

FCOS transforms object detection from an anchor-refinement problem into a straightforward per-pixel dense prediction task. It predicts a class label and four distances (left, top, right, bottom) from each feature map location to the bounding box boundaries, plus a "center-ness" score to filter low-quality predictions.

2
How FCOS Works Internally
▼

Architecture Overview

FCOS uses a standard backbone (e.g., ResNet) combined with a Feature Pyramid Network (FPN) to extract multi-scale feature maps. These feature maps capture objects at different scales, which is crucial for detecting both small and large objects. Unlike anchor-based methods, FCOS applies small convolutional heads directly to each FPN level.

Per-Pixel Prediction Heads

For each spatial location \((x,y)\) on a feature map at a specific FPN level (with stride \(s\)), FCOS predicts three things:

  1. Classification Scores: A \(C\)-dimensional vector (where \(C\) is the number of object classes) indicating the probability of each class being present at that location. This is typically handled by two convolutional layers followed by a sigmoid activation per class.
  2. Regression Distances: A 4-dimensional vector \((l, t, r, b)\) representing the distances from the current location \((x,y)\) to the left, top, right, and bottom edges of the bounding box that most accurately contains the object centered at \((x,y)\). These are typically positive values.
  3. Center-ness Score: A single scalar value, ranging from 0 to 1, that measures how close the current location \((x,y)\) is to the center of its corresponding ground-truth bounding box. This is crucial for suppressing low-quality bounding box predictions generated by locations far from the object's true center.

Training Target Assignment

During training, a feature map location \((x,y)\) (which maps to a coordinate \((sx, sy)\) in the input image, where \(s\) is the stride of the feature map) is considered a positive sample if it falls inside any ground-truth bounding box. If a location falls into multiple ground-truth boxes, it is assigned to the one with the smallest area (or based on FPN level area ranges) to resolve ambiguity. The regression targets \((l,t,r,b)\) and the center-ness score are then calculated based on this assigned ground-truth box.

Inference and Post-Processing

At inference time, FCOS generates a large number of bounding box predictions. To filter these, the predicted classification score for each box is multiplied by its predicted center-ness score. This operation effectively down-weights bounding boxes predicted by locations far from an object's center, which tend to be of lower quality. Finally, standard Non-Maximum Suppression (NMS) is applied to remove redundant overlapping boxes, yielding the final set of detections.

🔑 Key Property

The center-ness branch is FCOS's secret sauce for anchor-free success. Without it, many low-quality bounding boxes would be predicted from locations near the edges of objects, leading to poor performance. Center-ness dynamically prioritizes predictions from central regions, acting as a soft filter.

3
Why It Works — The Math
▼

Regression Targets

For a given feature map location \((x,y)\) corresponding to an input image coordinate \((x_c, y_c)\), and an assigned ground-truth bounding box \(B = (x_0, y_0, x_1, y_1)\), the regression targets for FCOS are simply the distances from the center of the feature map cell to the four sides of the bounding box:

$$l = x_c - x_0 \quad t = y_c - y_0$$ $$r = x_1 - x_c \quad b = y_1 - y_c$$

These four values \((l,t,r,b)\) are always non-negative. If the point \((x_c, y_c)\) is outside the ground-truth box, then at least one of these values would be negative, which implies it's not a positive sample for that box.

Center-ness Score Calculation

The center-ness score for a location \((x_c, y_c)\) and its corresponding regression targets \((l,t,r,b)\) is defined as:

$$\text{center-ness} = \sqrt{\frac{\min(l,r)}{\max(l,r)} \times \frac{\min(t,b)}{\max(t,b)}}$$

This score is 1 when \((x_c, y_c)\) is exactly at the horizontal and vertical center of the bounding box (i.e., \(l=r\) and \(t=b\)). It approaches 0 as \((x_c, y_c)\) moves towards any of the four borders. This formulation is robust and differentiable, making it suitable for training.

Loss Functions

FCOS uses three main loss components:

  • Classification Loss: Typically Focal Loss, which addresses the extreme foreground-background class imbalance inherent in dense prediction tasks.
  • Regression Loss: Generalized Intersection over Union (GIoU) Loss or IoU Loss, which directly optimizes the overlap between predicted and ground-truth boxes.
  • Center-ness Loss: Binary Cross-Entropy (BCE) Loss, applied only to positive samples, to train the network to accurately predict the center-ness score.
The total loss is a weighted sum of these three components.

⚠️ Ambiguity Resolution

A key challenge in anchor-free detection is handling overlapping ground-truth boxes. If a feature map location falls into multiple boxes, which one should it predict? FCOS resolves this by assigning the location to the ground-truth box with the smallest area. This prioritizes smaller objects and helps prevent ambiguous regression targets.

Key Takeaways
▼

When to use FCOS (and anchor-free methods):

  • When you want to simplify your object detection pipeline by removing anchor-related heuristics and hyperparameters.
  • For datasets with highly varied object scales or aspect ratios where designing optimal anchors is difficult.
  • When computational efficiency and memory usage (due to fewer anchor boxes) are crucial, especially for smaller models or edge devices.
  • As a strong baseline for dense prediction tasks, offering competitive performance with anchor-based methods.

Limitations and considerations:

  • While anchor-free, FCOS still requires Non-Maximum Suppression (NMS) as a post-processing step, which can be a bottleneck.
  • The "center-ness" score is critical; without it, FCOS might produce many low-quality bounding boxes near object boundaries.
  • Ambiguity resolution for overlapping ground-truth boxes (e.g., smallest area assignment) is a heuristic that might not be optimal in all scenarios.
  • Performance is highly dependent on the quality of the Feature Pyramid Network (FPN) and the backbone architecture.
💡 Broader Context

FCOS is part of a larger trend in computer vision towards simpler, more direct approaches to object detection. By framing it as a dense prediction task, FCOS paved the way for other anchor-free methods like CenterNet and CornerNet, demonstrating that anchors are not an indispensable component for high-performance detection.

import numpy as np
# Assume feature_map_coords are (x_f, y_f) from FPN output
# gt_box is [x0, y0, x1, y1] (xmin, ymin, xmax, ymax)
# stride is the downsampling factor of the feature map
def calculate_regression_targets(feature_map_coords, gt_box, stride):
x_f, y_f = feature_map_coords
x_c = (x_f + 0.5) * stride # Center of the feature map cell in input image coords
y_c = (y_f + 0.5) * stride
x0, y0, x1, y1 = gt_box
l = x_c - x0
t = y_c - y0
r = x1 - x_c
b = y1 - y_c
# A point is positive if it's inside the GT box (l,t,r,b > 0)
if l < 0 or t < 0 or r < 0 or b < 0:
return None # Not a positive sample for this GT box
return [l, t, r, b]
def calculate_center_ness(l, t, r, b):
center_ness_x = np.sqrt(np.min([l, r]) / np.max([l, r]))
center_ness_y = np.sqrt(np.min([t, b]) / np.max([t, b]))
return center_ness_x * center_ness_y
def nms(boxes, scores, iou_threshold):
# Simplified NMS (Non-Maximum Suppression)
# boxes: list of [x0, y0, x1, y1]
# scores: list of confidence scores
# Returns indices of boxes to keep
if len(boxes) == 0: return []
x1 = boxes[:, 0]; y1 = boxes[:, 1]; x2 = boxes[:, 2]; y2 = boxes[:, 3]
areas = (x2 - x1 + 1) * (y2 - y1 + 1)
order = scores.argsort()[::-1]
keep = []
while order.size > 0:
i = order[0]
keep.append(i)
xx1 = np.maximum(x1[i], x1[order[1:]])
yy1 = np.maximum(y1[i], y1[order[1:]])
xx2 = np.minimum(x2[i], x2[order[1:]])
yy2 = np.minimum(y2[i], y2[order[1:]])
w = np.maximum(0.0, xx2 - xx1 + 1)
h = np.maximum(0.0, yy2 - yy1 + 1)
inter = w * h
ovr = inter / (areas[i] + areas[order[1:]] - inter)
inds = np.where(ovr <= iou_threshold)[0]
order = order[inds + 1]
return keep
