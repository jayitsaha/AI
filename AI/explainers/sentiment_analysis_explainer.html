Sentiment Analysis: Lexicon-Based vs ML-Based

Two philosophies for deciding whether text is positive, negative, or neutral
Foundational NLP Text Classification O(n) inference
1
Understanding Sentiment Analysis
▼

What is it? Sentiment analysis takes a piece of text — a review, a tweet, a support ticket — and decides whether the writer feels positive, negative, or neutral about something. There are two very different ways to build this: lexicon-based methods that use a dictionary of word scores and hand-written rules, and ML-based methods that learn the scoring rules automatically from labeled examples.

Analogy: A lexicon-based system is like a strict grammar teacher with a rulebook: "good" is worth +3 points, "not" flips the sign of the next sentiment word, "really" multiplies it by 1.5. It applies the same fixed rules to every sentence, no matter the context. An ML-based system is like an experienced editor who has read a million reviews and developed an intuition — she doesn't apply rigid rules, she has learned, from experience, that "not really good, but the acting was brilliant" reads as an overall rave, because she has seen thousands of similar contrastive constructions before.

💡 If you remember one thing

Lexicon-based scoring is a fixed function of word lookups and hand-coded rules: $$\text{score} = \frac{1}{|S|}\sum_{w \in S} m(w)\cdot \ell(w)$$ ML-based scoring is a learned function whose weights come from data: $$p(\text{positive}) = \sigma\Big(\sum_i w_i x_i + b\Big)$$ where \(\ell(w)\) is a hand-written lexicon score, \(m(w)\) a hand-written modifier multiplier, and \(w_i\) are weights learned by gradient descent on labeled data.

2
How Each Approach Works Internally
▼

Lexicon-Based Pipeline

1. Tokenize the sentence into words. 2. Look up each token in a sentiment lexicon (e.g. AFINN, VADER, SentiWordNet) — words not present score 0. 3. Apply modifiers: negators (\(not\), \(never\), \(no\)) within a fixed window flip the sign of the sentiment word that follows; intensifiers (\(really\), \(very\), \(extremely\)) scale its magnitude. 4. Aggregate — sum or average the per-token contributions. 5. Threshold the aggregate score against 0 (or tunable cutoffs) to output Positive / Negative / Neutral.

ML-Based Pipeline

1. Featurize the text — bag-of-words, TF-IDF, n-grams, or dense embeddings from a neural encoder. 2. Score — a model (logistic regression, SVM, LSTM, or fine-tuned Transformer like BERT) combines features with learned weights to produce a logit. 3. Squash the logit through a sigmoid/softmax into a probability. 4. Classify by thresholding the probability. Crucially, the weights for "not", "good", and the bigram "not_good" were never hand-written — they were fit by minimizing a loss function over thousands of labeled reviews, so the model can learn that "not_good" is only mildly negative (people say it as understatement) rather than a full sign flip.

🔑 Key Design Decision

Lexicon rules are interpretable and require zero training data — every score can be traced to a dictionary entry and a rule. ML models are context-sensitive and data-hungry — they discover compositional patterns (negation, sarcasm, contrastive "but" clauses) directly from examples, but need labeled data and are harder to audit token-by-token.

3
Why It Works — The Math
▼

Lexicon Score

For a sentence tokenized into \(S = \{w_1,\dots,w_n\}\), define the lexicon score \(\ell(w)\) (e.g. \(\ell(\text{good})=+3\)), a negation flag \(\nu(w) \in \{-1,+1\}\) determined by whether a negator appears within a window of \(k\) tokens before \(w\), and an intensifier multiplier \(m(w)\) (default 1). The per-token contribution and aggregate score are:

$$c(w) = \nu(w)\cdot m(w)\cdot \ell(w) \qquad\qquad \text{Score}(S) = \frac{1}{|S_{\ell}|}\sum_{w \in S_\ell} c(w)$$

where \(S_\ell \subset S\) is the subset of tokens that actually have a nonzero lexicon entry. This is a deterministic, closed-form computation — no optimization involved.

ML Score (Logistic Regression View)

Represent the sentence as a feature vector \(x \in \mathbb{R}^d\) (word/bigram indicators). The model computes a logit \(z\) and squashes it with the sigmoid \(\sigma\):

$$z = w^\top x + b \qquad\qquad p(\text{positive}\mid x) = \sigma(z) = \frac{1}{1+e^{-z}}$$

The weights \(w\) and bias \(b\) are learned by minimizing binary cross-entropy over a labeled training set \(\{(x^{(i)}, y^{(i)})\}\):

$$\mathcal{L}(w,b) = -\frac{1}{N}\sum_{i=1}^N \Big[y^{(i)}\log \sigma(z^{(i)}) + (1-y^{(i)})\log\big(1-\sigma(z^{(i)})\big)\Big]$$

Gradient descent updates each weight in proportion to how much it contributed to the error: \(\frac{\partial \mathcal{L}}{\partial w_j} = \frac{1}{N}\sum_i (\sigma(z^{(i)}) - y^{(i)})\,x_j^{(i)}\). This is exactly how a feature like the bigram "not_good" ends up with a moderate weight of \(-1.4\) instead of the lexicon's blunt sign-flip of \(-4.5\) — the training data showed that "not good" reviews are still often mixed rather than fully negative.

⚠️ Common Pitfall

Lexicon negation windows are brittle — "not only good but amazing" gets wrongly flipped by a naive fixed-window negator, while "I do not think this was a bad movie" (double negation) confuses simple sign-flip rules entirely. ML models learn these patterns implicitly, but only if the training data contains enough similar examples — they can fail just as badly on out-of-distribution phrasing.

Key Takeaways
▼
Lexicon-BasedML-Based
Training data neededNone (just a dictionary)Thousands of labeled examples
InterpretabilityFully transparent, per-wordOpaque (esp. deep models)
Handles negation/sarcasmOnly via hand-written rulesLearns it if data supports it
Domain adaptationManual — edit the dictionaryRetrain / fine-tune on new domain
Cold-startWorks immediatelyNeeds labels first
Typical accuracyLower, especially on nuanceHigher with enough data

When to use lexicon-based: no labeled data, need instant transparency/auditability, low-resource languages, or as a fast baseline / feature for a larger system.

When to use ML-based: you have (or can get) labeled data, sentiment is nuanced/domain-specific (sarcasm, mixed reviews, contrastive clauses), and accuracy matters more than interpretability.

💡 In Practice

Modern production systems rarely use either in pure form — they often fine-tune a pretrained Transformer (e.g. BERT, RoBERTa) on domain-labeled data, which is ML-based but implicitly captures lexical cues too. Lexicon methods (like VADER) remain popular for quick, dependency-free baselines and for interpretable auditing of model decisions.

Code Trace
▼
sentence = "the movie was not really good but the acting was brilliant"
tokens = sentence.split()
# ── LEXICON-BASED ──
lexicon = {"good": 3, "brilliant": 4, "bad": -3, "terrible": -4}
negators = {"not", "never", "no"}
intensifiers = {"really": 1.5, "very": 1.5, "extremely": 2.0}
def lexicon_score(tokens, window=3):
contribs = []
for i, w in enumerate(tokens):
if w not in lexicon: continue
base = lexicon[w]
ctx = tokens[max(0, i - window):i]
for m in ctx:
if m in intensifiers: base *= intensifiers[m]
if any(n in negators for n in ctx): base *= -1
contribs.append(base)
return sum(contribs) / len(contribs) if contribs else 0.0
# ── ML-BASED (logistic regression) ──
weights = {"not": -0.3, "really": 0.1, "good": 1.8,
"not_good": -1.4, "but": 0.6, "brilliant": 2.6}
bias = -0.4
def ml_score(tokens):
z = bias
for i, w in enumerate(tokens):
if w in weights: z += weights[w]
if w == "good" and "not" in tokens[max(0,i-3):i]:
z += weights["not_good"]
return 1 / (1 + pow(2.71828, -z)) # sigmoid
print(lexicon_score(tokens)) # -0.25 -> Negative (borderline)
print(ml_score(tokens)) # 0.953 -> Positive (95.3%)
