N-BEATS: Basis Expansion & Interpretable Stacks

A deep learning architecture for univariate time series forecasting with built-in interpretability
Intermediate Deep Learning Time Series O(N) inference
1
Understanding N-BEATS
▼

What is it? N-BEATS (Neural Basis Expansion Analysis for Time Series) is a deep neural network architecture specifically designed for univariate (single-variable) time series forecasting. It achieves state-of-the-art accuracy on many benchmarks while offering an optional "interpretable" mode that decomposes forecasts into components like trend and seasonality.

Analogy: Imagine you're forecasting sales, and you have a team of specialized analysts. One analyst is great at spotting long-term trends, another is an expert in weekly and monthly seasonal patterns, and a third is good at capturing everything else. N-BEATS works similarly: it uses a stack of neural network "blocks," where each block focuses on modeling a specific aspect of the time series (like trend or seasonality) or learning a generic representation. They pass the "leftover" signal (the residual) to the next analyst in line, ensuring each one tackles a progressively simpler problem.

💡 If you remember one thing

N-BEATS decomposes a time series into interpretable components (trend, seasonality, etc.) by using specialized blocks. Each block not only forecasts the future but also "backcasts" the past, which is subtracted from the input to create a residual for the next block. This residual learning strategy, combined with basis expansion, makes it powerful and robust.

2
How N-BEATS Works Internally
▼

The Basic Block: Forecast & Backcast

The fundamental building block of N-BEATS is a series of fully-connected (dense) layers. Unlike traditional RNNs or CNNs for time series, N-BEATS avoids sequential processing or explicit convolutions. Instead, each block takes a segment of the time series (the "lookback window") as input and produces two outputs:

  1. A forecast for the future horizon.
  2. A backcast for the historical lookback window.

These outputs are generated via basis expansion: the FC layers output coefficients, which are then multiplied by a set of basis functions (e.g., polynomials for trend, sinusoids for seasonality). This allows the block to reconstruct complex patterns from a small set of coefficients.

Stacks and Residual Connections

Multiple blocks are organized into stacks. The key to N-BEATS's power is its residual learning mechanism:

  • The first block in a stack processes the original time series.
  • It produces a backcast, which is then subtracted from the original input to form a residual.
  • This residual becomes the input for the next block in the stack. This process continues, with each subsequent block learning to forecast the remaining "unexplained" variation in the series.

The final forecast is the sum of all individual forecasts from all blocks in all stacks.

Interpretable vs. Generic Stacks

N-BEATS supports two types of stacks:

  • Generic Stacks: The basis functions are learned by the network itself. This offers maximum flexibility and often leads to high accuracy.
  • Interpretable Stacks: The basis functions are fixed and pre-defined (e.g., polynomial functions for a "trend" stack, Fourier series for a "seasonality" stack). This forces the network to decompose the time series into these human-understandable components, providing interpretability, albeit with potentially less flexibility than generic stacks.
🔑 Key Property

The backcasting mechanism is crucial. By forcing each block to reconstruct the past input, N-BEATS acts as a powerful regularizer, preventing overfitting and making the model more robust to noise and varying time series patterns. It's essentially a self-supervision task that helps the network learn better representations.

Why It Works — The Math
▼

The Core Block Operation

Consider an input time series segment \(x \in \mathbb{R}^{H_b}\) (lookback window) and the desired forecast horizon \(H_f\). A single N-BEATS block, parametrized by \(\theta\), produces backcast coefficients \(c_b\) and forecast coefficients \(c_f\):

$$ (c_b, c_f) = \text{FC}_{\text{layers}}(x; \theta) $$

These coefficients are then used with basis functions \(\phi_b\) and \(\phi_f\) to generate the backcast \(\hat{x}\) and forecast \(\hat{y}\):

$$ \hat{x} = \Phi_b c_b \quad \text{and} \quad \hat{y} = \Phi_f c_f $$

Here, \(\Phi_b \in \mathbb{R}^{H_b \times D_b}\) and \(\Phi_f \in \mathbb{R}^{H_f \times D_f}\) are matrices whose columns are the basis functions evaluated at each time step. \(D_b\) and \(D_f\) are the number of basis functions for backcast and forecast, respectively. For generic stacks, \(\Phi_b\) and \(\Phi_f\) are also learned parameters; for interpretable stacks, they are fixed (e.g., polynomial or sinusoidal matrices).

Residual Learning Across Stacks

Let \(x_0\) be the original input time series. Each stack \(s\) (composed of \(K_s\) blocks) processes a residual. The input to the first block of stack \(s\) is \(x_{s-1}\), which is the original input minus the backcasts from all previous stacks. Within a stack, each block \(k\) processes the residual from the previous block:

$$ x_{s,k} = x_{s,k-1} - \hat{x}_{s,k-1} $$

The overall forecast \(\hat{Y}\) is the sum of all individual forecasts \(\hat{y}_{s,k}\) from all blocks across all stacks:

$$ \hat{Y} = \sum_{s=1}^{N_{\text{stacks}}} \sum_{k=1}^{K_s} \hat{y}_{s,k} $$

The network is trained end-to-end to minimize a forecasting loss (e.g., Mean Squared Error) between \(\hat{Y}\) and the true future values \(Y\).

⚠️ Common Pitfall

The "interpretable" aspect of N-BEATS is only truly present when using fixed basis functions for specific components (e.g., polynomial for trend, Fourier for seasonality). If you use "generic" stacks where the basis functions are learned, the model is still highly effective but loses its direct human interpretability, as the learned basis functions may not correspond to obvious patterns.

Key Takeaways
▼

When to use N-BEATS:

  • For univariate time series forecasting problems where high accuracy is desired.
  • When interpretability of components (trend, seasonality) is valuable, by using interpretable stacks.
  • As an alternative to traditional RNN/CNN-based models, often outperforming them with simpler FC architecture.
  • When you need a model that is robust to varying data patterns due to its residual learning and backcasting.

When NOT to use:

  • For highly multivariate time series where inter-series dependencies are crucial (N-BEATS is primarily univariate).
  • When simpler, less computationally intensive models (e.g., ARIMA, Exponential Smoothing) provide sufficient accuracy.
  • If the time series exhibits extremely long-range dependencies that might exceed the effective receptive field of the blocks/stacks.
  • When computational resources are extremely limited, as deep stacks can still be quite large.
💡 Big Picture

N-BEATS is a testament to the power of simple, fully-connected layers when combined with clever architectural choices like basis expansion and residual learning. Its ability to achieve state-of-the-art results without complex recurrent or convolutional structures highlights that effective decomposition and ensemble-like stacking can be more critical than complex individual "neuron" types.

import torch
import torch.nn as nn
class NBEATSBlock(nn.Module):
def __init__(self, hidden_dim, num_layers, lookback, horizon, basis_fn_type='generic'):
super().__init__()
self.fc_stack = nn.Sequential(
*[nn.Linear(lookback if i==0 else hidden_dim, hidden_dim) for i in range(num_layers)],
nn.ReLU()
)
# Output layers for basis coefficients
self.backcast_coeffs = nn.Linear(hidden_dim, num_basis_backcast)
self.forecast_coeffs = nn.Linear(hidden_dim, num_basis_forecast)
# Basis functions (fixed for interpretable, learned for generic)
if basis_fn_type == 'trend':
self.basis_backcast = self._get_polynomial_basis(lookback) # Fixed polynomial
self.basis_forecast = self._get_polynomial_basis(horizon)
elif basis_fn_type == 'seasonality':
self.basis_backcast = self._get_fourier_basis(lookback) # Fixed sinusoidal
self.basis_forecast = self._get_fourier_basis(horizon)
else: # 'generic'
self.basis_backcast = nn.Parameter(torch.randn(num_basis_backcast, lookback)) # Learnable
self.basis_forecast = nn.Parameter(torch.randn(num_basis_forecast, horizon))
def forward(self, x):
x = self.fc_stack(x)
# Compute coefficients
c_back = self.backcast_coeffs(x)
c_fore = self.forecast_coeffs(x)
# Basis expansion
backcast = torch.matmul(c_back, self.basis_backcast)
forecast = torch.matmul(c_fore, self.basis_forecast)
return backcast, forecast
class NBEATSStack(nn.Module):
def __init__(self, num_blocks, block_params):
super().__init__()
self.blocks = nn.ModuleList([NBEATSBlock(**block_params) for _ in range(num_blocks)])
def forward(self, x_input):
block_forecasts = []
current_residual = x_input
for block in self.blocks:
backcast, forecast = block(current_residual)
current_residual = current_residual - backcast # Residual connection
block_forecasts.append(forecast)
return torch.sum(torch.stack(block_forecasts), dim=0), current_residual
# Main N-BEATS Model (simplified for clarity)
class NBEATS(nn.Module):
def __init__(self, lookback, horizon, num_stacks, blocks_per_stack, hidden_dim):
super().__init__()
self.stacks = nn.ModuleList()
for i in range(num_stacks):
# Example: alternating generic and interpretable stacks
basis_type = 'generic' if i % 2 == 0 else 'trend'
self.stacks.append(NBEATSStack(blocks_per_stack, {
'hidden_dim': hidden_dim, 'num_layers': 4,
'lookback': lookback, 'horizon': horizon, 'basis_fn_type': basis_type
}))
def forward(self, x_input):
total_forecast = 0
current_input = x_input
for stack in self.stacks:
forecast_from_stack, _ = stack(current_input)
total_forecast += forecast_from_stack
# In a full N-BEATS, total_forecast would accumulate and residual would pass
# For simplicity here, we assume one large stack for visualization.
return total_forecast
