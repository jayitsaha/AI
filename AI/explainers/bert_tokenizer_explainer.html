Understanding WordPiece
▼

What is it? WordPiece is the subword tokenization algorithm used by BERT and its relatives. Rather than treating every unique word as one indivisible token (a vocabulary explosion, and every unseen word becomes [UNK]) or breaking text down to raw characters (tiny vocabulary, but sequences become very long and lose lexical structure), WordPiece finds a middle ground: it splits rare or complex words into a small number of meaningful, reusable subword units drawn from a fixed vocabulary of roughly 30,000 entries.

Analogy: Imagine a box of Scrabble tiles where, alongside single letters, some tiles carry whole common fragments — "ing", "un", "able", "token". To spell "unwanted" you would not necessarily reach for eight single-letter tiles; you would reach for "un" + "##want" + "##ed". The ## marker on a tile means "this piece continues the previous one, it doesn't start a new word." WordPiece always reaches for the longest tile that fits before shrinking down.

If you remember one thing

WordPiece tokenizes with a greedy longest-match-first strategy: for each whitespace-delimited word, starting from position 0, try the longest remaining substring against the vocabulary; if it's not found, shrink by one character and try again; once a match is found, consume it, prefix everything after the first piece with ##, and repeat on the remainder. If no prefix of the remainder matches anything at all, the whole word becomes [UNK].

How WordPiece Works Internally
▼

The Full BERT Tokenization Pipeline

BERT's tokenizer is a two-stage pipeline. First, the BasicTokenizer normalizes the text: lowercasing (for uncased models), Unicode/accent stripping, whitespace collapsing, and splitting punctuation off into its own tokens. Second, the WordpieceTokenizer takes each whitespace-delimited word from that output and greedily decomposes it into vocabulary subwords.

The Greedy Longest-Match Algorithm, Precisely

For a word like "unwanted", the algorithm sets start = 0 and tries the substring from start to the end of the word first: "unwanted" (8 chars) — not in the vocabulary. It shrinks the end by one character and tries "unwante", then "unwant", and so on, until it reaches "un" (2 chars), which is in the vocabulary. That becomes the first token. The scan resumes at start = 2 on the remainder "wanted", this time prefixing every candidate with ## (since it's mid-word): "##wanted", "##wante", "##want" — found. Then the remainder "ed" matches "##ed" directly. Final result: ["un", "##want", "##ed"].

The ## Prefix Convention

The ## marker distinguishes word-initial tokens from continuation tokens as separate vocabulary entries with separate learned embeddings. "play" (a standalone word) and "##play" (mid-word, as in "dis-play") are different rows of the embedding matrix — this lets the model learn that a subword's meaning shifts depending on whether it starts a word or continues one.

Key Design Decision

bert-base-uncased ships with a vocabulary of 30,522 tokens. This sits between character-level models (tiny vocab, very long sequences, weak per-token semantics) and word-level models (huge vocab, many out-of-vocabulary words). With ~30K subwords, BERT represents virtually any English text with zero or near-zero [UNK] tokens while keeping sequences compact enough for quadratic self-attention to stay tractable.

Special Tokens

Every input is wrapped with reserved tokens: [CLS] (ID 101) prepended — its final hidden state becomes the pooled sequence representation used for classification — and [SEP] (ID 102) appended to mark a sequence boundary; a second [SEP] separates sentence pairs for tasks like QA or NLI. Also reserved: [PAD]=0 for batch padding and [UNK]=100 for anything unmatched.

The Math Behind WordPiece
▼

The tokenizer applies WordPiece greedily at inference time using a vocabulary that was fixed during training. That vocabulary itself is built once, offline, using a likelihood-based merge objective — this is the part that is easy to conflate with BPE, but is mathematically different.

Vocabulary Construction Objective

Starting from individual characters as the initial vocabulary, WordPiece training repeatedly merges the symbol pair \((a, b)\) that maximizes the increase in the likelihood of the training corpus under a unigram language model built from the current vocabulary. This reduces to choosing, at each step, the pair that maximizes:

$$\text{score}(a, b) = \frac{\text{count}(ab)}{\text{count}(a) \times \text{count}(b)}$$

This is a pointwise mutual information (PMI) criterion: merge symbols that co-occur far more often than their individual frequencies alone would predict. A pair like "t"+"h" gets merged early because "th" is vastly more common than chance co-occurrence of independent "t" and "h" tokens would suggest.

Tokenization-Time Complexity

For a single word of length \(n\), the greedy scan tries decreasing prefix lengths starting from \(n\) at each of up to \(n\) start positions in the worst case, giving \(O(n^2)\) character comparisons. With hash-based vocabulary lookup at \(O(1)\) amortized per candidate, and because most real words match after only a handful of shrink steps, average-case performance is close to linear in practice. HuggingFace's implementation additionally caps max_input_chars_per_word (default 100) and immediately emits [UNK] beyond that, bounding worst-case cost per word.

WordPiece vs BPE — Not the Same Algorithm

WordPiece is not Byte Pair Encoding. BPE's training merges the most frequent adjacent pair at each step and then, at tokenization time, replays those merge rules in the order they were learned. WordPiece's training merges the pair maximizing the likelihood/PMI score above, and at tokenization time does not replay merge rules at all — it does greedy longest-match lookup directly against the final vocabulary, discarding the merge order entirely. GPT-2/3/4 and RoBERTa use BPE; BERT and ELECTRA use WordPiece.

Key Takeaways & Comparisons
▼

When to Use WordPiece

WordPiece is the default for BERT-family encoders: BERT, DistilBERT, ELECTRA, MobileBERT. If you fine-tune any of these, you must use the matching WordPiece tokenizer and vocabulary file — the vocabulary indices are baked into the pretrained embedding matrix, so a mismatched vocabulary silently corrupts every input.

Decision Guide

Use WordPiece when working with a BERT-family encoder — the choice isn't really yours, it comes with the pretrained checkpoint. Use BPE for GPT-family decoders. Use Unigram/SentencePiece for multilingual or language-agnostic setups where you can't assume whitespace-delimited words. All three solve the same underlying tension: balancing vocabulary size against sequence length while driving out-of-vocabulary tokens toward zero.

def wordpiece_tokenize(word, vocab, max_chars=100):
if len(word) > max_chars:
return ['[UNK]']
tokens, start = [], 0
while start < len(word):
end = len(word)
cur = None
while start < end: # shrink from longest
sub = word[start:end]
if start > 0:
sub = '##' + sub # continuation marker
if sub in vocab:
cur = sub
break # greedy: take longest match
end -= 1
if cur is None:
return ['[UNK]']
tokens.append(cur)
start = end
return tokens
