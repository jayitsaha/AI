BERT Tokenizer: WordPiece

Greedy longest-match-first subword segmentation, trained by likelihood — not raw frequency
Foundational NLP Tokenization O(n²) worst case
1
Understanding WordPiece
▼

What is it? Before a neural network can read text, the text must become numbers. WordPiece is the algorithm BERT uses to chop words into a fixed vocabulary of ~30,000 subword pieces so that any input — even a word the model has never seen — can always be represented. Common words stay whole ("play"); rare or unseen words get split into familiar fragments ("unaffordable" → "un" + "##afford" + "##able"). The ## prefix marks a piece that continues the previous one rather than starting a new word.

Analogy: Imagine a box of alphabet-soup magnets that also contains a few thousand pre-glued common syllables ("un-", "-ing", "-tion"). To spell any word, you first look for the largest ready-made chunk from the left, snap it down, then keep grabbing the next-largest chunk for what's left. You almost never fall back to single letters, but you always can — so no word is ever unspellable.

💡 If you remember one thing

WordPiece tokenization is greedy longest-match-first against a fixed vocabulary: at each position, take the longest prefix of the remaining text that exists in the vocab, mark continuations with ##, and repeat. If no prefix matches at all, the whole word becomes [UNK].

2
How It Works Internally
▼

Two Separate Phases

WordPiece has a training phase (done once, offline, on a huge corpus) and an inference phase (done every time you tokenize a sentence). Training builds the vocabulary; inference just looks pieces up in it. BERT ships with the vocabulary already built — you almost never retrain it — but understanding both halves explains why the pieces look the way they do.

Training: Building the Vocabulary

Start with every individual character as a token. Repeatedly merge the pair of adjacent symbols \((a,b)\) that gives the biggest boost to the training corpus's likelihood under a unigram language model, and add the merged symbol \(ab\) to the vocabulary. This continues until the vocabulary reaches a target size (30,000 for BERT-base). Non-word-initial merged pieces are marked with ## so the detokenizer knows where word boundaries were.

Inference: Greedy Longest-Match-First

Given a word and the frozen vocabulary, start a pointer at position 0. Try the longest substring from the pointer to the end of the word; if it's in the vocabulary, emit it as a token and move the pointer past it (every emission after the first is prefixed with ##). If the longest substring isn't found, shrink the window by one character from the right and try again. Repeat until a match is found or the window shrinks to nothing — in which case the entire word is replaced by [UNK].

🔑 Design decision: why not BPE's raw frequency?

Byte-Pair Encoding (BPE) merges whichever adjacent pair is simply most frequent. WordPiece instead merges the pair that most increases the likelihood of the training data, which naturally discounts pairs that are frequent only because their parts are individually common (like "the" + "e"). This produces a vocabulary tuned for language-modeling quality, not just compression.

3
Why It Works — The Math
▼

Likelihood-Based Merge Criterion

Treat the training corpus as a sequence of symbols drawn i.i.d. from a unigram vocabulary \(V\), where symbol \(s\) has empirical probability \(P(s) = \text{count}(s) / N\). The log-likelihood of the corpus under this model is:

$$\log \mathcal{L}(V) = \sum_{s \in \text{corpus}} \log P(s)$$

Merging two adjacent symbols \(a, b\) into a new symbol \(ab\) changes the likelihood only for the occurrences where \(a\) is immediately followed by \(b\). Schuster & Nakajima (2012) show that the change in log-likelihood from merging \((a,b)\) is maximized by picking the pair with the highest pointwise mutual-information-like score:

$$\text{score}(a,b) = \frac{\text{count}(ab)}{\text{count}(a)\cdot \text{count}(b)}$$

Intuitively: a pair scores high when it co-occurs far more than you'd expect from its parts' individual frequencies — i.e. \(a\) and \(b\) are not independent. This is exactly why "un" + "able" scores lower than "un" + "known" style pairs that behave as a genuine unit, even if the former is more frequent in raw counts.

Longest-Match Is a Greedy Approximation

Finding the segmentation of a word into vocabulary pieces that maximizes total likelihood is, in general, a shortest-path problem over an exponential number of segmentations. WordPiece sidesteps this with a greedy heuristic — always take the longest valid prefix — which is \(O(n^2)\) per word in the worst case (trying up to \(n\) window sizes at up to \(n\) positions) but runs in practice close to \(O(n)\) because most matches are found within a few characters.

⚠️ Common pitfall

Greedy longest-match is not guaranteed optimal. It can commit to a long prefix early that forces an ugly, high-[UNK]-risk split later, even when a different (shorter first-piece) segmentation would have covered the whole word with valid pieces. This tradeoff is accepted because greedy matching is deterministic and fast — essential for tokenizing billions of tokens during pretraining.

Key Takeaways
▼

When WordPiece shines:

  • Open-vocabulary text — no word is ever truly "unknown," it degrades gracefully into subwords
  • Morphologically rich languages where prefixes/suffixes ("un-", "-ing", "-tion") recur across many words
  • Keeping vocabulary size fixed and small (~30K) regardless of corpus size, which bounds embedding-table memory

Limitations:

  • Greedy matching can produce awkward splits that a global-optimum search would avoid
  • Tokenization is not injective — the same surface word can only ever segment one way, ignoring context or sense
  • Newer models (GPT family) mostly use byte-level BPE instead, which needs no [UNK] fallback at all since it operates on raw bytes
💡 Hierarchy of subword tokenizers

Character-level (always covers everything, long sequences) → WordPiece (likelihood-merged, greedy longest-match, ## markers, used by BERT) → BPE (frequency-merged, used by GPT-2/RoBERTa) → Unigram LM / SentencePiece (probabilistic, used by T5/ALBERT, allows multiple valid segmentations).

Code Trace
▼
def wordpiece_tokenize(word, vocab):
"""Greedy longest-match-first, same as BERT's tokenizer."""
chars = list(word)
tokens = []
start = 0
while start < len(chars):
end = len(chars)
matched = None
while start < end:
piece = "".join(chars[start:end])
if start > 0:
piece = "##" + piece # continuation marker
if piece in vocab: # O(1) hash lookup
matched = piece
break
end -= 1 # shrink window, retry
if matched is None:
return ["[UNK]"] # no valid segmentation
tokens.append(matched)
start = end
return tokens
# Production usage (HuggingFace)
from transformers import BertTokenizer
tok = BertTokenizer.from_pretrained("bert-base-uncased")
tok.tokenize("unaffordable")
# -> ['una', '##ffor', '##da', '##ble'] (real BERT vocab, 30K pieces)
