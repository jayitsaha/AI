Understanding WordPiece
▼

What is it? WordPiece is a subword tokenization algorithm used by BERT and other transformer models. Instead of treating every unique word as a separate token (which creates an enormous vocabulary) or breaking text into individual characters (which loses meaning), WordPiece finds a middle ground: it splits words into meaningful subword units from a fixed vocabulary of about 30,000 entries.

Analogy: Imagine you have a set of Scrabble tiles, but instead of single letters, some tiles carry common letter combinations like "ing", "un", "play", or "ed". To spell "unplayable", you would pick tiles: "un" + "play" + "##able". The ## prefix tells you this piece continues the previous one rather than starting a new word. WordPiece works the same way — it greedily picks the longest matching tile at each position.

If you remember one thing

WordPiece uses a greedy longest-match-first strategy: for each word, it finds the longest prefix in the vocabulary, consumes it, then continues with the remainder (prefixed by ##) until the entire word is consumed. Characters not in any vocabulary entry become [UNK].

How WordPiece Works Internally
▼

The Full BERT Tokenization Pipeline

BERT tokenization is a multi-stage pipeline. First, the BasicTokenizer handles normalization: lowercasing (for uncased models), Unicode cleanup, whitespace splitting, and punctuation separation. Then the WordPieceTokenizer takes each whitespace-delimited word and splits it into subword tokens using the greedy algorithm.

The Greedy Longest-Match Algorithm

For a word like "embeddings", WordPiece scans the vocabulary for the longest matching prefix. Suppose the vocab contains "embed", "##ding", "##dings", "##s". The algorithm tries "embeddings" (not found), then "embedding" (not found), keeps shrinking until "embed" (found!). It takes "embed" and repeats on the remainder "dings" with ## prefix: tries "##dings" (found!). Result: ["embed", "##dings"].

The ## Prefix Convention

The ## marker distinguishes word-initial tokens from continuation tokens. "play" as a standalone word and "##play" as part of "display" are different vocabulary entries with different learned embeddings. This lets the model learn that word-initial subwords carry different semantics from mid-word subwords.

Key Design Decision

BERT uses a vocabulary of ~30,000 tokens (30,522 for bert-base-uncased). This balances character-level models (tiny vocab, very long sequences) against word-level models (huge vocab, many OOV words). With 30K subwords, BERT can represent virtually any English text with no [UNK] tokens while keeping sequences compact.

Special Tokens

BERT wraps every input with special tokens: [CLS] at the start (its final hidden state becomes the sequence representation for classification) and [SEP] at the end (marks sentence boundaries). For sentence pairs, a second [SEP] separates them. Reserved IDs: [PAD]=0, [UNK]=100, [CLS]=101, [SEP]=102.

The Math Behind WordPiece
▼

While BERT's tokenizer applies WordPiece greedily at inference time, the vocabulary itself is trained using a likelihood-based objective. Starting from individual characters, the algorithm iteratively merges symbol pairs.

Vocabulary Construction Objective

At each step, WordPiece selects the pair \((a, b)\) that maximizes:

$$\text{score}(a, b) = \frac{\text{freq}(ab)}{\text{freq}(a) \times \text{freq}(b)}$$

This is a pointwise mutual information (PMI) criterion: merge pairs that co-occur far more often than chance predicts. The pair "th" appears far more often than the product of individual "t" and "h" frequencies would suggest, so it gets merged early.

Tokenization Complexity

For a word of length \(n\), the greedy algorithm tries decreasing prefix lengths at each position, giving \(O(n^2)\) worst case. In practice with hash-based vocabulary lookup at \(O(1)\) per check, and since most prefixes match quickly, average performance is nearly linear.

WordPiece vs BPE

WordPiece is not the same as BPE (Byte Pair Encoding). BPE merges the most frequent pair at each step; WordPiece merges the pair maximizing likelihood (the PMI score above). BPE is used by GPT; WordPiece by BERT. At tokenization time, BPE applies learned merge rules sequentially, while WordPiece does greedy longest-match against the final vocabulary.

Key Takeaways & Comparisons
▼

When to Use WordPiece

WordPiece is the default for BERT-family models: BERT, DistilBERT, ELECTRA, and many encoder-based transformers. If you are fine-tuning any of these, you must use the corresponding WordPiece tokenizer — the vocabulary is baked into the pretrained embedding matrix.

Decision Guide

Use WordPiece with BERT-family encoders. Use BPE with GPT-family decoders. Use Unigram/SentencePiece for multilingual or language-agnostic models. All three solve the same core problem: balancing vocabulary size against sequence length while eliminating out-of-vocabulary tokens.
