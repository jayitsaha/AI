Understanding Change Point Detection
▼

What is it? Change point detection (CPD) is the task of identifying times when the statistical properties of a time series (like mean, variance, or trend) abruptly change. These "change points" indicate shifts in underlying behavior, system state, or data generating process.

Analogy: Imagine monitoring a patient's heart rate. For most of the day, it's stable. Then, suddenly, it jumps and stays elevated. A change point detection algorithm would flag the exact moment of that jump. Other examples include detecting fraud in financial transactions, identifying system failures in sensor data, or segmenting speech signals.

💡 If you remember one thing

CPD algorithms aim to partition a time series into segments, where each segment is statistically homogeneous. This is often framed as minimizing a cost function (e.g., how well a segment fits a model) plus a penalty for each additional change point, balancing fit and model complexity.

2
How CPD Algorithms Work
▼

The General Problem: Optimal Partitioning

Given a time series \(X = (x_1, \dots, x_T)\), we want to find a set of change points \(\{t_1, \dots, t_k\}\) (where \(0 < t_1 < \dots < t_k < T\)) that partition \(X\) into \(k+1\) segments. The goal is to minimize a total cost function:

$$\sum_{j=0}^k \operatorname{Cost}(x_{t_j+1}, \dots, x_{t_{j+1}}) + \beta \cdot k$$

Here, \(\operatorname{Cost}\) measures how well a segment fits a model (e.g., squared error for a constant mean), and \(\beta\) is a penalty for each change point, preventing overfitting (too many segments).

PELT (Pruned Exact Linear Time)

PELT is an efficient offline algorithm for exact change point detection. It's based on dynamic programming, but with a crucial pruning step that dramatically reduces its computational complexity from quadratic to near-linear (\(O(T \log T)\) or \(O(T)\) in practice). It guarantees finding the global optimum for a given cost and penalty. The core idea is to recursively find the optimal last change point for each prefix of the series.

Bayesian Online Changepoint Detection (BOCPD)

Unlike PELT, BOCPD is an online algorithm, meaning it processes data sequentially and can detect change points as they occur, without needing the entire time series. It maintains a probability distribution over the "run length" (how long the current segment has been active without a change point). When this distribution shifts towards shorter run lengths, it signals a high probability of a change point. BOCPD is probabilistic, providing a measure of uncertainty.

The ruptures Library

The `ruptures` library in Python provides state-of-the-art implementations of various change point detection algorithms, including PELT, BOCPD, Binary Segmentation, Window-based methods, and more. It offers a unified API for different cost functions (e.g., 'l2' for mean changes, 'rbf' for distribution changes, 'normal' for Gaussian models) and penalty types.

🔑 Key Distinction

PELT is an offline (batch) algorithm: it needs all data upfront, but finds the globally optimal set of change points. BOCPD is an online algorithm: it processes data sequentially, making real-time predictions, but is typically approximate.

3
Why It Works — The Core Math
▼

PELT: Dynamic Programming with Pruning

Let \(F(t)\) be the minimum cost of segmenting the series up to time \(t\). The dynamic programming recurrence for PELT is:

$$F(t) = \min_{0 \le s < t} \left[ F(s) + \operatorname{Cost}(x_{s+1}, \dots, x_t) + \beta \right]$$

A naive computation of this recurrence for all \(t\) takes \(O(T^2)\) time. PELT introduces a pruning rule: if for a given \(t\), there exist two candidate change points \(s_1 < s_2\), and \(F(s_1) + \operatorname{Cost}(x_{s_1+1}, \dots, x_t) \ge F(s_2) + \operatorname{Cost}(x_{s_2+1}, \dots, x_t)\) for all future \(t'\), then \(s_1\) can be pruned. More generally, if for a candidate \(s\), for any \(s' < s\), if \(F(s') + \operatorname{Cost}(x_{s'+1}, \dots, x_t) \ge F(s) + \operatorname{Cost}(x_{s+1}, \dots, x_t) + \nu\) (where \(\nu\) is a small constant related to the cost function), then \(s'\) can be removed from consideration for future \(t\). This pruning is what makes PELT efficient.

BOCPD: Recursive Bayesian Inference

BOCPD tracks the probability of the current "run length" \(r_t\), which is the number of time steps since the last change point. It uses a recursive update for \(P(r_t | x_{1:t})\):

$$P(r_t | x_{1:t}) = \frac{P(x_t | r_t, x_{1:t-1}) \cdot P(r_t | x_{1:t-1})}{P(x_t | x_{1:t-1})}$$

The prior \(P(r_t | x_{1:t-1})\) is derived from the previous run length distribution and a "hazard function" \(H(r)\) that gives the probability of a change point at run length \(r\). Typically, \(H(r) = 1/\lambda\) (constant hazard rate). The predictive distribution \(P(x_t | r_t, x_{1:t-1})\) is estimated from the data within the current segment. When a change point occurs, the probability mass shifts to \(r_t=0\), indicating a new segment.

$$P(r_t=0 | x_{1:t-1}) = \sum_{r_{t-1}} P(\text{change} | r_{t-1}) P(r_{t-1} | x_{1:t-1})$$

And for \(r_t > 0\), it's \(P(r_t | x_{1:t-1}) = P(\text{no change} | r_{t-1}=r_t-1) P(r_{t-1}=r_t-1 | x_{1:t-1})\).

⚠️ Parameter Sensitivity

Both PELT's \(\beta\) (penalty) and BOCPD's hazard rate \(\lambda\) are critical hyper-parameters. A poorly chosen \(\beta\) can lead to too many or too few change points for PELT. For BOCPD, a low \(\lambda\) makes it slow to react to changes, while a high \(\lambda\) can lead to false positives. These parameters often require careful tuning or domain knowledge.

Key Takeaways
▼

When to use which algorithm:

  • PELT: Ideal for offline analysis where the entire time series is available. It guarantees finding the optimal partition for a given cost and penalty, making it suitable for retrospective analysis (e.g., historical data segmentation).
  • BOCPD: Best for online, real-time detection. It can process data incrementally and flag changes as they occur, crucial for monitoring systems (e.g., anomaly detection, patient monitoring).
  • `ruptures` library: A robust choice for practical applications, offering a wide range of algorithms and cost functions for various data types and change point patterns.

Limitations and considerations:

  • Parameter Tuning: Both algorithms require careful tuning of their respective penalty/hazard parameters (\(\beta\) for PELT, \(\lambda\) for BOCPD). This often involves cross-validation or domain expertise.
  • Cost Function Choice: The choice of cost function (e.g., 'l2' for mean shifts, 'rbf' for distribution changes) is crucial and depends on the type of change you expect.
  • Computational Cost: While PELT is near-linear, it can still be slow for extremely long time series or complex cost functions. BOCPD's online nature makes its per-step cost low, but its memory footprint can grow if not managed.
💡 Practical Tip

Always start with visualizing your time series data. Understanding the nature of the changes (abrupt vs. gradual, mean vs. variance, single vs. multiple) will guide your choice of algorithm and hyper-parameters. The `ruptures` library is an excellent starting point for experimentation.

Code Trace (Python ruptures library)
▼
import ruptures as rpt
import numpy as np
# 1. Generate synthetic data
n_samples, dim = 500, 1
n_bkps = 3 # Number of true change points
signal, bkps_true = rpt.pw_constant(n_samples, dim, n_bkps, noise_std=1.0)
# 2. PELT (Pruned Exact Linear Time)
algo_pelt = rpt.Pelt(model="l2", jump=1, min_size=1).fit(signal)
penalty_pelt = 30 # Hyperparameter: penalty for each change point
bkps_pelt = algo_pelt.predict(pen=penalty_pelt)
# Note: ruptures returns (k+1) indices, where k is number of CPs.
# The last index is n_samples. Remove it for actual change points.
bkps_pelt = bkps_pelt[:-1]
# 3. Bayesian Online Changepoint Detection (BOCPD)
# For BOCPD, we need to manually iterate through the signal
algo_bocpd = rpt.BayesianOnline(model="normal")
hazard_bocpd = 100 # Hyperparameter: expected length of a segment
bkps_bocpd = []
for i in range(n_samples):
algo_bocpd.update(signal[i], hazard_bocpd)
# A change point is detected when the probability of r=0 (new segment) is high
# This is a simplification; actual detection involves thresholding a score
if algo_bocpd.rt.argmax() == 0 and i > 0: # If most likely run length is 0
bkps_bocpd.append(i)
print(f"True change points: {bkps_true[:-1]}")
print(f"PELT detected: {bkps_pelt}")
print(f"BOCPD detected: {bkps_bocpd}")
