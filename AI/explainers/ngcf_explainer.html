NGCF: High-Order Connectivity

Neural Graph Collaborative Filtering for deep representation learning on user-item graphs
Intermediate Deep Learning Recommender Systems O(L * |E|)
1
Understanding NGCF
▼

What is it? Neural Graph Collaborative Filtering (NGCF) is a recommendation model that explicitly propagates embedding information over the user-item interaction graph to capture "high-order connectivity." Traditional collaborative filtering (e.g., matrix factorization) models direct user-item interactions. NGCF goes further by modeling indirect connections: users who interact with similar items, or items interacted with by similar users, and so on, through multiple "hops" on the graph.

Analogy: Imagine you want to recommend movies. A simple system looks at movies you've watched. A slightly better one also considers movies watched by people who watched the same movies as you (1st-order connection). An even better one considers movies watched by people who watched movies that were similar to movies watched by people who watched the same movies as you (2nd-order connection). NGCF systematically explores these increasingly indirect connections to build richer user and item representations.

💡 If you remember one thing

NGCF learns user and item embeddings by iteratively propagating and aggregating messages across the bipartite user-item interaction graph. Each propagation layer captures higher-order connectivity, enriching the embeddings with information from increasingly distant neighbors. The final embedding for a user or item is a concatenation of its representations from all layers.

2
How NGCF Works Internally
▼

The User-Item Interaction Graph

NGCF starts by representing users and items as nodes in a bipartite graph. An edge exists between a user node and an item node if the user has interacted with that item (e.g., watched, purchased, rated). Each user \(u\) and item \(i\) is initialized with a latent embedding vector, \(e_u^{(0)}\) and \(e_i^{(0)}\).

Message Propagation Layers

The core of NGCF is its layered propagation structure. For each layer \(k \in \{0, \dots, L-1\}\), embeddings are updated in two steps:

  1. Message Construction: For each edge \((u, i)\), a message is constructed from node \(j\)'s embedding to node \(p\)'s embedding (where \(j\) is a neighbor of \(p\)). This message captures the interaction between \(e_j^{(k)}\) and \(e_p^{(k)}\). The original NGCF paper uses a specific interaction function.
  2. Message Aggregation: Each node \(p\) aggregates all messages it receives from its neighbors to form its next-layer embedding \(e_p^{(k+1)}\). This aggregation is typically a sum, followed by a non-linear activation (e.g., ReLU). Crucially, the node also incorporates its own embedding from the previous layer, \(e_p^{(k)}\), ensuring self-connection.

After \(L\) layers, each node has \(L+1\) embeddings: \(e_p^{(0)}, e_p^{(1)}, \dots, e_p^{(L)}\). Each \(e_p^{(k)}\) captures information from neighbors up to \(k\) hops away.

Final Embedding and Prediction

To get a comprehensive representation, the embeddings from all layers are concatenated for each user and item:

$$e_u^* = \text{concat}(e_u^{(0)}, e_u^{(1)}, \dots, e_u^{(L)})$$
$$e_i^* = \text{concat}(e_i^{(0)}, e_i^{(1)}, \dots, e_i^{(L)})$$

These concatenated embeddings \(e_u^*\) and \(e_i^*\) are then used to predict the user's preference for an item, typically via a simple inner product: \(\hat{r}_{ui} = (e_u^*)^\top e_i^*\).

🔑 Key Property

The explicit modeling of high-order connectivity allows NGCF to capture nuanced collaborative signals that are missed by models only considering direct interactions. For example, if User A interacts with Item X, and User B interacts with Item X and Item Y, then a 2nd-order connection exists between User A and Item Y (via Item X and User B).

3
Why It Works — The Math
▼

Propagation Rule for Layer \(k+1\)

Let \(e_u^{(k)}\) and \(e_i^{(k)}\) be the embeddings of user \(u\) and item \(i\) at layer \(k\). NGCF defines the message passing from a neighbor \(j\) to node \(p\) as:

$$m_{j \to p}^{(k)} = \mathcal{W}_1 e_j^{(k)} + \mathcal{W}_2 (e_j^{(k)} \odot e_p^{(k)})$$

where \(\odot\) denotes the element-wise product, and \(\mathcal{W}_1, \mathcal{W}_2\) are trainable weight matrices. This message explicitly models the interaction between the embeddings. After generating messages from all neighbors, node \(p\) aggregates them to update its embedding:

$$e_p^{(k+1)} = \text{ReLU}\left( \mathcal{W}_0 e_p^{(k)} + \sum_{j \in \mathcal{N}_p} \frac{1}{\sqrt{|\mathcal{N}_p||\mathcal{N}_j|}} m_{j \to p}^{(k)} \right)$$

Here, \(\mathcal{N}_p\) denotes the set of neighbors of node \(p\), and \(\frac{1}{\sqrt{|\mathcal{N}_p||\mathcal{N}_j|}}\) is a symmetric normalization term (similar to GCNs) that prevents large degree nodes from dominating. \(\mathcal{W}_0\) is another trainable weight matrix for the self-connection. The ReLU activation introduces non-linearity.

Final Embedding Representation

The key to capturing high-order information is the concatenation of embeddings from all layers. For a user \(u\), the final embedding \(e_u^*\) is:

$$e_u^* = e_u^{(0)} \Vert e_u^{(1)} \Vert \dots \Vert e_u^{(L)}$$

This means \(e_u^*\) simultaneously contains features learned from direct interactions (0-order, \(e_u^{(0)}\)), 1-hop neighbors (\(e_u^{(1)}\)), 2-hop neighbors (\(e_u^{(2)}\)), and so on, up to \(L\) hops. This rich, multi-perspective representation allows the model to learn more expressive preferences and item characteristics.

⚠️ Computational Cost

While powerful, NGCF's message passing incurs a computational cost proportional to the number of edges and layers. For very large graphs or many layers, this can be expensive. Simplifications like LightGCN (which removes the transformation matrices \(\mathcal{W}\) and non-linearities, keeping only the aggregation) aim to reduce this cost while retaining much of the performance benefits.

Key Takeaways
▼

When to use NGCF:

  • When your recommendation problem can be naturally modeled as a user-item interaction graph.
  • When capturing complex, indirect relationships between users and items is crucial for performance.
  • For datasets with sparse interactions, where leveraging high-order connectivity can help alleviate the cold-start problem and enrich representations for less-interacted entities.
  • As a strong baseline for graph neural network-based recommender systems.

Limitations & Alternatives:

  • Computational Cost: As discussed, message passing can be expensive. This led to simplified variants.
  • Over-smoothing: Too many layers (\(L\)) can lead to embeddings becoming indistinguishable, hurting performance. Finding the optimal \(L\) is important.
  • LightGCN: A popular simplification that removes non-linearities and weight matrices from the propagation layers, making it faster and sometimes more effective by focusing purely on graph structure.
  • Self-Supervised GNNs: Newer approaches combine graph propagation with self-supervised learning tasks (e.g., contrastive learning) to further enhance representation quality.
💡 Impact

NGCF was a pivotal model in popularizing Graph Neural Networks (GNNs) for recommender systems. It demonstrated the power of explicitly encoding graph structure beyond direct interactions, paving the way for a new generation of graph-based collaborative filtering models.

import torch
import torch.nn as nn
class NGCF(nn.Module):
def __init__(self, num_users, num_items, embed_dim, num_layers, adj_matrix):
super().__init__()
self.num_users = num_users
self.num_items = num_items
self.embed_dim = embed_dim
self.num_layers = num_layers
self.adj_matrix = adj_matrix # Bipartite adjacency matrix
self.user_embeddings = nn.Embedding(num_users, embed_dim)
self.item_embeddings = nn.Embedding(num_items, embed_dim)
# Weight matrices for message construction and aggregation
self.W0 = nn.Linear(embed_dim, embed_dim, bias=False)
self.W1 = nn.Linear(embed_dim, embed_dim, bias=False)
self.W2 = nn.Linear(embed_dim, embed_dim, bias=False)
def forward(self):
# Initial embeddings (Layer 0)
u_embeds_0 = self.user_embeddings.weight
i_embeds_0 = self.item_embeddings.weight
all_embeds_k = torch.cat([u_embeds_0, i_embeds_0], dim=0) # [N+M, D]
all_embeds_layers = [all_embeds_k] # Store embeddings from each layer
# Compute degree normalizations (sqrt(|N_p||N_j|))
# This is typically pre-computed for the sparse adjacency matrix
# For simplicity, assume `norm_adj` is already normalized adjacency
norm_adj = self._get_normalized_adj(self.adj_matrix)
for k in range(self.num_layers):
# Message construction and aggregation (simplified)
# The full NGCF message passing involves e_j, e_p, and their Hadamard product
# For clarity, let's use a GCN-like simplified message passing here
# Message from neighbors: A @ (W1*e_k + W2*(e_k Hadamard e_k))
# A more direct representation for simplified visual:
# neighbor_messages = norm_adj @ (self.W1(all_embeds_k) + self.W2(all_embeds_k * all_embeds_k))
# Self-connection: W0 * all_embeds_k
# Simplified for visual: just aggregate neighbor embeddings
# (This is closer to LightGCN's propagation for simplicity)
aggregated_messages = torch.sparse.mm(norm_adj, all_embeds_k)
# Combine self-embedding with aggregated messages and apply ReLU
all_embeds_k = nn.functional.relu(self.W0(all_embeds_k) + aggregated_messages)
all_embeds_layers.append(all_embeds_k)
# Concatenate embeddings from all layers
final_all_embeds = torch.cat(all_embeds_layers, dim=1)
# Split back into user and item embeddings
final_user_embeds = final_all_embeds[:self.num_users]
final_item_embeds = final_all_embeds[self.num_users:]
return final_user_embeds, final_item_embeds
def _get_normalized_adj(self, adj):
# Placeholder for actual normalized adjacency matrix computation
# This involves computing D^(-1/2) A D^(-1/2) for GCN-like normalization
# or the specific NGCF normalization factor for message passing.
# Here, `adj` is a (N+M) x (N+M) matrix.
# For this example, we'll assume a simplified sparse matrix.
# In real NGCF, it's more complex, involving (A+I) and degree matrices.
return adj.to_sparse() # simplified example
