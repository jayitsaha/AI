Understanding AlphaZero
▼

What is it? AlphaZero is a general-purpose reinforcement learning algorithm for perfect information games like Chess, Shogi, and Go. It combines a deep neural network with Monte Carlo Tree Search (MCTS), learning from scratch (tabula rasa) through self-play, without any human-provided game knowledge or handcrafted features. Its core innovation is the synergistic loop where the neural network guides the MCTS search, and the improved MCTS search statistics then become the training target for the neural network, leading to continuous self-improvement.

Analogy: Imagine a brilliant chess prodigy who has never read a single chess book. Instead, they play millions of games against themselves, constantly refining their intuition (neural network) about which moves are promising and how good a position is. Before each move, they "think deeply" (MCTS) by mentally simulating many lines of play, but instead of simulating to the very end, they use their current intuition to quickly evaluate positions. This process makes their intuition sharper, which in turn makes their thinking deeper, in a powerful self-improving cycle.

💡 If you remember one thing

AlphaZero unifies search (Monte Carlo Tree Search) and learning (deep neural network) into a powerful self-improving loop. The neural network's policy and value outputs guide the MCTS tree traversal, and the MCTS's improved search statistics (visit counts, action values) then serve as the supervision signal to train the next iteration of the neural network.

2
How AlphaZero Works Internally
▼

The AlphaZero Self-Improvement Loop

AlphaZero operates through a continuous cycle of three main phases:

  1. Self-Play: The current neural network (NN) guides MCTS to play games against itself. For each move, MCTS performs hundreds or thousands of simulations, using the NN to evaluate positions and suggest moves. The resulting game states, the MCTS-derived policy (visit counts for each move), and the game outcome are stored as training data.
  2. Neural Network Training: A new NN is trained on the collected self-play data. The NN takes a board state as input and outputs two things: a policy vector (\(p\)), representing the probability of selecting each possible move, and a scalar value (\(v\)), estimating the expected outcome of the game from that state. The training targets are the MCTS visit counts (\(\pi\)) for policy and the actual game outcome (\(z\)) for value.
  3. Evaluation: The newly trained NN is evaluated against the previous NN (or a strong baseline). If it performs better, it replaces the old NN and the cycle continues, leading to a stronger player over time.

MCTS with Neural Network Guidance

Traditional MCTS relies on random playouts to estimate value. AlphaZero replaces these computationally expensive random playouts with rapid evaluations from its neural network. Each MCTS simulation consists of four steps:

  1. Selection: Starting from the root, traverse the tree by repeatedly choosing the child node that maximizes an Upper Confidence Bound (UCB) score, which balances exploitation (nodes with high average value \(Q\)) and exploration (less visited nodes). The NN's prior policy \(P\) biases exploration towards moves it deems promising.
  2. Expansion: When a leaf node (an unvisited state) is reached, it's added to the tree. The NN evaluates this new state, providing an initial policy \(P(s,a)\) for its children and an initial value \(V(s)\).
  3. Evaluation: The NN's value \(V(s)\) for the expanded leaf node is used directly as the simulation result, bypassing costly random playouts.
  4. Backpropagation: The value \(V(s)\) is propagated back up the tree to all nodes on the selection path. For each node \(s\) and action \(a\) on the path, the visit count \(N(s,a)\) is incremented, and the action-value estimate \(Q(s,a)\) is updated by averaging in the new value.

Design Decision: Why a single NN for both policy and value?

Using a single neural network to predict both the policy and value from a given state allows for shared feature extraction layers. This makes the network more parameter-efficient, potentially improves generalization, and acts as a form of regularization, as both tasks benefit from learning robust representations of the game state. The shared architecture is a hallmark of AlphaZero's elegance.

🔑 Key Property

The MCTS search statistics — specifically the visit counts for each action from the root node — become the target policy (\(\pi\)) for training the neural network. This means MCTS is not just searching for the best move; it's also generating a powerful, informed training signal that teaches the NN which moves are truly good, far beyond its initial raw policy output.

Why It Works — The Math
▼

Neural Network Outputs and Loss Function

The neural network \(f_\theta(s)\) takes a board state \(s\) as input and outputs a policy vector \(p\) and a scalar value \(v\):

$$f_\theta(s) = (p, v)$$

where \(p\) is a vector of probabilities for each possible action \(a\), \(p_a = P(a|s)\), and \(v\) is the scalar value \(V(s) \in [-1, 1]\) (win/loss/draw perspective). The network is trained to minimize a combined loss function:

$$L(s, \pi, z) = (z - v)^2 - \pi^\top \log p + c \|\theta\|^2$$

Here, \(z\) is the game outcome from the self-play game (\(\pm 1\) for win/loss, \(0\) for draw), \(\pi\) is the MCTS-derived policy (proportional to visit counts for each action from state \(s\)), and \(c\|\theta\|^2\) is an L2 regularization term for the network weights \(\theta\). The loss has three components: mean squared error for value, cross-entropy for policy, and L2 regularization.

MCTS Selection: Upper Confidence Bound for Trees (UCT)

In the selection phase, from a given node \(s\), an action \(a\) is chosen to maximize the UCB score:

$$U(s, a) = Q(s, a) + C_{puct} P(s, a) \frac{\sqrt{N(s)}}{1 + N(s, a)}$$

where:

  • \(Q(s, a)\) is the current average action value (mean outcome of games played through action \(a\)).
  • \(P(s, a)\) is the prior probability of choosing action \(a\) from state \(s\), as predicted by the neural network.
  • \(N(s)\) is the total visit count for state \(s\).
  • \(N(s, a)\) is the visit count for action \(a\) from state \(s\).
  • \(C_{puct}\) is an exploration constant that balances exploitation (high \(Q\)) and exploration (high \(P\) and low \(N(s,a)\)). A higher \(C_{puct}\) encourages more exploration.

Dirichlet Noise for Exploration

During self-play, to ensure sufficient exploration and prevent the MCTS from getting stuck in local optima, Dirichlet noise is added to the prior probabilities at the root node of each search. This encourages MCTS to explore a wider range of moves that the NN might initially deem less promising:

$$\tilde{P}(s, a) = (1 - \epsilon) P(s, a) + \epsilon \cdot \text{Dirichlet}(a)$$

where \(\epsilon\) is a small fraction (e.g., 0.25) and \(\text{Dirichlet}(a)\) samples from a Dirichlet distribution with parameter \(\alpha_a\). This noise is only applied at the root of the MCTS search tree, not during subsequent internal node selections.

⚠️ Computational Cost

While AlphaZero is incredibly powerful, its training is extremely compute-intensive. Each MCTS simulation requires a neural network evaluation, and millions of such evaluations are performed across millions of self-play games. Efficient hardware (TPUs, GPUs) and highly optimized implementations are critical for success, making it a challenging algorithm for small-scale projects.

Key Takeaways
▼

When to use AlphaZero:

  • Perfect Information Games: Games where all players have full knowledge of the game state (e.g., Chess, Go, Shogi, Othello).
  • Complex Search Spaces: Games with a very large number of possible moves and states, where brute-force search is infeasible.
  • Tabula Rasa Learning: When human domain expertise is unavailable, difficult to encode, or you want to discover novel strategies.
  • Self-Play Data Generation: When generating high-quality training data through interaction with the environment is feasible and effective.

When NOT to use:

  • Imperfect Information Games: Games where players have hidden information (e.g., Poker, Starcraft). AlphaZero's MCTS is not directly applicable, requiring extensions like Counterfactual Regret Minimization (CFR).
  • Games with Short Horizons: For very simple games with few states or moves, the overhead of MCTS and neural network evaluation might outweigh the benefits compared to simpler search algorithms or tabular methods.
  • Problems Not Involving Sequential Decision-Making: AlphaZero is designed for game-like environments; it's not a general-purpose supervised or unsupervised learning algorithm for static datasets.
  • Limited Computational Resources: Training AlphaZero requires significant computational power (many GPUs/TPUs for extended periods) for complex games.
💡 Big Picture

AlphaZero's true power lies in its ability to transcend human intuition. By learning fundamental game principles purely from self-play, it can discover strategies that are unintuitive or even unknown to human experts, often leading to superhuman performance. It represents a paradigm shift from human-engineered AI to self-learning AI in complex domains.

import torch
import torch.nn as nn
import numpy as np
# --- Neural Network (Policy & Value Head) ---
class AlphaZeroNet(nn.Module):
def __init__(self, board_size, num_actions):
super().__init__()
# Shared body (e.g., ResNet-like architecture)
self.shared_layers = nn.Sequential(
nn.Conv2d(board_size[0], 128, kernel_size=3, padding=1),
nn.ReLU(),
# ... more residual blocks ...
)
# Policy head
self.policy_head = nn.Sequential(
nn.Conv2d(128, 2, kernel_size=1),
nn.ReLU(),
nn.Flatten(),
nn.Linear(2 * board_size[1] * board_size[2], num_actions)
)
# Value head
self.value_head = nn.Sequential(
nn.Conv2d(128, 1, kernel_size=1),
nn.ReLU(),
nn.Flatten(),
nn.Linear(board_size[1] * board_size[2], 1),
nn.Tanh() # Value between -1 and 1
)
def forward(self, x):
x = self.shared_layers(x)
policy_logits = self.policy_head(x)
value = self.value_head(x)
return torch.softmax(policy_logits, dim=1), value
# --- MCTS Node & Search Logic (simplified for clarity) ---
class MCTSNode:
def __init__(self, state, parent=None, action_from_parent=None, P_nn=None):
self.state = state
self.parent = parent
self.action_from_parent = action_from_parent
self.children = {} # action -> node
self.N = 0 # Visit count
self.Q = 0.0 # Total action value
self.P_nn = P_nn # NN's prior policy for this node's children
def select_child(self, C_puct):
best_score = -float('inf')
best_action = -1
for action, child in self.children.items():
# UCT formula: Q(s,a) + C_puct * P(s,a) * sqrt(N(s)) / (1 + N(s,a))
score = child.Q / child.N if child.N > 0 else 0.0 # Average Q
score += C_puct * self.P_nn[action] * (np.sqrt(self.N) / (1 + child.N))
if score > best_score:
best_score = score
best_action = action
return best_action, self.children[best_action]
def expand(self, nn_policy_vector, nn_value, legal_moves):
# Create children nodes for legal moves, initialize with NN policy
for action in legal_moves:
next_state = self.state.apply_move(action) # Game-specific logic
self.children[action] = MCTSNode(next_state, self, action, nn_policy_vector)
return nn_value # Return value for backpropagation
def backpropagate(self, value):
self.N += 1
self.Q += value # Sum of values
if self.parent:
self.parent.backpropagate(-value) # Negate for opponent's perspective

criterion_policy = nn.CrossEntropyLoss()
for epoch in range(num_epochs):
