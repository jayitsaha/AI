ResNet (2015): Residual Connections

Solving the degradation problem with identity mapping for ultra-deep networks
Foundational Deep Learning Architecture O(1) extra cost
1
Understanding ResNet
▼

What is it? ResNet (Residual Network) introduced a simple yet revolutionary concept: the residual connection (or skip connection). Instead of forcing a stack of layers to directly learn a desired mapping \(H(x)\), ResNet proposes that these layers learn a residual function \(F(x)\). The output of the block then becomes \(H(x) = F(x) + x\), where \(x\) is the input to the block, added back directly to the output of the stacked layers.

This seemingly small change allowed neural networks to become dramatically deeper (e.g., 152 layers vs. VGG's 19) without encountering the "degradation problem" — a phenomenon where very deep networks start performing worse than shallower ones, not due to overfitting, but due to optimization difficulties.

Analogy: Imagine you're trying to teach a student a complex new concept. The traditional approach (plain network) is to teach them the entire concept from scratch. The ResNet approach is to say, "Assume you already know the previous concept perfectly. Now, just tell me what's different or new about this next concept." It's often easier to learn a small change (the residual) than to re-learn the whole thing, especially if the optimal change is to do nothing at all (i.e., the identity mapping).

💡 If you remember one thing

ResNet's core idea is that learning an identity mapping \(H(x)=x\) (i.e., \(F(x)=0\)) is much easier for a residual block than for a plain stack of layers. This directly addresses the degradation problem, allowing for ultra-deep networks to optimize effectively.

How ResNet Works Internally
▼

The Degradation Problem

Before ResNet, simply stacking more layers in a deep neural network often led to higher training error, not lower. This wasn't due to overfitting (which would lead to high training accuracy but low test accuracy) but to an optimization difficulty called degradation. Intuitively, adding more layers should at least not hurt performance (by simply learning an identity mapping for the new layers). However, plain deep networks struggled to learn this identity mapping.

The Residual Block: \(H(x) = F(x) + x\)

A residual block consists of a few convolutional layers (e.g., two 3x3 conv layers with ReLU activations) that form the 'residual function' \(F(x)\). Crucially, the input \(x\) is added to the output of these layers. This sum then typically passes through a final activation function (e.g., ReLU). The direct connection that bypasses the main layers is the skip connection or identity shortcut.

🔑 Identity Mapping and Gradient Flow

The skip connection allows information and gradients to flow directly through the network, bypassing potentially difficult transformations. If the optimal function for a block is close to an identity, the network can easily set the weights of \(F(x)\) to zero, effectively learning \(F(x) \approx 0\), so \(H(x) \approx x\). This is much simpler than learning \(H(x)=x\) directly through a non-linear stack of layers.

Projection Shortcuts (for dimension mismatch)

When the input \(x\) and the output of \(F(x)\) have different dimensions (e.g., due to stride > 1 or change in feature map channels), the identity shortcut \(x\) cannot be directly added to \(F(x)\). In such cases, a projection shortcut \(W_s x\) is used, where \(W_s\) is a learnable 1x1 convolution matrix that matches the dimensions. This adds a few parameters but preserves the core residual idea.

Bottleneck Architecture for Deeper ResNets

For very deep ResNets (like ResNet-50, 101, 152), a "bottleneck" residual block is used to reduce computational cost. It typically consists of three convolutional layers: a 1x1 convolution to reduce dimensions, a 3x3 convolution, and another 1x1 convolution to restore dimensions. This makes the block more efficient while maintaining representational power.

Why It Works — The Math of Gradient Flow
▼

Unimpeded Gradient Flow

The primary mathematical reason for ResNet's success lies in how gradients propagate through the network. Consider the output \(y\) of a residual block given its input \(x\):

$$y = F(x) + x$$

Let \(\mathcal{L}\) be the loss function. When we backpropagate, we need to compute the gradient of the loss with respect to the input \(x\). Using the chain rule:

$$\frac{\partial \mathcal{L}}{\partial x} = \frac{\partial \mathcal{L}}{\partial y} \frac{\partial y}{\partial x}$$

Now, let's find \(\frac{\partial y}{\partial x}\):

$$\frac{\partial y}{\partial x} = \frac{\partial (F(x) + x)}{\partial x} = \frac{\partial F(x)}{\partial x} + \frac{\partial x}{\partial x} = \frac{\partial F(x)}{\partial x} + 1$$

Substituting this back into the gradient of the loss:

$$\frac{\partial \mathcal{L}}{\partial x} = \frac{\partial \mathcal{L}}{\partial y} \left( \frac{\partial F(x)}{\partial x} + 1 \right) = \frac{\partial \mathcal{L}}{\partial y} \frac{\partial F(x)}{\partial x} + \frac{\partial \mathcal{L}}{\partial y}$$

This equation reveals the crucial insight: the gradient \(\frac{\partial \mathcal{L}}{\partial y}\) is directly propagated back to \(x\) through the "+1" term. Even if the weights in \(F(x)\) are initialized such that \(\frac{\partial F(x)}{\partial x}\) is very small (potentially leading to vanishing gradients in a plain network), the gradient can still flow unimpeded through the identity shortcut. This ensures that information from deeper layers can always reach shallower layers during training, mitigating vanishing gradients.

Ease of Learning Identity Mapping

The degradation problem suggests that deeper networks struggle to learn an identity mapping. With a residual connection, if the optimal function for a block is \(H(x) = x\), then \(F(x)\) needs to learn to produce zero. Learning to output zero is generally easier for a neural network than learning a complex identity transformation through multiple non-linear layers. This makes the optimization landscape smoother and allows deeper networks to achieve at least the same performance as their shallower counterparts (and typically much better).

⚠️ Not just for Vanishing Gradients

While residual connections help with vanishing gradients, the original motivation for ResNet was primarily the degradation problem. The "gradient highway" provided by the identity shortcut ensures that adding more layers doesn't hurt optimization, even if the optimal mapping is simply to pass the input through unchanged.

Key Takeaways
▼

When to use ResNet / Residual Connections:

  • Deep Convolutional Neural Networks: ResNets are the standard backbone for most computer vision tasks, enabling models with 50, 101, 152, or even 1000+ layers.
  • Image Classification: The original application, where ResNets achieved state-of-the-art performance on ImageNet.
  • Object Detection & Segmentation: ResNet backbones are widely used in architectures like Faster R-CNN, Mask R-CNN, U-Net, etc.
  • Any Deep Network Architecture: The residual connection principle can be applied beyond CNNs, for example, in some transformer architectures (e.g., "add & norm" layers).

When NOT to use / Considerations:

  • Very Shallow Networks: For networks with only a few layers (e.g., <10), the degradation problem is less pronounced, and the overhead of residual connections might be unnecessary.
  • Non-Sequential Data: For tasks where "depth" isn't a natural concept (e.g., some tabular data models), residual connections might not offer the same benefits.
  • Computational Overhead: While the skip connection itself is cheap, deeper networks imply more overall computation. Bottleneck blocks help mitigate this.
💡 Impact & Legacy

ResNet was a paradigm shift, winning ImageNet 2015 and directly leading to architectures like DenseNet, Highway Networks, and the "Add & Norm" layers in Transformers. It showed that depth itself wasn't the problem, but rather how we allow information and gradients to flow through that depth.

Code Trace (PyTorch-like)
▼
import torch
import torch.nn as nn
class BasicBlock(nn.Module):
def __init__(self, in_channels, out_channels, stride=1):
super().__init__()
self.conv1 = nn.Conv2d(in_channels, out_channels, kernel_size=3, stride=stride, padding=1, bias=False)
self.bn1 = nn.BatchNorm2d(out_channels)
self.relu = nn.ReLU(inplace=True)
self.conv2 = nn.Conv2d(out_channels, out_channels, kernel_size=3, stride=1, padding=1, bias=False)
self.bn2 = nn.BatchNorm2d(out_channels)
self.shortcut = nn.Sequential()
if stride != 1 or in_channels != out_channels:
self.shortcut = nn.Sequential(
nn.Conv2d(in_channels, out_channels, kernel_size=1, stride=stride, bias=False),
nn.BatchNorm2d(out_channels)
) # Projection shortcut (1x1 conv) for dimension matching
def forward(self, x):
identity = self.shortcut(x) # This is the 'x' in F(x) + x
out = self.conv1(x)
out = self.bn1(out)
out = self.relu(out)
out = self.conv2(out)
out = self.bn2(out) # Output of F(x)
out += identity # The crucial residual connection: F(x) + x
out = self.relu(out)
return out
# Example for a Plain Block (no shortcut)
class PlainBlock(nn.Module):
def __init__(self, in_channels, out_channels, stride=1):
super().__init__()
self.conv1 = nn.Conv2d(in_channels, out_channels, kernel_size=3, stride=stride, padding=1, bias=False)
self.bn1 = nn.BatchNorm2d(out_channels)
self.relu = nn.ReLU(inplace=True)
self.conv2 = nn.Conv2d(out_channels, out_channels, kernel_size=3, stride=1, padding=1, bias=False)
self.bn2 = nn.BatchNorm2d(out_channels)
def forward(self, x):
out = self.conv1(x)
out = self.bn1(out)
out = self.relu(out)
out = self.conv2(out)
out = self.bn2(out)
out = self.relu(out)
return out
