How Each Strategy Works Internally
▼

Recursive (Iterated) Strategy

Train exactly one one-step-ahead model \(\hat{y}_{t+1} = f(y_t, y_{t-1})\). To reach horizon \(h\), apply it \(h\) times in a loop, and each time you need a lag that falls beyond the known data, you plug in the model's own previous prediction instead of the (unavailable) true value. So the input to step 2 is not real data — it's an estimate contaminated with step-1 error. That error is now baked into step 2's input, so step 2's output carries both its own new error AND a transformed version of step 1's error. By horizon \(h\) the errors have propagated through \(h-1\) rounds of the (possibly nonlinear) map \(f\), which is exactly why forecasts often blow up or drift for large \(h\) if \(f\) is even slightly misspecified.

Direct Strategy

Train a separate model \(\hat{y}_{t+h} = f_h(y_t, y_{t-1})\) for every horizon \(h = 1 \ldots H\), each one fit directly against its own \(h\)-step-ahead target using only lags that are already known at the forecast origin. No simulated intermediate values are ever fed back in, so there is no error-propagation chain. The price: you now maintain \(H\) independent models, each trained on progressively fewer usable rows (the last \(h\) rows of history can't supply a valid target), so large-horizon models are noisier, and — because nothing forces \(f_1, f_2, \ldots, f_H\) to agree — the forecast path can be jagged or even non-monotonic where a smooth process would predict smoothness.

MIMO (Joint / Multi-Output) Strategy

Train one model that outputs the entire vector \([\hat{y}_{t+1}, \ldots, \hat{y}_{t+H}]\) simultaneously from the same inputs \((y_t, y_{t-1})\), with the per-horizon coefficients estimated jointly rather than independently. Because the parameters for neighboring horizons are estimated together (here, approximated by smoothing the direct coefficients across \(h\); in production this is a true multi-output regressor, seq2seq network, or reduced-rank regression), statistical strength is pooled across horizons. This damps the horizon-to-horizon noise that hurts Direct, without introducing the compounding bias that hurts Recursive — usually landing in between on bias, but ahead on variance and internal consistency.

🔑 Key Property

All three strategies can start from the exact same one-step data — they differ only in what target each regression is trained against and whether predictions get fed back in as inputs. That single design choice is the whole story.

Why They Diverge — The Math
▼

The One-Step Model

Let the state at time \(t\) be \(x_t = [1, y_t, y_{t-1}]^\top\). A linear one-step model is fit by ordinary least squares over the training window:

$$\hat{\beta}^{(1)} = \underset{\beta}{\operatorname{argmin}} \sum_{t} \big(y_{t+1} - \beta^\top x_t\big)^2 = (X^\top X)^{-1}X^\top y_{+1}$$

Recursive: Composing the Map

The \(h\)-step recursive forecast is the one-step map applied to itself \(h\) times, each time substituting the previous forecast for the unknown lag:

$$\hat{y}_{t+h}^{\text{rec}} = f\big(\hat{y}_{t+h-1}^{\text{rec}}, \hat{y}_{t+h-2}^{\text{rec}}\big), \qquad f(a,b) = \hat\beta_0 + \hat\beta_1 a + \hat\beta_2 b$$

If \(f\) is exactly the true generating process, iterating it is unbiased (this is literally how the optimal multi-step conditional expectation is computed for a correctly specified linear system). But real one-step models are typically misspecified — e.g. they omit a true lag or nonlinearity — and the bias term \(\varepsilon = f - f_{\text{true}}\) does not stay put: applying \(f\) repeatedly amplifies it through repeated composition, so \(\operatorname{Var}(\hat{y}_{t+h}^{\text{rec}})\) and its bias both tend to grow with \(h\).

Direct: Separate Objective per Horizon

$$\hat{\beta}^{(h)} = \underset{\beta}{\operatorname{argmin}} \sum_{t} \big(y_{t+h} - \beta^\top x_t\big)^2, \qquad \hat{y}_{t+h}^{\text{dir}} = (\hat\beta^{(h)})^\top x_t$$

Each \(\hat\beta^{(h)}\) directly targets the \(h\)-step-ahead value, so it can absorb horizon-specific structure that a single iterated one-step model cannot. But the effective training set shrinks to \(n-h\) usable rows, inflating \(\operatorname{Var}(\hat\beta^{(h)})\) as \(h\) grows — a classic bias/variance trade against Recursive's bias-dominated error growth.

MIMO: Shared Parameters Across Horizons

$$\hat{B}^{\text{mimo}} = \underset{B}{\operatorname{argmin}} \sum_{t} \big\| y_{t+1:t+H} - B^\top x_t \big\|_2^2 + \lambda \cdot \text{Smooth}(B)$$

Instead of solving \(H\) unrelated regressions, MIMO solves one joint multi-output regression (or applies a smoothness/shared-structure prior across the columns of \(B\)). This reduces the effective number of free parameters, trading a little per-horizon flexibility for a large cut in variance — the same bias–variance logic that motivates ridge regression or multi-task learning.

⚠️ Common Pitfall

There is no universal winner. If the true process really is a clean low-order linear system, Recursive with a well-specified one-step model is optimal and Direct only adds variance for nothing. If the one-step model is even slightly wrong, Direct or MIMO usually forecast better at long horizons — this is an empirical, data-dependent choice, not a theorem.

Key Takeaways
▼

Choosing a strategy in practice:

Strategy# ModelsError growthConsistency across hData efficiency
Recursive1Can compound fast (bias-driven)High (single map)High (all rows reused)
DirectHSlower compounding, but noisierLow (independent fits)Low (fewer rows per h)
MIMO1 (multi-output)Smoothest, usually lowest averageHigh (shared params)Medium-high

Use Recursive when: you trust your one-step model is close to correctly specified, you need forecasts at every horizon cheaply, or you have very little data (it reuses every training row for the same single model).

Use Direct when: the relationship between inputs and the target genuinely changes shape with horizon, you have plenty of data per horizon, and you only care about a few specific horizons rather than the whole path.

Use MIMO when: you need the whole forecast path at once, forecasts across horizons must be mutually consistent (e.g. for downstream planning), and you can train a multi-output model (linear multi-task regression, seq2seq RNN/Transformer, or a model with H output heads).

💡 Big picture

Recursive, Direct, and MIMO are really just three different training objectives built from the same lagged features. The choice is a bias–variance trade-off: Recursive risks compounding bias, Direct risks per-horizon variance, MIMO trades a bit of both for shared structure. Modern deep forecasters (e.g. Seq2Seq, N-BEATS, Temporal Fusion Transformer) are almost all MIMO at heart — they emit the whole horizon in one forward pass.
