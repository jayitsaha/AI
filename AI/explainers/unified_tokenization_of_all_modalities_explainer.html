Understanding Unified Tokenization
▼

What is it? Every modality — a sentence, a photograph, a song, a video clip — is first compressed into a sequence of discrete integers drawn from one shared vocabulary. Once that happens, a plain decoder-only transformer no longer needs bespoke cross-attention branches per modality: it just predicts "the next token id," and the identity of the modality is nothing more than which slice of the vocabulary that id happens to fall in. This is what lets one model go any-to-any: text→image, audio→text, image+text→video, all with the same weights and the same training objective.

Analogy: Think of shipping containers. A factory doesn't design a different crane, ship, and port system for furniture versus electronics versus frozen food — everything is packed into a standard-sized steel box, and the entire logistics network only ever has to move "containers." Modality-specific tokenizers (BPE, VQ-VAE, VQ-GAN, RVQ audio codecs) are the packing step; the transformer is the crane that only ever speaks in container IDs.

How Unified Tokenization Works Internally
▼

Step 1 — Modality-specific discretizers

Text (BPE): byte-pair encoding greedily merges the most frequent adjacent symbol pair in a training corpus, repeatedly, until a target vocabulary size (~32k–100k) is reached. A word becomes a short sequence of subword ids.

Images (VQ-VAE / VQ-GAN): a CNN encoder maps each image patch to a continuous latent vector \(z_e\). Instead of keeping it continuous, we snap \(z_e\) to the nearest vector in a learned codebook of \(K\) embeddings — that codebook index is the token. A decoder later reconstructs pixels from the chosen codebook vectors.

Audio (Residual VQ — SoundStream / EnCodec): one codebook can't capture a waveform's fine detail at a usable bitrate, so RVQ cascades several small codebooks: quantize coarsely, subtract the approximation to get a residual, quantize that residual with a second codebook, and repeat. A handful of codebooks (e.g. 4–8) reach near-lossless quality at very low bitrate.

Video: extend image patchification along time — space-time "tubelets" (or per-frame VQ-GAN codes concatenated across frames) become a token grid indexed by (time, height, width).

Step 2 — Shared vocabulary & interleaving

Each modality's local codebook indices are offset into a disjoint slice of one master vocabulary id space, alongside special/control tokens (BOS, EOS, SEP, modality markers). A single training example then interleaves the slices — e.g. caption tokens, then image tokens, then audio tokens — into one flat integer sequence that the transformer reads left to right.

🔑 Key Property

One embedding table, one set of transformer weights, one softmax over \(|V|\) — because everything is just an integer id, nothing in the network architecture is modality-aware. Modality only exists as metadata about which range an id belongs to.

Why It Works — The Math
▼

Vector quantization: nearest-neighbor lookup

Given encoder output \(z_e(x)\) and codebook \(\{e_1,\dots,e_K\}\), the discrete code is the index of the closest codebook vector:

$$k = \arg\min_{j \in \{1,\dots,K\}} \lVert z_e(x) - e_j \rVert_2, \qquad z_q(x) = e_k$$

Because \(\arg\min\) is non-differentiable, VQ-VAE trains with a straight-through estimator (copy gradients from \(z_q\) straight back to \(z_e\)) plus two auxiliary losses — a codebook loss that pulls \(e_k\) toward \(z_e\), and a commitment loss that pulls \(z_e\) toward \(e_k\) (with stop-gradient \(\text{sg}[\cdot]\)):

$$\mathcal{L} = \underbrace{\lVert x - \hat{x} \rVert^2}_{\text{reconstruction}} + \underbrace{\lVert \text{sg}[z_e] - e_k \rVert^2}_{\text{codebook loss}} + \beta \underbrace{\lVert z_e - \text{sg}[e_k] \rVert^2}_{\text{commitment loss}}$$

Residual vector quantization (audio, and increasingly images/video)

RVQ approximates a vector with a sum of codeword picks from \(N\) separate small codebooks, each one modeling the previous stage's leftover error:

$$r_0 = z_e, \qquad r_{i+1} = r_i - e^{(i)}_{k_i}, \qquad z_q = \sum_{i=0}^{N-1} e^{(i)}_{k_i}$$

This gets the effective resolution of a codebook of size \(K^N\) while only ever needing \(N\) small nearest-neighbor searches over size-\(K\) codebooks — far cheaper than one giant codebook.

⚠️ Common Pitfall

A discrete bottleneck is inherently lossy: quantization error is irreducible for a fixed \(K\), and if a codebook is initialized poorly many entries can go unused ("codebook collapse"), wasting capacity. Bigger \(K\) reduces distortion but makes the softmax over the vocabulary bigger and the codebook harder to keep fully utilized.

Key Takeaways
▼

When to use unified tokenization:

  • Building any-to-any generative models (text→image, image→audio, video→text, …) with a single decoder
  • You want to inherit LLM-style scaling laws and infrastructure (KV-cache, sampling, RLHF) for multimodal generation
  • You'd rather avoid bespoke per-modality cross-attention fusion architectures

When NOT to use it:

  • You need raw, continuous-fidelity output (e.g. real-time TTS) where a diffusion/flow vocoder is cheaper and higher quality
  • Sequence-length blow-up is unacceptable — images/audio/video expand into thousands of tokens, and attention is quadratic in length
  • The discrete bottleneck's reconstruction loss is unacceptable for the downstream task (e.g. medical imaging fine detail)

Core trade-off — codebook size \(K\): larger \(K\) → lower quantization distortion and better reconstruction, but a bigger softmax to model, more codebook-collapse risk, and \(\log_2 K\) more information packed (and thus modeled) per token. Smaller \(K\) → easier to model and train, but blurrier / noisier reconstructions. Residual VQ sidesteps this by composing several small codebooks instead of one huge one.

💡 Hierarchy

Per-modality models (separate encoders, no shared representation) ⊂ cross-attention fusion (e.g. Flamingo-style, modality towers glued by attention) ⊂ unified tokenization (e.g. Chameleon, Unified-IO 2, VideoPoet, AnyGPT — one vocabulary, one transformer, one loss). Each step trades architectural specialization for a single shared sequence model.

class UnifiedTokenizer:
def __init__(self):
self.text_bpe = BPETokenizer(vocab_size=32000)
self.image_vq = VQGAN(codebook_size=8192)
self.audio_rvq = ResidualVQ(num_quantizers=4, codebook_size=1024)
self.video_vq = SpatiotemporalVQ(codebook_size=8192)
self.offsets = self._build_offsets()
def _build_offsets(self):
sizes = [8, 32000, 8192, 4096, 8192] # special, text, image, audio, video
offsets, c = [], 0
for s in sizes:
offsets.append(c); c += s
return offsets
def tokenize_text(self, s):
return [self.offsets[1] + t for t in self.text_bpe.encode(s)]
def tokenize_image(self, img):
patches = to_patches(img, size=16)
z_e = self.image_vq.encoder(patches)
ids = [argmin_j ||z_e_i - e_j||_2 for z_e_i in z_e]
return [self.offsets[2] + i for i in ids]
def tokenize_audio(self, wav):
codes = self.audio_rvq.encode(wav) # cascade of residual codebooks
return [self.offsets[3] + c for stage in codes for c in stage]
def tokenize_video(self, frames):
tubelets = to_spatiotemporal_patches(frames)
ids = self.video_vq.encode(tubelets)
return [self.offsets[4] + i for i in ids]
def interleave(self, text, image, audio, video):
seq = [BOS] + self.tokenize_text(text) + [SEP]
seq += self.tokenize_image(image) + [SEP]
seq += self.tokenize_audio(audio) + [SEP]
seq += self.tokenize_video(video) + [EOS]
return seq
def generate(self, prompt_ids, max_new=256):
ids = list(prompt_ids)
for _ in range(max_new):
logits = self.transformer(ids) # ONE model, any modality
ids.append(sample(logits[-1]))
return ids
def detokenize(self, ids):
groups = split_by_offset(ids, self.offsets) # route by id range
return (self.text_bpe.decode(groups['text']),
self.image_vq.decode(groups['image']),
self.audio_rvq.decode(groups['audio']),
self.video_vq.decode(groups['video']))
