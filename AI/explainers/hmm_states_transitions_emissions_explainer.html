Hidden Markov Models: States, Observations, Transitions & Emissions

The four ingredients — hidden states, observations, the transition matrix A, and the emission matrix B — that define every HMM, walked through with a live generative trellis.

Foundational Probabilistic ML Precedes Viterbi & Baum-Welch Sequence Models
1
Understanding the Concept
▾

A Hidden Markov Model describes a system with two coupled layers. The hidden layer is a chain of states — things you cannot directly observe (weather, a speaker's phoneme, a gene region). The visible layer is a sequence of observations — the only data you actually get to see (an activity report, an audio frame, a DNA base).

Two probability tables connect the layers. The transition matrix \(A\) says how likely the hidden chain is to move from one state to the next. The emission matrix \(B\) says how likely each state is to produce each possible observation. A third vector, the initial distribution \(\pi\), says which state the chain is likely to start in.

Analogy

You can't see the weather, but a friend calls daily and reports an activity (walk / shop / clean). Rainy days make "clean" likely — that's an emission probability. Rainy days also tend to stay rainy — that's a transition probability. From the activity sequence alone, you can infer the hidden weather sequence.

2
How It Works Internally
▾

An HMM is generative: it defines a recipe for producing a (state sequence, observation sequence) pair, one time step at a time.

1. Draw the starting state \(q_1 \sim \pi\).
2. That state immediately emits an observation \(o_1 \sim B(q_1, \cdot)\) — i.e. sample from row \(q_1\) of the emission matrix.
3. For every later step \(t\), transition to a new state \(q_t \sim A(q_{t-1}, \cdot)\) — sample from row \(q_{t-1}\) of the transition matrix — then emit \(o_t \sim B(q_t, \cdot)\).

Only the observations \(o_1, \dots, o_T\) are ever seen; the states \(q_1, \dots, q_T\) stay hidden forever unless you run an inference algorithm (Viterbi, forward-backward) on top of this model.

Row-Stochastic Constraint

Every row of \(A\) and every row of \(B\) is a probability distribution — it must sum to exactly 1, because "given I'm in state \(i\), where do I go / what do I emit" has to cover every possibility.

3
Why It Works — The Math Guarantee
▾

Two independence assumptions make the whole model tractable. The Markov property says the next state depends only on the current one:

$$P(q_t \mid q_1,\dots,q_{t-1}) = P(q_t \mid q_{t-1}) = a_{q_{t-1}q_t}$$

Output independence says each observation depends only on the state that produced it:

$$P(o_t \mid q_1,\dots,q_t,\,o_1,\dots,o_{t-1}) = P(o_t \mid q_t) = b_{q_t}(o_t)$$

Substituting both into the chain rule collapses the joint probability of an entire path into a simple product — the formula every HMM algorithm (Viterbi, forward-backward, Baum-Welch) is built on:

$$P(Q,O\mid\lambda) = \pi_{q_1}\,b_{q_1}(o_1)\prod_{t=2}^{T} a_{q_{t-1}q_t}\,b_{q_t}(o_t)$$
Common Misconception

"HMMs assume observations are independent of each other." Not quite — they're conditionally independent given the states. Because the states themselves are correlated over time (through \(A\)), the observed sequence still carries strong temporal structure.

5
Key Takeaways
▾

An HMM = \((A, B, \pi)\): a hidden Markov chain over states, wearing a per-state observation "costume." Two independence assumptions (Markov + output independence) collapse an exponentially large space of possible explanations into a simple product formula that dynamic programming can exploit.

Use this when

You have a discrete latent process generating noisy/indirect observations, need interpretable parameters, and want exact inference — not just an approximation.
