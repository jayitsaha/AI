Scaling Vision Transformers

ViT-S, B, L, H — how model size impacts performance and resource usage
Foundational Deep Learning Computer Vision O(N²) attention
1
Understanding ViT Scaling
▼

What is it? Vision Transformers (ViT) process images by splitting them into fixed-size patches, linearly embedding them, and then feeding these "tokens" into a standard Transformer encoder. Like all deep learning models, their performance often improves with scale: more parameters, more computation (FLOPs), and more data. The ViT paper introduced several standard model sizes: Small (S), Base (B), Large (L), and Huge (H), each with specific architectural configurations.

Analogy: Imagine building a custom telescope. A small, portable one (ViT-S) might be good for casual stargazing, offering decent views with minimal effort. A larger, more powerful one (ViT-B or ViT-L) requires more complex lenses, a sturdier mount, and more setup, but can resolve finer details and capture fainter objects. The largest observatory-grade telescope (ViT-H) demands immense resources and engineering, but provides unparalleled resolution and light-gathering capability, revealing secrets of the universe that smaller scopes cannot.

💡 If you remember one thing

Scaling a ViT primarily involves increasing its hidden dimension (\(D\)), number of Transformer layers (\(L\)), and number of attention heads (\(H\)). These changes drastically increase parameter count and computational cost (FLOPs), leading to better performance given sufficient pre-training data.

2
How ViT Scaling Works Internally
▼

Key Architectural Parameters for Scaling

A Vision Transformer's size is determined by a few core hyperparameters, often denoted as follows:

  • Hidden Size (\(D\)): The dimensionality of the token embeddings throughout the Transformer. This is arguably the most impactful parameter, as it affects the size of all linear layers (QKV projections, MLP feed-forward networks).
  • Number of Layers (\(L\)): The depth of the Transformer encoder, i.e., how many stacked Transformer blocks the tokens pass through. More layers allow the model to learn more complex, hierarchical representations.
  • Number of Attention Heads (\(H\)): The number of parallel attention mechanisms in each Multi-Head Self-Attention (MHSA) block. Typically, \(D\) is divisible by \(H\), so each head operates on a sub-dimension \(D/H\). More heads allow the model to attend to different parts of the input sequence simultaneously.
  • MLP Ratio (\(R\)): The expansion factor for the intermediate dimension in the Feed-Forward Network (FFN) within each Transformer block. Often fixed at 4 (e.g., \(D \to R \cdot D \to D\)).
  • Patch Size (\(P\)): The side length of the square image patches (e.g., 16x16). Smaller patches lead to more tokens (longer sequence length \(N\)), increasing attention computation quadratically. For standard ViT-S/B/L/H, this is usually fixed at 16x16 for 224x224 images.

The Trade-offs: Power vs. Resources

Increasing \(D\), \(L\), or \(H\) (or decreasing \(P\)) leads to:

  1. More Parameters: Larger models have greater capacity to learn intricate patterns and store more knowledge.
  2. More FLOPs (Computational Cost): Each forward pass requires more arithmetic operations. This means slower training and inference, and higher memory usage.
  3. Better Performance: Generally, larger models achieve higher accuracy on complex tasks, especially when pre-trained on vast datasets (like JFT-300M or ImageNet-21k) that can fully utilize their capacity.
  4. Increased Data Hunger: Larger models are more prone to overfitting on smaller datasets. They require extensive pre-training on massive, diverse datasets to generalize well.
🔑 Key Property

The self-attention mechanism, a core component of Transformers, has a computational complexity that scales quadratically with the sequence length (\(O(N^2)\)). While the number of patches (\(N\)) is often fixed for ViT-S/B/L/H, changes to hidden dimension (\(D\)) and layers (\(L\)) contribute linearly to parameters, but also significantly to FLOPs.

3
Why It Works — The Math of Scaling
▼

Parameter Count in a Transformer Block

Let \(D\) be the hidden dimension, \(L\) the number of layers, \(H\) the number of attention heads, and \(R\) the MLP ratio (typically 4). For a sequence length \(N\) (number of patches + CLS token).

A single Transformer block consists of Multi-Head Self-Attention (MHSA) and a Feed-Forward Network (FFN). We also have layer normalization layers, but their parameters are negligible (\(2D\) per layer norm, usually learnable scale and bias).

1. Multi-Head Self-Attention (MHSA) Parameters:

Each head performs query (Q), key (K), and value (V) projections. These are linear layers mapping \(D \to D\). There's also an output projection layer after concatenating all heads, mapping \(D \to D\).

$$\text{Params}_{\text{MHSA}} = (W_Q + W_K + W_V + W_O) = 4 \times (D \times D) = 4D^2$$

2. Feed-Forward Network (FFN) Parameters:

The FFN typically consists of two linear layers with a GELU activation in between: \(D \to R \cdot D \to D\). (e.g., \(D \to 4D \to D\)).

$$\text{Params}_{\text{FFN}} = (D \times RD) + (RD \times D) = 2RD^2$$

Total Parameters for \(L\) Transformer Blocks:

Summing these, and considering \(L\) blocks:

$$\text{Params}_{\text{Blocks}} = L \times (4D^2 + 2RD^2) = L \cdot D^2 (4 + 2R)$$

Additional parameters include the initial patch embedding (mapping \(P^2 \cdot C \to D\), where \(P\) is patch size, \(C\) is channels), positional embeddings (\(N \times D\)), and the final classification head (\(D \to \text{NumClasses}\)). The patch embedding is \(P^2 C D\). The positional embedding is \(N \times D\). These are small compared to the block parameters for large models.

Computational Cost (FLOPs)

FLOPs (Floating Point Operations) are a measure of computational intensity. For a sequence length \(N\):

1. MHSA FLOPs:

The dominant part is the matrix multiplications for Q, K, V projections, attention scores (\(QK^T\)), and attention values (\(AV\)). The attention score computation is \(N \times D \cdot D \times N \Rightarrow N \times N\), which is \(O(N^2 D)\) for \(QK^T\) and \(O(N^2 D)\) for \(AV\). Summing up QKV projections, attention scores, and output projection (each \(N \times D \cdot D \times D\) or \(N \times N \cdot N \times D\)):

$$\text{FLOPs}_{\text{MHSA}} \approx 2 \cdot (N \cdot D \cdot D) \text{ (QKV proj)} + 2 \cdot (N^2 \cdot D) \text{ (QKᵀ, AV)} + N \cdot D \cdot D \text{ (Output proj)} \approx O(N D^2 + N^2 D)$$

2. FFN FLOPs:

Two linear layers: \(N \times D \cdot D \times RD\) and \(N \times RD \cdot RD \times D\).

$$\text{FLOPs}_{\text{FFN}} \approx 2 \cdot (N \cdot D \cdot RD) = 2RND^2$$

Total FLOPs for \(L\) Transformer Blocks:

$$\text{FLOPs}_{\text{Blocks}} = L \times (O(N D^2 + N^2 D) + 2RND^2)$$

For typical ViT settings with \(N=196\), the \(N^2 D\) term from attention dominates over \(ND^2\) and \(RND^2\) for larger \(D\). This quadratic scaling \(O(N^2)\) is why attention is a bottleneck for very long sequences.

⚠️ Common Pitfall

Simply scaling a model larger doesn't guarantee better performance. It must be paired with sufficient, diverse, and high-quality training data. Without it, larger models are more likely to overfit or simply fail to converge due to increased complexity and instability during training.

Key Takeaways
▼

When to scale up:

  • Abundant Data: If you have access to massive pre-training datasets (e.g., billions of images), larger models can extract more signal and generalize better.
  • Complex Tasks: For highly nuanced or fine-grained visual recognition tasks, the increased capacity of larger models is often necessary.
  • State-of-the-Art Performance: To achieve top-tier benchmarks, especially in academic research, scaling up is a common strategy.
  • Resource Availability: When you have access to powerful GPUs/TPUs and sufficient computational budget for training.

When NOT to scale up (or scale down):

  • Limited Data: On smaller datasets, a large ViT will quickly overfit, performing worse than a smaller model or even a CNN.
  • Resource Constraints: Training a ViT-L or ViT-H requires immense compute. For practical applications with limited hardware, smaller models are essential.
  • Latency/Throughput Needs: Larger models are slower for inference. If your application requires real-time predictions or high throughput, smaller, more efficient models are preferred.
  • Deployment on Edge Devices: Mobile phones, embedded systems, and other edge devices cannot run large ViTs due to memory and computational limits.
💡 Scaling Laws

The concept of "scaling laws" suggests a predictable relationship between model size, dataset size, and computational budget, and how they contribute to performance. For ViTs, performance typically scales as a power law with model size, but only if enough data and compute are available to fully train the larger model. This implies an optimal balance between these three factors.

Code Trace (Parameter & FLOPs Calculation)
▼
def calculate_vit_params_flops(D, L, H, R=4, P=16, IMG_SIZE=224, NUM_CLASSES=1000, CHANNELS=3):
"""
Calculates approximate parameters and FLOPs for a Vision Transformer.
D: Hidden dimension
L: Number of Transformer layers
H: Number of attention heads
R: MLP ratio (expansion factor for FFN)
P: Patch size (e.g., 16 for 16x16 patches)
IMG_SIZE: Input image size (e.g., 224 for 224x224 images)
NUM_CLASSES: Number of output classes
CHANNELS: Number of image channels (e.g., 3 for RGB)
"""
# Sequence length (number of patches + CLS token)
N = (IMG_SIZE // P)**2 + 1
# --- Parameters ---
total_params = 0
# 1. Patch Embedding (Linear projection + Positional embedding)
patch_embed_params = (P * P * CHANNELS) * D + D # weights + bias
pos_embed_params = N * D # learnable positional embeddings
cls_token_params = D # learnable CLS token
total_params += patch_embed_params + pos_embed_params + cls_token_params
# 2. Transformer Blocks (L layers)
# Each block: Multi-Head Self-Attention (MHSA) + Feed-Forward Network (FFN)
# MHSA: QKV projections (3*D*D), Output projection (D*D)
mhsa_params_per_block = (3 * D * D) + (D * D) # 4D^2
# FFN: Linear1 (D*RD), Linear2 (RD*D)
ffn_params_per_block = (D * R * D) + (R * D * D) # 2RD^2
# LayerNorms (2 per block, each 2D params for scale/bias)
layernorm_params_per_block = 2 * (2 * D)
total_params += L * (mhsa_params_per_block + ffn_params_per_block + layernorm_params_per_block)
# 3. Final MLP Head (for classification)
mlp_head_params = D * NUM_CLASSES + NUM_CLASSES # weights + bias
total_params += mlp_head_params
# --- FLOPs --- (approximate, often measured as MACs * 2)
total_flops = 0
# 1. Patch Embedding (Linear projection)
patch_embed_flops = N * (P * P * CHANNELS * D)
total_flops += patch_embed_flops
# 2. Transformer Blocks (L layers)
# MHSA FLOPs: QKV projections (N*D*D*3), QK^T (N*N*D), Softmax (N*N), AV (N*N*D), Output proj (N*D*D)
mhsa_flops_per_block = (3 * N * D * D) + (2 * N * N * D) + (N * D * D)
# FFN FLOPs: Linear1 (N*D*RD), Linear2 (N*RD*D)
ffn_flops_per_block = (N * D * R * D) + (N * R * D * D)
total_flops += L * (mhsa_flops_per_block + ffn_flops_per_block)
# 3. Final MLP Head
mlp_head_flops = N * (D * NUM_CLASSES)
total_flops += mlp_head_flops
return {
"parameters_M": total_params / 1_000_000,
"flops_G": total_flops / 1_000_000_000,
"hidden_dim": D, "layers": L, "heads": H,
"mlp_ratio": R, "patch_size": P, "sequence_length": N
}
# Example usage for ViT-B (Base)
vit_b_specs = calculate_vit_params_flops(D=768, L=12, H=12)
print(f"ViT-B Parameters: {vit_b_specs['parameters_M']:.2f} M")
print(f"ViT-B FLOPs: {vit_b_specs['flops_G']:.2f} G")
