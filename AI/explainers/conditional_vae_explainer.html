1
Understanding CVAE
▼

What is it? A plain Variational Autoencoder (VAE) learns a latent space \(z\) that generates plausible data, but you cannot ask it for "a smiling face" or "the digit 7" — sampling is unguided. A Conditional VAE fixes this by feeding a label / attribute \(c\) into both the encoder and the decoder, so the model learns \(q(z\mid x,c)\) and \(p(x\mid z,c)\) instead of \(q(z\mid x)\) and \(p(x\mid z)\). The latent code \(z\) is then free to capture only the style/variation left over once the class is known, and generation becomes controllable: pick \(c\), sample \(z\), get a targeted output.

Analogy: Imagine a sketch artist who is told "draw a cat" (that's \(c\)) and then rolls dice to decide the pose, fur pattern, and lighting (that's \(z\)). Without the instruction, the artist would draw a random animal in a random style — you'd have no control over the subject. With the instruction, you control what is drawn while the dice still control how it looks.

💡 If you remember one thing

CVAE conditions every distribution on \(c\): $$q_\phi(z\mid x,c) \quad\text{and}\quad p_\theta(x\mid z,c)$$ This factors "what class" out of the latent code, so \(z\) alone controls intra-class style — letting you generate a specific class on demand by fixing \(c\) and sampling \(z \sim \mathcal{N}(0,I)\).

How CVAE Works Internally
▼

The Problem with a Plain VAE

A standard VAE maximizes a lower bound on \(\log p(x)\) using an encoder \(q_\phi(z\mid x)\) and decoder \(p_\theta(x\mid z)\). It generates realistic samples, but the mapping from a label to a region of \(z\)-space is emergent and unreliable — nearby points in \(z\) may belong to different classes, and there is no input slot to request a specific class.

The CVAE Fix: Concatenate c Everywhere

CVAE (Sohn, Lee & Yan, NeurIPS 2015 — "Learning Structured Output Representation using Deep Conditional Generative Models") augments both networks with \(c\) as extra input:

$$\text{Encoder: } [x; c] \to (\mu_\phi(x,c),\ \sigma_\phi(x,c)) \qquad \text{Decoder: } [z; c] \to \hat{x} = p_\theta(x\mid z,c)$$

\(c\) is typically a one-hot class vector or an attribute vector, concatenated to the pixel/feature input before the first layer, and again concatenated to \(z\) before the first decoder layer (or injected via FiLM/conditional batch-norm in deeper architectures).

Numerical Trace (2-D toy latent space)

For condition \(c\), the encoder outputs \(\mu_c=(1.7\cos\theta_c,\,1.7\sin\theta_c)\), \(\sigma_c\approx 0.3\). Sampling \(\varepsilon\sim\mathcal{N}(0,I)\) once, e.g. \(\varepsilon=(0.4,-0.2)\): \(z=\mu_c+\sigma_c\varepsilon\). Switching \(c\) moves \(\mu_c\) to a new position on the circle while \(\varepsilon\) — the "randomness budget" — stays fixed, so \(z\) slides to a new class region without being redrawn. Design Decision: Why Condition the Prior Only Implicitly?

Most CVAE variants keep the prior \(p(z)=\mathcal{N}(0,I)\) shared across classes (rather than learning \(p(z\mid c)\)) so that at generation time you only need \(c\) and a standard normal sample — no class-specific prior network required. The "Conditional Prior Network" variant (CVAE++) instead learns \(p_\psi(z\mid c)\), trading simplicity for tighter, more separated class clusters.

🔑 Key Property

Because \(c\) is given to the decoder directly, \(z\) does not need to encode class identity — it only needs to encode everything else (pose, stroke width, thickness, style). This disentanglement is what makes controllable generation possible.

3
Why It Works — The Conditional ELBO
▼

Deriving the Conditional Evidence Lower Bound

We want to maximize \(\log p_\theta(x\mid c)\). Introduce the variational posterior \(q_\phi(z\mid x,c)\) and apply Jensen's inequality exactly as in the unconditional VAE, but with \(c\) carried through every term:

$$\log p_\theta(x\mid c) \;\ge\; \underbrace{\mathbb{E}_{q_\phi(z\mid x,c)}\big[\log p_\theta(x\mid z,c)\big]}_{\text{reconstruction}} \;-\; \underbrace{D_{KL}\big(q_\phi(z\mid x,c)\,\|\,p(z\mid c)\big)}_{\text{regularization}} \;=\; \mathcal{L}_{\text{CVAE}}(\theta,\phi; x,c)$$

With a shared Gaussian prior \(p(z\mid c)=\mathcal{N}(0,I)\) and diagonal Gaussian posterior \(q_\phi(z\mid x,c)=\mathcal{N}(\mu_c,\operatorname{diag}(\sigma_c^2))\), the KL term is closed-form:

$$D_{KL}(q\|p) = \frac{1}{2}\sum_{i=1}^{d}\Big(\mu_{c,i}^2 + \sigma_{c,i}^2 - 1 - \log\sigma_{c,i}^2\Big)$$

The reconstruction term is estimated with one Monte-Carlo sample via the reparameterization trick, which keeps sampling differentiable:

$$z = \mu_c + \sigma_c \odot \varepsilon,\qquad \varepsilon \sim \mathcal{N}(0,I)$$

Training maximizes \(\mathcal{L}_{\text{CVAE}}\) (equivalently minimizes \(-\mathcal{L}_{\text{CVAE}} = \text{recon} + KL\)) by backpropagating through \(\theta\) and \(\phi\), since \(\varepsilon\) carries no trainable parameters.

⚠️ Common Pitfall

Posterior collapse with \(c\): if the decoder is powerful enough, it can learn to ignore \(z\) entirely and reconstruct \(x\) purely from \(c\) (or vice versa — ignore \(c\) if it correlates with easy-to-encode pixel statistics). KL annealing, free-bits, or limiting decoder capacity near the conditioning input keeps both \(z\) and \(c\) informative.

Key Takeaways
▼

When to use CVAE:

  • You need controllable generation — "give me class 7", "give me a smiling face" — not just realistic samples
  • Labels or attributes are available (fully or partially) at training time
  • You want a smooth, continuous style axis (\(z\)) within a discrete category (\(c\))
  • Data imputation / structured prediction — CVAE was originally proposed for segmentation, treating the label map as \(x\) and the image as \(c\)

When NOT to use:

  • No label information exists and cannot be inferred — a plain VAE or a clustering-based latent model is simpler
  • You need photorealistic samples — GANs/diffusion models with classifier-free guidance usually outperform CVAE's blurrier reconstructions
  • Continuous conditioning at very high dimensionality — a CVAE's concatenation approach scales awkwardly; FiLM-style conditioning or cross-attention (as in diffusion) is more parameter-efficient
💡 Hierarchy

VAE (\(z\) only) ⊂ CVAE (\(z\) and \(c\), shared prior) ⊂ CVAE with learned conditional prior \(p(z\mid c)\) ⊂ Diffusion with classifier-free guidance (implicit, iterative conditioning). Each step trades simplicity for sharper, more controllable generation.

Code Trace

import torch, torch.nn as nn, torch.nn.functional as F
class CVAE(nn.Module):
def __init__(self, x_dim, z_dim, n_classes, h=256):
super().__init__()
# Encoder sees [x ; one_hot(c)]
self.enc = nn.Sequential(nn.Linear(x_dim + n_classes, h), nn.ReLU())
self.mu = nn.Linear(h, z_dim)
self.logvar = nn.Linear(h, z_dim)
# Decoder sees [z ; one_hot(c)]
self.dec = nn.Sequential(nn.Linear(z_dim + n_classes, h), nn.ReLU(),
nn.Linear(h, x_dim), nn.Sigmoid())
def encode(self, x, c_onehot):
h = self.enc(torch.cat([x, c_onehot], dim=-1))
return self.mu(h), self.logvar(h) # mu_c, log sigma_c^2
def reparameterize(self, mu, logvar):
std = torch.exp(0.5 * logvar)
eps = torch.randn_like(std) # epsilon ~ N(0, I)
return mu + eps * std # z = mu + sigma * epsilon
def decode(self, z, c_onehot):
return self.dec(torch.cat([z, c_onehot], dim=-1)) # p(x | z, c)
def forward(self, x, c_onehot):
mu, logvar = self.encode(x, c_onehot)
z = self.reparameterize(mu, logvar)
xhat = self.decode(z, c_onehot)
return xhat, mu, logvar
def cvae_loss(xhat, x, mu, logvar):
recon = F.binary_cross_entropy(xhat, x, reduction='sum')
kl = -0.5 * torch.sum(1 + logvar - mu.pow(2) - logvar.exp())
return recon + kl, recon, kl # minimize -ELBO = recon + KL
# Controllable generation at inference time:
c = F.one_hot(torch.tensor([7]), n_classes).float() # "give me class 7"
z = torch.randn(1, z_dim) # sample the prior
sample = model.decode(z, c) # -> a generated '7'
