1
Understanding Alignment
▼

What is it? A picture and a sentence live in completely different worlds — pixels vs. tokens. "Alignment" is the training process that maps both into the same vector space, so that a photo of a cat and the sentence "a photo of a cat" end up as nearby points, while unrelated pairs end up far apart. Once that shared space exists, you can compare an image and a sentence just by measuring the distance between two vectors.

Analogy: Imagine two translators who have never met — one only speaks "Image" and one only speaks "Text" — being forced to agree on a single shared code so that any thought either of them expresses lands in the same coordinate. Contrastive alignment trains them by playing a matching game: given a batch of photos and captions, pull each true pair's codes together and push every wrong pairing apart. Generative alignment instead trains one translator to literally speak the other's language: show the image encoder's output to a text decoder and make it write the caption word by word, so the decoder is forced to extract alignment-relevant information from the image representation.

💡 If you remember one thing

Contrastive alignment (CLIP) learns a shared space by discrimination — pull matched pairs together, push mismatched pairs apart via a softmax over similarities: $$\mathcal{L}_{\text{contrastive}} = -\log\frac{\exp(\text{sim}(i,t)/\tau)}{\sum_{j} \exp(\text{sim}(i,t_j)/\tau)}$$ Generative alignment learns it by reconstruction — condition a text decoder on the image and maximize the likelihood of the real caption, token by token.

How Alignment Works Internally
▼

Contrastive Alignment (CLIP / ALIGN)

Two independent encoders — a vision transformer/CNN \(f_\theta\) and a text transformer \(g_\phi\) — each map their input to a \(d\)-dimensional vector. Both vectors are L2-normalized onto the unit hypersphere, so the dot product becomes cosine similarity: \(\text{sim}(i,t) = \hat{u}_i^\top \hat{v}_t\), scaled by a learned temperature \(\tau\). For a batch of \(N\) image-text pairs, you build an \(N\times N\) similarity matrix. The diagonal holds the \(N\) true pairs; every off-diagonal cell is a free negative. A symmetric InfoNCE loss (image→text softmax over rows, text→image softmax over columns) is averaged, so each encoder gets a gradient that says "raise your similarity to your true partner relative to every other item in this batch."

Generative Alignment (BLIP-2 / Flamingo / GIT / LLaVA-style)

A frozen or lightly-tuned vision encoder produces a grid of patch embeddings. A small bridging module — a linear projection, an MLP, or a cross-attention "Q-Former" with learned query tokens — compresses those patches into a handful of "visual tokens" the same width as the language model's embeddings. These visual tokens are prepended (or cross-attended) as a prefix, and a causal language-model decoder is trained with the ordinary next-token objective: predict the ground-truth caption one token at a time, conditioned on the visual prefix. There is no explicit negative pair — alignment emerges only because the decoder cannot write an accurate caption unless the visual tokens encode the right information.

🔑 Design decision: why two families exist

Contrastive alignment optimizes a global, symmetric, retrieval-shaped objective — cheap at inference (one dot product), ideal for search/zero-shot classification, but needs huge batches (thousands of negatives) to be sample-efficient. Generative alignment optimizes a local, asymmetric, generation-shaped objective — expensive at inference (autoregressive decoding), but needs no negatives and directly produces free-form language (captions, answers, reasoning).

Why It Works — The Math
▼

InfoNCE Derivation (Contrastive)

Given a batch of \(N\) image embeddings \(\{\hat u_i\}\) and text embeddings \(\{\hat v_j\}\), the image→text loss for pair \(i\) is a softmax classification over the batch:

$$\mathcal{L}^{i2t}_i = -\log\frac{\exp(\hat u_i^\top \hat v_i / \tau)}{\sum_{j=1}^{N}\exp(\hat u_i^\top \hat v_j / \tau)}$$

The symmetric text→image loss swaps the roles, and the total is the batch mean of both:

$$\mathcal{L}_{\text{CLIP}} = \frac{1}{2N}\sum_{i=1}^N \left(\mathcal{L}^{i2t}_i + \mathcal{L}^{t2i}_i\right)$$

The gradient with respect to a logit \(z_{ij} = \hat u_i^\top \hat v_j/\tau\) is exactly the softmax residual \(p_{ij} - \mathbb{1}[i=j]\) — so every negative in the batch contributes a repulsive gradient proportional to how confusable it currently is with the true pair. This is why larger batches = harder, more informative negatives = better representations, and why \(\tau\) matters: small \(\tau\) sharpens the softmax and focuses gradient on the hardest negatives.

Autoregressive NLL (Generative)

Given visual prefix tokens \(\mathbf{v} = h_\psi(\text{image})\) and target caption tokens \(y_1,\dots,y_T\), the decoder \(p_\theta\) is trained to maximize:

Because \(\mathbf v\) is the only image-dependent input, the gradient \(\partial \mathcal{L}_{\text{gen}}/\partial \mathbf v\) only flows back through cross-attention/prefix-attention weights — alignment is learned implicitly, as a byproduct of caption likelihood, rather than from an explicit similarity target.

⚠️ Common Pitfall

Contrastive alignment needs a large negative pool — with a tiny batch (say \(N=8\)) the softmax denominator barely constrains anything and the embeddings barely separate. Generative alignment needs no negatives but can silently collapse into ignoring the image (captioning from language priors alone) if the visual prefix is too weak or the decoder too strong — always check that swapping the image changes the generated caption.

Key Takeaways
▼

When to reach for contrastive alignment:

  • Zero-shot classification and image/text retrieval (embed once, compare with dot products)
  • Building a reusable, modality-agnostic embedding space for downstream tasks
  • You can afford large batches / memory banks / momentum encoders for enough negatives

When to reach for generative alignment:

  • Captioning, visual question answering, visual dialog, chain-of-thought over images
  • You want free-form language output, not just a similarity score
  • You want to reuse a pretrained frozen LLM's world knowledge and reasoning ability

💡 Hierarchy in practice

Modern multimodal LLMs rarely pick one exclusively — BLIP-2 pretrains its Q-Former with an image-text contrastive loss and a captioning loss together; Flamingo/GIT/LLaVA lean generative but often start from a CLIP-pretrained vision encoder, inheriting an already-aligned space as their starting point. Contrastive pretraining gives cheap, well-structured features; generative fine-tuning teaches the model to talk about them.
