Computational Complexity of Attention

Why self-attention costs O(n²·d) time and O(n²) memory — and what breaks first as sequences grow
Advanced Transformers Efficient Attention O(n²·d) time · O(n²) memory
1
Understanding the Concept
▼

What is it? Self-attention lets every token in a sequence look at every other token and decide how much to "pay attention" to it. To do that, the model builds an \(n \times n\) table of scores — one score for every pair of positions — where \(n\) is the sequence length. Building and storing that table is what makes attention expensive: double the sequence length, and the table doesn't get twice as big, it gets four times as big.

Analogy: Imagine a conference room where every attendee must have a private one-on-one conversation with every other attendee before the meeting can proceed. With 10 people that's 100 conversations (fine). With 10,000 people that's 100,000,000 conversations — the room, and the schedule, collapse long before you get anywhere near that many attendees. That's self-attention: pairwise interactions between every token and every other token.

💡 If you remember one thing

Self-attention costs \(O(n^2 \cdot d)\) time and \(O(n^2)\) memory because it materializes an \(n \times n\) score matrix — one entry per pair of tokens. Doubling the context length quadruples the compute and quadruples the memory for that matrix, which is why "long context" is a hard engineering problem, not just a bigger GPU problem.

2
How It Works Internally
▼

The Three Stages of Self-Attention

Given queries \(Q\), keys \(K\), values \(V\), each of shape \((n, d)\) (sequence length \(n\), model/head dimension \(d\)), scaled dot-product attention runs in three stages:

  • 1. Score matrix — \(QK^\top\): An \((n,d)\times(d,n)\) matmul producing an \((n,n)\) matrix. Cost: \(2n^2d\) FLOPs (multiply + add per output element per inner-dim step). This is where the \(n \times n\) table is materialized — it must be written to memory in full before softmax can run over it.
  • 2. Softmax over rows: Normalizes each of the \(n\) rows of the \((n,n)\) matrix into a probability distribution. Cost: \(O(n^2)\) — cheap in FLOPs, but it still touches all \(n^2\) entries, so it is memory-bandwidth bound.
  • 3. Weighted sum — \(\text{softmax}(\cdot) V\): An \((n,n)\times(n,d)\) matmul producing the \((n,d)\) output. Cost: another \(2n^2d\) FLOPs.

Summing stages 1 and 3 (softmax is comparatively negligible in FLOPs): total compute ≈ \(4n^2d\) FLOPs per attention head, and — critically — this holds regardless of how many heads you split \(d\) into, since splitting \(d\) into \(h\) heads of size \(d/h\) and summing over heads gives back \(4n^2d\).

Numerical Trace

Take \(n = 2048\), \(d = 768\) (roughly GPT-2-scale). The score matrix alone has \(n^2 = 4{,}194{,}304\) entries. At 2 bytes each (fp16) that's about 8 MB per head, per layer, per sequence in the batch. FLOPs for stages 1+3: \(4 \times 2048^2 \times 768 \approx 1.29 \times 10^{10}\) — about 13 GFLOPs, for a single attention block. A 96-layer model processing a batch of 8 such sequences multiplies that by \(96 \times 8 \approx 768\), landing near \(10^{13}\) FLOPs just for attention score/output matmuls.

Design Decision: why materialize the full matrix at all?

The naive implementation stores the entire \((n,n)\) matrix because softmax needs the full row before it can normalize any entry. This is exactly the memory bottleneck that FlashAttention attacks: it computes attention in blocks, keeping only small tiles in fast on-chip SRAM and re-deriving the softmax normalizer incrementally (online softmax), so the full \(n \times n\) matrix is never written to slow GPU memory — but the FLOP count \(O(n^2d)\) is unchanged. FlashAttention fixes the memory-bandwidth bottleneck, not the quadratic compute.

🔑 Key Property

The quadratic term comes purely from the number of token pairs, \(n^2\), not from the model width \(d\). Every architectural fix for long context targets the same lever: stop computing (or stop storing) all \(n^2\) pairs.

3
Why It Works This Way — The Math
▼

Deriving the FLOP Count

For a single head with \(Q, K, V \in \mathbb{R}^{n \times d}\), scaled dot-product attention is:

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right) V$$

Matrix multiplication of an \((n,d)\) matrix by a \((d,n)\) matrix requires \(n \cdot n \cdot d\) multiply-accumulate pairs, i.e. \(2n^2d\) FLOPs (one multiply + one add each). The same count applies to \(\text{softmax}(\cdot)V\), an \((n,n)\times(n,d)\) product. So:

$$\text{FLOPs}_{\text{attn}} \approx \underbrace{2n^2d}_{QK^\top} + \underbrace{2n^2d}_{\text{scores} \cdot V} = 4n^2d = O(n^2 d)$$

Contrast this with the per-token feed-forward (MLP) sublayer, which is independent per position: cost \(O(n \cdot d^2)\) (linear in \(n\)). Attention's cost grows relative to the FFN cost by a factor of \(n/d\) — for short sequences (\(n \ll d\)) the FFN dominates total FLOPs; for long sequences (\(n \gg d\)) attention dominates and eventually swamps everything else.

Memory Footprint

$$\text{Memory}_{\text{scores}} = h \cdot n^2 \cdot b \quad \text{bytes}$$

where \(h\) is the number of heads and \(b\) is bytes per element (2 for fp16/bf16, 4 for fp32). This is the term that makes attention memory grow quadratically in \(n\) even though the rest of the network (embeddings, FFN weights, KV cache for a single position) scales linearly.

Crossover Point

Setting the two costs equal, \(4n^2d = c \cdot n d^2\), gives a crossover at \(n \approx d\) (up to a small constant). Below that point, per-token FFN work dominates; above it, pairwise attention work dominates — which is exactly why complexity only becomes the headline bottleneck once context lengths reach the thousands-to-hundreds-of-thousands range used by modern long-context LLMs.

⚠️ Common Misconception

"Attention is \(O(n^2)\)" is a memory statement, not the full compute statement — the compute is \(O(n^2 d)\). For large \(d\) (e.g. 4096 in modern LLMs) the \(d\) factor is not negligible: it means attention FLOPs scale with both sequence length squared and model width, which is why scaling both context and model size simultaneously is so expensive.

Key Takeaways
▼

Why this matters:

  • The \(n \times n\) score matrix is the single biggest structural bottleneck to long-context transformers — it dictates both FLOPs (\(O(n^2d)\)) and peak memory (\(O(n^2)\)).
  • FlashAttention removes the memory-bandwidth cost (never materializing the full matrix in slow memory) but does not reduce the \(O(n^2d)\) FLOP count — it makes the same amount of compute run faster and fit in less memory.
  • Truly sub-quadratic alternatives change the algorithm: sliding-window / local attention (\(O(n \cdot w \cdot d)\)), sparse attention patterns, and kernel-based linear attention (\(O(n \cdot d^2)\)) all trade some modeling flexibility for linear scaling in \(n\).

When quadratic cost bites: retrieval-augmented generation over long documents, genomics sequences, high-resolution vision transformers, and any "give me the whole codebase as context" use case — anywhere \(n\) reaches into the tens of thousands or beyond.

When it doesn't matter much: short-context classification/encoding tasks (\(n\) in the hundreds), where the per-token FFN and embedding costs dominate total compute anyway.

💡 Rule of thumb

If your context length \(n\) is smaller than your model width \(d\), don't worry about attention's quadratic term — the linear-in-\(n\) feed-forward layers dominate. Once \(n\) exceeds \(d\) by an order of magnitude or more, attention's \(O(n^2d)\) cost is the thing to optimize first.

Code: Counting the FLOPs
▼

A from-scratch FLOP/memory counter for full self-attention vs. two sub-quadratic alternatives — this is exactly the math driving the live numbers in the visualization above.

import numpy as np

def attention_cost(n, d, heads=12, bytes_per_el=2):
    """Full (dense) self-attention: O(n^2 d) time, O(n^2) memory."""
    flops = 4 * n**2 * d                      # QK^T + softmax(.)V, both ~2n^2d
    score_matrix_bytes = heads * n**2 * bytes_per_el
    return flops, score_matrix_bytes

def sliding_window_cost(n, d, window=256, heads=12, bytes_per_el=2):
    """Local/sliding-window attention: O(n * w * d) time & memory — linear in n."""
    flops = 4 * n * window * d
    score_matrix_bytes = heads * n * window * bytes_per_el
    return flops, score_matrix_bytes

def linear_attention_cost(n, d, heads=12, bytes_per_el=2):
    """Kernel-based linear attention (e.g. Performer): O(n * d^2) time,
    O(n * d) memory — never forms an n x n matrix at all."""
    flops = 4 * n * d**2
    state_bytes = heads * n * d * bytes_per_el
    return flops, state_bytes

# Example: n=8192 tokens, d=1024
for name, fn in [("full", attention_cost),
                  ("sliding-window(256)", sliding_window_cost),
                  ("linear", linear_attention_cost)]:
    flops, mem = fn(8192, 1024)
    print(f"{name:22s} FLOPs={flops:.3e}  memory={mem/1e6:.1f} MB")
