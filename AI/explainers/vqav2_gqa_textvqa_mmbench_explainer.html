1
Understanding the Four Benchmarks
▼

What are they? These are four exam papers for vision-language models. Each one is designed to expose a different way models cheat or fail: guessing from language alone (VQAv2), memorizing shortcuts instead of reasoning over the scene (GQA), ignoring text printed inside the image (TextVQA), and getting lucky on multiple-choice letters (MMBench).

Analogy: Imagine grading a student four different ways. First, you make sure two nearly-identical photos have opposite answers so they can't guess from the question alone (VQAv2). Second, you build every question from a strict logical program so "reasoning" can't be faked (GQA). Third, you ask about the fine print in the photo, forcing them to actually read it (TextVQA). Fourth, you shuffle "A/B/C/D" around and demand they get it right every single time it's shuffled (MMBench) — a lucky guess only survives one arrangement.

💡 If you remember one thing

Each benchmark targets a specific failure mode: VQAv2 fights language priors with balanced image pairs and soft accuracy \(\min(\tfrac{n}{3},1)\); GQA fights reasoning shortcuts with scene-graph-generated programs; TextVQA fights text-blindness by requiring OCR; MMBench fights positional guessing with CircularEval, which requires the correct answer on every cyclic shuffle of the options.

2
How Each Benchmark Works Internally
▼

VQAv2 — Balancing Away Language Bias

The original VQA v1 dataset let models score ~50% just by ignoring the image ("What color is the banana?" → "yellow" is right most of the time). VQAv2 (Goyal et al., 2017) fixes this by finding a complementary image for every question so that the same question has two different correct answers on two different images. A model that answers without looking loses on one of the pair. Ten independent human annotators write answers per question; scoring uses soft accuracy so a single quirky human doesn't tank a reasonable answer.

GQA — Compositional Reasoning from Scene Graphs

GQA (Hudson & Manning, 2019) starts from Visual Genome scene graphs (objects, attributes, relations) and generates questions via structured functional programs, e.g. select(cup) → relate(table, on, subject) → query(attribute:color). Because the program is known, GQA can also measure consistency (do related questions get logically compatible answers?), plausibility, and distribution match against real-world answer frequencies — not just raw accuracy.

TextVQA — Reading Is Part of Seeing

TextVQA (Singh et al., 2019) collects images from Open Images that contain visible text (signs, labels, price tags) and asks questions that require reading it, e.g. "What brand is on the can?" Models need an OCR module plus a dynamic pointer mechanism that can copy a detected OCR token straight into the answer, because the right answer often is not in any fixed answer vocabulary — it's whatever text happens to be in that specific image.

MMBench — Robustness via CircularEval

MMBench (Liu et al., 2023) organizes ~3000 questions into a hierarchical ability taxonomy (perception, reasoning → 20 fine-grained abilities) and uses multiple-choice format so an LLM "choice extractor" can reliably parse free-form model output into A/B/C/D. Its key trick is CircularEval: each question is asked N times with the option order cyclically rotated, and the model must answer correctly in every rotation for the question to count as correct — turning a 25%-by-chance format into one where guessing is punished exponentially.

🔑 Design decision: why not just use plain accuracy everywhere?

Plain accuracy is gameable in a benchmark-specific way: language priors (VQA), memorized co-occurrence shortcuts (GQA), vocabulary-only answering (TextVQA), and position bias (MMBench). Each benchmark instead redesigns its data collection or its scoring rule to close the specific loophole that plain accuracy leaves open.

3
Why It Works — The Scoring Math
▼

VQAv2 Soft Accuracy

Each question has 10 human answers \(\{a_1,\dots,a_{10}\}\). For a predicted answer \(\hat{a}\), the official metric averages over the 10 ways of leaving one human out:

$$\text{Acc}(\hat{a}) = \frac{1}{10}\sum_{i=1}^{10}\min\left(\frac{\big|\{j \neq i : a_j = \hat{a}\}\big|}{3},\ 1\right)$$

Intuitively: if at least 3 of the other 9 annotators agree with the model, it gets full credit; agreement from 1 or 2 annotators gives partial credit (\(1/3\) or \(2/3\)); zero agreement scores 0. Averaging over all 10 leave-one-out subsets reduces the variance contributed by any single annotator's idiosyncrasy.

GQA Auxiliary Metrics

Beyond accuracy, GQA computes Consistency — the fraction of logically-entailed question groups answered coherently — and Plausibility — whether the answer is a priori sensible for the question type (e.g. "elephant" is implausible for "what color") regardless of correctness.

MMBench CircularEval

Let a question have \(k\) options. CircularEval tests all \(k\) cyclic rotations of the option order and defines:

$$\text{score} = \prod_{r=1}^{k} \mathbb{1}\big[\hat{a}_r = a^\star\big]$$

where \(\hat{a}_r\) is the model's choice under rotation \(r\) and \(a^\star\) is the (rotation-invariant) correct content. A model that answers by pure positional guessing (e.g. always picking "A") has single-pass expected accuracy \(1/k\), but expected CircularEval accuracy \((1/k)^k \to 0\) rapidly as \(k\) grows — this is precisely why MMBench catches models that "look right" under naive accuracy.

⚠️ Common pitfall

Comparing raw accuracy numbers across these benchmarks is meaningless — an 85% on VQAv2 (open-ended, soft-scored, 10-way voted) is not comparable to an 85% on MMBench (4-way multiple choice, all-rotations-must-pass). Always compare a model to others on the same benchmark and metric.

Key Takeaways
▼

When each benchmark is the right tool:

  • VQAv2 — general open-ended VQA ability and robustness to language priors; the most widely reported baseline number.
  • GQA — probing multi-step compositional/relational reasoning and answer-distribution bias, not just "did it get the word right."
  • TextVQA (and its successor ST-VQA/OCR-VQA family) — evaluating scene-text reading, essential for documents, UI screenshots, signage.
  • MMBench — stress-testing modern MLLMs (GPT-4V-style) for genuine understanding vs. positional/format guessing, with fine-grained ability breakdowns.

💡 The meta-lesson

Every generation of benchmark exists because models found a shortcut through the previous one. Good evaluation design isn't about picking a harder question set — it's about closing the specific exploit (bias, shortcut, blindness, or guessing) that let models "pass" without doing the intended skill.

Code Trace — Computing the Metrics
▼
import itertools, collections
# --- VQAv2 soft accuracy (official formula) ---
def vqav2_soft_accuracy(pred, humans):
accs = []
for i in range(len(humans)): # leave-one-out, i = held-out annotator
others = humans[:i] + humans[i+1:] # remaining 9 answers
matches = sum(1 for a in others if a == pred)
accs.append(min(matches / 3, 1.0))
return sum(accs) / len(accs)
# --- GQA: functional program execution over a scene graph ---
def run_program(scene_graph, program):
ref = None
for op, *args in program:
if op == "select": ref = scene_graph.find_object(args[0])
elif op == "relate": ref = scene_graph.find_related(ref, *args)
elif op == "query": return ref.get(args[0]) # e.g. args[0]='color'
# --- TextVQA: answer space is fixed vocab UNION detected OCR tokens ---
def textvqa_predict(vocab_logits, ocr_tokens, ocr_logits):
candidates = vocab_logits + list(zip(ocr_tokens, ocr_logits))
return max(candidates, key=lambda c: c[1])[0] # pointer picks highest-scoring source
# --- MMBench: CircularEval over k options ---
def circular_eval(model, question, options, correct_content):
k = len(options)
for r in range(k): # k cyclic rotations
rotated = options[r:] + options[:r]
choice = model.answer(question, rotated) # e.g. returns 'A','B','C','D'
if rotated[ord(choice) - ord('A')] != correct_content:
return 0 # any rotation wrong -> whole question fails
return 1
