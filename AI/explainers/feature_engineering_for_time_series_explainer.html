1
Understanding Time Series Feature Engineering
▼

What is it? Many machine learning models (like linear regression, tree-based models, or even simple neural networks) assume that input features are independent and identically distributed (i.i.d.). Time series data, by definition, violates this assumption: observations are ordered and often dependent on past values. Feature engineering for time series is the process of transforming raw time-indexed data into a set of features that explicitly capture temporal dependencies, trends, and seasonality, making it suitable for standard ML algorithms.

Analogy: Imagine trying to predict tomorrow's stock price. If you only look at today's price, you're missing crucial context. A good investor considers yesterday's price (lag), the average price over the last month (rolling statistic), the day of the week (date feature), and long-term market cycles (Fourier feature). Feature engineering is equipping your model with this "investor's intuition" by making the temporal context explicit.

💡 If you remember one thing

Feature engineering for time series is about converting the implicit temporal information (order, seasonality, trends) into explicit, static numerical features. This allows traditional, non-recurrent ML models to 'understand' and leverage the time dimension effectively for forecasting or classification tasks.

2
How Each Feature Type Works
▼

1. Lag Features

Lag features represent the value of the time series at a previous time step. For example, if you want to predict sales tomorrow, knowing sales yesterday or last week is often highly predictive. A lag of \(k\) means using the value from \(k\) time steps ago: \(X_{t-k}\).

2. Rolling Statistics (Moving Window)

These features summarize the time series over a sliding window of past observations. Common examples include:

  • Rolling Mean: Average value over the last \(w\) periods. Captures local trend.
  • Rolling Standard Deviation: Volatility over the last \(w\) periods.
  • Rolling Min/Max: Extreme values over the last \(w\) periods.
These help smooth out noise and highlight underlying patterns within a specific timeframe.

3. Date and Time-Based Features

Many real-world time series exhibit patterns tied to calendars. These features extract components from the timestamp:

  • Day of Week/Month/Year: E.g., sales are often higher on weekends.
  • Hour of Day: E.g., energy consumption peaks during working hours.
  • Holiday Flags: Binary indicators for holidays or special events.
  • Is Quarter/Month End: Accounting periods can show different behaviors.
These features directly model known periodicities and external influences.

4. Fourier Features (Seasonal Components)

For strong, regular seasonal patterns (e.g., yearly, quarterly, daily), sine and cosine transformations of the time index can be powerful. They convert a cyclical variable into two continuous features that capture its position within the cycle without implying linear progression (e.g., December isn't "much larger" than January, it's just at the other end of the cycle). They are typically added for multiple frequencies to capture complex seasonality.

Design Decision: Why not just use LSTMs or Transformers?

Deep learning models like LSTMs and Transformers are designed to learn temporal dependencies automatically. However, explicit feature engineering still offers several advantages:

  • Interpretability: Knowing that 'sales on Sunday' is a strong feature is more transparent than a learned hidden state.
  • Simpler Models: Often, well-engineered features allow simpler, faster models (e.g., XGBoost) to achieve competitive performance, reducing computational cost.
  • Data Scarcity: With limited data, deep models struggle to learn patterns; explicit features provide a strong inductive bias.
  • Domain Knowledge: Feature engineering allows direct injection of domain expertise (e.g., specific holiday effects).

🔑 Key Property

The core idea behind all these techniques is to transform a time series forecasting problem into a supervised learning problem for traditional models. Each observation \\(X_t\\) becomes a row in a feature matrix, with columns representing \\(X_{t-k}\\), rolling statistics, and date components, effectively giving the model a "snapshot" of the past and present context for each prediction.

3
The Math Behind the Features
▼

Lag Features

A lag feature for a time series \(X_t\) at lag \(k\) is simply its value \(k\) periods ago. This is crucial for capturing autocorrelation — the correlation of a time series with its past values:

$$ \text{Lag}(X, k)_t = X_{t-k} $$

For example, a common lag is \(k=1\) (yesterday's value), or \(k=\text{seasonal period}\) (e.g., same day last week/year).

Rolling Statistics

Rolling statistics summarize a window of \(w\) previous observations. For a rolling mean, this is:

$$ \text{RollMean}(X, w)_t = \frac{1}{w} \sum_{i=1}^{w} X_{t-i} $$

Similarly, rolling standard deviation \(\text{RollStd}(X, w)_t = \sqrt{\frac{1}{w} \sum_{i=1}^{w} (X_{t-i} - \text{RollMean}(X, w)_t)^2}\). These features are effective at capturing local trends, seasonality, and volatility, acting as a form of low-pass filter or change detector.

Fourier Features for Seasonality

Cyclical patterns can be represented using sine and cosine functions. For a given period \(P\) (e.g., 365.25 for yearly, 7 for weekly) and a time index \(t\) (e.g., day of year, day of week), the features are:

$$ \text{Sine}(t, P) = \sin\left(\frac{2\pi t}{P}\right) \quad \text{and} \quad \text{Cosine}(t, P) = \cos\left(\frac{2\pi t}{P}\right) $$

These two features together capture the cyclical position without implying a linear relationship (e.g., that day 364 is "much larger" than day 1). Multiple frequencies (harmonics) can be used (e.g., for yearly seasonality, also include \(\sin(2\pi \cdot 2t/P)\), \(\cos(2\pi \cdot 2t/P)\), etc.).

⚠️ Common Pitfall: Data Leakage

When creating lag or rolling features, ensure you only use past data relative to the current time step \(t\). Using future values (e.g., `X.shift(-1)` in Pandas without careful handling) introduces data leakage, leading to artificially inflated model performance during training and poor generalization in real-world forecasting.

Key Takeaways
▼

When to use these features:

  • Lag Features: When there's strong autocorrelation (e.g., yesterday's sales predict today's). Essential for capturing short-term memory.
  • Rolling Statistics: To capture trends (mean), volatility (std dev), or extremes (min/max) over specific durations. Useful for smoothing noisy data.
  • Date Features: When patterns are tied to calendar cycles (e.g., weekly, monthly, yearly seasonality, holidays). Almost always beneficial for human-activity-driven data.
  • Fourier Features: For strong, smooth, and regular seasonal patterns. Provides a compact and continuous representation of cycles, especially useful when a simple one-hot encoding for dates is too sparse or implies incorrect ordering.

When NOT to use (or consider alternatives):

  • Long-term dependencies: For very long-range dependencies, deep learning models (LSTMs, Transformers) might learn patterns more effectively without explicit feature engineering, though engineered features can still help.
  • Non-stationary data: Some features (like simple lags) can perform poorly on non-stationary data. Differencing the series might be needed first.
  • High dimensionality: Generating too many features can lead to the "curse of dimensionality" and overfitting, especially with redundant features. Feature selection is key.
💡 Big Picture

Feature engineering for time series is a powerful art and science. It transforms a dynamic problem into a static one, allowing a vast array of traditional ML models to be applied. While deep learning offers end-to-end solutions, explicit feature engineering often provides a more interpretable, efficient, and robust approach, especially when domain knowledge is available or computational resources are limited.

Code Trace (Python / Pandas)
▼
import pandas as pd
import numpy as np
# Example data (replace with your actual time series)
dates = pd.to_datetime(pd.date_range(start='2022-01-01', periods=100))
values = np.random.rand(100) * 100
df = pd.DataFrame({'date': dates, 'value': values}).set_index('date')
# 1. Lag Features
df['lag_1'] = df['value'].shift(1)
df['lag_7'] = df['value'].shift(7)
# 2. Rolling Statistics
df['rolling_mean_3'] = df['value'].rolling(window=3).mean().shift(1)
df['rolling_std_7'] = df['value'].rolling(window=7).std().shift(1)
# .shift(1) is crucial to prevent data leakage (only use past data)
# 3. Date Features
df['day_of_week'] = df.index.dayofweek
df['month'] = df.index.month
df['is_weekend'] = (df.index.dayofweek >= 5).astype(int)
# 4. Fourier Features (e.g., for yearly seasonality)
df['day_of_year'] = df.index.dayofyear
df['sin_yearly'] = np.sin(2 * np.pi * df['day_of_year'] / 365.25)
df['cos_yearly'] = np.cos(2 * np.pi * df['day_of_year'] / 365.25)
print(df.head(10))
