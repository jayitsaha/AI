Data Distribution Shift

i.i.d. assumption · covariate shift · label shift · concept drift — detection & correction
Foundational Classical ML Part III Must Know
1
Understanding the Concept
▼

The i.i.d. assumption is the bedrock of supervised learning: training data and test data are assumed to be independent and identically distributed — drawn from the same fixed probability distribution \(p(x, y)\). Almost every theoretical guarantee in ML (bias-variance decomposition, PAC bounds, central limit theorem for estimates) rests on this assumption.

The Real-World Analogy

Imagine training a spam filter on 2019 emails, then deploying it in 2024. The words and styles that spammers use have changed completely (concept drift). Or: training a cancer detector on hospital A's MRI machines, then running it on hospital B's different scanner (covariate shift — the image textures differ). The model was never told the world would change.

Distribution shift is an umbrella term for any violation of i.i.d. It splits into three fundamental types based on what changed:

  • Covariate shift: \(p_{\text{train}}(x) \neq p_{\text{test}}(x)\) but \(p(y|x)\) stays the same — the input distribution changed but the labelling rule did not.
  • Label / prior shift: \(p_{\text{train}}(y) \neq p_{\text{test}}(y)\) but \(p(x|y)\) stays the same — the class frequencies changed but each class still looks the same.
  • Concept drift: \(p_{\text{train}}(y|x) \neq p_{\text{test}}(y|x)\) — the very meaning of a label changes over time (e.g., what counts as spam).
If you remember one thing

i.i.d. = same distribution always. Covariate shift = the features moved but the rule didn't. Concept drift = the rule itself changed. All three break your model's guarantees.

2
How the Assumption Breaks — Formal Definitions
▼

Let \(p_s(x,y)\) be the source (training) distribution and \(p_t(x,y)\) be the target (deployment) distribution. The joint decomposes as \(p(x,y) = p(y|x)\,p(x) = p(x|y)\,p(y)\).

Covariate Shift

$$p_s(y \mid x) = p_t(y \mid x) \quad \text{but} \quad p_s(x) \neq p_t(x)$$

The labelling rule is unchanged, but test inputs come from a different marginal. Classic example: training a credit model on young urban applicants, deploying to rural retirees. The boundary \(p(y|x)\) is identical; the density of examples around it differs.

Label / Prior Shift

$$p_s(x \mid y) = p_t(x \mid y) \quad \text{but} \quad p_s(y) \neq p_t(y)$$

Each class looks the same in feature space, but class proportions shift. E.g., a disease detector trained on 50% prevalence deployed where prevalence is 1%.

Concept Drift

$$p_s(y \mid x) \neq p_t(y \mid x)$$

The actual mapping from features to labels changes. Subtypes:

  • Sudden/abrupt: system change causes an instantaneous jump.
  • Gradual: slow drift over time (e.g., customer taste).
  • Recurring: seasonal patterns that repeat.
  • Incremental: monotone, slow directional drift.
Importance Weighting for Covariate Shift

Under covariate shift, the optimal correction is to reweight each training sample by its importance ratio (density ratio): \(w(x) = p_t(x) / p_s(x)\). The corrected empirical risk becomes \(\hat{R}_{\text{IW}} = \frac{1}{n}\sum_{i=1}^n w(x_i)\,\ell(f(x_i), y_i)\).

Common Confusion

Covariate shift and concept drift are not opposites — both can occur simultaneously. When \(p(x)\) and \(p(y|x)\) both change, it is called dataset shift in the general sense. Always decompose carefully.

3
Detection & Correction Methods
▼

Detecting Covariate Shift

  • Two-sample tests: Train a binary classifier to distinguish source vs. target features. If it achieves AUC > 0.55, shift is present. This is the classifier two-sample test.
  • Maximum Mean Discrepancy (MMD): \(\text{MMD}^2 = \|\mu_s - \mu_t\|_{\mathcal{H}}^2\) measures distance between kernel mean embeddings. If MMD² > threshold → shift detected.
  • KL divergence: Estimate \(D_{\text{KL}}(p_t \| p_s)\) via kernel density estimation on each feature dimension.
  • Kolmogorov-Smirnov (KS) test: Per-feature univariate test; p-value < 0.05 signals distributional change. Simple, fast, industry standard.

Detecting Concept Drift

  • CUSUM / Page-Hinkley: Sequential tests on a running error rate. Triggers an alarm when the cumulative sum of deviations exceeds a threshold \(\lambda\).
  • DDM (Drift Detection Method): Monitors the online error rate \(p_t\) and its standard deviation \(\sigma_t\). Drift: \(p_t + \sigma_t \geq p_{\min} + 2\sigma_{\min}\).
  • ADWIN (Adaptive Windowing): Maintains a variable-length window; splits it when the mean in sub-windows differs beyond \(\epsilon\).
  • Performance monitoring: Simply track accuracy/F1 over sliding windows; statistically significant drop → drift.

KLIEP Density Ratio Estimation

KLIEP (Kullback-Leibler Importance Estimation Procedure) fits \(w(x) \approx \sum_j \alpha_j k(x, x_j^t)\) by maximising \(\sum_{x \in \mathcal{D}_t} \log w(x)\) subject to \(\mathbb{E}_{p_s}[w(x)] = 1\). Numerically more stable than naïve ratio of histograms.

From-Scratch Implementation
▼

Key algorithms for detecting and correcting covariate shift — numerically traced with real values.

KS Test for Covariate Shift Detection

$$D_{n,m} = \sup_x \left| F_n(x) - G_m(x) \right|, \quad p\text{-value} \approx 2e^{-2D_{n,m}^2 \frac{nm}{n+m}}$$
import numpy as np
from scipy.stats import ks_2samp
# Simulate source (train) and target (test) feature distributions
rng = np.random.default_rng(42)
X_source = rng.normal(loc=0.0, scale=1.0, size=1000) # N(0,1)
X_target = rng.normal(loc=1.5, scale=1.2, size=800) # N(1.5, 1.44) — shifted
# KS two-sample test
stat, p_value = ks_2samp(X_source, X_target)
# stat ≈ 0.412, p_value ≈ 1.4e-62 → highly significant shift
# Importance weights via kernel density ratio (simplified)
from sklearn.neighbors import KernelDensity
kde_t = KernelDensity(bandwidth=0.3).fit(X_target.reshape(-1,1))
kde_s = KernelDensity(bandwidth=0.3).fit(X_source.reshape(-1,1))
log_pt = kde_t.score_samples(X_source.reshape(-1,1)) # log p_t(x_i)
log_ps = kde_s.score_samples(X_source.reshape(-1,1)) # log p_s(x_i)
w = np.exp(log_pt - log_ps) # w(x) = p_t/p_s
w = np.clip(w, 0, 10) # clip for numerical stability
# w ≈ near 0 for x«0 (source-heavy region), ≈ 2–4 for x≈1.5 (target region)
# Apply in training: sample_weight=w in sklearn estimators
from sklearn.linear_model import LogisticRegression
clf = LogisticRegression()
clf.fit(X_source.reshape(-1,1), y_source, sample_weight=w)
# Corrected model now performs as if trained on p_t(x)

ADWIN Concept Drift Detection (Sketch)

def adwin_check(window, delta=0.002):
"""Return True if drift detected in window."""
n = len(window)
for split in range(1, n): # try every split point
w0 = window[:split] # older sub-window
w1 = window[split:] # newer sub-window
mu0, mu1 = w0.mean(), w1.mean()
n0, n1 = len(w0), len(w1)
# Hoeffding bound on the difference of means
eps = np.sqrt(np.log(4*n/delta) / (2*n0*n1/n))
if abs(mu0 - mu1) >= eps: # gap exceeds bound → drift
return True, split
return False, None

Production Red Flags

Accuracy looks fine on test set → deploy → silent failure. This is the silent killer of ML in production. Always monitor feature distributions (KS per feature) AND output label frequencies AND performance metrics separately. A model can maintain accuracy while experiencing heavy covariate shift if shift happens to cancel out.
