The local backward rule for every primitive op — copy, swap, transpose, route, reduce, shape
Intermediate Deep Learning Backpropagation O(1) per op
1
Understanding Gradient Flow
▼

What is it? When a network computes a loss, it needs to know how a nudge to any internal number changes that loss. Backpropagation gets this by walking the computational graph backward, and every operation node — add, multiply, matmul, max, sum, concat — has its own small, fixed rule for turning the gradient it receives from downstream into the gradients it hands to its own inputs.

Analogy: Picture a bucket brigade passing water (the gradient) backward down a chain of people (operations). The "add" person hands the full bucket to everyone behind them, unchanged. The "multiply" person swaps buckets — each neighbor gets an amount scaled by what the OTHER neighbor was holding. The "max" person only pours water to whoever was tallest on the forward pass; everyone else gets nothing.

💡 If you remember one thing

Every op's backward rule only needs (1) values it cached on the forward pass and (2) the single upstream gradient \(\bar{z} = \partial L/\partial z\) it's handed. It never needs to know anything about the rest of the network — this locality is what makes autograd modular.

Add → Copy
Gradient passes through unchanged to every input.
Multiply → Swap
Each input's grad is scaled by the other input's value.
Matmul → Transpose
Grad flows back through the transposed weight matrix.
Max / ReLU → Route
Full grad to the winner, zero to everyone else.
Sum ↔ Broadcast → Reduce/Distribute
Reduce ops broadcast grad back; broadcast ops sum grad back.
Concat ↔ Split → Shape
Concat's backward splits; split's backward concatenates.

How It Works Internally
▼

The Graph Walk

During the forward pass, every op caches whatever its backward rule needs: multiply caches both inputs, max caches which input won, matmul caches both matrices. Backward then visits nodes in reverse topological order. At each node: take the upstream gradient \(\bar{z}\), apply the local rule, hand the results to the inputs.

Add — Gradient Copies

\(z = x + y \Rightarrow \partial z/\partial x = 1,\ \partial z/\partial y = 1\), so \(\bar{x} = \bar{z}\), \(\bar{y} = \bar{z}\) — copied unchanged. This is exactly why residual connections \(y = x + F(x)\) protect gradient flow in very deep networks: the identity branch always hands back a gradient with coefficient 1.

Multiply — Gradient Swaps

\(z = xy \Rightarrow \bar{x} = \bar{z}\cdot y,\ \bar{y} = \bar{z}\cdot x\). Each input's gradient depends on the OTHER input's forward value — this is why you must cache both operands.

Matmul — Gradient Transposes

For \(Z = XW\), dimension matching forces \(\bar{X} = \bar{Z}W^\top\) and \(\bar{W} = X^\top\bar{Z}\) — the only way to contract shapes back to the originals.

Max / ReLU — Gradient Routes

\(z=\max(x,y)\) sends the full upstream gradient to whichever input was larger, and exactly zero to the other — a hard, value-dependent gate. This is the mechanism behind "dead ReLUs": a unit with permanently negative input gets zero gradient forever.

Design Decision: Cache vs. Recompute

Nearly every local rule is an algebraic function of forward values (swap needs both operands, matmul-backward needs the other matrix, max needs the winner). Caching those values trades memory for a single cheap backward pass instead of re-running forward computation.

🔑 Key Property

If a value fans out to multiple downstream ops, its total gradient is the sum of the gradients along every path (multivariable chain rule) — never an overwrite.

Why It Works — The Math
▼

Vector-Jacobian Products (VJPs)

For any op \(z = f(u)\), the exact backward rule is \(\bar{u} = J_f^\top \bar{z}\), where \(J_f = \partial z/\partial u\) is the Jacobian and \(\bar{z} = \partial L/\partial z\) is the upstream gradient. Forming \(J_f\) explicitly would be huge for high-dimensional tensors, so every local rule below is really just a closed-form shortcut for computing \(J_f^\top \bar{z}\) without ever materializing \(J_f\).

Add: Jacobian = Identity

\(z = x + y \Rightarrow J_{zx} = J_{zy} = I\). Since \(I^\top \bar{z} = \bar{z}\), both inputs simply receive \(\bar{z}\) unchanged — the "copy" rule falls straight out of the Jacobian being the identity matrix.

Elementwise Multiply: Jacobian = diag(other operand)

\(z = x \odot y \Rightarrow J_{zx} = \operatorname{diag}(y)\). Then \(\bar{x} = \operatorname{diag}(y)^\top \bar{z} = y \odot \bar{z}\) — a diagonal Jacobian collapses the matrix-vector product into an elementwise product, which is the "swap" rule.

Matmul: Index Notation Gives Matrix Form

For \(Z = XW\) with \(Z_{ij} = \sum_k X_{ik}W_{kj}\), differentiate directly:

$$\frac{\partial L}{\partial X_{ik}} = \sum_j \bar{Z}_{ij}\,\frac{\partial Z_{ij}}{\partial X_{ik}} = \sum_j \bar{Z}_{ij} W_{kj} = (\bar{Z}W^\top)_{ik} \quad\Longrightarrow\quad \bar{X} = \bar{Z}W^\top,\ \ \bar{W} = X^\top \bar{Z}$$

No 4D Jacobian tensor ever needs to exist — the index-notation sum collapses directly into two matrix multiplications, one with \(W\) transposed and one with \(X\) transposed.

Max / ReLU: Jacobian = Indicator Diagonal

\(z = \max(x, 0)\) is piecewise-linear: \(\partial z/\partial x = \mathbb{1}[x>0]\). So \(\bar{x} = \bar{z}\cdot\mathbb{1}[x>0]\) — a hard, value-dependent gate. At the kink \(x=0\) the function is non-differentiable; frameworks pick a subgradient convention (usually 0 or the incoming gradient) rather than a true derivative.

⚠️ Common Pitfall

Chaining many matmul + nonlinearity layers means the input gradient is a product of Jacobians: \(\bar{x}^{(0)} = J_1^\top J_2^\top \cdots J_L^\top \bar{z}\). If each \(J_\ell\) has singular values consistently <1 or >1, this product vanishes or explodes exponentially in depth — the mathematical root of vanishing/exploding gradients, and the reason residual connections (Jacobian of the identity branch is exactly \(I\)) stabilize deep networks.

Key Takeaways
▼

What to remember about each rule:

  • Add → Copy: gradient passes through unchanged to every summand — this is why residual connections \(y=x+F(x)\) guarantee at least a coefficient-1 path for gradient back to \(x\).
  • Multiply → Swap: each input's gradient needs the OTHER input's cached forward value — forgetting to cache both operands is a classic custom-autograd bug.
  • Matmul → Transpose: \(\bar{X}=\bar{Z}W^\top\), \(\bar{W}=X^\top\bar{Z}\) — backward through a linear layer costs about the same FLOPs as forward, roughly tripling total compute per training step (1 forward + 2 backward matmuls).
  • Max / ReLU → Route: full gradient to the winner, zero to the loser — a unit stuck with permanently negative input receives zero gradient forever ("dead ReLU").
  • Sum ↔ Broadcast → Reduce/Distribute: a reduction's backward broadcasts the gradient back out; a broadcast's backward sums the gradient back down the broadcast axes.

When this matters in practice:

  • Debugging vanishing/exploding gradients — trace which local Jacobians are shrinking or growing the signal.
  • Writing a custom autograd `Function` — you must implement exactly this forward-cache / backward-VJP pair correctly.
  • Reasoning about memory — every op that caches forward values for its backward rule (multiply, matmul, max) holds onto activations until backward runs, which is why activation checkpointing trades recompute for memory.
💡 The Big Picture

Reverse-mode autodiff never needs global knowledge of the network. Every op only needs its own cached forward values and the single upstream gradient handed to it — this locality is exactly what makes it possible to compose arbitrarily complex graphs from a small library of local rules, and it's why frameworks like PyTorch/JAX can differentiate almost any Python-expressible computation automatically.
