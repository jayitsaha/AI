Baum-Welch Algorithm

Expectation-Maximization for learning Hidden Markov Model parameters from unlabeled sequences
Advanced Probabilistic ML Sequence Models O(N²T) per iteration
1
Understanding Baum-Welch
▼

What is it? A Hidden Markov Model (HMM) has hidden states that drive observable emissions, governed by parameters \(\lambda=(A,B,\pi)\): transition matrix \(A\), emission matrix \(B\), and initial distribution \(\pi\). Baum-Welch learns these parameters from raw observation sequences alone — nobody ever labels which hidden state produced which observation.

Analogy: A detective sees only your daily activity (ice cream, tennis, staying home) but never the weather that caused it. She guesses rough weather-transition and activity rules, uses them to softly infer "today was probably rainy," recounts those soft guesses to sharpen the rules, and repeats. Each loop the rules and guesses reinforce each other until they stabilize.

💡 If you remember one thing

Baum-Welch alternates: (1) forward-backward computes soft posteriors \(\gamma_t(i)\), \(\xi_t(i,j)\) over hidden states given the current parameters (E-step), then (2) those soft counts are turned into new \(\hat\pi,\hat A,\hat B\) by simple normalized averaging (M-step). $$P(O\mid\lambda^{(n+1)}) \geq P(O\mid\lambda^{(n)})$$ — the data likelihood never decreases.

2
How Baum-Welch Works Internally
▼

The Problem: A Log Outside a Sum

We want \(\arg\max_\lambda \log P(O\mid\lambda) = \log\sum_Q P(O,Q\mid\lambda)\), summing over every possible hidden state path \(Q\). The log sits outside the sum, making direct maximization intractable — and brute-force enumeration of all paths costs \(O(N^T)\).

Stage 1 — Forward Pass (α)

\(\alpha_t(i)=P(O_1,\ldots,O_t,q_t=S_i\mid\lambda)\), computed left-to-right via dynamic programming: \(\alpha_1(i)=\pi_i b_i(O_1)\), then \(\alpha_{t+1}(j) = \big[\sum_i \alpha_t(i)a_{ij}\big]b_j(O_{t+1})\).

Stage 2 — Backward Pass (β)

\(\beta_t(i)=P(O_{t+1},\ldots,O_T\mid q_t=S_i,\lambda)\), computed right-to-left: \(\beta_T(i)=1\), then \(\beta_t(i)=\sum_j a_{ij}b_j(O_{t+1})\beta_{t+1}(j)\). Together, forward + backward compute the full likelihood in \(O(N^2T)\) instead of \(O(N^T)\) — roughly 47 orders of magnitude cheaper for \(N{=}10,T{=}50\).

Stage 3 — Posteriors (γ, ξ)

Combining messages at each time seam gives the soft counts:

$$\gamma_t(i)=\frac{\alpha_t(i)\beta_t(i)}{\sum_k\alpha_t(k)\beta_t(k)} \qquad \xi_t(i,j)=\frac{\alpha_t(i)a_{ij}b_j(O_{t+1})\beta_{t+1}(j)}{\sum_k\alpha_t(k)\beta_t(k)}$$

Stage 4 — M-Step Re-estimation

Each parameter becomes a ratio of expected counts — exactly like supervised counting, but with soft (fractional) counts instead of hard 0/1 labels:

$$\hat\pi_i=\gamma_1(i) \qquad \hat a_{ij}=\frac{\sum_t \xi_t(i,j)}{\sum_t \gamma_t(i)} \qquad \hat b_j(k)=\frac{\sum_{t:O_t=k}\gamma_t(j)}{\sum_t \gamma_t(j)}$$

Design Decision: Why Dynamic Programming?

Forward-backward reuses overlapping partial sums across all \(N^T\) paths, collapsing the cost to \(O(N^2T)\) — the same trick used in the Viterbi algorithm and CRF training. Without it, Baum-Welch would be computationally impossible for any real sequence length.

🔑 Key Property

Baum-Welch is coordinate ascent on a variational lower bound (the EM auxiliary function \(Q(\lambda,\bar\lambda)\)). The E-step tightens the bound to touch the true log-likelihood exactly at the current \(\lambda\); the M-step maximizes that bound in closed form.

3
Why It Works — The Math
▼

The EM Auxiliary Function

EM maximizes a tractable lower bound instead of the log-of-a-sum directly:

$$Q(\lambda,\bar\lambda) = \sum_Q P(Q\mid O,\lambda)\,\log P(O,Q\mid\bar\lambda)$$

By Jensen's inequality this bound touches \(\log P(O\mid\bar\lambda)\) exactly when \(\bar\lambda=\lambda\), so maximizing \(Q\) over \(\bar\lambda\) can never decrease the true log-likelihood.

Deriving the M-Step via Lagrange Multipliers

The complete-data likelihood factorizes as \(P(O,Q\mid\lambda)=\pi_{q_1}b_{q_1}(O_1)\prod_{t=1}^{T-1}a_{q_tq_{t+1}}b_{q_{t+1}}(O_{t+1})\), so \(Q(\lambda,\bar\lambda)\) splits into independent pieces for \(\pi\), \(A\), and \(B\). Maximizing \(\sum_i\gamma_1(i)\log\bar\pi_i\) subject to \(\sum_i\bar\pi_i=1\):

$$\mathcal{L}=\sum_i\gamma_1(i)\log\bar\pi_i+\eta\Big(\sum_i\bar\pi_i-1\Big) \;\Rightarrow\; \frac{\partial\mathcal{L}}{\partial\bar\pi_i}=\frac{\gamma_1(i)}{\bar\pi_i}+\eta=0 \;\Rightarrow\; \hat\pi_i=\gamma_1(i)$$

The identical argument row-by-row on \(A\) and \(B\) gives the ratio-of-expected-counts formulas — every M-step is an exact closed-form maximizer, no gradient step or learning rate needed.

Convergence Guarantee

Baum's inequality: \(P(O\mid\hat\lambda)\geq P(O\mid\lambda)\), with equality only at a stationary point. Since \(P(O\mid\lambda)\in[0,1]\) is bounded, the likelihood sequence is monotonic and bounded, hence convergent — but only to a local optimum.

⚠️ Common Pitfall

Baum-Welch does not find the globally optimal HMM — the likelihood surface is highly non-convex, and different random initializations of \((A,B,\pi)\) can converge to very different local optima. Always run multiple restarts and keep the best-scoring model. Also, raw \(\alpha_t(i)\) shrinks geometrically with \(T\) and underflows in floating point without rescaling or log-space computation.

Key Takeaways
▼

When to use Baum-Welch:

  • You have a generative HMM with discrete hidden states and want interpretable transition/emission probabilities
  • No labeled state sequences exist, but raw observation sequences are plentiful
  • You need a principled likelihood-based training criterion with monotonic convergence

When NOT to use:

  • Labeled state sequences exist — just count directly (supervised MLE), it's exact and far cheaper
  • A discriminative model (CRF, neural sequence tagger) would out-predict a generative HMM
  • Sequences/states are so large that repeated \(O(N^2T)\) forward-backward passes become a bottleneck
💡 Big Picture

Baum-Welch = EM specialized to HMMs. The forward-backward algorithm is the tractable "E-step engine"; the M-step is pure normalized counting. It converges monotonically but only to a local optimum — always multi-restart. Related: Viterbi training (hard EM), Kalman filters (continuous-state analogue), CRFs (discriminative analogue).

Code Trace

import numpy as np
# pi=[0.6,0.4] A=[[0.7,0.3],[0.4,0.6]] B=[[0.5,0.5],[0.1,0.9]] O=(A,B,A)
def forward(O, A, B, pi):
T, N = len(O), A.shape[0]
alpha = np.zeros((T, N))
alpha[0] = pi * B[:, O[0]] # alpha_1(i) = pi_i * b_i(O_1)
for t in range(1, T):
alpha[t] = (alpha[t-1] @ A) * B[:, O[t]] # alpha_{t+1}(j) = [sum_i alpha_t(i) a_ij] b_j(O_{t+1})
return alpha
def backward(O, A, B):
T, N = len(O), A.shape[0]
beta = np.zeros((T, N)); beta[T-1] = 1.0 # beta_T(i) = 1
for t in range(T-2, -1, -1):
beta[t] = A @ (B[:, O[t+1]] * beta[t+1]) # beta_t(i) = sum_j a_ij b_j(O_{t+1}) beta_{t+1}(j)
return beta
alpha, beta = forward(O, A, B, pi), backward(O, A, B)
P_O = alpha[-1].sum() # P(O|lambda) = sum_i alpha_T(i)
gamma = alpha * beta / P_O # gamma_t(i) = alpha_t(i)beta_t(i) / P(O|lambda)
xi = np.zeros((T-1, N, N))
for t in range(T-1):
xi[t] = (alpha[t][:,None]*A) * (B[:,O[t+1]]*beta[t+1])[None,:] / P_O
pi_hat = gamma[0] # M-step: pi_hat_i = gamma_1(i)
A_hat = xi[:T-1].sum(0) / gamma[:T-1].sum(0)[:,None] # sum_t xi_t(i,j) / sum_t gamma_t(i)
B_hat = np.stack([gamma[np.array(O)==k].sum(0) for k in range(2)], axis=1)
B_hat /= gamma.sum(0)[:,None] # sum_{t:O_t=k} gamma_t(j) / sum_t gamma_t(j)
