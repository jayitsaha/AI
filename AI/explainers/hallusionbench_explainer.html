1
Understanding HallusionBench
▼

What is it? HallusionBench is a diagnostic benchmark that asks the same yes/no question about two versions of an image — the original and a deliberately edited (counterfactual) version — to figure out why a multimodal LLM (MLLM) gets a visual question wrong. Getting it wrong isn't one failure mode: sometimes the model never really looked at the pixels and just repeated a memorized/"common sense" answer (Language Hallucination); other times it looked, but misread what was actually there (Visual Illusion).

Analogy: Imagine quizzing someone about a photo of a fruit bowl with 5 apples, then editing the photo to show 3 apples and asking the exact same question again. If they say the same thing both times ("yes, more than four") they weren't looking at the new photo at all — they answered from memory/expectation of what fruit bowls usually look like. That's language hallucination. If instead they squint at the new photo and confidently miscount to a wrong number, that's a visual illusion — they engaged with the pixels but perceived them incorrectly.

💡 If you remember one thing

HallusionBench pairs every question with an edited-image counterfactual. If a model's answer doesn't change even though the correct answer did — that's the model's parametric language prior overriding the pixels. If the answer changes but lands on the wrong value — that's a genuine perceptual misread of the image.

2
How the Diagnostic Works Internally
▼

The Entangled Failure Problem

Standard VQA accuracy conflates two very different failure sources. A model can be wrong on a visual question because (a) it never conditioned on the image and instead output whatever its language-model prior says is likely (Language Hallucination, LH), or (b) it did attend to the image but its visual encoder / cross-modal grounding misperceived the content (Visual Illusion, VI). A single accuracy number can't tell these apart — HallusionBench's contribution is a benchmark structure that makes them separable.

Question-Pair Construction

Every base question is asked on (at least) two images that share the same question text but have opposite ground-truth answers: an original image and an edited image where some visual fact has been deliberately flipped — a count changed, a color swapped, an object's position mirrored, a chart bar redrawn, a map route altered. Because the question wording is identical, any difference in the model's behavior across the pair is attributable to the pixels, not to prompt phrasing.

Grouping into Figures

Multiple question-pairs that share the same base image/topic are grouped into a figure. A figure might ask several distinct yes/no questions (e.g. about count, about color, about relative position) all keyed to the same original/edited image pair. This lets HallusionBench compute accuracy at three granularities — per individual question, per question-pair (both variants must be right), and per whole figure (every question about that figure must be right) — which is exactly what the interactive diagram below tracks live.

🔑 Key Design Decision

Why edit the image rather than the question? Because editing the question changes what's being asked; editing the image while holding the question fixed isolates exactly one variable — whether the model's answer tracks the pixels. This is the same logic as a counterfactual/ablation study, applied to perception.

3
Why It Works — The Metrics
▼

Let \(\hat{y}\) denote the model's predicted yes/no answer and \(y\) the ground truth. HallusionBench reports accuracy at three nested granularities that get progressively stricter.

Per-question accuracy — the naive (and misleading) number

$$a_{All} = \frac{1}{N}\sum_{i=1}^{N} \mathbb{1}[\hat{y}_i = y_i]$$

This is ordinary VQA accuracy over every single question instance (both original and edited images counted independently). It is the metric everyone reports — and the one most inflated by lucky guesses and prior-matching.

Question-pair accuracy — catches Language Hallucination

$$a_{PQ} = \frac{1}{P}\sum_{p=1}^{P} \mathbb{1}\big[\hat{y}_{p,o}=y_{p,o} \;\wedge\; \hat{y}_{p,e}=y_{p,e}\big]$$

A pair \(p\) (original \(o\), edited \(e\)) only counts as correct if both answers are right. Since \(y_{p,o} \neq y_{p,e}\) by construction, a model that ignores the image and outputs a constant answer scores 0 on that pair — even though it might score 50% on \(a_{All}\) for the same pair. This is precisely the arithmetic signature of language hallucination.

Figure-level accuracy — the strictest, most holistic view

$$a_{FP} = \frac{1}{F}\sum_{f=1}^{F} \mathbb{1}\Big[\textstyle\bigwedge_{p \,\in\, f} \big(\hat{y}_{p,o}=y_{p,o} \wedge \hat{y}_{p,e}=y_{p,e}\big)\Big]$$

A figure \(f\) counts as correct only if every question-pair belonging to it is fully correct. Because it's a conjunction over more binary events, \(a_{FP} \le a_{PQ} \le a_{All}\) always. Also useful: splitting \(a_{All}\) by image type gives \(a_{Easy}\) (accuracy on original, unedited images) and \(a_{Hard}\) (accuracy on edited, counterfactual images) — the gap \(a_{Easy}-a_{Hard}\) directly measures how much the model relies on its language prior instead of the pixels.

⚠️ Common Pitfall

Reporting only \(a_{All}\) can make a badly-hallucinating model look competent. A model that always answers "Yes" gets 50% on \(a_{All}\) for every flipped pair, yet scores 0% on \(a_{PQ}\) and \(a_{FP}\) — the drop from \(a_{All}\) to \(a_{PQ}/a_{FP}\) is the tell-tale sign of entangled hallucination, not a rounding artifact.

Key Takeaways
▼

Diagnosing a wrong answer:

  • Same answer on original & edited image, wrong on at least one → Language Hallucination — model ignored the pixels and repeated its parametric prior.
  • Different answer on original & edited image, but still not both correct → Visual Illusion — model did condition on pixels, but perceived them incorrectly.
  • Correct on both → genuinely grounded, image-faithful reasoning.

When to trust which metric:

  • Use \(a_{All}\) only as a coarse sanity check — never as evidence of visual grounding.
  • Use \(a_{PQ}\) to detect language hallucination specifically.
  • Use \(a_{FP}\) when you need a holistic, hardest-to-game measure of whether a model reasons consistently about a whole scene.
💡 Big Picture

HallusionBench's central empirical finding: leading MLLMs that score 70-90% on \(a_{All}\) often collapse to 20-40% on \(a_{FP}\). The gap is not noise — it is quantified evidence that most "visual understanding" benchmarks were letting language priors do the heavy lifting.

Code Trace — Computing the Three Metrics
▼
import numpy as np
# records: list of dicts, one per question-pair
# each has figure_id, model_o, model_e, truth_o, truth_e
records = load_hallusionbench_predictions()
# --- a_All: naive per-question accuracy ---
correct, total = 0, 0
for r in records:
correct += int(r['model_o'] == r['truth_o'])
correct += int(r['model_e'] == r['truth_e'])
total += 2
a_all = correct / total
# --- a_PQ: question-pair accuracy (catches LH) ---
pair_correct = [int(r['model_o']==r['truth_o'] and
r['model_e']==r['truth_e']) for r in records]
a_pq = np.mean(pair_correct)
# --- a_FP: figure-level accuracy (strictest) ---
from collections import defaultdict
by_fig = defaultdict(list)
for r, ok in zip(records, pair_correct):
by_fig[r['figure_id']].append(ok)
a_fp = np.mean([all(v) for v in by_fig.values()])
print(f"a_All={a_all:.1%} a_PQ={a_pq:.1%} a_FP={a_fp:.1%}")
# classic pattern: a_All > a_PQ > a_FP (LH + VI compound)
