Understanding Graph ML Tasks
▼

What is it? Graph Machine Learning (GML) applies ML techniques to data structured as graphs (nodes and edges). Unlike traditional ML on tabular data, GML models learn not just from individual feature vectors, but also from the relationships (edges) between data points (nodes). Three fundamental tasks dominate GML:

  • Node Classification: Predicting a label or category for each node in the graph. Examples: classifying users in a social network (e.g., "influencer" or "bot"), categorizing scientific papers in a citation network by topic.
  • Link Prediction: Predicting the existence of a link (edge) between two nodes. Examples: recommending friends in a social network, identifying potential drug-target interactions, predicting future citations.
  • Graph Classification: Predicting a label or category for an entire graph. Examples: classifying molecules by toxicity, categorizing social networks by type (e.g., "professional" or "casual"), detecting fraudulent transaction graphs.

Analogy: Imagine a school where students are nodes and friendships are edges.

  • Node Classification: Predicting if a student is "good at math" based on their own grades and who their friends are.
  • Link Prediction: Predicting if two students who aren't currently friends are likely to become friends in the future, based on their shared friends and interests.
  • Graph Classification: Analyzing an entire class's friendship network to predict if it's a "collaborative" or "competitive" class overall.

💡 If you remember one thing

All three tasks fundamentally rely on learning effective graph representations (embeddings) that capture both local node features and global graph structure. The choice of task dictates what level of granularity (node, pair, or whole graph) these embeddings are used for prediction.

2
How It Works Internally
▼

The Common Thread: Graph Neural Networks (GNNs)

At the heart of modern GML tasks are Graph Neural Networks (GNNs). GNNs learn node embeddings (vector representations for each node) by iteratively aggregating information from a node's local neighborhood. This "message passing" mechanism allows nodes to learn representations that are aware of their structural context.

Task-Specific Prediction Heads

Once GNNs have generated rich node embeddings, different "prediction heads" are attached for each task:

  • Node Classification: For each node \(v\), its learned embedding \(h_v\) is passed through a simple classifier (e.g., a linear layer followed by softmax) to predict its label \(\hat{y}_v\). The model learns to map node features and neighborhood context to node labels.
  • Link Prediction: To predict a link between two nodes \(u\) and \(v\), their respective embeddings \(h_u\) and \(h_v\) are combined (e.g., by concatenation, element-wise product, or dot product) and then fed into a binary classifier (e.g., a linear layer with sigmoid activation) to output the probability of an edge \(\hat{A}_{uv}\). The model learns to identify patterns in node similarity or interaction.
  • Graph Classification: For tasks involving entire graphs, the individual node embeddings \(h_v\) from all nodes in a graph \(G\) must be aggregated into a single graph-level embedding \(h_G\). This is typically done via a "readout" function (e.g., sum, mean, or max-pooling over all node embeddings). This \(h_G\) is then passed to a classifier to predict the graph's label \(\hat{y}_G\). The model learns to summarize global structural and feature patterns.

Input Data Structure

All these tasks operate on a graph \(G = (V, E)\) where \(V\) is the set of nodes and \(E\) is the set of edges. Each node \(v \in V\) can have initial features \(x_v \in \mathbb{R}^d\) (e.g., age, text description, etc.). Edges can also have features, though often they are simply binary (exist/not exist).

🔑 Key Property

The power of GML comes from its ability to learn context-aware node embeddings. For node tasks, this context directly informs the node's label. For link tasks, it informs the relationship between nodes. For graph tasks, it informs a global summary of the graph's properties.

3
Why It Works — The Math of Message Passing
▼

The Message Passing Paradigm

A core idea in GNNs, underpinning all three tasks, is message passing. In a simple GNN layer (like a Graph Convolutional Network, GCN), a node's embedding at layer \((l+1)\) is computed by aggregating its own embedding from layer \((l)\) and the embeddings of its neighbors. For a node \(v\) with neighbors \(\mathcal{N}(v)\):

$$h_v^{(l+1)} = \sigma\left(W_{self} h_v^{(l)} + W_{neigh} \sum_{u \in \mathcal{N}(v)} \frac{1}{\sqrt{\text{deg}(v)\text{deg}(u)}} h_u^{(l)}\right)$$

Here, \(\sigma\) is an activation function (e.g., ReLU), \(W_{self}\) and \(W_{neigh}\) are learnable weight matrices, and the sum is a normalized aggregation of neighbor messages. This process is repeated for several layers, allowing information to propagate across the graph.

Task-Specific Output Layers

Once a final set of node embeddings \(H = \{h_v | v \in V\}\) is obtained (after \(L\) layers of message passing), the task-specific predictions are made:

  • Node Classification: Each node's embedding \(h_v\) is fed into a linear layer followed by softmax to get class probabilities:
    $$\hat{y}_v = \text{softmax}(W_{node} h_v + b_{node})$$
    The loss function is typically cross-entropy, computed over labeled nodes.
  • Link Prediction: For a pair of nodes \((u, v)\), their embeddings are combined (e.g., via a dot product) and passed through a sigmoid to predict edge existence:
    $$\hat{A}_{uv} = \sigma_{sigmoid}(h_u^\top h_v)$$
    The loss is often binary cross-entropy, comparing \(\hat{A}_{uv}\) to the true adjacency matrix entry \(A_{uv}\). More complex combination functions can also be used.
  • Graph Classification: All node embeddings in a graph \(G\) are aggregated into a single graph embedding \(h_G\). A common "readout" function is simple summation:
    $$h_G = \text{READOUT}(H) = \sum_{v \in V} h_v$$
    Then, \(h_G\) is passed to a classifier:
    $$\hat{y}_G = \text{softmax}(W_{graph} h_G + b_{graph})$$
    Again, cross-entropy is a typical loss, computed over labeled graphs.
⚠️ Common Pitfall

GNNs are powerful, but they are inherently transductive for node and link prediction on a single large graph — they learn embeddings for nodes present during training. For new, unseen nodes (cold-start problem) or entirely new graphs (for graph classification), specialized inductive learning techniques or careful aggregation strategies are required.

Key Takeaways
▼

When to use each task:

  • Node Classification: When you need to label individual entities within a graph structure, and these labels are influenced by their connections (e.g., identifying spam accounts, recommending content to users).
  • Link Prediction: When you need to infer missing connections or predict future interactions between entities (e.g., friend recommendations, knowledge graph completion, protein-protein interaction prediction).
  • Graph Classification: When the entire graph represents a single instance whose overall property needs to be predicted (e.g., drug discovery, social network analysis for community detection, malware detection from execution graphs).

When NOT to use / Challenges:

  • Non-graph data: If your data has no inherent relational structure, GML is not applicable.
  • Scalability: Training GNNs on extremely large graphs (billions of nodes/edges) can be computationally intensive, requiring advanced sampling or distributed techniques.
  • Cold-start problem: Predicting for entirely new nodes or graphs that were not seen during training can be challenging without specific inductive learning strategies.
  • Over-smoothing: Deep GNNs can cause node embeddings to become too similar (indistinguishable), losing local information.
💡 Big Picture

Node, link, and graph classification represent a hierarchy of prediction granularities in Graph ML. All three leverage the power of Graph Neural Networks to learn context-rich embeddings, transforming raw graph data into a format suitable for downstream predictive tasks.

import torch
import torch.nn.functional as F
from torch_geometric.nn import GCNConv
from torch_geometric.data import Data
# 1. Define a simple GNN model
class GNN(torch.nn.Module):
def __init__(self, in_channels, hidden_channels, out_channels):
super().__init__()
self.conv1 = GCNConv(in_channels, hidden_channels)
self.conv2 = GCNConv(hidden_channels, hidden_channels)
# Output layers for each task
self.node_classifier = torch.nn.Linear(hidden_channels, out_channels)
self.graph_classifier = torch.nn.Linear(hidden_channels, out_channels)
def forward(self, x, edge_index, batch=None):
# Generate node embeddings (h_v)
x = self.conv1(x, edge_index)
x = F.relu(x)
x = self.conv2(x, edge_index)
node_embeddings = x # h_v for all nodes
# Node Classification Head
node_logits = self.node_classifier(node_embeddings)
node_preds = F.log_softmax(node_logits, dim=-1) # log-probabilities
# Link Prediction Head (example: dot product similarity)
# For a pair (u, v), get h_u, h_v and compute h_u @ h_v.T
# This is typically done for positive and negative examples during training
# For inference, you might compute scores for all non-existent links
# Example: score for link between node 0 and node 1
link_score = torch.sum(node_embeddings[0] * node_embeddings[1])
link_pred = torch.sigmoid(link_score) # probability of link
# Graph Classification Head (using global mean pooling)
if batch is not None: # batch is required for pooling multiple graphs
graph_embedding = torch_geometric.nn.global_mean_pool(node_embeddings, batch)
graph_logits = self.graph_classifier(graph_embedding)
graph_preds = F.log_softmax(graph_logits, dim=-1)
else:
graph_preds = None # Not applicable for single graph without batch
return node_preds, link_pred, graph_preds, node_embeddings
