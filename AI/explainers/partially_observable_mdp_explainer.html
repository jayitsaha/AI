Decision making under uncertainty: when the true state is hidden, but observations provide clues

Understanding POMDPs
▼

What is it? A Partially Observable Markov Decision Process (POMDP) is a mathematical framework for sequential decision-making where an agent cannot directly observe the true state of the world. Instead, it relies on noisy observations to infer its current situation and make decisions. It's a generalization of a Markov Decision Process (MDP), where the state is fully observable.

Analogy: Imagine you're a robot navigating a house in the dark. You don't know exactly which room you're in (the true state), but you can feel the texture of the floor, hear sounds, or smell food (observations). Based on these clues, you form a "belief" about your location. You then decide to move left or right (actions), and after each move, you gather new observations to update your belief. Your goal is to reach the kitchen (reward) without bumping into furniture (penalty), all while being uncertain about your exact position.

💡 If you remember one thing

In a POMDP, the agent doesn't act on the (hidden) true state \(s\), but on its belief state \(b(s)\) — a probability distribution over all possible true states. The core challenge is maintaining and updating this belief state effectively, turning a problem with hidden states into an MDP over belief states.

2
How It Works Internally
▼

The Components of a POMDP

A POMDP is defined by a 7-tuple \((S, A, T, R, O, Z, \gamma)\):

  • \(S\): A set of unobservable states (e.g., `Room1`, `Room2`).
  • \(A\): A set of observable actions the agent can take (e.g., `MoveLeft`, `MoveRight`).
  • \(T\): The transition function, \(P(s' | s, a)\), giving the probability of transitioning to state \(s'\) from state \(s\) after taking action \(a\).
  • \(R\): The reward function, \(R(s, a)\) (or \(R(s, a, s')\)), giving the immediate reward for taking action \(a\) in state \(s\).
  • \(O\): A set of observable observations the agent can perceive (e.g., `GreenLight`, `RedLight`).
  • \(Z\): The observation function, \(P(o | s', a)\) (often simplified to \(P(o | s')\)), giving the probability of observing \(o\) when in state \(s'\) after taking action \(a\). This is where uncertainty enters.
  • \(\gamma\): The discount factor, for future rewards.

The Belief State and Its Update

Since the true state \(s\) is hidden, the agent maintains a belief state \(b\), which is a probability distribution over \(S\). That is, \(b(s)\) is the probability that the agent is currently in state \(s\). After taking an action \(a\) and receiving an observation \(o\), the belief state is updated using Bayes' rule:

$$b'(s') = P(s' | o, a, b) = \eta \cdot P(o | s', a) \sum_{s \in S} P(s' | s, a) b(s)$$

where \(\eta\) is a normalizing constant to ensure \( \sum_{s' \in S} b'(s') = 1 \). This belief update is the core mechanism that allows a POMDP agent to reason about its hidden state.

Design Decision: Why is POMDP much harder than MDP?

In an MDP, the state space is discrete (e.g., 3 rooms). In a POMDP, the state space is the set of all possible belief distributions over \(S\). If \(S\) has \(N\) states, the belief state \(b\) is a point in an \((N-1)\)-dimensional simplex (a continuous space). Solving for an optimal policy in this continuous belief space is computationally very challenging, often P-SPACE complete. This is why approximate methods are common in practice.

🔑 Key Property

The belief state \(b\) is a sufficient statistic for optimal decision-making. This means that to choose the best action, the agent only needs to know its current belief state; it doesn't need to remember the entire history of actions and observations that led to that belief.

Why It Works — The Belief Update Derivation
▼

Deriving the Belief Update Formula

Let's derive the belief update formula \(b'(s') = P(s' | o, a, b)\). We want to find the probability of being in state \(s'\) given the previous belief \(b\), the action \(a\), and the new observation \(o\).

Using Bayes' rule, we can write:

$$P(s' | o, a, b) = \frac{P(o | s', a, b) P(s' | a, b)}{P(o | a, b)}$$

Since the observation \(o\) only depends on the current state \(s'\) and action \(a\) (and not the previous belief \(b\)), we simplify \(P(o | s', a, b)\) to \(P(o | s', a)\). The term \(P(s' | a, b)\) is the probability of transitioning to \(s'\) after action \(a\) given the previous belief \(b\). We can expand this by summing over all possible previous states \(s\):

$$P(s' | a, b) = \sum_{s \in S} P(s' | s, a, b) P(s | a, b) = \sum_{s \in S} P(s' | s, a) b(s)$$

Here, \(P(s' | s, a, b)\) simplifies to \(P(s' | s, a)\) due to the Markov property (next state only depends on current state and action), and \(P(s | a, b)\) is simply the belief \(b(s)\) from the previous step. Substituting these back into the Bayes' rule equation:

$$b'(s') = \frac{P(o | s', a) \sum_{s \in S} P(s' | s, a) b(s)}{P(o | a, b)}$$

The denominator \(P(o | a, b)\) is a normalizing constant, often denoted \(\eta\), which ensures that the new belief probabilities sum to 1. Thus, we arrive at the standard belief update:

$$b'(s') = \eta \cdot P(o | s', a) \sum_{s \in S} P(s' | s, a) b(s)$$

This formula precisely captures how an agent integrates its prior knowledge (belief \(b\)), its action \(a\), and new sensory information \(o\) to form an updated understanding of its current situation.

⚠️ Common Pitfall

The observation function \(P(o | s', a)\) is crucial. If observations are too noisy (high uncertainty), the belief state might never converge to a single state, even after many steps. If observations are perfectly reliable, the POMDP effectively collapses to an MDP, as the true state can always be inferred. Balancing these is key to modeling realistic scenarios.

Key Takeaways
▼

When to use POMDPs:

  • Any real-world scenario where the agent's sensors are imperfect or provide incomplete information (e.g., robot navigation, medical diagnosis, financial trading).
  • When the agent needs to explicitly reason about its uncertainty and plan actions that gather information (e.g., "explore" actions).
  • For modeling human-computer interaction where user intent (state) is inferred from behavior (observations).

Challenges and Alternatives:

  • Computational Complexity: Solving POMDPs optimally is intractable for large state spaces due to the continuous belief space.
  • Approximation Methods: Point-based value iteration, particle filters for belief tracking, or deep reinforcement learning (e.g., recurrent neural networks that implicitly maintain belief).
  • Model Learning: The transition and observation functions \(P(s' | s, a)\) and \(P(o | s', a)\) are often unknown and must be learned from experience, adding another layer of complexity.
  • Heuristics: For many practical problems, simpler heuristics or fully observable approximations (e.g., treating the most likely state as the true state) might be used if optimality is not strictly required.
💡 Big Picture

POMDPs represent a fundamental step towards intelligent agents that can operate robustly in complex, uncertain environments. While computationally demanding, they provide a rigorous framework for understanding how to act optimally when you don't know exactly what's going on.

import numpy as np
# Example POMDP parameters
states = ['Room1', 'Room2', 'Room3']
actions = ['MoveLeft', 'MoveRight']
observations = ['GreenLight', 'RedLight', 'NoLight']
# Transition model P(s' | s, a) - simplified for explanation
# T[action_idx][s_idx][s_prime_idx]
T = {
'MoveRight': np.array([[0.1, 0.9, 0.0], # from Room1: 10% stay, 90% to Room2
[0.0, 0.1, 0.9], # from Room2: 10% stay, 90% to Room3
[0.0, 0.0, 1.0]]), # from Room3: 100% stay (boundary)
'MoveLeft': np.array([[1.0, 0.0, 0.0], # from Room1: 100% stay (boundary)
[0.9, 0.1, 0.0], # from Room2: 90% to Room1, 10% stay
[0.0, 0.9, 0.1]]) # from Room3: 90% to Room2, 10% stay
}
# Observation model P(o | s') - simplified for explanation
# Z[s_prime_idx][o_idx] given noise_level
def get_observation_prob(obs, s_prime_idx, noise_level):
true_obs_map = {'Room1': 'GreenLight', 'Room2': 'RedLight', 'Room3': 'NoLight'}
s_name = states[s_prime_idx]
if obs == true_obs_map[s_name]:
return 1.0 - noise_level
else:
return noise_level / (len(observations) - 1)
def belief_update(prev_belief, action, observation, noise_level):
next_belief = np.zeros_like(prev_belief)
trans_matrix = T[action]
for s_prime_idx in range(len(states)):
# Calculate P(s' | a, b) = sum_s P(s' | s, a) * b(s)
prob_s_prime_given_a_b = np.sum(trans_matrix[s_idx, s_prime_idx] * prev_belief[s_idx]
for s_idx in range(len(states)))
# Apply P(o | s', a) (or P(o | s'))
obs_prob_given_s_prime = get_observation_prob(observation, s_prime_idx, noise_level)
next_belief[s_prime_idx] = obs_prob_given_s_prime * prob_s_prime_given_a_b
# Normalize the belief distribution
normalization_factor = np.sum(next_belief)
if normalization_factor == 0: # Avoid division by zero if all probabilities are zero
return np.ones_like(next_belief) / len(states) # Revert to uniform belief
return next_belief / normalization_factor
# Initial belief (uniform)
initial_belief = np.array([1/3, 1/3, 1/3])
# Example usage:
current_belief = initial_belief
action = 'MoveRight'
observation = 'RedLight'
noise = 0.1
updated_belief = belief_update(current_belief, action, observation, noise)
print(updated_belief)
