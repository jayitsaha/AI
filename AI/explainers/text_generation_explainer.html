Understanding Decoding & Controllable Generation
▼

What is it? A language model doesn't output words — at every step it outputs a probability distribution over its entire vocabulary (tens of thousands of candidate next tokens). Decoding is the algorithm that turns that distribution into an actual word, one step at a time. Controllable generation goes further: it reshapes that distribution so the generated text follows a topic, sentiment, or style — without retraining the whole model from scratch.

Analogy: Imagine a chef who, after tasting a dish, has an opinion about every possible next ingredient — 70% "add basil," 15% "add oregano," 5% "add chili," and a long tail of unlikely options. Decoding is the rule the chef uses to actually pick one: always take the top choice (greedy), keep a shortlist of promising full recipes and revisit them later (beam search), or roll dice weighted toward the good options (sampling). Controllable generation is like handing the chef a note that says "make it Italian" — it biases every future choice toward basil and oregano without changing how the chef tastes food.

💡 If you remember one thing

The model only ever produces \(p(x_t \mid x_{post-processing rule applied to that same distribution before or during sampling. Decoding strategy and model weights are separable design choices.

How It Works Internally
▼

The Generation Loop

At each timestep \(t\), the transformer produces a hidden state \(h_t\), which the LM head projects to logits \(z_t = W h_t \in \mathbb{R}^{V}\) over the vocabulary of size \(V\). A softmax turns logits into a distribution \(p(x_t \mid x_{

Deterministic vs. Stochastic Decoding

Greedy always takes \(\arg\max\) — fast, deterministic, but myopic: a locally optimal token can lock the sequence into a globally poor continuation, and it is notorious for degenerate repetition loops. Beam search fixes the myopia by tracking \(B\) partial sequences ("beams") in parallel, extending each by its top candidates and keeping only the \(B\) highest cumulative log-probability sequences at every step — a breadth-limited best-first search over sequences. Sampling methods (temperature, top-k, top-p) instead draw a token stochastically from a reshaped distribution, trading determinism for diversity and avoiding beam search's tendency toward bland, generic text.

Controllable Generation: Two Families

CTRL (Keskar et al., 2019) bakes control into training: the model is trained as a conditional LM \(p(x_t \mid x_{PPLM (Dathathri et al., 2019) instead keeps the base LM frozen and steers generation at inference time: a small attribute classifier (or bag-of-words) scores the current hidden states, and gradient ascent on \(\log p(a \mid h_t)\) perturbs the hidden states, with a KL penalty holding the perturbed distribution close to the original LM so fluency is preserved.

🔑 Key Property

CTRL controls generation by changing what the model was trained to condition on. PPLM controls generation by perturbing activations of a frozen model at test time using gradients from an external attribute model. Same goal, opposite design axis: train-time vs. inference-time control.

Why It Works — The Math
▼

Softmax with Temperature

Given logits \(z \in \mathbb{R}^V\), temperature \(T\) rescales before the softmax:

$$p_i = \frac{\exp(z_i / T)}{\sum_{j=1}^{V} \exp(z_j / T)}$$

As \(T \to 0^+\), \(p\) collapses onto \(\arg\max z\) (softmax → greedy). As \(T \to \infty\), \(p \to \) uniform. \(T=1\) recovers the model's native distribution.

Top-k and Top-p (Nucleus) Truncation

Top-k keeps only the \(k\) highest-probability tokens and renormalizes: \(V_k = \{i : \text{rank}(p_i) \le k\}\), \(p_i' = p_i / \sum_{j \in V_k} p_j\) for \(i \in V_k\), else \(0\). Top-p instead keeps the smallest set whose cumulative mass exceeds threshold \(p\):

$$V_p = \min\Big\{ |S| : S \subseteq \mathcal{V},\ \textstyle\sum_{i \in S} p_i \ge p,\ i \in S \Rightarrow p_i \ge p_j\ \forall j \notin S \Big\}$$

Top-p adapts the cutoff to the shape of the distribution — a peaked distribution keeps few tokens, a flat one keeps many — which top-k with fixed \(k\) cannot do.

PPLM Update Rule

PPLM combines a Bayesian factorization \(p(x \mid a) \propto p(a \mid x)\, p(x)\) with a gradient step on the hidden state \(H_t\) of the frozen LM:

$$\Delta H_t \leftarrow \Delta H_t + \alpha \frac{\nabla_{\Delta H_t} \log p(a \mid H_t + \Delta H_t)}{\lVert \nabla_{\Delta H_t} \log p(a \mid H_t + \Delta H_t) \rVert^{\gamma}}$$

subject to a KL-divergence penalty \(\lambda \, D_{KL}\big(p(x_t \mid H_t + \Delta H_t) \,\|\, p(x_t \mid H_t)\big)\) that discourages drifting too far from the base model's distribution, iterated for a few gradient steps per token.

⚠️ Common Pitfall

Temperature, top-k, and top-p are often confused with "creativity dials," but they don't add information — they only reshape probability mass the model already assigned. If the model's true distribution is bad (e.g. miscalibrated or repetitive), no decoding strategy fixes that; it can only trade diversity for coherence within what the model already believes.

Key Takeaways
▼
StrategyTypeStrengthWeakness
GreedyDeterministicFast, reproducibleRepetition, myopic
Beam searchDeterministicBetter global coherenceBland, generic; still degenerates
TemperatureStochasticSimple diversity knobNo control over tail risk

When to use what: Use greedy/beam for tasks with one correct answer (translation, summarization) where diversity hurts. Use temperature + top-p for open-ended creative generation (stories, chat). Use CTRL-style control codes when you can afford to fine-tune and need cheap, repeatable steering. Use PPLM-style inference-time steering when you must control a frozen, expensive model without retraining it.

💡 Modern Note

Most production LLM APIs today expose temperature and top_p as the primary knobs, often combined with repetition penalties. Beam search is rare for chat models (it hurts diversity); CTRL-style control codes evolved into instruction-tuning / system prompts, and PPLM's idea — steer activations at inference time — lives on in techniques like activation steering and classifier-guided / RLHF-guided decoding.

import torch
import torch.nn.functional as F
def sample_next_token(logits, temperature=1.0, top_k=0, top_p=1.0):
# 1. Temperature scaling
logits = logits / temperature
# 2. Top-k filtering: zero out all but the k highest logits
if top_k > 0:
topk_vals, _ = torch.topk(logits, top_k)
min_keep = topk_vals[..., -1, None]
logits = torch.where(logits < min_keep, torch.full_like(logits, -float('inf')), logits)
# 3. Top-p (nucleus) filtering
if top_p < 1.0:
sorted_logits, sorted_idx = torch.sort(logits, descending=True)
probs = F.softmax(sorted_logits, dim=-1)
cum_probs = torch.cumsum(probs, dim=-1)
remove = cum_probs > top_p
remove[..., 1:] = remove[..., :-1].clone(); remove[..., 0] = False
sorted_logits[remove] = -float('inf')
logits = torch.zeros_like(logits).scatter(-1, sorted_idx, sorted_logits)
# 4. Softmax -> probability distribution, then sample (argmax = greedy)
probs = F.softmax(logits, dim=-1)
return torch.multinomial(probs, num_samples=1)
# PPLM: perturb hidden states toward an attribute, keep base LM frozen
def pplm_step(H, attribute_classifier, lm_head, alpha=0.02, kl_scale=0.01, n_iter=3):
delta = torch.zeros_like(H, requires_grad=True)
for _ in range(n_iter):
p_attr = attribute_classifier(H + delta) # p(a | H + delta)
fluency_kl = F.kl_div(F.log_softmax(lm_head(H + delta), -1),
F.softmax(lm_head(H), -1), reduction='batchmean')
loss = -torch.log(p_attr) + kl_scale * fluency_kl
grad = torch.autograd.grad(loss, delta)[0]
delta = (delta - alpha * grad).detach().requires_grad_(True)
return lm_head(H + delta) # attribute-steered logits
