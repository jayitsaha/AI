Intermediate Reinforcement Learning Deep Learning O(N) data, O(N) compute
1
Understanding Reward Model Training
▼

What is it? Reward Model (RM) training is "Step 2" in the Reinforcement Learning from Human Feedback (RLHF) pipeline. Its goal is to create a scalar function \(R(x,y)\) that takes a prompt \(x\) and a model response \(y\) and outputs a single number indicating how "good" that response is, according to human preferences. This RM then serves as the objective function for the final RL fine-tuning step.

Analogy: Imagine you're teaching a robot chef to cook. Instead of writing down a perfect recipe (which is hard!), you simply show it two dishes, A and B, and tell it "A is better." You repeat this thousands of times. The robot then learns to predict which dish *you* would prefer based on its ingredients and presentation. This "preference predictor" is the reward model.

💡 If you remember one thing

The Reward Model is trained on a dataset of pairwise human preferences: for a given prompt and two responses, a human annotator picks the better one. The RM learns to predict these preferences by assigning a higher scalar reward to the chosen response than to the rejected one, typically using a binary cross-entropy loss on the difference of their scores.

2
How It Works Internally
▼

The Data: Human Preference Pairs

The training data consists of tuples \((x, y_A, y_B, \text{preference})\), where \(x\) is a prompt, \(y_A\) and \(y_B\) are two different responses generated by a language model (often the SFT model from RLHF Step 1), and \(\text{preference}\) indicates which response a human judge preferred (e.g., \(y_A > y_B\)). These responses are typically generated by sampling from the SFT model and then presented to human annotators for ranking.

The Model: A Neural Network

The reward model \(R(x,y)\) is usually a neural network, often a copy of the language model itself (or a smaller version) with a single linear layer on top that outputs a scalar. It takes the prompt and response concatenated (or processed separately and combined) as input and produces a single reward score.

The Objective: Preference Ranking Loss

For each training example \((x, y_C, y_R)\) (where \(y_C\) is the chosen/preferred response and \(y_R\) is the rejected response), the RM computes two scores: \(R(x, y_C)\) and \(R(x, y_R)\). The goal is to make \(R(x, y_C) > R(x, y_R)\). This is achieved by minimizing a loss function, commonly the log-sigmoid of the difference:

$$L(R(x, y_C), R(x, y_R)) = -\log\left(\sigma\left(R(x, y_C) - R(x, y_R)\right)\right)$$

Minimizing this loss encourages \(R(x, y_C) - R(x, y_R)\) to be large and positive. If \(R(x, y_C) - R(x, y_R)\) is very large, \(\sigma(\cdot)\) approaches 1, and \(\log(1) = 0\), so the loss is low. If \(R(x, y_C) - R(x, y_R)\) is negative (i.e., the RM incorrectly prefers \(y_R\)), \(\sigma(\cdot)\) approaches 0, and \(\log(0) = -\infty\), leading to a very high loss (penalizing the model heavily).

🔑 Key Property

The RM is trained to predict a relative ordering of responses, not absolute "goodness." Its absolute score values don't matter as much as their differences. This makes the pairwise comparison loss a natural fit.

3
Why It Works — The Math
▼

The Sigmoid Function

The sigmoid function, \(\sigma(z) = 1 / (1 + e^{-z})\), maps any real number to a probability between 0 and 1. In our case, \(z = R(x, y_C) - R(x, y_R)\). So, \(\sigma(R(x, y_C) - R(x, y_R))\) can be interpreted as the RM's predicted probability that \(y_C\) is preferred over \(y_R\).

$$P(y_C > y_R \mid x) = \sigma(R(x, y_C) - R(x, y_R))$$

The Binary Cross-Entropy Connection

The loss function is effectively a binary cross-entropy. If we consider the human preference as a "true" probability of 1 for \(y_C > y_R\), then the loss is \(-\log P(\text{true preference})\). This is a standard way to train a binary classifier where the input is the difference in scores.

$$L = -\log(P(y_C > y_R \mid x)) = -\log\left(\frac{1}{1 + e^{-(R(x, y_C) - R(x, y_R))}}\right)$$

This loss is convex and differentiable, allowing standard gradient-based optimization. The gradients will push \(R(x, y_C)\) up and \(R(x, y_R)\) down, effectively separating their scores.

Gradients for Optimization

Let \(s_C = R(x, y_C)\) and \(s_R = R(x, y_R)\). Let \(d = s_C - s_R\). The loss is \(L = -\log(\sigma(d))\). The gradient of the loss with respect to the difference \(d\) is:

$$\frac{\partial L}{\partial d} = -\frac{1}{\sigma(d)} \cdot \sigma(d)(1 - \sigma(d)) = -(1 - \sigma(d)) = \sigma(d) - 1$$

⚠️ Common Pitfall

The RM is only as good as the human preferences. If annotators are inconsistent, biased, or simply wrong, the RM will learn those flaws. This is why careful data collection, quality control, and diverse annotator pools are critical for successful RLHF.

Key Takeaways
▼

When to use Reward Model training:

  • As Step 2 in an RLHF pipeline to align a language model with complex human values (e.g., helpfulness, harmlessness).
  • When explicit reward functions are difficult or impossible to engineer for a task.
  • To distill human preferences into a computable objective for reinforcement learning.

Challenges and considerations:

  • Data Quality: The RM learns human biases and inconsistencies. High-quality, diverse, and carefully curated human preference data is paramount.
  • Scalability: Collecting human preferences is expensive and time-consuming. Synthetic preference data or active learning strategies are often explored.
  • Generalization: The RM might overfit to the training distribution of responses and fail to generalize to novel or out-of-distribution responses generated during RL fine-tuning.
  • "Reward Hacking": The RM can sometimes be exploited by the policy model, leading to responses that score high on the RM but are not truly good according to humans (e.g., overly verbose, repetitive).
💡 Big Picture

The Reward Model bridges the gap between nuanced human judgment and a concrete, differentiable objective function that a machine learning model can optimize. It's a critical component in making AI systems behave in ways that humans prefer, even for abstract or subjective criteria.

Code Trace (PyTorch)
▼
import torch
import torch.nn as nn
import torch.optim as optim
# 1. Define the Reward Model architecture
class RewardModel(nn.Module):
def __init__(self, input_dim):
super().__init__()
# Typically a pre-trained LM backbone with a linear head
self.backbone = nn.Sequential(
nn.Linear(input_dim, 64), # Simplified for illustration
nn.ReLU(),
nn.Linear(64, 32),
nn.ReLU()
)
self.reward_head = nn.Linear(32, 1) # Outputs a scalar reward
def forward(self, x):
# x is a concatenated (prompt, response) embedding/feature vector
features = self.backbone(x)
return self.reward_head(features)
# 2. Define the preference loss function
def preference_loss(rewards_chosen, rewards_rejected):
# This is the negative log-sigmoid of the difference
# It encourages rewards_chosen > rewards_rejected
return -torch.log(torch.sigmoid(rewards_chosen - rewards_rejected)).mean()
# 3. Simulate a training loop
# Assume 'dataset' provides batches of (response_chosen_features, response_rejected_features)
input_dim = 2 # e.g., for [helpfulness, safety]
model = RewardModel(input_dim)
optimizer = optim.Adam(model.parameters(), lr=1e-3)
# Example dummy data point (chosen_features, rejected_features)
# In reality, these would come from a DataLoader
chosen_features = torch.tensor([[0.8, 0.9]], dtype=torch.float32)
rejected_features = torch.tensor([[0.3, 0.2]], dtype=torch.float32)
# Training step
optimizer.zero_grad() # Clear gradients from previous step
# Forward pass: get scalar rewards for both responses
r_chosen = model(chosen_features)
r_rejected = model(rejected_features)
# Calculate the preference loss
loss = preference_loss(r_chosen, r_rejected)
# Backward pass: compute gradients
loss.backward()
# Optimizer step: update model weights
optimizer.step()
print(f"Loss: {loss.item():.4f}")
print(f"New reward for chosen: {r_chosen.item():.4f}")
print(f"New reward for rejected: {r_rejected.item():.4f}")
