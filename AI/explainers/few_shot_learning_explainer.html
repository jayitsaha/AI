Understanding Few-shot Learning
▼

What is it? Few-shot learning (FSL) is a machine learning paradigm where a model is trained to learn new concepts from very few examples, typically 1 to 5 per class. This contrasts with traditional deep learning, which often requires hundreds or thousands of examples per class to generalize well. FSL is crucial for tasks where data is scarce or expensive to acquire, like medical imaging, rare species classification, or personalized recommendations.

Analogy: Imagine showing a child just one picture of a zebra and one picture of a giraffe. The child can immediately recognize new zebras and giraffes they haven't seen before. They leverage prior knowledge about animals, stripes, long necks, etc. Few-shot learning aims to endow AI models with a similar "learning to learn" (meta-learning) capability, enabling them to quickly adapt to novel categories with minimal supervision.

💡 If you remember one thing

Few-shot learning models are trained on a large number of diverse "tasks" (or episodes), each mimicking the few-shot problem. The goal is to learn a generalizable learning strategy or a good model initialization, rather than to classify specific categories seen during training.

How It Works: Episodic Training & Key Architectures
▼

The Episodic Training Setup (N-way K-shot)

FSL models are typically trained using an "episodic" approach. During meta-training, the model is presented with many small classification tasks, called episodes. Each episode consists of:

  • Support Set (\(S\)): \(N\) randomly chosen classes, with \(K\) labeled examples per class. (This is the "N-way K-shot" configuration).
  • Query Set (\(Q\)): Additional unlabeled examples from the same \(N\) classes.

The model learns to classify the query examples based *only* on the information provided by the support set within that episode. This forces the model to learn a generalizable learning strategy rather than memorizing classes.

Three Popular Approaches

While many FSL methods exist, three prominent ones illustrate different meta-learning strategies:

  • Prototypical Networks (ProtoNets): These learn an embedding function that maps inputs into a low-dimensional space. For each class in the support set, a "prototype" (the mean of its support embeddings) is computed. Query examples are then classified by finding the nearest prototype in this embedding space. This is a metric-learning approach.
  • Matching Networks (MatchNets): Similar to ProtoNets, MatchNets also learn an embedding space. However, instead of prototypes, they classify query examples by comparing them directly to *all* support examples using an attention mechanism. The predicted probability for a class is a weighted sum of similarities to its support examples.
  • Model-Agnostic Meta-Learning (MAML): MAML is an optimization-based meta-learning approach. Instead of learning an embedding or a comparison function, MAML learns a good *initialization* for a model's parameters. This initialization allows the model to adapt quickly to new tasks with just a few gradient descent steps, using only the support set. The meta-training objective is to find an initialization that performs well after adaptation across many diverse tasks.
🔑 Key Property

Prototypical and Matching Networks are metric-learning methods: they learn a similarity function in an embedding space. MAML is an optimization-based method: it learns a meta-initialization that enables fast gradient-based adaptation.

Why It Works — Prototypical Networks (Math)
▼

Prototypical Networks: Learning a Metric Space

Prototypical Networks (Snell et al., 2017) are elegant due to their simplicity and effectiveness. They learn a non-linear mapping \(f_\phi: \mathcal{X} \to \mathbb{R}^M\) (an embedding function, typically a neural network with parameters \(\phi\)) such that examples from the same class are close together, and examples from different classes are far apart. This is achieved by defining a "prototype" for each class and classifying query points based on their distance to these prototypes.

Given a support set \(S = \{(x_i, y_i)\}_{i=1}^{N \times K}\), for each class \(k \in \{1, \dots, N\}\), the prototype \(c_k\) is computed as the mean of the embedded support examples for that class:

$$c_k = \frac{1}{|S_k|} \sum_{(x_i, y_i) \in S_k} f_\phi(x_i)$$

where \(S_k\) is the set of \(K\) support examples for class \(k\).

Once prototypes are established, a query example \(q\) is classified by computing a softmax over the negative distances to each prototype. The probability of query \(q\) belonging to class \(k\) is:

$$P(y=k|q) = \frac{\exp(-d(f_\phi(q), c_k))}{\sum_{k'=1}^N \exp(-d(f_\phi(q), c_{k'}))}$$

Common choices for the distance function \(d\) include Euclidean distance (squared Euclidean is often used for computational convenience, as it avoids a square root and maintains monotonicity). For squared Euclidean distance, \(d(a,b) = \|a-b\|^2\).

The network is trained end-to-end to minimize the negative log-likelihood of correctly classifying query points:

$$\mathcal{L}(\phi) = -\sum_{q \in Q} \log P(y_q=k_q|q)$$

where \(Q\) is the query set for the current episode, and \(k_q\) is the true class of query \(q\). This forces the embedding function \(f_\phi\) to learn a metric space where prototypes are good representatives for their classes and queries are easily separable.

⚠️ Common Pitfall

MAML, while powerful, is computationally expensive due to requiring second-order derivatives (gradients of gradients) during meta-optimization. This can be mitigated with first-order approximations (FOMAML), but still requires careful implementation and significant compute. ProtoNets are much simpler to implement and train.

Key Takeaways
▼

When to use Few-shot Learning:

  • Limited Data: When obtaining labeled data for new classes is difficult, expensive, or time-consuming.
  • Rapid Adaptation: In scenarios requiring a model to quickly learn and classify novel categories without extensive retraining (e.g., in robotics, personalized medicine).
  • Dynamic Environments: Where new classes frequently emerge, and the model needs to adapt on-the-fly.

When NOT to use / Caveats:

  • Abundant Data: If ample labeled data is available for all classes, traditional supervised learning often yields better performance and is simpler.
  • Domain Shift: FSL models meta-trained on one domain may struggle if the meta-test tasks come from a significantly different domain.
  • Computational Cost: MAML, in particular, can be very resource-intensive during meta-training due to higher-order gradients.
💡 Hierarchy & Trade-offs

Prototypical Networks are simple, efficient, and effective metric-learning. Matching Networks offer more flexibility with attention but are slightly more complex. MAML is powerful and model-agnostic (can apply to any differentiable model) but computationally demanding. The choice depends on the task complexity, available compute, and desired inductive bias.

import torch
import torch.nn as nn
class EmbeddingNet(nn.Module):
def __init__(self, input_dim, hidden_dim, output_dim):
super().__init__()
self.encoder = nn.Sequential(
nn.Linear(input_dim, hidden_dim),
nn.ReLU(),
nn.Linear(hidden_dim, output_dim)
)
def forward(self, x):
return self.encoder(x)
def prototypical_loss(support_embeddings, support_labels, query_embeddings, query_labels):
# 1. Compute Prototypes
classes = torch.unique(support_labels)
prototypes = []
for c in classes:
# Mean of embedded support examples for class c
proto = support_embeddings[support_labels == c].mean(dim=0)
prototypes.append(proto)
prototypes = torch.stack(prototypes) # (N_way, embedding_dim)
# 2. Compute Distances from Query to Prototypes (Squared Euclidean)
# query_embeddings: (N_query, embedding_dim)
# prototypes: (N_way, embedding_dim)
# distances: (N_query, N_way)
distances = torch.cdist(query_embeddings, prototypes, p=2)**2
# 3. Compute Negative Log-Likelihood Loss (Softmax over negative distances)
log_probs = -nn.functional.log_softmax(-distances, dim=1)
loss = log_probs.gather(1, query_labels.unsqueeze(1)).squeeze().mean()
return loss, prototypes
