OPTICS: Ordering Points To Identify the Clustering Structure

A density-based clustering algorithm that orders points by reachability to reveal clusters at multiple density scales through a reachability plot.
Intermediate Unsupervised Learning Clustering O(n² log n)
1
Understanding the Concept
▼

What is OPTICS?

Imagine you're looking at a city from an airplane. You can see tight downtown clusters of buildings, looser suburban neighborhoods, and isolated farmhouses in the countryside. OPTICS (Ordering Points To Identify the Clustering Structure) does exactly this: it scans all your data points and arranges them in a special order that reveals which points belong to which "neighborhoods" — at any density level simultaneously.

The key output is a reachability plot — a bar chart where valleys correspond to clusters. Deep valleys = dense clusters. Higher plateaus between valleys = sparser regions or noise. You choose the valley depth threshold to extract clusters.

The Core Insight

OPTICS is a generalization of DBSCAN that does not require choosing a global ε (neighborhood radius). It produces a hierarchical ordering of points such that similar points appear consecutively, and any DBSCAN clustering for any ε can be extracted from this single ordering without re-running the algorithm.

Real-World Analogy

Think of OPTICS like plotting a terrain elevation map of your data. Points in dense clusters sit in valleys — they're easy to reach from their neighbors. Points in sparse regions or noise sit on tall plateaus — reaching them requires a large "step." The reachability plot is that elevation profile. You slice horizontally (choose a threshold) to flood the valleys and find your clusters — exactly as DBSCAN would, but for any threshold at once.

Key Concept

OPTICS orders \(n\) points into a sequence \(\mathcal{O}\) and assigns each point a reachability distance. A connected valley in the reachability plot below threshold \(\xi\) corresponds to a cluster at that density level. The algorithm generalizes DBSCAN across all \(\varepsilon\) simultaneously.

Prerequisites to Know First

  • Distance metrics (Euclidean, Minkowski)
  • DBSCAN — OPTICS is a generalization of it
  • Density estimation basics (ε-neighborhood, core points)

How OPTICS Works Internally
▼

Two Key Distance Concepts

OPTICS builds on two distances computed for each point \(p\) given a fixed minPts parameter:

  • Core distance \(\text{cd}(p)\): the distance to the minPts-th nearest neighbor of \(p\). If \(p\) has fewer than minPts neighbors within any radius, \(\text{cd}(p) = \text{UNDEFINED}\).
  • Reachability distance \(\text{rd}(p, o)\): the maximum of the core distance of the source point \(o\) and the actual distance from \(p\) to \(o\). This ensures small distances within a core point's neighborhood are "inflated" to at least the core distance, preventing the reachability value from being smaller than the density at the source.
Formulas

$$\text{cd}_{\text{minPts}}(p) = \text{dist}(p,\; \text{minPts-th nearest neighbor of } p)$$

$$\text{rd}_{\text{minPts}}(p, o) = \max\!\left(\text{cd}_{\text{minPts}}(o),\; \text{dist}(p, o)\right)$$

The Algorithm Step by Step

  1. Initialize all reachability distances to \(\infty\) and mark all points as unprocessed.
  2. Pick any unprocessed point \(p\). Mark it processed, output it to the order with reachability = \(\infty\) (first point in a new cluster run).
  3. If \(p\) is a core point (its minPts neighborhood exists): compute reachability distances from \(p\) to all unprocessed neighbors. Insert/update them in a priority queue (ordered seeds) keyed by reachability distance.
  4. Extract the minimum-reachability-distance point \(q\) from seeds. Output \(q\) with its stored reachability distance. Update seeds from \(q\).
  5. Repeat 4 until seeds is empty. If unprocessed points remain, go to step 2 (a new reachability spike = new cluster or noise).

Numerical Trace (7-Point Example)

Dataset: A=(1,2), B=(2,2), C=(2,3), D=(8,7), E=(8,8), F=(7,8), N=(25,80). With minPts=2:

  • cd(A)=1.414, cd(B)=1.000, cd(C)=1.414 — tight cluster
  • cd(D)=1.414, cd(E)=1.000, cd(F)=1.414 — tight cluster
  • cd(N)=74.216 — isolated, very large core distance

Starting from A: B gets rd=max(cd(B),dist(A,B))=max(1.0,1.0)=1.0, C gets rd=max(1.414,1.414)=1.414. Seeds: {B:1.0, C:1.414}. Extract B (lowest). From B: C updates to max(1.414,1.0)=1.414 (no improvement). Next extract C. C's neighbors outside cluster all have high distances. Eventually F enters seeds with rd=7.071. Then D=1.414, E=1.414. Finally N with rd=73.98. Final order: A(∞) → B(1.414) → C(1.0) → F(7.071) → D(1.414) → E(1.414) → N(73.98).

Design Decision: Why max()?

The max() in the reachability formula prevents "leaking" into a cluster at a density finer than the core distance permits. Without it, two dense clusters connected by a sparse bridge could appear merged at a low threshold. The max() ensures the reachability rises at cluster boundaries, creating the visible valleys in the plot.

The Mathematics
▼

Core Definitions (Formal)

Let \(\mathcal{D}\) be a dataset, \(\text{dist}:\mathcal{D}\times\mathcal{D}\to\mathbb{R}_{\geq 0}\) a distance function, and \(\text{minPts}\in\mathbb{N}\) a density threshold.

$$\text{cd}_{\text{minPts}}(p) = \begin{cases} \text{UNDEF} & |\mathcal{N}_\varepsilon(p)| < \text{minPts} \\ \text{dist}(p,\; o_{\text{minPts}}) & \text{otherwise} \end{cases}$$

where \(o_{\text{minPts}}\) is the minPts-th nearest neighbor of \(p\). Note that unlike DBSCAN, we do not fix \(\varepsilon\) — core distance is simply the distance to the minPts-th neighbor in the full dataset.

$$\text{rd}_{\text{minPts}}(p, o) = \begin{cases} \text{UNDEF} & \text{cd}(o) = \text{UNDEF} \\ \max\!\left(\text{cd}(o),\; \text{dist}(p,o)\right) & \text{otherwise} \end{cases}$$

The ξ (Xi) Method for Cluster Extraction

Given the ordered reachability sequence, the ξ method extracts clusters by finding steep downward and upward slopes in the plot. A "steep down area" starts a cluster; a "steep up area" ends it. Formally:

  • A point \(p_i\) is in a steep down area if \(\text{rd}(p_i) \cdot (1-\xi) \geq \text{rd}(p_{i+1})\)
  • A point \(p_i\) is in a steep up area if \(\text{rd}(p_i) \leq \text{rd}(p_{i+1}) \cdot (1-\xi)\)

A cluster corresponds to a consecutive run bracketed by a steep down area on the left and a steep up area on the right, with interior reachability values below the cluster's characteristic level.

$$\text{cluster} = \{p_i, \ldots, p_j\} \text{ where } \text{rd}(p_k) \leq \max(\text{rd}(p_i), \text{rd}(p_j)) \cdot (1-\xi), \; \forall k \in [i,j]$$

Complexity

  • Naive: \(O(n^2)\) time — brute-force neighbor search for each point
  • With spatial index (k-d tree, ball tree): \(O(n \log n)\) average case
  • Space: \(O(n)\) for the reachability array and order sequence
Connection to DBSCAN

Every DBSCAN clustering for any \(\varepsilon' \leq \varepsilon_{\max}\) and fixed minPts can be read off the OPTICS reachability plot by applying a horizontal cutline at height \(\varepsilon'\). The valleys below the cutline correspond exactly to the DBSCAN clusters. OPTICS with ε→∞ subsumes DBSCAN for all ε.

When to Use OPTICS

  • You suspect clusters of varying densities — DBSCAN will either miss sparse clusters or merge dense ones
  • You want to explore structure visually before committing to a threshold
  • Arbitrary-shaped clusters (not spherical)
  • Dataset has noise/outliers that should not be forced into clusters

When NOT to Use OPTICS

  • Very high dimensions (curse of dimensionality degrades density estimates)
  • Massive datasets (>100k points) without a fast spatial index
  • When you need cluster probabilities (use HDBSCAN or GMM instead)
  • When clusters are known to be spherical and similarly sized (K-Means is faster)
Rule of Thumb

Use OPTICS when you can't pick a single ε for DBSCAN and you want to explore the clustering hierarchy. For production with large data, prefer HDBSCAN (which builds the same hierarchy more efficiently). For interpretability via the reachability plot, OPTICS is the gold standard.

From-Scratch NumPy Implementation

import numpy as np
from scipy.spatial.distance import cdist
def optics(X, min_pts=5):
"""OPTICS algorithm from scratch.
Returns: (order, reachability_dists, core_dists)
"""
n = len(X)
# Step 1: compute full pairwise distance matrix O(n^2)
D = cdist(X, X) # shape (n, n)
# Step 2: core distances — distance to min_pts-th nearest neighbor
sorted_D = np.sort(D, axis=1) # sort each row ascending
core_dists = sorted_D[:, min_pts - 1] # (min_pts-1)th neighbor = index min_pts-1
# Step 3: reachability distances and ordering
reach_dists = np.full(n, np.inf)
processed = np.zeros(n, dtype=bool)
order = []
seeds = {} # {point_index: reachability_dist}
def update(idx):
"""Update seeds from newly processed core point idx."""
cd = core_dists[idx]
if cd == np.inf:
return # not a core point
for j in range(n):
if processed[j]:
continue
# reachability distance from j to current point idx
new_rd = max(cd, D[idx, j])
if new_rd < reach_dists[j]: # improvement found
reach_dists[j] = new_rd
seeds[j] = new_rd # insert or update priority
for start in range(n):
if processed[start]:
continue
# Begin a new ordering run (reachability = inf → cluster boundary)
processed[start] = True
order.append(start)
update(start)
while seeds:
# Extract minimum-reachability point from seeds
q = min(seeds, key=seeds.get)
del seeds[q]
processed[q] = True
order.append(q)
update(q)
reach_plot = [reach_dists[i] for i in order]
return order, reach_plot, core_dists
# Production usage: sklearn
from sklearn.cluster import OPTICS
clust = OPTICS(min_samples=5, xi=0.05, min_cluster_size=0.05)
clust.fit(X)
labels = clust.labels_ # -1 = noise
reach = clust.reachability_
order = clust.ordering_

Key gotcha: sklearn's OPTICS uses xi (default 0.05) for cluster extraction by default. Set cluster_method='dbscan' and provide eps to use the horizontal-cutline extraction method instead.
