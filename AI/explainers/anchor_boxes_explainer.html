1
Understanding Anchor Boxes
▼

What are they? Anchor boxes (or "prior boxes") are a set of predefined bounding box templates of various aspect ratios and scales, strategically placed across an image (or more accurately, across a feature map). They serve as a starting point for an object detection model to predict the presence and exact location of objects.

Analogy: Imagine you're looking for objects in a photo, but you only have a few "stencils" of common object shapes (e.g., a tall rectangle for a person, a wide rectangle for a car, a small square for a ball). You place these stencils all over the photo. For each stencil, you ask: "Is there an object here that roughly matches this stencil? If so, how much do I need to nudge/stretch this stencil to perfectly fit the object?" Anchor boxes are these stencils, and the deep learning model learns to predict the "nudge/stretch" (offsets) for each one.

💡 If you remember one thing

Anchor boxes transform the problem of finding arbitrary bounding boxes into a simpler one: predicting small adjustments (offsets) to a fixed set of reference boxes. This makes the regression task easier for the neural network.

2
How Anchor Boxes Work Internally
▼

Grid-Based Prediction

Object detection models like Faster R-CNN, SSD, and YOLO (earlier versions) operate on a feature map produced by a backbone CNN. This feature map has a spatial grid structure (e.g., 16x16 or 8x8). For each cell in this grid, the model generates a fixed number of anchor boxes. These anchors vary in their aspect ratios (e.g., 1:1, 1:2, 2:1) and scales (e.g., small, medium, large).

For instance, if a model uses 3 aspect ratios and 3 scales, it will generate \(3 \times 3 = 9\) anchor boxes at each spatial location (grid cell) in the feature map. Each of these 9 anchors will then be used to make predictions.

Predictions per Anchor

For every anchor box at every grid cell, the network typically predicts:

  1. An objectness score: a probability that an object exists within this anchor box.
  2. Class probabilities: if an object exists, what class it belongs to (e.g., car, person, dog).
  3. Bounding box offsets: four values (\(\Delta x, \Delta y, \Delta w, \Delta h\)) that represent the adjustments needed to transform the anchor box into the precise ground truth bounding box.

This results in potentially thousands or tens of thousands of predictions per image. A crucial post-processing step, Non-Maximum Suppression (NMS), is then used to filter out redundant and low-confidence predictions, leaving only the best ones.

The Rise of Anchor-Free Methods

While effective, anchor-based methods have drawbacks: they rely heavily on hand-tuned hyperparameters (aspect ratios, scales), generate a huge number of redundant boxes (requiring expensive NMS), and struggle with objects of extreme or unusual shapes. These limitations led to the development of anchor-free object detection models (e.g., FCOS, CenterNet, YOLOv5+). These models directly predict object properties from points, bypassing the need for predefined anchors.

🔑 Key Property

Anchor boxes simplify the regression task by predicting relative offsets. The network learns to refine these "guesses" rather than predicting absolute coordinates from scratch. This makes training more stable and efficient for many architectures.

3
Why It Works — The Math
▼

Generating Anchor Boxes

For a feature map of size \(W_f \times H_f\), each cell \((i, j)\) corresponds to a specific region in the input image. Its center \((c_x, c_y)\) can be calculated based on the stride \(S_{stride}\) of the convolutional layers:

$$c_x = (j + 0.5) \cdot S_{stride}, \quad c_y = (i + 0.5) \cdot S_{stride}$$

For each cell, we define a set of \(N_a\) anchor boxes. These are derived from a base size \(S_{base}\), a set of aspect ratios \(\{a_r\}\), and a set of scales \(\{s_k\}\). For each combination of \(a_r\) and \(s_k\), an anchor box has width \(w_a\) and height \(h_a\):

$$w_a = S_{base} \cdot s_k \cdot \sqrt{a_r}, \quad h_a = S_{base} \cdot s_k / \sqrt{a_r}$$

The total number of anchors per image is \(W_f \times H_f \times N_a\). For a \(16 \times 16\) feature map with \(N_a=9\) anchors per cell, this is \(256 \times 9 = 2304\) anchors.

Bounding Box Regression Targets

During training, each ground truth box \(G=(G_x, G_y, G_w, G_h)\) is matched to an anchor box \(A=(A_x, A_y, A_w, A_h)\) (e.g., by highest Intersection Over Union - IOU). The network then learns to predict the transformation from \(A\) to \(G\). These transformations are typically normalized offsets:

$$\begin{aligned} t_x &= (G_x - A_x) / A_w \\ t_y &= (G_y - A_y) / A_h \\ t_w &= \log(G_w / A_w) \\ t_h &= \log(G_h / A_h) \end{aligned}$$

Where \((A_x, A_y)\) are the center coordinates of the anchor box. The inverse transformations are used during inference to convert predicted offsets \((t'_x, t'_y, t'_w, t'_h)\) back into absolute bounding box coordinates:

$$\begin{aligned} P_x &= A_x + t'_x \cdot A_w \\ P_y &= A_y + t'_y \cdot A_h \\ P_w &= A_w \cdot e^{t'_w} \\ P_h &= A_h \cdot e^{t'_h} \end{aligned}$$

This formulation makes the regression task more stable. Instead of predicting large, absolute coordinates, the network predicts small, relative shifts and scaling factors.

⚠️ Common Pitfall

The choice of anchor box hyperparameters (aspect ratios, scales) is crucial. If they don't closely match the typical shapes and sizes of objects in your dataset, the network will struggle to learn accurate offsets, leading to poorer detection performance. These are often determined by clustering ground truth boxes (e.g., K-means).

Key Takeaways
▼

Anchor-Based Pros:

  • Robustness: Provide strong priors, making the regression task easier and more stable.
  • Efficiency: Allow parallel prediction across all anchors, leveraging GPU parallelism.
  • Maturity: Well-established in many high-performing architectures (Faster R-CNN, SSD).

Anchor-Based Cons:

  • Hyperparameter Tuning: Requires careful selection of aspect ratios and scales, often data-dependent.
  • Redundancy: Generates many redundant boxes, increasing computation for NMS.
  • Flexibility: Can struggle with objects of unusual shapes or sizes not covered by anchors.

Anchor-Free Pros:

  • Simplicity: No need for anchor box hyperparameters, simplifying the pipeline.
  • Flexibility: Better at detecting objects of arbitrary shapes and sizes.
  • Efficiency: Often faster due to fewer predictions and simpler NMS.

Anchor-Free Cons:

  • Ambiguity: Can struggle with defining a "center" for some objects (e.g., a hollow object).
  • Performance Gap (Historically): Initially, anchor-free models lagged behind anchor-based ones, but this gap has largely closed.
💡 Modern Trend

While anchor boxes were foundational, the trend in recent years (YOLOv5+, FCOS, CenterNet) is towards anchor-free approaches, which offer simpler pipelines, fewer hyperparameters, and often better performance across a wider range of object shapes.

Code Trace (Anchor Box Generation)
▼
import numpy as np
def generate_anchors(feature_map_size, base_size, aspect_ratios, scales, stride):
"""
Generates anchor boxes for a single feature map level.
Args:
feature_map_size (int): H or W of the square feature map.
base_size (int): Base anchor size (e.g., 16 for a 16x16 anchor).
aspect_ratios (list): List of aspect ratios (e.g., [0.5, 1.0, 2.0]).
scales (list): List of scales (e.g., [0.5, 1.0, 2.0]).
stride (int): Stride of the feature map relative to input image.
Returns:
np.ndarray: Array of anchor boxes [cx, cy, w, h] for the entire feature map.
"""
anchors = []
for i in range(feature_map_size):
for j in range(feature_map_size):
center_x = (j + 0.5) * stride
center_y = (i + 0.5) * stride
for ar in aspect_ratios:
for s in scales:
width = base_size * s * np.sqrt(ar)
height = base_size * s / np.sqrt(ar)
anchors.append([center_x, center_y, width, height])
return np.array(anchors)
# Example usage:
fm_size = 8 # 8x8 feature map
base_s = 16 # Base anchor size 16x16 pixels in input image
aspects = [0.5, 1.0, 2.0]
scales = [0.5, 1.0, 2.0]
stride = 32 # e.g., input 256x256 -> 8x8 feature map (stride 32)
all_anchors = generate_anchors(fm_size, base_s, aspects, scales, stride)
print(f"Total anchors: {len(all_anchors)}")
# Expected: 8*8 * 3*3 = 576 anchors
print(f"First anchor: {all_anchors[0].round(2)}")
# Expected: [16. 16. 11.31 32.] (for ar=0.5, scale=0.5)
