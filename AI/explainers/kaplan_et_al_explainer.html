1
Understanding Scaling Laws
▼

What is it? The "Scaling Laws for Neural Language Models" paper by Kaplan et al. (2020) revealed that the performance (measured by test loss) of large language models (LLMs) follows predictable power-law relationships with respect to three key factors: the number of model Parameters (\(N\)), the size of the training Dataset (\(D\)), and the total training Compute (\(C\)). This means that as you increase any of these resources, the model's loss decreases in a mathematically precise, predictable way, rather than hitting hard plateaus.

Analogy: Imagine you're building a tower. Its height (performance) depends on three things: the number of bricks (parameters), the amount of cement (data), and how many workers you have (compute). Kaplan's laws say that if you want a taller tower, you can predict exactly how much taller it will get if you add more bricks, or more cement, or more workers. Crucially, they also tell you the *best way* to allocate your resources — e.g., should you buy more bricks or more cement for the same budget?

💡 If you remember one thing

The test loss of a language model decreases as a power law with increasing \(N\), \(D\), and \(C\). More importantly, for any given compute budget, there's an optimal allocation of parameters and data that minimizes test loss, which Kaplan et al. initially suggested was roughly \(N \propto D\).

2
How the Factors Interact
▼

The Three Key Factors

The paper systematically varied three independent factors across hundreds of transformer models:

  • Parameters (\(N\)): The number of non-embedding parameters in the model. This directly impacts the model's capacity to learn complex patterns.
  • Dataset Size (\(D\)): The total number of tokens (words or sub-word units) the model is trained on. This represents the breadth and depth of information the model is exposed to.
  • Training Compute (\(C\)): The total FLOPs (floating-point operations) expended during training. This is typically proportional to \(N \times D \times \text{sequence_length}\), but for simplicity, we often consider it roughly \(N \times D\).

The researchers observed that each of these factors, when increased, independently contributed to reducing the final test loss. However, these factors are not truly independent in a practical sense; increasing \(N\) or \(D\) invariably increases \(C\).

The Irreducible Loss (\(L_{min}\))

Even with infinite resources, a language model cannot achieve zero test loss. This is due to intrinsic unpredictability in natural language, noise in datasets, and fundamental limits of the modeling task itself. Kaplan et al. found an irreducible loss component, \(L_{min}\), which acts as a lower bound on achievable test loss, regardless of how large \(N\), \(D\), or \(C\) become. This implies diminishing returns: as test loss approaches \(L_{min}\), further resource investment yields smaller improvements.

Design Decision: Why Power Laws?

Power laws (\(y = ax^b\)) are ubiquitous in natural and social phenomena (e.g., Zipf's law for word frequencies, Pareto distribution for wealth). In machine learning, they often arise when systems are composed of many interacting elements, and their behavior exhibits scale-invariance. For LLMs, it suggests that the underlying learning dynamics are remarkably consistent across vast scales, making performance highly predictable and guiding future model development.

🔑 Key Property

The exponents in these power laws (\(\alpha_N, \alpha_D, \alpha_C\)) quantify the efficiency of each resource. For example, if \(\alpha_N > \alpha_D\), it means increasing parameters is initially more effective at reducing loss than increasing data, for the same relative increase in the resource.

3
Why It Works — The Scaling Equations
▼

The Core Loss Equation

Kaplan et al. proposed a loss function that combines the effects of parameters (\(N\)), dataset size (\(D\)), and training compute (\(C\)) on the final test loss (\(L\)):

$$L(N, D, C) = \left(\frac{C_0}{C}\right)^{\alpha_C} + \left(\frac{N_0}{N}\right)^{\alpha_N} + \left(\frac{D_0}{D}\right)^{\alpha_D} + L_{min}$$

Here, \(C_0, N_0, D_0\) are characteristic scale constants (effectively setting the "unit" for each resource), and \(\alpha_C, \alpha_N, \alpha_D\) are the respective scaling exponents (all positive). As \(C, N, D\) increase, the terms \((C_0/C)^{\alpha_C}\), \((N_0/N)^{\alpha_N}\), and \((D_0/D)^{\alpha_D}\) decrease, driving the total loss towards \(L_{min}\).

Optimal Allocation for Fixed Compute

A crucial insight from the paper is how to optimally allocate resources given a fixed total compute budget, \(C_{total}\). Assuming training FLOPs are roughly proportional to \(N \times D\), i.e., \(C_{total} \approx k \cdot N \cdot D\), one can find the values of \(N\) and \(D\) that minimize \(L(N, D)\) subject to this constraint. Kaplan et al. found that for optimal scaling, the number of parameters \(N\) and the number of training tokens \(D\) should scale approximately equally with compute:

$$N_{opt} \propto C_{total}^{a} \quad \text{and} \quad D_{opt} \propto C_{total}^{b}$$

Initially, the paper's empirical results suggested \(a \approx b \approx 0.73\), implying that for a fixed compute budget, one should scale \(N\) and \(D\) roughly proportionally to each other (\(N \propto D\)). This means if you have more compute, you should increase both model size and data tokens proportionally to get the best performance.

The Impact on Loss

When resources are optimally allocated, the minimum achievable loss for a given compute budget \(C_{total}\) also follows a power law:

$$L_{minimized}(C_{total}) \approx A \cdot C_{total}^{-\alpha_L} + L_{min}$$

where \(\alpha_L\) is a combined exponent reflecting the overall efficiency of compute in reducing loss. This equation highlights that even with optimal resource allocation, there are diminishing returns to increasing compute, as the loss asymptotically approaches \(L_{min}\).

⚠️ Common Pitfall

The exponents (\(\alpha_N, \alpha_D, \alpha_C\)) are empirical and can change with model architecture, pre-training objectives, or data distribution. While Kaplan et al. provided robust initial estimates, subsequent research (e.g., Chinchilla) has refined these, suggesting different optimal resource allocations, particularly a greater emphasis on data scaling.

Key Takeaways
▼

Implications of Kaplan's Laws:

  • Predictability: Performance is not arbitrary; it follows smooth, predictable curves, enabling robust forecasting of model capabilities.
  • Resource Optimization: For any given budget (e.g., total compute), there is an optimal way to balance model size (\(N\)) and training data (\(D\)) to achieve the best performance.
  • Diminishing Returns: The power-law exponents imply that while increasing resources always helps, the gains become smaller as \(L\) approaches \(L_{min}\).
  • Guidance for Design: These laws provide a framework for designing and training large models efficiently, preventing over-investment in one resource while neglecting another.

Evolution of the Laws (The "Chinchilla" Update):

While Kaplan et al. (2020) suggested that for a given compute budget, parameters and data should scale roughly equally (\(N \propto D\)), a later paper by Hoffmann et al. (2022), "Training Compute-Optimal Large Language Models" (known as the Chinchilla paper), found a different optimal ratio. Chinchilla suggested that for the same compute budget, models should be trained with significantly more data and fewer parameters than previously thought (roughly \(N \approx D/20\)). This implies that many large models (like GPT-3) were "undertrained" on data relative to their parameter count.

💡 Big Picture

The scaling laws fundamentally changed how large language models are developed. They moved LLM design from heuristic trial-and-error to a more principled, empirically-driven science, guiding resource allocation and setting expectations for performance gains.

Code Trace (Simplified Model)
▼
import numpy as np
# --- Kaplan et al. (2020) simplified scaling law parameters ---
L_min = 1.5 # Irreducible loss
alpha_N = 0.07 # Exponent for parameters (N)
alpha_D = 0.05 # Exponent for data (D)
# Constants 'A' and 'B' for loss terms, derived from reference values
N_ref_kaplan = 1e9 # Reference parameters (e.g., 1B)
D_ref_kaplan = 1.67e10 # Reference data tokens (e.g., 16.7B)
L_ref_kaplan = 2.5 # Reference loss at N_ref, D_ref
# Calculate A and B such that L(N_ref, D_ref) = L_ref_kaplan
# Assuming equal contribution to loss reduction for simplicity:
A = (L_ref_kaplan - L_min) / (2 * (N_ref_kaplan**-alpha_N))
B = (L_ref_kaplan - L_min) / (2 * (D_ref_kaplan**-alpha_D))
# Function to calculate test loss for given N and D
def calculate_loss(N, D):
return L_min + A * (N**-alpha_N) + B * (D**-alpha_D)
# Simplified compute model (FLOPs = k * N * D)
K_FLOPs = 6 # Constant (e.g., 6 FLOPs per parameter per token)
# Calculate optimal N and D for a given compute budget C_total
# Kaplan optimal: N ~ D --> N_opt * D_opt = C_total / K_FLOPs
def get_kaplan_optimal_ND(C_total):
# N_opt = D_opt = sqrt(C_total / K_FLOPs)
optimal_val = np.sqrt(C_total / K_FLOPs)
return optimal_val, optimal_val
# Chinchilla optimal: D ~ 20 * N --> N_opt * (20*N_opt) = C_total / K_FLOPs
def get_chinchilla_optimal_ND(C_total):
N_opt = np.sqrt(C_total / (K_FLOPs * 20))
D_opt = 20 * N_opt
return N_opt, D_opt
# Example usage:
C_example = 1e20
N_kap, D_kap = get_kaplan_optimal_ND(C_example)
loss_kap = calculate_loss(N_kap, D_kap)
print(f"Kaplan optimal N: {N_kap:.2e}, D: {D_kap:.2e}, Loss: {loss_kap:.3f}")
N_chin, D_chin = get_chinchilla_optimal_ND(C_example)
loss_chin = calculate_loss(N_chin, D_chin)
print(f"Chinchilla optimal N: {N_chin:.2e}, D: {D_chin:.2e}, Loss: {loss_chin:.3f}")
