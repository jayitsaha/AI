1
Understanding Prototypical Networks
▼

What is it? Prototypical Networks (Snell et al., 2017) are a powerful approach to few-shot learning, where a model must learn to classify new categories given only a handful of examples. Instead of learning explicit decision boundaries, they learn an embedding function that maps inputs into a feature space where examples from the same class cluster together. Classification is then performed by simply finding the nearest "prototype" in this embedding space.

Analogy: Imagine a master chef who can identify a dish's cuisine (Italian, French, Mexican) from just a few ingredients. For a new cuisine, they don't need to learn complex rules; they just taste a few representative dishes (the "support set") and form a mental "average flavor profile" (the "prototype") for that cuisine. When presented with an unknown dish, they compare its flavor to their mental prototypes and assign it to the closest one. Prototypical Networks do this for data points in a high-dimensional feature space.

💡 If you remember one thing

Prototypical Networks learn to map data into an embedding space where each class is represented by a single prototype (the mean of its support examples' embeddings). New, unseen examples (queries) are then classified by assigning them to the class of the prototype they are closest to in this space.

2
How Prototypical Networks Work Internally
▼

The Two-Stage Process

A Prototypical Network operates in two main conceptual stages:

  1. Embedding: An input \(x\) (e.g., an image) is passed through an embedding function \(f_\theta\), typically a convolutional neural network. This function maps \(x\) into a \(D\)-dimensional feature vector (embedding) \(f_\theta(x) \in \mathbb{R}^D\). The parameters \(\theta\) of this network are learned during training.
  2. Distance-based Classification:
    • Prototype Computation: For each class \(c\) in the current task, a prototype vector \(p_c\) is computed as the mean of the embeddings of its support examples. If \(S_c = \{(x_i, y_i) | y_i = c\}\) is the set of support examples for class \(c\), then: $$p_c = \frac{1}{|S_c|} \sum_{(x_i, y_i) \in S_c} f_\theta(x_i)$$
    • Query Classification: For a new, unlabelled query example \(x_q\), its embedding \(f_\theta(x_q)\) is computed. Then, the distance \(d(f_\theta(x_q), p_c)\) from the query embedding to each prototype \(p_c\) is calculated. The query is assigned to the class whose prototype is closest.

Design Decision: Why Distance-Based Classification?

Traditional neural networks often use a softmax layer to output class probabilities. Prototypical Networks instead use distances in the embedding space. This approach is particularly effective for few-shot learning because:

  • It's inherently data-efficient: prototypes can be formed from just one or a few examples per class.
  • It's flexible: new classes can be added by simply computing their prototypes without retraining the entire network.
  • It encourages a semantically meaningful embedding space where similar items are geometrically close.

The network's training objective is to learn the embedding function \(f_\theta\) such that query examples are consistently closer to their true class prototypes than to any other class's prototype.

🔑 Key Property

The embedding function \(f_\theta\) is trained to produce representations such that a simple Euclidean distance (or squared Euclidean) in the embedding space directly reflects the semantic similarity between inputs. This makes the classification step a straightforward nearest-neighbor search.

3
Why It Works — The Math
▼

Probability Distribution over Classes

For a given query example \(x_q\), the probability of it belonging to class \(c\) is determined by a softmax over the negative distances to the prototypes. A common choice for the distance metric \(d\) is the squared Euclidean distance: \(d(v_1, v_2) = \|v_1 - v_2\|_2^2\).

The probability \(P(y=c|x_q)\) is given by:

$$P(y=c|x_q; f_\theta, S) = \frac{\exp(-d(f_\theta(x_q), p_c))}{\sum_{c'} \exp(-d(f_\theta(x_q), p_{c'}))}$$

Here, \(p_c\) is the prototype for class \(c\) (computed as the mean of support embeddings), \(f_\theta(x_q)\) is the embedding of the query example, and \(S\) denotes the support set used to compute the prototypes.

The Loss Function

During training, the goal is to minimize the negative log-likelihood of the true class \(y_q\) for each query \(x_q\). This is standard cross-entropy loss:

$$L(x_q, y_q) = -\log P(y=y_q|x_q; f_\theta, S)$$

The total loss for an episode (a training iteration with a sampled support and query set) is the sum of losses for all query examples. The gradients of this loss are then backpropagated through the embedding function \(f_\theta\) to update its parameters \(\theta\). This pushes the query embedding closer to its true prototype and further from incorrect prototypes.

The Role of Distance and Temperature

The exponential function in the softmax effectively converts distances into similarities. Smaller distances result in larger \(\exp(-d)\) values, leading to higher probabilities. The absence of an explicit "temperature" parameter (which is common in other metric learning methods) means the network learns to scale its embeddings such that the raw Euclidean distances are directly meaningful for classification probabilities.

⚠️ Important Note on Distance

While Euclidean distance is the canonical choice for Prototypical Networks, other distance metrics (e.g., cosine similarity) can be used. However, the specific form of the probability distribution and the resulting gradients would change. Euclidean distance implicitly assumes a spherical decision boundary around prototypes, whereas cosine similarity implies a conical boundary.

Key Takeaways
▼

When to use Prototypical Networks:

  • Few-shot learning: This is their primary application. When you have very few labeled examples for new classes, Prototypical Networks excel at rapidly adapting.
  • Meta-learning: They are a prominent example of meta-learning architectures, where the model learns "how to learn" new tasks efficiently.
  • Interpretability: The concept of class prototypes as centroids in an embedding space offers a degree of interpretability, as you can visualize and analyze these central representations.
  • Online learning: Since prototypes are simply means, they can be updated efficiently as new support examples arrive.

When NOT to use or considerations:

  • Non-linear separability: If classes are not linearly separable (or separable by simple distance metrics) in the learned embedding space, Prototypical Networks may struggle. The embedding function \(f_\theta\) needs to be powerful enough to achieve this separation.
  • High intra-class variance: If a class has highly diverse examples that naturally form multiple clusters, a single prototype (mean) might not be a good representation. More advanced methods like Gaussian Prototypical Networks can address this.
  • Computational cost: For a very large number of classes or very high-dimensional embeddings, computing and comparing against all prototypes can become computationally intensive.
💡 Relation to other methods

Prototypical Networks are closely related to k-Nearest Neighbors (k-NN) but learn the distance metric via the embedding function. They share principles with Siamese Networks (learning a similarity function) and Triplet Networks (learning to pull positives closer and push negatives further apart), but simplify the classification step by explicitly forming class centroids.

Code Trace (PyTorch-style Pseudocode)
▼
import torch
import torch.nn as nn
class EmbeddingNet(nn.Module):
def __init__(self, input_dim, hidden_dim, output_dim):
super().__init__()
# Example: a simple MLP for 2D inputs to 2D embeddings
self.encoder = nn.Sequential(
nn.Linear(input_dim, hidden_dim),
nn.ReLU(),
nn.Linear(hidden_dim, output_dim)
)
def forward(self, x):
return self.encoder(x)
def euclidean_distance_sq(a, b):
return torch.sum((a - b)**2, dim=-1) # Squared Euclidean
def prototypical_loss(embedding_net, support_data, query_data, n_classes, n_support):
# support_data: (n_classes * n_support, input_dim)
# query_data: (n_classes * n_query, input_dim)
# 1. Embed all support examples
support_embeddings = embedding_net(support_data) # (n_classes * n_support, output_dim)
support_embeddings = support_embeddings.view(n_classes, n_support, -1)
# 2. Compute prototypes (centroids for each class)
prototypes = torch.mean(support_embeddings, dim=1) # (n_classes, output_dim)
# 3. Embed all query examples
query_embeddings = embedding_net(query_data) # (n_classes * n_query, output_dim)
# 4. Calculate distances from each query to all prototypes
# Reshape query_embeddings for broadcasting: (n_queries, 1, output_dim)
# Reshape prototypes for broadcasting: (1, n_classes, output_dim)
distances = euclidean_distance_sq(
query_embeddings.unsqueeze(1), # (n_queries, 1, D)
prototypes.unsqueeze(0) # (1, n_classes, D)
) # Result: (n_queries, n_classes)
# 5. Compute log probabilities via softmax over negative distances
log_probs = nn.functional.log_softmax(-distances, dim=-1)
# 6. Prepare true labels for query examples
# Assuming query_data is ordered by class: 0,0,0...1,1,1...2,2,2...
n_query = query_data.shape[0] // n_classes
true_labels = torch.arange(n_classes).repeat_interleave(n_query)
# 7. Compute negative log-likelihood loss
loss = -log_probs.gather(1, true_labels.unsqueeze(1)).mean()
return loss
