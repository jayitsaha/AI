Understanding the DeepSeek Family
▼

What is it? DeepSeek is a family of open-source large language models that introduced several architectural breakthroughs to make training and inference dramatically more efficient. Rather than simply scaling parameters, DeepSeek innovated at the architecture level -- compressing attention memory, routing tokens to specialist sub-networks, and ultimately teaching models to reason through reinforcement learning.

Analogy: Imagine a massive consulting firm. Instead of having every consultant attend every meeting (dense model), DeepSeek V2 organizes specialists into teams -- each client question is routed to only the 8 most relevant experts out of 160 (MoE). V2 also invented a clever shorthand for meeting notes, compressing pages of context into a tiny summary that any consultant can quickly decode (MLA). V3 then taught the firm to predict multiple client needs at once (MTP), and R1 trained consultants to show their reasoning step-by-step before giving answers (RL for reasoning).

If you remember one thing

DeepSeek's core thesis: you don't need to activate all parameters for every token. V2 introduced Multi-head Latent Attention (compresses KV cache by 93.3%) and DeepSeekMoE (activates only 21B of 236B params). V3 scaled to 671B with FP8 training and Multi-Token Prediction. R1 added reinforcement learning (GRPO) to unlock chain-of-thought reasoning without supervised data.

DeepSeek-V2: MLA + DeepSeekMoE
▼

Multi-head Latent Attention (MLA)

Standard Multi-Head Attention (MHA) stores separate Key and Value vectors for every head and every token, leading to a KV cache that grows linearly with sequence length and number of heads. Multi-Query Attention (MQA) and Grouped-Query Attention (GQA) reduce this by sharing KV across heads, but sacrifice quality. MLA takes a fundamentally different approach: it compresses the KV representation into a low-rank latent vector.

For each token, instead of storing \(n_h\) separate K and V vectors of dimension \(d_h\), MLA projects the hidden state \(h_t\) into a compressed latent \(c_t^{KV} \in \mathbb{R}^{d_c}\) where \(d_c \ll n_h \cdot d_h\). During attention, K and V are reconstructed on-the-fly via learned up-projection matrices:

$$c_t^{KV} = W^{DKV} h_t, \quad k_t = W^{UK} c_t^{KV}, \quad v_t = W^{UV} c_t^{KV}$$

The KV cache stores only \(c_t^{KV}\) (dimension 512) instead of full KV pairs (dimension 12,288 in a 96-head model), achieving a 93.3% compression with negligible quality loss. A decoupled Rotary Position Embedding (RoPE) handles positional information separately.

DeepSeekMoE Architecture

DeepSeekMoE uses finer-grained experts than conventional MoE. Instead of 8 large experts (as in Mixtral), it uses 2 shared experts + 160 routed experts per layer. Each token activates only 6 of the 160 routed experts, plus the 2 shared experts. The shared experts capture common knowledge while routed experts specialize.

The routing uses a learned gating function with auxiliary load-balancing losses to prevent expert collapse:

$$g_i = \text{Softmax}(\text{TopK}(s_i, K)), \quad s_i = u_i^\top h_t$$

where \(u_i\) is the centroid vector for expert \(i\), \(h_t\) is the token hidden state, and TopK selects the top-K experts by score. A device-level balance loss and a communication balance loss ensure experts are evenly utilized across GPUs.

Key Design Decision

V2 uses finer-grained experts (more but smaller) rather than fewer large ones. This allows more precise specialization -- a token about Python syntax might activate different experts than one about French grammar, even though both are "code/language" tokens. The shared experts prevent catastrophic forgetting of common capabilities.

DeepSeek-V3: Scaling with FP8 + Multi-Token Prediction
▼

FP8 Mixed-Precision Training

V3 was the first large-scale model to be trained end-to-end with FP8 (8-bit floating point) for most computations. While the master weights and critical accumulations remain in higher precision (BF16/FP32), the matrix multiplications in both forward and backward passes use FP8, nearly doubling throughput on modern GPUs (H800). A fine-grained quantization strategy applies per-block scaling factors to maintain numerical stability.

Multi-Token Prediction (MTP)

Standard language models predict one next token at a time. V3 adds MTP modules that predict multiple future tokens simultaneously. Each MTP module \(k\) (for \(k = 1, \ldots, D\)) uses a separate output head with shared embedding but independent projection layers:

$$\mathcal{L}_{MTP} = \frac{1}{D}\sum_{k=1}^{D} \mathcal{L}_k, \quad \mathcal{L}_k = \text{CrossEntropy}(t_{i+k} \mid t_1, \ldots, t_i)$$

This provides a richer training signal (each position supervises \(D+1\) predictions), acts as implicit data augmentation, and during inference enables speculative decoding -- the MTP heads propose multiple tokens that can be verified in parallel, accelerating generation by 1.8x.

Auxiliary-Loss-Free Load Balancing

V2 used auxiliary losses to balance expert loads, which slightly degraded performance. V3 introduces a bias-based balancing mechanism: each expert gets a learnable bias term added to its gating score. These biases are adjusted dynamically to balance loads without contaminating the main training objective. The result is better load balance with no accuracy penalty.

Training Cost Perspective

DeepSeek-V3 (671B params, 14.8T tokens) was trained for only $5.576M in compute, roughly 1/10th the cost of comparable models (Llama 3.1 405B cost an estimated $60M+). The combination of MoE (fewer active params), FP8 (higher throughput), and efficient engineering made this possible -- challenging the assumption that frontier models require hundreds of millions in compute.

DeepSeek-R1: Reinforcement Learning for Reasoning
▼

From Language Modeling to Reasoning

R1 starts from the V3 base model and applies reinforcement learning to develop reasoning capabilities. The key insight: instead of collecting expensive human-annotated chain-of-thought data (as in OpenAI's o1), R1 shows that RL alone can cause reasoning behaviors to emerge naturally.

Group Relative Policy Optimization (GRPO)

R1 uses GRPO instead of PPO to avoid the cost of training a separate critic/value model. For each prompt \(q\), GRPO samples a group of \(G\) outputs from the current policy \(\pi_\theta\). It computes rewards for each output, then normalizes within the group to get advantages:

$$\hat{A}_i = \frac{r_i - \text{mean}(\{r_1, \ldots, r_G\})}{\text{std}(\{r_1, \ldots, r_G\})}$$

The policy is then optimized with a clipped objective (similar to PPO) using these group-relative advantages:

$$\mathcal{L}_{GRPO} = -\frac{1}{G}\sum_{i=1}^{G}\min\left(\frac{\pi_\theta(o_i|q)}{\pi_{\text{old}}(o_i|q)}\hat{A}_i,\; \text{clip}\left(\frac{\pi_\theta(o_i|q)}{\pi_{\text{old}}(o_i|q)}, 1\pm\epsilon\right)\hat{A}_i\right) + \beta \, D_{KL}(\pi_\theta \| \pi_{\text{ref}})$$

Emergent Reasoning Behaviors

The DeepSeek-R1-Zero experiment (RL directly on the base model, no SFT) revealed remarkable emergent behaviors: the model spontaneously developed self-verification ("Wait, let me check..."), reflection ("I made an error, let me reconsider..."), and allocated more thinking tokens to harder problems. However, it suffered from readability issues and language mixing.

The full R1 pipeline addresses this with a multi-stage approach: (1) cold-start SFT with a small set of long-CoT examples, (2) reasoning-focused RL with accuracy and format rewards, (3) rejection sampling to create high-quality SFT data, and (4) a final RL stage covering all scenarios including helpfulness and safety.

Emergent Chain-of-Thought

R1-Zero demonstrates that reasoning can emerge purely from RL, without any chain-of-thought supervision. The "aha moment" from the paper: the model spontaneously learns to re-evaluate its answers mid-generation, producing outputs like "Wait, I need to reconsider..." -- a behavior never present in the training data. This suggests that the capacity for systematic reasoning is latent in large pretrained models and can be unlocked through appropriate reward signals.

Decision Guide

Use V3 for general-purpose tasks where you need frontier-quality at low inference cost. Use R1 for math, coding, and complex reasoning tasks requiring step-by-step analysis. Study V2 for understanding the foundational MLA and DeepSeekMoE architectures that all subsequent models build upon. For deployment, note that MoE models require more total memory (all params loaded) but use less compute per token (only active params run).
