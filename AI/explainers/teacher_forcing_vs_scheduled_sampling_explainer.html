1
Understanding Teacher Forcing & Scheduled Sampling
▼

What is it? When training a recurrent neural network (RNN, LSTM, Transformer decoder) for sequence generation tasks (like machine translation or text summarization), the model predicts one token at a time. The crucial question is: what input should the model receive for predicting the *next* token? Should it be the *ground truth* token from the training data (Teacher Forcing), or its *own previously predicted* token (Scheduled Sampling)?

Analogy: Imagine you're teaching a child to write a story. You give them the first word, and they write the second. With Teacher Forcing, if they write the wrong word, you immediately correct it and give them the *correct* word to continue their story. They never see their own mistakes. With Scheduled Sampling, you gradually let them use their *own* (potentially wrong) previous word to write the next. This forces them to learn how to recover from mistakes, but might make the story (training) more chaotic initially.

💡 If you remember one thing

Teacher Forcing feeds ground truth, leading to stable but potentially brittle models (exposure bias). Scheduled Sampling gradually introduces model predictions as input during training to make models more robust at test time, but can be harder to optimize.

2
How It Works Internally
▼

Teacher Forcing: The Standard Approach

In most sequence-to-sequence training, **Teacher Forcing** is the default. At each time step \(t\), the model receives the *actual ground truth token* \(y_{t-1}^{\text{true}}\) as input to predict the current token \(\hat{y}_t\). This holds true even if the model's prediction for \(y_{t-1}\) was incorrect. The advantages are clear:

  • Stability: The model always sees a "perfect" prefix, making training very stable and fast.
  • Simplicity: Easy to implement, as the input sequence for the decoder is simply the shifted ground truth.

However, this creates a **train-test mismatch** (also called **exposure bias**). During training, the model never sees its own generated (and potentially erroneous) tokens. At test time, it *must* use its own predictions, which can lead to compounding errors: one small mistake can snowball into a completely incoherent sequence.

Scheduled Sampling: Bridging the Gap

To mitigate exposure bias, **Scheduled Sampling** (Bengio et al., 2015) proposes a gradual transition. During training, at each time step \(t\), the input to the decoder is chosen stochastically:

  • With probability \(\epsilon_t\): use the ground truth token \(y_{t-1}^{\text{true}}\).
  • With probability \(1 - \epsilon_t\): use the model's own previous prediction \(\hat{y}_{t-1}\).

The probability \(\epsilon_t\) typically starts high (e.g., 1.0, pure teacher forcing) and decays over training epochs, gradually exposing the model to more of its own generated output. This forces the model to learn to recover from its own mistakes, making it more robust at inference time.

Design Decision: Why Decay \(\epsilon_t\)?

Starting with a high \(\epsilon_t\) (more teacher forcing) allows the model to learn basic sequence dependencies stably. As training progresses, gradually decreasing \(\epsilon_t\) (more scheduled sampling) introduces the "self-correction" aspect when the model is already somewhat competent. A sudden switch to full self-sampling early on would likely destabilize training due to compounding errors.

🔑 Key Property

Both methods address how to provide the *previous token* to a sequence decoder during training. Teacher forcing is a constant input strategy, while scheduled sampling is a *stochastic, time-varying* input strategy that aims to make training conditions closer to inference conditions.

Why It Works — The Math
▼

Teacher Forcing Formulation

Given an input sequence \(X = (x_1, \dots, x_N)\) and a target sequence \(Y^{\text{true}} = (y_1^{\text{true}}, \dots, y_T^{\text{true}})\), the decoder aims to learn \(P(y_t | y_{

$$h_t = \text{RNN}(h_{t-1}, y_{t-1}^{\text{true}})$$

The loss is typically the sum of cross-entropy losses over all time steps:

$$\mathcal{L}_{\text{TF}} = \sum_{t=1}^T \text{CrossEntropy}(y_t^{\text{true}}, \hat{y}_t)$$

where \(\hat{y}_t\) is the probability distribution over the vocabulary predicted by the model at time \(t\).

Scheduled Sampling Formulation

Scheduled sampling modifies the input to the RNN at each step. Instead of always using \(y_{t-1}^{\text{true}}\), it samples from a mixture distribution:

$$y_{t-1}^{\text{input}} = \begin{cases} y_{t-1}^{\text{true}} & \text{with probability } \epsilon_t \\ \operatorname{argmax}(\hat{y}_{t-1}) & \text{with probability } 1 - \epsilon_t \end{cases}$$

where \(\hat{y}_{t-1}\) is the model's predicted probability distribution from the previous step. The sequence of \(\epsilon_t\) values (often denoted \(\epsilon_k\) for epoch \(k\)) defines the sampling schedule. Common schedules include linear decay (\(\epsilon_k = \max(0, 1 - \alpha k)\)), exponential decay (\(\epsilon_k = c^k\)), or inverse sigmoid decay (\(\epsilon_k = \frac{K}{K + \exp(k/K)}\)). The loss function remains the same as teacher forcing, but the internal states and gradients are computed based on the mixed inputs.

⚠️ Common Pitfall

A poorly chosen sampling schedule (e.g., \(\epsilon_t\) decaying too quickly) can destabilize training. If the model is not yet good enough to generate reasonable tokens, feeding its own bad predictions can lead to a rapid cascade of errors, making it impossible to learn. Careful tuning of the schedule is often required.

Key Takeaways
▼

When to use Teacher Forcing:

  • Early in training: Provides stability and faster initial convergence.
  • Simple tasks/models: Where exposure bias might not be a severe issue.
  • When ground truth is always reliable: No risk of feeding noisy inputs.
  • Baseline comparison: A good starting point before introducing more complex techniques.

When to use Scheduled Sampling:

  • Long sequences: Where compounding errors from exposure bias are more likely.
  • Complex generation: Tasks like abstractive summarization or dialogue generation, where creativity and robustness to slight deviations are important.
  • Later stages of training: To fine-tune and improve generalization after the model has learned basic patterns.
  • To improve robustness: Makes the model more resilient to its own mistakes during inference.

When NOT to use Scheduled Sampling:

  • Very noisy ground truth: Introducing randomness when the target itself is unreliable can further confuse the model.
  • Small datasets: The model might overfit to its own generated errors, leading to poor generalization.
  • Computational cost: The stochastic nature can make training slightly slower or require more epochs to converge.
  • If training becomes unstable: If the model struggles to learn with self-generated inputs, revert to teacher forcing or a gentler schedule.
💡 Big Picture

The choice between Teacher Forcing and Scheduled Sampling represents a fundamental trade-off in sequence modeling: prioritizing training stability and speed (TF) versus improving robustness and mitigating exposure bias at inference time (SS). Modern approaches often combine elements, such as using TF initially and then gradually switching to SS, or employing more advanced techniques like reinforcement learning for sequence training.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
import random
class Decoder(nn.Module):
def __init__(self, vocab_size, embed_dim, hidden_size):
super().__init__()
self.embedding = nn.Embedding(vocab_size, embed_dim)
self.rnn = nn.LSTM(embed_dim, hidden_size)
self.out = nn.Linear(hidden_size, vocab_size)
def forward(self, input_token, hidden_state):
embedded = self.embedding(input_token).unsqueeze(0) # (1, B, embed_dim)
output, hidden_state = self.rnn(embedded, hidden_state)
logits = self.out(output.squeeze(0)) # (B, vocab_size)
return logits, hidden_state
# --- Training Loop Snippet ---
def train_step(model, target_sequence, criterion, optimizer, ss_probability, hidden_state):
optimizer.zero_grad()
batch_size = 1 # simplified for single sequence
total_loss = 0
# Start token is always ground truth
input_token = target_sequence[0] # e.g., token
for t in range(1, len(target_sequence)): # Iterate through target tokens
logits, hidden_state = model(input_token, hidden_state)
target_token = target_sequence[t]
total_loss += criterion(logits, target_token)
# Decision for next input token: Teacher Forcing or Scheduled Sampling
if random.random() < ss_probability: # Use model's own prediction
input_token = torch.argmax(logits, dim=1)
else: # Teacher Forcing: Use ground truth
input_token = target_token
total_loss.backward()
optimizer.step()
return total_loss.item()
