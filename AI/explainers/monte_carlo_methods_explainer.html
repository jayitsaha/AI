1
Understanding Monte Carlo Methods
▼

What are they? Monte Carlo (MC) methods in Reinforcement Learning (RL) are a class of algorithms used to estimate the value functions (how good a state or state-action pair is) for a given policy. Unlike Dynamic Programming (DP) methods, MC methods are "model-free" – they don't require knowing the environment's transition probabilities or reward function. Instead, they learn directly from complete episodes of experience, collecting rewards and calculating "returns" (total discounted future rewards).

Analogy: Imagine you're trying to figure out the best move in a complex board game at various stages. A DP approach would require you to know the probabilities of every possible outcome from every move, which is often impossible. An MC approach is like playing the game many times from different positions, observing the final score (return) each time, and then averaging those scores for each position you encountered. You learn which positions are good by experiencing the outcomes, not by calculating them from a perfect model.

💡 If you remember one thing

Monte Carlo methods learn directly from complete episodes of experience. They estimate the value of a state or state-action pair by simply averaging the returns (total discounted rewards) observed following visits to that state or state-action pair across many episodes.

First-Visit vs. Every-Visit Monte Carlo
▼

The Core Idea: Returns from Episodes

In MC methods, an episode is a sequence of states, actions, and rewards: \(S_0, A_0, R_1, S_1, A_1, R_2, \dots, S_{T-1}, A_{T-1}, R_T, S_T\), where \(S_T\) is a terminal state. The return \(G_t\) at time \(t\) is the total discounted reward from that point onward:

$$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots + \gamma^{T-t-1} R_T$$

where \(\gamma \in [0, 1]\) is the discount factor. The goal is to estimate the expected return, \(q_\pi(s,a) = \mathbb{E}_\pi[G_t | S_t=s, A_t=a]\), the value of taking action \(a\) in state \(s\) and then following policy \(\pi\).

First-Visit Monte Carlo

To estimate \(q_\pi(s,a)\) using First-Visit MC, we average the returns \(G_t\) only for the first time that state-action pair \((s,a)\) is visited in an episode. If \((s,a)\) appears multiple times in a single episode, only the return following its first occurrence is used for that episode's update.

  • Algorithm:
    1. Initialize \(Q(s,a) = 0\) and \(Returns(s,a) = \text{empty list}\) for all \((s,a)\).
    2. For each episode:
      1. Generate an episode following policy \(\pi\).
      2. For each state-action pair \((s,a)\) appearing for the *first time* in the episode:
        1. Calculate \(G_t\) (the return from time \(t\) onward).
        2. Add \(G_t\) to \(Returns(s,a)\).
        3. Update \(Q(s,a) = \text{average}(Returns(s,a))\).

Every-Visit Monte Carlo

Every-Visit MC is similar, but it averages the returns \(G_t\) for every time that state-action pair \((s,a)\) is visited in an episode. If \((s,a)\) appears multiple times, each occurrence contributes its subsequent return to the average.

  • Algorithm:
    1. Initialize \(Q(s,a) = 0\) and \(Returns(s,a) = \text{empty list}\) for all \((s,a)\).
    2. For each episode:
      1. Generate an episode following policy \(\pi\).
      2. For each state-action pair \((s,a)\) appearing in the episode (at any time \(t\)):
        1. Calculate \(G_t\) (the return from time \(t\) onward).
        2. Add \(G_t\) to \(Returns(s,a)\).
        3. Update \(Q(s,a) = \text{average}(Returns(s,a))\).
🔑 Key Property

Both First-Visit and Every-Visit MC are on-policy methods. This means they estimate the value function for the policy \(\pi\) that is actually used to generate the episodes. They are guaranteed to converge to the true value function \(q_\pi\) as the number of episodes approaches infinity.

Off-Policy Learning with Importance Sampling
▼

The Off-Policy Problem

On-policy methods are simple but have a drawback: they can only learn about the policy they are currently following. To improve a policy, we often need to explore actions that are suboptimal according to the current policy. Off-policy methods allow us to learn about a target policy \(\pi\) (the one we want to evaluate/improve) while following a different behavior policy \(b\) (the one generating the data, usually more exploratory).

For off-policy MC, we need to correct for the fact that the data comes from \(b\) but we want to evaluate \(\pi\). This is done using Importance Sampling (IS).

Importance Sampling Ratio

The IS ratio \(\rho_{t:T-1}\) for an episode segment from time \(t\) to \(T-1\) is the product of the relative probabilities of actions taken under \(\pi\) versus \(b\):

$$\rho_{t:T-1} = \prod_{k=t}^{T-1} \frac{\pi(A_k|S_k)}{b(A_k|S_k)}$$

This ratio tells us how much more or less likely the observed trajectory segment is under the target policy \(\pi\) compared to the behavior policy \(b\). For this to be well-defined, we must ensure that \(b(A_k|S_k) > 0\) whenever \(\pi(A_k|S_k) > 0\) (i.e., the behavior policy must explore all actions that the target policy might take).

⚠️ Common Pitfall

Importance sampling can suffer from high variance, especially if the target policy \(\pi\) is very different from the behavior policy \(b\), or if episodes are very long. This is because the IS ratio \(\rho\) can become extremely large for unlikely trajectories under \(b\) but likely under \(\pi\), leading to unstable estimates. Careful choice of policies and potentially using WIS are crucial.

Key Takeaways
▼

First-Visit vs. Every-Visit:

  • First-Visit MC: Uses the return from the first time a state-action pair is visited in an episode. Simpler, but discards information from subsequent visits within the same episode.
  • Every-Visit MC: Uses the return from every time a state-action pair is visited in an episode. Utilizes all available data, often leading to faster convergence in practice, though its theoretical guarantees are more complex when combined with control.

On-Policy vs. Off-Policy:

  • On-Policy: Learns about the policy that generates the data. Requires the policy to be sufficiently exploratory (e.g., \(\epsilon\)-greedy) to ensure all state-action pairs are visited.
  • Off-Policy: Learns about a target policy \(\pi\) while following a different behavior policy \(b\). This is crucial for separating exploration (done by \(b\)) from optimization (for \(\pi\)).

Importance Sampling:

  • The core mechanism for off-policy MC, correcting for the difference between \(\pi\) and \(b\).
  • Ordinary Importance Sampling (OIS): Simple ratio-weighted average of returns. Can have high variance.
  • Weighted Importance Sampling (WIS): Normalized ratio-weighted average. Generally preferred due to lower variance, though it introduces a small bias.
  • Requires "coverage": \(b(a|s) > 0\) whenever \(\pi(a|s) > 0\).
💡 Big Picture

Monte Carlo methods are fundamental model-free approaches. They provide unbiased estimates of value functions directly from experience. While simpler than Temporal Difference (TD) methods (which bootstrap), MC methods require complete episodes, making them less suitable for continuing tasks without natural termination. Off-policy methods with importance sampling extend their utility by allowing learning from diverse data generated by exploratory policies.

import numpy as np
# Grid world setup (simplified for brevity)
GRID_SIZE = 5
ACTIONS = ['UP', 'RIGHT', 'DOWN', 'LEFT']
GOAL_STATE = (4, 4); GOAL_REWARD = 10
PIT_STATE = (2, 2); PIT_REWARD = -10
# Q-values: (grid_size, grid_size, num_actions)
Q = np.zeros((GRID_SIZE, GRID_SIZE, len(ACTIONS)))
returns_sum = np.zeros_like(Q)
returns_count = np.zeros_like(Q)
# Policy functions
def get_behavior_policy(state, epsilon):
# Epsilon-greedy policy based on current Q-values
action_probs = np.ones(len(ACTIONS)) * (epsilon / len(ACTIONS))
best_action = np.argmax(Q[state])
action_probs[best_action] += (1.0 - epsilon)
return action_probs
def get_target_policy(state):
# Greedy policy based on current Q-values
action_probs = np.zeros(len(ACTIONS))
best_action = np.argmax(Q[state])
action_probs[best_action] = 1.0
return action_probs
def run_episode(policy_func, start_state=(0,0)):
episode = [] # List of (state, action, reward) tuples
current_state = start_state
while current_state not in [GOAL_STATE, PIT_STATE]:
action_probs = policy_func(current_state)
action = np.random.choice(len(ACTIONS), p=action_probs)
next_state, reward = simulate_step(current_state, action) # Env logic
episode.append((current_state, action, reward))
current_state = next_state
return episode
def mc_evaluation(num_episodes, gamma, method='first-visit', off_policy=False, weighted_is=False, epsilon=0.1):
global Q, returns_sum, returns_count
for _ in range(num_episodes):
if off_policy:
behavior_policy_func = lambda s: get_behavior_policy(s, epsilon)
episode = run_episode(behavior_policy_func)
else:
on_policy_func = lambda s: get_target_policy(s) # On-policy uses target policy for data gen
episode = run_episode(on_policy_func)
G = 0 # Return accumulator
W = 1.0 # Importance sampling ratio accumulator
visited_sa = set() # For first-visit
# Iterate episode backwards to calculate returns and update Q
for t in reversed(range(len(episode))):
s, a, r = episode[t]
state_action = (s, a)
G = gamma * G + r
if off_policy:
target_prob = get_target_policy(s)[a]
behavior_prob = get_behavior_policy(s, epsilon)[a]
if behavior_prob == 0: break # Avoid division by zero, essential for coverage
W *= (target_prob / behavior_prob)
if method == 'first-visit' and state_action in visited_sa:
continue
visited_sa.add(state_action)
if off_policy:
if weighted_is: # Weighted Importance Sampling
returns_sum[s][a] += W * G
returns_count[s][a] += W # Denominator is sum of weights
else: # Ordinary Importance Sampling
returns_sum[s][a] += W * G
returns_count[s][a] += 1.0 # Denominator is count of visits
else: # On-policy methods
returns_sum[s][a] += G
returns_count[s][a] += 1.0
# Update Q-value (average)
if returns_count[s][a] > 0:
Q[s][a] = returns_sum[s][a] / returns_count[s][a]
if off_policy and target_prob == 0: break # Cannot follow target policy
