Stemming (Porter, Snowball) vs Lemmatization

Two ways to normalize word forms — rule-based suffix stripping vs dictionary-based lookup
Foundational NLP Text Preprocessing O(1) rules per word
1
Understanding Stemming vs Lemmatization
▼

What is it? Search engines and text classifiers don't want to treat "running", "runs", and "ran" as three unrelated words — they all refer to the same underlying concept. Stemming and lemmatization are the two classic techniques for collapsing these inflected forms down to a single canonical token before indexing or modeling.

Analogy: Stemming is like a librarian who chops the last few letters off every book title using a fixed set of scissors-rules — fast, but sometimes cuts too much ("university" and "universe" both become "univers"). Lemmatization is like a librarian who actually looks each word up in a dictionary and knows its part of speech — slower, but always returns a real word ("better" → "good", "went" → "go").

💡 If you remember one thing

Stemming is a blind, rule-based suffix stripper — no dictionary, no meaning, just pattern matching gated by a crude syllable-count heuristic \(m\). Lemmatization is a dictionary + part-of-speech lookup that always returns a valid base word. Stemming is faster and language-agnostic-ish; lemmatization is more accurate but needs linguistic resources.

2
How It Works Internally
▼

Porter Stemmer (Martin Porter, 1980)

The Porter algorithm runs a word through 5 ordered rule groups (Steps 1–5, with 1 split into 1a/1b/1c). Each rule looks like (condition) SUFFIX → REPLACEMENT, e.g. (m>0) ATIONAL → ATE. Rules fire only if the word ends in the suffix and the remaining stem satisfies a measure condition \(m\), which approximates the stem's syllable count so that short words like "cat" or "be" don't get mangled. Only the first matching rule in each step group fires, then the (possibly changed) word moves to the next step.

Snowball / Porter2 (Porter, 2001)

Snowball is a stemming language plus a rewritten, more consistent English algorithm ("Porter2") that fixes edge cases in the original (e.g. handling of y, better treatment of exceptions like "sky", "news") and generalizes the framework to French, German, Russian, and 15+ other languages. Same core idea — suffix rules gated by stem length/vowel structure — just cleaner and multilingual.

Lemmatization

A lemmatizer (e.g. NLTK's WordNetLemmatizer, spaCy) does two things stemming never does: (1) it usually needs a part-of-speech tag (is "leaves" a noun or a verb?), and (2) it looks the inflected form up in a morphological dictionary to return the real dictionary headword — including irregulars that follow no suffix pattern at all ("went" → "go", "mice" → "mouse", "better" → "good").

🔑 Key Property

Stemming is a pure function of the surface string — same rules, no context. Lemmatization is a function of the string AND its part of speech, resolved against a fixed vocabulary — which is why lemmatizers can fix irregular forms that no suffix rule could ever predict.

3
Why It Works — The Math of the "Measure"
▼

Every word is first reduced to a signature string \(\sigma\) over the alphabet \(\{C, V\}\) (consonant / vowel), where \(y\) is special-cased: it counts as a consonant when it starts a word or follows a vowel, and as a vowel when it follows a consonant. Porter shows any word can be written in the canonical form:

$$ \text{word} = [C](VC)^{m}[V] $$

where the brackets denote an optional single C or V, and \((VC)^m\) is the core repeated \(m\) times. The measure \(m\) is computed by counting V→C transitions in the signature:

$$ m(\sigma) = \big|\{\, i : \sigma_i = V \;\wedge\; \sigma_{i+1} = C \,\}\big| $$

Each rule is gated by a condition on \(m\) of the stem after the candidate suffix is removed — e.g. Step 4 only deletes suffixes like -AL, -ANCE, -MENT when \(m>1\), which is why "revival" (\(m=1\)) keeps its "-al" but "controllable"-style longer stems lose theirs. \(m\) is a cheap proxy for syllable count: it stops the algorithm from stripping short, meaningful stems down to nothing.

⚠️ Common Pitfall

Stemming has no correctness guarantee — there is no proof it maps semantically related words to the same stem, only that it's deterministic and idempotent-ish. Classic failure: "university", "universal", and "universe" all stem to univers (over-stemming / conflation), while "alumnus" and "alumni" stem to different roots (under-stemming). Lemmatization avoids over-stemming by construction (dictionary lookup) but is bounded by tagger accuracy and vocabulary coverage — out-of-vocabulary words fall back to unchanged forms.

Key Takeaways
▼

Use stemming when:

  • Speed matters and you're building a search/IR index at scale
  • Some loss of precision (over-/under-stemming) is acceptable for higher recall
  • You don't have (or want to depend on) a POS tagger or lexical database

Use lemmatization when:

  • Output readability matters (chatbots, summarization, downstream display)
  • You need correctness on irregular forms ("went"→"go", "mice"→"mouse")
  • You already have POS tags available (lemmatizers need them to disambiguate)
💡 Hierarchy

Porter (1980, English only, well-known quirks) → Snowball/Porter2 (2001, cleaner rules, multilingual) → Lemmatization (dictionary + POS, always outputs a real word, highest accuracy, highest cost). Modern transformer pipelines mostly skip both in favor of subword tokenization — but stemming/lemmatization are still standard in classical IR, TF-IDF, and topic modeling pipelines.

from nltk.stem import PorterStemmer, WordNetLemmatizer
from nltk.corpus import wordnet
stemmer = PorterStemmer()
lemmatizer = WordNetLemmatizer()
# --- Stemming: pure suffix-rule pipeline, no context needed ---
def porter_trace(word):
w = step1a(word) # SSES->SS, IES->I, S->''
w = step1b(w) # (m>0)EED->EE, *v*ED->'', *v*ING->''
w = step1c(w) # *v* Y -> I
w = step2(w) # (m>0) ATIONAL->ATE, IZATION->IZE, ...
w = step3(w) # (m>0) ICATE->IC, ALIZE->AL, NESS->'', ...
w = step4(w) # (m>1) AL, ANCE, MENT, (S)ION, IZE -> ''
w = step5a(w) # (m>1) E->'' ; (m=1 and not *o) E->''
w = step5b(w) # (m>1 and *d and *L) -> single letter
return w
# --- Lemmatization: needs a POS tag to disambiguate the lexicon lookup ---
def lemmatize(word, pos_tag):
pos_map = {'NOUN': wordnet.NOUN, 'VERB': wordnet.VERB,
'ADJ': wordnet.ADJ, 'ADV': wordnet.ADV}
return lemmatizer.lemmatize(word, pos=pos_map[pos_tag])
print(porter_trace("universities")) # -> 'univers' (over-stemmed)
print(lemmatize("universities", 'NOUN')) # -> 'university'
print(porter_trace("went")) # -> 'went' (rules can't help)
print(lemmatize("went", 'VERB')) # -> 'go'
