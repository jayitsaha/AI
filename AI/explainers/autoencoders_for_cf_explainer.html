Understanding Autoencoders for CF
▼

What is it? Collaborative filtering asks: given a user who rated a handful of items, what would they think of the rest? An autoencoder-for-CF treats each user's row of the rating matrix as an input vector, compresses it through a bottleneck, then decodes it back out to the full item space — including items the user never rated. The genius move is that the reconstruction target IS the sparse input itself: the network is trained to fill in its own blanks, and the loss only looks at the entries that were actually observed.

Analogy: Imagine showing a friend only 3 of your 6 favorite movies and asking them to guess your rating on the other 3. A good friend doesn't memorize — they infer a compressed "taste profile" (sci-fi lover, tolerates romance) and use it to predict the rest. That compressed profile is exactly the autoencoder's latent bottleneck.

Three landmark instantiations of this idea, each a different bet on the encoder/decoder shape:

💡 If you remember one thing

AutoRec is a point-estimate neural autoencoder trained with masked MSE. Mult-VAE is a probabilistic, generative version with a multinomial decoder tuned for ranking. EASE² throws away the hidden layer entirely and solves for an item-item weight matrix \(B\) in closed form — one matrix inversion, no gradient descent, and often the strongest baseline of the three.

How They Work Internally
▼

AutoRec — the point-estimate autoencoder

Feed a user's rating vector \(r \in \mathbb{R}^n\) (zeros for unrated items) through a single hidden layer: \(h = \sigma(W_1 r + b_1)\), then decode: \(\hat r = W_2 h + b_2\). Training minimizes squared error only on the observed entries — this masking is what stops the network from trivially learning "output zero everywhere," since zeros for missing entries are never penalized.

Mult-VAE — probabilistic and generative

Instead of one reconstruction, Mult-VAE learns a distribution over latent tastes. An encoder maps the (L2-normalized) rating vector to a Gaussian posterior \(q(z\mid x) = \mathcal{N}(\mu, \operatorname{diag}(\sigma^2))\); a sample \(z\) (via the reparameterization trick) is decoded into a softmax over all items — a multinomial likelihood, which matches the "pick a few items out of many" nature of implicit feedback far better than Gaussian error.

EASE² — embarrassingly shallow, closed form

Drop the hidden layer completely. Learn a single \(n\times n\) item-item matrix \(B\) so that \(X \approx XB\), regularized by \(\lambda\lVert B\rVert^2\) and constrained so \(\operatorname{diag}(B)=0\) — without that constraint the trivial solution \(B=I\) reproduces the input perfectly and learns nothing. Because the objective is convex quadratic with a linear constraint, \(B\) has an exact closed-form solution: one Gram-matrix inversion, done.

🔑 Key Property

All three are self-supervised: input equals target. The only real difference is how much function class sits between input and output — none (EASE², linear), a little (AutoRec, one nonlinear layer), or a probabilistic generative model over it (Mult-VAE).

Why It Works — The Math
▼

AutoRec: masked reconstruction loss

$$\mathcal{L}_{\text{AutoRec}} = \sum_{i \in \mathcal{O}} \left(r_i - \hat r_i\right)^2 + \lambda\left(\lVert W_1\rVert_F^2 + \lVert W_2\rVert_F^2\right), \quad \hat r = W_2\,\sigma(W_1 r + b_1) + b_2$$

where \(\mathcal{O}\) is the set of observed ratings. Gradients for unobserved entries are zeroed out before backprop.

Mult-VAE: the evidence lower bound (ELBO)

$$\log p(x) \ge \mathbb{E}_{q(z\mid x)}\big[\log p(x\mid z)\big] - \beta \cdot \mathrm{KL}\big(q(z\mid x)\,\Vert\,p(z)\big)$$

The reconstruction term uses a multinomial log-likelihood \(\log p(x\mid z) = \sum_i x_i \log \pi_i(z)\) with \(\pi = \text{softmax}(\text{decoder}(z))\). The KL term has a closed form for Gaussians: \(\mathrm{KL} = -\tfrac12\sum_j\left(1+\log\sigma_j^2-\mu_j^2-\sigma_j^2\right)\). The \(\beta\) weight (often \(<1\), "KL annealing") trades reconstruction fidelity against how tightly \(z\) is pulled toward the prior \(\mathcal{N}(0, I)\).

EASE²: constrained ridge regression, solved exactly

Minimize \(\lVert X - XB\rVert_F^2 + \lambda\lVert B\rVert_F^2\) subject to \(\operatorname{diag}(B)=0\). Introducing a diagonal Lagrange multiplier for the constraint and setting the gradient to zero gives \(B = I - \hat P\, \operatorname{diagMat}(1/\operatorname{diag}(\hat P))\), where:

$$\hat P = \left(X^\top X + \lambda I\right)^{-1}, \qquad B_{jk} = \begin{cases} 0 & j=k \\ -\hat P_{jk}/\hat P_{kk} & j \ne k\end{cases}$$

Predictions for a user are just a linear combination of items they've already interacted with: \(\hat s = r^\top B\).

⚠️ Common Pitfall

Forgetting the zero-diagonal constraint in EASE² lets the model cheat by copying \(B=I\) — perfect training loss, zero generalization. Likewise, setting Mult-VAE's \(\beta\) too high causes posterior collapse (the encoder ignores the input and \(z\) always looks like the prior); too low and it barely regularizes at all.

Key Takeaways
▼

When to reach for each:

  • AutoRec — simple, fast neural baseline; a good first "hidden layer" model, but sensitive to regularization and needs SGD training.
  • Mult-VAE — usually the strongest deep model for implicit feedback / top-N ranking; probabilistic, can sample novel taste profiles, but needs careful \(\beta\)-annealing and more compute.
  • EASE² — extremely strong linear baseline, trains in one matrix inversion (no epochs, no learning rate), and is famously hard to beat on many benchmarks. Cost scales as \(O(n_{\text{items}}^3)\), so it's item-catalog-bound rather than user-bound — great when items are numbered in the thousands, awkward at web-scale catalogs.

Shared limitation: all three need some interaction history — none solves cold-start for a brand-new user or item out of the box.

💡 Hierarchy

EASE² (linear, closed-form) ⊂ AutoRec (one nonlinear layer, point estimate) ⊂ Mult-VAE (nonlinear, probabilistic, generative). Each step trades a cheaper, more stable optimum for a richer function class — and in practice EASE²'s convex optimum often wins anyway, so it's the baseline you should always try first.

import numpy as np
# ---- AutoRec: masked MSE autoencoder ----
def autorec_forward(r, W1, b1, W2, b2):
h = 1 / (1 + np.exp(-(W1 @ r + b1))) # sigmoid bottleneck
r_hat = W2 @ h + b2 # linear reconstruction
return r_hat
def autorec_loss(r, r_hat, observed_idx, W1, W2, lam=0.01):
err = sum((r[i] - r_hat[i])**2 for i in observed_idx) # masked!
reg = lam * (np.sum(W1**2) + np.sum(W2**2))
return err + reg
# ---- Mult-VAE: probabilistic encoder/decoder ----
def multvae_forward(x, params, eps):
x_norm = x / np.linalg.norm(x)
mu = params.W_mu @ x_norm + params.b_mu
logvar = params.W_lv @ x_norm + params.b_lv
z = mu + np.exp(0.5 * logvar) * eps # reparameterization trick
logits = params.W_dec @ z + params.b_dec
pi = np.exp(logits) / np.sum(np.exp(logits)) # softmax over items
return pi, mu, logvar
def multvae_neg_elbo(x, pi, mu, logvar, beta=0.2):
recon_ll = np.sum(x * np.log(pi + 1e-9))
kl = -0.5 * np.sum(1 + logvar - mu**2 - np.exp(logvar))
return -recon_ll + beta * kl
# ---- EASE^R: closed-form item-item weights ----
def ease_fit(X, lam=0.5):
G = X.T @ X + lam * np.eye(X.shape[1])
P = np.linalg.inv(G) # one inversion, no SGD
B = P / (-np.diag(P)) # column-normalize
np.fill_diagonal(B, 0.0) # enforce diag(B) = 0
return B
