Batch-mode Active Learning

Selecting diverse and informative batches of unlabeled data for efficient annotation
Intermediate Machine Learning Unsupervised Learning O(k·N) to O(N²)
1
Understanding Batch-mode Active Learning
▼

What is it? Active learning aims to reduce the cost of labeling data by strategically selecting the most "valuable" unlabeled examples for human annotation. Traditional active learning often queries one data point at a time. Batch-mode active learning extends this by querying a *batch* of \(k\) unlabeled data points simultaneously. This is crucial for real-world scenarios where human annotators prefer to work on groups of examples, or where communication latency makes single-query loops impractical.

Analogy: Imagine a doctor trying to diagnose a patient. Sequential active learning is like ordering one test, waiting for the result, then deciding the next test. Batch-mode active learning is like ordering a panel of \(k\) tests at once. The challenge isn't just to pick the \(k\) most "confusing" symptoms (most uncertain points), but to pick a *diverse* set of \(k\) tests that cover different diagnostic avenues, ensuring no two tests are redundant and collectively provide the most information. This balances getting informative results with covering all bases efficiently.

💡 If you remember one thing

The core challenge of batch-mode active learning is to select a batch of \(k\) points that are both informative (high uncertainty for the current model) and diverse (represent different regions of the unlabeled data space). Simply picking the \(k\) most uncertain points often leads to a redundant batch, wasting annotation budget.

2
How Batch-mode Active Learning Works
▼

The Problem of Redundancy

When a model is uncertain about a particular region of the feature space (e.g., near its decision boundary), many unlabeled points in that region will also be highly uncertain. If we simply pick the top \(k\) most uncertain points, they are likely to be highly clustered and similar. Labeling all of them provides diminishing returns: once one point from that cluster is labeled, the model's uncertainty for nearby, similar points often resolves itself, making the other labels in the batch less valuable.

Balancing Informativeness and Diversity

Batch-mode active learning algorithms address this by explicitly incorporating a diversity criterion into their selection process. This usually involves defining a score for each unlabeled point that combines its informativeness (e.g., model uncertainty) with how "different" it is from other points already selected for the batch, or from other points in the unlabeled pool. Common strategies include:

  • Greedy Selection: Iteratively select points. In each step, pick the point that maximizes a combined uncertainty-diversity score, given the points already chosen for the batch.
  • Clustering-based Methods: Cluster the highly uncertain points, then select a representative (e.g., the centroid or most uncertain point) from each cluster until the batch size \(k\) is reached.
  • Submodular Optimization: Formulate the batch selection as maximizing a submodular function that inherently captures the "diminishing returns" property of diversity and informativeness.

Design Decision: Why Not Just Retrain Between Each Point?

The ideal active learning loop would retrain the model after *every single point* is labeled, and then select the next most informative point based on the updated model. This is called "sequential" or "online" active learning. However, retraining a deep learning model is computationally expensive and takes time. Batch-mode active learning is a compromise: we assume the model's uncertainty landscape doesn't change drastically within a small batch of \(k\) points, allowing us to select them all at once, send them for annotation, and only retrain once the entire batch is returned.

🔑 Key Property

The goal is to select a batch that offers the maximum expected reduction in model error for a fixed annotation budget. This is achieved by finding points that are not only individually informative but also collectively cover a broad range of the model's current ambiguities, preventing redundant queries.

3
Why It Works — The Math
▼

Quantifying Informativeness (Uncertainty)

A common measure of a model's uncertainty about a point \(x\) is the entropy of its predicted class probabilities:

$$U(x) = -\sum_{c=1}^C P(y=c|x) \log P(y=c|x)$$

where \(C\) is the number of classes. A higher entropy indicates greater uncertainty (e.g., probabilities close to uniform for all classes). Other measures include Least Confidence (\(1 - \max_c P(y=c|x)\)) or Margin Sampling (\(P(y=c_1|x) - P(y=c_2|x)\) for top two classes \(c_1, c_2\)).

Quantifying Diversity

Diversity typically measures how "far apart" points are in the feature space (or an embedding space). For two points \(x_i\) and \(x_j\), a common dissimilarity measure is Euclidean distance:

$$D(x_i, x_j) = \|f(x_i) - f(x_j)\|_2$$

where \(f(x)\) could be the raw feature vector, or a representation from an intermediate layer of the neural network. A higher \(D(x_i, x_j)\) means the points are more diverse.

The Batch Selection Objective

Many batch-mode active learning algorithms can be seen as optimizing a utility function \(F(S)\) for a subset of unlabeled points \(S\) of size \(k\). A general form combining uncertainty and diversity often looks like:

$$S^* = \underset{S \subset U, |S|=k}{\operatorname{argmax}} \left[ \sum_{x \in S} U(x) + \lambda \sum_{x_i, x_j \in S, i \neq j} D(x_i, x_j) \right]$$

Here, \(U\) is the pool of unlabeled data, \(U(x)\) is the uncertainty of point \(x\), \(D(x_i, x_j)\) is the diversity (dissimilarity) between \(x_i\) and \(x_j\), and \(\lambda \ge 0\) is a hyperparameter that balances the trade-off between informativeness and diversity. Maximizing this function is often NP-hard, so greedy approximations are commonly used.

⚠️ Computational Complexity

A naive search for the optimal batch of \(k\) points from an unlabeled pool of size \(N\) would involve checking \(\binom{N}{k}\) combinations, which is intractable. Greedy algorithms reduce this to roughly \(O(k \cdot N)\) or \(O(k \cdot N^2)\) depending on the diversity calculation, making them practical for large datasets but still more costly than simple top-k uncertainty sampling.

Key Takeaways
▼

When to use batch-mode active learning:

  • High annotation cost: When human labeling is expensive or time-consuming, and you want to maximize the impact of each annotation budget.
  • Large unlabeled pools: When you have vast amounts of unlabeled data but limited resources to label it all.
  • Human-in-the-loop systems: When the annotation process involves human experts who prefer to work with batches rather than single examples.
  • Slow model retraining: When retraining the model after each single point is labeled is computationally prohibitive.
  • Stable model updates: When you want the model to learn from a diverse set of examples in each iteration, leading to more robust updates.

When NOT to use:

  • Very small datasets: If your unlabeled pool is tiny, sequential active learning or even random sampling might be sufficient.
  • Computational overhead: If the batch selection algorithm itself is too complex for your available compute, outstripping the benefits.
  • Only uncertainty matters: In some niche cases (e.g., pure anomaly detection), diversity might be less critical than finding the single most anomalous point.
💡 Big Picture: Practicality vs. Theory

While theoretically, sequential active learning might offer slightly better performance by always reacting to the latest model, batch-mode active learning is often a more practical and efficient choice for real-world machine learning systems. It effectively bridges the gap between theoretical optimality and the operational realities of human annotation workflows and computational constraints.

Code Trace (Greedy Batch Selection)
▼
import numpy as np
from sklearn.metrics.pairwise import euclidean_distances
def calculate_uncertainty(probabilities):
# Entropy sampling: higher entropy means more uncertainty
# probabilities: (N, C) array of class probabilities for N points
epsilon = 1e-10 # to prevent log(0)
return -np.sum(probabilities * np.log(probabilities + epsilon), axis=1)
def select_batch_greedy(unlabeled_features, model_probs, k, lambda_diversity):
n_unlabeled = unlabeled_features.shape[0]
uncertainties = calculate_uncertainty(model_probs)
selected_indices = []
remaining_indices = list(range(n_unlabeled))
# Precompute all pairwise distances for efficiency
all_distances = euclidean_distances(unlabeled_features, unlabeled_features)
for _ in range(k):
if not remaining_indices: break
best_score = -np.inf
best_idx = -1
for candidate_idx in remaining_indices:
# Informativeness term (uncertainty)
informativeness = uncertainties[candidate_idx]
# Diversity term: sum of distances to already selected points
diversity = 0
if selected_indices:
diversity = np.sum(all_distances[candidate_idx, selected_indices])
# Combined score
current_score = informativeness + lambda_diversity * diversity
if current_score > best_score:
best_score = current_score
best_idx = candidate_idx
if best_idx != -1:
selected_indices.append(best_idx)
remaining_indices.remove(best_idx)
return selected_indices
