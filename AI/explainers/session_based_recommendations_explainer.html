1
Understanding Session-Based Recommendation
▼

What is it? Classic recommenders (matrix factorization, collaborative filtering) need a long history tied to a known user ID. But most e-commerce and streaming traffic comes from anonymous or short-lived sessions — a shopper browsing without logging in. Session-based recommendation predicts the next item a person will click, using only the sequence of clicks made so far in the current session.

Analogy: Imagine watching over someone's shoulder as they shop: they click Running Shoes → Socks → Running Shoes again → Water Bottle. You don't know their name or purchase history, but the pattern already screams "runner assembling a race-day kit" — the next click is probably Energy Gel, not a random product. The model's job is to compress that click sequence into a representation that captures exactly this kind of intent.

Two landmark approaches: GRU4Rec (2016) treats the session as a sequence and feeds it through a Gated Recurrent Unit (GRU), reading clicks one at a time like a sentence. SR-GNN (2019) instead treats the session as a small graph — items are nodes, clicks-in-a-row are edges — and uses a Graph Neural Network plus attention to build the session representation, which better captures repeat visits and non-adjacent transitions that a strictly left-to-right RNN can blur together.

💡 If you remember one thing

Both models compress a session \(S = [v_1, v_2, \dots, v_n]\) into a single vector \(\mathbf{s}_h\) (the "session embedding"), then rank every catalog item \(v\) by \(\hat{z}_v = \mathbf{s}_h \cdot \mathbf{e}_v\). GRU4Rec builds \(\mathbf{s}_h\) by folding clicks through time; SR-GNN builds it by passing messages over a session graph and attending over the result.

2
How They Work Internally
▼

GRU4Rec: sessions as sequences

Each session is a sequence of item IDs. Every item is embedded into a dense vector \(\mathbf{e}_{v_t}\), and fed one-at-a-time into a GRU layer. The GRU keeps a hidden state \(\mathbf{h}_t\) that acts as compressed memory of everything seen so far, updated at each step by update and reset gates that decide how much of the past to keep versus overwrite. After the last click, \(\mathbf{h}_n\) is the session representation, scored against every candidate item's embedding to rank "what's next."

SR-GNN: sessions as graphs

A session graph turns unique items into nodes and consecutive clicks into directed edges (with self-loops / repeated edges when an item is revisited). A gated graph neural network (GGNN) propagates messages along these edges — structurally the same gated update math as a GRU, just applied across graph neighbors instead of across time steps. After a few propagation rounds, every node embedding reflects its local neighborhood. An attention mechanism then blends the local signal (the last clicked item) with a global signal (an attention-weighted sum over all nodes) into the final session embedding.

Design decision: why bother with a graph?

A pure RNN reads clicks strictly left-to-right, so it struggles to represent that item A was revisited, or that two non-adjacent clicks are strongly related. A graph makes those relationships explicit edges the GNN can propagate over directly, regardless of how far apart the clicks are in the raw sequence.

🔑 Key Property

Both models are trained with a ranking loss over the entire item catalog (or a sampled subset) — cross-entropy / sampled softmax for GRU4Rec, or TOP1 / BPR pairwise losses — because the target is "which item is clicked next," not a single scalar rating.

3
Why It Works — The Math
▼

GRU update equations

At time step \(t\), given input embedding \(\mathbf{x}_t = \mathbf{e}_{v_t}\) and previous hidden state \(\mathbf{h}_{t-1}\):

$$\mathbf{z}_t = \sigma(W_z \mathbf{x}_t + U_z \mathbf{h}_{t-1} + \mathbf{b}_z) \qquad \mathbf{r}_t = \sigma(W_r \mathbf{x}_t + U_r \mathbf{h}_{t-1} + \mathbf{b}_r)$$
$$\tilde{\mathbf{h}}_t = \tanh\big(W_h \mathbf{x}_t + U_h(\mathbf{r}_t \odot \mathbf{h}_{t-1}) + \mathbf{b}_h\big) \qquad \mathbf{h}_t = (1-\mathbf{z}_t)\odot \mathbf{h}_{t-1} + \mathbf{z}_t \odot \tilde{\mathbf{h}}_t$$

\(\mathbf{z}_t\) is the update gate (how much to overwrite), \(\mathbf{r}_t\) the reset gate (how much past state to ignore when proposing a new candidate state \(\tilde{\mathbf{h}}_t\)).

SR-GNN graph propagation

With normalized session-graph adjacency \(A\), each node aggregates its neighbors' current embeddings, then applies the same style of gated update as the GRU above, but indexed by node \(i\) instead of time \(t\):

$$\mathbf{a}_i = \sum_j A_{ij}\, \mathbf{h}_j \qquad \mathbf{h}_i \leftarrow \text{GRU-update}(\mathbf{a}_i, \mathbf{h}_i)$$

SR-GNN attention & readout

Let \(\mathbf{s}_l = \mathbf{h}_{v_n}\) be the local embedding of the last clicked item. The global embedding attends over all node embeddings:

$$\alpha_i = \mathbf{q}^\top \sigma\big(W_1 \mathbf{h}_i + W_2 \mathbf{s}_l + \mathbf{c}\big) \qquad \mathbf{s}_g = \sum_i \operatorname{softmax}(\alpha)_i \, \mathbf{h}_i$$

The final session embedding fuses both signals: \(\mathbf{s}_h = W_3 [\mathbf{s}_l \, ; \, \mathbf{s}_g]\). Both models finish identically — score every candidate item \(v\) by \(\hat{z}_v = \mathbf{s}_h \cdot \mathbf{e}_v\), then softmax to get a probability of being clicked next.

⚠️ Common Pitfall

Because sessions are short and the catalog is huge, computing the softmax over every item is expensive. Both papers use negative sampling (mini-batch-based sampling in GRU4Rec) rather than a full softmax at training time — the visualization below uses a small candidate set to keep the full softmax tractable to show.

Key Takeaways
▼
GRU4RecSR-GNN
Session representationSequential — RNN hidden stateStructural — graph + attention
Handles repeated clicksImplicitly, via memory decayExplicitly, via self-loops / merged edges
Non-adjacent transitionsMust survive through every intermediate stepDirect edge / message if items co-occur
Complexity per session\(O(n \cdot d^2)\), strictly sequential\(O(n \cdot d^2)\) per GNN layer, more parallel-friendly across nodes
Good fit forLong, clearly ordered sessions (e.g. music playlists)Short, noisy sessions with repeats/backtracking (e.g. e-commerce)

When to use session-based models at all:

  • Most traffic is anonymous or has very sparse user history (cold-start users)
  • Intent shifts within a single visit matter more than long-term taste (e.g. gift shopping)
  • Catalog and trends move fast, so long-term collaborative-filtering profiles go stale

When NOT to bother:

  • You have strong, stable long-term user profiles — classic CF / two-tower models may suffice
  • Sessions are extremely short (1 click) — there's no sequence to model yet
💡 The bigger picture

GRU4Rec (RNN) → NARM / STAMP (RNN + attention) → SR-GNN (graph + attention) → later Transformer-based session models (e.g. SASRec) all chase the same goal through increasingly expressive session encoders: turn a short, noisy click stream into one vector that predicts the next click.

session = [3, 7, 3, 9] # item ids, click order

z = sigmoid(Wz @ x + Uz @ h + bz)
r = sigmoid(Wr @ x + Ur @ h + br)
h_tilde = tanh(Wh @ x + Uh @ (r * h) + bh)
h = (1 - z) * h + z * h_tilde
session_repr_gru4rec = h # final hidden state
scores = {v: session_repr_gru4rec @ E[v] for v in candidates}
# ---------- SR-GNN ----------
nodes = unique(session) # [3, 7, 9]
A = build_normalized_adjacency(session, nodes)
H = {v: E[v] for v in nodes} # init node states = embeddings
for v in nodes:
a_v = sum(A[v][u] * H[u] for u in nodes)
H[v] = gru_update(a_v, H[v]) # same gated-update math as GRU4Rec
s_l = H[session[-1]] # local embedding (last click)
alpha = {v: q @ sigmoid(W1 @ H[v] + W2 @ s_l + c) for v in nodes}
alpha = softmax(alpha)
s_g = sum(alpha[v] * H[v] for v in nodes) # global embedding
session_repr_srgnn = W3 @ concat(s_l, s_g)
scores = {v: session_repr_srgnn @ E[v] for v in candidates}
