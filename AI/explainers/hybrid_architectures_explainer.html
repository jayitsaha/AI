Hybrid Architectures: Jamba (Mamba + Attention)

Interleaving state-space layers with sparse full attention for long-context efficiency at transformer-level quality
Advanced LLM Architecture Sequence Models O(1) state vs O(n²) attention
1
Understanding Jamba
▼

What is it? Jamba is a language model that mixes two very different ways of looking at a sequence of tokens: Mamba layers, which read the sequence once and compress everything seen so far into a small fixed-size "state," and Transformer attention layers, which keep every past token around and let each new token look directly at all of them. Jamba stacks these two layer types together, with a few sparse Mixture-of-Experts (MoE) layers sprinkled in, into one model.

Analogy: Imagine reading a long novel. A Mamba layer is like a reader who keeps a running mental summary — after each page they update a short note card and throw away the page. A Transformer attention layer is like a reader who keeps every page pinned to a giant corkboard and can glance back at any page instantly, but the corkboard grows with every page and gets expensive to scan. Jamba is a reader who mostly works from the note card (cheap, constant effort) but every so often — say every 8th page — steps back and rereads the whole corkboard to catch anything the summary missed.

💡 If you remember one thing

Jamba interleaves cheap, constant-memory Mamba (state-space) layers with a small fraction of expensive, full-context attention layers, so the model gets attention's precise recall at a fraction of attention's memory and compute cost: $$\text{KV cache}_{\text{Jamba}} \approx \frac{1}{k}\cdot\text{KV cache}_{\text{Transformer}}$$ where \(k\) is the attention-layer ratio (e.g. 1 attention layer per \(k{=}8\) layers).

How Jamba Works Internally
▼

The Block Pattern

Jamba is built from repeating "Jamba blocks." Each block stacks several layers; most are Mamba layers, and one in every \(k\) layers (AI21's released model uses \(k{=}8\)) is a full self-attention layer instead. Roughly half the layers — Mamba and attention alike — are further widened into a sparse Mixture-of-Experts (MoE) feed-forward layer, where a small router picks the top-\(2\) of many experts per token instead of running one dense MLP. This gives four knobs to tune: total depth, attention ratio \(k\), MoE frequency, and number of active experts.

Mamba Layer: Selective State-Space Recurrence

Each Mamba layer walks the sequence left to right, maintaining a hidden state matrix \(h_t\) of fixed size (state dimension \(n\), independent of sequence length). At every step it discretizes continuous parameters \(A,B\) into \(\bar A, \bar B\) (a function of the token itself — this is the "selective" part that makes Mamba input-dependent rather than a static filter), then updates: \(h_t = \bar A h_{t-1} + \bar B x_t\), and reads out \(y_t = C h_t + D x_t\). Because \(h_t\) only depends on \(h_{t-1}\), inference is O(1) memory per step and the whole layer trains in O(n) via a parallel scan.

Attention Layer: Full Lookback

The interspersed attention layers behave exactly like ordinary Transformer self-attention: every token computes \(Q,K,V\) and attends to all previous tokens via \(\text{softmax}(QK^\top/\sqrt{d})V\). This is what lets Jamba do precise "needle in a haystack" retrieval that pure state-space models sometimes miss — but it requires caching every past token's \(K,V\) vectors, so memory grows linearly with context length.

🔑 Design Decision: Why not pure Mamba or pure Transformer?

Pure Mamba is fast and memory-flat but empirically weaker at tasks needing exact recall of a specific earlier token (in-context learning, copying). Pure Transformer is strong but its KV cache and O(n²) attention cost make very long contexts expensive. Jamba's authors found that even a small fraction of attention layers (1-in-8) recovers most of the recall quality while keeping memory close to Mamba's — the two mechanisms are complementary, not competing.

3
Why It Works — The Math
▼

State-Space Recurrence

A continuous-time linear state-space model is \(h'(t) = Ah(t) + Bx(t)\), \(y(t) = Ch(t)\). Mamba discretizes it with step size \(\Delta\) (the zero-order hold rule):

$$\bar A = \exp(\Delta A), \qquad \bar B = (\Delta A)^{-1}(\exp(\Delta A) - I)\cdot \Delta B$$

giving the discrete recurrence used at every token: \(h_t = \bar A h_{t-1} + \bar B x_t\), \(y_t = Ch_t + Dx_t\). Mamba's key innovation is making \(\Delta, B, C\) functions of \(x_t\) (selectivity), so the model can choose, per token, how much to remember versus forget — something a fixed linear filter cannot do.

Attention Cost

Standard attention computes a full \(n\times n\) score matrix per layer: \(\text{Attn}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V\), costing \(O(n^2 d)\) time and requiring a KV cache of size \(O(n \cdot d)\) per layer that grows with every generated token.

Jamba's Memory Formula

For a model with \(L\) total layers, attention ratio \(k\) (1 attention layer per \(k\)), state dimension \(n_s\), and KV head dimension \(d\), the memory used for the recurrent/cached parts at sequence length \(n\) is approximately:

$$M_{\text{Jamba}}(n) \;=\; \underbrace{L\cdot n_s}_{\text{Mamba states, constant in }n} \;+\; \underbrace{\frac{L}{k}\cdot n \cdot d}_{\text{attention KV cache}}$$

compared to a pure Transformer's \(M_{\text{Transformer}}(n) = L\cdot n\cdot d\). As \(n\to\infty\), \(M_{\text{Jamba}}/M_{\text{Transformer}} \to 1/k\) — an asymptotic \(k\times\) memory reduction, which is exactly why Jamba can serve much longer contexts on the same hardware.

⚠️ Common Pitfall

The \(1/k\) saving is asymptotic. At short sequences the fixed Mamba state overhead \(L\cdot n_s\) can dominate, so the memory advantage only becomes visible once \(n\) is large enough that the attention KV cache term would otherwise dominate. Also, selectivity makes Mamba non-linear-time-invariant, so the convenient convolutional view of vanilla SSMs no longer applies — training relies on a hardware-aware parallel scan, not an FFT convolution.

Key Takeaways
▼

When hybrid (Jamba-style) architectures shine:

  • Very long context windows (100K+ tokens) where a full-attention KV cache would blow the memory budget
  • Workloads needing both cheap streaming generation (Mamba) and occasional precise recall (attention), e.g. long-document QA
  • Single-GPU / constrained-memory serving where throughput matters as much as quality

When NOT to reach for it:

  • Short sequences where a plain Transformer's simplicity and mature tooling win — the memory saving hasn't kicked in yet
  • Tasks that are almost entirely about exact multi-hop retrieval across the whole context — leaning attention-heavy (lower \(k\)) may be worth the extra memory
  • Extreme low-latency single-token decoding where MoE routing overhead isn't worth it — a dense small Mamba model may be simpler
💡 Hierarchy

Attention (\(k{=}1\), all layers attend) generalizes to Jamba (\(k \gg 1\), mostly Mamba with sparse attention), which generalizes to pure Mamba (\(k \to \infty\), no attention at all). Jamba sits deliberately in the middle of this spectrum, trading a small amount of attention for a large amount of memory efficiency.

class JambaBlock(nn.Module):
"""8 layers: 7 Mamba + 1 Attention; alternating layers use MoE FFN."""
def __init__(self, d_model, n_state, k_attn=8, n_experts=8, top_k=2):
self.layers = []
for i in range(8):
is_attn = (i % k_attn == k_attn - 1) # 1-in-8 is attention
mixer = Attention(d_model) if is_attn else Mamba(d_model, n_state)
ffn = MoE(d_model, n_experts, top_k) if i % 2 == 0 else MLP(d_model)
self.layers.append((mixer, ffn))
def mamba_step(x_t, h_prev, A, B, C, D, delta):
# Selective discretization: delta, B, C are functions of x_t
A_bar = exp(delta * A) # (n_state,) fixed-size state transition
B_bar = delta * B # zero-order-hold approx
h_t = A_bar * h_prev + B_bar * x_t # O(1) memory recurrence
y_t = C @ h_t + D * x_t
return y_t, h_t # only h_t is kept, not full history
def attention_layer(x, kv_cache):
q, k, v = proj_q(x), proj_k(x), proj_v(x)
kv_cache.append(k, v) # cache grows every token: O(n) memory
scores = (q @ kv_cache.K.T) / sqrt(d) # O(n^2) compute at generation step n
return softmax(scores) @ kv_cache.V
def moe_ffn(x, router, experts, top_k=2):
logits = router(x) # (n_experts,) per token
idx = top_k_indices(logits, top_k) # sparse: only 2 of 8 experts run
weights = softmax(logits[idx])
return sum(w * experts[i](x) for w, i in zip(weights, idx))
