Sliding Window Attention

Mistral's local attention trick: each token only looks back W steps — yet depth still sees everything
Intermediate Transformers / LLMs Efficient Attention O(n·W)
1
Understanding Sliding Window Attention
▼

What is it? In standard ("full" or "global") self-attention, every token attends to every earlier token — a query at position 10,000 can directly look at position 1. That is powerful but costs \(O(n^2)\) time and memory as the sequence grows. Sliding window attention (SWA), used in Mistral 7B, restricts each token to only look back at the previous \(W\) tokens (a fixed-size window). Everything outside the window is masked out, just like the "future" is masked in causal attention.

Analogy: Imagine reading a book through a narrow paper tube that only shows the last few words you passed — you can't glance back to page 1. That seems limiting for a single glance. But if you stack several readers in a relay, where each one summarizes what the previous reader told them plus what they see through their own tube, information from far back can still propagate forward — just indirectly, through many hops. That's exactly what stacking transformer layers does.

💡 If you remember one thing

A single sliding-window layer only sees \(W\) tokens back, but stacking \(L\) such layers gives an effective receptive field that grows roughly linearly with depth: $$\text{RF}(L) \approx 1 + L\,(W-1)$$ — the same trick dilated/stacked convolutions use to see far with small kernels.

2
How It Works Internally
▼

The Attention Mask

Ordinary causal self-attention masks out future tokens: query \(i\) may attend to keys \(j \le i\). Sliding window attention adds a second constraint — the key must also be recent enough: \(j > i - W\). So the allowed set is:

$$\mathcal{A}(i) = \{\, j \;:\; \max(0,\, i-W+1) \le j \le i \,\}$$

Plotted as an \(n \times n\) mask, this produces a diagonal band of width \(W\) instead of a full lower-triangular matrix. Every row (query) has at most \(W\) unmasked cells regardless of how long the sequence is.

Why This Doesn't Truncate Context — Stacking Layers

A single layer's output token \(h^{(1)}_i\) is a mix of raw tokens \([i-W+1, i]\). Feed that into a second sliding-window layer: token \(h^{(2)}_i\) mixes \(h^{(1)}_{i-W+1}, \dots, h^{(1)}_i\) — each of those already mixed \(W\) raw tokens. Composing the windows, layer 2's receptive field reaches back \(2W-1\) raw positions. This is identical to how stacking convolutions (or dilated convolutions) with kernel size \(W\) enlarges the receptive field with depth, rather than width.

Design Decision: Why cap the window instead of shrinking the model?

The attention compute and KV-cache memory scale with the number of unmasked entries, not the model size. With SWA, both attention FLOPs and the key/value cache become \(O(n \cdot W)\) and \(O(W)\) per new token (a rolling buffer — old keys past the window can be evicted), instead of \(O(n^2)\) FLOPs and \(O(n)\) cache for full attention. Mistral 7B uses \(W = 4096\) with 32 layers, so information can in principle propagate across \(\approx 131K\) tokens even though no single layer looks further than 4096 tokens back.

🔑 Key Property

Sliding window attention trades per-layer receptive field for compute/memory efficiency, and recovers long-range context across depth instead of within a single layer — an implicit, learned form of the dilation trick from convolutional networks.

3
Why It Works — The Math
▼

Attention Cost With a Window

Standard scaled dot-product attention for a sequence of length \(n\) computes an \(n \times n\) score matrix:

$$\text{Attn}(Q,K,V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right) V$$

where \(M\) is the mask (\(-\infty\) on disallowed entries, \(0\) on allowed ones). For causal attention, \(M\) has \(O(n^2)\) finite entries. For sliding window attention, \(M_{ij} = 0\) only when \(j \in \mathcal{A}(i)\) — at most \(W\) entries per row, so the number of finite (score-computing) entries is bounded by \(n \cdot W\):

$$\text{FLOPs}_{\text{SWA}} = O(n \cdot W \cdot d_k) \quad \text{vs.} \quad \text{FLOPs}_{\text{full}} = O(n^2 \cdot d_k)$$

Since \(W\) is a fixed constant (e.g. 4096) independent of \(n\), cost grows linearly in sequence length rather than quadratically once \(n > W\).

Effective Receptive Field Across Depth

Treat each attention layer like a 1-D convolution with kernel size \(W\) (causal, stride 1, no dilation). The standard receptive-field recurrence for stacking \(L\) such kernels is:

$$\text{RF}(L) = \text{RF}(L-1) + (W - 1), \qquad \text{RF}(1) = W$$

Solving the recurrence gives closed form:

$$\text{RF}(L) = 1 + L\,(W - 1)$$

Plugging in Mistral 7B's actual values \(W = 4096\), \(L = 32\): \(\text{RF} = 1 + 32 \times 4095 = 131{,}041 \approx 131K\) tokens — this is exactly the "theoretical attention span" quoted in the Mistral 7B paper (Jiang et al., 2023).

⚠️ Common Misconception

The \(131K\)-token span is a theoretical upper bound on information flow, not a guarantee that layer 32 uses distant tokens as effectively as a full-attention model would. Gradients and relevance must be learned to actually exploit the full path — in practice, influence attenuates with hop count, same as with deep dilated CNNs.

Key Takeaways
▼

When to use sliding window attention:

  • Long sequences where full \(O(n^2)\) attention is the compute/memory bottleneck (long documents, long-context chat)
  • Streaming / rolling KV-cache inference — old keys beyond the window can be evicted, bounding cache size at \(O(W)\)
  • You can tolerate a learned, indirect (multi-hop) path for very long-range dependencies rather than direct attention

When NOT to use:

  • Tasks that need precise, direct long-range lookups in a shallow network (few layers) — the effective receptive field may not reach far enough
  • Sequences shorter than \(W\) — SWA degenerates to full causal attention anyway, so there's no benefit
  • When retrieval-style exact recall from anywhere in context is critical (favor full attention or explicit retrieval/RAG)
💡 Mental Model

Sliding window attention is to transformers what a small convolution kernel + depth is to CNNs: local mixing at every layer, global reach through composition. Mistral combines it with a rolling-buffer KV cache and grouped-query attention for fast, memory-bounded long-context inference.

import numpy as np
def sliding_window_mask(n, W):
"""Boolean mask: True = allowed to attend."""
i = np.arange(n)[:, None] # query positions (rows)
j = np.arange(n)[None, :] # key positions (cols)
causal = j <= i # can't see the future
windowed = j > i - W # can't see too far back
return causal & windowed # banded diagonal mask
def sliding_window_attention(Q, K, V, W):
n, d_k = Q.shape[-2], Q.shape[-1]
scores = Q @ K.transpose(-2, -1) / np.sqrt(d_k)
mask = sliding_window_mask(n, W)
scores = np.where(mask, scores, -np.inf)
weights = softmax(scores, axis=-1)
return weights @ V
# Effective receptive field after stacking L layers
def receptive_field(W, L):
return 1 + L * (W - 1)
# Mistral 7B: W=4096, L=32 -> ~131K token theoretical span
print(receptive_field(4096, 32)) # 131041
# Rolling KV-cache: only keep the last W keys/values per layer
class RollingCache:
def __init__(self, W, d_model):
self.W, self.buf, self.pos = W, np.zeros((W, d_model)), 0
def add(self, kv):
self.buf[self.pos % self.W] = kv # overwrite oldest slot
self.pos += 1
