Understanding InternVL & InternLM-XComposer
▼

What is it? InternVL and InternLM-XComposer are two companion projects from Shanghai AI Lab that push open-source multimodal LLMs (MLLMs) toward GPT-4V-level capability. InternVL asks: "what if the vision encoder were as large and as carefully trained as the language model?" — and builds InternViT-6B, a 6-billion-parameter Vision Transformer, then aligns it to LLMs through a progressive training curriculum. InternLM-XComposer asks a complementary question: "how do we let a model freely weave images and text together — reading interleaved articles, and even writing them, choosing which image belongs next to which paragraph?"

Analogy: Most MLLMs bolt a small "eye" (a ~300M-parameter CLIP encoder) onto a huge "brain" (a 7B–70B LLM) — like giving a brilliant scholar reading glasses with a tiny, blurry lens. InternVL instead grows the eye until it is proportionate to the brain: a 6B-parameter visual cortex that can actually resolve fine detail, dense text, charts, and small objects. InternLM-XComposer is the "art director" layer on top — it doesn't just describe one picture, it composes magazine-style spreads, deciding where images and captions interleave, using an LLM that has learned to switch fluidly between "reading pixels" and "reading words" mid-sentence.

💡 If you remember one thing

Scaling the vision encoder to billions of parameters (InternViT-6B) and aligning it with an LLM through a progressive contrastive → generative → instruction-tuning curriculum closes the capacity gap between "seeing" and "reasoning" — while dynamic tiling and pixel-shuffle compression keep the resulting token count tractable for the LLM's context window.

2
How It Works Internally
▼

1. Dynamic High-Resolution Tiling

Raw images arrive at arbitrary aspect ratios and resolutions (a phone screenshot, a wide poster, a dense table). InternVL's dynamic preprocessing picks the pre-defined aspect ratio (from 1:1 up to 1:6, up to 12 tiles) that best matches the input, resizes the image to that grid, then slices it into non-overlapping 448×448 tiles, plus one extra downsampled thumbnail tile that preserves global context. A 1344×896 image becomes, e.g., 6 local tiles + 1 thumbnail — each tile is small enough to match the encoder's native training resolution, yet together they preserve high-frequency detail (small text, faces, icons) that a single low-res resize would destroy.

2. InternViT-6B — a Scaled Vision Transformer

Each 448×448 tile is split into 14×14 patches, giving a 32×32 = 1024-token sequence, which is fed through InternViT-6B: 48 transformer blocks, hidden size 3200, roughly 6 billion parameters — comparable in depth and width to the LLM it will feed, not a token-sized CLIP-ViT-L (300M). Every tile is encoded independently (shared weights), producing 1024 contextualized patch embeddings per tile.

3. Pixel-Shuffle Token Compression

1024 tokens per tile × 7 tiles would blow the LLM's context budget. InternVL applies a pixel-shuffle operation: group each 2×2 neighborhood of patch embeddings and concatenate them along the channel dimension, quartering the spatial grid (32×32 → 16×16) while quadrupling channel width. This is a lossless reshaping — no information is dropped, just re-packed — after which a linear layer projects back to the model width. Result: 1024 → 256 tokens per tile, a 4× reduction, with negligible accuracy cost.

4. Progressive Alignment (Contrastive → Generative → SFT)

InternViT-6B isn't trained jointly with the LLM from scratch — that would be unstable at this scale. Instead InternVL uses a 3-stage curriculum: Stage 1 trains InternViT-6B contrastively against a multilingual LLaMA-based text encoder on web-scale image-text pairs (CLIP-style). Stage 2 freezes/soft-adapts the ViT and trains a middleware "QLLaMA" (96 learnable query tokens, cross-attending into the ViT features, initialized from an 8B LLaMA) generatively — next-token image captioning. Stage 3 plugs the aligned visual features into a full decoder LLM (Vicuna, InternLM2, …) via a lightweight MLP projector and instruction-tunes end-to-end. Later InternVL versions (1.5/2.x) simplify this to ViT + MLP projector + LLM trained jointly, reusing the earlier stages only for the encoder's initialization.

5. InternLM-XComposer — Interleaved Composition via PLoRA

XComposer2's key trick is Partial LoRA (PLoRA): a low-rank adapter is injected into the LLM's weights, but it is applied only at sequence positions that carry image tokens — text-token positions use the frozen base weights untouched. This lets the model absorb rich, fine-grained visual signal without ever perturbing the language modeling capability the base LLM already has, so image and text tokens can be freely interleaved in one causal sequence: [text][img][img]...[text][img][text]..., in any order, across multiple images and turns.

🔑 Design decision: why not just use a bigger LLM instead of a bigger ViT?

Early MLLMs (LLaVA, MiniGPT-4) scaled the language side while keeping a small frozen CLIP-ViT-L/14 (~300M params) as the "eyes." InternVL's ablations show that beyond a point, adding LLM parameters gives diminishing returns on visual tasks (OCR, chart QA, fine-grained grounding) because the bottleneck is representational capacity of the visual features, not reasoning. Scaling the encoder to 6B — closer in magnitude to the LLM — closes that bottleneck.

Why It Works — The Math
▼

Stage 1 — Contrastive Vision-Language Pretraining

InternViT-6B and a text encoder \(f_T\) are trained with a symmetric InfoNCE / CLIP objective over a batch of \(N\) image-text pairs \((I_i, T_i)\):

$$\mathcal{L}_{\text{contrastive}} = -\frac{1}{2N}\sum_{i=1}^{N}\left[\log\frac{\exp(\text{sim}(v_i,t_i)/\tau)}{\sum_{j=1}^N \exp(\text{sim}(v_i,t_j)/\tau)} + \log\frac{\exp(\text{sim}(v_i,t_i)/\tau)}{\sum_{j=1}^N \exp(\text{sim}(v_j,t_i)/\tau)}\right]$$

where \(v_i = f_V(I_i)\), \(t_i = f_T(T_i)\), \(\text{sim}(\cdot,\cdot)\) is cosine similarity, and \(\tau\) is a learned temperature. This pulls matched image/text embeddings together and pushes apart the \(N-1\) mismatched pairs in-batch — it teaches InternViT-6B a semantically rich embedding space before it ever sees the LLM.

Stage 2 — Generative Alignment (QLLaMA middleware)

A set of 96 learnable query tokens \(Q\) cross-attend into the frozen/lightly-adapted ViT features \(V = f_V(I)\), and the resulting query outputs condition an autoregressive captioning objective over caption tokens \(y_1,\dots,y_T\):

$$\mathcal{L}_{\text{gen}} = -\sum_{t=1}^{T}\log P_\theta\big(y_t \mid y_{

This is standard next-token cross-entropy, but the conditioning signal is now a compact, learned summary of the image rather than a global CLIP embedding — forcing the query tokens to retain the fine-grained detail needed to generate accurate captions.

Pixel-Shuffle as a Deterministic Reshape

Given patch features \(X \in \mathbb{R}^{H\times W\times C}\) (here \(H=W=32,\ C=3200\)), pixel-shuffle with downscale factor \(r=2\) regroups each \(r\times r\) spatial block into the channel axis:

$$X \in \mathbb{R}^{H\times W\times C} \;\longrightarrow\; X' \in \mathbb{R}^{\frac{H}{r}\times \frac{W}{r}\times (r^2 C)},\qquad N_{\text{tokens}} = \frac{H}{r}\cdot\frac{W}{r} = \frac{HW}{r^2}$$

followed by a learned linear map \(W_{\text{proj}}: \mathbb{R}^{r^2C}\to\mathbb{R}^{d_{\text{model}}}\). Because this is a bijective reshape (not pooling or striding), zero information is discarded in the compression step itself — all loss comes later from the projection.

Stage 3 — Full Instruction Tuning

The projected visual tokens \(\hat V = W_{\text{proj}}(X')\) are spliced into the LLM's input embedding sequence at image placeholder positions, and the whole interleaved sequence \((\hat V, \text{text tokens})\) is trained with the same causal next-token loss as a text-only LLM:

$$\mathcal{L}_{\text{SFT}} = -\sum_{t=1}^{T}\log P_\theta\big(y_t \mid y_{

with gradients flowing back through \(W_{\text{proj}}\) (and, depending on the stage, through InternViT-6B itself) — this is what finally teaches the model to reason jointly over pixels and words, not just describe images in isolation.

PLoRA — Conditional Low-Rank Adaptation

For a frozen weight matrix \(W_0\), standard LoRA adds \(\Delta W = BA\) (with \(B\in\mathbb{R}^{d\times r}, A\in\mathbb{R}^{r\times d}\), \(r \ll d\)) everywhere. PLoRA instead gates the adapter by a per-token image mask \(m_i \in \{0,1\}\):

$$h_i = W_0 x_i + m_i \cdot (BA)\, x_i, \qquad m_i = \mathbb{1}[\text{token } i \text{ is an image token}]$$

so text tokens see exactly the pretrained LLM (preserving its language ability), while image tokens get an extra learned transformation that specializes for vision — a cheap way to add vision capacity without catastrophic forgetting of language skill.

⚠️ Common Pitfall

Naively fine-tuning all LLM weights on multimodal data (no PLoRA / no staged freezing) tends to degrade pure-text benchmarks — the model "forgets" language skill while learning vision. Gating adaptation by token type, or freezing the ViT/LLM at different stages, is what prevents this trade-off from tanking either modality.

Key Takeaways
▼

When these ideas matter most:

  • OCR-heavy or dense-detail tasks (documents, charts, UI screenshots, small text) — dynamic tiling preserves resolution that a single 224/336px resize would blur away.
  • Tasks needing strong joint visual-textual reasoning (chart QA, visual math, grounding) — a 6B-parameter encoder carries far richer features than a 300M CLIP-ViT into the LLM.
  • Multi-image / interleaved documents (visual storytelling, article generation with figure placement) — PLoRA + interleaved sequences are exactly what InternLM-XComposer was built for.

When simpler architectures suffice:

  • Single low-resolution image, coarse "what's in this picture" captioning — a small CLIP-ViT + LLaVA-style linear projector is far cheaper and nearly as accurate.
  • Latency/memory-constrained deployment — a 6B vision encoder roughly doubles inference cost versus a 300M one; distilled or pruned variants (InternViT-300M) trade some accuracy for speed.
💡 The big-picture pattern

Dynamic tiling solves the resolution problem, a scaled ViT solves the representational-capacity problem, pixel-shuffle solves the token-budget problem, progressive alignment solves the training-stability problem, and PLoRA solves the catastrophic-forgetting problem. Each piece targets one specific failure mode of naively bolting a big LLM onto a small vision encoder.

H, W, C = x.shape
x = x.view(H//r, r, W//r, r, C).permute(0, 2, 1, 3, 4)
return x.reshape(H//r, W//r, r*r*C) # (16, 16, 4C)
