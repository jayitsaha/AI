Online Learning vs Batch Learning
Incremental per-example updates vs full-dataset retraining — when to use each and how each adapts
Foundational Classical ML Regret · Drift · Memory
1
Understanding the Concept

Batch learning collects every training example, trains on the full dataset to convergence, and then deploys a frozen model. To incorporate new data you must retrain from scratch (or from a checkpoint). Like cramming for an exam: read all textbooks, take the test, done.

Online learning (incremental / sequential learning) updates model parameters after each example or small mini-batch, continuously — the model never "stops training." Like a doctor who refines their diagnosis skills after every new patient, without re-reading every medical textbook.

Key Invariant

Online learning maintains bounded memory: it needs to store only the current model parameters \(\theta\), not the entire history of data. Batch learning memory grows as \(\mathcal{O}(N)\) with dataset size \(N\).

💡 If you remember one thing

Online learning's update rule is \(\theta_{t+1} = \theta_t - \eta_t \nabla \ell(\theta_t; x_t, y_t)\) — one gradient step per example. Batch learning takes one step per pass over the entire dataset: \(\theta \leftarrow \theta - \eta \frac{1}{N}\sum_{i=1}^N \nabla \ell(\theta; x_i, y_i)\).

2
Internal Mechanics — Numerical Trace

Consider online SGD for linear regression on a stream of examples \((x_t, y_t)\). The loss for one example is \(\ell_t(\theta) = \frac{1}{2}(y_t - \theta^\top x_t)^2\).

$$\theta_{t+1} = \theta_t + \eta_t (y_t - \theta_t^\top x_t) x_t$$

Concrete trace with \(\theta_0 = [0.5,\ 0.0]\), \(\eta = 0.1\):

Example 1: x=[1,2], y=3.0
pred = [0.5, 0.0]·[1,2] = 0.5
error = 3.0 − 0.5 = 2.5
update = 0.1 × 2.5 × [1,2] = [0.25, 0.50]
θ₁ = [0.75, 0.50] ← immediate adaptation
Example 2: x=[2,1], y=4.0
pred = [0.75, 0.50]·[2,1] = 2.00
error = 4.0 − 2.0 = 2.0
update = 0.1 × 2.0 × [2,1] = [0.40, 0.20]
θ₂ = [1.15, 0.70] ← model keeps adapting

In batch learning, those same two examples would yield: \(\theta_1 = \theta_0 - \eta \frac{1}{2}\sum_{i=1}^{2}\nabla\ell_i = [0.5,0] - 0.1 \times \frac{1}{2}([-2.5,-5] + [-4,-2]) = [0.5,0] + [0.325, 0.35] = [0.825, 0.35]\). The difference: online takes two separate gradient steps; batch takes one averaged step.

⚠ Online update noise

Because each online update uses only one noisy gradient, \(\theta_t\) is noisier than the batch solution. Reducing the learning rate \(\eta_t \propto 1/\sqrt{t}\) ensures convergence but slows adaptation. There is an inherent bias-variance trade-off in choosing \(\eta_t\).

3
Why It Works — Regret, Drift, Convergence

Online learning is analysed via regret, not test loss. Regret measures how much worse the algorithm does compared to the best fixed model in hindsight:

$$R_T = \sum_{t=1}^{T} \ell_t(\theta_t) - \min_{\theta^*} \sum_{t=1}^{T} \ell_t(\theta^*)$$

For online gradient descent with convex losses and step size \(\eta_t = \frac{D}{G\sqrt{t}}\) (where \(D\) = diameter of parameter space, \(G\) = gradient norm bound):

$$R_T \leq DG\sqrt{T} \implies \frac{R_T}{T} \to 0 \text{ as } T \to \infty$$

This is sublinear regret — the algorithm "catches up" to the best fixed model. Batch learning doesn't have this guarantee at all when the distribution shifts (concept drift).

Concept drift: if the true relationship \(P(y|x)\) changes over time, the batch model trained on old data becomes stale. Online learning continuously incorporates new examples, naturally tracking the drift:

$$\theta_{t+1} = (1-\lambda)\theta_t - \eta_t \nabla \ell_t(\theta_t)$$

where \(\lambda\) is a forgetting factor (small positive number, e.g. \(10^{-4}\)) that decays old weights, enabling the model to "forget" outdated patterns.

Convergence Comparison

Batch GD: converges to global minimum (convex) at rate \(\mathcal{O}(1/t)\) with exact gradients. Online SGD: converges in expectation at rate \(\mathcal{O}(1/\sqrt{T})\) — slower, but processes \(T\) examples instead of \(N\) passes over \(N\) examples. For large \(N\), online is often faster per wall-clock second.

5
When To Use Each
⚡ Use Online Learning when…
  • Data arrives as a stream (click logs, sensor readings, financial ticks)
  • Concept drift is expected (user preferences, market regimes)
  • Memory is bounded (edge devices, embedded systems)
  • Dataset is too large to fit in RAM
  • Low-latency model updates are required
  • Labeled examples arrive one-at-a-time
📦 Use Batch Learning when…
  • Dataset is static and fully available upfront
  • Reproducibility and exact convergence matter
  • Hyperparameter search requires multiple full training runs
  • Complex regularization or second-order methods are needed
  • Data distribution is stationary (i.i.d. assumption holds)
  • Inference-time latency more important than update latency
