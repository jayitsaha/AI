Learning from evolving graph structures and time-stamped interactions
Advanced Deep Learning Graph ML O(N log N) or O(N)
1
Understanding Temporal GNNs
▼

What is it? Traditional Graph Neural Networks (GNNs) operate on static graphs, assuming connections and node features don't change. Temporal GNNs (TGNNs) extend this to dynamic graphs, where nodes interact over time. These interactions can be new edges forming, existing edges changing features, or nodes appearing/disappearing. TGNNs aim to capture both the structural (who is connected) and temporal (when did they interact, how recent) aspects to generate time-aware node embeddings.

Analogy: Imagine a social network where users (nodes) send messages, 'like' posts, or form new friendships (edges) at specific timestamps. A static GNN would only see the final network. A TGNN, however, processes these events chronologically. It can tell you not just *who* is friends with *whom*, but also *when* that friendship started, *how recently* they interacted, and *what kind* of interaction it was. This allows for predictions like "who is likely to interact next?" or "how will a user's interests evolve?"

💡 If you remember one thing

The core challenge in Temporal GNNs is to integrate time into node representations. TGAT (Temporal Graph Attention Network) uses self-attention over historical interactions, while TGN (Temporal Graph Network) maintains a recurrent memory for each node that updates with every new event, offering complementary approaches to capture temporal dynamics.

2
How TGAT & TGN Work Internally
▼

The Event Stream Perspective

Both TGAT and TGN view the dynamic graph as a stream of discrete, time-stamped interactions (edges). When a new interaction \((u, v, t, \mathbf{e}_{uv})\) occurs (node \(u\) interacts with node \(v\) at time \(t\) with edge features \(\mathbf{e}_{uv}\)), the goal is to update the representations of \(u\) and \(v\).

TGAT: Temporal Attention Over Historical Interactions

TGAT extends the Graph Attention Network (GAT) by incorporating time. For a target node \(u\), it queries its historical interactions. For each neighbor \(v\) that interacted with \(u\) at time \(t'\), TGAT computes an attention score based on:

  • The current embedding of \(u\).
  • The embedding of \(v\) at time \(t'\).
  • The edge features \(\mathbf{e}_{uv}\) for that interaction.
  • A time encoding of the time difference \(t - t'\).

These attention scores are then used to aggregate information from neighbors, similar to GAT, to produce an updated embedding for \(u\). TGAT is essentially stateless; it re-computes from a node's entire relevant history for each update.

TGN: Recurrent Memory for Continuous Node State

TGN takes a different approach by introducing a recurrent memory for each node. This memory \(\mathbf{m}_i(t)\) is a vector that continuously tracks the node's evolving state. When an interaction involving node \(i\) occurs:

  1. Message Generation: A message \(\mathbf{msg}\) is created, typically from the current memory of the interacting nodes, the edge features, and the time difference.
  2. Message Aggregation: If a node receives multiple messages (e.g., from multiple neighbors in a batch), these messages are aggregated.
  3. Memory Update: The node's memory \(\mathbf{m}_i(t)\) is updated using a Recurrent Neural Network (RNN) such as a GRU, taking its previous memory \(\mathbf{m}_i(t^-)\) and the aggregated message as input.
  4. Node Embedding: The final node embedding \(\mathbf{z}_i(t)\) for downstream tasks is derived from its updated memory, sometimes combined with a local GNN module.

This memory acts as a compressed summary of all past interactions, allowing TGN to capture long-term dependencies more effectively than stateless attention mechanisms.

🔑 Key Property

TGAT is stateless and memory-free: it processes each query by attending over historical interactions. TGN is stateful and memory-based: it maintains a dynamic memory for each node, updated by recurrent units, which implicitly summarizes past interactions and explicitly carries forward temporal information.

3
Why It Works — The Math Behind TGAT & TGN
▼

TGAT: Temporal Attention Mechanism

For an interaction between node \(i\) and node \(j\) at time \(t\), TGAT calculates attention scores \(\alpha_{ij}\) as:

$$ \mathbf{q}_i = \text{MLP}_Q(\mathbf{h}_i(t^-)), \quad \mathbf{k}_j = \text{MLP}_K(\mathbf{h}_j(t^-)), \quad \mathbf{v}_j = \text{MLP}_V(\mathbf{h}_j(t^-)) $$

The attention score for neighbor \(j\) interacting with \(i\) at time \(t'\) (where \(t'\) is the timestamp of the edge \((i,j)\) being considered from history) is then:

$$ \alpha_{ij} = \text{softmax}\left(\frac{(\mathbf{q}_i \cdot \mathbf{k}_j + \text{MLP}_{edge}(\mathbf{e}_{ij})) \cdot \text{TimeEncoder}(t - t')}{\sqrt{d}}\right) $$

The updated embedding for node \(i\) is a weighted sum of neighbor values and its own previous state:

$$ \mathbf{h}_i(t) = \text{MLP}_{out}\left(\mathbf{h}_i(t^-) + \sum_{j \in \mathcal{N}(i)} \alpha_{ij} (\mathbf{v}_j + \text{MLP}_{edge}(\mathbf{e}_{ij}))\right) $$

Here, \(\mathbf{h}_i(t^-)\) is node \(i\)'s embedding just before time \(t\), \(\mathbf{e}_{ij}\) are edge features, and \(\text{TimeEncoder}\) maps the time difference to a scalar or vector, often using sinusoidal embeddings or simple exponential decay.

TGN: Memory, Message, and Embedding Updates

TGN updates a node's memory \(\mathbf{m}_i(t)\) and embedding \(\mathbf{z}_i(t)\) sequentially. When node \(u\) interacts with node \(v\) at time \(t\):

  1. Message Creation: For each node \(i \in \{u, v\}\), a message \(\mathbf{msg}_{i}\) is created from its own memory, its neighbor's memory, edge features, and a time encoding. For example, for node \(u\): $$ \mathbf{msg}_{u} = \text{MessageFunction}(\mathbf{m}_u(t^-), \mathbf{m}_v(t^-), \mathbf{e}_{uv}, \text{TimeEncoder}(t - t_u^-)) $$ where \(t_u^-\) is the last time \(u\)'s memory was updated.
  2. Message Aggregation: If multiple messages arrive for a node (e.g., from different neighbors in a batch), they are aggregated (e.g., by sum or mean).
  3. Memory Update: The node's memory is updated using an RNN (e.g., GRU): $$ \mathbf{m}_u(t) = \text{RNN}(\mathbf{m}_u(t^-), \text{AggregatedMessage}_u) $$
  4. Node Embedding Generation: Finally, a temporary node embedding \(\mathbf{z}_u(t)\) is generated from the updated memory, often combined with a local GNN module that aggregates information from neighbors in the current snapshot: $$ \mathbf{z}_u(t) = \text{MLP}(\mathbf{m}_u(t), \text{GNN}_{\text{local}}(\{\mathbf{z}_j(t^-)\}_{j \in \mathcal{N}(u)})) $$ This allows TGN to leverage both the long-term memory and the immediate structural context.
⚠️ Computational Cost & Memory Footprint

Both TGAT and TGN can be computationally intensive. TGAT requires storing and processing historical interactions for attention, which can grow with the graph's density and length of history. TGN, while avoiding full history re-computation, needs to store and update a memory vector for every node, and its recurrent nature can be slower than parallel attention mechanisms for very dense interaction patterns.

Key Takeaways
▼

When to use Temporal GNNs (TGAT/TGN):

  • Evolving Networks: Social networks, citation graphs, communication networks where connections form and dissolve over time.
  • Recommendation Systems: Predicting future interactions (e.g., purchases, clicks) based on a user's chronological activity and their neighbors'.
  • Fraud Detection: Identifying anomalous interaction patterns in financial transactions or online activity.
  • Traffic Prediction: Modeling dynamic traffic flows on road networks.
  • Any domain where 'when' an interaction happened is as important as 'who' interacted.

When NOT to use:

  • Static Graphs: If the graph structure is fixed, traditional GNNs are simpler and more efficient.
  • Graphs with Sparse or Irregular Temporal Data: If interactions are too infrequent or lack clear timestamps, the temporal aspect may not add much value, or the models might struggle to learn meaningful patterns.
  • Extremely Large Graphs with Very Long Histories: Computational and memory costs can become prohibitive. Approximations or sampling techniques are often necessary.
  • Simple Tasks: If a simple heuristic or a static graph model already performs well, the added complexity of TGNNs might not be justified.
💡 TGAT vs. TGN: A Choice

TGAT is often good for tasks requiring fine-grained attention to specific past events. TGN excels at capturing long-term dependencies and maintaining a continuous, evolving node state. The choice depends on the specific task, data characteristics, and computational budget. TGN's memory can be more robust to missing interactions, while TGAT's attention is more explicit about historical influence.

Code Trace (Simplified PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
class TimeEncoder(nn.Module):
def __init__(self, output_dim):
super().__init__()
self.output_dim = output_dim
self.lin = nn.Linear(1, output_dim) # Simple linear for time delta
def forward(self, time_delta):
# time_delta shape: (batch_size,)
return self.lin(time_delta.unsqueeze(-1)) # Output: (batch_size, output_dim)
class TGATLayer(nn.Module):
def __init__(self, node_dim, edge_dim, time_dim, num_heads=1):
super().__init__()
self.node_dim = node_dim
self.time_encoder = TimeEncoder(time_dim)
self.query_lin = nn.Linear(node_dim, node_dim)
self.key_lin = nn.Linear(node_dim + edge_dim + time_dim, node_dim)
self.value_lin = nn.Linear(node_dim + edge_dim + time_dim, node_dim)
self.out_lin = nn.Linear(node_dim * 2, node_dim) # Self-concat + aggregated
def forward(self, src_h, dst_h_hist, edge_feat_hist, time_delta_hist):
# src_h: (1, node_dim) - current node embedding
# dst_h_hist: (num_neighbors, node_dim) - historical neighbor embeddings
# edge_feat_hist: (num_neighbors, edge_dim) - historical edge features
# time_delta_hist: (num_neighbors,) - historical time differences
query = self.query_lin(src_h)
time_enc = self.time_encoder(time_delta_hist) # (num_neighbors, time_dim)
# Concat neighbor embedding, edge feat, time encoding for keys/values
key_input = torch.cat([dst_h_hist, edge_feat_hist, time_enc], dim=-1)
keys = self.key_lin(key_input)
values = self.value_lin(key_input)
# Attention scores
attn_scores = torch.bmm(query.unsqueeze(1), keys.transpose(1, 2)).squeeze(1)
attn_weights = torch.softmax(attn_scores, dim=-1)
# Aggregate neighbor information
aggregated_output = torch.bmm(attn_weights.unsqueeze(1), values).squeeze(1)
# Combine with source node and output
return self.out_lin(torch.cat([src_h, aggregated_output], dim=-1))
class TGNLayer(nn.Module):
def __init__(self, node_dim, edge_dim, memory_dim, time_dim):
super().__init__()
self.time_encoder = TimeEncoder(time_dim)
self.message_fn = nn.Linear(memory_dim * 2 + edge_dim + time_dim, memory_dim)
self.memory_updater = nn.GRUCell(memory_dim, memory_dim) # Updates memory
self.embedding_fn = nn.Linear(memory_dim, node_dim) # Derives node emb from memory
def forward(self, src_mem, dst_mem, edge_feat, time_delta):
# src_mem, dst_mem: (1, memory_dim) - current node memories
# edge_feat: (1, edge_dim)
# time_delta: (1,)
time_enc = self.time_encoder(time_delta)
# Message from src to dst (and vice versa, simplified here for one direction)
message_input = torch.cat([src_mem, dst_mem, edge_feat, time_enc], dim=-1)
message = torch.relu(self.message_fn(message_input)) # (1, memory_dim)
# Aggregate messages (trivial for single interaction)
aggregated_message = message
# Update memory for src (assuming src is the one whose memory is updated)
new_src_mem = self.memory_updater(aggregated_message, src_mem)
# Generate new node embedding from updated memory
new_src_h = self.embedding_fn(new_src_mem)
return new_src_h, new_src_mem
