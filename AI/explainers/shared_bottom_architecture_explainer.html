Shared Bottom Architecture

Efficient multi-task learning with shared representations and task-specific heads
Foundational Deep Learning Multi-Task Learning Architecture
1
Understanding Shared Bottom Architecture
▼

What is it? The Shared Bottom architecture is a fundamental approach in multi-task learning (MTL). It consists of a common "bottom" network (an encoder or feature extractor) that processes the input and learns a generalized representation. This shared representation is then fed into multiple "task-specific heads," each responsible for solving a different, but often related, prediction task. This structure allows the model to leverage commonalities between tasks while still specializing for individual objectives.

Analogy: Imagine a university with a common core curriculum (the shared bottom) that all students must complete, regardless of their major. This curriculum builds foundational knowledge in areas like critical thinking, mathematics, and communication. After completing the core, students then specialize in their chosen majors (the task-specific heads), applying their foundational skills to specific fields like engineering, literature, or medicine. The shared bottom ensures a robust, generalized understanding, while the heads allow for tailored expertise.

💡 If you remember one thing

Shared Bottom architectures are efficient: they reduce the total number of parameters compared to separate models, facilitate knowledge transfer between related tasks, and often lead to better generalization by forcing the shared layers to learn robust, common features. The key is balancing the influence of each task on the shared representation.

2
How It Works Internally
▼

The Architecture: Common Encoder, Multiple Decoders

The structure is straightforward:

  1. Input Layer: Receives the raw data (e.g., an image, a sensor reading, tabular features).
  2. Shared Bottom Network: A series of layers (e.g., convolutional blocks, transformer encoders, dense layers) that process the input. All tasks share these parameters, learning a common set of features. This network acts as a powerful feature extractor, distilling the most relevant information from the input.
  3. Task-Specific Heads: After the shared bottom, the network branches. Each branch is a smaller, independent sub-network (e.g., a few dense layers, a decoder) designed to output the prediction for a specific task. These heads have their own unique parameters, allowing them to specialize.
  4. Output Layers: Each head culminates in an output layer that produces the final prediction for its respective task (e.g., a classification score, a regression value).

Training: Joint Optimization with Weighted Loss

The model is trained end-to-end. For each input, all task heads produce predictions, and their respective losses are calculated. These individual task losses (\(L_k\)) are then combined into a single total loss function, typically as a weighted sum: \(L_{total} = \sum_{k=1}^K \lambda_k L_k\), where \(\lambda_k\) are scalar weights that determine the relative importance of each task. During backpropagation, gradients from all task losses flow back through their respective heads and converge in the shared bottom, updating its parameters based on a "consensus" of all tasks.

Benefits and Challenges

  • Parameter Efficiency: Sharing a large portion of the network significantly reduces the total number of parameters, making models smaller and faster to train/deploy.
  • Knowledge Transfer (Positive Transfer): If tasks are related, features learned for one task can be beneficial for others, leading to improved performance, especially when data for some tasks is scarce.
  • Regularization: Training on multiple tasks implicitly regularizes the shared layers, preventing overfitting to any single task and encouraging more robust, general representations.
  • Negative Transfer: If tasks are very dissimilar, forcing them to share features can hinder performance on one or more tasks. Carefully designing the shared/private layers and balancing task losses is crucial.
🔑 Key Property

The shared bottom layers learn representations that are useful across all tasks, acting as a general-purpose feature extractor. The task-specific heads then transform these general features into specialized outputs. The success hinges on the assumption that tasks benefit from a common underlying data representation.

3
Why It Works — The Math of Joint Optimization
▼

Formalizing the Architecture

Let \(x\) be the input data. The shared bottom network \(f_{shared}\) maps \(x\) to a shared representation \(z\):

$$z = f_{shared}(x; w_s)$$

where \(w_s\) are the parameters of the shared layers. For each of \(K\) tasks, a task-specific head \(g_k\) maps \(z\) to the task's prediction \(\hat{y}_k\):

$$\hat{y}_k = g_k(z; w_k)$$

where \(w_k\) are the parameters unique to task \(k\).

The Combined Loss and Gradient Flow

During training, each task \(k\) has its own loss function \(L_k(y_k, \hat{y}_k)\), comparing the true label \(y_k\) with the prediction \(\hat{y}_k\). These individual losses are combined into a total loss \(L_{total}\) using task weights \(\lambda_k \ge 0\):

$$L_{total} = \sum_{k=1}^K \lambda_k L_k(y_k, g_k(f_{shared}(x; w_s); w_k))$$

The crucial part is how gradients for the shared parameters \(w_s\) are computed. By the chain rule, the gradient of \(L_{total}\) with respect to \(w_s\) is the sum of gradients from each task:

$$\frac{\partial L_{total}}{\partial w_s} = \sum_{k=1}^K \lambda_k \frac{\partial L_k}{\partial w_s}$$

Each individual term \(\frac{\partial L_k}{\partial w_s}\) is itself computed via the chain rule through task \(k\)'s head and the shared bottom:

$$\frac{\partial L_k}{\partial w_s} = \frac{\partial L_k}{\partial \hat{y}_k} \cdot \frac{\partial \hat{y}_k}{\partial z} \cdot \frac{\partial z}{\partial w_s}$$

This means that every gradient update to \(w_s\) is a weighted average of the "opinions" from all tasks. This constant feedback from diverse, yet related, tasks encourages the shared layers to learn features that are robust and generalizable, rather than specific to any single task. This implicit regularization helps prevent overfitting and improves generalization.

⚠️ Common Pitfall: Negative Transfer

If tasks are unrelated or if one task's gradients consistently dominate, the shared bottom might learn features detrimental to other tasks. This is called negative transfer. Careful selection of tasks, architectural design (e.g., adding more private layers), and tuning of loss weights \(\lambda_k\) are essential to mitigate this risk.

Key Takeaways
▼

When to use Shared Bottom Architecture:

  • Related Tasks: When tasks share underlying patterns or features (e.g., object detection and segmentation on the same image).
  • Limited Data: For tasks where individual datasets are small, multi-task learning can act as a form of data augmentation, improving generalization.
  • Resource Constraints: To reduce memory footprint and computational cost compared to training separate models for each task.
  • Improved Generalization: When the goal is to build a more robust model that performs well across a suite of related problems, not just one.

When NOT to use:

  • Unrelated Tasks: If tasks have little to no commonality, forcing shared representations can lead to negative transfer, where performance on one or more tasks degrades.
  • Vastly Different Scales/Distributions: Tasks with very different output scales or loss magnitudes can make balancing \(\lambda_k\) difficult, leading to one task dominating the shared layers.
  • Single-Task Optimization: If the absolute best performance on a single, isolated task is the sole objective, a dedicated single-task model might be simpler to optimize and achieve marginally better results.
💡 Big Picture

The Shared Bottom architecture is a powerful and widely adopted pattern in deep learning, especially for real-world applications like recommendation systems, natural language processing, and computer vision. It represents a fundamental trade-off: sacrificing some task-specific optimization for overall efficiency, robustness, and better generalization across a set of related problems.

Code Trace (PyTorch Example)
▼
import torch
import torch.nn as nn
class SharedBottomModel(nn.Module):
def __init__(self, input_dim, shared_dim, task_a_out_dim, task_b_out_dim):
super().__init__()
# Shared Bottom Network
self.shared_bottom = nn.Sequential(
nn.Linear(input_dim, shared_dim),
nn.ReLU(),
nn.Linear(shared_dim, shared_dim // 2),
nn.ReLU()
)
# Task A Specific Head
self.task_a_head = nn.Sequential(
nn.Linear(shared_dim // 2, shared_dim // 4),
nn.ReLU(),
nn.Linear(shared_dim // 4, task_a_out_dim)
)
# Task B Specific Head
self.task_b_head = nn.Sequential(
nn.Linear(shared_dim // 2, shared_dim // 4),
nn.ReLU(),
nn.Linear(shared_dim // 4, task_b_out_dim)
)
def forward(self, x):
shared_representation = self.shared_bottom(x) # shared features
output_a = self.task_a_head(shared_representation)
output_b = self.task_b_head(shared_representation)
return output_a, output_b
# Example Usage:
input_dim = 16
shared_dim = 64
task_a_out_dim = 1 # e.g., binary classification
task_b_out_dim = 10 # e.g., multi-class classification
model = SharedBottomModel(input_dim, shared_dim, task_a_out_dim, task_b_out_dim)
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
# Dummy data and labels
x_input = torch.randn(32, input_dim) # Batch of 32 inputs
y_a_true = torch.randint(0, 2, (32, task_a_out_dim)).float()
y_b_true = torch.randint(0, task_b_out_dim, (32,)).long()
# Forward pass
output_a, output_b = model(x_input)
# Calculate losses
loss_a = nn.BCEWithLogitsLoss()(output_a, y_a_true)
loss_b = nn.CrossEntropyLoss()(output_b, y_b_true)
# Combine losses with weights
lambda_a = 0.7
lambda_b = 0.3
total_loss = lambda_a * loss_a + lambda_b * loss_b
# Backward pass and optimization
optimizer.zero_grad()
total_loss.backward() # Gradients flow back to shared_bottom and heads
optimizer.step()
