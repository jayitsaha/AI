1
Understanding FLAVA
▼

What is it? FLAVA (Foundational Language And Vision Alignment, Singh et al., CVPR 2022) is a single transformer-based model that is good at image-only tasks, text-only tasks, AND joint image-text tasks — all from one set of weights. Most earlier models picked a lane: CLIP is great at aligning images and text but can't do BERT-style masked-language tasks well; BERT understands text but has never seen a pixel; ViLBERT/UNITER fuse image and text but can't be used as a standalone unimodal encoder.

Analogy: Think of FLAVA as a trilingual employee with three desks in one office: one desk only reads photographs (the image encoder), one desk only reads captions (the text encoder), and a third desk sits between them and cross-references what both desks reported (the multimodal encoder). All three desks were trained together, in the same building, on the same days — so their vocabularies stay compatible, unlike hiring three separate freelancers who never talk to each other.

💡 If you remember one thing

FLAVA jointly optimizes five losses over three transformer encoders — masked image modeling (MIM), masked language modeling (MLM), global image-text contrastive (GC), masked multimodal modeling (MMM), and image-text matching (ITM) — so a single checkpoint serves image-only, text-only, and multimodal downstream tasks without task-specific pretraining.

2
How FLAVA Works Internally
▼

Three Encoders

Image encoder is a ViT: the image is cut into non-overlapping patches, linearly projected, given a prepended [CLS_I] token and position embeddings, then run through a standard transformer stack. During pretraining, a random subset of patches is replaced by a learned [MASK] embedding (BEiT-style), and the target for each masked patch is a discrete visual token id produced offline by a frozen dVAE tokenizer.

Text encoder is a BERT-style transformer: the caption is tokenized (WordPiece/BPE), wrapped with [CLS_T]/[SEP], and a subset of tokens is replaced with [MASK] exactly like BERT's MLM.

Multimodal encoder takes the hidden states produced by the image and text encoders (each passed through its own linear projection so the two spaces are compatible), concatenates them into one sequence with learned modality-type embeddings, prepends a [CLS_MM] token, and runs a second transformer stack over the fused sequence so image tokens can attend to text tokens and vice versa.

Information Flow (Numerical Trace)

Concretely, for a 4-patch image with 2 patches masked and a 6-token caption with 1 token masked: (1) unimodal encoders each run self-attention over their own tokens producing 4-dim contextual vectors; (2) the masked positions' output vectors are fed to lightweight MIM/MLM classification heads over a visual/text vocabulary; (3) the two [CLS] vectors are projected + L2-normalized and scored against in-batch negatives for the contrastive loss; (4) both encoders' outputs are projected, concatenated, and re-encoded by the multimodal transformer; (5) the fused masked positions again predict their tokens (MMM) and the fused [CLS_MM] feeds a sigmoid match/no-match head (ITM). The interactive walkthrough below runs every one of these steps with real numbers.

🔑 Design Decision — Why Not Just CLIP + BERT Bolted Together?

Bolting a frozen CLIP image tower onto a frozen BERT gives you contrastive alignment but no way to do deep cross-attention reasoning (VQA, NLVR2) or to reconstruct masked content jointly. FLAVA instead trains all three encoders end-to-end from scratch on the same batches, so the unimodal representations are shaped from the start to be easy for the multimodal encoder to fuse — the losses regularize each other rather than being bolted on post-hoc.

3
Why It Works — The Five Objectives
▼

1 & 2 — Unimodal Reconstruction (MIM, MLM)

Both use masked-token cross-entropy. Let \(z_i\) be the encoder output at a masked position and \(W\) the head's weight matrix mapping to a vocabulary of size \(V\):

$$\mathcal{L}_{MIM} = -\frac{1}{|M_I|}\sum_{i \in M_I} \log \frac{\exp(W_{img} z_i)_{t_i}}{\sum_{v=1}^{V_{img}} \exp(W_{img} z_i)_v} \qquad \mathcal{L}_{MLM} = -\frac{1}{|M_T|}\sum_{j \in M_T} \log \frac{\exp(W_{txt} z_j)_{t_j}}{\sum_{v=1}^{V_{txt}} \exp(W_{txt} z_j)_v}$$

\(t_i\) is the ground-truth token id (a discrete dVAE visual code for images, a vocabulary id for text) and \(M_I, M_T\) are the sets of masked positions.

3 — Global Contrastive (GC)

Project and L2-normalize the two [CLS] embeddings, \(\hat h_I = h_I/\|h_I\|\), \(\hat h_T = h_T/\|h_T\|\), and treat matching pairs in the batch as positives against all other pairs as negatives (InfoNCE, temperature \(\tau\)):

$$\mathcal{L}_{GC} = -\frac{1}{2N}\sum_{k=1}^{N}\left[\log \frac{\exp(\hat h_I^{(k)}\cdot \hat h_T^{(k)}/\tau)}{\sum_{n=1}^N \exp(\hat h_I^{(k)}\cdot \hat h_T^{(n)}/\tau)} + \log \frac{\exp(\hat h_T^{(k)}\cdot \hat h_I^{(k)}/\tau)}{\sum_{n=1}^N \exp(\hat h_T^{(k)}\cdot \hat h_I^{(n)}/\tau)}\right]$$

4 — Masked Multimodal Modeling (MMM)

Identical cross-entropy form to MIM/MLM, but the classifier now reads off the fused multimodal encoder outputs \(z_i^{MM}\), so it must use context from the other modality to fill in masked patches/words:

$$\mathcal{L}_{MMM} = -\frac{1}{|M_I|+|M_T|}\left[\sum_{i \in M_I} \log p(t_i \mid z_i^{MM}) + \sum_{j \in M_T} \log p(t_j \mid z_j^{MM})\right]$$

5 — Image-Text Matching (ITM)

Binary classification on the fused [CLS_MM] vector \(z_{CLS}^{MM}\), with label \(y=1\) for a true pair and \(y=0\) for a hard-negative mismatched pair (mined from the GC similarity matrix):

$$\mathcal{L}_{ITM} = -\big[y\log\sigma(w_{itm}^\top z_{CLS}^{MM}) + (1-y)\log(1-\sigma(w_{itm}^\top z_{CLS}^{MM}))\big]$$

Combined Objective

$$\mathcal{L}_{FLAVA} = \mathcal{L}_{MIM} + \mathcal{L}_{MLM} + \lambda_{GC}\mathcal{L}_{GC} + \mathcal{L}_{MMM} + \mathcal{L}_{ITM}$$

A single backward pass on this sum updates the image encoder, text encoder, and multimodal encoder simultaneously — every gradient step nudges all three towards representations that are simultaneously good unimodal features AND easy to fuse.

⚠️ Common Pitfall

Because five losses live on very different scales (a 30k-way MLM softmax vs. a single sigmoid for ITM), naively summing them can let one loss dominate the gradient. FLAVA trains in two rounds-of-batches per step (unimodal-only batches for MIM/MLM/GC, and paired batches for MMM/ITM) and tunes loss weights so no single objective collapses the others — treat \(\lambda_{GC}\) (and implicit per-loss scaling) as a real hyperparameter, not a footnote.

Key Takeaways
▼

Why FLAVA vs. the alternatives:

ModelUnimodal imageUnimodal textMultimodal fusionRetrieval
CLIP✅ good⚠️ weak (no MLM)❌ none✅ excellent
ViLBERT / UNITER❌ needs region features✅ good✅ good⚠️ needs fusion pass
FLAVA✅ good✅ good✅ good✅ good

When to reach for a FLAVA-style design:

  • You need ONE checkpoint to cover image classification, text/NLU benchmarks, AND VQA/NLVR2-style multimodal reasoning
  • You can afford joint pretraining on paired + unpaired image/text corpora (unlike CLIP-only, which needs only pairs)
  • Downstream tasks benefit from deep cross-attention fusion, not just a dot-product similarity

When NOT to use it:

  • You only need fast image-text retrieval at scale — a CLIP-style dual encoder is cheaper to serve (no fusion pass needed)
  • You have no unpaired unimodal data — much of FLAVA's advantage comes from also training on text-only and image-only corpora
💡 Lineage

BERT (text MLM) + BEiT (image MIM) + CLIP (contrastive) + ViLBERT/UNITER (multimodal fusion + ITM) all get unified into FLAVA — one model, one training run, five losses, three encoders.

Code Trace
▼
import torch, torch.nn.functional as F
# --- three encoders, one shared model ---
h_I = image_encoder(mask_patches(image_patches)) # ViT tower
h_T = text_encoder(mask_tokens(caption_tokens)) # BERT tower
# --- 1) masked image modeling ---
logits_img = mim_head(h_I[masked_patch_idx]) # -> vocab_img
loss_mim = F.cross_entropy(logits_img, visual_token_targets)
# --- 2) masked language modeling ---
logits_txt = mlm_head(h_T[masked_token_idx]) # -> vocab_txt
loss_mlm = F.cross_entropy(logits_txt, word_id_targets)
# --- 3) global contrastive (CLIP-style, in-batch negatives) ---
z_I = F.normalize(proj_img(h_I[:, CLS]), dim=-1)
z_T = F.normalize(proj_txt(h_T[:, CLS]), dim=-1)
logits_gc = z_I @ z_T.T / tau
loss_gc = (F.cross_entropy(logits_gc, labels) + F.cross_entropy(logits_gc.T, labels)) / 2
# --- multimodal encoder fuses projected h_I, h_T ---
fused_in = torch.cat([proj_mm_i(h_I) + mod_embed_img,
proj_mm_t(h_T) + mod_embed_txt], dim=1)
h_MM = multimodal_encoder(fused_in)
# --- 4) masked multimodal modeling ---
loss_mmm = F.cross_entropy(mim_head(h_MM[img_mask_idx]), visual_token_targets) \
+ F.cross_entropy(mlm_head(h_MM[txt_mask_idx]), word_id_targets)
# --- 5) image-text matching (hard negatives from loss_gc similarities) ---
p_match = torch.sigmoid(itm_head(h_MM[:, CLS_MM]))
loss_itm = F.binary_cross_entropy(p_match, match_labels)
# --- one joint backward pass updates all three encoders ---
loss = loss_mim + loss_mlm + lambda_gc * loss_gc + loss_mmm + loss_itm
loss.backward(); optimizer.step()
