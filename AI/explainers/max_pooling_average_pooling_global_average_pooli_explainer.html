Max, Average & Global Average Pooling

Spatial downsampling operations in convolutional neural networks
Foundational Deep Learning CNNs O(k²·H·W) per layer
1
Understanding Pooling
▼

What is pooling? After a convolutional layer produces a feature map, pooling is a spatial downsampling operation that reduces the height and width of that map while retaining the most important information. Think of it as a lossy compression step that makes the network more computationally efficient, more robust to small spatial shifts, and less prone to overfitting.

Why do we need it? A raw feature map from an early convolutional layer might be 112×112 pixels with 64 channels. Without downsampling, the network would be enormous and every pixel's exact location would matter — but we usually want the network to be translation invariant: a cat in the top-left corner should be recognized just as well as a cat in the bottom-right. Pooling builds this invariance in.

Analogy: Imagine you're reading a newspaper from across the room. You can't see individual letters, but you can see the big headlines and whether there are photos. Pooling does the same thing — it discards fine-grained spatial detail while preserving the coarse structure (strong activations, average intensity) that matters for classification.

💡 Three flavors

Max pooling keeps the strongest activation in each window — great for detecting whether a feature is present anywhere in the region. Average pooling takes the mean — preserves overall intensity and is smoother. Global average pooling (GAP) collapses an entire feature map to a single number per channel — used at the end of modern CNNs to replace fully-connected layers.

Hyperparameters: All pooling operations share the same spatial hyperparameters as convolutions: a kernel size \(k\) (typically 2 or 3), a stride \(s\) (typically equal to \(k\) for non-overlapping), and optional padding. The output spatial size is \(\lfloor (H - k)/s \rfloor + 1\) for each dimension.

How Pooling Works Internally
▼

Max Pooling — Mechanism

A \(k \times k\) window slides over the input feature map with stride \(s\). At each position, the output is simply the maximum value among all \(k^2\) elements in the window. This is a non-parametric operation — there are no learned weights. The gradient during backpropagation flows only to the position that held the maximum (the "argmax"), and all other positions receive zero gradient. This is sometimes called the "switch" or "mask" in the backward pass.

Average Pooling — Mechanism

Identical sliding-window procedure, but the output is the arithmetic mean of all \(k^2\) values. During backpropagation, the gradient is distributed equally to all \(k^2\) positions (each receives \(1/k^2\) of the upstream gradient). Average pooling is differentiable everywhere, unlike max pooling which has a subgradient at ties.

Global Average Pooling (GAP) — Mechanism

GAP is a special case of average pooling where the kernel size equals the full spatial extent of the feature map. Given a feature map of shape \(H \times W \times C\), GAP produces a vector of length \(C\) by averaging each channel independently over all \(H \times W\) spatial positions. The output is a single number per channel — a global summary of "how much of this feature is present in the image overall."

🔑 Why GAP replaced fully-connected layers

Traditional CNNs (AlexNet, VGG) ended with 2–3 fully-connected layers with millions of parameters. GAP (introduced in NIN, popularized by GoogLeNet/ResNet) replaces this with a single averaging operation — zero extra parameters, built-in spatial averaging, and the output is interpretable as a class activation map when combined with a final linear classifier.

Overlap and Stride

When stride \(s < k\), windows overlap and the pooling is "overlapping pooling" (used in AlexNet). When \(s = k\), windows tile the input without overlap — the most common setting. Overlapping pooling provides slightly more spatial coverage but increases computation. With stride \(s=2\) and kernel \(k=2\), a feature map of size \(H \times W\) becomes \((H/2) \times (W/2)\), reducing spatial size by 4× and computation by 4×.

⚠️ Max pooling discards information

Max pooling throws away the exact location of the maximum within a window and discards all non-maximum values entirely. This is a feature (translation invariance) but also a bug — fine-grained spatial relationships are lost. Capsule networks and attention mechanisms were partly motivated by this limitation.

The Math — Why It Works
▼

Formal Definitions

Let \(\mathbf{X} \in \mathbb{R}^{H \times W}\) be a single-channel feature map. A pooling window at position \((i, j)\) covers the patch \(\mathcal{P}_{ij} = \{X_{i \cdot s + r,\; j \cdot s + c} : 0 \le r, c < k\}\) where \(s\) is the stride and \(k\) is the kernel size.

Max pooling output:

$$Y_{ij}^{\text{max}} = \max_{(r,c) \in [0,k)^2} X_{i \cdot s + r,\; j \cdot s + c}$$

Average pooling output:

$$Y_{ij}^{\text{avg}} = \frac{1}{k^2} \sum_{r=0}^{k-1} \sum_{c=0}^{k-1} X_{i \cdot s + r,\; j \cdot s + c}$$

Global average pooling (applied to a full \(H \times W\) feature map, producing a scalar per channel \(c\)):

$$\text{GAP}(\mathbf{X}^{(c)}) = \frac{1}{H \cdot W} \sum_{i=0}^{H-1} \sum_{j=0}^{W-1} X_{ij}^{(c)}$$

Output Size Formula

For an input of spatial size \(H\) with kernel \(k\), stride \(s\), and padding \(p\):

$$H_{\text{out}} = \left\lfloor \frac{H + 2p - k}{s} \right\rfloor + 1$$

For the common case \(k=2, s=2, p=0\): \(H_{\text{out}} = H/2\). For GAP: \(H_{\text{out}} = W_{\text{out}} = 1\) regardless of input size.

Backpropagation

Let \(\delta_{ij} = \partial \mathcal{L}/\partial Y_{ij}\) be the upstream gradient. For average pooling, the gradient distributes uniformly:

$$\frac{\partial \mathcal{L}}{\partial X_{i \cdot s+r,\; j \cdot s+c}} = \frac{\delta_{ij}}{k^2}$$

For max pooling, let \((r^*, c^*) = \arg\max \mathcal{P}_{ij}\). Then:

$$\frac{\partial \mathcal{L}}{\partial X_{i \cdot s+r,\; j \cdot s+c}} = \begin{cases} \delta_{ij} & \text{if } (r,c) = (r^*, c^*) \\ 0 & \text{otherwise} \end{cases}$$
📐 Translation Invariance

If a feature shifts by up to \(\lfloor k/2 \rfloor\) pixels within a pooling window, the max-pool output is unchanged (the maximum is still captured). This gives local translation invariance proportional to the pooling kernel size, which compounds across layers.

Key Takeaways
▼

When to use Max Pooling: Max pooling is the default choice in classification CNNs (VGG, AlexNet). It works best when you care about whether a feature is present anywhere in a region, not how much of it is present. The hard maximum is robust to noise — a single strong activation dominates.

When to use Average Pooling: Average pooling is preferred when the overall intensity or density of activations matters. It is smoother and more informative about the average response. Used in Inception modules and as a gentler downsampling alternative. Also used in the intermediate layers of some architectures when you want to preserve more spatial information.

When to use GAP: GAP is the modern replacement for fully-connected layers at the end of a CNN. It has zero parameters, is less prone to overfitting, and produces a vector that can be directly interpreted as class confidence scores when followed by a softmax. It also makes the network input-size agnostic — you can feed images of any resolution and still get a fixed-length output vector.

  • Max pool: translation invariant, sparse gradients, no parameters
  • Avg pool: smooth gradients, preserves average intensity, no parameters
  • GAP: collapses spatial dims entirely, zero params, enables Class Activation Maps (CAM)
  • All three: reduce spatial size, increase receptive field, reduce computation
💡 Modern trends

Many modern architectures (ResNet, EfficientNet, ViT) use strided convolutions instead of max pooling for downsampling — learned downsampling can be more expressive. However, GAP at the network's end remains nearly universal. Attention pooling (weighted average where weights are learned) is an emerging generalization.

⚠️ Receptive field grows with pooling

Each pooling layer doubles the effective receptive field of subsequent layers. A 3×3 conv after a 2×2 max pool sees a 6×6 region of the original input. This is a feature — deeper layers see larger context — but also means early layers must learn fine-grained features before pooling discards spatial resolution.

Code Trace
▼
import numpy as np
import torch, torch.nn as nn
# ── Input: single-channel 4×4 feature map ──
X = np.array([[3, 1, 2, 8],
[5, 9, 4, 2],
[7, 3, 6, 1],
[2, 8, 5, 4]], dtype=float)
# ── Max Pooling 2×2, stride 2 (NumPy from scratch) ──
k, s = 2, 2
H_out = (X.shape[0] - k) // s + 1 # = 2
max_out = np.zeros((H_out, H_out))
for i in range(H_out):
for j in range(H_out):
patch = X[i*s:i*s+k, j*s:j*s+k]
max_out[i, j] = patch.max()
# max_out = [[9, 8], [8, 6]]
# ── Average Pooling 2×2, stride 2 (NumPy) ──
avg_out = np.zeros((H_out, H_out))
for i in range(H_out):
for j in range(H_out):
patch = X[i*s:i*s+k, j*s:j*s+k]
avg_out[i, j] = patch.mean()
# avg_out = [[4.5, 4.25], [5.0, 4.0]]
# ── Global Average Pooling (NumPy) ──
gap_out = X.mean() # scalar: 4.6875
# ── PyTorch equivalents ──
t = torch.tensor(X).unsqueeze(0).unsqueeze(0).float()
max_pool = nn.MaxPool2d(kernel_size=2, stride=2)
avg_pool = nn.AvgPool2d(kernel_size=2, stride=2)
gap_layer = nn.AdaptiveAvgPool2d(output_size=(1, 1))
print(max_pool(t)) # [[[[9., 8.], [8., 6.]]]]
print(avg_pool(t)) # [[[[4.5, 4.25], [5.0, 4.0]]]]
print(gap_layer(t)) # [[[[4.6875]]]]
