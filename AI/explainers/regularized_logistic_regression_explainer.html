Understanding Regularized Logistic Regression
▼

What is it? Logistic regression fits a decision boundary between two classes by finding weights \(\mathbf{w}\) that make the sigmoid of \(\mathbf{w}^\top \mathbf{x}\) match the class probabilities. Left unconstrained, those weights can grow arbitrarily large — especially when the classes are perfectly separable — causing overconfident predictions and poor generalization. Regularization adds a penalty term to the loss that keeps the weights small.

Analogy: Imagine fitting a rubber band around two clusters of points. Without tension (no regularization), the band wraps tightly, memorizing every point. With tension (strong regularization), the band snaps to a simpler shape that generalizes better. The amount of tension is controlled by \(\lambda\) (equivalently, \(C = 1/\lambda\) in scikit-learn — larger C = less tension).

💡 If you remember one thing

Adding an L2 penalty shrinks all weights smoothly toward zero (good for multicollinearity and separability). L1 drives some weights exactly to zero, selecting features. Elastic net blends both. The hyperparameter \(C = 1/\lambda\) controls boundary complexity — small C → simpler boundary.

How Regularization Works Internally
▼

The Unregularized Objective

Standard logistic regression minimizes the binary cross-entropy (negative log-likelihood):

$$\mathcal{L}(\mathbf{w}) = -\frac{1}{n}\sum_{i=1}^n \left[ y_i \log \sigma(\mathbf{w}^\top \mathbf{x}_i) + (1-y_i)\log(1-\sigma(\mathbf{w}^\top \mathbf{x}_i)) \right]$$

where \(\sigma(z) = 1/(1+e^{-z})\) is the sigmoid. When classes are linearly separable, this loss reaches zero only as \(\|\mathbf{w}\| \to \infty\), so gradient descent drives weights to blow up.

L2 Regularization (Ridge)

Append the squared \(\ell_2\) norm of the weights (excluding bias \(b\)):

$$\mathcal{L}_{L2}(\mathbf{w}) = \mathcal{L}(\mathbf{w}) + \frac{\lambda}{2}\|\mathbf{w}\|_2^2$$

The gradient becomes \(\nabla_{\mathbf{w}} \mathcal{L}_{L2} = \nabla_{\mathbf{w}} \mathcal{L} + \lambda \mathbf{w}\). L2 shrinks all coefficients proportionally — larger weights get penalized more. It never zeroes them out but controls collinearity gracefully because no single coordinate is preferred.

L1 Regularization (Lasso)

$$\mathcal{L}_{L1}(\mathbf{w}) = \mathcal{L}(\mathbf{w}) + \lambda\|\mathbf{w}\|_1 = \mathcal{L}(\mathbf{w}) + \lambda\sum_{j=1}^{d}|w_j|$$

The subgradient w.r.t. \(w_j\) is \(\partial \mathcal{L} / \partial w_j + \lambda \operatorname{sign}(w_j)\). Crucially, for a weight to remain non-zero the log-likelihood gradient must overcome the full \(\lambda\) barrier — small, unimportant weights get pushed to exactly zero. L1 thus performs automatic feature selection.

Elastic Net

$$\mathcal{L}_{EN}(\mathbf{w}) = \mathcal{L}(\mathbf{w}) + \lambda\left[\rho\|\mathbf{w}\|_1 + \frac{(1-\rho)}{2}\|\mathbf{w}\|_2^2\right]$$

where \(\rho \in [0,1]\) is the L1 ratio. Setting \(\rho=0\) recovers L2, \(\rho=1\) recovers L1. Elastic net is preferred when features are correlated: L1 arbitrarily picks one from a correlated group, while L2 shares weight evenly. Elastic net encourages a sparse group selection.

🔑 Why L1 Is Sparse but L2 Is Not

Geometrically, the L1 ball is a diamond (corners on axes) and the L2 ball is a sphere. The loss contours hit the L1 ball at a corner — where a coordinate is exactly zero. They hit the L2 ball on a smooth surface — nowhere is exactly zero. This is the fundamental geometric reason for L1 sparsity.

⚠️ Bias Term Convention

The bias (intercept) is never regularized — it just shifts the decision boundary and does not cause overfitting. Both sklearn and the math convention exclude it from the penalty. Always confirm your framework's default.

The Math — Objectives, Gradients, Geometry
▼

L2 Gradient and Update Rule

For a single training example \((\mathbf{x}_i, y_i)\), the L2-regularized gradient per weight \(w_j\) is:

$$\frac{\partial \mathcal{L}_{L2}}{\partial w_j} = \frac{1}{n}\sum_{i=1}^n (\sigma(\mathbf{w}^\top\mathbf{x}_i) - y_i) \, x_{ij} + \lambda w_j$$

Gradient descent update: \(w_j \leftarrow w_j - \eta \left[\text{data gradient} + \lambda w_j\right] = w_j(1 - \eta\lambda) - \eta \cdot \text{data gradient}\). The factor \((1-\eta\lambda)\) is called weight decay — the weight shrinks by a multiplicative factor each step regardless of the data gradient.

L1 Subgradient and Soft-Thresholding

The L1 penalty is non-differentiable at zero. The proximal operator for L1 is soft-thresholding:

$$\text{prox}_{\lambda}(w_j) = \operatorname{sign}(w_j)\max(|w_j|-\lambda, 0)$$

This is used in proximal gradient methods. If the full gradient step yields \(w_j^*\), the proximal step sets \(w_j = \text{prox}_\lambda(w_j^*)\): weights with magnitude \(\leq \lambda\) snap to zero exactly.

Bayesian Interpretation

Regularized logistic regression is equivalent to maximum a posteriori (MAP) estimation:

  • L2 ↔ Gaussian prior: \(p(\mathbf{w}) = \mathcal{N}(0, \sigma^2 I)\), with \(\lambda = 1/(2\sigma^2)\)
  • L1 ↔ Laplace prior: \(p(w_j) = \frac{\lambda}{2}e^{-\lambda|w_j|}\)
  • Elastic net ↔ mixture of Gaussian and Laplace priors
$$\hat{\mathbf{w}}_{MAP} = \underset{\mathbf{w}}{\arg\max}\; \log p(\mathbf{y}|\mathbf{w}, X) + \log p(\mathbf{w}) = \underset{\mathbf{w}}{\arg\min}\; \mathcal{L}(\mathbf{w}) + \text{penalty}(\mathbf{w})$$

The Separability Problem — Why Regularization is Essential

If the two classes are linearly separable, the maximum likelihood solution does not exist: as \(\|\mathbf{w}\|\to\infty\), the log-likelihood increases monotonically to 0 while predicted probabilities approach 0 or 1. The model can assign perfect probability without error — the optimizer diverges. Adding any regularization creates a proper minimum and prevents this divergence.

📐 Key Formulas

L2 loss (sklearn convention, C = 1/λ):

\(\mathcal{L}_{L2} = C \cdot \mathcal{L}_{CE} + \tfrac{1}{2}\|\mathbf{w}\|_2^2\)

L1 loss:

\(\mathcal{L}_{L1} = C \cdot \mathcal{L}_{CE} + \|\mathbf{w}\|_1\)

Elastic net (sklearn, l1_ratio=ρ):

\(\mathcal{L}_{EN} = C \cdot \mathcal{L}_{CE} + \rho\|\mathbf{w}\|_1 + \tfrac{(1-\rho)}{2}\|\mathbf{w}\|_2^2\)

⚠️ sklearn's C Convention is Inverted

sklearn's LogisticRegression(C=...) uses \(C = 1/\lambda\): larger C = less regularization. This is the opposite of most textbook notation. Always double-check: if accuracy is near 50%, C is too small. If weights are enormous, C is too large.

From Scratch — NumPy Gradient Descent

import numpy as np
def sigmoid(z):
z = np.clip(z, -500, 500) # prevent overflow
return 1.0 / (1.0 + np.exp(-z))
def log_loss(w, b, X, y):
p = sigmoid(X @ w + b)
p = np.clip(p, 1e-12, 1-1e-12)
return -np.mean(y * np.log(p) + (1-y) * np.log(1-p))
def regularized_logistic(X, y, lam=1.0, penalty='l2',
l1_ratio=0.5, lr=0.05, epochs=2000):
"""Regularized logistic regression via gradient descent.
penalty: 'l2' | 'l1' | 'elasticnet'
lam: regularization strength (C = 1/lam in sklearn)
"""
n, d = X.shape
w = np.zeros(d) # feature weights
b = 0.0 # bias — never regularized
for _ in range(epochs):
p = sigmoid(X @ w + b) # probabilities, shape (n,)
err = p - y # residuals
dw = X.T @ err / n # data gradient
db = err.mean() # bias gradient
# Penalty gradient
if penalty == 'l2':
dw += lam * w # weight decay term
elif penalty == 'l1':
dw += lam * np.sign(w) # subgradient
elif penalty == 'elasticnet':
dw += lam * (l1_ratio * np.sign(w) + (1-l1_ratio) * w)
w -= lr * dw
b -= lr * db
return w, b
# Example: 2D toy data
np.random.seed(42)
X_pos = np.random.randn(20, 2) + [1.5, 1.5]
X_neg = np.random.randn(20, 2) - [1.5, 1.5]
X = np.vstack([X_pos, X_neg])
y = np.array([1]*20 + [0]*20, dtype=float)
w_l2, b_l2 = regularized_logistic(X, y, lam=1.0, penalty='l2')
w_l1, b_l1 = regularized_logistic(X, y, lam=1.0, penalty='l1')
w_en, b_en = regularized_logistic(X, y, lam=1.0, penalty='elasticnet')
print(f'L2 w={w_l2.round(3)} ||w||2={np.linalg.norm(w_l2):.3f}')
print(f'L1 w={w_l1.round(3)} ||w||1={np.abs(w_l1).sum():.3f}')
print(f'EN w={w_en.round(3)}')

Production Usage — scikit-learn

from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
# CRITICAL: Always scale features before regularization!
# Regularization penalizes large weights — raw features on different
# scales give unfair penalties to large-valued features.
pipe = Pipeline([
('scaler', StandardScaler()),
('clf', LogisticRegression(
penalty='l2', # 'l1', 'l2', 'elasticnet', None
C=1.0, # C = 1/lambda; default=1.0
solver='lbfgs', # 'liblinear' for L1; 'saga' for elasticnet
l1_ratio=None, # only for elasticnet; set 0..1
max_iter=1000, # increase if ConvergenceWarning
fit_intercept=True, # bias NOT regularized
class_weight='balanced', # useful for imbalanced data
))
])
# Tune C via cross-validation (log scale)
param_grid = {'clf__C': [0.001, 0.01, 0.1, 1, 10, 100]}
gs = GridSearchCV(pipe, param_grid, cv=5, scoring='roc_auc')

🎯 Decision Guide

Use L2 when: you believe most features contribute, features are correlated, or you need reliable standard errors.

Use L1 when: you have many irrelevant features (high-dimensional), you want interpretable sparse models.

Use Elastic Net when: features are correlated in groups (gene expression, NLP), you want sparsity but L1 is too unstable.
