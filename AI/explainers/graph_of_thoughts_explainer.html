1
Understanding Graph of Thoughts
▼

What is it? Graph of Thoughts (GoT) is a prompting paradigm that extends Chain-of-Thought (CoT) and Tree-of-Thought (ToT) by allowing LLMs to organize their reasoning steps into arbitrary computational graphs. Each node in the graph represents a "thought" (an intermediate output from the LLM), and edges represent dependencies or transformations. This enables non-linear reasoning, dynamic exploration, self-correction, and iterative refinement, moving beyond simple linear sequences or fixed tree structures.

Analogy: Imagine solving a complex problem not with a rigid checklist (Chain-of-Thought) or a fixed decision tree (Tree-of-Thought), but with a dynamic whiteboard. You can brainstorm multiple ideas in parallel (branching), combine insights from different approaches (merging), cross out unpromising paths (pruning), and refine existing ideas (transformation) as new information or better strategies emerge. This flexible, adaptive approach is what GoT brings to LLM orchestration.

💡 If you remember one thing

GoT formalizes LLM orchestration by treating intermediate thoughts as nodes in a dynamic graph. This graph can be generated, evaluated, pruned, and merged, allowing for complex, adaptive problem-solving that surpasses the limitations of linear or tree-structured prompting methods.

2
How GoT Works Internally
▼

Core Operations: Generate, Evaluate, Transform, Aggregate

GoT's power comes from a set of fundamental operations, each typically implemented by an LLM call with a specific prompt:

  1. Thought Generation: An LLM generates new thoughts (nodes) based on a current thought or a set of thoughts (e.g., brainstorming ideas, proposing next steps).
  2. Thought Evaluation: An LLM assesses the quality, relevance, or utility of a thought, often returning a numerical score or a categorical judgment.
  3. Thought Transformation/Refinement: An LLM refines, corrects, or expands upon an existing thought to improve its quality or detail.
  4. Thought Aggregation/Merging: An LLM combines multiple thoughts into a single, more comprehensive or synthesized thought.

These operations are orchestrated to dynamically build and modify the graph structure, allowing for complex control flow like branching, merging, and pruning.

Comparison to Other Prompting Paradigms

  • Chain-of-Thought (CoT): A linear sequence of intermediate reasoning steps. Simple and effective for many tasks, but rigid.
  • Tree-of-Thought (ToT): Extends CoT to a tree structure, allowing for branching exploration (e.g., BFS or DFS search). Better for tasks requiring exploration of multiple paths, but still limited to tree topology.
  • Graph of Thoughts (GoT): The most general paradigm. Allows arbitrary graph structures, including cycles, dynamic creation/deletion of nodes/edges, and re-evaluation. This flexibility enables truly non-linear problem-solving strategies like dynamic programming or iterative refinement.

Design Decision: Why a Graph?

The graph structure is crucial because many real-world complex problems are inherently non-linear. A graph allows the LLM agent to:

  • Branch: Explore multiple hypotheses or sub-problems in parallel.
  • Merge: Combine insights from different branches to form a stronger solution.
  • Prune: Discard unpromising lines of reasoning early based on evaluation, saving computational resources.
  • Backtrack/Re-evaluate: Revisit and refine earlier thoughts if a current path proves unfruitful or new information emerges.

This dynamic adaptation and self-correction capability is what sets GoT apart for truly hard reasoning tasks.

🔑 Key Property

GoT formalizes LLM reasoning as graph traversal and manipulation. It enables dynamic and adaptive problem-solving by treating thoughts as manipulable nodes in a graph, offering a powerful abstraction for complex tasks that go beyond sequential or tree-like prompt structures.

3
Why It Works — The Formalism
▼

Formalizing Thoughts and Operations

A "thought" \(T_i\) can be represented as a state, typically a text string, but potentially augmented with embeddings or other metadata. The Graph of Thoughts is a directed graph \(G = (V, E)\), where \(V\) is a set of thought nodes and \(E\) is a set of directed edges representing transitions or dependencies between thoughts.

The core operations can be mathematically expressed as functions applied by an LLM:

$$ \begin{aligned} \text{Generate: } & T_{\text{new}} = \mathcal{G}(\text{prompt}, T_{\text{current}}) \\ \text{Evaluate: } & S_i = \mathcal{E}(\text{scorer\_prompt}, T_i) \in [0,1] \\ \text{Transform: } & T'_{i} = \mathcal{F}(\text{refine\_prompt}, T_i) \\ \text{Aggregate: } & T_{\text{merged}} = \mathcal{A}(\text{merge\_prompt}, T_a, T_b, \dots) \end{aligned} $$

Here, \(\mathcal{G}, \mathcal{E}, \mathcal{F}, \mathcal{A}\) represent calls to the LLM with specific instructions. The prompts guide the LLM to perform the desired reasoning step. The overall goal is often to find a path through the graph that leads to a high-quality final solution, or to iteratively refine a solution until it meets specific criteria.

Graph Traversal and Optimization

The process can be seen as a search problem on the dynamically constructed graph. Various search algorithms (e.g., A*, BFS, DFS) can be adapted, guided by the evaluation scores \(S_i\). For example, a simple greedy approach might always expand the highest-scoring unexpanded thought. The total cost is proportional to the number of LLM calls, making efficient pruning and effective evaluation crucial.

The implicit objective function is to maximize the quality of the final thought, often expressed as a score or adherence to constraints. This is achieved by iteratively improving the graph:

$$ \max_{T_{\text{final}} \in V} \mathcal{E}(\text{final\_scorer}, T_{\text{final}}) \quad \text{subject to } T_{\text{final}} \text{ being a valid solution} $$

The dynamic nature means the graph structure itself is part of the optimization process, not fixed beforehand.

⚠️ Common Pitfall

The computational cost of GoT can be significantly higher than simpler prompting methods due to numerous LLM calls. Each generation, evaluation, or transformation step incurs latency and token usage. Without robust, carefully engineered prompts for evaluation and transformation, the LLM can get stuck in unproductive loops, generate low-quality thoughts, or fail to converge to a solution, leading to wasted resources and poor outcomes.

Key Takeaways
▼

When to use Graph of Thoughts:

  • For complex, multi-step reasoning tasks that benefit from non-linear exploration, such as scientific discovery, legal analysis, or advanced code generation.
  • When problems require iterative refinement, self-correction, or parallel exploration of multiple hypotheses.
  • When simpler methods like Chain-of-Thought or Tree-of-Thought prove insufficient due to their structural limitations.
  • In scenarios where the cost of a wrong answer or suboptimal solution outweighs the computational expense of more LLM calls.

When NOT to use:

  • For straightforward tasks where a simple CoT prompt yields good results — the overhead of GoT is unnecessary.
  • In highly cost-sensitive environments where LLM calls are expensive and budget is a primary constraint.
  • Without robust and well-calibrated LLM prompts for generation, evaluation, and transformation steps, which can lead to inefficient exploration, poor-quality thoughts, or failure to converge.
  • When the problem space is extremely large and unstructured, potentially leading to an unmanageable graph size.
💡 Big Picture

GoT is a meta-prompting strategy that elevates LLMs from text generators to dynamic graph processors. Its strength lies in its flexible topology, enabling sophisticated reasoning patterns. However, its effectiveness hinges on precise control over graph operations and judicious management of its inherently higher computational demands.

import uuid
class Thought:
def __init__(self, content, score=None, status="initial"):
self.id = str(uuid.uuid4())[:8]
self.content = content
self.score = score
self.status = status # e.g., "initial", "generated", "evaluated", "pruned", "transformed", "merged", "final"
self.parents = []
self.children = []
class GraphOfThoughts:
def __init__(self, llm_client):
self.nodes = {} # id -> Thought object
self.llm = llm_client
def add_thought(self, content, parent_ids=None, score=None, status="generated"):
new_thought = Thought(content, score, status)
self.nodes[new_thought.id] = new_thought
if parent_ids:
for p_id in parent_ids:
if p_id in self.nodes:
self.nodes[p_id].children.append(new_thought.id)
new_thought.parents.append(p_id)
return new_thought
def generate_thoughts(self, current_thought_ids, prompt_template, num_thoughts=1):
input_contents = [self.nodes[tid].content for tid in current_thought_ids]
combined_input = "\n".join(input_contents)
full_prompt = prompt_template.format(input=combined_input)
llm_output = self.llm.generate(full_prompt, num_completions=num_thoughts)
new_thoughts = []
for output_text in llm_output:
new_thoughts.append(self.add_thought(output_text, current_thought_ids, status="generated"))
return new_thoughts
def evaluate_thoughts(self, thought_ids, scorer_prompt_template):
for t_id in thought_ids:
thought = self.nodes[t_id]
full_prompt = scorer_prompt_template.format(thought=thought.content)
score_str = self.llm.generate(full_prompt) # LLM returns a score (e.g., "Score: 0.75")
thought.score = float(score_str.split(":")[-1].strip()) # Parse score
thought.status = "evaluated"
def prune_thoughts(self, thought_ids, min_score_threshold):
pruned_ids = []
for t_id in thought_ids:
thought = self.nodes[t_id]
if thought.score is not None and thought.score < min_score_threshold:
thought.status = "pruned"
pruned_ids.append(t_id)
return pruned_ids
def transform_thought(self, thought_id, refine_prompt_template):
thought = self.nodes[thought_id]
full_prompt = refine_prompt_template.format(thought=thought.content)
refined_content = self.llm.generate(full_prompt)
new_thought = self.add_thought(refined_content, [thought_id], status="transformed")
return new_thought
def merge_thoughts(self, thought_ids, merge_prompt_template):
input_contents = [self.nodes[tid].content for tid in thought_ids]
combined_input = "\n".join(input_contents)
full_prompt = merge_prompt_template.format(thoughts=combined_input)
merged_content = self.llm.generate(full_prompt)
new_thought = self.add_thought(merged_content, thought_ids, score=None, status="merged")
return new_thought
