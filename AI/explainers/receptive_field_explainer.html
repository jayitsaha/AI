Receptive Field

How much of the input does one output neuron actually "see"?
Foundational CNN / Computer Vision O(L) recurrence
1
Understanding Receptive Field
▼

What is it? Every neuron in a convolutional network's output only "looks at" a limited patch of the original input — never the whole image. That patch is the neuron's receptive field (RF): the region of input pixels that can, through the chain of convolutions and pooling, influence that single output value. Stack more layers and the patch grows, because each new layer folds in a slightly wider neighborhood of the layer beneath it.

Analogy: Imagine looking at a courtyard through a stack of frosted windows, one behind the other. Standing at the last window you can't see the whole courtyard directly — but light scattered from a wide area of the courtyard has bounced through every window to reach your eye. Add another window behind you (another conv layer) and the area of courtyard that can possibly influence what you see grows a little more, even though you never moved.

💡 If you remember one thing

Receptive field grows layer by layer through the recurrence $$RF_l = RF_{l-1} + (K_l - 1)\cdot j_{l-1}, \qquad j_l = j_{l-1}\cdot S_l$$ where \(K_l\) is kernel size, \(S_l\) is stride, and \(j_l\) ("jump") is the cumulative stride of all layers so far. Strided layers don't just shrink the map — they make every later layer's kernel cover exponentially more original pixels.

How Receptive Field Grows Internally
▼

One Layer at a Time

A single convolution with kernel size \(K\) and stride \(S=1\) lets an output unit see \(K\) input positions in each dimension. If we stack a second identical layer on top, the second layer's output unit sees \(K\) positions of the first layer's output — but each of those positions already covers \(K\) input pixels, and neighboring positions overlap. The combined span is \(K + (K-1) = 2K - 1\), not \(2K\), because adjacent receptive fields share pixels.

Why Stride Matters More Than Depth Alone

Stride doesn't just downsample the feature map — it rescales the "step size" that every subsequent layer's kernel takes in input-pixel units. This step size is the jump \(j_l\): after a stride-2 layer, moving one unit in the new feature map corresponds to moving 2 pixels in the original input. Any kernel applied after that stride effectively spans twice as many input pixels per kernel-tap as it would without the stride. This is why downsampling (via strided conv or pooling) is the cheapest way to grow receptive field fast — it's multiplicative, while adding stride-1 layers is only additive.

Numerical Trace

Take a 4-layer stack: conv3×3/s1 → conv3×3/s1 → conv3×3/s2 → conv3×3/s1, starting from \(RF_0=1,\ j_0=1\):

  • Layer 1 (K=3,S=1): \(RF_1 = 1+(3-1)\cdot1=3\), \(j_1=1\cdot1=1\)
  • Layer 2 (K=3,S=1): \(RF_2 = 3+(3-1)\cdot1=5\), \(j_2=1\)
  • Layer 3 (K=3,S=2): \(RF_3 = 5+(3-1)\cdot1=7\), \(j_3=1\cdot2=2\)
  • Layer 4 (K=3,S=1): \(RF_4 = 7+(3-1)\cdot2=11\), \(j_4=2\)

Notice layer 4 adds 4 pixels of RF from a 3×3 kernel — double what layer 1 or 2 added — purely because the jump doubled after the stride-2 layer.

Design Decision: Dilation as a "Free" Stride

Dilated (atrous) convolutions insert gaps between kernel taps, giving an effective kernel size \(K_{eff} = (K-1)\cdot D + 1\) for dilation rate \(D\) — this plugs directly into the same recurrence in place of \(K\). Dilation grows RF exponentially (dilation rates 1,2,4,8,...) without shrinking the feature map or adding parameters, which is why it's the backbone of architectures like WaveNet and DeepLab that need wide context at full resolution.

🔑 Key Property

Receptive field size depends only on the sequence of \((K_l, S_l, D_l)\) per layer — not on the learned weights. It's a purely geometric/architectural property, computable before any training happens.

3
Why It Works — The Math
▼

Deriving the Recurrence

Let \(RF_l\) be the receptive field (in input pixels) of a unit in the output of layer \(l\), and \(j_l\) be the "jump" — the distance, in input pixels, between two horizontally/vertically adjacent units in layer \(l\)'s output. Layer \(l\) has kernel size \(K_l\) and stride \(S_l\). A unit at layer \(l\) reads \(K_l\) adjacent units from layer \(l-1\), each spaced \(j_{l-1}\) input-pixels apart:

$$RF_l = RF_{l-1} + (K_l - 1)\cdot j_{l-1}$$

and the spacing between output units compounds multiplicatively with each stride:

$$j_l = j_{l-1}\cdot S_l, \qquad RF_0 = 1,\ \ j_0 = 1$$

Unrolling the recurrence gives a closed form:

$$RF_L = 1 + \sum_{l=1}^{L}(K_l-1)\prod_{i=0}^{l-1}S_i$$

The product term is exactly why strides early in the network are so powerful for growing RF: a stride applied at layer 2 multiplies the contribution of every subsequent layer's kernel, whereas a stride at the last layer barely matters.

Theoretical vs. Effective Receptive Field

The formula above gives the theoretical RF — the maximal set of input pixels that could possibly affect the output through some path of nonzero weights. Luo et al. (2016, "Understanding the Effective Receptive Field") showed that the actual effective RF (weighted by gradient magnitude) is much smaller and looks approximately Gaussian, concentrated near the center, and grows only as \(O(\sqrt{L})\) rather than \(O(L)\) with depth — because contributions from pixels near the theoretical boundary are reachable via exponentially fewer weight-paths than central pixels.

⚠️ Common Pitfall

A large theoretical RF does not guarantee the network actually uses that full context. Segmentation/detection models can silently underperform on large objects because the effective RF, despite a huge theoretical one, is concentrated near the center — the fix is architectural (dilated convs, attention, or residual connections that flatten the effective-RF distribution), not just "add more layers."

Key Takeaways
▼

Ways to grow receptive field (cheapest → most expensive):

  • Add stride or pooling — multiplies the jump, compounds for every later layer
  • Use dilated convolutions — exponential RF growth, no resolution loss, no extra params
  • Use larger kernels — additive growth per layer, more parameters
  • Stack more stride-1 layers — additive growth, cheapest per-layer but slowest
  • Global attention / pooling — instant RF = entire input, at O(n²) or O(n) cost

Where RF size actually matters: semantic segmentation and detection need RF ≥ the largest object in the image; a network whose theoretical RF is smaller than an object literally cannot classify pixels of that object correctly, no matter how it's trained.

💡 Rule of Thumb

Always compute RF before training, not after debugging a mysteriously underperforming model. If \(RF_L\) at your final feature map is smaller than the objects you care about, no amount of extra training data fixes it — you need architectural changes (stride, dilation, depth, or attention).

Code Trace
▼
# layers: list of (kernel, stride, dilation)
layers = [
(3, 1, 1), (3, 1, 1), (3, 2, 1),
(3, 1, 1), (3, 2, 1), (3, 1, 1), (3, 1, 2),
]
def receptive_field(layers):
rf, jump = 1, 1 # RF_0 = 1, jump_0 = 1
trace = [(rf, jump)]
for k, s, d in layers:
k_eff = (k - 1) * d + 1 # dilation-adjusted kernel
rf = rf + (k_eff - 1) * jump # grow RF by one kernel's reach
jump = jump * s # stride compounds the jump
trace.append((rf, jump))
return trace
for i, (rf, jump) in enumerate(receptive_field(layers)):
print(f"after layer {i}: RF={rf:>3} jump={jump}")
# after layer 0: RF= 1 jump=1 (raw input)
# after layer 7: RF= 39 jump=4 (final feature map unit)
