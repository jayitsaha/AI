1
Understanding Global Interpretability
▼

What is it? Global interpretability aims to explain the overall behavior of a machine learning model across its entire dataset, rather than focusing on individual predictions. It answers questions like: "Which features are most important to the model?", "How does changing a feature's value, on average, affect the model's prediction?", or "Are there interactions between features?" This is crucial for understanding model biases, validating its logic, and building trust.

Analogy: Imagine a complex expert system that predicts house prices. Local interpretability is asking, "Why did *this specific* house get *this specific* price?" Global interpretability is asking, "In general, what's the most important factor in house prices for this system: size, age, or location? And how much does price typically go up for every extra square foot, across all houses?"

💡 If you remember one thing

Global interpretability methods like Feature Importance (which features matter most) and Partial Dependence Plots (PDPs) (how a feature affects predictions on average) help us understand the model's learned function \(f(x)\) as a whole, rather than just explaining a single prediction.

How It Works: Feature Importance & PDPs
▼

Permutation Feature Importance (PFI)

PFI (Breiman, 2001, later refined by Fisher et al., 2018) measures how much a model's prediction error increases when the values of a single feature are randomly shuffled. If shuffling a feature significantly increases the error, that feature is important. If the error barely changes, the feature is not important. This method is model-agnostic (works for any model) and dataset-agnostic (works for any dataset).

The algorithm for PFI is:

  1. Train a model \(f\) and calculate a baseline error \(e_{base}\) on a validation set.
  2. For each feature \(j\):
    1. Create a copy of the validation set.
    2. Randomly shuffle the values of feature \(j\) in this copy.
    3. Calculate the model's error \(e_j\) on this shuffled dataset.
  3. The importance of feature \(j\) is \(e_j - e_{base}\) (or \(e_j / e_{base}\)).

Partial Dependence Plots (PDPs)

A PDP shows the marginal effect of one or two features on the predicted outcome of a trained model. It visualizes how the prediction changes when a feature's value varies, while accounting for the average effect of all other features. This helps to visualize whether the relationship between the target feature and the prediction is linear, monotonic, or more complex.

The algorithm for a 1-way PDP for a feature \(x_S\) (where \(S\) is the subset of features we are interested in, and \(C\) are the complement features):

  1. Select a feature \(x_S\) for which to plot the partial dependence.
  2. Define a grid of values for \(x_S\) (e.g., min to max, or quantiles).
  3. For each grid value \(v\) of \(x_S\):
    1. For every instance \(x^{(i)}\) in the dataset, create a new instance where \(x_S\) is set to \(v\), and \(x_C\) retains its original values: \((v, x_C^{(i)})\).
    2. Predict the outcome for all these modified instances using the model \(f\).
    3. Average these predictions: \(\hat{f}_S(v) = \frac{1}{N} \sum_{i=1}^N f(v, x_C^{(i)})\).
  4. Plot the averaged predictions \(\hat{f}_S(v)\) against the grid values \(v\).
🔑 Key Property

Both PFI and PDPs are model-agnostic. They treat the model as a black box, only requiring access to its prediction function. This makes them highly versatile for understanding complex models like deep neural networks or ensemble methods.

3
Why It Works — The Math
▼

Partial Dependence Function

The partial dependence function for a subset of features \(x_S\) is defined as:

$$\hat{f}_S(x_S) = \mathbb{E}_{x_C}\left[f(x_S, x_C)\right]$$

where \(x_S\) are the features for which we want to plot the partial dependence, and \(x_C\) are the other features (complement). The expectation \(\mathbb{E}_{x_C}\) means we average the model's predictions over the marginal distribution of the features in \(x_C\).

In practice, since we usually don't know the true marginal distribution of \(x_C\), we approximate the expectation using the empirical distribution of \(x_C\) from our training (or a representative) dataset. For a dataset with \(N\) instances \(\{x^{(1)}, \dots, x^{(N)}\}\), the empirical partial dependence function is:

$$\hat{f}_{S}(x_S) = \frac{1}{N} \sum_{i=1}^N f(x_S, x_{C}^{(i)})$$

This formula is what's used in the algorithm: for a fixed value of \(x_S\), we iterate through all data points, replace their \(x_S\) values with the fixed one, make a prediction, and then average these predictions.

Impact of Feature Interactions

PDPs work best when the features in \(x_S\) do not strongly interact with the features in \(x_C\). If there are strong interactions, the average effect shown by a PDP might obscure important conditional relationships. For example, if "square footage" has a positive effect on price for new houses but a negative effect for very old houses, a single 1-way PDP for "square footage" (averaging over "age") might show a flat line, hiding the true conditional effects. This is where 2-way PDPs (plotting two features simultaneously) or Individual Conditional Expectation (ICE) plots can be more informative.

⚠️ Common Pitfall

PDPs can create "unrealistic" data points. When we fix \(x_S\) to a grid value and combine it with \(x_C\) from observed data, we might create combinations that never occur in reality (e.g., a 500 sq ft mansion). If the model extrapolates poorly to such regions, the PDP will be misleading. Always consider the feature distribution when interpreting PDPs.

Key Takeaways
▼

When to use Feature Importance & PDPs:

  • When you need to understand the overall behavior of a complex "black-box" model (e.g., deep neural networks, gradient boosting).
  • To identify which features drive predictions the most (Feature Importance).
  • To visualize the average directional relationship between a feature and the prediction (PDPs).
  • For model debugging, identifying unexpected relationships, or confirming domain knowledge.
  • To communicate model insights to non-technical stakeholders.

When to be cautious or use alternatives:

  • Highly correlated features: PFI can give misleading results if features are highly correlated. Shuffling one feature might create unrealistic data points that the model has never seen. PDPs also suffer here.
  • Strong interactions: A 1-way PDP averages out interactions, potentially hiding complex conditional effects. Consider 2-way PDPs or ICE plots for deeper insights into interactions.
  • Extrapolation: PDPs can show model behavior in regions of the feature space that are sparse in the training data, leading to unreliable interpretations if the model extrapolates poorly.
  • Local explanations: For explaining individual predictions, methods like SHAP or LIME are more appropriate.
💡 Complementary Tools

Global interpretability methods complement local ones. PDPs show the "general rule," while local methods explain "why this specific exception happened." Using both provides a comprehensive understanding of your model.

Code Trace (Scikit-learn)
▼
import numpy as np
from sklearn.ensemble import RandomForestRegressor
from sklearn.inspection import permutation_importance, PartialDependenceDisplay
import matplotlib.pyplot as plt
# 1. Generate synthetic data
np.random.seed(42)
sq_ft = np.random.uniform(1000, 3000, 200)
age = np.random.uniform(0, 50, 200)
# True price function with interaction
true_price = 100 + 0.15 * sq_ft - 2 * age + 0.0001 * sq_ft * age + np.random.normal(0, 20, 200)
X = np.column_stack([sq_ft, age])
y = true_price
feature_names = ['Square Footage', 'Age']
# 2. Train a black-box model
model = RandomForestRegressor(n_estimators=50, random_state=42)
model.fit(X, y)
# 3. Calculate Permutation Feature Importance
result = permutation_importance(model, X, y, n_repeats=10, random_state=42)
sorted_idx = result.importances_mean.argsort()
print("Feature Importances:")
for i in sorted_idx:
print(f" {feature_names[i]}: {result.importances_mean[i]:.3f} +/- {result.importances_std[i]:.3f}")
# 4. Generate and plot Partial Dependence Plots
fig, ax = plt.subplots(figsize=(10, 5))
PartialDependenceDisplay.from_estimator(
model, X, features=[0, 1], feature_names=feature_names, ax=ax,
line_kw={"color": "purple", "alpha": 0.7}
)
ax.set_title("Partial Dependence Plots")
plt.tight_layout()
plt.show()
