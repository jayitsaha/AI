Understanding Scalable GPs
▼

What is it? An exact Gaussian Process (GP) is a beautifully principled non-parametric regressor: it places a distribution over functions and updates it with Bayes' rule to give calibrated predictive uncertainty. The catch is cost — exact inference requires forming and factorizing an \(n\times n\) kernel (Gram) matrix, an \(O(n^3)\) time and \(O(n^2)\) memory operation. Past a few thousand points, this becomes computationally impossible on any hardware. "Scalable GPs" is the umbrella term for the toolkit that lets GPs handle datasets of \(10^4\)–\(10^7\) points while keeping (approximately) the same uncertainty guarantees.

Analogy: Imagine answering a question by personally interviewing every person in a stadium of 50,000 — that's exact GP inference. Random Fourier Features is like replacing each person with a short numeric summary card, so you only ever compare summary cards. Inducing points is like appointing a small panel of \(m\) representative delegates whose opinions approximate the whole crowd's. Kronecker structure is like noticing the stadium is arranged in a perfect grid of sections and rows, so you only need to survey one row and one section rather than every seat.

💡 If you remember one thing

Exact GP regression needs \((K + \sigma^2 I)^{-1}\) for an \(n\times n\) kernel matrix \(K\) — that's the \(O(n^3)\) wall. Every scalable-GP method is a different way to avoid ever forming or inverting the full \(n\times n\) matrix: approximate the kernel (RFF), approximate the data with \(m \ll n\) inducing points (SVGP), or exploit structure in the inputs (Kronecker/KISS-GP).

2
How It Works Internally
▼

Random Fourier Features (RFF)

Bochner's theorem says any continuous, shift-invariant, positive-definite kernel \(k(x-x')\) is the Fourier transform of a non-negative spectral density \(p(\omega)\). Sample \(\omega_i \sim p(\omega)\) and \(b_i \sim \mathrm{Unif}(0,2\pi)\), then define the random feature map \(\varphi(x) = \sqrt{2/D}\,\cos(\omega_i^\top x + b_i)\) for \(i=1,\dots,D\). In expectation over \(\omega,b\), \(\varphi(x)^\top\varphi(x') \approx k(x,x')\). GP regression becomes ordinary Bayesian linear regression in the \(D\)-dimensional feature space: cost drops to \(O(nD^2+D^3)\), independent of any \(n\times n\) matrix.

Inducing Points / Sparse Variational GP (SVGP)

Instead of approximating the kernel, SVGP (Titsias 2009; Hensman et al. 2013) approximates the posterior using \(m \ll n\) inducing inputs \(Z=(z_1,\dots,z_m)\) with inducing values \(u = f(Z)\). A variational distribution \(q(u) = \mathcal{N}(\mathbf{m}_u, S_u)\) is fit by maximizing an Evidence Lower Bound (ELBO) that only ever touches \(K_{nm}\) and \(K_{mm}\) — never the full \(K_{nn}\). Cost falls to \(O(nm^2+m^3)\) time and \(O(nm+m^2)\) memory, and because the ELBO decomposes as a sum over data points it supports stochastic mini-batch training — the mechanism GPyTorch's ApproximateGP + VariationalStrategy use to scale to millions of rows.

Kronecker / Grid Structure (KISS-GP)

When inputs live on a Cartesian product grid (e.g. a 2D sensor grid, or time × space) and the kernel is a product kernel \(k = k_1 \otimes k_2\), the full Gram matrix factorizes exactly as a Kronecker product \(K = K_1 \otimes K_2\). Eigenvectors/eigenvalues of a Kronecker product come directly from the eigendecompositions of the small factors \(K_1, K_2\) — so an \(n=g^2\) point grid costs \(O(g^3)\), not \(O(g^6)=O(n^3)\). GPyTorch's GridInterpolationKernel (KISS-GP) interpolates scattered data onto a grid to unlock this speedup even for non-gridded inputs.

🔑 Key Property

All three techniques trade a small, controllable amount of approximation error for asymptotically lower complexity, while preserving the core GP ingredient that made it worth using in the first place: calibrated predictive uncertainty.

3
Why It Works — The Math
▼

RFF Unbiasedness

Using the product-to-sum identity \(\cos A\cos B = \tfrac12[\cos(A-B)+\cos(A+B)]\):

$$\mathbb{E}_{b}\big[2\cos(\omega^\top x+b)\cos(\omega^\top x'+b)\big] = \cos\!\big(\omega^\top(x-x')\big)$$

because averaging \(\cos(\omega^\top(x+x')+2b)\) over \(b\sim\mathrm{Unif}(0,2\pi)\) vanishes. Taking the further expectation over \(\omega \sim p(\omega)\) recovers \(k(x-x')\) exactly by Bochner's theorem — so the Monte-Carlo feature map is an unbiased estimator of the kernel, with estimator variance shrinking as \(O(1/D)\).

The SVGP ELBO

$$\log p(y) \;\ge\; \mathbb{E}_{q(f)}\big[\log p(y\mid f)\big] \;-\; \mathrm{KL}\big[q(u)\,\Vert\, p(u)\big] \;-\; \frac{1}{2\sigma^2}\,\mathrm{tr}\big(K_{nn}-Q_{nn}\big)$$

where \(Q_{nn} = K_{nm}K_{mm}^{-1}K_{mn}\) is the Nyström (low-rank) approximation of \(K_{nn}\). The trace term explicitly penalizes information the inducing points fail to capture — it is exactly zero only if \(Q_{nn}=K_{nn}\). Optimizing this bound jointly over inducing locations \(Z\), variational parameters, and kernel hyperparameters costs \(O(nm^2)\) per step, dominated by forming \(K_{nm}K_{mm}^{-1}\).

Kronecker Eigenstructure

If \(K_1 = U_1\Lambda_1U_1^\top\) and \(K_2=U_2\Lambda_2U_2^\top\), then \((K_1\otimes K_2) = (U_1\otimes U_2)(\Lambda_1\otimes\Lambda_2)(U_1\otimes U_2)^\top\) — eigenvalues of the big matrix are all pairwise products of the small eigenvalues, and eigenvectors are Kronecker products of the small eigenvectors. Log-determinants, matrix-vector products, and solves needed for GP training and prediction all become \(O(g^3)\) instead of \(O(g^6)\) for a \(g\times g\) grid.

⚠️ Common Pitfalls

RFF needs many features \(D\) for long lengthscales or high-dimensional inputs (variance grows with dimension). Inducing-point placement is a non-convex optimization — poor initialization (not using k-means++ or a coreset) can trap SVGP in bad local optima. Kronecker/KISS-GP structure only applies exactly to grid-structured inputs; scattered data needs an interpolation step that introduces its own approximation error.

Key Takeaways
▼

When to reach for each tool:

  • Random Fourier Features — stationary kernels, want a fast finite-dimensional feature map for downstream linear methods or kernel ridge regression at scale.
  • SVGP / inducing points — large \(n\), need a full Bayesian treatment, non-Gaussian likelihoods (classification, Poisson counts), or streaming / mini-batch data — GPyTorch's ApproximateGP.
  • Kronecker / KISS-GP — inputs are naturally on a grid (or can be interpolated onto one), and near-exact GP quality with massive speedup is required.

Complexity cheat sheet (n = data points, D = random features, m = inducing points, g = grid side, so n≈g² in 2D):

  • Exact GP: \(O(n^3)\) time, \(O(n^2)\) memory
  • RFF: \(O(nD^2+D^3)\) time, \(O(nD)\) memory
  • SVGP: \(O(nm^2+m^3)\) time, \(O(nm+m^2)\) memory
  • Kronecker/KISS-GP: \(O(g^3)\) time (≈\(O(n^{1.5})\)), \(O(n)\) memory
💡 The GPyTorch philosophy

These techniques are complementary, not exclusive: GPyTorch combines blackbox matrix-matrix inference (BBMM), inducing-point SVGP, structured (Kronecker/Toeplitz) kernels, and GPU batching so a single framework scales from a few hundred points on a laptop to tens of millions on a GPU cluster — with the same gpytorch.models API throughout.

import torch, gpytorch
# 1. Exact GP — feasible only up to n ~ 10,000 (O(n^3) Cholesky)
class ExactGPModel(gpytorch.models.ExactGP):
def __init__(self, x, y, likelihood):
super().__init__(x, y, likelihood)
self.mean_module = gpytorch.means.ConstantMean()
self.covar_module = gpytorch.kernels.ScaleKernel(gpytorch.kernels.RBFKernel())
def forward(self, x):
return gpytorch.distributions.MultivariateNormal(self.mean_module(x), self.covar_module(x))
# 2. Random Fourier Features — finite random basis approximates k(x,x')
rff_kernel = gpytorch.kernels.RFFKernel(num_samples=256)
# 3. Sparse Variational GP (SVGP) — m << n inducing points
class SVGPModel(gpytorch.models.ApproximateGP):
def __init__(self, inducing_points):
var_dist = gpytorch.variational.CholeskyVariationalDistribution(inducing_points.size(0))
var_strategy = gpytorch.variational.VariationalStrategy(
self, inducing_points, var_dist, learn_inducing_locations=True)
super().__init__(var_strategy)
self.mean_module = gpytorch.means.ConstantMean()
self.covar_module = gpytorch.kernels.ScaleKernel(gpytorch.kernels.RBFKernel())
Z = train_x[torch.randperm(train_x.size(0))[:64]] # m = 64 inducing points
model = SVGPModel(inducing_points=Z)
# 4. Kronecker / grid structure (KISS-GP) — K = K1 ⊗ K2 for grid inputs
grid_kernel = gpytorch.kernels.GridInterpolationKernel(
gpytorch.kernels.RBFKernel(), grid_size=100, num_dims=2)
# 5. Mini-batch training — SVGP's ELBO scales to millions of points
mll = gpytorch.mlls.VariationalELBO(likelihood, model, num_data=train_y.size(0))
for x_batch, y_batch in train_loader:
optimizer.zero_grad()
output = model(x_batch)
loss = -mll(output, y_batch)
loss.backward()
optimizer.step()
