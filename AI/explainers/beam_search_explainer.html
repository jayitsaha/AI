Beam Search: Beam Width & Length Penalty

Efficiently finding high-probability sequences without exhaustive search
Foundational Deep Learning NLP O(T · B · V)
1
Understanding Beam Search
▼

What is it? Beam search is a heuristic search algorithm used to find the most probable sequence of items (e.g., words, actions) when generating from a probabilistic model. Instead of exhaustively exploring all possible sequences (which grows exponentially with length), it keeps only a fixed number, \(B\), of the most promising partial sequences ("beams") at each step, pruning the rest.

Analogy: Imagine you're trying to find the best route through a complex city. Exhaustive search would mean mapping out every single possible turn at every intersection. Greedy search (beam width \(B=1\)) would just pick the single "best" road at each intersection, potentially missing a better long-term path. Beam search says: "At each intersection, I'll consider my top \(B\) best routes so far, and only expand those. I might miss the absolute best route, but I'll find a pretty good one much faster."

💡 If you remember one thing

Beam search is a compromise between greedy search (fast, often sub-optimal) and breadth-first search (optimal, but computationally intractable for long sequences). It's widely used in sequence generation tasks like machine translation, text summarization, and speech recognition to find a high-quality (but not necessarily globally optimal) sequence.

2
How It Works Internally
▼

The Core Algorithm

Beam search operates step-by-step to build a sequence of length \(L\). At each time step \(t\), it considers all possible next tokens for each of the \(B\) partial sequences currently in its "beam":

  1. Initialization: Start with a single partial sequence (e.g., `<START>` token) with a log-probability of 0.
  2. Expansion: For each partial sequence in the current beam, generate all possible next tokens from the vocabulary. For each new token, create a new candidate sequence and calculate its log-probability (sum of log-probabilities of tokens so far).
  3. Pruning: Collect all new candidate sequences. Sort them by their log-probability score (higher is better). Keep only the top \(B\) sequences to form the next beam.
  4. Termination: Repeat steps 2-3 until a maximum length is reached, or a sufficient number of sequences ending with an `<END>` token are found.

The parameter \(B\) is called the beam width. A larger \(B\) explores more paths, increasing the chance of finding a better sequence, but at a higher computational cost (\(O(L \cdot B \cdot V)\) where \(V\) is vocabulary size). A smaller \(B\) is faster but more prone to missing good sequences.

The Length Penalty

Longer sequences naturally accumulate more (negative) log-probabilities, making them appear less probable than shorter sequences, even if they are semantically better. For example, a sequence `the cat ` might have a higher raw log-probability than `the cat runs fast ` simply because it's shorter and has fewer terms to multiply (or add negative log-probs). To counteract this bias, a length penalty is often applied:

$$\text{Adjusted Score} = \frac{\text{Raw Log-Probability}}{\text{Length Penalty Factor}}$$

The length penalty factor is typically a function of the sequence length \(L\) and a hyperparameter \(\alpha\). This adjusts the scores of longer sequences upwards, allowing them to compete fairly with shorter ones.

🔑 Key Property

The beam width \(B\) controls the breadth of the search, while the length penalty \(\alpha\) influences the preference for length in the generated sequences. Both are crucial hyperparameters that need tuning for optimal performance in real-world applications.

3
Why It Works — The Math
▼

Raw Sequence Score

For a sequence \(Y = (y_1, y_2, \dots, y_L)\), where \(y_1\) is the first generated token (after `<START>`), the probability of the sequence is the product of conditional probabilities:

$$P(Y) = P(y_1 | \text{context}) \cdot P(y_2 | y_1, \text{context}) \cdot \dots \cdot P(y_L | y_1, \dots, y_{L-1}, \text{context})$$

To avoid numerical underflow with very small probabilities and to work with sums instead of products (which is more convenient for optimization), we typically use the log-probability:

$$\text{Raw Log-Probability} = \log P(Y) = \sum_{i=1}^L \log P(y_i | y_1, \dots, y_{i-1}, \text{context})$$

Since probabilities are \( \le 1 \), their logarithms are \( \le 0 \). Thus, longer sequences will always have a lower (more negative) raw log-probability, creating a bias against them.

The Length Penalty Function

A common length penalty (from Wu et al., 2016, "Google's Neural Machine Translation System") scales the raw log-probability by a factor that depends on the sequence length \(L\) and a hyperparameter \(\alpha \ge 0\):

$$\text{Length Penalty Factor} = \frac{(LENGTH\_PENALTY\_BIAS + L)^\alpha}{(LENGTH\_PENALTY\_BIAS + 1)^\alpha}$$

Where \(LENGTH\_PENALTY\_BIAS\) is a small constant (often 5). The adjusted score used for ranking during beam search becomes:

$$\text{Adjusted Log-Probability} = \frac{\text{Raw Log-Probability}}{\text{Length Penalty Factor}}$$

If \(\alpha = 0\), the factor is 1, and no length penalty is applied (score = raw log-prob). As \(\alpha\) increases, the penalty factor grows faster with length, giving more preference to longer sequences. This effectively normalizes the score, allowing sequences of different lengths to be compared more fairly.

⚠️ Common Pitfall

Choosing optimal values for beam width \(B\) and length penalty \(\alpha\) is crucial and often requires empirical tuning on a validation set. Too small \(B\) leads to sub-optimal sequences; too large \(B\) wastes computation. Incorrect \(\alpha\) can lead to overly short or excessively long (and potentially repetitive) generations.

Key Takeaways
▼

When to use Beam Search:

  • In sequence generation tasks (machine translation, summarization, image captioning, speech recognition) where a greedy approach often yields sub-optimal results.
  • When you need a balance between computational cost and sequence quality.
  • When the search space is too large for exhaustive search (e.g., a vocabulary of thousands of words over sequences of dozens of tokens).

When Beam Search might be suboptimal:

  • If the globally optimal sequence is strictly required (beam search is a heuristic and not guaranteed to find it).
  • If the model's probabilities are poorly calibrated, leading to misleading scores.
  • For very short sequences or small vocabularies where exhaustive search might be feasible.
  • For creative or diverse generation (beam search tends to produce very similar, high-probability outputs; sampling-based methods are better for diversity).
💡 Practical Advice

Start with a small beam width (e.g., \(B=3\) or \(B=5\)) and \(\alpha=0\). Gradually increase \(B\) and tune \(\alpha\) on a validation set, monitoring both generation quality and inference speed. Often, a small \(B\) (e.g., 5-10) is sufficient for good results, as increasing it further yields diminishing returns.

Code Trace (Python / PyTorch-style)
▼
import torch
def beam_search(model, start_token_id, max_len, beam_width, alpha):
# Initialize beam with start token
initial_sequence = torch.tensor([[start_token_id]], device=model.device)
# (sequence, score, raw_score, is_finished)
beam = [(initial_sequence, 0.0, 0.0, False)]
finished_sequences = []
for _ in range(max_len):
candidates = []
for seq, score, raw_score, is_finished in beam:
if is_finished:
candidates.append((seq, score, raw_score, True))
continue
# Get next token probabilities from model
last_token = seq[:, -1]
log_probs = model(seq)[:, -1, :].log_softmax(dim=-1) # (1, vocab_size)
# Expand each beam with all possible next tokens
for next_token_id in range(log_probs.shape[-1]):
next_token_log_prob = log_probs[0, next_token_id].item()
new_raw_score = raw_score + next_token_log_prob
new_seq = torch.cat([seq, torch.tensor([[next_token_id]], device=model.device)], dim=1)
# Apply length penalty
length = new_seq.shape[1] - 1 # Exclude start token
penalty_factor = ((5 + length)**alpha) / ((5 + 1)**alpha)
new_adjusted_score = new_raw_score / penalty_factor
new_is_finished = (next_token_id == model.end_token_id)
candidates.append((new_seq, new_adjusted_score, new_raw_score, new_is_finished))
# Sort all candidates by adjusted score (descending)
candidates.sort(key=lambda x: x[1], reverse=True)
# Select top B candidates for next beam
new_beam = []
for candidate in candidates:
if candidate[3]: # If finished, add to final list and don't count towards beam_width
finished_sequences.append(candidate)
else:
new_beam.append(candidate)
if len(new_beam) + len(finished_sequences) >= beam_width: # Keep top B total paths
break
beam = new_beam
if not beam and not finished_sequences: # All paths finished or pruned
break
# Combine remaining paths in beam with finished ones
final_results = finished_sequences + beam
final_results.sort(key=lambda x: x[1], reverse=True) # Sort by adjusted score
return final_results
