Understanding the Models
▼

What are they? GPT-4o ("omni") is a single neural network that natively reads and writes text, images, and audio — no separate speech-to-text or vision bolt-on. GPT-o1 and GPT-o3 are "reasoning models": before answering, they generate a private internal monologue (a chain of thought) that lets them plan, backtrack, and check their own work, trading extra time and compute for higher accuracy on hard problems.

Analogy: GPT-4o is like a brilliant multilingual interpreter who answers instantly, in whichever medium you speak — text, voice, or a photo you hold up. o1/o3 are like that same interpreter handed a hard logic puzzle: instead of blurting out the first guess, they grab scratch paper, work through several approaches privately, cross out dead ends, and only then say the answer out loud.

💡 If you remember one thing

GPT-4o scales model size and modalities; o1/o3 add a new axis entirely — test-time compute. Instead of only getting smarter by training bigger, they get smarter by "thinking longer" at inference: $$\text{Accuracy} = f(\text{train-time compute},\ \textbf{test-time compute})$$

How They Work Internally
▼

GPT-4o: Early-Fusion Multimodality

Earlier "multimodal" GPT-4 pipelines stitched together a text model, a separate vision encoder, and a separate speech pipeline (Whisper → text → GPT-4 → text-to-speech), which threw away tone, pauses, and emotion. GPT-4o instead tokenizes text, image patches, and raw audio frames into one shared token vocabulary and trains a single end-to-end transformer to autoregressively predict the next token in any modality. This is why 4o can respond to a spoken question with laughter or a sigh in ~320ms — there is no serial hand-off between models.

o1 / o3: Reinforcement-Learned Chains of Thought

o1 is trained with reinforcement learning to produce long, private "reasoning tokens" before the final answer. The model is rewarded when its final answer is verifiably correct (math, code with unit tests, logic puzzles), which teaches it useful reasoning behaviors — trying a strategy, noticing an error, backtracking, and trying another — purely from the RL signal, without those behaviors being hand-labeled by humans. These reasoning tokens are hidden from the user (only a summary is shown) so the model isn't penalized for "thinking messy."

o3: Deeper Search + Deliberative Alignment

o3 extends the same recipe with more RL compute, more extensive tool use (code execution, browsing) inside the chain of thought, and "deliberative alignment" — the model explicitly reasons over safety specifications as part of its chain before responding. o3 can also allocate a variable "reasoning effort," and its accuracy keeps climbing as more test-time compute (more reasoning tokens, or more parallel reasoning attempts combined by majority vote) is thrown at a problem.

🔑 Key Property

GPT-4o is optimized for low-latency, single-pass, any-modality generation. o1/o3 are optimized for correctness on verifiable problems by spending variable inference-time compute — they are not simply "GPT-4o with a bigger prompt," their reasoning behavior is itself the product of RL training.

Why It Works — The Math
▼

The Test-Time Compute Scaling Law

OpenAI's o1 report shows accuracy improving log-linearly with the number of reasoning tokens \(N\) spent at inference. A simple saturating model that captures this trend is:

$$\text{Acc}(N) = p_0 + (c - p_0)\left(1 - e^{-\alpha \log_2(N / N_0)}\right), \quad N \ge N_0$$

where \(p_0\) is the accuracy with a minimal reasoning budget \(N_0\), \(c\) is the ceiling accuracy for that model family, and \(\alpha\) controls how efficiently extra tokens convert into accuracy. Every doubling of \(N\) buys a fixed increment of "distance closed" toward the ceiling — the same shape seen in train-time scaling laws, but along a completely different axis (inference compute, not parameter count).

Boosting Accuracy Further: Self-Consistency / Majority Vote

If a single reasoning chain is correct with probability \(p\), sampling \(k\) independent chains and taking a majority vote succeeds with probability given by the binomial tail:

$$P_{\text{maj}}(k, p) = \sum_{i=\lceil k/2 \rceil}^{k} \binom{k}{i} p^i (1-p)^{k-i}$$

This is a direct application of the Condorcet Jury Theorem: if \(p > 0.5\), adding more independent voters (more parallel reasoning attempts) drives \(P_{\text{maj}} \to 1\) as \(k \to \infty\). o3's stronger performance comes partly from a higher per-chain \(p\) (better RL training) and partly from spending more test-time compute on search/voting.

⚠️ Common Pitfall

The majority-vote formula assumes chains are independent. In practice, sampled reasoning chains from the same model share correlated blind spots — if the model systematically misunderstands the problem, more samples don't help. This is why o3's real gains come from RL-improved per-chain accuracy \(p\), not just brute-force voting.

Key Takeaways
▼

When to use GPT-4o:

  • Real-time voice or vision conversations — low latency matters
  • Everyday tasks: drafting, summarizing, casual Q&A, image description
  • High-volume, cost-sensitive applications (no expensive hidden reasoning tokens)

When to use o1 / o3:

  • Hard math, competitive programming, multi-step logic, scientific reasoning
  • Tasks with a verifiable answer, where you can afford extra latency and cost
  • Situations where a wrong "confident-sounding" answer is expensive (agentic tool use, code that must compile)
💡 The Big Picture

Pre-2024, the only lever was train-time compute — bigger models, more data. o1/o3 proved a second, independent lever: test-time compute — spend more inference tokens "thinking" per query. The two axes compose: a bigger, better-trained model that also reasons longer beats either improvement alone.

Code Trace

import math
from math import comb
# Test-time compute scaling law (illustrative, fit to published trends)
def acc(N, p0, cap, alpha, N0=128):
if N <= N0: return p0
return p0 + (cap - p0) * (1 - math.exp(-alpha * math.log2(N / N0)))
# Self-consistency: majority vote over k independent reasoning chains
def majority_vote_acc(k, p):
return sum(comb(k, i) * p**i * (1 - p)**(k - i)
for i in range(math.ceil(k / 2), k + 1))
# o1 params (illustrative): p0=0.13, cap=0.83, alpha=0.17
p_single = acc(N=16384, p0=0.13, cap=0.83, alpha=0.17)
p_voted = majority_vote_acc(k=16, p=p_single)
print(f"single chain: {p_single:.1%} | 16-way vote: {p_voted:.1%}")
# Calling the real OpenAI reasoning models:
from openai import OpenAI
client = OpenAI()
resp = client.chat.completions.create(
model="o3",
reasoning_effort="high", # low | medium | high — controls test-time compute
messages=[{"role": "user", "content": "Prove there are infinitely many primes."}],
)
print(resp.choices[0].message.content) # hidden reasoning tokens are billed but not shown
