Understanding Layer Normalization
▼

What is it? Every hidden vector flowing through a network can drift to wildly different scales as it passes through layers — some numbers huge, some tiny — which makes training unstable. Layer Normalization (LayerNorm) fixes this by rescaling each individual token's feature vector to have zero mean and unit variance, then letting the network re-learn whatever scale it actually needs via two learned parameters, \(\gamma\) and \(\beta\).

Analogy: Imagine grading student essays. BatchNorm is like curving grades by comparing every student in the room to each other — the curve changes if you add or remove students, or if the room size changes. LayerNorm is like grading each essay against its own internal rubric — how balanced are this student's own answers across the different sections of the exam. It never needs to look at anyone else's paper, so it works identically whether the room has 1 student or 1,000, and however long any individual essay is.

💡 If you remember one thing

LayerNorm normalizes across the feature dimension, for each token independently — not across the batch. That single design choice makes it batch-size independent and sequence-length independent, which is exactly what variable-length NLP sequences need: $$\text{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^2+\epsilon}} + \beta, \quad \mu,\sigma^2 \text{ computed per token over features}$$

How LayerNorm Works Internally
▼

The Tensor and the Two Candidate Axes

A transformer's activations form a tensor of shape \((B, T, F)\) — batch size \(B\), sequence length \(T\), feature/hidden dimension \(F\). Any normalization scheme must pick which axis (or axes) to pool statistics over. There are exactly two natural choices for a token at position \((b,t)\):

  • BatchNorm's axis: for a fixed feature \(j\), pool over every \((b,t)\) pair — i.e. across the batch and sequence positions. One \(\mu_j,\sigma_j^2\) per feature, shared by the whole batch.
  • LayerNorm's axis: for a fixed token \((b,t)\), pool over all \(F\) features of that token alone. One \(\mu_{b,t},\sigma_{b,t}^2\) per token, independent of every other token and every other sequence in the batch.

Why BatchNorm Breaks for NLP

NLP batches are ragged — sentences have different lengths, so shorter sequences get padded with dummy tokens to form a rectangular tensor. BatchNorm's statistics pool over the batch/sequence axis, so those pad tokens either have to be carefully masked out (extra bookkeeping, extra kernel complexity) or they silently pollute \(\mu_j,\sigma_j^2\). Worse, at autoregressive inference time you generate one token at a time (\(B{=}1, T{=}1\)) — there is no batch to compute statistics over at all, forcing reliance on running averages accumulated during training, which mismatch the true distribution of activations token-by-token.

Why LayerNorm Just Works

LayerNorm's statistics are computed per token, over the feature dimension only. That axis always has exactly \(F\) entries — a fixed, known size — no matter the batch size, no matter the sequence length, no matter whether you're training on 512-token batches or decoding a single new token during generation. There is nothing to pad, nothing to mask, and no train/inference statistic mismatch.

🔑 Key Property

LayerNorm's normalizing statistics \(\mu,\sigma^2\) depend only on the token's own feature vector — never on other tokens, other sequences, or the batch size. This makes it batch-size independent and sequence-length independent by construction, which is exactly why every major transformer (BERT, GPT, T5, LLaMA-family via RMSNorm) uses it instead of BatchNorm.

Why It Works — The Math
▼

Definition

For a single token's activation vector \(x \in \mathbb{R}^F\) (feature dimension \(F\)), LayerNorm computes:

$$\mu = \frac{1}{F}\sum_{i=1}^{F} x_i \qquad \sigma^2 = \frac{1}{F}\sum_{i=1}^{F}(x_i-\mu)^2$$
$$\hat{x}_i = \frac{x_i - \mu}{\sqrt{\sigma^2 + \epsilon}} \qquad y_i = \gamma_i \hat{x}_i + \beta_i$$

Note that \(\mu\) and \(\sigma^2\) are scalars per token (computed by reducing over \(i=1,\dots,F\)), while \(\gamma,\beta \in \mathbb{R}^F\) are learned vectors shared across every token and every position — they let the network undo the normalization and recover any scale/shift it actually needs, feature by feature.

Contrast: BatchNorm's Reduction

BatchNorm instead reduces over the batch (and, for sequences, the time) axis, producing one statistic per feature that mixes information across examples:

$$\mu_j = \frac{1}{BT}\sum_{b=1}^{B}\sum_{t=1}^{T} x_{b,t,j} \qquad \sigma_j^2 = \frac{1}{BT}\sum_{b=1}^{B}\sum_{t=1}^{T} (x_{b,t,j}-\mu_j)^2$$

Because \(\mu_j\) sums over \(B \cdot T\) terms, its value literally changes if \(B\) or \(T\) changes — different batch sizes, different sequence-length padding, or different mini-batch composition all shift the normalizing statistic. LayerNorm's \(\mu\) sums over exactly \(F\) terms, which never changes.

Gradient Flow

Backpropagating through the normalization, the gradient with respect to a single input component involves all other components of the same token (through \(\mu\) and \(\sigma^2\)), but never touches other tokens or other batch elements:

$$\frac{\partial \mathcal{L}}{\partial x_i} = \frac{\gamma_i}{\sqrt{\sigma^2+\epsilon}}\left[\frac{\partial \mathcal{L}}{\partial \hat{x}_i} - \frac{1}{F}\sum_{k=1}^F \frac{\partial \mathcal{L}}{\partial \hat{x}_k} - \frac{\hat{x}_i}{F}\sum_{k=1}^F \frac{\partial \mathcal{L}}{\partial \hat{x}_k}\hat{x}_k\right]$$

This locality is what makes LayerNorm trivially parallel across tokens and batch elements — each token's forward and backward pass is fully independent of every other token's.

⚠️ Common Misconception

"LayerNorm normalizes the whole layer's activations." Not quite — it normalizes each token's vector independently, across that token's own \(F\) features. A batch of \((B,T,F)\) activations produces \(B \times T\) independent scalar \((\mu,\sigma^2)\) pairs, not one global pair. The name is a historical artifact from the original (non-sequential) formulation.

When to use LayerNorm: sequence models, transformers, variable-length inputs, small or batch-size-1 inference, anywhere batch statistics are unreliable or unavailable.

When NOT to use: large-batch CNNs on images with a fixed spatial size, where BatchNorm's cross-example statistics act as a helpful regularizer and its extra smoothing of the loss landscape is a net win.

💡 One-Line Summary

LayerNorm trades BatchNorm's cross-example regularization for per-token independence — exactly the trade NLP needs, since sentences vary in length and inference often happens one token at a time.

Code Trace
▼
import numpy as np
# x: one token's activations, shape (F,)
def layer_norm(x, gamma, beta, eps=1e-5):
mu = x.mean() # scalar: reduce over F only
var = x.var() # scalar: reduce over F only
x_hat = (x - mu) / np.sqrt(var + eps)
return gamma * x_hat + beta # learned per-feature scale/shift
# Batched sequence tensor: shape (B, T, F)
def layer_norm_batched(x, gamma, beta, eps=1e-5):
mu = x.mean(axis=-1, keepdims=True) # reduce over F only!
var = x.var(axis=-1, keepdims=True) # NOT axis=0 (batch) or axis=1 (time)
x_hat = (x - mu) / np.sqrt(var + eps)
return gamma * x_hat + beta # broadcasts over (B, T)
# PyTorch production usage
import torch.nn as nn
ln = nn.LayerNorm(normalized_shape=768) # F = hidden size
y = ln(x) # x: (B, T, 768) -> normalizes each (b,t) row independently
# ⚠️ Gotcha: normalized_shape must match the LAST dim(s) of x.
# Padding tokens still get normalized (mean≈0 vec / eps) — mask
# them out of the LOSS, not the norm itself; LayerNorm needs no masking.
