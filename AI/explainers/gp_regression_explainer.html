Understanding GP Regression
▼

What is it? A Gaussian Process (GP) puts a probability distribution directly over functions instead of over a fixed set of parameters. Before seeing any data, you declare a prior belief: "functions that are smooth and vary at roughly this scale are plausible." After observing a handful of \((x,y)\) pairs, Bayes' rule tells you exactly how that belief updates — this update is the posterior predictive distribution, and it comes with a principled uncertainty band for free.

Analogy: Imagine sketching a curve blindfolded, guided only by a few pins someone pushes through the paper at known points. Near a pin, your curve must pass through it exactly (if you trust the pin). Far from any pin, you could draw almost anything, so your "cone of plausible curves" fans out. That fan is the GP's predictive uncertainty — tight near data, wide in the gaps.

💡 If you remember one thing

A GP is fully specified by a mean function (usually zero) and a covariance function \(k(x,x')\) — the kernel — which encodes how correlated \(f(x)\) and \(f(x')\) are. Conditioning a GP on data is just conditioning a (possibly huge) multivariate Gaussian: $$\mu_* = K_*^\top (K+\sigma_n^2 I)^{-1} y, \qquad \Sigma_* = K_{**} - K_*^\top (K+\sigma_n^2 I)^{-1} K_*$$

How GP Regression Works Internally
▼

Step 1 — The Prior

Choose a kernel, e.g. the squared-exponential (RBF): \(k(x,x') = \sigma_f^2 \exp\!\big(-\tfrac{(x-x')^2}{2\ell^2}\big)\). Any finite collection of function values \(f(X) = (f(x_1),\dots,f(x_n))\) is then jointly Gaussian: \(f(X) \sim \mathcal{N}(0, K)\), where \(K_{ij} = k(x_i,x_j)\). The lengthscale \(\ell\) controls how "wiggly" plausible functions are; \(\sigma_f^2\) controls their amplitude.

Step 2 — Observe Noisy Data

We assume \(y_i = f(x_i) + \varepsilon_i\), \(\varepsilon_i \sim \mathcal{N}(0,\sigma_n^2)\) independently. So the training targets are jointly Gaussian too: \(y \sim \mathcal{N}(0, K+\sigma_n^2 I)\).

Step 3 — Condition on What You've Seen

Stack the training outputs \(y\) and a batch of test outputs \(f_*\) into one joint Gaussian vector:

$$\begin{bmatrix} y \\ f_* \end{bmatrix} \sim \mathcal{N}\!\left(0,\ \begin{bmatrix} K+\sigma_n^2 I & K_* \\ K_*^\top & K_{**} \end{bmatrix}\right)$$

Applying the standard rule for conditioning a joint Gaussian on part of its variables gives the posterior predictive distribution \(f_* \mid X, y, X_* \sim \mathcal{N}(\mu_*, \Sigma_*)\) with the formulas from Card 1. Every prediction is a full distribution, not a point estimate.

🔑 Key Property

The predictive variance \(\Sigma_*\) does not depend on \(y\) — only on the input locations. Uncertainty shrinks near training inputs and grows in gaps or extrapolation regions, purely as a geometric fact about the kernel.

3
Why It Works — The Math
▼

Deriving the Posterior Predictive

For a jointly Gaussian \(\begin{bmatrix}a\\b\end{bmatrix}\sim\mathcal N\!\left(0,\begin{bmatrix}A&B\\B^\top&C\end{bmatrix}\right)\), the conditional \(b\mid a\) is Gaussian with mean \(B^\top A^{-1}a\) and covariance \(C - B^\top A^{-1} B\) — pure linear algebra, no sampling required. Substituting \(a=y\), \(A=K+\sigma_n^2I\), \(B=K_*\), \(C=K_{**}\) yields exactly \(\mu_*, \Sigma_*\) from Card 1.

The Marginal Likelihood

To pick hyperparameters \(\theta=(\ell,\sigma_f,\sigma_n)\) we don't need a held-out validation set — GPs offer a closed-form marginal likelihood (a.k.a. evidence), the probability of the observed \(y\) after integrating out every possible function:

$$\log p(y\mid X,\theta) = -\tfrac12 y^\top (K+\sigma_n^2I)^{-1} y \;-\; \tfrac12 \log|K+\sigma_n^2I| \;-\; \tfrac{n}{2}\log(2\pi)$$

The first term is a data-fit term (small when the model explains \(y\) well). The second term is a complexity penalty — it grows when the kernel makes \(K\) close to singular (i.e. an overly flexible, low-\(\ell\) model that could fit anything). Maximizing this sum over \(\theta\) automatically trades off fit against complexity: it is Bayesian Occam's razor, computed exactly rather than approximated by cross-validation.

⚠️ Common Pitfall

The marginal likelihood surface is non-convex in \(\theta\) — gradient-based optimizers (using \(\partial \log p(y)/\partial\theta\), itself closed-form via the trace identity) can land in different local optima depending on initialization. Always check a few restarts, and remember: exact inference costs \(O(n^3)\) per likelihood evaluation because of the Cholesky factorization of \(K+\sigma_n^2I\).

Key Takeaways
▼

When to use GP regression:

  • Small-to-medium datasets (roughly \(n \lesssim 10^4\) without sparse approximations) where calibrated uncertainty matters
  • Bayesian optimization / active learning, where the predictive variance drives what to query next
  • Smooth, low-dimensional regression where a sensible kernel is easy to specify

When NOT to use:

  • Very large \(n\) — the exact \(O(n^3)\) Cholesky factorization becomes the bottleneck; use sparse/inducing-point GPs instead
  • High-dimensional inputs with little structure — kernels based on Euclidean distance degrade ("curse of dimensionality")
  • Extremely non-stationary functions poorly matched by a single global kernel
💡 Hierarchy

Bayesian linear regression is a GP with a linear kernel. GP regression generalizes it to arbitrary (possibly infinite-dimensional feature) kernels, while keeping exact, closed-form Bayesian inference — no MCMC, no variational bound, just linear algebra.

Code Trace

import numpy as np
# Training data
X = np.array([-3.5, -1.2, 0.8, 3.0])
y = np.sin(X) + np.array([0.08, -0.05, 0.10, -0.07])
# RBF kernel
def kernel(a, b, l, sf):
d2 = (a[:, None] - b[None, :]) ** 2
return sf**2 * np.exp(-0.5 * d2 / l**2)
l, sf, sn = 1.0, 1.0, 0.25
K = kernel(X, X, l, sf) + sn**2 * np.eye(len(X))
L = np.linalg.cholesky(K) # K = L Lᵀ
alpha = np.linalg.solve(L.T, np.linalg.solve(L, y))
# Predict at test points
Xs = np.linspace(-6, 6, 121)
Ks = kernel(X, Xs, l, sf) # n x m
mu_s = Ks.T @ alpha
v = np.linalg.solve(L, Ks)
var_s = sf**2 - np.sum(v**2, axis=0) # diag(Sigma*)
# Log marginal likelihood
def log_mll(X, y, l, sf, sn):
K = kernel(X, X, l, sf) + sn**2 * np.eye(len(X))
L = np.linalg.cholesky(K)
a = np.linalg.solve(L.T, np.linalg.solve(L, y))
return (-0.5 * y @ a - np.sum(np.log(np.diag(L)))
- 0.5 * len(X) * np.log(2 * np.pi))
# Model selection: maximize log_mll over l
ls = np.linspace(0.1, 4.0, 79)
l_opt = ls[np.argmax([log_mll(X, y, l, sf, sn) for l in ls])]
