1
Understanding Multi-Head Attention
▼

What is it? Multi-Head Attention is a core component of the Transformer architecture. It extends the concept of self-attention by running multiple attention mechanisms in parallel, each focusing on different parts of the input sequence or different relationships between tokens. The outputs from these "heads" are then concatenated and linearly transformed to produce the final output.

Why multiple heads? A single attention head might be good at capturing one type of relationship (e.g., subject-verb agreement). But language (and other sequential data) is rich with many different types of relationships: syntactic, semantic, long-range, short-range, etc. Parallel heads allow the model to simultaneously attend to diverse aspects of the input, creating a richer, more comprehensive contextual representation.

Analogy: Imagine a team of experts analyzing a document. A single expert (attention head) might focus only on grammar. A multi-headed team would have a grammar expert, a sentiment expert, a topic expert, and a named entity expert. Each expert reads the same document, forms their own understanding (attention weights), and extracts relevant information. Their individual insights are then combined to form a holistic summary.

💡 If you remember one thing

Multi-Head Attention allows the Transformer to jointly attend to information from different representation subspaces at different positions. It's like having multiple specialized "lenses" through which to view the input, capturing a wider range of dependencies than a single lens could.

2
How Multi-Head Attention Works Internally
▼

The Self-Attention Foundation

At its core, Multi-Head Attention builds upon the self-attention mechanism. For an input sequence of embeddings \(X\), self-attention computes three matrices: Query (\(Q\)), Key (\(K\)), and Value (\(V\)). These are derived by linearly projecting \(X\) with learned weight matrices \(W^Q, W^K, W^V\).

$$Q = XW^Q, \quad K = XW^K, \quad V = XW^V$$

Attention scores are calculated as the dot product of \(Q\) and \(K^\top\), scaled by \(\sqrt{d_k}\) (where \(d_k\) is the dimension of the keys). A softmax function then converts these scores into attention weights, which are used to compute a weighted sum of the \(V\) matrix, yielding the output of a single attention head.

Parallel Projections and Splitting

Instead of just one set of \(W^Q, W^K, W^V\) matrices, Multi-Head Attention uses \(h\) different sets of projection matrices: \((W_1^Q, W_1^K, W_1^V), \dots, (W_h^Q, W_h^K, W_h^V)\). Each set projects the input \(X\) into a lower-dimensional space, creating \(h\) independent sets of Queries, Keys, and Values: \((Q_1, K_1, V_1), \dots, (Q_h, K_h, V_h)\). The dimension of these sub-projections, \(d_k\), is typically \(d_{model} / h\).

Independent Attention Calculations

Each of these \(h\) sets \((Q_i, K_i, V_i)\) then undergoes an independent self-attention calculation. This means each head learns its own set of attention weights and produces its own output, \(head_i\).

Concatenation and Final Projection

The outputs from all \(h\) heads (\(head_1, \dots, head_h\)) are then concatenated back together along the feature dimension. This results in a matrix with the same sequence length as the input, but with a feature dimension of \(h \times d_k\), which equals \(d_{model}\). Finally, this concatenated output is passed through one last linear projection layer, defined by a weight matrix \(W^O\), to produce the final output of the Multi-Head Attention layer.

🔑 Key Mechanism

By performing multiple attention calculations in parallel, each with its own learned linear projections, Multi-Head Attention allows the model to learn different notions of "relatedness" between tokens. This parallel processing of distinct feature subspaces is crucial for the Transformer's ability to capture complex dependencies.

3
Why It Works — The Math
▼

Single Head Scaled Dot-Product Attention

The fundamental building block is Scaled Dot-Product Attention. Given Queries \(Q\), Keys \(K\), and Values \(V\), its output is:

$$Attention(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Here, \(Q \in \mathbb{R}^{L \times d_k}\), \(K \in \mathbb{R}^{L \times d_k}\), and \(V \in \mathbb{R}^{L \times d_v}\), where \(L\) is the sequence length, \(d_k\) is the dimension of keys (and queries), and \(d_v\) is the dimension of values. Often, \(d_k = d_v\).

Multi-Head Attention Formulation

Multi-Head Attention consists of \(h\) parallel attention heads. First, for each head \(i\), the input embeddings \(X \in \mathbb{R}^{L \times d_{model}}\) are linearly projected to create \(Q_i, K_i, V_i\):

$$Q_i = XW_i^Q, \quad K_i = XW_i^K, \quad V_i = XW_i^V$$

where \(W_i^Q \in \mathbb{R}^{d_{model} \times d_k}\), \(W_i^K \in \mathbb{R}^{d_{model} \times d_k}\), and \(W_i^V \in \mathbb{R}^{d_{model} \times d_v}\). Typically, \(d_k = d_v = d_{model}/h\). Each head \(i\) then computes its own attention output:

$$head_i = Attention(Q_i, K_i, V_i) = \text{softmax}\left(\frac{Q_i K_i^\top}{\sqrt{d_k}}\right)V_i$$

Finally, the outputs from all heads are concatenated and projected by a final weight matrix \(W^O \in \mathbb{R}^{(h \cdot d_v) \times d_{model}}\):

$$MultiHead(Q, K, V) = Concat(head_1, \dots, head_h)W^O$$
⚠️ Design Choice: Dimension Reduction

Reducing the dimension of \(Q_i, K_i, V_i\) to \(d_{model}/h\) for each head is crucial. If each head operated on the full \(d_{model}\) dimension, the computational cost would be \(h\) times higher than single-head attention. By reducing the dimension, the total computational cost of Multi-Head Attention (with \(h\) heads) is roughly similar to that of a single attention head with \(d_k = d_{model}\), while offering the benefits of diverse representation subspaces.

Key Takeaways
▼

Benefits of Multi-Head Attention:

  • Diverse Relationship Capture: Each head can learn to attend to different types of information or relationships within the sequence, enhancing the model's ability to understand complex contexts.
  • Robustness: By combining multiple perspectives, the model becomes more robust to noise or ambiguities that a single head might misinterpret.
  • Parallelism: The independent computation of heads allows for efficient parallelization, which is crucial for training large Transformer models.
  • Increased Representational Power: The concatenation and final linear projection allow the model to integrate these diverse perspectives into a rich, high-dimensional output representation.

Considerations:

  • Computational Cost: While efficient due to dimension reduction, increasing the number of heads or the model dimension still increases computational complexity.
  • Hyperparameter Tuning: The number of heads (\(h\)) and the model dimension (\(d_{model}\)) are critical hyperparameters that need careful tuning.
  • Interpretability: While powerful, understanding what each individual head "learns" can be challenging, though research is ongoing in this area.
💡 Relation to other concepts

Multi-Head Attention is often followed by a Feed-Forward Network (FFN) in a Transformer block. The FFN processes each token's representation independently, adding non-linearity. This combination allows the model to both integrate global context (attention) and process local features (FFN).

import numpy as np
def scaled_dot_product_attention(Q, K, V, mask=None):
d_k = Q.shape[-1]
scores = np.matmul(Q, K.transpose(0, 2, 1)) / np.sqrt(d_k)
if mask is not None:
scores = scores + mask * -1e9 # Apply mask (e.g., for padding or causality)
attention_weights = np.softmax(scores, axis=-1)
output = np.matmul(attention_weights, V)
return output, attention_weights
def multi_head_attention(X, Wq, Wk, Wv, Wo, h, d_model):
# X: (batch_size, seq_len, d_model)
# Wq, Wk, Wv: (h, d_model, d_k) where d_k = d_model / h
# Wo: (d_model, d_model)
batch_size, seq_len, _ = X.shape
d_k = d_model // h
# 1. Linear projections for Q, K, V (for all heads)
# Q_all = X @ Wq_combined # (batch_size, seq_len, d_model)
# K_all = X @ Wk_combined
# V_all = X @ Wv_combined
# (Simplified for conceptual clarity, usually done with one large matrix multiply)
Q_heads = np.array([X @ Wq[i] for i in range(h)]) # (h, batch_size, seq_len, d_k)
K_heads = np.array([X @ Wk[i] for i in range(h)])
V_heads = np.array([X @ Wv[i] for i in range(h)])
# Reshape for multi-head processing: (batch_size, h, seq_len, d_k)
Q_heads = Q_heads.transpose(1, 0, 2, 3)
K_heads = K_heads.transpose(1, 0, 2, 3)
V_heads = V_heads.transpose(1, 0, 2, 3)
# 2. Apply scaled dot-product attention for each head in parallel
# (This step is parallelized across heads and batch items)
attention_outputs, _ = scaled_dot_product_attention(Q_heads, K_heads, V_heads)
# attention_outputs: (batch_size, h, seq_len, d_k)
# 3. Concatenate outputs of all heads
concat_attention = attention_outputs.transpose(0, 2, 1, 3).reshape(
batch_size, seq_len, h * d_k) # (batch_size, seq_len, d_model)
# 4. Final linear projection
output = np.matmul(concat_attention, Wo) # (batch_size, seq_len, d_model)
return output
