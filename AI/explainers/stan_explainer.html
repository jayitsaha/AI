Understanding Stan
▼

What is it? Stan is a probabilistic programming language for Bayesian statistical modeling. You write a model (priors + likelihood) in Stan's own syntax, and Stan's compiler translates it into efficient C++ that computes the log-posterior density and its gradient. That gradient is the key: Stan's default sampler, the No-U-Turn Sampler (NUTS), is a self-tuning variant of Hamiltonian Monte Carlo (HMC) — a physics-inspired MCMC algorithm that uses gradients to propose distant, high-acceptance-rate moves instead of the small, shuffling steps of classic Metropolis-Hastings.

Analogy: Imagine the negative log-posterior as a bowl-shaped landscape (valleys = high probability). A random-walk sampler is a blindfolded hiker taking tiny random steps, occasionally stumbling downhill. HMC instead gives the hiker a skateboard and a push (random momentum): they glide along the bowl's contours, using the slope (gradient) to carve a long, physically realistic arc before we sample where they land. NUTS is the smart engineer that automatically decides how long to let the skateboard roll before it would start heading back where it came from — a "U-turn."

💡 If you remember one thing

HMC augments parameters \(\theta\) with auxiliary momentum \(p\) and simulates Hamiltonian dynamics on \(H(\theta,p) = U(\theta) + K(p)\), where \(U(\theta) = -\log \pi(\theta)\). Because energy is (nearly) conserved, proposals travel far across the posterior yet are accepted with high probability — dramatically better mixing than random-walk Metropolis, especially in high dimensions.

How HMC / NUTS Works Internally
▼

Step 1 — Augment with momentum

For parameters \(\theta \in \mathbb{R}^d\), introduce an auxiliary momentum \(p \sim \mathcal{N}(0, M)\), where \(M\) is a "mass matrix" (Stan adapts \(M\) during warm-up). Define the Hamiltonian:

$$H(\theta, p) = U(\theta) + K(p), \qquad U(\theta) = -\log \pi(\theta \mid y), \qquad K(p) = \tfrac{1}{2}p^\top M^{-1} p$$

Sampling \(p\) fresh each iteration and simulating dynamics that conserve \(H\) leaves the joint distribution \(p(\theta,p) \propto e^{-H(\theta,p)}\) invariant — so its \(\theta\)-marginal is exactly the posterior.

Step 2 — Simulate with the leapfrog integrator

Hamilton's equations \(\dot\theta = \partial H/\partial p,\ \dot p = -\partial H/\partial \theta\) have no closed form for general posteriors, so Stan uses the symplectic leapfrog integrator with step size \(\varepsilon\), which is time-reversible and volume-preserving (needed for detailed balance):

$$p_{t+\varepsilon/2} = p_t - \tfrac{\varepsilon}{2}\nabla U(\theta_t),\quad \theta_{t+\varepsilon} = \theta_t + \varepsilon M^{-1}p_{t+\varepsilon/2},\quad p_{t+\varepsilon} = p_{t+\varepsilon/2} - \tfrac{\varepsilon}{2}\nabla U(\theta_{t+\varepsilon})$$

Chaining \(L\) leapfrog steps traces a trajectory across the posterior. A Metropolis correction (accept with probability \(\min(1, e^{H(\theta_0,p_0)-H(\theta_L,p_L)})\)) then removes the small numerical-integration bias — this is exactly the HMC algorithm.

Design decision: why NUTS instead of fixed-\(L\) HMC?

Vanilla HMC needs \(L\) hand-tuned: too small wastes the gradient information (looks like random walk); too large wastes computation retracing the same region or looping back. NUTS removes this tuning knob: it grows the trajectory by doubling forward and backward in time, and stops as soon as continuing would make the endpoints turn back toward each other — the no-U-turn criterion \((\theta^+ - \theta^-)\cdot p^- < 0\) or \((\theta^+-\theta^-)\cdot p^+ < 0\). It then samples one state from the trajectory built (via a slice/multinomial scheme), preserving detailed balance.

🔑 Key Property

Both \(\varepsilon\) (step size, via dual averaging targeting a ~0.8 acceptance rate) and \(M\) (mass matrix, from warm-up sample covariance) are adapted automatically during Stan's warm-up phase — this is what lets Stan run "out of the box" on most models without manual MCMC tuning.

3
Why It Works — The Math
▼

Why the acceptance rate is high

The leapfrog integrator is symplectic and time-reversible, so it conserves \(H\) up to \(O(\varepsilon^2)\) local error (global error \(O(\varepsilon^2)\) per unit time too, for a fixed trajectory length). Because the error is small and bounded rather than a random walk's diffusive error, proposals thousands of steps "away" in parameter space can still be accepted at high probability — unlike Metropolis, where far proposals are almost always rejected.

$$\alpha = \min\!\Big(1,\ \exp\big[H(\theta_0,p_0) - H(\theta_L,p_L)\big]\Big)$$

The no-U-turn stopping criterion

Let \(\theta^-, p^-\) and \(\theta^+, p^+\) be the backward- and forward-most states of the current trajectory. Continuing to extend the trajectory stops improving exploration once the ends start curving back toward each other. NUTS detects this by checking:

$$\frac{d}{dt}\Big[\tfrac{1}{2}\|\theta^+(t) - \theta^-(t)\|^2\Big] = (\theta^+ - \theta^-)\cdot(p^+ + p^-) < 0$$

which decomposes into the two per-end checks \((\theta^+-\theta^-)\cdot p^- < 0\) or \((\theta^+-\theta^-)\cdot p^+ < 0\) applied recursively across all sub-trees built during doubling (this is what makes the full algorithm still satisfy detailed balance despite the adaptive length).

Random walk vs. gradient-guided: the scaling argument

For a \(d\)-dimensional target, random-walk Metropolis needs \(O(d)\) steps to traverse a unit of "effective" distance with a well-tuned step size, and its optimal acceptance rate is famously ~23%. HMC's trajectory length can traverse the same distance in \(O(d^{1/4})\) gradient evaluations under favorable conditions, and Stan tunes step size toward ~65-80% acceptance — this asymptotic gap is why HMC/NUTS scales to hundreds or thousands of parameters where random-walk samplers stall.

⚠️ Common Pitfall

Divergent transitions (Stan warns "divergent transitions after warmup") occur when the leapfrog integrator's discretization error blows up in regions of high curvature (e.g., funnel-shaped hierarchical posteriors) — this is a numerical breakdown of the \(H\)-conservation the whole method relies on, not just a low acceptance rate. Fix by reparameterizing (non-centered parameterization) or increasing adapt_delta, not by ignoring the warning.

Key Takeaways
▼

When Stan / HMC-NUTS shines:

  • Continuous parameter spaces with a differentiable log-posterior (hierarchical models, GLMs, ODEs, GPs)
  • Moderate-to-high dimension (tens to thousands of parameters) where random-walk MCMC mixes too slowly
  • You want automatic diagnostics: R-hat, effective sample size (ESS), divergent transitions, energy (E-BFMI) — all built in

When NOT to reach for it:

  • Discrete latent parameters (Stan cannot sample discrete parameters directly — must marginalize them out)
  • Extremely cheap, low-dimensional, well-behaved posteriors — a simple Gibbs sampler or even grid evaluation may be faster to set up
  • Multimodal posteriors with modes separated by low-density regions — HMC trajectories rarely jump between modes
💡 PyStan vs. CmdStan vs. CmdStanPy

CmdStan is the reference command-line interface: it compiles a .stan file straight to a native binary via the Stan-to-C++ transpiler + a C++ compiler, then runs sampling as a subprocess — most stable, least Python integration. PyStan historically embedded the C++ toolchain directly in Python (heavier install, tighter coupling, version-sensitive). CmdStanPy is now the recommended path: a thin, actively-maintained Python wrapper that shells out to CmdStan binaries, giving PyStan-like convenience with CmdStan's stability. All three ultimately run the identical NUTS sampler compiled from your model.

Code Trace
▼
// model.stan
data {
int<lower=0> N;
vector[N] x; vector[N] y;
}
parameters {
real alpha; real beta; real<lower=0> sigma;
}
model {
alpha ~ normal(0, 5); // prior -> contributes to U(theta)
beta ~ normal(0, 5);
y ~ normal(alpha + beta * x, sigma); // likelihood
}
# --- CmdStanPy (recommended) ---
from cmdstanpy import CmdStanModel
model = CmdStanModel(stan_file="model.stan") # transpile + compile to C++/binary
fit = model.sample(data=data_dict,
chains=4, iter_warmup=1000, iter_sampling=1000,
adapt_delta=0.9) # target accept rate for step-size adaptation
print(fit.diagnose()) # divergences, E-BFMI, R-hat, ESS
draws = fit.draws_pd() # posterior samples as a DataFrame
# --- CmdStan CLI (equivalent, no Python) ---
$ ./model sample num_warmup=1000 num_samples=1000 \
adapt delta=0.9 data file=data.json output file=out.csv
