Content-Based Filtering

Recommending items by matching item features to a user's own taste profile
Foundational Recommender Systems Information Retrieval O(n·d) per query
1
Understanding Content-Based Filtering
▼

What is it? Content-based filtering recommends items by comparing their features (genre tags, keywords, descriptions, specs) against a profile that represents what a specific user likes. Unlike collaborative filtering, it never needs other users' behavior — it only needs the item's own content and this one user's history.

Analogy: Imagine a librarian who reads the back cover of every book you've ever loved, writes down the recurring themes ("space battles", "witty banter", "found family"), and then walks the shelves looking for the next book whose back cover matches that theme list most closely. No other patron's checkout history is consulted at all.

💡 If you remember one thing

Every item becomes a numeric feature vector (often via TF-IDF over its text/tags). Every user becomes a vector too — a rating-weighted average of the vectors of items they liked. Recommending is just: rank items by cosine similarity to the user's profile vector. $$\text{score}(u, i) = \cos(\vec{p}_u, \vec{v}_i) = \frac{\vec{p}_u \cdot \vec{v}_i}{\lVert \vec{p}_u \rVert \, \lVert \vec{v}_i \rVert}$$

How It Works Internally
▼

Step 1 — Turn items into feature vectors

Each item has a bag of terms (genre tags, plot keywords, ingredients, specs). We build a vocabulary across the whole catalog and score every (item, term) pair with TF-IDF: term frequency rewards terms that dominate this item's description; inverse document frequency penalises terms so common across the catalog that they carry no discriminating signal (e.g. "movie", "story").

Step 2 — Turn the user into a feature vector

The user profile is built purely from items the user has already rated or engaged with — no other users involved. It is typically a rating-weighted average of the liked items' feature vectors:

$$\vec{p}_u = \frac{\sum_{i \in \text{liked}(u)} r_{u,i}\, \vec{v}_i}{\sum_{i \in \text{liked}(u)} r_{u,i}}$$

The profile literally lives in the same vector space as the items — it is the "average taste direction" the user has shown so far.

Step 3 — Rank unseen items by similarity

For every item the user hasn't interacted with, compute the cosine of the angle between the user profile vector and the item vector. Cosine similarity ignores vector length (which mostly reflects how much text an item has) and only cares about direction — i.e., whether the same terms dominate both vectors.

🔑 Key Property

Content-based filtering needs zero data from other users. A brand-new item can be recommended the instant its features are known ("item cold start" solved), and a user's recommendations update the moment they rate one more thing — no retraining, no waiting for the crowd.

3
Why It Works — The Math
▼

TF-IDF weighting

For term \(t\) in item \(d\), with catalog of \(N\) items and document frequency \(\text{df}(t)\) (number of items containing \(t\)):

$$\text{tf}(t,d) = \frac{\text{count}(t,d)}{\sum_{t' \in d} \text{count}(t',d)} \qquad \text{idf}(t) = \ln\!\left(\frac{N}{\text{df}(t)}\right) \qquad \text{tfidf}(t,d) = \text{tf}(t,d)\cdot \text{idf}(t)$$

An item's feature vector \(\vec{v}_d\) stacks \(\text{tfidf}(t,d)\) across every term \(t\) in the vocabulary. Rare, distinctive terms get amplified; terms in every item shrink toward zero because \(\ln(N/N) = 0\).

Cosine similarity — why not Euclidean distance?

Two item descriptions about the same topic but of very different lengths produce vectors of very different magnitude but similar direction. Euclidean distance would penalize the longer one; cosine similarity normalizes both vectors to unit length before comparing, so only the angle between them matters:

$$\cos(\theta) = \frac{\vec{p}_u \cdot \vec{v}_i}{\lVert \vec{p}_u \rVert\,\lVert \vec{v}_i \rVert} = \frac{\sum_k p_{u,k}\,v_{i,k}}{\sqrt{\sum_k p_{u,k}^2}\,\sqrt{\sum_k v_{i,k}^2}} \in [0,1]\ \text{for non-negative TF-IDF vectors}$$

\(\cos\theta = 1\) means the profile and item point in exactly the same direction (perfect topical match); \(\cos\theta = 0\) means they share no weighted terms at all (orthogonal, i.e. no overlap in vocabulary).

⚠️ Common Pitfall

Content-based filtering can only recommend items that are similar to what the user already liked — it has no mechanism for serendipity or discovering taste the user hasn't expressed yet. This "filter bubble" / overspecialization problem is the classic weakness versus collaborative filtering, which can surface items liked by similar users even if their content looks nothing alike.

Key Takeaways
▼

When to use content-based filtering:

  • Rich item metadata / text exists (articles, products with specs, movies with genres)
  • New items must be recommendable immediately (item cold start)
  • Explainability matters — "recommended because it shares tags with X" is easy to justify
  • User base is small or interactions are sparse, so user-user or item-item collaborative signal is weak

When NOT to use (or to combine with something else):

  • Item features are thin or uninformative — TF-IDF vectors collapse and everything looks similar
  • You want serendipity/discovery beyond the user's expressed taste — collaborative filtering fills this gap
  • New users with zero history (user cold start) — profile vector is undefined until they rate something
💡 Hierarchy

Most production systems run hybrid recommenders: content-based features solve item cold-start and explainability, collaborative signals solve overspecialization — combined via a weighted blend, a re-ranker, or as extra features into a learned ranking model.

Code Trace

import numpy as np
# Vocabulary + raw tag counts per item
vocab = ["space", "action", "robot", "love", "comedy"]
items = {
"Galaxy Wars": [3, 2, 1, 0, 0],
"Robo Love": [0, 1, 3, 2, 0],
"Funny Nights": [0, 0, 0, 1, 3],
"Star Combat": [2, 3, 0, 0, 0],
"Romance Comedy":[0, 0, 0, 2, 2],
}
# TF: normalize counts within each item
def tf(counts):
total = sum(counts)
return [c / total for c in counts]
# IDF: rarer terms across the catalog score higher
N = len(items)
df = np.sum([[1 if c > 0 else 0 for c in v] for v in items.values()], axis=0)
idf = np.log(N / df)
# TF-IDF feature vector per item
vectors = {name: np.array(tf(c)) * idf for name, c in items.items()}
# User profile = rating-weighted average of liked items
liked = {"Galaxy Wars": 5, "Robo Love": 3}
w = np.array(list(liked.values()), dtype=float)
profile = sum(w[i] * vectors[n] for i, n in enumerate(liked)) / w.sum()
# Cosine similarity ranking over unseen items
def cosine(a, b):
return a @ b / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-9)
candidates = ["Funny Nights", "Star Combat", "Romance Comedy"]
ranked = sorted(candidates, key=lambda n: -cosine(profile, vectors[n]))
print(ranked) # top hit: "Star Combat" (shares sci-fi vocabulary)
