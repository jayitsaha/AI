N-gram Language Models

Predicting the next word from the last n−1 words — counting, not learning
Foundational NLP Language Modeling O(1) lookup
1
Understanding N-gram Models
▼

What is it? An n-gram language model predicts the next word in a sentence by looking only at the previous \(n-1\) words, and answers the question purely by counting how often word sequences appeared in a training corpus. No neural network, no gradient descent — just tallying.

Analogy: Imagine you've read thousands of sentences and, without understanding grammar at all, you notice that whenever you see the words "peanut butter and", the next word is almost always "jelly". An n-gram model is exactly this: a giant lookup table of "after seeing these last few words, here's what usually comes next," built by brute-force counting.

💡 If you remember one thing

An n-gram model makes the Markov assumption — the probability of the next word depends only on the last \(n-1\) words, not the entire history: $$P(w_i \mid w_1, \dots, w_{i-1}) \approx P(w_i \mid w_{i-n+1}, \dots, w_{i-1})$$ This turns an intractable problem (conditioning on unbounded history) into a finite counting problem.

How N-gram Models Work Internally
▼

Step 1: Tokenize and Pad

Every training sentence is split into tokens and padded with \(n-1\) start-of-sentence markers \(\langle s \rangle\) and one end marker \(\langle /s \rangle\). Padding lets the model assign a probability to the very first real word, and lets it learn when a sentence should end.

Step 2: Count Every Window

A window of size \(n\) slides across each padded sentence. For each position, the last \(n-1\) tokens form the context and the current token is the target. Two count tables are built: \(C(\text{context})\) — how often that context appeared — and \(C(\text{context}, w)\) — how often that context was followed specifically by word \(w\).

Step 3: Convert Counts to Probabilities (MLE)

The maximum-likelihood estimate simply divides the joint count by the context count. If "the cat" was seen 5 times and followed by "sat" 3 of those times, then \(P(\text{sat} \mid \text{the cat}) = 3/5\).

Design Decision: Why not condition on the full history?

Conditioning on all previous words would require a probability table with one entry per possible sentence prefix — infinite and never fully observed. Truncating to \(n-1\) words trades long-range accuracy for a finite, estimable table. Bigrams (\(n=2\)) and trigrams (\(n=3\)) are the classic sweet spots: enough context to capture local syntax, few enough parameters to estimate from a modest corpus.

🔑 Key Property

Larger \(n\) captures more context but the number of distinct contexts grows roughly as \(|V|^{n-1}\) — most of them will be seen rarely or never in any finite corpus. This is the central bias–variance trade-off of n-gram modeling.

3
Why It Works — The Math
▼

Chain Rule + Markov Assumption

Any joint sentence probability factors exactly by the chain rule of probability:

$$P(w_1,\dots,w_m) = \prod_{i=1}^{m} P(w_i \mid w_1,\dots,w_{i-1})$$

The Markov assumption truncates each conditional to a fixed window, giving the n-gram approximation:

$$P(w_1,\dots,w_m) \approx \prod_{i=1}^{m} P(w_i \mid w_{i-n+1},\dots,w_{i-1})$$

Maximum Likelihood Estimation

Each conditional is estimated by relative frequency, which is provably the maximum-likelihood estimator under a categorical/multinomial model of "what follows this context":

$$\hat{P}(w_i \mid w_{i-n+1}^{i-1}) = \frac{C(w_{i-n+1}^{i-1}, w_i)}{C(w_{i-n+1}^{i-1})}$$

The Zero-Count Problem & Add-k Smoothing

If a context/word pair never appeared in training, MLE assigns it probability exactly 0 — and since sentence probability is a product, one zero anywhere makes the whole sentence probability zero. Add-k (Laplace-style) smoothing fixes this by pretending every word in the vocabulary \(V\) was seen \(k\) extra times:

$$P_{\text{add-}k}(w_i \mid \text{ctx}) = \frac{C(\text{ctx}, w_i) + k}{C(\text{ctx}) + k|V|}$$

As \(k \to 0\) this reduces to MLE; as \(k\) grows, probabilities are pulled toward the uniform distribution \(1/|V|\).

Evaluating a Model: Perplexity

Perplexity measures how "surprised" the model is by held-out text — lower is better. It is the inverse probability of the test set, normalized by length \(N\):

$$PP(W) = P(w_1,\dots,w_N)^{-1/N} = \sqrt[N]{\prod_{i=1}^{N} \frac{1}{\hat{P}(w_i \mid w_{i-n+1}^{i-1})}}$$
⚠️ Common Pitfall

A higher-order n-gram (larger \(n\)) almost always has lower perplexity on training data but can have higher perplexity on unseen data — this is overfitting via data sparsity. Smoothing and back-off/interpolation with lower-order models are essential in practice.

Key Takeaways
▼

When to use n-gram models:

  • Fast, interpretable baselines for spelling correction, autocomplete, and OCR/ASR re-ranking
  • Low-resource settings where a neural model can't be trained or deployed
  • As a component in back-off/interpolation systems (e.g. KenLM) for latency-critical language modeling

When NOT to use:

  • Tasks needing long-range dependencies beyond a few words — n-grams are structurally blind to anything outside the window
  • Large open vocabularies without smoothing/back-off — sparsity dominates and most contexts are unseen
  • Anywhere a Transformer/RNN language model is feasible — they dominate on perplexity and generalization
💡 Historical Thread

N-grams (Markov 1913, Shannon 1948) were the dominant language modeling paradigm for decades — powering early speech recognition and machine translation — until neural language models (RNNs, then Transformers) overtook them in the 2010s by learning distributed representations instead of counting discrete sequences.

from collections import defaultdict
def train_ngram(sentences, n, k=0.0):
context_counts = defaultdict(int)
ngram_counts = defaultdict(int)
vocab = set()
for sent in sentences:
toks = ['<s>']*(n-1) + sent.split() + ['</s>']
vocab.update(toks)
for i in range(n-1, len(toks)):
ctx = tuple(toks[i-(n-1):i])
w = toks[i]
context_counts[ctx] += 1
ngram_counts[(ctx, w)] += 1
V = len(vocab)
def prob(ctx, w):
return (ngram_counts[(ctx, w)] + k) / (context_counts[ctx] + k*V)
return prob, vocab, context_counts, ngram_counts
def generate(prob, vocab, n, max_len=10):
ctx = tuple(['<s>']*(n-1))
out = []
for _ in range(max_len):
w = max(vocab, key=lambda v: prob(ctx, v)) # argmax next word
if w == '</s>': break
out.append(w)
ctx = (ctx + (w,))[-(n-1):] if n > 1 else ctx
return ' '.join(out)
def perplexity(prob, sentence, n):
toks = ['<s>']*(n-1) + sentence.split() + ['</s>']
logp, N = 0.0, 0
for i in range(n-1, len(toks)):
ctx = tuple(toks[i-(n-1):i])
p = max(prob(ctx, toks[i]), 1e-12)
logp += -1 * __import__('math').log(p)
N += 1
return __import__('math').exp(logp / N)
