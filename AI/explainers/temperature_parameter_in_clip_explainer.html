Temperature in CLIP: The Learned Logit Scale

A single trainable scalar that decides how sharply CLIP's contrastive softmax judges "match" vs "no match"
Advanced Multimodal Contrastive Learning O(N²) per batch
1
Understanding the Logit Scale
▼

What is it? CLIP scores an image against a piece of text by taking the cosine similarity of their two embeddings — a number squeezed into \([-1, 1]\). That range is far too narrow to feed directly into a softmax classifier: the differences between "correct pair" and "wrong pair" are tiny (like 0.35 vs 0.10), so a plain softmax over raw cosine similarities barely distinguishes right from wrong. CLIP fixes this with one extra trainable number, the logit scale \(s = \exp(t)\), that multiplies every similarity before the softmax: \(\text{logit}_{ij} = s \cdot \cos(\mathbf{i}_i, \mathbf{t}_j)\).

Analogy: Imagine grading photos as "matches the caption" on a scale from -1 to 1, but everyone's scores cluster around 0.1–0.4 — too close together to tell a strong match from a weak one. The logit scale is like handing the grader a magnifying glass: it stretches those tiny gaps into a wide range (e.g. -30 to +40) so the eventual "pick the best match" decision (softmax) becomes confident and decisive, instead of a shrug.

💡 If you remember one thing

CLIP does not fix a temperature by hand — it learns \(t\) by gradient descent, initialized so \(s=\exp(t)\approx 14.3\) (i.e. \(t = \ln(1/0.07)\)), and clamps \(s\) to at most \(100\) after every optimizer step so training can't blow up: $$\text{logits} = \text{clamp}(\exp(t),\, \max{=}100)\cdot \left(\hat{\mathbf{i}}^\top \hat{\mathbf{t}}\right)$$

How It Works Internally
▼

From Embeddings to a Similarity Matrix

For a batch of \(N\) image–text pairs, CLIP's image encoder and text encoder each produce an embedding, which is then L2-normalized: \(\hat{\mathbf{i}}_k = \mathbf{i}_k / \|\mathbf{i}_k\|_2\), likewise for \(\hat{\mathbf{t}}_k\). Because both vectors sit on the unit hypersphere, their dot product is exactly the cosine similarity, bounded in \([-1,1]\). Stacking all pairs gives an \(N\times N\) similarity matrix \(C\) where \(C_{ij} = \hat{\mathbf{i}}_i^\top \hat{\mathbf{t}}_j\); the diagonal holds the "correct" pairs from the batch.

The Learned Scalar \(t\)

CLIP stores a single trainable scalar \(t\) (a raw, unconstrained parameter — an ordinary nn.Parameter) and always uses it through \(s=\exp(t)\), never \(t\) directly. Working in log-space guarantees \(s>0\) with no explicit positivity constraint needed in the optimizer, and produces smooth multiplicative updates: a fixed additive step in \(t\) becomes a proportional (percentage) change in \(s\). The logits fed to cross-entropy are \(L_{ij} = s\cdot C_{ij}\).

Design Decision: Learned vs. Fixed Temperature

Earlier contrastive/metric-learning methods (e.g. NT-Xent in SimCLR, InstDisc) fixed the temperature as a hand-tuned hyperparameter, requiring a costly sweep. CLIP's authors instead let \(t\) be optimized jointly with the network weights via the same gradient descent — it converges to a value the model itself finds useful, removing an entire hyperparameter search dimension while typically reaching a sharper optimum than any single fixed guess.

🔑 Key Property

The logit scale is clamped, not just initialized. After each optimizer step, CLIP applies \(t \leftarrow \min(t,\, \ln 100)\), i.e. caps \(s=\exp(t)\) at 100. Without this cap, \(t\) can run away during early training (when the model is confidently wrong), causing enormous gradients and destabilizing the whole encoder.

3
Why It Works — The Math of Gradient Sharpness
▼

Symmetric InfoNCE Loss

CLIP applies softmax cross-entropy in both directions over the scaled similarity matrix — image-to-text rows and text-to-image columns — and averages them:

$$\mathcal{L} = \tfrac{1}{2}\Big[\underbrace{-\tfrac{1}{N}\sum_i \log \frac{e^{sC_{ii}}}{\sum_j e^{sC_{ij}}}}_{\text{image}\to\text{text}} + \underbrace{-\tfrac{1}{N}\sum_j \log \frac{e^{sC_{jj}}}{\sum_i e^{sC_{ij}}}}_{\text{text}\to\text{image}}\Big]$$

Gradient Through the Softmax

Let \(p_{ij}=\text{softmax}_j(sC_{i,:})_j\). For row \(i\) with label \(j{=}i\), the gradient of cross-entropy with respect to the logit is the classic softmax-minus-one-hot form:

$$\frac{\partial \mathcal{L}_i}{\partial L_{ij}} = p_{ij} - \mathbb{1}[j=i] \quad\Longrightarrow\quad \frac{\partial \mathcal{L}_i}{\partial C_{ij}} = s\,(p_{ij} - \mathbb{1}[j=i])$$

This is the crux of "gradient sharpness": the scale \(s\) is a multiplicative factor on every similarity gradient. But \(s\) also sits inside \(p_{ij}\), so its effect is nonlinear. As \(s\to\infty\), \(p_{ii}\to 1\) and \(p_{ij\ne i}\to 0\): the gradient on the correct pair \((p_{ii}-1)\to 0\) and on every wrong pair \(p_{ij}\to 0\) too — the loss saturates and gradients vanish everywhere, even though the model may still be somewhat wrong. As \(s\to 0\), all \(p_{ij}\to 1/N\) (uniform): the loss is high and roughly constant, but the gradient signal that distinguishes "which pair is correct" is also washed out because every off-diagonal residual is nearly identical.

📐 Sweet Spot

The useful regime is where \(s\) is large enough to make \(p_{ii}\) meaningfully bigger than \(p_{ij\ne i}\) (informative ranking) but small enough that \(p_{ii} \ll 1\) so \((p_{ii}-1)\) still carries real gradient. This is exactly why \(s\) is learned rather than fixed at an extreme — training naturally seeks this sweet spot and the clamp at 100 prevents it from overshooting into the saturated, vanishing-gradient regime.

⚠️ Common Pitfall

"Higher temperature is always better for discrimination" is a misconception. Too high \(s\) makes the softmax nearly one-hot on whatever the model currently believes is correct — including confidently wrong early answers — which can amplify noise and cause collapse. That is precisely why CLIP hard-clamps \(s \le 100\) instead of leaving it unconstrained.

Key Takeaways
▼

When the logit scale matters:

  • Any contrastive / InfoNCE-style objective on normalized embeddings (CLIP, SigLIP, ALIGN, SimCLR-family) — the similarity range is always too narrow for raw softmax
  • Whenever a hyperparameter search over a fixed temperature would be expensive — make it learnable instead
  • Large-batch training where too few "hard negatives" would otherwise make the softmax indifferent

Watch out for:

  • Unclamped scale exploding early in training (model confidently wrong ⇒ huge gradients ⇒ divergence)
  • Scale saturating near the clamp too early — probabilities near one-hot, gradients vanish, embeddings stop improving
  • Comparing loss values across runs with different final \(s\) — the loss scale itself is not comparable, only relative ranking / retrieval metrics are
💡 Big Picture

Temperature is not a decoration on softmax — it is what turns a bounded, low-contrast similarity score into a well-scaled classification logit. CLIP's contribution is simply to stop guessing that number and let backpropagation find it, subject to one safety rail: clamp(s, max=100).

Code Trace
▼
import torch, torch.nn.functional as F
# Learned logit scale, stored in log-space
logit_scale = torch.nn.Parameter(torch.log(torch.tensor(1/0.07))) # t0 ≈ 2.659
def clip_loss(image_embeds, text_embeds, logit_scale):
# 1. L2-normalize onto the unit hypersphere
img = F.normalize(image_embeds, dim=-1)
txt = F.normalize(text_embeds, dim=-1)
# 2. Cosine similarity matrix, C in [-1, 1]
C = img @ txt.t()
# 3. Scale logits by the learned, exponentiated temperature
scale = logit_scale.exp()
logits = scale * C
# 4. Symmetric cross-entropy against the diagonal labels
labels = torch.arange(C.size(0), device=C.device)
loss_i2t = F.cross_entropy(logits, labels)
loss_t2i = F.cross_entropy(logits.t(), labels)
return (loss_i2t + loss_t2i) / 2
# After every optimizer.step(): clamp so exp(t) never exceeds 100
with torch.no_grad():
logit_scale.clamp_(max=torch.log(torch.tensor(100.0)))
