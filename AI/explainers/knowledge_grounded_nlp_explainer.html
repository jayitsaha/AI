Integrating external knowledge into language models for factual reasoning and enhanced understanding

Understanding Knowledge-grounded NLP
▼

What is it? Traditional pre-trained language models (PLMs) like BERT and GPT learn vast amounts of implicit knowledge from text corpora. However, this knowledge is often shallow, lacks explicit factual connections, and struggles with rare entities or complex reasoning. Knowledge-grounded NLP aims to explicitly inject structured knowledge, typically from knowledge graphs (KGs), into PLMs to enhance their understanding, factual consistency, and reasoning capabilities.

Why is it important? For tasks requiring precise factual recall (e.g., question answering), entity relation extraction, or commonsense reasoning, relying solely on patterns learned from raw text can be insufficient. By grounding language models with external knowledge, we can mitigate issues like hallucination, improve interpretability, and enable models to reason over explicit facts rather than just statistical correlations.

💡 If you remember one thing

Knowledge-grounded models enrich standard token embeddings with explicit entity and relation information from knowledge graphs. This fusion can happen at various stages: at the input layer (ERNIE, K-BERT), during attention (KG-BERT), or by pre-learning knowledge graph representations (KGAT) that are then integrated.

2
How Knowledge is Integrated (ERNIE, K-BERT)
▼

The Challenge: Bridging Text and Graphs

The core challenge is how to effectively combine the continuous, sequential representations of text with the discrete, relational structures of knowledge graphs. Different models propose different strategies for this "knowledge injection":

  • Entity Alignment/Linking: The first step is to identify mentions of entities in the text and link them to corresponding nodes in a knowledge graph. This typically involves named entity recognition (NER) followed by entity disambiguation.
  • Knowledge Graph Embedding (KGE): Knowledge graphs are often too large and sparse to be used directly. KGE models (e.g., TransE, DistMult, RotatE) learn low-dimensional vector representations (embeddings) for entities and relations, capturing their semantic properties and relationships.

ERNIE (Enhanced Representation through kNowledge IntEgration)

Baidu's ERNIE (Sun et al., 2019) focuses on integrating entity-level knowledge. After entity linking, it fuses the contextual token embeddings from a BERT-like encoder with pre-trained entity embeddings (obtained from a KG embedding model). This fusion happens at the input layer, often through concatenation and a linear projection, or a more sophisticated attention mechanism. The model is then fine-tuned on knowledge-masked language modeling tasks, where it predicts masked entities based on context and knowledge.

K-BERT (Knowledge-enhanced BERT)

K-BERT (Liu et al., 2019) takes a different approach by directly injecting knowledge triplets into the input sequence. For each entity identified in the text, relevant triplets (e.g., (subject, relation, object)) are extracted from the KG. These triplets are then linearized into "knowledge sentences" (e.g., "subject [SEP] relation [SEP] object") and appended to the original text sequence. To manage the expanded input and prevent irrelevant interactions, K-BERT uses a special "knowledge attention mask" that restricts which tokens can attend to which others, ensuring knowledge is used to ground entities without overwhelming the core text understanding.

KGAT (Knowledge Graph Attention Network)

While ERNIE and K-BERT focus on injecting knowledge into a transformer, KGAT (Wang et al., 2019) is a powerful example of a graph neural network (GNN) that learns rich entity and relation embeddings directly from the knowledge graph. It recursively propagates embedding information across multi-hop neighbors in the KG, using an attention mechanism to weigh the importance of different neighbors and relations. These refined entity embeddings can then be used as input features for various downstream NLP tasks, either by concatenating them with token embeddings or by using them to initialize entity representations in a PLM.

🔑 Key Property

The core idea is to move beyond implicit knowledge learned from text-only pre-training. By providing explicit, structured facts from KGs, these models aim to achieve more robust, interpretable, and factually consistent understanding, especially for domain-specific or long-tail entities.

3
Why It Works — The Mathematical Basis
▼

BERT's Standard Input Representation

Before knowledge injection, a standard BERT-like model constructs its input embedding for a token \(t_i\) by summing three components:

$$E_i^{\text{BERT}} = E_{token}(t_i) + E_{position}(p_i) + E_{segment}(s_i)$$

where \(E_{token}\) is the token embedding, \(E_{position}\) is the positional embedding, and \(E_{segment}\) is for distinguishing sentences in a pair. Knowledge-grounded models modify this base representation.

ERNIE's Knowledge Fusion

ERNIE introduces an additional entity embedding \(E_{entity}(e_j)\) for each entity mention \(e_j\) found in the text. For tokens corresponding to an entity, this entity embedding is fused with the standard token embedding. A common fusion strategy is concatenation followed by a linear transformation:

$$E_i^{\text{ERNIE}} = \text{LayerNorm}(\text{ReLU}(W_1[E_{token}(t_i); E_{entity}(e_j)] + b_1)) \quad \text{if } t_i \text{ is part of } e_j$$

Otherwise, for non-entity tokens, it reverts to the standard BERT input. This allows the model to learn a joint representation that captures both the lexical meaning and the structured factual knowledge associated with an entity. The knowledge masking objective during pre-training further forces the model to leverage this fused information.

K-BERT's Knowledge Graph Embedding Layer

K-BERT's approach of injecting knowledge triplets as "knowledge sentences" effectively creates a "knowledge layer" in the input. For an original sentence with tokens \(T = [t_1, \dots, t_N]\) and extracted knowledge triplets \(K = [k_1, \dots, k_M]\), the input sequence becomes \(S' = [CLS, T, SEP, k_1, SEP, \dots, k_M, SEP]\). The embeddings for this extended sequence are then fed into a BERT encoder. The crucial part is the attention mask, which defines how tokens interact:

$$M_{ij} = \begin{cases} 1 & \text{if } t_i, t_j \in T \text{ or } (t_i \in T \text{ and } t_j \in k_m \text{ for relevant } k_m) \\ 0 & \text{otherwise} \end{cases}$$

This mask is designed to allow text tokens to attend to knowledge tokens that are relevant to their entities, but typically prevents knowledge tokens from attending to unrelated text or other knowledge triplets, reducing noise and focusing the grounding effect.

⚠️ Common Pitfall

The performance of knowledge-grounded models heavily relies on the quality of the external knowledge graph and the entity linking process. Errors or incompleteness in the KG, or incorrect entity linking, can introduce noise and degrade model performance, potentially making it worse than a vanilla PLM.

Key Takeaways
▼

When to use Knowledge-grounded NLP:

  • Factual Question Answering: When precise answers requiring external facts are crucial.
  • Entity-centric Tasks: For tasks like relation extraction, entity typing, or knowledge graph completion.
  • Low-resource Languages/Domains: KGs can provide a rich source of structured information where text corpora are scarce.
  • Mitigating Hallucination: To reduce models generating factually incorrect information.

When to be cautious:

  • KG Quality: Performance is bottlenecked by the completeness and accuracy of the underlying knowledge graph.
  • Entity Linking Errors: Mis-linking entities can introduce noise and degrade performance.
  • Computational Overhead: Entity linking, KG embedding, and constructing augmented inputs add computational cost.
  • General Text Understanding: For tasks that rely heavily on pure linguistic patterns (e.g., sentiment analysis on opinionated text), explicit knowledge might offer diminishing returns or even distract.
💡 Future Directions

The field is moving towards more sophisticated ways of dynamically retrieving and integrating knowledge, often beyond just the input layer. This includes hybrid architectures that combine PLMs with graph neural networks, or models that learn to query KGs during inference. The goal remains to combine the strengths of statistical language modeling with the precision of structured knowledge.

import torch
from transformers import AutoTokenizer, AutoModel
import numpy as np
# --- 1. Setup: Tokenizer, Language Model, and Mock KG Embeddings ---
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased")
# Mock KG embeddings (e.g., from TransE, RotatE)
# For simplicity, assume entity_to_id and entity_embeddings exist
entity_embeddings = torch.randn(100, model.config.hidden_size) # 100 entities, 768 dim
entity_to_id = {"Tim Cook": 0, "iPhone": 1, "Apple Park": 2, "Apple": 3, "Cupertino": 4, "CEO_OF": 5, "PRODUCT_OF": 6, "LOCATED_IN": 7}
# Sample sentence and entity linking (mocked)
sentence = "Tim Cook announced the new iPhone at Apple Park."
# Linked entities: (text_span, kg_entity_name, token_start_idx, token_end_idx)
linked_entities = [
("Tim Cook", "Tim Cook", 1, 2), # Tokens: [CLS], Tim, Cook, announced...
("iPhone", "iPhone", 6, 6),
("Apple Park", "Apple Park", 8, 9)
]
# --- 2. ERNIE-like Input Construction ---
def get_ernie_input_embeddings(sentence, linked_entities, tokenizer, model, entity_embeddings, entity_to_id):
inputs = tokenizer(sentence, return_tensors="pt", add_special_tokens=True)
token_embeddings = model.embeddings.word_embeddings(inputs.input_ids)
position_embeddings = model.embeddings.position_embeddings(inputs.position_ids)
segment_embeddings = model.embeddings.token_type_embeddings(inputs.token_type_ids)
# Start with vanilla BERT input embeddings
ernie_input_embeddings = token_embeddings + position_embeddings + segment_embeddings
# Fuse entity embeddings for recognized entities
for _, kg_entity_name, start_idx, end_idx in linked_entities:
if kg_entity_name in entity_to_id:
entity_id = entity_to_id[kg_entity_name]
e_embed = entity_embeddings[entity_id].unsqueeze(0).unsqueeze(0) # [1,1,H]
# Fusion: for simplicity, let's just add (more complex fusion like concat+linear is typical)
# In a real ERNIE, there's a linear layer after concat: W[token;entity] + b
for i in range(start_idx, end_idx + 1):
ernie_input_embeddings[0, i] = ernie_input_embeddings[0, i] + e_embed
return ernie_input_embeddings
# --- 3. K-BERT-like Input Construction ---
# Mock Knowledge Graph (triplets)
kg_triplets = {
"Tim Cook": [("Tim Cook", "CEO_OF", "Apple")],
"iPhone": [("iPhone", "PRODUCT_OF", "Apple"), ("iPhone", "RELEASED_YEAR", "2007")],
"Apple Park": [("Apple Park", "LOCATED_IN", "Cupertino"), ("Apple Park", "BUILT_BY", "Apple")]
}
def get_kbert_input(sentence, linked_entities, kg_triplets, tokenizer, max_knowledge_triplets=1):
original_tokens = tokenizer.tokenize(sentence)
# Add special tokens for BERT input format
input_tokens = [tokenizer.cls_token] + original_tokens + [tokenizer.sep_token]
token_type_ids = [0] * len(input_tokens)
knowledge_tokens = []
knowledge_type_ids = []
knowledge_mask = [] # 1 for original, 0 for knowledge
current_knowledge_count = 0
for _, kg_entity_name, _, _ in linked_entities:
if kg_entity_name in kg_triplets and current_knowledge_count < max_knowledge_triplets:
for s, r, o in kg_triplets[kg_entity_name]:
if current_knowledge_count >= max_knowledge_triplets: break
# Linearize triplet: [SEP] Subject [SEP] Relation [SEP] Object [SEP]
triplet_tokens = [tokenizer.sep_token] + tokenizer.tokenize(s) + \
[tokenizer.sep_token] + tokenizer.tokenize(r) + \
[tokenizer.sep_token] + tokenizer.tokenize(o) + \
[tokenizer.sep_token]
knowledge_tokens.extend(triplet_tokens)
knowledge_type_ids.extend([1] * len(triplet_tokens)) # Segment ID 1 for knowledge
knowledge_mask.extend([0] * len(triplet_tokens)) # Mask out knowledge tokens for self-attention
current_knowledge_count += 1
if current_knowledge_count >= max_knowledge_triplets: break
final_input_tokens = input_tokens + knowledge_tokens
final_token_type_ids = token_type_ids + knowledge_type_ids
# K-BERT specific attention mask: 1 for original text, 0 for knowledge tokens
attention_mask = [1] * len(input_tokens) + knowledge_mask
return final_input_tokens, final_token_type_ids, attention_mask
