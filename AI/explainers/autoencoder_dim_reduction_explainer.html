Autoencoders for Dimensionality Reduction

Learning compact, nonlinear representations by bottlenecking information flow

Intermediate Unsupervised Learning Deep Learning O(n·d·k) training
1
Understanding the Concept

What is this? An autoencoder is a neural network trained to copy its input to its output — but with a twist: it must pass the data through a narrow "bottleneck" in the middle. Because information is squeezed through fewer numbers, the network is forced to discover the most important structure in the data. The bottleneck values are called the latent code or latent representation.

Real-world analogy: Imagine trying to describe a high-resolution photo to a friend using only 10 words, who then recreates it from your description. You'll choose only the most essential features — dominant colours, main shapes, overall mood. That 10-word summary is the latent code. The compression forces you to find what matters.

💡 If you remember one thing

An autoencoder learns a bottleneck representation not by being told what matters, but by being forced to reconstruct the input. The reconstruction pressure discovers structure automatically — no labels needed.

Linear vs nonlinear: If the encoder and decoder use only linear transformations with no activation functions, the autoencoder's bottleneck is mathematically equivalent to PCA — it finds the same principal subspace. With nonlinear activations (ReLU, tanh, etc.), the bottleneck can encode curved structure (manifolds) that PCA cannot capture.

2
How It Works Internally

An autoencoder has two halves: the encoder \(f_\phi\) maps input \(\mathbf{x} \in \mathbb{R}^d\) to a latent code \(\mathbf{z} \in \mathbb{R}^k\) (with \(k \ll d\)); the decoder \(g_\theta\) maps \(\mathbf{z}\) back to a reconstruction \(\hat{\mathbf{x}} \in \mathbb{R}^d\). Both are trained jointly to minimise reconstruction error.

$$\mathbf{z} = f_\phi(\mathbf{x}), \quad \hat{\mathbf{x}} = g_\theta(\mathbf{z}), \quad \mathcal{L} = \|\mathbf{x} - \hat{\mathbf{x}}\|_2^2$$

Information flow (numerical trace): Suppose \(\mathbf{x} \in \mathbb{R}^4\) and the bottleneck is \(k=2\).

  • Input: \(\mathbf{x} = [1.2,\ -0.5,\ 0.8,\ 2.1]\)
  • Encoder layer: \(\mathbf{h} = \text{ReLU}(W_1 \mathbf{x} + b_1) \in \mathbb{R}^3\) → e.g. \([0.9,\ 0.0,\ 1.4]\)
  • Bottleneck: \(\mathbf{z} = W_2 \mathbf{h} + b_2 \in \mathbb{R}^2\) → e.g. \([0.62,\ -0.31]\)
  • Decoder: \(\hat{\mathbf{x}} = g_\theta(\mathbf{z})\) → e.g. \([1.18,\ -0.48,\ 0.81,\ 2.09]\)
  • Loss: \(\mathcal{L} = (1.2-1.18)^2 + (-0.5+0.48)^2 + (0.8-0.81)^2 + (2.1-2.09)^2 = 0.0010\)
Key Invariant

The bottleneck dimension \(k\) is the only constraint that forces compression. Without it, the network would learn the identity function trivially. Choosing \(k\) controls the trade-off between fidelity and compression.

Why not just use PCA? PCA finds the best linear subspace — it can only capture flat structure. Autoencoders with nonlinear activations can learn the best curved subspace (manifold), capturing structure like the Swiss roll that PCA destroys by projecting onto a flat plane.

3
The Math — Why It Works

Loss function — for continuous inputs, MSE reconstruction loss:

$$\mathcal{L}(\phi, \theta) = \frac{1}{N}\sum_{i=1}^{N} \|\mathbf{x}^{(i)} - g_\theta(f_\phi(\mathbf{x}^{(i)}))\|_2^2$$

For binary inputs (images with pixel ∈ {0,1}), use binary cross-entropy:

$$\mathcal{L} = -\frac{1}{N}\sum_{i=1}^{N}\sum_{j=1}^{d}\left[x_j^{(i)}\log\hat{x}_j^{(i)} + (1-x_j^{(i)})\log(1-\hat{x}_j^{(i)})\right]$$

Linear autoencoder = PCA (proof sketch): With a single linear encoder \(\mathbf{z} = W_e\mathbf{x}\) and linear decoder \(\hat{\mathbf{x}} = W_d\mathbf{z}\), the optimal \(W_e\) and \(W_d\) satisfying \(\min \mathbb{E}[\|\mathbf{x} - W_dW_e\mathbf{x}\|^2]\) have columns of \(W_d\) that span the same subspace as the top-\(k\) eigenvectors of the data covariance matrix \(\Sigma = \mathbb{E}[\mathbf{x}\mathbf{x}^\top]\). The eigenvalue decomposition \(\Sigma = V\Lambda V^\top\) gives the principal components \(\{v_1,\ldots,v_k\}\) as optimal basis — identical to PCA.

⚠️ Common Misconception

Autoencoders do not explicitly learn a probabilistic model of the data. The latent space has no guaranteed structure — codes for different inputs can be scattered arbitrarily. This is why generating new samples by sampling from the latent space of a vanilla autoencoder produces garbage. VAEs fix this by adding a KL-divergence regulariser.

Gradient flow: By the chain rule, gradients flow from reconstruction loss back through decoder then encoder:

$$\frac{\partial \mathcal{L}}{\partial \phi} = \frac{\partial \mathcal{L}}{\partial \hat{\mathbf{x}}} \cdot \frac{\partial \hat{\mathbf{x}}}{\partial \mathbf{z}} \cdot \frac{\partial \mathbf{z}}{\partial \phi}$$

Decision Guide

Use autoencoder when: data lies on a curved manifold; you want an unsupervised, reusable encoder for downstream tasks; you need anomaly detection (high reconstruction error = anomaly).

Prefer VAE when: you need to generate new samples or want a structured, continuous latent space.

Prefer PCA when: data is high-dimensional but approximately linear; you need a closed-form, interpretable solution.

6
Key Takeaways
  • Bottleneck = compression. The latent dimension \(k\) controls how much information is preserved. Smaller \(k\) → more compression, potentially more noise.
  • Linear AE = PCA. Nonlinear activations are what make autoencoders strictly more powerful than PCA.
  • Reconstruction loss drives representation. No labels needed — the signal is purely "can you reconstruct the input?"
  • Latent space has no guarantees. Unlike VAEs, codes can be discontinuous and scattered — not suitable for sampling/generation.
  • Deep encoders generalise better. More layers allow progressively more abstract representations.
