AI / ML Mastery · Sequence Models Beyond Attention

Hyena

A subquadratic drop-in for attention: long implicit convolutions generated by a small MLP over positions, mixed with data-controlled gating, and evaluated in O(n log n) via the FFT.

Advanced Sequence Mixing O(n log n) Implicit Convolutions
1
Understanding the Concept
▼

What is this? Transformers understand long text by having every token "look at" every other token — that's the attention mechanism, and it costs O(n²) work for a sequence of length n. Hyena is a replacement operator: instead of looking at every pair of tokens, it convolves the whole sequence with a very long filter — a filter as long as the sequence itself — and that filter is not stored directly but generated on the fly by a tiny neural network that takes a position index and outputs a filter value. Combined with elementwise gating (multiplying by a data-dependent signal), this recovers attention-like data-dependent mixing at a fraction of the cost.

Analogy: Imagine a huge orchestra (the sequence) and a conductor (attention) who individually cues every single musician in response to every other musician — that's n² cues. Hyena instead plays one long, cleverly-shaped echo/reverb effect (the implicit convolution) across the whole hall that blends everyone together, and the "shape" of that echo is composed on the fly by a small synthesizer (the positional MLP) rather than being hand-recorded. A sound engineer can compute the effect on the entire hall in one fast pass using the FFT, instead of manually mixing every pair.

One-sentence summary: Hyena replaces O(n²) attention with stacked O(n log n) implicit long convolutions (FFT-evaluated, MLP-parameterized filters) interleaved with data-controlled elementwise gating.

If you remember one thing

Hyena never materializes an n×n attention matrix. It generates an n-length filter from an MLP, convolves it with the sequence via FFT in O(n log n), and gates the result with data-dependent projections — recursively, a few times per layer, to approximate attention's expressivity.

2
How It Works Internally
▼

The problem with attention. Self-attention computes a full n×n similarity matrix (queries · keys), softmaxes it, and mixes values with it. This is what gives transformers their power (direct, data-dependent, any-to-any routing) but it is quadratic in both compute and memory in sequence length — a serious bottleneck for genomics, high-resolution images-as-sequences, or long documents where n can be in the tens of thousands.

The Hyena recipe. A Hyena operator of order N (the paper's default is N=2) works like this at every layer:

1. Dense input projections. The input u ∈ ℝn×d is linearly projected (a short causal convolution + linear map) into N+1 parallel projections: x¹, x², …, xᵉ, v.

2. Implicit long filters. Instead of learning N explicit filter tensors of length n (which would not generalize across sequence lengths and would be huge), Hyena parameterizes each filter hᵢ implicitly: a positional encoding t → (sin, cos features) is fed through a small feed-forward network (FFN) to output hᵢ(t) for every position t, and the result is multiplied by an exponential decay window so the filter naturally attenuates at long range like a well-behaved convolution kernel.

3. FFT convolution. Each filter is circularly convolved with the running signal using the Fast Fourier Transform: transform both to the frequency domain, multiply pointwise (convolution theorem), inverse-transform back. This costs O(n log n) instead of the O(n²) a naive time-domain convolution (or attention) would cost.

4. Data-controlled gating. After each convolution, the result is multiplied elementwise by the next projection xᵢ. This elementwise product is what injects data-dependence — without it, convolution alone would be a fixed linear operator regardless of content, unable to mimic attention's "look at relevant tokens" behavior.

5. Recursion. Steps 3–4 repeat N times, each time gating with the next projection, so the final output is a degree-(N+1) polynomial mixing of the input projections — giving Hyena the same kind of high-order, input-dependent interactions that make attention expressive.

Design decision: why FFT and not a direct long convolution?

A direct (time-domain) convolution with a length-n filter costs O(n²) per channel — no better than attention. The convolution theorem says convolution in time equals pointwise multiplication in frequency, and the FFT computes that frequency transform in O(n log n). That single substitution is what makes "attention-strength mixing" tractable at long sequence lengths.

3
Why It Works — The Math
▼

For order N=2, define projections x¹, x², v = P(u) (short causal convs + linear maps of the input). The Hyena operator computes:

$$z^1 = x^1 \odot (h^1 * v), \qquad y = x^2 \odot (h^2 * z^1)$$

where ⊙ is elementwise (Hadamard) product and * is causal convolution along the sequence dimension. Generalized to order N, this is a recurrence:

$$z^{t+1} = x^{t+1} \odot (h^{t+1} * z^t), \quad z^0 = v, \quad y = z^N$$

The implicit filter. Each hᵢ is not a free parameter tensor — it is the output of a shared, tiny FFN applied to a positional embedding, so it generalizes to any sequence length:

$$h(t) = \text{Window}(t)\cdot \text{FFN}(\text{PosEnc}(t)), \qquad \text{Window}(t)=e^{-\alpha t}$$

Convolution via FFT (the complexity win). By the convolution theorem, for signals of length n:

$$h * v = \mathcal{F}^{-1}\big(\mathcal{F}(h)\cdot \mathcal{F}(v)\big)$$

Computing ℱ and ℱ-1 via the Fast Fourier Transform costs O(n log n); the pointwise multiply in frequency space costs O(n). Total per filter: O(n log n), versus O(n²) for attention's query·key score matrix and its softmax-weighted aggregation.

Gradient flow. Because ⊙ and * are both differentiable (the FFT is a linear, invertible, differentiable transform), gradients flow through the whole recurrence via standard backprop; the implicit FFN's parameters receive gradients aggregated across all n positions it was evaluated at, similar to how a weight-shared RNN/CNN is trained.

Common misconception

"Hyena is just a CNN." A vanilla CNN uses a short, fixed, position-independent filter and no gating — it cannot route information based on content. Hyena's filter spans the entire sequence (global receptive field in one layer) and, crucially, every convolution output is gated by a data-dependent projection, giving it attention-like content-based mixing that a plain CNN lacks.

Complexity at a glance

Attention: O(n² d) compute, O(n²) memory for the score matrix. Hyena: O(N n \log n \, d) compute, O(n d) memory — no quadratic term in n at all.

Key Takeaways
▼
DimensionSelf-AttentionHyena
ComputeO(n² d)O(N n log n · d)

Mixing weightsExplicit, softmax(QKᵀ)Implicit filter × gating (no explicit matrix)
Data-dependenceFull pairwise (Q,K,V)Elementwise gates (x¹…xᵉ) at each recursion step

Best regimeShort/medium sequences, max expressivity per FLOPVery long sequences (genomics, long documents, raw audio)

Use Hyena when sequence length is large enough that n² dominates cost/memory (e.g. n > 8K–64K), or when you need a subquadratic backbone that still learns rich, data-dependent mixing rather than a fixed local kernel.

Be cautious when sequences are short (attention's constant factors and mature tooling often win), or when you need exact, interpretable pairwise attention weights (e.g. for attribution/explainability use cases).

Takeaway

Hyena shows that the two structural ingredients of attention — long-range mixing and data-dependence — can be decomposed and reimplemented with cheaper primitives: an FFT-evaluated implicit convolution supplies the long range, and elementwise gating supplies the data-dependence. Neither ingredient alone matches attention; together, recursively applied, they closed most of the quality gap at a fraction of the asymptotic cost.

Code Trace — Hyena Operator (Order 2)
▼

Minimal order-2 Hyena operator (PyTorch-style pseudocode). fft_conv does exactly what the interactive viz below animates: FFT the signal, FFT the implicit filter, multiply pointwise, inverse FFT.

def implicit_filter(t, mlp, alpha): pe = positional_encoding(t) # sin/cos features per position h = mlp(pe) # tiny FFN -> filter value h(t) return h * exp(-alpha * t) # exponential decay window def fft_conv(signal, filt): F_signal = fft(signal) # O(n log n) F_filt = fft(filt) # O(n log n) return real(ifft(F_signal * F_filt)) # pointwise mult + inverse FFT def hyena_operator(u, N=2): x1, x2, v = dense_projections(u) # short causal conv + linear h1 = implicit_filter(positions, mlp1, alpha1) h2 = implicit_filter(positions, mlp2, alpha2) z1 = x1 * fft_conv(v, h1) # gate 1: elementwise data-control y = x2 * fft_conv(z1, h2) # gate 2: elementwise data-control return y # O(N n log n) total, no n x n matrix
