Tensor Contraction & Reshaping

How multi-dimensional arrays change shape without moving bytes in memory
Foundational Linear Algebra Math & Stats O(n) reshape · O(nk) contract
1
Understanding Tensors, Reshaping & Contraction
▼

What is a tensor? A tensor is a multi-dimensional array of numbers. A scalar is a rank-0 tensor (one number), a vector is rank-1 (a list), a matrix is rank-2 (a grid), and anything beyond that — say, a video (time × height × width × channels) — is a rank-3 or higher tensor. The key idea: every tensor, however many axes it has, sits as a flat sequence of numbers in computer memory.

What is reshaping? Reshaping changes which axes you call a tensor by, without moving a single number in memory. A tensor of shape \((2, 3, 4)\) (2 groups, each 3 rows, each 4 columns) stores 24 numbers. Reshaping to \((6, 4)\) says: "pretend those 24 numbers have 6 rows and 4 columns." The data bytes don't move — only the interpretation changes.

What is contraction? Contraction generalises matrix multiplication. You sum over one or more shared "index" axes across two tensors, collapsing them. Ordinary matrix multiplication \(C = AB\) is a contraction over the shared inner dimension: \(C_{ik} = \sum_j A_{ij} B_{jk}\). With tensors, you can contract over any pair of matching axes.

Analogy: Think of a hotel with 2 floors, 3 corridors per floor, and 4 rooms per corridor — that's shape \((2, 3, 4)\), 24 rooms total. The room numbers are 0–23, painted on the floor in order. "Reshaping" to \((6, 4)\) is like putting up new corridor signs that say "6 corridors, 4 rooms each" — the rooms don't move, just the signage changes.

💡 If you remember one thing

Reshape is a free operation (no copy) when data is contiguous in memory — it merely updates shape metadata. Contraction is the workhorse that generalises matrix multiplication to arbitrary-rank tensors, and is the fundamental compute primitive behind every deep-learning layer.

Memory Layout, Strides & Why Reshape is Free
▼

Row-Major (C) Order

NumPy, PyTorch, and most modern frameworks store tensors in row-major (C-contiguous) order: the last axis varies fastest. A matrix \(A\) of shape \((3, 4)\) is laid out as \(A_{00}, A_{01}, A_{02}, A_{03}, A_{10}, A_{11}, \ldots, A_{22}, A_{23}\) — 12 elements, indices running right first, then down.

Strides

The stride of an axis tells you how many memory slots to skip to advance one step along that axis. For shape \((2, 3, 4)\) in row-major order:

$$\text{strides} = (3 \times 4,\; 4,\; 1) = (12,\; 4,\; 1)$$

Element \(T[i, j, k]\) lives at flat address \(12i + 4j + k\). Reshape to \((6, 4)\) simply changes the shape metadata and recomputes strides: \((4, 1)\). No byte moves.

The Multi-Index Formula

For a rank-\(N\) tensor with shape \((d_0, d_1, \ldots, d_{N-1})\) stored in C-order, the flat index of element \((i_0, i_1, \ldots, i_{N-1})\) is:

$$\text{flat} = \sum_{k=0}^{N-1} i_k \cdot \left(\prod_{l=k+1}^{N-1} d_l\right)$$

Reshape is valid whenever the total size \(\prod d_k\) is preserved. The flat index of each element is identical before and after.

🔑 Key Property

A reshape is a view — the same memory, a new stride tuple. Contiguous tensors always support zero-copy reshape. Non-contiguous tensors (e.g., after a transpose) may need a .contiguous() copy first.

⚠️ Common Mistake

Transposing a matrix and then reshaping without calling .contiguous() can silently produce wrong results in some frameworks, because transpose makes strides non-contiguous. Always check tensor.is_contiguous() before relying on reshape being a view.

3
Contraction — The Mathematics
▼

Einstein Summation Notation

Einstein notation suppresses the sum symbol: any repeated index is summed over. Matrix multiplication \(C_{ik} = \sum_j A_{ij} B_{jk}\) is written \(C_{ik} = A_{ij} B_{jk}\). In NumPy / PyTorch this is einsum('ij,jk->ik', A, B).

General Contraction

Given tensors \(A\) of shape \((d_0, \ldots, d_{p-1}, k)\) and \(B\) of shape \((k, e_0, \ldots, e_{q-1})\), contracting over shared dimension \(k\) yields \(C\) of shape \((d_0, \ldots, d_{p-1}, e_0, \ldots, e_{q-1})\):

$$C_{i_0 \ldots i_{p-1},\, j_0 \ldots j_{q-1}} = \sum_{s=0}^{k-1} A_{i_0 \ldots i_{p-1},\, s}\; B_{s,\, j_0 \ldots j_{q-1}}$$

Numerical Trace Example

Let \(A\) have shape \((2,3)\) and \(B\) have shape \((3,2)\). Contract over the inner axis \((k=3)\):

$$A = \begin{bmatrix}1&2&3\\4&5&6\end{bmatrix},\quad B = \begin{bmatrix}7&8\\9&10\\11&12\end{bmatrix}$$
$$C_{00} = 1\cdot7+2\cdot9+3\cdot11 = 7+18+33 = 58$$
$$C_{01} = 1\cdot8+2\cdot10+3\cdot12 = 8+20+36 = 64$$
$$C_{10} = 4\cdot7+5\cdot9+6\cdot11 = 28+45+66 = 139$$
$$C_{11} = 4\cdot8+5\cdot10+6\cdot12 = 32+50+72 = 154$$

Result \(C\) has shape \((2,2)\), as expected: contracting the \(3\)-axis eliminates it.

∑ Complexity

For tensors of total sizes \(P\) and \(Q\) sharing a contracted axis of size \(k\), the contraction costs \(O(P \cdot Q / k \cdot k) = O(PQ)\) multiply-adds. Reshape costs \(O(1)\) (only metadata changes; or \(O(n)\) if a copy is forced).

Production Usage & Key Takeaways
▼

Reshape in NumPy / PyTorch

# NumPy
import numpy as np
T = np.arange(24).reshape(2, 3, 4)  # (2,3,4)
T.strides            # (48, 16, 4) bytes — dtype=int64, 8 bytes each
T2 = T.reshape(6, 4) # view — same data pointer
np.shares_memory(T, T2)  # True

# PyTorch
import torch
t = torch.arange(24).view(2, 3, 4)  # view = zero-copy
t2 = t.reshape(6, 4)                # reshape = view if contiguous
t.is_contiguous()                   # True
t.T.is_contiguous()                 # False — after transpose!
t.T.contiguous().reshape(8, 3)      # safe: force a copy first

Einsum for Contraction

import torch
# Batched matrix multiply: (B, m, k) x (B, k, n) -> (B, m, n)
C = torch.einsum('bik,bkj->bij', A, B)

# Trace: sum of diagonal (contraction i=j)
tr = torch.einsum('ii->', M)

# Outer product: (m,) x (n,) -> (m, n)  — no contraction
O = torch.einsum('i,j->ij', u, v)

# opt_einsum chooses optimal contraction order automatically
from opt_einsum import contract
result = contract('ijk,jkl->il', T1, T2)
💡 Key Takeaways
  • Reshape is \(O(1)\) for contiguous tensors — it changes metadata only, not bytes.
  • Strides encode axis semantics: shape \((d_0,\ldots,d_{N-1})\) → strides \((\prod_{l>0}d_l,\ldots,d_{N-1},1)\).
  • Contraction eliminates shared axes by summing their products — it generalises matrix multiply, trace, dot product, and outer product.
  • Einstein notation (einsum) is the universal language for expressing any tensor contraction concisely and unambiguously.
  • In deep learning, every linear layer, attention head, convolution, and batch-norm is ultimately a sequence of reshapes and contractions.

Common Interview Questions

Q1 (Easy): What does reshape do, and when does it require a copy?
A: Reshape changes shape metadata and recomputes strides. It is a zero-copy view when the tensor is C-contiguous. After a non-trivial permutation (like transpose), the tensor is non-contiguous and reshape must copy data to produce a contiguous block first.

Q2 (Medium): How does einsum notation 'ij,jk->ik' specify matrix multiplication?
A: Index \(j\) appears on both input sides but not in the output spec \(ik\), so it is summed over (contracted). Indices \(i\) and \(k\) survive to the output. The notation is equivalent to \(C_{ik} = \sum_j A_{ij} B_{jk}\).

Q3 (Hard): A transformer attention layer computes \(\text{softmax}(QK^\top/\sqrt{d_k})V\). Express this as einsum operations over a batch of heads, and state each tensor's shape.
A: With \(Q, K, V \in \mathbb{R}^{B \times H \times T \times d_k}\), scores = einsum('bhid,bhjd->bhij', Q, K) / \(\sqrt{d_k}\), shape \((B,H,T,T)\). Output = einsum('bhij,bhjd->bhid', attn, V), shape \((B,H,T,d_k)\).
