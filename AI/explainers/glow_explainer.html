Understanding 1×1 Invertible Convolutions
▼

What is it? In the context of normalizing flows (like Glow), a 1×1 invertible convolution is a special type of convolutional layer that performs a linear transformation on the channels of a feature map, independently at each spatial location. Its defining characteristic is that the transformation matrix (the convolution kernel) is guaranteed to be invertible, allowing both a forward pass (encoding) and a perfect backward pass (decoding or sampling).

Analogy: Imagine you have three distinct colors of paint (channels) in separate buckets. A standard 1×1 convolution lets you mix these paints to create new colors (output channels). An invertible 1×1 convolution is like a magical mixer that not only creates new colors but can also perfectly un-mix them to recover the original paints in their original buckets. This "un-mixing" capability is crucial for generative models that need to go both from data to latent space and back.

💡 If you remember one thing

A 1×1 invertible convolution applies a fixed square matrix \(W\) to the channel dimension of every spatial pixel. This matrix \(W\) is parameterized (often via an LU decomposition) to guarantee invertibility (\(\det(W) \neq 0\)) and to make its log-determinant — a key term for normalizing flows — computationally efficient: \(\log|\det(W)| = \sum_i \log|U_{ii}|\).

2
How It Works Internally
▼

The 1×1 Convolution as a Matrix Multiplication

A standard 1×1 convolution with \(C_{in}\) input channels and \(C_{out}\) output channels uses a kernel of shape \((C_{out}, C_{in}, 1, 1)\). When \(C_{in} = C_{out} = C\), this kernel acts as a simple \(C \times C\) matrix \(W\). For any given spatial location \((h, w)\), the input feature vector \(\mathbf{x}_{h,w} \in \mathbb{R}^C\) is transformed into an output feature vector \(\mathbf{y}_{h,w} \in \mathbb{R}^C\) by a matrix multiplication:

$$\mathbf{y}_{h,w} = W \mathbf{x}_{h,w}$$

This operation is applied identically across all spatial locations \((h, w)\) of the feature map. The "1×1" refers to the spatial extent of the kernel, meaning it only mixes information *within* a pixel's channels, not across neighboring pixels.

Ensuring Invertibility and Tractable Log-Determinant

For normalizing flows, two properties are critical: (1) the transformation must be invertible (so we can go from latent space to data and back), and (2) the logarithm of the absolute determinant of its Jacobian must be easy to compute. For a 1×1 convolution, the Jacobian determinant is simply \(\det(W)\) repeated for each spatial location. To satisfy these, Glow parameterizes \(W\) using an LU decomposition:

$$W = P L U$$

Where:

  • \(P\) is a fixed permutation matrix (e.g., a random permutation, or identity if no explicit permutation is desired). This shuffles the channels.
  • \(L\) is a lower-triangular matrix with ones on the diagonal. Its off-diagonal elements are learnable.
  • \(U\) is an upper-triangular matrix with learnable diagonal elements. Its off-diagonal elements are also learnable.

Because \(P\) is a permutation, \(\det(P) = \pm 1\). Because \(L\) is lower-triangular with ones on the diagonal, \(\det(L) = 1\). The determinant of \(U\) is simply the product of its diagonal elements: \(\det(U) = \prod_{i=1}^C U_{ii}\). Therefore, \(\log|\det(W)| = \log|\det(P)| + \log|\det(L)| + \log|\det(U)| = \sum_{i=1}^C \log|U_{ii}|\). This is extremely efficient to compute.

🔑 Key Property

The LU decomposition of \(W\) guarantees invertibility as long as all diagonal elements of \(U\) are non-zero. The decomposition also provides a simple, efficient way to compute the log-determinant of \(W\), which is essential for exact likelihood estimation in flow-based models.

3
Why It Works — The Math of Invertibility and Determinants
▼

The Flow Transformation and Jacobian

In a normalizing flow, we transform a data point \(\mathbf{x}\) into a latent variable \(\mathbf{z}\) through a sequence of invertible transformations \(f\). The change of variables formula for likelihood requires the absolute determinant of the Jacobian matrix of \(f\):

$$p_x(\mathbf{x}) = p_z(f(\mathbf{x})) \left| \det\left(\frac{\partial f}{\partial \mathbf{x}}\right) \right|$$

For a 1×1 convolution \(y_{h,w,c'} = \sum_c W_{c',c} x_{h,w,c}\), let \(\mathbf{x}_{vec}\) be the flattened input feature map \((H \cdot W \cdot C)\) and \(\mathbf{y}_{vec}\) be the flattened output. The Jacobian matrix \(\frac{\partial \mathbf{y}_{vec}}{\partial \mathbf{x}_{vec}}\) is a block-diagonal matrix where each block is \(W\). Thus, its determinant is \(\det(W)^{H \cdot W}\). Therefore, the log-determinant term is:

$$\log \left| \det\left(\frac{\partial \mathbf{y}_{vec}}{\partial \mathbf{x}_{vec}}\right) \right| = H \cdot W \cdot \log|\det(W)|$$

This means we only need to compute \(\log|\det(W)|\) once per layer, then scale it by the spatial dimensions.

Derivation of Log-Determinant from LU Decomposition

Given the parametrization \(W = P L U\), where \(P\) is a permutation, \(L\) is lower-triangular with ones on the diagonal, and \(U\) is upper-triangular with learnable diagonal elements. The property of determinants states that \(\det(AB) = \det(A)\det(B)\). So:

$$\det(W) = \det(P) \det(L) \det(U)$$

We know \(\det(P) = \pm 1\) (depending on the permutation), \(\det(L) = \prod_{i=1}^C L_{ii} = \prod_{i=1}^C 1 = 1\), and \(\det(U) = \prod_{i=1}^C U_{ii}\). Therefore, the log-determinant becomes:

$$\log|\det(W)| = \log|\det(P)| + \log|\det(L)| + \log|\det(U)| = \log|(\pm 1)| + \log|1| + \log\left|\prod_{i=1}^C U_{ii}\right| = \sum_{i=1}^C \log|U_{ii}|$$

This elegant result means the log-determinant, which is a crucial part of the likelihood calculation, can be computed by simply summing the logarithms of the absolute values of the diagonal elements of the \(U\) matrix. This avoids computing a full matrix determinant, which would be \(O(C^3)\), and instead makes it \(O(C)\).

⚠️ Common Pitfall

Naive implementation of 1×1 convolutions in generative flows might directly optimize a \(C \times C\) weight matrix \(W\). This can lead to issues: (1) \(W\) might become singular (non-invertible) during training, breaking the flow, and (2) computing \(\log|\det(W)|\) for a general matrix numerically is \(O(C^3)\), which is slow for many channels. The LU parametrization specifically addresses both these issues.

Key Takeaways
▼

When to use 1×1 invertible convolutions:

  • In normalizing flows (like Glow, RealNVP, etc.) for generative modeling, where exact likelihood computation is required.
  • In any invertible neural network architecture where transformations must be perfectly reversible.
  • To provide expressive channel-wise mixing without affecting spatial dimensions, enabling complex transformations while preserving spatial resolution.

Benefits:

  • Guaranteed Invertibility: The LU decomposition ensures that the transformation matrix \(W\) is invertible (as long as \(U_{ii} \neq 0\)), allowing for both forward (encoding) and inverse (decoding/sampling) passes.
  • Tractable Log-Determinant: The log-determinant of the Jacobian is efficiently computable as \(\sum \log|U_{ii}|\), which is \(O(C)\) instead of \(O(C^3)\) for a general matrix. This is crucial for training normalizing flows via maximum likelihood.
  • Powerful Channel Mixing: It allows for flexible linear mixing of channels, increasing the expressiveness of the flow.

Limitations and Considerations:

  • Computational Cost: While \(O(C)\) for the log-determinant, the matrix multiplication itself is \(O(C^2)\) per spatial location. For very large \(C\), this can be a bottleneck.
  • No Spatial Mixing: As a 1×1 convolution, it does not mix information across different spatial locations. Other flow components (like affine coupling layers) are needed for spatial transformations.
  • Numerical Stability: While the LU decomposition improves stability, care must still be taken with very small \(U_{ii}\) values during training to prevent numerical issues (e.g., \(\log(0)\)).
💡 Big Picture

The 1×1 invertible convolution is a clever and fundamental building block that enables flow-based generative models to achieve both high expressiveness in modeling complex data distributions and computational tractability for exact likelihood estimation. It showcases how careful mathematical parametrization can unlock powerful capabilities in deep learning.

Code Trace (PyTorch-like Implementation Sketch)
▼
import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np
class Invertible1x1Conv(nn.Module):
def __init__(self, num_channels):
super().__init__()
self.num_channels = num_channels
# Initialize W as a random orthogonal matrix for stability
W_init = torch.linalg.qr(torch.randn(num_channels, num_channels))[0]
# Perform LU decomposition of W_init
P, L_lower, U_upper = torch.linalg.lu_factor(W_init)
# P is a permutation matrix, L_lower is lower-triangular, U_upper is upper-triangular
# Extract diagonal of U for log-determinant calculation
U_diag = torch.diag(U_upper)
# L and U factors are stored as parameters
self.register_buffer("P", P) # P is fixed after init
self.L_lower = nn.Parameter(L_lower)
self.U_upper = nn.Parameter(U_upper)
self.U_diag_param = nn.Parameter(U_diag) # Learnable diagonal for U
def _get_W(self):
# Reconstruct L and U from parameters
L = torch.tril(self.L_lower, diagonal=-1) + torch.eye(self.num_channels, device=self.L_lower.device)
U = torch.triu(self.U_upper, diagonal=1) + torch.diag(self.U_diag_param)
return self.P @ L @ U
def forward(self, x, inverse=False):
# x: (B, C, H, W)
W = self._get_W()
if not inverse:
# Forward pass: y = Wx
# F.conv2d expects W as (C_out, C_in, kH, kW)
y = F.conv2d(x, W.unsqueeze(2).unsqueeze(3))
log_det_W = torch.sum(torch.log(torch.abs(self.U_diag_param)))
# Total log-determinant for the batch and spatial dimensions
log_det_total = log_det_W * x.size(2) * x.size(3)
return y, log_det_total
else:
# Inverse pass: x = W^-1 y
W_inv = torch.linalg.inv(W)
x_inv = F.conv2d(x, W_inv.unsqueeze(2).unsqueeze(3))
return x_inv
# Example Usage
num_channels = 3
inv_conv = Invertible1x1Conv(num_channels)
input_feature_map = torch.randn(1, num_channels, 32, 32) # Batch, Channels, H, W
output_feature_map, log_det = inv_conv(input_feature_map)
print(f"Output shape: {output_feature_map.shape}, Log-determinant: {log_det.item():.4f}")
reconstructed_map = inv_conv(output_feature_map, inverse=True)
print(f"Reconstructed shape: {reconstructed_map.shape}")
