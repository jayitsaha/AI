Model Soups: Averaging Weights for Better Generalization

Combining independently trained models to find flatter minima and improve performance
Intermediate Deep Learning Ensembling O(K) extra cost
1
Understanding Model Soups
▼

What is it? Model soups (Wortsman et al., 2022) is a simple yet powerful technique to improve the performance and robustness of deep learning models. Instead of selecting the single best model from a set of independently trained checkpoints (e.g., from different random seeds, hyperparameter settings, or training epochs), it averages their weights to create a "soup" model. This averaged model often outperforms its individual components.

Analogy: Imagine you're baking a cake, but you have several slightly different recipes (models) that all produce decent cakes. Instead of picking just one recipe, you take a little bit of flour from one, a bit of sugar from another, and so on, carefully combining the ingredients (weights) from multiple recipes. The resulting "soup" cake often turns out even better and more balanced than any single recipe could achieve, especially if the individual recipes were already pretty good.

💡 If you remember one thing

Model soups exploit the observation that deep neural networks often converge to "flat minima" in the loss landscape. Averaging weights from models in such minima tends to keep the soup model within a low-loss region, reducing variance and improving generalization, rather than landing in a high-loss region.

2
How It Works Internally
▼

The Core Idea: Flat Minima

Deep learning models are highly overparameterized, meaning they can fit the training data in many different ways. During training, they often converge to different local minima in the loss landscape. Some minima are "sharp" (small changes in weights lead to large changes in loss), while others are "flat" (weights can vary significantly without much change in loss). Models in flat minima tend to generalize better because they are more robust to perturbations (like new, unseen data).

When you average the weights of several models, the resulting "soup" model's weights lie on a line segment (or hyperplane) connecting the individual models. If the individual models are all in flat minima, this line segment is likely to remain within a low-loss region. If models are in sharp minima, averaging might push the soup into a high-loss region.

Two Main Strategies

Given a set of \(K\) independently trained models \(\{M_1, \dots, M_K\}\), each with weights \(w_k\):

  • Uniform Soup: This is the simplest approach. It averages the weights of all \(K\) models. This works best when all models perform similarly well, suggesting they've all found good, flat minima.
  • Greedy Soup: This strategy is more selective. It starts with the single best-performing model (based on validation accuracy). Then, it iteratively considers adding each of the remaining models. If adding a model (by averaging its weights with the current soup's weights) improves validation performance, that model is added to the soup. This process continues until no further improvement is observed. Greedy soups are useful when there's more variability in individual model performance.

Design Decision: Why average weights, not predictions?

Ensembling by averaging predictions (e.g., voting classifiers) is a well-established technique that typically yields strong performance gains. Model soups, by contrast, average the *weights* directly. This has two key advantages: (1) The soup model is a single model, so inference is as fast as a single model, unlike prediction ensembles which require running multiple models. (2) Weight averaging can sometimes find even better solutions than prediction averaging, especially when models are close in parameter space and reside in flat minima.

🔑 Key Property

Model soups work best when models are trained with similar architectures, datasets, and optimization objectives. Large discrepancies can lead to models occupying vastly different regions of the parameter space, making simple weight averaging less effective or even detrimental.

3
Why It Works — The Math
▼

General Formulation of a Model Soup

A model soup is formed by a weighted average of the parameters (weights and biases) of \(K\) individual models. Let \(w_k\) denote the vector of all parameters for model \(k\). The soup model's parameters \(w_{soup}\) are given by:

$$w_{soup} = \sum_{k=1}^K \alpha_k w_k$$

where \(\alpha_k\) are non-negative weights such that \(\sum_{k=1}^K \alpha_k = 1\).

Uniform Soup

For a uniform soup, all selected models contribute equally. If we select \(K_{sel}\) models, then \(\alpha_k = 1/K_{sel}\) for the selected models and \(\alpha_k = 0\) for the others. The uniform soup parameters are:

$$w_{uniform} = \frac{1}{K_{sel}} \sum_{k \in \text{selected}} w_k$$

This is a simple arithmetic mean of the parameter vectors. It's effective when the selected models are all good and diverse enough to cover a robust flat minimum region.

Greedy Soup

The greedy soup algorithm constructs the soup iteratively. Let \(w_{greedy}^{(j)}\) be the soup after \(j\) models have been added. To add the \((j+1)\)-th model, \(w_{k^*}\), the new soup is formed by averaging \(w_{k^*}\) with the current soup:

$$w_{greedy}^{(j+1)} = \frac{j \cdot w_{greedy}^{(j)} + w_{k^*}}{j+1}$$

Here, \(k^*\) is chosen from the remaining available models such that combining it with \(w_{greedy}^{(j)}\) yields the highest validation performance. The process starts with \(w_{greedy}^{(0)}\) being the weights of the single best model found, and continues until no further improvement is observed on the validation set.

⚠️ Common Pitfall

Model soups are most effective when models are trained with the same architecture. Averaging weights across models with different layer counts, different activation functions, or different parameter names (even if the same size) will lead to meaningless results or errors. Ensure checkpoint compatibility before attempting to create a soup.

Key Takeaways
▼

When to use Model Soups:

  • You have a collection of trained models (checkpoints from different seeds, epochs, or minor hyperparameter tweaks) that perform reasonably well.
  • You need the speed of a single model at inference time, but want the generalization benefits of an ensemble.
  • You suspect your models are converging to flat minima, making weight averaging a robust strategy.
  • To squeeze out a few extra percentage points of performance from an already well-tuned training pipeline.

When NOT to use / be cautious:

  • Models have vastly different architectures or were trained on very different datasets — weight averaging will likely fail.
  • Models are in "sharp" minima; averaging might lead to a soup that performs worse than individual components. This is less common in modern overparameterized networks but can happen.
  • You are already achieving satisfactory performance and the extra computational cost of training multiple models is not justified.
  • For very early-stage experimentation, focus on core model improvements first.
💡 Beyond Simple Averaging

While uniform and greedy soups are the most common, research continues into more sophisticated ways to combine models, such as learned weighting schemes or methods that explicitly search for flat regions. The core idea of leveraging multiple trained checkpoints remains a powerful tool in the ML practitioner's toolkit.

def make_uniform_soup(models_to_avg):
if not models_to_avg: return None
soup_state_dict = copy.deepcopy(models_to_avg[0].state_dict())
for key in soup_state_dict:
for i in range(1, len(models_to_avg)):
soup_state_dict[key] += models_to_avg[i].state_dict()[key]
soup_state_dict[key] /= len(models_to_avg)
soup_model = model_class()
soup_model.load_state_dict(soup_state_dict)
soup_model.eval()

def make_greedy_soup(models, val_dataloader):
# Sort models by initial validation accuracy
evaluations = [(m, evaluate(m, val_dataloader)[0]) for m in models]
evaluations.sort(key=lambda x: x[1], reverse=True)
best_val_acc = evaluations[0][1]
greedy_soup = evaluations[0][0] # Start with the best individual model
current_soup_members = [greedy_soup]
for i in range(1, len(evaluations)):
candidate_model = evaluations[i][0]
temp_soup_members = current_soup_members + [candidate_model]
temp_soup = make_uniform_soup(temp_soup_members)
temp_val_acc, _ = evaluate(temp_soup, val_dataloader)
if temp_val_acc > best_val_acc:
best_val_acc = temp_val_acc
greedy_soup = temp_soup
current_soup_members = temp_soup_members
return greedy_soup
