Turning class names into a classifier — no labeled training images required
Foundational Multimodal Vision-Language O(C·d) inference
1
Understanding Zero-Shot CLIP Classification
▼

What is it? A normal image classifier only recognizes the exact categories it was trained on — add a new class and you must collect labeled photos and retrain. CLIP (Contrastive Language-Image Pre-training) sidesteps this: it learns a single shared space where images and sentences that describe them land near each other. To classify a new photo into brand-new categories, you never touch the image encoder again — you just write down the class names as sentences ("a photo of a {class}"), embed those sentences, and ask which one the photo's embedding is closest to.

Analogy: Imagine a bilingual translator who has spent years pairing millions of photos with their captions, until they've built an intuition for which pictures "sound like" which sentences. Now show them a brand-new photo and a list of possible captions they've never seen paired together before — "a photo of a corgi", "a photo of a pretzel", "a photo of a submarine". Even without ever training specifically on "corgi vs. pretzel vs. submarine", the translator can still say which caption fits best, because they understand the general relationship between images and language.

Summary: Zero-shot CLIP classification turns each class name into a text embedding (a "classifier weight vector" synthesized from language, not from labeled images), then classifies an image by picking the class whose text embedding has the highest cosine similarity to the image embedding.

💡 If you remember one thing

Class names become the classifier. CLIP builds classifier weights on the fly by embedding "a photo of a {class}" for every candidate class, so it can classify categories it has never explicitly been trained to recognize: $$P(y=c\mid x) = \frac{\exp(\tau \cdot \cos(\mathbf{e}_{img}, \mathbf{e}_{txt}^{(c)}))}{\sum_{k=1}^{C}\exp(\tau \cdot \cos(\mathbf{e}_{img}, \mathbf{e}_{txt}^{(k)}))}$$

How It Works Internally
▼

Two Towers, One Shared Space

CLIP has an image encoder \(f_{img}\) (a ViT or ResNet) and a text encoder \(f_{txt}\) (a Transformer). During pre-training on ~400M (image, caption) pairs scraped from the web, both towers are trained jointly with a contrastive loss so that the embedding of an image and the embedding of its matching caption are pulled close together, while embeddings of mismatched pairs are pushed apart. Critically, nothing in this objective refers to a fixed label set — it only ever sees free-form text.

Building a Classifier from Class Names

At inference time for a new task with classes \(\{c_1,\dots,c_C\}\), each class name is dropped into a prompt template such as "a photo of a {class}." — turning a bare word like "dog" into a full sentence that resembles the captions CLIP saw during pre-training. Each filled-in prompt is passed through the frozen text encoder to get a vector \(\mathbf{t}_c = f_{txt}(\text{prompt}_c)\). Stacking these \(C\) vectors as rows produces a matrix that behaves exactly like the weight matrix of a linear classifier's final layer — except it was synthesized from language, never fit with gradient descent on labeled images of these classes.

Scoring an Image

The new image is passed through the frozen image encoder to get \(\mathbf{e}_{img} = f_{img}(x)\). Both \(\mathbf{e}_{img}\) and every \(\mathbf{t}_c\) are L2-normalized onto the unit hypersphere, so their dot product equals cosine similarity. The class whose text vector is most "aligned" in direction with the image vector wins.

Design Decision: Why Prompt Templates, Not Bare Words?

Feeding the raw word "dog" underperforms feeding "a photo of a dog." — pre-training captions are full sentences, so a bare noun is out-of-distribution for the text encoder and produces a noisier embedding. The original CLIP paper found templated prompts plus prompt ensembling (averaging embeddings from ~80 templates like "a photo of a {}", "a black and white photo of a {}", "a cropped photo of a {}") improved ImageNet zero-shot accuracy by roughly 3.5 points over a single naive prompt, essentially for free at inference time.

🔑 Key Property

Zero-shot transfer works because classification is reduced to nearest-neighbor search in a shared embedding space, and that space was learned once, generically, from language-image co-occurrence — not from any specific label taxonomy. Adding a new class costs one text-encoder forward pass, not a retraining run.

3
Why It Works — The Math
▼

Cosine Similarity as the Scoring Function

Let \(\mathbf{e}_{img}, \mathbf{t}_c \in \mathbb{R}^d\) be the (pre-normalization) image and class-\(c\) text embeddings. Normalize both to unit length, \(\hat{\mathbf{e}} = \mathbf{e}/\|\mathbf{e}\|_2\), so that the dot product is bounded and scale-invariant:

$$\cos(\mathbf{e}_{img}, \mathbf{t}_c) = \hat{\mathbf{e}}_{img}^\top \hat{\mathbf{t}}_c \in [-1, 1]$$

Normalizing removes the magnitude of each vector as a confound — otherwise a class whose text embedding merely has larger norm (unrelated to semantic match) could dominate purely by scale. Only the direction in embedding space should matter.

From Similarity to Probability

The raw cosine similarities live in a narrow range (empirically often 0.2–0.35 for the correct class), which would make a plain softmax nearly uniform. CLIP learns a scalar logit scale \(\tau\) (parameterized as \(\exp(\text{a learned temperature})\), clipped to \(\le 100\)) during pre-training, and multiplies it into the logits before the softmax:

$$P(y=c \mid x) = \operatorname{softmax}_c\big(\tau \cdot \cos(\mathbf{e}_{img}, \mathbf{t}_c)\big) = \frac{\exp\!\big(\tau \cos(\mathbf{e}_{img}, \mathbf{t}_c)\big)}{\displaystyle\sum_{k=1}^{C}\exp\!\big(\tau \cos(\mathbf{e}_{img}, \mathbf{t}_k)\big)}$$

This is the same softmax that trains the model contrastively: during pre-training, the diagonal of the (image × text) similarity matrix for a batch are the positive pairs, and \(\tau\)-scaled cosine similarities become logits for a symmetric InfoNCE / cross-entropy loss over both directions.

Prompt Ensembling as Variance Reduction

Averaging \(K\) template embeddings per class before normalizing, \(\bar{\mathbf{t}}_c = \frac{1}{K}\sum_{k=1}^K f_{txt}(\text{prompt}_c^{(k)})\), acts like averaging \(K\) noisy estimates of the "true" class direction — it cancels idiosyncratic wording noise while reinforcing the semantic signal shared across templates, in the same way ensembling reduces variance for any noisy estimator.

⚠️ Common Pitfall

Zero-shot accuracy is extremely prompt-sensitive. Swapping "a photo of a {}" for a bare class name, or picking ambiguous class names (e.g. "crane" the bird vs. crane the machine), can shift accuracy by several points without changing any model weights — the classifier really is just the sentence you chose.

Key Takeaways
▼

When zero-shot CLIP classification shines:

  • Long-tail or rapidly changing label sets — add a class by writing one sentence, no retraining
  • Rough triage / open-vocabulary tasks where perfect accuracy matters less than flexibility
  • Bootstrapping a labeled dataset before training a dedicated supervised model
  • Cheap baselines to compare against fine-tuned or few-shot methods

When NOT to rely on it:

  • Fine-grained distinctions the pre-training data rarely captioned (e.g. exact bird sub-species)
  • Safety-critical decisions — zero-shot accuracy trails supervised fine-tuning and is prompt-sensitive
  • Domains far from web photo-caption style (medical scans, satellite imagery) without domain adaptation
💡 Hierarchy

Zero-shot (class names only) → Prompt ensembling (many templates averaged) → Linear probing (freeze encoder, fit a real linear layer on labeled features) → Full fine-tuning (unfreeze everything). Each step trades away generality for accuracy on the specific target task.

import torch, clip
model, preprocess = clip.load("ViT-B/32")
# Candidate classes -- the "training set" is just this list of words
classes = ["cat", "dog", "car", "airplane"]
templates = ["a photo of a {}.", "a cropped photo of a {}.", "an image of a {}."]
# Build a "classifier weight" per class by ensembling prompt templates
def build_text_weights(classes, templates):
weights = []
for c in classes:
prompts = [t.format(c) for t in templates]
tok = clip.tokenize(prompts)
with torch.no_grad():
t_emb = model.encode_text(tok) # (K, d)
t_emb = t_emb / t_emb.norm(dim=-1, keepdim=True)
t_emb = t_emb.mean(dim=0) # ensemble average
t_emb = t_emb / t_emb.norm() # re-normalize
weights.append(t_emb)
return torch.stack(weights) # (C, d)
