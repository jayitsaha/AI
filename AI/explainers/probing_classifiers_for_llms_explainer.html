Uncovering what linguistic properties Large Language Models encode in their representations

1
Understanding Probing
▼

What is it? Probing is a technique used to understand what kind of information Large Language Models (LLMs) implicitly store within their intermediate representations (embeddings). It involves training a simple, "probe" classifier on these embeddings to predict a specific linguistic property (e.g., part-of-speech, sentiment, syntactic role). If the probe can accurately predict the property, it suggests that the LLM's embeddings encode that information in an accessible way.

Analogy: Imagine you're a detective trying to figure out if a complex, encrypted diary (the LLM's internal state) contains information about a specific topic, say, "the weather." Instead of trying to decrypt the whole diary, you take a few sentences, translate them into a simplified code (the embedding), and then train a very simple, small algorithm (the probe) to predict if those sentences were about the weather. If your small algorithm is highly successful, you conclude that "weather information" is present and easily extractable from the diary's simplified code, even if you don't know *how* the main diary uses it.

💡 If you remember one thing

Probing helps us peer into the "black box" of LLMs. By training a simple, interpretable classifier on LLM embeddings, we can infer what linguistic features (syntax, semantics, sentiment, etc.) are implicitly captured and represented by the LLM at different layers, without needing to understand the LLM's full internal complexity.

How Probing Works Internally
▼

The Probing Pipeline

The standard probing methodology follows a clear sequence of steps:

  1. Data Preparation: Select a dataset where each text input is explicitly labeled with the linguistic property you want to investigate (e.g., sentences labeled with sentiment, words labeled with their part-of-speech).
  2. Embedding Extraction: Pass the text inputs through the target LLM (which is typically frozen, i.e., its weights are not updated). Extract the intermediate representation (embedding vector) from a specific layer for each input. This yields pairs of \((h_i, y_i)\), where \(h_i\) is the LLM embedding and \(y_i\) is the ground-truth label for the property.
  3. Probe Training: Train a simple, often linear, classifier (the "probe") on these \((h_i, y_i)\) pairs. The probe learns to map the LLM's embeddings to the target linguistic labels. Common choices include logistic regression, a single-layer perceptron, or a small feedforward network.
  4. Probe Evaluation: Evaluate the trained probe's performance (e.g., accuracy, F1-score) on a held-out test set. A high score suggests the LLM's embeddings contain readily accessible information about the probed property.

Design Decisions: Why Simplicity Matters

The simplicity of the probe is crucial. If a complex probe (e.g., a deep neural network) achieves high accuracy, it might be learning to *compute* the linguistic property from very raw, unstructured information in the embeddings, rather than simply *reading out* information the LLM already explicitly encoded. A simple probe (like a linear classifier) suggests that the information is organized in a linearly separable fashion within the embedding space, indicating a strong, "explicit" encoding by the LLM itself.

Researchers also often probe different layers of an LLM. Early layers might encode more surface-level properties (like word forms), while deeper layers might capture more abstract, semantic, or syntactic information.

🔑 Key Property

Probing is a diagnostic tool for interpretability. The LLM's weights remain fixed during probing; only the probe's weights are trained. This ensures we are measuring what the LLM *already represents*, not teaching the LLM new capabilities or optimizing its performance on the probing task.

3
Why It Works — The Math & Theory
▼

Formalizing the Probing Objective

Let \(f\) be a pre-trained LLM, and \(h = f(x)\) be the embedding vector extracted from a specific layer for input text \(x\). We want to determine if \(h\) contains information about a linguistic property \(y\). A probe \(g\) is a simple classifier, often a linear layer, with parameters \(\theta_g\).

The probe's prediction is \(\hat{y} = g(h) = g(f(x))\). We train the probe by minimizing a loss function \(\mathcal{L}\) over a dataset \(D = \{(x_i, y_i)\}_{i=1}^N\):

$$\min_{\theta_g} \sum_{(x_i, y_i) \in D} \mathcal{L}(y_i, g(f(x_i)))$$

For a binary classification task (e.g., positive/negative sentiment), \(g\) might be a linear layer followed by a sigmoid activation: \(g(h) = \sigma(w^\top h + b)\). The loss \(\mathcal{L}\) would typically be binary cross-entropy.

The Linear Separability Hypothesis

The core assumption behind using simple linear probes is the "linear separability hypothesis." If a linguistic property is encoded in the LLM's embeddings in such a way that examples with different labels for that property can be perfectly (or near-perfectly) separated by a hyperplane in the embedding space, then a linear probe will achieve high accuracy. This implies a clear, disentangled representation of that property within the LLM's internal state.

The probe effectively searches for such a hyperplane. If it finds one, it means the LLM has already done the heavy lifting of transforming the raw text into a representation where the desired property is easily discernible.

Information Bottleneck and Representational Capacity

Probing is related to the information bottleneck principle. By training a probe, we are asking how much information about \(Y\) is "bottlenecked" through \(H\) (the LLM's embedding space). A high-performing probe means the mutual information \(I(Y; H)\) is high. This can also be seen as an investigation into the *representational capacity* of different LLM layers for various tasks.

⚠️ Common Pitfall

High probe accuracy does not necessarily mean the LLM actively *uses* that information for its primary generative task. It only confirms that the information *exists* in the representation. It's a measure of presence, not necessarily of utility or causality. Furthermore, a low probe accuracy doesn't mean the information is absent, only that it's not linearly separable or easily extractable by the chosen simple probe.

Key Takeaways
▼

When to use probing:

  • Interpretability: To understand what information LLM layers encode (e.g., syntactic trees, semantic roles, factual knowledge).
  • Model Comparison: To compare different LLM architectures or pre-training objectives by seeing which models better encode certain properties.
  • Emergent Capabilities: To investigate if complex linguistic phenomena "emerge" in deeper layers of models trained on simpler tasks.
  • Debugging/Diagnosis: To identify if an LLM is failing at a downstream task because it lacks a crucial upstream linguistic representation.

When NOT to use / Limitations:

  • Improving LLM Performance: Probing is an analysis tool, not a training technique to improve the LLM's primary task performance.
  • Over-interpretation: A high-performing probe doesn't mean the LLM *uses* that information causally for its output, only that it is present.
  • Probe Complexity: Using overly complex probes can obscure whether the information is truly "explicit" in the embedding or merely learnable by the probe itself.
  • Non-linear Encoding: If a property is encoded non-linearly, a simple linear probe might show low accuracy even if the information is present. This is a limitation of the probe, not necessarily the LLM.
💡 Big Picture

Probing classifiers are an indispensable tool in the LLM interpretability toolkit. They offer a systematic, quantitative way to test hypotheses about the internal representations of these powerful, yet opaque, models, allowing researchers to build a clearer picture of their linguistic understanding and capabilities.

Code Trace (Python / PyTorch-like)

import torch
import torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset
# 1. Assume we have a pre-trained LLM (e.g., BERT, GPT)
# and a dataset with text inputs and linguistic labels.
# LLM is frozen: model.eval(), requires_grad=False
# 2. Extract embeddings (e.g., from the last hidden layer)
# text_inputs = ["The cat sat.", "A dog barked loudly."]
# true_labels = [0, 1] # e.g., 0=singular subject, 1=plural subject
# with torch.no_grad():
# llm_embeddings = llm_model(text_inputs).last_hidden_state[:, 0, :]
# # (batch_size, embedding_dim)
# For this example, let's use simulated embeddings and labels
embedding_dim = 768
num_samples = 1000
llm_embeddings = torch.randn(num_samples, embedding_dim)
true_labels = torch.randint(0, 2, (num_samples,)) # Binary labels
# Create DataLoader
dataset = TensorDataset(llm_embeddings, true_labels)
dataloader = DataLoader(dataset, batch_size=32, shuffle=True)
# 3. Define a simple linear probe classifier
class LinearProbe(nn.Module):
def __init__(self, input_dim, num_classes):
super().__init__()
self.linear = nn.Linear(input_dim, num_classes)
def forward(self, x):
return self.linear(x)
probe = LinearProbe(embedding_dim, num_classes=2)
optimizer = torch.optim.Adam(probe.parameters(), lr=0.001)
loss_fn = nn.CrossEntropyLoss()
# 4. Train the probe
num_epochs = 10
for epoch in range(num_epochs):
for batch_embeddings, batch_labels in dataloader:
optimizer.zero_grad()
outputs = probe(batch_embeddings)
loss = loss_fn(outputs, batch_labels)
loss.backward()
optimizer.step()
# 5. Evaluate the probe
probe.eval()
with torch.no_grad():
total_correct = 0
for batch_embeddings, batch_labels in dataloader:
outputs = probe(batch_embeddings)
_, predicted = torch.max(outputs.data, 1)
total_correct += (predicted == batch_labels).sum().item()
accuracy = total_correct / num_samples
print(f"Probe Accuracy: {accuracy:.4f}")
