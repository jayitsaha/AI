Exact Inference: Variable Elimination & Belief Propagation

Computing exact marginals in Bayesian Networks and Markov Random Fields
Advanced Bayesian Networks Probabilistic ML O(n · exp(w))
1
Understanding the Concept
⌄

A Bayesian Network encodes a joint probability distribution over many random variables as a directed graph. Computing a marginal probability — say \(P(X_i)\) — naively requires summing the full joint over all other variables, which is exponential in the number of variables.

Exact inference computes these marginals and conditionals precisely (no sampling, no approximation) by exploiting the graph's factored structure. Two canonical algorithms achieve this:

  • Variable Elimination (VE): Eliminate one variable at a time by multiplying factors that mention it, then summing it out. Yields a single query answer.
  • Belief Propagation (BP): Pass "messages" along graph edges (on a tree/junction-tree). Each node's belief is the product of incoming messages. Runs in one forward+backward sweep; gives ALL marginals simultaneously.
Key Insight
Both algorithms exploit the same algebraic identity — distributivity of summation over products — to avoid exponential blowup. The complexity is governed by treewidth \(w\): the graph structure that determines how large the largest factor table can grow.

Real-world analogy: think of summing a product of many variables. Instead of expanding everything first, you "push sums inside" to cancel variables early — exactly like factoring out constants in algebra before summing.

How It Works Internally
⌄

Variable Elimination

Given a joint \(P(X_1,\ldots,X_n) = \prod_i \phi_i(\mathbf{X}_{C_i})\), to compute \(P(X_q)\):

  1. Choose an elimination ordering \(\pi\) of all non-query variables.
  2. For the next variable \(X_k\) in \(\pi\): collect all factors mentioning \(X_k\), multiply them into one joint factor \(\psi\), then sum \(X_k\) out: \(\tau_k = \sum_{X_k} \psi\). This new factor \(\tau_k\) is added back to the factor pool.
  3. Repeat until only the query variable remains; normalize to get \(P(X_q)\).
$$P(X_q) \propto \sum_{X_1}\cdots\sum_{X_{n-1}} \prod_i \phi_i(\mathbf{X}_{C_i}) = \text{(push sums inside products)}$$

Belief Propagation on Trees

On a tree-structured factor graph, BP runs in two passes — collect (leaves → root) and distribute (root → leaves). Each variable node \(X_i\) sends a message \(\mu_{X_i \to f_j}\) to adjacent factor node \(f_j\), and each factor sends back \(\mu_{f_j \to X_i}\).

$$\mu_{X_i \to f_j}(x_i) = \prod_{f_k \in \text{ne}(X_i) \setminus f_j} \mu_{f_k \to X_i}(x_i)$$
$$\mu_{f_j \to X_i}(x_i) = \sum_{\mathbf{x}_{C_j} \setminus x_i} f_j(\mathbf{x}_{C_j}) \prod_{X_m \in \text{ne}(f_j) \setminus X_i} \mu_{X_m \to f_j}(x_m)$$

The final belief at node \(X_i\) is the (normalized) product of all incoming factor messages:

$$b(x_i) \propto \prod_{f_k \in \text{ne}(X_i)} \mu_{f_k \to X_i}(x_i)$$
Key Property
BP on a tree is exact and terminates in \(O(n \cdot k^2)\) where \(k\) = state-space size. On graphs with cycles, "Loopy BP" runs iteratively but loses exactness guarantees (though it often works well in practice).

Junction Tree for General Graphs

For graphs with cycles, exact inference first runs a triangulation step to add "fill edges," then clusters variables into cliques arranged as a tree (the junction tree). BP is then run on this clique tree. Complexity: \(O(n \cdot k^w)\) where \(w\) = treewidth.

Complexity Warning
Treewidth \(w\) can be as large as \(n-1\) (for a clique), making inference \(O(k^n)\) — intractable. Finding the optimal elimination ordering is NP-hard. In practice, heuristics like min-fill are used.

The Math — Derivation & Guarantees
⌄

Marginal via Factor-Graph Factorization

A factor graph factorizes the joint as \(p(\mathbf{x}) = \frac{1}{Z}\prod_s f_s(\mathbf{x}_{C_s})\). The marginal over \(x_i\) is:

$$p(x_i) = \sum_{\mathbf{x} \setminus x_i} \frac{1}{Z}\prod_s f_s(\mathbf{x}_{C_s})$$

The distributive law lets us push summations inside when a factor does not depend on the variable being summed:

$$\sum_x \phi_A(x,y)\,\phi_B(x,z) = \left(\sum_x \phi_A(x,y)\,\phi_B(x,z)\right) = \tau(y,z)$$

The size of \(\tau\) is the product of the domains of its free variables — this is the source of exponential cost in treewidth.

Message Correctness (Tree Case)

On a tree, messages are computed from leaves inward. Let \(T(f_j, X_i)\) be the subtree rooted at \(f_j\) away from \(X_i\). Then:

$$\mu_{f_j \to X_i}(x_i) = \sum_{\mathbf{x}_{C_j \setminus i}} f_j(\mathbf{x}_{C_j}) \prod_{X_m \in C_j \setminus i} \mu_{X_m \to f_j}(x_m)$$

This is exactly the marginal of the subtree \(T(f_j, X_i)\) over \(x_i\), computed exactly by induction. Belief \(b(x_i) = \prod_k \mu_{f_k \to X_i}(x_i) / Z\) then equals the true marginal \(p(x_i)\).

Numerical Trace — 3-node Chain

Consider \(X_1 - X_2 - X_3\) (binary, each \(\in \{0,1\}\)), with factors:

  • \(\phi_{12}(x_1,x_2) = \begin{bmatrix}0.9 & 0.1 \\ 0.2 & 0.8\end{bmatrix}\) — rows index \(x_1\), cols \(x_2\)
  • \(\phi_{23}(x_2,x_3) = \begin{bmatrix}0.7 & 0.3 \\ 0.4 & 0.6\end{bmatrix}\)
  • Prior \(\phi_1(x_1) = [0.6, 0.4]\)

VE: eliminate \(X_1\), then \(X_2\), query \(X_3\):

$$\tau_1(x_2) = \sum_{x_1} \phi_1(x_1)\,\phi_{12}(x_1,x_2)$$

\(\tau_1(0) = 0.6\times0.9 + 0.4\times0.2 = 0.54+0.08=0.62\); \(\tau_1(1)=0.6\times0.1+0.4\times0.8=0.06+0.32=0.38\).

$$\tau_2(x_3) = \sum_{x_2} \tau_1(x_2)\,\phi_{23}(x_2,x_3)$$

\(\tau_2(0)=0.62\times0.7+0.38\times0.4=0.434+0.152=0.586\); \(\tau_2(1)=0.62\times0.3+0.38\times0.6=0.186+0.228=0.414\). After normalization (sum=1): \(P(X_3=0)=0.586,\;P(X_3=1)=0.414\). ✓ Exact.

Treewidth & Complexity
For an elimination ordering \(\pi\), the induced width \(w_\pi\) = max clique size − 1. The optimal ordering minimizes \(w_\pi\); its minimum over all orderings is the treewidth \(w^*\). VE/BP on the junction tree runs in \(O(n \cdot k^{w^*+1})\).

Key Takeaways & When to Use
⌄
When to Use Exact Inference
  • Graph treewidth is small (≤ 15–20) — VE / junction-tree BP is tractable.
  • You need provably correct marginals (medical diagnosis, formal verification).
  • Tree-structured model: BP is linear-time and exact.
When to Switch to Approximate Inference
  • Dense graphs (e.g., fully connected MRFs) — treewidth too large.
  • Continuous latent variables — use Variational Bayes or MCMC instead.
  • Scale: millions of nodes — use Loopy BP or mean-field VI.

Summary

  • VE and BP both exploit distributivity of + over × — the same idea, different schedules.
  • BP on a tree is exact in \(O(n\,k^2)\); on a junction tree in \(O(n\,k^{w+1})\).
  • Treewidth \(w\) is the fundamental complexity parameter; NP-hard to minimize exactly.
  • Loopy BP often converges to good approximate marginals despite lacking guarantees.

Related topics: Bayes Nets, Markov Random Fields, Approximate Inference (MCMC, Variational), Loopy Belief Propagation, Junction Tree Algorithm.

From-Scratch Python: VE on a Chain
⌄
import numpy as np
def variable_elimination(factors, elim_order, query):
"""Compute P(query) by eliminating variables in elim_order."""
pool = list(factors) # list of (variables_tuple, np.ndarray)
for X in elim_order: # eliminate each non-query variable
# collect all factors that mention X
relevant = [f for f in pool if X in f[0]]
pool = [f for f in pool if X not in f[0]]
# multiply them into a joint factor
joint_vars, joint_table = factor_product(relevant)
# sum out X
ax = joint_vars.index(X)
tau_table = joint_table.sum(axis=ax)
tau_vars = [v for v in joint_vars if v != X]
pool.append((tau_vars, tau_table)) # new factor τ
# multiply remaining factors (only mention query)
_, result = factor_product(pool)
return result / result.sum() # normalize → P(query)
