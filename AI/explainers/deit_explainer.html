Understanding DeiT
▼

What is it? The original Vision Transformer (ViT) chops an image into patches, feeds them through a Transformer, and gets great accuracy — but only if you pre-train it on hundreds of millions of images (Google's private JFT-300M). DeiT ("Data-efficient image Transformer") asks: can we train the exact same architecture using only the public 1.28M-image ImageNet-1K dataset? The answer is yes — using aggressive data augmentation and a clever trick called knowledge distillation through an extra token.

Analogy: Imagine a bright but inexperienced student (the Vision Transformer) trying to master a subject from a small textbook. Instead of just reading the textbook (ground-truth labels), DeiT gives the student a tutor — a seasoned CNN (like RegNet) that already knows the material well. The student doesn't just memorize the answer key; it also learns to imitate exactly how the tutor thinks, via a dedicated "tutor-notes" token that sits alongside the "exam-answer" token in the student's working memory.

💡 If you remember one thing

DeiT adds a second special token — the distillation token — next to the usual class token. Both flow through the same Transformer and attend to the same patches, but the class token is trained against the true label while the distillation token is trained to mimic a CNN teacher's prediction. This, plus heavy augmentation, lets ViT match CNN accuracy training on ImageNet alone.

How DeiT Works Internally
▼

Two Tokens, One Backbone

An image is split into \(N\) fixed-size patches (e.g. 16×16), each linearly projected into a \(D\)-dim embedding, plus a learned position embedding. Two extra learnable vectors are prepended to this sequence: the class token \([\text{cls}]\) (inherited from ViT/BERT) and the distillation token \([\text{dist}]\) (DeiT's contribution). The sequence of length \(N+2\) is fed through standard Transformer encoder blocks — multi-head self-attention followed by an MLP, with LayerNorm and residual connections at every block.

Crucially, self-attention lets every token — including \([\text{cls}]\) and \([\text{dist}]\) — attend to every patch and to each other, at every layer. Nothing architecturally special happens to the distillation token inside the encoder; it is treated exactly like any other token. What makes it special is what it is trained to predict at the output.

Two Heads, Two Teachers

After the final encoder block, the output embedding of \([\text{cls}]\) is passed through a linear classification head and trained with cross-entropy against the true ImageNet label \(y\). The output embedding of \([\text{dist}]\) is passed through a separate linear head and trained to match the prediction of a pre-trained CNN teacher (e.g. RegNetY-16GF) — not the ground truth. Because the two supervision signals differ, the two tokens are free to specialize and, empirically, learn different (complementary) attention patterns before their embeddings even partly correlate at deeper layers.

Design Decision: A Token, Not a Loss Term

An obvious simpler alternative is standard soft-label distillation: just add a KL term between the class token's softmax output and the teacher's softmax output. DeiT's ablations show the token approach — with hard-label distillation — works meaningfully better. Because the distillation token has its own gradient path and its own output embedding, it can converge to a solution that is different from the class token's solution, giving the model two diverse "votes" that are averaged at inference — an implicit ensemble baked into one network.

DeiT also leans hard on augmentation the original ViT paper didn't need at ImageNet scale: RandAugment, Mixup, CutMix, random erasing, and stochastic depth. Without heavy augmentation, ViT overfits badly on only 1.28M images because it lacks the convolutional inductive biases (locality, translation equivariance) that let CNNs generalize from less data.

🔑 Key Property

The distillation token is architecturally identical to the class token — same dimension, same self-attention treatment — but carries a different training signal (teacher prediction instead of ground truth). This turns knowledge distillation into a pure "extra input token + extra loss term" trick, requiring zero changes to the Transformer block itself.

3
Why It Works — The Math
▼

Self-Attention (unchanged from ViT)

Every token \(i\) in the sequence \(Z \in \mathbb{R}^{(N+2)\times D}\) (patches + \([\text{cls}]\) + \([\text{dist}]\)) computes queries, keys, values and attends to all tokens:

$$\text{Attn}(Q,K,V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V, \qquad Q=ZW_Q,\ K=ZW_K,\ V=ZW_V$$

This is what lets \([\text{dist}]\) "look at" every patch and at \([\text{cls}]\) at every layer — there is no separate pathway, only a separate output loss.

Soft Distillation (KL to teacher probabilities)

Let \(Z_s\) be the student logits (from the class-token head) and \(Z_t\) the teacher's logits, \(\psi\) the softmax, \(\tau\) a temperature, and \(\lambda\) a mixing weight. The general distillation objective is:

$$\mathcal{L}_{\text{soft}} = (1-\lambda)\,\mathcal{L}_{\text{CE}}\big(\psi(Z_s), y\big) \;+\; \lambda \tau^2\, \mathrm{KL}\big(\psi(Z_s/\tau)\,\|\,\psi(Z_t/\tau)\big)$$

Hard-Label Distillation (what DeiT actually uses)

DeiT's key empirical finding: replacing the KL term with a second cross-entropy against the teacher's argmax decision \(y_t = \operatorname{argmax}_c Z_t(c)\) works better and needs no temperature or \(\lambda\) tuning. With two separate heads (class head output \(Z_s^{\text{cls}}\), distillation head output \(Z_s^{\text{dist}}\)):

$$\mathcal{L}_{\text{global}} = \tfrac{1}{2}\,\mathcal{L}_{\text{CE}}\big(\psi(Z_s^{\text{cls}}),\, y\big) \;+\; \tfrac{1}{2}\,\mathcal{L}_{\text{CE}}\big(\psi(Z_s^{\text{dist}}),\, y_t\big)$$

Both loss terms backpropagate through their own head into the shared Transformer backbone — the patches, position embeddings, and attention weights are updated by both signals simultaneously.

Inference-Time Fusion

At test time there is no teacher and no ground truth — DeiT simply adds the two heads' softmax outputs to form the final prediction, an implicit two-member ensemble from a single forward pass:

$$\hat{y} = \operatorname{argmax}_c \Big[\psi(Z_s^{\text{cls}})_c + \psi(Z_s^{\text{dist}})_c\Big]$$
⚠️ Common Pitfall

Hard-label distillation still allows label smoothing / Mixup / CutMix on the ground-truth branch — the teacher target \(y_t\) is computed with the CNN's own hard decision, so it stays a single class index even when the input image is a Mixup blend. Conflating the two branches' targets is a common implementation bug.

Key Takeaways
▼

When DeiT's recipe matters:

  • You need Transformer-level accuracy but only have ImageNet-scale (or smaller) labeled data — no access to JFT-300M-style private datasets.
  • You already have a strong CNN checkpoint lying around — it makes a free, effective teacher (CNN teachers outperform Transformer teachers here, likely because they pass on useful inductive biases).
  • You want a training recipe (augmentation + distillation) that is architecture-agnostic and reusable across ViT variants (DeiT-Ti/S/B).

When NOT to reach for it:

  • You already have massive pre-training data/compute (JFT-300M, LAION-scale) — plain ViT pre-training already works fine there.
  • You have no decent teacher model available and training one is more expensive than just collecting more labeled data.
  • Latency-critical deployment where the extra distillation token/head add (small but nonzero) inference cost and you don't need the accuracy bump — drop the token and keep only the class head at inference.
💡 Legacy

DeiT proved Vision Transformers are not inherently data-hungry — the data hunger was a training-recipe problem, not an architecture problem. Its augmentation stack (RandAugment, Mixup/CutMix, stochastic depth) and token-based distillation became standard components in nearly every ViT training pipeline that followed (DeiT-III, Swin, BEiT fine-tuning, etc.).

Code Trace

import torch, torch.nn as nn, torch.nn.functional as F
class DeiT(nn.Module):
def __init__(self, vit_backbone, dim, num_classes):
super().__init__()
self.backbone = vit_backbone # patch embed + encoder blocks
self.cls_token = nn.Parameter(torch.zeros(1, 1, dim))
self.dist_token = nn.Parameter(torch.zeros(1, 1, dim)) # DeiT addition
self.pos_embed = nn.Parameter(torch.zeros(1, 1 + 1 + N_PATCHES, dim))
self.head = nn.Linear(dim, num_classes) # trained on true label
self.head_dist = nn.Linear(dim, num_classes) # trained on teacher
def forward(self, x):
patches = self.backbone.patch_embed(x) # (B, N, D)
cls = self.cls_token.expand(x.shape[0], -1, -1)
dist = self.dist_token.expand(x.shape[0], -1, -1)
z = torch.cat([cls, dist, patches], dim=1) + self.pos_embed
z = self.backbone.encoder(z) # self-attention sees all tokens
cls_out, dist_out = z[:, 0], z[:, 1]
return self.head(cls_out), self.head_dist(dist_out)
def deit_loss(logits_cls, logits_dist, y, teacher_logits):
y_teacher = teacher_logits.argmax(dim=-1) # HARD label distillation
loss_cls = F.cross_entropy(logits_cls, y)
loss_dist = F.cross_entropy(logits_dist, y_teacher)
return 0.5 * loss_cls + 0.5 * loss_dist
@torch.no_grad()
def deit_predict(logits_cls, logits_dist):
probs = F.softmax(logits_cls, -1) + F.softmax(logits_dist, -1) # ensembled
return probs.argmax(dim=-1)
