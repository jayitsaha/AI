How a simple probabilistic model filters unwanted messages

1
Understanding Spam Classifiers
▼

What is it? A spam classifier is a machine learning model designed to automatically detect and filter unwanted (spam) messages from legitimate (ham) ones. It learns patterns from a dataset of labeled emails or texts to predict the category of new, unseen messages.

Analogy: Imagine you have two piles of letters: "important" and "junk mail". You notice that "junk mail" often contains words like "free", "winner", "cash", while "important" letters contain words like "meeting", "report", "deadline". A spam classifier learns these word associations. When a new letter arrives, it checks for these tell-tale words and decides which pile it belongs to, even if it's never seen that exact letter before.

💡 If you remember one thing

Many spam classifiers, especially simpler ones, rely on word frequencies. They calculate the probability of a message being spam or ham based on the individual words it contains, using Bayes' Theorem. The key assumption is that the presence of one word is independent of others, given the message's class (hence "Naive").

2
How Naive Bayes Classifiers Work
▼

The Core Idea: Bayes' Theorem

A Naive Bayes classifier determines the probability of a message belonging to a class (e.g., spam) given its words, \(P(\text{Class} \mid \text{Words})\). It does this by leveraging Bayes' Theorem:

$$P(\text{Class} \mid \text{Words}) = \frac{P(\text{Words} \mid \text{Class}) \cdot P(\text{Class})}{P(\text{Words})}$$

In practice, we compare \(P(\text{Spam} \mid \text{Words})\) with \(P(\text{Ham} \mid \text{Words})\). Since \(P(\text{Words})\) is the same for both, we only need to compare the numerator: \(P(\text{Words} \mid \text{Class}) \cdot P(\text{Class})\).

The "Naive" Assumption: Conditional Independence

The "Naive" part comes from assuming that the presence of each word in a message is conditionally independent of the other words, given the message's class. So, \(P(\text{Words} \mid \text{Class})\) can be broken down into a product of individual word probabilities:

$$P(\text{Words} \mid \text{Class}) \approx \prod_{i=1}^k P(\text{word}_i \mid \text{Class})$$

This simplification makes the model computationally efficient, even though it's often violated in real language (e.g., "credit" often appears with "card"). Despite this, Naive Bayes performs surprisingly well for text classification.

Training Phase: Learning Probabilities

During training, the classifier learns two main types of probabilities from a labeled dataset:

  1. Prior Probabilities: \(P(\text{Class})\) — the overall probability of a message being spam or ham, calculated from the proportion of each class in the training data.
  2. Likelihoods: \(P(\text{word}_i \mid \text{Class})\) — the probability of a specific word appearing in a message, given that the message belongs to a certain class. These are calculated by counting word occurrences within spam and ham messages.

To prevent zero probabilities for unseen words (which would make the entire product zero), a technique called Laplace smoothing (or Add-1 smoothing) is often used. This adds 1 to every word count and adjusts the denominator, ensuring all words have a non-zero probability.

🔑 Key Property

Naive Bayes is a generative model: it models the joint probability \(P(\text{Class}, \text{Words})\) and then uses Bayes' Theorem to derive the posterior \(P(\text{Class} \mid \text{Words})\). Its simplicity and efficiency make it a strong baseline for text classification tasks, especially with limited data.

3
Why It Works — The Probabilistic Framework
▼

Formalizing the Classification Rule

Given a message \(D\) consisting of words \(w_1, w_2, \dots, w_k\), we want to find the class \(C \in \{\text{Spam, Ham}\}\) that maximizes the posterior probability:

$$\hat{C} = \underset{C}{\operatorname{argmax}} \, P(C \mid w_1, \dots, w_k)$$

Using Bayes' Theorem and the Naive assumption:

$$P(C \mid w_1, \dots, w_k) \propto P(C) \prod_{i=1}^k P(w_i \mid C)$$

To avoid numerical underflow when multiplying many small probabilities, we often work with log-probabilities:

$$\hat{C} = \underset{C}{\operatorname{argmax}} \left( \log P(C) + \sum_{i=1}^k \log P(w_i \mid C) \right)$$

The class with the higher log-score is the predicted class.

Calculating Likelihoods with Laplace Smoothing

Let \(N_C\) be the total number of words in all training messages of class \(C\), and \(N_{w,C}\) be the count of word \(w\) in training messages of class \(C\). Let \(V\) be the size of the vocabulary (all unique words seen in training). With Laplace smoothing, the likelihood is:

$$P(w \mid C) = \frac{N_{w,C} + 1}{N_C + V}$$

This ensures that even words not seen in a particular class (where \(N_{w,C}=0\)) get a non-zero probability, preventing the entire product from becoming zero. The "+1" in the numerator is the "add-1" part, and the "+V" in the denominator accounts for adding 1 to all \(V\) word counts.

⚠️ Common Pitfall

The "Naive" assumption means that word order and context are completely ignored. For example, "buy now" and "now buy" are treated identically. This limits its ability to understand nuances like sarcasm or complex sentence structures. More advanced NLP models (like Transformers) capture these dependencies but are far more complex.

Key Takeaways
▼

When to use Naive Bayes for spam classification:

  • When you have a relatively small dataset and need a simple, fast, and interpretable baseline.
  • For tasks where the "naive" conditional independence assumption holds reasonably well (e.g., many text classification problems).
  • When computational resources are limited, as it's very efficient to train and classify.
  • As a component in more complex systems (e.g., for initial filtering before heavier models).

When NOT to use / limitations:

  • When word order, context, or semantic relationships are crucial for classification (e.g., distinguishing "not good" from "good").
  • If features are highly correlated, violating the independence assumption can lead to suboptimal performance.
  • For tasks requiring very high accuracy where more sophisticated models (SVMs, deep learning) can extract richer features.
  • When dealing with very sparse data without proper smoothing, probabilities can become zero, leading to issues.
💡 Beyond Naive Bayes

While foundational, real-world spam filters today use a combination of techniques: advanced machine learning models (gradient boosting, deep learning), heuristic rules, sender reputation, domain blacklists, and even user feedback. Naive Bayes remains a powerful conceptual tool and a strong baseline for many text tasks.

Code Trace (Python from scratch)
▼
import math
from collections import defaultdict
class NaiveBayesClassifier:
def __init__(self, alpha=1.0): # alpha is Laplace smoothing parameter
self.alpha = alpha
self.vocab = set()
self.class_counts = defaultdict(int) # N_C
self.word_counts = defaultdict(lambda: defaultdict(int)) # N_w,C
self.total_words_in_class = defaultdict(int) # sum of N_w,C for all w in C
def _tokenize(self, text):
return text.lower().split()
def train(self, messages, labels):
for msg, label in zip(messages, labels):
self.class_counts[label] += 1
tokens = self._tokenize(msg)
for word in tokens:
self.vocab.add(word)
self.word_counts[label][word] += 1
self.total_words_in_class[label] += 1
def _get_word_prob(self, word, label):
# P(word | Class) = (N_w,C + alpha) / (N_C + alpha * |V|)
count_word_in_class = self.word_counts[label][word]
total_words_in_class = self.total_words_in_class[label]
vocab_size = len(self.vocab)
return (count_word_in_class + self.alpha) / \
(total_words_in_class + self.alpha * vocab_size)
def classify(self, message):
tokens = self._tokenize(message)
scores = {}
for label in self.class_counts:
# log P(Class)
log_prior = math.log(self.class_counts[label] / sum(self.class_counts.values()))
log_likelihood = 0.0
for word in tokens:
log_likelihood += math.log(self._get_word_prob(word, label))
scores[label] = log_prior + log_likelihood
return max(scores, key=scores.get), scores
