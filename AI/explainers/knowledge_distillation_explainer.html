Understanding Knowledge Distillation
▼

What is it? Knowledge distillation trains a small "student" network to reproduce the behavior of a large, accurate "teacher" network — not by copying its weights, but by matching its output distribution. Instead of only telling the student "this image is a cat" (a hard 0/1 label), the teacher also reveals how confident it is in every wrong answer, e.g. "a little bit dog, almost no car."

Analogy: Imagine a master chef (teacher) tasting a dish and grading it not just "good" or "bad" (hard label) but saying "this tastes 70% like dish A, 25% like dish B, 5% like dish C." An apprentice (student) who trains on this rich feedback learns the subtle relationships between dishes far faster than one who only ever hears pass/fail.

One-sentence summary: Distillation transfers a big model's soft, temperature-scaled probability distribution — its "dark knowledge" of inter-class similarity — into a much smaller model via a KL-divergence loss.

💡 If you remember one thing

Raising the softmax temperature \(T\) flattens the teacher's distribution, exposing relative probabilities between wrong classes ("dark knowledge") that a hard one-hot label throws away completely. The student learns from this richer signal via $$\mathcal{L} = \alpha T^2 \cdot \mathrm{KL}(p_T^{(T)} \,\|\, p_S^{(T)}) + (1-\alpha)\cdot \mathrm{CE}(y, p_S^{(1)})$$

How Distillation Works Internally
▼

Step 1 — The Teacher's Raw Logits

A large, already-trained teacher network runs a forward pass on an image of a cat and outputs raw, un-normalized logits — one real number per class — say \(z_T = [4.0,\ 2.0,\ 1.6,\ -0.5,\ -2.5]\) for classes {Cat, Dog, Wolf, Car, Plane}. At standard temperature (\(T=1\)) the softmax of these logits is extremely peaked: roughly 84% Cat and under 2% for Car — nearly indistinguishable from the hard one-hot label.

Step 2 — Soften with Temperature

Dividing logits by a temperature \(T>1\) before the softmax compresses the gaps between logits, so the exponentials don't blow up the largest one. At \(T=4\), Cat might drop to ~40% while Dog rises to ~18% and Car creeps up to ~4% — still ranked correctly, but now the ratios between wrong classes carry information: the teacher is saying "Dog is much more cat-like than Car," which is exactly the kind of relational knowledge a one-hot label can never express.

Step 3 — Train the Student on Soft + Hard Targets

The small student computes its own logits \(z_S\) for the same input. It is trained on a weighted mix: match the teacher's softened distribution (KL divergence at temperature \(T\)) and match the true hard label (ordinary cross-entropy at \(T=1\)). Both teacher and student use the same \(T\) when computing the soft-target loss so the comparison is apples-to-apples.

🔑 Design decision — why multiply by T²?

The gradient of the soft-target loss with respect to student logits scales as \(1/T\) (each softmax-with-temperature gradient carries a \(1/T\) factor). Without correction, a large \(T\) would shrink this gradient toward zero relative to the hard-label term. Multiplying the whole KL term by \(T^2\) exactly cancels that shrinkage, keeping the two loss components on comparable scales regardless of the temperature chosen (Hinton, Vinyals & Dean, 2015).

3
Why It Works — The Math
▼

The Distillation Loss

Let \(p_T^{(T)} = \mathrm{softmax}(z_T/T)\) and \(p_S^{(T)} = \mathrm{softmax}(z_S/T)\) be the temperature-softened teacher and student distributions, and \(y\) the one-hot hard label. The full loss is:

$$\mathcal{L}(z_S) = \alpha\, T^2 \underbrace{\sum_i p_{T,i}^{(T)} \log\frac{p_{T,i}^{(T)}}{p_{S,i}^{(T)}}}_{\mathrm{KL}(p_T^{(T)} \Vert p_S^{(T)})} \;+\; (1-\alpha)\underbrace{\left(-\sum_i y_i \log p_{S,i}^{(1)}\right)}_{\text{cross-entropy on hard label}}$$

Gradient Derivation

Since \(\log p_{S,i}^{(T)} = z_{S,i}/T - \log\sum_j e^{z_{S,j}/T}\), differentiating gives \(\partial \log p_{S,i}^{(T)}/\partial z_{S,j} = \tfrac{1}{T}(\delta_{ij} - p_{S,j}^{(T)})\). Substituting into the KL term (the teacher term is constant w.r.t. the student) and simplifying with \(\sum_i p_{T,i}^{(T)} = 1\):

$$\frac{\partial\, \mathrm{KL}(p_T^{(T)}\Vert p_S^{(T)})}{\partial z_{S,j}} = \frac{1}{T}\left(p_{S,j}^{(T)} - p_{T,j}^{(T)}\right)$$

The \(T^2\) prefactor cancels one power of \(T\), leaving a clean, \(T\)-scaled gradient. Adding the standard softmax cross-entropy gradient for the hard-label term gives the full update direction actually used by the training loop in the visualization below:

$$\frac{\partial \mathcal{L}}{\partial z_{S,j}} = \alpha\, T\left(p_{S,j}^{(T)} - p_{T,j}^{(T)}\right) \;+\; (1-\alpha)\left(p_{S,j}^{(1)} - y_j\right)$$

Gradient descent \(z_S \leftarrow z_S - \eta \,\partial \mathcal{L}/\partial z_S\) pulls the student's logits toward a shape whose softmax matches the teacher's soft targets while still respecting the ground truth.

⚠️ Common pitfall

Temperature is a double-edged knob. \(T\) too low (\(\approx 1\)) recovers almost no dark knowledge — the teacher's distribution is already near one-hot. \(T\) too high flattens everything toward uniform, drowning the useful relative signal in noise. In practice \(T \in [2,10]\) with \(\alpha \in [0.5, 0.9]\) is the typical sweet spot, tuned per task.

Key Takeaways
▼

When to use distillation:

  • You need a much smaller/faster model for deployment (mobile, edge, low-latency serving)
  • You have (or can query) a strong teacher, but limited labeled data for the student
  • You want an ensemble's knowledge compressed into a single model

When NOT to use:

  • The teacher itself is barely better than the student — little dark knowledge to transfer
  • Extremely tight latency budgets where even student inference plus teacher-generation cost is unaffordable at train time (mitigated by pre-computing teacher outputs offline)
  • Task requires calibrated probabilities and no one has validated the temperature choice
ApproachSignal usedTypical result
Train student from scratch (hard labels only)One-hot \(y\)Baseline accuracy, slower convergence

💡 Takeaway

Distillation is compression through imitation of the output distribution, not through pruning or quantizing weights. It is complementary — you can prune AND distill the same student.

Code Trace
▼
import numpy as np
def softmax(z, T=1.0):
z = z / T
z = z - z.max() # numerical stability
e = np.exp(z)
return e / e.sum()
def kd_loss_and_grad(z_teacher, z_student, y_onehot, T=4.0, alpha=0.7):
pT_soft = softmax(z_teacher, T) # frozen teacher soft target
pS_soft = softmax(z_student, T) # student soft prediction
pS_hard = softmax(z_student, 1.0) # student prediction, T=1
kl = np.sum(pT_soft * np.log(pT_soft / pS_soft))
ce = -np.sum(y_onehot * np.log(pS_hard))
loss = alpha * (T ** 2) * kl + (1 - alpha) * ce
# dL/dz_student (derived in Card 3)
grad = alpha * T * (pS_soft - pT_soft) + (1 - alpha) * (pS_hard - y_onehot)
return loss, grad
# Training loop: distill teacher -> tiny student
z_student = np.zeros(5) # untrained student logits
for step in range(40):
loss, grad = kd_loss_and_grad(z_teacher, z_student, y_onehot, T=4.0, alpha=0.7)
z_student -= 0.6 * grad # gradient descent
print("Student now agrees with teacher:", softmax(z_student).argmax() == z_teacher.argmax())
