Understanding Dynamic Programming in RL
▼

What is it? Dynamic Programming (DP) refers to a collection of algorithms that solve complex problems by breaking them down into simpler subproblems and storing the solutions to avoid recomputing them. In Reinforcement Learning (RL), DP is used when we have a perfect model of the environment (a Markov Decision Process, or MDP) to compute optimal policies and value functions. It's a foundational concept, even if real-world problems rarely provide perfect models.

Analogy: Imagine you're planning a trip across a city with many interconnected roads and various points of interest (states). Each road segment (action) has a travel time (reward). You want to find the fastest route to a specific destination (optimal policy) and know how long it will take from any starting point (value function). DP is like having a map with all travel times and using it to systematically calculate the fastest route for every single intersection, working backward or iteratively until all routes are optimized.

💡 If you remember one thing

DP algorithms in RL iterate over Bellman equations to find consistent value functions and policies. Policy Evaluation computes the value for a fixed policy, Policy Iteration alternates between evaluation and improvement, and Value Iteration directly solves for the optimal value function.

2
How DP Algorithms Work
▼

The Markov Decision Process (MDP)

DP methods require a full model of the MDP, defined by:

  • A set of states \(\mathcal{S}\) (e.g., grid cells).
  • A set of actions \(\mathcal{A}\) (e.g., Up, Down, Left, Right).
  • Transition probabilities \(P(s' \mid s, a)\): the probability of reaching state \(s'\) from state \(s\) after taking action \(a\).
  • Reward function \(R(s, a, s')\): the immediate reward received after transitioning from \(s\) to \(s'\) via action \(a\).
  • A discount factor \(\gamma \in [0, 1]\): how much future rewards are valued relative to immediate rewards.

Policy Evaluation: Estimating \(V^{\pi}\)

Given a fixed policy \(\pi(a \mid s)\) (the probability of taking action \(a\) in state \(s\)), policy evaluation computes the state-value function \(V^{\pi}(s)\). This function represents the expected total discounted future reward an agent can expect to receive starting from state \(s\) and following policy \(\pi\). It's an iterative process that repeatedly applies the Bellman expectation equation as an update rule until \(V^{\pi}(s)\) converges.

Policy Improvement: Deriving a Better Policy

Once \(V^{\pi}(s)\) is known, we can improve the policy. For each state \(s\), we consider all possible actions \(a\), and choose the action that leads to the highest expected future reward, given the current value function \(V^{\pi}\). This creates a new, greedy policy \(\pi'\) that is guaranteed to be as good as, or better than, the previous policy \(\pi\).

Policy Iteration: Alternating Evaluation and Improvement

Policy iteration combines these two steps:

  1. Policy Evaluation: Evaluate the current policy \(\pi\) to get \(V^{\pi}\).
  2. Policy Improvement: Create a new, greedy policy \(\pi'\) from \(V^{\pi}\).
These steps are repeated until the policy no longer changes (i.e., \(\pi' = \pi\)), at which point both the optimal policy \(\pi^*\) and the optimal value function \(V^*\) have been found.

Value Iteration: Directly Finding \(V^*\)

Value iteration is a simpler, more direct approach to finding \(V^*\). Instead of evaluating a full policy first, it directly applies the Bellman optimality equation as an update rule. This single update step combines the evaluation and improvement logic by taking the maximum over all possible actions. It iterates until the value function converges, from which the optimal policy can then be extracted.

🔑 Key Property

All DP algorithms are bootstrapping methods: they update the value estimate for a state \(s\) based on the estimated values of successor states \(s'\). This iterative self-consistency is what drives convergence to optimal solutions.

3
Why It Works — The Bellman Equations
▼

Bellman Expectation Equation (for Policy Evaluation)

The core of policy evaluation is the Bellman expectation equation. It expresses the value of a state \(s\) under a policy \(\pi\) as the sum of the immediate reward \(R_{s,a,s'}\) and the discounted value of the next state \(V^{\pi}(s')\), averaged over all possible actions and next states:

$$V^{\pi}(s) = \sum_{a \in \mathcal{A}} \pi(a \mid s) \sum_{s' \in \mathcal{S}} P(s' \mid s, a) \left( R(s, a, s') + \gamma V^{\pi}(s') \right)$$

This equation is used iteratively: \(V_{k+1}(s) = \dots\) where \(V_k(s')\) is used on the right-hand side. Convergence is guaranteed for \(\gamma < 1\).

Policy Improvement Theorem

If a policy \(\pi'\) is greedy with respect to \(V^{\pi}\), meaning for all \(s \in \mathcal{S}\):

$$\pi'(s) = \underset{a}{\operatorname{argmax}} \sum_{s' \in \mathcal{S}} P(s' \mid s, a) \left( R(s, a, s') + \gamma V^{\pi}(s') \right)$$

then \(\pi'\) is guaranteed to be as good as, or better than, \(\pi\). If \(\pi' = \pi\), then \(\pi\) is an optimal policy \(\pi^*\).

Bellman Optimality Equation (for Value Iteration)

Value iteration directly finds the optimal value function \(V^*(s)\) by applying the Bellman optimality equation. This equation states that the optimal value of a state must be equal to the maximum expected return over all possible actions:

$$V^*(s) = \underset{a}{\operatorname{max}} \sum_{s' \in \mathcal{S}} P(s' \mid s, a) \left( R(s, a, s') + \gamma V^*(s') \right)$$

Similar to policy evaluation, this is applied iteratively: \(V_{k+1}(s) = \underset{a}{\operatorname{max}} \sum_{s' \in \mathcal{S}} P(s' \mid s, a) \left( R(s, a, s') + \gamma V_k(s') \right)\). The convergence of \(V_k\) to \(V^*\) is guaranteed.

⚠️ Computational Complexity

DP algorithms are computationally intensive. Each iteration involves a sweep over all states, and for each state, considering all actions and all possible next states. This leads to a complexity per iteration of roughly \(O(|\mathcal{S}|^2 |\mathcal{A}|)\) for dense MDPs, making them impractical for very large state spaces. For sparse MDPs, it's \(O(|\mathcal{S}| |\mathcal{A}| \sum_{s'} P(s'|s,a))\).

Key Takeaways
▼

When to use Dynamic Programming:

  • When you have a perfect model of the environment (a known MDP with all transition probabilities and rewards).
  • For small to medium-sized state spaces where \(O(|\mathcal{S}|^2 |\mathcal{A}|)\) or \(O(|\mathcal{S}| |\mathcal{A}|)\) complexity per iteration is acceptable.
  • As a foundational understanding for more advanced RL algorithms that approximate these DP ideas (e.g., Q-learning, SARSA).

Limitations of DP:

  • Requires a model: This is the biggest drawback. In most real-world scenarios, the environment dynamics are unknown.
  • Computational expense: The "curse of dimensionality" means DP becomes intractable for large state spaces (e.g., continuous states, or states with many features).
  • Fixed environment: DP assumes a stationary MDP. If environment dynamics change, the optimal policy must be recomputed.
💡 Policy Iteration vs. Value Iteration

Policy Iteration typically takes fewer iterations to converge than Value Iteration, but each policy evaluation step might require many sweeps. Value Iteration often takes more iterations but each iteration is computationally cheaper (a single Bellman optimality update per state). Both converge to the optimal policy and value function.

Code Trace (Python-like Pseudocode)
▼
# Assume: S (states), A (actions), P(s'|s,a), R(s,a,s'), gamma
# V: state-value function (dict {s: float}), pi: policy (dict {s: a})
def policy_evaluation(pi, V, gamma, theta=1e-6):
while True:
delta = 0
for s in S:
v = V[s]
new_v_s = 0
for a in A: # For deterministic policy, pi(a|s) is 1 for chosen a, 0 otherwise
if a == pi[s]:
for s_prime in S:
prob = P(s_prime | s, a) # Transition probability
reward = R(s, a, s_prime) # Immediate reward
new_v_s += prob * (reward + gamma * V[s_prime])
V[s] = new_v_s
delta = max(delta, abs(v - V[s]))
if delta < theta:
break
return V
def policy_improvement(V, gamma):
new_pi = {}
for s in S:
q_values = {}
for a in A:
q = 0
for s_prime in S:
prob = P(s_prime | s, a)
reward = R(s, a, s_prime)
q += prob * (reward + gamma * V[s_prime])
q_values[a] = q
new_pi[s] = max(q_values, key=q_values.get) # Greedy action
return new_pi
def policy_iteration(gamma):
V = {s: 0 for s in S} # Initialize V arbitrarily
pi = {s: random_action() for s in S} # Initialize pi arbitrarily
while True:
V = policy_evaluation(pi, V, gamma)
new_pi = policy_improvement(V, gamma)
if new_pi == pi:
break
pi = new_pi
return V, pi
def value_iteration(gamma, theta=1e-6):
V = {s: 0 for s in S} # Initialize V arbitrarily
while True:
delta = 0
for s in S:
v = V[s]
max_q = -float('inf')
for a in A:
q = 0
for s_prime in S:
prob = P(s_prime | s, a)
reward = R(s, a, s_prime)
q += prob * (reward + gamma * V[s_prime])
max_q = max(max_q, q)
V[s] = max_q
delta = max(delta, abs(v - V[s]))
if delta < theta:
break
pi = policy_improvement(V, gamma) # Derive optimal policy from V*
return V, pi
