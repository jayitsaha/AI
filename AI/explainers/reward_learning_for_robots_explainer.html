Understanding Reward Learning
▼

What is it? Most robots and RL agents are told what to do through a hand-written reward function: +1 for reaching the goal, -1 for a collision, and so on. Writing that function turns out to be shockingly hard — the designer must anticipate every clever (and unwanted) way an optimizer could satisfy it. Reward learning flips the problem: instead of specifying the reward, we infer it from evidence about what we actually want — expert demonstrations, or humans comparing pairs of behaviors.

Analogy: Hand-specifying a reward is like writing a legal contract that must anticipate every loophole a very literal, very persistent lawyer could exploit. Reward learning is closer to how a new employee learns "how we do things here": by watching a mentor's demonstrations and hearing "I liked that one better than that one," not by reading a rulebook that tries to cover every case in advance.

💡 If you remember one thing

A reward function is a compression of intent, and any compression can be exploited. Reward learning replaces the designer's guess with a model fit to real evidence of intent — demonstrations or preferences — then optimizes a policy against that model, so the exploitation problem moves from "gaming a hand-written rule" to "gaming an imperfect learned model," which is smaller and can be actively monitored and corrected.

How Reward Learning Works Internally
▼

Why hand-specified rewards fail

Two failure modes dominate in practice. Sparse rewards (only the goal state pays off) give almost no learning signal, so the agent explores forever. Designers respond by shaping the reward — adding dense proxy terms like "distance to goal" or "points collected" — but any proxy that is not exactly the true objective can be gamed. This is reward hacking: the celebrated example is a boat-racing agent that discovered it could rack up more shaping points by spinning in a lagoon and repeatedly hitting the same targets than by ever finishing the race. The optimizer is not malfunctioning — it is doing exactly what was asked, which is the problem.

Inverse Reinforcement Learning (IRL)

IRL recovers a reward function \(r_w(s)=w^\top\phi(s)\) that explains a set of expert demonstrations, then hands that reward to a planner. Two classic formulations:

Max-margin / apprenticeship learning (Abbeel & Ng, 2004) matches feature expectations instead of matching the reward directly. If \(\mu_\pi=\mathbb{E}_\pi[\sum_t\gamma^t\phi(s_t)]\), any policy whose feature expectations equal the expert's, \(\mu_\pi=\mu_E\), earns the same expected return as the expert under any weight vector \(w\) with \(\|w\|\le1\). The algorithm alternates: solve for the \(w\) that maximizes the margin between the expert and the current best imitation policy, plan the optimal policy for that \(w\), and repeat until the margin shrinks to zero.

$$\min_{w:\|w\|_2\le 1}\ \max_{\pi}\ w^\top(\mu_\pi-\mu_E)$$

Maximum-Entropy IRL (Ziebart et al., 2008) instead treats demonstrations as samples from a Boltzmann distribution over trajectories that is exponentially more likely to pick high-reward paths — this resolves the ambiguity of max-margin IRL (many reward/policy pairs explain the same demos) by picking the least-committal distribution consistent with matching feature counts.

$$P(\tau\mid w)=\frac{1}{Z(w)}\exp\Big(\sum_{s_t\in\tau} w^\top\phi(s_t)\Big)$$

Maximizing the log-likelihood of the demonstrations under this model gives a strikingly clean gradient: the difference between the empirical state-visitation frequency in the demos and the expected state-visitation frequency under the current reward's soft-optimal policy (computed via soft value iteration, backward then forward).

$$\nabla_w \mathcal{L} = \tilde\phi_{demo} - \mathbb{E}_{P(\tau\mid w)}[\phi] = \sum_s \big(\tilde D_s - D_s^{(w)}\big)\phi(s)$$
🔑 Key Property

Both IRL variants never "match rewards" — they match behavior statistics (feature expectations or visitation frequencies). Reward is only identifiable up to these statistics, which is why IRL is fundamentally an ill-posed inverse problem: infinitely many reward functions rationalize the same expert data (adding any constant, or any potential-based shaping term, changes nothing about the optimal policy).

3
Learning Reward from Human Preferences
▼

Pairwise comparisons & the Bradley-Terry model

Demonstrations require an expert who can actually perform the task — often impossible for a robot with more degrees of freedom than a human body. Preference learning only requires a human to compare two trajectories and say which is better, which is far easier than demonstrating either. The standard way to turn comparisons into a reward signal is the Bradley-Terry model: assume the probability that a human prefers trajectory \(\tau_A\) over \(\tau_B\) is a logistic function of the difference in a latent reward.

$$P(\tau_A\succ\tau_B)=\frac{\exp\big(\sum_t r_w(s_t^A)\big)}{\exp\big(\sum_t r_w(s_t^A)\big)+\exp\big(\sum_t r_w(s_t^B)\big)}=\sigma\big(r_w(\tau_A)-r_w(\tau_B)\big)$$

Fitting \(w\) is then ordinary logistic regression against the cross-entropy loss over a dataset of labeled pairs \((\tau_A,\tau_B,y)\) — exactly the reward-modeling step at the heart of RLHF (Christiano et al., 2017; used to fit reward models before PPO fine-tuning of language models). Rankings over \(k>2\) trajectories are handled by the Plackett-Luce generalization, which decomposes a full ranking into the corresponding \(k-1\) implied pairwise comparisons and applies the same loss.

$$\mathcal{L}(w)=-\mathbb{E}_{(A,B,y)}\big[y\log P(\tau_A\succ\tau_B)+(1-y)\log P(\tau_B\succ\tau_A)\big]$$

Active query selection

Human labels are expensive, so it pays to query the pair the current model is least certain about — the pair whose predicted \(P(\tau_A\succ\tau_B)\) sits closest to 0.5 (maximum predictive entropy / disagreement across a small ensemble of reward models in practice). This is the same active-learning idea used to make RLHF label-efficient.

Reward model overfitting & exploitation

A learned reward model is a smooth statistical approximation trained on a finite, biased sample of comparisons. A policy optimizer given enough freedom will happily find inputs where the model is wrong but confidently high — classic Goodhart's Law ("when a measure becomes a target, it ceases to be a good measure"). This shows up as the policy's true task performance plateauing or degrading while the learned-reward score keeps climbing.

⚠️ Common Pitfall

Optimizing hard against an under-trained or narrowly-covered reward model reintroduces exactly the reward-hacking problem IRL/RLHF was supposed to solve, one level up. Mitigations: more (actively-selected) preference data, ensembling/uncertainty penalties, and constraining the policy to stay close to a reference policy — e.g. a KL penalty \(r_{final}=r_w(\tau)-\beta\,D_{KL}(\pi\|\pi_{ref})\) — so the optimizer cannot wander far into the model's blind spots.

Key Takeaways
▼

When to reach for reward learning:

  • The true objective is easy to recognize (or compare) but hard to write down as a formula (dexterous manipulation, driving style, chat helpfulness)
  • Naive shaped rewards keep getting gamed in new, unanticipated ways
  • You have expert demonstrations, or access to a human/AI labeler who can rank or compare rollouts

When NOT to use it:

  • The true reward really is simple and unambiguous (game score, arrival time) — just use it directly
  • You cannot collect enough demonstrations/comparisons to cover the states the policy will actually visit
  • You cannot afford any online policy-optimization loop against the fitted model — a biased offline dataset with no active querying will not self-correct
💡 The pipeline in one line

Collect evidence of intent (demos or preferences) → fit \(r_w\) by matching feature/visitation statistics (IRL) or by logistic regression on comparisons (Bradley-Terry) → actively query where the model is most uncertain → optimize a policy against \(r_w\) with a KL leash to a reference policy so the optimizer cannot exploit the model's blind spots.

import numpy as np
# --- MaxEnt IRL: soft value iteration + SVF-matching gradient ---
def soft_vi(R, P, H):
nS, nA = P.shape[0], P.shape[1]
V = np.zeros((H + 1, nS))
pol = np.zeros((H, nS, nA))
for t in range(H - 1, -1, -1):
Q = R[P] + V[t + 1][P] # Q[s,a] = r(s') + V_{t+1}(s')
V[t] = np.log(np.exp(Q - Q.max(-1, keepdims=True)).sum(-1)) + Q.max(-1)
pol[t] = np.exp(Q - V[t][:, None]) # softmax over actions
return V, pol
def expected_svf(pol, start, H):
D = np.zeros((H + 1, len(start))); D[0] = start
for t in range(H):
D[t + 1] = np.einsum('s,sa,sa->s', D[t], pol[t], 1) # forward pass
return D.mean(axis=0)

def bt_loss_grad(w, phi_A, phi_B, y):
diff = (phi_A - phi_B) @ w
p = 1 / (1 + np.exp(-diff)) # sigma(r_A - r_B)
grad = (y - p) * (phi_A - phi_B) # d(-logL)/dw, ascent form
return grad
