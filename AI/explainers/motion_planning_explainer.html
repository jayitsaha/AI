1
Understanding Motion Planning
▼

What is it? Motion planning answers one question: given a robot, a start pose, a goal pose, and a set of obstacles, find a continuous, collision-free path (and ideally a smooth, low-cost trajectory) from start to goal. The robot's possible poses form its configuration space (C-space) — for a point robot in the plane, C-space is just the plane; for a robot arm with 6 joints, C-space is 6-dimensional. Obstacles in the real world become "blocked regions" carved out of C-space (typically by inflating each obstacle by the robot's radius so the robot can be treated as a point).

Analogy: Imagine navigating a maze of bookshelves in the dark, holding a map. A* is like methodically checking every promising aisle in order of "how close does this get me, plus how far have I already walked" — guaranteed to find the shortest route if you check enough aisles. RRT is like throwing darts at random spots in the room and growing a trail of breadcrumbs toward each dart from your nearest breadcrumb — fast to get *a* route, but not necessarily the shortest. Trajectory optimization is what you do afterward: you already have a rough route, so you nudge it smoother and further from the shelves without redoing the whole search.

💡 If you remember one thing

There is no single best planner. A* is complete and optimal but needs a discretized, low-dimensional space. PRM/RRT trade optimality for the ability to scale to high-dimensional, continuous C-spaces via random sampling. RRT* recovers optimality asymptotically. Trajectory optimization (CHOMP/TrajOpt) takes any of these as a seed and locally polishes it for smoothness and clearance.

2
How the Planners Work Internally
▼

A* — Best-First Graph Search

A* discretizes C-space into a graph (e.g. a grid) and explores it with a priority queue ordered by \(f(n) = g(n) + h(n)\), where \(g(n)\) is the exact cost-so-far from the start and \(h(n)\) is a heuristic estimate of the cost-to-go. It maintains an open set (frontier, not yet expanded) and a closed set (finalized nodes). Each pop takes the lowest-\(f\) node, expands its neighbors, and relaxes their tentative costs — exactly Dijkstra's algorithm, but guided toward the goal by \(h\).

PRM — Probabilistic Roadmap (multi-query)

PRM builds a reusable graph over the free space: sample \(N\) random collision-free configurations, then connect pairs within a radius \(r\) whenever the straight-line segment between them is collision-free. The result is a roadmap that any number of start/goal queries can later search (e.g. with Dijkstra or A*) — the expensive roadmap construction is amortized across many queries.

RRT — Rapidly-exploring Random Tree (single-query)

RRT grows one tree rooted at the start. Each iteration samples a random configuration (occasionally the goal itself, "goal biasing"), finds the nearest existing tree node, and takes one small step ("steer") toward the sample. If that step is collision-free, it becomes a new node. This greedily and quickly explores the free space, biased toward large unexplored Voronoi regions — but the resulting path is whatever the tree happened to grow, usually jagged and far from optimal.

RRT* & CHOMP/TrajOpt — Adding Optimality

RRT* keeps RRT's sampling but adds two extra steps per iteration: choose the parent among nearby nodes that minimizes total path cost, then rewire nearby nodes if routing them through the new node would be cheaper. As iterations \(\to \infty\), the tree cost converges to the true optimum — asymptotic optimality. Trajectory optimization instead starts from an existing (possibly rough) path and runs local gradient descent on a cost functional balancing smoothness against obstacle proximity.

🔑 Design decision: why sample instead of search a grid in high-D?

Discretizing a \(d\)-dimensional C-space at resolution \(k\) per axis produces \(k^d\) cells — a 7-DOF arm at a modest \(k=50\) needs \(50^7 \approx 8\times10^{11}\) cells, infeasible for A*. Sampling-based planners (PRM/RRT) never enumerate the space; they only need a fast collision checker, so their cost scales with the number of samples, not \(k^d\).

3
Why It Works — The Math
▼

A* Optimality: Admissibility & Consistency

A* is guaranteed to return the optimal path if the heuristic is admissible — it never overestimates the true remaining cost:

$$h(n) \le h^*(n) \quad \text{for all } n$$

Straight-line (Euclidean) distance to the goal is admissible whenever moves cannot be cheaper than going straight there. If \(h\) is also consistent (satisfies the triangle inequality \(h(n) \le c(n,n') + h(n')\) for every edge), then A* never needs to re-open a closed node, which is what makes the closed set final the moment a node is popped.

RRT* Rewiring & Asymptotic Optimality

Let \(\text{cost}(x)\) be the accumulated path cost from the root to node \(x\). When inserting \(x_{new}\), RRT* searches a shrinking radius \(X_{near}\) and picks the parent minimizing total cost:

$$x_{parent} = \operatorname*{argmin}_{x \in X_{near}} \big[\text{cost}(x) + \|x - x_{new}\|\big]$$

It then rewires: for every \(x \in X_{near}\), if routing through \(x_{new}\) is cheaper, \(x\) adopts \(x_{new}\) as its new parent. Karaman & Frazzoli (2011) show that with the neighborhood radius shrinking as \(r_n \propto (\log n / n)^{1/d}\), the tree cost converges to the optimum in probability as the number of samples \(n \to \infty\).

Trajectory Optimization Objective (CHOMP/TrajOpt)

Given a trajectory \(\xi = (q_1, \dots, q_M)\) of waypoints, CHOMP minimizes a functional trading off smoothness and obstacle cost:

$$U(\xi) = \underbrace{\tfrac{1}{2}\xi^\top A \xi}_{\text{smoothness (discrete Laplacian)}} \;+\; w \sum_{i} c_{obs}(q_i)$$

where \(c_{obs}(q) = \max(0, d_{safe} - d(q))^2\) penalizes points closer than a safety margin \(d_{safe}\) to the nearest obstacle (using the signed distance \(d(q)\)). Gradient descent \(\xi \leftarrow \xi - \eta \nabla U(\xi)\) is local: it refines the given path, it does not search for alternative topological routes — hence it needs a reasonable initial trajectory (e.g. from RRT/PRM) to converge to something collision-free.

⚠️ Common Pitfall

Feeding CHOMP/TrajOpt a straight-line seed that passes through a large obstacle can get it stuck — the gradient locally pushes off the nearest surface but cannot discover it should go around the far side. In practice, seed trajectory optimization with a feasible path from PRM/RRT/RRT* rather than a naive straight line.

Key Takeaways
▼

Trade-off summary:

MethodCompletenessOptimalityScales to high-DTypical use
A*CompleteOptimal*Poor2D/3D grids, game AI
PRMProb. completeNear-optimalGoodMulti-query, static maps
RRTProb. completeNo guaranteeGoodFast single-query, high-D arms
RRT*Prob. completeAsymptotically optimalGoodWhere path quality matters
CHOMP/TrajOptLocal onlyLocal optimumGoodPolishing a seed trajectory

*A* is optimal only for the resolution of its discretization — it finds the best path on the grid, which approximates but does not equal the true continuous optimum.

💡 Hierarchy of use

Low-dimensional, need the provably shortest path → A*. Same environment, many queries → PRM. High-DOF robot, need a fast feasible path → RRT. Have time budget, want a good path → RRT*. Have any path, want it smooth and safe → CHOMP/TrajOpt to refine it. Real systems often chain these: RRT* for a global feasible route, then trajectory optimization for the final smooth, dynamically-executable trajectory.

# --- A* search (grid, 8-connected) ---
open = {start}; g[start] = 0
while open not empty:
n = pop node with min f = g[n] + h(n)
if n == goal: return reconstruct_path(n)
for neighbor in expand(n):
tentative_g = g[n] + cost(n, neighbor)
if tentative_g < g[neighbor]:
g[neighbor] = tentative_g; parent[neighbor] = n
push(open, neighbor, f = tentative_g + h(neighbor))
 
# --- PRM: Probabilistic Roadmap (multi-query) ---
V = N random collision-free samples + {start, goal}
for each pair (a, b) with dist(a, b) < r:
if collision_free(a, b): E.add(edge(a, b))
path = dijkstra(V, E, start, goal) # reused for any query
 
# --- RRT: Rapidly-exploring Random Tree (single-query) ---
T = {start}
for i in range(max_iter):
x_rand = goal if rand() < bias else uniform_sample()
x_near = nearest(T, x_rand)
x_new = steer(x_near, x_rand, step_size)
if collision_free(x_near, x_new):
T.add(x_new, parent = x_near)
if dist(x_new, goal) < tol: return path
 
# --- RRT*: add near-optimal rewiring ---
X_near = near(T, x_new, radius)
x_parent = argmin_{x in X_near} cost(x) + dist(x, x_new)
T.add(x_new, parent = x_parent)
for x in X_near: # rewire
if cost(x_new) + dist(x_new, x) < cost(x):
x.parent = x_new # asymptotically optimal
 
# --- Trajectory Optimization (CHOMP/TrajOpt-style) ---
xi = resample(seed_path, M) # M waypoints
for it in range(K):
grad_smooth = laplacian(xi) # penalize jerk
grad_obs = d(cost_obstacle)/d(xi) # push off obstacles
xi -= lr * (w1*grad_smooth + w2*grad_obs)
