Triplet Loss (Metric Learning)

Pull anchor and positive together, push anchor and negative apart — by a margin
Intermediate Metric Learning Face Recognition O(1) per triplet
1
Understanding Triplet Loss
▼

What is it? Triplet loss trains a neural network to produce embeddings (vectors) such that examples of the same identity/class land close together, and examples of different identities land far apart — without ever needing a fixed list of classes. It does this by looking at three examples at a time: an anchor (A), a positive (P, same identity as A), and a negative (N, a different identity).

Analogy: Imagine sorting a shoebox of photos into a giant room, where you're only allowed to say "these two are closer than those two." You grab a photo of your friend (anchor), another photo of the same friend (positive), and a stranger's photo (negative). You then physically nudge the photos so the two friend-photos end up nearer each other than the stranger's photo is to your friend — with some breathing room (a margin) so the arrangement doesn't just barely satisfy the rule.

This is exactly how FaceNet (Schroff et al., 2015) learned face embeddings good enough to power Google Photos' face clustering — no closed set of "known faces," just a geometry where distance means identity similarity.

💡 If you remember one thing

Triplet loss doesn't care about absolute distances — only about relative order: it pushes until the anchor–negative distance exceeds the anchor–positive distance by at least a margin. $$\mathcal{L}(a,p,n) = \max\big(0,\; d(a,p) - d(a,n) + \text{margin}\big)$$

How It Works Internally
▼

Architecture

A backbone network \(f_\theta\) (e.g., an Inception/ResNet CNN in FaceNet) maps an image \(x\) to an embedding \(e = f_\theta(x) \in \mathbb{R}^d\), usually L2-normalized onto the unit hypersphere so distance is bounded and comparable across examples. Training samples triplets \((a, p, n)\) from a batch: \(a\) and \(p\) share a label, \(n\) does not. The distance used is typically Euclidean: \(d(x,y) = \lVert f_\theta(x) - f_\theta(y) \rVert_2\).

Triplet Mining — the part that actually matters

With \(B\) images per batch there are \(O(B^3)\) possible triplets — far too many, and most are useless. Three mining regimes emerge from where the negative sits relative to the anchor–positive gap:

  • Easy negatives — already farther than \(d(a,p)+\text{margin}\). Loss is exactly 0, gradient is 0. Training on these wastes compute; the network learns nothing.
  • Hard negatives — closer to the anchor than the positive is (\(d(a,n) < d(a,p)\)). These give the largest gradient, but mining only these early in training is notorious for causing collapsed embeddings (see Card 3).
  • Semi-hard negatives — farther than the positive but still inside the margin band: \(d(a,p) < d(a,n) < d(a,p)+\text{margin}\). FaceNet's key trick: mine only semi-hard negatives within each mini-batch. They produce a nonzero, well-behaved gradient without the instability of the hardest examples.

Numerical trace

Anchor at \((0,0)\), positive at \((0.3, 0.4)\) ⇒ \(d(a,p) = 0.5\). With margin \(=1.0\), three candidate negatives:

  • \(n_1 = (0.1, 0.1)\), \(d(a,n_1) \approx 0.14\) → hard → loss \(= 0.5 - 0.14 + 1.0 = 1.36\)
  • \(n_2 = (0.5, 0.6)\), \(d(a,n_2) \approx 0.78\) → semi-hard → loss \(= 0.5 - 0.78 + 1.0 = 0.72\)
  • \(n_3 = (1.6, 1.6)\), \(d(a,n_3) \approx 2.26\) → easy → loss \(= \max(0,\, 0.5-2.26+1.0)=0\)
🔑 Design Decision — why a margin at all?

Without a margin, the loss is satisfied the instant \(d(a,n) \ge d(a,p)\) — an infinitesimally thin, unstable boundary. The margin forces a buffer zone between classes, which is what gives the resulting embedding space robustness to noise and unseen identities at test time.

3
Why It Works — The Math
▼

The hinge objective

For embeddings \(e_a, e_p, e_n \in \mathbb{R}^d\) with \(d(x,y) = \lVert e_x - e_y \rVert_2\), the objective over the whole training set is:

$$\sum_{(a,p,n)\in\mathcal{T}} \max\Big(0,\; \lVert e_a-e_p\rVert_2 - \lVert e_a-e_n\rVert_2 + \alpha\Big)$$

where \(\mathcal{T}\) is the (mined) set of triplets and \(\alpha\) is the margin. This is a hinge loss on the difference of distances — it is zero exactly when the margin constraint \(d(a,p) + \alpha \le d(a,n)\) already holds, so no gradient flows through satisfied triplets.

Gradient computation

When the triplet is active (loss \(>0\)), differentiating \(d(x,y)=\lVert e_x-e_y\rVert_2\) gives \(\partial d(x,y)/\partial e_x = (e_x-e_y)/d(x,y)\), so:

$$\frac{\partial \mathcal{L}}{\partial e_a} = \frac{e_a-e_p}{d(a,p)} - \frac{e_a-e_n}{d(a,n)}, \qquad \frac{\partial \mathcal{L}}{\partial e_p} = -\frac{e_a-e_p}{d(a,p)}, \qquad \frac{\partial \mathcal{L}}{\partial e_n} = \frac{e_a-e_n}{d(a,n)}$$

Read geometrically: the positive's gradient pulls it directly toward the anchor; the negative's gradient pushes it directly away from the anchor; the anchor's gradient is a tug-of-war between the two. When the triplet is inactive, all three gradients are exactly zero.

Convergence intuition

Minimizing this over many triplets is a large-margin nearest-neighbor objective (closely related to LMNN): it shapes the embedding space so every same-class pair is closer than every different-class pair by at least \(\alpha\), for as many triplets as possible simultaneously — it does not pull same-class points to a single location, only enforces the relative ordering.

⚠️ Failure Mode — Embedding Collapse

If the network maps every input to (nearly) the same vector, then \(d(a,p)\approx d(a,n)\approx 0\), so \(\mathcal{L}\approx \max(0,\alpha)=\alpha\) — a constant loss with a near-zero gradient for every triplet (since \(e_a-e_p \approx e_a - e_n \approx 0\)). This is a shallow, easy-to-reach bad optimum that random or all-hard mining can walk straight into early in training. Semi-hard mining and a well-tuned margin are what keep training away from this trap.

Key Takeaways
▼

When to use triplet loss:

  • Open-set problems — face verification, person re-identification, speaker verification — where the label set at test time is unbounded or unseen during training
  • You need a metric embedding space (nearest-neighbor search, clustering, one-shot/few-shot matching), not just a classifier

When NOT to use it:

  • Closed, fixed set of classes — a softmax classifier (or ArcFace/CosFace margin-softmax) trains faster and more stably, with no mining pipeline
  • Small batches / no mining infrastructure — random triplets are mostly "easy" and waste nearly all your gradient steps

💡 The real lesson

Triplet loss's formula is simple; its mining strategy is where nearly all the engineering and research effort goes. Semi-hard mining (FaceNet) — and later proxy-based losses that sidestep mining entirely (ArcFace) — exist precisely because naive triplet sampling doesn't scale or converge reliably.

Code: Triplet Loss + Semi-Hard Mining
▼
import torch, torch.nn.functional as F
# embeddings: (B, d) L2-normalized batch, labels: (B,)
def pairwise_dist(emb):
# ||x_i - x_j||_2 for all pairs, shape (B, B)
sq = (emb ** 2).sum(dim=1, keepdim=True)
d2 = sq + sq.T - 2 * emb @ emb.T
return d2.clamp(min=0).sqrt()
def semi_hard_triplet_loss(embeddings, labels, margin=1.0):
D = pairwise_dist(embeddings) # (B, B)
same = labels.unsqueeze(0) == labels.unsqueeze(1)
losses = []
for a in range(len(labels)):
pos_idx = (same[a] & (torch.arange(len(labels)) != a)).nonzero().flatten()
neg_idx = (~same[a]).nonzero().flatten()
if len(pos_idx) == 0 or len(neg_idx) == 0:
continue
for p in pos_idx:
d_ap = D[a, p]
d_an = D[a, neg_idx]
# semi-hard: farther than positive, but within the margin band
semi_hard = neg_idx[(d_an > d_ap) & (d_an < d_ap + margin)]
if len(semi_hard) > 0:
n = semi_hard[D[a, semi_hard].argmin()] # closest semi-hard negative
else:
n = neg_idx[D[a, neg_idx].argmin()] # fallback: hardest negative
loss = F.relu(d_ap - D[a, n] + margin)
losses.append(loss)
return torch.stack(losses).mean()
