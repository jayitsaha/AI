Understanding ALiBi
▼

What is it? ALiBi (Attention with Linear Biases) is a way for a transformer to know the order of tokens without ever adding a positional-embedding vector to the input. Instead, right before the softmax in each attention head, it subtracts a penalty proportional to how far apart the query and key tokens are. Close tokens get almost no penalty; far tokens get heavily discouraged.

Analogy: Think of a classroom discussion where the teacher (the query token) hears everyone, but students sitting far away are asked to speak more quietly the farther back they sit — a simple, fixed "distance tax." No student needs a name tag encoding their seat number (a positional embedding); the room's physical layout does the job automatically, and it still works if you add more rows of chairs later (a longer sequence at inference time).

💡 If you remember one thing

ALiBi replaces learned/sinusoidal positional embeddings with a static, non-learned bias added directly to attention logits: $$\text{softmax}\Big(q_i k_j^\top / \sqrt{d} \;-\; m \cdot (i-j)\Big), \quad j \le i$$ where \(m\) is a fixed, head-specific slope. This one change lets the same model extrapolate to sequences far longer than it was trained on.

How ALiBi Works Internally
▼

The Problem with Learned/Sinusoidal Positions

Standard transformers inject position by adding a vector \(p_i\) to the token embedding at position \(i\), either learned (GPT-2, BERT) or sinusoidal (original Transformer). Both are computed or trained for positions \(0 \ldots L_{\text{train}}-1\). Feed the model a sequence longer than \(L_{\text{train}}\) and it either has no embedding to use (learned) or extrapolates into a regime the sinusoids were never optimized for — performance collapses, an effect the ALiBi paper calls failure to extrapolate.

The ALiBi Fix: Bias the Scores, Not the Inputs

ALiBi removes positional embeddings entirely. After computing the usual scaled dot-product attention scores \(q_i k_j^\top\), it adds a bias matrix that only depends on the integer distance \(i-j\) between query position \(i\) and key position \(j\) (causal attention, so \(j \le i\)). The bias is linear in distance and scaled by a head-specific slope \(m\), then softmax is applied as usual.

Design Decision: Why Different Slopes Per Head?

Every attention head gets its own fixed slope \(m_h\), chosen from a geometric sequence — e.g. for 8 heads: \(2^{-1}, 2^{-2}, \ldots, 2^{-8}\). A head with a steep slope (large \(m_h\)) is forced to attend almost only to nearby tokens (a "local" head); a head with a shallow slope (small \(m_h\)) can still see far-away tokens (a "global" head). Because the slopes are fixed rather than learned, no extra parameters are introduced and the same construction extends cleanly to any sequence length.

🔑 Key Property

The bias is additive, distance-only, and untrained. It never touches \(Q\), \(K\), or \(V\) — it is injected once, right before softmax, as a fixed \(n \times n\) matrix \(-m \cdot |i-j|\) that is trivially recomputable at any sequence length \(n\), including lengths never seen during training.

Why It Works — The Math
▼

Full Attention with ALiBi

For query position \(i\) attending over keys \(j \le i\) (causal masking), standard scaled dot-product attention is modified to:

$$\text{softmax}\left(\frac{q_i k_j^\top}{\sqrt{d}} - m_h \cdot (i-j)\right)_{j=0}^{i}$$

Because \(i - j \ge 0\) always (we never look at future tokens), the bias term is a non-positive number that grows in magnitude as \(j\) moves further into the past. Subtracting a larger and larger penalty from the logit before softmax exponentially shrinks the attention weight assigned to distant tokens — softmax turns linear penalties in log-space into a geometric decay in probability-space.

The Slope Sequence

For a model with \(n\) heads, the slopes form a geometric sequence starting at \(2^{-8/n}\) with common ratio \(2^{-8/n}\):

$$m_h = 2^{-\frac{8h}{n}}, \qquad h = 1, 2, \ldots, n$$

For \(n=8\) heads this gives \(m = \{2^{-1}, 2^{-2}, 2^{-3}, \ldots, 2^{-8}\} = \{0.5, 0.25, 0.125, \ldots, 0.0039\}\). Spanning several orders of magnitude means some heads act as sharp local-context detectors while others stay nearly uniform across long ranges — the model gets both behaviors "for free" without learning either.

Why Extrapolation Works

Because \(m_h \cdot (i-j)\) is a closed-form function evaluable for any \(i,j\), a model trained on sequences of length \(L\) can be run on length \(L' \gg L\) at inference with zero retraining — the bias matrix is simply recomputed at the new size. Contrast this with learned embeddings, which have no defined value past position \(L-1\), or sinusoidal embeddings, whose extrapolated frequencies were never encountered during training.

⚠️ Common Pitfall

ALiBi's bias is not learned and has no dependence on content — it penalizes distance identically for every token pair regardless of what the tokens are. This is a strength (cheap, extrapolates) but also a limitation: ALiBi cannot express "attend far away only if the content matches," a pattern relative-position schemes like RoPE or T5-bias can approximate more flexibly.

Key Takeaways
▼

When ALiBi shines:

  • Long-context / streaming LLMs that must generalize beyond their training window (used in BLOOM, MPT)
  • Compute-constrained training — no extra positional parameters, near-zero overhead
  • Causal (decoder-only) language modeling, where the distance is always non-negative

When to reach for something else:

  • Tasks needing fine-grained, content-dependent relative position (consider RoPE or T5 relative bias)
  • Bidirectional encoders with complex 2D/graph structure (images, molecules) — ALiBi assumes a 1D sequence
  • Extremely short, fixed-length sequences where extrapolation is irrelevant — any scheme works equally well
💡 Mental Model

ALiBi = "forget positional embeddings, tax distance instead." One scalar slope per head, no learned parameters, and the model naturally reads further at inference than it ever saw at training time.

Code Trace
▼
import numpy as np
# Geometric slope sequence, one per head
def get_slopes(n_heads):
start = 2 ** (-8 / n_heads)
return np.array([start ** (h + 1) for h in range(n_heads)])
# Distance matrix: (i - j) for causal attention, j <= i
def alibi_bias(seq_len, slope):
i = np.arange(seq_len)[:, None]
j = np.arange(seq_len)[None, :]
dist = i - j # >= 0 for j <= i
bias = -slope * dist
bias[j > i] = -np.inf # causal mask
return bias
# Attention with ALiBi (single head)
def alibi_attention(Q, K, V, slope):
d = Q.shape[-1]
scores = Q @ K.T / np.sqrt(d) # (n, n) raw scores
scores = scores + alibi_bias(Q.shape[0], slope)
weights = softmax(scores, axis=-1)
return weights @ V
# Runs unchanged at any seq_len, even far beyond training length
slopes = get_slopes(n_heads=8)
out_train = alibi_attention(Q, K, V, slopes[0]) # seq_len = 6
out_extrap = alibi_attention(Q2, K2, V2, slopes[0]) # seq_len = 16
