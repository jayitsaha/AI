Understanding mT5 & mBART
▼

What are they? mT5 and mBART are multilingual versions of encoder-decoder ("sequence-to-sequence") Transformers. A single shared model reads text in one of 100+ languages and writes text in another — the same weights handle translation, summarization, and question answering across languages, with no per-language model needed.

Analogy: Imagine one universal scribe who has read enormous amounts of text in 101 languages. You hand the scribe a damaged manuscript with words blotted out (in any of those languages), and they fill in the gaps using patterns learned across all languages at once — because "cat", "chat", and "बिल्ली" all end up meaning the same thing inside the scribe's head, translation and cross-lingual transfer become almost a side-effect of denoising practice.

Summary: mT5 (Xue et al., 2021) scales T5's "span corruption" pretraining to the mC4 corpus (101 languages); mBART (Liu et al., 2020) pretrains a BART-style denoising autoencoder on CC25 (25 languages) using token masking plus sentence permutation. Both share one encoder-decoder Transformer across all languages instead of training separate monolingual models.

💡 If you remember one thing

Both models are pretrained with a self-supervised denoising objective — corrupt text, then reconstruct it — applied jointly across dozens of languages sharing one vocabulary and one Transformer. How They Work Internally
▼

The Pretraining Objectives

mT5's span corruption (inherited from T5): randomly select ~15% of input tokens, group contiguous corrupted tokens into spans, and replace each span with a single unique sentinel token (\(\langle\text{extra\_id\_0}\rangle\), \(\langle\text{extra\_id\_1}\rangle\), ...). The encoder sees the corrupted sequence with sentinels; the decoder must autoregressively generate only the missing spans, each preceded by its sentinel. This is far cheaper than reconstructing the whole sequence.

mBART's denoising is closer to BART: (1) token masking — randomly mask ~35% of words/sub-spans with a single \(\langle\text{mask}\rangle\) token, and (2) sentence permutation — shuffle the order of sentences within a document. The decoder must reconstruct the entire original document, prefixed by a language-ID token that tells the decoder which language to emit.

Shared Vocabulary, Shared Weights

Both models use a single SentencePiece vocabulary (mT5: 250K tokens; mBART: 250K tokens) fit jointly over all languages, oversampling low-resource languages so rare languages aren't drowned out by English/Chinese/Russian data volume (controlled by a temperature parameter \(\alpha\), typically \(\alpha \approx 0.3\)). Because every language passes through the same encoder-decoder weights, gradient updates from high-resource languages shape representations that low-resource languages benefit from — this is the mechanism behind zero-shot transfer.

Design Decision: Sentinels vs. Full Reconstruction

mT5 only decodes the corrupted spans (short targets, cheap training) while mBART decodes the whole document (expensive, but better suited to tasks like translation/summarization that already require full-sequence generation and benefit from mBART's document-level sentence-shuffling signal). mT5 optimizes for efficient pretraining; mBART optimizes for direct fine-tuning transfer to generation tasks.

🔑 Key Property

Neither model is told which language is which during pretraining beyond the raw text itself (mT5) or an explicit language-ID token (mBART). The shared parameters are forced to discover language-agnostic semantics purely to minimize the denoising loss — cross-lingual alignment emerges, it isn't hand-engineered.

Why It Works — The Math
▼

Sampling Ratio Across Languages

Naively sampling proportional to corpus size would starve low-resource languages. Both models sample language \(L\) with probability

$$p(L) \propto \left(\frac{n_L}{\sum_{L'} n_{L'}}\right)^{\alpha}$$

where \(n_L\) is the number of examples in language \(L\) and \(\alpha \in (0,1]\) (mT5 uses \(\alpha=0.3\)). As \(\alpha \to 0\), all languages are sampled uniformly (helps rare languages, hurts English); as \(\alpha \to 1\), sampling matches natural corpus proportions (helps high-resource languages). This single knob directly trades off high-resource fluency against low-resource / zero-shot transfer quality.

The Denoising Loss

Both objectives are instances of the same conditional log-likelihood, maximized over corrupted/target pairs \((\tilde{x}, y)\) drawn from the multilingual corpus:

$$\theta^\star = \underset{\theta}{\operatorname{argmax}} \; \mathbb{E}_{L}\, \mathbb{E}_{(\tilde{x},y)\sim D_L} \left[ \sum_{t=1}^{|y|} \log P_\theta\big(y_t \mid y_{

For mT5, \(y\) is the concatenation of masked spans (short); for mBART, \(y\) is the full original document (long). Cross-entropy gradients from every language flow into the same parameters \(\theta\), which is what geometrically pulls same-meaning tokens from different languages toward nearby points in the shared embedding space — this alignment is what the visualization below animates.

Zero-Shot Transfer as a Function of Alignment

Empirically, downstream zero-shot performance on language \(L\) after fine-tuning only on a source language \(S\) degrades with linguistic/typological distance \(d(S,L)\) and improves with pretraining alignment quality \(\rho \in [0,1]\) (itself a function of pretraining steps and \(\alpha\)):

$$\text{score}(L) \approx \text{score}(S)\cdot \rho^{\,\gamma}\cdot e^{-\beta\, d(S,L)}$$

This is the formula driving the "Cross-Lingual Transfer" step in the walkthrough — as the pretraining-progress slider raises \(\rho\), predicted zero-shot scores for typologically distant languages rise fastest (they had the most room to gain from alignment).

⚠️ Common Pitfall

"Curse of multilinguality": for a fixed parameter budget, adding more languages to one shared model eventually hurts per-language quality — capacity is finite and must be shared. mT5's largest variant (13B params) mitigates this by scaling parameters, not just data.

Key Takeaways
▼

When to use mT5 / mBART:

  • Multilingual translation, especially many-to-many or low-resource pairs
  • Cross-lingual summarization / QA where labeled data exists only in one or few languages
  • Zero-shot or few-shot transfer to a language with little to no fine-tuning data
  • Building one deployable model instead of maintaining N monolingual models

When NOT to use:

  • A single high-resource language task where a monolingual model (e.g. English T5/BART) will out-perform the shared model due to the "curse of multilinguality"
  • Extremely latency-sensitive serving where the larger multilingual vocabulary/embedding table is a cost you can't amortize across languages
  • Domains far from the pretraining corpus (mC4/CC25) without further domain-adaptive pretraining
💡 Mental Model

mT5 = "T5, but the span-corruption objective is run over 101 languages sampled with temperature \(\alpha\)." mBART = "BART's denoising autoencoder, but with language-ID tokens and 25 languages sharing one vocabulary." Both convert monolingual pretraining tricks into multilingual ones by sharing weights and vocabulary across languages.

Code Trace

from transformers import MT5ForConditionalGeneration, T5Tokenizer
# mT5 span-corruption style pretraining input
tokenizer = T5Tokenizer.from_pretrained("google/mt5-small")
model = MT5ForConditionalGeneration.from_pretrained("google/mt5-small")
# Corrupted input: spans replaced by sentinels
input_text = "The <extra_id_0> sat on the <extra_id_1>."
target_text = "<extra_id_0> cat <extra_id_1> mat <extra_id_2>"
enc = tokenizer(input_text, return_tensors="pt")
lbl = tokenizer(target_text, return_tensors="pt").input_ids
loss = model(**enc, labels=lbl).loss # cross-entropy on spans only
# --- mBART: full-sequence denoising with language-ID forcing ---
from transformers import MBartForConditionalGeneration, MBart50TokenizerFast
mbart_tok = MBart50TokenizerFast.from_pretrained("facebook/mbart-large-50")
mbart = MBartForConditionalGeneration.from_pretrained("facebook/mbart-large-50")
mbart_tok.src_lang = "hi_IN" # source language tag
enc = mbart_tok("यह एक परीक्षण है", return_tensors="pt")
forced_bos = mbart_tok.lang_code_to_id["fr_XX"] # force French output
gen = mbart.generate(**enc, forced_bos_token_id=forced_bos)
print(mbart_tok.batch_decode(gen, skip_special_tokens=True))
