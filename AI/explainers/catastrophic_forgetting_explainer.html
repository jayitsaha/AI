Why neural networks forget old tasks when learning new ones, and how to measure it

1
Understanding Catastrophic Forgetting
▼

What is it? Catastrophic forgetting (also known as catastrophic interference) describes the tendency of an artificial neural network to completely and abruptly forget previously learned information upon learning new information. When a model is sequentially trained on a new task, its performance on older, unrelated tasks often plummets, as the new learning overwrites the parameters critical for the old tasks.

Analogy: Imagine a student who studies intensely for a new exam, say on quantum physics. After the exam, they try to recall concepts from a previous exam on classical mechanics, only to find they've forgotten nearly everything they once knew about it. This is similar to how a neural network might behave: optimizing for a new objective can wipe out the knowledge gained from a prior objective, rather than integrating it gracefully.

💡 If you remember one thing

Catastrophic forgetting highlights the fundamental plasticity-stability dilemma in neural networks: the ability to adapt quickly to new data (plasticity) often comes at the cost of retaining previously acquired knowledge (stability). This is a core challenge in building truly intelligent, lifelong learning systems.

2
How It Happens Internally
▼

The Problem of Parameter Overlap

At its core, catastrophic forgetting arises from the distributed nature of knowledge representation in neural networks. The weights (parameters) of a network are typically shared across different tasks and concepts. When a network is trained on a Task A, its weights adjust to encode the patterns relevant to Task A. If it's then trained on a Task B, the optimization process will modify these same weights to minimize the loss for Task B. If the optimal weight configuration for Task B is significantly different from that for Task A, the network effectively "overwrites" the knowledge of Task A with that of Task B.

This is unlike how humans typically learn. While we might forget details, we generally don't lose the ability to perform an old skill or recall a major topic just because we learned something new. Human memory systems are thought to have more sophisticated mechanisms for consolidation and retrieval, allowing for continuous learning without severe degradation of past knowledge.

The Plasticity-Stability Dilemma

The challenge is to design networks that are both *plastic* (able to learn new information quickly and efficiently) and *stable* (able to retain previously learned information). Standard backpropagation, while highly effective for single-task learning, does not inherently distinguish between parameters important for old tasks and those that are not. Every parameter is equally susceptible to modification, leading to widespread changes that can disrupt established knowledge.

🔑 Key Property

Forgetting is typically observed and measured as a significant drop in a model's performance on previously learned tasks after it has been trained on a new, distinct task. The more distinct the tasks, and the more training on the new task, the more pronounced the forgetting tends to be.

3
Quantifying Forgetting: The Metrics
▼

To measure catastrophic forgetting, we typically evaluate a model's performance on a set of tasks \(T_1, T_2, \dots, T_k\) after training sequentially on them. Let \(a_{i,j}\) be the accuracy (or other performance metric) of the model on task \(T_j\) after it has been trained on task \(T_i\) (and all previous tasks up to \(T_i\)). So, \(a_{j,j}\) is the performance on task \(T_j\) immediately after training on it.

Metrics for Continual Learning

Several metrics are used to quantify different aspects of learning and forgetting:

  1. Accuracy on Task \(j\) after training on Task \(i \ge j\): \(a_{i,j}\). This is the fundamental building block.
  2. Forward Transfer: How well learning task \(T_j\) benefits subsequent learning on task \(T_i\) (\(i > j\)). This is usually measured by comparing \(a_{i,i}\) to a baseline where \(T_i\) is learned from scratch.
  3. Backward Transfer (Forgetting): How much learning task \(T_i\) harms performance on previous task \(T_j\) (\(i > j\)). This is the core measure of forgetting.
  4. Retention: The ability to retain knowledge of previous tasks.

Formulas for Forgetting & Retention

For a sequence of tasks \(T_1, \dots, T_N\), after training on all tasks up to \(T_N\):

Forgetting for a specific task \(T_j\) (after training on \(T_N\)):

$$F_j = \max_{k \in \{1, \dots, j-1\}} (a_{k,j} - a_{N,j})$$

This measures the maximal drop in performance on task \(T_j\) from its peak performance (which might occur after training on some \(T_k\) where \(k < j\)) to its performance after training on the final task \(T_N\). A simpler, more common measure of forgetting on task \(T_j\) is just the drop from its own peak performance: \(a_{j,j} - a_{N,j}\).

Average Forgetting across all previous tasks (after training on \(T_N\)):

$$F_{avg} = \frac{1}{N-1} \sum_{j=1}^{N-1} (a_{j,j} - a_{N,j})$$

This gives an overall picture of how much, on average, the network has forgotten its prior knowledge. A value of 0 indicates no forgetting, while positive values indicate a performance drop.

Retention for a specific task \(T_j\):

$$R_j = \frac{a_{N,j}}{a_{j,j}}$$

This expresses the final performance on task \(T_j\) as a fraction of its performance immediately after training on \(T_j\). A value of 1 means perfect retention, while values closer to 0 indicate severe forgetting.

⚠️ Not always a bug

While often framed as a "problem," forgetting is not always undesirable. In some scenarios, old information truly becomes irrelevant, and overwriting it is efficient. The challenge lies in distinguishing between irrelevant forgetting and the loss of critical, generalizable knowledge.

Key Takeaways
▼

When catastrophic forgetting is a major concern:

  • Sequential Task Learning: When a single model needs to learn a series of distinct tasks over time (e.g., continually adding new classes to an image classifier).
  • Fine-tuning Pre-trained Models: Adapting a large pre-trained model to a new, specific downstream task can lead to forgetting of the general representations learned during pre-training.
  • Robotics and Embodied AI: Agents that need to learn new skills in the real world without forgetting previously mastered ones.

When it might be less of an issue, or even desirable:

  • Batch Training on a Fixed Dataset: If all data for all tasks is available simultaneously, multi-task learning can be used, where the model is trained to optimize all tasks concurrently, often leading to better generalization and less forgetting.
  • Irrelevant Information: If the "forgotten" information is truly obsolete or irrelevant to the model's current objectives, then forgetting can be seen as an efficient pruning of unnecessary knowledge.
💡 Strategies to Mitigate Forgetting

Active research areas focus on mitigating catastrophic forgetting. Common strategies include regularization-based methods (e.g., EWC, LwF) that protect important parameters for old tasks, memory-based methods (e.g., experience replay) that store and periodically revisit old data, and parameter isolation methods (e.g., dynamic architectures) that allocate new parameters for new tasks.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
import torch.optim as optim
from copy import deepcopy
# 1. Define a simple MLP model
class SimpleMLP(nn.Module):
def __init__(self, input_dim, hidden_dim, output_dim):
super().__init__()
self.fc1 = nn.Linear(input_dim, hidden_dim)
self.relu = nn.ReLU()
self.fc2 = nn.Linear(hidden_dim, output_dim)
def forward(self, x):
return self.fc2(self.relu(self.fc1(x)))
# Helper to train for one task
def train_task(model, data_X, data_y, epochs, lr=0.01):
criterion = nn.CrossEntropyLoss()
optimizer = optim.SGD(model.parameters(), lr=lr)
for epoch in range(epochs):
optimizer.zero_grad()
outputs = model(data_X)
loss = criterion(outputs, data_y)
loss.backward()
optimizer.step()
# Helper to evaluate accuracy
def evaluate_task(model, data_X, data_y):
with torch.no_grad():
outputs = model(data_X)
_, predicted = torch.max(outputs.data, 1)
correct = (predicted == data_y).sum().item()
return correct / len(data_y)
# 2. Setup model and data
model = SimpleMLP(input_dim=2, hidden_dim=4, output_dim=2)
# task_A_X, task_A_y, task_B_X, task_B_y are pre-generated tensors
# 3. Train on Task A
train_task(model, task_A_X, task_A_y, epochs=20)
task_A_acc_initial = evaluate_task(model, task_A_X)
print(f"Initial Task A Accuracy: {task_A_acc_initial:.2f}")
# 4. Train on Task B (catastrophic forgetting happens here)
train_task(model, task_B_X, task_B_y, epochs=20)
task_B_acc_final = evaluate_task(model, task_B_X)
print(f"Final Task B Accuracy: {task_B_acc_final:.2f}")
# 5. Re-evaluate Task A
task_A_acc_final = evaluate_task(model, task_A_X)
print(f"Final Task A Accuracy: {task_A_acc_final:.2f}")
# 6. Calculate Forgetting
forgetting = task_A_acc_initial - task_A_acc_final
print(f"Forgetting (Task A): {forgetting:.2f}")
