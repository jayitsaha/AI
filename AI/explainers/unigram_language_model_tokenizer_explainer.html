Understanding Unigram Tokenization
▼

What is it? The Unigram Language Model tokenizer (Kudo, 2018) treats tokenization as a probabilistic problem. Instead of greedily merging characters like BPE, it starts with a large vocabulary of candidate subwords and iteratively removes the least useful ones. Each subword has a learned probability, and the best segmentation of any word is the one that maximizes the product of subword probabilities.

Analogy: Imagine you have a massive box of Scrabble tiles, including multi-letter tiles like "ing", "tion", "un". To spell a word, you find the combination of tiles whose total "score" (log-probability) is highest. Then, after observing which tiles are actually useful across thousands of words, you throw away the tiles nobody needs -- keeping only the most valuable ones. Repeat until your tile set is the perfect size.

If you remember one thing

Unigram tokenization finds the segmentation \(\mathbf{x}^* = \arg\max_{\mathbf{x} \in S(w)} \sum_i \log p(x_i)\) by treating each token as independent (unigram assumption), then prunes the vocabulary by removing tokens whose removal causes the smallest increase in total corpus loss.

2
How the EM Algorithm Works
▼

The Two-Step Dance

Unigram training alternates between two steps. The E-step finds the most probable segmentation of every word in the corpus given current token probabilities (using the Viterbi algorithm on a segmentation lattice). The M-step re-estimates each token's probability by counting how often it appears across all optimal segmentations and normalizing.

The Segmentation Lattice

For a word like "unigram", the lattice encodes every possible way to split it into known subwords. Each path through the lattice is a valid segmentation, and its score is the sum of log-probabilities of the subwords along that path. The Viterbi algorithm efficiently finds the highest-scoring path without enumerating all possibilities.

Vocabulary Pruning

After EM converges, we compute each token's pruning loss: how much the total corpus log-likelihood would decrease if we removed that token. Tokens with the smallest loss are pruned (typically removing 10-20% per round). We repeat EM + pruning until the vocabulary reaches the target size. Single characters are never pruned, guaranteeing any word can still be tokenized.

Key Design Decision

Unlike BPE which builds vocabulary bottom-up (merging), Unigram works top-down (pruning). This lets it explore a much larger space of possible vocabularies and find more globally optimal token sets. It also naturally produces a probability distribution over segmentations, enabling techniques like subword regularization.

The Math Behind It
▼

Given vocabulary \(V\) with token probabilities \(p(x_i)\) where \(\sum_{x \in V} p(x) = 1\), the probability of a segmentation \(\mathbf{x} = (x_1, \ldots, x_k)\) under the unigram assumption is:

$$P(\mathbf{x}) = \prod_{i=1}^{k} p(x_i) \implies \log P(\mathbf{x}) = \sum_{i=1}^{k} \log p(x_i)$$

The corpus log-likelihood under the most probable segmentation of each word \(w_j\) is:

$$\mathcal{L} = \sum_{j=1}^{|D|} \max_{\mathbf{x} \in S(w_j)} \sum_{i} \log p(x_i)$$

The M-step re-estimates token probabilities as relative frequencies from optimal segmentations:

$$p(x) \leftarrow \frac{c(x)}{\sum_{x' \in V} c(x')}$$

where \(c(x)\) counts occurrences of token \(x\) across all Viterbi-optimal segmentations.

The pruning loss for removing token \(x\) is:

$$\Delta\mathcal{L}(x) = \mathcal{L}_{V} - \mathcal{L}_{V \setminus \{x\}}$$
Common Misconception

Unigram does NOT mean "one word at a time." The "unigram" refers to the independence assumption between subword tokens within a segmentation: the probability of each token is independent of its neighbors. This simplification enables efficient Viterbi decoding but ignores token-to-token dependencies.

5
Key Takeaways
▼

When to use Unigram: Unigram is the default tokenizer in SentencePiece (used by T5, ALBERT, XLNet, Marian). It excels when you want probabilistic segmentation, subword regularization for data augmentation, or a vocabulary that generalizes well across languages.

Versus BPE: BPE is deterministic and greedy (bottom-up merges). Unigram is probabilistic and top-down (pruning). Unigram often produces more linguistically meaningful subwords because its global optimization can discover better token boundaries than BPE's local merge decisions.

Subword Regularization: Because Unigram defines a probability distribution over segmentations, you can sample different tokenizations of the same word during training. This acts as data augmentation and improves model robustness -- a unique advantage over BPE.

Complexity

Viterbi segmentation of a word of length \(n\) with vocabulary \(V\): \(O(n^2)\) (check all substrings). Full training: \(O(I \cdot |D| \cdot n^2)\) where \(I\) is the number of EM iterations and \(|D|\) is corpus size. Pruning adds \(O(|V|)\) per round for loss computation.

import math
from collections import Counter
def viterbi_segment(word, vocab):
"""Find best segmentation via Viterbi."""
n = len(word)
best_score = [-float('inf')] * (n + 1)
best_score[0] = 0.0
best_edge = [None] * (n + 1)
for end in range(1, n + 1):
for start in range(0, end):
sub = word[start:end]
if sub in vocab:
score = best_score[start] + vocab[sub]
if score > best_score[end]:
best_score[end] = score
best_edge[end] = start
# Backtrack
tokens = []
pos = n
while pos > 0:
start = best_edge[pos]
tokens.append(word[start:pos])
pos = start
return tokens[::-1]
