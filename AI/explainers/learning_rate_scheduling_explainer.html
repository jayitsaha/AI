Understanding Learning Rate Scheduling
▼

What is it? The learning rate \(\eta\) controls how big a step the optimizer takes at every update: \(\theta_{t+1} = \theta_t - \eta_t \nabla \mathcal{L}(\theta_t)\). A fixed learning rate is almost always suboptimal — too large and training oscillates or diverges near a good minimum; too small and training crawls. A learning rate schedule changes \(\eta_t\) over training so it is large early (fast progress) and small late (fine-grained convergence), sometimes with extra structure like warmup or periodic resets.

Analogy: Think of parking a car. Far from the spot, you drive fast (large steps close the distance quickly). As you approach the curb, you slow down — otherwise you overshoot and hit it. Some drivers even reverse and re-approach a few times to get the angle just right (that's a cyclical schedule / restarts). Learning rate schedules are the "foot on the gas/brake" policy for gradient descent.

💡 If you remember one thing

Every practical LR schedule is really just answering two questions: (1) how fast do we ramp up at the start (warmup, to avoid early instability), and (2) how do we ramp down over training (decay shape — step, exponential, cosine, linear, or cyclical) so the optimizer settles into a good minimum instead of bouncing around it.

How Each Schedule Works Internally
▼

Step Decay

Multiply \(\eta\) by a factor \(\gamma < 1\) every fixed number of steps (or epochs). Simple, interpretable, but creates visible "cliffs" in the loss curve — the optimizer suddenly gets a much smaller step and loss often drops sharply right after each decay point.

Exponential Decay

Decay continuously rather than in jumps: \(\eta_t = \eta_0 \cdot \gamma^t\) (or equivalently \(\eta_0 e^{-kt}\)). Smoother than step decay, but the rate of decay is constant in relative terms — it never "pauses" to let the model explore at a given scale.

Cosine Annealing (with warm restarts, SGDR)

Follows one half-cosine arc from \(\eta_{max}\) down to \(\eta_{min}\). Unlike exponential decay, cosine annealing decays slowly at first and last, and fastest in the middle — spending more time near both the high-LR exploration regime and the low-LR fine-tuning regime. SGDR (Loshchilov & Hutter, 2017) restarts the cosine cycle periodically (often doubling cycle length each restart), acting like simulated-annealing "reheating" to escape sharp minima.

Linear Warmup + Decay

Used almost universally for Transformers (original "Attention Is All You Need" used warmup + inverse-sqrt decay; BERT/GPT-style fine-tuning uses warmup + linear decay). For the first warmup_steps, \(\eta\) ramps up linearly from ~0 to \(\eta_{max}\). Only after warmup does the decay phase begin. Warmup exists because at initialization, gradients (and especially Adam's second-moment estimate) are unreliable/high-variance — a large LR from step 0 can blow up the first few updates, particularly in deep or attention-heavy networks.

Cyclical Learning Rates (CLR, triangular)

Instead of monotonically decaying, oscillate \(\eta\) between a lower and upper bound in a triangular (or sinusoidal) wave with a fixed period. Smith (2017) showed this lets training benefit from periodic "large LR" phases (escaping sharp minima / saddle points) without ever fully committing to a single decay schedule — and it removes the need to hand-tune exactly when to decay.

OneCycleLR

A single cycle (not many): LR rises from a low initial value to a high peak over the first \(\sim\)30% of training, then anneals (usually via cosine) down to a value far below the initial LR for the remainder. Momentum is cycled inversely — low momentum while LR is high (so large steps aren't over-accelerated), high momentum while LR is low (to push through flat regions). Smith & Topin (2018) showed this "super-convergence" pattern can match baseline accuracy in far fewer epochs.

🔑 Key Property

All of these are just different shapes for \(\eta_t\) as a function of step \(t\) — none change the underlying update rule \(\theta_{t+1} = \theta_t - \eta_t \nabla\mathcal{L}(\theta_t)\). The schedule is a hyperparameter trajectory, chosen ahead of time (unlike adaptive optimizers such as Adam, which adapt per-parameter scaling based on gradient history).

Why It Works — The Math
▼

The formulas, precisely

Step decay (decay every \(s\) steps by factor \(\gamma\)):

$$\eta_t = \eta_0 \cdot \gamma^{\lfloor t / s \rfloor}$$

Exponential decay:

$$\eta_t = \eta_0 \cdot \gamma^{t} = \eta_0 \, e^{-kt}, \quad k = -\ln\gamma$$

Cosine annealing over a cycle of length \(T\):

$$\eta_t = \eta_{min} + \tfrac{1}{2}(\eta_{max}-\eta_{min})\left(1+\cos\!\left(\frac{\pi t}{T}\right)\right)$$

Linear warmup (for \(t \le t_w\)) then decay (for \(t > t_w\)):

$$\eta_t = \begin{cases}\eta_{max}\cdot \dfrac{t}{t_w} & t \le t_w \\[6pt] \eta_{max}\cdot f(t - t_w) & t > t_w \end{cases}$$

Cyclical (triangular, half-period \(s\)):

$$x = \left|\frac{t \bmod 2s}{s} - 1\right|, \qquad \eta_t = \eta_{min} + (\eta_{max}-\eta_{min})(1-x)$$

Why warmup prevents early divergence

Early in training, weights are randomly initialized and (for adaptive optimizers like Adam) the second-moment estimate \(v_t\) is a biased, high-variance estimate of the true gradient scale — it hasn't seen enough samples to average out. Taking a large step \(\eta \nabla\mathcal{L}/(\sqrt{v_t}+\epsilon)\) when \(v_t\) is unreliable can push weights into a region with pathologically large gradients (common in pre-LayerNorm Transformers), from which the model may never recover. Warmup keeps \(\eta_t\) small exactly while this estimate is noisiest, then hands off to the main schedule once statistics stabilize.

Why cosine's shape matters (not just monotonic decay)

Consider the derivative of the cosine schedule: \(\frac{d\eta_t}{dt} \propto -\sin(\pi t/T)\), which is near zero at \(t\approx 0\) and \(t \approx T\), and maximal (steepest decrease) at \(t \approx T/2\). This means cosine annealing spends more wall-clock/step budget lingering at both the high-LR exploration regime and the low-LR convergence regime, and moves quickly through the "unstable middle" — compared to exponential decay, which decreases at a constant relative rate throughout and spends comparatively less time at either extreme.

⚠️ Common Pitfall

Schedules are usually defined in terms of total training steps \(T\) (e.g. cosine needs to know when it will reach \(\eta_{min}\)). If you change batch size, dataset size, or number of epochs without recomputing \(T\), the decay curve silently mismatches your actual training budget — e.g. cosine annealing "finishing early" leaves many steps at \(\eta_{min}\), wasting compute on near-zero updates.

Key Takeaways
▼

Quick decision table:

ScheduleShapeBest forWatch out for
Step decayPiecewise constant, cliffsClassic CNN training (ResNet on ImageNet)Manual tuning of drop points; visible loss jumps
Exponential decaySmooth constant-ratio decaySimple baselines, RLDecays same %/step everywhere — no "settling" phase
Cosine annealingSlow-fast-slow half arcMost modern vision/NLP training; pairs well with SGDR restartsMust know total steps T in advance
Warmup + decayRamp up, then decayTransformers, large batch training, AdamWarmup length under-tuned → still unstable; too long → wastes budget
Cyclical (triangular)Repeating up-down sawtoothFinding good LR range; escaping sharp minima mid-trainingNeeds bound tuning (LR range test)
OneCycleLROne up-then-down arc + inverse momentumFast "super-convergence" training in fixed epoch budgetsSensitive to max_lr choice; not for open-ended/continual training
💡 Hierarchy of ideas

Decay shape (step / exponential / cosine) answers "how do we cool down?". Warmup answers "how do we heat up safely?". Cyclical / restarts answers "should we ever reheat?". OneCycleLR combines all three ideas — warmup, a single controlled cooldown, and momentum coupling — into one schedule tuned for fast convergence in a fixed budget.

Code Trace
▼
import numpy as np
def step_decay(t, lr0=0.5, gamma=0.5, step_size=40):
return lr0 * gamma ** (t // step_size)
def exponential_decay(t, lr0=0.5, gamma=0.97):
return lr0 * gamma ** t
def cosine_annealing(t, T, lr_max=0.5, lr_min=0.02):
cos_term = 1 + np.cos(np.pi * t / T)
return lr_min + 0.5 * (lr_max - lr_min) * cos_term
def warmup_then_decay(t, warmup, T, lr_max=0.5, lr_min=0.02):
if t <= warmup:
return lr_max * t / max(warmup, 1) # linear ramp-up
progress = (t - warmup) / max(T - warmup, 1)
return lr_min + 0.5*(lr_max-lr_min)*(1+np.cos(np.pi*progress))
def cyclical_triangular(t, lr_min=0.02, lr_max=0.5, step_size=40):
cycle = t // (2 * step_size)
x = abs(t / step_size - 2 * cycle - 1)
return lr_min + (lr_max - lr_min) * max(0, 1 - x)
def one_cycle_lr(t, T, lr_max=0.5, lr_min=0.02, pct_start=0.3):
up_end = int(T * pct_start)
if t <= up_end: # rising phase
prog = t / max(up_end, 1)
return lr_min + (lr_max - lr_min) * 0.5 * (1 - np.cos(np.pi * prog))
prog = (t - up_end) / max(T - up_end, 1) # falling phase (below lr_min floor)
final_lr = lr_min * 0.01
return lr_max - (lr_max - final_lr) * 0.5 * (1 - np.cos(np.pi * prog))
# Momentum is cycled inversely to LR in OneCycleLR:
# high LR phase -> low momentum (0.85); low LR phase -> high momentum (0.95)
