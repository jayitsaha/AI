Understanding Offline Metrics
▼

What is it? Before a recommender ever reaches a real user, we need to grade it on historical data: given a ranked list of items the model produced for a user, and a ground-truth set of items the user actually engaged with, how good is that list? "Offline metrics" are the family of formulas that turn a ranked list + ground truth into a single number, computed entirely offline (no live traffic needed).

Analogy: Think of grading a multiple-choice exam where the student ranks their top-10 guesses in order of confidence for a set of true/false facts. Precision asks "of the guesses you made, how many were right?" Recall asks "of all the true facts, how many did you find?" NDCG asks "did you put your correct guesses near the top, or buried at the bottom?" MRR asks "how quickly did you get your first guess right?" And beyond correctness, coverage/diversity/novelty/serendipity ask "did you just guess the same five obvious facts everyone guesses, or did you show me something I didn't already expect?"

💡 If you remember one thing

There is no single "best" metric. Rank-aware metrics (Precision@K, Recall@K, NDCG@K) grade a cutoff list; query-aggregate metrics (MAP, MRR) average behavior across many users/queries; classification metrics (AUC, log loss) grade the underlying scores regardless of cutoff; and beyond-accuracy metrics (coverage, diversity, novelty, serendipity) catch a model that is accurate but boring.

How These Metrics Work Internally
▼

Set the stage: ranked list + ground truth

For one user, the recommender outputs a ranked list of \(N\) items \(i_1, i_2, \dots, i_N\) (rank 1 = most confident). We also know a binary (or graded) relevance label \(rel_i \in \{0,1\}\) for each item — did the user actually click / purchase / watch it? \(R\) is the total number of relevant items for that user across the whole catalog (which may exceed what's visible in the top-\(N\) list).

Rank-cutoff metrics (Precision@K, Recall@K, F1@K, Hit Rate@K)

These only look at the top-\(K\) slice of the list. Precision@K asks "how pure is the top-K?"; Recall@K asks "how much of the full relevant set did the top-K capture?"; F1@K is their harmonic mean; Hit Rate@K is the blunt yes/no version — did the top-K contain at least one hit.

Position-aware metrics (NDCG@K, MAP, MRR)

Precision@K treats rank 1 and rank K as equally valuable, which is unrealistic — users rarely scroll to the bottom. NDCG applies a logarithmic discount so a hit at rank 1 counts far more than a hit at rank 10, then normalizes against the best-possible ("ideal") ordering. MRR looks only at the position of the very first relevant item, which matters most for single-answer tasks (search, "did you find it"). MAP averages precision computed at every relevant rank, then averages that across many users — it rewards models that front-load ALL relevant items, not just the first one.

Classification-style metrics (AUC, Log Loss)

If the model outputs calibrated scores/probabilities rather than just a ranking, we can treat "is this item relevant" as a binary classification problem. AUC measures whether relevant items systematically score higher than irrelevant ones (rank-order correctness, cutoff-free). Log loss measures whether the predicted probabilities are well-calibrated — it punishes confident-but-wrong predictions heavily.

Beyond-accuracy metrics (Coverage, Diversity, Novelty, Serendipity)

A model that always recommends the 10 most popular items on the platform can score deceptively well on precision/recall while being useless as a discovery engine. Coverage measures what fraction of the catalog ever gets recommended; diversity measures how different the items within one list are from each other; novelty measures how "non-obvious" (unpopular) the recommended items are; serendipity measures the intersection: relevant AND unexpected.

🔑 Key Property

Rank-cutoff and position-aware metrics are computed per user/query and then averaged ("mean" Precision@K, MAP, MRR). A single user's number is rarely reported alone — always check what's being averaged over.

Why It Works — The Math
▼

Precision, Recall, F1, Hit Rate

$$\text{P@K} = \frac{|\{\text{relevant items in top-}K\}|}{K} \qquad \text{R@K} = \frac{|\{\text{relevant items in top-}K\}|}{R}$$
$$\text{F1@K} = \frac{2 \cdot \text{P@K} \cdot \text{R@K}}{\text{P@K} + \text{R@K}} \qquad \text{HR@K} = \mathbb{1}\left[\sum_{i=1}^{K} rel_i > 0\right]$$

NDCG@K — discounted, normalized gain

Discounted Cumulative Gain sums relevance with a \(1/\log_2(\text{rank}+1)\) discount; Ideal DCG (IDCG) is the DCG of the best possible ordering (all relevant items pushed to the top):

$$\text{DCG@K} = \sum_{i=1}^{K} \frac{rel_i}{\log_2(i+1)} \qquad \text{NDCG@K} = \frac{\text{DCG@K}}{\text{IDCG@K}} \in [0,1]$$

MAP and MRR — averaged over queries

$$\text{AP} = \frac{1}{R}\sum_{k:\,rel_k=1} \text{P@k} \qquad \text{MAP} = \frac{1}{|Q|}\sum_{q=1}^{|Q|} \text{AP}_q \qquad \text{MRR} = \frac{1}{|Q|}\sum_{q=1}^{|Q|} \frac{1}{\text{rank of first relevant item}_q}$$

AUC — a rank statistic

AUC equals the probability a randomly chosen relevant item scores higher than a randomly chosen irrelevant one — exactly the Mann-Whitney U statistic:

$$\text{AUC} = \frac{1}{|\mathcal{R}||\mathcal{I}|}\sum_{r \in \mathcal{R}}\sum_{j \in \mathcal{I}} \left[\mathbb{1}(s_r > s_j) + \tfrac{1}{2}\mathbb{1}(s_r = s_j)\right]$$

Log Loss — calibrated cross-entropy

$$\text{LogLoss} = -\frac{1}{N}\sum_{i=1}^{N}\left[y_i \ln p_i + (1-y_i)\ln(1-p_i)\right]$$

⚠️ Common Pitfall

NDCG's denominator (IDCG) depends on how many relevant items actually exist for that user — comparing NDCG@K across users with wildly different \(R\) can be misleading. Likewise, optimizing purely for Precision/Recall/NDCG can silently collapse coverage and diversity to zero (the "filter bubble" failure mode) — always report a beyond-accuracy metric alongside accuracy metrics.

Key Takeaways
▼

Which metric to reach for:

  • Precision@K / Recall@K / F1@K — quick, interpretable cutoff metrics for "does the shown slice look good," e.g. grading a homepage carousel.
  • Hit Rate@K — coarse but robust for sparse implicit feedback (did the user's ONE known next action appear in top-K).
  • NDCG@K — the default choice when position matters and relevance can be graded (not just binary).
  • MAP / MRR — aggregate ranking quality across many users; MRR when only the first hit matters (search-like), MAP when all relevant items matter.
  • AUC / Log Loss — evaluate the underlying scoring model itself, independent of any cutoff; log loss additionally checks calibration.
  • Coverage / Diversity / Novelty / Serendipity — guardrail metrics to catch popularity bias and filter bubbles that accuracy metrics reward but users hate.

Common pitfalls:

  • Optimizing a single accuracy metric in isolation almost always sacrifices diversity/novelty — track both.
  • Offline gains do not always translate to online gains (offline-online metric mismatch) — always confirm with an A/B test.
  • Implicit feedback (clicks) is a noisy proxy for true relevance — treat "relevant" labels as approximate.
💡 Hierarchy

Cutoff metrics (P/R/F1/HR) ⊂ position-aware metrics (NDCG, MAP, MRR add rank sensitivity) ⊂ full evaluation suite (add AUC/LogLoss for the raw scorer, plus Coverage/Diversity/Novelty/Serendipity so accuracy gains aren't bought with a boring, homogeneous catalog.)

# rank 1..10, ground-truth relevance and predicted score
relevant = np.array([0,1,1,1,0,0,1,0,1,0])
scores = np.array([.95,.90,.85,.78,.70,.60,.55,.40,.30,.20])
R_total = 6 # total relevant items for this user (in full catalog)
def precision_at_k(k): return relevant[:k].sum() / k
def recall_at_k(k): return relevant[:k].sum() / R_total
def f1_at_k(k):
p, r = precision_at_k(k), recall_at_k(k)
return 0 if p+r==0 else 2*p*r/(p+r)
def hit_rate_at_k(k): return float(relevant[:k].sum() > 0)
def dcg_at_k(k):
ranks = np.arange(1, k+1)
return (relevant[:k] / np.log2(ranks+1)).sum()
def idcg_at_k(k):
ideal = min(R_total, k)
ranks = np.arange(1, ideal+1)
return (1 / np.log2(ranks+1)).sum()
def ndcg_at_k(k):
idcg = idcg_at_k(k)
return 0 if idcg==0 else dcg_at_k(k) / idcg
def average_precision():
hits, s = 0, 0.0
for i, rel in enumerate(relevant, start=1):
if rel: hits += 1; s += hits / i
return s / R_total
def reciprocal_rank():
hit = np.argmax(relevant == 1) + 1
return 1.0 / hit if relevant.any() else 0.0

rel_s, irr_s = scores[relevant==1], scores[relevant==0]
wins = sum((r>i) + 0.5*(r==i) for r in rel_s for i in irr_s)
return wins / (len(rel_s) * len(irr_s))

p = np.clip(scores, eps, 1-eps)
return -np.mean(relevant*np.log(p) + (1-relevant)*np.log(1-p))
