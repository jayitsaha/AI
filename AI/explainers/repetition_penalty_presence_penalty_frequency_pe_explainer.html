Repetition, Presence, & Frequency Penalties

Controlling LLM generation to prevent unwanted repetition
Foundational LLMs Generation O(N) per token
1
Understanding Repetition Penalties
▼

What is it? Large Language Models (LLMs) often fall into repetitive loops, generating the same phrases, words, or patterns over and over. Repetition penalties are a family of techniques applied during text generation (decoding) to discourage the model from producing tokens that have already appeared in the generated sequence. By adjusting the "scores" (logits) of previously seen tokens, these penalties make it less likely for the model to pick them again.

Analogy: Imagine a writer who, without realizing it, keeps using the same descriptive words or sentence structures. An editor steps in and says, "For every word you've used before, I'm going to make it harder for you to use it again. If you've used 'amazing' once, it's a little harder. If you've used it five times, it's much harder." This editor is applying a repetition penalty to encourage more diverse and less redundant prose.

💡 If you remember one thing

Repetition penalties modify the raw output scores (logits) of a language model for tokens that have already appeared in the generated text. This happens *before* the softmax function converts logits to probabilities and *before* any sampling (like top-k or nucleus sampling) occurs, directly influencing the next token choice.

2
How Penalties Work Internally
▼

The Decoding Loop & Logit Modification

LLMs generate text one token at a time. At each step, the model outputs a vector of raw scores (logits) for every possible next token in its vocabulary. These logits are then typically converted into a probability distribution via a softmax function, and a token is sampled. Repetition penalties intervene *before* this softmax step:

  1. The model predicts logits for the next token.
  2. The generated sequence so far is analyzed to identify previously used tokens.
  3. If a token has been seen, its logit is adjusted downwards based on the chosen penalty type and strength.
  4. The modified logits are then passed to softmax, and sampling occurs.

Three Common Penalty Types

While all aim to reduce repetition, they do so with different mechanisms:

  • Repetition Penalty (General Factor): This is the simplest. If a token has appeared in the generated sequence, its logit is divided by a specified factor \(\alpha\) (where \(\alpha > 1\)). This globally reduces the likelihood of *any* previously seen token.
  • Presence Penalty: This penalty decreases the logit of a token if it *has appeared at least once* in the generated text, regardless of how many times it has appeared. It applies a fixed subtraction \(\beta\) to the logit of any token that's been seen.
  • Frequency Penalty: This penalty decreases the logit of a token based on *how many times* it has appeared in the generated text. The subtraction amount \(\gamma \cdot c_i\) is proportional to the count \(c_i\) of the token. The more a token has been used, the more its logit is reduced.

Design Decision: Why Multiple Penalties?

Each penalty type offers a different nuance. The general repetition penalty acts as a broad deterrent. Presence penalty is a strong "one-and-done" discouragement for any token. Frequency penalty allows for more gradual discouragement, where a token might be acceptable once or twice, but becomes increasingly unlikely with more occurrences. Different tasks and desired output styles benefit from different mechanisms. For instance, creative writing might benefit from frequency penalty to allow some repetition for stylistic effect, while a summarization task might prefer a stronger presence penalty to avoid redundancy.

🔑 Key Property

All these penalties operate on the logit space. This means they directly manipulate the raw numerical scores before they are transformed into a probability distribution. This direct modification is powerful because it can drastically shift the relative likelihoods of tokens, even if the model's "natural" preference is to repeat.

3
Why It Works — The Math
▼

Modifying Logits

Let \(z_i\) be the original logit for token \(i\) predicted by the LLM. Let \(c_i\) be the count of token \(i\) in the sequence generated so far. The modified logit \(z'_i\) for token \(i\) is calculated as follows:

1. Repetition Penalty (General Factor)

This penalty applies a multiplicative factor \(\alpha\) (typically \(\alpha > 1\)) to the logit of any token that has appeared at least once. If \(\alpha < 1\), it would encourage repetition. The common implementation is to divide the logit by \(\alpha\):

$$z'_i = \begin{cases} z_i / \alpha & \text{if } c_i > 0 \\ z_i & \text{if } c_i = 0 \end{cases}$$

For example, if a logit is 5 and \(\alpha=2.0\), the new logit becomes 2.5. If the logit is -2, it becomes -1. This means positive logits become less positive (less likely), and negative logits become less negative (more likely, which is usually not the intent for negative logits, so models often use a different form of repetition penalty for negative logits, e.g., multiply by \(\alpha\) if logit < 0). For simplicity and common practice, we focus on \(\alpha > 1\) to reduce positive logits.

2. Presence Penalty

This penalty subtracts a fixed strength \(\beta\) (typically \(\beta \ge 0\)) from the logit of any token that has appeared at least once, regardless of its frequency:

$$z'_i = z_i - \beta \cdot \mathbb{I}(c_i > 0)$$

Here, \(\mathbb{I}(c_i > 0)\) is an indicator function that is 1 if \(c_i > 0\) (token has appeared) and 0 otherwise. This ensures a consistent reduction for any previously seen token.

3. Frequency Penalty

This penalty subtracts an amount proportional to the token's count \(c_i\) and a strength \(\gamma\) (typically \(\gamma \ge 0\)) from its logit:

$$z'_i = z_i - \gamma \cdot c_i$$

This means a token seen once is penalized by \(\gamma\), twice by \(2\gamma\), and so on, making it increasingly unlikely with each repetition.

⚠️ Common Pitfall

Applying too strong a penalty can lead to nonsensical or grammatically incorrect output. If the model is forced to avoid common words (like "the" or "is") too aggressively, it may generate awkward phrasing or completely derail the coherence of the text. Conversely, too weak a penalty may not solve the repetition problem at all. Finding the right balance often requires empirical tuning for a given model and task.

Key Takeaways
▼

When to use repetition penalties:

  • Preventing repetitive loops: The most common use case, especially for open-ended generation where models can get stuck.
  • Encouraging diversity: Useful in creative writing, brainstorming, or anytime you want more varied output.
  • Fine-tuning generation style: Adjusting penalties can subtly shift the model's output towards more concise or more expansive text.

When NOT to use or use with caution:

  • Sensitive tasks requiring specific phrasing: If the model *must* use a certain word or phrase (e.g., legal or medical text generation), penalties can hinder accuracy.
  • Very short generations: For single-sentence or short-paragraph outputs, aggressive penalties can quickly lead to awkward phrasing.
  • When other parameters suffice: If temperature, top-k, or top-p sampling already provide satisfactory diversity, adding penalties might be overkill or detrimental.
  • Common words: Penalizing common words like "the", "a", "is" too heavily can quickly break grammatical correctness.
💡 Rule of Thumb

Repetition penalties are powerful tools for shaping LLM output, but they are a form of *heuristic intervention*. They don't make the model "smarter" or inherently less repetitive; they simply override its natural preferences. Always test and tune penalty strengths carefully to achieve desired results without sacrificing coherence or correctness.

Code Trace (Python/NumPy)

import numpy as np
def apply_penalties(logits, generated_token_ids, vocab_size,
repetition_penalty_factor=1.0,
presence_penalty_strength=0.0,
frequency_penalty_strength=0.0):
penalized_logits = np.copy(logits)
token_counts = np.zeros(vocab_size)
for token_id in generated_token_ids:
token_counts[token_id] += 1
for i in range(vocab_size):
if token_counts[i] > 0: # Token has appeared in generated sequence
# 1. Repetition Penalty (Factor)
if repetition_penalty_factor != 1.0:
# Common implementation: divide by factor if logit > 0, multiply if logit < 0
# For simplicity here, we'll just divide all by factor > 1 to reduce.
penalized_logits[i] /= repetition_penalty_factor
# 2. Presence Penalty
if presence_penalty_strength > 0:
penalized_logits[i] -= presence_penalty_strength
# 3. Frequency Penalty
if frequency_penalty_strength > 0:
penalized_logits[i] -= frequency_penalty_strength * token_counts[i]
return penalized_logits
