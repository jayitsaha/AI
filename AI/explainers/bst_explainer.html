Behavior Sequence Transformer (BST)

Using self-attention over a user's click history to predict click-through rate
Recommender Systems Transformers CTR Prediction O(n²) attention
1
Understanding BST
▼

What is it? The Behavior Sequence Transformer (Chen et al., Alibaba 2019) predicts whether a user will click a candidate item by treating that user's recent browsing/purchase history as a sequence and running it through a Transformer encoder. Instead of collapsing the history into one "average interest" vector (as classic Wide & Deep / pooling-based models do), BST lets the model learn which past items are relevant to the candidate item right now, via self-attention.

Analogy: Imagine a shop assistant who watched everything you looked at today — sneakers, socks, a basketball, a novel, running shorts, a water bottle — and now you pick up a pair of running shoes. A good assistant doesn't weigh every earlier glance equally; they instantly know your basketball and running-shorts browsing is far more relevant to "running shoes" than the novel you flipped through. That selective focus is exactly what self-attention computes.

💡 If you remember one thing

BST appends the candidate ("target") item to the user's behavior sequence, adds positional encodings so the Transformer knows the order of events, and runs multi-head self-attention so every item — including the target — can look at every other item. The resulting context vector, fused with other features, is fed into an MLP that outputs a click probability: $$\hat{y} = \sigma\big(\text{MLP}(\text{Attention}(Q,K,V) \oplus e_{\text{target}} \oplus \text{other features})\big)$$

2
How BST Works Internally
▼

The Problem with Pooling

Earlier CTR models (Wide & Deep, sum/average pooling of behavior embeddings) squash a user's entire history into one fixed vector before it ever "meets" the candidate item. A user who browsed sports gear and a novel gets one blended interest vector — the novel's embedding drags the average away from "sporty," hurting the score for a genuinely relevant candidate like running shoes.

The BST Pipeline

1) Embed each behavior item (and the candidate/target item) into a dense vector. 2) Add positional encoding — self-attention has no notion of order by itself, so BST injects sinusoidal position signals so "clicked 5 items ago" differs from "clicked just now." 3) Self-attention: project every item into Query/Key/Value vectors; the target item's query is compared against every behavior item's key to get relevance scores, softmax-normalized into attention weights, then used to weight-sum the values into a context vector. 4) Point-wise MLP combines the attention context with the target embedding and other (user/item) features and outputs a click probability via sigmoid.

Design Decision: Why append the target to the sequence?

Unlike DIN (Deep Interest Network), which runs a single target-attention layer comparing the target only against history, BST treats [behavior₁, …, behaviorₙ, target] as one sequence and lets a full Transformer encoder block (self-attention + residual + layer norm + feed-forward) operate over all of it — every item can attend to every other item, not just the target attending to history. This demo implements the core scaled dot-product attention step that drives that mechanism.

🔑 Key Property

Self-attention gives BST a content-aware, adaptive receptive field over the user's history — the weight given to each past item is computed on the fly from how relevant it is to the candidate, not fixed by a hand-designed pooling rule.

3
Why It Works — The Math
▼

Positional Encoding

For position \(pos\) and embedding dimension \(d\), BST uses the sinusoidal encoding from the original Transformer:

$$PE_{(pos,2i)} = \sin\left(\frac{pos}{10000^{2i/d}}\right), \qquad PE_{(pos,2i+1)} = \cos\left(\frac{pos}{10000^{2i/d}}\right)$$

This is added elementwise to the item embedding: \(x_i = e_i + PE(pos_i)\), giving the model a way to distinguish "this item happened first" from "this item happened last."

Scaled Dot-Product Self-Attention

Each transformed vector is linearly projected into a Query, Key, and Value using learned weight matrices \(W^Q, W^K, W^V\): \(Q = XW^Q,\; K = XW^K,\; V = XW^V\). Attention weights come from comparing the target's query against every item's key:

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

The \(\sqrt{d_k}\) scaling prevents large dot products (which grow with dimension) from pushing softmax into regions with vanishing gradients. The softmax output is a probability distribution over behavior items — the attention weights — used to form a weighted-sum context vector.

The Prediction Head

$$\hat{y} = \sigma\Big(W_3\,\text{ReLU}\big(W_2\,\text{ReLU}(W_1 z + b_1) + b_2\big) + b_3\Big), \quad z = [\text{context} \,\oplus\, e_{\text{target}} \,\oplus\, \text{other feats}]$$

The context vector (what the model learned to focus on), the raw target embedding, and dense/sparse side features (user age bucket, price tier, etc.) are concatenated and passed through a small feed-forward network trained with binary cross-entropy against observed clicks.

⚠️ Common Pitfall

Without positional encoding, self-attention is permutation-invariant — shuffling the behavior sequence would give an identical prediction. That throws away real signal: recency matters a lot in shopping behavior. Forgetting positional encodings is one of the most common bugs when implementing attention-based sequence models.

Key Takeaways
▼

When to use BST:

  • You have rich, ordered per-user behavior sequences (clicks, add-to-cart, purchases) and want to model intra-session or cross-session relevance dynamically.
  • Sequence length is moderate (tens of items) — full self-attention is \(O(n^2)\) in sequence length, so very long histories need truncation, hierarchical attention, or sparse attention variants.
  • You need to rank/score many candidate items per user in a recommendation or ads system (BST was built for exactly this at Alibaba's Taobao display advertising).

When NOT to use / watch out:

  • Extremely short histories (1-2 items) — attention has little to select from; simple concatenation may suffice.
  • Latency-critical serving with huge candidate sets — the sequence encoder cost is amortized per-user but still adds inference overhead versus pooling.
  • Don't skip positional encoding — without it the model cannot tell recent behavior from old behavior.
💡 Hierarchy

Sum/Avg Pooling (no relevance weighting) ⊂ DIN (target-only attention over history) ⊂ BST (full Transformer self-attention over history + target, with positional encoding). Each step lets the model express richer, more adaptive interest representations.

Code Trace
▼
import numpy as np
# Behavior sequence (6 items) + 1 candidate/target item
e_seq = embed(item_ids) # (6, d)
e_tgt = embed(target_id) # (d,)
# Sinusoidal positional encoding, added elementwise
pe = positional_encoding(range(7), d)
x_seq = e_seq + pe[:6]
x_tgt = e_tgt + pe[6]
# Linear projections
Q = x_tgt @ Wq # (d,)
K = x_seq @ Wk # (6, d)
V = x_seq @ Wv # (6, d)
# Scaled dot-product attention
scores = (Q @ K.T) / np.sqrt(d) # (6,)
attn = softmax(scores) # (6,)
context = attn @ V # (d,)
# Point-wise MLP -> click probability
z = concat([context, e_tgt, other_feats])
h1 = relu(W1 @ z + b1)
h2 = relu(W2 @ h1 + b2)
ctr = sigmoid(W3 @ h2 + b3)
# Baseline for comparison: uniform average pooling
context_avg = V.mean(axis=0)
ctr_avg = sigmoid(W3 @ relu(W2 @ relu(W1 @ concat([context_avg, e_tgt, other_feats]) + b1) + b2) + b3)
