Self-supervised learning with swapped predictions and multi-scale views

1
Understanding SwAV
▼

What is it? SwAV (Swapping Assignments between multiple Views) is a self-supervised learning method that trains neural networks to learn powerful visual representations without human labels. It works by generating multiple augmented "crops" (views) of an image, extracting features from them, and then enforcing a consistency constraint: the cluster assignment (or "code") of one crop should be predictable from the feature representation of another crop of the same image. This is achieved through an online clustering process that uses a set of learnable "prototypes" and the Sinkhorn-Knopp algorithm for balanced assignments.

Analogy: Imagine teaching a child to recognize objects, but instead of telling them "that's a cat," you show them many different pictures of cats (full body, close-up of face, zoomed-out, slightly distorted). Each time, you ask them to group it with similar pictures they've seen before. If they group a close-up of a cat's eye with a picture of a dog, you gently correct them by showing them the full cat picture and saying, "No, this eye belongs to *this* full cat." SwAV does this for a neural network: it expects different views of the same object to be assigned to the same "conceptual cluster" (prototype), even if the views are drastically different.

💡 If you remember one thing

SwAV learns visual features by clustering different augmented views of the same image and then making them predict each other's cluster assignments. It combines elements of contrastive learning (consistency across views) with clustering (prototypes), but without needing explicit negative pairs, making it memory-efficient and effective.

2
How SwAV Works Internally
▼

The Core Mechanism: Multi-Crop & Swapped Prediction

SwAV operates on a batch of images by applying a multi-crop strategy: for each image, it generates two large resolution crops (e.g., 224x224) and several small resolution crops (e.g., 96x96). All these crops are passed through a shared neural network encoder \(f_\theta\), yielding feature vectors (embeddings).

For each feature vector \(z_v = f_\theta(x_v)\) corresponding to a crop \(x_v\), SwAV performs two main steps:

  1. Prototype Assignment: It computes a "code" or soft assignment \(q_v\) for \(z_v\) by matching it to a set of \(K\) learnable prototype vectors \(C = \{c_1, \dots, c_K\}\). This assignment is done using an optimal transport formulation solved by the Sinkhorn-Knopp algorithm, ensuring that each prototype is used approximately equally across the batch.
  2. Swapped Prediction: For any pair of crops \((x_v, x_{v'})\) from the same image, the goal is to predict the code \(q_{v'}\) (from crop \(x_{v'}\)) using the feature \(z_v\) (from crop \(x_v\)). Simultaneously, it predicts \(q_v\) using \(z_{v'}\). This "swapped" prediction forces the network to learn rich, consistent representations regardless of the crop's scale or content.

Design Decisions: Why Multi-Crop and Sinkhorn-Knopp?

  • Multi-Crop Strategy: Using multiple views at different scales (large and small) forces the network to learn representations that are robust to scale changes and partial occlusions. Small crops typically contain less context, preventing the network from relying on trivial global cues and pushing it towards learning more local, discriminative features.
  • Sinkhorn-Knopp Algorithm: This algorithm is used to obtain the "codes" \(q_v\). It ensures that the assignments are balanced, meaning no single prototype dominates the assignments and each prototype gets used by a roughly equal number of samples in a batch. This prevents "collapse" where all features might map to a single prototype. It also provides soft, differentiable assignments, crucial for end-to-end training.
🔑 Key Property

SwAV's loss function encourages consistency between different augmented views of the same image by making the feature representation of one view predict the cluster assignment (code) of another view. This "swapped" prediction, combined with multi-crop augmentation and online clustering with balanced prototype usage, enables robust self-supervised learning.

Why It Works — The Math
▼

The Swapped Prediction Loss Function

Let \(x\) be an image, and \((x_v, x_{v'})\) be two different augmented crops from \(x\). Let \(z_v = f_\theta(x_v)\) and \(z_{v'} = f_\theta(x_{v'})\) be their corresponding feature vectors from the encoder \(f_\theta\). Let \(C = \{c_1, \dots, c_K\}\) be the set of \(K\) learnable prototype vectors. The objective is to match the feature \(z_v\) to the code \(q_{v'}\) of \(z_{v'}\), and vice-versa. The loss for a pair of views is:

$$\mathcal{L}(z_v, z_{v'}) = \ell(z_v, q_{v'}) + \ell(z_{v'}, q_v)$$

where \(\ell(z, q) = -\sum_{k=1}^K q_k \log p_k\) is the cross-entropy loss, and \(p_k\) is the probability that feature \(z\) belongs to prototype \(c_k\):

$$p_k = \frac{\exp(z^\top c_k / \tau)}{\sum_{j=1}^K \exp(z^\top c_j / \tau)}$$

Here, \(\tau\) is a temperature parameter. The codes \(q_v\) and \(q_{v'}\) are obtained by solving an optimal transport problem using Sinkhorn-Knopp, which assigns feature vectors to prototypes while ensuring a balanced distribution across prototypes. Specifically, for a batch of \(B\) features \(\{z_1, \dots, z_B\}\) and \(K\) prototypes \(\{c_1, \dots, c_K\}\), we want to find a matrix \(Q \in \mathbb{R}^{B \times K}\) such that:

$$Q = \arg\min_Q \sum_{b=1}^B \sum_{k=1}^K (-\text{sim}(z_b, c_k)) Q_{bk} \quad \text{s.t.} \quad Q \mathbf{1}_K = \frac{1}{B}\mathbf{1}_B, \quad Q^\top \mathbf{1}_B = \frac{1}{K}\mathbf{1}_K$$

where \(\text{sim}(z_b, c_k)\) is a similarity measure (e.g., dot product). The Sinkhorn-Knopp algorithm iteratively normalizes rows and columns of a similarity matrix to satisfy these marginal constraints, producing soft assignments \(Q_{bk}\) which are then used as the target codes \(q_b\).

⚠️ Common Pitfall

The Sinkhorn-Knopp algorithm, while powerful for balanced assignments, can be computationally intensive, especially for large batches or many prototypes. Implementations often use a small number of iterations (e.g., 3-5) for efficiency. Also, the prototypes \(C\) are typically updated via an exponential moving average (EMA) of the gradients or directly from the features, rather than standard SGD, to maintain stability in the online clustering process.

Key Takeaways
▼

When to use SwAV:

  • Self-supervised pretraining: When you have a large unlabeled dataset and want to learn general-purpose visual features without manual annotation.
  • Transfer learning: Pretraining with SwAV can yield representations that transfer well to various downstream tasks (classification, detection, segmentation) with limited labeled data.
  • Computational efficiency: Compared to contrastive methods that require explicit negative pairs, SwAV's clustering approach can be more memory-efficient as it doesn't need a large memory bank or very large batch sizes to form negative pairs.

When NOT to use:

  • Small datasets: Self-supervised methods generally require abundant data to learn meaningful representations. For very small datasets, simpler supervised approaches might be more effective.
  • Limited compute resources: While memory-efficient, the multi-crop strategy (processing many crops per image) and the Sinkhorn-Knopp algorithm (even with few iterations) add computational overhead compared to a single-crop supervised baseline.
  • Tasks where labels are abundant: If you have a fully labeled dataset, a standard supervised training approach might be simpler and provide competitive results without the added complexity of self-supervised pipelines.
💡 Big Picture

SwAV effectively bridges the gap between contrastive learning and clustering-based methods. By forcing consistency across diverse views of the same image through swapped prediction and using optimal transport to balance prototype assignments, it learns powerful, robust, and transferable visual features without relying on hand-crafted negative pairs.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
import torch.nn.functional as F
class SwAV(nn.Module):
def __init__(self, encoder, prototypes, temperature=0.1, epsilon=0.05, sinkhorn_iterations=3):
super().__init__()
self.encoder = encoder
self.prototypes = nn.Linear(encoder.output_dim, prototypes, bias=False)
self.temperature = temperature
self.epsilon = epsilon
self.sinkhorn_iterations = sinkhorn_iterations
def forward(self, multi_crop_views):
# multi_crop_views is a list of tensors, each representing a batch of crops
all_features = []
for view_batch in multi_crop_views:
features = self.encoder(view_batch)
features = F.normalize(features, dim=1) # L2 normalize features
all_features.append(features)
# Compute scores for prototypes (logits)
logits = [self.prototypes(z) for z in all_features]
# Compute codes (soft assignments) using Sinkhorn-Knopp
with torch.no_grad(): # Codes q are targets, don't backprop through them
codes = []
for logit in logits:
q = self.sinkhorn_knopp(logit)
codes.append(q)
# Calculate swapped prediction loss
loss = 0
num_views = len(all_features)
for i in range(num_views):
for j in range(num_views):
if i == j: continue # Don't compare a view with itself
# Predict code[j] from logits[i]
p_i = F.log_softmax(logits[i] / self.temperature, dim=1)
loss -= (codes[j] * p_i).sum(dim=1).mean()
# Update prototypes (EMA, not shown here for brevity)
# self.prototypes.weight.data = EMA(self.prototypes.weight.data, all_features)
return loss
def sinkhorn_knopp(self, M):
# M is the similarity matrix (batch_size, num_prototypes)
Q = torch.exp(M / self.epsilon).T # K x B matrix
Q /= Q.sum(dim=1, keepdim=True) # sum to 1 over prototypes for each feature
for _ in range(self.sinkhorn_iterations):
Q /= Q.sum(dim=0, keepdim=True) # column-wise normalization (balance prototype usage)
Q /= Q.sum(dim=1, keepdim=True) # row-wise normalization (sum to 1 for each feature)
return Q.T # B x K matrix of codes
