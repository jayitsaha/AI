Understanding Tensors
▼

What is a tensor? In deep learning, a tensor is simply an N-dimensional array of numbers. A single temperature reading is a scalar (0-D tensor). A list of daily temperatures is a vector (1-D tensor). A spreadsheet of temperatures per city per day is a matrix (2-D tensor). A video frame stack (batch × height × width × channels) is a 4-D tensor. The word "tensor" is just the general name for this family.

Why the word "tensor"? The term comes from physics and differential geometry, where tensors are objects that transform in specific ways under coordinate changes. In ML we use a simpler, purely computational meaning: any rectangular grid of numbers with any number of axes.

If you remember one thing

A tensor's order (also called its degree or number of modes) equals the number of indices you need to pick out one element. Scalars need 0 indices, vectors need 1, matrices need 2, and so on. In NumPy/PyTorch this is ndim.

The Two Meanings of "Rank"
▼
The Terminology Trap

The word "rank" means two completely different things depending on your community. Confusing them is one of the most common source of misunderstanding at the math/ML interface. Always ask: order rank or CP rank?

Meaning 1 — Order / Number of Axes (DL usage)

In PyTorch, TensorFlow, and most ML code, "rank" = number of dimensions = ndim. This is more precisely called the order or degree of the tensor. It tells you how many index slots exist.

$$\text{order}(\mathcal{T}) = \text{number of axes} = \texttt{T.ndim}$$
  • Scalar \(s \in \mathbb{R}\): order 0
  • Vector \(\mathbf{v} \in \mathbb{R}^n\): order 1
  • Matrix \(M \in \mathbb{R}^{m \times n}\): order 2
  • 3-D tensor \(\mathcal{T} \in \mathbb{R}^{d_1 \times d_2 \times d_3}\): order 3
Order in ML code

torch.Tensor.ndim and tf.Tensor.ndim return the order. A batch of RGB images has shape \((B, H, W, 3)\) and order 4. When PyTorch docs say "a rank-3 tensor," they mean order 3.

Meaning 2 — CP-Rank (Multilinear Algebra)

The CP-rank (Canonical Polyadic rank, also called tensor rank) is the minimum number of rank-1 tensors whose sum equals \(\mathcal{T}\). A rank-1 tensor is an outer product of vectors:

$$\mathcal{T} \text{ has CP-rank } R \iff \mathcal{T} = \sum_{r=1}^{R} \mathbf{u}_r \otimes \mathbf{v}_r \otimes \mathbf{w}_r \quad (\text{for 3-D tensor})$$

This generalizes matrix rank. For matrices, CP-rank = matrix rank = min outer products. For tensors of order ≥ 3, CP-rank is NP-hard to compute in general — a deep contrast with matrix rank which is solvable via SVD in polynomial time.

Why CP-rank is hard

Unlike matrices where SVD gives an exact rank-1 decomposition in polynomial time, computing the CP-rank of an order-3 tensor is NP-hard (Håstad, 1990). Even worse: the set of tensors with CP-rank \(\leq r\) is not closed — you can have a sequence of rank-2 tensors converging to a rank-3 tensor!

The Math — CP Decomposition & Why It's Hard
▼

Rank-1 Tensors: The Building Block

An order-\(N\) tensor \(\mathcal{T} \in \mathbb{R}^{d_1 \times \cdots \times d_N}\) is rank-1 if it can be written as an outer product of \(N\) vectors:

$$\mathcal{T} = \mathbf{u}^{(1)} \otimes \mathbf{u}^{(2)} \otimes \cdots \otimes \mathbf{u}^{(N)}, \quad \mathcal{T}_{i_1 i_2 \cdots i_N} = u^{(1)}_{i_1} \cdot u^{(2)}_{i_2} \cdots u^{(N)}_{i_N}$$

CP Decomposition (Canonical Polyadic / PARAFAC)

Every tensor can be written as a finite sum of rank-1 terms. The CP decomposition of a 3-D tensor is:

$$\mathcal{T} = \sum_{r=1}^{R} \lambda_r \, \mathbf{a}_r \otimes \mathbf{b}_r \otimes \mathbf{c}_r$$

where \(\lambda_r \in \mathbb{R}\) are scalars (weights) and \(\mathbf{a}_r, \mathbf{b}_r, \mathbf{c}_r\) are unit vectors along each mode. In matrix form, using factor matrices \(A = [\mathbf{a}_1 | \cdots | \mathbf{a}_R]\), \(B, C\) similarly:

$$\mathcal{T}_{ijk} = \sum_{r=1}^{R} A_{ir} B_{jr} C_{kr}$$

Concrete 2×2×2 Example

Let \(\mathcal{T}\) have slices: \(\mathcal{T}_{:,:,0} = \begin{bmatrix}2&0\\1&0\end{bmatrix}\) and \(\mathcal{T}_{:,:,1} = \begin{bmatrix}0&0\\1&2\end{bmatrix}\). This has CP-rank 2 with decomposition:

$$\mathcal{T} = \begin{bmatrix}2\\1\end{bmatrix}\!\otimes\!\begin{bmatrix}1\\0\end{bmatrix}\!\otimes\!\begin{bmatrix}1\\0\end{bmatrix} + \begin{bmatrix}0\\1\end{bmatrix}\!\otimes\!\begin{bmatrix}1\\2\end{bmatrix}\!\otimes\!\begin{bmatrix}0\\1\end{bmatrix}$$

Verify element \(\mathcal{T}_{0,0,0}\): \(2 \cdot 1 \cdot 1 + 0 \cdot 1 \cdot 0 = 2\). Element \(\mathcal{T}_{1,1,1}\): \(1 \cdot 0 \cdot 0 + 1 \cdot 2 \cdot 1 = 2\). Correct.

Why Tensor Decomposition Matters

  • Compression: A \(d \times d \times d\) tensor has \(d^3\) entries. If CP-rank is \(R\), we need only \(3Rd\) numbers (\(3\times\) factor matrices).
  • Tucker decomposition (a generalization) underlies methods like HOSVD and multilinear PCA.
  • Tensor networks (MPS/TT-format) are used in quantum computing and as compressed DL weight representations.
Key mathematical fact

For matrices: \(\text{rank}(M) = \text{CP-rank}(M)\). For order-3 tensors over \(\mathbb{R}\): CP-rank can exceed the matrix rank of any unfolding (matricization), and the set of rank-\(\leq r\) tensors is not a closed set (no direct analogue of the matrix Eckart-Young theorem).

Key Takeaways & Comparison
▼

The essential summary:

  • A tensor is an N-dimensional rectangular array of numbers. Order = number of axes = ndim.
  • Order (also misleadingly called "rank" in DL): count of index slots. 0=scalar, 1=vector, 2=matrix, 3+=tensor.
  • CP-rank: minimum rank-1 outer-product terms in a CP decomposition. Generalizes matrix rank. NP-hard to compute for order ≥ 3.
  • The word "rank" alone is ambiguous. Always clarify: order-rank or CP-rank.
Where these show up in ML

Order: Every PyTorch tensor has a .ndim. Convolution expects 4-D (NCHW), transformers use 3-D (B,T,d) or 4-D (B,H,T,T) attention.
CP-rank: Low-rank tensor decompositions are used to compress weight tensors in mobile DL (Tucker/CP compression), and in matrix factorization for recommender systems.

Code Trace — PyTorch & NumPy
▼
import numpy as np
import torch
# ── ORDER (number of axes) ────────────────────────────────────
scalar = np.array(3.14) # order 0, shape ()
vector = np.array([1.,2.,3.]) # order 1, shape (3,)
matrix = np.arange(9.).reshape(3,3) # order 2, shape (3,3)
t3d = np.zeros((2,3,4)) # order 3, shape (2,3,4)
print(scalar.ndim) # 0 ← "rank" in DL = order
print(vector.ndim) # 1
print(matrix.ndim) # 2
print(t3d.ndim) # 3
# ── RANK-1 OUTER PRODUCT ─────────────────────────────────────
u = np.array([2., 1.]) # shape (2,)
v = np.array([1., 0.]) # shape (2,)
w = np.array([1., 0.]) # shape (2,)
term1 = np.einsum('i,j,k->ijk', u, v, w) # rank-1 tensor, shape (2,2,2)
a = np.array([0., 1.])
b = np.array([1., 2.])
c = np.array([0., 1.])
term2 = np.einsum('i,j,k->ijk', a, b, c) # second rank-1 term
T = term1 + term2 # CP-rank-2 tensor
print(T[:,:,0]) # [[2,0],[1,0]] ← slice k=0
print(T[:,:,1]) # [[0,0],[1,2]] ← slice k=1
# ── PyTorch equivalent ────────────────────────────────────────
x = torch.randn(8, 16, 32) # order 3: batch×seq×embed
print(x.ndim) # 3 ← PyTorch calls this "rank"
print(x.shape) # torch.Size([8, 16, 32])
# ── Tucker / multilinear rank ─────────────────────────────────
# Unfolding (matricization) along mode 0:
T_unfold0 = T.reshape(2, -1) # shape (2, 4)
print(np.linalg.matrix_rank(T_unfold0)) # mode-0 rank
# Tucker rank = tuple of mode ranks, computable via HOSVD
