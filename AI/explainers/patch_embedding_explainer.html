Patch Embedding: Image to Sequence

Transforming 2D images into 1D token sequences for Vision Transformers
Foundational Deep Learning Computer Vision O(HWCD)
1
Understanding Patch Embedding
▼

What is it? Patch embedding is the crucial first step in Vision Transformers (ViTs) that converts a standard 2D image into a 1D sequence of vectors. This transformation is necessary because Transformer architectures, originally designed for natural language processing, expect sequential input (like words in a sentence). It involves dividing the image into fixed-size, non-overlapping patches, flattening each patch into a vector, and then linearly projecting these vectors into a higher-dimensional embedding space.

Analogy: Imagine an art critic analyzing a large mural. Instead of trying to grasp the entire mural at once, they divide it into smaller, manageable squares (patches). For each square, they describe its key visual features in a concise summary (flatten and embed). Then, to understand the whole mural, they analyze the sequence of these summaries, considering how each described square relates to others.

💡 If you remember one thing

Patch embedding is the "tokenization" step for Vision Transformers, converting raw pixel data into a sequence of abstract tokens (patch embeddings) that can be processed by a standard Transformer encoder, just like word embeddings are used for text.

How It Works Internally
▼

The Core Steps: Patch, Flatten, Project

For an input image \(X \in \mathbb{R}^{H \times W \times C}\) (Height, Width, Channels), the patch embedding process typically follows these steps:

  1. Patching: The image is divided into \(N\) non-overlapping square patches of size \(P \times P\). For example, a \(224 \times 224\) image with \(16 \times 16\) patches yields \((224/16) \times (224/16) = 14 \times 14 = 196\) patches. Each patch has dimensions \(P \times P \times C\).
  2. Flattening: Each \(P \times P \times C\) patch is then reshaped (flattened) into a 1D vector. The dimension of this vector is \(P \times P \times C\).
  3. Linear Projection: Each flattened patch vector is linearly projected into a target embedding dimension \(D\). This is achieved by multiplying the flattened vector by a learnable weight matrix \(W_{proj} \in \mathbb{R}^{(P \times P \times C) \times D}\) and adding a learnable bias vector \(b_{proj} \in \mathbb{R}^D\). This operation maps the raw pixel values of a patch into a richer, higher-level feature representation.
  4. Sequence Formation: The \(N\) resulting \(D\)-dimensional patch embeddings are arranged into a 1D sequence.

Augmenting the Sequence: Class Token & Positional Embeddings

Once the basic sequence of patch embeddings is formed, two additional components are typically added before feeding it to a Transformer encoder:

  • Class Token ([CLS]): A special, learnable embedding vector, often prepended to the sequence. Similar to BERT, its final hidden state (after passing through the Transformer) serves as the image's aggregated representation for classification.
  • Positional Embeddings: Since Transformers are permutation-invariant (they don't inherently know the order or spatial arrangement of tokens), learnable positional embeddings are added to each patch embedding (and the class token). These embeddings encode the 2D spatial location of each patch within the original image, allowing the Transformer to retain and utilize spatial information.
🔑 Key Property

The output of the patch embedding module is a sequence of \(N_{tokens}\) vectors, each of dimension \(D\). Here, \(N_{tokens} = N + 1\) (if a class token is used), and \(N = (H/P) \times (W/P)\). This sequence is directly compatible with the input requirements of a standard Transformer encoder block.

3
Why It Works — The Math
▼

Input Image and Patching

Let an input image be \(X \in \mathbb{R}^{H \times W \times C}\). We divide it into \(N\) non-overlapping patches, each of size \(P \times P \times C\). The number of patches is given by:

$$N = \frac{H}{P} \times \frac{W}{P}$$

We can conceptually represent the collection of these patches as \(X_{patches} \in \mathbb{R}^{N \times P \times P \times C}\).

Flattening and Linear Projection

Each individual patch \(X_i \in \mathbb{R}^{P \times P \times C}\) is flattened into a 1D vector \(v_i \in \mathbb{R}^{P \cdot P \cdot C}\). This flattened vector is then linearly projected into a \(D\)-dimensional embedding space:

$$e_i = v_i W_{proj} + b_{proj}$$

where \(W_{proj} \in \mathbb{R}^{(P \cdot P \cdot C) \times D}\) is the learnable projection weight matrix, and \(b_{proj} \in \mathbb{R}^D\) is the learnable bias vector. The resulting patch embedding \(e_i \in \mathbb{R}^D\).

If we consider all \(N\) flattened patches stacked into a matrix \(V \in \mathbb{R}^{N \times (P \cdot P \cdot C)}\), the projection can be written as a single matrix multiplication:

$$E_{patches} = V W_{proj} + B_{proj}$$

Here, \(E_{patches} \in \mathbb{R}^{N \times D}\) is the matrix of patch embeddings, and \(B_{proj} \in \mathbb{R}^{N \times D}\) is the bias vector \(b_{proj}\) broadcasted across all \(N\) patches.

Final Sequence with Class and Positional Embeddings

The final sequence of tokens \(Z \in \mathbb{R}^{(N+1) \times D}\) fed to the Transformer is constructed by concatenating the learnable class token \(e_{cls} \in \mathbb{R}^D\) with the patch embeddings, and then adding positional embeddings \(E_{pos} \in \mathbb{R}^{(N+1) \times D}\):

$$Z = [e_{cls}; E_{patches}] + E_{pos}$$

Each row of \(Z\) is a \(D\)-dimensional vector representing a "token" (either the class token or an embedded patch) with its spatial information encoded. This sequence is now ready for the Transformer's self-attention mechanism.

⚠️ Positional Embeddings Are Crucial

Without positional embeddings, the Transformer would treat the image patches as an unordered bag of features. This would completely destroy the spatial relationships between parts of the image, leading to a severe loss of information and poor performance on visual tasks. The positional embeddings explicitly re-introduce this vital spatial context.

Key Takeaways
▼

When to use Patch Embedding:

  • When applying Transformer architectures (originally for sequences) to image data, especially for Vision Transformers (ViT, DeiT, MAE, Swin Transformer).
  • When you want to leverage the global attention mechanisms of Transformers to capture long-range dependencies across image regions, rather than relying solely on local convolutional operations.
  • For tasks where a global context is critical, as self-attention can relate any patch to any other patch.

When NOT to use Patch Embedding (or use with caution):

  • For very small images where patches become too small or too few (e.g., an 8x8 image with 4x4 patches yields only 4 patches, limiting the sequence length and attention capacity).
  • When computational efficiency is paramount for very high-resolution images. Many patches lead to a long sequence, and Transformer's self-attention has quadratic complexity with respect to sequence length, making it computationally expensive.
  • When the strong inductive biases of Convolutional Neural Networks (translation equivariance, local receptive fields) are explicitly desired and have shown superior performance for specific tasks or datasets.
💡 Patch Embedding as a Bridge

Patch embedding is a fundamental bridge between the pixel domain and the token domain, enabling the powerful self-attention mechanism of Transformers to process visual information by treating image regions as abstract tokens. It's a key innovation that brought Transformer architectures to the forefront of computer vision.

Code Trace (Python/NumPy)
▼
import numpy as np
def patch_embedding(image, patch_size, embed_dim, add_cls_token=True, add_pos_embed=True):
H, W, C = image.shape
assert H % patch_size == 0 and W % patch_size == 0, "Image dimensions must be divisible by patch size"
num_patches_h = H // patch_size
num_patches_w = W // patch_size
num_patches = num_patches_h * num_patches_w
patch_dim = patch_size * patch_size * C
# 1. Divide image into patches and flatten
patches = image.reshape(num_patches_h, patch_size, num_patches_w, patch_size, C)
patches = patches.transpose(0, 2, 1, 3, 4).reshape(num_patches, patch_dim)
# 2. Linear projection
# (In a real model, W_proj and b_proj are learnable parameters)
W_proj = np.random.randn(patch_dim, embed_dim) * 0.01
b_proj = np.zeros(embed_dim)
patch_embeddings = patches @ W_proj + b_proj
# 3. Add Class Token (optional)
if add_cls_token:
cls_token = np.random.randn(1, embed_dim) * 0.01 # learnable [CLS] token
patch_embeddings = np.concatenate((cls_token, patch_embeddings), axis=0)
# 4. Add Positional Embeddings (optional)
if add_pos_embed:
# Simplified positional embeddings (in reality, often learned or fixed sin/cos)
pos_embed = np.random.randn(patch_embeddings.shape[0], embed_dim) * 0.01
patch_embeddings = patch_embeddings + pos_embed
return patch_embeddings
# Example usage:
input_image = np.random.rand(16, 16, 3) # 16x16 RGB image
patch_size = 4
embed_dim = 64
output_sequence = patch_embedding(input_image, patch_size, embed_dim)
print(f"Output sequence shape: {output_sequence.shape}")
# Expected: (17, 64) for 16 patches + 1 CLS token
