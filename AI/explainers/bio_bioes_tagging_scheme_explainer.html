BIO / BIOES Tagging Scheme

Turning entity spans into a token-by-token labeling problem for NER
Foundational NLP Sequence Labeling O(n) tagging
1
Understanding BIO / BIOES
▼

What is it? A Named Entity Recognition (NER) model doesn't output "spans" directly — it classifies one token at a time. BIO and BIOES are the encoding schemes that translate an entity span like "New York = LOCATION" into a sequence of per-token labels the model can actually predict, and that a decoder can turn back into spans.

Analogy: Imagine reading a sentence aloud and, for every single word, whispering one of five stickers onto it: "this word begins a name," "this word is inside a name," "this word ends a name," "this word is the whole name by itself," or "this word is nothing special." Line the stickers back up and you can reconstruct exactly which words formed each name — without ever having stored the spans explicitly.

💡 If you remember one thing

BIO uses 3 tag types per entity class (\(B\), \(I\), \(O\)); BIOES adds two more (\(E\), \(S\)) so every span's exact start and end is marked explicitly — turning span detection into a strictly local, token-level classification problem.

2
How the Schemes Work Internally
▼

BIO (a.k.a. IOB2): three symbols per class

For each entity type \(t\) (e.g. PER, LOC, ORG), BIO defines two tags plus one shared tag: \(B\text{-}t\) marks the first token of an entity of type \(t\); \(I\text{-}t\) marks every subsequent token inside that same entity; \(O\) marks a token that belongs to no entity at all. Critically, \(B\text{-}t\) is used even when two entities of the same type sit right next to each other — that is what lets a decoder tell "Barack Obama" and "Cristiano Ronaldo" apart even though both are back-to-back \(PER\) spans: the second one restarts with \(B\text{-}PER\) instead of continuing with \(I\text{-}PER\).

BIOES (a.k.a. IOBES): five symbols per class

BIOES keeps \(B\) and \(I\) but splits the "end of span" and "single-token span" cases out of \(I\)/\(B\) into their own explicit tags: \(E\text{-}t\) marks the last token of a multi-token entity, and \(S\text{-}t\) marks an entity that is exactly one token long (so it is simultaneously its own begin and end). A multi-token span of length \(k\) is therefore tagged \(B, I^{k-2}, E\); a length-1 span is tagged \(S\) alone.

Design Decision: why bother with E and S at all?

Under BIO, a model that emits \(I\text{-}PER\) is not committing to "the span ends here" — the very next token could also be \(I\text{-}PER\). Under BIOES, emitting \(E\text{-}PER\) is an unambiguous, local statement that the span stops at this token. This extra granularity gives sequence taggers (CRFs, BiLSTM-CRF, transformer token classifiers) a sharper training signal at span boundaries, which empirically reduces boundary errors — the dominant error class in NER.

🔑 Key Property

Both schemes are lossless and invertible: given the full tag sequence you can reconstruct the exact entity spans and types with no ambiguity, and given the spans you can always regenerate the tags deterministically.

3
Why It Works — Tag Space & Boundary Signal
▼

Tag vocabulary size

If there are \(E\) entity types, the label set size for each scheme is:

$$|\mathcal{Y}_{BIO}| = 2E + 1 \qquad\qquad |\mathcal{Y}_{BIOES}| = 4E + 1$$

The "+1" is the shared \(O\) tag. This is the softmax output size of a token classifier, or the state space of a linear-chain CRF — bigger for BIOES, but still linear in \(E\), not a real cost in practice.

Valid transition constraints (structured decoding)

When a CRF or Viterbi decoder is used on top of the tagger, illegal tag transitions are given \(-\infty\) score, e.g. \(O \to I\text{-}t\) is illegal (an "inside" tag must be preceded by \(B\text{-}t\) or \(I\text{-}t\) of the same type), and under BIOES, \(B\text{-}t \to O\) is also illegal (a begun span must be continued or closed with \(E\text{-}t\)):

$$\text{score}(y_{1:n}) = \sum_{i=1}^n \phi(y_i \mid x_i) + \sum_{i=2}^n A(y_{i-1}, y_i), \qquad A(y_{i-1},y_i) = -\infty \text{ if illegal}$$

BIOES supplies more illegal-transition constraints than BIO (e.g. it also forbids "\(I\text{-}t\) immediately followed by \(O\)" since a span must be properly closed with \(E\)), which prunes more invalid sequences during Viterbi decoding and further sharpens predictions.

Boundary-signal ratio

Define the boundary ratio as the fraction of non-\(O\) tags that explicitly mark a span edge (\(B\), \(E\), or \(S\)) versus purely "interior" tags (\(I\)):

$$\rho = \frac{\#\{B,E,S\}}{\#\{B,I,E,S\}}$$

For BIO, only the start is marked, so \(\rho_{BIO} < \rho_{BIOES}\) whenever any span has length \(\ge 2\) — BIOES always marks both edges, so \(\rho_{BIOES} \ge \rho_{BIO}\), with equality only when every entity is length 1.

⚠️ Common Pitfall

BIOES is not always better in practice for every model. With very little training data, the larger, sparser label space \((4E+1\) vs \(2E+1)\) can hurt a plain softmax classifier that has no CRF layer to enforce structure — each rare \(E\text{-}t\)/\(S\text{-}t\) tag gets fewer training examples. It shines most when paired with a CRF/Viterbi decoding layer that can exploit the extra transition constraints.

Key Takeaways
▼

When to use BIO:

  • Small / low-resource training sets — fewer, denser tag classes generalize better
  • Simple softmax token classifiers without a CRF/decoding layer
  • You want the smallest possible label space (\(2E+1\)) for speed or interpretability

When to use BIOES:

  • You have a BiLSTM-CRF / transformer-CRF that can exploit richer transition constraints
  • Entity boundaries are the main error source (long or ambiguous spans)
  • Sufficient training data to populate the sparser \(E\)-/\(S\)- tag classes
💡 Hierarchy

Every entity span, however it's encoded — BIO \((B,I,O)\), BIOES \((B,I,E,S,O)\), or the older IOB1 (\(B\) only when disambiguating adjacent same-type spans) — reduces to the same underlying object: a list of \((\text{start}, \text{end}, \text{type})\) triples. The scheme only changes how much boundary information is exposed to the token classifier during training.

Code Trace
▼
tokens = ["Barack","Obama","and","Cristiano","Ronaldo",
"visited","New","York","with","Messi","yesterday"]
# Ground-truth entity spans: (start_idx, end_idx_exclusive, type)
spans = [(0, 2, "PER"), (3, 5, "PER"), (6, 8, "LOC"), (9, 10, "PER")]
def to_bio(tokens, spans):
tags = ["O"] * len(tokens)
for start, end, etype in spans:
tags[start] = f"B-{etype}"
for i in range(start + 1, end):
tags[i] = f"I-{etype}" # every non-first token
return tags
def to_bioes(tokens, spans):
tags = ["O"] * len(tokens)
for start, end, etype in spans:
length = end - start
if length == 1:
tags[start] = f"S-{etype}" # single-token entity
else:
tags[start] = f"B-{etype}"
tags[end - 1] = f"E-{etype}" # explicit end marker
for i in range(start + 1, end - 1):
tags[i] = f"I-{etype}"
return tags
# tags_to_spans is the exact inverse of either function above --
# scan left to right, open a span at B/S, close it at E/S/next-B/O.
print("BIO: ", to_bio(tokens, spans))
print("BIOES:", to_bioes(tokens, spans))
