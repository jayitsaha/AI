1
Understanding N-HiTS
▼

What is it? N-HiTS (Neural Hierarchical Interpolation for Time Series) is a powerful neural network architecture designed for long-horizon time series forecasting. It builds upon the successful N-BEATS model by introducing a key innovation: hierarchical interpolation. Instead of directly predicting future values, N-HiTS blocks predict coefficients for interpolation functions, which then generate the actual time series. This allows it to efficiently capture patterns at multiple scales (e.g., daily, weekly, monthly trends) and combine them into a robust forecast.

Analogy: Imagine you're a chief meteorologist trying to predict the weather for the next year. You have several specialized forecasters: one is good at predicting broad seasonal temperature shifts (coarse patterns), another excels at weekly temperature cycles, and a third focuses on daily fluctuations and anomalies (fine details). N-HiTS is like a system that combines these experts. Each expert (block) processes the "leftover" prediction errors from the previous one, and critically, each expert provides a smooth, interpolated prediction. The final forecast is a sum of all these smooth, multi-scale predictions.

💡 If you remember one thing

N-HiTS is a stack of neural blocks that decompose a time series forecasting problem into learning interpolation coefficients at different temporal resolutions. By summing these hierarchically learned, smoothly interpolated components, it achieves high accuracy and efficiency for long-horizon predictions.

2
How N-HiTS Works Internally
▼

Building on N-BEATS: Stacking Blocks and Residuals

N-HiTS inherits its core structure from N-BEATS: a deep stack of identical "blocks." Each block takes a segment of historical data as input and produces two outputs:

  1. A forecast for the future.
  2. A backcast, which is a reconstruction of the historical input.

The crucial part is how these blocks are chained: the backcast from the current block is subtracted from the original historical input, and the residual (the part the current block couldn't explain) is passed as input to the next block. This residual learning allows each subsequent block to focus on progressively finer or different patterns in the time series.

The N-HiTS Innovation: Hierarchical Interpolation

Unlike N-BEATS, which directly outputs time series points, N-HiTS blocks output coefficients for an interpolation function. Specifically:

  • Each block learns a set of coefficients for its backcast and another set for its forecast.
  • These coefficients parameterize a fixed interpolation function (e.g., a cubic spline or linear interpolation). The interpolation function then generates the actual time series values.
  • Crucially, different blocks can operate at different "sampling rates" or "resolutions." A block might be configured to predict coefficients for a coarsely downsampled version of the series, capturing long-term trends, while another block might target a fine-grained, high-resolution interpolation for short-term fluctuations.

The final forecast is simply the sum of the forecasts generated by all individual blocks. This hierarchical combination of interpolated components allows N-HiTS to be highly effective at capturing both global trends and local details, especially for very long forecasting horizons where traditional point-wise prediction can struggle due to error accumulation.

Why Interpolation?

Interpolation provides several advantages:

  • Smoothness: Interpolated forecasts are inherently smooth, which can be desirable for many real-world time series and helps to regularize the model.
  • Efficiency: Instead of predicting \(H\) individual future points, a block predicts a small number of interpolation coefficients, which can then generate the \(H\) points. This reduces the output dimension of the neural network head.
  • Multi-rate Flexibility: The choice of interpolation points and methods allows blocks to easily operate at different temporal resolutions, a core tenet of hierarchical forecasting.
🔑 Key Property

N-HiTS leverages the compositionality of interpolation functions. Each block contributes a smooth, basis-expanded component to the total forecast. The residual connections ensure that later blocks refine the predictions of earlier blocks, focusing on unexplained variance at different scales.

Why It Works — The Math
▼

The N-BEATS Foundation

The N-BEATS family of models relies on a stack of \(K\) blocks. For a given historical input \(x_{hist}\) of length \(L\), each block \(k\) processes a residual input \(x^{(k)}\) and produces a backcast \(b_k\) and a forecast \(f_k\). The residual for the next block is then \(x^{(k+1)} = x^{(k)} - b_k\). The total forecast is the sum of all individual block forecasts:

$$ \hat{y} = \sum_{k=1}^K f_k $$ $$ \text{where } (b_k, f_k) = \text{Block}_k(x^{(k)}), \quad x^{(1)} = x_{hist}, \quad x^{(k+1)} = x^{(k)} - b_k $$

This residual connection ensures that each block learns to explain the remaining variance in the signal, leading to a robust decomposition.

N-HiTS: Coefficients and Interpolation

The key difference in N-HiTS is that each block \(k\) doesn't directly output \(b_k\) and \(f_k\). Instead, its internal neural network (typically an MLP) outputs sets of coefficients:

$$ (\mathbf{c}_{b,k}, \mathbf{c}_{f,k}) = \text{MLP}_k(x^{(k)}) $$

These coefficients are then used to generate the backcast and forecast time series via an interpolation function \(\mathcal{I}(\cdot)\). The interpolation function itself is fixed (e.g., linear, cubic, or a specific basis expansion like Fourier or Legendre polynomials), but the neural network learns the optimal coefficients for it. The general form of such an interpolation is:

$$ \text{series}(t) = \mathcal{I}(\mathbf{c}, \mathbf{t}) = \sum_{j=1}^{N_c} c_j \cdot \phi_j(t) $$

Here, \(\mathbf{c}\) are the learned coefficients, \(\mathbf{t}\) are the time indices (or normalized versions thereof), and \(\phi_j(t)\) are the fixed basis functions (e.g., polynomial terms, sinusoidal waves for Fourier, etc.). The number of coefficients \(N_c\) can be much smaller than the output length \(L\) or \(H\), making the representation efficient.

For N-HiTS, the interpolation is often performed at different resolutions. A block might output coefficients for a downsampled version of the time series, effectively capturing lower-frequency components, while another block handles higher-frequency details. This hierarchical approach, combined with the residual learning, allows the model to effectively disentangle and forecast complex multi-scale temporal patterns.

⚠️ Common Pitfall

While interpolation provides smoothness and efficiency, it can also act as a low-pass filter. If a time series contains critical, sharp, non-smooth changes (e.g., sudden spikes or drops) that are not well-represented by the chosen interpolation basis functions, N-HiTS might struggle to capture them accurately, potentially smoothing them out. This is a trade-off for its robustness and efficiency.

Key Takeaways
▼

When to use N-HiTS:

  • Long-horizon forecasting: Its hierarchical, interpolated approach excels at predicting far into the future without accumulating excessive error.
  • Complex multi-frequency time series: Data with overlapping trends, seasonality, and irregular fluctuations can be effectively decomposed and learned.
  • Computational efficiency: Compared to attention-based transformers for very long sequences, N-HiTS can be more efficient due to its basis expansion and MLP-only architecture.
  • Need for smooth forecasts: The inherent smoothness from interpolation is often a desirable property for many applications.

When NOT to use:

  • Very short horizons: Simpler models (ARIMA, Exponential Smoothing, even vanilla N-BEATS) might offer comparable performance with less complexity.
  • Critical, sharp, non-smooth changes: If the time series features abrupt, non-interpolable events that are crucial to predict precisely, the smoothing effect of interpolation might obscure them.
  • Extremely sparse or irregular data: Interpolation methods assume some underlying continuity, which might not hold for highly irregular or sparse time series.
  • Extreme interpretability of individual feature contributions: While the block decomposition offers some interpretability, the final forecast is a sum of many interpolated components, making direct feature-to-output mapping less clear than in simpler linear models.
💡 Big Picture

N-HiTS is a testament to the power of combining modular neural architectures (N-BEATS) with classical signal processing ideas (basis expansion, interpolation). By reformulating point-wise prediction into learning smooth, multi-resolution components, it addresses key challenges in modern time series forecasting.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
import torch.nn as nn
import numpy as np
from scipy.interpolate import interp1d
# Helper for interpolation (e.g., linear or cubic spline)
def interpolate_from_coeffs(coeffs, target_len, interpolation_type='linear'):
num_coeffs = coeffs.shape[-1]
# Assume coeffs represent values at `num_coeffs` evenly spaced points
original_indices = np.linspace(0, 1, num_coeffs)
target_indices = np.linspace(0, 1, target_len)
interp_fn = interp1d(original_indices, coeffs.detach().numpy(),
kind=interpolation_type, fill_value="extrapolate")
return torch.tensor(interp_fn(target_indices), dtype=coeffs.dtype)
class NHITSBlock(nn.Module):
def __init__(self, input_size, hidden_size, num_layers,
backcast_coeffs, forecast_coeffs, interpolation_type='linear'):
super().__init__()
self.mlp = nn.Sequential(
*[nn.Linear(input_size if i == 0 else hidden_size, hidden_size) for i in range(num_layers)],
nn.ReLU() # N-HiTS typically uses GELU, but ReLU is simpler here
)
self.backcast_head = nn.Linear(hidden_size, backcast_coeffs)
self.forecast_head = nn.Linear(hidden_size, forecast_coeffs)
self.interpolation_type = interpolation_type
def forward(self, x_history, history_len, forecast_len):
# x_history is (batch_size, history_len)
x_flat = x_history.view(x_history.shape[0], -1) # Flatten history
hidden_state = self.mlp(x_flat)
backcast_coeffs = self.backcast_head(hidden_state)
forecast_coeffs = self.forecast_head(hidden_state)
# Interpolate coefficients to get actual time series
backcast = interpolate_from_coeffs(backcast_coeffs, history_len, self.interpolation_type)
forecast = interpolate_from_coeffs(forecast_coeffs, forecast_len, self.interpolation_type)
return backcast, forecast
class NHITSModel(nn.Module):
def __init__(self, history_len, forecast_len, num_blocks,
hidden_size=128, num_layers=4,
backcast_coeffs_per_block=[8, 4, 2], forecast_coeffs_per_block=[8, 4, 2],
interpolation_type='linear'):
super().__init__()
self.history_len = history_len
self.forecast_len = forecast_len
self.num_blocks = num_blocks
self.blocks = nn.ModuleList()
for i in range(num_blocks):
block = NHITSBlock(history_len, hidden_size, num_layers,
backcast_coeffs_per_block[i % len(backcast_coeffs_per_block)],
forecast_coeffs_per_block[i % len(forecast_coeffs_per_block)],
interpolation_type)
self.blocks.append(block)
def forward(self, x_history):
# x_history is (batch_size, history_len)
residual_history = x_history
total_forecast = torch.zeros(x_history.shape[0], self.forecast_len, dtype=x_history.dtype)
for block in self.blocks:
backcast, forecast = block(residual_history, self.history_len, self.forecast_len)
residual_history = residual_history - backcast # Residual connection
total_forecast = total_forecast + forecast # Sum forecasts
return total_forecast
