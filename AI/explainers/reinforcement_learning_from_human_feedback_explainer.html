1
Understanding RLHF
▼

What is it? Reinforcement Learning from Human Feedback (RLHF) is a powerful technique used to align large language models (LLMs) with human values, preferences, and instructions. It combines supervised learning with reinforcement learning, using human judgments to train a separate "reward model" that then guides the LLM's behavior.

Analogy: Imagine you're training a highly intelligent but naive robot to write poems. Simply showing it good poems (Supervised Fine-Tuning) might teach it grammar and style, but it won't necessarily know what *you* find "good" or "creative." So, you introduce a "poetry critic" robot (Reward Model) that you train by showing it two poems and telling it which one you prefer. Once trained, this critic robot can rapidly score millions of new poems. Finally, you set your poet robot loose, telling it to write poems that maximize the critic robot's score (Reinforcement Learning), gently nudging it to explore new styles without straying too far from its initial training.

💡 If you remember one thing

RLHF is a three-stage pipeline: (1) Supervised Fine-Tuning (SFT) to get basic instruction-following, (2) Reward Model (RM) Training based on human preferences, and (3) Reinforcement Learning (RL), typically with Proximal Policy Optimization (PPO), using the RM to optimize the LLM.

2
How the RLHF Pipeline Works Internally
▼

Stage 1: Supervised Fine-Tuning (SFT)

The process begins with a pre-trained large language model (LLM) that has learned general language patterns from vast amounts of text. This base model is then fine-tuned on a dataset of high-quality human-written prompt-response pairs, often called "demonstrations." This stage teaches the model to follow instructions, generate coherent and helpful text, and generally behave as a chatbot. The goal is to maximize the likelihood of generating the human-preferred response for a given prompt.

Stage 2: Reward Model (RM) Training

Next, we need a way to quantify human preferences automatically. This is where the Reward Model comes in. It's typically a separate, smaller LLM (or a fine-tuned version of the original LLM) that takes a prompt and a model-generated response as input, and outputs a single scalar "reward" score. To train it:

  1. Generate a diverse set of prompts.
  2. For each prompt, generate several different responses from the SFT model.
  3. Have human annotators rank these responses from best to worst.
  4. Train the Reward Model on these human preference rankings, typically using a binary cross-entropy loss that encourages the model to assign higher scores to preferred responses.

The RM acts as a scalable proxy for human judgment, providing feedback much faster than humans could directly.

Stage 3: Reinforcement Learning (RL) with PPO

Finally, the SFT model is further optimized using reinforcement learning. The SFT model becomes the "policy" (or "agent"), and the trained Reward Model acts as the "environment" providing a reward signal. The goal is to update the policy (the LLM's weights) to maximize the reward given by the RM. Proximal Policy Optimization (PPO) is commonly used for this. The PPO objective typically includes:

  • Maximizing the reward from the RM.
  • A KL divergence penalty to keep the updated policy close to the initial SFT policy, preventing it from drifting too far and generating nonsensical text (reward hacking).

This iterative process allows the LLM to explore new ways of responding and refine its behavior to better align with the learned human preferences.

🔑 Key Property

The Reward Model is the crucial link that translates sparse, slow human feedback into a dense, fast reward signal. Its accuracy and alignment with true human preferences directly determine the quality of the final RLHF-trained LLM.

3
Why It Works — The Math Behind Each Stage
▼

Stage 1: Supervised Fine-Tuning (SFT) Loss

The SFT stage is a standard supervised learning task. Given a dataset \(D_{SFT} = \{(x_i, y_i)\}\) of prompts \(x_i\) and desired responses \(y_i\), the LLM's parameters \(\theta\) are updated to minimize the negative log-likelihood (cross-entropy loss) of generating \(y_i\) given \(x_i\):

$$L_{SFT}(\theta) = -\mathbb{E}_{(x,y)\sim D_{SFT}}[\log P_\theta(y|x)]$$

This makes the model capable of producing high-quality, on-topic responses, but without explicit preference alignment.

Stage 2: Reward Model (RM) Loss

The Reward Model \(\text{RM}_\phi\) (parameterized by \(\phi\)) takes a prompt \(x\) and a response \(y\) and outputs a scalar score \(r_\phi(x,y)\). It's trained on a dataset of human preferences \(D_{pref} = \{(x, y_1, y_2)\}\), where \(y_1\) is preferred over \(y_2\). The loss function is typically a binary cross-entropy over the sigmoid difference of scores:

$$L_{RM}(\phi) = -\mathbb{E}_{(x,y_1,y_2)\sim D_{pref}}[\log(\sigma(r_\phi(x,y_1) - r_\phi(x,y_2)))]$$

Minimizing this loss pushes the score of the preferred response \(r_\phi(x,y_1)\) higher than the score of the dispreferred response \(r_\phi(x,y_2)\).

Stage 3: Reinforcement Learning (RL) with PPO Objective

The SFT model (now denoted \(\pi_\theta\)) is optimized using PPO. The objective function is designed to maximize the reward from the RM while staying close to the original SFT policy \(\pi_{\theta_{ref}}\) (often the SFT model itself) to prevent catastrophic forgetting or reward hacking. The PPO objective is roughly:

$$L_{PPO}(\theta) = \mathbb{E}_{(x,y)\sim \pi_{\theta_{old}}} \left[ \min\left( \frac{\pi_\theta(y|x)}{\pi_{\theta_{old}}(y|x)} A_t, \text{clip}\left(\frac{\pi_\theta(y|x)}{\pi_{\theta_{old}}(y|x)}, 1-\epsilon, 1+\epsilon\right) A_t \right) - \beta D_{KL}( \pi_\theta \| \pi_{\theta_{ref}} ) \right]$$

Here, \(A_t\) is the advantage function derived from the RM's rewards, \(\pi_{\theta_{old}}\) is the policy before the current update, \(\epsilon\) is the PPO clipping parameter, and \(\beta\) controls the strength of the KL divergence penalty against \(\pi_{\theta_{ref}}\).

⚠️ Common Pitfall

A poorly trained or biased Reward Model can lead to "reward hacking," where the LLM learns to generate responses that score highly on the RM but are not genuinely preferred by humans. The KL divergence term is crucial to temper this, but finding the right \(\beta\) is often a delicate balancing act.

Key Takeaways
▼

When to use RLHF:

  • Aligning large language models with complex, nuanced human preferences that are difficult to specify with explicit rules.
  • Improving helpfulness, harmlessness, and honesty (HHH) in conversational AI.
  • When human evaluation is available for ranking responses, but direct reward function engineering is intractable.
  • Scaling human feedback by leveraging a learned reward model.

When NOT to use:

  • For simple tasks where a rule-based system or direct supervised fine-tuning is sufficient.
  • With very small models where the overhead of the multi-stage pipeline and additional data collection might not yield significant benefits.
  • When human feedback is scarce, inconsistent, or biased, as this will directly degrade the quality of the Reward Model.
  • If the computational resources for training multiple large models (SFT, RM, PPO policy, PPO reference) are not available.
💡 Big Picture

RLHF is a cornerstone technique for unlocking the full potential of LLMs, moving them beyond mere text generation to truly understanding and responding to human intent. It represents a powerful paradigm for injecting human values into complex generative AI systems.

Code Trace (PyTorch-like Pseudocode)
▼
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from trl import SFTTrainer, RewardTrainer, PPOTrainer
from datasets import load_dataset
# --- Stage 1: Supervised Fine-Tuning (SFT) ---
base_model = AutoModelForCausalLM.from_pretrained("gpt2")
tokenizer = AutoTokenizer.from_pretrained("gpt2")
sft_dataset = load_dataset("sft_data", split="train") # e.g., prompt-response pairs
sft_trainer = SFTTrainer(
model=base_model,
train_dataset=sft_dataset,
tokenizer=tokenizer,
# ... other training args
)
sft_trainer.train()
sft_model = sft_trainer.model # This is our policy for RL stage
# --- Stage 2: Reward Model (RM) Training ---
reward_model = AutoModelForCausalLM.from_pretrained("gpt2-small") # often smaller model
reward_model.config.num_labels = 1 # Configure for scalar output
preference_dataset = load_dataset("preference_data", split="train") # e.g., (prompt, chosen, rejected) tuples
rm_trainer = RewardTrainer(
model=reward_model,
train_dataset=preference_dataset,
tokenizer=tokenizer,
# ... other training args (e.g., preference loss)
)
rm_trainer.train()
# --- Stage 3: Reinforcement Learning (PPO) ---
ppo_dataset = load_dataset("prompts_for_rl", split="train") # Just prompts for generation
ppo_trainer = PPOTrainer(
model=sft_model, # Policy to optimize
ref_model=sft_model, # Reference model for KL penalty
tokenizer=tokenizer,
reward_model=reward_model, # The trained reward function
# ... other PPO specific args (e.g., learning rate, KL coeff)
)
# PPO training loop (simplified)
for epoch in range(ppo_trainer.config.num_ppo_epochs):
for batch in ppo_dataset:
# Generate responses from current policy
query_tensors = tokenizer(batch["prompt"], return_tensors="pt").input_ids
response_tensors = ppo_trainer.generate(query_tensors, **ppo_trainer.generation_kwargs)
# Get rewards from the Reward Model
texts = [tokenizer.decode(r.squeeze()) for r in response_tensors]
rewards = [reward_model(batch["prompt"][i], texts[i]).item() for i in range(len(texts))]
# Perform PPO update
stats = ppo_trainer.step(query_tensors, response_tensors, rewards)
# ... log stats ...
aligned_model = ppo_trainer.model # The final RLHF-aligned LLM
