1
Understanding GPT-4
▼

What is it? GPT-4 (OpenAI, March 2023) is a large language model that reads two kinds of input — text and images — and writes text output. It also remembers far more of a conversation than its predecessors: while GPT-3 could "see" about 4,000 tokens at once, GPT-4 launched with 8K and 32K context variants, and GPT-4 Turbo later reached 128,000 tokens — roughly a 300-page book in a single prompt.

Analogy: Picture a research assistant who used to work with sticky notes (short memory, text-only) and now works at a desk with an entire filing cabinet open (long memory) plus a pair of eyes (vision). They can flip through hundreds of pages of context and glance at a photograph, chart, or screenshot, and reason about all of it together in one coherent answer.

💡 If you remember one thing

GPT-4 turns an image into a short sequence of "vision tokens" that sit in the exact same embedding space as text tokens, then feeds the combined sequence through one shared decoder-only Transformer. Longer context simply means a bigger sequence the same architecture must attend over — at a cost that grows like \(O(n^2)\) in sequence length \(n\).

How GPT-4 Works Internally
▼

Two upgrades, one architecture

GPT-4 is still an autoregressive, decoder-only Transformer in the GPT lineage — it predicts the next token given everything before it, \(p(x_t \mid x_{

Multimodality: images become tokens

An input image is first resized and split into tiles (OpenAI's public vision pricing describes tiling at 512×512 resolution). A vision encoder — a ViT-style network trained to align image and text representations, in the spirit of CLIP — turns each tile into a small number of patch embeddings. A learned projection layer maps those embeddings into the same dimensionality as the language model's token embeddings. The result: the model doesn't have a "vision module" bolted on the side — image content becomes a run of extra vectors inserted directly into the token sequence, indistinguishable in format from word tokens once fusion happens.

Longer context: same attention, bigger buffer

Self-attention lets every token look at every other token in the sequence. Making the window bigger doesn't require a new mechanism — it requires the positional scheme and memory budget to tolerate a larger \(n\). Techniques the field uses for this (rotary position embeddings with interpolation, ALiBi, sparse/local attention patterns, KV-cache compression) let a Transformer trained at one length generalize, or be fine-tuned, to run efficiently at much greater lengths — which is how the same architecture serves 8K, 32K, and 128K variants.

🔑 Key Property

Multimodality and long context are orthogonal upgrades to the input pipeline, not to the core Transformer. Vision tokens increase the "alphabet" fed into the model; a longer window increases how many symbols of that alphabet fit before earlier ones are dropped.

3
Why It Works — The Math
▼

Vision tokenization cost

For "high detail" image understanding, OpenAI's documented scheme tiles the image into \(512\times512\) blocks. If an image has width \(w\) and height \(h\) (already resized so the short side ≤ 768px and long side ≤ 2048px), the number of tiles is:

$$\text{tiles} = \left\lceil \frac{w}{512} \right\rceil \times \left\lceil \frac{h}{512} \right\rceil, \qquad \text{vision\_tokens} = 85 + 170 \cdot \text{tiles}$$

The constant 85 covers a low-resolution overview tile; each additional 512px tile costs 170 tokens. This is exactly the formula the interactive walkthrough below computes live as you resize the image.

Self-attention cost in sequence length

For a sequence of length \(n\) and hidden size \(d\), scaled dot-product attention computes:

$$\text{Attention}(Q,K,V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Forming \(QK^\top\) costs \(O(n^2 d)\) time and \(O(n^2)\) memory (one score per token pair, per head). Quadrupling the context window (say 8K → 32K) is not 4× the compute — it is roughly \(4^2 = 16\times\) the raw attention cost, which is why long-context inference leans heavily on engineering tricks (KV-cache reuse, flash-attention style fused kernels, sparse/windowed attention) rather than brute-force scaling alone.

⚠️ Common Pitfall

"128K context" does not mean the model uses all 128K tokens equally well. Empirically, models exhibit a "lost in the middle" effect — recall is strongest for content near the start and end of a long prompt and weaker for content buried in the middle, even though attention is mathematically capable of reaching it.

Key Takeaways
▼

When GPT-4's multimodal + long-context design shines:

  • Reasoning over screenshots, charts, diagrams, or scanned documents alongside text instructions
  • Summarizing or answering questions about very long documents, codebases, or transcripts in one pass
  • Multi-document, multi-turn tasks where earlier context (retrieved data, prior turns) must stay "in view"

Where it still struggles:

  • Fine-grained spatial reasoning in images (precise counting, exact pixel coordinates)
  • Reliable recall from the middle of very long contexts ("lost in the middle")
  • Latency and cost scale with both tokens used and image resolution — bigger isn't free
💡 Lineage

GPT-3 (4K, text-only) → GPT-3.5 (4K–16K, text-only) → GPT-4 (8K/32K, +vision) → GPT-4 Turbo (128K, +vision) → GPT-4o (natively multimodal, unified encoder/decoder for text, image, audio). Each generation relaxes an earlier bottleneck without changing the core next-token-prediction objective.

Code Trace

import math
# --- Vision token cost (OpenAI GPT-4V "high detail" scheme) ---
def vision_tokens(width, height, tile=512):
tiles_w = math.ceil(width / tile)
tiles_h = math.ceil(height / tile)
tiles = tiles_w * tiles_h
return 85 + 170 * tiles # base overview + per-tile cost
# --- Fuse text + vision tokens into one sequence ---
def build_sequence(text_tokens, image_w, image_h, ctx_window):
v_tokens = vision_tokens(image_w, image_h)
total = text_tokens + v_tokens
used_pct = 100 * total / ctx_window
overflow = max(0, total - ctx_window)
return total, used_pct, overflow
# --- Quadratic attention cost relative to an 8K baseline ---
def relative_attention_cost(n, baseline=8192):
return (n / baseline) ** 2
seq_len, pct, overflow = build_sequence(1500, 512, 512, 8192)
print(f"tokens used: {seq_len} ({pct:.1f}% of window)")
print(f"cost @128K vs 8K: {relative_attention_cost(128000):.1f}x")
