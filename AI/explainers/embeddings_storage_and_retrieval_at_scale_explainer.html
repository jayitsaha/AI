Understanding Embeddings & The Scale Challenge
▼

What are Embeddings? In modern AI, data like text, images, or audio is often transformed into numerical vectors called "embeddings." These vectors capture the semantic meaning of the data: items with similar meanings or properties are mapped to vectors that are "close" to each other in a high-dimensional space. For example, the embedding for "king" might be close to "queen" but far from "apple."

Why Store & Retrieve Them? The ability to quickly find items with similar embeddings is fundamental to many AI applications:

  • Semantic Search: Find documents or products semantically related to a query, even if keywords don't match.
  • Recommendation Systems: Recommend items similar to what a user liked.
  • Retrieval-Augmented Generation (RAG): Ground large language models (LLMs) with relevant external knowledge.
  • Anomaly Detection: Identify data points far from typical clusters.

The Scale Challenge: The problem arises when you have millions or billions of items (N) and each embedding is high-dimensional (D, e.g., 768 or 1536 for common LLMs). A naive "brute-force" approach would calculate the distance (or similarity) between your query embedding and *every single item* in your database. This takes \(O(N \cdot D)\) time, which quickly becomes impossibly slow for large N, even with optimized hardware.

💡 If you remember one thing

Embeddings represent meaning as vectors. Finding similar meanings means finding "nearest neighbors" in vector space. At scale, brute-force search is too slow, necessitating Approximate Nearest Neighbor (ANN) algorithms that trade a little accuracy for massive speedups.

How Approximate Nearest Neighbor (ANN) Works
▼

The Trade-off: Speed vs. Accuracy

ANN algorithms aim to find *approximately* the nearest neighbors, rather than guaranteeing the absolute closest ones. This small compromise allows for dramatic speed improvements, often reducing search time from linear \(O(N \cdot D)\) to logarithmic \(O(\log N \cdot D)\) or sub-linear. They do this by building a specialized data structure (an "index") over the embeddings that allows for faster traversal or pruning of the search space.

Categories of ANN Algorithms

While many techniques exist, they generally fall into a few categories:

  • Tree-based: Partition the space hierarchically (e.g., KD-trees, Annoy). Effective in lower dimensions, but struggle with the "curse of dimensionality" (data becomes sparse, tree depth increases) in high dimensions.
  • Quantization-based: Compress vectors into shorter codes, then search in the compressed space (e.g., Product Quantization, Scalar Quantization). Reduces memory and allows faster distance calculations.
  • Hashing-based: Map similar items to the same "bucket" using hash functions (e.g., Locality Sensitive Hashing - LSH).
  • Graph-based: Build a graph where nodes are embeddings and edges connect neighbors. Search by traversing the graph (e.g., Hierarchical Navigable Small World - HNSW).

Focus: Hierarchical Navigable Small World (HNSW) Graphs

HNSW is a state-of-the-art graph-based ANN algorithm. It constructs a multi-layer graph reminiscent of a skip list:

  1. Base Layer (Layer 0): Contains all data points, with dense local connections.
  2. Higher Layers: Contain a sparse subset of points from the layer below, with longer-range connections. Points are added to higher layers probabilistically.
  3. Greedy Search: To query, HNSW starts at a random entry point in the topmost layer. It then greedily traverses the graph, always moving to the neighbor closest to the query vector.
  4. Layer Traversal: Once it can no longer improve its distance to the query in the current layer, it "drops down" to the next lower layer, continuing the greedy search from the best candidate found so far. This process repeats until the base layer is reached.
  5. Final Candidate Search: In the base layer, a more exhaustive (but still approximate) search is performed around the final candidate from the layer traversal to find the \(k\) nearest neighbors.
🔑 Key Property

ANN algorithms build an index that enables efficient, approximate search. HNSW excels by combining a multi-layer graph (for fast long-range jumps) with greedy traversal, offering excellent recall at high speeds, making it a popular choice for vector databases.

Why It Works — The Math Behind HNSW
▼

Distance Metrics

The core of similarity search is a distance (or similarity) function. Common choices include:

  • Euclidean Distance (L2): Measures the straight-line distance between two points. Preferred for general-purpose similarity. $$d_{\text{Euclidean}}(v, q) = \sqrt{\sum_{i=1}^D (v_i - q_i)^2}$$
  • Cosine Similarity: Measures the angle between two vectors. Often used for text embeddings where vector magnitude might not be as important as direction. $$\text{sim}_{\text{Cosine}}(v, q) = \frac{v \cdot q}{\|v\|_2 \|q\|_2}$$ Note: Minimizing Euclidean distance on normalized vectors is equivalent to maximizing cosine similarity.

HNSW Index Construction (Simplified)

HNSW builds a graph incrementally. Each new element \(p\) is inserted by:

  1. Determining Max Layer \(L_p\): A random integer \(l\) is chosen from a geometric distribution \(P(l) \propto e^{-\lambda l}\). This means most elements are only in the base layer, fewer in layer 1, even fewer in layer 2, and so on. This creates the hierarchical structure.
  2. Finding Neighbors in Layers \(L_p\) down to 0: Starting from the top layer of the current graph (or \(L_p\), if \(L_p\) is lower), a greedy search is performed to find \(efConstruction\) nearest neighbors to \(p\). These are candidate neighbors.
  3. Connecting Neighbors: For each layer \(l \le L_p\), \(p\) is connected to up to \(M\) (a parameter, e.g., 16) of its closest neighbors found in step 2. The connections are bidirectional.

This probabilistic layer assignment and greedy neighbor selection ensures that higher layers have "express lanes" for long-range jumps, while lower layers provide fine-grained local connectivity, creating a "small-world" graph where any two nodes are connected by a short path.

HNSW Querying: Greedy Search with Bounded Exploration

To find the \(k\) nearest neighbors for a query \(q\):

  1. Entry Point: Start from a fixed entry node \(e\) in the topmost layer \(L_{max}\) of the graph.
  2. Layer Traversal (Top-Down): For each layer \(l\) from \(L_{max}\) down to 1:
    • Maintain a dynamic list of \(efSearch\) (a parameter) best candidates found so far.
    • Perform a greedy search, starting from the best candidate from the layer above. Explore its neighbors and add closer ones to the candidate list. This continues until no better candidates are found or a maximum number of hops is reached.
    • Pass the best candidate(s) to the layer below.
  3. Base Layer Search (Layer 0): Perform a more extensive greedy search in the base layer, starting from the best candidate from layer 1. This time, explore up to \(efSearch\) neighbors, keeping track of the \(k\) closest.

The parameter \(efSearch\) controls the trade-off: higher \(efSearch\) means more nodes are visited, leading to better recall (more accurate results) but slower queries. $$\text{Search Cost} \approx O(\log N \cdot D \cdot \text{efSearch})$$ The logarithmic dependence on \(N\) comes from the hierarchical structure and greedy traversal, which effectively prunes large parts of the search space.

➕ Math Insight

The expected number of layers for a node is \(\log_{1/e^{-\lambda}} N\). This logarithmic scaling, combined with the greedy search in each layer, is what gives HNSW its efficiency. The \(M\) connections per node provide robustness against local minima during greedy search.

Key Takeaways
▼

When to use Embeddings Storage & Retrieval at Scale:

  • Large Datasets: When you have millions or billions of items (documents, images, users) to search through.
  • Semantic Search: When keyword-based search is insufficient and you need to find items based on their meaning or conceptual similarity.
  • Real-time Applications: For applications like recommendation engines, RAG systems, or real-time anomaly detection where latency is critical.
  • High Dimensionality: When embeddings are typically 100-2000 dimensions, making traditional indexing methods inefficient.

Choosing an ANN Algorithm:

  • HNSW: Generally a strong default, offering excellent recall and speed. Widely adopted in vector databases.
  • Product Quantization (PQ): Good for extreme memory compression, but can have lower recall than HNSW. Often combined with other methods.
  • Locality Sensitive Hashing (LSH): Simple to implement, but typically has lower recall and requires more hash tables for good performance.
  • Annoy: Tree-based, good for balanced recall/speed, often used for smaller-to-medium datasets.

When NOT to use ANN (or when brute-force is fine):

  • Small Datasets: If N is small (e.g., < 10,000), brute-force search might be fast enough and guarantees 100% recall.
  • Exact Nearest Neighbor Required: If you absolutely need the mathematically exact nearest neighbors, and a slight approximation is unacceptable (rare in ML applications).
  • Extremely Low Latency, Small N: For very small N and extremely low latency, sometimes a GPU-accelerated brute-force can be faster than loading/querying an index.
💡 Vector Databases

Specialized "vector databases" (like Pinecone, Weaviate, Milvus, Qdrant) are built to manage and query embeddings at scale. They abstract away the complexities of ANN index management, distributed storage, and real-time updates, making it easier to integrate vector search into applications.

Code Trace: HNSWLib for Python
▼
import hnswlib
import numpy as np
# 1. Generate some random 128-dim embeddings
num_elements = 100_000
dim = 128
data = np.float32(np.random.random((num_elements, dim)))
# 2. Initialize HNSW index
# 'l2' for Euclidean distance, 'ip' for Cosine similarity (inner product)
p = hnswlib.Index(space='l2', dim=dim)
# 3. Build the index
# M: number of bidirectional links created for each element
# ef_construction: size of the dynamic list during index construction
p.init_index(max_elements=num_elements, ef_construction=200, M=16)
p.add_items(data)
# 4. Define a query vector
query_vector = np.float32(np.random.random((1, dim)))
# 5. Query the index for k nearest neighbors
k = 5
# ef: size of the dynamic list during search (efSearch)
p.set_ef(50) # Set efSearch parameter
labels, distances = p.knn_query(query_vector, k=k)
print(f"Nearest neighbor labels: {labels}")
print(f"Distances: {distances}")
