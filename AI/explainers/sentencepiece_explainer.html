1
Understanding SentencePiece
▼

What is it? SentencePiece is a tokenizer that converts raw text into subword units without relying on language-specific rules like whitespace splitting. Unlike traditional tokenizers that first split on spaces and then break words into pieces, SentencePiece treats the entire input as a raw byte/character stream, making it truly language-agnostic.

Analogy: Imagine translating a book written in a language you have never seen. A traditional approach would look for spaces between words first. But what if the language has no spaces, like Chinese or Japanese? SentencePiece is like a universal code-breaker: it looks at the raw stream of characters and discovers the most efficient set of "building blocks" to represent any text, regardless of language.

Key Insight

SentencePiece replaces whitespace with a special meta-symbol ▁ (Unicode U+2581) and treats the input as a sequence of Unicode characters. This means tokenization is reversible and lossless -- you can always reconstruct the exact original text from the token sequence, including whitespace.

2
Pre-Tokenized vs. Raw-Text Approach
▼

The Problem with Pre-Tokenization

Traditional subword methods (WordPiece, BPE in GPT-2) assume input is already split into words by spaces. This creates three critical failures: (1) Languages like Chinese, Japanese, and Thai have no word-delimiting spaces. (2) Even in English, treating space as a hard boundary prevents learning cross-word patterns and forces language-specific rules. (3) The tokenization becomes irreversible -- "New York" tokenized as ["New", "York"] loses the information about the original spacing.

SentencePiece's Solution

SentencePiece normalizes the input by prepending ▁ before every word (replacing spaces), then operates on the full character sequence. The input "Hello World" becomes "▁Hello▁World". Now the tokenizer can freely segment across what were formerly word boundaries, and the original text is perfectly recoverable by joining tokens and replacing leading ▁ with spaces.

Common Misconception

SentencePiece is not a single algorithm -- it is a framework that supports multiple subword models: Unigram Language Model (default), BPE, char, and word. The Unigram model is unique to SentencePiece and uses a fundamentally different training approach than BPE's greedy merge strategy.

3
The Unigram Language Model
▼

The Unigram model takes a top-down approach, the opposite of BPE. Instead of starting with individual characters and merging upward, it starts with a very large vocabulary of candidate subword pieces and iteratively prunes the least useful ones.

Training via EM (Expectation-Maximization)

Given a training corpus, the Unigram model defines the probability of a sentence \(X = (x_1, x_2, \ldots, x_n)\) as the product of subword probabilities under a unigram assumption:

$$P(X) = \prod_{i=1}^{n} p(x_i), \quad \text{where } \sum_{x \in \mathcal{V}} p(x) = 1$$

E-step: For each sentence in the corpus, find the best segmentation using the Viterbi algorithm (or compute expected frequencies over all possible segmentations using the forward-backward algorithm). M-step: Re-estimate subword probabilities from the expected counts. After convergence, compute the loss reduction for removing each piece, and prune a fixed percentage (e.g., 20%) of the lowest-impact pieces. Repeat until the target vocabulary size is reached.

Viterbi Segmentation

For a character sequence \(c_1 c_2 \ldots c_T\), the best segmentation maximizes: $$x^* = \underset{x \in S(X)}{\operatorname{argmax}} \sum_{i=1}^{|x|} \log p(x_i)$$ This is solved in \(O(T \cdot L)\) time where \(L\) is the max piece length, using dynamic programming identical to the shortest-path algorithm.

4
Handling CJK & Unknown Characters
▼

Because SentencePiece operates on raw Unicode, it naturally handles CJK (Chinese, Japanese, Korean) characters where there are no spaces between words. The characters 東京 ("Tokyo" in Japanese) are treated as individual characters that the Unigram model can group into subwords based purely on corpus frequency, with no need for a word segmenter like MeCab.

For truly unknown characters (e.g., rare emoji, obscure scripts), SentencePiece falls back to byte-level encoding: each unknown byte is mapped to a special token like <0xE2>. This guarantees that any input can be tokenized -- there is no "out of vocabulary" failure. This byte-fallback mechanism is what makes SentencePiece fully lossless and language-agnostic.

Design Decision

Why not just use character-level tokenization? Because it produces very long sequences (a 100-word paragraph might become 500+ character tokens), making attention \(O(n^2)\) prohibitively expensive. Subword tokenization finds the sweet spot: short sequences that preserve semantic units. SentencePiece's Unigram model is information-theoretically optimal -- it minimizes the total encoding length of the corpus.

5
Key Takeaways
▼

Use SentencePiece when: You need a single tokenizer for multilingual models (mBERT, XLM-R, T5, LLaMA all use it), when your data includes CJK or non-space-delimited languages, or when you require deterministic and reversible tokenization.

Key advantages over BPE: (1) Language-agnostic -- no pre-tokenization rules. (2) Supports regularization via subword sampling. (3) Exact lossless reconstruction. (4) The Unigram model enables probabilistic segmentation, useful for data augmentation.

Key models using SentencePiece: T5, ALBERT, XLNet, mBART, LLaMA, Gemma, Mistral -- essentially most modern multilingual and monolingual LLMs.
