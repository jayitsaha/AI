1
Understanding GPT-3
▼

What is it? GPT-3 (Brown et al., 2020) is a 175-billion-parameter autoregressive Transformer trained to predict the next token on internet-scale text. The surprise wasn't the architecture — it's almost identical to GPT-2 — it was a capability: at this scale, GPT-3 can perform a new task after seeing just a handful of examples typed into its prompt, with zero gradient updates. This is called in-context learning (ICL).

Analogy: Imagine handing a extremely well-read colleague a sticky note with three example translations, then asking them to translate a fourth sentence. They don't go back to school — they just infer the pattern from the note and apply it on the spot. That "sticky note" is the prompt; the "colleague" is the frozen network doing a single forward pass.

Zero / one / few-shot: GPT-3 is evaluated three ways: zero-shot (only a natural-language task description), one-shot (description + 1 example), and few-shot (description + K examples, K up to the context window). No weights change between these — only the text in the context window changes.

💡 If you remember one thing

In-context learning is not learning in the gradient-descent sense — it is pattern completion inside a single forward pass. The examples in the prompt act as conditioning context that steers the next-token distribution, and this steering ability emerges reliably only once the model is large enough.

2
How In-Context Learning Works Internally
▼

Architecture: Nothing New, On Purpose

GPT-3 uses the same decoder-only Transformer as GPT-2, with alternating dense and locally-banded sparse attention layers (à la Sparse Transformer), just scaled up: 96 layers, \(d_{model}=12288\), 96 attention heads, context window of 2048 tokens, trained on ~300B tokens. The architecture choice was deliberately conservative — the paper's entire point was that scale alone, not architectural cleverness, drives the emergence of few-shot ability.

What Actually Happens at Inference

A prompt is built as: [task description] [example 1] [example 2] ... [example K] [query]. This whole string is tokenized (via byte-pair encoding) into one sequence and fed through the frozen network in a single forward pass. Self-attention lets the query position attend back to every demonstration — the model can literally look at the input/output pairs and copy the transformation pattern into its prediction for the new query. The output is a probability distribution over the next token(s); greedy or sampled decoding produces the answer.

Design Decision: Why No Fine-Tuning?

Fine-tuning needs a fresh gradient update per task and a labeled dataset, risks overfitting to narrow benchmark distributions, and cannot generalize outside its training task. By keeping weights frozen and moving all the "adaptation" into the prompt, GPT-3 trades a small amount of per-task accuracy (it typically trails fine-tuned SOTA) for enormous generality — one checkpoint performs translation, arithmetic, Q&A, and code completion just by changing what's typed in.

🔑 Key Property

In-context learning ability is an emergent property of scale: small models barely benefit from extra demonstrations, but as parameter count grows, the gap between zero-shot and few-shot accuracy widens sharply — the model gets better at "reading the pattern," not just at raw next-token prediction.

3
Why It Works — Scaling Laws & The Math
▼

Neural Scaling Laws (Kaplan et al., 2020)

GPT-3's design was guided by an empirical finding: cross-entropy test loss \(L\) follows a smooth power law in non-embedding parameter count \(N\), holding data and compute large enough not to bottleneck:

$$L(N) = \left(\frac{N_c}{N}\right)^{\alpha_N}, \qquad \alpha_N \approx 0.076,\ \ N_c \approx 8.8\times10^{13}$$

Similar power laws hold for dataset size \(D\) and training compute \(C\). Crucially, the curve is smooth across seven orders of magnitude of \(N\) — no plateau, no "elbow." That smoothness is what let OpenAI extrapolate: if loss keeps dropping predictably, capabilities riding on top of that loss (like ICL) should keep improving too.

From Loss to In-Context Accuracy

There's no closed-form formula in the paper mapping \(N\) directly to few-shot accuracy — but the qualitative relationship is robust and is what the visualization below reproduces: define a normalized "model quality" \(q(N) \in [0,1]\) from the loss curve,

$$q(N) = \frac{L(N_{\text{small}}) - L(N)}{L(N_{\text{small}}) - L(N_{175B})}$$

Accuracy as a function of the number of shots \(K\) then rises from a zero-shot floor \(A_0(N)\) toward a few-shot ceiling \(A_{\max}(N)\), saturating faster for stronger models (smaller time-constant \(\tau\)):

$$A(K,N) = A_0(N) + \big(A_{\max}(N)-A_0(N)\big)\left(1 - e^{-K/\tau(N)}\right)$$

Both \(A_0\), \(A_{\max}\) increase with \(q(N)\) and \(\tau\) shrinks with \(q(N)\) — larger models start higher AND climb faster per example. This is exactly the fan-shaped family of curves in Figure 1.2 of the GPT-3 paper.

⚠️ Common Pitfall

Don't confuse the scaling law (a statement about pretraining loss vs. compute/params/data) with a guarantee about downstream task accuracy. Loss improves smoothly and predictably; specific capabilities can appear more suddenly once a loss threshold is crossed — this is the seed of what later work called "emergent abilities."

Key Takeaways
▼

When few-shot prompting shines:

  • Rapid prototyping across many tasks with one frozen checkpoint — no per-task fine-tuning pipeline
  • Low-data regimes — you have 5-50 examples, not 5,000
  • Tasks where the "instructions" are easy to phrase in natural language

When it falls short:

  • Tasks requiring precise, high-volume supervision — fine-tuning still wins on accuracy
  • Small models — the ICL curve is nearly flat below a few hundred million parameters
  • Context-length-limited tasks — you can't fit enough demonstrations for very long inputs
💡 The Big Picture

GPT-3's core claim is a bitter-lesson style result: scaling a vanilla Transformer with more data and compute — without new architecture or task-specific engineering — produces qualitatively new behavior (in-context learning) that smaller models simply do not exhibit. This motivated the entire subsequent race to scale (PaLM, Chinchilla, GPT-4) and the shift toward prompting as the primary interface to language models.

Code Trace

import numpy as np
# Kaplan et al. 2020 power-law loss scaling in params N
Nc, alpha_N = 8.8e13, 0.076
def loss(N):
return (Nc / N) ** alpha_N
# GPT-3 model family (non-embedding params)
sizes = [125e6, 350e6, 760e6, 1.3e9, 2.7e9, 6.7e9, 13e9, 175e9]
losses = [loss(N) for N in sizes]
# normalized model quality q(N) in [0, 1]
def quality(N):
return (loss(sizes[0]) - loss(N)) / (loss(sizes[0]) - loss(sizes[-1]))
# illustrative few-shot accuracy curve A(K, N)
def accuracy(K, N):
q = quality(N)
a0, amax = 0.05 + 0.25 * q, 0.30 + 0.65 * q
tau = 8.0 - 6.0 * q
return a0 + (amax - a0) * (1 - np.exp(-K / tau))
# Prompt construction: no gradient step, ever
def build_prompt(task_desc, examples, query):
ctx = task_desc + "\n"
for x, y in examples:
ctx += f"{x} -> {y}\n"
ctx += f"{query} ->"
return ctx # fed through ONE frozen forward pass
print(f"175B, K=8 shots -> accuracy ~ {accuracy(8, sizes[-1]):.2f}")
print(f"125M, K=8 shots -> accuracy ~ {accuracy(8, sizes[0]):.2f}")
