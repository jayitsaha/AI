1
Understanding Neural Module Networks
▼

What is it? Most VQA systems in 2016 glued a CNN (image) to an LSTM (question) and fed both into one monolithic classifier: one giant network for every possible question. Neural Module Networks (NMN) instead ask: what if a question already tells you the shape of the computation it needs? “What color is the cube left of the sphere?” is really a small program — find the sphere, look to its left, find a cube there, read off its color. NMN parses the question into exactly that program, and assembles a bespoke neural network out of small, reusable, jointly-trained pieces called modules.

Analogy: Think of the modules as a tiny standard library — find, relate, and, describe — the way Unix pipes compose grep, sort, and uniq differently for every command line. The programs (pipelines) are new for every question, but the tools themselves are shared, reused, and never rewritten.

💡 If you remember one thing

NMN separates what to compute (a question-specific layout, i.e. a program) from how to compute it (a small, fixed library of neural modules whose weights are shared across every question that uses them). Composability lets a handful of modules cover a combinatorial space of questions.

2
How NMN Works Internally
▼

From Question to Program (the Layout)

A question is first turned into a layout: a tree whose nodes are module types and whose leaves are grounded on words from the question. The original paper used an off-the-shelf dependency parser plus hand-written rules to turn parse fragments into module calls; the layout for our running example is \(\text{Describe}_{color}(\text{And}(\text{Relate}_{left\_of}(\text{Find}[sphere]), \text{Find}[cube]))\).

The Module Library

  • Find[c] — convolves image features with a concept-specific kernel and outputs a soft attention map over the image (“where is the sphere?”).
  • Relate[r] / Transform — takes an attention map and re-projects it through a relation-specific kernel (“shift attention to whatever is left of the currently attended region”).
  • And / Filter — combines two attention maps (elementwise product or min) to enforce a conjunction (“a cube AND left of the sphere”).
  • Describe / Measure — reads an attention map back against the image features and classifies an answer (color, count, yes/no).
  • Compare — a later addition: contrasts two attended regions or two sub-answers (“is the cube the same color as the sphere?”).

Assembly: One Library, Many Networks

Given a layout, the system instantiates one object per node — cloning the module class but sharing its learned parameters — and wires them exactly as the tree specifies. Two different questions that both mention “Find[sphere]” reuse the identical convolutional weights; only the graph topology differs. The assembled graph is then just an ordinary feed-forward network, differentiable end to end, trained jointly with a small handful of question-independent parameters per module type.

🔑 Key Property

Because the same Find module instance is reused across thousands of distinct question layouts, gradient updates from every question that mentions “cube” sharpen the one shared cube-detector — this is what lets NMN generalize to word combinations never seen at training time.

3
Why It Works — The Math
▼

Attention as Softmax over Match Scores

Find[c] computes, for every spatial location \(i\) of the image feature map, a match score \(s_i = \langle \phi(i), w_c\rangle\) between the local feature \(\phi(i)\) and a concept vector \(w_c\), then turns scores into a probability distribution:

$$a_i = \frac{\exp(s_i/\tau)}{\sum_j \exp(s_j/\tau)}$$

This is attention — the same softmax-normalized weighting used throughout deep learning, just applied over image locations conditioned on a word instead of over tokens conditioned on a query.

Relate as a Learned Convolution over Attention

Relater treats the incoming attention map as an image itself and convolves it with a relation-specific kernel \(k_r\), redistributing mass according to the geometry of \(r\) (e.g. shifting weight toward cells whose column index is smaller, for “left of”):

$$b_j \;\propto\; \sum_i a_i \cdot k_r(i,j), \qquad b = b / \textstyle\sum_j b_j$$

Composition and Readout

And composes two attentions by an elementwise product followed by renormalization — a soft conjunction — and Describe contracts the final attention against the raw image features into a summary vector, classified by a small softmax head:

$$c_i \propto a_i\,b_i \qquad\qquad \hat{y} = \operatorname{softmax}\!\Big(W\sum_i c_i\,\phi(i)\Big)$$

The whole assembled graph — Find → Relate → And → Describe — is one differentiable computation; a single cross-entropy loss on the answer backpropagates through every module simultaneously.

⚠️ Common Pitfall

The original NMN layout comes from an external, non-differentiable parser — errors there cannot be corrected by gradient descent, and the discrete choice of module types is not learned jointly with their weights. This motivated end-to-end successors: N2NMN (Hu et al., 2017) learns the layout with a seq2seq policy trained via REINFORCE (or a Gumbel-softmax relaxation) so layout and module parameters are optimized together, and Stack-NMN (Hu et al., 2018) removes discrete layout decisions entirely, executing a continuous, differentiable soft mixture over module types at each timestep using a neural stack for compositional memory.

Key Takeaways
▼

When NMN-style compositionality shines:

  • Questions with rich compositional structure (relations, negation, counting, comparison) drawn from a large combinatorial space, as in CLEVR
  • Settings where systematic generalization matters — answering novel combinations of familiar concepts (e.g. training on “red cube left of sphere” and testing on “yellow cylinder left of cube”)
  • Applications wanting an inspectable reasoning trace: each module’s attention map is a debuggable, visualizable intermediate step

Limitations that motivated later work:

  • Reliance on an external parser (fixed, brittle grammar) → fixed by N2NMN’s learned layout policy
  • Discrete layout choice breaks end-to-end gradients → fixed by N2NMN’s REINFORCE / Gumbel-softmax, and fully removed by Stack-NMN’s soft, differentiable module mixture with a neural stack
  • Hand-designed module inventory limits expressiveness compared to a large pretrained monolithic model on huge, non-compositional data (e.g. real-world VQA photographs)
💡 Lineage

NMN (2016, external parser, hand-built modules) → N2NMN (2017, learned layout policy, still discrete) → Stack-NMN (2018, fully differentiable soft layout + neural stack). Each generation removes one hand-engineered, non-differentiable piece while keeping the core idea: small reusable modules, question-specific wiring.

import torch, torch.nn as nn
class FindModule(nn.Module):
def forward(self, img_feats, concept_vec):
scores = conv1x1(img_feats, concept_vec) # match score per cell
return softmax(scores / tau) # attention map
class RelateModule(nn.Module):
def forward(self, attn, kernel):
return normalize(conv2d(attn, kernel)) # e.g. "left_of" kernel
class AndModule(nn.Module):
def forward(self, a, b):
return normalize(a * b) # elementwise AND
class DescribeModule(nn.Module):
def forward(self, attn, img_feats):
summary = (attn[..., None] * img_feats).sum((0, 1))
return classifier(summary) # softmax over answers
def build_network(layout):
# layout, e.g. Describe(And(Relate['left_of'](Find['sphere']), Find['cube']))
modules = {'find': FindModule(), 'relate': RelateModule(),
'and': AndModule(), 'describe': DescribeModule()}
return assemble(layout, modules) # clone + wire per question
net = build_network(parse(question)) # parser or learned layout policy
answer = net(image_features); loss = xent(answer, gold); loss.backward()
