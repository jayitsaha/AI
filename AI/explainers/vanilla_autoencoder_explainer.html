Understanding Autoencoders
▼

What is it? An autoencoder is a neural network trained to copy its input to its output, but with a twist: it must first compress the data through a narrow "bottleneck" layer. The network has two halves — an encoder that compresses the input into a compact representation, and a decoder that reconstructs the original from that compressed form. The bottleneck forces the network to learn only the most essential features.

Analogy: Imagine summarizing a 300-page novel into a 10-word telegram, then asking someone to reconstruct the full story from just those 10 words. The encoder writes the telegram (compression), the bottleneck is the telegram's word limit (information constraint), and the decoder attempts the reconstruction. The better the summary captures the book's essence, the better the reconstruction.

If you remember one thing

An autoencoder learns a compressed representation \(z = f_\theta(x)\) by minimizing reconstruction error: $$\mathcal{L} = \|x - g_\phi(f_\theta(x))\|^2$$ where \(f_\theta\) is the encoder, \(g_\phi\) is the decoder, and the bottleneck dimension controls how much information survives.

Architecture & Internal Workings
▼

Three-Part Architecture

The vanilla autoencoder consists of three components stacked sequentially:

Encoder \(f_\theta\): Maps the input \(x \in \mathbb{R}^n\) to a latent vector \(z \in \mathbb{R}^d\) where \(d \ll n\). Each layer applies an affine transformation followed by a nonlinearity: \(h = \sigma(Wx + b)\). The encoder progressively reduces dimensionality, forcing the network to discard irrelevant details and retain only the most informative features.

Bottleneck: The layer with the fewest neurons, \(z \in \mathbb{R}^d\). This is the learned compressed representation. If \(d\) is too large, the network can trivially copy the input (identity mapping); if too small, too much information is lost. The right bottleneck size depends on the intrinsic dimensionality of the data.

Decoder \(g_\phi\): Maps the latent code back to input space: \(\hat{x} = g_\phi(z) \in \mathbb{R}^n\). It mirrors the encoder's architecture in reverse, progressively expanding dimensions. The final activation (e.g., sigmoid for [0,1] data) constrains the output range to match the input domain.

Key Design Decision

Why symmetric architecture? Tying the decoder to mirror the encoder isn't strictly required, but it reduces hyperparameters and, when combined with tied weights (\(W_{dec} = W_{enc}^\top\)), acts as a regularizer. The symmetry also ensures the decoder has sufficient capacity to invert the encoder's transformation.

The Math Behind It
▼

Forward Pass

For a single-hidden-layer autoencoder with input \(x \in \mathbb{R}^n\):

Encoding: The hidden representation is computed as:

$$z = \sigma(W_1 x + b_1), \quad W_1 \in \mathbb{R}^{d \times n},\; b_1 \in \mathbb{R}^d$$

Decoding: The reconstruction is:

$$\hat{x} = \sigma(W_2 z + b_2), \quad W_2 \in \mathbb{R}^{n \times d},\; b_2 \in \mathbb{R}^n$$

Loss Function

The network is trained to minimize Mean Squared Error (MSE) between input and reconstruction:

$$\mathcal{L}_{MSE} = \frac{1}{n}\sum_{i=1}^{n}(x_i - \hat{x}_i)^2 = \frac{1}{n}\|x - \hat{x}\|_2^2$$

For binary inputs (e.g., pixel intensities normalized to [0,1]), Binary Cross-Entropy is often preferred:

$$\mathcal{L}_{BCE} = -\frac{1}{n}\sum_{i=1}^{n}\left[x_i \log(\hat{x}_i) + (1-x_i)\log(1-\hat{x}_i)\right]$$
Common Misconception

A linear autoencoder (no activation functions) learns the same subspace as PCA. The encoder weights span the principal component subspace. Nonlinear activations are what give autoencoders their power to capture nonlinear manifolds that PCA misses entirely.

PyTorch From Scratch

import torch
import torch.nn as nn
class Autoencoder(nn.Module):
def __init__(self, input_dim, latent_dim):
super().__init__()
# Encoder: compress input_dim -> latent_dim
self.encoder = nn.Sequential(
nn.Linear(input_dim, 128),
nn.ReLU(),
nn.Linear(128, latent_dim),
nn.ReLU()
)
# Decoder: reconstruct latent_dim -> input_dim
self.decoder = nn.Sequential(
nn.Linear(latent_dim, 128),
nn.ReLU(),
nn.Linear(128, input_dim),
nn.Sigmoid() # output in [0,1]
)
def forward(self, x):
z = self.encoder(x) # latent code
x_hat = self.decoder(z) # reconstruction
return x_hat, z
# Training loop

optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

optimizer.zero_grad()
loss.backward()
optimizer.step()

Key Takeaways & When To Use
▼

Use autoencoders for: dimensionality reduction, denoising (denoising autoencoders), anomaly detection (high reconstruction error = anomaly), feature learning for downstream tasks, and pretraining deep networks.

Do not use when: you need to generate new samples (use VAE/GAN instead), your data is already low-dimensional, or you need interpretable features (PCA may be better).

Comparison with PCA

Linear autoencoder ≈ PCA (learns same subspace). Nonlinear autoencoder captures curved manifolds. VAE adds a probabilistic prior \(p(z) = \mathcal{N}(0, I)\) on the latent space, enabling generation. Sparse autoencoders add an \(\ell_1\) penalty on \(z\) for interpretability.
