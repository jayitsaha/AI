Understanding Knowledge Graph Completion
▼

What is it? A Knowledge Graph (KG) represents real-world facts as a network of entities (e.g., "Paris", "Eiffel Tower") and relations (e.g., "isCapitalOf", "locatedIn"). These facts are stored as triples: (head entity, relation, tail entity), like (Paris, isCapitalOf, France). Knowledge Graph Completion (KGC), also known as link prediction, is the task of automatically discovering missing triples in an incomplete KG.

Analogy: Imagine a vast, incomplete encyclopedia where some entries are missing connections. You know "Paris is a city" and "France is a country", but the link "(Paris, isCapitalOf, France)" is missing. KGC is like an intelligent assistant that can infer this missing link by understanding patterns in the existing facts. It might notice that if (X, isCapitalOf, Y) and (X, locatedIn, Y) are common, and (Paris, locatedIn, France) exists, then (Paris, isCapitalOf, France) is a plausible missing link.

💡 If you remember one thing

KGC models learn vector representations (embeddings) for every entity and relation in a low-dimensional space. The core idea is that if a triple (head, relation, tail) is true, its corresponding embeddings \(h, r, t \in \mathbb{R}^d\) should satisfy a certain geometric relationship (e.g., \(h + r \approx t\)). Predicting a link means finding the entity that best completes this relationship.

2
How KGC Models Work Internally
▼

Representing Knowledge Graphs: Triples

A knowledge graph is fundamentally a collection of facts, each expressed as a (head entity, relation, tail entity) triple. For example: (EiffelTower, locatedIn, Paris), (France, hasCapital, Paris). The entities and relations form a vocabulary. The goal is to predict new, unobserved triples that are likely to be true.

Embedding Entities and Relations

The first step in most KGC models is to embed each entity \(e\) and each relation \(r\) into a continuous vector space, typically \(\mathbb{R}^d\). So, Paris becomes a vector \(\mathbf{e}_{\text{Paris}}\), isCapitalOf becomes a vector \(\mathbf{r}_{\text{isCapitalOf}}\), and so on. These embeddings are learned during training. The dimensionality \(d\) is a hyperparameter, usually much smaller than the number of entities or relations.

Scoring Functions: Measuring Plausibility

The heart of a KGC model is its scoring function \(f(h, r, t)\). This function takes the embeddings of a head entity \(\mathbf{h}\), a relation \(\mathbf{r}\), and a tail entity \(\mathbf{t}\), and outputs a scalar score. A lower score typically indicates a more plausible (true) triple. Different models define \(f\) differently:

  • TransE (Translational Embeddings): Assumes that for a true triple \((h,r,t)\), the relation vector \(\mathbf{r}\) acts as a translation from \(\mathbf{h}\) to \(\mathbf{t}\) in the embedding space. So, \(\mathbf{h} + \mathbf{r} \approx \mathbf{t}\). The scoring function is \(f(h,r,t) = \|\mathbf{h} + \mathbf{r} - \mathbf{t}\|_{L_1 \text{ or } L_2}\).
  • DistMult (Diagonal Matrix Factorization): Models relations as diagonal matrices. \(f(h,r,t) = \mathbf{h}^\top \text{diag}(\mathbf{r}) \mathbf{t}\) or \(\langle \mathbf{h}, \mathbf{r}, \mathbf{t} \rangle\), where \(\mathbf{r}\) is element-wise multiplied with \(\mathbf{h}\) before dot product with \(\mathbf{t}\).
  • ComplEx (Complex Embeddings): Extends DistMult to complex numbers to better handle asymmetric relations.

Training with Negative Sampling

KGC models are trained by minimizing a margin-based ranking loss. For each positive (true) triple \((h,r,t)\) in the training set, we generate one or more negative (false) triples. A negative triple \((h',r',t')\) is created by corrupting a positive triple, usually by replacing either the head or the tail entity with a random, incorrect one (e.g., \((h,r,t')\) where \(t' \neq t\)). The loss function then encourages the score of positive triples to be lower than the score of negative triples by a certain margin.

🔑 Key Property

The choice of scoring function \(f(h,r,t)\) defines the geometric properties of the embedding space. TransE's simple additive rule (\(\mathbf{h} + \mathbf{r} \approx \mathbf{t}\)) is intuitive but struggles with complex relation patterns like one-to-many or many-to-many. More advanced models introduce richer interactions between \(\mathbf{h}\), \(\mathbf{r}\), and \(\mathbf{t}\).

3
Why It Works — The TransE Model & Margin Loss
▼

TransE: Translational Embeddings

TransE (Bordes et al., 2013) is one of the most influential KGC models due to its simplicity and effectiveness. It posits that if a triple \((h,r,t)\) holds, then the embedding of the tail entity \(\mathbf{t}\) should be close to the sum of the head entity embedding \(\mathbf{h}\) and the relation embedding \(\mathbf{r}\). This is a "translation" principle:

$$\mathbf{h} + \mathbf{r} \approx \mathbf{t}$$

To quantify this "closeness," TransE uses a distance-based scoring function. A smaller distance implies a more plausible triple:

$$f(h,r,t) = \|\mathbf{h} + \mathbf{r} - \mathbf{t}\|_{L_1 \text{ or } L_2}$$

Both entities and relations are typically normalized to have unit L2 norm (\(\|\mathbf{e}\|_2 = 1\), \(\|\mathbf{r}\|_2 = 1\)) to prevent them from growing arbitrarily large during training and to ensure the distance truly reflects the geometric relationship.

Margin-based Ranking Loss

The model is trained using a margin-based ranking loss. For each positive triple \((h,r,t)\) in the training set, we generate a set of corrupted (negative) triples \((h',r',t')\). The objective is to ensure that the score of a positive triple is always lower than that of a negative triple by at least a margin \(\gamma > 0\):

$$L = \sum_{(h,r,t) \in S} \sum_{(h',r',t') \in S'} \max(0, \gamma + f(h,r,t) - f(h',r',t'))$$

Here, \(S\) is the set of positive training triples, and \(S'\) is the set of negative triples. \((h',r',t')\) is typically formed by replacing either \(h\) or \(t\) from a positive triple \((h,r,t)\) with a random entity. The \(\max(0, \dots)\) ensures that only "hard" negative samples (those with scores too close to or better than positive samples) contribute to the loss.

This loss is minimized using stochastic gradient descent (SGD) or its variants (Adam, RMSprop). The gradients guide the embeddings \(\mathbf{h}, \mathbf{r}, \mathbf{t}\) to adjust their positions in the vector space such that \(\mathbf{h} + \mathbf{r}\) moves closer to \(\mathbf{t}\) for true triples, and further away from corrupted tails \(\mathbf{t'}\) for false triples.

⚠️ Common Pitfall

TransE assumes relations are purely translational. This means it struggles with symmetric relations (e.g., "friendOf" where \(\mathbf{h} + \mathbf{r} \approx \mathbf{t}\) implies \(\mathbf{t} + \mathbf{r} \approx \mathbf{h}\), which means \(\mathbf{r} \approx -\mathbf{r}\), forcing \(\mathbf{r}\) to be near zero) and one-to-many/many-to-one/many-to-many relations (e.g., "hasChild" where \(\mathbf{h} + \mathbf{r}\) should map to multiple \(\mathbf{t}\) entities, but TransE forces it to a single point). More complex models like RotatE or ComplEx address these limitations.

Key Takeaways
▼

When to use Knowledge Graph Completion:

  • To enrich incomplete knowledge bases (e.g., Wikidata, Freebase) by automatically inferring new facts.
  • To improve downstream tasks like question answering, recommendation systems, or semantic search by providing a denser graph.
  • To discover novel relationships that human curation might miss.
  • As a form of unsupervised or self-supervised learning for graph representations.

Limitations and Challenges:

  • Scalability: Real-world KGs can have millions of entities and billions of triples, requiring efficient training and inference.
  • Long-tail entities: Entities with few connections are hard to embed accurately due to lack of data.
  • Complex relations: TransE's simple additive model struggles with symmetric, inverse, or one-to-many/many-to-one relations. More advanced models like RotatE, ComplEx, or those based on Graph Neural Networks (GNNs) offer richer relational modeling.
  • Negative sampling: The quality of negative samples significantly impacts training. Random corruption can be too easy; "hard" negative sampling (e.g., using adversarial methods) is often needed.
  • Interpretability: Embeddings are often high-dimensional and difficult to interpret directly, making it hard to understand why a specific link was predicted.
💡 Beyond TransE

While TransE provides an intuitive foundation, modern KGC research explores diverse approaches: from more expressive tensor factorization models (DistMult, ComplEx) to geometric models using rotations (RotatE), and increasingly, Graph Neural Networks (GNNs) that aggregate neighborhood information to learn context-aware embeddings (e.g., R-GCN, CompGCN).

Code Trace (TransE from Scratch)
▼
import numpy as np
class TransE:
def __init__(self, n_entities, n_relations, embedding_dim, margin=1.0, lr=0.01):
self.entity_embeddings = np.random.uniform(-6/np.sqrt(embedding_dim), 6/np.sqrt(embedding_dim), (n_entities, embedding_dim))
self.relation_embeddings = np.random.uniform(-6/np.sqrt(embedding_dim), 6/np.sqrt(embedding_dim), (n_relations, embedding_dim))
self.entity_embeddings = self._normalize_embeddings(self.entity_embeddings) # L2 norm = 1
self.relation_embeddings = self._normalize_embeddings(self.relation_embeddings)
self.margin = margin
self.lr = lr
def _normalize_embeddings(self, embeddings):
return embeddings / np.linalg.norm(embeddings, axis=1, keepdims=True)
def score_triple(self, h_idx, r_idx, t_idx):
h = self.entity_embeddings[h_idx]
r = self.relation_embeddings[r_idx]
t = self.entity_embeddings[t_idx]
return np.linalg.norm(h + r - t) # L2 distance as score
def train_step(self, positive_triple, negative_triple):
h_pos, r_pos, t_pos = positive_triple
h_neg, r_neg, t_neg = negative_triple
score_pos = self.score_triple(h_pos, r_pos, t_pos)
score_neg = self.score_triple(h_neg, r_neg, t_neg)
loss = max(0, self.margin + score_pos - score_neg)
if loss > 0: # Only update if there's a positive loss
# Simplified gradient update for illustration (actual gradients are more complex)
# For L2 norm, gradients are proportional to (h+r-t)
grad_pos = (self.entity_embeddings[h_pos] + self.relation_embeddings[r_pos] - self.entity_embeddings[t_pos])
grad_neg = (self.entity_embeddings[h_neg] + self.relation_embeddings[r_neg] - self.entity_embeddings[t_neg])
self.entity_embeddings[h_pos] -= self.lr * grad_pos
self.relation_embeddings[r_pos] -= self.lr * grad_pos
self.entity_embeddings[t_pos] += self.lr * grad_pos
self.entity_embeddings[h_neg] += self.lr * grad_neg
self.relation_embeddings[r_neg] += self.lr * grad_neg
self.entity_embeddings[t_neg] -= self.lr * grad_neg
# Re-normalize embeddings after update
self.entity_embeddings[h_pos] = self._normalize_embeddings(self.entity_embeddings[h_pos].reshape(1,-1))[0]
self.relation_embeddings[r_pos] = self._normalize_embeddings(self.relation_embeddings[r_pos].reshape(1,-1))[0]
self.entity_embeddings[t_pos] = self._normalize_embeddings(self.entity_embeddings[t_pos].reshape(1,-1))[0]
self.entity_embeddings[h_neg] = self._normalize_embeddings(self.entity_embeddings[h_neg].reshape(1,-1))[0]
self.relation_embeddings[r_neg] = self._normalize_embeddings(self.relation_embeddings[r_neg].reshape(1,-1))[0]
self.entity_embeddings[t_neg] = self._normalize_embeddings(self.entity_embeddings[t_neg].reshape(1,-1))[0]
return loss
