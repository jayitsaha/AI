Foundational NLP Tokenization O(n) encode
1
Understanding the Concept
▼

What is it? A neural network can't read words — it reads integers. Vocabulary construction is the process of building a fixed lookup table that maps every token (word, sub-word, or punctuation mark) a model will ever see to a unique integer ID. On top of that vocabulary, a handful of special tokens — [CLS], [SEP], [MASK], [PAD], [UNK], [BOS], [EOS] — are reserved as extra vocabulary entries that carry structural meaning rather than linguistic meaning.

Analogy: Think of the vocabulary like a hotel's room directory: every guest (word) gets a room number (ID) so the front desk (the model) never has to deal with names directly. Special tokens are like the hotel's own reserved signage — a "LOBBY" sign ([CLS]) marking where to collect the summary of the whole stay, a "CHECKOUT" sign ([SEP]) marking where one guest's stay ends and the next begins, a "DO NOT DISTURB" tag ([MASK]) hiding a room's contents so staff must guess what's inside, and "VACANT" placards ([PAD]) filling empty rooms just so every floor (batch) has the same number of rooms.

💡 If you remember one thing

Special tokens are ordinary vocabulary entries with reserved IDs (usually the lowest IDs, e.g. 0–6) that a tokenizer inserts around and inside a sequence according to task-specific rules — the vocabulary itself doesn't change per task, only the wrapping recipe does.

How It Works Internally
▼

Step 1 — Build the vocabulary offline

Before any model sees a single sentence, a tokenizer (WordPiece for BERT, byte-pair encoding for GPT) is trained on a huge corpus to find the most frequent sub-word units. This produces a static table token → id of, say, 30,000–50,000 entries. The special tokens are inserted into this table first, at fixed low IDs, before any corpus-derived merges are added — that way their IDs never collide with real words and never change across model versions.

Step 2 — Reserve special tokens for structural roles

TokenUsed byRole
[CLS]BERT-familyPrepended once; its final hidden state is the pooled "whole sequence" representation for classification.

[UNK]All modelsCatches any token not present in the vocabulary (rare with sub-word tokenizers, common with whole-word ones).
[BOS]/[EOS]GPT-familyMark the start/end of a generation stream; no [CLS]/[SEP] concept exists here.

Step 3 — The tokenizer applies a task-specific "wrapping recipe" at encode time

Calling tokenizer.encode_plus(...) or tokenizer(text, text_pair=...) does three things in sequence: (1) split raw text into sub-word tokens using the trained vocabulary, replacing anything unseen with [UNK]; (2) insert the structural special tokens per the model's convention (BERT: [CLS] A [SEP] or [CLS] A [SEP] B [SEP]; GPT: [BOS] A [EOS]); (3) pad or truncate to the batch's fixed length and emit an attention mask (1 = real token, 0 = padding) alongside token_type_ids / segment IDs (0 for sentence A, 1 for sentence B) and position_ids.

🔑 Key Property

The vocabulary and the special-token IDs are frozen and identical at pretraining and fine-tuning time. Only the wrapping function — which tokens get inserted where — changes per downstream task. This is what lets one pretrained checkpoint serve classification, QA, and generation with the same embedding table.

3
Why It Works — The Math
▼

From token ID to vector

Once a sentence is wrapped into a sequence of IDs \(t_1,\dots,t_n \in \{0,\dots,|V|-1\}\), each ID indexes a row of the embedding matrix \(E \in \mathbb{R}^{|V|\times d}\):

$$e_i = E^\top \mathbf{1}_{t_i} = E[t_i,:] \in \mathbb{R}^d$$

Special tokens are learned rows of \(E\) just like any word — [CLS] at row 2 or [MASK] at row 4 has its own trainable embedding vector, updated by gradient descent exactly like the row for "cat".

The attention mask neutralizes [PAD]

Padding must not influence attention. Before softmax, the attention logits for padded key positions are pushed to \(-\infty\) using the mask \(m_j \in \{0,1\}\):

$$\text{score}_{ij} = \frac{q_i \cdot k_j}{\sqrt{d_k}} + (1-m_j)\cdot(-\infty) \quad\Rightarrow\quad \alpha_{ij}=\frac{\exp(\text{score}_{ij})}{\sum_{j'} \exp(\text{score}_{ij'})} \approx 0 \text{ for padded } j$$

Because \(\exp(-\infty)=0\), padded positions receive exactly zero attention weight — they contribute nothing to the weighted sum, regardless of what embedding [PAD] happens to have.

The [MASK] objective and the causal mask

For BERT's Masked Language Modeling, the loss is cross-entropy computed only at masked positions, with all other positions set to an ignored index (commonly \(-100\)):

$$\mathcal{L}_{MLM} = -\sum_{i \in \text{masked}} \log P(t_i \mid t_{\setminus \text{masked}})$$

GPT instead never masks tokens directly — it masks future positions in the attention matrix so token \(i\) can only attend to \(j \le i\), enforcing the autoregressive factorization \(P(t_1,\dots,t_n) = \prod_i P(t_i \mid t_{[BOS]/[EOS] marking the boundaries of that product.

⚠️ Common Misconception

"[PAD] tokens don't matter because they get masked." Only attention and loss are masked — if you forget to pass the attention mask to the model, [PAD] embeddings still participate in every self-attention computation and silently corrupt the output. The mask is a separate tensor you must construct and pass explicitly.

Key Takeaways
▼

Wrapping recipes by task:

  • BERT single-sequence classification: [CLS] tokens [SEP], segment id all 0 — pool [CLS]'s hidden state into a classifier head.
  • BERT sentence-pair (NLI / QA): [CLS] A [SEP] B [SEP], segment ids 0 for A, 1 for B — lets the model condition A on B and vice versa.
  • BERT pretraining (MLM): random tokens swapped for [MASK] (80%), a random token (10%), or left unchanged (10%) — never masked at inference.
  • GPT causal LM: [BOS] tokens [EOS], no segment ids, causal attention mask instead of a padding-only mask.
  • Batched generation: variable-length sequences padded (often left-padded for GPT) with [PAD] plus an explicit attention mask tensor.

When [UNK] shows up: Whole-word vocabularies see it often; modern sub-word tokenizers (WordPiece, BPE) almost eliminate it because any unseen word can be broken into known sub-word pieces or even raw bytes.

💡 One vocabulary, many wrappings

The embedding table and special-token IDs are fixed at pretraining time. Fine-tuning for a new task only changes how the tokenizer arranges tokens around those fixed IDs — never the IDs themselves.

Code Trace

# --- 1. Vocabulary: special tokens reserved at the lowest IDs ---
vocab = {"[PAD]":0, "[UNK]":1, "[CLS]":2, "[SEP]":3, "[MASK]":4, "[BOS]":5, "[EOS]":6,
"the":7, "quick":8, "brown":9, "fox":10, "jumps":11, "movie":12, "great":13, ...}
def encode(tokens, vocab):
return [vocab.get(t, vocab["[UNK]"]) for t in tokens] # OOV -> [UNK]
# --- 2. BERT single-sequence classification ---
ids = encode(["[CLS]"] + sentence_a + ["[SEP]"], vocab)
segment_ids = [0] * len(ids)
# --- 3. BERT sentence-pair (NLI / QA) ---
ids = encode(["[CLS]"] + sentence_a + ["[SEP]"] + sentence_b + ["[SEP]"], vocab)
segment_ids = [0]*(len(sentence_a)+2) + [1]*(len(sentence_b)+1)
# --- 4. Padding + attention mask for a fixed batch length ---
pad_len = max_len - len(ids)
attention_mask = [1]*len(ids) + [0]*pad_len
ids = ids + [vocab["[PAD]"]] * pad_len
# --- 5. MLM pretraining: randomly hide a token, predict it back ---
mask_pos = random.choice(range(1, len(ids)-1))
labels = [-100] * len(ids); labels[mask_pos] = ids[mask_pos] # -100 = ignored in loss
ids[mask_pos] = vocab["[MASK]"]
# --- 6. GPT causal LM formatting ---
ids = encode(["[BOS]"] + sentence + ["[EOS]"], vocab)
causal_mask = np.tril(np.ones((len(ids), len(ids)))) # token i sees j <= i only
