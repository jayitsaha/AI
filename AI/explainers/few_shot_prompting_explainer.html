Understanding Few-shot Prompting
▼

What is it? Few-shot prompting is a technique where a Large Language Model (LLM) is given a few examples of an input-output task directly within the prompt itself, before being asked to complete a new, unseen input. This allows the model to "learn" the task pattern without any explicit weight updates (fine-tuning). It's a form of in-context learning.

Analogy: Imagine teaching a child a new game. Instead of explaining all the rules (like fine-tuning), you just show them a few rounds of the game being played. "See? I said 'cat', you said 'animal'. I said 'apple', you said 'fruit'. Now, what about 'carrot'?" The child infers the pattern from the examples. For LLMs, the quality and arrangement of these "demonstrations" greatly impact how well they infer the pattern.

💡 If you remember one thing

Few-shot prompting leverages the LLM's ability to learn patterns from examples within its input context. The performance heavily depends on which examples are selected from a larger pool and the order in which they are presented in the prompt. This is especially critical for complex tasks or when the model is sensitive to subtle cues.

2
How Selection & Ordering Affect LLMs
▼

The LLM as a Pattern Recognizer

When an LLM processes a prompt, it's essentially trying to predict the next token based on the entire preceding context. Few-shot examples establish a "latent task representation" in the model's activations. The model tries to find a continuation that is consistent with this inferred task. If the examples are noisy, irrelevant, or contradictory, the model's internal representation of the task will be fuzzy, leading to poor performance.

Example Selection Strategies

Given a large dataset of labeled examples, how do we pick the best few for our prompt?

  • Random Selection: Simplest, but often suboptimal. Ignores relevance to the query.
  • Similarity-Based Selection: Embed the query and all available examples into a vector space. Select examples whose embeddings are "closest" (e.g., highest cosine similarity) to the query's embedding. This ensures relevance.
  • Diversity-Based Selection: Select examples that are similar to the query, but also diverse among themselves. This prevents redundancy and covers more aspects of the task.
  • Task-Specific Metrics: For some tasks, more complex metrics (e.g., uncertainty sampling, active learning techniques) can be used to pick examples that are most informative.

Ordering Effects

Even with the same set of examples, their sequence in the prompt can significantly alter the model's output. This phenomenon, known as "ordering effects," can be attributed to several factors:

  • Recency Bias: Models might give more weight to examples appearing later in the prompt.
  • Topic Drift: A sequence of examples that gradually shifts topic might lead the model astray.
  • Anchor Bias: The first example might set an "anchor" that influences the interpretation of subsequent examples.
  • Implicit Weighting: The internal attention mechanisms of the transformer might implicitly assign different weights to examples based on their position.
🔑 Key Property

The LLM's "inductive bias" in few-shot learning is highly sensitive to the prompt's structure. Effective example selection ensures relevance to the query, while thoughtful ordering can mitigate biases and enhance the clarity of the task definition. Together, these optimize the model's ability to generalize from the in-context demonstrations.

Why It Works — Embeddings & Similarity
▼

Semantic Similarity with Cosine

The foundation of similarity-based example selection lies in vector embeddings. Text inputs (the query and examples) are mapped into a high-dimensional vector space where semantically similar texts are close to each other. The most common metric for "closeness" between two non-zero vectors \(\mathbf{a}\) and \(\mathbf{b}\) is cosine similarity:

$$\text{similarity}(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a} \cdot \mathbf{b}}{\|\mathbf{a}\| \|\mathbf{b}\|} = \frac{\sum_{i=1}^d a_i b_i}{\sqrt{\sum_{i=1}^d a_i^2} \sqrt{\sum_{i=1}^d b_i^2}}$$

This metric ranges from -1 (perfectly dissimilar) to +1 (perfectly similar). For selecting examples, we typically look for the highest positive cosine similarity values between the query embedding and example embeddings.

The Role of Embeddings in Diversity

Beyond simple similarity, embeddings also enable diversity-aware selection. A common approach is to select examples that are individually similar to the query, but also dissimilar to each other. This can be formulated as a maximization problem:

$$\underset{E \subset \text{Pool}, |E|=K}{\arg\max} \left( \sum_{\mathbf{e} \in E} \text{similarity}(\mathbf{q}, \mathbf{e}) - \lambda \sum_{\mathbf{e}_i, \mathbf{e}_j \in E, i \neq j} \text{similarity}(\mathbf{e}_i, \mathbf{e}_j) \right)$$

Here, \(\mathbf{q}\) is the query embedding, \(E\) is the set of selected examples, \(K\) is the desired number of examples, and \(\lambda\) is a hyperparameter balancing query-similarity with intra-example diversity. This often requires more complex algorithms like Maximal Marginal Relevance (MMR) or clustering-based approaches.

Theoretical Basis for Ordering Effects

While less formalized mathematically, ordering effects stem from the sequential nature of transformer attention. The self-attention mechanism computes interactions between all tokens in the context. The positional encodings, combined with the learned attention weights, mean that the model's internal state (and thus its next-token prediction) is not invariant to permutation of the input tokens. ⚠️ Common Pitfall

Relying solely on "random" example selection is a common mistake that leaves significant performance on the table. While it might work for very simple tasks or extremely powerful models, for most real-world applications, a similarity-based approach (at minimum) is crucial for robust few-shot performance. Ignoring ordering effects can also lead to inconsistent or suboptimal results.

Key Takeaways
▼

When to optimize example selection & ordering:

  • Complex or Nuanced Tasks: When the task requires subtle reasoning or is easily misinterpreted (e.g., sarcasm detection, code generation, medical diagnosis).
  • Limited Compute/API Calls: When you need to maximize performance from fewer examples due to token limits or cost constraints.
  • Consistency and Robustness: To ensure the model provides stable and reliable outputs across different queries and deployments.
  • High-Stakes Applications: Where incorrect predictions have significant consequences.

When it might be less critical:

  • Very Simple Tasks: For straightforward tasks where the pattern is obvious (e.g., basic translation, trivial summarization).
  • Models with Stronger In-Context Learning: Newer, larger models (e.g., GPT-4o, Claude 3 Opus) are often more robust to suboptimal prompting, but optimization still helps.
  • Abundant Fine-tuning Data: If you have enough labeled data to fine-tune the model, that typically outperforms even the best few-shot prompting.
💡 The Prompt as a Mini-Dataset

Think of your few-shot prompt as a tiny, highly specialized training dataset. Just like a real dataset, its quality (relevant examples) and structure (effective ordering) are paramount for the model to learn the desired function effectively. Investing time in these aspects is a form of "prompt engineering" that yields significant returns.

Code Trace (Python: Example Selection)
▼
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity
# Example data: (text, embedding, label)
examples = [
{"text": "This movie was great!", "embedding": np.array([0.8, 0.7]), "label": "+1"},
{"text": "A truly awful film.", "embedding": np.array([-0.7, -0.8]), "label": "-1"},
# ... more examples ...
]
query = {"text": "Fantastic experience!", "embedding": np.array([0.75, 0.7]), "label": "+1"}
def select_most_similar_examples(query_embedding, example_pool, k):
# Extract all example embeddings
example_embeddings = np.array([ex["embedding"] for ex in example_pool])
# Compute cosine similarity between query and all examples
similarities = cosine_similarity(query_embedding.reshape(1, -1), example_embeddings)[0]
# Get indices of top-k most similar examples
top_k_indices = np.argsort(similarities)[::-1][:k]
# Return the selected examples
return [example_pool[i] for i in top_k_indices]
# Usage:
selected_examples = select_most_similar_examples(query["embedding"], examples, k=3)
for ex in selected_examples:
print(f"'{ex['text']}' -> {ex['label']}")
