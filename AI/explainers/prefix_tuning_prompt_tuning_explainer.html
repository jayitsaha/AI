Understanding Soft Prompts
▼

What is it? Large Language Models (LLMs) are incredibly powerful, but fine-tuning them for new tasks can be prohibitively expensive. Soft prompts (encompassing techniques like Prompt Tuning and Prefix Tuning) are a family of Parameter-Efficient Fine-Tuning (PEFT) methods. Instead of updating the entire LLM, these methods optimize only a tiny set of continuous, learnable vectors — the "soft prompt" or "prefix" — that guide the frozen LLM to perform specific tasks. This drastically reduces computational cost and memory footprint.

Analogy: Imagine a master chef (the LLM) who knows how to cook an infinite variety of dishes. To make a new dish, you could either retrain the chef from scratch (full fine-tuning), which is time-consuming and expensive, or you could give the chef a special "spice blend" (the soft prompt/prefix) that subtly alters the flavor profile of their existing cooking process. The chef's core skills remain unchanged, but the output is customized to your taste. Soft prompts are those custom spice blends for LLMs.

💡 If you remember one thing

Soft prompts leverage the vast knowledge of a pre-trained LLM by optimizing only a minuscule fraction of its parameters (often <0.1%). This makes fine-tuning much faster, cheaper, and more portable, while effectively adapting the model to downstream tasks without risking catastrophic forgetting of its general capabilities.

How Soft Prompts Work Internally
▼

Contrast with Full Fine-tuning

In traditional full fine-tuning, every single weight in the pre-trained LLM is updated via backpropagation. While powerful, this requires storing gradients for billions of parameters, high memory bandwidth, and significant computational resources. It also risks "catastrophic forgetting," where the model loses its general knowledge in favor of task-specific overfitting.

Prompt Tuning: Shallow Intervention

Introduced by Lester et al. (2021), Prompt Tuning is the simplest form of soft prompting. It works by:

  1. Defining a short sequence of learnable continuous vectors (the "soft prompt") of length \(l_p\).
  2. These vectors are prepended to the input embedding sequence of the original input tokens.
  3. The combined sequence \([P; E]\) (soft prompt embeddings followed by input embeddings) is fed into the frozen LLM.
  4. During training, only the soft prompt vectors \(P\) are updated via gradient descent; all LLM weights remain fixed.

This approach is extremely parameter-efficient, as typically \(l_p\) is very small (e.g., 5-100 tokens), and \(d_e\) (embedding dimension) is the only other factor. The soft prompt essentially acts as a "virtual token" sequence that subtly shifts the model's internal representations from the very first layer.

Prefix Tuning: Deeper Intervention

Proposed by Li & Liang (2021), Prefix Tuning takes a deeper approach. Instead of modifying only the input embeddings, it:

  1. Generates a sequence of learnable "prefix" vectors for the key (\(K\)) and value (\(V\)) matrices at every Transformer layer.
  2. These prefixes are prepended to the \(K\) and \(V\) states within the attention mechanism of each layer.
  3. The LLM processes the input, and at each attention block, the attention computation is influenced by these prefixes.
  4. Similar to prompt tuning, only these prefix vectors are updated; the core LLM weights are frozen.

By injecting learnable parameters into the attention mechanism at every layer, Prefix Tuning offers more expressive power than Prompt Tuning, allowing for more complex task adaptation. It's often implemented by training a small MLP to generate the prefix vectors, further reducing the number of directly optimized parameters.

🔑 Key Property

Both Prompt Tuning and Prefix Tuning achieve efficiency by decoupling the large, frozen LLM parameters from the small, task-specific learnable parameters. This means you only need to save and load tiny soft prompt/prefix files for each task, rather than a full fine-tuned model checkpoint.

Why It Works — The Math
▼

The Transformer Block Foundation

A Transformer processes an input sequence \(X = [x_1, \dots, x_L]\) by first converting tokens into embeddings \(E = [e_1, \dots, e_L]\), where \(e_i \in \mathbb{R}^{d_e}\). Within each attention layer, queries \(Q\), keys \(K\), and values \(V\) are derived from these embeddings (or previous layer's hidden states) via linear projections:

$$Q = E W_Q, \quad K = E W_K, \quad V = E W_V$$

The self-attention mechanism then computes outputs by weighing values based on query-key similarity:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

where \(d_k\) is the dimension of the keys (and queries). The core idea of soft prompts is to modify these \(Q, K, V\) sequences in a parameter-efficient way.

Prompt Tuning: Modifying Input Embeddings

In Prompt Tuning, we define a set of learnable prompt embeddings \(P \in \mathbb{R}^{l_p \times d_e}\), where \(l_p\) is the length of the soft prompt and \(d_e\) is the embedding dimension. The input sequence to the LLM becomes the concatenation of the soft prompt and the original input embeddings \(E_x\):

$$E' = [P; E_x] = [p_1, \dots, p_{l_p}, e_1, \dots, e_L]$$

The entire LLM (with its frozen weights \(\theta_{\text{LLM}}\)) then processes \(E'\). The training objective minimizes a task-specific loss (e.g., cross-entropy for classification) by optimizing only the prompt parameters \(\theta_P\):

$$\min_{\theta_P} \mathcal{L}(f_{\text{LLM}}(P, E_x; \theta_{\text{LLM}}), y)$$

This is a shallow intervention, affecting the model's representations from the very first layer by changing the "context" provided at the input.

Prefix Tuning: Modifying Key and Value States

Prefix Tuning operates deeper within the Transformer architecture. For each layer \(i\) and each attention head, we learn prefix vectors \(P_{k,i}, P_{v,i} \in \mathbb{R}^{l_p \times d_h}\) (where \(d_h\) is the hidden dimension for keys/values). These are prepended to the computed \(K\) and \(V\) matrices for that layer:

$$K' = [P_{k,i}; K], \quad V' = [P_{v,i}; V]$$

The attention computation then uses these modified key and value matrices:

$$\text{Attention}(Q, K', V') = \text{softmax}\left(\frac{Q (K')^T}{\sqrt{d_k}}\right)V'$$

The queries \(Q\) are still derived from the original input sequence. By influencing \(K\) and \(V\) directly, the prefixes guide the attention mechanism at every layer, providing a more fine-grained control over the model's behavior. The parameters \(\theta_{P_{k,i}}, \theta_{P_{v,i}}\) are the only ones optimized.

⚠️ Design Choice: How to initialize?

Soft prompts are often initialized from the embeddings of real task-related tokens (e.g., "classify this review as positive or negative") to provide a good starting point. Random initialization is also possible but may require more training steps to converge to a good solution. The choice can impact convergence speed and final performance.

Key Takeaways
▼

When to use soft prompts (Prompt Tuning / Prefix Tuning):

  • Large LLMs: When full fine-tuning billions of parameters is computationally infeasible or too expensive (e.g., 7B+ models).
  • Limited compute/memory: Dramatically reduces GPU memory usage during training and storage size for task-specific models.
  • Rapid task adaptation: Quickly adapt a single pre-trained backbone to many downstream tasks by swapping out small soft prompt files.
  • Avoiding catastrophic forgetting: Since the core LLM weights are frozen, the model retains its general knowledge and capabilities.
  • Multi-task learning: Train multiple soft prompts for different tasks on the same frozen backbone, allowing for efficient deployment.

When NOT to use or when to be cautious:

  • Very small models: If your base model is small (e.g., <100M parameters), full fine-tuning might be equally efficient and potentially yield slightly better performance.
  • Tasks requiring deep structural changes: Soft prompts are best for guiding existing capabilities, not fundamentally altering the model's architecture or core functions.
  • Maximum possible performance is critical: While highly competitive, full fine-tuning can sometimes achieve marginally superior results if compute resources are not a constraint.
  • Interpretable prompts: Soft prompts are continuous vectors, not human-readable tokens, making them harder to interpret or debug than hard prompts.
💡 Hierarchy & Alternatives

Prompt Tuning and Prefix Tuning are part of a broader family of PEFT methods. Prompt Tuning is generally simpler and less expressive. Prefix Tuning offers more control by intervening at every layer. Other PEFT methods like LoRA (Low-Rank Adaptation) also train a small number of parameters but do so by adding low-rank decomposition matrices to the existing weight matrices, rather than injecting new token/activation sequences.

import torch
import torch.nn as nn
from transformers import AutoModelForCausalLM, AutoTokenizer
# --- 1. Load a pre-trained LLM and freeze its weights ---
model_name = "gpt2" # or "llama-7b"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)
for param in model.parameters():
param.requires_grad = False # Freeze all LLM parameters
d_model = model.config.hidden_size
num_layers = model.config.num_hidden_layers
# --- 2. Prompt Tuning Example ---
# Define learnable soft prompt embeddings
prompt_length = 20
soft_prompt_embeddings = nn.Embedding(prompt_length, d_model) # (L_p, D_e)
# Initialize with embeddings of real tokens (optional but common)
# soft_prompt_embeddings.weight.data = model.get_input_embeddings()(some_token_ids)
# Optimizer only sees the soft prompt parameters
optimizer_pt = torch.optim.Adam(soft_prompt_embeddings.parameters(), lr=1e-3)
# During forward pass: prepend soft prompt to input
input_ids = tokenizer("The movie was", return_tensors="pt").input_ids
input_embeds = model.get_input_embeddings()(input_ids) # (1, L_input, D_e)
prompt_embeds = soft_prompt_embeddings(torch.arange(prompt_length)) # (L_p, D_e)
prompt_embeds = prompt_embeds.unsqueeze(0) # (1, L_p, D_e)
combined_embeds = torch.cat([prompt_embeds, input_embeds], dim=1)
# Pass through model with custom inputs_embeds
output_pt = model(inputs_embeds=combined_embeds)
# Backprop and update ONLY soft_prompt_embeddings
# loss_pt.backward(); optimizer_pt.step()
# --- 3. Prefix Tuning Example ---
# Generate prefix vectors for K and V at each layer
prefix_length = 50
# A small MLP to generate prefixes (more stable than direct Parameter)
class PrefixEncoder(nn.Module):
def __init__(self, config, prefix_len):
super().__init__()
self.prefix_len = prefix_len
self.input_tokens = torch.arange(prefix_len).long()
# Map input tokens to a larger hidden state for K/V prefixes
self.embedding = nn.Embedding(prefix_len, config.hidden_size)
self.mlp = nn.Sequential(
nn.Linear(config.hidden_size, config.hidden_size),
nn.Tanh(),
nn.Linear(config.hidden_size, 2 * config.num_hidden_layers * config.hidden_size)
) # 2 * layers * hidden_size for K and V prefixes per layer
def forward(self):
# Reshape to (num_layers, 2, prefix_len, hidden_size) for K/V
return self.mlp(self.embedding(self.input_tokens)).view(
num_layers, 2, self.prefix_len, d_model
)
