Understanding Regression Metrics
▼

What are they? Regression models predict continuous values. Metrics are how we quantify "how good" those predictions are by comparing them to the true observed values. Unlike classification (where a prediction is simply right or wrong), regression errors have magnitude — a prediction off by 10 is usually worse than one off by 1, but "worse" can be defined in many ways. Choosing the right metric depends heavily on the problem context, the distribution of your data, and the business cost of different types of errors.

Analogy: Imagine a dartboard. MAE measures the average distance from the bullseye. RMSE measures the average distance, but heavily penalizes darts that land far away (squaring amplifies large errors). MAPE measures the average percentage miss (e.g., "10% off target"). sMAPE is similar but tries to be more fair if the bullseye itself is very small. MASE compares your darts to someone who just throws at the last spot the previous dart hit. WQL lets you say, "missing high is much worse than missing low," or vice versa.

💡 If you remember one thing

There is no single "best" regression metric. Each metric captures a different aspect of prediction quality and has its own strengths and weaknesses (e.g., sensitivity to outliers, scale-dependence, interpretability, behavior with zero values). Always consider your domain and error tolerance when selecting.

Common Metrics: Magnitude, Percentage, & Scaled Errors
▼

MAE (Mean Absolute Error)

MAE measures the average magnitude of errors. It's robust to outliers because it doesn't square errors. It's easy to interpret: "on average, our predictions are off by X units."

$$\text{MAE} = \frac{1}{N} \sum_{i=1}^{N} |y_i - \hat{y}_i|$$

RMSE (Root Mean Squared Error)

RMSE is the square root of the average of squared errors. Squaring errors gives larger errors disproportionately more weight, making RMSE sensitive to outliers. It's often preferred when large errors are particularly undesirable.

$$\text{RMSE} = \sqrt{\frac{1}{N} \sum_{i=1}^{N} (y_i - \hat{y}_i)^2}$$

MAPE (Mean Absolute Percentage Error)

MAPE expresses error as a percentage of the true value. It's intuitive for many business contexts ("we're off by 5%"). However, it's undefined for \(y_i=0\) and heavily penalizes negative errors (over-predictions) when \(y_i\) is small, making it asymmetric.

$$\text{MAPE} = \frac{1}{N} \sum_{i=1}^{N} \left| \frac{y_i - \hat{y}_i}{y_i} \right| \times 100\%$$

sMAPE (Symmetric Mean Absolute Percentage Error)

sMAPE addresses some of MAPE's asymmetry by normalizing by the average of true and predicted values. It's typically bounded between 0% and 200%, but can still be problematic if both \(y_i\) and \(\hat{y}_i\) are zero (division by zero).

$$\text{sMAPE} = \frac{1}{N} \sum_{i=1}^{N} \frac{|y_i - \hat{y}_i|}{(|y_i| + |\hat{y}_i|)/2} \times 100\%$$

MASE (Mean Absolute Scaled Error)

MASE scales the forecast error by the mean absolute error of a naive forecast (e.g., the previous period's value). A MASE < 1 means your model is better than the naive baseline, > 1 means it's worse. It is scale-independent and robust to zeros, making it suitable for intermittent demand data or comparing models across different scales.

$$\text{MASE} = \frac{\frac{1}{N} \sum_{i=1}^{N} |y_i - \hat{y}_i|}{\frac{1}{N-1} \sum_{i=2}^{N} |y_i - y_{i-1}|}$$
🔑 Key Differences

Magnitude-based (MAE, RMSE) are scale-dependent, meaning a value of 10 is different if predicting temperature vs. sales. Percentage-based (MAPE, sMAPE) are scale-independent but can break with zero values. Scaled-error (MASE) is also scale-independent and robust to zeros, offering a relative performance benchmark.

Weighted Quantile Loss (WQL)
▼

Beyond Point Estimates: Quantile Regression

Sometimes, we don't just want a single best prediction \(\hat{y}_i\), but rather an estimate of a specific quantile of the conditional distribution of \(y_i\) (e.g., the 90th percentile). This is common in forecasting where over-prediction or under-prediction carries asymmetric costs (e.g., inventory management: overstocking is costly, but understocking is even worse). The quantile loss function, also known as pinball loss, is designed for this.

The Pinball Loss Function

For a given quantile \(\tau \in (0,1)\), the loss for a single prediction \(\hat{y}_i\) and true value \(y_i\) is:

$$\rho_\tau(y_i, \hat{y}_i) = \begin{cases} \tau (y_i - \hat{y}_i) & \text{if } y_i > \hat{y}_i \quad (\text{under-prediction}) \\ (1-\tau) (\hat{y}_i - y_i) & \text{if } y_i \le \hat{y}_i \quad (\text{over-prediction}) \end{cases}$$

This can be compactly written using the indicator function \(\mathbf{1}_{u < 0}\):

$$\rho_\tau(u) = u \cdot (\tau - \mathbf{1}_{u < 0}) \quad \text{where } u = y_i - \hat{y}_i$$

The total Weighted Quantile Loss (WQL) for a dataset is typically the sum or mean of these individual losses:

$$\text{WQL}_\tau = \frac{1}{N} \sum_{i=1}^{N} \rho_\tau(y_i, \hat{y}_i)$$

Notice the asymmetry: if \(\tau = 0.5\), the loss becomes \((y_i-\hat{y}_i) \cdot (0.5 - \mathbf{1}_{y_i-\hat{y}_i < 0})\). If \(y_i > \hat{y}_i\), loss is \(0.5(y_i - \hat{y}_i)\). If \(y_i \le \hat{y}_i\), loss is \(0.5(\hat{y}_i - y_i)\). This is symmetric, equivalent to MAE scaled by 0.5. For \(\tau = 0.9\), under-predictions (where \(y_i > \hat{y}_i\)) are penalized by \(0.9 \cdot |y_i - \hat{y}_i|\), while over-predictions (where \(y_i \le \hat{y}_i\)) are penalized by only \(0.1 \cdot |\hat{y}_i - y_i|\). This means the model is heavily incentivized to predict higher, pushing the \(\hat{y}_i\) towards the 90th percentile.

⚠️ Loss vs. Metric

While many metrics (like MAE, RMSE) can also serve as loss functions for training, WQL is primarily designed as a loss function to optimize for specific quantiles. Evaluating a point prediction model with WQL (where the model wasn't trained for that quantile) can be misleading. It's best used when your model explicitly outputs quantile forecasts.

Key Takeaways
▼

When to use which metric:

  • MAE: Simple, robust to outliers, easy to interpret "average error magnitude." Good default for general-purpose evaluation.
  • RMSE: Penalizes large errors more heavily, useful when big mistakes are very costly. Often used in scientific and engineering contexts.
  • MAPE: Intuitive percentage error, good for comparing performance across different scales. Be cautious with small or zero true values.
  • sMAPE: A more robust percentage error for values near zero, but still has edge cases.
  • MASE: Excellent for time series forecasting, provides a scale-independent benchmark against a naive forecast. Robust to zero values.
  • WQL (Quantile Loss): When you need to optimize for a specific quantile (e.g., 90th percentile) or when over/under-prediction costs are asymmetric. Used as a loss function for quantile regression.

General best practices:

  • Always report at least two metrics, especially one magnitude-based and one percentage/scaled-based.
  • Understand the distribution of your errors (e.g., plot residuals). Metrics summarize, but hide details.
  • Consider the business impact of errors. Does a 10-unit error in sales prediction cost the same as a 10-unit error in temperature prediction?
  • Be aware of metric limitations (e.g., MAPE with zeros, RMSE's outlier sensitivity).
💡 Context is King

The choice of metric is a crucial part of defining "success" for your regression model. It should be driven by the domain, the characteristics of your data, and the specific decision-making context where the predictions will be used.

Code Trace (Python / NumPy)
▼
import numpy as np
def mae(y_true, y_pred):
return np.mean(np.abs(y_true - y_pred))
def rmse(y_true, y_pred):
return np.sqrt(np.mean((y_true - y_pred)**2))
def mape(y_true, y_pred):
# Handle division by zero for y_true = 0 (returns inf, or 0 if error is 0)
return np.mean(np.abs((y_true - y_pred) / np.where(y_true == 0, 1e-8, y_true))) * 100
def smape(y_true, y_pred):
numerator = np.abs(y_true - y_pred)
denominator = (np.abs(y_true) + np.abs(y_pred)) / 2
# Handle division by zero for both y_true and y_pred = 0
return np.mean(numerator / np.where(denominator == 0, 1e-8, denominator)) * 100
def mase(y_true, y_pred):
n = len(y_true)
mae_numerator = np.mean(np.abs(y_true - y_pred))
# Naive forecast error (seasonal difference for time series, here just y_i - y_{i-1})
mae_denominator = np.mean(np.abs(y_true[1:] - y_true[:-1]))
return mae_numerator / np.where(mae_denominator == 0, 1e-8, mae_denominator)
def weighted_quantile_loss(y_true, y_pred, tau):
errors = y_true - y_pred
# Pinball loss: tau * max(error, 0) + (1-tau) * max(-error, 0)
return np.mean(np.where(errors > 0, tau * errors, (1 - tau) * -errors))
# Example usage:
y_true = np.array([10, 12, 11, 15, 13, 18])
y_pred_model1 = np.array([11, 11, 12, 14, 14, 17])
print(f"MAE: {mae(y_true, y_pred_model1):.2f}")
print(f"RMSE: {rmse(y_true, y_pred_model1):.2f}")
print(f"MAPE: {mape(y_true, y_pred_model1):.2f}%")
print(f"sMAPE: {smape(y_true, y_pred_model1):.2f}%")
print(f"MASE: {mase(y_true, y_pred_model1):.2f}")
print(f"WQL (tau=0.9): {weighted_quantile_loss(y_true, y_pred_model1, 0.9):.2f}")
