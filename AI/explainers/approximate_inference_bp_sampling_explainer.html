Understanding Approximate Inference
▼

What is it? A graphical model (Markov random field / Bayes net) encodes a joint distribution over many variables as a graph of local interactions. Computing an exact marginal — "what's the probability variable X is 1?" — requires summing over every possible setting of every other variable. When the graph has cycles or high treewidth, that sum is exponential in size and exact inference becomes intractable. Approximate inference trades exactness for speed: either pass messages on the graph pretending it has no cycles (loopy belief propagation), or draw random samples from the distribution and estimate marginals empirically (Gibbs / importance sampling).

Analogy: Imagine a rumor spreading through a friend circle where everyone influences everyone else in a loop. Loopy BP is like each person repeatedly asking "given what my neighbors currently believe, what should I believe?" — even though the loop means information echoes back around and gets double-counted. Sampling is the opposite strategy: instead of reasoning about beliefs directly, you simulate thousands of plausible "realities" consistent with the rules, and just count how often each outcome shows up.

💡 If you remember one thing

Belief propagation (sum-product) is exact on trees. Run the identical local message-update rule on a graph with cycles anyway — "loopy BP" — and it has no convergence guarantee, yet in practice it often converges to good approximate marginals. Sampling methods make no such structural assumption: they are asymptotically exact but pay for it with variance and mixing time.

How Loopy BP & Gibbs Sampling Work Internally
▼

Exact BP: The Sum-Product Algorithm on a Tree

On a tree-structured graphical model, each node \(i\) sends a message to each neighbor \(j\) summarizing everything it has learned from the rest of the tree beyond the edge \((i,j)\):

$$m_{i\to j}(x_j) = \sum_{x_i} \phi_i(x_i)\,\psi_{ij}(x_i,x_j) \!\!\prod_{k \in N(i)\setminus j}\!\! m_{k\to i}(x_i)$$

where \(\phi_i\) is the unary (node) potential and \(\psi_{ij}\) the pairwise (edge) potential. On a tree, messages are computed leaves-inward then root-outward exactly once each, and the resulting belief \(b_i(x_i) \propto \phi_i(x_i)\prod_{k\in N(i)} m_{k\to i}(x_i)\) is the true marginal \(P(x_i)\).

Loopy BP: Same Rule, No Guarantees

When the graph has cycles, there is no valid elimination order that visits each edge once — a message sent around the loop influences itself. Loopy BP just runs the identical local update rule anyway, synchronously or asynchronously, iterating until messages stop changing (or a max iteration budget is hit). There is no proof this converges: it can oscillate forever, converge to the wrong fixed point, or converge to values close to the truth. Empirically (and in the interactive walkthrough below) it very often converges to accurate approximate marginals, especially on graphs that are "nearly" tree-like or have weak cycles.

Gibbs Sampling: Coordinate-Wise Simulation

Gibbs sampling sidesteps message passing entirely. Starting from any joint assignment, it repeatedly picks one variable \(x_i\) and resamples it from its exact conditional distribution given the current values of its neighbors (the Markov blanket):

$$x_i^{(t+1)} \sim P\big(x_i \mid x_{N(i)}^{(t)}\big) \propto \phi_i(x_i)\!\!\prod_{k\in N(i)}\!\!\psi_{ik}(x_i, x_k^{(t)})$$

This conditional is cheap because it only involves the immediate neighbors, not the whole graph. After a "burn-in" period the chain of samples converges to the true joint distribution (its stationary distribution), and marginals are estimated by counting how often each sampled state occurs.

Design Decision: Why Not Always Sample?

Loopy BP is deterministic and often converges in a handful of iterations — fast, but with no error bars and no guarantee. Sampling is stochastic but asymptotically exact — given enough samples it provably converges to the true marginal, and you can quantify uncertainty. In practice: use loopy BP for speed on error-correcting codes, computer vision CRFs, and structured prediction; use MCMC/Gibbs when correctness matters more than speed or the model has strong, long-range correlations that make BP unreliable.

🔑 Key Property

Loopy BP fixed points are exactly the stationary points of the Bethe free energy approximation to the true free energy (Yedidia, Freeman & Weiss, 2001). Gibbs sampling's stationary distribution is exactly the target joint \(P(x)\) by construction, since each conditional update satisfies detailed balance.

Why It Works (and Sometimes Doesn't) — The Math
▼

The Joint Distribution (Pairwise MRF)

For our 4-cycle \(A\!-\!B\!-\!C\!-\!D\!-\!A\), the joint factorizes over node and edge potentials:

$$P(a,b,c,d) = \frac{1}{Z}\,\phi_A(a)\phi_B(b)\phi_C(c)\phi_D(d)\,\psi_{AB}(a,b)\psi_{BC}(b,c)\psi_{CD}(c,d)\psi_{DA}(d,a)$$

with normalizer \(Z = \sum_{a,b,c,d}\) (numerator), summing over all \(2^4=16\) joint states. Exact inference here is a 16-term brute-force sum; on an \(n\)-node graph with treewidth \(w\), exact junction-tree inference costs \(O(n\cdot k^{w+1})\) for \(k\)-valued variables — exponential in treewidth, which is why loopy graphs with high treewidth force us to approximate.

Bethe Free Energy: Why Loopy BP Fixed Points Are Meaningful

Exact inference minimizes the Gibbs free energy \(F(P) = \mathbb{E}_P[-\log \phi\psi] - H(P)\) over all valid distributions \(P\), which requires the full joint entropy \(H(P)\). Bethe's approximation replaces the exact joint entropy with a sum of pairwise and singleton entropies:

$$F_{\text{Bethe}} = \sum_{ij} \sum_{x_i,x_j} b_{ij}\log\frac{b_{ij}}{\phi_i\phi_j\psi_{ij}} - \sum_i (d_i-1)\sum_{x_i} b_i \log b_i$$

where \(d_i\) is the degree of node \(i\). Taking the stationary point of \(F_{\text{Bethe}}\) subject to the marginalization constraints \(\sum_{x_j} b_{ij}=b_i\), via Lagrange multipliers, yields exactly the loopy BP message-passing fixed-point equations. On a tree, Bethe's approximation is exact (\(F_{\text{Bethe}}=F\)) because pairwise marginals fully determine the tree-structured joint — this is why BP is exact there and only approximate on graphs with cycles.

Gibbs Sampling: Detailed Balance and Convergence

Each Gibbs update resamples \(x_i \sim P(x_i \mid x_{-i})\) holding the rest fixed. This transition kernel satisfies detailed balance with respect to the target \(P\):

$$P(x)\,T(x \to x') = P(x')\,T(x' \to x)$$

Detailed balance implies \(P\) is a stationary distribution of the Markov chain. Under mild conditions (irreducibility — every state reachable, aperiodicity), the chain is ergodic and the empirical sample distribution converges to \(P\) as the number of sweeps \(T\to\infty\), regardless of the starting state. The Monte Carlo marginal estimate is the sample average:

$$\hat{P}(x_i = 1) = \frac{1}{T}\sum_{t=1}^{T} \mathbb{1}[x_i^{(t)} = 1] \;\xrightarrow{\;T\to\infty\;}\; P(x_i=1)$$

with Monte Carlo standard error shrinking as \(O(1/\sqrt{T_{\text{eff}}})\), where \(T_{\text{eff}} < T\) accounts for autocorrelation between consecutive samples along the chain.

⚠️ Common Misconception

"Loopy BP always converges to something close to the truth" — false in general. Strong, tightly coupled cycles (e.g., frustrated cycles with conflicting attractive/repulsive edges) can make loopy BP oscillate indefinitely or converge to badly biased beliefs. Damping the updates (mixing old and new messages) improves convergence but doesn't fix correctness. Likewise, "Gibbs sampling gives the exact answer after a few samples" is false — the chain needs to mix (forget its start state), and highly correlated variables can mix extremely slowly.

Key Takeaways
▼

When to use loopy BP:

  • Sparse graphs with weak/moderate cycles — error-correcting codes (turbo/LDPC decoding), low-level computer vision (stereo, denoising CRFs)
  • You need fast, deterministic, low-latency approximate marginals and can tolerate no correctness guarantee
  • The graph is close to tree-structured (few, long cycles)

When to use sampling (Gibbs / importance sampling):

  • You need asymptotically exact answers, or uncertainty estimates on the marginal itself
  • The graph has strong, short, frustrated cycles where BP is known to misbehave
  • You can afford many sweeps / have a well-mixing chain (or use importance sampling when you can design a good proposal distribution)

When NOT to use either:

  • Graph is small enough / low enough treewidth for exact junction-tree inference — just do it exactly
  • Gibbs sampling on strongly multi-modal distributions with isolated modes — chain gets stuck; consider parallel tempering or better proposals
💡 The Big Picture

Exact inference (junction tree) ⊂ loopy BP (variational, deterministic, biased) and Gibbs/MCMC (sampling, stochastic, asymptotically unbiased) are two different philosophies for the same intractability problem — approximate the distribution's shape (BP) vs. approximate the distribution's samples (MCMC). Modern systems often combine both: use BP for a fast initialization, then refine with a short MCMC run.

import numpy as np, itertools, random
# Unary potentials phi[node] = [P(x=0)-weight, P(x=1)-weight]
phi = {'A':[0.7,0.3], 'B':[0.4,0.6], 'C':[0.6,0.4], 'D':[0.3,0.7]}
psi = np.array([[2.0,0.5],[0.5,2.0]]) # shared edge potential (attractive)
neighbors = {'A':['B','D'],'B':['A','C'],'C':['B','D'],'D':['C','A']}
def loopy_bp(n_iters=6):
msg = {(i,j): np.array([1.0,1.0]) for i in phi for j in neighbors[i]}
for _ in range(n_iters):
new_msg = {}
for i in phi:
for j in neighbors[i]:
others = [k for k in neighbors[i] if k != j]
m = np.zeros(2)
for xj in (0,1):
s = 0.0
for xi in (0,1):
p = phi[i][xi]
for k in others: p *= msg[(k,i)][xi]
s += p * psi[xi][xj]
m[xj] = s
new_msg[(i,j)] = m / m.sum() # normalize (numerical stability)
msg = new_msg
beliefs = {}
for i in phi:
b = np.array(phi[i])
for k in neighbors[i]: b = b * msg[(k,i)]
beliefs[i] = b / b.sum()
return beliefs
def gibbs_sampling(n_steps=2000, burn_in=200, seed=0):
rng = random.Random(seed)
state = {n: 0 for n in phi}
counts = {n: 0 for n in phi}
nodes = list(phi)
for t in range(n_steps):
i = nodes[t % len(nodes)]
unnorm = [phi[i][xi] * np.prod([psi[xi][state[k]] for k in neighbors[i]])
for xi in (0,1)]
p1 = unnorm[1] / sum(unnorm) # conditional P(x_i=1 | neighbors)
state[i] = 1 if rng.random() < p1 else 0
if t >= burn_in: counts[i] += state[i] # only count post-burn-in samples
n_counted = (n_steps - burn_in) / len(nodes)
return {n: counts[n] / n_counted for n in phi} # empirical P(x=1)
