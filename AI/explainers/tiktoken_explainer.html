Understanding Tiktoken
▼

What is it? Tiktoken is OpenAI's fast tokenizer library that converts text into sequences of integer token IDs before feeding them to GPT models. It implements byte-level Byte Pair Encoding (BPE), meaning it can represent any text — including emojis, code, and non-English scripts — by working at the raw byte level rather than the character level.

Analogy: Imagine compressing a message by finding frequently repeated letter combinations and replacing them with shorter codes. "th" appears constantly in English, so you replace every "th" with a single symbol. Then "the" becomes that symbol + "e", which is also common, so you merge that too. Tiktoken does exactly this, but learned from billions of text bytes — it has a lookup table of ~100,000 pre-learned merges.

If you remember one thing

Tiktoken first splits text using a regex into coarse chunks (words, numbers, punctuation), then applies BPE merges from a pre-trained vocabulary to each chunk independently. The regex prevents merges from crossing word boundaries, which dramatically improves tokenization quality.

How Byte-Level BPE Works
▼

The Two-Phase Pipeline

Phase 1 — Regex Pre-tokenization: Before any BPE merges happen, the input text is split using a carefully designed regex pattern. For cl100k_base (GPT-4), this regex matches words with optional leading/trailing apostrophes, sequences of digits, runs of whitespace, and punctuation. Each match becomes an independent chunk that BPE processes separately.

Phase 2 — BPE Merge Lookup: Each chunk is converted to its UTF-8 byte sequence. Then, iteratively, the algorithm finds the byte pair with the highest priority in the pre-trained merge table and replaces every occurrence of that pair with a single new token. This continues until no more merges are available.

Key Design Decision: Why regex pre-splitting?

Without regex pre-splitting, BPE could merge the space before a word with the word itself (e.g., " the" as one token). This creates inconsistencies: the same word would tokenize differently depending on what precedes it. The regex ensures words, numbers, and punctuation are always processed independently, producing deterministic, context-free tokenization within each category.

The cl100k_base Regex Pattern

(?i:'s|'t|'re|'ve|'m|'ll|'d)|[^\r\n\p{L}\p{N}]?\p{L}+|\p{N}{1,3}| ?[^\s\p{L}\p{N}]+[\r\n]*|\s*[\r\n]|\s+(?!\S)|\s+

This pattern handles English contractions, Unicode letters, number groups (up to 3 digits), punctuation with optional spaces, and various whitespace configurations.

The Math Behind BPE
▼

BPE training constructs the merge table by greedily selecting the most frequent adjacent pair at each iteration. Given a corpus tokenized into byte sequences, at iteration \(k\):

$$\text{merge}_k = \underset{(a,b) \in V_k \times V_k}{\operatorname{argmax}} \; \text{count}(a,b) \quad \text{where } V_k \text{ is the vocabulary at step } k$$

The selected pair \((a,b)\) is replaced with a new symbol \(c = ab\), and \(V_{k+1} = V_k \cup \{c\}\). Training stops after a predetermined number of merges (e.g., 100,256 for cl100k_base minus the 256 base byte tokens).

Compression Ratio

The compression ratio \(r\) of a tokenizer is: \(r = \frac{\text{number of UTF-8 bytes}}{\text{number of tokens}}\). For cl100k_base on English text, \(r \approx 3.5\text{--}4.0\), meaning each token represents roughly 3.5–4 bytes. For code, \(r \approx 2.5\text{--}3.0\) since variable names produce less mergeable patterns.

Common Misconception

BPE merges are not re-learned at encoding time. The merge table is fixed during training. At encoding time, Tiktoken simply looks up which merges apply, in priority order. This makes encoding deterministic and fast — it is a pure lookup, not a frequency-counting step.

Evolution: r50k → p50k → cl100k
▼

OpenAI has iterated on its BPE vocabulary across model generations. Each new encoding improves efficiency, multilingual support, and handling of special content like code.

Encoding Vocab Size Models Key Change
r50k_base 50,257 GPT-2, davinci Original byte-level BPE; basic regex
p50k_base 50,281 GPT-3.5, text-davinci-003 Slightly expanded for code completions
cl100k_base 100,256 GPT-4, GPT-3.5-turbo 2x vocab, better multilingual + code, new regex
Why doubling vocabulary helps

A larger vocabulary means more common subwords get their own token, reducing the total token count for any given text. This directly reduces inference cost (which scales with sequence length) and allows longer effective context windows. GPT-4's cl100k_base typically uses 10–20% fewer tokens than r50k_base on the same English text, and up to 50% fewer on non-Latin scripts.

5
Key Takeaways
▼

When tokenization matters: Token count determines API cost, context window usage, and how the model "sees" your text. Understanding tokenization helps you write more efficient prompts, debug unexpected model behavior (like splitting a word mid-syllable), and estimate costs accurately.

Summary:

  • Tiktoken uses byte-level BPE — it can tokenize any byte sequence, never produces unknown tokens
  • Regex pre-splitting prevents cross-boundary merges, ensuring consistent tokenization
  • The merge table is static — encoding is a fast deterministic lookup, not training
  • cl100k_base (GPT-4) has ~100K tokens, ~2x more efficient than r50k_base (GPT-2)
  • Non-English text and rare words use more tokens per character than common English words
