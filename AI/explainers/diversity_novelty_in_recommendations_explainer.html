Understanding Diversity & Novelty
▼

What is it? A ranking model scores every candidate item independently and sorts by predicted relevance. But the top-K items by relevance alone are often near-duplicates: five sequels of the same franchise, five nearly identical sneakers. Users don't experience relevance in isolation — they experience the set you show them. Diversity-aware re-ranking chooses which items to show together, trading a little relevance for a lot less redundancy.

Analogy: A tapas menu that serves five variations of the same dish is technically "high quality" per-dish, but a bad meal. A good host picks dishes that are each good and different from each other. MMR is the host who compares each new dish to what's already on the table. DPP is the host who thinks about the whole table's "spread" at once — literally the geometric volume the dishes span in flavor space.

💡 If you remember one thing

Both methods score a set, not a list. MMR builds the set greedily with an explicit relevance–redundancy knob \(\lambda\): $$\text{MMR} = \arg\max_{i \in R \setminus S}\; \big[\lambda\, \text{rel}(i) \;-\; (1-\lambda)\max_{j \in S} \text{sim}(i,j)\big]$$ DPP instead defines a probability over every possible subset proportional to the determinant of a kernel: $$P(S) \propto \det(L_S)$$ where \(\det(L_S)\) is the squared volume spanned by the selected items' feature vectors — near-duplicate items span almost zero volume, so DPP naturally down-weights them.

How MMR and DPP Work Internally
▼

MMR: Greedy, One Item at a Time

MMR starts from a candidate pool \(R\) (e.g. the top-N items from a relevance model) and builds the shown set \(S\) greedily. At each step it scores every remaining candidate \(i\) by a mix of its own relevance and its worst-case similarity to anything already chosen, then adds the best-scoring one. Because it only looks at the single most-similar already-picked item, it is cheap — \(O(k \cdot n)\) for a set of size \(k\) from \(n\) candidates — and it is easy to explain and to tune live via \(\lambda\).

DPP: Probabilistic, Set-at-a-Time via a Kernel

A DPP is defined by a positive semi-definite kernel matrix \(L\), typically decomposed as \(L_{ij} = q_i\, q_j\, S_{ij}\), where \(q_i \ge 0\) is a quality score (relevance) for item \(i\) and \(S_{ij} \in [-1,1]\) is the similarity between items \(i\) and \(j\) (cosine similarity of embeddings, say). The probability of showing exactly subset \(S\) is proportional to \(\det(L_S)\) — the determinant of the sub-matrix of \(L\) restricted to rows/columns in \(S\). Geometrically, \(\det(L_S)\) is the squared volume of the parallelepiped spanned by the quality-scaled feature vectors of the items in \(S\). Similar items point in nearly the same direction, so that volume collapses toward zero — the model self-penalizes redundancy without any hand-set \(\lambda\).

Design Decision: Why not just re-rank by relevance − similarity?

MMR's greedy \(\max_j\) penalty only ever "looks back" at the single closest neighbor already picked — it can still leave 3 near-duplicates if they're all just far enough apart pairwise. DPP's determinant captures global set diversity: adding an item close to any subspace spanned by the current set shrinks volume, even if it isn't close to any single item. This is why exact DPP MAP inference is NP-hard, and why in practice we use a fast greedy approximation that is provably a good approximation to the optimal set.

🔑 Key Property

MMR trades relevance for diversity via an explicit dial \(\lambda \in [0,1]\): \(\lambda{=}1\) is pure top-K, \(\lambda{=}0\) is pure diversity (ignores relevance entirely). DPP has no such dial — quality and diversity are fused inside one kernel \(L\), and the greedy MAP algorithm approximately maximizes \(\log\det(L_S)\), which is submodular, giving a \((1-1/e)\) guarantee relative to the true optimum.

3
Why It Works — The Math
▼

MMR Objective

Given already-selected set \(S\) and remaining candidates \(R \setminus S\), MMR picks:

$$i^\star = \arg\max_{i \in R \setminus S} \Big[\lambda \cdot \text{rel}(i) - (1-\lambda) \cdot \max_{j \in S} \text{sim}(i, j)\Big]$$

When \(S = \emptyset\) the redundancy term is 0, so the very first pick is always the most relevant item regardless of \(\lambda\). Every subsequent pick balances "is this good on its own" against "is this too close to something I already picked."

DPP Kernel Decomposition & Determinant

With \(L = \text{Diag}(q)\, S\, \text{Diag}(q)\), for a 2-item subset \(\{i,j\}\):

$$\det(L_{\{i,j\}}) = \det\begin{bmatrix} q_i^2 & q_i q_j S_{ij} \\ q_i q_j S_{ij} & q_j^2 \end{bmatrix} = q_i^2 q_j^2 (1 - S_{ij}^2)$$

This is maximized when both items have high quality \(q_i, q_j\) and low similarity \(S_{ij}\) — quality and diversity multiply together rather than being linearly traded off. If \(S_{ij} \to 1\) (near-duplicates), the determinant collapses to 0 no matter how relevant both items are.

Fast Greedy MAP Inference (used in practice)

Exact subset selection maximizing \(\det(L_S)\) is NP-hard, so production systems use an incremental Cholesky-style greedy algorithm. Maintaining vectors \(c_i\) and residual "novelty" \(d_i^2\) for each unselected item, at each round:

$$j = \arg\max_i d_i^2, \qquad e_i = \frac{L_{ij} - c_j \cdot c_i}{d_j}, \qquad d_i^2 \mathrel{-}= e_i^2$$

\(d_i^2\) is exactly the marginal gain \(\log\det(L_{S\cup i}) - \log\det(L_S)\) in disguise — once an item is "explained away" by the current set (its \(d_i^2\) shrinks toward 0), it stops looking attractive even if its raw relevance \(q_i\) is high.

⚠️ Common Pitfall

Both methods depend entirely on the similarity metric you feed them. If your item embeddings only capture genre but the redundancy users actually feel is about mood or pacing, MMR/DPP will diversify the wrong axis. Diversity re-ranking never fixes a bad embedding space — garbage similarity in, garbage diversity out.

Key Takeaways
▼

When to reach for MMR:

  • You want a simple, explainable, tunable knob (\(\lambda\)) that product/ops can adjust per surface
  • Low latency re-ranking of a small shortlist (search results, session-level slates)
  • You only need "not too similar to what's already shown," not global set optimality

When to reach for DPP:

  • You want quality and diversity fused principled-ly, without hand-tuning a trade-off weight
  • Set-level optimality matters (e.g. a homepage carousel, a single "for you" shelf)
  • You can afford the extra \(O(k^2 n)\) of greedy MAP inference (still fast for typical slate sizes)
💡 Novelty vs Diversity

Diversity is about the relationship among shown items (don't show 5 near-duplicates). Novelty is about the relationship between shown items and the user's history (don't show what they've already seen or already know about). Both MMR and DPP generalize directly to novelty by swapping "similarity to other candidates" for "similarity to the user's past interactions" in the same formulas.

import numpy as np
# candidates: relevance q[i], embeddings x[i] (2D here, usually higher-D)
def sim(xi, xj):
return float(np.dot(xi, xj) / (np.linalg.norm(xi)*np.linalg.norm(xj)))
# ---- MMR: greedy, one item at a time ----
def mmr(candidates, q, x, k, lam=0.5):
S, R = [], list(range(len(candidates)))
while len(S) < k:
best, best_score = None, -1e9
for i in R:
red = max([sim(x[i], x[j]) for j in S], default=0.0)
score = lam*q[i] - (1-lam)*red
if score > best_score: best, best_score = i, score
S.append(best); R.remove(best)
return S
# ---- DPP: fast greedy MAP (Chen et al., 2018) ----
def dpp_greedy(L, k):
n = L.shape[0]
d2 = np.diag(L).copy() # marginal gain of adding i alone
c = np.zeros((k, n)) # Cholesky-style projection coeffs
S = []
for t in range(k):
j = int(np.argmax(d2))
S.append(j)
dj = np.sqrt(d2[j])
e = (L[j, :] - c[:t, j] @ c[:t, :]) / dj
c[t, :] = e
d2 -= e**2
d2[j] = -1e9 # never re-pick j
return S
