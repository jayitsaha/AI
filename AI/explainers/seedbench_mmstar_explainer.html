Understanding SEED-Bench & MMStar
▼

What is SEED-Bench? It is a large-scale multiple-choice benchmark for Multimodal Large Language Models (MLLMs) — 19K human-annotated questions spanning 12 evaluation dimensions of spatial (image) and temporal (video) understanding, from "what object is this" to "what action happens next." Because every question is graded as a 4-way multiple-choice pick, it can be scored cheaply and reproducibly by comparing the model's log-likelihood over option letters — no LLM judge needed.

What is MMStar? MMStar is not a new task type — it is an audit of benchmarks like SEED-Bench. Its authors discovered two quiet failure modes: (1) many questions can be answered correctly by a text-only LLM that never sees the image, because the question doesn't really need vision or because the answer already leaked into the LLM's pretraining text; (2) as a result, reported accuracy overstates genuine multimodal skill. MMStar hand-curates 1,500 vision-indispensable, leakage-minimized questions and proposes two diagnostic metrics — Multi-modal Gain (MG) and Multi-modal Leakage (ML) — that any benchmark can be scored on.

Analogy: Imagine grading a "picture comprehension" exam, but some students score well with the picture covered up — because the question text gives it away, or because they memorized the answer key. SEED-Bench is the exam; MMStar is the proctor who re-runs the exam with the picture covered, throws out every question that's still answerable, and keeps only the ones where covering the picture truly blinds the student.

💡 If you remember one thing

A benchmark's raw accuracy conflates two things: genuine visual reasoning and lucky/leaked guessing. MMStar splits them apart: $$MG = Acc_{vision} - Acc_{blind}, \qquad ML = \max(0,\, Acc_{blind} - Acc_{random})$$ High ML means the "multimodal" benchmark can be gamed without ever looking at the image.

How SEED-Bench Is Built — and Where It Leaks
▼

The 12-Dimension Taxonomy

SEED-Bench splits perception and cognition into 12 fine-grained dimensions: 9 spatial (image) dims — Scene Understanding, Instance Identity, Instance Attributes, Instance Location, Instance Counting, Spatial Relations, Instance Interaction, Visual Reasoning, Text Understanding — plus 3 temporal (video) dims — Action Recognition, Action Prediction, Procedure Understanding. Coverage this broad (19K questions, x6 more than prior benchmarks at release) is exactly why it became a default leaderboard.

The Generation Pipeline

For each dimension, source images/videos are annotated with dense ground-truth (objects, attributes, captions, timestamps), then an LLM (ChatGPT/GPT-4) is prompted with that ground-truth context to draft a question, the correct answer, and three plausible-but-wrong distractors. An automatic + human filtering pass removes ambiguous items and enforces the strict MCQ format, which is what makes scoring any MLLM trivial: just compare the likelihood the model assigns to "A"/"B"/"C"/"D".

Design Decision: Why Multiple-Choice, Not Open-Ended?

Open-ended answers need a second LLM to judge correctness — itself noisy, expensive and hard to reproduce across papers. Forcing every question into 4-way MCQ trades some expressiveness for a scoring function that is deterministic, cheap, and comparable across every model, forever. The cost of this convenience is exactly what MMStar exposes: an MCQ format that never tests "can you use the image" also never requires it — a text-only LLM can pattern-match distractors, exploit dataset-specific phrasing, or simply recall the answer from having seen similar captions during pretraining.

🔑 Key Property MMStar Checks For

A well-posed multimodal MCQ question must satisfy visual dependency (unanswerable by a blind LLM across several different LLM backbones), minimal data leakage (the correct option isn't simply memorized text), and must require advanced multimodal reasoning — not trivial OCR or color-naming a blind model could still fail at by chance alone.

The Math — Multi-modal Gain & Leakage
▼

Setup

Let a benchmark have \(N\) MCQ items, each with \(k\) options (SEED-Bench/MMStar use \(k=4\)). For item \(i\), define two indicator variables by evaluating the same question twice — once with the image, once with the image blanked out and given only to a text-only "blind" LLM:

$$c_i^{vision} = \mathbb{1}[\text{sighted model correct on } i], \qquad c_i^{blind} = \mathbb{1}[\text{blind LLM correct on } i]$$

Accuracies

$$Acc_{vision} = \frac{1}{N}\sum_{i=1}^N c_i^{vision}, \qquad Acc_{blind} = \frac{1}{N}\sum_{i=1}^N c_i^{blind}, \qquad Acc_{random} = \frac{1}{k}$$

Multi-modal Gain (MG)

MG measures how much the image actually helps — the genuine multimodal skill signal:

$$MG = Acc_{vision} - Acc_{blind}$$

Multi-modal Leakage (ML)

ML measures how much better than random chance the blind LLM does — i.e. how much of the benchmark is solvable from text priors, phrasing shortcuts, or memorized answers, with no image at all. It is clipped at zero because a blind model performing below chance is just noise, not "negative leakage":

$$ML = \max\!\big(0,\; Acc_{blind} - Acc_{random}\big)$$

MMStar's curation criterion for keeping a candidate item is precisely: low per-item leakage across several LLM backbones AND correct with vision — i.e. it selects for the population where \(ML \to 0\) and \(MG\) is maximized, so that raw accuracy on the curated set is (almost) entirely attributable to visual reasoning.

⚠️ Common Pitfall

A model can post a high raw accuracy on a leaky benchmark while its MG is near zero — meaning the score says almost nothing about its vision encoder or cross-modal fusion. Always report (Acc, MG, ML) as a triple; accuracy alone is not comparable across benchmarks with different leakage rates, and leaderboards that only show accuracy can rank a "blindfolded" model above a genuinely multimodal one.

Key Takeaways
▼

When broad benchmarks like SEED-Bench shine:

  • Fast, cheap, reproducible MCQ scoring across 12 fine-grained spatial/temporal dimensions
  • Wide coverage for tracking progress across many MLLM capabilities at once
  • Good for regression testing during model development, not for final leaderboard claims

When a curated audit like MMStar is necessary:

  • Comparing frontier models where a few accuracy points decide a leaderboard ranking
  • Publishing claims about "multimodal capability," not just next-token pattern-matching
  • Any benchmark reused for years — leakage grows over time as leaderboard answers and blog posts about the benchmark enter future pretraining corpora
💡 The Generalizable Lesson

MG and ML are not SEED-Bench/MMStar-specific — they are a general audit recipe for any multimodal (or even unimodal) benchmark: re-run every item with the "extra" modality removed, and report the gap. If removing the image barely changes accuracy, the benchmark isn't testing what its name claims.

import numpy as np
# results: one dict per MCQ item after running BOTH evaluation modes
# { 'dim': str, 'vision_correct': bool, 'blind_correct': bool }
def compute_metrics(results, num_choices=4):
n = len(results)
acc_vision = np.mean([r['vision_correct'] for r in results])
acc_blind = np.mean([r['blind_correct'] for r in results])
acc_random = 1.0 / num_choices
mg = acc_vision - acc_blind # Multi-modal Gain
ml = max(0.0, acc_blind - acc_random) # Multi-modal Leakage
return dict(n=n, acc_vision=acc_vision, acc_blind=acc_blind, mg=mg, ml=ml)
# MMStar-style curation: keep only vision-dependent, low-leakage items
def curate(candidates, blind_llm_votes, vote_threshold=1):
kept = []
for item, votes in zip(candidates, blind_llm_votes):
# votes = how many of several blind LLM backbones answered it correctly
if votes <= vote_threshold and item['vision_correct']:
kept.append(item) # low leakage + vision-dependent
return kept # -> human review -> final set
