Understanding Face Recognition
▼

What is Face Recognition? Unlike face detection (finding faces) or face verification (is this person who they claim to be?), face recognition (or identification) is an "open-set" problem: given an image, identify the person from a database of known individuals, or determine they are unknown. This requires learning a robust representation of a face.

Face Embeddings: The core idea is to transform a face image into a low-dimensional vector, called a face embedding. This embedding should capture the unique features of an individual's face. For effective recognition, embeddings of the same person should be very close in the embedding space, while embeddings of different people should be far apart.

Why not standard classification? Training a softmax classifier on millions of identities is problematic: it's an "open-set" problem (new people appear constantly), requires all identities during training, and doesn't explicitly optimize for distance relationships between embeddings. Metric learning approaches solve this by directly optimizing the embedding space geometry.

Analogy: Imagine you're organizing a library by topic. A standard classifier might assign each book a specific topic label. Face recognition, however, is like assigning each book a "topic vector" such that similar books (same author/genre) are shelved very close together, and dissimilar books (different authors/genres) are far apart. FaceNet, ArcFace, and CosFace are different strategies for defining "close" and "far."

💡 If you remember one thing

Face recognition models learn an embedding space where the distance between two face vectors directly indicates whether they belong to the same person. The goal is to maximize inter-class separation and minimize intra-class variance.

2
How It Works — The Loss Functions
▼

1. FaceNet (Triplet Loss)

Introduced by Google in 2015, FaceNet revolutionized face recognition by directly optimizing for face embeddings using a Triplet Loss. Instead of classifying faces, it learns an embedding \(f(x)\) from a Convolutional Neural Network (CNN) such that for any three face images — an Anchor (A), a Positive (P) (same person as A), and a Negative (N) (different person from A) — the distance between A and P is smaller than the distance between A and N by at least a margin \(\alpha\):

$$||f(x^a) - f(x^p)||_2^2 + \alpha < ||f(x^a) - f(x^n)||_2^2$$

A crucial aspect is hard triplet mining: selecting triplets (A, P, N) that are "hard" to distinguish, meaning \(d(A,P)\) is large or \(d(A,N)\) is small. Training on these hard examples forces the model to learn more discriminative features.

2. ArcFace (Additive Angular Margin Loss)

ArcFace (2019) is a state-of-the-art method that modifies the standard softmax classification loss to enforce angular separation in the embedding space. It works by adding an angular margin \(m\) to the angle between the feature vector \(\mathbf{f}\) (embedding) and the target class's weight vector \(\mathbf{W}_y\) (centroid) in a normalized hypersphere. The logits for the target class become \(s \cos(\theta_y + m)\), where \(s\) is a scaling factor and \(\theta_y\) is the angle between \(\mathbf{f}\) and \(\mathbf{W}_y\). This explicitly increases the angular separation requirement for correct classification.

3. CosFace (Additive Cosine Margin Loss)

CosFace (2018), also known as Large-Margin Cosine Loss (LMCL), is similar to ArcFace but applies the margin directly in the cosine space. Instead of modifying the angle, it subtracts a cosine margin \(m\) from the cosine similarity: \(s (\cos(\theta_y) - m)\). Both ArcFace and CosFace normalize the feature vectors and class weights to unit length, projecting them onto a hypersphere. This makes the dot product equivalent to cosine similarity, and thus the angle becomes the primary metric.

🔑 Key Differences

FaceNet uses a direct distance-based loss (triplet loss) on an L2-normalized embedding. ArcFace and CosFace are classification-based losses that modify the logits of a final linear layer by adding margins (angular for ArcFace, cosine for CosFace) to enforce stricter separation on a normalized hypersphere.

3
Why It Works — Mathematical Formulations
▼

1. FaceNet: Triplet Loss

Given an anchor embedding \(f_A\), a positive embedding \(f_P\), and a negative embedding \(f_N\), the triplet loss aims to satisfy \(||f_A - f_P||_2^2 + \alpha < ||f_A - f_N||_2^2\). This is formulated as:

$$L_{Triplet} = \max\left(0, ||f_A - f_P||_2^2 - ||f_A - f_N||_2^2 + \alpha\right)$$

Here, \(\alpha\) is a margin hyperparameter. The \(\max(0, \dots)\) ensures that the loss is zero if the condition is already met, preventing over-optimization. The embeddings \(f\) are typically L2-normalized, so \(||f||_2 = 1\). This loss directly pushes same-person embeddings closer and different-person embeddings further apart in Euclidean space.

2. ArcFace: Additive Angular Margin Loss

ArcFace modifies the standard softmax cross-entropy loss. For a feature vector \(\mathbf{f}_i\) (L2-normalized, \(||\mathbf{f}_i||=1\)) and class weight vectors \(\mathbf{W}_j\) (L2-normalized, \(||\mathbf{W}_j||=1\)), the original logit for class \(j\) is \(\mathbf{W}_j^\top \mathbf{f}_i = \cos(\theta_j)\). ArcFace transforms the target logit (\(j=y_i\)) by adding an angular margin \(m\):

$$L_{ArcFace} = -\frac{1}{N} \sum_{i=1}^N \log \frac{e^{s (\cos(\theta_{y_i} + m))}}{e^{s (\cos(\theta_{y_i} + m))} + \sum_{j \neq y_i} e^{s \cos(\theta_j)}}$$

The term \(s\) is a scaling factor (hyperparameter) that amplifies the angular differences, making the decision boundaries sharper. By increasing \(\theta_{y_i}\) to \(\theta_{y_i} + m\), the cosine value \(\cos(\theta_{y_i} + m)\) decreases, effectively pushing the feature \(\mathbf{f}_i\) further away from its target class center \(\mathbf{W}_{y_i}\) in angular space, creating more compact clusters.

3. CosFace: Additive Cosine Margin Loss

CosFace also modifies the softmax cross-entropy loss, but it applies the margin directly to the cosine similarity. For the target class \(y_i\), the logit is modified by subtracting a cosine margin \(m\):

$$L_{CosFace} = -\frac{1}{N} \sum_{i=1}^N \log \frac{e^{s (\cos(\theta_{y_i}) - m)}}{e^{s (\cos(\theta_{y_i}) - m)} + \sum_{j \neq y_i} e^{s \cos(\theta_j)}}$$

Similar to ArcFace, \(s\) is a scaling factor. Subtracting \(m\) from \(\cos(\theta_{y_i})\) for the target class effectively moves the decision boundary outwards from the class center. Both ArcFace and CosFace enhance inter-class separability and intra-class compactness by imposing stricter requirements on the decision boundaries.

📐 Geometric Intuition

For normalized features and weights, the decision boundary between two classes \(i\) and \(j\) is defined by \(\mathbf{W}_i^\top \mathbf{f} = \mathbf{W}_j^\top \mathbf{f}\). In angular space, this is \(\theta_i = \theta_j\). ArcFace shifts this boundary to \(\theta_i + m = \theta_j\), while CosFace shifts it to \(\cos(\theta_i) - m = \cos(\theta_j)\). Both methods create a "buffer zone" between classes.

Key Takeaways & Comparison
▼

Comparison Table

Feature FaceNet (Triplet Loss) ArcFace CosFace
Loss Type Metric Learning (distance-based) Classification-based (angular margin) Classification-based (cosine margin)
Embedding Space Euclidean distance Angular distance on hypersphere Cosine similarity on hypersphere
Margin Application Additive margin \(\alpha\) in Euclidean distance Additive margin \(m\) to angle \(\theta\) Additive margin \(m\) to cosine \(\cos(\theta)\)
Pros Directly optimizes distance, flexible for various tasks State-of-the-art accuracy, clear geometric interpretation, robust to pose/illumination Strong performance, simpler to implement than ArcFace's angular manipulation
Cons Complex hard triplet mining, slow convergence, sensitive to triplet selection Requires inverse cosine/cosine for margin, slightly higher computational cost per sample Less intuitive geometric interpretation compared to angular margin

When to use these methods:

  • Large-scale Face Recognition Systems: All three are designed for high-performance, high-accuracy face recognition and verification, especially with large datasets and many identities.
  • Open-Set Recognition: When the system needs to handle identities not seen during training, these metric learning approaches excel as they learn a generalizable embedding space.
  • Verification: Determining if two faces belong to the same person (e.g., passport control). The distance between their embeddings is compared against a threshold.

When NOT to use:

  • Small Datasets: For very small datasets, the complexity of these losses (especially triplet loss's mining) might lead to overfitting or unstable training. Simpler contrastive losses might be better.
  • Non-Face Applications: While the core ideas can be adapted to other metric learning tasks (e.g., person re-identification, fine-grained image retrieval), direct application without careful tuning of margins and scales may not yield optimal results.
💡 Evolution of Face Recognition Loss

The progression from FaceNet's direct distance optimization to ArcFace/CosFace's angular/cosine margin enforcement highlights a shift towards more geometrically intuitive and computationally efficient ways to achieve highly discriminative face embeddings, particularly by normalizing features onto a hypersphere.

Code Trace (Simplified PyTorch-like)
▼
import torch
import torch.nn.functional as F
# Assume a batch of L2-normalized embeddings `embeddings` (B, D)
# and corresponding `labels` (B)
# `W` is the classification layer weights (num_classes, D), also L2-normalized
def triplet_loss(anchor, positive, negative, margin=0.2):
# L2 distances (squared for simplicity as in original paper)
d_ap = torch.sum((anchor - positive)**2, dim=1)
d_an = torch.sum((anchor - negative)**2, dim=1)
loss = torch.relu(d_ap - d_an + margin)
return loss.mean()
def arcface_loss_logits(embeddings, labels, W, m=0.5, s=64.0):
# embeddings: (B, D), labels: (B), W: (num_classes, D)
cosine = F.linear(embeddings, W) # (B, num_classes)
theta = torch.acos(torch.clamp(cosine, -1.0 + 1e-7, 1.0 - 1e-7))
# Apply angular margin to target class's angle
one_hot = F.one_hot(labels, num_classes=W.size(0))
theta_target = theta[one_hot.bool()]
theta_target_margined = theta_target + m
# Replace original cosine with margined cosine for target class
cosine_margined = torch.cos(theta_target_margined)
logits = cosine.clone()
logits[one_hot.bool()] = cosine_margined
return logits * s # Scale logits
def cosface_loss_logits(embeddings, labels, W, m=0.35, s=64.0):
# embeddings: (B, D), labels: (B), W: (num_classes, D)
cosine = F.linear(embeddings, W) # (B, num_classes)
# Apply cosine margin to target class's cosine similarity
one_hot = F.one_hot(labels, num_classes=W.size(0))
cosine_target = cosine[one_hot.bool()]
cosine_target_margined = cosine_target - m
# Replace original cosine with margined cosine for target class
logits = cosine.clone()
logits[one_hot.bool()] = cosine_target_margined
return logits * s # Scale logits
