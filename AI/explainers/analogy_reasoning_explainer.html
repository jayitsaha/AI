Analogy Reasoning: king − man + woman = queen

How linear vector arithmetic in embedding space encodes relational meaning
Foundational NLP / Embeddings Word2Vec O(V·d) search
1
Understanding Analogy Reasoning
▼

What is it? Word embeddings map every word to a point (a vector) in a continuous, high-dimensional space, learned so that words used in similar contexts end up near each other. The famous demonstration of this geometry is: \(\vec{king} - \vec{man} + \vec{woman} \approx \vec{queen}\). If you take the vector for "king," subtract the vector for "man," add the vector for "woman," and then search for the closest word to the resulting point, you land on "queen" — not because anyone told the model about royalty or gender, but because that structure emerged purely from statistics of word co-occurrence.

Analogy: Picture a giant 3D city map where every word is a building. It turns out that "walking" from the "man" building to the "king" building takes you in roughly the same direction and distance as walking from "woman" to "queen" — a consistent "commoner → royalty" street. Once you know that street, you can start at any building on the "female side of town" and walk it to discover that building's royal counterpart.

Summary: Analogy reasoning treats semantic relationships (gender, tense, capital-of-country, plurality) as roughly constant offset vectors that can be added to or subtracted from any word vector to "transport" meaning.

💡 If you remember one thing

Relationships between words become directions in embedding space. Solve analogies with vector arithmetic, then find the nearest real word by cosine similarity: $$\underset{b^*}{\operatorname{argmax}}\ \cos\big(b^*,\ king - man + woman\big) = queen$$

2
How It Works Internally
▼

Where the Structure Comes From

Word2Vec's skip-gram objective trains each word's vector to be predictive of its surrounding context words (or vice versa, for CBOW). Two words that appear in similar contexts — "man" appears near "he," "his," "worker"; "king" appears near "he," "his," "throne" — are pushed to similar vectors along the dimensions that matter for those contexts, while contexts unique to royalty ("throne," "crown," "reign") push "king" and "queen" together along a different dimension. Because the same swap of "male-context words" for "female-context words" recurs across many word pairs (man/woman, king/queen, actor/actress, uncle/aunt), the optimizer ends up encoding "gender" as an approximately consistent, linear direction shared across all of them. This is the "linear substructure" hypothesis formalized by Mikolov et al. (2013).

Solving Analogies: the 3CosAdd Method

Given "a is to a* as b is to ?", compute the offset \(d = a^* - a\) and add it to \(b\) to get a target point \(t = b + d\). Since \(t\) is a fictitious point (probably no word sits exactly there), we search the vocabulary for the real word vector closest to \(t\), using cosine similarity rather than Euclidean distance — cosine similarity ignores each word's vector magnitude (which mostly reflects raw frequency, not meaning) and focuses purely on direction. We also explicitly exclude the input words \(a, a^*, b\) from the search, since they are always trivially close to \(t\).

Design Decision: Why Cosine, Not Euclidean Distance?

Frequent words tend to have larger vector norms during training. If we used Euclidean distance, common short words would dominate every nearest-neighbor search regardless of direction. Cosine similarity \(\cos(u,v) = \frac{u \cdot v}{\|u\|\|v\|}\) normalizes both vectors first, so only the angle between them — the semantic direction — matters. An alternative, 3CosMul (Levy & Goldberg, 2014), replaces the additive combination with a multiplicative one, which further reduces the tendency for any single large term to dominate the score.

🔑 Key Property

Analogy solving is nearest-neighbor search after vector translation: translate a query word by a learned relation vector, then retrieve. No new model, no gradient step — just arithmetic on frozen embeddings, which is why it became the go-to sanity check for embedding quality.

3
Why It Works — The Math
▼

The Parallelogram Assumption

Suppose a semantic relation \(r\) (e.g., "male → female") is encoded as an approximately constant offset across many word pairs: \(\vec{queen} - \vec{king} \approx \vec{woman} - \vec{man} \approx r\). Rearranging this single assumption directly gives the analogy formula:

$$\vec{queen} - \vec{king} \approx \vec{woman} - \vec{man} \implies \vec{queen} \approx \vec{king} - \vec{man} + \vec{woman}$$

Geometrically, the four points \(man, king, woman, queen\) form (approximately) a parallelogram: the edge from \(man\to king\) is parallel and equal in length to the edge from \(woman \to queen\).

3CosAdd, Formally

Generalizing "\(a\) is to \(a^*\) as \(b\) is to \(b^*\)", we solve for the unknown \(b^*\) by maximizing cosine similarity to the algebraic target:

$$\hat{b}^* = \underset{w \in V \setminus \{a,a^*,b\}}{\operatorname{argmax}}\ \cos\big(\vec{w},\ \vec{a}^* - \vec{a} + \vec{b}\big)$$

where \(\cos(u,v) = \dfrac{u \cdot v}{\|u\|\,\|v\|}\) and \(V\) is the vocabulary. Under the parallelogram assumption, the target \(\vec{a}^* - \vec{a} + \vec{b}\) sits arbitrarily close to \(\vec{b}^*\)'s true vector, so the \(\operatorname{argmax}\) recovers it exactly when the relation is perfectly linear, and approximately when it is only approximately linear (the realistic case).

⚠️ Common Pitfall

The parallelogram model is a useful approximation, not an exact law. Real embedding spaces exhibit "hubness" (some words are close to almost everything) and frequency effects that bias nearest-neighbor search. Analogies also fail when a relation isn't consistently linear across the vocabulary — e.g., irregular plurals, multi-sense words, or relations that depend on context. 3CosMul and vector-space debiasing techniques exist specifically to counter these failure modes.

Key Takeaways
▼

When it works well:

  • Syntactic relations: singular/plural, tense (walk/walked), comparative/superlative
  • Frequent, well-trained semantic relations: gender roles, capital-of-country, currency-of-country
  • Static embeddings trained on large corpora (word2vec, GloVe, fastText)

When it breaks down:

  • Rare words or relations with few training examples — the offset vector is noisy
  • Relations that aren't consistently linear (e.g., "capital of" fails for countries with multiple historical capitals)
  • Polysemous words, where a single vector conflates multiple meanings
  • Contextual embeddings (BERT, GPT) — a word doesn't have one fixed vector, so naive 3CosAdd applies less cleanly; relation vectors must be computed per-context or via probing
💡 Why It Still Matters

Analogy tests (Google's word2vec analogy dataset, BATS) became the standard intrinsic benchmark for embedding quality for years, and the linear-structure insight underlies later ideas like steering vectors and concept-editing directions in modern LLM interpretability — the same "add a direction, shift the meaning" trick, just in a much higher-dimensional, contextual space.

Code Trace
▼
import numpy as np
# Toy 6-D embedding table (real word2vec has d=100-300)
emb = {
"man": np.array([0.10, -1.0, 0.60, 1.0, 0.50, 0.20]),
"woman": np.array([0.10, 1.0, 0.60, 1.0, 0.40, 0.20]),
"king": np.array([1.00, -1.0, 0.80, 1.0, 0.55, 0.90]),
"queen": np.array([1.00, 1.0, 0.80, 1.0, 0.45, 0.90]),
# ... rest of vocabulary
}
def cosine(u, v):
return (u @ v) / (np.linalg.norm(u) * np.linalg.norm(v))
# Step 1: build the offset (relation) vector
d = emb["king"] - emb["man"] # "royalty" direction
# Step 2: translate woman by that offset
target = emb["woman"] + d # = king - man + woman
# Step 3: nearest-neighbor search, excluding the inputs
exclude = {"man", "king", "woman"}
best_word, best_score = None, -1
for word, vec in emb.items():
if word in exclude:
continue
score = cosine(vec, target)
if score > best_score:
best_word, best_score = word, score
print(best_word, best_score) # -> "queen" 1.000
