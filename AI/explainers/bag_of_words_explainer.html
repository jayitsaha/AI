Bag of Words (BoW)

Turning text into numbers by counting words, ignoring order
Foundational NLP Feature Engineering O(n·|V|)
1
Understanding Bag of Words
▼

What is it? Bag of Words is the simplest way to turn a piece of text into a vector of numbers a machine-learning model can use. It builds a vocabulary of every distinct word seen across a collection of documents, then represents each document as a count of how many times each vocabulary word appears in it — completely throwing away word order and grammar.

Analogy: Imagine dumping a sentence into a literal bag and shaking it up. All you can now do is reach in and count how many "cat" tokens, "the" tokens, "sat" tokens, etc. are inside. "The cat sat on the mat" and "the mat sat on the cat" produce the exact same bag — same words, same counts, order destroyed. That's the trade-off BoW makes for simplicity.

💡 If you remember one thing

BoW represents document \(d\) as a vector \(\mathbf{x}_d \in \mathbb{N}^{|V|}\) where \(|V|\) is the vocabulary size and each entry \(x_{d,i}\) is the raw count of vocabulary word \(w_i\) in \(d\): $$x_{d,i} = \text{count}(w_i, d)$$

2
How BoW Works Internally
▼

Step 1: Tokenization

Each raw string is lowercased and split into tokens — usually on whitespace and punctuation. "The Cat Sat on the Mat." becomes [the, cat, sat, on, the, mat]. This is the only place BoW looks at structure; after this, order is gone forever.

Step 2: Vocabulary Construction

Scan every document in the corpus and collect the set of distinct tokens — this is the vocabulary \(V\), typically sorted alphabetically or by first appearance so every document maps to the same fixed-length axis. Vocabulary size \(|V|\) can be in the tens of thousands for real corpora, which is why BoW vectors are extremely sparse (mostly zeros).

Step 3: Vectorization

For each document, walk its tokens and increment a counter at the vocabulary index of each word seen. The result is one row per document in a document-term matrix — rows are documents, columns are vocabulary words, cell \((d,i)\) is how many times word \(i\) appears in document \(d\).

Design Decision: Why counts and not just presence?

A simpler variant — binary BoW — only records whether a word appears (0/1), losing frequency information. Raw counts preserve "how much" a word dominates a document, which downstream weighting schemes like TF-IDF then refine by discounting words that are common across the whole corpus (like "the") and boosting words that are distinctive to a document.

🔑 Key Property

BoW is a bijection from multiset of tokens to count vector — it preserves exactly the frequency of every word and discards everything about position, adjacency, and syntax. Two documents with identical word multisets are indistinguishable to BoW, no matter how their meaning differs.

3
Why It Works — The Math
▼

Formalizing the Representation

Let the corpus vocabulary be \(V = \{w_1, w_2, \dots, w_{|V|}\}\). For document \(d\) with token sequence \(t_1, t_2, \dots, t_n\), the BoW vector is:

$$x_{d,i} = \sum_{k=1}^{n} \mathbb{1}[t_k = w_i], \qquad i = 1, \dots, |V|$$

where \(\mathbb{1}[\cdot]\) is the indicator function. This is exactly a histogram of tokens over the vocabulary alphabet — order of summation doesn't matter, which is precisely why word order is lost.

Similarity Between Documents

Once documents live in \(\mathbb{R}^{|V|}\), we can measure how similar two documents are with cosine similarity — the cosine of the angle between their count vectors, invariant to document length:

$$\cos(\mathbf{x}_a, \mathbf{x}_b) = \frac{\mathbf{x}_a \cdot \mathbf{x}_b}{\|\mathbf{x}_a\|_2 \, \|\mathbf{x}_b\|_2} = \frac{\sum_i x_{a,i} x_{b,i}}{\sqrt{\sum_i x_{a,i}^2}\sqrt{\sum_i x_{b,i}^2}}$$

A cosine of 1 means identical word-frequency profiles; 0 means no shared vocabulary at all. This is the backbone of classical information retrieval (search engines pre-embeddings) and text classification (Naive Bayes, logistic regression on BoW features).

⚠️ Common Pitfall

Because BoW is permutation invariant over tokens, "dog bites man" and "man bites dog" get identical vectors. Any downstream model trained purely on raw BoW counts is mathematically incapable of distinguishing them — you need n-grams, positional features, or sequence models (RNNs, Transformers) to recover word-order information.

Key Takeaways
▼

When to use BoW:

  • Fast baselines for text classification (spam filtering, sentiment analysis)
  • Document retrieval / search when combined with TF-IDF weighting
  • Topic modeling input (LDA, NMF operate on count/term matrices)
  • Interpretable, low-latency, no-GPU-required pipelines

When NOT to use:

  • Tasks needing word order or syntax (translation, generation, coreference)
  • Very short texts where vocabulary overlap is rare (extreme sparsity)
  • Tasks needing semantic similarity beyond exact word match — use embeddings instead
💡 Hierarchy

Binary BoW (presence only) ⊂ Count BoW (raw frequency) ⊂ TF-IDF (frequency reweighted by rarity) ⊂ N-gram BoW (adds local order) ⊂ Dense embeddings (learned semantic vectors). Each step trades simplicity for expressiveness.

Code Trace

from collections import Counter
import re, math
docs = [
"The cat sat on the mat",
"The dog sat on the log",
]
def tokenize(text):
return re.findall(r"[a-z]+", text.lower())
tokenized = [tokenize(d) for d in docs]
# [['the','cat','sat','on','the','mat'], ['the','dog','sat','on','the','log']]
# Build vocabulary: sorted set of all tokens
vocab = sorted(set(tok for doc in tokenized for tok in doc))
# ['cat','dog','log','mat','on','sat','the']
# Vectorize: count occurrences at each vocab index
def vectorize(tokens, vocab):
counts = Counter(tokens)
return [counts[w] for w in vocab]
X = [vectorize(t, vocab) for t in tokenized]
# X[0] = [1,0,0,1,1,1,2] X[1] = [0,1,1,0,1,1,2]
# Cosine similarity between the two documents
def cosine(a, b):
dot = sum(x*y for x, y in zip(a, b))
na = math.sqrt(sum(x*x for x in a))
nb = math.sqrt(sum(y*y for y in b))
return dot / (na * nb)
print(cosine(X[0], X[1])) # 0.75
