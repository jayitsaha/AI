Understanding XLNet
▼

What is it? XLNet is a powerful language model that addresses limitations of previous models like BERT. It combines the strengths of auto-regressive (AR) models (like GPT) and auto-encoding (AE) models (like BERT) without their respective drawbacks. It achieves this through two key innovations: Permutation Language Modeling (PLM) and integrating ideas from Transformer-XL, especially Relative Positional Encoding (RPE).

The Problem: BERT's Masked Language Model (MLM) objective creates a "discrepancy" between pre-training (with `[MASK]` tokens) and fine-tuning (no `[MASK]` tokens). Also, BERT assumes independence between masked tokens, which is untrue. Traditional AR models like GPT predict tokens one by one, limiting their ability to incorporate bidirectional context (a token can only see tokens to its left).

Analogy: Imagine learning a language by filling in blanks (BERT). You might guess "The [blank] fox" as "red" or "quick". But if you also know "jumps over the [blank] dog", you'd know "quick" is better. XLNet is like learning by predicting words in a scrambled sentence, always knowing all other words, just not their original order. It also remembers what happened in previous sentences (Transformer-XL) to understand long narratives.

💡 If you remember one thing

XLNet's Permutation Language Modeling (PLM) objective trains a model to predict tokens in a random permuted order, allowing each token to see full bidirectional context from all other tokens. This avoids BERT's mask discrepancy and captures dependencies better, while Transformer-XL's recurrence handles long-range dependencies efficiently.

How XLNet Works Internally
▼

1. Permutation Language Modeling (PLM)

Instead of predicting masked tokens (like BERT) or strictly left-to-right (like GPT), XLNet predicts tokens in a randomized permutation of the input sequence. For a given target token \(x_t\), it learns to predict \(x_t\) based on all other tokens \(x_{

To enable this, XLNet uses a Two-Stream Attention Mechanism:

  • Content Stream (f-stream): This is a standard Transformer self-attention. It computes a representation \(h_i\) that encodes both the token \(x_i\) and its positional context. When computing attention for token \(x_i\), it can attend to \(x_i\)'s own content and all tokens that come *before* \(x_i\) in the current permutation.
  • Query Stream (g-stream): This stream computes a representation \(g_i\) that *only* knows the position \(i\) and the context it attends to, but *not* the content of \(x_i\) itself. This is crucial for predicting \(x_i\). When computing attention for \(g_i\), it can attend to all tokens that come *before* \(x_i\) in the current permutation, plus the *content* of \(x_i\) from the f-stream, but it cannot see \(x_i\)'s own content. This ensures the prediction task is non-trivial.

The query stream is used to predict the target token, while the content stream is passed to the next layer to build richer representations.

2. Transformer-XL Integration

XLNet incorporates two key ideas from Transformer-XL to handle long-range dependencies and overcome the fixed-length context limitation of standard Transformers:

  • Segment Recurrence Mechanism: During training, hidden states from previous segments are cached and reused as "memory" for the current segment. This allows the model to attend to information far beyond the current segment's boundaries without increasing computational cost for the current segment.
  • Relative Positional Encoding (RPE): Instead of encoding absolute positions (which would be problematic with segment recurrence, as a token's absolute position changes across segments), XLNet uses relative positional encodings. This means the model learns how to attend based on the *distance* between tokens, rather than their fixed location.
🔑 Key Difference from BERT

BERT's MLM objective predicts masked tokens independently, assuming they are conditionally independent given unmasked tokens. This is a simplification. XLNet's PLM predicts tokens in a permuted order, ensuring that the prediction of one token can leverage the context of other predicted tokens in the permutation, leading to more coherent and context-aware representations.

Permutation Language Modeling Objective

Given a sequence \(x = [x_1, \dots, x_T]\), PLM considers all possible permutations \(z\) of the indices \([1, \dots, T]\). The objective is to maximize the expected log-likelihood of predicting each token \(x_{z_t}\) given the preceding tokens in the permuted sequence \(x_{z_{

Where \(\mathcal{P}_T\) is the set of all possible permutations of length \(T\). In practice, a subset of permutations is sampled. This objective is auto-regressive, but the permutation allows for bidirectional context.

The content stream \(h_i^{(l+1)}\) is computed as:

$$ h_i^{(l+1)} = \text{Attention}(Q=h_i^{(l)}, K=H_{z_{\le t}}^{(l)}, V=H_{z_{\le t}}^{(l)}) $$

The content stream \(h_i^{(l)}\) includes information about \(x_i\) itself. Thus, it can attend to its own content and the content of all tokens that precede it in the permutation. The content stream is passed to the next layer.

Relative Positional Encoding in Attention

Instead of adding absolute positional embeddings to queries and keys, XLNet modifies the attention score calculation to incorporate relative positional information. For a query at position \(i\) and a key at position \(j\), the attention score \(A_{i,j}\) is computed with four terms:

$$ A_{i,j} = \underbrace{q_i^\top k_j}_{\text{content-content}} + \underbrace{q_i^\top R_{ij}}_{\text{content-relative}} + \underbrace{u^\top k_j}_{\text{global-content}} + \underbrace{v^\top R_{ij}}_{\text{global-relative}} $$

Where \(q_i\) and \(k_j\) are the query and key vectors, \(R_{ij}\) is the relative positional embedding for the distance \(i-j\), and \(u, v\) are learnable global parameters representing a "content-agnostic" query vector and "position-agnostic" key vector, respectively. This allows the model to learn different types of relationships based on content and relative position, robustly handling long sequences and segment recurrence.

⚠️ Computational Cost

Generating all permutations for long sequences is computationally prohibitive. XLNet typically samples a subset of permutations and focuses on predicting a few target tokens within a "prediction window" in each permutation. This makes the training feasible but still more complex than BERT.

Key Takeaways
▼

When to use XLNet:

  • When long-range dependencies are crucial (e.g., document summarization, question answering over long texts).
  • When avoiding the pre-train/fine-tune discrepancy of BERT's `[MASK]` tokens is important for task performance.
  • For tasks requiring deep contextual understanding where bidirectional context is vital for every token.
  • When state-of-the-art performance is desired, and computational resources allow.

Advantages over BERT:

  • No Masking Discrepancy: PLM avoids the artificial `[MASK]` tokens, making pre-training more consistent with fine-tuning.
  • Better Context Modeling: PLM allows each token to see full bidirectional context (from other tokens in the permutation), unlike BERT's conditional independence assumption for masked tokens.
  • Longer Context: Transformer-XL's segment recurrence mechanism allows XLNet to process and leverage much longer input sequences effectively.

Limitations:

  • Computational Cost: The permutation sampling and two-stream attention add significant computational overhead during pre-training compared to BERT.
  • Complexity: The architecture and training objective are more intricate, making it harder to debug or modify.
💡 Impact

XLNet demonstrated that combining the best aspects of auto-regressive and auto-encoding models, along with efficient long-range context handling, could push the boundaries of language understanding, influencing subsequent models to explore more sophisticated pre-training objectives.

self.d_head = d_model // n_head
