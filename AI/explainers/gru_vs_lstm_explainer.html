GRU vs LSTM

Simplified architecture, comparable performance, fewer parameters
Foundational Deep Learning RNNs Intermediate
1
Understanding GRU and LSTM
▼

Recurrent Neural Networks (RNNs) are powerful for sequential data, but vanilla RNNs struggle with long-term dependencies due to vanishing/exploding gradients. To overcome this, Long Short-Term Memory (LSTM) networks were introduced.

LSTMs use a "cell state" and various "gates" (forget, input, output) to regulate the flow of information, allowing them to remember or forget information over long sequences. This solved the vanishing gradient problem effectively.

However, LSTMs are complex and computationally intensive. This led to the development of Gated Recurrent Units (GRUs), a simpler variant proposed by Cho et al. in 2014, which combines some of LSTM's gates.

💡 If you remember one thing

GRUs achieve performance comparable to LSTMs on many tasks, but with fewer parameters and a simpler architecture. This often means faster training and less memory usage, making them a popular choice for sequence modeling.

2
How They Work Internally
▼

LSTM: The Three Gates and Cell State

An LSTM cell at time step \(t\) takes the current input \(x_t\), the previous hidden state \(h_{t-1}\), and the previous cell state \(C_{t-1}\). It produces a new hidden state \(h_t\) and a new cell state \(C_t\).

  • Forget Gate (\(f_t\)): Decides what information to discard from the cell state. It outputs a number between 0 and 1 for each value in \(C_{t-1}\).
  • Input Gate (\(i_t\)): Decides what new information to store in the cell state. It works with the Candidate Cell State (\(\tilde{C}_t\)), which is a new candidate for the cell state.
  • Cell State Update (\(C_t\)): The old cell state \(C_{t-1}\) is multiplied by \(f_t\) (forgetting old info), then new candidate info \(i_t \odot \tilde{C}_t\) is added.
  • Output Gate (\(o_t\)): Decides what parts of the cell state to output as the hidden state \(h_t\).

GRU: Two Gates, No Separate Cell State

A GRU cell at time step \(t\) takes the current input \(x_t\) and the previous hidden state \(h_{t-1}\). It produces a new hidden state \(h_t\). GRUs merge the cell state and hidden state into a single "hidden state".

  • Update Gate (\(z_t\)): Combines the functionality of LSTM's forget and input gates. It decides how much of the previous hidden state to carry over and how much of the new candidate hidden state to incorporate.
  • Reset Gate (\(r_t\)): Decides how much of the previous hidden state to "forget" when calculating the new candidate hidden state. A small \(r_t\) means the candidate hidden state largely ignores the past.
  • Candidate Hidden State (\(\tilde{h}_t\)): This is similar to LSTM's candidate cell state, but it uses the reset gate to potentially "reset" the influence of the previous hidden state.
  • Hidden State Update (\(h_t\)): The new hidden state is a linear interpolation between the previous hidden state and the candidate hidden state, controlled by the update gate.
🔑 Key Difference

LSTMs maintain a separate cell state (\(C_t\)) and hidden state (\(h_t\)), while GRUs merge these into a single hidden state. This simplification in GRUs leads directly to fewer parameters.

3
Why GRU is Simpler: The Math
▼

LSTM Equations

Each gate and the candidate cell state in an LSTM involves a linear transformation (matrix multiplication) of the concatenated input \([h_{t-1}, x_t]\) followed by an activation function. Let \(D_x\) be the input dimension and \(D_h\) be the hidden dimension.

$$f_t = \sigma(W_f x_t + U_f h_{t-1} + b_f)$$ $$i_t = \sigma(W_i x_t + U_i h_{t-1} + b_i)$$ $$\tilde{C}_t = \tanh(W_C x_t + U_C h_{t-1} + b_C)$$ $$C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t$$ $$o_t = \sigma(W_o x_t + U_o h_{t-1} + b_o)$$ $$h_t = o_t \odot \tanh(C_t)$$

For each of the four components (\(f_t, i_t, \tilde{C}_t, o_t\)), there's an input weight matrix (\(W\)), a recurrent weight matrix (\(U\)), and a bias vector (\(b\)).

  • Size of each \(W\) matrix: \(D_h \times D_x\)
  • Size of each \(U\) matrix: \(D_h \times D_h\)
  • Size of each \(b\) vector: \(D_h\)

Since there are 4 such transformations, the total number of parameters for an LSTM cell is:

$$N_{LSTM} = 4 \times (D_h D_x + D_h D_h + D_h)$$

GRU Equations

GRUs simplify this by combining the forget and input gates into a single update gate, and removing the separate cell state. The output gate is also merged into the main hidden state update.

$$z_t = \sigma(W_z x_t + U_z h_{t-1} + b_z) \quad \text{(Update Gate)}$$ $$r_t = \sigma(W_r x_t + U_r h_{t-1} + b_r) \quad \text{(Reset Gate)}$$ $$\tilde{h}_t = \tanh(W_h x_t + U_h (r_t \odot h_{t-1}) + b_h) \quad \text{(Candidate Hidden State)}$$ $$h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t \quad \text{(New Hidden State)}$$

Notice there are only 3 sets of \(W, U, b\) parameters for the \(z_t, r_t, \tilde{h}_t\) calculations. The element-wise product \(r_t \odot h_{t-1}\) does not introduce new parameters.

  • Size of each \(W\) matrix: \(D_h \times D_x\)
  • Size of each \(U\) matrix: \(D_h \times D_h\)
  • Size of each \(b\) vector: \(D_h\)

Therefore, the total number of parameters for a GRU cell is:

$$N_{GRU} = 3 \times (D_h D_x + D_h D_h + D_h)$$
🧮 Parameter Count Comparison

From the formulas, it's clear that GRU has \(1/4\) fewer parameters than LSTM for the same input and hidden dimensions. This translates to \(25\%\) fewer weights and biases, directly reducing model complexity and memory footprint.

Key Takeaways
▼

When to use GRU:

  • When computational efficiency and faster training are critical.
  • For smaller datasets where a simpler model might generalize better.
  • When you need good performance but want to reduce model complexity and memory footprint.
  • Often a good default choice, especially in early experimentation.

When to prefer LSTM:

  • For very long sequences and complex tasks where the explicit cell state might offer a slight edge in capturing long-term dependencies.
  • When interpretability of the separate cell state is desired (though still challenging).
  • When you have ample computational resources and a large dataset that can benefit from the additional capacity.
💡 Practical Advice

In practice, the choice between GRU and LSTM often comes down to empirical performance on your specific task. Start with GRU for its simplicity, and switch to LSTM if it demonstrably performs better, or if you encounter specific long-term memory issues that GRU can't resolve.

Code Trace: Parameter Calculation
▼
import torch
import torch.nn as nn
# Define input and hidden dimensions
input_size = 10 # D_x
hidden_size = 32 # D_h
print(f"Input Size (D_x): {input_size}")
print(f"Hidden Size (D_h): {hidden_size}\n")
# --- LSTM Parameters ---
lstm_cell = nn.LSTMCell(input_size, hidden_size)
lstm_params = sum(p.numel() for p in lstm_cell.parameters())
print(f"LSTMCell parameters (PyTorch): {lstm_params}")
# Manual calculation for LSTM:
# 4 gates (forget, input, candidate, output)
# Each gate: (W_x * D_x + U_h * D_h + bias) * D_h
lstm_manual_params = 4 * (hidden_size * input_size + hidden_size * hidden_size + hidden_size)
print(f"LSTMCell parameters (Manual): {lstm_manual_params}\n")
# --- GRU Parameters ---
gru_cell = nn.GRUCell(input_size, hidden_size)
gru_params = sum(p.numel() for p in gru_cell.parameters())
print(f"GRUCell parameters (PyTorch): {gru_params}")
# Manual calculation for GRU:
# 3 gates (update, reset, candidate)
# Each gate: (W_x * D_x + U_h * D_h + bias) * D_h
gru_manual_params = 3 * (hidden_size * input_size + hidden_size * hidden_size + hidden_size)
print(f"GRUCell parameters (Manual): {gru_manual_params}\n")
# Comparison
print(f"GRU has {lstm_params - gru_params} fewer parameters than LSTM.")
print(f"This is {((lstm_params - gru_params) / lstm_params * 100).toFixed(1)}% fewer parameters.")
