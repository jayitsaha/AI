Data Type Inconsistencies

Part III · Classical ML / Data Cleaning · Section 1.3.1
Intermediate Data Cleaning Feature Engineering Must Know
1
Understanding the Problem

Real-world data is entered by humans, scraped from the web, or merged from multiple systems — and humans are inconsistent. A column that should hold numbers might contain "$1,200", "1.2k", 1200, and "N/A" all in the same column. A date column may mix "2024-01-15" with "Jan 15, 2024". Boolean fields may hold "yes", "TRUE", 1, and "no".

Machine learning models cannot work with such heterogeneity. They need arrays of uniform numeric type. Type inconsistencies are therefore one of the very first things you fix in any data pipeline — before any model, before any feature transformation, before any EDA plot.

Key Concept

A data type inconsistency exists whenever values in the same logical column belong to different Python/pandas types, or carry different implicit units/formats that make direct comparison or arithmetic incorrect. Detection is forensic; resolution is a parse + coerce pipeline.

💡 If you remember one thing

Type inconsistency is not just a Python dtype problem — it is a semantic problem. "1.2k" and 1200 have the same meaning but different representations. Fixing the dtype alone is not enough; you must also normalise the value.

2
The Three-Phase Detect → Parse → Coerce Pipeline

Phase 1 — Detect: Scan the column for type diversity. Key signals:

  • pandas dtype is object (catch-all for mixed types)
  • df[col].apply(type).value_counts() returns more than one type
  • Regex patterns: currency symbols ($), multiplier suffixes (k, M), comma separators, date formats, boolean words
  • Attempt pd.to_numeric(col, errors='coerce') — any NaN introduced = non-numeric string lurking

Phase 2 — Parse (normalise representation): Map every surface form to a canonical numeric or typed value. This is domain-specific. For monetary columns:

  • Strip $, €, £, commas, spaces
  • Expand multipliers: k → ×1 000, M → ×1 000 000
  • Handle sentinel strings: "N/A", "–", "None" → np.nan

Phase 3 — Coerce (enforce dtype): After parsing, cast to the target dtype using pandas:

  • pd.to_numeric(col) for int/float
  • pd.to_datetime(col, infer_datetime_format=True) for dates
  • col.map({'yes':True,'no':False,...}).astype(bool) for booleans
⚠️ Common Mistake

Calling df[col].astype(float) directly on a dirty column silently fails or raises ValueError. Always parse first, then coerce. Validate after coercion by checking that no unexpected NaNs were introduced.

3
Why This Matters — Information-Theoretic View

Consider a column \(X\) with \(n\) rows where \(k\) rows carry numeric values and \(m = n - k\) rows carry string representations of the same quantity. If we naively treat the column as categorical (label-encode it), we create a cardinality of up to \(n\) distinct tokens. The effective information content the model can extract is measured by mutual information \(I(X; Y)\) with the target \(Y\).

$$I(X_{\text{dirty}}; Y) \ll I(X_{\text{clean}}; Y)$$

String-encoded numbers carry the same semantic information as their numeric counterparts, but a model that sees them as categorical treats "1200" and 1200 as unrelated categories with no ordinal or continuous relationship. This destroys any monotone signal. Formally, the Fano inequality bounds prediction error from below when features are corrupted:

$$H(Y \mid X_{\text{dirty}}) \geq H(Y \mid X_{\text{clean}})$$

Even for mixed-format numeric columns, arithmetic breaks: the mean of \(\{1200, \texttt{"1.2k"}, \texttt{"\$1,200"}\}\) as strings is undefined, while as floats it is \(1200.0\). The parse + coerce step is what makes the column's semantic content accessible to any downstream model or statistic.

Mathematical Invariant

After cleaning, for any two rows \(i, j\) representing the same quantity \(v\), we require \(x_i = x_j = v\) exactly. Before cleaning, \(x_i = \texttt{"\$1,200"}\) and \(x_j = 1200\) violates this — they share meaning but not representation.

import re, numpy as np, pandas as pd
raw = ["$1,200", "1200", "1.2k", "2024-01-15",
"yes", "850.0", "N/A", "2.5M"]
SENTINELS = {"n/a", "none", "null", "nan", "-", ""} # → NaN
BOOL_MAP = {"yes":1,"no":0,"true":1,"false":0,"y":1,"n":0}
def detect_pattern(val):
v = str(val).strip()
if v.lower() in SENTINELS: return "missing"
if v.lower() in BOOL_MAP: return "bool-string"
if re.match(r'^\d{4}-\d{2}-\d{2}$', v): return "date-iso"
if re.match(r'^[\$€£]?[\d,]+(\.\d+)?[kKmMbB]?$', v): return "numeric-variant"
return "unknown"
def parse_value(val):
v = str(val).strip()
if v.lower() in SENTINELS: return np.nan
if v.lower() in BOOL_MAP: return float(BOOL_MAP[v.lower()])
if re.match(r'^\d{4}-\d{2}-\d{2}$', v): # days since epoch
return (pd.Timestamp(v) - pd.Timestamp("1970-01-01")).days
v = re.sub(r'[\$€£,\s]', '', v) # strip symbols
multipliers = {'k':1e3,'m':1e6,'b':1e9}
if v[-1].lower() in multipliers:
return float(v[:-1]) * multipliers[v[-1].lower()]
return float(v)
clean = [parse_value(v) for v in raw] # apply to column
s = pd.Series(clean, dtype="float64") # enforce dtype
