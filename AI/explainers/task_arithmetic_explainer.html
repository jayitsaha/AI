Task Arithmetic: Adding & Subtracting Task Vectors

Combining and disentangling model behaviors by vector math in weight space
Intermediate Deep Learning Model Editing O(N) weights
1
Understanding Task Arithmetic
▼

What is it? Task arithmetic is a technique that allows for the combination, amplification, or disentanglement of specific behaviors in large language models (LLMs) by performing simple vector operations (addition, subtraction, scaling) on their weight differences. These "task vectors" represent the changes a model undergoes when finetuned for a specific task, typically defined as the difference between the finetuned model's weights and the original base model's weights.

Analogy: Imagine a master chef with a base recipe for a plain cake (\(W_{base}\)). To make a "chocolate" cake, they add specific chocolate ingredients (\(W_{chocolate}\)). To make a "vanilla" cake, they add vanilla ingredients (\(W_{vanilla}\)). The "chocolate task vector" is the difference in ingredients between the chocolate cake and the plain cake. Similarly for vanilla. Now, if the chef wants a "chocolate-vanilla swirl" cake without making a new recipe from scratch, they can combine the "chocolate task vector" and the "vanilla task vector" and apply them to the base recipe. To remove the "chocolate" flavor from a chocolate cake, they'd subtract the chocolate task vector.

💡 If you remember one thing

A task vector is defined as the difference between a model's weights after finetuning on a specific task (\(W_{finetuned}\)) and the original base model's weights (\(W_{base}\)): $$V_{task} = W_{finetuned} - W_{base}$$ Task arithmetic then involves linearly combining these \(V_{task}\) vectors (e.g., \(W_{new} = W_{base} + V_A + V_B\)) to create models with composite behaviors.

2
How It Works Internally
▼

The Core Mechanism

The process of task arithmetic typically follows these steps:

  1. Base Model (\(W_{base}\)): Start with a large, general-purpose pretrained model (e.g., Llama 2, GPT-3). This model serves as the neutral reference point.
  2. Task-Specific Finetuning (\(W_A, W_B\)): Create several finetuned versions of the base model. For example, finetune \(W_{base}\) on Task A (e.g., sentiment analysis) to get \(W_A\), and on Task B (e.g., humorous style generation) to get \(W_B\).
  3. Task Vector Creation (\(V_A, V_B\)): Calculate the difference vector for each finetuned model: \(V_A = W_A - W_{base}\) and \(V_B = W_B - W_{base}\). These vectors capture the specific changes in the model's weights that correspond to learning each task. The subtraction is element-wise across all weights in the model.
  4. Vector Arithmetic (\(W_{new}\)): Combine these task vectors through addition, subtraction, or scalar multiplication to create a new, desired composite behavior. For instance, to get a model that performs both Task A and Task B, you might compute \(W_{new} = W_{base} + V_A + V_B\).
  5. Inference: The newly constructed model \(W_{new}\) can then be used for inference, ideally exhibiting the combined or modified behaviors.

The operations are performed element-wise across all parameters (weights and biases) of the model. This means if a model has millions or billions of parameters, each parameter (or corresponding tensor element) is individually added, subtracted, or scaled.

Design Decision: Why does this work?

The underlying hypothesis of task arithmetic is that the "knowledge" or "skill" for a specific task is encoded in a somewhat linear or separable manner within the high-dimensional weight space of a neural network. When a model is finetuned, it moves from the \(W_{base}\) point to \(W_{finetuned}\) along a specific "task direction." By adding or subtracting these directional vectors, we are essentially navigating this weight space to combine or disentangle these learned directions. While this linearity is a simplification, it has been empirically shown to be surprisingly effective for many tasks, especially in large, overparameterized models.

🔑 Key Property

Task arithmetic relies on the assumption that finetuning induces changes in the weight space that are sufficiently independent and additive for different tasks. The base model acts as a common reference point, allowing the task vectors to represent relative changes rather than absolute weight values.

3
Why It Works — The Math
▼

Formalizing Task Vectors

Let \(W_0\) denote the weights of the base (pre-trained) model. Suppose we finetune \(W_0\) on Task A to obtain \(W_A\), and on Task B to obtain \(W_B\). The task vectors \(V_A\) and \(V_B\) are then defined as:

$$V_A = W_A - W_0$$
$$V_B = W_B - W_0$$

These vectors represent the change in weights from the base model that imbues it with the capabilities for Task A and Task B, respectively. All operations (subtraction, addition) are element-wise across all corresponding parameters.

Combining Tasks

To create a new model \(W_{A+B}\) that exhibits the behaviors of both Task A and Task B, we can add their respective task vectors to the base model:

$$W_{A+B} = W_0 + V_A + V_B$$

Notice that this can also be expressed by adding a task vector to an already finetuned model. By substituting \(V_A = W_A - W_0\) into the equation above, we get:

$$W_{A+B} = W_0 + (W_A - W_0) + V_B = W_A + V_B$$

This means we can combine tasks either by adding all task vectors to the base model, or by adding a new task vector to an existing finetuned model. Similarly, \(W_{A+B} = W_B + V_A\).

Subtracting and Scaling Tasks

The arithmetic extends to subtraction and scalar multiplication. For instance, to "remove" the effect of Task A from a model finetuned on Task A (i.e., revert to the base model):

$$W_{A-A} = W_A - V_A = W_A - (W_A - W_0) = W_0$$

To amplify or attenuate the effect of a task, we can apply a scalar factor \(\alpha\) to its task vector:

$$W_{\alpha A} = W_0 + \alpha V_A$$

This allows for fine-grained control, where \(\alpha > 1\) might enhance the task's influence, and \(0 < \alpha < 1\) might soften it. A negative \(\alpha\) could even reverse a task's effect, for example, turning a "positive sentiment" model into a "negative sentiment" one.

⚠️ Common Pitfall

The effectiveness of task arithmetic is highly dependent on the tasks and the model architecture. Not all tasks combine linearly without interference; complex or conflicting behaviors may not yield desired results. Furthermore, the "task vector" is a simplified representation, and a task's true essence is unlikely to be purely linear in weight space. Empirically, it works best for distinct, somewhat orthogonal tasks.

Key Takeaways
▼

When to use task arithmetic:

  • Combining behaviors: To imbue a single model with multiple distinct capabilities (e.g., generating code and poetry) without costly sequential finetuning or multi-task learning.
  • Disentangling/Removing behaviors: To remove an undesirable trait (e.g., toxicity, bias) from a finetuned model by subtracting a corresponding task vector.
  • Amplifying/Attenuating: To fine-tune the strength of a learned behavior (e.g., making a model "more creative" or "less verbose") using scalar multipliers.
  • Rapid experimentation: Quickly prototype new model behaviors by combining existing task vectors, saving significant computational resources compared to full finetuning.
  • With large pretrained models: The technique is particularly effective for large models where finetuning from scratch is prohibitively expensive.

When NOT to use:

  • Highly non-linear tasks: If the underlying tasks interact in a complex, non-additive manner in weight space, simple vector arithmetic might lead to degraded performance or unexpected behaviors.
  • Conflicting tasks: Tasks with inherently contradictory objectives might not combine well.
  • Small models: The linearity assumption may hold less true for smaller models or those with less capacity, where weight changes might be more intertwined.
  • When precise, optimal performance is critical: While powerful for exploration, task arithmetic may not always yield models as performant as those achieved through dedicated finetuning or multi-task learning for specific combinations.
💡 Big Picture

Task arithmetic offers a powerful, intuitive, and computationally efficient paradigm for controlling and understanding the capabilities of large neural networks. It treats learned behaviors as navigable directions in weight space, opening avenues for model customization far beyond traditional finetuning.

Code Trace (PyTorch-like Example)
▼
import torch
# Assume we have model weights as state_dict objects
# W_0: Base model (e.g., Llama-2-7B)
# W_A: Finetuned on Task A (e.g., sentiment analysis)
# W_B: Finetuned on Task B (e.g., creative writing)
# (In reality, these are loaded from checkpoints)
W_0 = {name: torch.randn(1024, 1024) for name in ['layer1.weight', 'layer2.weight']}
W_A = {name: W_0[name] + torch.randn(1024, 1024) * 0.1 for name in W_0}
W_B = {name: W_0[name] + torch.randn(1024, 1024) * 0.15 for name in W_0}
# 1. Compute Task Vectors
V_A = {name: W_A[name] - W_0[name] for name in W_0}
V_B = {name: W_B[name] - W_0[name] for name in W_0}
# 2. Perform Task Arithmetic (Example: W_0 + V_A + V_B)
# This creates a model with both Task A and Task B capabilities
W_combined_AB = {}
for name in W_0:
W_combined_AB[name] = W_0[name] + V_A[name] + V_B[name]
# 3. Example: Scale a task vector (e.g., amplify Task A)
alpha = 1.5 # amplify Task A's effect
W_scaled_A = {}
for name in W_0:
W_scaled_A[name] = W_0[name] + alpha * V_A[name]
# 4. Example: Subtract a task vector (e.g., remove Task A from W_A)
W_reverted_to_base = {}
for name in W_A:
W_reverted_to_base[name] = W_A[name] - V_A[name]
# W_reverted_to_base should now be very close to W_0
# print(f"Max diff W_0 vs W_reverted: {max(torch.max(torch.abs(W_0[n] - W_reverted_to_base[n])) for n in W_0):.2e}")
