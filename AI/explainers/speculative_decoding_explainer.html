Speculative Decoding: Draft Model + Verification

Accelerating LLM inference by drafting multiple tokens and verifying them in parallel
Intermediate Deep Learning LLMs ~2-4× speedup
1
Understanding Speculative Decoding
▼

What is it? Speculative decoding is a powerful technique to accelerate the inference speed of large language models (LLMs) without any loss in output quality. It works by employing a smaller, faster "draft" model to quickly generate a sequence of candidate tokens. These candidates are then simultaneously fed into the larger, higher-quality "main" model for verification. If the draft tokens are found to be consistent with the main model's distribution, multiple tokens are accepted in a single step, leading to significant speedups.

Analogy: Imagine a master chef (the main LLM) who is very precise but a bit slow. To speed things up, they hire an eager apprentice (the draft model) who can quickly chop vegetables. The apprentice rapidly chops several ingredients, then the master chef quickly glances over all of them. If all the apprentice's cuts are perfect, the master approves them all at once. If the master spots a single imperfect cut, they stop, correct it, and the apprentice must restart chopping from that corrected point. The final dish (the generated text) is still exactly what the master chef would have produced, but it was prepared much faster.

💡 If you remember one thing

Speculative decoding offers a "free lunch" speedup: the generated output is guaranteed to be identical (probabilistically) to the main model's output, but generated much faster. The core trick is replacing many sequential main model forward passes with a single, parallel batch verification pass.

How It Works Internally
▼

The process of speculative decoding involves a tight loop between a smaller, faster draft model and the larger, more capable main model. Here's the typical sequence of operations for generating a new set of tokens:

The Core Loop

  1. Initial Generation: The main model generates the very first token given the prompt. This sets the initial context.
  2. Drafting Phase: Given the current sequence of accepted tokens, the smaller, faster draft model generates a short sequence of \(k\) candidate tokens, one after another. This is fast because the draft model is small.
  3. Parallel Verification: The larger, higher-quality main model takes the original sequence plus all \(k\) drafted tokens. It performs a single parallel forward pass over this entire sequence (length \(N+k\)), computing its probability distribution for the next token at *each* of the \(k\) candidate positions. This is the main source of speedup.
  4. Acceptance/Rejection Phase: We iterate through the \(k\) drafted tokens. For each drafted token \(t_i\), we perform a probabilistic check:
    • Compare the draft model's probability \(P_d(t_i)\) for \(t_i\) with the main model's probability \(P_m(t_i)\) for \(t_i\) at that position.
    • If a random number is less than or equal to \(\min(1, P_m(t_i) / P_d(t_i))\), the token is accepted. We move to the next drafted token.
    • If the check fails, the token is rejected. This token and all subsequent drafted tokens are discarded. A new token is then sampled from an adjusted distribution derived from the main model's probabilities at that specific position. The entire drafting process restarts from this newly sampled token.
  5. Fallback Sampling: If all \(k\) drafted tokens are accepted, or if the draft model's sequence is exhausted, the next token is sampled from the main model's distribution (adjusted to account for the acceptance probabilities). This ensures the output distribution remains faithful to the main model.

Key Components

  • Draft Model: A smaller, computationally cheaper LLM (e.g., a distilled version of the main model, or a model with fewer layers/parameters). Its role is to propose plausible continuations rapidly.
  • Main Model: The large, high-quality LLM whose output distribution we want to preserve. Its role is to verify the draft and generate tokens when the draft fails.
  • Parallelism: The critical insight is that the main model's verification can be batched. Instead of running the main model \(k\) times sequentially (once for each token), it runs once on a batch of \(k\) positions. This leverages GPU tensor cores efficiently.
🔑 Key Property

The output sequence produced by speculative decoding is statistically indistinguishable from the sequence produced by the main model generating tokens one by one. The acceptance/rejection mechanism and adjusted sampling ensure that the true target distribution of the main model is always matched at each step.

Why It Works — The Math
▼

The mathematical genius of speculative decoding lies in its ability to reproduce the exact probability distribution of the main model's output. This is achieved through a carefully designed acceptance-rejection sampling scheme.

The Acceptance Rule

Consider a position \(i\) in the sequence where the draft model proposes token \(t_d\). The main model, after its single parallel forward pass, provides its own probability \(P_m(t)\) for every possible token \(t\) at position \(i\). The draft model also produced its probability \(P_d(t_d)\) for its chosen token \(t_d\).

The decision to accept the drafted token \(t_d\) is made probabilistically. We draw a random number \(u \sim \text{Uniform}(0, 1)\). If \(u\) is less than or equal to a specific acceptance ratio, the token is accepted:

$$\text{Accept } t_d \text{ if } u \le A(t_d) \quad \text{where } A(t_d) = \min\left(1, \frac{P_m(t_d)}{P_d(t_d)}\right)$$

This rule ensures that if the draft model is very confident in a token (\(P_d(t_d)\) is high), but the main model is not (\(P_m(t_d)\) is low), the token is likely to be rejected. Conversely, if the main model is more confident than the draft model, the token is always accepted (since the ratio is \(\ge 1\), so \(\min(1, \dots)=1\)).

Reconstructing the Main Model's Distribution

If the drafted token \(t_d\) is rejected, we must still sample a token from the main model's true distribution. However, we've already "used up" some probability mass by potentially accepting other tokens or even considering \(t_d\). ⚠️ Common Pitfall

The speedup is highly dependent on the quality of the draft model. If the draft model is consistently poor, generating tokens that are frequently rejected by the main model, the algorithm will spend most of its time falling back to single-token main model sampling, negating much of the potential speedup. A good draft model is crucial.

Key Takeaways
▼

When to use speculative decoding:

  • Accelerating LLM Inference: This is the primary use case, especially for interactive applications like chatbots or coding assistants where low latency is crucial.
  • Deterministic Output: When you need the output to be identical (probabilistically) to what the main model would produce, but faster. Unlike distillation, it doesn't trade quality for speed.
  • Leveraging Model Hierarchies: Ideal when you have a smaller, faster model (e.g., a fine-tuned smaller LLM or a distilled version of the main model) that can serve as an effective draft model.
  • Hardware Utilization: Efficiently utilizes modern GPU tensor cores by converting sequential token generation into parallel batch verification.

When NOT to use:

  • Poor Draft Model: If the draft model is significantly worse than the main model, it will propose many incorrect tokens. This leads to frequent rejections and restarts, negating the speedup and potentially making the process slower than naive decoding.
  • Very Short Sequences: For generating very short responses, the overhead of the speculative decoding loop might outweigh the benefits.
  • Memory Constraints: Running two models (draft and main) simultaneously requires more GPU memory than running just one.
  • Already Fast Models: If the main model is already small and fast enough for your latency requirements, the added complexity might not be worth it.
💡 Big Picture

Speculative decoding is an elegant solution to a fundamental problem in LLM inference: the sequential nature of token generation. By intelligently "guessing ahead" and then verifying in parallel, it transforms a bottleneck into an opportunity for significant, quality-preserving acceleration.

import torch
def speculative_decode(prompt_tokens, draft_model, main_model, K=5, temperature=1.0):
generated_tokens = list(prompt_tokens)
while True:
# 1. Draft Phase: Generate K candidate tokens sequentially
draft_tokens = []
draft_probs = [] # P_d(t_i) for drafted tokens
current_context = torch.tensor(generated_tokens).unsqueeze(0)
for _ in range(K):
draft_logits = draft_model(current_context).logits[:, -1, :] / temperature
draft_dist = torch.softmax(draft_logits, dim=-1)
draft_token = torch.multinomial(draft_dist, num_samples=1)
draft_tokens.append(draft_token.item())
draft_probs.append(draft_dist[0, draft_token].item())
current_context = torch.cat([current_context, draft_token.unsqueeze(0)], dim=-1)
# 2. Verification Phase: Main model checks all K+1 tokens in parallel
# Context for main model is prompt + all generated_tokens + all draft_tokens
verification_context = torch.tensor(generated_tokens + draft_tokens).unsqueeze(0)
main_logits = main_model(verification_context).logits[:, len(generated_tokens)-1:-1, :] / temperature
main_dists = torch.softmax(main_logits, dim=-1) # P_m(t) for each position
# 3. Acceptance/Rejection Phase
num_accepted = 0
for i in range(K):
t_draft = draft_tokens[i]
p_draft = draft_probs[i]
p_main_for_t_draft = main_dists[0, i, t_draft].item()
acceptance_prob = min(1.0, p_main_for_t_draft / p_draft)
if torch.rand(1).item() < acceptance_prob:
generated_tokens.append(t_draft) # Accept token
num_accepted += 1
else:
# Reject: sample from residual distribution & restart
residual_dist = torch.max(torch.tensor(0.0), main_dists[0, i, :] - draft_dists[0, i, :])
residual_dist = residual_dist / residual_dist.sum() # Normalize
next_token = torch.multinomial(residual_dist, num_samples=1).item()
generated_tokens.append(next_token)
break # Restart loop from this new token
if num_accepted == K: # All K tokens accepted, or loop broke early
# Fallback Sampling: Sample the (K+1)-th token from main model's adjusted distribution
# (Complex logic for exact distribution match, simplified here)
main_logits_last = main_model(current_context).logits[:, -1, :] / temperature
main_dist_last = torch.softmax(main_logits_last, dim=-1)
next_token = torch.multinomial(main_dist_last, num_samples=1).item()
