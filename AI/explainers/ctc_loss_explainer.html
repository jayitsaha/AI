CTC Loss — Connectionist Temporal Classification

Training sequence models without pre-aligned labels — the engine behind end-to-end speech and OCR
Foundational Deep Learning Speech / OCR O(T·|S|) DP Sequence Modeling
1
Understanding CTC Loss
▼

The core problem: In speech recognition, a neural network sees a sequence of audio frames and must output a sequence of characters. But we don't know which frame corresponds to which character — the alignment is unknown. Traditional cross-entropy loss requires exact alignment: "frame 5 is the letter 'h'". CTC removes this requirement entirely.

Analogy: Imagine you're watching someone write "CAT" on a whiteboard, but you only see a blurry video. You can tell the word is "CAT" at the end, but you can't tell exactly which video frame corresponds to each letter. CTC says: "I'll consider ALL possible ways the writing could have been timed, and train the model to make their total probability sum to 1." This is the key insight — CTC marginalizes over all valid alignments.

The blank token: CTC introduces a special blank symbol \(\epsilon\) (often written as \(-\)) that the model can output at any time step. This serves two purposes: (1) it fills frames where no character is being produced, and (2) it separates repeated characters. "AA" must be encoded as "A\(\epsilon\)A" to distinguish it from a single long "A".

💡 If you remember one thing

CTC loss = \(-\log P(\text{label} \mid \text{input})\), where \(P(\text{label} \mid \text{input})\) is computed by summing probabilities of ALL valid frame-level sequences that collapse to the target label. This sum is computed efficiently with dynamic programming (forward-backward algorithm).

Where is CTC used?

  • Speech recognition: DeepSpeech, wav2vec, Whisper-style encoders all use or were inspired by CTC
  • OCR (Optical Character Recognition): Reading text from images without character bounding boxes
  • Handwriting recognition: Online and offline cursive text
  • Keyword spotting and phoneme recognition: Any task where input length ≫ output length

How CTC Works Internally
▼

Step 1 — The Network Output

A neural network (typically an RNN, LSTM, or Transformer encoder) processes \(T\) input frames and produces a \(T \times (|V|+1)\) matrix of logits, where \(|V|\) is the vocabulary size and the +1 is for the blank token. After softmax, each row is a probability distribution over all possible output tokens at that time step.

Step 2 — The CTC Alphabet and Paths

A path \(\pi\) is a sequence of length \(T\) drawn from the extended alphabet \(V' = V \cup \{\epsilon\}\). There are \((|V|+1)^T\) possible paths — astronomically many. The collapse function \(\mathcal{B}(\pi)\) maps a path to a label by: (1) merging consecutive repeated tokens, then (2) removing all blanks. For example: \(\mathcal{B}(\text{-A-AA-B-}) = \text{AB}\).

Step 3 — Summing Over Valid Paths

The probability of a label \(\ell\) given input \(x\) is the sum of probabilities of all paths that collapse to \(\ell\):

$$P(\ell \mid x) = \sum_{\pi \in \mathcal{B}^{-1}(\ell)} \prod_{t=1}^{T} p_t(\pi_t)$$

Since paths are independent across time steps (the model is conditionally independent given the input), the probability of a path is just the product of per-frame probabilities. The challenge is computing this sum efficiently.

Step 4 — The Forward-Backward Algorithm

Direct enumeration is impossible. Instead, CTC uses a dynamic programming algorithm on the modified label sequence \(\ell' = \epsilon, \ell_1, \epsilon, \ell_2, \epsilon, \ldots, \ell_L, \epsilon\) of length \(|S| = 2L+1\). The forward variable \(\alpha(t, s)\) = probability of being at position \(s\) in \(\ell'\) after processing \(t\) frames. The total probability is \(\alpha(T, |S|) + \alpha(T, |S|-1)\).

🔑 Key Insight: Modified Label Sequence

Inserting blanks between every label character creates the sequence \(\ell' = [\epsilon, c_1, \epsilon, c_2, \epsilon, \ldots, c_L, \epsilon]\). The DP tracks positions in this sequence, allowing the algorithm to correctly handle both blank frames and the separation of repeated characters.

Step 5 — Gradient and Training

The CTC loss is \(\mathcal{L} = -\log P(\ell \mid x)\). Gradients flow back through the forward-backward computation to the network's softmax outputs, then to the network weights. The backward pass reuses the forward DP table and a corresponding backward variable \(\beta(t,s)\), making the full gradient computation \(O(T \cdot |S|)\).

⚠️ Common Pitfall: Length Constraint

CTC requires \(T \geq |S| = 2L+1\), i.e., the number of input frames must be at least twice the label length plus one. If your audio is too short or your label too long, the loss is undefined (probability = 0). Always check this constraint in your data pipeline!

The Math — Why It Works
▼

The Modified Label Sequence

Given target label \(\ell = (\ell_1, \ldots, \ell_L)\), define the modified sequence by inserting blanks:

$$\ell' = (\epsilon, \ell_1, \epsilon, \ell_2, \epsilon, \ldots, \ell_L, \epsilon), \quad |\ell'| = 2L+1$$

Forward Variable Recurrence

Define \(\alpha(t, s)\) as the total probability of all partial paths up to time \(t\) that correspond to the first \(s\) symbols of \(\ell'\). The recurrence is:

$$\alpha(t,s) = \begin{cases} [\alpha(t-1,s) + \alpha(t-1,s-1)] \cdot p_t(\ell'_s) & \text{if } \ell'_s = \epsilon \text{ or } \ell'_s = \ell'_{s-2} \\ [\alpha(t-1,s) + \alpha(t-1,s-1) + \alpha(t-1,s-2)] \cdot p_t(\ell'_s) & \text{otherwise} \end{cases}$$

The second case allows "skipping" the blank between two different characters. The base case is \(\alpha(1,1) = p_1(\epsilon)\), \(\alpha(1,2) = p_1(\ell_1)\), and \(\alpha(1,s) = 0\) for \(s > 2\).

Total Probability and Loss

After filling the DP table, the total probability of the label is obtained by summing the two valid terminal states:

$$P(\ell \mid x) = \alpha(T, |\ell'|) + \alpha(T, |\ell'|-1)$$

The CTC loss for a single training example is then:

$$\mathcal{L}_{CTC} = -\log P(\ell \mid x) = -\log\bigl[\alpha(T, |\ell'|) + \alpha(T, |\ell'|-1)\bigr]$$

Gradient via Forward-Backward

Define the backward variable \(\beta(t,s)\) analogously. The gradient of the loss with respect to the network's output \(p_t(k)\) (probability of token \(k\) at time \(t\)) is:

$$\frac{\partial \mathcal{L}}{\partial p_t(k)} = -\frac{1}{P(\ell|x)} \sum_{s:\ell'_s=k} \frac{\alpha(t,s)\,\beta(t,s)}{p_t(k)}$$

This is the standard forward-backward formula from HMMs, adapted for the CTC lattice. The key property is that \(\alpha(t,s)\beta(t,s) / P(\ell|x)\) is the posterior probability of being at state \(s\) at time \(t\), which tells the model how much to "credit" each output token for producing the correct label.

📐 Numerical Stability

In practice, \(\alpha\) values become extremely small (products of many probabilities). Implementations work in log-space using the log-sum-exp trick: \(\log(a+b) = \log a + \log(1 + e^{\log b - \log a})\). PyTorch and TensorFlow's CTC implementations do this automatically.

Key Takeaways
▼

Why CTC was revolutionary: Before CTC (2006, Graves et al.), training sequence-to-sequence models required either pre-segmented data (expensive to annotate) or complex HMM-based systems with hand-crafted features. CTC enabled truly end-to-end training from raw audio to text with only utterance-level transcriptions.

CTC vs. Attention-based Seq2Seq: Attention models (like Transformer decoders) also avoid explicit alignment but work differently — they learn a soft alignment via attention weights. CTC makes a stronger conditional independence assumption (outputs are independent given the input), which makes it faster but less expressive. In practice, CTC and attention are often combined (joint CTC/attention training).

CTC decoding at inference time: The simplest decoder is greedy — take argmax at each time step, then collapse. Better results come from beam search with a language model. The key insight is that CTC decoding is separable: you can add an external language model score without retraining the acoustic model.

💡 The Conditional Independence Assumption

CTC assumes \(P(\pi \mid x) = \prod_t p_t(\pi_t \mid x)\) — outputs at different time steps are independent given the input. This is why a bidirectional encoder (like BiLSTM or Transformer) is critical: the "given x" part must capture all context, since the output distribution can't attend back to previous outputs.

When to use CTC

  • Input sequence is much longer than output sequence (speech frames vs. characters)
  • You have utterance-level labels but no frame-level alignment
  • You need fast, streaming-compatible inference (CTC is monotonic)
  • You want to combine with an external language model at decode time

Limitations

  • Conditional independence assumption limits modeling of output dependencies (e.g., language model priors)
  • Requires \(T \geq 2L+1\) — fails on very short inputs or very long labels
  • Tends to produce "spiky" posteriors — the model learns to output the correct token at one specific frame rather than smoothly
  • Harder to incorporate output-side context compared to autoregressive models
🔑 Modern Context

CTC remains widely used in production ASR systems (e.g., Mozilla DeepSpeech, NVIDIA NeMo, ESPnet). Whisper uses an encoder-decoder with cross-attention, but many streaming ASR systems still rely on CTC for its low latency and the ability to decode incrementally as audio arrives.

Code Trace
▼

A from-scratch CTC forward algorithm in NumPy, then PyTorch's built-in.

import numpy as np
import torch, torch.nn as nn
# ── Inputs ──────────────────────────────────────────────
# log_probs: (T, N, C) — T frames, N batch, C classes+blank
# PyTorch CTC expects blank=0 by default
T, vocab = 6, 3 # 3 tokens: blank(0), A(1), B(2)
label = [1, 2] # target: "A", "B"
# ── Build modified label sequence ℓ' ────────────────────
BLANK = 0
def make_label_prime(label, blank=0):
lp = [blank]
for c in label:
lp.append(c)
lp.append(blank)
return lp # [0,1,0,2,0] for "AB"
# ── Forward algorithm (log-space) ───────────────────────
def ctc_forward(log_probs, label, blank=0):
T, C = log_probs.shape
lp = make_label_prime(label, blank) # length S = 2L+1
S = len(lp)
NEG_INF = float('-inf')
# alpha[t,s] = log P(partial path ending at lp[s] at time t)
alpha = np.full((T, S), NEG_INF)
# Base case: t=0
alpha[0, 0] = log_probs[0, lp[0]] # blank
alpha[0, 1] = log_probs[0, lp[1]] # first label char
# Recurrence
for t in range(1, T):
for s in range(S):
# Always allow staying or coming from s-1
candidates = [alpha[t-1, s]]
if s > 0: candidates.append(alpha[t-1, s-1])
# Skip blank if current != blank and != prev label
if s > 1 and lp[s] != blank and lp[s] != lp[s-2]:
candidates.append(alpha[t-1, s-2])
# log-sum-exp over candidates
alpha[t, s] = log_sum_exp(candidates) + log_probs[t, lp[s]]
# Total log-probability
return log_sum_exp([alpha[T-1, S-1], alpha[T-1, S-2]])
def log_sum_exp(vals):
vals = [v for v in vals if v != float('-inf')]
if not vals: return float('-inf')
m = max(vals)
return m + np.log(sum(np.exp(v - m) for v in vals))
# ── PyTorch built-in (production use) ───────────────────
ctc_loss = nn.CTCLoss(blank=0, reduction='mean')
# log_probs: (T, N, C), targets: (N, L) or flat
log_probs_pt = torch.randn(6, 1, 3).log_softmax(2)
targets = torch.tensor([[1, 2]]) # "AB"
input_lengths = torch.tensor([6])
target_lengths = torch.tensor([2])
loss = ctc_loss(log_probs_pt, targets, input_lengths, target_lengths)
print(f"CTC loss: {loss.item():.4f}")
