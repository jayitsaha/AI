SASRec: Self-Attentive Sequential Recommendation

Predicting your next click with a causally-masked Transformer over interaction history
Foundational Recommender Systems Attention / Transformers O(n²d) per layer
1
Understanding SASRec
▼

What is it? SASRec (Kang & McAuley, 2018) reframes "what will this user do next?" as a sequence-modeling problem. It takes a user's chronologically ordered interactions — items clicked, viewed, or purchased — and feeds them through a stack of causally-masked self-attention blocks, exactly like a GPT-style decoder, except the "tokens" are catalog items instead of words. At every position it predicts the next item in the sequence.

Analogy: think of a language model predicting the next word from everything written so far, never peeking ahead. SASRec does the same over a shopping or browsing history: after 📱 Phone → 🎧 Earbuds → ⌚ Watch, what's the most likely next item? Unlike a simple Markov chain that only looks at the last 1–2 items, SASRec's attention can reach arbitrarily far back and learn which past items matter most for the next decision — sparsely, for sparse histories, and broadly, for dense ones.

It sits between two older families: Markov-chain recommenders (FPMC), which only model short local transitions, and RNN-based recommenders (GRU4Rec), which model the whole sequence but must be unrolled step-by-step and are slow to train. SASRec keeps the long-range modeling power of RNNs while training as a single parallel matrix computation like a Transformer.

💡 If you remember one thing

SASRec attends only to the past. A causal mask blocks every position \(t\) from seeing positions \(j > t\), so the model can be trained to predict all next-items in a sequence simultaneously, in one forward pass — the same trick that makes GPT training parallelizable: $$\hat r_{t} = \text{softmax}\!\left(\frac{Q_tK^\top}{\sqrt{d}} + M\right)V, \qquad M_{tj}=\begin{cases}0 & j\le t\\-\infty & j>t\end{cases}$$

How SASRec Works Internally
▼

Input Representation

Each item \(i\) in the catalog has a learned embedding \(\mathbf{M}_i \in \mathbb{R}^d\). For a user's sequence \((s_1,\dots,s_n)\), the input to the network at position \(t\) is the item embedding plus a learnable positional embedding \(\mathbf{P}_t\): \(\mathbf{h}^0_t = \mathbf{M}_{s_t} + \mathbf{P}_t\). Positions matter — "Phone then Case" is a different signal from "Case then Phone".

Stacked Causal Self-Attention Blocks

Each block projects the sequence into queries, keys and values (\(Q=H W^Q\), \(K=HW^K\), \(V=HW^V\)) and computes attention exactly as in a Transformer — but with the causal mask \(M\) added before the softmax, so position \(t\) can only mix information from positions \(1,\dots,t\). The attention output is followed by a point-wise feed-forward network (two linear layers with a ReLU in between, applied identically to every position), and both sublayers are wrapped with residual connections + layer normalization, stabilizing training as blocks are stacked (SASRec typically uses 2 blocks).

Design Decision: Why Causal Masking?

Without the mask, predicting item \(t{+}1\) from position \(t\) would let the model attend to position \(t{+}1\) itself — the model would trivially "cheat" by looking at the label. Masking future positions is what turns a bidirectional encoder (like BERT) into an autoregressive decoder that can be trained on every position of every sequence in parallel, then used causally at serving time.

Prediction Layer (Weight Tying)

To score how likely item \(i\) is to follow position \(t\), SASRec reuses the same item embedding matrix \(\mathbf{M}\) used on the input side: \(r_{i,t} = \mathbf{o}_t^\top \mathbf{M}_i\), where \(\mathbf{o}_t\) is the final block's output at position \(t\). No separate output embedding table is learned — this halves the parameter count and regularizes the model.

🔑 Key Property

SASRec is a decoder-only Transformer applied to item IDs instead of tokens. Every design choice — positional embeddings, causal masking, weight-tied output projection, parallel next-item loss at every position — mirrors autoregressive language modeling, which is why SASRec's ideas later fed directly into BERT4Rec and LLM-based recommenders.

Why It Works — The Math
▼

Causal Self-Attention

For input matrix \(H \in \mathbb{R}^{n\times d}\) (stacked \(\mathbf{h}^0_t\) rows):

$$Q = HW^Q,\quad K = HW^K,\quad V = HW^V \qquad \text{Attn}(H) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}} + M\right)V$$

The mask \(M\) is added before the softmax so masked entries become \(-\infty\) and vanish to exactly \(0\) probability after normalization — the model literally cannot assign attention weight to the future.

Point-wise Feed-Forward + Residual Stack

$$\text{FFN}(x) = \text{ReLU}(xW_1+b_1)W_2+b_2 \qquad x_{l+1} = \text{LayerNorm}\big(x_l + \text{Dropout}(\text{Sublayer}(x_l))\big)$$

The FFN is applied independently to every position (no mixing across time), giving the model nonlinear per-item transformation capacity between attention rounds. Stacking \(L\) such blocks lets position \(t\)'s representation aggregate signal from an increasingly rich combination of earlier items.

Training Objective

At every position \(t=1,\dots,n-1\) simultaneously, SASRec treats the true next item \(s_{t+1}\) as a positive and samples a negative item \(j\notin\mathcal S^u\); it minimizes binary cross-entropy on the scores \(r_{i,t}=\mathbf o_t^\top\mathbf M_i\):

$$\mathcal{L} = -\sum_{u}\sum_{t=1}^{n-1}\Big[\log\sigma\big(r_{s_{t+1},t}\big) + \log\big(1-\sigma(r_{j,t})\big)\Big]$$

Because every position contributes a loss term in one forward pass, training cost per sequence is \(O(n^2 d)\) for the attention matrix — quadratic in length but fully parallel across positions — versus an RNN's \(O(n)\) sequential steps that cannot be parallelized over time at all.

⚠️ Common Pitfall

Forgetting the causal mask (or masking it after the softmax instead of before) leaks future items into training and inflates offline metrics — the model looks great in evaluation and fails in production, because at serving time position \(n\) genuinely has no future to see.

Key Takeaways
▼

When to use SASRec:

  • Session-based or sequential recommendation with a meaningful chronological order (e-commerce clickstreams, playlist continuation, video watch history)
  • User histories long enough (roughly 10+ interactions) that attention can find non-adjacent dependencies a Markov chain would miss
  • You want fast, parallel training and single-pass inference (score all candidates from one final-position vector)

When NOT to use:

  • Severe cold-start: brand-new items/users have no learned embedding — content-based or hybrid models are needed instead
  • Very short sequences (1–2 items) — a simple Markov/co-occurrence model may perform just as well with far less compute
  • Extremely long sequences at serving scale — the \(O(n^2)\) attention cost motivates truncating history or using efficient-attention variants
💡 Where SASRec Sits

FPMC (Markov, local) → GRU4Rec (RNN, sequential, whole-history) → SASRec (causal self-attention, whole-history, parallel training) → BERT4Rec (bidirectional self-attention via masked-item / cloze training instead of causal next-item prediction). Modern LLM-based recommenders inherit SASRec's item-as-token, causal-decoder framing directly.

import numpy as np
# Item + positional embeddings (weight-tied output layer)
item_emb = ItemEmbedding(num_items, d) # M, shared in and out
pos_emb = PositionEmbedding(max_len, d) # P
h0 = item_emb(seq) + pos_emb(positions) # (n, d)
# Causal self-attention block
Q, K, V = h0 @ Wq, h0 @ Wk, h0 @ Wv
scores = (Q @ K.T) / np.sqrt(d) # (n, n)
scores = scores + causal_mask # mask[i,j] = -inf if j > i
attn = softmax(scores, axis=-1)
attn_out = attn @ V # (n, d)
# residual + layernorm + point-wise FFN, per position
x = layernorm(h0 + attn_out)
ffn_out = relu(x @ W1 + b1) @ W2 + b2
o = layernorm(x + ffn_out) # block output o_t, t=1..n
# next-item prediction at EVERY position, trained in parallel
for t in range(n - 1):
pos_logit = o[t] @ item_emb(seq[t + 1])
neg_logit = o[t] @ item_emb(sample_negative())
loss += -log(sigmoid(pos_logit)) - log(1 - sigmoid(neg_logit))
# inference: recommend from the LAST position's representation
scores_all = o[-1] @ item_emb.weight.T # (num_items,)
top_k = np.argsort(-scores_all)[:k]
