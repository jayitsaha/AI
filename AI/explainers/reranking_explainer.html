Understanding Reranking
▼

What is it? Reranking is a crucial second stage in many information retrieval (search) systems. Initial retrieval methods (like BM25, TF-IDF, or dense vector search using bi-encoders) are designed for speed and recall, quickly fetching a large set of candidate documents that might be relevant to a query. Reranking then takes this initial, often imperfect, list and re-scores each candidate with a more powerful (and usually slower) model to produce a much more accurate, finely-tuned final ranking.

Analogy: Imagine you're looking for the perfect gift. First, you quickly browse a large online store, filtering for "electronics" and "under $100" (initial retrieval). This gives you 100 potential items. Then, you carefully read the reviews, specifications, and compare features of those 100 items to pick the absolute top 5 for your friend (reranking). The first stage is broad and fast; the second is narrow and precise.

💡 If you remember one thing

Reranking is a critical trade-off: initial retrieval prioritizes speed and recall (finding many potentially relevant items), while the reranking stage prioritizes precision and accuracy (ordering the top items perfectly), using models too slow for the initial large-scale search.

How Reranking Works Internally
▼

The Two-Stage Retrieval Pipeline

A typical semantic search system operates in two stages:

  1. Initial Retrieval (First Stage): A fast, scalable model (e.g., lexical search like BM25, or a dense bi-encoder like Sentence-BERT) efficiently queries a large corpus (millions to billions of documents). It generates a candidate set of perhaps 50-200 documents that are *potentially* relevant. This stage must be very fast, often relying on pre-computed embeddings and approximate nearest neighbor (ANN) search.
  2. Reranking (Second Stage): A more sophisticated model then takes this smaller candidate set (e.g., 50-200 documents) and re-scores each (query, document) pair. These models are typically much slower but can capture deeper semantic relationships, leading to a significantly improved final ranking.

Three Common Reranking Approaches

The core difference between reranking models lies in their "interaction pattern" — how deeply and efficiently the query and document interact to produce a relevance score:

  • Cross-encoders: These models concatenate the query and document into a single input sequence (e.g., [CLS] Query [SEP] Document [SEP]) and feed it through a transformer. This allows for full, fine-grained attention between every query token and every document token, leading to very high accuracy. However, they are computationally expensive as the transformer's self-attention scales quadratically with input length.
  • ColBERT (Contextualized Late Interaction for Efficient Retrieval): ColBERT offers a compromise. It encodes the query and document into separate sets of contextualized token embeddings (like a bi-encoder), but then performs a "late interaction" by computing the maximum similarity between each query token embedding and all document token embeddings. This sum-max operation is more efficient than full self-attention but captures more interaction than a simple dot product of global embeddings.
  • Cohere Rerank (API): Services like Cohere Rerank provide powerful, pre-trained reranking models as an API. They abstract away the complexity of model deployment and scaling, often leveraging advanced cross-encoder architectures, ensembles, or distillation techniques. They offer a simple, high-performance solution for developers.
🔑 Key Property

The choice of reranker involves a trade-off between computational cost (latency) and relevance accuracy. Cross-encoders offer the highest accuracy at the highest cost, while ColBERT provides a strong balance, and API services offer convenience and state-of-the-art performance without local resource management.

Why It Works — The Math Behind the Models
▼

Cross-Encoder: Full Interaction

A cross-encoder model processes the concatenated query (\(q\)) and document (\(d\)) as a single sequence. Let \(T(\cdot)\) denote the transformer encoder and \(\text{MLP}(\cdot)\) a small multi-layer perceptron head that maps the final `[CLS]` token embedding to a scalar score. The relevance score \(s(q, d)\) is given by:

$$s(q, d) = \text{MLP}(\text{Transformer}(\text{concat}([CLS], q, [SEP], d, [SEP])))$$

The strength of this approach comes from the self-attention mechanism within the Transformer, where every token in the concatenated sequence can directly attend to every other token. This allows the model to learn complex, fine-grained interactions such as "does the query mention 'vegan' and the document mention 'menu' in the same context?"

ColBERT: Late Interaction with MaxSim

ColBERT aims to retain the fine-grained interaction of cross-encoders while improving efficiency. It first encodes the query and document independently into dense contextualized token embeddings. Let \(E_Q\) be the encoder for the query and \(E_D\) for the document. The outputs are matrices of token embeddings:

$$\mathbf{Q}_m = E_Q(q) \in \mathbb{R}^{|q| \times d_e} \quad \text{and} \quad \mathbf{D}_m = E_D(d) \in \mathbb{R}^{|d| \times d_e}$$

where \(|q|\) and \(|d|\) are the number of tokens in the query and document, respectively, and \(d_e\) is the embedding dimension. The relevance score is then computed using a "MaxSim" operation:

$$s(q, d) = \sum_{i=1}^{|q|} \max_{j=1}^{|d|} (\mathbf{Q}_{m,i} \cdot \mathbf{D}_{m,j})$$

This means for each query token embedding \(\mathbf{Q}_{m,i}\), we find the document token embedding \(\mathbf{D}_{m,j}\) that is most similar to it (using dot product), and then sum these maximum similarities across all query tokens. This allows for a form of token-level matching that is more expressive than a single vector dot product, but the document embeddings \(\mathbf{D}_m\) can be pre-computed and indexed, making reranking much faster than cross-encoders for a given query.

⚠️ Computational Cost Comparison

For a candidate set of \(N\) documents, a query length \(L_Q\), and document length \(L_D\):
Cross-encoder: \(O(N \cdot (L_Q + L_D)^2)\) — quadratic in total length, very slow.
ColBERT: \(O(N \cdot L_Q \cdot L_D)\) — linear in query and document lengths, much faster, especially with pre-computed document embeddings.

When to use reranking:

  • When initial retrieval provides good recall but insufficient precision in the top results.
  • For high-stakes search applications where the quality of the top-K results is critical (e.g., legal search, medical information).
  • When you have computational budget for a second, more expensive pass over a reduced set of documents.

When NOT to use:

  • For systems with extremely low latency requirements (reranking adds a measurable delay).
  • If the initial retrieval quality is already very high and further gains from reranking are marginal.
  • If the candidate set from the first stage is still too large (e.g., thousands of documents) for the chosen reranker's cost.
💡 Big Picture

Reranking is a cornerstone of modern semantic search, enabling systems to combine the speed of vector search with the nuanced understanding of large language models. It's a key pattern for building production-grade information retrieval pipelines.
