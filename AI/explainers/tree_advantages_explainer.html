1
Why Practitioners Love Trees
▾

Decision trees are among the oldest supervised learning algorithms — and yet they remain the go-to model whenever a data scientist needs to explain a decision to a non-technical stakeholder. Three structural properties set them apart from nearly every other model family:

  1. Interpretability: every prediction is a sequence of human-readable if/then rules you can print on an index card.
  2. Scale invariance: splits are threshold comparisons, so multiplying a feature by any positive constant changes the threshold value but not the split or its quality. No standardisation step is needed.
  3. Native mixed types: continuous features, ordinal features, and categorical features live in the same tree without dummy encoding or normalisation.

A fourth emergent benefit flows from these three: automatic feature interactions. When a deeper node splits on feature B after an ancestor split on feature A, the tree implicitly models the A × B interaction — something linear models require explicit engineering to capture.

The One-Line Intuition

A decision tree is a nested sequence of binary questions over raw feature values. Because the questions only compare values to thresholds, the relative ordering of data points is all that matters — not their absolute scale.

The analogy: a GP diagnosing a patient uses if/then rules — "Is the temperature above 38 °C? If yes, is the WBC count elevated? If yes, suspect infection." This is exactly what a decision tree does, and a doctor can audit every branch.

2
Splits Are Threshold Comparisons
▾

At each internal node, a decision tree evaluates a binary predicate of the form:

$$x_j \leq t \quad \text{(numeric feature}\ j\text{, threshold}\ t\text{)}$$

The learning algorithm finds the best \((j, t)\) pair by maximising the information gain (or equivalently minimising weighted impurity) after the split. For Gini impurity on a node with label distribution \(p_1, \ldots, p_K\):

$$G(S) = 1 - \sum_{k=1}^{K} p_k^2$$

and the gain of splitting node \(S\) into \(S_L, S_R\) at threshold \(t\) is:

$$\Delta G = G(S) - \frac{|S_L|}{|S|}\,G(S_L) - \frac{|S_R|}{|S|}\,G(S_R)$$

Numerical trace (our mushroom dataset, n = 10):

Root node: \(p(\text{toxic}) = 0.4\), \(p(\text{edible}) = 0.6\), so \(G(S) = 1 - (0.4^2 + 0.6^2) = 0.48\).

Candidate split stem_cm ≤ 1.2: left set is 4 toxic samples, \(G(S_L) = 0\). Right set is 5 edible + 1 toxic, \(G(S_R) = 1 - (1/6)^2 - (5/6)^2 = 1 - 0.0278 - 0.6944 = 0.2778\).

$$\Delta G = 0.48 - \tfrac{4}{10}(0) - \tfrac{6}{10}(0.2778) = 0.48 - 0.1667 = 0.3333$$
Key Property: Only Orderings Matter

The split predicate \(x_j \leq t\) partitions the dataset into the same two subsets for any monotone transformation \(f\): the predicate becomes \(f(x_j) \leq f(t)\), and the child sets \(S_L, S_R\) are unchanged. Therefore \(G(S_L)\), \(G(S_R)\), and \(\Delta G\) are all unchanged.

Categorical features

For a nominal feature \(x_j \in \{a, b, c, \ldots\}\) the tree tests \(x_j \in C'\) for some subset \(C' \subseteq \mathcal{C}\). No ordinal encoding is required; the algorithm enumerates (or greedily selects) the best subset. This is why features like color, country, or device_type can be fed in raw.

Watch Out: High-Cardinality Categoricals

With many categories the number of subsets is \(2^{|\mathcal{C}|-1}\). Most implementations cap this with heuristics (e.g., sklearn sorts categories by mean target and binary-searches). For very high cardinality (ZIP codes, user IDs) ordinal encoding or embeddings are still preferable.

3
The Math Behind Scale Invariance
▾

Theorem (scale invariance of tree splits). Let \(f : \mathbb{R} \to \mathbb{R}\) be a strictly monotone increasing function. Then for any dataset \(\{(x_i, y_i)\}\) and any split \(x_j \leq t\):

$$\Delta G\bigl(x_j \leq t\bigr) = \Delta G\bigl(f(x_j) \leq f(t)\bigr)$$

Proof sketch. Define \(S_L = \{i : x_{ij} \leq t\}\) and \(S_R = \{i : x_{ij} > t\}\). For the transformed feature \(z_{ij} = f(x_{ij})\), strict monotonicity means \(z_{ij} \leq f(t) \Leftrightarrow x_{ij} \leq t\), so the partition \((S_L, S_R)\) is identical. Because Gini impurity depends only on the label distribution within each partition — not on feature values — \(G(S_L)\), \(G(S_R)\), and hence \(\Delta G\) are unchanged. \(\square\)

Concrete Check: cm → mm (×100)

stem_cm split at \(t = 1.2\) → gain \(= 0.3333\).

stem_mm split at \(f(t) = 120\) → same 4/6 partition → gain \(= 0.3333\). ✓

This is verified numerically above (Python: abs(g1 - g1_mm) < 1e-10).

Why SVM and k-NN cannot make this claim

An SVM optimises \(\min \tfrac{1}{2}\|w\|^2\) subject to margin constraints. The dual solution involves dot products \(\langle x_i, x_j \rangle\) — re-scaling feature \(k\) by 100 multiplies its contribution to every dot product by \(100^2 = 10000\), completely changing the margin and support vectors.

k-NN computes Euclidean distance \(\|x_i - x_j\|_2\). A feature measured in mm will dominate one in meters, shifting which neighbours are "nearest." Features must be standardised to prevent this.

Decision trees are inherently invariant because they never compute distances or dot products — only rank-order comparisons.

Feature Interaction Bonus

A depth-2 tree splitting on A then B in one branch effectively models the interaction \(\mathbb{1}[A \leq t_A] \cdot \mathbb{1}[B \leq t_B]\). Logistic regression must add \(A \times B\) as an explicit column; the tree discovers it automatically during greedy search.

Decision Guide

Use a decision tree (or Random Forest) when: (1) you need to explain every decision to a stakeholder or regulator; (2) your features are on incomparable scales and you want to skip preprocessing; (3) your data has mixed types without painful encoding. Use logistic regression when the boundary is genuinely linear and calibrated probabilities matter. Use SVM when the margin/kernel formulation matches the geometry of your problem.

6
Key Takeaways
▾
  • Interpretability: every leaf corresponds to a conjunction of axis-aligned predicates — you can print the model as a flowchart and audit it without a PhD.
  • Scale invariance: formally, for any monotone \(f\), \(\Delta G(x \leq t) = \Delta G(f(x) \leq f(t))\). SVM, k-NN, and linear models do not satisfy this.
  • Mixed types: numeric, ordinal, and nominal features participate in the same tree without preprocessing — each gets the split type that maximises gain.
  • Automatic interactions: depth-\(d\) trees capture up to degree-\(d\) interaction effects without any feature engineering.
  • Main weakness: a single tree overfits badly (high variance). This is why practitioners almost always use Random Forests or Gradient Boosted Trees in production — they preserve all the advantages listed above while reducing variance by averaging.
The Bigger Picture

All three advantages stem from one fact: the tree's learning objective (Gini / entropy gain) depends only on the partition of the dataset — not on the feature values per se. This is the deepest reason why trees are so robust and so easy to explain.
