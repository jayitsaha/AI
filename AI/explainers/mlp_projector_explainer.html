Understanding the MLP Projector
▼

What is it? A frozen vision encoder (CLIP ViT) and a large language model (Vicuna, LLaMA) speak two completely different "languages" — one outputs patch features, the other expects token embeddings. The MLP projector is the small trainable network in LLaVA that translates one into the other: a tiny 2-layer perceptron that takes every CLIP patch feature vector and reshapes it into a vector that looks like a word embedding to the LLM.

Analogy: Imagine hiring a simultaneous interpreter for a meeting between an engineer who only speaks in blueprints and a novelist who only speaks in prose. The interpreter doesn't need to be a genius — a fast, competent translator who converts "this is a 45° beam under 200N load" into "a slanted support bearing moderate weight" is enough for the novelist to keep writing. The projector is that interpreter: it does not understand the image, and it does not understand language — it just re-expresses patch features in the LLM's native vocabulary space.

💡 If you remember one thing

The projector is just \(h_v = W_2\,\text{GELU}(W_1 v + b_1) + b_2\) applied identically to every one of the ~576 patch vectors coming out of CLIP. Once projected, these vectors are spliced directly into the LLM's input sequence — the LLM never knows they didn't come from its own embedding table.

How It Works Internally
▼

The Pipeline

An image is resized (e.g. 336×336) and fed to a frozen CLIP ViT-L/14. The ViT chops the image into a grid of patches (24×24 = 576 patches at a 14px patch size) and, after self-attention layers, emits one feature vector per patch, each of dimension \(d_v = 1024\). LLaVA uses features from the penultimate transformer layer rather than the final layer, since the last layer is overly specialized toward CLIP's contrastive image-text matching objective and discards some local detail useful for captioning/VQA.

Linear (LLaVA v1) → 2-Layer MLP (LLaVA-1.5)

The original LLaVA paper (Liu et al., 2023) used a single linear layer \(W: \mathbb{R}^{d_v} \to \mathbb{R}^{D}\) to project each patch vector to the LLM's hidden size \(D\) (4096 for a 7B Vicuna). LLaVA-1.5 ("Improved Baselines with Visual Instruction Tuning", Liu et al., 2023) replaced this with a 2-layer MLP — Linear → GELU → Linear — and reported consistent gains across nearly every benchmark, for a few million extra parameters and negligible added latency.

Design Decision: Why an MLP and not a Q-Former?

BLIP-2's Q-Former uses 32 learnable query tokens that cross-attend into the frozen vision features through a ~200M-parameter transformer, compressing 256+ patches down to a fixed 32 tokens. The MLP projector makes the opposite bet: keep it dead simple (≈20M params, no attention, no learned queries) and preserve all patch tokens, trading a longer LLM input sequence for zero information loss and much faster, more stable training — because the LLM's own attention layers do the "querying" instead of a separate module.

🔑 Key Property

The projector applies the exact same weights \((W_1,b_1,W_2,b_2)\) to every patch independently — it is a per-token (position-wise) feed-forward map, structurally identical to the FFN inside a Transformer block, just without the surrounding attention or residual connection.

Why It Works — The Math
▼

Forward Computation

For a patch feature vector \(v \in \mathbb{R}^{d_v}\), the projector computes:

$$h_1 = W_1^\top v + b_1 \in \mathbb{R}^{d_h}, \qquad h_v = W_2^\top\, \text{GELU}(h_1) + b_2 \in \mathbb{R}^{D}$$

where \(\text{GELU}\) is the Gaussian Error Linear Unit, approximated as:

$$\text{GELU}(x) \approx 0.5\,x\left(1+\tanh\!\left[\sqrt{2/\pi}\left(x+0.044715\,x^3\right)\right]\right)$$

Stacking all \(N{=}576\) patch vectors as rows of a matrix \(V \in \mathbb{R}^{N \times d_v}\) gives the batched form \(H_v = \text{MLP}_\phi(V) \in \mathbb{R}^{N \times D}\) — a matrix of "visual tokens" living in exactly the same \(\mathbb{R}^D\) space as the LLM's word embeddings.

Training Objective

There is no dedicated projector loss — it is trained purely through the LLM's next-token cross-entropy loss on captioning/instruction data, back-propagated through the frozen LLM's embeddings and the frozen CLIP features (frozen models still pass gradient through them, just don't update their own weights):

$$\mathcal{L}(\phi) = -\sum_{t} \log p_\theta\big(y_t \mid y_{

Only \(\phi = (W_1,b_1,W_2,b_2)\) (and, in stage 2, the LLM weights \(\theta\)) receive gradient updates; CLIP's weights stay frozen throughout both training stages.

⚠️ Common Pitfall

The projector's output dimension \(D\) is tied to a specific LLM's hidden size (4096 for Vicuna-7B, 5120 for Vicuna-13B). Swapping the LLM backbone means the last layer \(W_2\) must be re-shaped and re-trained from scratch — you cannot just plug a 7B-trained projector into a 13B model.

Key Takeaways
▼

When to use an MLP projector:

  • Bootstrapping a vision-language model quickly and cheaply on modest compute
  • Tasks needing fine-grained spatial detail — OCR, counting, visual grounding, chart reading
  • When the LLM backbone is fixed and you can afford a longer input sequence per image

When NOT to use it:

  • Video or many-image inputs, where 576 tokens/image explodes the context length — resamplers/Q-Formers or token pooling compress better
  • Extreme compute-constrained inference, where a fixed small token budget (e.g. 32 tokens) matters more than spatial fidelity
  • Cross-modal retrieval objectives — a projector trained only for generation isn't optimized for that
💡 Hierarchy

Linear projection (LLaVA v1) ⊂ 2-layer MLP (LLaVA-1.5) ⊂ Resampler / Q-Former (BLIP-2, Flamingo). Each step trades simplicity and full token fidelity for parameter count and token compression — pick the point on that spectrum that matches your compute and context-length budget.

import torch, torch.nn as nn
class MLPProjector(nn.Module):
"""LLaVA-1.5 style 2-layer MLP vision-language projector."""
def __init__(self, vision_dim=1024, hidden_dim=4096, llm_dim=4096):
super().__init__()
self.fc1 = nn.Linear(vision_dim, hidden_dim)
self.act = nn.GELU()
self.fc2 = nn.Linear(hidden_dim, llm_dim)
def forward(self, patch_features):
# patch_features: (B, num_patches, vision_dim) e.g. (B, 576, 1024)
h = self.fc1(patch_features) # -> (B, 576, hidden_dim)
h = self.act(h) # GELU nonlinearity
h = self.fc2(h) # -> (B, 576, llm_dim) == token embed size
return h # these are the "visual tokens"
