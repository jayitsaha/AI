Understanding Pointwise (1×1) Convolution
▼

What is it? A 1×1 convolution, often called a "pointwise" convolution, is a convolutional operation where the kernel (filter) size is 1×1. Unlike larger kernels that mix spatial information (e.g., a 3×3 kernel looking at a 3×3 patch of pixels), 1×1 convolutions operate independently on each spatial location. Their key role is to mix information across the channel dimension at each pixel.

Analogy: Imagine a chef preparing a dish where each "pixel" is a tiny spot on the counter, and "channels" are different ingredients (salt, pepper, garlic powder) available at that spot. A standard 3×3 convolution is like mixing ingredients from a small area (a 3×3 patch of counter spots) to create a new flavor. A 1×1 convolution is different: it takes a single spot on the counter, and for *that specific spot*, it mixes all the ingredients (channels) present there to create a new set of mixed ingredients. This "mixing recipe" (the 1×1 kernel weights) is then applied consistently to every single spot on the counter.

💡 If you remember one thing

A 1×1 convolution is essentially a fully connected layer applied to the channels dimension at each spatial location, with the same weights shared across all spatial locations. It transforms a vector of input channels into a vector of output channels, pixel by pixel.

2
How It Works Internally
▼

The Mechanism: Channel-wise Linear Combination

Consider an input feature map \(X\) with dimensions \(H \times W \times C_{in}\) (Height, Width, Input Channels). A 1×1 convolution uses a kernel \(K\) with dimensions \(1 \times 1 \times C_{in} \times C_{out}\) (Height, Width, Input Channels, Output Channels). For each output channel, there's a \(1 \times 1 \times C_{in}\) kernel that essentially acts as a vector of weights.

For every single spatial location \((i, j)\) in the input feature map:

  1. It extracts the vector of channel values at that specific location: \(X_{i,j,:} = [X_{i,j,0}, X_{i,j,1}, \dots, X_{i,j,C_{in}-1}]\).
  2. For each desired output channel \(k\), it computes a dot product between this input channel vector \(X_{i,j,:}\) and the \(k\)-th kernel vector \(K_{0,0,:,k}\).
  3. This produces the value for the \(k\)-th output channel at spatial location \((i, j)\): \(Y_{i,j,k}\).
  4. This process is repeated for all \(C_{out}\) output channels, creating a new output channel vector \(Y_{i,j,:}\) for that pixel.

The result is an output feature map \(Y\) with dimensions \(H \times W \times C_{out}\). Notice that the spatial dimensions \(H \times W\) remain unchanged.

Design Decisions & Applications

1×1 convolutions are surprisingly versatile:

  • Dimensionality Reduction/Expansion: By setting \(C_{out} < C_{in}\), they can reduce the number of channels (e.g., bottleneck layers in Inception/ResNet architectures), which saves computation and parameters. Conversely, \(C_{out} > C_{in}\) expands channels.
  • Introducing Non-linearity: When followed by an activation function (like ReLU), they add non-linearity to the channel transformations, allowing the network to learn more complex relationships between features.
  • Computational Efficiency: Reducing channel depth early in a network can significantly reduce the computational cost of subsequent larger convolutions, making models faster and smaller.
  • Feature Transformation: They allow the network to learn optimal linear combinations of existing features across channels, creating new, richer feature representations.
🔑 Key Property

A 1×1 convolution operates identically to a fully connected (dense) layer if you consider each pixel's channel vector as an input to that FC layer. The "convolutional" aspect is that the weights of this FC layer are shared across all spatial locations in the feature map.

3
Why It Works — The Math
▼

The Core Operation

Let the input feature map be denoted by \(X \in \mathbb{R}^{H \times W \times C_{in}}\) and the output feature map by \(Y \in \mathbb{R}^{H \times W \times C_{out}}\). The 1×1 convolution kernel can be viewed as a 4D tensor \(K \in \mathbb{R}^{1 \times 1 \times C_{in} \times C_{out}}\). For each spatial location \((i, j)\) and each output channel \(k\), the operation is defined as:

$$Y_{i,j,k} = \sum_{c=0}^{C_{in}-1} X_{i,j,c} \cdot K_{0,0,c,k} + B_k$$

Here, \(B_k\) is the bias term for the \(k\)-th output channel. Notice the summation only happens over the input channels \(c\), not over spatial dimensions. The kernel indices \(0,0\) emphasize its 1×1 spatial nature.

Matrix Multiplication View

We can re-express this more compactly. For a fixed spatial location \((i, j)\), let \(X_{i,j,:} \in \mathbb{R}^{C_{in}}\) be the vector of input channel values at that pixel. Let \(W \in \mathbb{R}^{C_{in} \times C_{out}}\) be the matrix formed by stacking the \(C_{out}\) 1×1 kernels as columns (i.e., \(W_{c,k} = K_{0,0,c,k}\)). Let \(B \in \mathbb{R}^{C_{out}}\) be the bias vector. Then, for each pixel \((i, j)\), the output channel vector \(Y_{i,j,:}\) is computed as:

$$Y_{i,j,:} = X_{i,j,:} \cdot W + B$$

This is a standard matrix-vector multiplication, performed identically and independently for every \((i, j)\) pair. This makes it clear why it's a "channel-wise fully connected layer."

Computational Cost

The total number of parameters for a 1×1 convolution is \(C_{in} \times C_{out}\) (for weights) + \(C_{out}\) (for biases). The number of floating-point operations (FLOPs) is proportional to \(H \times W \times C_{in} \times C_{out}\).

$$\text{FLOPs} \approx H \times W \times C_{in} \times C_{out}$$

This is why reducing \(C_{out}\) can lead to significant computational savings for subsequent layers, especially if \(C_{in}\) is large.

⚠️ Don't Confuse With...

A 1×1 convolution is NOT the same as a depthwise convolution. Depthwise convolutions operate on each channel independently, without mixing them. 1×1 convolutions, by contrast, are all about mixing information between channels.

Key Takeaways
▼

When to use 1×1 convolutions:

  • Channel Dimensionality Control: To reduce (bottleneck) or expand the number of feature channels, thereby managing model capacity and computational cost.
  • Feature Transformation: To create new, more abstract feature representations by learning optimal linear combinations of existing channels.
  • Non-linearity: When paired with an activation function (e.g., ReLU), to introduce non-linearity into the channel-mixing process.
  • Computational Efficiency: As part of complex architectures (like Inception or ResNet) to reduce the number of parameters and FLOPs in deeper layers.

When NOT to use 1×1 convolutions:

  • Spatial Feature Extraction: When your primary goal is to extract local spatial patterns (e.g., edges, textures), a larger kernel (3×3, 5×5) is necessary.
  • Already Optimal Channel Count: If the current number of channels is already well-suited for the task and computational budget, adding a 1×1 conv might be redundant.
  • Direct Replacement for Depthwise Convolutions: They serve different purposes. Depthwise convolutions are for spatial processing per channel, 1×1 convs are for channel mixing.
💡 One-Line Summary

A 1×1 convolution transforms the channel representation at each pixel independently, acting as a spatially shared "mini fully-connected layer" that mixes input features into new output features.

Code Trace (PyTorch Example)
▼
import torch.nn as nn
import torch
# 1. Define input feature map: Batch x C_in x H x W
# Example: 1 batch, 4 input channels, 3x3 spatial resolution
input_feature_map = torch.randn(1, 4, 3, 3)
# 2. Define a 1x1 Convolution layer
# in_channels=4, out_channels=2, kernel_size=1
conv1x1 = nn.Conv2d(in_channels=4, out_channels=2, kernel_size=1)
# 3. Perform the forward pass
output_feature_map = conv1x1(input_feature_map)
print(f"Input shape: {input_feature_map.shape}")
print(f"Kernel weights shape: {conv1x1.weight.shape}") # (C_out, C_in, 1, 1)
print(f"Output shape: {output_feature_map.shape}")
# 4. Manually simulate the 1x1 conv for a single pixel (e.g., spatial location (0,0))
# The input channel vector for pixel (0,0)
pixel_input_vector = input_feature_map[0, :, 0, 0] # shape (C_in,)
# Extract the 1x1 kernel weights. In PyTorch, weights are (C_out, C_in, H, W).
# We need to reshape it to (C_in, C_out) for standard matrix multiplication.
kernel_matrix = conv1x1.weight.squeeze(2).squeeze(2).T # shape (C_in, C_out)
# Perform the matrix multiplication (dot product for each output channel)
# Add the bias term (conv1x1.bias) if present
pixel_output_vector_manual = torch.matmul(pixel_input_vector, kernel_matrix) + conv1x1.bias
print(f"\nPixel (0,0) input channel vector: {pixel_input_vector.tolist()}")
print(f"Kernel matrix for channel mixing:\n{kernel_matrix.tolist()}")
print(f"Bias vector: {conv1x1.bias.tolist()}")
print(f"Pixel (0,0) output channel vector (manual): {pixel_output_vector_manual.tolist()}")
print(f"Pixel (0,0) output channel vector (from conv): {output_feature_map[0, :, 0, 0].tolist()}")
# Verify they are close (due to floating point precision)
assert torch.allclose(pixel_output_vector_manual, output_feature_map[0, :, 0, 0])
