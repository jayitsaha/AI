CenterNet: Objects as Center Points

A simple, anchor-free, one-stage object detection model
Foundational Deep Learning Computer Vision O(1) inference
1
Understanding CenterNet
▼

What is it? CenterNet (Zhou et al., 2019) is an innovative object detection approach that treats objects not as bounding boxes, but as single center points. Unlike traditional detectors (like Faster R-CNN) that propose many anchor boxes and then refine them, CenterNet directly predicts an object's center and then regresses its size, offset, and other attributes (like 3D depth or pose) from that single point.

This paradigm shift simplifies the detection pipeline significantly: it removes the need for anchor boxes, non-maximal suppression (NMS) post-processing (mostly), and complex feature alignment. It results in a detector that is both conceptually simpler and often faster, while maintaining competitive accuracy.

Analogy: Imagine you're playing a game of "pin the tail on the donkey." Most object detectors would draw a hundred tails (anchor boxes) all over the donkey, then try to pick the best one and adjust its position. CenterNet, however, just says: "Find the donkey's belly button (center point), and from there, tell me how wide and tall the donkey is." It's a more direct and intuitive way to locate and size objects.

💡 If you remember one thing

CenterNet maps an input image to a heatmap where peaks correspond to object centers. All other object properties (bounding box width/height, sub-pixel offset, etc.) are regressed directly from the features at these detected center locations. This is an anchor-free, one-stage approach.

2
How CenterNet Works Internally
▼

The Architecture: Encoder-Decoder Backbone

CenterNet uses a standard encoder-decoder network (e.g., Hourglass Network, DLA-34, ResNet with upsampling) to process an input image and produce high-resolution feature maps. The key is that this backbone outputs a single feature map which is then fed into several "heads" for different prediction tasks.

Output Heads: What CenterNet Predicts

For each input image, the network produces three primary output maps, typically at a lower resolution (e.g., 1/4th of the input size) due to downsampling in the backbone:

  • 1. Center Heatmap (\(\hat{Y}\)): A \(W/R \times H/R \times C\) tensor, where \(R\) is the output stride (e.g., 4), and \(C\) is the number of object classes. Each channel is a heatmap for a specific class, where peaks indicate the likely center points of objects of that class.
  • 2. Local Offset Map (\(\hat{O}\)): A \(W/R \times H/R \times 2\) tensor. Since the heatmap is at a lower resolution, an object's true center might not perfectly align with an integer coordinate on the downsampled grid. This head predicts a small sub-pixel offset \((dx, dy)\) for each potential center to correct for this quantization error.
  • 3. Size Map (\(\hat{S}\)): A \(W/R \times H/R \times 2\) tensor. For each potential center point, this head directly predicts the width and height \((w, h)\) of the bounding box for the object associated with that center.

Other variants of CenterNet can add more heads for 3D object detection (depth, orientation) or human pose estimation (keypoint heatmaps).

Training Targets: Generating Ground Truth

To train CenterNet, ground truth bounding boxes are converted into the target formats for each head:

  • Center Heatmap Target: For each ground truth bounding box, its center point \((x_c, y_c)\) is projected onto the low-resolution output grid \((x_c/R, y_c/R)\). A 2D Gaussian kernel is then "splatted" at this location on the corresponding class's heatmap. This smooth target makes training easier than a single hot pixel.
  • Offset Target: The fractional part of the projected center \((x_c/R - \lfloor x_c/R \rfloor, y_c/R - \lfloor y_c/R \rfloor)\) serves as the target for the offset map at the integer center location.
  • Size Target: The actual width and height of the bounding box are directly used as the target for the size map at the integer center location.

Inference: From Heatmaps to Bounding Boxes

At inference time, the process is reversed:

  1. The network outputs the three maps.
  2. Peaks in the center heatmaps are detected (e.g., by finding local maxima). A simple 3x3 max-pooling can achieve this.
  3. For each detected peak, its value is used as a confidence score. Its location \((x,y)\) on the heatmap, combined with the predicted offset \((dx, dy)\) and size \((w, h)\) from the corresponding locations in the offset and size maps, forms the final bounding box: \((x + dx - w/2, y + dy - h/2, x + dx + w/2, y + dy + h/2)\).
  4. A confidence threshold is applied to filter out low-scoring detections. Crucially, CenterNet largely avoids the need for heavy Non-Maximal Suppression (NMS) because each object should ideally correspond to only one peak in the heatmap.
🔑 Key Property

CenterNet's elegance lies in its directness: it avoids the complexity of anchor box design and matching, and simplifies post-processing, making it a truly end-to-end differentiable object detector. The core idea is that a single keypoint can implicitly represent an object's extent.

3
Why CenterNet Works — The Math
▼

Ground Truth Heatmap Generation

For each object \(k\) with bounding box \((x_1^{(k)}, y_1^{(k)}, x_2^{(k)}, y_2^{(k)})\) and class \(c_k\), its center point \(p_k = ((x_1^{(k)}+x_2^{(k)})/2, (y_1^{(k)}+y_2^{(k)})/2)\) is mapped to the output stride \(R\) coordinates \(\tilde{p}_k = (\lfloor p_x^{(k)}/R \rfloor, \lfloor p_y^{(k)}/R \rfloor)\). The ground truth heatmap \(Y\) for class \(c_k\) is then populated by a 2D Gaussian kernel centered at \(\tilde{p}_k\):

$$Y_{xyc_k} = \exp\left(-\frac{(x - \tilde{p}_x^{(k)})^2 + (y - \tilde{p}_y^{(k)})^2}{2\sigma_p^2}\right)$$

where \(\sigma_p\) is an adaptive standard deviation based on the object's size. This smooth target allows for some tolerance in predicting the exact center.

The Overall Loss Function

CenterNet's total training loss is a weighted sum of three components, one for each prediction head:

$$L = L_{k} + \lambda_{size}L_{size} + \lambda_{off}L_{off}$$

Here, \(\lambda_{size}\) and \(\lambda_{off}\) are hyperparameters (typically 0.1 and 1, respectively) that balance the contributions of the size and offset losses. \(L_k\) is the heatmap loss, \(L_{size}\) is the bounding box size loss, and \(L_{off}\) is the local offset loss.

Heatmap Loss (\(L_k\)): Modified Focal Loss

The heatmap loss uses a pixel-wise logistic regression with a variant of Focal Loss (Lin et al., 2017). This loss is crucial because the number of negative locations (no object center) far outweighs positive locations (object centers), leading to class imbalance. The modified Focal Loss downweights easy negatives and focuses on hard positives/negatives:

$$L_k = -\frac{1}{N} \sum_{x,y,c} \begin{cases} (1 - \hat{Y}_{x,y,c})^\alpha \log(\hat{Y}_{x,y,c}) & \text{if } Y_{x,y,c} = 1 \\ (1 - Y_{x,y,c})^\beta (\hat{Y}_{x,y,c})^\alpha \log(1 - \hat{Y}_{x,y,c}) & \text{otherwise} \end{cases}$$

Here, \(\hat{Y}_{x,y,c}\) is the predicted heatmap value, \(Y_{x,y,c}\) is the Gaussian-blurred ground truth target, \(N\) is the number of objects, and \(\alpha\), \(\beta\) are Focal Loss hyperparameters (typically 2 and 4, respectively). Note that the "otherwise" case handles all negative locations, including those within the Gaussian blob (where \(0 < Y_{x,y,c} < 1\)), effectively pushing predictions away from non-peak areas.

Offset Loss (\(L_{off}\)) and Size Loss (\(L_{size}\)): L1 Regression

Both the local offset and bounding box size predictions are continuous values, so they are trained using simple L1 regression loss. These losses are applied only at the ground truth center locations \(\tilde{p}_k\):

$$L_{off} = \frac{1}{N} \sum_{k=1}^N \left|\hat{O}_{\tilde{p}_k} - \left(\frac{p_k}{R} - \tilde{p}_k\right)\right|_1$$
$$L_{size} = \frac{1}{N} \sum_{k=1}^N \left|\hat{S}_{\tilde{p}_k} - s_k\right|_1$$

where \(s_k = (w_k, h_k)\) is the actual width and height of object \(k\). The L1 loss promotes robust training against outliers.

⚠️ Limitations & Challenges

CenterNet can struggle with highly overlapping objects, as it can only detect one center per location. If two objects of the same class have very close centers, the heatmap might only show one peak. Its performance on very small objects also depends heavily on the output resolution (output stride \(R\)) — smaller \(R\) means higher resolution, but more computation.

Key Takeaways
▼

CenterNet's Strengths:

  • Simplicity: No anchor boxes to design or tune, no complex Intersection-over-Union (IoU) matching during training, and minimal NMS during inference. This makes the pipeline cleaner and easier to understand.
  • Efficiency: Often faster than two-stage detectors due to its one-stage nature and simplified post-processing.
  • Versatility: The keypoint-based approach is highly extensible. By adding more output heads, CenterNet can easily be adapted for 3D object detection, multi-person pose estimation, or tracking.
  • Directness: Predicts properties directly from the center point, avoiding intermediate steps that can introduce errors.

When to use CenterNet:

  • When you need a simple, efficient, and direct object detection solution.
  • For real-time applications where speed is critical.
  • When you want to extend detection to other keypoint-based tasks (e.g., 3D, pose).
  • As a strong baseline for many computer vision tasks.

When NOT to use CenterNet:

  • In scenarios with extreme object overlap, especially of the same class, where multiple objects might share a single "center" on the heatmap, leading to missed detections.
  • When computational resources are extremely constrained and even a backbone with upsampling is too heavy (though lighter backbones can be used).
💡 CenterNet vs. Anchor-based Detectors

CenterNet eschews the "propose-and-refine" paradigm of anchor-based detectors (like Faster R-CNN or YOLO) for a more direct "locate-and-predict" approach. By defining an object by its center keypoint, it achieves a streamlined, elegant, and often faster detection pipeline, proving that simpler models can still be highly effective.

Code Trace (Conceptual Python)
▼
import numpy as np
from scipy.ndimage import gaussian_filter
# --- 1. Ground Truth Target Generation ---
def generate_gt_targets(bboxes, img_size, output_stride=4, gaussian_sigma=2):
output_W, output_H = img_size[0] // output_stride, img_size[1] // output_stride
num_classes = max(b['class_id'] for b in bboxes) + 1 # Assuming 0-indexed classes
gt_heatmap = np.zeros((num_classes, output_H, output_W), dtype=np.float32)
gt_offset = np.zeros((2, output_H, output_W), dtype=np.float32)
gt_size = np.zeros((2, output_H, output_W), dtype=np.float32)
gt_mask = np.zeros((output_H, output_W), dtype=np.bool_) # To indicate where losses apply
for bbox in bboxes:
x1, y1, x2, y2 = bbox['bbox']
class_id = bbox['class_id']
center_x, center_y = (x1 + x2) / 2, (y1 + y2) / 2
# Project center to output resolution
proj_center_x, proj_center_y = center_x / output_stride, center_y / output_stride
int_center_x, int_center_y = int(proj_center_x), int(proj_center_y)
# Heatmap target (Gaussian)
# Create a temporary Gaussian centered at int_center_x,y
tmp_heatmap = np.zeros((output_H, output_W), dtype=np.float32)
tmp_heatmap[int_center_y, int_center_x] = 1 # Peak at integer center
tmp_heatmap = gaussian_filter(tmp_heatmap, sigma=gaussian_sigma)
gt_heatmap[class_id] = np.maximum(gt_heatmap[class_id], tmp_heatmap) # Handle overlaps
# Offset target
gt_offset[0, int_center_y, int_center_x] = proj_center_x - int_center_x
gt_offset[1, int_center_y, int_center_x] = proj_center_y - int_center_y
# Size target
gt_size[0, int_center_y, int_center_x] = x2 - x1 # width
gt_size[1, int_center_y, int_center_x] = y2 - y1 # height
gt_mask[int_center_y, int_center_x] = True # Mark location for loss computation
return gt_heatmap, gt_offset, gt_size, gt_mask
# --- 2. Inference: Decode Bounding Boxes from Predictions ---
def decode_bboxes(pred_heatmap, pred_offset, pred_size, output_stride=4, conf_threshold=0.3):
num_classes, output_H, output_W = pred_heatmap.shape
# Apply 3x3 max pooling to find local peaks (NMS-like)
# For simplicity, we'll just find peaks > neighbors here. Real NMS is more complex.
peaks = []
for c in range(num_classes):
for y in range(1, output_H - 1): # Skip borders for simple NMS
for x in range(1, output_W - 1):
score = pred_heatmap[c, y, x]
if score < conf_threshold: continue
# Check if it's a local maximum
is_peak = True
for dy in [-1, 0, 1]:
for dx in [-1, 0, 1]:
if dx == 0 and dy == 0: continue
if pred_heatmap[c, y + dy, x + dx] >= score:
is_peak = False; break
if not is_peak: break
if is_peak:
peaks.append({'class_id': c, 'score': score, 'x': x, 'y': y})
# Construct bounding boxes from peaks
detections = []
for peak in peaks:
c, score, x, y = peak['class_id'], peak['score'], peak['x'], peak['y']
# Retrieve offset and size from predicted maps
offset_x, offset_y = pred_offset[0, y, x], pred_offset[1, y, x]
width, height = pred_size[0, y, x], pred_size[1, y, x]
# Calculate precise center in original image coordinates
center_x_orig = (x + offset_x) * output_stride
center_y_orig = (y + offset_y) * output_stride
# Calculate bounding box coordinates
x1 = center_x_orig - width / 2
y1 = center_y_orig - height / 2
x2 = center_x_orig + width / 2
y2 = center_y_orig + height / 2
detections.append({
'class_id': c, 'score': score,
'bbox': [x1, y1, x2, y2],
'center_orig': [center_x_orig, center_y_orig]
})
return detections
