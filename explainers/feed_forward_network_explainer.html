The Feed-Forward Network (FFN) in Transformers

The position-wise MLP sublayer that gives every token its own nonlinear "thinking" step
Foundational Transformers Architecture ~2/3 of params
1
Understanding the Feed-Forward Network
▼

What is it? Every Transformer block has two sublayers: self-attention (which lets tokens look at each other) and a Feed-Forward Network, or FFN (which lets each token think on its own). The FFN takes each token's vector, one at a time, pushes it up into a much bigger space, applies a nonlinear "squashing" function, and projects it back down — with the exact same two weight matrices reused for every single position in the sequence.

Analogy: Imagine a factory floor where attention is a big meeting room — every worker (token) walks in, listens to everyone else, and updates their notes. The FFN is what happens next: each worker walks to an identical private desk, expands their notes into a huge scratchpad (the "expansion"), highlights the important parts with a nonlinear pen, then condenses everything back into a short summary. Every worker uses an identical desk and an identical scratchpad template — but because each worker's notes are different, they walk away with different conclusions.

Analogy for "position-wise": It's like a photocopier with a fixed stencil (the weights) — you feed it different pages (token vectors), and it processes each page independently and identically. No page influences how another page is processed inside the FFN — that cross-token mixing is entirely attention's job.

💡 If you remember one thing

The FFN is a tiny 2-layer MLP applied independently and identically to every position: $$\text{FFN}(x) = W_2\,\sigma(W_1 x + b_1) + b_2$$ It expands \(x\) from \(d_{model}\) dimensions up to \(d_{ff} = r \cdot d_{model}\) dimensions (the expansion ratio \(r\), typically 4), applies a nonlinearity \(\sigma\), then projects back down to \(d_{model}\).

2
How the FFN Works Internally
▼

Where it sits

Each Transformer block is: x → Self-Attention → Add & Norm → FFN → Add & Norm → output. Attention mixes information across token positions (it is the only sublayer that lets token \(i\) see token \(j\)). The FFN then processes each position's resulting vector completely independently — it has zero visibility into any other position. This division of labor is deliberate: attention = "communication," FFN = "computation."

The two linear maps, and why the shape is expand-then-contract

\(W_1 \in \mathbb{R}^{d_{ff}\times d_{model}}\) projects up into a wider "working space," and \(W_2 \in \mathbb{R}^{d_{model}\times d_{ff}}\) projects back down. This is an inverted bottleneck — the opposite of an autoencoder's compressive bottleneck. The wide intermediate layer gives the network an over-complete basis: it can afford many redundant, sparsely-firing "feature detectors" (each hidden unit responds to a specific combination of input features), and the nonlinearity \(\sigma\) between the two matrices is what makes this useful — without it, \(W_2 W_1\) would collapse into one linear map no more expressive than a single matrix.

Design decision: why the same weights at every position?

Sharing \(W_1, W_2, b_1, b_2\) across all \(n\) positions keeps the parameter count independent of sequence length \(n\) (crucial — you don't want your model to grow every time you feed it a longer sentence), and it lets the whole FFN sublayer be computed as one big batched matrix multiply \(XW_1^\top\) over the entire sequence at once — fully parallel, GPU-friendly, no sequential dependency (unlike an RNN's per-step nonlinear update, which the FFN is a spiritual descendant of).

The "key-value memory" interpretation

Geva et al. (2020) showed the FFN can be read as an associative memory: \(W_1\) rows act like keys that pattern-match against the input (each hidden unit fires when the input resembles its key), and \(W_2\) columns act like values that get mixed in proportional to how strongly each key fired. This reframes "expansion ratio" as "memory capacity" — more hidden units means more (key, value) slots the model can use to store factual associations and lexical patterns.

🔑 Key Property

The FFN is position-wise (same function \(f_\theta\) applied to every token) and permutation-equivariant on its own — reordering the input tokens just reorders the outputs identically, since there is no interaction between positions. All sequence-order-dependent mixing in a Transformer comes from attention (and positional encodings), never from the FFN.

3
Why the Expansion Ratio Matters — The Math
▼

Definition

For a token vector \(x \in \mathbb{R}^{d_{model}}\), applied identically at every sequence position \(t = 1,\dots,n\):

$$\text{FFN}(x) = W_2\,\sigma(W_1 x + b_1) + b_2, \qquad W_1 \in \mathbb{R}^{d_{ff}\times d_{model}},\ \ W_2 \in \mathbb{R}^{d_{model}\times d_{ff}}$$

The expansion ratio is \(r = d_{ff}/d_{model}\). The original Transformer (Vaswani et al., 2017) used \(d_{model}=512,\ d_{ff}=2048 \Rightarrow r=4\). This \(r=4\) convention persisted through BERT (768→3072), GPT-2 (768→3072, …, 1600→6400) and GPT-3 (12288→49152) — all exactly \(r=4\).

Parameter cost of the expansion ratio

Ignoring the (relatively tiny) biases, the FFN's weight count is \(2\,d_{model}\,d_{ff} = 2r\,d_{model}^2\). Compare against the four projection matrices of self-attention (\(W_Q,W_K,W_V,W_O\), each \(d_{model}\times d_{model}\)):

$$\text{Params}_{FFN} \approx 2r\,d_{model}^2 \qquad \text{Params}_{Attn} \approx 4\,d_{model}^2 \qquad \frac{\text{Params}_{FFN}}{\text{Params}_{Attn}} = \frac{r}{2}$$

At the canonical \(r=4\), the FFN has 2× as many parameters as attention — which is why roughly two-thirds of a Transformer's weights live inside its FFN sublayers, not its attention sublayers.

Activation functions \(\sigma\)

The original paper used ReLU: \(\text{ReLU}(x)=\max(0,x)\). BERT/GPT-2/GPT-3 switched to the smoother GELU, \(\text{GELU}(x) = x\,\Phi(x) \approx 0.5x\big(1+\tanh[\sqrt{2/\pi}(x+0.044715x^3)]\big)\), which avoids ReLU's hard zero-gradient region. Modern LLMs (LLaMA, PaLM, Mistral) use a gated variant, SwiGLU:

$$\text{SwiGLU-FFN}(x) = \big(\text{Swish}(xW_1)\odot xV\big)W_2, \qquad \text{Swish}(z)=z\cdot\text{sigmoid}(z)$$

SwiGLU adds a third matrix \(V\) (a learned gate), so to keep the parameter budget equal to a non-gated \(r=4\) FFN, practitioners shrink the ratio to \(r \approx \tfrac{8}{3}\) — solving \(3\,d_{model}\,d_{ff}=8\,d_{model}^2 \Rightarrow d_{ff}=\tfrac{8}{3}d_{model}\).

⚠️ Common Pitfall

"Position-wise" does not mean the FFN knows the token's position index — it means the same function is applied at every position with no cross-position mixing. Positional information enters the model elsewhere (sinusoidal/learned/RoPE embeddings), before or alongside attention — never inside the FFN's matmuls.

Key Takeaways
▼

The two ideas to hold onto:

  • Position-wise: identical MLP, applied independently to every token vector — parameter count is decoupled from sequence length, and the whole sublayer is a single parallel batched matmul.
  • Expansion ratio \(r\): how much wider the hidden layer is than \(d_{model}\). Bigger \(r\) → more "memory slots" / representational capacity, but roughly linear growth in both parameters and FLOPs. \(r=4\) is the historical default; gated variants (SwiGLU) use \(r\approx 8/3\) to stay parameter-matched.

💡 Why it dominates the parameter budget

At \(r=4\), \(\text{Params}_{FFN} \approx 2\times \text{Params}_{Attn}\) per block. Across a whole model this means FFN sublayers hold roughly two-thirds of all Transformer weights — which is exactly why techniques like Mixture-of-Experts (sparsely activating only a few FFN "experts" per token) target the FFN, not attention, to cut inference cost.

Code Trace
▼
import numpy as np
# d_model = 4 (toy), expansion ratio r, d_ff = r * d_model
d_model, r = 4, 4
d_ff = r * d_model
# Shared weights -- SAME for every position in the sequence
W1 = np.random.randn(d_ff, d_model) * 0.5 # expand
b1 = np.zeros(d_ff)
W2 = np.random.randn(d_model, d_ff) * 0.5 # contract
b2 = np.zeros(d_model)
def gelu(x):
return 0.5*x*(1+np.tanh(np.sqrt(2/np.pi)*(x+0.044715*x**3)))
def ffn(x):
h = W1 @ x + b1 # expand: d_model -> d_ff
a = gelu(h) # nonlinearity
y = W2 @ a + b2 # contract: d_ff -> d_model
return y
# Position-wise: apply the SAME ffn() to every token independently
X = np.stack([x_tok1, x_tok2, x_tok3]) # shape (n, d_model)
out = np.stack([x + ffn(x) for x in X]) # residual, one call per position
# Equivalent single batched matmul (what GPUs actually run):
out_batched = X + gelu(X @ W1.T + b1) @ W2.T + b2
# Param cost: FFN ~ 2*d_model*d_ff vs Attention ~ 4*d_model**2
ffn_params = 2*d_model*d_ff + d_ff + d_model
attn_params = 4*d_model*d_model
