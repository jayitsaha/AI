Why There Is Always a Global Optimum
▼

Logistic regression minimizes the log-loss (negative log-likelihood). For a dataset with \(n\) samples, features \(x_i \in \mathbb{R}^d\), labels \(y_i \in \{0,1\}\), and weights \(w \in \mathbb{R}^d\), the objective is:

$$\mathcal{L}(w) = \frac{1}{n}\sum_{i=1}^n \left[-y_i \log \sigma(w^\top x_i) - (1-y_i)\log(1 - \sigma(w^\top x_i))\right] + \frac{\lambda}{2}\|w\|^2$$

where \(\sigma(z) = \frac{1}{1+e^{-z}}\) is the sigmoid. This function is convex — which means every local minimum is a global minimum, and gradient-based optimizers are guaranteed to converge to the optimal \(w^*\).

💡 Convexity Proof Sketch

The Hessian of \(\mathcal{L}\) is \(H = \frac{1}{n}X^\top S X + \lambda I\) where \(S = \mathrm{diag}(\sigma_i(1-\sigma_i))\). Since \(\sigma_i(1-\sigma_i) > 0\) for all finite inputs, \(S \succ 0\). Adding \(\lambda I \succeq 0\) keeps \(H \succ 0\), so \(\mathcal{L}\) is strictly convex for \(\lambda > 0\). Without regularization (\(\lambda=0\)) and linearly separable data, the optimum is at \(\|w\| \to \infty\) — solvers diverge.

Key Convergence Facts

  • Strongly convex objective (\(\lambda > 0\)): linear convergence rate — error halves each iteration at a geometric rate.
  • Without regularization: sublinear convergence; may not converge if data is linearly separable.
  • All standard solvers (lbfgs, newton-cg, saga, liblinear, sag) find the same \(w^*\) — they differ in cost per step and memory, not in the quality of the solution.
2
L-BFGS: Quasi-Newton Without the Full Hessian
▼

Newton's method updates \(w \leftarrow w - H^{-1}\nabla\mathcal{L}\). This uses curvature (second-order info) for fast convergence, but computing and inverting \(H \in \mathbb{R}^{d \times d}\) costs \(O(d^2)\) memory and \(O(d^3)\) per step — intractable for large \(d\).

L-BFGS (Limited-memory Broyden–Fletcher–Goldfarb–Shanno) avoids forming \(H\) explicitly. Instead, it maintains a sliding window of the last \(m\) gradient differences \(\{s_k, y_k\}\) and uses them to implicitly approximate \(H^{-1}\):

$$s_k = w_{k+1} - w_k, \quad y_k = \nabla\mathcal{L}(w_{k+1}) - \nabla\mathcal{L}(w_k)$$
$$B_{k+1}^{-1} \approx \text{rank-}2\text{ update of } B_k^{-1} \text{ via } (s_k, y_k) \quad \text{(two-loop recursion)}$$

Memory: \(O(md)\) with \(m \approx 5\text{–}20\). Each iteration costs \(O(nd + md)\) — one full gradient pass over all \(n\) samples, plus \(O(md)\) for the two-loop Hessian approximation update.

🔑 When to Use L-BFGS

Small-to-medium datasets (\(n \lesssim 10^5\)), any dimensionality. Converges in far fewer iterations than gradient descent (superlinear, near-quadratic convergence near the optimum). Supports L2 penalty only (not L1, which is non-smooth). sklearn default for \(n < 10^5\). Also the best choice for multinomial (multi-class) logistic regression.

# sklearn interface
from sklearn.linear_model import LogisticRegression
clf = LogisticRegression(solver='lbfgs', C=1.0, max_iter=100)
# C = 1/lambda. Larger C = weaker regularization.
# max_iter: increase if ConvergenceWarning fires.
3
Newton-CG: Exact Curvature via Hessian-Vector Products
▼

Newton-CG (Conjugate Gradient) solves the Newton step \(H\,p = -\nabla\mathcal{L}\) without ever forming \(H\) — using only Hessian-vector products \(Hv\). This is a key insight: you never need \(H\) itself, only its action on a vector.

For logistic regression, \(Hv = \frac{1}{n}X^\top (S \cdot (Xv)) + \lambda v\) costs just \(O(nd)\) — two matrix-vector products. The inner CG loop runs for \(k\) iterations (each \(O(nd)\)), so one Newton step costs \(O(knd)\).

$$\text{Newton-CG step: solve } \left(\tfrac{1}{n}X^\top S X + \lambda I\right) p = -\nabla\mathcal{L} \text{ via CG}$$
🧮 Convergence Rate

Newton methods exhibit quadratic convergence near the optimum: if \(\|w_k - w^*\| \leq \epsilon\), then \(\|w_{k+1} - w^*\| \leq C\epsilon^2\). This is exponentially faster than L-BFGS's superlinear rate — but each step is more expensive because CG must run to sufficient precision.

🔑 When to Use Newton-CG

Medium datasets, high accuracy required, L2 penalty only. Slower per-iteration than L-BFGS in practice for typical tolerances. Best suited when you need very high-precision solutions or the condition number of \(H\) is small. In sklearn, often interchangeable with lbfgs; lbfgs typically wins in wall-clock time due to simpler iteration structure.

4
SAGA: Variance-Reduced Stochastic Gradient
▼

Plain SGD picks one sample \(i\) per step and computes \(\nabla\ell_i(w)\) as a noisy gradient estimate. The noise never vanishes — SGD oscillates around \(w^*\) rather than converging to it. SAGA (Defazio et al., 2014) eliminates this variance by maintaining a gradient table:

$$w_{k+1} = w_k - \eta\left[\nabla\ell_{i_k}(w_k) - \phi_{i_k} + \frac{1}{n}\sum_{j=1}^n \phi_j\right] \quad \text{then update } \phi_{i_k} \leftarrow \nabla\ell_{i_k}(w_k)$$

Each step uses the difference between the fresh gradient and the stored stale gradient, corrected by the average — the correction term is unbiased and has zero variance at convergence. Memory: \(O(nd)\) for the gradient table.

💡 Why SAGA Supports L1 (and lbfgs does not)

L-BFGS and Newton-CG require the objective to be smooth (differentiable everywhere). The L1 penalty \(\lambda\|w\|_1\) has a kink at zero — its subgradient is \([-\lambda, \lambda]\) at \(w=0\). SAGA applies proximal updates: after the SAGA gradient step, apply \(w \leftarrow \mathrm{prox}_{\eta\lambda\|\cdot\|_1}(w)\), i.e. soft-threshold each coordinate. This gives the exact sparse solution. sklearn's SAGA is currently the only sklearn logistic solver that supports L1 + multiclass simultaneously.

🔑 When to Use SAGA

Large datasets (\(n \gtrsim 10^5\)) OR when you need L1 regularization (sparsity). Convergence rate: \(O(1/k)\) for convex, linear for strongly-convex — same asymptotic as SVRG but with simpler implementation. Step size (learning rate) must be set to \(\eta \leq \frac{1}{3\max_i\|x_i\|^2 + \lambda}\) for convergence — sklearn sets this automatically.

# L1 sparsity — only saga supports this in sklearn
clf = LogisticRegression(solver='saga', penalty='l1', C=0.1,
max_iter=1000) # needs more iters for large n
# For elasticnet: solver='saga', penalty='elasticnet', l1_ratio=0.5

⚠️ Common Pitfalls

ConvergenceWarning: increase max_iter or scale your features (solvers are sensitive to feature magnitudes — always StandardScaler first). Linearly separable data without regularization: all solvers will fail to converge — add \(\lambda > 0\) (i.e., C < ∞). saga on small data: gradient table is \(O(nd)\) — wasteful when \(n\) is small and lbfgs would converge in 10 steps.

Interview Q&A
▼

Q: Why is log-loss convex but 0-1 loss is not?

The 0-1 loss \(\mathbf{1}[\hat{y} \neq y]\) is a step function — non-convex and non-differentiable. Log-loss \(-y\log\hat{p} - (1-y)\log(1-\hat{p})\) is a smooth convex upper bound on 0-1 loss (it's the negative log-likelihood of a Bernoulli). The key: composition of a convex non-decreasing function (log) with a linear function (logit) preserves convexity.

Q: Why can't lbfgs handle L1?

L-BFGS requires the gradient to exist everywhere. The L1 penalty \(\|w\|_1 = \sum|w_j|\) has a subgradient (not a gradient) at \(w_j=0\). Quasi-Newton methods accumulate curvature from gradient differences — undefined where the gradient jumps discontinuously. SAGA avoids this by using proximal operators (soft-thresholding), which handle non-smooth penalties natively.

Q: What is SAGA's step size rule?

For convergence, SAGA requires \(\eta \leq \frac{1}{3L}\) where \(L = \max_i\|x_i\|^2 / n + \lambda\) is the per-sample Lipschitz constant of \(\nabla\ell_i\). Too large: diverges. Too small: converges but slowly. sklearn auto-estimates \(L\) from the data.

Q: Do all solvers converge to the same solution?

Yes — for strictly convex objectives (\(\lambda > 0\)), the global minimizer \(w^*\) is unique, and all correct implementations converge to it. Differences in final coefficients are floating-point noise below the convergence tolerance. Set the same tol across solvers to compare them fairly.

Q: When would you pick newton-cg over lbfgs?

Rarely in practice. Newton-CG uses exact Hessian-vector products — better conditioning — but requires the inner CG solve to converge, adding overhead. L-BFGS with \(m=10\) history pairs typically matches Newton-CG quality in fewer wall-clock seconds. Newton-CG shines when \(H\) is nearly diagonal (well-conditioned) or you need extremely tight convergence.
