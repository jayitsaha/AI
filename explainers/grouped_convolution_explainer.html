Grouped Convolution

Splitting channels into independent groups — from AlexNet's dual-GPU hack to ResNeXt's cardinality
Intermediate CNN / Computer Vision Architecture O(Cin·Cout·K²/G) params

Understanding Grouped Convolution
▼

What is it? A standard convolution layer connects every input channel to every output channel — each output feature map is a weighted sum over the entire input depth. Grouped convolution instead slices the input channels into G independent groups and convolves each group with its own, smaller filter bank. No group ever looks at another group's channels. The outputs are simply concatenated back together.

Analogy: Imagine a factory with 8 raw-material streams feeding 8 assembly lines. A "full" convolution routes all 8 streams into every assembly line — maximum information, maximum wiring cost. Grouped convolution instead splits the factory into G independent sub-factories, each with its own 8/G streams and its own 8/G assembly lines, wired only internally. Fewer wires, cheaper to build, and each sub-factory can even run on a separate machine — which is exactly why AlexNet used this trick to split a network across two GPUs that couldn't hold the whole layer in memory.

Summary: Grouped convolution partitions channels into G groups, convolves each independently, and concatenates the results — cutting parameters and FLOPs by a factor of roughly G.

💡 If you remember one thing

Splitting a convolution into \(G\) groups divides both parameters and compute by \(G\): $$\text{params} = G \times \frac{C_{in}}{G} \times \frac{C_{out}}{G} \times K^2 = \frac{C_{in} C_{out} K^2}{G}$$ At the extreme \(G = C_{in} = C_{out}\), every group is a single channel — this is depthwise convolution.

How Grouped Convolution Works Internally
▼

The Origin: AlexNet's Memory Constraint (2012)

Krizhevsky, Sutskever & Hinton trained AlexNet across two NVIDIA GTX 580 GPUs, each with only 3GB of memory — too little to hold the full network. Their solution: split the 96 filters of the first conv layer's output (and subsequent layers) into two groups of 48, placing one group on each GPU. Each GPU computed its group's convolutions independently, with the two streams only communicating at specific layers (e.g. layer 3). This was originally an engineering hack for parallelism, not a deliberate regularization technique — but it revealed that splitting channels barely hurt accuracy while roughly halving compute.

The General Mechanism

Given an input with \(C_{in}\) channels and a target of \(C_{out}\) output channels, standard convolution uses a weight tensor of shape \((C_{out}, C_{in}, K, K)\) — every output channel has its own full-depth filter. Grouped convolution with \(G\) groups instead:

  • Splits the input into \(G\) contiguous chunks of \(C_{in}/G\) channels each.
  • Splits the output into \(G\) chunks of \(C_{out}/G\) channels each.
  • Convolves group \(g\)'s input chunk with its own weight tensor of shape \((C_{out}/G,\ C_{in}/G,\ K, K)\) to produce group \(g\)'s output chunk.
  • Concatenates all \(G\) output chunks along the channel dimension.

Crucially, group \(g\)'s output channels have zero connectivity to input channels outside group \(g\) — this is what shrinks the weight tensor.

ResNeXt: Cardinality as a First-Class Design Axis

Xie et al. (2017) turned this accidental trick into a deliberate architectural dimension called cardinality (\(C\), the number of groups/paths). Inside a ResNeXt bottleneck block, a \(1{\times}1\) conv reduces channels, a grouped \(3{\times}3\) conv (cardinality = 32 in the reference model) processes the groups in parallel as "aggregated transformations," and a final \(1{\times}1\) conv restores and mixes channels. Their key finding: increasing cardinality improves accuracy more reliably than increasing depth or width at a fixed parameter budget — an alternative scaling axis, described as "ResNet + Inception-style split-transform-merge, done at every block."

Design Decision: Why Not Just Use Fewer Channels?

Shrinking \(C_{in}\)/\(C_{out}\) directly also cuts params, but throws away representational capacity — fewer total feature maps. Grouped convolution keeps the same total channel count (so the same representational width) while restricting connectivity, not capacity. This is a genuinely different lever: same channels, sparser wiring.

🔑 Key Property

Grouped convolution is a block-diagonal restriction of the full convolution's weight tensor — the off-block-diagonal entries (cross-group connections) are forced to exactly zero rather than learned. It is not a different operation, just a structured sparsity constraint on standard convolution.

Why It Works — The Math
▼

Parameter Count Derivation

A standard 2D convolution with kernel size \(K\), \(C_{in}\) input channels and \(C_{out}\) output channels has weight tensor shape \((C_{out}, C_{in}, K, K)\), giving:

$$P_{full} = C_{out} \cdot C_{in} \cdot K^2$$

Splitting into \(G\) groups, each group independently maps \(C_{in}/G\) input channels to \(C_{out}/G\) output channels, contributing \((C_{out}/G) \cdot (C_{in}/G) \cdot K^2\) parameters. Summing over all \(G\) identical-sized groups:

$$P_{grouped} = G \cdot \frac{C_{out}}{G} \cdot \frac{C_{in}}{G} \cdot K^2 = \frac{C_{out} \cdot C_{in} \cdot K^2}{G} = \frac{P_{full}}{G}$$

FLOPs scale identically, since each output pixel still requires one multiply-add per weight: \(\text{FLOPs} = P \times H_{out} \times W_{out} \times 2\). So grouped convolution cuts both parameters and compute by exactly \(G\times\), for equal channel counts.

The Depthwise Limit

Setting \(G = C_{in}\) (requires \(C_{out}\) to be a multiple of \(C_{in}\); the common case is \(C_{out}=C_{in}\)) makes each group a single input channel mapped to \(C_{out}/G\) output channel(s). With \(C_{out}=C_{in}=C\):

$$P_{depthwise} = C \cdot \frac{C}{C} \cdot \frac{C}{C} \cdot K^2 = C \cdot K^2$$

Compare \(C \cdot K^2\) to the full \(C^2 K^2\) — a reduction of exactly \(C\times\). This is why MobileNet pairs a depthwise \(3{\times}3\) with a pointwise \(1{\times}1\) convolution ("depthwise separable convolution") to cheaply mix channel information back after the depthwise stage.

ResNeXt: Compute-Matched Scaling

ResNeXt keeps a bottleneck's total FLOPs roughly fixed while increasing cardinality \(C\) by simultaneously widening the per-group channel width \(d\), following \(C \cdot d \approx \text{const}\). This lets cardinality substitute for depth/width as a scaling axis without inflating the compute budget.

⚠️ Common Pitfall

Grouped convolution alone blocks information flow across groups — a feature computed in group 1 can never influence group 2's output within that layer. Stacking many grouped layers without mixing creates isolated "channel silos." Fixes: ResNeXt uses \(1{\times}1\) convs before/after to mix; ShuffleNet explicitly permutes ("shuffles") channels between grouped layers to restore cross-group information flow.

Key Takeaways
▼

When to use grouped convolution:

  • You need to cut parameters/FLOPs by a known factor without shrinking channel width (mobile/edge deployment, larger effective models under a fixed budget)
  • You want an extra scaling axis (cardinality) alongside depth and width, as in ResNeXt
  • You need to split a layer across multiple devices with minimal cross-device communication (AlexNet's original motivation)
  • Extreme case — depthwise separable convolutions (MobileNet, Xception) for maximum compute efficiency

When NOT to use:

  • Very small channel counts, where \(C_{in}/G\) or \(C_{out}/G\) would drop below a few channels — too little capacity per group
  • Without any channel-mixing mechanism (1×1 convs or shuffling) across many stacked grouped layers — information gets siloed
  • On hardware/frameworks with poor grouped-conv kernel support — the theoretical FLOP savings don't always translate to wall-clock speedups

💡 Hierarchy

Standard conv (\(G=1\)) ⊃ Grouped conv (\(1 < G < C_{in}\)) ⊃ Depthwise conv (\(G = C_{in}\)). Each is the same operation with an increasingly aggressive block-diagonal sparsity constraint on the weight tensor.

import numpy as np
def grouped_conv2d(x, weight, groups):
# x: (Cin, H, W) weight: (Cout, Cin//groups, K, K)
Cin, H, W = x.shape
Cout, Cin_g, K, _ = weight.shape
Cout_g = Cout // groups
out = np.zeros((Cout, H-K+1, W-K+1))
for g in range(groups):
x_g = x[g*Cin_g:(g+1)*Cin_g] # this group's input slice
w_g = weight[g*Cout_g:(g+1)*Cout_g] # this group's filters
for oc in range(Cout_g):
for i in range(H-K+1):
for j in range(W-K+1):
patch = x_g[:, i:i+K, j:j+K]
out[g*Cout_g+oc, i, j] = np.sum(patch * w_g[oc])
return out
def params(Cin, Cout, K, groups=1):
return groups * (Cin//groups) * (Cout//groups) * K * K
full = params(256, 256, 3, groups=1) # 589,824
resnext = params(256, 256, 3, groups=32) # 18,432 (32x fewer)
depthwise= params(256, 256, 3, groups=256) # 2,304 (256x fewer)
