Part VI · Transformer Architecture Families

Encoder-only, Decoder-only & Encoder-Decoder

BERT reads both directions at once, GPT reads only what came before, and T5 does both — one stack to understand, one stack to generate, bridged by cross-attention.

Intermediate NLP · Transformers Attention Masking
1
Understanding the Concept
▼

What is this? A Transformer is just a stack of attention layers — but who is allowed to look at whom changes everything about what the model can do. There are three shapes to memorize:

  • Encoder-only (BERT) — every token sees every other token, left and right. Great for understanding text (classification, search, masked-word prediction).
  • Decoder-only (GPT) — every token sees only itself and what came before it (a causal mask). Great for generating text one token at a time.
  • Encoder-Decoder (T5 / BART) — an encoder that reads the whole input bidirectionally, plus a decoder that writes output causally while also peeking at the encoder via cross-attention. Great for transforming one sequence into another (translation, summarization).

Analogy: Think of three different exam formats. BERT is an open-book fill-in-the-blank test — you can read the whole passage, both before and after the blank, to guess the missing word. GPT is writing a story out loud, one word at a time, with no eraser — you only know what you've already said. T5 is translating a letter: you read the entire source letter first (bidirectionally, like BERT), then you write the translation word by word (causally, like GPT) while constantly glancing back at the original letter (cross-attention).

If you remember one thing

The architecture doesn't change the attention formula — it changes the mask added to the attention scores before softmax. Full mask = understand. Causal mask = generate. Cross mask = translate/condition. Same math, three different triangles of allowed connections.

2
How It Works Internally
▼

The problem before 2017–2019: RNN encoder-decoder models (Sutskever et al. 2014) compressed a whole source sentence into one fixed vector, then generated the target sequentially — a bottleneck for long sequences. The Transformer (Vaswani et al. 2017) replaced recurrence with self-attention, but the original paper only described the full encoder-decoder shape. Researchers soon realized you could keep one half and specialize:

  1. BERT (Devlin et al. 2018) kept only the encoder stack and trained it with Masked Language Modeling (MLM): randomly hide 15% of tokens, predict them using context from both sides. Because there is nothing to "leak" from the future (there's no generation step), the mask can be fully open — every position attends to every position.
  2. GPT (Radford et al. 2018) kept only the decoder stack and trained it with plain next-token prediction. Because the model must generate token t without having seen token t+1 at inference time, training uses a causal mask so the model never cheats by attending to the future during training either.
  3. T5 (Raffel et al. 2019) & BART (Lewis et al. 2019) kept both halves. The encoder is BERT-style (full mask) — it builds a rich bidirectional representation of the input. The decoder is GPT-style (causal mask) on its own output tokens, plus a third mask type: cross-attention, where decoder queries can look at every encoder position (no causality constraint, because the encoder output is fully known in advance).

Each sub-component computes exactly the same scaled dot-product attention — softmax(QK⊤/√d + mask)V — the only thing that changes between the three families is what values sit inside that additive mask matrix: zeros for allowed pairs, −∞ for forbidden pairs.

Design decision: why not always use the full mask?

Full bidirectional attention is strictly more informative — so why doesn't GPT use it? Because GPT is trained to generate: at inference time token 5 genuinely does not exist yet, so if training let token 3 attend to token 5, the model would learn a shortcut it can never use at test time (exposure bias / train-test mismatch). The causal mask forces training and inference to see identical information at every position.

3
Why It Works — The Masking Invariant
▼

The invariant that makes each architecture correct for its job is: a token may only condition on information that is actually available when the model is used.

  • BERT is never asked to predict the "next" token in an unseen future — it fills in blanks inside a fully-observed sentence. So attending in both directions never leaks information it wouldn't have at use-time. This is why BERT cannot generate free text token-by-token (there's no notion of "not yet written" tokens for it to respect).
  • GPT is asked to predict token t+1 having only produced tokens 1..t. The causal mask is exactly the mathematical statement of "you may not see the future," which guarantees training loss matches deployment behavior.
  • T5 satisfies both invariants at once by splitting the model in two: the encoder's "future" (the rest of the input sentence) is always fully available, so it gets a full mask; the decoder's future (words not yet generated) is not available, so it gets a causal mask; and cross-attention is safe to be full because the entire encoded input is fixed and known before decoding starts.
Common misconception

"Decoder-only models can't understand context as well as encoders." Not quite — a causal-masked model still sees all preceding context, which for long generated sequences can be substantial. The real trade-off is that the first tokens in a decoder-only sequence are computed with very little context, whereas in an encoder every token — including the first — sees the entire sequence immediately.

The Math — Masked Attention
▼

Standard scaled dot-product attention for query/key/value matrices \(Q, K, V \in \mathbb{R}^{n\times d}\):

$$\text{Attention}(Q,K,V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d}} + M\right)V$$

Every architecture uses this exact formula. Only the additive mask matrix \(M \in \mathbb{R}^{n\times n}\) (or \(n \times m\) for cross-attention) differs:

$$M^{\text{full}}_{ij} = 0 \quad \forall i,j \qquad\qquad M^{\text{causal}}_{ij} = \begin{cases} 0 & j \le i \\ -\infty & j > i \end{cases} \qquad\qquad M^{\text{cross}}_{ij} = 0 \quad \forall i,j$$

Because \(e^{-\infty} = 0\), adding \(-\infty\) before the softmax zeroes out that pair's contribution entirely — the query at position \(i\) receives no gradient signal and no value from a masked key at position \(j\). In practice this is implemented as a large negative number (e.g. -1e9) for numerical stability rather than literal infinity.

Cross-attention in T5's decoder layer is the same softmax formula but with queries from the decoder's hidden states \(Q = H^{dec}W_Q\) and keys/values from the final encoder output \(K = H^{enc}W_K,\ V = H^{enc}W_V\) — so \(M^{\text{cross}}\) has shape \((n_{dec} \times n_{enc})\) and is always full (zero), since the whole encoder output is a fixed, fully-observed conditioning signal by the time decoding starts.

Formula box — per-layer mask summary

BERT layer: \(\text{Attn}(Q,K,V,M^{\text{full}})\), self-attention only.
GPT layer: \(\text{Attn}(Q,K,V,M^{\text{causal}})\), self-attention only.
T5 encoder layer: \(\text{Attn}(Q,K,V,M^{\text{full}})\), self-attention.
T5 decoder layer: \(\text{Attn}(Q,K,V,M^{\text{causal}})\) self-attention, then \(\text{Attn}(Q^{dec},K^{enc},V^{enc},M^{\text{cross}})\) cross-attention.

Subtlety

The causal mask is applied identically at training and inference for GPT — but at inference, generation is literally sequential (one token at a time via a KV-cache), so the mask is almost trivial: there simply are no future keys yet. At training time, the whole target sequence is available in parallel, so the explicit \(-\infty\) mask is what prevents the model from "looking ahead" through parallelized matrix multiplication.

Decision rule

Need to understand or classify fixed input → encoder-only. Need to generate open-ended continuations → decoder-only (this is why nearly all modern chat LLMs are decoder-only — it's a strict superset of "understanding" once scaled). Need to transform a well-defined input into a structurally different output (translate, summarize) → encoder-decoder, though large decoder-only models can now also be prompted to do this reasonably well.
