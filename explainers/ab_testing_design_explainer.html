A/B Testing Design

Sample size, significance, power, MDE — and the tradeoffs between them
Intermediate Probability & Stats Experimentation Must Know
1
The 30-Second Version
▼

A/B testing is how you prove that a product change actually works — not just looks good on a dashboard. You split users randomly into control (A) and treatment (B), measure a metric, and use statistics to decide whether the difference is real or noise.

The four quantities you must set before collecting any data:

  • α (significance level) — acceptable false-alarm rate (typically 0.05)
  • 1−β (power) — probability of detecting a real effect (typically 0.80)
  • Δ (MDE) — minimum detectable effect: smallest lift that matters to the business
  • n (sample size per arm) — computed from the three above
💡 If you remember one thing

The master formula: $$n \approx \frac{2(z_{\alpha/2}+z_\beta)^2\,\sigma^2}{\Delta^2}$$ For \(\alpha=0.05\), power\(=80\%\), Cohen's \(d=\Delta/\sigma=0.20\): you need ~393 users per arm. Because of \(\Delta^2\) in the denominator, halving the MDE quadruples the required sample size — the most important intuition in experimental design.

2
The Four Levers Every Experimenter Controls
▼

Lever 1: Significance Level α

\(\alpha\) is the false positive rate — the probability of declaring a winner when there is no real effect. Standard choice is 5% (one in 20 tests will be a false positive purely by chance). For a two-sided test, the critical z-value is \(z_{\alpha/2}=1.96\). Lowering \(\alpha\) (stricter) increases required n. High-stakes decisions (medical, legal) use \(\alpha=0.01\); rapid-cycle product teams sometimes relax to \(\alpha=0.10\).

Lever 2: Power 1−β

Power is the probability of detecting a real effect when one exists. Its complement \(\beta\) is the false negative rate. Industry default is 80% power (\(z_\beta=0.842\)). At 90% power (\(z_\beta=1.282\)) you need ~34% more samples per arm. Raising power is quadratically expensive in n.

Lever 3: Minimum Detectable Effect (MDE)

The MDE \(\Delta\) is the smallest effect the business cares about. This is a business decision, not a statistical one. Setting a tiny MDE requires millions of users. Express as Cohen's d = \(\Delta/\sigma\) for continuous metrics; for proportions, d ≈ \((p_2-p_1)/\sqrt{p(1-p)}\).

🔑 The Quadratic Penalty on MDE

Because n scales as \(1/\Delta^2\), reducing the MDE by 2× multiplies required sample size by 4×. This is why "let's just run it longer" is often the wrong answer — question whether the MDE is set too small instead.

Lever 4: Sample Size n

With the other three locked in, n is a calculation, not a choice. The two-sided, two-sample formula (equal group sizes, equal variance):

$$n \approx \frac{2\left(z_{\alpha/2}+z_\beta\right)^2\sigma^2}{\Delta^2} = \frac{2\left(z_{\alpha/2}+z_\beta\right)^2}{d^2}$$

For proportions with the Fleiss correction (accounts for different variances under H₀ and H₁):

$$n = \frac{\left(z_{\alpha/2}\sqrt{2\bar{p}(1-\bar{p})} + z_\beta\sqrt{p_1(1-p_1)+p_2(1-p_2)}\right)^2}{(p_2-p_1)^2}$$
⚠️ Common Mistake: Unequal Allocation

Optimal power is at 50:50. A 90:10 split needs ~3.6× more total users than 50:50 to achieve the same power, because the smaller arm is the bottleneck. If you must ramp slowly, account for this in planning.

3
Math: Where Does the Formula Come From?
▼

Two-Sample Z-Test Setup

Observe \(\bar{X}_A\) from \(n\) control users and \(\bar{X}_B\) from \(n\) treatment users (equal variance \(\sigma^2\)). The test statistic:

$$Z = \frac{\bar{X}_B - \bar{X}_A}{\sigma\sqrt{2/n}} \xrightarrow{H_0} \mathcal{N}(0,1)$$

We reject H₀ at level \(\alpha\) (two-sided) when \(|Z|>z_{\alpha/2}\).

Derivation via the Power Condition

Under H₁ (true mean difference = \(\Delta\)), the test statistic shifts:

$$Z \sim \mathcal{N}\!\left(\frac{\Delta}{\sigma\sqrt{2/n}},\; 1\right)$$

Power equals \(1-\beta\) when the non-centrality parameter equals \(z_{\alpha/2}+z_\beta\):

$$\frac{\Delta}{\sigma\sqrt{2/n}} = z_{\alpha/2}+z_\beta \implies \Delta^2\frac{n}{2} = \sigma^2(z_{\alpha/2}+z_\beta)^2$$

Solving for n:

$$\boxed{n = \frac{2\sigma^2(z_{\alpha/2}+z_\beta)^2}{\Delta^2}}$$

Numerical Verification

For \(\alpha=0.05\) (two-sided), power\(=80\%\), Cohen's \(d=0.20\):

$$n = \frac{2(1.960+0.842)^2}{(0.20)^2} = \frac{2\times 7.852}{0.04} = 392.6 \approx 393 \;\text{per arm}$$

Power sensitivity: power\(=90\%\) ⇒ \(n=526\); power\(=95\%\) ⇒ \(n=651\). Effect size table (fixed \(\alpha=0.05\), power\(=80\%\)):

∑ Connection to t-test

For small samples, replace \(z_{\alpha/2}\) with \(t_{\alpha/2,\,2n-2}\) (Welch's t with 2n−2 degrees of freedom). The t-distribution has heavier tails, requiring slightly more samples. The z-approximation is reliable for \(n\geq30\) per arm.

From-Scratch Python Implementation
▼

A complete A/B test toolbox — sample size, analysis, effect size — no external dependencies beyond math.

import math
# ─── Normal distribution helpers ────────────────────────────────────────────
def pnorm(x): # standard normal CDF
t = 1/(1 + 0.2316419*abs(x))
d = 0.3989422820*math.exp(-x*x/2)
p = 1 - d*t*(0.3193815 + t*(-0.3565638
+ t*(1.7814779 + t*(-1.8212560 + t*1.3302744))))
return p if x >= 0 else 1 - p
def qnorm(p, tol=1e-10): # inverse CDF (Newton-Raphson)
assert 0 < p < 1
x = 0.0 if p > 0.5 else -2.0
for _ in range(60):
dx = (pnorm(x) - p) / (0.3989422820*math.exp(-x*x/2))
x -= dx
if abs(dx) < tol: break
return x
# ─── Sample size calculator ──────────────────────────────────────────────────
def sample_size(alpha=0.05, power=0.80, cohen_d=0.20):
"""n per arm for two-sided two-sample z-test."""
za2 = qnorm(1 - alpha/2) # 1.9600 for alpha=0.05
zb = qnorm(power) # 0.8416 for power=0.80
return math.ceil(2*(za2 + zb)**2 / cohen_d**2)
# ─── Two-sample z-test ───────────────────────────────────────────────────────
def two_sample_ztest(xa, xb, sigma):
"""Returns (z_stat, p_value, cohen_d, 95% CI for delta)."""
na, nb = len(xa), len(xb)
mean_a = sum(xa)/na
mean_b = sum(xb)/nb
delta = mean_b - mean_a
se = sigma * math.sqrt(1/na + 1/nb)
z = delta / se
p = 2*(1 - pnorm(abs(z)))
ci = (delta - 1.96*se, delta + 1.96*se)
d = delta / sigma
return {"z": round(z,4), "p": round(p,4),
"cohen_d": round(d,4), "ci_95": (round(ci[0],4), round(ci[1],4))}
# ─── Example ─────────────────────────────────────────────────────────────────
if __name__ == "__main__":
# Plan: detect d=0.20 with 80% power, alpha=0.05
n = sample_size(alpha=0.05, power=0.80, cohen_d=0.20)
print(f"Need {n} users per arm ({2*n} total)")
# Output: Need 393 users per arm (786 total)
# Simulate an experiment (true delta = 0.20 * sigma = 0.20)
import random; random.seed(42)
xa = [random.gauss(0.0, 1.0) for _ in range(n)]
xb = [random.gauss(0.2, 1.0) for _ in range(n)]
result = two_sample_ztest(xa, xb, sigma=1.0)
print(result)
# {'z': 2.4..., 'p': 0.015..., 'cohen_d': 0.18..., 'ci_95': (0.03, 0.33)}

Pitfalls, Multiple Metrics & Interview Q&A
▼
🚫 Pitfall 1: Peeking / Optional Stopping

Stopping when p < 0.05 (and running longer when p > 0.05) inflates type-I error far above α. With 5 equally-spaced looks and α=0.05, true error is ~19%. Fix: pre-register sample size and stop once; or use sequential testing (SPRT, always-valid confidence intervals, mSPRT) that controls error at every look.

🚫 Pitfall 2: Multiple Metrics & Multiple Variants

Testing 10 metrics at α=0.05 each gives FWER ≈ 1−0.95¹⁰ ≈ 40%. Solutions: (1) Bonferroni correction — use α/k per metric (conservative); (2) Holm-Bonferroni (more powerful); (3) Pre-specify a single primary metric and treat others as secondary; (4) FDR control (Benjamini-Hochberg) when many metrics are exploratory.

⚠️ Pitfall 3: Network Effects (SUTVA violation)

Standard A/B assumes the Stable Unit Treatment Value Assumption: one user's assignment doesn't affect another's outcome. In social networks, marketplaces, or email/push channels this breaks down. Fixes: cluster randomization (randomize at the group level), switchback experiments (time-based), or geo experiments.

⚠️ Pitfall 4: Simpson's Paradox & Covariate Imbalance

Even with randomization, small experiments can show covariate imbalance (e.g., more mobile users in treatment). Always check balance before analyzing. Use CUPED (Controlled-experiment Using Pre-Experiment Data) to reduce variance by regressing out pre-experiment covariates: \(\hat{Y}' = Y - \theta(X - \bar{X})\), which can reduce required n by 30–50%.

Interview Q&A

QuestionKey Answer
Why do we need a pre-specified sample size?Without it, optional stopping inflates type-I error. The p-value is only calibrated at the pre-specified stopping point.
What is statistical power, intuitively?The probability of not missing a real effect. Low power = lots of wasted experiments that return "no significance" even when the effect is real.
How do you handle multiple comparisons?Bonferroni (divide α by number of tests), Holm-Bonferroni (step-down, less conservative), or Benjamini-Hochberg FDR control for exploratory analysis.
What's the tradeoff between MDE and sample size?Quadratic: halve MDE ⇒ 4× more samples. This forces you to think hard about the minimum lift that's actually worth caring about.
What is CUPED?A variance reduction technique that subtracts a pre-experiment covariate (correlated with the metric) from each user's outcome, reducing residual variance and effectively shrinking required n.
When would you use a t-test instead of a z-test?Small samples (n < 30 per arm) or unknown population variance. The Welch t-test is preferred for unequal group sizes/variances.
