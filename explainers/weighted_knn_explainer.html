Weighted KNN (Distance-Weighted)

Each neighbor votes in proportion to its closeness — nearer points count more
Intermediate Classical ML Supervised Learning O(n·d) predict
1
Understanding the Concept
▼

Standard K-Nearest Neighbors treats all K neighbors as equals: each casts one vote regardless of whether they are 0.1 units away or 10 units away. That is often wrong. A point sitting right on top of the query should scream its class; a point on the fringes should whisper.

Distance-weighted KNN fixes this by giving each neighbor a vote proportional to its closeness. The most common weight is the inverse distance: \(w_i = 1/d(\mathbf{x}, \mathbf{x}_i)\). A neighbor at distance 0.2 gets weight 5; one at distance 2.0 gets weight 0.5 — ten times less influence.

Intuition

Think of it like gravity. Your closest neighbor pulls your prediction toward its class with enormous force. Distant neighbors exert a gentle tug, not a decisive vote. The final prediction goes to whichever class accumulates the most total gravitational pull.

Real-World Analogy

You are lost in an unfamiliar city and ask five strangers for directions. The person standing right next to you gives detailed, loud advice. Four people a block away give quiet suggestions. You weight the nearby person's advice much more heavily — that is distance-weighted KNN.

One-Sentence Summary

Weighted KNN replaces equal votes with \(w_i = 1/d_i\) weights (or a kernel), so nearer neighbors dominate the prediction, producing smoother decision boundaries and graceful tie-breaking.

2
How It Works Internally
▼

The algorithm has exactly four stages:

1. Compute All Distances

For a query point \(\mathbf{x}\), compute \(d_i = \|\mathbf{x} - \mathbf{x}_i\|_2\) for every training point. Euclidean distance is the default but Manhattan, Minkowski, and cosine similarity are common alternatives.

2. Select K Nearest Neighbors

Sort by \(d_i\) and take the K smallest. This is identical to standard KNN — the difference lies only in what happens next.

3. Compute Weights

Assign a weight to each of the K neighbors. The most common scheme:

$$w_i = \frac{1}{d(\mathbf{x}, \mathbf{x}_i)}$$

Alternative kernel weights that stay bounded when \(d_i \to 0\):

$$w_i^{\text{Gaussian}} = \exp\!\left(-\frac{d_i^2}{2h^2}\right), \qquad w_i^{\text{Epanechnikov}} = \max\!\left(0,\, 1 - \frac{d_i^2}{h^2}\right)$$
Edge Case: Exact Tie (d = 0)

If a test point exactly coincides with a training point, \(1/d_i = \infty\). In practice: return the training label directly (it is the perfect match), or use \(w_i = 1/(d_i + \varepsilon)\) for numerical safety.

4. Weighted Aggregation

Classification — sum weights per class, predict the argmax:

$$\hat{y} = \underset{c}{\operatorname{argmax}} \sum_{i \in \mathcal{N}_K(\mathbf{x})} w_i \cdot \mathbf{1}[y_i = c]$$

Regression — weighted average of neighbor labels:

$$\hat{y} = \frac{\sum_{i \in \mathcal{N}_K(\mathbf{x})} w_i\, y_i}{\sum_{i \in \mathcal{N}_K(\mathbf{x})} w_i}$$

The denominator normalises so weights sum to 1, ensuring the output stays in the range of training labels.

Design Insight

Unlike standard KNN, ties (equal votes for two classes) almost never occur in weighted KNN because the weights are continuous real numbers. This alone is a practical advantage — no need for a tie-breaking rule.

3
The Math Behind It
▼

Notation

Let \(\mathcal{N}_K(\mathbf{x})\) denote the index set of the K nearest neighbors of query \(\mathbf{x} \in \mathbb{R}^d\). Let \(d_i = \|\mathbf{x} - \mathbf{x}_i\|_2\).

Classification Decision Rule

Define the weighted class score for class \(c\):

$$s_c(\mathbf{x}) = \sum_{i \in \mathcal{N}_K(\mathbf{x})} \frac{1}{d_i} \cdot \mathbf{1}[y_i = c]$$

The predicted class is \(\hat{y} = \underset{c}{\operatorname{argmax}}\; s_c(\mathbf{x})\). Because weights \(w_i = 1/d_i > 0\), this is equivalent to a probabilistic estimate:

$$\hat{P}(Y = c \mid \mathbf{x}) = \frac{s_c(\mathbf{x})}{\sum_{i \in \mathcal{N}_K(\mathbf{x})} w_i}$$

Regression Estimate

$$\hat{f}(\mathbf{x}) = \frac{\displaystyle\sum_{i \in \mathcal{N}_K(\mathbf{x})} w_i\, y_i}{\displaystyle\sum_{i \in \mathcal{N}_K(\mathbf{x})} w_i}$$

This is a Nadaraya–Watson kernel regression restricted to the K nearest neighbors. As \(K \to n\) (use all points) and with the Gaussian kernel, it recovers the full Nadaraya–Watson estimator.

Kernel Generalisation

Any positive kernel \(K(d)\) with \(K(0) > K(d)\) for \(d > 0\) gives a valid weighting. The Gaussian kernel \(w_i = e^{-d_i^2/(2h^2)}\) is smooth and never zero, so it avoids the \(1/0\) problem entirely. The bandwidth \(h\) plays a role analogous to K in standard KNN.

Key Takeaways
▼
When to Use Weighted KNN

Use distance-weighted KNN whenever: (1) training density is uneven, (2) a single very close neighbor should dominate, (3) you want smoother decision boundaries without tuning K aggressively, or (4) ties in standard KNN are a practical problem.

vs. Standard KNN

PropertyStandard KNNWeighted KNN
Vote schemeUniform (1 vote each)\(w_i = 1/d_i\) (or kernel)
Sensitivity to KHigh — K matters a lotLower — close neighbors self-regulate
Decision boundaryStepped / blockySmoother, continuous
TiesCommon (requires rule)Almost never occur
Probability outputProportion (coarse)Inverse-distance soft probability
Computational costO(nd)O(nd) — identical
Pitfalls

Scale sensitivity: distances are meaningless if features have different scales — always standardise. High dimensions: all distances become similar (curse of dimensionality) making weights nearly uniform anyway. Exact duplicates: \(d_i=0\) needs special handling.

Weighted KNN is the default choice in sklearn.neighbors.KNeighborsClassifier(weights='distance') and almost always outperforms uniform KNN on real datasets with little extra cost.

From-Scratch Code
▼
import numpy as np
from collections import Counter
def weighted_knn_classify(X_train, y_train, x_query, K=5, epsilon=1e-9):
"""Distance-weighted KNN classifier. w_i = 1 / d_i.
epsilon guards against exact duplicate points (d=0)."""
# 1. Compute Euclidean distances to all training points
diffs = X_train - x_query # shape (n, d)
dists = np.sqrt((diffs**2).sum(1)) # shape (n,)
# 2. Select K nearest neighbor indices
k_idx = np.argsort(dists)[:K]
k_dists = dists[k_idx] # the K smallest distances
k_labels = y_train[k_idx]
# 3. Compute inverse-distance weights (add epsilon for safety)
weights = 1.0 / (k_dists + epsilon)
# 4. Sum weights per class → argmax
classes = np.unique(y_train)
scores = {c: weights[k_labels == c].sum() for c in classes}
return max(scores, key=scores.get)
def weighted_knn_regress(X_train, y_train, x_query, K=5, epsilon=1e-9):
"""Distance-weighted KNN regression: weighted average of neighbor labels."""
dists = np.sqrt(((X_train - x_query)**2).sum(1))
k_idx = np.argsort(dists)[:K]
k_dists = dists[k_idx]; k_labels = y_train[k_idx]
weights = 1.0 / (k_dists + epsilon)
return (weights * k_labels).sum() / weights.sum() # normalised avg
# --- sklearn production usage ---
from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
# Always scale before KNN — distances are meaningless otherwise
pipe = Pipeline([
('scaler', StandardScaler()),
('knn', KNeighborsClassifier(
n_neighbors=5,
weights='distance', # ← the key flag for weighted KNN
metric='euclidean',
algorithm='ball_tree', # efficient for d < 20
))
])
pipe.fit(X_train, y_train)
proba = pipe.predict_proba(X_test) # soft inverse-distance probabilities
