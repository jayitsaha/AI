Advanced Sequence Models Efficient Attention O(1) inference / token
1
Understanding RWKV
▼

What is it? RWKV ("Receptance Weighted Key Value") is a language model architecture that gets the best of two worlds. During training, it can be unrolled into a form that processes an entire sequence in parallel, just like a Transformer. During inference (generating text token-by-token), it collapses into a plain recurrent neural network that only needs a small, fixed-size state — no matter how long the conversation gets.

Analogy: A Transformer generating text is like a detective who, to solve today's case, re-reads the entire case file from page one every single time a new clue arrives — the file (KV cache) keeps growing, and re-reading it gets slower and more expensive. RWKV is like a detective who keeps a small notebook: each new clue updates a few key notes (with older notes fading in relevance — "time-decay"), and the notebook never grows past a fixed number of pages, no matter how long the case runs.

💡 If you remember one thing

RWKV replaces quadratic self-attention with a linear recurrence (the "WKV" operator) that has two mathematically equivalent forms: a parallelizable sum for training, and a step-by-step update — $$a_t = e^{-w}a_{t-1} + e^{k_t}v_t,\quad b_t = e^{-w}b_{t-1} + e^{k_t}$$ — for inference, giving \(O(1)\) memory and compute per generated token instead of the Transformer's ever-growing KV cache.

How RWKV Works Internally
▼

The Building Blocks

Each RWKV block has two sub-layers, echoing a Transformer block but replacing self-attention entirely:

  • Time-Mixing (replaces self-attention): produces receptance \(r_t\), key \(k_t\), value \(v_t\) from a blend of the current and previous token's hidden state ("token shift"), then runs the WKV linear-attention recurrence over them.
  • Channel-Mixing (replaces the FFN): a position-wise gated MLP, also using token-shift, that mixes information across feature channels.

Token Shift

Before projecting, RWKV linearly interpolates each token's hidden state \(x_t\) with the previous token's \(x_{t-1}\): \(x_t^{\mu} = \mu \odot x_t + (1-\mu)\odot x_{t-1}\). This gives every projection (R, K, V) a cheap, built-in one-step lookback — a tiny "local attention" for free.

The WKV Recurrence — the Heart of RWKV

Instead of computing an \(n\times n\) attention matrix, RWKV maintains, per channel, a running weighted sum of past values (numerator \(a\)) and past weights (denominator \(b\)). Each channel has a learned time-decay \(w>0\) (how fast old information fades) and a learned bonus \(u\) (extra emphasis given to the current token so it isn't drowned out by decayed history):

$$\text{wkv}_t = \frac{a_{t-1} + e^{u+k_t}v_t}{b_{t-1} + e^{u+k_t}}, \qquad a_t = e^{-w}a_{t-1} + e^{k_t}v_t,\quad b_t = e^{-w}b_{t-1} + e^{k_t}$$

Finally, the receptance gate \(r_t\) (passed through a sigmoid) decides how much of this WKV output to let through: \(\text{output}_t = \sigma(r_t)\odot \text{wkv}_t\), then an output projection mixes channels.

Numerical Trace (single channel, \(w=0.5\), \(u=0.3\))

Start \(a_0=0, b_0=0\). Token 1: \(k_1=0.80, v_1=1.20\) → \(\text{wkv}_1 = e^{1.10}\cdot1.20 / e^{1.10} = 1.20\) (only the current token exists). Update state: \(a_1=e^{0.80}\cdot1.20\approx2.67\), \(b_1=e^{0.80}\approx2.23\). Token 2: \(k_2=-0.30, v_2=0.50\) → numerator \(=a_1+e^{u+k_2}v_2 = 2.67 + e^{0.0}\cdot0.5\approx3.17\), denominator \(=b_1+e^{0.0}\approx3.23\) → \(\text{wkv}_2\approx0.98\). Note the state (just two numbers per channel) never grows — the interactive walkthrough below runs this exact recurrence live for 8 tokens.

Design Decision: Why decay + bonus, not raw softmax attention?

Softmax attention needs every past key/value kept around to normalize over. RWKV's trick is that \(\sum e^{k_i}\) and \(\sum e^{k_i}v_i\) can each be accumulated incrementally with an exponential decay — mathematically equivalent to a weighted softmax-like average over the whole past, but computed as a running total. The bonus \(u\) exists because, without it, the current token's key would be decayed by \(w\) exactly like everything else and lose its "recency" edge.

🔑 Key Property

The WKV recurrence has two equivalent forms: a closed-form parallel sum over all positions (used during training, like attention) and a two-scalar-per-channel recurrent update (used during inference). This dual form is exactly what makes RWKV "parallelizable like a Transformer, recurrent like an RNN."

Why It Works — The Math
▼

The Parallel (Training) Form

Written out over all positions \(1,\dots,t\), the WKV output for position \(t\) is a weighted average of all past and present values, where weights decay geometrically the further back in time they are, except the current position gets a special bonus \(u\) instead of decay:

$$\text{wkv}_t = \frac{\displaystyle\sum_{i=1}^{t-1} e^{-(t-1-i)w+k_i}\,v_i \;+\; e^{u+k_t}v_t}{\displaystyle\sum_{i=1}^{t-1} e^{-(t-1-i)w+k_i} \;+\; e^{u+k_t}}$$

This looks like a softmax-weighted attention sum (numerator and denominator, exponentiated scores) — but the "attention scores" \(e^{-(t-1-i)w+k_i}\) depend only on relative distance \((t-1-i)\) and the key \(k_i\), never on a query. There is no \(Q\), no pairwise dot product, and no \(n\times n\) matrix.

Deriving the Recurrent (Inference) Form

Define the running numerator and denominator excluding the bonus term as \(a_{t-1}=\sum_{i=1}^{t-1}e^{-(t-1-i)w+k_i}v_i\) and \(b_{t-1}=\sum_{i=1}^{t-1}e^{-(t-1-i)w+k_i}\). Factor out one decay step:

$$a_t = e^{-w}a_{t-1} + e^{k_t}v_t \qquad b_t = e^{-w}b_{t-1} + e^{k_t}$$

and the output at time \(t\) simply mixes in the current token with its bonus instead of decay: \(\text{wkv}_t = (a_{t-1}+e^{u+k_t}v_t)/(b_{t-1}+e^{u+k_t})\). Because \((a_t,b_t)\) is a sufficient statistic for the entire past, generation needs only these two numbers per channel — this is the algebraic reason RWKV memory is \(O(1)\) in sequence length, versus the Transformer KV cache's \(O(t)\).

Numerical Stability

In practice \(k_t\) and cumulative decay can make \(e^{k_t}\) overflow. Real implementations track a running max \(p_t = \max(p_{t-1}-w, u+k_t)\) and rewrite the recurrence in log-space (a log-sum-exp trick), exactly as softmax subtracts its max for stability — the math is identical, just shifted.

⚠️ Common Misconception

"RWKV has no attention." It does compute an attention-like weighted average of values — it just never materializes the \(n\times n\) score matrix, and the weights are distance-based decay rather than learned query-key similarity. This trades expressiveness (no content-based query matching) for constant memory and linear-time training.

When to use RWKV:

  • Long-context generation / streaming chat where KV-cache memory would explode
  • Edge or resource-constrained deployment needing constant, predictable memory
  • Very long documents or genomic/audio sequences where \(O(n^2)\) attention is infeasible

When NOT to use:

  • Tasks needing precise content-based long-range retrieval (e.g., exact copy of a token from far back) — decay-based mixing is weaker than direct attention
  • Small-scale tasks where a standard Transformer already fits comfortably in memory

Code Trace — WKV Recurrence from Scratch
▼

The exact recurrence powering the visualization above, in NumPy. This is the O(1)-memory inference path — no cache of past tokens is ever kept.

import numpy as np
def rwkv_step(a_prev, b_prev, k_t, v_t, w, u):
"""One O(1) recurrent update — no history is stored."""
bonus = np.exp(u + k_t) # current token gets bonus, not decay
wkv_t = (a_prev + bonus * v_t) / (b_prev + bonus)
a_t = np.exp(-w) * a_prev + np.exp(k_t) * v_t # decay old state, add new
b_t = np.exp(-w) * b_prev + np.exp(k_t)
return wkv_t, a_t, b_t # state stays 2 floats/channel forever
a, b = 0.0, 0.0 # fixed-size state, init once
for k_t, v_t in token_stream: # generation loop — sequence length irrelevant
wkv_t, a, b = rwkv_step(a, b, k_t, v_t, w=0.5, u=0.3)
r_t = sigmoid(receptance_proj(x_t))
output_t = r_t * wkv_t # gate, then project back to hidden dim
⚠️ Gotcha

Naive np.exp(k_t) overflows for large logits after many decay steps. Production RWKV kernels (e.g. the official CUDA WKV kernel) track a running max and compute everything in log-space — same math, numerically safe.
