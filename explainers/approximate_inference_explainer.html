Understanding Approximate Inference
▼

What is inference? In probabilistic graphical models (like Bayesian Networks or Markov Random Fields), inference means computing the probability of certain variables given others. This usually boils down to finding marginal probabilities (e.g., \(P(X_i)\)) or conditional probabilities (e.g., \(P(X_i \mid \text{evidence})\)).

Why approximate? For many real-world graphical models, especially those with many variables, complex dependencies (like "loops" in the graph structure), or high-dimensional variables, exact inference is computationally intractable. It often requires summing or integrating over an exponential number of states, making it an NP-hard problem. Approximate inference methods trade off some accuracy for computational feasibility.

There are two main families of approximate inference techniques:

  • Deterministic Methods: These algorithms transform the inference problem into an optimization problem or use iterative message-passing schemes. Examples include Variational Inference (e.g., Mean Field) and Loopy Belief Propagation (LBP). They aim to find a "best guess" for the probabilities.
  • Stochastic Methods (Sampling): These algorithms draw random samples from the target probability distribution. By observing the frequency of different variable states in these samples, we can estimate their probabilities. Examples include Importance Sampling and Markov Chain Monte Carlo (MCMC) methods like Gibbs Sampling.

Analogy: Imagine you want to know the average income of everyone in a large country. Exact inference would be a full census, which is too expensive. Approximate inference is like taking a well-designed smaller survey (sampling) or asking people in local communities to iteratively share their estimates and update them based on neighbors' information (LBP).

💡 If you remember one thing

Approximate inference is a necessary trade-off between computational cost and accuracy for complex probabilistic models. It allows us to work with models that would otherwise be intractable, enabling applications in areas like computer vision, natural language processing, and bioinformatics.

How Loopy Belief Propagation (LBP) Works Internally
▼

Belief Propagation (BP) is an algorithm for exact inference on graphical models that have a tree structure (or are "polytrees," where multiple parents can share children but there's still no undirected cycle). It works by passing "messages" between neighboring nodes, where each message summarizes a node's belief about the state of its neighbor's variable.

The Loopy Extension

Loopy Belief Propagation (LBP) applies the same message-passing rules to general graphs that contain cycles (loops). Unlike on trees, where messages only need to pass once in each direction, on loopy graphs, messages must be passed iteratively until they converge (or a maximum number of iterations is reached). Because of the loops, messages can "cycle" back to their origin, potentially causing oscillations or non-convergence, and the resulting beliefs are only approximations.

Message Passing Rules (for a pairwise Markov Random Field)

For a variable \(X_i\) and its neighbor \(X_j\), the message \(m_{i \to j}(x_j)\) from \(X_i\) to \(X_j\) about the state \(x_j\) of \(X_j\) is typically computed as:

$$m_{i \to j}(x_j) = \sum_{x_i} \left( \psi_{ij}(x_i, x_j) \cdot \phi_i(x_i) \cdot \prod_{k \in N(i) \setminus \{j\}} m_{k \to i}(x_i) \right)$$

Where:

  • \(\psi_{ij}(x_i, x_j)\) is the pairwise potential (compatibility function) between \(X_i\) and \(X_j\).
  • \(\phi_i(x_i)\) is the local evidence (unary potential) for \(X_i\).
  • \(N(i) \setminus \{j\}\) are all neighbors of \(X_i\) except \(X_j\).
  • \(m_{k \to i}(x_i)\) are incoming messages to \(X_i\) from its other neighbors.

These messages are normalized to sum to 1 to prevent numerical issues. The process iterates: all nodes compute and send messages simultaneously (or in a fixed schedule), then update their beliefs based on newly received messages.

Belief Calculation

After messages have converged (or after a fixed number of iterations), the approximate belief (marginal probability) for a variable \(X_i\) in state \(x_i\) is given by:

$$Bel(x_i) \propto \phi_i(x_i) \cdot \prod_{k \in N(i)} m_{k \to i}(x_i)$$

This belief is then normalized to sum to 1 across all states of \(X_i\).

🔑 Key Property

LBP's strength lies in its ability to efficiently propagate local information across the graph. While not exact for loopy graphs, it often provides good approximations in practice and is widely used in applications like image denoising, error-correcting codes, and computer vision.

How Sampling Methods Work Internally
▼

Sampling methods approximate inference by generating a set of configurations (samples) of the random variables according to the model's underlying probability distribution. The frequencies of these configurations then serve as estimates for the true probabilities. This approach is particularly powerful for high-dimensional models or when the exact distribution is too complex to compute directly.

The General Idea

If we can draw \(N\) samples, \(X^{(1)}, X^{(2)}, \dots, X^{(N)}\), from the joint distribution \(P(X)\), then the marginal probability of a variable \(X_i\) being in state \(x_i\) can be estimated by:

$$P(X_i=x_i) \approx \frac{1}{N} \sum_{s=1}^N \mathbb{I}(X_i^{(s)}=x_i)$$

where \(\mathbb{I}(\cdot)\) is the indicator function (1 if true, 0 if false). The accuracy of this approximation improves as \(N \to \infty\).

Markov Chain Monte Carlo (MCMC) and Gibbs Sampling

For complex distributions where direct sampling is not feasible, MCMC methods are used. They construct a Markov chain whose stationary distribution is the target distribution \(P(X)\). After a "burn-in" period, samples drawn from this chain will be approximately from \(P(X)\).

Gibbs Sampling is a popular MCMC algorithm. It works by iteratively sampling each variable \(X_i\) from its conditional distribution given the current states of all other variables. For an MRF, this conditional distribution is proportional to the product of all potentials (factors) that involve \(X_i\):

$$P(X_i \mid X_{\text{rest}}) = \frac{P(X_i, X_{\text{rest}})}{P(X_{\text{rest}})} \propto \prod_{f \in F(X_i)} \psi_f(\text{clique}_f)$$

where \(F(X_i)\) is the set of factors that involve \(X_i\). The update rule for Gibbs sampling is:

  1. Initialize all variables \(X^{(0)} = (x_1^{(0)}, \dots, x_n^{(0)})\) randomly.
  2. For \(t = 0, \dots, N-1\):
    • For each variable \(X_i\) (in some order): $$X_i^{(t+1)} \sim P(X_i \mid X_1^{(t+1)}, \dots, X_{i-1}^{(t+1)}, X_{i+1}^{(t)}, \dots, X_n^{(t)})$$

This means we sample \(X_i\) based on the most recently updated values of its neighbors. Gibbs sampling is particularly straightforward when these conditional distributions are easy to compute.

🔑 Key Property

Sampling methods provide a statistical guarantee: as the number of samples increases, the approximation converges to the true distribution. They are robust to graph structure (loops, high treewidth) but can be computationally expensive due to the large number of samples often required for good accuracy, especially in high-dimensional or multimodal distributions.

Key Takeaways
▼

Approximate inference methods are indispensable for tackling complex probabilistic models where exact computations are intractable. Choosing between deterministic (like LBP) and stochastic (like MCMC sampling) methods depends on the specific problem's characteristics and computational constraints.

Loopy Belief Propagation (LBP):

  • Pros: Fast per iteration, often provides good approximations, especially for sparse graphs. Deterministic output.
  • Cons: Not guaranteed to converge on loopy graphs, and if it converges, the result is not guaranteed to be the true marginal. Can oscillate or get stuck in local optima.
  • Best for: Models where speed is critical, graphs are relatively sparse or "tree-like," and a good-enough approximation is acceptable. Common in computer vision (e.g., MRFs for image segmentation), coding theory.

Sampling Methods (e.g., Gibbs Sampling):

  • Pros: Guaranteed to converge to the true marginals as the number of samples approaches infinity. Applicable to virtually any probabilistic model, regardless of graph structure. Provides a measure of uncertainty (e.g., credible intervals).
  • Cons: Can be very slow to converge, especially for high-dimensional or multimodal distributions (requiring many samples and a long burn-in). Stochastic nature means results vary slightly between runs.
  • Best for: Models where accuracy is paramount, distributions are complex or high-dimensional, and computational budget allows for many samples. Common in Bayesian inference, deep generative models.
💡 Deterministic vs. Stochastic

LBP is a deterministic approximation: it iteratively refines beliefs based on local messages. Sampling is a stochastic approximation: it generates instances from the distribution, and the empirical frequencies provide the estimate. Both are powerful tools for managing the computational burden of inference in large probabilistic models.

import numpy as np
# --- Loopy Belief Propagation (LBP) ---
def run_lbp(nodes, adj_list, unary_potentials, pairwise_potentials, max_iter=10):
messages = {} # messages[(i,j)] = {state_j: prob} from i to j
# Initialize messages to uniform
for i in nodes:
for j in adj_list[i]:
messages[(i, j)] = {0: 0.5, 1: 0.5}
for iteration in range(max_iter):
new_messages = messages.copy()
for i in nodes:
for j in adj_list[i]: # For each neighbor j of i
msg_ij = {0: 0.0, 1: 0.0}
for xj_state in [0, 1]:
sum_over_xi = 0.0
for xi_state in [0, 1]:
prod_incoming = 1.0
# Product of messages from other neighbors of i
for k in adj_list[i]:
if k != j: # Exclude the target neighbor j
prod_incoming *= messages[(k, i)][xi_state]
# Get pairwise potential (assume symmetry or consistent key)
# For (i,j) or (j,i) edge, potential is psi_ij[xi_state][xj_state]
psi_ij = pairwise_potentials.get((i, j)) or pairwise_potentials.get((j, i))
pairwise_term = psi_ij[xi_state][xj_state]
unary_term = unary_potentials[i][xi_state]
sum_over_xi += unary_term * pairwise_term * prod_incoming
msg_ij[xj_state] = sum_over_xi
# Normalize message
norm_factor = msg_ij[0] + msg_ij[1]
if norm_factor > 0:
new_messages[(i, j)] = {s: p / norm_factor for s, p in msg_ij.items()}
else: # Fallback for zero potentials
new_messages[(i, j)] = {0: 0.5, 1: 0.5}
messages = new_messages
# Calculate final beliefs (marginals)
beliefs = {}
for i in nodes:
belief_i = {0: unary_potentials[i][0], 1: unary_potentials[i][1]}
for k in adj_list[i]: # Product of all incoming messages to i
belief_i[0] *= messages[(k, i)][0]
belief_i[1] *= messages[(k, i)][1]
norm_factor = belief_i[0] + belief_i[1]
if norm_factor > 0: beliefs[i] = {s: p / norm_factor for s, p in belief_i.items()}
else: beliefs[i] = {0: 0.5, 1: 0.5}
return beliefs
# --- Gibbs Sampling ---
def run_gibbs(nodes, adj_list, unary_potentials, pairwise_potentials, num_samples=1000, burn_in=100):
current_state = {node: np.random.randint(2) for node in nodes} # Random init
sample_counts = {node: {0: 0, 1: 0} for node in nodes}
for t in range(num_samples + burn_in):
for i in nodes: # Iterate through nodes to resample
# Calculate P(X_i | X_rest) for both states of X_i
prob_xi = {0: unary_potentials[i][0], 1: unary_potentials[i][1]}
for j in adj_list[i]: # Iterate over neighbors of i
psi_ij = pairwise_potentials.get((i, j)) or pairwise_potentials.get((j, i))
prob_xi[0] *= psi_ij[0][current_state[j]]
prob_xi[1] *= psi_ij[1][current_state[j]]
# Normalize to get actual probabilities
norm_factor = prob_xi[0] + prob_xi[1]
if norm_factor > 0: prob_xi = {s: p / norm_factor for s, p in prob_xi.items()}
else: prob_xi = {0: 0.5, 1: 0.5} # Fallback for zero potentials
# Sample new state for X_i
current_state[i] = np.random.choice([0, 1], p=[prob_xi[0], prob_xi[1]])
if t >= burn_in: # After burn-in, accumulate samples
for node in nodes:
sample_counts[node][current_state[node]] += 1
# Calculate final beliefs from counts
beliefs = {}
total_sampled = num_samples
if total_sampled == 0: return {node: {0: 0.5, 1: 0.5} for node in nodes}
for node in nodes:
beliefs[node] = {0: sample_counts[node][0] / total_sampled,
1: sample_counts[node][1] / total_sampled}
return beliefs
