Mean Reciprocal Rank

A ranking metric that rewards finding the first relevant result fast — averaged across all queries.

Intermediate Ranking Evaluation Information Retrieval O(n) per query
1
Understanding MRR

Imagine you search for something online. You don't want to dig through ten irrelevant results before finding the answer — you want it at the top. Mean Reciprocal Rank (MRR) is a way to score how good a search system is at this task.

For each query, MRR looks at where the first relevant result appears in the ranked list. If it's rank 1, you score 1/1 = 1.0 (perfect). If it's rank 2, you score 1/2 = 0.5. If it's rank 3, you score 1/3 ≈ 0.33. Then MRR averages these scores across all queries.

💡 If You Remember One Thing

MRR = average of (1 ÷ rank-of-first-relevant-result) across all queries. A system that always puts the answer first scores MRR = 1.0; one that never finds anything scores MRR = 0.

Key Property

MRR cares only about the single first hit. Unlike NDCG or MAP, it completely ignores all subsequent relevant documents. It's ideal for known-item search (one target exists) and QA tasks (one correct answer).

2
How It Works — Step by Step

Given \(Q\) queries, for each query \(q_i\) a retrieval system returns a ranked list of documents. Let \(\text{rank}_i\) be the position (1-indexed) of the first relevant document in that list.

The Reciprocal Rank for query \(i\) is simply \(1 / \text{rank}_i\). If no relevant document appears in the list at all, \(\text{RR}_i = 0\).

$$\text{RR}(q_i) = \frac{1}{\text{rank}_i}$$

The Mean Reciprocal Rank averages these values over all queries:

$$\text{MRR} = \frac{1}{|Q|} \sum_{i=1}^{|Q|} \frac{1}{\text{rank}_i}$$

Worked example: Three queries with first-relevant ranks of 1, 3, and 2 respectively:

RR values: 1/1 = 1.000, 1/3 ≈ 0.333, 1/2 = 0.500

$$\text{MRR} = \frac{1}{3}(1.000 + 0.333 + 0.500) = \frac{1.833}{3} \approx 0.611$$
⚠️ Common Trap

MRR is only meaningful up to the rank cutoff \(K\). If you evaluate MRR@10, ranks beyond position 10 score 0, not the true reciprocal. Always state the cutoff when reporting MRR.

3
The Mathematics

The reciprocal function \(f(r) = 1/r\) is the key design choice. It gives a harmonic discount: the cost of not finding a result at rank 1 vs rank 2 is 0.5 (large penalty), but the difference between rank 9 and 10 is only 0.011 (minimal penalty). This reflects real user behaviour — few users scroll past the first few results.

Range: \(\text{MRR} \in (0, 1]\). Achieving 1.0 requires every query to return the relevant document at rank 1.

Asymptotic behaviour: As the first hit rank \(r \to \infty\), \(\text{RR} \to 0\). For practical purposes, MRR@10 and MRR (unlimited) are nearly identical because \(1/r\) shrinks rapidly.

$$\lim_{r \to \infty} \frac{1}{r} = 0 \quad \Rightarrow \quad \text{RR@}K \approx \text{RR} \text{ for } K \geq 10$$

Relationship to Precision@1: If each query has exactly one relevant document and you only care about rank 1, then \(\text{P@1} = \Pr[\text{rank}_i = 1]\) whereas MRR captures a richer signal across all positions, though it's still "first-hit only."

When MRR misleads: If queries have multiple relevant documents, MRR ignores all but the first. MAP and NDCG are better in those cases.

📐 Key Formula Summary

\(\text{RR}_i = 1 / \text{rank}_i\) where \(\text{rank}_i\) = position of first relevant result for query \(i\).
\(\text{MRR} = \frac{1}{|Q|}\sum_{i=1}^{|Q|} \text{RR}_i\), \(\quad\text{MRR} \in (0, 1]\)

✅ Use MRR When…

Each query has a single authoritative answer (QA systems, entity lookups, chatbot grounding). User satisfaction depends almost entirely on whether the top result is correct.

⚠️ Avoid MRR When…

Queries can have many relevant results (e.g., "show me Python tutorials") or when the quality of ranking beyond the first hit matters. Use NDCG or MAP instead.
