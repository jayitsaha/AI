1
Understanding Tensor Decompositions
▼

What is a tensor? A tensor is simply a multi-dimensional array. A 0-D tensor is a scalar, 1-D is a vector, 2-D is a matrix, and 3-D looks like a data cube — e.g., a video (frames × height × width) or a brain scan (x × y × z). In ML, tensors frequently arise in recommender systems (users × items × time), neural weight layers (output × input × kernel), and knowledge graphs (entity × relation × entity).

Analogy: Think of a 3-D cube made of coloured LEGO bricks. A tensor decomposition finds a small recipe — a handful of coloured rods that you can stack and combine — which reconstructs that cube with far fewer pieces. The three main recipes are CP (a sum of rank-1 "spikes"), Tucker (a compressed core with scaled axes), and Tensor-Train (a chain of thin slices).

💡 If you remember one thing

All three methods generalise the singular value decomposition (SVD) to higher dimensions. CP generalises rank-1 matrix decomposition (outer products). Tucker generalises truncated SVD per mode. Tensor-Train generalises a left-to-right chain of matrix products.

Why it matters for ML: Compressing a 512×512×512 neural network weight tensor from 134 M parameters to ~5 M (≈28× compression) while keeping most accuracy is tractable with TT decomposition. CP, Tucker, and TT each make different trade-offs between expressiveness, compression, and computational cost.

2
CP, Tucker & Tensor-Train — Mechanics
▼

CP (CANDECOMP/PARAFAC) Decomposition

CP expresses a tensor \(\mathcal{T} \in \mathbb{R}^{I \times J \times K}\) as a sum of \(R\) rank-1 terms — each an outer product of three vectors:

$$\mathcal{T} \approx \sum_{r=1}^{R} \lambda_r \; \mathbf{a}_r \otimes \mathbf{b}_r \otimes \mathbf{c}_r, \quad \mathbf{a}_r \in \mathbb{R}^I,\; \mathbf{b}_r \in \mathbb{R}^J,\; \mathbf{c}_r \in \mathbb{R}^K$$

The CP rank is the minimum \(R\) giving an exact representation. Each component is one "spike" — a 3-D rank-1 array. Fitting uses Alternating Least Squares (ALS): fix \(B, C\), solve for \(A\) by OLS; repeat cyclically.

Tucker Decomposition

Tucker projects each mode onto a low-dimensional subspace via factor matrices \(U^{(n)}\) and stores residual structure in a small core tensor \(\mathcal{G}\):

$$\mathcal{T} \approx \mathcal{G} \times_1 U^{(1)} \times_2 U^{(2)} \times_3 U^{(3)}, \quad \mathcal{G} \in \mathbb{R}^{R_1 \times R_2 \times R_3}$$

The mode-\(n\) product \(\times_n\) multiplies every mode-\(n\) fibre by \(U^{(n)}\). The factor matrices are obtained via truncated SVD of each mode-\(n\) unfolding \(\mathbf{T}_{(n)}\); the core follows by projection: \(\mathcal{G} = \mathcal{T} \times_1 U^{(1)\top} \times_2 U^{(2)\top} \times_3 U^{(3)\top}\).

Tensor-Train (TT) Decomposition

For a \(d\)-mode tensor \(\mathcal{T} \in \mathbb{R}^{n_1 \times \cdots \times n_d}\), TT writes each element as a product of matrix slices drawn from 3-way cores:

$$\mathcal{T}(i_1, \ldots, i_d) = G_1[i_1] \, G_2[i_2] \cdots G_d[i_d]$$

where \(G_k \in \mathbb{R}^{r_{k-1} \times n_k \times r_k}\) and \(r_0 = r_d = 1\). The sequence \((r_0, r_1, \ldots, r_d)\) are the TT-ranks. Each \(G_k[i_k]\) is a \(r_{k-1} \times r_k\) matrix; their product is a scalar (the tensor element). TT is fitted via sequential SVD on left-to-right unfoldings — this is the TT-SVD algorithm and gives a quasi-optimal approximation.

🔑 Key Structural Difference

CP: global (all modes interact in each rank-1 term). Tucker: separable per mode but core couples all modes. TT: sequential — modes interact only through adjacent bond dimensions, making it ideal for very high-order tensors (\(d \gg 3\)).

3
Why It Works — The Math
▼

Kruskal Uniqueness (CP)

Unlike matrix SVD, CP decomposition is essentially unique under mild conditions — a remarkable property that gives it strong interpretability. Let \(k_A, k_B, k_C\) be the k-ranks (maximum number of linearly independent columns of factor matrices). Kruskal's theorem states: CP is unique up to permutation and scaling if

$$k_A + k_B + k_C \geq 2R + 2$$

No analogous uniqueness holds for matrix factorisation — an SVD can be rotated freely. CP's uniqueness is why it is used to decompose EEG signals, fluorescence spectra, and social network slices into interpretable factors.

Tucker via Higher-Order SVD (HOSVD)

The mode-\(n\) unfolding \(\mathbf{T}_{(n)}\) rearranges the tensor so that mode-\(n\) fibres become columns of an \(n_n \times \prod_{k \neq n} n_k\) matrix. Taking its left singular vectors:

$$U^{(n)} = \text{leading } R_n \text{ left singular vectors of } \mathbf{T}_{(n)}$$

Then the core is \(\mathcal{G} = \mathcal{T} \times_1 U^{(1)\top} \times_2 U^{(2)\top} \times_3 U^{(3)\top}\). HOSVD is suboptimal (not jointly minimising the Frobenius reconstruction error); the optimal Tucker is found by Higher-Order Orthogonal Iteration (HOOI), which iterates HOSVD until convergence.

TT-SVD Quasi-Optimality

The TT-SVD algorithm sequentially reshapes the tensor and takes truncated SVDs from left to right. Each step is an exact SVD on a 2-D unfolding:

$$\mathbf{T}_{(1)} \in \mathbb{R}^{n_1 \times n_2 \cdots n_d} \xrightarrow{\text{truncated SVD}} G_1 \in \mathbb{R}^{n_1 \times r_1}, \quad \text{remainder} \in \mathbb{R}^{r_1 \times n_2 \cdots n_d}$$

The total approximation error is bounded by the sum of truncation errors (Oseledets 2011):

$$\|\mathcal{T} - \mathcal{T}_{TT}\|_F \leq \sqrt{d-1} \cdot \varepsilon_{\max}$$

where \(\varepsilon_{\max}\) is the largest per-step truncation error. This quasi-optimal bound means TT-SVD cannot be arbitrarily bad.

Parameter Counts (key formula)

For \(\mathcal{T} \in \mathbb{R}^{I \times J \times K}\) and a large \(d\)-mode hypercubic tensor of side \(n\):

$$\text{CP}_R: \; R(I+J+K), \qquad \text{Tucker}_{(R_1,R_2,R_3)}: \; R_1 I + R_2 J + R_3 K + R_1 R_2 R_3$$
$$\text{TT}_r \text{ (hypercubic)}: \; n r + (d-2)\, n r^2 + n r = (d-2)\,nr^2 + 2nr \approx \mathcal{O}(d n r^2)$$

TT avoids the exponential \(\mathcal{O}(n^d)\) curse of dimensionality — crucial when \(d \gg 3\).

⚠️ Critical Difference from SVD

Computing the exact CP rank of a tensor is NP-hard (Håstad 1990). ALS for CP can fail to converge and may suffer from degeneracy (near-collinear components with diverging norms). Always monitor the ALS loss and use regularisation or random restarts.

💡 Decision Rule

Use CP when \(d \leq 4\) and you need unique/interpretable factors (e.g. latent topics in a 3-way count tensor). Use Tucker when you want per-mode subspace reduction and can tolerate a dense core (e.g. compressing a 4-D weight tensor in a small CNN). Use TT when \(d \geq 5\) or the tensor is very large — TT's \(\mathcal{O}(d n r^2)\) cost avoids the exponential curse.

Code Trace — From Scratch (NumPy)
▼
import numpy as np
from numpy.linalg import svd, norm
# ── Helper: mode-n unfolding ──────────────────────────────────────────
def unfold(T, mode):
# Move mode to front, then reshape to 2-D
axes = [mode] + [i for i in range(T.ndim) if i != mode]
return T.transpose(axes).reshape(T.shape[mode], -1)
# ── Helper: mode-n product (Tucker core reconstruction) ───────────────
def mode_product(T, U, mode):
# T: arbitrary-order tensor; U: matrix; mode: which mode to contract
T2 = unfold(T, mode) # (n_mode, rest)
result = U @ T2 # (R_mode, rest)
new_shape = list(T.shape); new_shape[mode] = U.shape[0]
return result.reshape([new_shape[mode]] + [new_shape[i] for i in range(T.ndim) if i!=mode])\
.transpose(np.argsort([mode] + [i for i in range(T.ndim) if i!=mode]))
# ── HOSVD (Tucker) ────────────────────────────────────────────────────
def hosvd(T, ranks): # ranks = (R1, R2, ..., Rd)
Us = []
for n, R in enumerate(ranks):
T_n = unfold(T, n) # mode-n unfolding
U, _, _ = svd(T_n, full_matrices=False)
Us.append(U[:, :R]) # keep R left singular vectors
G = T.copy()
for n, U in enumerate(Us): # project into core
G = mode_product(G, U.T, n)
return G, Us # core + factor matrices
# ── TT-SVD ────────────────────────────────────────────────────────────
def tt_svd(T, max_rank, eps=1e-10):
cores = []; C = T.copy(); r = 1
for k in range(T.ndim - 1):
C = C.reshape(r * T.shape[k], -1) # (r*n_k, rest)
U, s, Vt = svd(C, full_matrices=False)
r_new = min(max_rank, np.sum(s > eps))
U = U[:, :r_new]; s = s[:r_new]; Vt = Vt[:r_new, :]
cores.append(U.reshape(r, T.shape[k], r_new))
C = np.diag(s) @ Vt; r = r_new
cores.append(C.reshape(r, T.shape[-1], 1)) # last core
return cores
# ── Demo on 3x4x5 tensor ─────────────────────────────────────────────
np.random.seed(42)
T = np.random.randn(3, 4, 5)
G, Us = hosvd(T, ranks=(2, 2, 2)) # Tucker
T_tucker = mode_product(mode_product(mode_product(G, Us[0], 0), Us[1], 1), Us[2], 2)
print(f"Tucker err: {norm(T - T_tucker)/norm(T):.4f}") # ~0.55 for rank-2
cores = tt_svd(T, max_rank=2) # Tensor-Train
print(f"TT param count: {sum(c.size for c in cores)}")
