Boosting: Sequential, Error-Correcting Ensembles

Part III · Classical ML (Ensembles) — How weak learners cooperate to drive bias to zero
Intermediate Classical ML Ensembles Must Know
1
Understanding the Concept
▼

What is this? Boosting trains a sequence of simple predictors (called weak learners), where each new one focuses specifically on the mistakes of all the previous ones combined. The final answer is a weighted vote of every learner.

Real-World Analogy

Think of a tutoring chain. A student gets tested; the tutor marks the wrong answers with big red circles (more weight). The next tutor only studies those circled questions — now the hard ones get more practice time. Each tutor specialises in what the previous ones got wrong. After five tutors, the combined notes cover every type of question.

One-sentence summary: Boosting = add weak learners one at a time, each concentrating on the current ensemble's errors, producing a strong learner via bias reduction.

If You Remember One Thing

Bagging reduces variance by averaging parallel models on random data subsets. Boosting reduces bias by training models sequentially, each fitting the residual error of the ensemble so far.

2
How It Works Internally
▼

Two Flavours of Error-Correction

All boosting algorithms follow the same skeleton: maintain a notion of the current error, train a weak learner to reduce it, add it to the ensemble, update the error signal. Two implementations dominate:

AdaBoost (adaptive reweighting) — used for classification. After each round, misclassified training examples get their sampling weight increased; correctly classified ones get their weight decreased. The next weak learner is trained on the reweighted dataset, so it will naturally specialise in the hard examples. The learner's vote weight \(\alpha_t\) is proportional to its accuracy: a better learner gets a louder vote.

Gradient Boosting (residual / functional gradient) — used for regression and classification. Instead of reweighting, each new tree is fit directly to the residuals (or negative gradients of the loss) of the current ensemble prediction. This is gradient descent in function space: we are greedily descending the loss with respect to the predictions.

Ensemble Update Rule (both flavours)

At round \(t\), the ensemble prediction becomes:
\(F_t(x) = F_{t-1}(x) + \eta \cdot \alpha_t \cdot h_t(x)\) where \(h_t\) is the new weak learner, \(\alpha_t\) is its weight, and \(\eta\) is the learning rate (shrinkage).

Why Sequentiality Matters

Each learner sees the current residual/error computed from all previous learners. This chain dependency is what makes boosting sequential — you cannot train learner 3 until learner 2 is done, because learner 3's training target depends on learner 2's predictions.

Common Misconception

Boosting does NOT simply "vote" like a democracy. Each weak learner's contribution is scaled by its own accuracy (\(\alpha_t\)) and a global learning rate (\(\eta\)). Weak, inaccurate learners contribute very little; accurate ones dominate.

The Math: AdaBoost & Gradient Boosting
▼

AdaBoost — Numerical Trace (N=5 samples, 3 rounds)

Binary classification: labels \(y_i \in \{-1, +1\}\). Initial sample weights \(w_i^{(1)} = 1/5 = 0.2\) for all \(i\).

Round 1. Stump \(h_1\) achieves weighted error:

$$\varepsilon_1 = \sum_{i : h_1(x_i) \neq y_i} w_i^{(1)} = 0.2 + 0.2 = 0.40$$

Learner weight (must have \(\varepsilon < 0.5\) for the sign to make sense):

$$\alpha_1 = \frac{1}{2}\ln\!\left(\frac{1 - \varepsilon_1}{\varepsilon_1}\right) = \frac{1}{2}\ln\!\left(\frac{0.60}{0.40}\right) = \frac{1}{2}\ln(1.5) \approx 0.2027$$

Weight update (unnormalised):

$$\tilde{w}_i^{(2)} = w_i^{(1)} \cdot \exp\!\left(-\alpha_1 \cdot y_i \cdot h_1(x_i)\right)$$

For correctly classified samples (\(y_i h_1(x_i) = +1\)): \(\tilde{w} = 0.2 \cdot e^{-0.2027} \approx 0.163\).
For misclassified samples (\(y_i h_1(x_i) = -1\)): \(\tilde{w} = 0.2 \cdot e^{+0.2027} \approx 0.245\).
Normalise so they sum to 1. The two wrong examples now carry more weight going into round 2.

Gradient Boosting — Residual Trace (Regression, MSE loss)

5 training points: \(y = [3, 7, 5, 8, 2]\). Start with \(F_0(x) = \bar{y} = 5.0\) (mean).

Residuals after \(F_0\): \(r^{(1)} = y - F_0 = [-2, +2, 0, +3, -3]\).

Fit tree \(h_1\) to \(r^{(1)}\). Suppose it predicts \(h_1 = [-1.5, +1.5, 0, +2.0, -2.0]\) (leaf averages).

Update with learning rate \(\eta = 0.5\):

$$F_1(x_i) = F_0 + 0.5 \cdot h_1(x_i) = [5 - 0.75,\ 5 + 0.75,\ 5 + 0,\ 5 + 1,\ 5 - 1] = [4.25,\ 5.75,\ 5.0,\ 6.0,\ 4.0]$$

Residuals after \(F_1\): \(r^{(2)} = y - F_1 = [-1.25, +1.25, 0, +2.0, -2.0]\).
Repeat: fit \(h_2\) to \(r^{(2)}\), add \(\eta \cdot h_2\). Each round, residuals shrink.

Bias-Variance View

Let \(\text{Bias}^2[F_T] + \text{Var}[F_T] + \text{Noise} = \mathbb{E}[(y - F_T(x))^2]\).

Each additional weak learner primarily reduces the bias (the systematic error of \(F_{T-1}\) on training data) rather than the variance. Adding more learners without regularisation will eventually increase variance (overfitting), so shrinkage \(\eta\) and early stopping are essential.

$$\text{Bias reduces with more rounds; variance grows} \Rightarrow \text{optimum at some } T^*$$

Key Takeaways & Comparisons
▼

Boosting vs Bagging

DimensionBagging (e.g. Random Forest)Boosting (e.g. XGBoost)
Training orderParallel (independent)Sequential (dependent)
Error targetRandom subsets of dataResiduals / reweighted samples
Error reducedVarianceBias
Overfitting riskLow (averaging smooths noise)High without shrinkage/early stop
Typical learner depthDeep trees (high variance, low bias)Shallow stumps/trees (low variance)
ParallelisableYesNo (sequential dependency)
InterpretabilityModerate (feature importances)Lower (additive model of many trees)

When to Use Boosting

  • Structured/tabular data where XGBoost/LightGBM consistently win Kaggle
  • When bias (underfitting) is the dominant problem
  • When you have enough data to regularise with shrinkage + early stopping
  • When training time is not a bottleneck (sequential)

When NOT to Use

  • Noisy labels — boosting will fit the noise hard
  • Real-time training that must be parallelised
  • Very small datasets — easy to overfit
