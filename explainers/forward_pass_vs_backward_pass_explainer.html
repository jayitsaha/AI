Forward Pass vs. Backward Pass

How a network computes a prediction — and how it computes the gradients that improve it
Intermediate Deep Learning Backpropagation ~2× compute
1
Understanding the Concept
▼

What is it? Training a neural network is two passes over the same graph of computation, in opposite directions. The forward pass pushes the input through every layer, left to right, producing a prediction and finally a loss — the number that says "how wrong were we?" The backward pass then walks back through the exact same graph, right to left, using the chain rule to work out how much each weight contributed to that wrongness.

Analogy: Think of baking a cake (forward pass): flour → batter → baked cake → taste-test against the "ideal cake" (loss). The backward pass is a chef tasting the result and tracing blame backward — "too dry, that's the oven time; too oven time, that's because I under-measured the butter" — walking back ingredient by ingredient, reusing exactly what she remembers she measured (the cached quantities) to know how to adjust each one.

💡 If you remember one thing

Forward pass = compute and cache activations layer by layer to get the loss. Backward pass = reuse those cached activations, layer by layer in reverse, to get \(\partial L/\partial W\) for every weight via the chain rule. Same graph, opposite direction, shared cache.

How It Works Internally
▼

Forward pass: build the computation graph, layer by layer

For layer \(l\) with weights \(W^{(l)}\), bias \(b^{(l)}\), and activation \(f^{(l)}\): compute the pre-activation \(z^{(l)} = W^{(l)}a^{(l-1)} + b^{(l)}\), then the activation \(a^{(l)} = f^{(l)}(z^{(l)})\). Every \(a^{(l)}\) (and often \(z^{(l)}\)) is written to a cache — not thrown away — because the backward pass will need it. This repeats until the final layer produces a prediction, which is compared against the target to produce a scalar loss \(L\).

Backward pass: walk the same graph in reverse using cached values

Reverse-mode autodiff starts at \(L\) with \(\partial L/\partial L = 1\) and applies the chain rule one layer at a time, moving from the output toward the input. At each layer it needs two things that were computed during the forward pass and stored in the cache: the incoming activation \(a^{(l-1)}\) (to compute \(\partial L/\partial W^{(l)}\)) and the pre-activation \(z^{(l)}\) (to compute the local derivative of \(f^{(l)}\)). Without the cache, the backward pass would have to re-run the entire forward computation from scratch at every layer — reverse-mode autodiff is only cheap because it trades memory (stored activations) for compute (no recomputation).

Numerical trace — a 2→2→1 network

Input \(x=[1.0, 2.0]\), target \(t=1.0\), hidden layer uses ReLU, output is linear. Forward: \(z^{(1)}=[0.05, 0.9]\) → cached, \(a^{(1)}=\mathrm{ReLU}(z^{(1)})=[0.05, 0.9]\) → cached, \(y=-0.22\), \(L=0.744\). Backward reuses those exact cached numbers: \(\partial L/\partial y=-1.22\), then \(\partial L/\partial W^{(2)} = (\partial L/\partial y)\cdot a^{(1)\top}\) — note \(a^{(1)}\) is the cached hidden activation, not recomputed. Design decision: why cache instead of recompute?

An alternative ("recomputation" / activation checkpointing) discards activations and recomputes them during the backward pass when needed. This trades memory for extra compute — used deliberately in gradient checkpointing to fit huge models in limited GPU memory. The default, however, is to cache everything because compute is usually more precious than memory for typical-sized networks — recomputing every layer would roughly double the backward pass's already-heavier compute cost.

🔑 Key Property

The forward and backward passes are structurally symmetric: every edge that carries a value forward carries a gradient backward. This is why frameworks like PyTorch build a graph during the forward pass (autograd) and simply replay it in reverse to get gradients — no separate "backward architecture" needs to be hand-designed.

Why It Works — The Math
▼

Forward pass, formally

For \(l = 1, \dots, L\), with \(a^{(0)} = x\) the input:

$$z^{(l)} = W^{(l)} a^{(l-1)} + b^{(l)}, \qquad a^{(l)} = f^{(l)}\!\left(z^{(l)}\right)$$

The final layer's output \(a^{(L)}\) is compared to a target \(y\) via a loss \(L = \mathcal{L}(a^{(L)}, y)\).

Backward pass, formally (reverse-mode chain rule)

Define the error signal at layer \(l\) as \(\delta^{(l)} = \partial L/\partial z^{(l)}\). Starting from the output layer:

$$\delta^{(L)} = \frac{\partial L}{\partial a^{(L)}} \odot f'^{(L)}\!\left(z^{(L)}\right)$$

Then, propagating backward for \(l = L-1, \dots, 1\):

$$\delta^{(l)} = \left(W^{(l+1)\top} \delta^{(l+1)}\right) \odot f'^{(l)}\!\left(z^{(l)}\right)$$

Finally, the weight and bias gradients at every layer:

$$\frac{\partial L}{\partial W^{(l)}} = \delta^{(l)}\, a^{(l-1)\top}, \qquad \frac{\partial L}{\partial b^{(l)}} = \delta^{(l)}$$

Look closely at \(\partial L/\partial W^{(l)}\): it needs \(a^{(l-1)}\) — the activation flowing into layer \(l\) — which was computed and cached during the forward pass. This is the precise mathematical reason activations must be stored: the weight gradient is literally an outer product of the backward error signal and the forward-cached activation.

Why backward costs ~2× forward

Forward pass at layer \(l\) does one matrix multiply: \(W^{(l)}a^{(l-1)}\) (cost \(\propto\) size of \(W^{(l)}\)). Backward pass at layer \(l\) does two matrix multiplies of comparable size: \(W^{(l+1)\top}\delta^{(l+1)}\) (to propagate the error signal further back) and \(\delta^{(l)}a^{(l-1)\top}\) (to actually form the weight gradient). So backward FLOPs ≈ 2× forward FLOPs, and a full training step (forward + backward) costs roughly 3× a forward-only pass — the basis of the common "6 FLOPs per parameter per token" rule of thumb for transformer training compute (2 forward + 4 backward).

⚠️ Common Misconception

"Backward pass just re-runs the forward pass in reverse" — not quite. It doesn't recompute activations; it reuses the cached ones and computes a different quantity (gradients, via the outer product above) at each layer. That's also why activation memory — not just weight memory — is often the binding constraint when training large models, and why techniques like gradient checkpointing exist to discard and selectively recompute activations.

When memory is the bottleneck: gradient checkpointing (activation recomputation) discards some cached activations during the forward pass and recomputes them on-demand during backward — trading extra forward compute for lower peak memory. Common for very deep/large models where activation memory dominates.

When compute is the bottleneck: cache everything (the default) so backward never has to redo forward work — this is why frameworks default to storing the full activation graph unless told otherwise (e.g. torch.utils.checkpoint, or @torch.no_grad() to skip caching entirely at inference).

6
Key Takeaways
▼
  • Forward pass computes values and caches activations; backward pass computes gradients by reusing those caches via the reverse-mode chain rule.
  • The two passes are structurally symmetric — same graph, opposite direction — which is exactly what lets autograd frameworks build the graph once (forward) and replay it in reverse (backward).
  • Backward costs roughly 2× the FLOPs of forward, because each layer needs both a propagated-error matmul and a weight-gradient outer product.
  • Activations must be cached because \(\partial L/\partial W^{(l)} = \delta^{(l)} a^{(l-1)\top}\) directly depends on the forward-time input to that layer.
  • At inference time only the forward pass runs — no cache, no backward — which is why inference is cheaper and lower-memory than training.
💡 Interview Angle

"Why does training need ~3× the compute of inference?" → 1× forward (to get the loss) + ~2× backward (to get the gradients), because backward does both an error-propagation matmul and a weight-gradient matmul per layer, versus forward's single matmul.
