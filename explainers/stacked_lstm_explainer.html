Stacked LSTM (Multi-Layer LSTM)

Chaining LSTM layers vertically so depth and time form a 2D computation grid
Intermediate Deep Learning Sequence Models O(L·T·H²) per pass
1
Understanding Stacked LSTMs
▼

What is it? A single LSTM layer reads a sequence and produces one hidden state per timestep. A stacked (multi-layer) LSTM takes the entire hidden-state sequence produced by layer 1 and feeds it as the input sequence to layer 2, whose output sequence feeds layer 3, and so on. Depth (number of layers) and time (sequence length) become two independent axes of computation.

Analogy: Imagine three editors reviewing a long document in sequence. The first editor reads the raw text sentence by sentence and writes a short note after each sentence, carrying forward a memory of what came before. The second editor never sees the raw text — she only reads the first editor's notes, sentence-position by sentence-position, and writes her own higher-level notes, also carrying forward her own memory. A third editor repeats this on the second editor's notes. Each layer up abstracts further away from the raw input while still tracking its own thread of memory through time.

One-sentence summary: A stacked LSTM is \(L\) independent LSTM layers chained vertically, where layer \(l\)'s hidden-state sequence over time becomes layer \(l{+}1\)'s input sequence.

💡 If you remember one thing

Layer \(l\) at time \(t\) consumes two — and only two — vectors: \(h_t^{l-1}\) (this timestep's output from the layer below) and \(h_{t-1}^{l}\) (this same layer's own hidden state from the previous timestep). It never sees the raw input \(x_t\) unless \(l=1\), and it never sees the future.

2
How It Works Internally
▼

Two Axes, One Grid

Unroll a stacked LSTM and you get a 2D grid of cells: rows are layers (depth, \(l = 1 \dots L\)), columns are timesteps (time, \(t = 1 \dots T\)). Every cell in the grid receives exactly two incoming arrows: a vertical arrow carrying \(h_t^{l-1}\) from the cell directly below it (depth connection, feed-forward, no memory), and a horizontal arrow carrying \(h_{t-1}^l, c_{t-1}^l\) from the cell directly to its left (time connection, recurrent, carries memory).

$$h_t^l,\, c_t^l = \operatorname{LSTMCell}^{(l)}\!\big(\underbrace{h_t^{l-1}}_{\text{from below (depth)}},\ \underbrace{h_{t-1}^l,\, c_{t-1}^l}_{\text{from left (time)}}\big), \qquad h_t^0 \triangleq x_t$$

Internal Mechanism — Each Cell Is a Full LSTM

Every layer owns its own weights \(W^{(l)}\) and its own memory cell \(c_t^l\) — layers do not share parameters or share cell state. Inside each cell, the standard four gates are computed from the concatenation \([h_{t-1}^l,\ h_t^{l-1}]\):

$$f_t=\sigma(W_f[h_{t-1}^l,h_t^{l-1}]+b_f),\quad i_t=\sigma(W_i[\cdot]+b_i),\quad o_t=\sigma(W_o[\cdot]+b_o),\quad g_t=\tanh(W_g[\cdot]+b_g)$$
$$c_t^l = f_t \odot c_{t-1}^l + i_t \odot g_t \qquad\qquad h_t^l = o_t \odot \tanh(c_t^l)$$

Why this design? Giving every layer its own independent memory cell (rather than one shared cell across layers) lets each layer specialize on a different timescale or level of abstraction — empirically, lower layers tend to track short, local patterns while higher layers integrate longer-range, more abstract structure, much like how deeper CNN layers detect higher-level visual features. This is a genuine capacity gain that simply widening a single layer's hidden size does not provide: width adds more features at one level of abstraction, depth adds levels of abstraction.

In practice (e.g. PyTorch's nn.LSTM(num_layers=L), cuDNN), the forward pass is computed layer-major: the entire sequence is run through layer 1 first (so it can be batched efficiently across time), then the entire resulting sequence is run through layer 2, and so on — not interleaved timestep-by-timestep across layers, even though the dependency graph would also allow that order.

🔑 Key Property

Depth connections are feed-forward (no recurrence, no gating of a "memory"), while time connections are recurrent and gated through \(c_t^l\). This asymmetry is exactly why gradient behavior differs sharply along the two axes (Card 3).

Regularization: Dropout Goes Between Layers

Standard dropout, if applied naively to the recurrent connections \(h_{t-1}^l \to h_t^l\), destroys the LSTM's ability to remember anything reliably over long horizons. The fix (Zaremba, Sutskever & Vinyals, 2014) is to apply dropout only on the vertical, depth-wise connections \(h_t^{l-1} \to h_t^l\) between stacked layers, leaving every layer's own time axis dropout-free.

3
Why It Works — The Math
▼

Gradient Flow Along Time (Protected)

Within a single layer, the cell state update \(c_t^l = f_t \odot c_{t-1}^l + i_t \odot g_t\) is additive. Differentiating:

$$\frac{\partial c_t^l}{\partial c_{t-1}^l} = \operatorname{diag}(f_t)$$

Because this Jacobian is a sum with the forget gate on the diagonal (not a repeated matrix-and-squash multiplication like in a vanilla RNN), gradients can flow backward through many timesteps with \(f_t \approx 1\) largely undamped. This is the famous "constant error carousel" — the reason LSTMs handle long time dependencies.

Gradient Flow Along Depth (Unprotected)

Now consider the depth direction. \(h_t^{l}\) is a function of \(h_t^{l-1}\) purely through the ordinary nonlinear gate computations of layer \(l\) — there is no additive cell-state shortcut across layers:

$$\frac{\partial h_t^{l}}{\partial h_t^{l-1}} = \frac{\partial}{\partial h_t^{l-1}}\Big[o_t \odot \tanh(c_t^l)\Big], \quad\text{a dense Jacobian through } f_t, i_t, o_t, g_t \text{ — no identity shortcut}$$

Stacking \(L\) layers multiplies \(L\) such Jacobians together end to end, exactly the mechanism that causes vanishing/exploding gradients in a deep feed-forward network. The total gradient at layer \(l\), time \(t\) sums contributions along both paths (backprop-through-time within the layer, and backprop-through-depth from the layer above):

$$\frac{\partial \mathcal{L}}{\partial h_t^l} = \underbrace{\frac{\partial \mathcal{L}}{\partial h_{t+1}^{l}}\frac{\partial h_{t+1}^{l}}{\partial h_t^{l}}}_{\text{from the future, same layer}} \;+\; \underbrace{\frac{\partial \mathcal{L}}{\partial h_t^{l+1}}\frac{\partial h_t^{l+1}}{\partial h_t^{l}}}_{\text{from the layer above, same time}}$$
⚠️ Common Misconception

"LSTMs solve vanishing gradients, so stacking more LSTM layers is always safe." False. The gate-based highway that fixes vanishing gradients protects the time axis only. The depth axis has no such highway, which is precisely why plain stacked LSTMs rarely benefit past roughly 2–4 layers without extra help — residual/highway connections between layers, layer normalization, or careful initialization.

Key Takeaways
▼

When to use stacked LSTMs:

  • Task benefits from hierarchical temporal abstraction (speech recognition, POS/NER tagging, pre-Transformer machine translation encoders)
  • Enough training data to fit the extra parameters without overfitting
  • Sequence lengths where full self-attention would be too memory-hungry, but a few extra layers of nonlinearity still help

When NOT to use:

  • Very long sequences needing full parallel training — a Transformer removes the sequential-time bottleneck entirely
  • Simple, shallow pattern — a single wider LSTM layer may match performance with less depth-gradient risk
  • Adding layers past ~4 without residual/highway connections or layer norm — expect diminishing or negative returns
💡 Hierarchy

Single LSTM ⊂ Stacked LSTM ⊂ Stacked Bidirectional LSTM ⊂ Stacked LSTM + Residual/Highway connections. Each generalization adds capacity along a different axis: time (base LSTM), depth (stacking), direction (bidirectional), and gradient highway across depth (residual stacking).

import numpy as np
sigmoid = lambda z: 1/(1+np.exp(-z))
def lstm_cell(input_vec, h_prev, c_prev, W):
concat = np.concatenate([h_prev, input_vec])
f = sigmoid(W['f'] @ concat + W['bf'])
i = sigmoid(W['i'] @ concat + W['bi'])
o = sigmoid(W['o'] @ concat + W['bo'])
g = np.tanh(W['g'] @ concat + W['bg'])
c = f * c_prev + i * g
h = o * np.tanh(c)
return h, c
# Stacked forward pass — layer-major (matches PyTorch nn.LSTM)
h = [np.zeros(H) for _ in range(L)]
c = [np.zeros(H) for _ in range(L)]
for l in range(L):
layer_input_seq = x if l == 0 else h_seq[l-1] # depth: read layer below
for t in range(T):
h[l], c[l] = lstm_cell(layer_input_seq[t], h[l], c[l], W[l]) # time: own recurrence
h_seq[l][t] = h[l]
