Regularization in Logistic Regression

Controlling model complexity via L1, L2, and elastic-net penalties on the log-loss
Intermediate Classical ML Logistic Regression Review Track
1
Understanding Regularization
▼

Logistic regression finds weights \(\mathbf{w}\) that maximize the log-likelihood of the data. Without any constraint, the optimizer can make weights arbitrarily large — especially when classes are linearly separable, where perfect separation sends weights to \(\pm\infty\) and the sigmoid saturates to hard 0/1. This is the weight blow-up problem.

Regularization adds a penalty term to the loss that shrinks weights toward zero, trading a little bias for a lot of variance reduction. The strength of regularization is controlled by the inverse parameter \(C = 1/\lambda\): small \(C\) → strong regularization, large \(C\) → weak regularization (approaches unregularized MLE).

Key Insight

Regularization is a soft constraint that encodes a prior belief: weights should be small. L2 encodes a Gaussian prior; L1 encodes a Laplace prior. The prior prevents the likelihood from driving weights to infinity on separable data.

There are three common penalty forms:

  • L2 (Ridge) — penalty \(\lambda \|\mathbf{w}\|_2^2\); pulls all weights toward zero smoothly; default in sklearn.
  • L1 (Lasso) — penalty \(\lambda \|\mathbf{w}\|_1\); induces sparsity; many weights go exactly to zero.
  • Elastic-net — convex mix of L1 + L2; balances sparsity and smoothness.
2
The Penalized Log-Loss
▼

Unregularized logistic regression minimizes the binary cross-entropy (negative log-likelihood):

$$\mathcal{L}(\mathbf{w}) = -\frac{1}{n}\sum_{i=1}^{n}\left[y_i \log \sigma(\mathbf{w}^\top \mathbf{x}_i) + (1-y_i)\log(1 - \sigma(\mathbf{w}^\top \mathbf{x}_i))\right]$$

Regularization appends a penalty scaled by \(\lambda = 1/C\):

$$\mathcal{L}_{\text{reg}}(\mathbf{w}) = \mathcal{L}(\mathbf{w}) + \underbrace{\frac{\lambda}{2}\|\mathbf{w}\|_2^2}_{\text{L2}} \quad\text{or}\quad \mathcal{L}(\mathbf{w}) + \underbrace{\lambda\|\mathbf{w}\|_1}_{\text{L1}}$$

The elastic-net combines both:

$$\mathcal{L}_{\text{EN}}(\mathbf{w}) = \mathcal{L}(\mathbf{w}) + \lambda\left[\frac{1-\rho}{2}\|\mathbf{w}\|_2^2 + \rho\|\mathbf{w}\|_1\right]$$

where \(\rho \in [0,1]\) is the L1 mixing ratio (sklearn's l1_ratio).

Gradient Update

For L2, the gradient adds \(\lambda \mathbf{w}\) to the cross-entropy gradient — this is weight decay and shrinks every weight proportionally each step. For L1, the subgradient adds \(\lambda \operatorname{sign}(\mathbf{w})\) — a constant push toward zero that drives small weights all the way to zero (sparsity).

Bias Term

Convention: the intercept \(b\) is typically not penalized (it shifts the decision boundary without affecting complexity). sklearn's LogisticRegression(fit_intercept=True) follows this convention by default.

Numerical trace (L2, C=1.0): Suppose after one gradient step the unregularized gradient for weight \(w_1 = 3.0\) is \(-0.4\) (pushing it up). With L2 penalty \(\lambda=1\), the full gradient is \(-0.4 + 1\times3.0 = 2.6\). With learning rate \(\eta=0.1\) the update is \(w_1 \leftarrow 3.0 - 0.1 \times 2.6 = 2.74\) — the weight decays toward zero.

L1 vs L2 Geometry & Sparsity
▼

The key geometric difference: the feasible region for L2 is a smooth sphere \(\|\mathbf{w}\|_2^2 \le t\); for L1 it is a diamond \(\|\mathbf{w}\|_1 \le t\). The loss contours (ellipses for quadratic losses, more complex for log-loss) intersect the constraint region at a corner of the diamond for L1, setting one or more coordinates exactly to zero — sparsity.

Why L2 Prevents Weight Blow-up on Separable Data

On separable data the log-loss alone decreases monotonically as \(\|\mathbf{w}\| \to \infty\) (the sigmoid approaches a step function). Adding \(\lambda\|\mathbf{w}\|_2^2\) creates a bowl-shaped total loss with a unique finite minimum. The optimizer can no longer escape to infinity.

4
C Controls Boundary Complexity
▼

sklearn uses C = 1/λ — the inverse regularization strength. This is confusing at first: large C means less regularization (model can fit the training set more tightly), small C means more regularization (smoother, more conservative boundary).

  • C=0.01 — heavy regularization, very smooth boundary, high bias, may underfit.
  • C=1.0 — default; balanced bias–variance trade-off.
  • C=100 — near-MLE; boundary hugs training data, may overfit; on separable data, weights can still blow up numerically.

Use cross-validation (e.g. LogisticRegressionCV) to select \(C\) from a logarithmic grid like np.logspace(-4, 4, 20).

Interview Tip

Always clarify sklearn's \(C\) convention in interviews — candidates who say "large C = more regularization" are immediately flagged. The API follows SVM convention where \(C\) is the penalty on slack variables (larger = less regularization).

Key Takeaways & When to Use
▼
  • Always regularize logistic regression — even on non-separable data, regularization reduces variance and improves generalization.
  • L2 is the default — smooth, stable, works well with all solvers, and prevents weight blow-up on (near-)separable data.
  • Use L1 for feature selection — when you want a sparse model or have many irrelevant features.
  • Elastic-net is best when features are correlated and you want both sparsity and stable group selection.
  • Cross-validate C over a log-scale grid; never leave it at the default without checking.
  • Do NOT regularize the bias — the intercept is not a complexity-contributing parameter.
Bayesian Interpretation

MAP estimation with a Gaussian prior \(\mathbf{w} \sim \mathcal{N}(0, 1/\lambda)\) is equivalent to L2-regularized logistic regression. MAP with a Laplace prior \(\mathbf{w} \sim \text{Laplace}(0, 1/\lambda)\) gives L1. This connects regularization to Bayesian inference.
