1
Understanding Bayesian Model Averaging
▾

Imagine you are trying to forecast tomorrow's weather and you have three meteorologists: one swears it will be sunny (linear model), another says partly cloudy (quadratic model), and a third says stormy (cubic model). Instead of picking just one meteorologist and ignoring the others, Bayesian Model Averaging (BMA) asks each of them to make a prediction and then takes a weighted vote — the weight for each meteorologist is proportional to how well they've explained past weather patterns.

More precisely, BMA maintains a probability distribution over a set of candidate models. After observing data, the posterior probability of each model is computed: models that explain the data well get high weight; models that are too complex or fit poorly get low weight. The final prediction is a mixture of all model predictions, each scaled by its posterior probability.

Key Insight

BMA does not select a single "best" model — it integrates over all candidate models, weighted by their evidence. This properly accounts for model uncertainty, not just parameter uncertainty within a single model. The result is better-calibrated predictions and honest uncertainty quantification.

The marginal likelihood (also called the evidence), \(P(\mathcal{D} \mid M_k)\), plays the role of automatic model selection: it rewards models that explain the data but penalizes unnecessary complexity via Occam's razor — a model with more parameters has to spread its probability mass over a larger parameter space, so if that extra complexity doesn't buy better fit it is penalised.

One Sentence Summary

BMA predicts as \(\hat{y} = \sum_k P(M_k \mid \mathcal{D})\cdot \mathbb{E}[y \mid x, M_k]\), where the model posteriors \(P(M_k \mid \mathcal{D})\) are automatically calibrated by how well each model explains observed data — no manual model selection required.

2
How BMA Works Internally
▾

BMA operates in three phases: (1) define a model space, (2) compute posterior model probabilities, (3) compute the BMA predictive distribution.

Phase 1: Define the Model Space

Specify a finite set of models \(\mathcal{M} = \{M_1, M_2, \ldots, M_K\}\). Each \(M_k\) is a complete probabilistic model: a likelihood function \(P(\mathcal{D} \mid \theta_k, M_k)\) and a prior \(P(\theta_k \mid M_k)\) over its parameters. Models can differ in structure (e.g., linear vs. quadratic) or in which variables they include.

Phase 2: Compute Posterior Model Probabilities

By Bayes' theorem applied at the model level:

$$P(M_k \mid \mathcal{D}) = \frac{P(\mathcal{D} \mid M_k)\, P(M_k)}{\sum_{j=1}^K P(\mathcal{D} \mid M_j)\, P(M_j)}$$

The quantity \(P(\mathcal{D} \mid M_k)\) is the marginal likelihood — the probability of the data under model \(M_k\) after integrating out all parameters:

$$P(\mathcal{D} \mid M_k) = \int P(\mathcal{D} \mid \theta_k, M_k)\, P(\theta_k \mid M_k)\, d\theta_k$$

This integral is the key computation. It is analytically tractable for conjugate models and approximated by BIC, Laplace, or MCMC for general models.

Phase 3: BMA Predictive Distribution

For a new input \(x^*\), the BMA predictive distribution is:

$$P(y^* \mid x^*, \mathcal{D}) = \sum_{k=1}^K P(M_k \mid \mathcal{D})\; P(y^* \mid x^*, \mathcal{D}, M_k)$$

where \(P(y^* \mid x^*, \mathcal{D}, M_k) = \int P(y^* \mid x^*, \theta_k, M_k)\, P(\theta_k \mid \mathcal{D}, M_k)\, d\theta_k\) is the within-model posterior predictive.

Design Decision: Why Not Just Pick the Best Model?

Model selection (picking the single highest-posterior model) ignores model uncertainty. If \(P(M_1 \mid \mathcal{D}) = 0.55\) and \(P(M_2 \mid \mathcal{D}) = 0.45\), selecting \(M_1\) and ignoring \(M_2\) throws away 45% of the posterior probability mass. BMA retains all models weighted by evidence — producing predictions that are more robust and better calibrated, especially when multiple models are nearly equally plausible.

3
The Mathematics — Posterior Weights & BIC Approximation
▾

The Marginal Likelihood and Occam's Razor

The marginal likelihood \(P(\mathcal{D} \mid M_k)\) automatically penalises complexity. For a model with many parameters, the prior \(P(\theta_k \mid M_k)\) must spread probability mass over a large parameter space. When data could be explained by a simpler model, the complex model's marginal likelihood is lower, even if its maximum-likelihood fit is better. This is the Bayesian form of Occam's razor — no tuning of a regularisation parameter is needed.

BIC Approximation to the Log Marginal Likelihood

The Bayesian Information Criterion (BIC) provides a practical approximation:

$$\log P(\mathcal{D} \mid M_k) \approx -\frac{1}{2}\,\text{BIC}_k = \log \hat{L}_k - \frac{k_p}{2}\log n$$

where \(\hat{L}_k\) is the maximised log-likelihood, \(k_p\) is the number of parameters in model \(M_k\), and \(n\) is the number of data points. The \(-\tfrac{k_p}{2}\log n\) term is the complexity penalty.

Posterior Weight Computation (numerically stable)

To avoid floating-point underflow when exponentiating large negative numbers, use the log-sum-exp trick:

$$\log P(M_k \mid \mathcal{D}) = \log P(\mathcal{D} \mid M_k) + \log P(M_k) - \log \sum_{j} \exp\!\bigl[\log P(\mathcal{D} \mid M_j) + \log P(M_j)\bigr]$$

Practically: let \(L_k = \log P(\mathcal{D} \mid M_k) + \log P(M_k)\), then \(w_k = \tfrac{\exp(L_k - \max_j L_j)}{\sum_j \exp(L_j - \max_j L_j)}\).

BMA Posterior Variance (Uncertainty Decomposition)

The BMA predictive variance decomposes into within-model and between-model components:

$$\operatorname{Var}(y^* \mid x^*, \mathcal{D}) = \underbrace{\sum_k w_k \operatorname{Var}_k(y^*)}_{\text{within-model}} + \underbrace{\sum_k w_k \bigl(\mu_k(x^*) - \bar{\mu}(x^*)\bigr)^2}_{\text{between-model}}$$

where \(\bar{\mu}(x^*) = \sum_k w_k \mu_k(x^*)\) is the BMA mean prediction and \(\mu_k, \operatorname{Var}_k\) are the posterior mean and variance of the \(k\)-th model. The between-model term captures pure model uncertainty — it is zero only when all models agree.

Formula Summary

Model posterior: \(w_k = P(M_k \mid \mathcal{D}) \propto P(\mathcal{D} \mid M_k)\,P(M_k)\)

Predictive mean: \(\hat{y}(x^*) = \sum_k w_k \mu_k(x^*)\)

Marginal likelihood (approx): \(\log P(\mathcal{D} \mid M_k) \approx -\tfrac{1}{2}\text{BIC}_k\)

BIC: \(\text{BIC}_k = -2\log\hat{L}_k + k_p \log n\)

Common Misconception

BMA is not model selection followed by prediction. It is a fundamentally different philosophy: instead of asking "which model is best?", it asks "given the data, what is the probability that each model is the true generating process, and what does the mixture of all models predict?" The difference matters most when model uncertainty is high and models disagree.

Key Takeaways & When to Use BMA
▾

When to Use BMA

  • You have genuine model uncertainty (no single obviously correct model)
  • You need well-calibrated predictive uncertainty (safety-critical decisions)
  • You want Occam's razor enforced automatically (avoid hand-tuning regularisation)
  • Data is limited and you cannot reliably select a single model

When NOT to Use BMA

  • Model space is huge and computing marginal likelihoods is intractable (use approximate BMA or Stacking instead)
  • The true model is known and is in your set — use it directly
  • Interpretability is critical — BMA predictions are opaque mixtures
  • All candidate models are seriously misspecified — BMA can still combine wrong models

Connections

BMA connects to: Bayes factor (ratio of marginal likelihoods), model evidence and variational inference (ELBO approximates log marginal likelihood), dropout as approximate BMA in deep networks (Gal & Ghahramani 2016), and Bayesian deep learning where weight uncertainty induces implicit model averaging.

6
Code — BMA From Scratch
▾

A self-contained BMA implementation using BIC approximation for the marginal likelihood:

import numpy as np
from scipy.special import logsumexp
def fit_poly_ols(X_feat, y):
"""OLS fit: returns beta, log-likelihood, BIC."""
beta, _, _, _ = np.linalg.lstsq(X_feat, y, rcond=None)
resid = y - X_feat @ beta
n, k = len(y), X_feat.shape[1]
sigma2 = np.var(resid) # MLE variance
log_lik = -n/2 * np.log(2*np.pi*sigma2) - np.sum(resid**2)/(2*sigma2)
bic = -2 * log_lik + k * np.log(n) # lower BIC = better
return beta, log_lik, bic
def bma_predict(x_train, y_train, x_test, max_degree=3):
"""BMA over polynomial models M1..M_max_degree."""
models = []
log_marginals = []
for deg in range(1, max_degree + 1):
X = np.vstack([x_train**i for i in range(deg+1)]).T
beta, _, bic = fit_poly_ols(X, y_train)
log_marginals.append(-bic / 2) # BIC approx
models.append((deg, beta))
# numerically stable posterior weights (log-sum-exp)
log_priors = np.zeros(max_degree) # equal priors
log_posteriors = np.array(log_marginals) + log_priors
log_Z = logsumexp(log_posteriors)
weights = np.exp(log_posteriors - log_Z) # sum to 1
# BMA prediction: weighted average of model predictions
bma_pred = np.zeros(len(x_test))
for w, (deg, beta) in zip(weights, models):
X_test = np.vstack([x_test**i for i in range(deg+1)]).T
bma_pred += w * (X_test @ beta)
return bma_pred, weights
# Usage
np.random.seed(7)
x = np.linspace(-2, 2, 30)
y = 1 + 2*x + 0.8*x**2 + np.random.normal(0, 0.6, 30)
x_test = np.linspace(-2, 2, 100)
pred, weights = bma_predict(x, y, x_test)
print(f"Weights: {weights.round(3)}") # [~0.000, ~0.712, ~0.288]

The log-sum-exp trick on line 25 prevents numerical underflow when the log-marginal likelihoods span a wide range. Without it, exp(log_marginals) can produce zeros for dominated models even though they have non-zero posterior weight.
