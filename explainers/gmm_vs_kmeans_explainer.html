GMM vs K-Means

Soft probabilistic assignment vs hard Voronoi partitioning — and how covariance type bridges the two
Intermediate Classical ML Clustering EM, O(nKD²) / iter
1
Understanding: Hard Votes vs Soft Probabilities
▼

What are they? Both K-Means and Gaussian Mixture Models (GMM) group unlabeled points into K clusters. K-Means asks "which single cluster does this point belong to?" and gives a hard yes/no answer. GMM asks "what is the probability this point came from each cluster?" and gives a soft, fractional answer that sums to 1.

Analogy: Imagine sorting fruit into "apple," "peach," and "plum" bins. K-Means is a worker who must drop each fruit into exactly one bin, even a fruit that's ambiguously between an apple and a peach. GMM is a worker who says "I'm 55% sure this is a peach, 45% sure it's an apple" — and keeps that uncertainty instead of forcing a premature decision.

💡 If you remember one thing

K-Means is a special case of GMM: it's what you get when every cluster is forced to be a spherical, equal-variance Gaussian and you round the soft probabilities \(\gamma_{ik}\) to the nearest 0 or 1 (hard argmax) instead of keeping them fractional.

How They Work Internally
▼

K-Means: Lloyd's Algorithm (hard EM)

1. Initialize \(K\) centroids \(\mu_1,\dots,\mu_K\) (e.g. random points). 2. Assign: each point \(x_i\) joins the cluster of its nearest centroid, \(z_i = \underset{k}{\operatorname{argmin}} \|x_i-\mu_k\|^2\) — this partitions the plane into a Voronoi diagram with straight-line boundaries. 3. Update: move each centroid to the mean of its assigned points. Repeat 2–3 until assignments stop changing. Guaranteed to converge because each step never increases the within-cluster sum of squares (inertia).

GMM: Expectation-Maximization (soft EM)

GMM models the data as generated by a mixture of \(K\) Gaussians: \(p(x)=\sum_{k=1}^K \pi_k \, \mathcal{N}(x \mid \mu_k,\Sigma_k)\), with mixing weights \(\pi_k\) summing to 1. E-step: for every point, compute the posterior "responsibility" — the probability it came from each component, via Bayes' rule. M-step: re-estimate \(\mu_k\), \(\Sigma_k\), \(\pi_k\) as responsibility-weighted statistics over ALL points (not just a hard subset). Repeat until the log-likelihood stops improving.

Design Decision: Why keep responsibilities soft?

Hard assignment throws away information: a point exactly between two clusters is forced into one, distorting the update step. Soft responsibilities let every point contribute to every cluster's statistics in proportion to how plausible that membership is — this is what allows GMM to fit overlapping, differently-shaped, differently-sized clusters that K-Means cannot represent.

🔑 Key Property

K-Means boundaries are always straight lines (perpendicular bisectors between centroids) because it only compares distances. GMM boundaries are curved (quadratic) contours shaped by each cluster's covariance \(\Sigma_k\) — they can be circles, ellipses, or rotated ellipses.

Why It Works — The Math
▼

The Responsibility (E-step)

By Bayes' theorem, the posterior probability that component \(k\) generated point \(x_i\) is:

$$\gamma_{ik} = \frac{\pi_k \, \mathcal{N}(x_i \mid \mu_k, \Sigma_k)}{\sum_{j=1}^{K} \pi_j \, \mathcal{N}(x_i \mid \mu_j, \Sigma_j)}$$

where the multivariate Gaussian density is \(\mathcal{N}(x\mid\mu,\Sigma) = (2\pi)^{-D/2}|\Sigma|^{-1/2}\exp\!\left(-\tfrac{1}{2}(x-\mu)^\top\Sigma^{-1}(x-\mu)\right)\). Each \(\gamma_{ik}\in[0,1]\) and \(\sum_k \gamma_{ik}=1\).

The Weighted Update (M-step)

Maximizing the expected complete-data log-likelihood gives closed-form updates — let \(N_k=\sum_i \gamma_{ik}\) be the effective size of cluster \(k\):

$$\mu_k = \frac{1}{N_k}\sum_{i=1}^n \gamma_{ik}\,x_i \qquad \Sigma_k = \frac{1}{N_k}\sum_{i=1}^n \gamma_{ik}(x_i-\mu_k)(x_i-\mu_k)^\top \qquad \pi_k = \frac{N_k}{n}$$

Each EM iteration is provably non-decreasing in the data log-likelihood \(\mathcal{L}=\sum_i \log\sum_k \pi_k\mathcal{N}(x_i\mid\mu_k,\Sigma_k)\) — this follows from Jensen's inequality applied to the evidence lower bound (ELBO), the same argument used to prove convergence of EM in general.

K-Means as a Limiting Case

If every \(\Sigma_k = \sigma^2 I\) (tied, spherical) and we let \(\sigma^2\to 0\), the responsibility \(\gamma_{ik}\) collapses to a hard indicator: 1 for the nearest centroid, 0 elsewhere. The M-step mean update reduces exactly to K-Means' centroid update. This is why K-Means is often called "hard EM" for an isotropic Gaussian mixture.

⚠️ Common Misconception

"GMM always finds the globally optimal clustering." False — like K-Means, EM only guarantees convergence to a local maximum of the likelihood and is sensitive to initialization. Both are typically run with multiple random restarts (or K-Means++ / K-Means-based init for GMM) and the best result is kept.

Covariance Types & Key Takeaways
▼

GMM's covariance_type controls how much shape freedom each cluster gets — it's a dial between K-Means-like rigidity and full flexibility:

TypeΣ constraintShapeParams (K=3, D=2)
spherical\(\sigma_k^2 I\)Circle, per cluster3
diagonal\(\operatorname{diag}(\sigma_{k1}^2,\dots)\)Axis-aligned ellipse, per cluster6
tied\(\Sigma\) shared across \(k\)Same-shaped ellipse, shared3
full\(\Sigma_k\) free, PDAny rotated ellipse, per cluster9

K-Means ⇔ GMM with spherical covariance, equal \(\pi_k\), and the variance \(\sigma^2\to 0\) (hard argmax instead of soft weighting). More free parameters fit training data better but risk overfitting with limited data — always validate with held-out log-likelihood or BIC/AIC.

When to use K-Means:

  • Clusters are roughly spherical, similar size, well-separated
  • You need speed/simplicity at large scale (single distance comparison per point)
  • You only need a hard partition, not uncertainty estimates

When to use GMM:

  • Clusters overlap, or have different sizes/shapes/orientations
  • You need calibrated membership probabilities (soft labels)
  • You want a generative density model (e.g. for anomaly detection, sampling)
💡 Decision

Start with K-Means for a fast, cheap partition (and to initialize GMM's means). Upgrade to GMM — usually full or tied covariance — when clusters are elongated/correlated, overlapping, or you need probabilistic (soft) membership.

Code Trace — GMM EM From Scratch
▼
import numpy as np
# 1. K-Means init: gives GMM's starting means
def kmeans(X, K, iters=10):
centroids = X[np.random.choice(len(X), K, replace=False)]
for _ in range(iters):
d2 = ((X[:,None,:]-centroids[None,:,:])**2).sum(-1)
z = d2.argmin(1) # HARD assignment
centroids = np.array([X[z==k].mean(0) for k in range(K)])
return centroids, z
def gaussian_pdf(x, mean, cov):
d = len(mean); diff = x - mean
inv, det = np.linalg.inv(cov), np.linalg.det(cov)
norm = 1.0 / np.sqrt((2*np.pi)**d * det)
return norm * np.exp(-0.5 * diff @ inv @ diff)
# 2. E-step: SOFT responsibilities via Bayes' rule
def e_step(X, means, covs, pis, K):
R = np.zeros((len(X), K))
for i, x in enumerate(X):
for k in range(K):
R[i, k] = pis[k] * gaussian_pdf(x, means[k], covs[k])
R[i] /= R[i].sum() # normalize -> sums to 1
return R
# 3. M-step: responsibility-weighted re-estimation
def m_step(X, R, K):
Nk = R.sum(0)
means = (R.T @ X) / Nk[:, None]
covs = np.array([
(R[:,k:k+1]*(X-means[k])).T @ (X-means[k]) / Nk[k]
for k in range(K)])
pis = Nk / len(X)
return means, covs, pis
# 4. Run EM until log-likelihood converges
for _ in range(50):
R = e_step(X, means, covs, pis, K)
means, covs, pis = m_step(X, R, K)
