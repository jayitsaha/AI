1
Understanding Subword Tokenization
▼

What is it? Before a language model can read text, it has to chop it into discrete units called tokens. Splitting on whole words breaks down for typos, rare words, and languages without spaces. Splitting into individual characters keeps the vocabulary tiny but makes sequences painfully long. Subword tokenization is the middle ground: common words stay whole ("the", "dog"), while rare or complex words get broken into meaningful fragments ("unbelievably" → "un" + "believ" + "ably").

Analogy: Think of a box of LEGO bricks. If every possible object had its own single custom brick, you'd need infinite bricks (word-level vocabulary explodes on rare words). If you only had 1×1 studs, you'd need thousands of pieces to build anything and lose the sense of larger shapes (character-level sequences explode in length). Subword tokenization gives you a curated kit — some big pre-built chunks ("ing", "tion", "un") and some small studs — so you can build any word efficiently.

💡 If you remember one thing

Every subword algorithm answers the same question — "which set of reusable pieces best compresses this corpus while keeping the vocabulary small?" — but they optimize different objectives: BPE greedily merges the most frequent adjacent pair, WordPiece merges the pair that most increases corpus likelihood, and Unigram starts big and prunes the pieces that hurt likelihood least.

2
How the Algorithms Work Internally
▼

Byte-Pair Encoding (BPE) — Bottom-Up Merging

BPE (Sennrich et al., 2016, adapting a 1994 data-compression trick) starts every word as a sequence of characters plus an end-of-word marker </w>. It then repeats a simple loop a fixed number of times: (1) count every adjacent symbol pair across the whole corpus, weighted by word frequency; (2) merge the single most frequent pair into a new symbol; (3) add that merge to an ordered merge table. Encoding new text later means re-applying the learned merges in the exact order they were learned.

WordPiece — Likelihood-Ranked Merging

WordPiece (used by BERT) follows the same merge loop, but instead of picking the pair with the highest raw count, it picks the pair that gives the biggest boost to the likelihood of the training corpus under a unigram language model. It scores each candidate pair \((a,b)\) as \(\text{score}(a,b) = \frac{\text{count}(ab)}{\text{count}(a)\cdot\text{count}(b)}\) — this favors pairs where the parts rarely occur alone but frequently occur together, avoiding BPE's bias toward merging very common characters just because they're common.

Unigram Language Model — Top-Down Pruning

Unigram (Kudo, 2018) works in the opposite direction. It starts from a huge candidate vocabulary (e.g. all substrings above some frequency) and a probability for each. It uses the EM algorithm to fit token probabilities, tokenizes the corpus with the Viterbi algorithm, computes how much the corpus log-likelihood would drop if each token were removed, and prunes the least-useful fraction (e.g. bottom 20%) each round — repeating until the vocabulary reaches the target size. Because it keeps probabilities per token, it can also sample multiple valid segmentations of the same word (subword regularization), which acts as a data-augmentation trick during training.

SentencePiece — The Language-Agnostic Wrapper

SentencePiece (Kudo & Richardson, 2018) is not a fourth merge algorithm — it's an implementation framework that can run either BPE or the Unigram LM on raw Unicode text, treating whitespace itself as a normal symbol (usually the "▁" meta-symbol). This means it needs no language-specific pre-tokenizer (no whitespace-splitting assumption), so it works identically well on English, Japanese, or Thai, and tokenization is fully reversible (detokenization is just string concatenation).

🔑 Design Decision: why not just use whole words?

A whole-word vocabulary must either cap vocabulary size (forcing an <UNK> token for every unseen word — catastrophic for rare words, typos, and morphology) or grow unbounded. Subword vocabularies guarantee full coverage — any string can always be encoded, in the worst case one byte/character at a time — while keeping the vocabulary at a fixed, practical size (typically 30k–100k).

3
Why It Works — The Math
▼

BPE's Merge Criterion

At each step, over the current symbol vocabulary, BPE picks the adjacent pair \((a,b)\) that maximizes raw co-occurrence count across the corpus \(C\) (words weighted by their frequency \(f_w\)):

$$(a^{*}, b^{*}) = \underset{(a,b)}{\operatorname{argmax}} \sum_{w \in C} f_w \cdot \text{adjacent-count}_w(a,b)$$

This is a greedy algorithm: at every step it makes the locally-optimal merge without reconsidering earlier merges. It is not guaranteed to find the vocabulary that best compresses the corpus overall — but it runs in roughly \(O(n)\) per merge with a priority-queue implementation, which is why it scales to web-scale corpora.

WordPiece's Likelihood Objective

WordPiece treats each word's segmentation as generated by a unigram model where tokens are independent: \(P(w) = \prod_i P(t_i)\). Merging \(a\) and \(b\) into \(ab\) changes the corpus log-likelihood by approximately:

$$\Delta \mathcal{L} \approx \text{count}(ab) \cdot \log\frac{P(ab)}{P(a)P(b)} = \text{count}(ab)\cdot\log\frac{\text{count}(ab)/N}{(\text{count}(a)/N)(\text{count}(b)/N)}$$

Ranking candidate merges by \(\frac{\text{count}(ab)}{\text{count}(a)\text{count}(b)}\) is exactly ranking by this likelihood gain (the \(\log\) and constant \(N\) terms don't change the ranking) — so WordPiece merges the pair that most improves how well a unigram LM explains the data, not simply the most common pair.

Unigram's Pruning Objective

Given vocabulary \(V\) with probabilities \(\{p_t\}\), the best segmentation of word \(w\) into tokens \(x_1 \ldots x_k\) is found by Viterbi:

$$\hat{x}(w) = \underset{x_1 \ldots x_k \in \text{Seg}(w)}{\operatorname{argmax}} \sum_{i=1}^{k} \log p(x_i)$$

Training alternates (a) re-estimating \(p(x_i)\) via EM over all possible segmentations, and (b) computing a "loss" \(\ell_t\) for each token \(t\) — the drop in total corpus log-likelihood if \(t\) were removed and words re-segmented with the remaining vocabulary — then dropping the tokens with smallest \(\ell_t\).

⚠️ Common Misconception

"BPE finds the optimal compression." It doesn't — greedy frequency-based merging is a fast heuristic, not an optimal codebook (that's an NP-hard problem in general). It works extremely well in practice because natural-language morphology is highly regular, not because it's provably optimal.

When to use which:

  • Building a GPT-style autoregressive LM → byte-level BPE (simple, fast, guarantees no <UNK>)
  • Fine-tuning/using BERT-family encoders → WordPiece (already baked into the pretrained vocab)
  • Need multilingual robustness or subword regularization for low-resource languages → Unigram via SentencePiece
  • Working with non-whitespace-delimited languages (Japanese, Chinese, Thai) → SentencePiece (any underlying algorithm)
💡 Decision Rule

If you're matching an existing pretrained model, use its tokenizer — mismatched vocabularies silently corrupt embeddings. If training from scratch, prefer SentencePiece + Unigram for maximum language coverage and the regularization benefit; prefer byte-level BPE for speed and simplicity when English-centric.

Code Trace — BPE From Scratch
▼

This is the exact algorithm powering the visualization above — the same functions run live in this page's JavaScript.

def get_vocab(corpus):
"""corpus: dict[str, int] word -> frequency"""
vocab = {}
for word, freq in corpus.items():
symbols = list(word) + ['</w>']
vocab[' '.join(symbols)] = freq
return vocab
def get_pair_stats(vocab):
pairs = defaultdict(int)
for word, freq in vocab.items():
symbols = word.split()
for i in range(len(symbols) - 1):
pairs[(symbols[i], symbols[i+1])] += freq
return pairs
def merge_vocab(pair, vocab_in):
merged = ''.join(pair)
vocab_out = {}
for word, freq in vocab_in.items():
symbols, out, i = word.split(), [], 0
while i < len(symbols):
if i < len(symbols)-1 and (symbols[i], symbols[i+1]) == pair:
out.append(merged); i += 2
else:
out.append(symbols[i]); i += 1
vocab_out[' '.join(out)] = freq
return vocab_out
# Training loop: repeat for num_merges iterations
vocab = get_vocab(corpus)
merges = []
for step in range(num_merges):
pairs = get_pair_stats(vocab)
if not pairs: break
best_pair = max(pairs, key=pairs.get) # highest frequency wins
vocab = merge_vocab(best_pair, vocab)
merges.append((best_pair, pairs[best_pair]))
