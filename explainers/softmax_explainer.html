Softmax: Numerical Stability & the Log-Sum-Exp Trick

Why naive softmax overflows, and how subtracting the max fixes it — exactly
Foundational Deep Learning Numerical Methods O(n) per row
1
Understanding Softmax
▼

What is it? Softmax turns a list of arbitrary real numbers ("logits") into a probability distribution — values between 0 and 1 that sum to 1, with larger logits mapped to larger probabilities. It's the standard last layer of a classifier: $$\sigma(z)_i = \frac{e^{z_i}}{\sum_{j=1}^n e^{z_j}}$$

Analogy: Imagine four runners finishing a race with times converted into "confidence scores." Softmax is the judge who converts those raw scores into betting odds that must add up to 100%. The catch: to compute the odds, the naive judge tries to compute e^score for every runner — and if a score is even moderately large (say 1000), that single exponential blows past what a computer's floating-point numbers can represent. The judge's calculator returns Infinity, and the odds become garbage (NaN).

💡 If you remember one thing

Softmax is shift-invariant: \(\sigma(z) = \sigma(z - c)\) for any constant \(c\). So before exponentiating, subtract \(m = \max_j z_j\) from every logit. The math is identical; the floating-point arithmetic no longer overflows.

How Naive Softmax Breaks Internally
▼

The IEEE-754 Ceiling

A standard 64-bit double can represent numbers up to roughly \(1.8 \times 10^{308}\). Since \(e^{709} \approx 8.2\times10^{307}\) but \(e^{710} = \text{Infinity}\) in floating point, ANY logit above ~709 makes exp() overflow. That sounds like an edge case, but unnormalized logits from a large model (before any scaling) routinely land in the hundreds or thousands — especially early in training or with high-magnitude embeddings.

What Actually Happens on the Wire

Say the logits are \(z = [712, 705, 698, 690]\). Computed naively:

  • exp(712) → Infinity (overflow — the true value ≈ \(2.5\times10^{309}\) can't be stored)
  • exp(705), exp(698), exp(690) → large but finite numbers
  • Sum → Infinity (Infinity + anything finite = Infinity)
  • \(\text{Infinity} / \text{Infinity} = \) NaN for the largest logit, and finite/Infinity = 0 for the rest

The output distribution is silently destroyed: one entry is NaN (poisons any downstream sum/loss), the others are hard 0 — even though the true softmax puts ~99.9% of the mass on the top logit and a tiny but nonzero amount on the others.

Design Decision: Why Subtract the Max (and not the mean, or clip)?

Subtracting the max guarantees the largest shifted logit is exactly 0, so \(e^0 = 1\) is the biggest term in the sum — every other term is \(e^{\text{negative}} \in (0,1]\), which can never overflow. Subtracting the mean doesn't give this guarantee (outliers can still overflow). Clipping logits changes the actual output distribution — subtracting the max does not, because of shift-invariance.

🔑 Key Property

After shifting by \(m=\max_j z_j\), every exponent satisfies \(z_i - m \le 0\), so \(e^{z_i-m} \in (0, 1]\). The sum of these terms is bounded below by 1 (the max term) and can never overflow — only underflow to 0 for very small terms, which is harmless.

3
Why It Works — The Math
▼

Proof: Softmax Is Shift-Invariant

For any constant \(c\) (in particular \(c = m = \max_j z_j\)):

$$\sigma(z-c)_i = \frac{e^{z_i-c}}{\sum_j e^{z_j-c}} = \frac{e^{-c}\,e^{z_i}}{e^{-c}\sum_j e^{z_j}} = \frac{e^{z_i}}{\sum_j e^{z_j}} = \sigma(z)_i$$

The \(e^{-c}\) factor appears in every term, top and bottom, and cancels exactly. This is why subtracting the max changes nothing mathematically — it only changes the magnitudes the computer has to exponentiate.

The Log-Sum-Exp (LSE) Trick

Cross-entropy loss needs \(\log \sigma(z)_i = z_i - \log\sum_j e^{z_j}\). Computing \(\sigma(z)_i\) first (which can underflow to exactly 0 for unlikely classes) and then taking \(\log(0) = -\infty\) is a second numerical trap. Instead, compute the log-normalizer directly and stably:

$$\operatorname{LSE}(z) = \log\sum_{j=1}^n e^{z_j} = m + \log\sum_{j=1}^n e^{z_j - m}, \qquad m = \max_j z_j$$

Derivation: factor out \(e^m\) exactly as above, then pull the \(\log\) through:

$$\log\sum_j e^{z_j} = \log\Big(e^m\sum_j e^{z_j-m}\Big) = \log e^m + \log\sum_j e^{z_j-m} = m + \log\sum_j e^{z_j-m}$$

Now every term inside the inner sum is \(e^{\le 0} \in (0,1]\), so the sum is well-conditioned and its log is safe. The stable log-probability is then \(\log \sigma(z)_i = z_i - \operatorname{LSE}(z)\) — computed without ever forming \(\sigma(z)_i\) itself.

⚠️ Common Misconception

"Just clip the logits to a safe range" is not equivalent to the max-subtraction trick — clipping changes which inputs map to which outputs (it's lossy), while shifting by the max is an exact re-parameterization that leaves \(\sigma(z)\) mathematically unchanged.

Key Takeaways
▼

Always do this:

  • Subtract \(m = \max_j z_j\) before exponentiating — every deep learning framework's softmax does this internally
  • Use log_softmax / log-sum-exp directly for cross-entropy loss instead of log(softmax(z)) — never round-trip through probabilities you're about to log again
  • Remember temperature scaling (\(z/T\)) happens before the max-subtraction, not after — the stability trick composes with any pre-scaling

When this bites you in practice:

  • Attention scores in transformers before the \(1/\sqrt{d_k}\) scaling and softmax — unscaled dot products can be large
  • Mixed-precision (fp16) training, where the safe exponent range shrinks to roughly ±11 instead of ±709
  • Reward models / RLHF pipelines computing log-probabilities over long sequences, where per-token errors compound
💡 One-Line Summary

Softmax is shift-invariant, so softmax(z) == softmax(z - max(z)) mathematically — but only the right-hand side is safe to actually compute.

Code Trace

import numpy as np
# Naive softmax — overflows for large logits
def softmax_naive(z):
exp_z = np.exp(z) # exp(712) -> inf
return exp_z / np.sum(exp_z) # inf/inf -> nan
# Numerically stable softmax
def softmax_stable(z, T=1.0):
z = np.asarray(z) / T
m = np.max(z, axis=-1, keepdims=True) # shift constant
exp_shifted = np.exp(z - m) # max term is exp(0)=1
return exp_shifted / np.sum(exp_shifted, axis=-1, keepdims=True)
# Log-sum-exp: stable log-normalizer for cross-entropy
def log_softmax(z):
z = np.asarray(z)
m = np.max(z, axis=-1, keepdims=True)
lse = m + np.log(np.sum(np.exp(z - m), axis=-1, keepdims=True))
return z - lse # log p_i, never forms p_i first
z = np.array([712.0, 705.0, 698.0, 690.0])
print(softmax_naive(z)) # [nan, 0., 0., 0.]
print(softmax_stable(z)) # [0.999, 0.00091, 0.00000083, 0.00000000028]
