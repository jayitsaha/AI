Decision Tree Disadvantages

High variance · Axis-aligned splits · Instability · Overfitting — and why ensembles fix them
Intermediate Classical ML Decision Trees Section 11
1
Understanding the Weaknesses
▾

A decision tree splits data by asking a sequence of yes/no questions: "Is feature \(x_j \leq t\)?". Each internal node is a split; each leaf stores a prediction. They are interpretable, fast, and require no feature scaling — yet they suffer from three entangled structural problems that make them unreliable as standalone models.

Key Concept — The Three Failure Modes

1. Axis-aligned splits — every boundary is a horizontal or vertical line in feature space, making smooth or diagonal decision surfaces impossible without exponentially many splits.

2. High variance — because splits are chosen greedily and the tree can grow arbitrarily deep, tiny perturbations in training data produce drastically different trees and predictions.

3. Instability — a single displaced training point can flip a root split, reordering every subsequent decision. The tree structure is not robust to sampling noise.

These three problems feed each other. High depth needed to approximate complex boundaries causes overfitting; overfitting amplifies variance; variance makes the model unstable. The correct fix is not to engineer a better splitting criterion — it is to aggregate many trees: bagging (random forests) reduces variance by averaging; boosting reduces bias by sequentially correcting residuals.

If You Remember One Thing

A single decision tree is a high-variance, low-bias learner. Moving one training point can completely restructure the tree. Ensembles (bagging / boosting) exist precisely because the individual tree's variance is so high that averaging multiple trees dramatically improves generalization — even with no individual tree being great.

Real-World Analogy

Imagine drawing the US state of Colorado on a map using only horizontal and vertical lines from a city street grid. You can approximate its (roughly) rectangular shape, but trying to draw California — with its diagonal coastline — forces you to use thousands of tiny stairstep segments. A decision tree faces exactly this problem: it can only draw right-angled boundaries, no matter how smooth the true decision surface is.

2
Axis-Aligned Splits: The Staircase Problem
▾

Every split in a CART decision tree has the form \(x_j \leq t\) for some feature index \(j\) and threshold \(t\). This means every decision boundary is a hyperplane perpendicular to one of the feature axes — a vertical or horizontal line in 2D. The resulting partition of feature space is always a union of axis-aligned rectangles.

$$\text{Split: } \{x : x_j \leq t\} \cup \{x : x_j > t\}, \quad j \in \{1,\ldots,p\},\; t \in \mathbb{R}$$

Why This Is Expensive for Diagonal Boundaries

Consider the true decision boundary \(x_2 = x_1\) (a 45° diagonal). A linear classifier captures this exactly with one hyperplane. A decision tree must approximate it with a staircase: to reduce misclassification error to \(\epsilon\), it needs \(O(1/\epsilon)\) splits. Empirically, a depth-4 tree achieves 90.0% accuracy on this diagonal boundary, while logistic regression achieves 98.4% — with a single parameter \(\theta_1 x_1 + \theta_2 x_2 = 0\).

Warning — Rotation Invariance

Decision trees are not rotation-invariant. Rotating a dataset by 45° turns a problem where trees perform well into one where they need twice as many splits. Linear models (logistic regression, SVMs with linear kernels) are fully rotation-invariant. This is one reason that feature engineering (e.g., creating \(x_1 - x_2\) as a feature) can dramatically improve tree performance on diagonal boundaries.

Numerical Example: Staircase Approximation of \(x_2 = x_1\)

With data uniform on \([0,10]^2\) and label \(y = \mathbf{1}[x_2 > x_1]\):

$$\text{Staircase with } k \text{ steps:} \quad \text{Accuracy} \approx 1 - \frac{1}{2k}$$
  • \(k = 1\) step: ~50% accuracy (uniform staircase, threshold=0 predicts class B everywhere)
  • \(k = 4\) steps (uniform staircase): 87.5% accuracy; CART depth-4: ~90.5%
  • \(k = 8\) steps (uniform staircase): 93.8% accuracy; error halved from k=4 but depth doubled
  • Linear model: 98.4% accuracy with zero depth

The staircase error decays as \(O(1/k)\), meaning to halve the error you need to double the tree depth — an exponentially expensive proposition for data with diagonal or curved boundaries.

Mathematical Insight

The class of functions representable by a depth-\(d\) binary tree partitions \(\mathbb{R}^p\) into at most \(2^d\) axis-aligned rectangles. For a Lipschitz-smooth boundary in \(\mathbb{R}^p\), the \(L_\infty\) approximation error is \(O(2^{-d/p})\) — it degrades exponentially with dimension \(p\), and only polynomially with depth \(d\). This is the geometric root of the curse of dimensionality for trees.

3
High Variance & Instability — The Flip Problem
▾

The bias-variance decomposition tells us that for any estimator \(\hat{f}\):

$$\text{Expected MSE} = \underbrace{\left(\mathbb{E}[\hat{f}(x)] - f(x)\right)^2}_{\text{Bias}^2} + \underbrace{\mathbb{E}\left[\left(\hat{f}(x) - \mathbb{E}[\hat{f}(x)]\right)^2\right]}_{\text{Variance}} + \sigma^2_\epsilon$$

Fully-grown decision trees have near-zero bias (they memorize the training data) and very high variance. In our numerical experiment, training depth-3 trees on 100 bootstrap resamplings of the same data and evaluating on 500 held-out points gave:

Numerical Verification

Bootstrap experiment on 2D diagonal boundary, \(n=100\), depth-3 trees vs logistic regression:

  • Decision Tree: mean test accuracy 86.3%, std 3.1% — high variance
  • Logistic Regression: mean test accuracy 97.5%, std 1.3% — low variance

The tree's standard deviation across bootstrap samples is 2.4× larger than logistic regression's.

Instability: One Point Changes Everything

Because the root split is chosen to maximize information gain (or minimize Gini impurity), and because this greedy choice is made with a fixed training set, even moving one data point near a split boundary can change the optimal threshold \(t^*\), which in turn changes every downstream split. The tree has no smoothness — there is no concept of "similar data produces similar trees." This is instability.

$$t^* = \underset{t}{\operatorname{argmin}} \; \text{Gini}\!\left(\mathcal{D}_{x_j \leq t}\right) \cdot \frac{|\mathcal{D}_{x_j \leq t}|}{n} + \text{Gini}\!\left(\mathcal{D}_{x_j > t}\right) \cdot \frac{|\mathcal{D}_{x_j > t}|}{n}$$

Formally, the CART algorithm is not Lipschitz-continuous in the training data. A perturbation of size \(\delta\) in one training point can cause a change of \(O(1)\) in the predicted boundary. Compare to a support vector machine whose solution changes by \(O(\delta)\) when you move a non-support-vector point.

Critical Failure Mode — Overfitting

Without pruning, a fully-grown tree achieves zero training error by memorizing every training point. It creates a separate leaf for each training example if needed. Training accuracy = 100%; test accuracy collapses. This is the worst-case manifestation of high variance: the tree fits noise as if it were signal.

Why Pruning Only Partially Helps

Cost-complexity pruning (minimal cost-complexity pruning, or \(\alpha\)-pruning) penalizes tree size:

$$R_\alpha(T) = R(T) + \alpha \cdot |T_{\text{leaves}}|$$

where \(R(T)\) is training error and \(\alpha \geq 0\) is the complexity penalty. Pruning reduces variance but cannot fix the axis-alignment problem — it only controls depth. And it does not fundamentally solve instability; a pruned tree grown on a slightly different dataset still produces a structurally different tree.

Why Ensembles Fix These Problems
▾

Each weakness of a single tree has a corresponding ensemble remedy. The insight is that many unstable, high-variance learners, when averaged, produce a stable, low-variance model — provided their errors are uncorrelated.

Bagging (Bootstrap Aggregating) → Reduces Variance

Train \(B\) trees on bootstrap samples \(\mathcal{D}_1^*, \ldots, \mathcal{D}_B^*\), each drawn with replacement from the original \(n\) points. Predict by majority vote (classification) or mean (regression):

$$\hat{f}_{\text{bag}}(x) = \frac{1}{B} \sum_{b=1}^{B} \hat{f}_b(x)$$

If each tree has variance \(\sigma^2\) and pairwise correlation \(\rho\), the ensemble variance is:

$$\text{Var}\!\left(\hat{f}_{\text{bag}}\right) = \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2$$

As \(B \to \infty\), variance approaches \(\rho\sigma^2\) — the irreducible correlation floor. Random Forests reduce \(\rho\) further by randomly subsampling \(m \approx \sqrt{p}\) features at each split, decorrelating the trees.

Boosting → Reduces Bias

Gradient Boosting fits trees sequentially, each one on the negative gradient (residuals) of the loss from the previous ensemble. It adds bias correction, not variance reduction. The combination of shallow (high-bias, low-variance) trees grown sequentially yields a powerful low-bias model without excessive variance.

Key Takeaways & When to Reach for Ensembles
▾
When to Use a Single Tree

Use a single decision tree when interpretability is paramount: medical diagnosis rules, loan approval criteria, or any context where a human must audit every decision. A depth-3 tree produces at most 8 rules that a domain expert can verify. In all other cases, prefer an ensemble.

Decision Guide

  • Need interpretability + fast inference → Single pruned tree (depth ≤ 5)
  • Tabular data, best accuracy → XGBoost / LightGBM (gradient boosting)
  • High-dimensional data, feature importance → Random Forest
  • Data with diagonal/curved boundaries → Linear model or SVM or neural network
  • Small training set, need stability → Random Forest (bagging averages out noise)

Summary of Decision Tree Disadvantages

  • Axis-aligned splits: Every boundary is horizontal/vertical. Approximating a 45° line requires \(O(1/\epsilon)\) splits for \(\epsilon\) error.
  • High variance: Bootstrap std of test accuracy is 2–3× higher than linear models. Small data changes → large prediction changes.
  • Instability: Moving one point near a split threshold can cascade through the entire tree structure.
  • Overfitting: Fully-grown trees memorize noise; pruning helps but does not fix the structural problems.
Common Interview Mistake

"Decision trees don't need feature scaling" — true, but this is not a sufficient reason to use them over a random forest. Random forests also don't need feature scaling, are more accurate, more stable, and can capture non-axis-aligned boundaries better. Cite instability and high variance as the primary reasons to move to ensembles, not just scaling.
