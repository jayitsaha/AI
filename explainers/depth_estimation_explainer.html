1
Understanding Depth Estimation
▼

What is it? Depth estimation is the task of inferring the distance of objects from a camera, typically for every pixel in an image. It transforms a 2D image into a 3D understanding of the scene, producing a "depth map" where each pixel's value represents its distance from the camera. This is crucial for applications like autonomous driving, augmented reality, 3D reconstruction, and robotics.

Analogy: Imagine you're looking at a photograph. Your brain effortlessly infers which objects are closer and which are farther away, even though the photo itself is flat. It uses cues like perspective, occlusion, relative size, and shading. Depth estimation algorithms try to replicate this ability, either by mimicking human binocular vision (stereo) or by learning these subtle cues from vast amounts of data (monocular).

💡 If you remember one thing

Depth estimation converts a 2D image into a 3D representation. Stereo depth uses two cameras and triangulation to calculate precise metric distances, while monocular depth uses a single image and deep learning to infer relative depth, often with scale ambiguity.

How It Works Internally
▼

Monocular Depth Estimation (MiDaS, DPT)

Monocular depth estimation uses a single 2D image as input. Since a single image inherently lacks explicit depth information, these methods rely heavily on learned contextual cues. Modern approaches leverage deep neural networks, often based on encoder-decoder architectures (like U-Nets or Transformers in DPT/MiDaS).

  • Input: A single RGB image.
  • Process: A convolutional neural network (CNN) or Vision Transformer (ViT) processes the image, extracting features that implicitly encode depth cues (e.g., vanishing points, object sizes, texture gradients, shadows, occlusions). Models like MiDaS (Multi-Dataset Automated Depth Estimation) and DPT (Dense Prediction Transformer) are state-of-the-art, trained on massive, diverse datasets to generalize well to unseen scenes.
  • Output: A dense depth map, where pixel values represent relative depth (e.g., darker = closer, lighter = farther). The absolute scale (e.g., meters) is typically ambiguous without additional information.

Stereo Depth Estimation

Stereo depth estimation mimics human binocular vision, using two cameras separated by a known baseline. The fundamental principle is triangulation: objects appear at slightly different horizontal positions in the left and right images, and this "shift" (disparity) is inversely proportional to their depth.

  • Input: A pair of synchronized left and right images.
  • Process:
    1. Rectification: The images are geometrically transformed so that corresponding points lie on the same horizontal scanline. This simplifies the search for matches.
    2. Correspondence Matching: For each pixel in the left image, the algorithm searches for its matching pixel in the right image along the same horizontal line. This is the most computationally intensive step, often done using correlation-based methods (e.g., Sum of Absolute Differences, Census Transform) or deep learning (e.g., PSMNet, RAFT-Stereo).
    3. Disparity Calculation: The horizontal distance between corresponding points in the rectified images is called disparity (\(d\)).
    4. Depth Triangulation: Using the disparity, along with known camera parameters (focal length \(f\), baseline \(B\)), the actual 3D depth (\(Z\)) can be calculated.
  • Output: A dense, metric depth map (e.g., in meters).
🔑 Key Distinction

Monocular methods infer depth from learned patterns in a single image, yielding relative depth. Stereo methods calculate depth from geometric principles using two images, yielding absolute metric depth.

Why It Works — The Math of Stereo Depth
▼

The Pinhole Camera Model & Triangulation

Stereo depth relies on the pinhole camera model, which simplifies how 3D points are projected onto a 2D image plane. Consider a 3D point \(P=(X, Y, Z)\) in the world. In an ideal pinhole camera, its projection \(p=(x,y)\) on the image plane is given by similar triangles. For stereo, we use two cameras (Left and Right) separated by a baseline \(B\).

Let's assume the cameras are perfectly aligned (rectified) such that their image planes are coplanar, and their optical axes are parallel. The focal length is \(f\). A point \(P\) at depth \(Z\) is projected to \(x_L\) in the left image and \(x_R\) in the right image.

From similar triangles (considering the horizontal plane containing the optical axes):

$$\frac{X}{Z} = \frac{x_L}{f} \quad \text{and} \quad \frac{X - B}{Z} = \frac{x_R}{f}$$

Rearranging the first equation, \(X = \frac{x_L Z}{f}\). Substitute this into the second equation:

$$\frac{\frac{x_L Z}{f} - B}{Z} = \frac{x_R}{f} \quad \implies \quad \frac{x_L}{f} - \frac{B}{Z} = \frac{x_R}{f}$$

Now, rearrange to solve for \(Z\):

$$\frac{B}{Z} = \frac{x_L}{f} - \frac{x_R}{f} = \frac{x_L - x_R}{f} \quad \implies \quad Z = \frac{f \cdot B}{x_L - x_R}$$

The term \(x_L - x_R\) is the disparity, \(d\). Thus, the fundamental stereo depth equation is:

$$Z = \frac{f \cdot B}{d}$$

This equation shows that depth \(Z\) is inversely proportional to disparity \(d\). Closer objects have larger disparity, and farther objects have smaller disparity. This relationship allows precise metric depth calculation.

Monocular Depth: Implicit Learning

For monocular depth, there's no explicit geometric formula like for stereo. Instead, deep networks learn to map image features to depth. This is a highly ill-posed problem, as infinitely many 3D scenes can project to the same 2D image. The network learns statistical regularities from training data. For example, a car appearing smaller in an image is likely farther away, or a textured surface that blurs into the distance implies increasing depth.

⚠️ Challenges & Pitfalls

Monocular: Suffers from inherent scale ambiguity (a small object nearby looks identical to a large object far away). Also struggles with novel objects or scenes outside its training distribution.
Stereo: Highly sensitive to camera calibration, requires textured surfaces for correspondence, and fails in occluded regions (where a point is visible in one camera but not the other).

Key Takeaways
▼

When to use Monocular Depth (e.g., MiDaS, DPT):

  • Resource Constraints: Only a single camera is available (e.g., smartphone, drone).
  • Flexibility: No need for precise camera calibration or hardware synchronization.
  • Relative Depth: When understanding scene layout (e.g., "this is closer than that") is sufficient, and metric scale is not strictly required or can be estimated via other means (e.g., known object sizes).
  • Generalization: Modern models generalize well to diverse, unseen environments.

When to use Stereo Depth:

  • Metric Accuracy: When precise, absolute distance measurements (e.g., in meters) are critical (e.g., autonomous driving for collision avoidance, industrial robotics for manipulation).
  • Robustness to Texture: While challenging for textureless regions, stereo is fundamentally geometric and less prone to "hallucinating" depth based on learned priors.
  • Known Camera Setup: Requires two calibrated cameras with a known baseline.

Limitations to consider:

  • Monocular: Inherently ambiguous scale; performance can degrade on out-of-distribution data.
  • Stereo: Requires careful camera calibration; struggles with textureless surfaces (no unique correspondences) and occlusions (points visible in one camera but not the other).
💡 Complementary Approaches

Monocular and stereo depth estimation are not mutually exclusive. Hybrid systems often combine deep learning (for robust feature extraction and monocular cues) with geometric principles (for metric scale and accuracy) to achieve superior performance.

FOCAL_LENGTH = 700.0 # pixels (fx, fy often same)
BASELINE = 0.5 # meters (distance between stereo cameras)
IMAGE_WIDTH = 640 # pixels
CENTER_X = IMAGE_WIDTH / 2
# --- Stereo Depth Calculation ---
def calculate_depth_from_disparity(disparity_map):
# Depth Z = (f * B) / d
# Handle zero disparity to avoid division by zero (set to max depth)
disparity_map[disparity_map == 0] = 1e-6 # Small non-zero for far objects
depth_map = (FOCAL_LENGTH * BASELINE) / disparity_map
return depth_map
# --- Simulate disparity for a point (X, Y, Z) ---
def simulate_disparity(X, Y, Z):
# Project 3D point (X,Y,Z) to left camera pixel x_L
x_L = (X * FOCAL_LENGTH / Z) + CENTER_X
# Project 3D point (X-B,Y,Z) to right camera pixel x_R
x_R = ((X - BASELINE) * FOCAL_LENGTH / Z) + CENTER_X
disparity = x_L - x_R
return disparity
# --- Example Usage ---
# A point at 5 meters depth, 0.2m to the right of center
point_X, point_Y, point_Z = 0.2, 0.0, 5.0
sim_disp = simulate_disparity(point_X, point_Y, point_Z)
print(f"Simulated disparity for Z={point_Z}m: {sim_disp:.2f} pixels")
# Calculate depth back from this disparity
calculated_depth = calculate_depth_from_disparity(np.array([sim_disp]))[0]
print(f"Calculated depth from disparity: {calculated_depth:.2f} meters")
