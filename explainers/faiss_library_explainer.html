What Is FAISS?
▾

Facebook AI Research's FAISS (Facebook AI Similarity Search) is the de-facto library for approximate nearest-neighbour (ANN) search in high-dimensional spaces. When you have millions or billions of vectors (embeddings, image descriptors, audio fingerprints) and need to find the closest ones to a query in milliseconds, brute-force \(O(N \cdot D)\) scan is infeasible. FAISS gives you sub-linear search time by trading a tiny accuracy drop for massive speed gains.

One-Sentence Summary
FAISS compresses and organises vectors into a two-level index—coarse Voronoi cells (IVF) that prune the search space, plus product-quantization codes (PQ) that compress each vector to a few bytes—enabling billion-scale ANN on a single GPU node.

Real-world analogy: Imagine finding the nearest coffee shop to you in a city of 10 million shops. Brute-force means checking every shop. IVF is like first locating which postal district you are in (reduces candidates to ~1 %), then PQ is like using a zip-code approximation of each shop's coordinate (saves memory 64×) instead of the exact GPS reading—good enough, and blindingly fast.

If you remember one thing
IVF prunes which vectors to compare; PQ compresses how each vector is stored and scored. IVFPQ does both simultaneously, giving sub-millisecond search over 10⁹ vectors in ≤16 GB RAM.
2
IVF — Inverted File (Coarse Quantizer)
▾

IVF first runs k-means to partition the entire database into \(k_{coarse}\) Voronoi cells. Each database vector is then assigned to the nearest centroid and stored in that cell's inverted list.

At query time:

  • Compute distance from the query \(\mathbf{q}\) to all \(k_{coarse}\) centroids — \(O(k_{coarse} \cdot D)\).
  • Select the \(n_{probe}\) closest centroids (typically 8–128 out of 4096).
  • Scan only the vectors in those lists — typically 0.5–3 % of \(N\).
$$\text{IVF recall} \approx P\!\left(\mathbf{x}^* \in \bigcup_{i=1}^{n_{probe}} \mathcal{L}_i\right) \approx 1 - \left(1 - \frac{n_{probe}}{k_{coarse}}\right)^{1} \quad \text{(single NN)}$$
Tuning trade-off
Higher \(n_{probe}\) → better recall, slower search. Rule of thumb: \(k_{coarse} = \lfloor\sqrt{N}\rfloor\), \(n_{probe} \approx \sqrt{k_{coarse}}\) for a reasonable recall/speed knee.

The FAISS IndexIVFFlat stores full float32 vectors in each list (no compression). This gives exact distances within scanned lists but still requires ~\(4D\) bytes per vector.

3
PQ — Product Quantization (Vector Compression)
▾

Product Quantization (Jégou et al., 2011) compresses a \(D\)-dimensional float32 vector into a short byte code by:

  1. Split the \(D\) dimensions into \(M\) disjoint subspaces of size \(D/M\).
  2. Train a separate 256-centroid k-means codebook for each subspace on sample data.
  3. Encode each vector: map its \(m\)-th sub-vector to the nearest centroid index \(q_m \in \{0,\ldots,255\}\).
$$\mathbf{x} \approx \hat{\mathbf{x}} = [c_1^{(1)}(q_1),\; c_2^{(2)}(q_2),\; \ldots,\; c_M^{(M)}(q_M)]$$

A vector is stored as \(M\) bytes (uint8). For \(D=128, M=8\): 512 bytes → 8 bytes (64× compression).

Asymmetric Distance Computation (ADC): At query time, precompute the \(M\) look-up tables (LUT) of distances from the query sub-vectors to all 256 centroids of each subspace:

$$d(\mathbf{q}, \hat{\mathbf{x}}) \approx \sum_{m=1}^{M} \text{LUT}_m[q_m]$$

One distance estimate = \(M\) table lookups — typically 4–32 additions, vs \(D\) multiplications for exact L2. This is the inner loop FAISS optimises with SIMD/GPU.

Quantization error bound
PQ reconstruction error satisfies \(\mathbb{E}\!\left[\|\mathbf{x} - \hat{\mathbf{x}}\|^2\right] = \sum_{m=1}^M \sigma_m^2\) where \(\sigma_m^2\) is the per-subspace k-means distortion. Smaller subspaces (larger \(M\)) reduce variance but require more training data per codebook.
4
IVFPQ — The Billion-Scale Combination
▾

IndexIVFPQ combines both techniques: vectors are first routed to a Voronoi cell (IVF), then stored as PQ codes within each inverted list. At query time, only the PQ codes in \(n_{probe}\) cells are scanned using ADC — the best of both worlds.

Memory footprint
For \(N = 10^9\), \(D = 128\), \(M = 8\), \(k_{coarse} = 65536\):
Flat: 512 GB · IVF only: 512 GB · IVFPQ: 8 GB (64× compression) + 2 GB for centroid table.

FAISS IVFPQ residual coding: Instead of encoding the raw vector, FAISS optionally encodes the residual \(\mathbf{r} = \mathbf{x} - \mathbf{c}_{cell}\) against the assigned cell centroid. This shifts the distribution to zero-mean, improving PQ reconstruction quality significantly.

$$\hat{\mathbf{x}} = \mathbf{c}_{cell} + \text{PQ}(\mathbf{x} - \mathbf{c}_{cell})$$
GPU acceleration
FAISS ships a CUDA implementation of IVFPQ that fits the codebook LUTs in shared memory. A single V100 GPU can score ~1 billion distance estimates per second, enabling real-time ANN over the full index.

Key Takeaways & When to Use
▾
FAISS Index Selection Guide
  • N < 1M, D ≤ 64: IndexFlatL2 — exact brute force fits in RAM.
  • N ∈ [1M, 10M], high recall needed: IndexIVFFlat with k_coarse = 4096.
  • N > 10M, memory constrained: IndexIVFPQ — the production standard.
  • GPU available: GpuIndexIVFPQ — 10–100× throughput vs CPU.
  • Tiny codes needed (<1 byte/dim): IndexIVFPQR — PQ + re-ranking with a refinement index.

Critical hyperparameters: \(k_{coarse}\) (number of Voronoi cells), \(n_{probe}\) (cells scanned at query time), \(M\) (PQ subspaces), \(k_{sub} = 256\) (sub-codebook size, fixed). Training requires ≥ 39× \(k_{coarse}\) sample vectors.

Common pitfalls
  • Forgetting to train() before add() — IVFPQ requires training data.
  • Setting \(M\) too large (slow ADC) or too small (poor recall) — start with \(M = D/4\).
  • Not normalising vectors before cosine search — use faiss.normalize_L2 then inner product index.
  • Misreading returned distances as true L2 — they are approximate ADC estimates.
