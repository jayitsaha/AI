Label Smoothing

Soft targets that trade a little training accuracy for a lot of calibration
Intermediate Regularization O(K) per example
1
Understanding the Concept
▾

When you train a classifier, the textbook recipe hands it a one-hot target: "this image is 100% a bird, 0% everything else." The network takes that literally — it keeps pushing the correct logit up and the wrong ones down, forever, because softmax can only reach probability 1 when the correct logit is infinitely larger than the rest. The model becomes overconfident: it reports 99.9% certainty even on ambiguous or mislabeled examples.

Label smoothing fixes this by lying to the model, gently and on purpose. Instead of the target "100% bird," it uses "92% bird, 2% cat, 2% dog, 2% fish, 2% frog" — a tiny amount of probability mass \(\varepsilon\) is redistributed uniformly across all classes. The model can never win by driving logits to infinity, because the target it's chasing never demands 100% certainty in the first place.

Real-world analogy

Imagine a teacher grading essays who never gives a perfect 100% — the best essay gets 92%, with the remaining 8 points spread thin across "areas any essay could improve." Students still learn to write the best essay they can, but none of them get trained to believe perfection is achievable, so nobody develops an inflated ego about a single essay. That's exactly what label smoothing does to a neural network's confidence.

💡 If you remember one thing

Label smoothing replaces the one-hot target with \((1-\varepsilon)\,y + \varepsilon/K\), capping the maximum achievable target probability below 1 — so the optimizer no longer has any incentive to push logits toward infinity, which keeps the network calibrated and its learned representations more tightly clustered.

How It Works Internally
▾

Where it sits in the pipeline

Label smoothing is a one-line change at the loss computation stage — nothing about the network architecture, forward pass, or optimizer changes. The data flow is: logits \(z \in \mathbb{R}^K\) → softmax \(p = \text{softmax}(z)\) → target construction (one-hot \(y\) is replaced by \(y_{LS} = (1-\varepsilon)y + \varepsilon/K\)) → cross-entropy \(L = -\sum_k y_{LS,k}\log p_k\).

Numerical trace (K = 5 classes, true class = "Bird", ε = 0.1)

Logits from the network: \(z = [1.2,\ 0.3,\ 2.6,\ -0.5,\ 0.8]\) for [Cat, Dog, Bird, Fish, Frog].

  1. Softmax: \(p \approx [0.158,\ 0.064,\ 0.642,\ 0.029,\ 0.106]\)
  2. One-hot target: \(y = [0, 0, 1, 0, 0]\)
  3. Smoothed target: \(y_{LS} = [0.02,\ 0.02,\ 0.92,\ 0.02,\ 0.02]\) — note the true class caps at \(1-\varepsilon+\varepsilon/K = 0.92\), never 1.0
  4. Vanilla cross-entropy: \(L = -\log(0.642) \approx 0.443\)
  5. Smoothed cross-entropy: \(L_{LS} \approx 0.615\) — higher loss even though the prediction is "correct," because the model is being penalized for not spreading any belief onto other classes
  6. Gradient at the logits, \(\partial L/\partial z_k = p_k - y_{LS,k}\): true class gets \(0.642-0.92=-0.278\) (push up, but weaker than vanilla's \(-0.358\)); wrong classes get small positive pushes like \(0.642\)'s neighbor Cat: \(0.158-0.02=+0.138\) (push down, but bounded — it never has to reach exactly 0)

Design decisions

Why uniform smoothing and not something smarter? Szegedy et al. (2016) chose to spread \(\varepsilon\) uniformly across all K classes for simplicity and because it requires no extra knowledge of class relationships. Sequence models sometimes smooth toward the unigram/vocabulary frequency distribution instead of uniform — spreading more mass to common tokens — which can work better when classes are highly imbalanced (this is "smoothing toward a prior" rather than toward uniform).

Why ε ≈ 0.1? Empirically robust across vision and NLP tasks. Too small (ε→0) recovers vanilla one-hot training (no effect); too large (ε→1) collapses the target toward pure uniform noise and the model can no longer learn to discriminate classes at all.

⚠️ Edge case: large vocabularies

In NMT/LLM training with vocabularies of 30k–100k+ tokens, \(\varepsilon/K\) becomes vanishingly small per wrong class, but summed over K−1 classes it still meaningfully caps the true-class target below 1 and softens the loss landscape — this is exactly the setting used in the original Transformer ("Attention Is All You Need") with ε = 0.1.

Why It Works — The Math
▾

1. The smoothed target and its decomposition

Define the smoothed target as a mixture of the one-hot label \(y\) and the uniform distribution \(u_k = 1/K\):

$$y_{LS} = (1-\varepsilon)\,y + \varepsilon\, u$$

Substituting into cross-entropy and splitting the sum:

$$L = -\sum_k y_{LS,k}\log p_k = (1-\varepsilon)\underbrace{\Big(-\log p_t\Big)}_{H(y,p)} \;+\; \varepsilon\underbrace{\Big(-\tfrac{1}{K}\sum_k \log p_k\Big)}_{H(u,p)}$$

The second term equals \(H(u) + \mathrm{KL}(u\|p) = \log K + \mathrm{KL}(u\|p)\), so minimizing \(L\) is equivalent to minimizing:

$$L \;=\; (1-\varepsilon)\,H(y,p) \;+\; \varepsilon\,\mathrm{KL}(u\|p) \;+\; \text{const}$$

This is the key structural insight: label smoothing is ordinary cross-entropy plus an explicit penalty that pulls the predicted distribution toward uniform, weighted by ε. It's mathematically a regularizer, not a data-labeling trick.

2. Why logits stay bounded (proof sketch)

With vanilla one-hot CE, the global infimum of the loss is 0, achieved only in the limit \(z_t - z_k \to \infty\) for all wrong classes k — training pushes logits toward infinity forever. With label smoothing, differentiate \(L\) with respect to the logit gap and set the gradient to zero. At the stationary point (treating all incorrect-class logits as tied at value \(z_w\) by symmetry), the softmax probabilities must satisfy \(p_t = 1-\varepsilon+\varepsilon/K\) and \(p_k = \varepsilon/K\) for k ≠ t exactly — because cross-entropy with a fixed target is minimized when the model's output distribution matches the target distribution. Solving \(p_t/p_k = e^{z_t-z_w}\) for the logit gap gives a finite, closed-form optimum:

$$z_t^{*} - z_w^{*} = \log\!\left(\frac{(1-\varepsilon)(K-1)}{\varepsilon}\right)$$

For ε = 0.1, K = 5 this evaluates to \(\log(36) \approx 3.58\) — a finite target gap the optimizer can actually reach and then stop, rather than an infinite one it chases forever. This bounded optimum is exactly why label smoothing tightens the clusters of penultimate-layer activations observed by Müller et al. (2019): the network has no gradient signal left to keep separating classes once it hits the bound.

📐 Formula box

$$y_{LS,k} = \begin{cases}1-\varepsilon+\varepsilon/K & k = t \\ \varepsilon/K & k \neq t\end{cases} \qquad \frac{\partial L}{\partial z_k} = p_k - y_{LS,k}$$

3. Gradient flow

Because softmax + cross-entropy has the famously clean gradient \(\partial L/\partial z_k = p_k - y_k\), label smoothing changes nothing about backprop mechanics — it just substitutes \(y_{LS}\) for \(y\) in that formula. This is why it's essentially free to implement: no architecture change, no extra forward pass, \(O(K)\) extra work per example to build \(y_{LS}\).

⚠️ Common misconception

"Label smoothing makes the model's probabilities calibrated." Not quite — it makes probabilities less overconfident on average and typically reduces Expected Calibration Error (ECE), but it does not guarantee calibration the way post-hoc temperature scaling (fit on a held-out set) does. It is a training-time regularizer, not a calibration guarantee.

Key Takeaways
▾
  • What: Replace one-hot targets \(y\) with \(y_{LS}=(1-\varepsilon)y+\varepsilon/K\) before computing cross-entropy.
  • Why it works: It's cross-entropy plus an explicit \(\varepsilon \cdot \mathrm{KL}(u\|p)\) penalty toward uniform, which bounds the optimal logit gap instead of letting it diverge to infinity.
  • Effect: Lower confidence on correct predictions, tighter/more equidistant clusters in the penultimate layer, better calibration (lower ECE).
  • Cost: Slightly worse teacher quality for knowledge distillation (Müller et al. 2019 showed it erases informative "dark knowledge" in the wrong-class logits), and can hurt when you specifically need sharp, high-confidence outputs (e.g. some active-learning acquisition functions).
  • Where it's used: Inception-v3, the original Transformer (ε = 0.1), most modern image classifiers, many seq2seq/translation systems.
🎯 When to reach for it

Default choice for classification training with noisy or ambiguous labels, or whenever calibrated confidence matters downstream (e.g. active learning, OOD detection, decision thresholds). Skip it when training a teacher model for distillation, or when the task genuinely needs peaked, low-entropy outputs.
