Understanding DBSCAN
▼

What is DBSCAN? Density-Based Spatial Clustering of Applications with Noise (DBSCAN) groups data points by how tightly they are packed together — dense regions become clusters, sparse regions become noise. Unlike k-means, you never have to tell it how many clusters to find.

Analogy: Imagine you're looking at a map of a city from a helicopter. Neighbourhoods (clusters) are where buildings are crammed together. Empty fields or isolated farms are noise. DBSCAN works the same way: it asks "is this point surrounded by enough neighbours within a given radius?" If yes, it's in a community. If no, it's an outlier.

Two parameters control everything: \(\varepsilon\) (epsilon) — the radius of the neighbourhood — and minPts — the minimum number of points needed inside that radius to call it "dense." Every point gets one of three labels:

  • Core point: has \(\geq\) minPts neighbours within radius \(\varepsilon\) (including itself). The nucleus of a cluster.
  • Border point: fewer than minPts neighbours, but lies within the \(\varepsilon\)-ball of a core point. On the edge of a cluster.
  • Noise point: not a core point and not reachable from any core point. An outlier.
If you remember one thing

DBSCAN finds clusters by density-connectivity: start from any unvisited core point, grow outward through all density-reachable neighbours, repeat. No K required; noise is automatically labelled \(-1\).

How DBSCAN Works Internally
▼

The Algorithm, Step by Step

DBSCAN processes each point exactly once. For each unvisited point \(p\):

  1. Mark \(p\) as visited. Find all points in \(N_\varepsilon(p) = \{q \mid \|p - q\| \le \varepsilon\}\).
  2. If \(|N_\varepsilon(p)| < \text{minPts}\): label \(p\) as noise (temporarily — it may later become a border point).
  3. Otherwise: start a new cluster \(C\). Add all of \(N_\varepsilon(p)\) to the seed set.
  4. For each point \(q\) in the seed set: if \(q\) is unvisited, visit it and if \(|N_\varepsilon(q)| \ge \text{minPts}\), add its neighbours to the seed set. Assign \(q\) to cluster \(C\).
  5. When the seed set is exhausted, cluster \(C\) is complete. Continue to the next unvisited point.

Key Definitions

Directly density-reachable: Point \(q\) is directly density-reachable from \(p\) (w.r.t. \(\varepsilon\), minPts) if \(q \in N_\varepsilon(p)\) and \(|N_\varepsilon(p)| \ge \text{minPts}\) — i.e., \(p\) is a core and \(q\) is a neighbour of \(p\).

Density-reachable: \(q\) is density-reachable from \(p\) if there exists a chain \(p = p_1, p_2, \ldots, p_n = q\) where each \(p_{i+1}\) is directly density-reachable from \(p_i\). This relation is transitive but not symmetric.

Density-connected: \(p\) and \(q\) are density-connected if there exists a core point \(o\) such that both \(p\) and \(q\) are density-reachable from \(o\). This is symmetric — the basis for cluster membership.

Key Property

A cluster \(C\) is a maximal set of density-connected points. Two core points in the same dense region will always end up in the same cluster, regardless of which one triggered the expansion first.

Why It Finds Arbitrary Shapes

K-means computes cluster membership by distance to centroid — it is intrinsically biased toward convex, spherical clusters. DBSCAN propagates membership through density-connected chains, so it naturally traces the contours of elongated, curved, or interleaved structures like the two-moons dataset. Any shape that is "connected through density" becomes one cluster.

Gotcha: Border Points Are Not Symmetric

A border point \(b\) can be reachable from core point \(p\) but NOT reachable from core point \(q\), even if both \(p\) and \(q\) are in the same cluster. In the original DBSCAN paper (Ester et al. 1996), border point assignment is implementation-dependent — a point at the intersection of two cluster boundaries may be assigned to whichever cluster discovers it first.

The Math Behind DBSCAN
▼

The \(\varepsilon\)-Neighbourhood

For a point \(p \in \mathbb{R}^d\) and distance function \(\text{dist}(\cdot,\cdot)\), the \(\varepsilon\)-neighbourhood is:

$$N_\varepsilon(p) = \{q \in D \mid \text{dist}(p, q) \le \varepsilon\}$$

where \(D\) is the dataset. With the Euclidean metric, \(N_\varepsilon(p)\) is a closed ball of radius \(\varepsilon\) centred at \(p\). Other metrics (Manhattan, cosine, Haversine for geo-data) can be substituted.

Core Point Condition

Point \(p\) is a core point if and only if:

$$|N_\varepsilon(p)| \ge \text{minPts}$$

Note: the convention varies — some implementations count \(p\) itself in \(|N_\varepsilon(p)|\) (requiring \(\ge \text{minPts}\)), while others exclude \(p\) (requiring \(\ge \text{minPts} - 1\) others). Always verify which convention is used.

Cluster Definition (Formal)

A non-empty subset \(C \subseteq D\) is a cluster w.r.t. \(\varepsilon\) and minPts if:

  • Maximality: For all \(p, q \in D\), if \(p \in C\) and \(q\) is density-reachable from \(p\), then \(q \in C\).
  • Connectivity: For all \(p, q \in C\), \(p\) and \(q\) are density-connected.

Complexity Analysis

The naive implementation queries all \(n\) points for each of the \(n\) points: \(\mathcal{O}(n^2)\) time, \(\mathcal{O}(n^2)\) space for the distance matrix. With a spatial index (k-d tree for low \(d\), ball tree otherwise), each neighbourhood query costs \(\mathcal{O}(\log n)\) on average, giving:

$$\text{Time complexity} = \mathcal{O}(n \log n) \quad \text{(with spatial index, low d)}$$
$$\text{Space complexity} = \mathcal{O}(n) \quad \text{(labels + index)}$$

In high dimensions (\(d \gg 10\)), k-d tree degrades to \(\mathcal{O}(n)\) per query, returning total cost \(\mathcal{O}(n^2)\) — the curse of dimensionality.

Parameter Sensitivity

If \(\varepsilon \to 0\): every point is noise (no neighbours). If \(\varepsilon \to \infty\): all points form one cluster. If minPts \(= 1\): every point is its own core. The heuristic \(\text{minPts} = 2d\) and the elbow of the sorted \(k\)-NN distance plot (\(k = \text{minPts} - 1\)) is the standard way to choose \(\varepsilon\).

Limitations & Key Takeaways
▼

The Core Limitation: Varying Density

DBSCAN uses a single \(\varepsilon\) for the entire dataset. If your clusters have very different densities — a tight, compact cluster next to a large, spread-out cluster — no single \(\varepsilon\) will work: too small and the sparse cluster fragments; too large and the tight cluster merges with nearby noise.

Critical Failure Mode

Consider a dense moon (spacing ~0.1) adjacent to a sparse galaxy (spacing ~0.5). Setting \(\varepsilon = 0.15\) correctly finds the moon but misses the galaxy. Setting \(\varepsilon = 0.6\) finds the galaxy but merges the moon with background noise. There is no single \(\varepsilon\) that works for both — this is DBSCAN's fundamental limitation. OPTICS and HDBSCAN address this.

When to Use DBSCAN

  • Clusters are non-convex or irregularly shaped (moons, rings, filaments)
  • The number of clusters is unknown a priori
  • Meaningful outlier detection is required
  • Data density is roughly uniform within clusters
  • Low to moderate dimensionality (\(d \le 20\))

When NOT to Use DBSCAN

  • Clusters have very different densities (use HDBSCAN or OPTICS)
  • High-dimensional data (\(d \gg 20\)) — \(\varepsilon\)-balls become meaningless
  • You need a completely deterministic assignment of border points
  • Data is a uniform distribution with no meaningful density structure
Decision Guide

Known K, spherical blobs → K-Means. Unknown K, arbitrary shapes, uniform density → DBSCAN. Unknown K, varying density → HDBSCAN. Hierarchy needed → Agglomerative. Very high-D → consider spectral or subspace clustering.

Code Trace
▼
import numpy as np
from scipy.spatial.distance import cdist
def dbscan(X, eps, min_pts):
n = len(X)
D = cdist(X, X) # pairwise distance matrix
labels = np.full(n, -1) # -1 = noise
visited = np.zeros(n, dtype=bool)
cluster_id = 0
def get_neighbors(i): # ε-neighbourhood
mask = (D[i] <= eps) & (np.arange(n) != i)
return np.where(mask)[0].tolist()
for i in range(n):
if visited[i]: continue
visited[i] = True
nbrs = get_neighbors(i)
if len(nbrs) < min_pts: # not a core → noise (for now)
labels[i] = -1
continue
labels[i] = cluster_id # start new cluster
seeds = list(nbrs) # BFS seed queue
while seeds:
q = seeds.pop(0)
if not visited[q]:
visited[q] = True
q_nbrs = get_neighbors(q)
if len(q_nbrs) >= min_pts: # q is also a core → expand
seeds.extend(q_nbrs)
if labels[q] == -1: # was noise, now border
labels[q] = cluster_id
cluster_id += 1
return labels
# sklearn one-liner (uses ball tree internally)
from sklearn.cluster import DBSCAN
db = DBSCAN(eps=0.35, min_samples=4, metric='euclidean', n_jobs=-1)
labels = db.fit_predict(X) # -1 = noise
core_mask = np.zeros_like(labels, bool)
core_mask[db.core_sample_indices_] = True
