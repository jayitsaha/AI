Convolution vs Cross-Correlation

Flip-then-slide vs slide-only — and why CNNs quietly do the latter
Foundational Signal Processing CNN O(N·M)
1
Understanding the Concept
▼

What is it? Both operations slide a small window (a "kernel" or "filter") across a longer signal and, at every position, multiply the overlapping numbers together and add them up. Cross-correlation slides the kernel exactly as written. Convolution does one extra step first: it flips the kernel back-to-front, then slides. That single flip is the entire difference between the two operations.

Analogy: Imagine dragging a small stamp of numbers along a strip of paper covered in other numbers, and at each position multiplying the numbers that line up and summing the products. Cross-correlation drags the stamp as-is — like sliding a ruler along a table to measure "how well does this pattern match right here?" Convolution turns the stamp around first (left becomes right) before dragging it — which is what happens physically when a signal echoes back, or when a system's impulse response gets "smeared" across an input.

💡 If you remember one thing

Convolution flips the kernel, correlation doesn't: $$(f * g)[n] = \sum_{m} f[m]\,g[n-m] \qquad (f \star g)[n] = \sum_{m} f[n+m]\,g[m]$$ Everything else — the sliding, the multiply-and-sum — is identical.

How It Works Internally
▼

The Sliding-Window Mechanism

Take a signal \(x\) of length \(N\) and a kernel \(h\) of length \(M\). For "valid" mode (no padding), the output has \(L = N-M+1\) samples, indexed \(n = 0, \dots, L-1\). At each \(n\), we align the kernel with the window \(x[n], x[n+1], \dots, x[n+M-1]\), multiply element-wise, and sum.

Cross-Correlation: Slide Only

Cross-correlation keeps \(h\) in its original order while sliding: \(y_{corr}[n] = \sum_{m=0}^{M-1} x[n+m]\,h[m]\). This is exactly a template match — it answers "how similar is the signal to this exact pattern, right here?" It is the operation behind matched filters and template detection.

Convolution: Flip, Then Slide

Convolution first reverses \(h\) to get \(h_{flip}[m] = h[M-1-m]\), then slides the reversed kernel the same way: \(y_{conv}[n] = \sum_{m=0}^{M-1} x[n+m]\,h_{flip}[m]\). Reversing the kernel before sliding is mathematically equivalent to the classic definition \((f*g)[n] = \sum_m f[m]g[n-m]\) — the index \(n-m\) runs backward through \(g\) as \(m\) increases, which is exactly a flip.

Numerical Trace

With \(x = [1,2,4,3,0,-1,2,3]\) and \(h = [1,0,-1]\): the flipped kernel is \(h_{flip} = [-1,0,1]\). At \(n=0\): correlation gives \(x[0]\cdot1 + x[1]\cdot0 + x[2]\cdot(-1) = 1-4=-3\); convolution gives \(x[0]\cdot(-1)+x[1]\cdot0+x[2]\cdot1 = -1+4=3\) — the exact negative, because this kernel is antisymmetric. Design Decision: Why Does Convolution Flip At All?

Convolution models physical superposition: if a linear time-invariant (LTI) system has impulse response \(h\), its output to any input \(x\) is \(y=x*h\). The flip falls directly out of the derivation (see Card 3) — it's what makes convolution commutative and associative, properties that make LTI system analysis (and the entire theory of filters, transfer functions, and the convolution theorem) work cleanly. Correlation has no such algebraic structure — it is not commutative in general.

🔑 Key Property

If the kernel is symmetric (e.g. a Gaussian blur, \(h[m]=h[M-1-m]\)), flipping does nothing — convolution and correlation coincide. This is precisely why CNNs, which almost never flip their learned filters, can call their operation "convolution" without practical consequence.

3
Why It Works — The Math
▼

Definition (Discrete, 1D)

$$(f * g)[n] = \sum_{m=-\infty}^{\infty} f[m]\,g[n-m]$$

Substitute \(k = n-m\) (so \(m = n-k\)):

$$(f*g)[n] = \sum_{k=-\infty}^{\infty} f[n-k]\,g[k] = (g*f)[n]$$

This substitution is the whole proof of commutativity: \(f*g = g*f\). Nothing about correlation gives you this for free — \((f \star g)[n] = \sum_m f[n+m]g[m]\) substituted the same way yields \((g \star f)[n] = \sum_m g[n+m]f[m] \ne f \star g\) in general; correlation only satisfies \(f \star g[n] = g \star f[-n]\) (a reversal, not equality).

Why LTI Systems Need Convolution

A linear time-invariant system is fully characterized by its response \(h\) to a unit impulse \(\delta\). Any input \(x\) can be written as a weighted sum of shifted impulses, \(x[n] = \sum_k x[k]\,\delta[n-k]\). By linearity and time-invariance, the output is the same weighted sum of shifted impulse responses:

$$y[n] = \sum_k x[k]\,h[n-k] = (x*h)[n]$$

The flip is not a cosmetic choice — it falls directly out of decomposing the input into impulses and superposing shifted responses. This is why filters, transfer functions, and the entire "convolution theorem" (\(\mathcal{F}\{f*g\} = \hat f \cdot \hat g\)) are built on convolution, not correlation.

⚠️ Common Misconception

"Deep learning convolutional layers perform convolution." They don't — they perform cross-correlation. Frameworks like PyTorch and TensorFlow never flip the kernel. It doesn't matter for learning (the network just learns the mirror-image weights it would've learned anyway), but it does matter if you ever need to interoperate with true signal-processing convolution (e.g. matching a hand-derived filter, or verifying against scipy.signal.convolve).

When to use cross-correlation: matching a known template against a signal/image (peak = best match location), computing autocorrelation to find periodicity, or any "how similar is X to Y at this offset?" question.

When to use true convolution: modeling how an LTI system (filter, room acoustics, optical blur) transforms a signal via its impulse response; anything that must satisfy \(f*g=g*f\) for downstream algebra (e.g. combining several filters into one by convolving their impulse responses in any order).

💡 The One-Line Summary

Same sliding multiply-and-sum machinery, one flip apart — correlation answers "how well does this match here?", convolution answers "what does this system do to my signal?" — and a CNN, despite its name, is doing the former.

Code Trace
▼
import numpy as np
x = np.array([1, 2, 4, 3, 0, -1, 2, 3]) # signal, N=8
h = np.array([1, 0, -1]) # kernel, M=3
def cross_correlate(x, h):
N, M = len(x), len(h)
L = N - M + 1
y = np.zeros(L)
for n in range(L):
window = x[n:n+M] # slide, no flip
y[n] = np.sum(window * h)
return y
def convolve(x, h):
h_flipped = h[::-1] # flip FIRST
return cross_correlate(x, h_flipped) # then slide
y_corr = cross_correlate(x, h) # matches np.correlate(x,h,'valid')
y_conv = convolve(x, h) # matches np.convolve(x,h,'valid')
print("correlation:", y_corr) # [-3 -1 4 4 -2 -4]
print("convolution:", y_conv) # [ 3 1 -4 -4 2 4]
# PyTorch's "Conv1d" is really cross-correlation — no flip:
import torch, torch.nn.functional as F
out = F.conv1d(torch.tensor(x[None,None,:].astype('float32')),
torch.tensor(h[None,None,:].astype('float32')))
# out == y_corr, NOT y_conv
