Counting ordered and unordered arrangements — the language of probability

Understanding Combinatorics
▼

Combinatorics is the mathematics of counting arrangements. Whenever probability says "how likely is it that…?", the denominator is usually a count of all equally likely outcomes — and combinatorics supplies that count.

Three tools cover almost every scenario you will meet:

  • Permutations \(P(n,r)\) — ordered selections (sequence matters)
  • Combinations \(C(n,r) = \binom{n}{r}\) — unordered selections (only membership matters)
  • Multinomial coefficients \(\binom{n}{k_1,\ldots,k_m}\) — distributing items into labelled groups
Real-World Analogy

Imagine picking a PIN code vs picking a lottery ticket. For a PIN, 1-2-3 is different from 3-2-1 — order matters (permutation). For a lottery, the ticket {1,2,3} is the same regardless of draw order — only the set matters (combination). Multinomial is like assigning 30 students to three project teams.

If You Remember One Thing

Permutations count ordered sequences; combinations count unordered subsets. Every combination corresponds to exactly \(r!\) permutations, so \(C(n,r) = P(n,r)/r!\).

2
Permutations vs Combinations
▼

The Multiplication Principle

Everything starts here: if task A has \(m\) outcomes and task B has \(n\) outcomes (independently), together they have \(m \times n\) outcomes. Filling \(r\) ordered slots from \(n\) distinct items (no repetition) gives \(n \times (n-1) \times \cdots \times (n-r+1)\) choices.

Permutations — When Order Matters

Select and arrange \(r\) items from \(n\) distinct items. The number of ordered arrangements is:

$$P(n,r) = \frac{n!}{(n-r)!} = n(n-1)\cdots(n-r+1)$$

Example: How many 3-letter words from {A,B,C,D,E} with no repeats? \(P(5,3) = 5 \times 4 \times 3 = 60\).

Common Confusion

\(P(n,n) = n!\) — the number of ways to arrange ALL \(n\) items. People often forget that \(P(5,5)=120\) while \(P(5,3)=60\). Only when \(r=n\) do we use the full factorial.

Combinations — When Order Doesn't Matter

Select \(r\) items from \(n\) where only the set matters — {A,B,C} = {C,B,A}. Each combination generates \(r!\) permutations, so:

$$C(n,r) = \binom{n}{r} = \frac{P(n,r)}{r!} = \frac{n!}{r!(n-r)!}$$

Example: A 5-card poker hand from a 52-card deck: \(C(52,5) = 2{,}598{,}960\).

Symmetry Identity

Choosing \(r\) items to include is the same as choosing \(n-r\) items to exclude:

$$\binom{n}{r} = \binom{n}{n-r}$$

The Mathematics
▼

Pascal's Triangle and the Recurrence

The binomial coefficients satisfy Pascal's identity — each cell equals the sum of the two cells above:

$$\binom{n}{k} = \binom{n-1}{k-1} + \binom{n-1}{k}, \quad \binom{n}{0} = \binom{n}{n} = 1$$

Proof: Label one item as "special." Either it is in our \(k\)-subset — then choose \(k-1\) from the remaining \(n-1\) — or it is not — choose \(k\) from \(n-1\).

Multinomial Coefficients

Distribute \(n\) distinct items into \(m\) labelled groups of sizes \(k_1, k_2, \ldots, k_m\) where \(\sum_i k_i = n\):

$$\binom{n}{k_1,\, k_2,\, \ldots,\, k_m} = \frac{n!}{k_1!\, k_2!\, \cdots\, k_m!}$$

Example: MISSISSIPPI has 11 letters (M×1, I×4, S×4, P×2). Distinct arrangements:

$$\frac{11!}{1!\,4!\,4!\,2!} = \frac{39{,}916{,}800}{24 \cdot 24 \cdot 2} = 34{,}650$$

Binomial Theorem (Combinatorics in Algebra)

$$(x + y)^n = \sum_{k=0}^{n} \binom{n}{k} x^k y^{n-k}$$

Setting \(x=y=1\) gives \(\sum_{k=0}^n \binom{n}{k} = 2^n\) — the total number of subsets of an \(n\)-element set.

Key Formulas

Permutations: \(P(n,r) = n!/(n-r)!\)

Combinations: \(\binom{n}{r} = n!/(r!(n-r)!)\)

Multinomial: \(n!/(k_1!\cdots k_m!)\) where \(\sum k_i = n\)

Pascal: \(\binom{n}{k} = \binom{n-1}{k-1}+\binom{n-1}{k}\)

Common Error

Forgetting that \(0! = 1\) (by convention / Gamma function). This ensures \(P(n,0)=1\) (one way to choose nothing) and \(\binom{n}{0}=1\) (one empty subset). Always check boundary cases.

ML Connections & Key Takeaways
▼

Probability Counting

Classical probability: \(P(\text{event}) = \text{favourable outcomes} / \text{total outcomes}\). Combinatorics supplies both counts. Example: probability of a 5-card flush in poker \(= 4 \times C(13,5) / C(52,5) = 5{,}148 / 2{,}598{,}960 \approx 0.00198\).

Multinomial Distribution in NLP / Cross-Entropy

When a language model predicts tokens it implicitly models a categorical/multinomial distribution. The multinomial log-likelihood for observed counts \(\mathbf{n} = (n_1,\ldots,n_m)\) under probabilities \(\mathbf{q}\) is:

$$\log P(\mathbf{n}\mid\mathbf{q}) = \log\binom{n}{n_1,\ldots,n_m} + \sum_{i=1}^{m} n_i \log q_i$$

Maximising over \(\mathbf{q}\) gives \(\hat{q}_i = n_i/n\). The term \(-\frac{1}{n}\sum n_i \log q_i\) is the categorical cross-entropy \(H(\hat{p}, q)\) that every classifier minimises.

Where Else Combinatorics Appears in ML

  • Attention masking — choosing which token pairs to attend to: \(C(n,2)\) pairs
  • Random forests — feature subset sampling at each split uses \(C(d, \lfloor\sqrt{d}\rfloor)\)
  • Bayesian priors — Dirichlet-Multinomial conjugacy for document modelling
  • Hypothesis testing — permutation tests enumerate all \(n!\) rearrangements
  • Neural architecture search — total candidate architectures = product of layer choices
Key Takeaways

1. Use permutations when sequence matters (PIN, ranking); combinations when only membership matters (team selection, hand of cards).
2. \(C(n,r) = P(n,r)/r!\) — the r! factor discards ordering.
3. Pascal's triangle gives an efficient recurrence; for large \(n,r\) use log-factorial via scipy.special.gammaln.
4. Multinomial coefficients underlie cross-entropy loss — the backbone of every classification model.

From-Scratch Code
▼

From-scratch implementations with line-by-line comments, then production-ready SciPy/itertools patterns:

import math
# ── Permutations P(n, r) ─────────────────────────────────────────────────
def permutations(n: int, r: int) -> int:
"""Number of ordered r-tuples from n distinct items (no repetition)."""
if r > n or r < 0: return 0 # guard: impossible cases
return math.factorial(n) // math.factorial(n - r) # n! / (n-r)!
# ── Combinations C(n, r) ─────────────────────────────────────────────────
def combinations(n: int, r: int) -> int:
"""Number of unordered r-subsets of n distinct items."""
if r > n or r < 0: return 0
return math.factorial(n) // (math.factorial(r) * math.factorial(n - r))
# Equivalent: math.comb(n, r) [Python 3.8+]
# ── Multinomial coefficient ──────────────────────────────────────────────
def multinomial(n: int, groups: list[int]) -> int:
"""n! / (k1! * k2! * ... * km!) — asserts sum(groups) == n."""
assert sum(groups) == n, "Group sizes must sum to n"
result = math.factorial(n)
for k in groups: # divide by each group factorial
result //= math.factorial(k)
return result
# ── Large n: use log-space to avoid overflow ──────────────────────────────
from scipy.special import gammaln
import numpy as np
def log_combinations(n, r): # log C(n,r) without overflow
return gammaln(n+1) - gammaln(r+1) - gammaln(n-r+1)
def log_multinomial(n, groups): # log of multinomial coefficient
return gammaln(n+1) - sum(gammaln(k+1) for k in groups)
# ── Production: enumerate objects ────────────────────────────────────────
from itertools import permutations as iter_perms, combinations as iter_combs
items = ['A', 'B', 'C', 'D', 'E']
all_perms = list(iter_perms(items, 3)) # 60 tuples: ('A','B','C'), ...
all_combs = list(iter_combs(items, 3)) # 10 tuples: ('A','B','C'), ...
# ── Quick checks ────────────────────────────────────────────────────────
print(permutations(5, 3)) # 60
print(combinations(5, 3)) # 10
print(multinomial(6, [2,2,2])) # 90
print(multinomial(11, [1,4,4,2])) # 34650 (MISSISSIPPI)
Production Gotchas

• For large \(n\) (e.g. \(n \geq 1000\)), use scipy.special.gammaln to compute in log-space — direct factorial overflows even 64-bit integers.

• Python's math.comb(n, r) (3.8+) and math.perm(n, r) (3.8+) are exact and fast for moderate \(n\).
