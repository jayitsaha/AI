Feature Importance from Trees

Mean Decrease in Impurity (MDI) — how decision trees attribute credit to each input feature, its bias toward high-cardinality features, and permutation importance as a less-biased alternative.

Intermediate Classical ML Decision Trees Must Know
1
Understanding Feature Importance
▶

When a decision tree learns to classify or regress, it repeatedly splits the data using the most informative features first. After training, every split records how much it reduced impurity (disorder in the data). Feature importance simply sums those reductions, weighted by how many samples flowed through each split, and normalizes the totals to sum to one.

Key Insight

A feature's importance = the total reduction in Gini (or entropy) it is responsible for, across all splits in the tree, weighted by the fraction of training samples at each split node.

Analogy. Imagine you're sorting mail by urgency. First you separate "today's deadline" from "no deadline" — that single sort resolves most ambiguity (big impurity drop). Then within each pile you refine by sender. The first sorting rule (feature) earned most of the credit; the second rule earned a smaller share. That accounting is exactly MDI.

One-sentence summary. MDI feature importance measures each feature's average contribution to making tree nodes purer, summed over all splits and normalized.

If You Remember One Thing

MDI importance = \(\sum_{\text{splits on feature } j} \frac{n_t}{n} \cdot \Delta I(t)\), normalized to sum to 1. It is fast but biased toward high-cardinality features.

2
How MDI Works Internally
▶

Step 1 — Gini Impurity at Each Node

For a node \(t\) with \(K\) classes and class probabilities \(p_k\), Gini impurity is:

$$G(t) = 1 - \sum_{k=1}^{K} p_k^2 \;=\; \sum_{k \ne k'} p_k p_{k'} $$

A pure node (all one class) has \(G = 0\); maximum disorder for binary classification gives \(G = 0.5\).

Step 2 — Impurity Decrease at a Split

When node \(t\) splits into left child \(t_L\) and right child \(t_R\), the impurity decrease is:

$$\Delta I(t) = G(t) - \frac{n_{t_L}}{n_t} G(t_L) - \frac{n_{t_R}}{n_t} G(t_R)$$

The tree greedily picks the feature and threshold that maximizes \(\Delta I(t)\) at every node.

Step 3 — Weighted Accumulation per Feature

For each feature \(j\), sum over every split node \(t\) that used \(j\):

$$\text{Imp}(j) = \sum_{t : \text{split on } j} \frac{n_t}{n} \cdot \Delta I(t)$$

The \(n_t / n\) factor (node sample fraction) weights deep splits in sparse regions less heavily.

Step 4 — Normalization

$$\hat{\text{Imp}}(j) = \frac{\text{Imp}(j)}{\sum_{j'} \text{Imp}(j')}$$

After normalization, all importances sum to exactly 1.0.

High-Cardinality Bias

A numerical feature (e.g., age with hundreds of unique values) has more possible split thresholds than a binary feature (e.g., gender). More thresholds → more chances to look good by chance → MDI systematically overestimates importance of high-cardinality features, especially on small datasets. Permutation importance does not share this bias.

3
Permutation Importance — The Less-Biased Alternative
▶

Permutation importance (Breiman 2001, refined by Fisher et al. 2019) sidesteps the cardinality problem entirely. Instead of inspecting split statistics, it asks: how much does model accuracy drop when feature \(j\)'s values are randomly shuffled?

$$\text{PI}(j) = \overline{\text{score}} - \frac{1}{K}\sum_{k=1}^{K} \text{score}\bigl(f,\, \tilde{\mathbf{X}}^{(j,k)}\bigr)$$

where \(\tilde{\mathbf{X}}^{(j,k)}\) is the dataset with column \(j\) randomly permuted in the \(k\)-th trial. Shuffling breaks the feature–target association while preserving marginal distributions.

Critical Pitfall

When two features are strongly correlated, permutation importance splits the credit between them (shuffling one is partly compensated by the other). MDI exhibits the same issue but also compounds it with cardinality bias. SHAP values (game-theoretic) are the gold standard when exact credit attribution matters.

Code Implementation
▶

From-Scratch MDI (NumPy)

# Compute MDI feature importances from a fitted sklearn DecisionTreeClassifier
# — identical logic to what sklearn does internally
import numpy as np
from sklearn.tree import DecisionTreeClassifier
 
def mdi_importance_from_scratch(tree, n_features):
"""Replicate sklearn's feature_importances_ from the tree's node data."""
t = tree.tree_
n_total = t.n_node_samples[0] # total training samples
importances = np.zeros(n_features)
 
for node_id in range(t.node_count):
# Skip leaf nodes (no split)
if t.children_left[node_id] == -1:
continue
feature_j = t.feature[node_id]
n_t = t.n_node_samples[node_id]
n_tL = t.n_node_samples[t.children_left[node_id]]
n_tR = t.n_node_samples[t.children_right[node_id]]
G_t = t.impurity[node_id]
G_tL = t.impurity[t.children_left[node_id]]
G_tR = t.impurity[t.children_right[node_id]]
 
# Weighted impurity decrease
delta = (n_t/n_total) * (G_t - (n_tL/n_t)*G_tL - (n_tR/n_t)*G_tR)
importances[feature_j] += delta
 
return importances / importances.sum() # normalize to sum=1

Production Usage (sklearn)

from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier

# MDI (fast, built-in, biased)
rf = RandomForestClassifier(n_estimators=100, random_state=42).fit(X_train, y_train)
mdi = rf.feature_importances_ # averaged MDI across all trees
 
# Permutation importance (slower, unbiased, use val set!)
pi = permutation_importance(rf, X_val, y_val, n_repeats=10, random_state=42)
perm_imp = pi.importances_mean # mean over permutation trials

# Using training data gives inflated importance for overfit features.
# ⚠️ Gotcha 2: MDI on a single tree can be noisy; average over a forest.
# ⚠️ Gotcha 3: Correlated features split importance between them (both methods).

Key Takeaways & When to Use
▶
When to Use MDI
  • Quick feature ranking during exploratory analysis
  • Features are roughly same cardinality (all continuous or all binary)
  • Dataset is large enough that split-selection noise is small
  • You need importances instantly post-training (no extra compute)
When NOT to Use MDI (Use Permutation Instead)
  • Dataset is small (< 1000 samples) — cardinality bias is severe
  • Features have very different cardinalities (mix of binary and continuous)
  • You need importance on unseen/test data
  • Regulatory requirements demand post-hoc, model-agnostic attribution

Related Topics

Decision Trees (prerequisite) • Random Forests (MDI averaged across trees) • Gradient Boosting / XGBoost (same MDI formula, gain importance) • SHAP Values (game-theoretic, handles correlations) • LIME (local, model-agnostic explanations)

Decision Rule

Exploration / fast feedback: use feature_importances_ (MDI).
Reporting / high-stakes decisions: use permutation_importance() on a validation set.
Correlated features / credit allocation: use SHAP TreeExplainer.
