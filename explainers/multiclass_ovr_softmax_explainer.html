Multi-class Classification

One-vs-Rest (OvR) & Softmax Regression — when each strategy wins
Intermediate Classical ML Logistic Regression K binary models vs 1 joint model
1
Understanding the Concept

Binary logistic regression draws one decision boundary between two classes. Real problems have many classes — recognizing 10 digits, categorising news into 20 topics, identifying 1000 ImageNet objects. Two clean strategies handle this:

  • One-vs-Rest (OvR) — train K independent binary classifiers, one per class. Classifier k asks: "is this sample class k, or anything else?" At prediction time, pick the class whose classifier fires most confidently.
  • Softmax regression (multinomial logistic) — train a single joint model that produces K scores simultaneously, then normalises them into a proper probability distribution via the softmax function.
💡 If you remember one thing
OvR runs K independent sigmoid models and takes the argmax of K independent probabilities. Softmax runs one model whose K outputs are coupled — they always sum to 1, so raising one class score automatically lowers the others.
2
How Each Strategy Works Internally

One-vs-Rest (OvR)

For K classes, train K binary logistic models. Model k has its own weight vector \(\mathbf{w}_k \in \mathbb{R}^d\) and bias \(b_k\). Each model is trained on a relabelled dataset: class k → positive (1), all others → negative (0).

$$\hat{p}_k(\mathbf{x}) = \sigma(\mathbf{w}_k^\top \mathbf{x} + b_k) = \frac{1}{1 + e^{-(\mathbf{w}_k^\top \mathbf{x} + b_k)}}$$

Prediction: \(\hat{y} = \arg\max_k \hat{p}_k(\mathbf{x})\). The K probabilities are not guaranteed to sum to 1 — they are independent sigmoid outputs.

Softmax Regression (Multinomial Logistic)

One model with weight matrix \(\mathbf{W} \in \mathbb{R}^{K \times d}\). The raw score (logit) for class k is \(z_k = \mathbf{w}_k^\top \mathbf{x} + b_k\). The softmax function converts all K logits jointly into a valid probability distribution:

$$P(y = k \mid \mathbf{x}) = \frac{\exp(z_k)}{\sum_{j=1}^{K} \exp(z_j)}$$

Prediction: \(\hat{y} = \arg\max_k z_k\) (equivalently \(\arg\max_k P(y=k|\mathbf{x})\), since softmax is monotone). The denominator \(\sum_j \exp(z_j)\) is the partition function — it couples all K outputs so they sum to exactly 1.

Key Concept — Numerical Stability
Computing \(\exp(z_k)\) can overflow for large \(z_k\). The standard fix: subtract the max logit before exponentiation. Mathematically equivalent: \(\dfrac{\exp(z_k - c)}{\sum_j \exp(z_j - c)}\) for any constant \(c\). In practice \(c = \max_j z_j\).
⚠️ Common Misconception
OvR probabilities are not calibrated relative to each other — multiple classifiers can all fire above 0.5 simultaneously, or all below 0.5. This is normal; only the argmax matters for prediction. Softmax outputs, by contrast, are always a proper probability distribution (though not necessarily well-calibrated without additional temperature scaling).
3
The Mathematics

Softmax Loss — Cross-Entropy

Softmax regression is trained by maximum likelihood. For one sample \((\mathbf{x}, y)\) with true class \(y \in \{1,\dots,K\}\):

$$\mathcal{L} = -\log P(y \mid \mathbf{x}) = -z_y + \log \sum_{j=1}^{K} \exp(z_j)$$

This is the negative log-likelihood / cross-entropy loss. The gradient w.r.t. logit \(z_k\) is elegantly:

$$\frac{\partial \mathcal{L}}{\partial z_k} = P(y = k \mid \mathbf{x}) - \mathbf{1}[y = k] = \hat{p}_k - \mathbf{1}_{k=y}$$

Predicted probability minus true label (0 or 1). This mirrors binary logistic regression's gradient exactly — a beautiful generalisation.

OvR Loss — K Independent Binary Cross-Entropies

$$\mathcal{L}_{\text{OvR}} = \sum_{k=1}^{K} \left[ -y_k \log \hat{p}_k - (1-y_k) \log(1-\hat{p}_k) \right]$$

where \(y_k = \mathbf{1}[y = k]\) is the one-hot encoding. Each term is minimised independently — no coupling between classifiers.

Decision Boundary Geometry

For OvR, the boundary between classes j and k is where \(\hat{p}_j(\mathbf{x}) = \hat{p}_k(\mathbf{x})\) — an implicit and potentially non-linear boundary in probability space. For softmax, the boundary between classes j and k is exactly where \(z_j = z_k\), i.e., \((\mathbf{w}_j - \mathbf{w}_k)^\top \mathbf{x} + (b_j - b_k) = 0\) — always a linear hyperplane. Softmax produces linear decision boundaries in input space; OvR does too (since each sigmoid is linear), but the union of OvR boundaries need not carve space cleanly.

Comparison & When to Use
DimensionOne-vs-Rest (OvR)Softmax (Multinomial)
No. of modelsK independent binary1 joint model
No. of parametersK × (d+1)K × (d+1) — same total, but shared
Output constraintUnconstrained; probs can sum ≠ 1Always sums to 1 (partition function)
Training independenceEach classifier trains on own lossAll classes trained jointly
Class couplingNone — classes don't inform each otherStrong — raising z_k lowers all others
Works with any binary clf?Yes — SVMs, trees, etc.No — requires differentiable logits
Handles class imbalancePer-classifier resampling easyClass weights in loss needed
Parallelisable trainingTrivially — K independent jobsRequires joint gradient descent
Calibrated probabilitiesNo (sigmoid per model, not normalised)Relatively better (but still not calibrated)
Preferred in deep learningRarelyAlmost always (final softmax layer)
🎯 Decision Guide
  • Use OvR when: using SVMs, decision trees, or any non-probabilistic binary base classifier; K is very large and parallel training matters; classes are highly imbalanced and per-class resampling is easier; you want interpretable per-class confidence scores independently.
  • Use Softmax when: building neural networks (softmax is the standard final layer); you need valid probability distributions (for uncertainty estimation, Bayesian inference, or as inputs to other models); mutually exclusive classes (exactly one is true — softmax enforces this); end-to-end gradient flow is required.
⚠️ OvR with SVMs — the Classic Use Case
sklearn's SVC with decision_function_shape='ovr' uses OvR because SVMs are naturally binary and have no softmax equivalent. For LogisticRegression with multi_class='ovr' vs 'multinomial' (softmax), multinomial is almost always preferred when using logistic regression specifically.
