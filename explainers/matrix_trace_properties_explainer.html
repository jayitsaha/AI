Matrix Trace

Properties, cyclic permutation, and connection to eigenvalues
Foundational Linear Algebra Math Foundations O(n) computation
1
Understanding the Trace
▼

What is it? The trace of a square matrix is simply the sum of the numbers along its main diagonal — the top-left to bottom-right line. For a 3×3 matrix, that's just three numbers added together. That's it.

Analogy: Imagine a spreadsheet where rows and columns are labeled with the same categories (say, departments). The diagonal entries are each department's interaction with itself — their "self-score." The trace is the total of all self-scores. Every other cell records cross-department interactions, which the trace completely ignores.

💡 If you remember one thing

The trace has a magical cyclic property: \(\operatorname{tr}(ABC) = \operatorname{tr}(BCA) = \operatorname{tr}(CAB)\) — you can rotate the matrices inside the trace freely. This makes it the go-to tool for simplifying matrix expressions in ML (gradients, losses, covariance identities).

🔑 Key Property

For any \(n \times n\) matrix \(A\) with eigenvalues \(\lambda_1, \ldots, \lambda_n\): $$\operatorname{tr}(A) = \sum_{i=1}^n a_{ii} = \sum_{i=1}^n \lambda_i$$ The trace equals both the diagonal sum AND the sum of all eigenvalues.

2
Properties Deep-Dive
▼

1. Definition

For \(A \in \mathbb{R}^{n \times n}\):

$$\operatorname{tr}(A) = \sum_{i=1}^{n} a_{ii} = a_{11} + a_{22} + \cdots + a_{nn}$$

2. Linearity

The trace is a linear map: \(\operatorname{tr}(A + B) = \operatorname{tr}(A) + \operatorname{tr}(B)\) and \(\operatorname{tr}(\alpha A) = \alpha \, \operatorname{tr}(A)\). This follows directly from summing the diagonal entries.

3. Transpose invariance

\(\operatorname{tr}(A^\top) = \operatorname{tr}(A)\) — transposing a matrix just reflects it across the diagonal, leaving the diagonal elements unchanged.

4. The cyclic property (trace trick)

For matrices of compatible sizes: \(\operatorname{tr}(AB) = \operatorname{tr}(BA)\), and more generally:

$$\operatorname{tr}(ABC) = \operatorname{tr}(BCA) = \operatorname{tr}(CAB)$$

Note: the cyclic permutation is valid, but arbitrary reordering is NOT. \(\operatorname{tr}(ABC) \neq \operatorname{tr}(BAC)\) in general.

5. Trace as inner product

The trace defines the Frobenius inner product of two matrices: \(\langle A, B \rangle_F = \operatorname{tr}(A^\top B) = \sum_{i,j} a_{ij} b_{ij}\). This is the matrix analogue of the dot product.

6. Relation to eigenvalues

If \(A = P \Lambda P^{-1}\) (eigendecomposition), then \(\operatorname{tr}(A) = \operatorname{tr}(P \Lambda P^{-1}) = \operatorname{tr}(\Lambda P^{-1} P) = \operatorname{tr}(\Lambda) = \sum_i \lambda_i\). This follows from the cyclic property.

⚠️ Common Misconception

Cyclic permutation does NOT extend to arbitrary reorderings. \(\operatorname{tr}(AB) = \operatorname{tr}(BA)\) but \(\operatorname{tr}(ABC) \neq \operatorname{tr}(ACB)\) in general. Only cyclic (rotational) shifts preserve the trace.

3
Why the Properties Hold — Proofs
▼

Proof: tr(AB) = tr(BA)

Let \(A \in \mathbb{R}^{m \times n}\) and \(B \in \mathbb{R}^{n \times m}\). Using index notation for matrix multiplication:

$$\operatorname{tr}(AB) = \sum_{i=1}^{m} (AB)_{ii} = \sum_{i=1}^{m} \sum_{k=1}^{n} a_{ik} b_{ki}$$
$$\operatorname{tr}(BA) = \sum_{k=1}^{n} (BA)_{kk} = \sum_{k=1}^{n} \sum_{i=1}^{m} b_{ki} a_{ik}$$

Both are the same double sum (swap the summation indices). Q.E.D.

Proof: Cyclic property tr(ABC) = tr(BCA)

Apply the pairwise result twice: \(\operatorname{tr}(ABC) = \operatorname{tr}(A \cdot BC) = \operatorname{tr}((BC) \cdot A) = \operatorname{tr}(BCA)\). Then \(\operatorname{tr}(BCA) = \operatorname{tr}(B \cdot CA) = \operatorname{tr}((CA) \cdot B) = \operatorname{tr}(CAB)\). The key is that at each step we only use the pairwise \(\operatorname{tr}(XY) = \operatorname{tr}(YX)\).

Proof: tr(A) = sum of eigenvalues

The characteristic polynomial of \(A\) is \(\det(\lambda I - A) = \prod_{i=1}^n (\lambda - \lambda_i)\). Expanding the determinant:

$$\det(\lambda I - A) = \lambda^n - \operatorname{tr}(A)\,\lambda^{n-1} + \cdots + (-1)^n \det(A)$$

Expanding the product of roots: \(\prod_{i}(\lambda - \lambda_i) = \lambda^n - (\sum_i \lambda_i)\lambda^{n-1} + \cdots\)

Matching the coefficient of \(\lambda^{n-1}\) gives \(\operatorname{tr}(A) = \sum_i \lambda_i\). For real symmetric matrices this is especially clean — all eigenvalues are real.

∑ The Trace Trick in ML

In ML, the trace trick is often used to turn a scalar expression into a traceable form: for column vector \(x\), \(x^\top A x = \operatorname{tr}(x^\top A x) = \operatorname{tr}(A x x^\top)\). This lets you move \(x\) outside when taking expectations: \(\mathbb{E}[x^\top A x] = \operatorname{tr}(A \, \mathbb{E}[xx^\top]) = \operatorname{tr}(A \Sigma)\).

5
Key Takeaways & When to Use
▼

The trace appears constantly in ML because:

  • Loss functions: Mean squared error \(\frac{1}{n}\|Y - \hat{Y}\|_F^2 = \frac{1}{n}\operatorname{tr}((Y-\hat{Y})^\top(Y-\hat{Y}))\)
  • Covariance/variance: \(\operatorname{tr}(\Sigma)\) = total variance of a random vector
  • Effective degrees of freedom: In regularized regression, \(\operatorname{tr}(H)\) where \(H\) is the hat matrix
  • Gradient of trace expressions: \(\frac{\partial}{\partial A}\operatorname{tr}(AB) = B^\top\) — used constantly in matrix calculus

The cyclic trick simplifies:

  • Quadratic forms: turn \(x^\top A x\) into \(\operatorname{tr}(Axx^\top)\)
  • Expectations through linearity: \(\mathbb{E}[\operatorname{tr}(X)] = \operatorname{tr}(\mathbb{E}[X])\)
  • Matrix gradient derivations in backprop
💡 Interview One-Liner

The trace is a linear functional on matrices satisfying \(\operatorname{tr}(AB) = \operatorname{tr}(BA)\). This one property — invariance under cyclic permutation — makes it the canonical inner product on matrix space and the bridge between matrices and their eigenvalues.

Code — From Scratch to NumPy
▼

From scratch (pure Python)

import numpy as np
def trace_scratch(A):
"""Sum diagonal elements of a square matrix."""
n = len(A) # number of rows (= cols for square matrix)
return sum(A[i][i] for i in range(n)) # accumulate a[0,0] + a[1,1] + ... + a[n-1,n-1]
A = [[5, 2, 0],
[2, 3, 1],
[0, 1, 4]]
print(trace_scratch(A)) # → 12 (= 5 + 3 + 4)
# Cyclic property verification
B = np.array([[1, 0, 2], [3, 1, 0], [0, 1, 2]])
C = np.array([[2, 1, 0], [0, 3, 1], [1, 0, 2]])
An = np.array(A)
assert np.isclose(np.trace(An @ B @ C), np.trace(B @ C @ An)) # tr(ABC) == tr(BCA)
assert np.isclose(np.trace(An @ B @ C), np.trace(C @ An @ B)) # tr(ABC) == tr(CAB)
# Eigenvalue connection
eigenvalues = np.linalg.eigvalsh(An) # eigvalsh for symmetric matrices (real eigenvalues)
print(np.sum(eigenvalues)) # → 12.0 (= tr(A), same as diagonal sum)
print(np.trace(An)) # → 12

NumPy: np.trace(A) — O(n), reads the diagonal. For the eigenvalue sum: np.linalg.eigvalsh(A).sum() — O(n³) but numerically equivalent.

⚠️ Gotcha

Use np.linalg.eigvalsh (not eigvals) for symmetric/Hermitian matrices — it guarantees real eigenvalues and is faster. eigvals may return complex numbers with tiny imaginary parts due to floating-point errors.
