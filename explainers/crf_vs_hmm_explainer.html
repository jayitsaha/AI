CRF vs HMM: Global Normalization

Why discriminative global normalization eliminates label bias — a numerical walkthrough
Advanced Classical ML · Sequence Labeling NLP · Structured Prediction
1
Understanding the Core Distinction
▼

Both HMMs and CRFs assign probabilities to label sequences \(\mathbf{y} = (y_1, \ldots, y_T)\) given observations \(\mathbf{x} = (x_1, \ldots, x_T)\). The critical difference is where and how normalization happens.

HMM — Generative, Local

Models joint \(P(\mathbf{x}, \mathbf{y})\). Each state emits an observation independently. Normalization is per-state: emission probabilities from state \(s\) sum to 1 over all possible observations. The model is generative — it could in principle generate \(\mathbf{x}\).

CRF — Discriminative, Global

Models conditional \(P(\mathbf{y} \mid \mathbf{x})\) directly. Normalization is over all possible label sequences given the full observation. The partition function \(Z(\mathbf{x})\) sums over exponentially many label sequences.

Key Insight

HMM local normalization causes label bias: states with fewer outgoing transitions absorb probability mass unfairly, biasing the Viterbi path toward low-fan-out states regardless of observation evidence. CRF global normalization has no such bias because every label sequence competes on equal footing.

In NER, POS tagging, or any sequence labeling task, this difference is decisive. A CRF can use arbitrary overlapping features of the entire input \(\mathbf{x}\) at every position, while an HMM is constrained to the generative independence assumptions.

2
Internal Mechanics: Normalization in Detail
▼

HMM: Local (Per-State) Normalization

The HMM defines a joint distribution that factors as:

$$P(\mathbf{x}, \mathbf{y}) = P(y_1) \prod_{t=2}^{T} P(y_t \mid y_{t-1}) \prod_{t=1}^{T} P(x_t \mid y_t)$$

Each factor is locally normalized:

  • \(\sum_{y'} P(y_1 = y') = 1\) — initial state probabilities sum to 1
  • \(\sum_{y'} P(y_t = y' \mid y_{t-1}) = 1\) — transition from each state sums to 1
  • \(\sum_{x'} P(x_t = x' \mid y_t) = 1\) — emission from each state sums to 1

Crucially, the emission \(P(x_t \mid y_t)\) is normalized independently per state. This is where label bias originates.

CRF: Global Normalization via Partition Function

A linear-chain CRF defines the conditional as:

$$P(\mathbf{y} \mid \mathbf{x}) = \frac{1}{Z(\mathbf{x})} \exp\!\left(\sum_{t=1}^{T} \sum_k \lambda_k f_k(y_t, y_{t-1}, \mathbf{x}, t)\right)$$

where the partition function normalizes over all \(|\mathcal{Y}|^T\) label sequences:

$$Z(\mathbf{x}) = \sum_{\mathbf{y}' \in \mathcal{Y}^T} \exp\!\left(\sum_{t=1}^{T} \sum_k \lambda_k f_k(y_t', y_{t-1}', \mathbf{x}, t)\right)$$
Label Bias — The HMM Failure Mode

Consider a state \(s\) with only one outgoing transition. Because \(\sum_{y'} P(y'|s) = 1\) and there is only one valid \(y'\), the probability mass is 1.0 regardless of the observation. The Viterbi algorithm greedily accumulates this certainty, producing a bias toward deterministic states — not because the observation supports it, but because local normalization forces it. CRF avoids this because no state's transition is normalized in isolation.

Features in CRF vs HMM

HMM emissions must satisfy \(\sum_x P(x|y) = 1\), restricting them to distributions over \(\mathbf{x}\). CRF feature functions \(f_k(y_t, y_{t-1}, \mathbf{x}, t)\) are unconstrained — they can fire on arbitrary patterns: whether the current word is capitalized AND preceded by a comma AND followed by a verb, etc.

3
Mathematical Derivation: Why Global Works
▼

HMM as a Special Case of CRF

A linear-chain CRF with only transition features \(f(y_t, y_{t-1}) = \mathbf{1}[y_t = a, y_{t-1} = b]\) and emission features \(f(y_t, \mathbf{x}, t) = \mathbf{1}[y_t = s, x_t = v]\) recovers the HMM conditionally but NOT generatively. The HMM's local normalization corresponds to constrained parameter space \(\exp(\lambda_{s \to v}) = P(x=v|y=s)\) satisfying simplex constraints per state.

Efficient Inference via Forward-Backward

Computing \(Z(\mathbf{x})\) naively requires summing \(|\mathcal{Y}|^T\) terms. The forward algorithm solves this in \(O(T |\mathcal{Y}|^2)\):

$$\alpha_t(y) = \sum_{y'} \alpha_{t-1}(y') \cdot \exp\!\left(\sum_k \lambda_k f_k(y, y', \mathbf{x}, t)\right)$$

Then \(Z(\mathbf{x}) = \sum_y \alpha_T(y)\). Log-space computation prevents underflow.

CRF Log-Likelihood Gradient

Given training pairs \(\{(\mathbf{x}^{(i)}, \mathbf{y}^{(i)})\}\), the log-likelihood is:

$$\ell(\boldsymbol{\lambda}) = \sum_i \left[\sum_{t,k} \lambda_k f_k(y_t^{(i)}, y_{t-1}^{(i)}, \mathbf{x}^{(i)}, t) - \log Z(\mathbf{x}^{(i)})\right]$$

The gradient with respect to \(\lambda_k\) is:

$$\frac{\partial \ell}{\partial \lambda_k} = \sum_i \left[\underbrace{\sum_t f_k(\cdot \mid \mathbf{y}^{(i)})}_{\text{empirical count}} - \underbrace{\mathbb{E}_{P(\mathbf{y}|\mathbf{x}^{(i)})}\!\left[\sum_t f_k\right]}_{\text{model expectation}}\right]$$

Training pushes empirical feature counts to match model expectations — a classic maximum entropy/exponential family result. The model expectation is computed via forward-backward, exactly as in HMM training but discriminatively.

Numerical Example: Partition Function

Sequence length \(T=2\), labels \(\mathcal{Y}=\{B,I\}\), single feature \(f(y_t,y_{t-1})=\mathbf{1}[y_t=I,y_{t-1}=B]\) with \(\lambda=1.5\):

Sequences: BB, BI, IB, II. Scores: \(\exp(0)=1\), \(\exp(1.5)=4.48\), \(\exp(0)=1\), \(\exp(0)=1\).

\(Z = 1 + 4.48 + 1 + 1 = 7.48\). So \(P(BI|\mathbf{x}) = 4.48/7.48 = 0.599\).

In HMM, \(P(B \to I) = 0.8\) (local) would give a different sequence probability without the global competition.

Common Misconception

"CRF is just a sequence of logistic regressions." False — independent logistic regressors per position also suffer from label bias. The CRF's global normalization ties all positions together through \(Z(\mathbf{x})\), coupling the inference across the entire sequence.

From-Scratch: Partition Function & Forward Algorithm
▼

Computing \(\log Z(\mathbf{x})\) and gradients for a linear-chain CRF:

# Linear-chain CRF forward pass — log-space for numerical stability
import numpy as np

def log_forward(log_psi):
    """Compute log forward variables for CRF.

    Args:
        log_psi: (T, Y, Y) — log potential psi[t, y_t, y_{t-1}]
                  where psi[t,j,i] = sum_k lambda_k * f_k(j, i, x, t)
    Returns:
        log_alpha: (T, Y) — log forward variables
        log_Z: scalar — log partition function
    """
    T, Y, _ = log_psi.shape
    # t=0: no previous state, use unary (psi[0, y, 0] = init potential)
    log_alpha = np.zeros((T, Y))
    log_alpha[0] = log_psi[0, :, 0]  # initial potentials

    for t in range(1, T):
        # log_alpha[t, j] = logsumexp over i of (log_alpha[t-1, i] + log_psi[t, j, i])
        scores = log_alpha[t-1, np.newaxis, :] + log_psi[t]  # (Y, Y)
        log_alpha[t] = logsumexp(scores, axis=1)              # (Y,)

    log_Z = logsumexp(log_alpha[-1])
    return log_alpha, log_Z

def logsumexp(a, axis=None):
    """Numerically stable log-sum-exp."""
    a_max = np.max(a, axis=axis, keepdims=True)
    out = np.log(np.sum(np.exp(a - a_max), axis=axis))
    return out + np.squeeze(a_max, axis=axis)

def log_backward(log_psi):
    """Compute log backward variables."""
    T, Y, _ = log_psi.shape
    log_beta = np.zeros((T, Y))  # log_beta[T-1] = log(1) = 0
    for t in range(T - 2, -1, -1):
        scores = log_beta[t+1, :, np.newaxis] + log_psi[t+1].T  # (Y, Y)
        log_beta[t] = logsumexp(scores, axis=0)
    return log_beta

def crf_gradient(log_psi, gold_y, log_alpha, log_beta, log_Z):
    """CRF gradient: empirical counts - model expected counts.

    Returns expected count matrix E[count(y_t=j, y_{t-1}=i)] under model.
    """
    T, Y, _ = log_psi.shape
    expected = np.zeros((Y, Y))
    for t in range(1, T):
        # marginal P(y_t=j, y_{t-1}=i | x)
        log_marg = (log_alpha[t-1, np.newaxis, :]
                    + log_psi[t]
                    + log_beta[t, :, np.newaxis]
                    - log_Z)  # (Y, Y)
        expected += np.exp(log_marg)

    # Empirical count
    empirical = np.zeros((Y, Y))
    for t in range(1, T):
        empirical[gold_y[t], gold_y[t-1]] += 1.0

    return empirical - expected  # gradient of log-likelihood

# HMM emission normalization (shows local constraint)
def hmm_emission_normalize(raw_counts):
    """Local normalization: each row (state) sums to 1."""
    return raw_counts / raw_counts.sum(axis=1, keepdims=True)

# CRF: NO per-state normalization constraint — features are unconstrained
def crf_score(lambdas, features):
    """Unconstrained linear combination of features."""
    return np.dot(lambdas, features)  # can be any real number
Production Usage

Use sklearn_crfsuite or pytorch-crf (torchcrf). For neural CRFs in NER: BiLSTM or BERT encoder → linear layer → CRF decoding layer. The CRF layer adds \(O(|\mathcal{Y}|^2)\) parameters (transition matrix) and uses Viterbi for inference. Hugging Face's BertForTokenClassification pairs well with torchcrf.CRF.

Use CRF When
  • Rich overlapping features matter (NER, POS, chunking)
  • You have labeled data and a discriminative loss is natural
  • Sequence accuracy is paramount over generation
  • Feature engineering over full context is needed
Use HMM When
  • Unlabeled data dominates (semi-supervised, speech)
  • Need to generate sequences (language modeling, HMM-based ASR)
  • Computational simplicity is required
  • The generative assumption holds approximately
The Bottom Line

CRFs dominate HMMs on discriminative sequence labeling tasks because global normalization eliminates label bias and allows arbitrary features. The partition function \(Z(\mathbf{x})\) is the price: it couples all positions and requires forward-backward for gradient computation. Modern NLP uses BiLSTM-CRF or BERT+CRF as the gold standard for NER precisely for these reasons.
