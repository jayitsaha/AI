Understanding BART
▼

What is it? BART (Bidirectional and Auto-Regressive Transformers) is a sequence-to-sequence model pretrained as a denoising autoencoder: take a piece of text, corrupt it with some noising function, and train the model to output the original, uncorrupted text. It fuses a BERT-style bidirectional encoder (reads the whole corrupted input at once) with a GPT-style autoregressive decoder (generates the reconstruction one token at a time).

Analogy: Imagine handing a copy editor a manuscript that has been vandalized — some words blacked out, whole sentences deleted or replaced with a single "[missing text]" stamp, paragraphs shuffled, and the opening page torn off and reattached at a random point. The editor reads the entire damaged manuscript at once (bidirectional understanding), then rewrites it from scratch, word by word, producing the original clean text (autoregressive generation).

How BART Works Internally
▼

The Five Noising Functions

BART's key experimental finding is that the choice of corruption matters enormously. The paper (Lewis et al., 2019) tests several, and mixes them freely since — unlike BERT — the encoder input and decoder output no longer need the same length:

  • Token Masking — replace individual tokens with [MASK], exactly like BERT.
  • Token Deletion — remove tokens entirely, with no placeholder. The model must decide which positions are missing, not just fill in a blank.
  • Text Infilling — sample span lengths from a Poisson\((\lambda{=}3)\) distribution and replace each entire span (including 0-length spans, i.e. pure insertions) with a single [MASK] token. This is BART's standout contribution: the model must predict how many tokens are missing from one mask, not just what they are.
  • Sentence Permutation — shuffle the order of sentences within the document randomly.
  • Document Rotation — pick a token uniformly at random and rotate the document to begin there, forcing the model to identify the true start of the document.

Architecture

BART is a standard Transformer sequence-to-sequence architecture (like the original Vaswani et al. Transformer), roughly BERT-large sized: 12 encoder layers + 12 decoder layers, GeLU activations instead of ReLU, parameters initialized from \(\mathcal{N}(0, 0.02)\). The encoder uses full bidirectional self-attention over the corrupted input; the decoder uses causal (masked) self-attention over its own generated prefix plus cross-attention over every encoder output position — identical to the classic encoder-decoder Transformer, not the encoder-only BERT or decoder-only GPT.

🔑 Design Decision: Why Text Infilling and not just Masking?

BERT's 1-to-1 masking never changes the number of tokens, so the model never has to reason about span length. Collapsing a variable-length span into a single mask forces the decoder to learn how much text is missing — a strictly harder and more generative skill that transfers directly to tasks like summarization, where output length differs from input length.

Why It Works — The Math
▼

The Denoising Objective

Let \(x\) be the original document and \(\tilde{x} = g(x)\) the corrupted version under noising function \(g\). BART maximizes the log-likelihood of reconstructing \(x\) autoregressively, conditioned on the entire corrupted sequence via the encoder:

$$\mathcal{L}_{BART}(\theta) = -\sum_{t=1}^{T}\log p_\theta\big(x_t \mid x_{

This is exactly standard cross-entropy, teacher-forced token-by-token, but the conditioning context \(\text{Encoder}(\tilde x)\) is bidirectional — every decoder step can attend to all positions of the corrupted input, not just a causal prefix of it.

BART Generalizes BERT and GPT

Restrict the noising function and architecture and you recover earlier objectives as special cases:

$$\mathcal{L}_{BERT} = -\sum_{i \in M}\log p(x_i \mid \tilde{x}), \qquad \tilde{x}=\text{mask}(x),\ \text{non-autoregressive, no decoder}$$
$$\mathcal{L}_{GPT} = -\sum_{t=1}^{T}\log p(x_t \mid x_{

BERT is the special case "mask individual tokens, predict only masked positions independently, no generation." GPT is the special case "no corruption at all, no bidirectional encoder, pure left-to-right factorization." BART sits strictly above both: arbitrary \(g\), full bidirectional encoding, full autoregressive decoding.

⚠️ Common Pitfall

Because the encoder and decoder sequence lengths can differ (a 12-token original can be corrupted to 9 tokens via infilling), you cannot naively reuse BERT's per-position classification head. BART's loss is a genuine sequence generation loss over the decoder's output distribution at each step, exactly like a translation model — length mismatch is a feature, not a bug, since it is what teaches span-length prediction.

Key Takeaways
▼

When to use BART:

  • Text generation conditioned on input text: summarization, abstractive QA, dialogue, translation (with a freshly initialized extra encoder for the source language)
  • Tasks needing both deep bidirectional understanding and free-form generation in one model
  • Classification/sequence tagging — feed the same sequence into encoder and decoder, take the final decoder hidden state as a pooled representation

When NOT to use:

  • Pure understanding tasks with no generation (e.g. simple sentence classification) — an encoder-only model like BERT/RoBERTa is cheaper and sufficient
  • Pure open-ended generation with no conditioning document — a decoder-only GPT-style model avoids the unused encoder cost
  • Extremely long documents — vanilla BART's \(O(n^2)\) attention needs long-context variants (e.g. LED/LongFormer-style sparsification) or chunking
💡 Hierarchy

BERT (mask-only, encoder-only, non-autoregressive) and GPT (no corruption, decoder-only, autoregressive) are both special cases of BART's general recipe: arbitrary noising function \(g\) + bidirectional encoder + autoregressive decoder trained end-to-end as a denoising autoencoder.

import numpy as np
# Original document (list of tokens)
x = ["The","chef","prepared","a","delicious","meal",".",
"The","guests","arrived","early","."]
# --- Noise function 1: token masking ---
def mask_tokens(x, idxs):
return [t if i not in idxs else "[MASK]" for i,t in enumerate(x)]
# --- Noise function 2: token deletion ---
def delete_tokens(x, idxs):
return [t for i,t in enumerate(x) if i not in idxs]
# --- Noise function 3: text infilling (span -> single mask) ---
def infill(x, span_start, span_len):
# span_len ~ Poisson(lambda=3); span_len=0 means a pure INSERTION
return x[:span_start] + ["[MASK]"] + x[span_start+span_len:]
# --- Noise function 4/5: permutation + rotation ---
def permute_sentences(sents): return sents[::-1] # e.g. swap order
def rotate(x, k): return x[k:] + x[:k]
# --- Seq2Seq denoising training step ---
def bart_loss(model, x, x_tilde):
enc_out = model.encoder(x_tilde) # bidirectional
dec_in = [""] + x[:-1] # teacher forcing
logits = model.decoder(dec_in, enc_out) # causal + cross-attn
logp = np.log(softmax(logits))
return -sum(logp[t, token_id(x[t])] for t in range(len(x)))
