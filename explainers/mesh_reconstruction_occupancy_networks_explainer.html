Understanding Occupancy Networks
▼

What is it? Occupancy Networks (OccNets) are a deep learning approach for 3D shape representation and reconstruction. Instead of directly predicting an explicit representation like a mesh or voxel grid, an OccNet learns a continuous function \(f_\theta(p)\) that maps any 3D point \(p = (x,y,z)\) to a scalar value between 0 and 1, representing the probability that point \(p\) is inside the object. The surface of the object is then implicitly defined as the isosurface where \(f_\theta(p) = 0.5\).

Analogy: Imagine you're blindfolded and trying to describe the shape of an apple. Instead of trying to sculpt a miniature apple (explicit mesh), you learn to answer "Am I inside or outside the apple?" for any point you touch. An Occupancy Network is like learning this "inside/outside" rule for every point in 3D space. Once you have this rule, you can trace the boundary to reconstruct the apple's surface.

💡 If you remember one thing

Occupancy Networks represent 3D shapes as a continuous implicit function: a neural network that predicts occupancy (inside/outside) for any given 3D coordinate. This allows for high-resolution, arbitrary topology mesh extraction without memory issues common with explicit voxel grids.

2
How Occupancy Networks Work
▼

The Network Architecture

An Occupancy Network is typically a simple Multi-Layer Perceptron (MLP). Its inputs are 3D coordinates \((x,y,z)\), and it outputs a single scalar value, usually passed through a sigmoid activation function to map it to \([0,1]\). Often, a latent code \(z_{latent}\) is also fed into the network, allowing a single OccNet to represent an entire class of objects (e.g., all chairs) by varying this code.

The network learns to distinguish between points that are "inside" (occupancy \(\approx 1\)) and "outside" (occupancy \(\approx 0\)) a given shape. The decision boundary, where occupancy is 0.5, defines the object's surface.

Training: Learning the Implicit Function

Training an OccNet involves sampling many 3D points. For each point \(p\), we determine its ground truth occupancy \(y\) (1 if inside, 0 if outside). These \((p, y)\) pairs form the training data. The network \(f_\theta(p)\) is then trained to predict \(y\) for each \(p\). The standard loss function is Binary Cross-Entropy (BCE):

$$ \mathcal{L} = -y \log(f_\theta(p)) - (1-y) \log(1-f_\theta(p)) $$

This loss encourages the network to output high values for points inside the object and low values for points outside. The key is that the network learns a continuous function, not just discrete labels for specific points.

Inference: Extracting a Mesh with Marching Cubes

Once trained, the OccNet can predict occupancy for any point in space. To get a mesh, we need to find the isosurface \(f_\theta(p) = 0.5\). This is typically done using the Marching Cubes algorithm:

  1. Define a dense 3D grid (like a voxel grid) covering the region of interest.
  2. For each vertex of this grid, query the trained Occupancy Network \(f_\theta(p)\) to get its occupancy value.
  3. Apply Marching Cubes: For every cube formed by 8 adjacent grid vertices, examine the occupancy values at its corners. Based on which corners are "inside" (value > 0.5) and "outside" (value \(\le\) 0.5), Marching Cubes determines how the surface passes through that cube, generating small triangles.
  4. These triangles, collected from all cubes, form the final explicit mesh.
🔑 Key Properties

Occupancy Networks offer several advantages: they represent shapes continuously (not discretely), can capture fine details at arbitrary resolution, are memory-efficient (only store network weights, not a huge voxel grid), and naturally handle arbitrary topology.

3
Why It Works — The Math
▼

Implicit Surface Definition

An implicit surface is defined by the zero-level set of a scalar function \(F(p): \mathbb{R}^3 \to \mathbb{R}\). For Occupancy Networks, the function \(f_\theta(p)\) directly predicts occupancy. We can define a signed distance function (SDF) implicitly as \(g(p) = \text{occupancy}(p) - 0.5\). Then, the surface \(\mathcal{S}\) is precisely where \(g(p) = 0\). This allows for representing complex geometries without explicit parametric equations.

Binary Cross-Entropy Loss for Training

Given a dataset \(\mathcal{D} = \{(p_k, y_k)\}_{k=1}^N\) of 3D query points \(p_k\) and their ground truth binary occupancy labels \(y_k \in \{0, 1\}\), the network parameters \(\theta\) are optimized by minimizing the Binary Cross-Entropy (BCE) loss:

$$ \mathcal{L}(\theta) = -\frac{1}{N} \sum_{k=1}^N \left[ y_k \log(f_\theta(p_k)) + (1-y_k) \log(1-f_\theta(p_k)) \right] $$

The network \(f_\theta(p)\) typically uses a sigmoid activation for its final output layer, ensuring its predictions are in \([0,1]\). During training, standard gradient descent (e.g., Adam optimizer) is used to update \(\theta\):

$$ \theta \leftarrow \theta - \eta \nabla_\theta \mathcal{L}(\theta) $$

where \(\eta\) is the learning rate. This process iteratively refines the network's ability to accurately classify points as inside or outside the object.

Marching Cubes Interpolation

When Marching Cubes determines that an edge of a grid cube is intersected by the isosurface (i.e., one vertex is inside, the other outside), it interpolates the exact intersection point. If vertices \(p_1\) and \(p_2\) have occupancy values \(v_1\) and \(v_2\), the intersection point \(p_{int}\) along the edge is given by linear interpolation:

$$ p_{int} = p_1 + (p_2 - p_1) \frac{0.5 - v_1}{v_2 - v_1} $$

This formula finds the point on the edge where the function value is exactly 0.5. This precise interpolation ensures the extracted mesh is smooth and accurately reflects the continuous function learned by the OccNet.

➗ Mathematical Advantage

The continuous nature of implicit functions means they can theoretically represent infinite detail. The resolution limit of the final mesh is determined by the density of the grid used for Marching Cubes, not by the model's capacity or memory constraints during representation.

Key Takeaways
▼

When to use Occupancy Networks:

  • High-fidelity reconstruction: When you need smooth, detailed surfaces from sparse or noisy input data (e.g., LiDAR scans, multi-view images).
  • Complex topologies: When dealing with objects that have intricate details, holes, or arbitrary genus, where explicit mesh representations might struggle with connectivity or parametrization.
  • Generative modeling: When you want to learn a latent space of shapes, allowing for interpolation between shapes or generation of novel geometries by sampling latent codes.
  • Memory efficiency at high resolution: For very detailed shapes, storing network weights is often more efficient than storing dense voxel grids.

When NOT to use:

  • Real-time mesh extraction: The Marching Cubes step, especially on very dense grids, can be computationally expensive and slow for interactive applications.
  • Guaranteed watertight meshes: While Marching Cubes generally produces watertight meshes, the quality depends on the underlying implicit function and grid resolution. Imperfections in the learned function can lead to artifacts.
  • Direct mesh editing: Occupancy networks output an implicit representation; direct manipulation of vertices or faces of the mesh requires an additional conversion step.
  • Small datasets: Like most deep learning methods, OccNets require a substantial amount of 3D data (points with occupancy labels) for effective training.
💡 Implicit vs. Explicit

Occupancy networks excel by learning an implicit representation (a function) that defines the shape. This contrasts with explicit representations like voxel grids (discrete volume) or direct mesh prediction (fixed topology), offering flexibility and resolution benefits but requiring an extra step (Marching Cubes) to get a renderable mesh.

import torch
import torch.nn as nn
import numpy as np
# from skimage.measure import marching_cubes # For 3D mesh extraction
class OccupancyNetwork(nn.Module):
def __init__(self, latent_dim=128):
super().__init__()
# Input: 3D point (x,y,z) + latent code (z_latent)
self.mlp = nn.Sequential(
nn.Linear(3 + latent_dim, 256),
nn.ReLU(),
nn.Linear(256, 256),
nn.ReLU(),
nn.Linear(256, 256),
nn.ReLU(),
nn.Linear(256, 1),
nn.Sigmoid() # Output occupancy probability [0,1]
)
def forward(self, p, z_latent):
# p: (batch_size, num_points, 3)
# z_latent: (batch_size, latent_dim)
z_latent_expanded = z_latent.unsqueeze(1).expand(-1, p.shape[1], -1)
input_features = torch.cat([p, z_latent_expanded], dim=-1)
return self.mlp(input_features)

def extract_mesh(model, z_latent_single, grid_res=64):
model.eval()
with torch.no_grad():
# Create a dense grid of query points
coords = np.linspace(-1, 1, grid_res)
x, y, z = np.meshgrid(coords, coords, coords, indexing='ij')
query_points = torch.tensor(np.stack([x, y, z], axis=-1).reshape(-1, 3)).float()
# Predict occupancy for all grid points
# Process in chunks to avoid OOM for large grids
occupancy_values = []
chunk_size = 8192
for i in range(0, query_points.shape[0], chunk_size):
chunk_points = query_points[i:i+chunk_size]
# z_latent needs to match batch size of chunk_points
z_latent_chunk = z_latent_single.unsqueeze(0).expand(chunk_points.shape[0], -1)
occ_chunk = model(chunk_points.unsqueeze(0), z_latent_chunk).squeeze().cpu().numpy()
occupancy_values.append(occ_chunk)
occupancy_field = np.concatenate(occupancy_values).reshape(grid_res, grid_res, grid_res)
# Apply Marching Cubes to extract mesh
# vertices, faces, normals, values = marching_cubes(occupancy_field, level=0.5)
