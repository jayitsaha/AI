GELU — Gaussian Error Linear Unit

The smooth, probabilistic activation that powers BERT, GPT, and Vision Transformers
Intermediate Deep Learning Transformers O(1) per element
1
Understanding GELU
▼

What is it? ReLU decides whether to pass a signal through with a hard rule: positive → keep it exactly, negative → kill it exactly (output 0). GELU replaces that hard rule with a soft, probabilistic one: it multiplies the input \(x\) by \(\Phi(x)\), the probability that a standard normal random variable is less than \(x\). Values that are "typically positive" pass through almost unchanged; values that are unusually negative get smoothly squashed toward (but not always exactly to) zero.

Analogy: Picture a bouncer who doesn't just check "over 18, yes/no." Instead, the more clearly your ID says you're an adult, the more fully you're waved through; borderline cases get partial access; clearly-underage cases get turned away — but gradually, not with a slammed door. That gradual, probability-weighted admission is exactly what \(x \cdot \Phi(x)\) computes.

💡 If you remember one thing

GELU multiplies the input by the probability it would be "kept" under a standard Gaussian gate: $$\text{GELU}(x) = x\cdot\Phi(x)$$ It is smooth everywhere, non-monotonic near zero (dips to about −0.17), and is the default activation in BERT, GPT-2/3, and Vision Transformer feed-forward layers.

How GELU Works Internally
▼

Where It Lives

Every transformer block has a feed-forward sublayer applied to each token independently: \(\text{FFN}(x) = \text{GELU}(xW_1+b_1)\,W_2 + b_2\). The original 2017 Transformer used ReLU here; BERT (2018) swapped in GELU and it became the default for encoder/decoder LLMs.

The Stochastic-Gate Origin

Hendrycks & Gimpel (2016) imagined multiplying \(x\) by a random 0/1 mask \(m \sim \text{Bernoulli}(\Phi(x))\) — the more positive \(x\) is, the more likely the mask keeps it. GELU is the expectation of that stochastic process, making it a deterministic, differentiable function usable in ordinary backprop:

$$\text{GELU}(x) = \mathbb{E}_m[m\,x] = \Phi(x)\cdot x$$

Why the Negative Dip Matters

Because \(\Phi(x)\) is never exactly 0 for finite \(x\), a small negative signal survives even for negative inputs — unlike ReLU, which zeroes the gradient completely. This is what keeps GELU non-monotonic: the function bottoms out near \(x\approx -0.75\) at \(\approx -0.17\) before climbing back to 0, so "dying neuron" behavior is far less common than with ReLU.

🔑 Key Property

GELU is smooth (C∞) and non-monotonic, asymptotically matching ReLU for large \(|x|\): as \(x\to+\infty\), \(\text{GELU}(x)\to x\); as \(x\to-\infty\), \(\text{GELU}(x)\to 0\).

3
Why It Works — The Math
▼

Definition

$$\text{GELU}(x) = x\,\Phi(x) = x\cdot\frac{1}{2}\left[1+\operatorname{erf}\!\left(\frac{x}{\sqrt2}\right)\right]$$

The Gradient

Differentiating with the product rule, using \(\Phi'(x)=\varphi(x)\) (the standard normal PDF):

$$\text{GELU}'(x) = \Phi(x) + x\,\varphi(x), \qquad \varphi(x)=\frac{1}{\sqrt{2\pi}}e^{-x^2/2}$$

At \(x=0\): gradient \(=0.5\). At \(x=1\): gradient \(\approx 1.083\) (briefly exceeds 1). At \(x=-1\): gradient \(\approx -0.083\) (briefly negative — this is exactly what produces the non-monotonic dip).

The Fast tanh Approximation

Exact \(\operatorname{erf}\) is costly at scale, so production kernels (GPT-2, many HF configs as "gelu_new") use:

$$\text{GELU}(x)\approx 0.5\,x\Big(1+\tanh\big[\sqrt{2/\pi}\,(x+0.044715\,x^3)\big]\Big)$$
⚠️ Common Pitfall

GELU is not monotonic like ReLU, Swish, or ELU — it dips below zero for \(x\) roughly in \((-3,0)\), bottoming at \(\approx -0.17\). Also, the exact (erf) and tanh-approximate forms differ by up to \(\sim 10^{-3}\) — always match the variant a checkpoint was pretrained with.

Key Takeaways
▼

Summary: GELU(x) = x·Φ(x) is a smooth, non-monotonic activation that arises as the expectation of a Gaussian-probability stochastic gate. It avoids ReLU's dead-neuron problem while asymptotically behaving like ReLU for large |x|.

When to use: Default choice for transformer feed-forward sublayers (BERT, GPT-2/3, ViT). For latency-critical edge inference, plain ReLU is cheaper; for state-of-the-art LLM pretraining from scratch, gated variants like SwiGLU/GEGLU often outperform plain GELU.
