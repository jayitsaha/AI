Kernel Selection & Hyperparameter Tuning in SVMs

How to choose the right kernel, tune \(C\) and \(\gamma\), and use cross-validation to avoid under- and over-fitting

Advanced Classical ML · SVM Part III
1
Understanding the Concept
›

A Support Vector Machine finds the widest possible margin between two classes in some feature space. The trick is that the feature space itself is determined by your kernel — a function \(K(\mathbf{x}_i, \mathbf{x}_j)\) that implicitly measures similarity between data points after (potentially infinite-dimensional) transformation.

Analogy
Imagine trying to separate red and blue marbles on a table. If they are linearly separable you just slide a ruler between them. If they are mixed, you lift some marbles up (project into 3-D) until a flat plane can divide them. The kernel tells you how to do the lifting — and two knobs, \(C\) and \(\gamma\), control how much you allow marbles to land on the wrong side versus how local your "lifting" is.

Two hyperparameters dominate SVM performance:

  • \(C\) (regularization / margin softness) — large \(C\) demands few or no misclassifications (hard margin, risk of overfitting); small \(C\) allows more violations in exchange for a wider margin (soft margin, risk of underfitting).
  • \(\gamma\) (RBF locality) — large \(\gamma\) makes each training point's influence extremely local (wiggly, overfit boundary); small \(\gamma\) makes influence global (smooth, possibly underfit boundary).
Key Insight
The best \((C, \gamma)\) pair lies where bias and variance are balanced. The only principled way to find it is k-fold cross-validation over a grid or random search — never tune on the test set.
2
How It Works Internally
›

The SVM primal with soft margin solves:

$$\min_{\mathbf{w},b,\boldsymbol{\xi}} \frac{1}{2}\|\mathbf{w}\|^2 + C\sum_{i=1}^n \xi_i \quad \text{s.t.}\; y_i(\mathbf{w}^\top\phi(\mathbf{x}_i)+b)\ge 1-\xi_i,\; \xi_i\ge0$$

Via Lagrangian duality this reduces to the dual, which is what solvers actually optimise:

$$\max_{\boldsymbol{\alpha}} \sum_{i=1}^n \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_i y_j K(\mathbf{x}_i,\mathbf{x}_j) \quad \text{s.t.}\; 0\le\alpha_i\le C,\;\sum_i\alpha_i y_i=0$$

The kernel \(K(\mathbf{x}_i,\mathbf{x}_j)=\phi(\mathbf{x}_i)^\top\phi(\mathbf{x}_j)\) replaces dot products, so we never compute \(\phi\) explicitly (the kernel trick).

Common kernels and when to prefer them:

KernelFormulaBest When
Linear\(K = \mathbf{x}_i^\top\mathbf{x}_j\)High-dimensional, sparse (text, genomics)
RBF / Gaussian\(K = e^{-\gamma\|\mathbf{x}_i-\mathbf{x}_j\|^2}\)Low–medium dim, unknown structure (default)
Polynomial\(K = (\mathbf{x}_i^\top\mathbf{x}_j + r)^d\)Image pixels, structured interactions
Sigmoid\(K = \tanh(\kappa\,\mathbf{x}_i^\top\mathbf{x}_j+\theta)\)Rarely: behaves poorly unless carefully tuned

After solving, the decision function is:

$$f(\mathbf{x}) = \text{sign}\!\left(\sum_{i\in\text{SV}}\alpha_i y_i K(\mathbf{x}_i,\mathbf{x}) + b\right)$$
Common Mistake
Tuning \(\gamma\) and \(C\) on the same data used for evaluation (data leakage). Always use a held-out validation fold or nested cross-validation.
3
The Math: C, γ, and the Bias–Variance Trade-off
›

The RBF kernel is \(K(\mathbf{x},\mathbf{z}) = \exp(-\gamma\|\mathbf{x}-\mathbf{z}\|^2)\). Taylor-expanding \(e^{-\gamma\|d\|^2}\) shows this corresponds to a dot product in an infinite-dimensional RKHS. As \(\gamma\to\infty\), \(K\to\delta(\mathbf{x}-\mathbf{z})\) (neighbourhood shrinks to a point). As \(\gamma\to0\), \(K\to1\) (all points are equally similar).

Effect of \(\gamma\) on the margin boundary:

  • Large \(\gamma\): each support vector has narrow Gaussian influence. Boundary becomes highly local, can memorise noise → overfitting.
  • Small \(\gamma\): influence is broad, decision surface is nearly linear → underfitting.

Effect of \(C\) (the slack penalty):

  • Large \(C\): \(\xi_i\approx0\) enforced, hard margin, sensitive to outliers → overfitting.
  • Small \(C\): many points can lie inside or on the wrong side of the margin, wide but impure margin → underfitting.

Cross-Validation Objective

For a grid of \((C, \gamma)\) values, we minimise the \(k\)-fold CV error:

$$\mathcal{E}_{CV}(C,\gamma) = \frac{1}{k}\sum_{j=1}^k \mathcal{L}\!\left(f_{-j}^{(C,\gamma)}, \mathcal{D}_j\right)$$

where \(f_{-j}^{(C,\gamma)}\) is the SVM trained on all folds except fold \(j\), and \(\mathcal{D}_j\) is the held-out fold. We pick \((C^*,\gamma^*) = \arg\min_{C,\gamma}\mathcal{E}_{CV}(C,\gamma)\).

Typical search ranges: \(C \in \{10^{-3},10^{-2},\ldots,10^3\}\), \(\gamma \in \{10^{-4},\ldots,10^1\}\) on a log scale.

Heuristic Starting Point
sklearn's default \(\gamma = 1/(n\_features \cdot \text{Var}(X))\) (i.e., "scale") is a reasonable first guess. Combine with \(C=1\) and refine via CV.

From-Scratch Grid Search + Cross-Validation
›

The annotated code below shows the exact steps for an SVM grid search with 5-fold CV. Click Next above to step through how each scenario maps to these lines.

import numpy as np
from sklearn.svm import SVC
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.preprocessing import StandardScaler
# Always scale before SVM — RBF kernel is distance-based
scaler = StandardScaler().fit(X_train)
X_s = scaler.transform(X_train)
param_grid = {
'C': [1e-2, 1e-1, 1, 1e1, 1e2, 1e3],
'gamma': [1e-3, 1e-2, 1e-1, 1, 1e1],
}
best_score, best_params = 0, {}
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
for C in param_grid['C']:
for gamma in param_grid['gamma']:
svm = SVC(kernel='rbf', C=C, gamma=gamma)
scores = cross_val_score(svm, X_s, y_train, cv=cv, scoring='accuracy')
mean_acc = scores.mean() # average over 5 folds
if mean_acc > best_score:
best_score = mean_acc
best_params = {'C': C, 'gamma': gamma}
# Retrain on full training set with best params
final_svm = SVC(kernel='rbf', **best_params).fit(X_s, y_train)
Gotcha: Data Leakage
If you scale using all data (including test), statistics from test leak into training. Always fit the scaler on training folds only, then transform validation/test.

Key Takeaways & Decision Guide
›
SymptomLikely CauseFix
Train acc ≫ Val accOverfit: \(C\) too large and/or \(\gamma\) too largeDecrease \(C\), decrease \(\gamma\)
Both train & val acc lowUnderfit: wrong kernel or \(C/\gamma\) too smallIncrease \(C\), increase \(\gamma\), try RBF if using linear
Training is very slow\(n\) large; quadratic SVM doesn't scaleUse LinearSVC (primal SGD) for \(n>50\text{k}\)
Accuracy plateaus despite grid searchFeature scale mismatch or wrong kernelNormalise features; try polynomial kernel
Rule of Thumb
Start with RBF kernel. Set \(\gamma=\text{"scale"}\) (sklearn default). Grid-search \(C \in [10^{-1}, 10^3]\) with 5-fold stratified CV. After finding a good region, zoom in with a finer log grid around the optimum.
  • For text: use linear kernel (high-dim sparse features are already "non-linear enough").
  • For small tabular data with unknown structure: RBF is the best default.
  • When \(n \gg d\) and classes overlap heavily: try polynomial degree 2–3.
