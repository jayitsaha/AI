GRU: Update Gate, Reset Gate & Comparison with LSTM

A leaner gated recurrent unit — two gates, one state, (almost) LSTM's power
Intermediate Deep Learning Sequence Models O(n) per step
1
Understanding the GRU
▼

What is it? The Gated Recurrent Unit (GRU), introduced by Cho et al. (2014) for neural machine translation, is a recurrent cell that decides, at every timestep, how much of its memory to keep and how much to overwrite with new information — using only two learned gates and a single hidden state \(h_t\). It was designed as a lighter alternative to the LSTM, which uses three gates and two states (a hidden state and a separate cell state).

Analogy: Picture a whiteboard you reuse every day (the hidden state). Before writing today's notes, you ask two questions. First, the reset gate: "how much of yesterday's notes should I even glance at while drafting today's entry?" Second, the update gate: "once I've drafted today's entry, how much of the whiteboard should I actually overwrite versus leave untouched?" A reset gate near 0 means "start the draft fresh, ignore history"; an update gate near 0 means "don't erase anything — my old notes are still the best summary."

💡 If you remember one thing

The GRU's final step is a convex interpolation: $$h_t = (1-z_t)\odot h_{t-1} + z_t \odot \tilde h_t$$ The update gate \(z_t\) is a per-dimension knob between "keep the past exactly" (\(z_t=0\)) and "fully overwrite with the new candidate" (\(z_t=1\)). That additive, gate-controlled path is precisely what lets gradients survive long sequences.

How the GRU Works Internally
▼

The Reset Gate — "How much of the past matters for my new idea?"

\(r_t = \sigma(W_r x_t + U_r h_{t-1} + b_r)\). The reset gate is applied elementwise to \(h_{t-1}\) before it is used to compute the candidate state. When \(r_t \approx 0\) for some dimension, the candidate computation effectively drops that part of history and treats the timestep as if it were starting fresh — useful right after sentence or topic boundaries. When \(r_t \approx 1\), the full history flows into the candidate.

The Update Gate — "How much do I overwrite?"

\(z_t = \sigma(W_z x_t + U_z h_{t-1} + b_z)\). This gate is computed independently of the reset gate (it also looks at \(x_t\) and \(h_{t-1}\), but with its own weights) and controls the final blend between old and new state. It plays the combined role of an LSTM's forget gate and input gate — GRU hard-codes the coupling \(i_t = 1-f_t\) that LSTMs often learn anyway in practice.

The Candidate State

\(\tilde h_t = \tanh(W_h x_t + U_h(r_t \odot h_{t-1}) + b_h)\) — a proposed new memory content, computed from the current input and the reset-gated history.

Design Decision: Why fuse forget + input, and why drop the cell state?

Greff et al. (2015, "LSTM: A Search Space Odyssey") and Jozefowicz et al. (2015) ran large architecture searches over gated-RNN variants and found that (a) coupling forget/input gates rarely hurts performance, and (b) removing the output gate and separate cell state rarely hurts either. GRU commits to both simplifications: one interpolation gate instead of two, and the hidden state itself carries memory instead of a protected cell state \(c_t\). The payoff is ~25% fewer parameters and faster training per step; the cost is slightly less independent control — a GRU cannot simultaneously "forget everything" and "write nothing," while an LSTM can.

🔑 Key Property

Every internal state in a GRU is fully exposed at every step — there is no hidden cell state shielded by an output gate. What you read out (\(h_t\)) is exactly what gets passed to the next timestep and to any downstream layer.

3
Why It Works — The Math
▼

The Full Recurrence

$$r_t=\sigma(W_rx_t+U_rh_{t-1}+b_r)\qquad z_t=\sigma(W_zx_t+U_zh_{t-1}+b_z)$$
$$\tilde h_t=\tanh\big(W_hx_t+U_h(r_t\odot h_{t-1})+b_h\big)\qquad h_t=(1-z_t)\odot h_{t-1}+z_t\odot \tilde h_t$$

Gradient Flow Across Time

Differentiating the combine step with respect to \(h_{t-1}\) (treating \(z_t\) and \(\tilde h_t\) as functions of \(h_{t-1}\) too, by the product rule):

$$\frac{\partial h_t}{\partial h_{t-1}} = \underbrace{\operatorname{diag}(1-z_t)}_{\text{additive highway}} \;+\; \underbrace{(\tilde h_t - h_{t-1})\frac{\partial z_t}{\partial h_{t-1}} + \operatorname{diag}(z_t)\frac{\partial \tilde h_t}{\partial h_{t-1}}}_{\text{gated, bounded correction terms}}$$

The dominant term \(\operatorname{diag}(1-z_t)\) is what matters: if the update gate learns to sit near 0 for a given dimension across many steps, the Jacobian of that path is close to the identity, so a gradient backpropagating through \(T\) steps is multiplied by numbers close to 1 rather than by \(\operatorname{diag}(1-\tanh^2(\cdot))W^\top\) at every step, as in a vanilla RNN. That plain-RNN Jacobian typically has spectral norm \(<1\), so gradients shrink geometrically in \(T\) — the classic vanishing-gradient result of Hochreiter (1991) and Bengio et al. (1994). The GRU's additive path is structurally identical in spirit to the LSTM's \(c_t = f_t\odot c_{t-1}+i_t\odot g_t\) constant-error path.

⚠️ Common Misconception

"GRUs solve the vanishing gradient problem." They don't solve it — they give the optimizer a learnable shortcut to mitigate it. If the update gate saturates near 1 (full overwrite every step) the additive highway disappears and the GRU degenerates toward vanilla-RNN-like gradient decay. Long-range memory is a property the network can learn to exploit, not a guarantee baked into the architecture.

GRU vs LSTM — Key Takeaways
▼
GRULSTM
Gates2 (reset, update)3 (forget, input, output)
State carried forward1 vector, \(h_t\) (fully exposed)2 vectors, \(c_t\) (protected) and \(h_t\) (exposed)
Memory-write mechanismCoupled interpolation \((1-z_t)/z_t\)Independent forget \(f_t\) and input \(i_t\)
Parameters (per gate ~ same size)~25% fewerBaseline (more)
Training speed / stepFasterSlower
ExpressivenessSlightly less independent controlCan forget and write independently
Typical empirical gapSmall and task-dependent — many papers report near-parity (Chung et al. 2014, Jozefowicz et al. 2015)

When to prefer GRU: smaller datasets, tighter compute/latency budgets, shorter-to-medium sequences, or as a fast baseline before trying an LSTM/Transformer.

When to prefer LSTM: tasks where empirically the extra gate helps (some language modeling / very long-range benchmarks), or when you need the cell state's stronger "protect this memory no matter what" guarantee via an explicit output gate.

💡 Hierarchy of Recurrent Cells

Vanilla RNN (no gates, pure multiplicative recurrence) → GRU (2 gates, 1 additive highway) → LSTM (3 gates, 1 additive highway + protected cell state). Each step adds a learnable mechanism to fight vanishing gradients, at the cost of more parameters and compute. Since ~2017, both are increasingly displaced by Transformers for very long sequences, but GRUs/LSTMs remain strong choices for streaming, low-latency, and small-data sequence tasks.

Code Trace — GRU Cell From Scratch
▼
import numpy as np
sigmoid = lambda v: 1 / (1 + np.exp(-v))
def gru_cell(x_t, h_prev, params):
Wr, Ur, br = params['Wr'], params['Ur'], params['br']
Wz, Uz, bz = params['Wz'], params['Uz'], params['bz']
Wh, Uh, bh = params['Wh'], params['Uh'], params['bh']
# reset gate: how much of h_prev to expose to the candidate
r_t = sigmoid(Wr @ x_t + Ur @ h_prev + br)
# update gate: interpolation weight between h_prev and candidate
z_t = sigmoid(Wz @ x_t + Uz @ h_prev + bz)
# candidate hidden state, built from reset-gated history
h_candidate = np.tanh(Wh @ x_t + Uh @ (r_t * h_prev) + bh)
# final state: convex combination controlled by z_t
h_t = (1 - z_t) * h_prev + z_t * h_candidate
return h_t, r_t, z_t, h_candidate
# Parameter count: 3 gates x (n_h*n_x + n_h*n_h + n_h)
def gru_param_count(n_x, n_h):
return 3 * (n_h * n_x + n_h * n_h + n_h)
# LSTM has 4 gates instead of 3 -> ~33% more parameters
def lstm_param_count(n_x, n_h):
return 4 * (n_h * n_x + n_h * n_h + n_h)
