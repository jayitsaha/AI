Understanding the Kernel Trick
▼

What is it? Support Vector Machines find a straight line (or hyperplane) that separates two classes. But many real problems are not linearly separable — imagine data arranged in concentric circles. The naive fix is to add new features (like \(r^2 = x_1^2 + x_2^2\)) that "lift" the data into a higher-dimensional space where it becomes separable. The kernel trick lets you do this lifting without ever actually computing the new features.

Analogy: Two tangled necklaces on a table look impossible to separate. But if you pick one up (add a third dimension), they come apart easily. The kernel trick is the mathematical equivalent — it picks up the data into a higher dimension where a flat cut separates it — but, crucially, uses a shortcut formula so you never need to describe the new 3D coordinates explicitly.

💡 If you remember one thing

Everywhere an SVM uses an inner product \(\mathbf{x}^\top \mathbf{x}'\), replace it with \(K(\mathbf{x},\mathbf{x}') = \langle\phi(\mathbf{x}),\phi(\mathbf{x}')\rangle\). The kernel function computes this inner product in feature space implicitly — sometimes in infinite-dimensional spaces — at the cost of a scalar evaluation. This is the kernel trick.

How It Works — The Four Kernels
▼

The SVM Dual and Why Inner Products Are Enough

The SVM optimization in dual form only ever touches training points through inner products \(\mathbf{x}_i^\top \mathbf{x}_j\). The decision function is \(f(\mathbf{x}) = \sum_i \alpha_i y_i \, K(\mathbf{x}_i, \mathbf{x}) + b\), and optimization depends only on the \(n \times n\) kernel (Gram) matrix \(\mathbf{K}_{ij} = K(\mathbf{x}_i, \mathbf{x}_j)\). Replace the inner product with any valid kernel, and you implicitly work in the induced feature space — without ever computing \(\phi(\mathbf{x})\).

The Four Major Kernels

KernelFormulaFeature SpaceKey Parameter
Linear \(K(\mathbf{x},\mathbf{x}') = \mathbf{x}^\top \mathbf{x}'\) Input space (no lift) None
Polynomial (degree d) \(K(\mathbf{x},\mathbf{x}') = (\mathbf{x}^\top \mathbf{x}' + c)^d\) \(\mathcal{O}(n^d)\) dimensions \(d\) (degree), \(c \ge 0\) (bias)
RBF / Gaussian \(K(\mathbf{x},\mathbf{x}') = \exp\!\left(-\gamma\|\mathbf{x}-\mathbf{x}'\|^2\right)\) Infinite dimensions \(\gamma > 0\) (locality / bandwidth)
Sigmoid \(K(\mathbf{x},\mathbf{x}') = \tanh(\alpha\,\mathbf{x}^\top\mathbf{x}' + c)\) Neural-network-like \(\alpha, c\) (not always PSD)
String kernel Counts shared subsequences of length \(k\) Subsequence feature space \(k\) (subsequence length)

RBF Gamma Controls Locality

With \(\gamma\) large, \(\exp(-\gamma\|\mathbf{x}-\mathbf{x}'\|^2)\) decays steeply — the kernel is near zero for points more than a tiny distance apart. Each training point influences only a small neighbourhood, creating a spiky, overfit decision boundary. With \(\gamma\) small, the kernel is broad and smooth, leading to a simple boundary resembling linear separation.

🔑 Mercer's Theorem

A symmetric function \(K(\mathbf{x},\mathbf{x}')\) is a valid kernel if and only if the Gram matrix \(K_{ij} = K(\mathbf{x}_i, \mathbf{x}_j)\) is positive semi-definite for all finite sets of points. This guarantees a corresponding feature map \(\phi\) exists (possibly in an RKHS), so the SVM dual is convex. The sigmoid kernel fails this for some parameter values.

Polynomial Kernel — Explicit Feature Map

For \(d=2, c=1\), input \(\mathbf{x} = (x_1, x_2)^\top\): the corresponding feature map is

$$\phi(\mathbf{x}) = \bigl(1,\;\sqrt{2}\,x_1,\;\sqrt{2}\,x_2,\;x_1^2,\;\sqrt{2}\,x_1 x_2,\;x_2^2\bigr)^\top$$

Verification: \(\phi(\mathbf{x})^\top\phi(\mathbf{x}') = 1 + 2x_1x_1' + 2x_2x_2' + x_1^2{x_1'}^2 + 2x_1x_2x_1'x_2' + x_2^2{x_2'}^2 = (\mathbf{x}^\top\mathbf{x}' + 1)^2\). For general \(d\), the feature space has \(\binom{n+d}{d}\) dimensions — computing it explicitly is prohibitive, but the kernel evaluates it in \(\mathcal{O}(n)\).

RBF — Why Infinite Dimensions?

Expanding via Taylor series: \(\exp(-\gamma\|\mathbf{x}\|^2) \exp(-\gamma\|\mathbf{x}'\|^2) \sum_{k=0}^\infty \frac{(2\gamma\,\mathbf{x}^\top\mathbf{x}')^k}{k!}\). Each term corresponds to a polynomial feature of degree \(k\). The RBF kernel implicitly sums over all polynomial degrees — an infinite-dimensional space. Yet evaluating \(K(\mathbf{x},\mathbf{x}')\) is a single exponential computation.

⚠️ Common Mistake

sklearn's SVC uses gamma='scale' by default (= \(1/(n\_features \cdot \text{Var}(X))\)). Using gamma='auto' (= \(1/n\_features\)) ignores variance and can badly over- or under-smooth. Always scale features before using RBF.

3
Why It Works — The Math
▼

SVM Dual Form — Where the Trick Lives

The primal SVM minimizes \(\frac{1}{2}\|\mathbf{w}\|^2\) subject to \(y_i(\mathbf{w}^\top\phi(\mathbf{x}_i) + b) \ge 1\). The Lagrangian dual (by KKT conditions) is:

$$\max_{\boldsymbol{\alpha}} \sum_{i=1}^n \alpha_i - \frac{1}{2}\sum_{i,j} \alpha_i \alpha_j y_i y_j \underbrace{\phi(\mathbf{x}_i)^\top \phi(\mathbf{x}_j)}_{K(\mathbf{x}_i,\,\mathbf{x}_j)}, \quad \alpha_i \ge 0$$

The feature map \(\phi\) appears only inside the inner product. Replace that inner product with any Mercer kernel \(K\), and you solve the same convex problem in the implicit feature space. The weight vector \(\mathbf{w}\) in feature space need never be materialized.

Decision Function

The classifier assigns label \(\text{sign}(f(\mathbf{x}))\) where:

$$f(\mathbf{x}) = \sum_{i \in \text{SVs}} \alpha_i y_i K(\mathbf{x}_i, \mathbf{x}) + b$$

Only support vectors (points with \(\alpha_i > 0\)) contribute. In the RBF case, each support vector acts as a "bump function" centred on \(\mathbf{x}_i\); their weighted sum traces the decision boundary.

Representer Theorem

For any loss function plus regularisation in an RKHS, the optimal solution has the form \(f^* = \sum_i \alpha_i K(\mathbf{x}_i, \cdot)\). This guarantees that even though the RKHS may be infinite-dimensional, the solution is parameterised by at most \(n\) coefficients — making computation tractable.

∑ Key Formula Chain

\(K(\mathbf{x},\mathbf{x}') = \langle\phi(\mathbf{x}),\phi(\mathbf{x}')\rangle_\mathcal{H}\) — kernel = inner product in RKHS
\(\mathbf{K}_{ij} = K(\mathbf{x}_i,\mathbf{x}_j)\) — Gram matrix, \(n \times n\), must be PSD
Polynomial: \(K_{\text{poly}}(\mathbf{x},\mathbf{x}') = (\mathbf{x}^\top\mathbf{x}' + c)^d\),   \(d\in\mathbb{Z}^+\)
RBF: \(K_{\text{RBF}}(\mathbf{x},\mathbf{x}') = \exp\!\bigl(-\gamma\|\mathbf{x}-\mathbf{x}'\|^2\bigr)\),   \(\gamma > 0\)
Complexity: kernel matrix in \(\mathcal{O}(n^2 p)\), SVM solve in \(\mathcal{O}(n^2)\) to \(\mathcal{O}(n^3)\)

Proof that RBF is PSD

Write \(\|\mathbf{x}-\mathbf{x}'\|^2 = \|\mathbf{x}\|^2 - 2\mathbf{x}^\top\mathbf{x}' + \|\mathbf{x}'\|^2\). So \(K_\text{RBF}(\mathbf{x},\mathbf{x}') = e^{-\gamma\|\mathbf{x}\|^2}\cdot e^{2\gamma\mathbf{x}^\top\mathbf{x}'}\cdot e^{-\gamma\|\mathbf{x}'\|^2}\). The middle factor is a positive combination of polynomial kernels (via Taylor expansion), each PSD. Positive combinations of PSD kernels are PSD. Scaling by positive functions preserves PSD. Hence \(K_\text{RBF}\) is PSD. ∎

⚠️ String Kernels Note

String kernels count shared subsequences between two strings, so \(\phi(\mathbf{x})\) indexes all possible subsequences of length \(\le k\) — a combinatorially large space. The kernel can still be computed in \(\mathcal{O}(k|s||t|)\) via dynamic programming. These kernels are valid Mercer kernels and power text classification, protein homology detection, and bioinformatics tasks.

Key Takeaways & When to Use Which Kernel
▼
ConditionRecommended KernelWhy
Linearly separable dataLinearNo lift needed; fastest, most interpretable
Known polynomial structurePolynomial (degree d)Explicitly captures degree-d interactions
Unknown structure, tabularRBF (default)Universal approximator; single \(\gamma\) to tune
Text / sequencesString kernel or bag-of-words linearOperates on discrete, variable-length inputs
Very large \(n\) (>100k)Linear or approx. RBF (RFF)Kernel matrix \(\mathcal{O}(n^2)\) becomes memory-prohibitive
💡 The Kernel Hierarchy

Linear ⊂ Polynomial (d=1) ⊂ Polynomial (any d) ⊂ RBF (as \(d\to\infty\)). RBF is the most flexible but also the most prone to overfitting — balance with the SVM \(C\) regularisation parameter. Rule of thumb: try RBF with cross-validated \(C\) and \(\gamma\) first; use linear SVM for text or very high-dimensional inputs.

Random Fourier Features (RFF): For large \(n\), approximate the RBF kernel by explicitly sampling a low-dimensional random feature map \(z(\mathbf{x})\) such that \(\mathbb{E}[z(\mathbf{x})^\top z(\mathbf{x}')] \approx K_{\text{RBF}}(\mathbf{x},\mathbf{x}')\). This reduces per-sample cost from \(\mathcal{O}(n)\) to \(\mathcal{O}(D)\) where \(D \ll n\), enabling linear-time training.

Code Trace — From Scratch & sklearn
▼
import numpy as np
from sklearn.svm import SVC
from sklearn.preprocessing import StandardScaler
# ── Kernel functions from scratch ────────────────────────────
def kernel_poly(x, xp, c=1, d=2):
"""Polynomial kernel: K(x,x') = (x.T x' + c)^d"""
return (x @ xp + c) ** d
def kernel_rbf(x, xp, gamma=0.5):
"""RBF kernel: K(x,x') = exp(-gamma ||x - x'||^2)"""
diff = x - xp
return np.exp(-gamma * diff @ diff)
def gram_matrix(X, kernel_fn):
"""Compute n×n Gram matrix K[i,j] = K(X[i], X[j])"""
n = len(X)
K = np.zeros((n, n))
for i in range(n):
for j in range(n):
K[i, j] = kernel_fn(X[i], X[j])
return K # symmetric, PSD guaranteed if kernel valid
# ── Verify: poly kernel equals explicit feature dot product ──
x = np.array([1.0, 2.0])
xp = np.array([3.0, 4.0])
phi = lambda v: np.array([1, np.sqrt(2)*v[0], np.sqrt(2)*v[1],
v[0]**2, np.sqrt(2)*v[0]*v[1], v[1]**2])
assert np.isclose(kernel_poly(x, xp), phi(x) @ phi(xp)) # True
# ── sklearn SVC with RBF (production usage) ──────────────────
from sklearn.datasets import make_circles
X_data, y_data = make_circles(n_samples=200, noise=0.1, factor=0.4)
sc = StandardScaler().fit(X_data)
X_scaled = sc.transform(X_data)
svm_rbf = SVC(kernel='rbf', C=1.0, gamma='scale') # gamma='scale' is default
svm_rbf.fit(X_scaled, y_data)
print(svm_rbf.score(X_scaled, y_data)) # ~0.99
print(f"Support vectors: {svm_rbf.n_support_}") # [n_sv per class]
svm_poly = SVC(kernel='poly', degree=2, coef0=1, C=1.0)
svm_poly.fit(X_scaled, y_data)
print(svm_poly.score(X_scaled, y_data)) # also ~0.99
# ⚠️ Gotcha: always scale features before RBF!
# Without scaling, features with large variance dominate ||x-x'||^2
