Understanding Contrastive Losses
▼

What is it? A contrastive loss trains an encoder to place similar inputs (an anchor and its "positive") close together in embedding space, and dissimilar inputs (its "negatives") far apart. Instead of learning a fixed decision boundary between K classes, it learns a general-purpose notion of similarity — useful even when the set of classes isn't known in advance or there are no labels at all.

Analogy: Sorting a pile of unlabeled photos by "who's in it." You pick a photo (anchor), find another photo of the same person (positive) and physically move them closer in a filing box, then take a photo of a stranger (negative) and push it to the far end. Repeat millions of times and the box self-organizes into per-person clusters — no names ever required.

💡 If you remember one thing

Every contrastive loss does the same relative-ranking job — make \(\mathrm{sim}(\text{anchor},\text{positive})\) bigger than \(\mathrm{sim}(\text{anchor},\text{negative})\) — they just differ in how many positives/negatives are compared per step and how the comparison is weighted.

How It Works Internally
▼

Triplet Loss

For anchor \(a\), positive \(p\), negative \(n\):

$$\mathcal{L}_{\text{triplet}} = \big[\|f(a)-f(p)\|_2^2 - \|f(a)-f(n)\|_2^2 + \alpha\big]_+$$

The hinge \([\cdot]_+\) means the gradient is exactly zero once the negative is already farther than the positive by margin \(\alpha\) — which is why FaceNet mines hard or semi-hard triplets online rather than sampling randomly; most random triplets already satisfy the margin and teach the network nothing.

NT-Xent (SimCLR)

A batch of N images is augmented twice each (2N views). For a positive pair \((i,j)\), every other view in the batch becomes a negative automatically — no mining needed:

$$\ell_{i,j} = -\log \frac{\exp(\mathrm{sim}(z_i,z_j)/\tau)}{\sum_{k \ne i}\exp(\mathrm{sim}(z_i,z_k)/\tau)}$$

This is literally a softmax classification problem: "which of the 2N-1 other views is my true positive?" Hard negatives (high similarity but wrong) get pulled into the denominator with large weight, so they dominate the gradient automatically.

Supervised Contrastive (SupCon)

Same machinery as NT-Xent, but uses ground-truth labels so every same-class sample in the batch — not just the augmented twin — counts as a positive, averaged over the positive set \(P(i)\).

🔑 Key Property

NT-Xent's InfoNCE loss maximizes a lower bound on mutual information between two views: \(I(X;Y) \ge \log(N) - \mathcal{L}_{\text{InfoNCE}}\). The bound tightens as the number of negatives N grows — this is exactly why SimCLR needs huge batches (or a momentum queue, as in MoCo).

3
Why It Works — The Math
▼

Gradient of NT-Xent

Let \(p_k = \mathrm{softmax}(z_i \cdot z_k/\tau)\) over candidates \(k \ne i\). Then:

$$\frac{\partial \mathcal{L}_{i,j}}{\partial z_i} = \frac{1}{\tau}\Big(\sum_{k \ne i} p_k z_k - z_j\Big)$$

This is a confusability-weighted average of every candidate, minus the true positive — hard negatives (high \(p_k\)) automatically dominate the update, with zero explicit mining logic required.

Supervised Contrastive Loss

$$\mathcal{L}^{sup}_i = \frac{-1}{|P(i)|}\sum_{p \in P(i)} \log \frac{\exp(z_i \cdot z_p/\tau)}{\sum_{a \in A(i)} \exp(z_i \cdot z_a/\tau)}$$

Averaging the log-probability over all same-class positives \(P(i)\) reduces gradient variance versus picking just one positive per anchor, and removes NT-Xent's biggest self-supervised flaw: treating same-class-but-different-instance samples as false negatives.

⚠️ Common Misconception

"InfoNCE directly maximizes mutual information." It only maximizes a lower bound, capped at \(\log N\). With too few negatives the bound is loose, so driving the loss to zero doesn't guarantee a good representation — batch size (or negative-queue size) is a first-class hyperparameter, not just a compute knob.

Key Takeaways
▼

When to use which:

  • Triplet loss — labeled, open-set problems (face verification, re-identification) where you need a distance metric at inference and can afford online hard-negative mining.
  • NT-Xent — no labels available, want a general-purpose pretrained encoder (SimCLR, MoCo, CLIP) — needs large batches or a momentum negative queue.
  • Supervised Contrastive — labels available and you want representations more robust than plain softmax cross-entropy classification.

Failure modes to watch for:

  • Representation collapse — without negatives, the trivial "map everything to the same point" solution minimizes the loss.
  • Weak signal from too-small batches in NT-Xent — too few negatives, loose mutual-information bound.
  • False negatives — self-supervised NT-Xent penalizes same-class-different-instance pairs as if they were negatives; SupCon fixes this with labels.
💡 Hierarchy

Triplet (1 negative, mined) → NT-Xent (all in-batch negatives, softmax-weighted, unsupervised) → SupCon (all in-batch negatives + all same-class positives, label-aware). Each generalizes the previous by using more of the batch's structure.

Code Trace — NT-Xent from Scratch
▼
import torch, torch.nn.functional as F
def nt_xent_loss(z1, z2, temperature=0.5):
B = z1.shape[0]
z = torch.cat([z1, z2], dim=0) # (2B, D)
z = F.normalize(z, dim=1) # unit hypersphere -> cosine sim via dot
sim = z @ z.T / temperature # (2B, 2B) scaled similarity matrix
sim.fill_diagonal_(-1e9) # mask self-similarity
# positive of sample i is i+B (mod 2B)
targets = torch.cat([torch.arange(B, 2*B), torch.arange(0, B)])
return F.cross_entropy(sim, targets) # exactly the InfoNCE softmax-CE form

Note how F.cross_entropy on the masked similarity matrix is the InfoNCE loss — no custom softmax/log needed, because NT-Xent is exactly an N-way classification problem in disguise.
