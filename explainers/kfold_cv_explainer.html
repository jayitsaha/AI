K-Fold Cross-Validation

Part III: Classical Machine Learning → Section 13.3 Cross-Validation Strategies

Intermediate Classical ML Model Selection Interview: Must Know
1
Understanding the Concept

What is it? Imagine you have a limited dataset and need to know how well your machine learning model will perform on data it has never seen. K-fold cross-validation splits your data into K equal-sized groups ("folds"). It trains the model K times — each time using K−1 folds to train and 1 fold to test — then averages the K scores. This gives a reliable performance estimate without wasting data.

Real-world analogy: You're a teacher grading an exam. Instead of one student marking everyone else's papers (biased), you rotate: student 1 grades papers 2–10, student 2 grades papers 1,3–10, and so on. You rotate who's "grading" (validation) and who's being evaluated. The final result averages all rounds — fair, unbiased, and uses every exam paper.

💡 If You Remember One Thing

Every data point is used exactly once as validation and K−1 times for training. The CV estimate is \(\hat{\text{Err}} = \frac{1}{K}\sum_{k=1}^{K} \text{Err}_k\), where each \(\text{Err}_k\) is computed on a held-out fold the model never trained on.

🔑 Key Property

Rotation invariant test estimate: K-fold partitions \(\mathcal{D} = \{(x_i, y_i)\}_{i=1}^n\) into K disjoint folds \(F_1,\ldots,F_K\) of size \(\approx n/K\). For fold \(k\), the model \(\hat{f}^{(-k)}\) is trained on \(\mathcal{D} \setminus F_k\). This means no validation point ever influences the weights it's evaluated on.

How It Works — Step by Step

Algorithm (5-fold example, n=20 samples):

📐 Formal Definition

Partition \(\{1,\ldots,n\}\) into K equally-sized index sets \(F_1,\ldots,F_K\) (folds). For each fold \(k=1,\ldots,K\):

  1. Train: fit \(\hat{f}^{(-k)}\) on \(\mathcal{D}_{-k} = \mathcal{D} \setminus F_k\) (all data except fold k)
  2. Validate: compute \(\text{Err}_k = \frac{K}{n}\sum_{i \in F_k} L(y_i,\, \hat{f}^{(-k)}(x_i))\)

Final CV estimate: \(\hat{\text{Err}}_{\text{CV}} = \frac{1}{K}\sum_{k=1}^{K}\text{Err}_k\)

⚠️ Common Mistake

Data leakage in preprocessing. If you fit a scaler or imputer on all data before CV, information from the validation fold bleeds into training. Always wrap preprocessing inside the fold loop or use sklearn's Pipeline.

3
The Math — Bias, Variance, and the K Trade-off

The central theoretical question: how does the choice of K affect the quality of the CV estimate?

$$\text{MSE}[\hat{\text{Err}}_{\text{CV}}] = \underbrace{\text{Bias}^2[\hat{\text{Err}}_{\text{CV}}]}_{\text{underestimates true err if K small}} + \underbrace{\text{Var}[\hat{\text{Err}}_{\text{CV}}]}_{\text{high if K large / folds correlated}}$$

Bias analysis: Each fold trains on \(n(1-1/K)\) samples. As K grows, training set approaches n → the CV estimate's bias toward the true n-sample model decreases. At K=n (LOOCV), training size is n−1, so bias is minimal but not zero.

$$\text{Bias} \approx \frac{\partial \text{Err}(n_{\text{train}})}{\partial n_{\text{train}}} \cdot \frac{n}{K}$$

Variance analysis (Arlot & Celisse 2010): The K fold-scores \(\text{Err}_1,\ldots,\text{Err}_K\) are not independent — each pair of fold-models shares \((K-2)/K\) of their training data. The variance of the average is:

$$\text{Var}\!\left[\hat{\text{Err}}_{\text{CV}}\right] = \frac{\sigma^2}{K} + \frac{K-1}{K}\,\rho\,\sigma^2 = \sigma^2\!\left(\frac{1}{K} + \frac{(K-1)\rho}{K}\right)$$

where \(\sigma^2 = \text{Var}[\text{Err}_k]\) and \(\rho\) is the pairwise correlation between fold scores. As K→n, \(\rho\)→1 and variance increases despite K growing — this is why LOOCV has high variance.

✅ The K=5 or K=10 Sweet Spot

Empirically (Kohavi 1995; Hastie et al.): K=5 and K=10 give the best bias-variance trade-off for the CV estimator itself. K=10 is the default recommendation — low enough bias, manageable variance and compute cost.

Key Takeaways & When to Use
✅ Use K-Fold When

Dataset is moderate-sized (few hundred to tens of thousands), you need reliable performance estimates, you're comparing models or tuning hyperparameters, and class distributions are reasonably balanced.

🚫 Do NOT Use Standard K-Fold When

Time series data — fold splitting ignores temporal order, causing data leakage. Use walk-forward (rolling) CV.
Grouped data — if patients/users appear in multiple folds, use GroupKFold.
Very imbalanced classes — a fold may contain no minority examples; use StratifiedKFold.
