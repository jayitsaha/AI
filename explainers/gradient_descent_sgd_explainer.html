1
Understanding Gradient Descent
▼

What is it? Gradient descent is the algorithm that trains nearly every machine learning model. Given a loss function \(\mathcal{L}(\theta)\) measuring how wrong the model is, gradient descent repeatedly nudges the parameters \(\theta\) in the direction that reduces the loss most steeply — the negative gradient direction.

Analogy: Imagine you're blindfolded on a hilly landscape trying to reach the lowest valley. At each step you feel the ground slope under your feet, then step in whichever direction slopes downward most steeply. The three variants — batch GD, mini-batch GD, and SGD — differ only in how much of the terrain you sense before each step: all of it, a random chunk, or just one patch.

If you remember one thing

All three variants execute the same update rule $$\theta \leftarrow \theta - \eta \nabla_\theta \mathcal{L}$$ but differ in what data \(\nabla_\theta \mathcal{L}\) is computed over. Batch uses all \(n\) samples (exact gradient, expensive). SGD uses 1 sample (noisy, cheap). Mini-batch uses \(B\) samples (the practical sweet spot).

The Core Update Rule

For a model with parameters \(\theta \in \mathbb{R}^d\), loss \(\mathcal{L}(\theta)\), and learning rate \(\eta > 0\):

$$\theta_{t+1} = \theta_t - \eta \cdot \hat{g}_t \quad \text{where} \quad \hat{g}_t \approx \nabla_\theta \mathcal{L}(\theta_t)$$

The three variants differ only in how \(\hat{g}_t\) is estimated from data.

2
The Three Variants — Mechanics & Tradeoffs
▼

Batch Gradient Descent (Full-Batch GD)

Computes the gradient over the entire training dataset of \(n\) samples at each step:

$$\hat{g}_t^{\text{batch}} = \frac{1}{n} \sum_{i=1}^{n} \nabla_\theta \ell(\theta_t; x_i, y_i)$$

This is the exact gradient of the empirical loss. Steps are smooth and guaranteed to descend (for small enough \(\eta\)). But computing it requires a full pass over all data — catastrophically slow for \(n = 10^9\).

Stochastic Gradient Descent (SGD)

Draws a single random sample \(i\) and computes its gradient as an unbiased estimate:

$$\hat{g}_t^{\text{SGD}} = \nabla_\theta \ell(\theta_t; x_i, y_i)$$

Each step is extremely cheap — \(O(1)\) instead of \(O(n)\). The estimator is unbiased (\(\mathbb{E}[\hat{g}^{\text{SGD}}] = \nabla \mathcal{L}\)) but has high variance. This noise is not always bad: it helps escape sharp local minima and can act as an implicit regularizer.

Mini-Batch Gradient Descent

The dominant choice in practice. Draw a random batch of \(B\) samples (typically 32–512):

$$\hat{g}_t^{\text{mini}} = \frac{1}{B} \sum_{i \in \mathcal{B}_t} \nabla_\theta \ell(\theta_t; x_i, y_i)$$

Gradient variance scales as \(\operatorname{Var}[\hat{g}^{\text{mini}}] = \frac{1}{B}\operatorname{Var}[\nabla \ell]\). Larger \(B\) reduces noise but reduces gradient diversity. GPU parallelism means batch size \(B\) costs almost the same wall-clock time as a single sample up to hardware limits.

Key Property — Variance Reduction

Mini-batch gradient variance is \(\sigma^2/B\) where \(\sigma^2\) is the single-sample variance. Doubling batch size halves noise but also halves the number of updates per epoch — a fundamental noise-vs-throughput tradeoff.

Learning Rate: The Critical Hyperparameter

The step size \(\eta\) determines convergence quality. For a quadratic loss with curvature \(L\) (largest eigenvalue of the Hessian), batch GD converges iff \(\eta < 2/L\). Too small: slow convergence. Too large: oscillation or divergence. The interactive visualization below shows all three regimes.

Common Pitfall

Increasing batch size requires scaling the learning rate proportionally (linear scaling rule: \(\eta \propto B\)) to maintain the same effective noise level and convergence speed — otherwise larger batches converge slower in terms of epochs.

3
Why It Works — The Math
▼

Convergence for Convex Loss

For an \(L\)-smooth, \(\mu\)-strongly convex loss \(\mathcal{L}\), batch GD with \(\eta = 1/L\) satisfies:

$$\mathcal{L}(\theta_t) - \mathcal{L}(\theta^*) \leq \left(1 - \frac{\mu}{L}\right)^t [\mathcal{L}(\theta_0) - \mathcal{L}(\theta^*)]$$

This is a linear convergence rate — the error shrinks by a constant factor each step. The condition number \(\kappa = L/\mu\) governs how fast: near-circular loss surfaces (\(\kappa \approx 1\)) converge rapidly; elongated bowls (\(\kappa \gg 1\)) converge slowly.

Why the Gradient Direction?

By first-order Taylor expansion around \(\theta_t\):

$$\mathcal{L}(\theta_t + \delta) \approx \mathcal{L}(\theta_t) + \nabla \mathcal{L}(\theta_t)^\top \delta$$

To decrease \(\mathcal{L}\) most, choose \(\delta \propto -\nabla \mathcal{L}(\theta_t)\). With a step-size constraint \(\|\delta\| \leq \eta\), the steepest descent direction is exactly \(\delta = -\eta \nabla \mathcal{L}(\theta_t)\). This is first-order — it ignores curvature (the Hessian), which is why learning rate tuning is so critical.

SGD Convergence (Nonconvex)

For nonconvex losses (neural networks), SGD with decreasing learning rate \(\eta_t = O(1/\sqrt{t})\) converges to a stationary point:

$$\frac{1}{T}\sum_{t=0}^{T-1} \mathbb{E}\|\nabla \mathcal{L}(\theta_t)\|^2 \leq O\!\left(\frac{1}{\sqrt{T}}\right)$$

No guarantee of the global minimum — but in overparameterized neural networks, most stationary points are saddle points or flat minima, and SGD noise helps escape them.

Variance of the SGD Gradient Estimator

For mini-batch size \(B\): \(\operatorname{Var}[\hat{g}^{\text{mini}}] = \frac{\sigma^2}{B}\) where \(\sigma^2 = \operatorname{Var}[\nabla \ell]\) is single-sample variance. This is why SGD (\(B=1\)) is noisiest, and batch GD (\(B=n\)) has zero variance (exact gradient).

Numerical Trace — Loss Surface \(\mathcal{L}(w_1,w_2) = w_1^2 + 5w_2^2\)

Starting from \((w_1, w_2) = (-3, 2)\), gradient \(\nabla\mathcal{L} = (2w_1, 10w_2)\), with \(\eta = 0.1\):

  • Step 0: \(\mathcal{L} = 9 + 20 = 29.00\). Gradient \(= (-6, 20)\).
  • Step 1 (Batch): \(w \leftarrow (-3, 2) - 0.1 \cdot (-6, 20) = (-2.4, 0.0)\). \(\mathcal{L} = 5.76\).
  • Step 2: Gradient \(= (-4.8, 0)\). \(w \leftarrow (-1.92, 0)\). \(\mathcal{L} = 3.69\).
  • Each step reduces loss by factor \((1 - 2\eta)^2 \approx 0.64\) in \(w_1\) and \((1 - 10\eta)^2 = 0\) in \(w_2\) — \(w_2\) collapses instantly because \(\eta = 1/L_{w_2}\) exactly!

With SGD noise, \(\hat{g}_t = (-6, 20) + \varepsilon_t\), the path zigzags around this smooth trajectory but still converges in expectation.

Decision Rule

Use mini-batch GD for all deep learning (B = 32–512, GPU-tuned). Use SGD for online learning where data arrives one sample at a time. Use batch GD only for small datasets (n < 1000) where the exact gradient is affordable. Always pair with a learning rate scheduler (cosine annealing, warmup, or step decay).
