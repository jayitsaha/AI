Segmentation Metrics: mIoU, Pixel Accuracy, Dice Coefficient

Quantifying how well a predicted segmentation mask matches ground truth
Foundational Deep Learning Computer Vision O(N) per class
1
Understanding Segmentation Metrics
▼

What is image segmentation? It's a computer vision task where we partition an image into regions (segments) that correspond to different objects or semantic categories. The output is a "mask" where each pixel is assigned a class label (e.g., 'car', 'road', 'sky', 'background').

Why do we need specialized metrics? Unlike classification (predicting one label for the whole image) or object detection (bounding boxes), segmentation requires pixel-level accuracy. We need metrics that go beyond simple accuracy to capture how well the predicted shapes and boundaries align with the true objects.

Analogy: Imagine you're coloring a picture of a cat, and a friend is trying to guess where you've colored the cat.

  • Pixel Accuracy is like counting how many individual dots you both agree on (cat or not-cat). If the picture is mostly background, you can get a high score just by agreeing on all the background, even if you draw a terrible cat.
  • Intersection over Union (IoU) and Dice Coefficient are like comparing the actual shape of your cat drawing to the true cat shape. They care much more about how well your cat outline matches the real cat's outline, penalizing you heavily for drawing outside the lines or missing parts of the cat.

💡 If you remember one thing

Segmentation metrics quantify the overlap between a ground truth (GT) mask and a predicted (Pred) mask. Pixel Accuracy is simple but often misleading for imbalanced classes or small objects. IoU and Dice are more robust as they focus on the foreground object's shape and boundary quality.

2
How Segmentation Metrics Work
▼

The Building Blocks: TP, FP, FN, TN

All these metrics are built from a confusion matrix at the pixel level, comparing the ground truth (GT) mask to the predicted (Pred) mask:

  • True Positives (TP): Pixels correctly predicted as foreground (object). (GT=1, Pred=1)
  • False Positives (FP): Pixels incorrectly predicted as foreground. (GT=0, Pred=1) - "false alarm"
  • False Negatives (FN): Pixels incorrectly predicted as background. (GT=1, Pred=0) - "missed object"
  • True Negatives (TN): Pixels correctly predicted as background. (GT=0, Pred=0)

Pixel Accuracy (PA)

This is the simplest metric, measuring the proportion of correctly classified pixels overall:

$$\text{Pixel Accuracy} = \frac{TP + TN}{TP + FP + FN + TN}$$

While intuitive, PA can be misleading. If 90% of an image is background, a model that predicts everything as background will achieve 90% PA, even if it completely misses all foreground objects. This is why it's rarely the sole metric for segmentation.

Intersection over Union (IoU) / Jaccard Index

IoU measures the overlap between the predicted segmentation and the ground truth. It's the ratio of the intersection area to the union area of the two masks:

$$\text{IoU} = \frac{\text{Area of Overlap}}{\text{Area of Union}} = \frac{TP}{TP + FP + FN}$$

IoU is sensitive to both false positives and false negatives. A perfect segmentation has an IoU of 1.0. If there's no overlap, IoU is 0. Unlike PA, IoU ignores True Negatives, making it more focused on foreground object detection.

Dice Coefficient / F1 Score

The Dice Coefficient is very similar to IoU and is also known as the F1 Score for binary masks. It's defined as twice the area of intersection divided by the total number of pixels in both masks:

$$\text{Dice} = \frac{2 \times \text{Area of Overlap}}{\text{Total Pixels in Both Masks}} = \frac{2 \times TP}{2 \times TP + FP + FN}$$

Dice also ranges from 0 to 1, with 1 being a perfect match. It's often preferred in medical imaging. Dice tends to be slightly higher than IoU for the same segmentation, as it effectively "counts" the intersection twice in the numerator and denominator.

Mean Intersection over Union (mIoU)

For multi-class segmentation, we calculate the IoU for each class independently and then average these IoU scores. This gives a single metric that represents the average performance across all classes.

🔑 Key Property

IoU and Dice focus on the quality of foreground object segmentation, penalizing errors more heavily than Pixel Accuracy. They are generally preferred for evaluating segmentation models, especially for tasks with class imbalance.

3
Why They Work — The Math
▼

Formal Definitions with Sets

Let \(A\) be the set of pixels belonging to a specific class in the Ground Truth mask, and \(B\) be the set of pixels predicted as belonging to that class in the Predicted mask. Let \(U\) be the set of all pixels in the image.

Pixel Accuracy: The proportion of pixels where the prediction matches the ground truth (both foreground or both background).

$$\text{PA} = \frac{|A \cap B| + |A^c \cap B^c|}{|U|}$$

Here, \(|A \cap B|\) is TP, \(|A^c \cap B^c|\) is TN, and \(|U|\) is the total number of pixels (\(TP + FP + FN + TN\)).

Intersection over Union (IoU) / Jaccard Index: This is the size of the intersection of \(A\) and \(B\) divided by the size of their union.

$$\text{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|} = \frac{TP}{TP + FP + FN}$$

The union \(|A \cup B|\) can also be expressed as \(|A| + |B| - |A \cap B|\), or in terms of confusion matrix components: \((TP + FN) + (TP + FP) - TP = TP + FP + FN\).

Dice Coefficient: This metric is defined as twice the size of the intersection divided by the sum of the sizes of \(A\) and \(B\).

$$\text{Dice}(A, B) = \frac{2 |A \cap B|}{|A| + |B|} = \frac{2 \times TP}{(TP + FN) + (TP + FP)} = \frac{2 \times TP}{2 \times TP + FP + FN}$$

Notice the denominator: it sums the number of pixels in the ground truth object (\(TP+FN\)) and the predicted object (\(TP+FP\)).

Relationship Between IoU and Dice

There's a direct mathematical relationship between IoU and Dice:

$$\text{Dice} = \frac{2 \times \text{IoU}}{1 + \text{IoU}} \quad \text{and} \quad \text{IoU} = \frac{\text{Dice}}{2 - \text{Dice}}$$

This means if you know one, you can derive the other. Dice tends to give higher values than IoU for the same level of overlap, especially for low overlaps. For example, an IoU of 0.5 corresponds to a Dice of 0.667. This can sometimes make Dice appear more "optimistic."

⚠️ Important Considerations

When calculating mIoU, it's common practice to exclude the background class from the average, as its IoU can be artificially high due to large TN counts. However, for some applications, including background might be relevant. Always clarify how mIoU is calculated in a given context.

Key Takeaways
▼

When to use each metric:

  • Pixel Accuracy: Best for very simple tasks with balanced classes, or as a quick sanity check. Rarely sufficient alone for real-world segmentation.
  • IoU (Jaccard Index): The most widely adopted metric for semantic segmentation. It provides a balanced assessment of overlap, penalizing both FP and FN equally.
  • Dice Coefficient: Popular in medical image segmentation. It's mathematically very similar to IoU but tends to give higher values, which can be interpreted as slightly more forgiving. It emphasizes overlap more heavily than IoU.
  • mIoU (mean IoU): Essential for multi-class segmentation. It provides an overall performance score by averaging IoU across all individual classes (often excluding background).

When NOT to use:

  • Avoid relying solely on Pixel Accuracy when classes are highly imbalanced (e.g., small objects on a large background).
  • If your task requires precise boundary detection and you have very thin or small objects, even IoU/Dice might need to be complemented with boundary-specific metrics.
  • For probabilistic outputs (e.g., a model outputs a confidence score for each pixel belonging to a class), these "hard" metrics require thresholding the probabilities to create binary masks, which can introduce its own challenges. "Soft" versions of these metrics (e.g., soft Dice loss) can be used directly with probabilities.
💡 Rule of Thumb

For most segmentation tasks, mIoU is the gold standard because it provides a robust, class-agnostic average of foreground object overlap quality. Consider IoU or Dice for individual class performance, and use Pixel Accuracy only as a supplementary measure.

Code Trace (Python/NumPy)
▼
import numpy as np
def calculate_segmentation_metrics(gt_mask, pred_mask, num_classes, ignore_background=True):
"""
Calculates Pixel Accuracy, per-class IoU, Dice, and mIoU.
gt_mask: HxW array of ground truth labels
pred_mask: HxW array of predicted labels
num_classes: total number of classes (e.g., 0 for background, 1 for object A, etc.)
"""
assert gt_mask.shape == pred_mask.shape
total_pixels = gt_mask.size
# Overall Pixel Accuracy
pixel_accuracy = np.sum(gt_mask == pred_mask) / total_pixels
# Per-class metrics
ious = []
dices = []
for class_id in range(num_classes):
if ignore_background and class_id == 0: continue # Skip background
gt_class = (gt_mask == class_id)
pred_class = (pred_mask == class_id)
tp = np.sum(gt_class & pred_class)
fp = np.sum(~gt_class & pred_class)
fn = np.sum(gt_class & ~pred_class)
# IoU
union = tp + fp + fn
iou = tp / union if union > 0 else 1.0 # If GT has no pixels for class, and pred also has none, IoU is 1.0
ious.append(iou)
# Dice
dice_denom = 2 * tp + fp + fn
dice = (2 * tp) / dice_denom if dice_denom > 0 else 1.0
dices.append(dice)
# Mean IoU (mIoU)
mean_iou = np.mean(ious) if ious else 0.0
mean_dice = np.mean(dices) if dices else 0.0
return {
"pixel_accuracy": pixel_accuracy,
"per_class_iou": ious,
"per_class_dice": dices,
"mean_iou": mean_iou,
"mean_dice": mean_dice
}
