1
Understanding MDL
▾

The Minimum Description Length (MDL) principle answers one of the most fundamental questions in machine learning: given several models that all fit the data, which one should you choose? MDL's answer is elegantly simple — pick the model that lets you compress the data most efficiently.

Formalized by Jorma Rissanen in 1978, MDL operationalizes Occam's Razor through information theory. It frames learning as a two-part communication problem: a sender must transmit data to a receiver using a chosen model. The total transmission cost is the model's own description length plus the cost of describing the residuals (the data not captured by the model). The best model minimizes this total cost.

Core Insight

A model that fits noise requires a short model code but a long residual code. A model that's too simple requires a short model code but still a long residual code. Only the model that captures true structure compresses both simultaneously — that is the MDL winner.

MDL provides a formal, principled connection between compression and learning. Its two most famous instantiations are two-part (crude) MDL — where model and data are described separately — and normalized maximum likelihood (NML), the modern refinement. For practical purposes, two-part MDL with a BIC penalty is the most common form encountered in ML.

The One Thing to Remember

MDL = L(model) + L(data | model). Minimizing this sum is equivalent to finding the best tradeoff between model complexity and goodness of fit — the information-theoretic formulation of Occam's Razor.

2
Historical Context & Connections
▾

Motivation

Before MDL, model selection relied on heuristics (AIC, cross-validation) or Bayesian approaches requiring explicit priors. Rissanen's 1978 paper "Modeling by Shortest Data Description" asked: what if instead of invoking priors, we think about how much information it takes to communicate the model and data? This grounded model selection in Shannon's information theory.

Connection to Kolmogorov Complexity

MDL is the computable proxy for Kolmogorov complexity. Kolmogorov complexity \(K(x)\) of a string \(x\) is the length of the shortest program that outputs \(x\) — the ultimate compression. It is uncomputable. MDL replaces "any program" with "a program drawn from a specific model class," making the complexity measurable in practice. As model classes grow richer, MDL approximates Kolmogorov complexity more closely.

Connection to BIC

The Bayesian Information Criterion (BIC) is asymptotically equivalent to two-part MDL under Gaussian errors. BIC penalizes likelihood by \(\frac{k}{2}\ln n\), which is exactly the code length for specifying \(k\) parameters to log-precision when there are \(n\) data points. MDL provides the information-theoretic derivation of what BIC's penalty means.

Connection to AIC

AIC uses a penalty of \(k\) (not \(\frac{k}{2}\ln n\)), which corresponds to a weaker complexity cost. AIC targets predictive accuracy for future data from the same distribution; MDL targets compression, which asymptotically favors the true model even when it has more parameters than AIC would select.

The Mathematics
▾

Two-Part (Crude) MDL

Let \(\mathcal{M}\) be a model class (e.g., polynomial regressors). For a model \(M \in \mathcal{M}\) with \(k\) parameters and a dataset \(D\) of \(n\) observations:

$$L_{\text{total}}(M, D) = L(M) + L(D \mid M)$$

The model description length \(L(M)\) encodes the parameter values. To log-precision with \(n\) data points, each of \(k\) parameters requires \(\frac{1}{2}\log_2 n\) bits:

$$L(M) = \frac{k}{2}\log_2 n$$

The data description length \(L(D \mid M)\) is the negative log-likelihood under the MLE parameters. For Gaussian residuals:

$$L(D \mid M) = \frac{n}{2}\log_2\!\left(\hat{\sigma}^2\right) + \frac{n}{2}\log_2(2\pi e)$$

where \(\hat{\sigma}^2 = \frac{1}{n}\sum_{i=1}^n (y_i - \hat{y}_i)^2\) is the MLE residual variance. The constant \(\frac{n}{2}\log_2(2\pi e)\) is independent of the model and can be dropped for comparison purposes.

Normalized Maximum Likelihood (NML)

NML MDL is the modern, exact formulation. The NML distribution over data sequences of length \(n\) under model class \(\mathcal{M}\) is:

$$p_{\text{NML}}(x^n \mid \mathcal{M}) = \frac{p(x^n \mid \hat{\theta}(x^n))}{\int p(y^n \mid \hat{\theta}(y^n))\, dy^n}$$

The denominator \(C_n(\mathcal{M}) = \int p(y^n|\hat{\theta}(y^n))\,dy^n\) is the parametric complexity (COMP). The NML code length is:

$$L_{\text{NML}}(x^n) = -\log p(x^n \mid \hat{\theta}(x^n)) + \log C_n(\mathcal{M})$$

Relationship to BIC

For regular parametric models with \(k\) parameters, Rissanen showed:

$$\log C_n(\mathcal{M}) \approx \frac{k}{2}\log\frac{n}{2\pi e} + \log \int \sqrt{\det I(\theta)}\, d\theta$$

Dropping the Fisher information integral (data-independent), the leading term is \(\frac{k}{2}\log n\), exactly the BIC penalty divided by \(\log 2\). This establishes BIC ≈ two-part MDL ≈ leading term of NML MDL.

Common Misconception

MDL does not choose the model with the highest likelihood — overfitted models always have higher (or equal) likelihood. MDL explicitly penalizes complexity via \(L(M)\), preventing this. The tradeoff is fundamental: models with more parameters need fewer bits to describe residuals but more bits to describe themselves.

Code: MDL for Polynomial Regression
▾

Below is a from-scratch MDL implementation for polynomial model selection. The numerically computed values are used directly in the interactive visualization:

import numpy as np
def mdl_two_part(x, y, degree):
"""Compute MDL two-part code for polynomial of given degree."""
n = len(y)
k = degree + 1 # number of parameters
# Fit model via OLS
coeffs = np.polyfit(x, y, degree)
y_hat = np.polyval(coeffs, x)
# MLE residual variance
sigma2 = np.sum((y - y_hat)**2) / n
# L(M): model cost — k params each need 0.5*log2(n) bits
L_model = 0.5 * k * np.log2(n)
# L(D|M): data cost — negative log-likelihood (Gaussian, log2)
L_data = 0.5 * n * np.log2(sigma2) + 0.5*n*np.log2(2*np.pi*np.e)
return L_model, L_data, L_model + L_data
# Example: select polynomial degree from 0–8
np.random.seed(42)
x = np.linspace(-2, 2, 20)
y = 0.5*x**2 + 0.3*x + np.random.randn(20)*0.5
for k in range(9):
lm, ld, lt = mdl_two_part(x, y, k)
print(f"deg={k}: L_model={lm:.1f} L_data={ld:.1f} Total={lt:.1f}")
# deg=2 achieves minimum total → MDL selects true model

Key Takeaways
▾
  • MDL = compression = learning: regularization is not arbitrary but derives from information theory.
  • Two-part MDL is BIC in disguise; use it when you want a consistent model selector with an interpretable penalty.
  • NML MDL is the theoretically pure form; computationally heavier but avoids the choice of how to encode parameters.
  • Underfitting: short model code, long data code — you need many bits to describe what the model missed.
  • Overfitting: long model code, short data code — you memorized noise and need many bits to transmit those complex parameters.
  • Just right: both codes are short — you found the true regularity.
Interview One-Liner

MDL selects the model \(M^* = \arg\min_M [L(M) + L(D|M)]\). For Gaussian models, this is equivalent to BIC: minimize negative log-likelihood plus \(\frac{k}{2}\ln n\).
