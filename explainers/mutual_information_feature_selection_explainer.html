Understanding Mutual Information
▼

What is it? Mutual information (MI) is a number that measures how much two variables "know about each other." If you learn the value of one variable, how many bits of uncertainty does that remove about the other? Zero means the variables are completely independent; larger values mean stronger statistical dependence.

Analogy: Imagine two smoke detectors in the same building. Detector A tells you a lot about whether there's a fire — high MI with the fire event. Detector B is in a completely sealed room — low MI with the fire. Now, if Detector A and Detector B are wired together and always agree, adding B tells you nothing new: they're redundant (high MI with each other). A good alarm system picks sensors with high relevance to the event and low redundancy with each other — exactly what mRMR does with features.

💡 If you remember one thing

Mutual information \(I(X;Y) = H(X) + H(Y) - H(X,Y)\) measures shared information. It equals zero iff \(X \perp Y\), and is always non-negative. Unlike correlation, it captures any statistical dependence — not just linear.

Why it matters in ML

  • Feature selection: Rank features by \(I(F_i; Y)\), filter by relevance; use mRMR to also minimise redundancy among selected features.
  • Representation learning: InfoMax principle — learn an encoder \(f\) that maximises \(I(f(x); x)\). InfoNCE / SimCLR / DIM are all MI-maximisation objectives in disguise.
  • Diagnostics: MI-based tests detect non-linear dependence where Pearson \(r = 0\) would miss it.

Feature Selection with MI — mRMR & Beyond
▼

Step 1: Compute I(Fᵢ; Y) for every feature

Estimate MI between each candidate feature \(F_i\) and the target \(Y\). For discrete variables use the plug-in estimator; for continuous variables use k-nearest-neighbour (KNN) estimators (Kraskov et al. 2004). Features with \(I(F_i; Y) \approx 0\) are irrelevant and discarded immediately.

Step 2: The redundancy problem — greedy MI ranking fails

Simply taking the top-\(k\) features by MI often selects a redundant set: if \(F_1\) and \(F_4\) are nearly identical (smoke detectors wired together), both rank high on \(I(F_i; Y)\) but carry the same information. The model gains nothing from both.

🔑 mRMR Criterion (Peng, Ding, Long 2005)

At each step, select the feature \(F^*\) that maximises: $$F^* = \underset{f \notin S}{\operatorname{argmax}}\;\left[I(f;\,Y) - \frac{1}{|S|}\sum_{s \in S} I(f;\,s)\right]$$ where \(S\) is the already-selected set. The subtracted term penalises overlap with selected features.

Numerical trace (5 features, verified)

Round 1: Best raw MI is \(F_4\) with \(I(F_4; Y) = 0.674\). Select \(S = \{F_4\}\).

Round 2: \(F_1\) has raw MI = 0.672 but \(I(F_1; F_4) = 0.950\), so mRMR score = \(0.672 - 0.950 = -0.278\). \(F_2\) has raw MI = 0.215 but redundancy = 0.110, giving mRMR = \(+0.105\). \(F_2\) wins.

Round 3: With \(S = \{F_4, F_2\}\), \(F_1\)'s redundancy penalty is now \((0.950 + 0.120)/2 = 0.535\), giving mRMR = \(0.672 - 0.535 = +0.137\). \(F_1\) now enters — its F4-redundancy is offset by its low correlation with \(F_2\).

⚠️ Common Pitfall

mRMR is a greedy algorithm — it does not guarantee the globally optimal feature subset. Joint MI \(I(F_1, F_2; Y)\) can exceed the sum of individual MIs (synergy), and mRMR can miss this. JMIM (Joint MI Maximisation) partially addresses this.

Why It Works — The Math
▼

Mutual Information via Entropy

For discrete \(X, Y\) with joint distribution \(p(x,y)\):

$$I(X;Y) = \sum_{x,y} p(x,y)\log\frac{p(x,y)}{p(x)p(y)} = H(X) + H(Y) - H(X,Y)$$

Continuous case — KL divergence form

MI equals the KL divergence from the product of marginals to the joint:

$$I(X;Y) = D_{\mathrm{KL}}\!\left(p(x,y) \,\big\|\, p(x)p(y)\right) \geq 0$$

This immediately implies \(I(X;Y) \geq 0\), with equality iff \(X \perp Y\) (joint = product of marginals).

Gaussian case (closed form)

For jointly Gaussian \((X, Y)\) with correlation \(\rho\):

$$I(X;Y) = -\tfrac{1}{2}\log(1-\rho^2)$$

At \(\rho = 0.8\): \(I = -0.5\ln(1 - 0.64) = -0.5\ln(0.36) \approx 0.511\) nats.

InfoNCE as an MI lower bound

For representation learning, MI between encoder outputs \(z = f(x)\) and input \(x\) is intractable in high dimensions. InfoNCE (van den Oord et al. 2018) provides a computable lower bound. For a batch of \(N\) samples with positive pairs \((z_i^{(1)}, z_i^{(2)})\):

$$\mathcal{L}_{\mathrm{InfoNCE}} = -\frac{1}{N}\sum_{i=1}^{N}\log\frac{\exp\!\left(\mathrm{sim}(z_i^{(1)}, z_i^{(2)})/\tau\right)}{\sum_{j=1}^{N}\exp\!\left(\mathrm{sim}(z_i^{(1)}, z_j^{(2)})/\tau\right)}$$
$$I(z^{(1)};z^{(2)}) \;\geq\; \log N - \mathcal{L}_{\mathrm{InfoNCE}}$$

Verified: with \(N=4\), mean loss \(= 0.807\): bound \(= \ln 4 - 0.807 = 0.579\) nats.

🧮 Data Processing Inequality

For any deterministic function \(g\): \(I(g(X); Y) \leq I(X; Y)\). An encoder can never increase MI — it can only preserve or lose it. InfoMax aims to preserve as much MI as possible in the bottleneck representation.

InfoMax, InfoNCE & Representation Learning
▼

InfoMax Principle (Linsker 1988, Bell & Sejnowski 1995)

The InfoMax principle states: learn an encoder \(f_\theta\) that maximises the mutual information \(I(f_\theta(x); x)\) subject to capacity constraints. This drives the representation to retain as much information about the input as possible. In ICA (Independent Component Analysis), InfoMax is used to find a transformation that maximises the entropy of the outputs — equivalent to finding statistically independent components.

Deep InfoMax (DIM — Hjelm et al. 2019)

DIM extends InfoMax to deep networks. Instead of maximising global MI \(I(E(x); x)\), it maximises local MI between the global representation \(E(x)\) and local patches of the input. This encourages the encoder to capture both fine-grained and semantic structure. The MI is estimated via a discriminator trained to distinguish real \((E(x), \text{patch}_k)\) pairs from fake ones — a binary cross-entropy objective that lower-bounds MI.

InfoNCE and Contrastive Learning

SimCLR, MoCo, and CLIP all implement InfoNCE implicitly. Two views \(x^{(1)}, x^{(2)}\) of the same image are encoded to \(z^{(1)}, z^{(2)}\). InfoNCE loss pushes positive pairs together and negative pairs apart in representation space. The temperature \(\tau\) controls selectivity: small \(\tau\) focuses the gradient on hard negatives; large \(\tau\) spreads gradients more uniformly.

🔑 Key Connection

InfoNCE = cross-entropy of an \(N\)-way classification problem: "which of the \(N\) negative samples is the true positive?" Minimising InfoNCE = maximising MI between the two views. The bound is: $$I(z^{(1)};z^{(2)}) \geq \log N - \mathcal{L}_{\mathrm{InfoNCE}}$$

From-scratch MI + mRMR in NumPy

import numpy as np
from sklearn.feature_selection import mutual_info_classif
# ── Step 1: MI with target ──────────────────────────────
X = np.column_stack([f1, f2, f3, f4, f5]) # (n_samples, 5)
mi_target = mutual_info_classif(X, y, random_state=42) # KNN estimator
# [0.672, 0.215, 0.000, 0.674, 0.055]
# ── Step 2: mRMR greedy selection ──────────────────────
def mrmr_select(mi_target, mi_feats, k):
selected, remaining = [], list(range(len(mi_target)))
for _ in range(k):
if not selected: # Round 1: pure relevance
best = max(remaining, key=lambda i: mi_target[i])
else:
best = max(remaining, key=lambda i:
mi_target[i] - np.mean([mi_feats[i,s] for s in selected]))
selected.append(best); remaining.remove(best)
return selected
chosen = mrmr_select(mi_target, mi_feats, k=3)
# → [3, 1, 0] (F4, F2, F1 in 0-indexed)
# ── Step 3: InfoNCE loss (contrastive) ─────────────────
def infonce_loss(z1, z2, tau=0.5):
z1 = z1 / np.linalg.norm(z1, axis=1, keepdims=True) # L2 normalise
z2 = z2 / np.linalg.norm(z2, axis=1, keepdims=True)
sim = z1 @ z2.T / tau # (N, N) scaled cosine sim
# Numerically stable log-softmax
log_sum = np.log(np.sum(np.exp(sim - sim.max(1,keepdims=True)), axis=1)) + sim.max(1)
pos = np.diag(sim) # positive pair scores
loss = -(pos - log_sum).mean() # scalar
mi_bound = np.log(len(z1)) - loss # I(z1;z2) >= log(N) - L
return loss, mi_bound

Key Takeaways

  • MI is model-agnostic and nonlinear — catches dependencies that correlation misses (e.g., XOR, circular).
  • mRMR's penalisation term prevents redundancy — feature F4 and F1 both have MI ≈ 0.674, but mRMR correctly avoids selecting both in round 2.
  • InfoNCE = differentiable MI maximisation — allows gradient-based optimisation of the encoder.
  • Larger batches = tighter MI bound — the bound \(\log N - \mathcal{L}\) grows with \(N\); hence large-batch contrastive training (e.g. SimCLR with N=4096) is important.
  • Temperature τ is critical: too small → collapse to top-1 gradient; too large → gradients wash out. Typical values: 0.07–0.5.
⚠️ MI Estimation is Hard in High Dimensions

KNN MI estimators have high variance in \(d \gg 10\). Binning estimators suffer from the curse of dimensionality. For high-dim feature selection, prefer model-based methods (e.g. LASSO, tree importance) alongside MI filters. Use MI primarily when \(d < 100\) per feature or when interpretability matters.
