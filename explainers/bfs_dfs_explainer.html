1
Understanding BFS & DFS
▼

What is graph traversal? A graph is a collection of nodes (vertices) connected by edges. Traversal means visiting every node exactly once in some systematic order. The two canonical strategies are Breadth-First Search (BFS) and Depth-First Search (DFS).

BFS analogy — ripples on water: Drop a stone in a pond. The ripple expands outward in concentric rings, hitting all nodes 1 hop away before any node 2 hops away. BFS works exactly like this: it explores the entire "frontier" at distance \(k\) before advancing to distance \(k+1\).

DFS analogy — exploring a maze: You always walk forward until you hit a dead end, then backtrack to the last junction and try the next corridor. DFS commits fully to one branch before retreating.

If you remember one thing

The data structure IS the algorithm. BFS uses a queue (FIFO) — so it processes the shallowest nodes first, giving shortest paths in unweighted graphs. DFS uses a stack (LIFO, or the call stack via recursion) — so it plunges deep first, enabling topological sort and cycle detection. Both run in \(\mathcal{O}(V+E)\).

BFS — Breadth-First

Explores level by level. Guaranteed shortest path (hop count) in unweighted graphs. Uses a queue. Frontier = all nodes at current depth.

DFS — Depth-First

Dives as deep as possible then backtracks. Uses a stack or recursion. Natural for topological ordering, cycle detection, connected components.

2
Internal Mechanics — Queue vs Stack
▼

BFS: FIFO Queue

BFS maintains a queue of discovered but not yet processed nodes — the "frontier." On each iteration it dequeues the front node \(u\), marks it visited, and enqueues all unvisited neighbors. Because a queue is FIFO, nodes are processed in the exact order they were discovered. Since neighbors of the level-\(k\) node are enqueued after all level-\(k\) nodes but before any level-\((k+2)\) node, BFS naturally processes level by level.

$$\text{BFS invariant: when node } u \text{ is dequeued, } d(s, u) \leq d(s, v) \text{ for all } v \text{ still in queue}$$

DFS: LIFO Stack

DFS maintains a stack. On each iteration it pops the top node \(u\). If unvisited, it marks \(u\) visited and pushes all its unvisited neighbors. Because a stack is LIFO, the most recently discovered neighbor is processed next — DFS always dives deeper before it processes siblings. Recursive DFS uses the call stack implicitly, which is equivalent.

Key Design Decision: Why Queue vs Stack?

Changing the data structure from queue to stack is the only difference between BFS and DFS at the implementation level. The choice of data structure determines whether you explore the shallowest known node next (BFS) or the deepest known node next (DFS). This single change produces profoundly different traversal orders and algorithmic properties.

Visited Marking — Critical Detail

In BFS, nodes must be marked visited when enqueued (not when dequeued) — otherwise the same node could be enqueued multiple times, breaking \(\mathcal{O}(V+E)\). In iterative DFS with a stack, nodes may be pushed multiple times; the visited check at pop time handles duplicates correctly.

Common Bug

Marking BFS nodes visited at dequeue time (instead of enqueue time) can enqueue the same node multiple times, degrading to \(\mathcal{O}(V \cdot E)\) in the worst case on dense graphs. Always mark at enqueue.

3
Why It Works — Correctness & Complexity
▼

Complexity: \(\mathcal{O}(V+E)\)

Both BFS and DFS visit each vertex exactly once (\(\mathcal{O}(V)\) work for the visited set) and inspect each edge exactly twice in an undirected graph — once from each endpoint (\(\mathcal{O}(E)\) total). With an adjacency list representation the sum is \(\mathcal{O}(V+E)\). With an adjacency matrix it degrades to \(\mathcal{O}(V^2)\) because inspecting all neighbors of a vertex takes \(\mathcal{O}(V)\) time.

$$T_{\text{BFS}} = T_{\text{DFS}} = \mathcal{O}(V + E)$$

BFS Shortest-Path Correctness (Proof Sketch)

Claim: BFS computes \(d[v]\) = shortest hop-distance from source \(s\) to all reachable \(v\).

Proof by induction on \(k = d(s,v)\). Base case \(k=0\): \(s\) is enqueued with \(d[s]=0\). Inductive step: Assume all nodes at distance \(\leq k\) get correct labels. Any node \(v\) at distance \(k+1\) has a parent \(u\) at distance \(k\). When \(u\) is dequeued (with correct label), \(v\) is enqueued as \(d[v] = d[u]+1 = k+1\). Since \(v\) cannot have been discovered earlier with a smaller label (no shorter path exists), \(d[v]\) is correct. \(\square\)

$$d[v] = \begin{cases} 0 & \text{if } v = s \\ d[u] + 1 & \text{if } (u,v) \in E \text{ and } u \text{ dequeued with shortest distance} \end{cases}$$

DFS — Topological Order & Cycle Detection

In a directed graph, DFS produces a finish-time ordering: the node that finishes (all descendants explored) last receives the latest finish time. Reversing finish times gives a valid topological order of a DAG. A back edge (an edge to an ancestor on the current DFS stack) witnesses a cycle — so DFS on directed graphs can detect cycles in \(\mathcal{O}(V+E)\).

Space Complexity

BFS space: \(\mathcal{O}(V)\) for the queue — in the worst case (a star graph) all \(V-1\) neighbors are enqueued simultaneously. DFS space: \(\mathcal{O}(H)\) where \(H\) is the maximum recursion/stack depth. For a balanced tree \(H = \mathcal{O}(\log V)\); for a path graph \(H = \mathcal{O}(V)\). BFS is therefore preferable for very deep graphs to avoid stack overflow.

Key Takeaways & When to Use Each
▼
Use BFS when:
  • You need shortest path by hop count (unweighted)
  • Finding all nodes within \(k\) hops of a source
  • Level-order traversal (e.g., print tree by levels)
  • Web crawlers exploring by link depth
  • Social network distance ("degrees of separation")
Use DFS when:
  • Topological sort of a DAG
  • Detecting cycles in directed graphs
  • Finding strongly connected components (Tarjan, Kosaraju)
  • Solving mazes / backtracking problems
  • Tree path problems (root-to-leaf)
Decision Rule

Shortest (unweighted) path? Always BFS. Exploring all paths / structural properties (cycles, ordering)? DFS. For weighted shortest paths use Dijkstra (non-negative) or Bellman-Ford (negative edges allowed).

Classic Applications at a Glance

  • BFS: Bipartite graph check, 0-1 BFS for 0/1-weighted graphs, Multi-source BFS (all fire spreads simultaneously)
  • DFS: Articulation points & bridges (Tarjan), 2-SAT, Euler path existence, Flood fill in images

from collections import deque
# BFS — O(V+E) with adjacency list
def bfs(graph, start):
visited, order = set(), []
queue = deque([start]) # FIFO
visited.add(start)
while queue:
node = queue.popleft() # dequeue front
order.append(node)
for nb in graph[node]:
if nb not in visited:
visited.add(nb)
queue.append(nb) # enqueue back
return order
# DFS — O(V+E) with adjacency list
def dfs(graph, start):
visited, order = set(), []
stack = [start] # LIFO
while stack:
node = stack.pop() # pop top
if node in visited: continue
visited.add(node)
order.append(node)
for nb in reversed(graph[node]):
if nb not in visited:
stack.append(nb) # push
return order
