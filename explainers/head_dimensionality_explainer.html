Head Dimensionality: d_model / n_heads

How multi-head attention splits one big representation into several small ones — and why the split size matters
Foundational Transformers Attention O(n²·d) per head
1
Understanding Head Dimensionality
▼

What is it? Every token in a Transformer is represented by a vector of size \(d_{model}\) (e.g. 512, 768, 4096). Multi-head attention doesn't run one giant attention computation on that whole vector — it slices it into \(h\) smaller pieces, each of size \(d_k = d_{model}/h\), and runs \(h\) independent attention computations in parallel, one per slice ("head"). The results are glued back together (concatenated) and passed through one more linear layer to mix them.

Analogy: Imagine reading a contract with 8 lawyers instead of 1. Give the whole document to a single generalist lawyer (one big head) and they form one broad opinion. Instead, split the document into 8 dimensions of concern — liability, IP, payment terms, etc. — and give each slice to a specialist (\(h\) small heads). Each specialist reads a narrower slice but can focus sharply on their pattern. At the end, a coordinator combines all 8 opinions into a final verdict (the output projection).

💡 If you remember one thing

The identity that governs everything here is $$d_k = \frac{d_{model}}{h}$$ Splitting into more heads means each head sees a narrower subspace — you trade the depth of any one attention pattern for the diversity of many simultaneous ones, at (almost) no extra parameter or compute cost.

2
How It Works Internally
▼

From one vector to h heads

Given token embeddings \(X \in \mathbb{R}^{n \times d_{model}}\), we first apply three learned projections \(W^Q, W^K, W^V \in \mathbb{R}^{d_{model}\times d_{model}}\) to get \(Q, K, V \in \mathbb{R}^{n \times d_{model}}\). Instead of allocating separate weight matrices per head, in practice \(Q\) is simply reshaped: the last axis of size \(d_{model}\) is split into \(h\) contiguous (or strided) chunks of size \(d_k = d_{model}/h\), producing \(Q_1, \dots, Q_h \in \mathbb{R}^{n\times d_k}\). Reshaping a big projection is mathematically equivalent to having \(h\) separate, smaller projection matrices \(W_i^Q \in \mathbb{R}^{d_{model}\times d_k}\) — it is just implemented as one matmul plus a reshape for GPU efficiency.

Independent attention per head, then merge

Each head computes its own scaled dot-product attention entirely inside its \(d_k\)-dimensional subspace: \(\text{head}_i = \text{softmax}\!\left(\frac{Q_iK_i^\top}{\sqrt{d_k}}\right)V_i\). Because the heads never see each other's subspace during the attention computation, they are free to specialize — one head might learn positional/local patterns, another might track syntactic dependencies, another semantic similarity. The \(h\) outputs (each \(n \times d_k\)) are concatenated back into \(n \times d_{model}\) and passed through a final output projection \(W^O \in \mathbb{R}^{d_{model}\times d_{model}}\) that mixes information across heads.

Design decision: why not one head with \(d_k = d_{model}\)?

A single head with the full \(d_{model}\) dimensionality can only produce one softmax attention distribution per query — one "lens" on the sequence. Splitting into \(h\) heads gives \(h\) independently-normalized attention distributions computed at essentially the same total compute and parameter budget, because the projection matrices are the same total size either way. This is the core justification from Vaswani et al. (2017): multi-head attention lets the model jointly attend to information from different representation subspaces at different positions, something a single softmax cannot do (a single softmax averages, it cannot represent two very different attention patterns simultaneously).

🔑 Key Property

Total attention-projection parameters — \(W^Q, W^K, W^V, W^O\) combined — are independent of \(h\): they always total \(4 \cdot d_{model}^2\). Changing \(h\) only changes how that fixed budget is partitioned across parallel subspaces, not how large it is.

3
Why It Works — The Math
▼

Parameter-count invariance

Let \(d_{model}\) be fixed and \(h\) be the number of heads with \(d_k = d_{model}/h\). Whether implemented as one big matrix or \(h\) small ones, the query projection has the same number of scalars:

$$\underbrace{d_{model}\times d_{model}}_{\text{one big }W^Q} \;=\; \underbrace{h \times (d_{model}\times d_k)}_{\text{h small } W_i^Q,\ d_k = d_{model}/h}$$

The right-hand side is \(h \cdot d_{model}\cdot(d_{model}/h) = d_{model}^2\) — identical to the left-hand side for any valid \(h\). This is why increasing \(h\) is "almost free": it does not grow the parameter count of \(W^Q,W^K,W^V,W^O\), it only changes how the same budget is split into parallel subspaces.

Compute cost of scaled dot-product attention per head

For one head, computing \(Q_iK_i^\top\) costs \(O(n^2 d_k)\); summed over \(h\) heads that is \(O(h \cdot n^2 d_k) = O(n^2 \cdot h \cdot \tfrac{d_{model}}{h}) = O(n^2 d_{model})\) — again independent of \(h\). The \(\sqrt{d_k}\) scaling in the denominator of the softmax logits exists precisely because \(d_k\) shrinks as \(h\) grows:

$$\text{score} = \frac{Q_iK_i^\top}{\sqrt{d_k}}$$

Without this scaling, dot products of \(d_k\)-dimensional random vectors have variance \(\propto d_k\); large \(d_k\) (few heads) pushes logits into the saturated tails of softmax, killing gradients. Dividing by \(\sqrt{d_k}\) keeps the pre-softmax variance at \(\approx 1\) regardless of how large or small each head is.

⚠️ Common Pitfall

\(d_{model}\) must be exactly divisible by \(h\) — \(d_k = d_{model}/h\) has to be an integer, otherwise the reshape into heads is undefined. This is why architecture configs pick round numbers: e.g. GPT-2 uses \(d_{model}=768,\ h=12 \Rightarrow d_k=64\); GPT-3 175B uses \(d_{model}=12288,\ h=96 \Rightarrow d_k=128\). If \(d_k\) becomes too small (e.g. \(d_k=1\) or \(2\)), each head has almost no room to represent a rich similarity function — attention degenerates toward near-uniform or near-one-hot patterns.

Key Takeaways
▼

When more heads (smaller \(d_k\)) helps:

  • The sequence exhibits multiple distinct relational patterns (syntax, coreference, position) that a single softmax cannot represent at once
  • You want redundancy/robustness — pruning studies show many heads are partially redundant, so extra heads add resilience
  • \(d_{model}\) is large enough that even a narrow \(d_k\) still has enough capacity per head

When fewer heads (larger \(d_k\)) helps:

  • \(d_{model}\) is small, so splitting too finely leaves each head with almost no representational capacity (\(d_k \to 1\) is nearly useless)
  • The task needs one sharp, high-resolution similarity function rather than many coarse ones
  • Latency-critical serving where per-head kernel-launch overhead matters more than representational diversity
💡 Rule of Thumb

Modern LLMs typically keep \(d_k \in [64, 128]\) roughly constant and scale \(h\) up as \(d_{model}\) grows (e.g. GPT-2: \(d_k{=}64\); LLaMA-2 70B: \(d_k{=}128\)) — treating head dimension, not head count, as the more stable design knob.

Code Trace
▼
import numpy as np
# d_model = 8, h = 4 => d_k = 2
d_model, h = 8, 4
d_k = d_model // h # 2 -- must divide evenly
# X: (n_tokens, d_model) embeddings; Wq/Wk/Wv: (d_model, d_model)
Q = X @ Wq # (n, d_model)
K = X @ Wk
V = X @ Wv
# split into heads: reshape, don't copy weights
def split_heads(t, h, d_k):
n = t.shape[0]
return t.reshape(n, h, d_k).transpose(1, 0, 2) # (h, n, d_k)
Qh, Kh, Vh = split_heads(Q,h,d_k), split_heads(K,h,d_k), split_heads(V,h,d_k)
# attention independently per head
def softmax(z):
z = z - z.max(axis=-1, keepdims=True)
e = np.exp(z)
return e / e.sum(axis=-1, keepdims=True)
scores = Qh @ Kh.transpose(0,2,1) / np.sqrt(d_k) # (h, n, n)
weights = softmax(scores)
head_out = weights @ Vh # (h, n, d_k)
# concat heads back to d_model, then mix with Wo
concat = head_out.transpose(1,0,2).reshape(-1, d_model) # (n, d_model)
output = concat @ Wo # (n, d_model)
