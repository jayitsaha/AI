Dependency & Constituency Parsing

Unpacking sentence structure for Natural Language Understanding
Foundational NLP Intermediate
1
Understanding Sentence Structure
▼

What is it? Parsing in Natural Language Processing (NLP) is the process of analyzing a sentence to determine its grammatical structure. This structure is crucial for understanding the meaning of a sentence, as words rarely convey meaning in isolation; their relationships and groupings are key.

There are two primary paradigms for syntactic parsing: Constituency Parsing (also known as phrase-structure parsing) and Dependency Parsing. Both aim to represent the grammatical relationships between words, but they do so using different formalisms and emphasize different aspects of sentence structure.

Analogy: Imagine a building. Constituency parsing is like identifying the rooms, floors, and sections – larger structural units. Dependency parsing is like tracing the load-bearing beams and supports, showing which parts directly hold up or modify other parts. Both are valid ways to describe the building, but they highlight different aspects of its construction.

💡 If you remember one thing

Constituency parsing groups words into nested, hierarchical phrases (like Noun Phrases, Verb Phrases), forming a tree where internal nodes are phrase types. Dependency parsing identifies direct grammatical relationships between individual words (head-dependent pairs), forming a directed graph.

2
How Each Parsing Type Works
▼

Constituency Parsing: Hierarchical Phrases

Constituency parsing breaks down a sentence into its constituent phrases. It produces a parse tree where the leaves are the words of the sentence, and the internal nodes are non-terminal categories representing syntactic constituents (e.g., S for Sentence, NP for Noun Phrase, VP for Verb Phrase, PP for Prepositional Phrase). These trees are typically unordered, meaning the order of children nodes doesn't imply anything about word order, only their grouping.

Common approaches include:

  • Context-Free Grammars (CFG): A set of production rules (e.g., \(S \to NP \ VP\)) define how symbols can be rewritten. Parsers (like CKY or Earley algorithms) search for a sequence of rules that derive the sentence.
  • Probabilistic Context-Free Grammars (PCFG): Assign probabilities to CFG rules, allowing the parser to find the most probable parse tree.
  • Neural Parsers: Modern approaches use deep learning models (e.g., LSTMs, Transformers) to predict parse trees, often trained end-to-end on treebanks.

Dependency Parsing: Head-Dependent Relations

Dependency parsing focuses on binary, asymmetrical grammatical relationships between words. For each word (except the root, usually the main verb), there is a single "head" word that it modifies or depends on. The relationship is labeled (e.g., `nsubj` for nominal subject, `obj` for object, `amod` for adjective modifier). The output is a directed graph where nodes are words and edges are labeled dependencies.

Key characteristics of dependency graphs:

  • Every word (except the root) has exactly one head.
  • There are no cycles.
  • The graph is connected.

Common approaches include:

  • Transition-based Parsers: Use a sequence of actions (shift, reduce, attach) to build the dependency tree, often guided by a classifier.
  • Graph-based Parsers: Score all possible dependency edges and then find the highest-scoring tree (e.g., using algorithms like Eisner's algorithm).
  • Neural Parsers: Similar to constituency parsing, neural models are now state-of-the-art, learning to predict dependencies directly.
🔑 Key Difference

Constituency parsing focuses on phrases as compositional units, while dependency parsing focuses on grammatical relations between individual words. Constituency trees are typically unordered and represent hierarchical groupings; dependency trees are directed graphs showing head-dependent links.

3
Formalisms & Algorithms
▼

Context-Free Grammars (CFG) for Constituency

A CFG is a 4-tuple \(G = (N, \Sigma, R, S)\) where:

  • \(N\) is a finite set of non-terminal symbols (e.g., S, NP, VP).
  • \(\Sigma\) is a finite set of terminal symbols (the words).
  • \(R\) is a finite set of production rules of the form \(A \to \beta\), where \(A \in N\) and \(\beta \in (N \cup \Sigma)^*\).
  • \(S \in N\) is the start symbol (usually 'S' for Sentence).

A sentence \(w_1 w_2 \dots w_n\) is parsed by finding a derivation from \(S\) to the sentence using the rules in \(R\). For example:

$$S \to NP \ VP$$ $$NP \to Det \ Noun$$ $$VP \to Verb \ NP$$ $$Det \to \text{`the'}$$ $$Noun \to \text{`dog'}$$ $$Verb \to \text{`chased'}$$

Parsing algorithms like CKY build a parse table, filling cells with non-terminals that can span a substring. The complexity is typically \(O(n^3 |G|)\) for a sentence of length \(n\) and grammar size \(|G|\).

Dependency Graph Formalism

A dependency tree for a sentence \(w_0, w_1, \dots, w_n\) (where \(w_0\) is an artificial ROOT symbol) is a directed graph \(D = (V, A)\) where:

  • \(V = \{w_0, w_1, \dots, w_n\}\) is the set of words.
  • \(A \subseteq V \times V\) is the set of directed arcs (dependencies), each labeled with a grammatical relation.

The graph must satisfy:

  1. Exactly one node (the root) has no incoming arcs.
  2. All other nodes have exactly one incoming arc.
  3. There are no cycles.
  4. The graph is connected.

These properties ensure it's a tree rooted at \(w_0\). The goal of a dependency parser is to find the set of arcs \(A\) and their labels that best describe the sentence. For graph-based parsers, this often involves maximizing a score function:

$$T^* = \underset{T \in \mathcal{T}(S)}{\operatorname{argmax}} \sum_{(h,d,l) \in T} \operatorname{score}(h, d, l)$$

where \(\mathcal{T}(S)\) is the set of all valid dependency trees for sentence \(S\), and \(\operatorname{score}(h, d, l)\) is a function estimating the likelihood of a head \(h\), dependent \(d\), and label \(l\) forming a dependency. This maximization can be solved efficiently using dynamic programming (e.g., Eisner's algorithm for projective trees).

➗ Mathematical Equivalence

While different, constituency and dependency representations are often interconvertible. Many dependency formalisms can be derived from phrase-structure trees by defining a "head-finding" rule for each phrase type (e.g., in an NP, the Noun is usually the head). This highlights their complementary nature in describing syntax.

Key Takeaways & Applications
▼

When to use which parsing type:

  • Constituency Parsing: Useful when you need to identify complete phrases as units. This is often preferred for tasks that require understanding nested grammatical structures, such as grammar checking, machine translation (where phrase alignment is important), or generating natural language. It provides a more abstract, high-level view of sentence organization.
  • Dependency Parsing: Often favored for tasks that rely on understanding direct semantic and grammatical relationships between words. This includes information extraction (e.g., finding subject-verb-object triples), sentiment analysis (identifying what word modifies a sentiment-bearing word), question answering, and coreference resolution. Its focus on head-dependent relations can be more intuitive for many downstream NLP tasks.

Advantages & Disadvantages:

  • Constituency: Provides a clear hierarchy, aligns well with traditional linguistic theory. Can be harder to interpret for direct semantic relations.
  • Dependency: More direct representation of grammatical functions, often simpler and more robust across languages (especially free word order languages). Can sometimes miss higher-level phrase groupings.
💡 Complementary Views

Neither parsing type is inherently "better"; they offer complementary views of sentence structure. Modern NLP systems often use features derived from both types of parses, or choose one based on the specific requirements of the downstream task.

Code Trace (Conceptual)
▼

This conceptual Python code snippet illustrates how one might represent and process parsing results, rather than implementing a full parser.

import spacy
# Initialize a spaCy model for English
nlp = spacy.load("en_core_web_sm")
def parse_sentence(text):
doc = nlp(text)
# --- Dependency Parsing ---
dependencies = []
for token in doc:
head_text = token.head.text if token.head != token else "ROOT"
dependencies.append({
"dependent": token.text,
"head": head_text,
"relation": token.dep_,
"dep_idx": token.i,
"head_idx": token.head.i if token.head != token else -1 # -1 for ROOT
})
# --- Constituency Parsing (simplified representation) ---
# spaCy does not directly output constituency trees, but we can approximate
# by extracting noun chunks and verb phrases.
constituents = []
for chunk in doc.noun_chunks:
constituents.append({"label": "NP", "text": chunk.text, "start": chunk.start, "end": chunk.end})
# For a full constituency tree, a dedicated library or parser would be used.
# E.g., NLTK's `nltk.tree.Tree.fromstring` for Penn Treebank format.
return {"dependencies": dependencies, "constituents": constituents}
# Example usage
sentence = "The quick brown fox jumps over the lazy dog."
parsed_data = parse_sentence(sentence)
