Intermediate Calibration Classical ML Single parameter

Understanding the Concept
▾

What is temperature scaling? A deep neural network trained with cross-entropy loss is often overconfident: it outputs softmax probabilities like 0.97 even when it's only right ~80% of the time. Temperature scaling fixes this with a single, elegant trick — divide every logit by a positive number \(T\) before applying softmax. Nothing else changes: the model weights, the argmax prediction, and the accuracy all stay identical.

Key Insight

Temperature scaling is the simplest possible calibration: it learns one scalar \(T > 0\) on a held-out validation set by minimising Negative Log-Likelihood (NLL). When \(T > 1\) the distribution softens (confidence decreases); when \(T < 1\) it sharpens. The argmax — and therefore accuracy — is invariant to \(T\).

Real-world analogy. Imagine a student who says "I'm 99% sure the answer is A" on every question. Temperature scaling is like telling the student: "Tone it down — you're right about 75% of the time when you say that." After calibration the student says "I'm 76% sure" instead, which is much more honest and useful for downstream decisions like buying insurance or diagnosing a disease.

If You Remember One Thing

\(\hat{p}_k = \text{softmax}(\mathbf{z}/T)_k\). Tune \(T\) on val NLL. Accuracy unchanged. Done.

How does overconfidence arise?

Modern NNs trained with cross-entropy minimise \(-\log p_y\), which is maximised when \(p_y \to 1\). With large model capacity, weight decay, and batch normalisation, the network learns to push logit gaps wider and wider to lower training loss — even past the point where the confidences reflect true frequencies. The result: a reliability diagram that bows far below the diagonal.

How Temperature Scaling Works
▾

Step-by-step computation

Given a trained classifier with frozen weights, the forward pass for a single example produces a logit vector \(\mathbf{z} \in \mathbb{R}^K\). Temperature scaling inserts one operation:

$$\hat{p}_k = \frac{\exp(z_k / T)}{\sum_{j=1}^{K} \exp(z_j / T)}, \quad k = 1,\ldots,K$$

The temperature \(T\) is then learned — not by backprop through the network — but by scalar optimisation on the validation set:

$$T^* = \underset{T > 0}{\operatorname{argmin}} \; \mathcal{L}_{\text{NLL}}(T) = -\frac{1}{N}\sum_{i=1}^{N} \log \hat{p}_{y_i}(T)$$

\(\mathcal{L}_{\text{NLL}}(T)\) is convex in \(T\) (see math card), so a single L-BFGS call converges instantly.

Why it preserves accuracy

Dividing all logits by \(T > 0\) is a monotone transformation: \(z_i > z_j \Leftrightarrow z_i/T > z_j/T\). So the argmax — the class with the highest logit — never changes. Accuracy (a function of argmax) is therefore exactly the same before and after calibration.

Common Misconception

Temperature scaling does NOT change accuracy. If calibration worsens or improves accuracy, something is wrong — you may be applying it before argmax on a multi-label or ranking task.

Numerical example (4 classes)

Raw logits: \(\mathbf{z} = [3.2,\ 1.5,\ 0.8,\ -0.6]\). The true class is 0.

Uncalibrated (T=1): softmax gives \([0.817, 0.120, 0.058, 0.014]\). Confidence = 81.7%.

After T=2.5: scaled logits \([1.28, 0.60, 0.32, -0.24]\), softmax \([0.459, 0.235, 0.175, 0.100]\). Confidence drops to 45.9% — much closer to the true accuracy of ~50% for examples at this logit magnitude.

Argmax in both cases = class 0. Accuracy unchanged.

The Math — Convexity & Calibration
▾

NLL as a function of T

Fix a validation set of \(N\) examples with one-hot targets. Define the NLL loss as a function of scalar \(T\):

$$\mathcal{L}(T) = -\frac{1}{N}\sum_{i=1}^{N} \log \text{softmax}(\mathbf{z}_i/T)_{y_i}$$

Expanding the softmax log:

$$\mathcal{L}(T) = -\frac{1}{N}\sum_{i=1}^{N}\!\left[\frac{z_{i,y_i}}{T} - \log\!\sum_{j}\exp\!\left(\frac{z_{ij}}{T}\right)\right]$$

Convexity

The function \(t \mapsto \log\sum_j \exp(a_j t)\) (where \(t = 1/T\)) is convex in \(t\) (it is a log-sum-exp of linear functions of \(t\)). The linear term \(-z_{i,y_i} t\) is affine. Their sum is therefore convex. This means the optimisation has no local minima — any gradient-based or line-search method finds the global optimum.

Key Convexity Result

\(\mathcal{L}(T)\) is strictly convex in \(1/T\), so the unique minimiser \(T^*\) can be found by a single L-BFGS or bisection call. No random restarts needed.

Gradient w.r.t. T

$$\frac{d\mathcal{L}}{dT} = \frac{1}{N T^2}\sum_{i=1}^{N}\!\left[z_{i,y_i} - \sum_j \hat{p}_{ij} z_{ij}\right]$$

Setting this to zero and solving (numerically) yields \(T^*\). Note the bracketed term is the residual of the true-class logit minus the expected logit under \(\hat{p}\). When the model is already calibrated, this averages to zero, giving \(T=1\).

ECE connection

Expected Calibration Error (ECE) measures the gap between confidence and accuracy in equal-frequency bins. NLL minimisation and ECE minimisation are not identical objectives, but empirically minimising NLL (proper scoring rule) produces well-calibrated probabilities in the ECE sense as well — this was validated extensively in Guo et al. 2017.

Limits

$$\lim_{T \to 0^+} \text{softmax}(\mathbf{z}/T) = \mathbf{e}_{k^*} \quad \text{(one-hot on argmax)}$$
$$\lim_{T \to \infty} \text{softmax}(\mathbf{z}/T) = \frac{1}{K}\mathbf{1} \quad \text{(uniform)}$$

Code Implementation
▾

From Scratch (NumPy)

import numpy as np
from scipy.optimize import minimize_scalar

def softmax_temp(logits, T=1.0):
    """Numerically stable softmax with temperature scaling."""
    z = logits / T
    z = z - z.max(axis=-1, keepdims=True)  # subtract max for stability
    e = np.exp(z)
    return e / e.sum(axis=-1, keepdims=True)

def nll_loss(T, logits, labels):
    """Scalar NLL as a function of temperature T."""
    probs = softmax_temp(logits, T)
    # gather probability of true class for each example
    true_probs = probs[np.arange(len(labels)), labels]
    return -np.log(true_probs + 1e-12).mean()

def find_temperature(val_logits, val_labels):
    """Find T* on validation set via golden-section search (convex)."""
    result = minimize_scalar(
        lambda T: nll_loss(T, val_logits, val_labels),
        bounds=(0.05, 20.0),
        method='bounded'
    )
    return result.x  # T*

# ── Example usage ─────────────────────────────────────────────────────────────
# val_logits: (N, K) float array from frozen model
# val_labels: (N,)  int array of true class indices

T_star = find_temperature(val_logits, val_labels)
print(f"Optimal T = {T_star:.4f}")

# At inference time — replace softmax(logits) with:
calibrated_probs = softmax_temp(test_logits, T_star)

Production (PyTorch + netcal)

import torch
import torch.nn.functional as F
from netcal.scaling import TemperatureScaling  # pip install netcal

# ── Option A: netcal library ──────────────────────────────────────────────────
calibrator = TemperatureScaling()
calibrator.fit(val_logits_np, val_labels_np)   # numpy arrays
calibrated = calibrator.transform(test_logits_np)

# ── Option B: pure PyTorch (12 lines, no dependency) ─────────────────────────
class TempScaling(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.log_T = torch.nn.Parameter(torch.zeros(1))  # log T for positivity

    def forward(self, logits):
        return logits / self.log_T.exp()

model.eval()
temp_model = TempScaling()
optimizer = torch.optim.LBFGS([temp_model.log_T], lr=0.01, max_iter=500)

with torch.no_grad():
    val_logits_t = model(val_inputs)  # (N, K) — frozen

def closure():
    optimizer.zero_grad()
    loss = F.cross_entropy(temp_model(val_logits_t), val_labels)
    loss.backward()
    return loss

optimizer.step(closure)
T_star = temp_model.log_T.exp().item()
print(f"T* = {T_star:.4f}")

# ⚠️  Gotcha: use .eval() on the backbone BEFORE collecting val logits.
# BatchNorm in train mode gives different activations → wrong T*.
# ⚠️  Gotcha: LBFGS needs a closure. SGD also works but slower to converge.
Gotchas

1. Always freeze backbone weights before fitting T — if you train them jointly the model re-overfits.

2. Use the same preprocessing (model.eval(), same normalization) for val logits as for test logits.

3. T is specific to the model+dataset pair. Refit T after fine-tuning.

Decision Rule

Try temperature scaling first — it's the simplest, most robust, and matches or beats more complex methods on most NN benchmarks (Guo et al. 2017). Only escalate to vector/matrix scaling if class-level miscalibration is detected in your reliability diagram.

When temperature scaling fails

  • Distribution shift: T fitted on val may not transfer to a shifted test distribution.
  • Class-conditional miscalibration: Different classes may need different T values — use class-wise temperature or vector scaling.
  • Selective prediction / abstention: If you reject low-confidence examples, temperature scaling may not produce optimal reject curves.
  • Very small val sets: Fewer than ~500 examples → T estimate is noisy; use cross-val T fitting.
