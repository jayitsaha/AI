Embedding Evaluation

How do we know if word/sentence embeddings are actually good? Intrinsic proxies vs. extrinsic ground truth
Intermediate NLP Representation Learning Evaluation Methodology
1
Understanding Embedding Evaluation
▼

What is it? You've trained (or downloaded) word embeddings — every word is now a vector of numbers. But how do you know if they're any good? Embedding evaluation is the set of tests we run to score embedding quality, split into two families: intrinsic tests (probe the geometry of the vector space directly, e.g. "does king − man + woman land near queen?") and extrinsic tests (plug the embeddings into a real downstream model — sentiment classifier, NER tagger — and measure task accuracy).

Analogy: Intrinsic evaluation is like judging a chef by having them plate a single dish in a lab and tasting it — fast, cheap, controlled. Extrinsic evaluation is opening the restaurant and watching whether customers actually come back. A dish that tastes great in the lab might still fail in a chaotic dinner rush; the lab test is a useful proxy, but the restaurant is the real verdict.

💡 If you remember one thing

Intrinsic scores (analogy accuracy, WordSim/SimLex correlation) are fast, cheap proxies computed directly from vector geometry — cosine similarity and vector arithmetic. Extrinsic scores (F1, accuracy on a real task) are the ground truth, but slow and expensive to obtain. The two frequently disagree, so neither alone is sufficient.

2
How Evaluation Works Internally
▼

Intrinsic Test 1: Word Analogies

Analogy tasks (popularized by the original word2vec paper) ask: given a : b :: c : ?, can vector arithmetic recover d? Concretely, compute \(v = \text{vec}(b) - \text{vec}(a) + \text{vec}(c)\), then search the entire vocabulary for the word whose vector has the highest cosine similarity to \(v\) (excluding \(a, b, c\) themselves — "3CosAdd"). If the nearest neighbor is \(d\), the analogy is scored correct. Accuracy is the fraction of correct analogies over a curated test set (e.g. Google's ~19,000-question analogy set covering capitals, gender, verb tense, and morphology).

Intrinsic Test 2: Similarity Benchmarks

Datasets like WordSim-353 and SimLex-999 contain word pairs rated by humans on a similarity scale (e.g. "car" and "automobile" score high; "car" and "cloud" score low). For each pair we compute the model's cosine similarity, rank all pairs by human score and by model score, then compute Spearman rank correlation \(\rho\) between the two rankings. A high \(\rho\) means the model's notion of "close in vector space" matches human intuition. SimLex-999 is stricter than WordSim-353 because it separates true similarity ("cat"/"dog" are related but not similar) from mere relatedness.

Extrinsic Test: Downstream Task Performance

Freeze the embeddings, feed them into a simple downstream model (linear classifier, small MLP, CRF for NER), train on a labeled task, and measure the task metric directly — accuracy, F1, BLEU. This is expensive (needs labeled data + training loops) but it's the only test that measures what actually matters: does the representation help the application you care about?

🔑 Key Property

Intrinsic tests are task-agnostic geometric proxies; extrinsic tests are task-specific ground truth. Because intrinsic tests never touch the downstream model, a strong analogy score is only a hypothesis that the embeddings are useful — not a guarantee.

3
Why It Works — The Math
▼

Cosine Similarity — the workhorse metric

Both intrinsic tests reduce to comparing vectors with cosine similarity, which measures the angle between two vectors, ignoring magnitude:

$$\cos(\mathbf{u}, \mathbf{v}) = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\|\,\|\mathbf{v}\|} = \frac{\sum_i u_i v_i}{\sqrt{\sum_i u_i^2}\sqrt{\sum_i v_i^2}}$$

Values range from \(-1\) (opposite) to \(1\) (identical direction). Magnitude is discarded because embedding vector length is often an artifact of word frequency, not meaning.

The Analogy Objective (3CosAdd)

Given \((a,b,c)\) with expected answer \(d\), the classic Mikolov et al. (2013) formulation finds:

$$\hat{d} = \underset{w \,\in\, V \setminus \{a,b,c\}}{\operatorname{argmax}} \; \cos\big(\text{vec}(w),\; \text{vec}(b) - \text{vec}(a) + \text{vec}(c)\big)$$

The analogy is correct iff \(\hat{d} = d\). This works only if the relation "\(a \to b\)" corresponds to a roughly consistent offset vector across many word pairs — i.e. the embedding space is locally linear along that relation.

Spearman Rank Correlation

For similarity benchmarks, we don't compare raw scores (human ratings and cosine similarities live on different scales) — we compare rankings. Convert both the human scores and the model's cosine similarities to ranks, then:

$$\rho = 1 - \frac{6 \sum_{i=1}^n d_i^2}{n(n^2 - 1)}, \qquad d_i = \text{rank}(h_i) - \text{rank}(s_i)$$

where \(h_i\) is the human score and \(s_i\) is the model's cosine similarity for pair \(i\). \(\rho \to 1\) means perfect rank agreement; \(\rho \to 0\) means no relationship.

⚠️ Common Pitfall

A model can achieve a high analogy score but low downstream performance, or vice versa. Analogy accuracy rewards a very specific kind of linear structure that mostly shows up in frequency-balanced, syntactic/semantic relations — it says little about how well the vectors separate classes for an arbitrary classifier. Never ship on intrinsic numbers alone.

When to use intrinsic evaluation:

  • Quick sanity check after training a new embedding (did anything break?)
  • Comparing many hyperparameter settings cheaply before committing to expensive downstream runs
  • Debugging — e.g. confirming gender/tense/plural relations are captured

When you MUST use extrinsic evaluation:

  • Final decision on which embedding to ship to production
  • When the downstream task is very different from generic semantic similarity (e.g. legal or biomedical NER)
  • Any time intrinsic and extrinsic scores are known to diverge for your domain
💡 Best Practice

Use intrinsic tests to filter quickly (discard clearly broken embeddings), then always confirm the final choice with extrinsic evaluation on the task you actually care about. Never select a production embedding on analogy accuracy alone.
