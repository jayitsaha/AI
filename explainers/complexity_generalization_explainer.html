The bias–variance tradeoff, overfitting, underfitting, and the double-descent phenomenon

Goldilocks principle: a model must be neither too simple nor too complex — it must be just right to generalise well.

Imagine training a model to recognise handwritten digits. A model so simple (linear) it can't even capture the curves in the digits fails on both training data and new data — that's underfitting. A model so complex (1000-degree polynomial) that it memorises every quirk of each training image will score perfectly on training but fail completely on new images — that's overfitting.

Between these two failure modes lies a sweet spot: a model complex enough to capture the real patterns but simple enough not to memorise noise. Finding that sweet spot is the central challenge of model selection.

Key intuition: generalisation error = error on unseen data. Always evaluate on a held-out test set you never touched during training.

Underfitting (High Bias)

A model with insufficient capacity cannot represent the underlying function \(f(x)\). It makes systematic errors — the predictions are consistently wrong in a predictable direction. Training error and test error are both high. Adding more data doesn't help much; you need more capacity.

Overfitting (High Variance)

A model with too much capacity fits the training data (including its noise) exactly, but the fitted function oscillates wildly between data points. Small changes in training data produce drastically different models. Training error is near zero; test error is high.

Bias–Variance Decomposition

The expected generalisation error decomposes into three orthogonal sources:

  • Bias² — systematic error from wrong model assumptions
  • Variance — sensitivity to fluctuations in training data
  • σ² (irreducible noise) — inherent randomness in the data

Increasing complexity reduces bias but increases variance. The optimal point minimises their sum.

Capacity Control Methods

  • Regularisation — add penalty \(\lambda \|\theta\|^2\) (ridge) or \(\lambda \|\theta\|_1\) (lasso) to the loss
  • Early stopping — halt training when validation error starts rising
  • Cross-validation — k-fold CV to estimate generalisation error and tune hyperparameters
  • Dropout / data augmentation — stochastic regularisation for neural networks
  • Pruning / feature selection — reduce effective model capacity post-hoc
Rule of thumb: start simple, then add complexity only when validation error is still decreasing.

Bias–Variance Decomposition

For a squared-error regression problem with true function \(f(x)\) and noise \(\varepsilon \sim \mathcal{N}(0, \sigma^2)\):

$$\mathbb{E}\!\left[(y - \hat{y})^2\right] = \underbrace{\mathrm{Bias}^2[\hat{y}]}_{\text{systematic}} + \underbrace{\mathrm{Var}[\hat{y}]}_{\text{sensitivity}} + \underbrace{\sigma^2}_{\text{irreducible}}$$

where the bias and variance terms are:

$$\mathrm{Bias}^2[\hat{y}] = \left(\mathbb{E}[\hat{y}] - f(x)\right)^2$$
$$\mathrm{Var}[\hat{y}] = \mathbb{E}\!\left[(\hat{y} - \mathbb{E}[\hat{y}])^2\right]$$

The expectation \(\mathbb{E}[\cdot]\) is taken over all possible training sets of size \(n\) drawn from the data distribution. Bias measures how wrong our model is on average; variance measures how much it fluctuates.

Regularised Empirical Risk

Ridge regression minimises:

$$\hat{\theta} = \arg\min_\theta \frac{1}{n}\sum_{i=1}^n \ell(y_i, f_\theta(x_i)) + \lambda \|\theta\|_2^2$$

Larger \(\lambda\) → stronger regularisation → higher bias, lower variance. Cross-validation selects the \(\lambda\) that minimises held-out error.

Capacity Measures

  • VC dimension \(d_{\text{VC}}\): the largest set of points a model class can shatter (label in every possible way). The generalisation bound \(\mathbb{E}[\text{test error}] \leq \hat{\text{err}}_{\text{train}} + O\!\left(\sqrt{d_{\text{VC}}/n}\right)\) shows that high capacity requires exponentially more data.
  • Rademacher complexity \(\mathcal{R}_n(\mathcal{F})\): a data-dependent measure of how well the function class \(\mathcal{F}\) can correlate with random \(\pm 1\) labels. Tighter than VC bounds in practice.
Both VC dimension and Rademacher complexity decrease (effectively) when you add regularisation — shrinking the hypothesis space to lower-capacity subsets.

When to Add Complexity

  • Training error and test error are both high → you are underfitting → add capacity
  • Training error is low but test error is high → overfitting → regularise or get more data
  • Both errors are low and similar → you are in the sweet spot
  • Test error on validation set has plateaued → don't add more complexity

Capacity Control Checklist

  • Always split data: train / validation / test (never touch test until final eval)
  • Plot learning curves: train and val error vs training set size
  • Use k-fold cross-validation for hyperparameter search
  • Apply L2 or L1 regularisation; tune λ via CV
  • For trees: tune max_depth, min_samples_leaf
  • For NNs: use dropout, weight decay, early stopping, batch norm
  • Monitor train–test error gap: closing gap = generalisation improving
  • Remember: more data often beats a fancier model

The Double Descent Caveat

In modern deep learning, extremely over-parameterised models (parameters ≫ data points) often generalise surprisingly well — especially with implicit regularisation from SGD and its noise. The classical U-curve is real but only captures the first regime; the full picture is a double-descent curve.

Bottom line: the bias–variance tradeoff is the fundamental lens for understanding generalisation in classical ML. In the modern regime, the tradeoff still operates but is shaped by implicit regularisation and the structure of over-parameterised landscapes.
