Group K-Fold Cross-Validation

Keeping all rows of a group in the same fold to prevent data leakage
Intermediate Classical ML Model Selection O(n) split
1
Understanding Group K-Fold
▼

What is it? Standard k-fold cross-validation randomly shuffles all rows into k buckets. That works fine when every row is independent. But what if your data comes from patients, users, or sessions — where multiple rows share the same person? If patient 7's Tuesday visit lands in training and their Wednesday visit lands in the test fold, the model has already "seen" that patient. The validation score becomes inflated — it measures memorisation, not generalisation.

Group K-Fold fixes this with one rule: every row belonging to a group must end up in exactly one fold. Groups never straddle train/test boundaries, so the test fold contains only patients the model has never seen during training.

Analogy: Imagine you're training a tutor AI on student homework. Standard k-fold might put 8 of Alice's 10 homework problems in training and 2 in the test set. The AI has already learned Alice's writing style, so the test score is misleadingly high. Group k-fold says: "Alice is either entirely in training or entirely in testing — never split." The tutor is tested on entirely new students, which is the real challenge.

💡 If you remember one thing

Group K-Fold assigns each group (not each row) to exactly one fold. All rows of that group follow along. This guarantees the test fold is truly unseen groups — eliminating within-group leakage that inflates CV scores.

2
How Group K-Fold Works Internally
▼

The Algorithm

Let \(G = \{g_1, g_2, \ldots, g_m\}\) be the set of unique groups, and \(k\) be the number of folds. The procedure is:

  1. Collect the unique groups from the groups array.
  2. Assign each group to one of the \(k\) folds (round-robin or sorted-count assignment to balance fold sizes).
  3. For fold \(i\): test = all rows whose group is in fold \(i\); train = all rows whose group is NOT in fold \(i\).
  4. Repeat for each fold \(i = 1, \ldots, k\).

Why Groups Determine the Split — Not Rows

The key invariant is: group membership is the unit of independence. If we assume observations within a group are correlated (same patient, same session, same user), then the model can only generalise to new groups, not new rows from old groups. Splitting on groups makes the evaluation task match the deployment task.

🔑 Key Invariant

For any two rows \(r_i, r_j\) with the same group label \(g\): they are always in the same fold. Formally, if \(\text{group}(r_i) = \text{group}(r_j)\) then \(\text{fold}(r_i) = \text{fold}(r_j)\).

Fold Size Balance

sklearn's implementation sorts groups by count (number of rows) descending, then assigns them to folds using a greedy bin-packing heuristic. This tends to balance the total number of rows across folds, though perfect balance is NP-hard in general. The number of groups per fold will be approximately \(\lfloor m/k \rfloor\) or \(\lceil m/k \rceil\).

⚠️ Common Mistake

Shuffling the rows before passing them to GroupKFold does nothing — the split is determined by the groups array, not by row order. What matters is correctly identifying which rows belong to the same group.

3
The Math: Why Leakage Inflates Scores
▼

Bias from Within-Group Correlation

Let \(\rho\) be the intra-class correlation (ICC) of the target within a group — the fraction of total variance explained by group membership:

$$\rho = \frac{\sigma^2_{\text{between}}}{\sigma^2_{\text{between}} + \sigma^2_{\text{within}}}$$

When standard k-fold splits rows, the test set contains rows from the same groups as training. The model's predictions on a test row \(r_j^{\text{(test)}}\) are contaminated by having trained on sibling rows \(r_i^{\text{(train)}}\) with \(\text{group}(r_i) = \text{group}(r_j)\). The effective contamination of the error estimate is proportional to \(\rho\). For high-ICC data (e.g., medical time-series where \(\rho \approx 0.6\)–\(0.9\)), this bias is severe.

Generalisation Gap Formula

If the true generalisation error is \(\mathcal{E}_{\text{true}}\) (on a new group), the naive k-fold estimate is:

$$\hat{\mathcal{E}}_{\text{naive}} \approx \mathcal{E}_{\text{true}} - \Delta, \quad \Delta \propto \rho \cdot \frac{n_g - 1}{n_g}$$

where \(n_g\) is the average group size. Large groups with high ICC produce the largest inflation \(\Delta\). Group K-Fold ensures \(\Delta = 0\) by design: no group row appears in both train and test.

📐 CV Score Formula

The Group K-Fold CV estimate is: $$\widehat{\text{CV}} = \frac{1}{k} \sum_{i=1}^{k} \mathcal{L}\!\left(f_{-G_i}, \mathcal{D}_{G_i}\right)$$ where \(f_{-G_i}\) is the model trained on all groups except fold \(i\), and \(\mathcal{D}_{G_i}\) is data from the held-out groups \(G_i\). This is an unbiased estimate of the expected loss on a new, unseen group.

Code — From Scratch & sklearn
▼

From Scratch (NumPy)

import numpy as np
from collections import defaultdict
def group_kfold(groups, k):
"""Yield (train_idx, test_idx) for each of k folds.
groups: array-like of group labels, length n_samples."""
groups = np.asarray(groups)
unique_groups = np.unique(groups) # m unique groups
m = len(unique_groups)
if k > m:
raise ValueError(f"k={k} > number of groups={m}")
# Assign each group to a fold (round-robin)
group_to_fold = {g: i % k for i, g in enumerate(unique_groups)}
# Map each row to its fold via its group
row_fold = np.array([group_to_fold[g] for g in groups])
indices = np.arange(len(groups))
for fold in range(k):
test_idx = indices[row_fold == fold] # rows in this fold
train_idx = indices[row_fold != fold] # all other rows
yield train_idx, test_idx

sklearn Production Usage

from sklearn.model_selection import GroupKFold, cross_val_score
from sklearn.ensemble import GradientBoostingClassifier
import numpy as np
# Dataset: 500 patient visits, 10 features, binary outcome
X = np.random.randn(500, 10)
y = np.random.randint(0, 2, 500)
patient_id = np.repeat(np.arange(100), 5) # 100 patients × 5 visits each
gkf = GroupKFold(n_splits=5)
model = GradientBoostingClassifier()
# CORRECT: pass groups= so the splitter keeps patients together
scores = cross_val_score(model, X, y, cv=gkf, groups=patient_id, scoring='roc_auc')
print(f"Group CV AUC: {scores.mean():.3f} ± {scores.std():.3f}")
# ⚠️ WRONG — standard KFold leaks patient data across folds:
# from sklearn.model_selection import KFold
# scores = cross_val_score(model, X, y, cv=KFold(5)) # inflated AUC!
⚠️ Gotcha

GroupKFold requires that k ≤ number of unique groups. If you have 8 groups and ask for k=10, it raises ValueError. Also, unlike StratifiedKFold, it does not ensure class balance within folds — use StratifiedGroupKFold (sklearn ≥ 1.1) if you need both group integrity and class balance.

Key Takeaways & Related Topics
▼

When to Use Group K-Fold

  • Medical datasets with repeated patient visits or measurements
  • Recommendation systems where the same user has multiple interactions
  • NLP tasks with multiple sentences from the same document or author
  • Any dataset where rows share a common entity that you'll generalise across

When NOT to Use It

  • Truly i.i.d. data with no natural grouping (standard k-fold is fine)
  • When you have very few groups (≤ k) — you'd run out of groups for folds
  • Time-series within groups — use TimeSeriesSplit inside each group instead
