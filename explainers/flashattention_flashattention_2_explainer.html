1
Understanding FlashAttention
▼

What is it? FlashAttention is a way to compute exact softmax attention — the same numbers you'd get from the textbook formula — while never writing the full \(N\times N\) attention matrix to slow GPU memory. It reorganizes the computation into small tiles that fit in the GPU's on-chip cache, and uses a running ("online") softmax so it never needs the whole row of scores at once.

Analogy: Imagine grading a giant stack of exams by hand and needing the class average as you go, but your desk (fast, tiny) can only hold a handful of papers at a time, while the file cabinet (slow, huge) holds all of them. A naive grader keeps carrying stacks between the cabinet and the desk, dropping and re-reading papers over and over — that's standard attention shuttling the whole \(N\times N\) score matrix to HBM (high-bandwidth memory) and back. FlashAttention instead grades a handful of papers at a time, keeps a running tally (sum and max so far) on a sticky note, and updates that tally as each new small batch arrives — never re-reading anything from the cabinet twice.

One-sentence summary: FlashAttention fuses the score, softmax, and weighted-sum steps of attention into one GPU kernel that streams tiles through fast on-chip SRAM, computing the mathematically identical output while cutting HBM traffic from \(O(N^2)\) to \(O(N)\).

💡 If you remember one thing

FlashAttention doesn't change what attention computes — it's numerically exact. It only changes where the intermediate \(N\times N\) matrix lives: never in HBM, only ever in small tiles inside SRAM, combined via an online (streaming) softmax that rescales a running output estimate as new tiles arrive.

How It Works Internally
▼

The Memory Wall, Not the FLOPs Wall

Standard attention computes \(S = QK^\top / \sqrt{d}\) (an \(N\times N\) matrix), applies softmax row-wise to get \(P\), then \(O = PV\). Each of these three steps is a separate GPU kernel: it must write its full output to HBM (the large, slow off-chip DRAM — tens of GB but only ~1.5–3 TB/s) and the next kernel must read it back. For a modern GPU, on-chip SRAM (shared memory / registers) is roughly 10–20× faster than HBM but only a few tens of MB. Attention's FLOPs scale as \(O(N^2 d)\), but the number of HBM reads+writes of standard attention also scales as \(O(N^2)\) because \(S\) and \(P\) are fully materialized — attention on long sequences is memory-bound, not compute-bound.

Tiling: Never Materialize the Full Matrix

FlashAttention splits \(Q\) into row blocks (\(Q_1,\dots,Q_{T_r}\), each of size \(B_r \times d\)) and \(K,V\) into column blocks (\(K_1,\dots,K_{T_c}\), \(V_1,\dots,V_{T_c}\), each \(B_c \times d\)), sized so a \(Q_i, K_j, V_j\) triple plus the \(B_r \times B_c\) score tile all fit in SRAM together. It loops: for each query block \(Q_i\) (outer loop), stream every key/value block \(K_j, V_j\) (inner loop) through SRAM once, computing a partial score tile \(S_{ij} = Q_i K_j^\top\), never storing the full row of scores.

Online (Streaming) Softmax

The catch: softmax needs a normalizer computed over the entire row before you can safely divide. FlashAttention sidesteps this using the identity that softmax can be computed incrementally. It keeps a running max \(m_i\) and running sum \(\ell_i\) per query row, plus a running (unnormalized) output accumulator \(O_i\). Every time a new key/value tile arrives, it: (1) computes a new local max, (2) rescales the OLD accumulator and sum by a correction factor \(\alpha=e^{m_{\text{old}}-m_{\text{new}}}\) to keep everything consistent with the new max, (3) adds the new tile's contribution. After the last tile, one final division by \(\ell_i\) yields the exact softmax output — no approximation.

Kernel Fusion & Recomputation

Because the whole inner loop lives inside one CUDA kernel, the matmul, masking, softmax rescaling, and weighted sum are fused — intermediate tiles never leave SRAM, eliminating the HBM round-trips between what used to be 3+ separate kernels. The backward pass has the same problem in reverse (it needs \(P\) again for gradients), so instead of storing the \(O(N^2)\) matrix \(P\) from the forward pass, FlashAttention only stores the small \(O(N)\) statistics \((m_i, \ell_i)\) per row and recomputes \(S_{ij}\) and \(P_{ij}\) on the fly during backward. This trades a bit of extra compute (cheap, since GPUs are FLOP-rich) for a huge reduction in memory traffic (expensive).

🔑 Design decision: why recompute instead of cache?

Caching \(P\) (size \(O(N^2)\)) for backward would need exactly the HBM traffic FlashAttention was built to avoid. Recomputing \(S_{ij}\) from the already-resident \(Q_i,K_j\) tiles costs extra matmul FLOPs — but GPUs have far more FLOP/s than HBM bandwidth, so trading compute for IO is a net win. This is the same "rematerialization" trick used in gradient checkpointing, applied at the kernel level.

Why It Works — The Math
▼

The Online Softmax Identity

Split a row of scores \(x \in \mathbb{R}^N\) into two chunks \(x^{(1)}, x^{(2)}\). Let \(m^{(1)}=\max(x^{(1)})\), \(\ell^{(1)}=\sum_j e^{x^{(1)}_j - m^{(1)}}\) be the (numerically stable) max and sum-of-exponentials for the first chunk alone. When the second chunk arrives:

$$m^{(2)} = \max\!\big(m^{(1)}, \max(x^{(2)})\big), \qquad \ell^{(2)} = \ell^{(1)} e^{m^{(1)} - m^{(2)}} + \sum_j e^{x^{(2)}_j - m^{(2)}}$$

The correction factor \(e^{m^{(1)}-m^{(2)}}\) exactly re-bases everything computed so far onto the new, larger max — algebraically \(\ell^{(2)} = \sum_{\text{all } j} e^{x_j - m^{(2)}}\), identical to computing the sum in one shot with the true global max. This telescoping identity extends to the weighted output accumulator too:

$$O^{(2)} = O^{(1)} \odot e^{m^{(1)} - m^{(2)}} + P^{(2)}V^{(2)}, \qquad \text{final: } O = O^{(T_c)} / \ell^{(T_c)}$$

where \(P^{(2)}_{j} = e^{x^{(2)}_j - m^{(2)}}\) are the (unnormalized) weights for the new chunk. By induction over all \(T_c\) key/value tiles, the final \(O/\ell\) equals the exact softmax-attention output \(\operatorname{softmax}(QK^\top/\sqrt d)\,V\) — FlashAttention is an exact algorithm, not an approximation.

IO Complexity

With SRAM of size \(M\) and block size \(B \sim M/d\), standard attention needs \(\Theta(Nd + N^2)\) HBM accesses (it must write and re-read the full \(N\times N\) matrix). FlashAttention needs only:

$$\Theta\!\left(\frac{N^2 d^2}{M}\right) \text{ HBM accesses} \quad\ll\quad \Theta(N^2) \text{ when } M \gg d^2$$

Both algorithms do the same \(\Theta(N^2 d)\) FLOPs — FlashAttention is not asymptotically cheaper in compute, only in memory traffic. Since attention on GPUs is memory-bandwidth bound, cutting IO by this factor is what translates into wall-clock speedups of 2–4× (FlashAttention) and 5–9× (FlashAttention-2) over a naive PyTorch implementation.

⚠️ Common misconception

"FlashAttention is a sparse or approximate attention method." It is not — it computes the exact same output as vanilla softmax attention, bit-for-bit up to floating point rounding. The speedup comes purely from an IO-aware scheduling of exact arithmetic, not from skipping computation (unlike sparse/linear attention variants).

Key Takeaways
▼

When it matters:

  • Long-context transformers (4K–1M+ tokens) — the \(N^2\) memory of standard attention would not fit in HBM at all; FlashAttention makes long context tractable
  • Training throughput — 2–4× (FA1) to 5–9× (FA2) wall-clock speedup on attention layers, translating directly into faster/cheaper pretraining
  • Any GPU kernel where FLOPs are cheap relative to memory bandwidth — the same "tile + fuse + recompute" recipe generalizes beyond attention

What changed in FlashAttention-2:

  • Fewer non-matmul FLOPs — rescale the output accumulator \(O_i\) by \(\alpha\) only once at the very end of the inner loop bookkeeping refactor, instead of after every tile, since GPU tensor cores are much faster at matmuls than at elementwise ops
  • Better work partitioning — parallelizes across the sequence-length dimension too (not just batch × heads), keeping all SMs busy even for small batch sizes / long sequences
  • Reduced inter-warp communication — splits \(Q\) (not \(K,V\)) across warps within a thread block so warps don't need to synchronize through shared memory to combine partial results
  • Causal-mask skipping — tiles fully above/below the causal boundary are skipped entirely rather than computed and masked
💡 Hierarchy

Standard attention (materializes \(O(N^2)\) to HBM) → FlashAttention (tiling + online softmax, \(O(N)\) memory, exact) → FlashAttention-2 (same algorithm, better GPU work scheduling) → FlashAttention-3 (further overlaps compute with data movement on Hopper-class GPUs using asynchronous tensor cores). Each generation keeps the math identical and only improves hardware utilization.

Code Trace
▼
import numpy as np
# Q, K, V: (N, d) matrices already in HBM. Br, Bc: tile sizes.
def flash_attention_forward(Q, K, V, Br=2, Bc=2):
N, d = Q.shape
scale = 1.0 / np.sqrt(d)
O = np.zeros((N, d)) # output accumulator, lives in HBM (small: O(N))
ell = np.zeros(N) # running softmax denominator per row
m = np.full(N, -np.inf) # running row max per row
for i in range(0, N, Br): # outer loop over query tiles
Qi = Q[i:i+Br] # load Qi into SRAM (once)
Oi, li, mi = np.zeros((Br, d)), np.zeros(Br), np.full(Br, -np.inf)
for j in range(0, N, Bc): # inner loop over key/value tiles
Kj, Vj = K[j:j+Bc], V[j:j+Bc] # load Kj, Vj into SRAM
Sij = scale * (Qi @ Kj.T) # (Br, Bc) tile, SRAM-only
m_new = np.maximum(mi, Sij.max(axis=1)) # new running max
Pij = np.exp(Sij - m_new[:, None]) # unnormalized weights
alpha = np.exp(mi - m_new) # correction factor
li = alpha * li + Pij.sum(axis=1) # rescale + add new sum
Oi = alpha[:, None] * Oi + Pij @ Vj # rescale + add new output
mi = m_new
# Kj, Vj, Sij, Pij are now discarded — never written to HBM
O[i:i+Br] = Oi / li[:, None] # final normalize, write Oi to HBM
ell[i:i+Br], m[i:i+Br] = li, mi # store only O(N) stats for backward
return O, ell, m
