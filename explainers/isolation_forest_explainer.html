Isolation Forest

Random partitioning, anomaly scores, and why outliers are easier to isolate
Advanced Anomaly Detection Tree Methods O(n) linear time
1
The 30-Second Version

Imagine you're playing a guessing game. You pick a random feature (like "height" or "income"), then pick a random cut-point, and ask: "Is the mystery point above or below?" You keep cutting until you've isolated the point completely — one point per box. Anomalies are weirdos that get cornered in just 2–3 cuts. Normal points blend in and take many more.

Isolation Forest builds hundreds of these random partition trees, measures how many cuts it takes to isolate each point on average, and turns that average path length into an anomaly score between 0 and 1. Near 1 → anomaly. Near 0.5 → normal.

💡 If you remember one thing

Anomalies are isolated in fewer random splits because they live in sparse, extreme regions. The anomaly score is \(s(x,n) = 2^{-E[h(x)]/c(n)}\) — where shorter average path length \(E[h(x)]\) → score closer to 1 → more anomalous.

One-sentence summary: Isolation Forest detects anomalies by measuring how quickly random recursive bisections isolate a point — outliers isolate fast, normals isolate slowly.

2
How It Works Internally

Building an Isolation Tree (iTree):

  1. Sub-sample \(\psi\) points (default \(\psi = 256\)) from the dataset.
  2. Pick a random feature \(q\) uniformly from all \(d\) features.
  3. Pick a random split value \(p\) uniformly from \([\min(q), \max(q)]\) in the current node.
  4. Recurse: points with \(x_q \le p\) go left; points with \(x_q > p\) go right.
  5. Stop when a node contains 1 point OR tree reaches max depth \(\lfloor \log_2 \psi \rfloor\).

Scoring a point:

  1. Run the point through all \(t = 100\) trees (default).
  2. Record its path length \(h_i(x)\) in each tree (number of edges traversed + adjustment for truncated paths).
  3. Average the path lengths: \(E[h(x)] = \frac{1}{t}\sum_{i=1}^t h_i(x)\).
  4. Normalize by \(c(n)\) — the expected path length of an unsuccessful Binary Search Tree search on \(n\) points — and apply the score formula.
🔑 Key Design Decision

The sub-sample size \(\psi = 256\) (not the full dataset) is the key hyperparameter. Small sub-samples (a) reduce masking by normal points, (b) give trees more variance for averaging, and (c) make construction \(O(\psi \log \psi)\) regardless of dataset size. Liu et al. showed \(\psi = 256\) is nearly always sufficient — adding more data gives diminishing returns.

📐 The Normalization Constant c(n)

\(c(n)\) is the average path length of an unsuccessful Binary Search Tree (BST) search with \(n\) nodes. Using the harmonic number \(H(n) = \ln(n) + 0.5772\) (Euler–Mascheroni constant):

$$c(n) = 2H(n-1) - \frac{2(n-1)}{n} \approx 2\ln(n-1) - \frac{2(n-1)}{n} + 0.5772$$

For \(n=256\): \(c(256) = 2\ln(255) - 2(255)/256 + 0.5772 \approx 2(5.5413) - 1.9922 + 0.5772 \approx 9.672\). This is the expected depth if isolation took a random BST — our baseline for "normal" isolation depth.

⚠️ Path Length Adjustment for External Nodes

When a leaf node still has \(n_{\text{leaf}} > 1\) points (because the tree was pruned at max depth), add \(c(n_{\text{leaf}})\) to the recorded path length. This corrects for the estimated depth that would be needed to isolate within that node. Without this, paths in pruned trees would be systematically underestimated.

3
The Math Behind the Anomaly Score

The anomaly score maps average path length to \([0, 1]\) so that different dataset sizes are comparable:

$$s(x, n) = 2^{-\frac{E[h(x)]}{c(n)}}$$

Three key reference points:

  • If \(E[h(x)] \approx c(n)\): then \(s \approx 2^{-1} = 0.5\) → point is indistinguishable from a normal BST node → not anomalous.
  • If \(E[h(x)] \ll c(n)\): then \(s \to 1\) → isolated very quickly → anomaly.
  • If \(E[h(x)] \to 2c(n)\): then \(s \to 0.25\) → takes much longer than average → very normal/dense region.

Numerical example with \(n = \psi = 256\), so \(c(256) \approx 9.672\):

  • Anomaly: isolated in average 2.4 splits → \(s = 2^{-2.4/9.672} = 2^{-0.248} \approx 0.841\)
  • Normal: isolated in average 8.1 splits → \(s = 2^{-8.1/9.672} = 2^{-0.837} \approx 0.558\)
  • Dense cluster: isolated in average 14.0 splits → \(s = 2^{-14.0/9.672} = 2^{-1.448} \approx 0.368\)
💡 Why the Exponential Base 2?

A balanced BST with \(n\) points has height \(\log_2 n\). The ratio \(E[h(x)]/c(n)\) measures path length relative to this expected depth. Raising 2 to the negative of this ratio maps \([0, 2c(n)] \to (0, 1]\) monotonically. The formula is directly inspired by the BST random-search path length analysis from Knuth (TAOCP Vol. 3).

Why linear time? Each tree construction is \(O(\psi \log \psi)\) with sub-sample \(\psi\). With \(t\) trees, training is \(O(t \cdot \psi \log \psi)\) — independent of the dataset size \(N\). Scoring is \(O(t \cdot \log \psi)\) per point. No distance computations, no kernel matrices.

🎯 Decision Rule

Use Isolation Forest when: dataset is large (>10K rows), features are tabular, you need fast training/inference, or you have no labels for anomalies. Use LOF when: anomalies are defined by local density differences and dataset is small. Use Autoencoder when: data is images/sequences or anomalies have complex structural patterns.

6
Key Takeaways & Interview Prep
  • Core insight: Anomalies are rare + different → they partition faster with random splits.
  • Score formula: \(s = 2^{-E[h(x)]/c(n)}\). Score > 0.6 → anomaly; ~0.5 → normal; < 0.4 → dense cluster.
  • Sub-sample \(\psi=256\): the magic number — small enough to remove masking, large enough for stable scores.
  • No distances, no densities: works in high dimensions, unlike LOF or DBSCAN.
  • Extended Isolation Forest (2018): uses random hyperplane cuts (not axis-aligned) to fix the bias near feature axes.

Common interview question: "Why does Isolation Forest use a sub-sample of 256 instead of the full dataset?"

⚠️ Masking & Swamping

Masking: A large cluster of anomalies can "look" normal because they group together and require many splits. Sub-sampling reduces this risk — with \(\psi = 256\), it's unlikely a large anomaly cluster dominates the sample. Swamping: Normal points near anomalies get incorrectly flagged. Extended IF with random hyperplanes mitigates both.
