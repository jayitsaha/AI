Understanding the Libraries
▼

What is Matplotlib? Matplotlib is Python's foundational plotting library. It gives you complete control over every element of a figure — the canvas size, axis labels, tick marks, colors, fonts — by exposing a rich object model that mirrors how a graphic artist would compose a chart from parts. Think of it as an extremely configurable drawing board.

What is Seaborn? Seaborn is a higher-level statistical visualization library built on top of Matplotlib. While Matplotlib asks you to specify every detail, Seaborn takes a tidy dataset and produces publication-quality statistical charts (histograms, box plots, violin plots, heatmaps, pair plots) with minimal code. Seaborn translates dataset columns directly into visual encodings (x, y, color, size, shape) via a grammar of graphics approach.

Analogy: Matplotlib is like assembling LEGO bricks — you place every piece yourself and can build anything, but it takes effort. Seaborn is like a LEGO set with pre-designed modules: "boxplot", "heatmap", "pairplot" snap together quickly, and you can still open them up and rearrange the underlying LEGO pieces (Matplotlib objects) when you need something custom.

💡 If you remember one thing

Every Seaborn chart is ultimately a Matplotlib Figure containing one or more Axes objects populated with Artists (lines, patches, text). Seaborn automates the Artist creation; Matplotlib gives you direct access to tweak every Artist after the fact. The two libraries are fully interoperable — call fig, ax = plt.subplots(), pass ax=ax to Seaborn, then continue customizing with Matplotlib.

The Figure / Axes / Artists Hierarchy
▼

The Three-Level Object Hierarchy

Matplotlib's design is an Artist hierarchy. Every visible element on a plot is an Artist object. The hierarchy has three tiers:

Figure ← the whole canvas / window
  ├── Axes ← one plot area (has its own coordinate system)
  │    ├── XAxis / YAxis (Ticks, TickLabels, AxisLabel)
  │    ├── Line2D (line plots, markers)
  │    ├── PathPatch (filled polygons — bars, violins)
  │    ├── Text (title, annotations, legend text)
  │    └── Collection (scatter clouds, PatchCollections)
  ├── Axes ← second subplot (same Figure, different coordinate system)
  └── FigurePatches, FigureText (suptitle, colorbar, watermark)

Figure vs. Axes — A Common Confusion

Beginners often confuse Figure and Axes. A Figure is the entire output window or image file (set its overall size with figsize=(width, height)). An Axes is a single plot panel inside that Figure — it has its own x/y coordinate system, axis labels, title, and tick marks. One Figure can hold many Axes arranged in a grid (subplots) or placed at arbitrary positions.

🔑 Key Property

fig, axes = plt.subplots(nrows, ncols) returns one Figure and a NumPy array of Axes. The Figure occupies the full canvas; each Axes occupies a rectangular cell. Every ax.plot(), ax.set_title(), etc. modifies that specific Axes object — zero ambiguity about which panel you're editing.

Artists in Detail

Primitive Artists (leaves of the tree) render actual pixels: Line2D (a polyline drawn with markers and a linestyle), Patch subclasses (Rectangle, Circle, Polygon, PathPatch), and Text. Container Artists (Figure, Axes, Axis) group and manage primitives. When you call ax.bar(), Matplotlib creates Rectangle patches and adds them to the Axes. When you call ax.legend(), it creates a Legend artist that contains Line2D and Text children.

⚠️ Note on Axes vs Axis

Axes (plural) is the plot panel; Axis (singular) is the x or y spine object. ax.xaxis and ax.yaxis give you the Axis objects with their Ticker, Formatter, and Locator children. This naming trips up virtually every beginner.

pyplot State Machine vs Object-Oriented API
▼

Two APIs, One Library

Matplotlib exposes two distinct programming interfaces. The pyplot state-machine API (import matplotlib.pyplot as plt) maintains an implicit "current figure" and "current axes" in module-level state. Every plt.plot() call acts on whichever Axes is currently active — convenient for interactive sessions, confusing for multi-panel scripts. The object-oriented (OO) API works directly with Figure and Axes objects, leaving no ambiguity about which panel is being modified.

Side-by-Side Code Comparison

# ── pyplot state-machine API (implicit current axes) ──
import matplotlib.pyplot as plt
import numpy as np
x = np.linspace(0, 2*np.pi, 100)
plt.figure(figsize=(8, 4)) # creates Figure, sets as current
plt.subplot(1, 2, 1) # creates Axes #1, sets as current
plt.plot(x, np.sin(x), 'b-') # acts on current axes
plt.title('Sine') # acts on current axes
plt.subplot(1, 2, 2) # creates Axes #2, sets as current
plt.plot(x, np.cos(x), 'r--') # acts on NEW current axes
plt.title('Cosine')
plt.tight_layout()
plt.savefig('out.png')
# ── Object-Oriented API (explicit Figure/Axes) ──
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(8, 4))
ax1.plot(x, np.sin(x), 'b-') # unambiguously modifies ax1
ax1.set_title('Sine')
ax2.plot(x, np.cos(x), 'r--') # unambiguously modifies ax2
ax2.set_title('Cosine')
fig.tight_layout()
fig.savefig('out.png')
💡 When to Use Which

pyplot API: Jupyter notebooks, quick exploratory plots, single-panel figures. OO API: multi-panel dashboards, functions that return a figure, reusable plotting utilities, any code running outside a notebook. Production code should always use the OO API — it is explicit, testable, and side-effect-free.

Subplots Layout Patterns

plt.subplots(nrows, ncols, figsize, sharex, sharey) is the workhorse. For non-uniform grid layouts use GridSpec: gs = fig.add_gridspec(2, 3); ax = fig.add_subplot(gs[0, :]) creates an Axes spanning the full first row. For arbitrary placement use fig.add_axes([left, bottom, width, height]) in figure coordinates (0–1).

Seaborn as a Statistical Layer
▼

Seaborn's Core Design Principles

Seaborn expects tidy data: each row is one observation, each column is one variable. You pass a DataFrame and column names, and Seaborn handles grouping, aggregation, and color mapping automatically. Under the hood every Seaborn function ends by drawing Matplotlib Artists onto the given (or current) Axes.

Figure-Level vs Axes-Level Functions

Seaborn functions split into two tiers. Axes-level functions (sns.histplot, sns.boxplot, sns.scatterplot, …) draw onto a single Axes and accept an ax= parameter — you control the layout. Figure-level functions (sns.displot, sns.catplot, sns.relplot, sns.pairplot, sns.clustermap) create their own Figure and a grid of Axes internally, returning a FacetGrid or PairGrid object. You cannot pass ax= to figure-level functions.

🔑 Key Pattern: Axes-level + Matplotlib customization

fig, ax = plt.subplots(figsize=(8,5))
sns.violinplot(data=df, x='species', y='sepal_length', ax=ax)
ax.set_title('Sepal Length by Species') # pure Matplotlib
ax.set_ylabel('Length (cm)') # pure Matplotlib
This is the idiomatic professional pattern: Seaborn for statistical rendering, Matplotlib for fine-grained cosmetics.

import seaborn as sns, matplotlib.pyplot as plt, pandas as pd
iris = sns.load_dataset('iris') # tidy DataFrame: 150 rows × 5 cols
# ── Axes-level: full Matplotlib control ────────────────────
fig, axes = plt.subplots(1, 2, figsize=(12, 5))
sns.violinplot(data=iris, x='species', y='sepal_length',
inner='box', palette='Set2', ax=axes[0])
axes[0].set_title('Sepal Length by Species')
sns.heatmap(iris.drop('species',axis=1).corr(),
annot=True, fmt='.2f', cmap='coolwarm', ax=axes[1])
axes[1].set_title('Feature Correlation')
fig.tight_layout(); plt.show()
# ── Figure-level: Seaborn manages the layout ───────────────
g = sns.pairplot(iris, hue='species', corner=True, diag_kind='kde')
g.figure.suptitle('Iris Pairwise Distributions', y=1.02)

🎯 Decision Guide

Use Matplotlib alone when you need pixel-perfect control, publication PDFs, or custom Artist subclasses.
Use Seaborn (axes-level) + Matplotlib for EDA of tidy DataFrames with statistical summaries — this is the daily-driver combo.
Use Seaborn figure-level (pairplot, displot) for quick multi-panel statistical overviews with minimal boilerplate.
Use Plotly when the audience needs interactivity in a browser (hover, zoom, filter).
Use Altair when you think declaratively (grammar of graphics) and need concise, composable specs.

Key Takeaways

  • The Matplotlib object hierarchy is Figure → Axes → Artists. Every visible element is an Artist.
  • The pyplot API maintains implicit state; the OO API is explicit — prefer OO for any non-trivial code.
  • Seaborn is a statistical layer on top of Matplotlib; all Seaborn plots are Matplotlib figures at heart.
  • Axes-level Seaborn functions accept ax=; figure-level functions create their own grid — do not mix them.
  • Tidy data (one observation per row) unlocks the full power of Seaborn's automatic grouping and faceting.
  • For fine-tuned cosmetics after a Seaborn call: grab the Axes from ax = plt.gca() or pass ax=ax upfront.
