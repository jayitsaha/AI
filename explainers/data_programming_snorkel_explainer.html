Understanding the Concept

The core problem: Training a machine learning model requires labelled data — a dataset where each example has a correct answer tag. Labelling is done by human experts. It is slow, expensive, and doesn't scale. A spam-detection system might need millions of labelled emails; hiring annotators to read every one is impractical.

The Snorkel insight: Instead of labelling examples one by one, write short programs — called labeling functions (LFs) — that each express a weak, heuristic rule. A single LF might say "if the email contains the word 'Viagra', label it spam." No single LF is perfect, but when you combine dozens of imperfect LFs, a label model can estimate their accuracies and correlations and produce probabilistic training labels that are often nearly as good as hand-labelled data.

💡 If you remember one thing
Snorkel replaces hand-labelled examples with hand-written programs. The label model resolves disagreements between those programs using their estimated accuracies and correlations — no ground truth required.
🔑 Real-World Analogy
Imagine a doctor who wants to diagnose thousands of X-rays but can only afford to consult a few specialist radiologists personally. Instead, she designs a set of quick checklists — "is there a shadow here?", "is the rib spacing abnormal?" — and asks five junior residents to each complete one checklist per scan. Each resident's checklist is noisy and incomplete. But a statistician can model which residents are trustworthy, which make correlated mistakes, and produce a combined diagnosis score — without ever needing a definitive specialist opinion for every single scan. That statistician is the label model.

How It Works — Architecture & Internal Mechanism

Step 1 — Write Labeling Functions. A labeling function \(\lambda_j: \mathcal{X} \to \{-1, 0, +1\}\) maps an input \(x\) to a label vote (+1 positive, -1 negative, 0 abstain). Multiple LFs form a label matrix \(\Lambda \in \{-1, 0, +1\}^{n \times m}\) for \(n\) data points and \(m\) labeling functions.

Step 2 — Fit the Label Model. The label model is a generative model over the joint distribution of \((Y, \Lambda)\). It has no access to true labels \(Y\). It estimates per-LF accuracies \(\alpha_j = P(\lambda_j = Y \mid \lambda_j \neq 0)\) and LF correlations by minimizing the difference between observed and expected pairwise agreements on \(\Lambda\).

Step 3 — Generate Probabilistic Labels. Using estimated parameters, the label model computes \(\tilde{P}(Y=+1 \mid \mathbf{\lambda}) \in [0,1]\) for each data point. This becomes the soft training label for the downstream discriminative model.

Step 4 — Train Discriminative Model. A standard model (BERT, logistic regression, etc.) trains on \((X, \tilde{Y})\) using the soft probabilistic labels, typically with cross-entropy loss. At inference time, only the discriminative model is used — the label model is discarded.

⚠️ Critical Design Decision
The label model learns from LF agreement and disagreement patterns, not from observed ground truth. This is possible because under conditional independence (given \(Y\)), LF errors are uncorrelated — so correlation in the label matrix signals accuracy. Snorkel extends this to the correlated-LF case using dependency structure learning.

The Math Behind the Label Model

The Snorkel label model (Ratner et al., 2019) factorizes as a graphical model. For binary classification \(Y \in \{-1, +1\}\) and \(m\) labeling functions:

$$P_\theta(Y, \Lambda) = \frac{1}{Z_\theta} \exp\!\left(\sum_{j=1}^{m} \theta_j Y \lambda_j + \sum_{(j,k) \in E} \theta_{jk} \lambda_j \lambda_k \right)$$

where \(Z_\theta\) is the partition function and \(E\) is a dependency graph over LFs. The key parameters are:

  • \(\alpha_j = \text{accuracy of LF}_j = P(\lambda_j = Y \mid \lambda_j \neq 0)\)
  • \(\beta_j = \text{coverage of LF}_j = P(\lambda_j \neq 0)\)
  • \(\rho_{jk} = \text{correlation between LF}_j \text{ and LF}_k\)

Parameter estimation (key insight): The model is fit by matching observed moments of \(\Lambda\) to model-implied moments. Specifically, for the pairwise expected agreements:

$$\mathbb{E}[\lambda_j \lambda_k] = \mathbb{E}_\theta[\lambda_j \lambda_k]$$

This is a method-of-moments estimator. The system of equations is solved via SGD on the negative log-likelihood of the observed \(\Lambda\), treating \(Y\) as a latent variable and marginalizing over it:

$$\hat{\theta} = \underset{\theta}{\operatorname{argmin}} \; -\sum_{i=1}^{n} \log \sum_{y \in \{-1,+1\}} P_\theta(y, \lambda^{(i)})$$

After fitting \(\hat{\theta}\), the probabilistic label for data point \(i\) is:

$$\tilde{P}(Y=+1 \mid \lambda^{(i)}) = \frac{P_{\hat{\theta}}(Y=+1, \lambda^{(i)})}{P_{\hat{\theta}}(\lambda^{(i)})}$$
📐 Simplified Majority Vote (Baseline)
Without a label model, one could use unweighted majority vote: \(\tilde{y} = \text{sign}\!\left(\sum_j \lambda_j\right)\). This treats all LFs equally accurate and independent — the label model strictly generalises this by weighting by estimated \(\alpha_j\) and de-correlating overlapping LFs.
⚠️ Common Misconception
The label model output is not calibrated probability in the frequentist sense — it is a posterior belief under the generative model. Calibration depends on how well the graphical model captures the true LF dependency structure.

Key Takeaways & When to Use

Use Snorkel / data programming when:

  • You have abundant unlabelled data but labelling is expensive or slow
  • Domain experts can articulate rules (even if imperfect or conflicting)
  • You want to programmatically curate training sets without re-labelling from scratch
  • You need to iterate quickly on labelling strategies

Do NOT use when:

  • You already have sufficient high-quality labelled data
  • The task has no exploitable structure (e.g., no heuristics can be written)
  • LF coverage is very low (most data points always abstain)
