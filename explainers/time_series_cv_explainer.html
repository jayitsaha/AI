Time Series Cross-Validation

Expanding window & sliding window forward-chaining strategies

Intermediate Classical ML O(T²)
1   Understanding the Concept

Standard k-fold cross-validation shuffles the dataset and assigns observations randomly to folds. This works fine for i.i.d. data — but time series data is not i.i.d. Observations are ordered in time, and tomorrow's value may depend on today's. Shuffling destroys this structure and creates data leakage: the model "sees" future data during training, producing optimistically biased performance estimates.

Why shuffling fails: If your training set includes t = 100 and your validation set includes t = 50, the model was trained on data that occurs after the point it's predicting. This is impossible in deployment and inflates reported accuracy.

The solution is forward-chaining (a.k.a. walk-forward validation). The invariant is simple: always train on the past, validate on the future. Every fold respects the temporal ordering — the validation window comes entirely after the training window, just as it would in production.

Deployment mirror principle: A well-designed time-series CV split mimics exactly how the model will be used. If you retrain weekly and forecast 2 weeks ahead, each CV fold should have a 2-week validation horizon, stepping forward by 1 week at a time.

There are two primary strategies for choosing the training window: expanding window (accumulates all history) and sliding window (uses a fixed-size recent window). The right choice depends on whether your data is stationary and how far back history remains predictive.

2   Expanding Window (Growing Train Set)

In the expanding window strategy, the training set always starts at t₁ and grows by a step size \(s\) each fold. The validation horizon \(h\) stays fixed. Given step \(s\) and horizon \(h\), fold \(k\) is defined as:

$$\text{Train}_k = [t_1, \; t_{k \cdot s}] \qquad \text{Val}_k = [t_{k \cdot s + 1}, \; t_{k \cdot s + h}]$$

For our walkthrough (T=12, s=2, h=2), the four folds are:

  • Fold 1: Train [t₁,t₂] → Val [t₃,t₄]
  • Fold 2: Train [t₁,t₄] → Val [t₅,t₆]
  • Fold 3: Train [t₁,t₆] → Val [t₇,t₈]
  • Fold 4: Train [t₁,t₈] → Val [t₉,t₁₀]

Total folds: \(\lfloor (T - h) / s \rfloor - \lfloor \text{min\_train}/s \rfloor + 1\). The number of folds available grows with T.

Advantages

  • Uses all available history
  • Stable if process is stationary
  • More training data in later folds
  • Closest to full-data final model

Disadvantages

  • Old data may be stale / irrelevant
  • Slower: O(T²) total training work
  • Structural breaks hurt all folds
  • Unequal fold sizes skew averaging
3   Sliding Window (Fixed Train Set)

In the sliding window strategy, the training set has a fixed size \(W\) and slides forward by step \(s\) each fold. Older data outside the window is discarded. Fold \(k\) is:

$$\text{Train}_k = [t_{(k-1)\cdot s + 1},\; t_{(k-1)\cdot s + W}] \qquad \text{Val}_k = [t_{(k-1)\cdot s + W + 1},\; t_{(k-1)\cdot s + W + h}]$$

For our walkthrough (W=4, s=2, h=2), the three folds are:

  • Fold 1: Train [t₁,t₄] → Val [t₅,t₆]  (starts at (1-1)·2+1=1)
  • Fold 2: Train [t₃,t₆] → Val [t₇,t₈]  (starts at (2-1)·2+1=3)
  • Fold 3: Train [t₅,t₈] → Val [t₉,t₁₀]  (starts at (3-1)·2+1=5)
Choosing W: Too small = model underfit; too large = old irrelevant data included. Common heuristic: W ≈ 3–5× the forecast horizon, but domain knowledge (seasonality, regime length) should guide the choice.

Advantages

  • Adapts to concept drift naturally
  • Equal-sized folds — fair averaging
  • O(W·T) total training — faster
  • Isolates recent regime behaviour

Disadvantages

  • Discards potentially useful history
  • Sensitive to W selection
  • Fewer folds if W is large
  • Wastes early data entirely

5   Key Takeaways & When to Use
Universal rule: In time series CV, validation data must always come after training data. Any fold where this is violated introduces look-ahead bias and should be rejected.

Use Expanding Window when:

  • The underlying process is stationary (no structural breaks).
  • You have limited data and need every observation in training.
  • The model benefits from long historical context (e.g., seasonal ARIMA, LSTM with long lookbacks).
  • The data-generating process is stable over time.

Use Sliding Window when:

  • The process exhibits concept drift (distribution shifts over time).
  • Older data may actively hurt model performance (stale patterns).
  • Computational budget is limited and equal-fold comparison matters.
  • You are evaluating online/streaming models that retrain on recent data only.
Practical tip: Report the average metric across folds and plot it fold-by-fold. A rising error trend across folds signals concept drift. Fold-by-fold variance tells you how stable your model is across different time regimes.

Finally, always use a minimum training size \(\text{min\_train} \geq p + q + 1\) for ARIMA models (where p, q are orders), or at least a few seasonal periods for seasonal models — otherwise early folds are statistically meaningless.

Strategy Comparison

Dimension Expanding Window Sliding Window
Train size per fold Grows: \(k \cdot s\) at fold \(k\) Fixed: always \(W\)
Memory of old data All history retained forever Only most recent \(W\) points
Drift adaptation Poor — old patterns dilute recent signal Good — naturally forgets stale patterns
Computation (T folds) O(T²) total training work O(W · T) — cheaper when W < T
Best for Stationary, data-scarce scenarios Non-stationary, drifting regimes

import numpy as np

def expanding_window_cv(y, h=1, min_train=2):
    """Forward-chaining CV with expanding training window.

    Parameters
    ----------
    y         : array-like, the time series (length T)
    h         : forecast horizon (validation window size)
    min_train : minimum number of training observations for the first fold
    """
    T = len(y)
    splits = []
    for train_end in range(min_train, T - h + 1):
        train_idx = list(range(train_end))
        val_idx   = list(range(train_end, train_end + h))
        splits.append((train_idx, val_idx))
    return splits


def sliding_window_cv(y, W, h=1, step=1):
    """Forward-chaining CV with fixed sliding training window.

    Parameters
    ----------
    y    : array-like, the time series (length T)
    W    : fixed training window size
    h    : forecast horizon (validation window size)
    step : how many steps to slide the window each fold
    """
    T = len(y)
    splits = []
    for start in range(0, T - W - h + 1, step):
        train_idx = list(range(start, start + W))
        val_idx   = list(range(start + W, start + W + h))
        splits.append((train_idx, val_idx))
    return splits


# ── Example ──────────────────────────────────────────────────────────
y = np.array([1.2, 2.1, 1.8, 3.0, 2.5, 3.8,
              3.2, 4.1, 3.9, 5.0, 4.5, 6.0])

print("=== Expanding Window (h=2, min_train=2, step=1) ===")
for train_idx, val_idx in expanding_window_cv(y, h=2, min_train=2):
    print(f"  Train: t{train_idx[0]+1}–t{train_idx[-1]+1} ({len(train_idx)} pts) | "
          f"Val: t{val_idx[0]+1}–t{val_idx[-1]+1}")

print("\n=== Sliding Window (W=4, h=2, step=2) ===")
for train_idx, val_idx in sliding_window_cv(y, W=4, h=2, step=2):
    print(f"  Train: t{train_idx[0]+1}–t{train_idx[-1]+1} ({len(train_idx)} pts) | "
          f"Val: t{val_idx[0]+1}–t{val_idx[-1]+1}")

# ── Using with scikit-learn compatible interface ──────────────────────
from sklearn.linear_model import LinearRegression

def walk_forward_mae(y, W=4, h=1, step=1, lag=1):
    """Evaluate a simple AR(lag) model via sliding-window CV."""
    X = np.column_stack([y[i:-(lag - i) or None] for i in range(lag)])
    Y = y[lag:]
    errors = []
    for tr, va in sliding_window_cv(Y, W=W, h=h, step=step):
        model = LinearRegression().fit(X[tr], Y[tr])
        preds = model.predict(X[va])
        errors.append(np.mean(np.abs(preds - Y[va])))
    return np.mean(errors), errors
