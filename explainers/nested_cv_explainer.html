Nested Cross-Validation

Hyperparameter tuning + unbiased evaluation in one principled framework

Intermediate Classical ML Model Selection Part III · Section 13.3
1
The Core Idea

You want to (a) tune hyperparameters and (b) honestly estimate how well your final model generalises. These two goals cannot share the same data — using the same folds for both leaks information and makes your reported accuracy too optimistic.

💡 The Analogy

Think of job interviews: the inner loop is a practice interview where you try different preparation strategies and pick the best one. The outer loop is the real interview. If you practised on real-interview questions you'd over-estimate your readiness. Nested CV keeps these two pools of questions completely separate.

🔑 If You Remember One Thing

Single-loop CV that also chose hyperparameters optimistically biases performance — the reported score is better than what you'd get on truly new data. Nested CV eliminates this bias by giving the outer fold's test set an exclusive role: it never touches hyperparameter selection, only final evaluation.

2
How It Works — Mechanism

Nested CV has two concentric loops over the same dataset \(D = \{(x_i, y_i)\}_{i=1}^n\).

Outer loop (evaluation): Split \(D\) into \(K_\text{out}\) folds. In each outer iteration \(k\), one fold is held out as the outer test set \(D_k^\text{test}\). The remaining \(K_\text{out}-1\) folds form \(D_k^\text{trainval}\).

Inner loop (tuning): \(D_k^\text{trainval}\) is itself split into \(K_\text{in}\) folds. A fresh CV is run over a hyperparameter grid \(\Lambda\). The best hyperparameter \(\hat\lambda_k = \arg\max_\lambda \text{CV}_\text{inner}(\lambda)\) is selected. A model is trained on the full \(D_k^\text{trainval}\) with \(\hat\lambda_k\), then scored on \(D_k^\text{test}\).

Final estimate: The average of the \(K_\text{out}\) outer test scores gives an unbiased generalisation estimate. The selected \(\hat\lambda_k\) may differ across outer folds — that variance is intentional and captured.

⚠️ Common Mistake

People run grid-search CV, take the best hyperparameter, then re-run CV with that fixed hyperparameter to "evaluate" it. This is still contaminated — the evaluation CV saw the data during the hyperparameter search. You must use a held-out outer fold that never participated in selection.

Why does single-loop CV over-fit to hyperparameters? When you evaluate \(|\Lambda|\) hyperparameter configurations, you implicitly perform \(|\Lambda|\) comparisons. The "winner" benefits from random variation across folds. This is analogous to testing 100 drugs in a clinical trial with \(p<0.05\) — about 5 will appear significant by chance. More hyperparameter options → more selection bias.

3
The Math — Bias of Single-Loop CV

Let \(\mathcal{A}(\lambda, D)\) be a learning algorithm with hyperparameter \(\lambda\) trained on dataset \(D\), and let \(\hat\lambda^\star = \arg\min_\lambda \widehat{R}_\text{CV}(\lambda)\) be the best hyperparameter found by \(K\)-fold CV on the same data used for evaluation.

The optimistic bias of single-loop CV is:

$$\text{Bias} = \mathbb{E}\!\left[\hat{R}_\text{single}\!\left(\mathcal{A}(\hat\lambda^\star,D)\right)\right] - R^\star$$

where \(R^\star = \mathbb{E}_{(x,y)\sim P}\!\left[\ell\!\left(\mathcal{A}(\hat\lambda^\star,D_\text{train}), (x,y)\right)\right]\) is the true expected loss on new data. This bias is strictly non-negative because:

$$\mathbb{E}\!\left[\max_\lambda \hat{R}_\text{CV}(\lambda)\right] \leq \max_\lambda \mathbb{E}\!\left[\hat{R}_\text{CV}(\lambda)\right]$$

Wait — we minimise loss, so flipping signs: the minimum estimated error is biased downward relative to the true minimum error. The magnitude grows with \(|\Lambda|\) (more hyperparameter candidates) and decreases with \(n\) (more data).

Nested CV's unbiased estimator: The outer test fold \(D_k^\text{test}\) is independent of the inner loop by construction, so:

$$\hat{R}_\text{nested} = \frac{1}{K_\text{out}}\sum_{k=1}^{K_\text{out}} \hat{R}\!\left(\mathcal{A}(\hat\lambda_k, D_k^\text{trainval}),\, D_k^\text{test}\right)$$

and \(\mathbb{E}\!\left[\hat{R}_\text{nested}\right] \approx R^\star\) — the estimator is conditionally unbiased given the data-generating process.

📐 Numerically Correct Example

Dataset: \(n=150\), 5-outer × 3-inner CV, SVM with \(C \in \{0.1, 1, 10\}\).

Single-loop CV reports: 87.3% accuracy (selected \(C=1\)).

Nested CV outer scores: 85.1%, 84.6%, 86.2%, 83.9%, 85.7% → mean 85.1%.

Optimistic bias ≈ 2.2 percentage points — the difference you'd report to a client vs. what happens in production.

Comparison & When to Use
ApproachHyperparameter TuningEvaluation BiasCompute CostBest For
Train/Val/Test split On val set Low (if large test) Low Large datasets (>10K samples)
Single-loop CV On same CV folds Optimistic (biased ↓) Low Exploration only, not reporting
Nested CV (5×5) Inner loop Unbiased High (K_out × K_in × |Λ|) Small datasets, final evaluation
Repeated nested CV Inner loop Unbiased + lower variance Very high Rigorous benchmarks, papers
💡 Rule of Thumb

n < 1000? Use nested CV for any published result. n > 10K? A simple train/val/test split suffices. In between: 5-outer × 3-inner with random search is a pragmatic default.

⚠️ Nested CV Does NOT Give a Deployable Model

The outer scores estimate generalisation error of "a model trained with this pipeline on this dataset size." The final deployed model is separately trained on all the data using the most common \(\hat\lambda_k\) across outer folds, or via a final inner CV over the full dataset.
