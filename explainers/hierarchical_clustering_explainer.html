Understanding Hierarchical Clustering
▼

What is it? Hierarchical clustering groups data points into a nested tree of clusters — you never have to decide the number of clusters upfront. It runs until all points are in one big cluster, then you "cut" the tree at any height to get any number of groups you like.

Analogy: Think of biological taxonomy. Every living thing can be grouped pairwise into species, then genus, then family, then order, all the way to kingdom. Hierarchical clustering does the same for data: start with every point as its own "species" and repeatedly merge the most similar pair until everything is one "kingdom." The family tree you draw is called a dendrogram.

Two directions:

  • Agglomerative (bottom-up): Start with \(n\) singleton clusters; at each step merge the pair with the smallest distance. This is by far the most common approach.
  • Divisive (top-down): Start with one big cluster and recursively split it. More expensive — \(O(2^n)\) exhaustive, so heuristic splits (e.g., bisecting k-means) are used in practice.
💡 If you remember one thing

Agglomerative hierarchical clustering merges the two clusters with the smallest inter-cluster distance at every step. The choice of how you measure distance between clusters — single, complete, average, or Ward linkage — dramatically changes the shape of the resulting dendrogram and the clusters you get.

Prerequisites: Euclidean distance, the notion of a cluster centroid, basic understanding of k-means as a comparison point.

Linkage Criteria — Single, Complete, Average, Ward
▼

The critical design choice in agglomerative clustering is the linkage criterion — the rule for computing the distance between two clusters \(A\) and \(B\), each potentially containing multiple points.

Single Linkage — "nearest neighbor"

$$d_{\text{single}}(A,B) = \min_{a \in A,\, b \in B} d(a,b)$$

Uses the distance between the closest pair of points, one from each cluster. Extremely sensitive to outliers; tends to produce long "chaining" clusters where clusters elongate like a snake rather than forming compact blobs.

Complete Linkage — "furthest neighbor"

$$d_{\text{complete}}(A,B) = \max_{a \in A,\, b \in B} d(a,b)$$

Uses the furthest pair of points. Produces compact, roughly equal-diameter clusters. Sensitive to outliers because a single far-away point inflates the cluster diameter.

Average Linkage (UPGMA)

$$d_{\text{avg}}(A,B) = \frac{1}{|A||B|} \sum_{a \in A} \sum_{b \in B} d(a,b)$$

Averages all pairwise distances between the two clusters. A balanced compromise — less sensitive to outliers than complete, less prone to chaining than single. Widely used in bioinformatics.

Ward Linkage — "minimum variance"

$$d_{\text{Ward}}(A,B) = \sqrt{\frac{|A|\,|B|}{|A|+|B|}\,\|\mu_A - \mu_B\|^2}$$

Merges the pair of clusters whose union has the smallest increase in total within-cluster sum of squares (ESS). Ward is the agglomerative analogue of k-means and generally produces the most compact, equal-sized clusters. It is the default choice for most applications on continuous data.

🔑 Key Property

Ward linkage is the only linkage that minimizes an objective function (total within-cluster variance). All other linkages are purely geometric distance-based heuristics. This makes Ward the agglomerative equivalent of k-means, and explains why it usually outperforms other linkages when clusters are globular and roughly equal in size.

The Math — Dendrogram & Cophenetic Correlation
▼

The Dendrogram

A dendrogram is a tree diagram where each leaf is a data point and each internal node records a merge. The height of a node equals the inter-cluster distance at which the merge occurred. To obtain \(k\) clusters, draw a horizontal cut line at height \(h\) such that exactly \(k\) branches cross it — all points in the same branch become one cluster.

$$\text{number of clusters} = \#\{\text{branches that cross the cut line at height } h\}$$

Cophenetic Distance & Cophenetic Correlation

The cophenetic distance \(t(i,j)\) between two points \(x_i, x_j\) is the height in the dendrogram at which they were first joined into the same cluster:

$$t(i,j) = \min\{h : x_i \text{ and } x_j \text{ are in the same cluster at height } h\}$$

The cophenetic correlation coefficient (CPCC) measures how faithfully the dendrogram preserves the original pairwise distances. Let \(d(i,j)\) be the original distance and \(t(i,j)\) the cophenetic distance. CPCC is the Pearson correlation between these two distance vectors:

$$r_c = \frac{\sum_{i < j}\bigl(d(i,j)-\bar{d}\bigr)\bigl(t(i,j)-\bar{t}\bigr)}{\sqrt{\sum_{i < j}\bigl(d(i,j)-\bar{d}\bigr)^2 \cdot \sum_{i < j}\bigl(t(i,j)-\bar{t}\bigr)^2}}$$

A CPCC close to 1 means the dendrogram is a faithful summary of the distance matrix. Values above 0.75 are generally considered good. Average and complete linkage tend to achieve higher CPCC than single linkage on compact datasets.

Numerical Trace — 6 points, Ward linkage

Points: \(A=(1,1),\, B=(2,2),\, C=(6,1),\, D=(7,2),\, E=(4,5),\, F=(5,6)\). Ward distances (first pass):

  • \(d_W(A,B) = \sqrt{\tfrac{1}{2}} \cdot \|A-B\| = \sqrt{0.5}\cdot\sqrt{2} = 1.0000\) — minimum
  • \(d_W(C,D) = 1.0000\), \(d_W(E,F) = 1.0000\) — three-way tie

Step 1–3: Merge \(\{A,B\}\), \(\{C,D\}\), \(\{E,F\}\) simultaneously at height 1.414 (Euclidean) / 1.000 (Ward criterion). Step 4: \(d_W(AB, EF)=5.00\), \(d_W(CD,EF)=4.472\) → merge \(\{C,D,E,F\}\) at Ward height 4.472. Step 5: merge all at 7.303.

⚠️ Common Misconception

The y-axis of a dendrogram is the inter-cluster distance (merge height), not the number of clusters. The horizontal cut line is placed on the y-axis, not the x-axis. Also, scipy's Ward linkage stores \(\sqrt{\Delta\text{ESS}}\) as the height, so heights are square roots of the variance increase — you must square them to recover the ESS.

From Scratch — NumPy agglomerative (Ward)

import numpy as np
from scipy.spatial.distance import squareform, pdist
def ward_distance(X, idxA, idxB):
"""Ward distance = sqrt( nA*nB/(nA+nB) ) * ||muA - muB||"""
nA, nB = len(idxA), len(idxB)
muA = X[idxA].mean(0)
muB = X[idxB].mean(0)
return np.sqrt(nA * nB / (nA + nB)) * np.linalg.norm(muA - muB)
def agglomerative_ward(X):
n = len(X)
clusters = {i: [i] for i in range(n)} # each point its own cluster
linkage = [] # (idx_A, idx_B, distance, new_size)
next_id = n
while len(clusters) > 1:
# Find pair with minimum Ward distance
ids = list(clusters.keys())
best_d, best_pair = np.inf, (ids[0], ids[1])
for i in range(len(ids)):
for j in range(i+1, len(ids)):
d = ward_distance(X, clusters[ids[i]], clusters[ids[j]])
if d < best_d:
best_d, best_pair = d, (ids[i], ids[j])
a, b = best_pair
merged = clusters[a] + clusters[b]
linkage.append((a, b, best_d, len(merged)))
clusters[next_id] = merged # new cluster gets new id
del clusters[a]; del clusters[b]
next_id += 1
return linkage
def cophenetic_correlation(X, linkage_matrix):
"""Pearson r between original pairwise distances and cophenetic distances."""
n = len(X)
d_orig = squareform(pdist(X)) # original distances
d_coph = np.zeros((n, n))
# Reconstruct cluster membership at each merge step
members = {i: {i} for i in range(n)}
next_id = n
for a, b, height, _ in linkage_matrix:
merged = members[a] | members[b]
for i in members[a]:
for j in members[b]:
d_coph[i,j] = d_coph[j,i] = height
members[next_id] = merged; del members[a]; del members[b]
next_id += 1
# Pearson correlation on upper triangle
idx = np.triu_indices(n, k=1)
return np.corrcoef(d_orig[idx], d_coph[idx])[0,1]

Production Usage — scipy + sklearn

from scipy.cluster.hierarchy import linkage, dendrogram, fcluster, cophenet
from scipy.spatial.distance import pdist
from sklearn.cluster import AgglomerativeClustering
import matplotlib.pyplot as plt
# --- scipy: full dendrogram + cophenetic correlation ---
Z = linkage(X, method='ward') # methods: 'single','complete','average','ward'
c, coph_dists = cophenet(Z, pdist(X))
print(f"Cophenetic correlation: {c:.4f}") # closer to 1 = better
# Cut dendrogram to get k clusters
labels = fcluster(Z, t=3, criterion='maxclust') # exactly 3 clusters
labels = fcluster(Z, t=5.0, criterion='distance') # cut at height 5.0
# Plot dendrogram
fig, ax = plt.subplots(figsize=(10, 4))
dendrogram(Z, ax=ax, color_threshold=5.0) # color_threshold draws the cut line
ax.axhline(y=5.0, color='r', linestyle='--', label='cut')
plt.tight_layout(); plt.show()
# --- sklearn: drop-in replacement (no dendrogram, but faster for large n) ---
model = AgglomerativeClustering(n_clusters=3, linkage='ward')
labels = model.fit_predict(X)
# ⚠️ Gotcha: sklearn's AgglomerativeClustering does NOT expose the dendrogram
# Use scipy if you need the full merge tree or cophenetic correlation

Key Takeaways & When to Use
▼

When to use Hierarchical Clustering:

  • You don't know the number of clusters ahead of time — try multiple cuts.
  • You want a visual, interpretable summary of cluster structure (dendrogram).
  • Dataset is small to medium (\(n \lesssim 10{,}000\)) — Ward is \(O(n^2 \log n)\).
  • Clusters are not necessarily globular (single linkage handles elongated shapes).

When NOT to use:

  • Very large datasets (\(n \gg 10{,}000\)) — use DBSCAN, k-means, or BIRCH instead.
  • Once merged, clusters are never split (no backtracking) — merges can be suboptimal.
  • High-dimensional data with many noisy features — distances become unreliable (curse of dimensionality). Reduce dimensionality first with PCA or UMAP.
🎯 Decision Guide

Compact, equal-sized clusters → Ward. Non-convex, irregular shapes → Single (carefully). General-purpose or bioinformatics → Average (UPGMA). Unknown structure, want visual → Ward + dendrogram, then validate with CPCC > 0.75.

Related topics: k-means (flat, centroid-based alternative), DBSCAN (density-based, no pre-specified k), Gaussian Mixture Models (soft assignment), PCA (dimensionality reduction before clustering), Silhouette Score (cluster quality metric).
