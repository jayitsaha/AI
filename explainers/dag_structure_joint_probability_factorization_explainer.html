Understanding DAGs in Probability
▼

What is it? A Directed Acyclic Graph (DAG) is a graph where all edges point in one direction (directed) and there are no cycles (acyclic). In probabilistic machine learning, DAGs are used to represent the conditional dependencies between random variables, forming a Bayesian Network. Each node in the graph is a random variable, and a directed edge from \(X_i\) to \(X_j\) means \(X_i\) is a parent of \(X_j\), implying that \(X_j\) directly depends on \(X_i\).

Analogy: Imagine a chain of dominoes. Each domino falling (an event) causes the next one to fall (another event). The direction of cause-and-effect is clear, and a domino can't cause itself to fall again later (no cycles). A DAG is like a complex network of dominoes, where some dominoes might be triggered by multiple others, but the overall flow of influence is always "forward." This structure allows us to break down complex joint probabilities into simpler, local conditional probabilities.

💡 If you remember one thing

The core power of a DAG in probability is that it allows us to factorize the joint probability distribution of all variables into a product of conditional probabilities, where each variable is conditioned ONLY on its direct parents in the graph. This is a massive simplification from needing to know all possible dependencies.

How Factorization Works Internally
▼

The Chain Rule vs. DAG Factorization

Any joint probability distribution \(P(X_1, \dots, X_n)\) can always be factorized using the general chain rule of probability:

$$P(X_1, \dots, X_n) = P(X_1) P(X_2 \mid X_1) P(X_3 \mid X_1, X_2) \dots P(X_n \mid X_1, \dots, X_{n-1})$$

This is always true, but it doesn't simplify anything because each term might depend on all preceding variables. The magic of a DAG comes from the local Markov property: each variable \(X_i\) is conditionally independent of its non-descendants given its parents.

The Local Markov Property

For a variable \(X_i\) in a Bayesian Network, its conditional probability distribution \(P(X_i \mid \text{all other variables})\) simplifies to \(P(X_i \mid \text{Parents}(X_i))\). This is the key assumption encoded by the DAG structure. It means we don't need to consider all variables that come before \(X_i\) in some arbitrary ordering; we only need its direct parents.

Substituting this into the chain rule (using an ordering consistent with the DAG, e.g., topological order) yields the simplified factorization:

$$P(X_1, \dots, X_n) = \prod_{i=1}^n P(X_i \mid \text{Parents}(X_i))$$

This product is taken over all variables \(X_i\) in the graph. If a variable has no parents (a root node), its term is simply \(P(X_i)\).

Design Decision: Why is this powerful?

Without a graphical model, specifying a joint distribution for \(N\) binary variables requires \(2^N - 1\) parameters. For \(N=10\), that's 1023 parameters. With a sparse DAG, each variable \(X_i\) only needs a Conditional Probability Table (CPT) for \(P(X_i \mid \text{Parents}(X_i))\). If each variable has at most \(k\) parents, the number of parameters grows linearly with \(N \cdot 2^k\), rather than exponentially with \(N\). This makes modeling feasible for many real-world systems.

🔑 Key Property

The factorization of a joint distribution according to a DAG is a direct consequence of the local Markov property. This property states that a node is conditionally independent of its non-descendants given its parents. This drastically reduces the number of parameters needed to define the joint distribution.

Why It Works — The Math
▼

Derivation from the Chain Rule and Local Markov Property

Let \(X_1, \dots, X_n\) be a set of random variables corresponding to nodes in a DAG. We can always write the joint probability using the chain rule (ordering variables topologically, such that parents always come before their children):

$$P(X_1, \dots, X_n) = P(X_1) \prod_{i=2}^n P(X_i \mid X_1, \dots, X_{i-1})$$

The local Markov property for a Bayesian Network states that each variable \(X_i\) is conditionally independent of its non-descendants given its parents. In a topological ordering, \(X_1, \dots, X_{i-1}\) includes all parents of \(X_i\), and potentially some non-descendants of \(X_i\) that are not its parents. By the local Markov property, we can simplify the conditional term:

$$P(X_i \mid X_1, \dots, X_{i-1}) = P(X_i \mid \text{Parents}(X_i))$$

Substituting this simplification into the chain rule, we obtain the fundamental factorization of the joint probability distribution according to the DAG:

$$P(X_1, \dots, X_n) = \prod_{i=1}^n P(X_i \mid \text{Parents}(X_i))$$

This elegant formula is the cornerstone of Bayesian Networks, allowing us to build complex probabilistic models from local, simpler conditional distributions.

⚠️ Important Condition

This factorization holds if and only if the joint distribution satisfies the local Markov property with respect to the DAG. In other words, the graph must accurately represent the conditional independencies of the underlying probability distribution. If the graph is incorrect, the factorization will be invalid.

Key Takeaways
▼

When to use DAG factorization:

  • Modeling complex systems: When you have many interdependent variables (e.g., medical diagnosis, fault detection, natural language processing).
  • Reducing parameter count: To make joint probability distributions tractable by exploiting conditional independencies.
  • Inference and learning: Forms the basis for algorithms that perform probabilistic inference (e.g., computing marginals, conditionals) and learning (e.g., estimating CPTs from data).
  • Causal inference: DAGs are often used to represent causal relationships, where edges denote direct causal influence, allowing for causal reasoning and intervention analysis.

When NOT to use / Limitations:

  • Cyclic dependencies: If your system truly has cycles (e.g., feedback loops), a DAG cannot represent it directly. You might need a Dynamic Bayesian Network (DBN) for time-series or other models.
  • Undirected dependencies: If relationships are purely correlational or symmetric (e.g., two symptoms that always appear together but neither causes the other), an undirected graphical model (Markov Random Field) might be more natural.
  • Unknown structure: Learning the optimal DAG structure from data is a hard problem (NP-hard in general) and often requires domain expertise or heuristic search.
💡 The Power of Locality

The core idea is to replace a single, astronomically complex global probability table with a collection of smaller, more manageable local conditional probability tables (CPTs). This "divide and conquer" approach makes probabilistic modeling of high-dimensional systems feasible.

Code Trace (Python for Factorization)
▼
import numpy as np
# Define CPTs (Conditional Probability Tables)
# P(A)
cpt_A = {0: 0.6, 1: 0.4}
# P(B | A)
cpt_B_given_A = {
(0, 0): 0.8, (0, 1): 0.2, # P(B=0|A=0), P(B=1|A=0)
(1, 0): 0.3, (1, 1): 0.7 # P(B=0|A=1), P(B=1|A=1)
}
# P(C | A)
cpt_C_given_A = {
(0, 0): 0.7, (0, 1): 0.3, # P(C=0|A=0), P(C=1|A=0)
(1, 0): 0.2, (1, 1): 0.8 # P(C=0|A=1), P(C=1|A=1)
}
# P(D | B, C)
cpt_D_given_BC = {
(0, 0, 0): 0.9, (0, 0, 1): 0.1, # P(D=0|B=0,C=0), P(D=1|B=0,C=0)
(0, 1, 0): 0.5, (0, 1, 1): 0.5, # P(D=0|B=0,C=1), P(D=1|B=0,C=1)
(1, 0, 0): 0.4, (1, 0, 1): 0.6, # P(D=0|B=1,C=0), P(D=1|B=1,C=0)
(1, 1, 0): 0.1, (1, 1, 1): 0.9 # P(D=0|B=1,C=1), P(D=1|B=1,C=1)
}
# Assignment for which to compute joint probability
assignment = {'A': 1, 'B': 1, 'C': 0, 'D': 1}
def compute_joint_probability(assignment, cpts):
p_A = cpts['A'][assignment['A']]
p_B_given_A = cpts['B'][(assignment['A'], assignment['B'])]
p_C_given_A = cpts['C'][(assignment['A'], assignment['C'])]
p_D_given_BC = cpts['D'][(assignment['B'], assignment['C'], assignment['D'])]
joint_prob = p_A * p_B_given_A * p_C_given_A * p_D_given_BC
return joint_prob
all_cpts = {
'A': cpt_A,
'B': cpt_B_given_A,
'C': cpt_C_given_A,
'D': cpt_D_given_BC
}
result = compute_joint_probability(assignment, all_cpts)
print(f"P({assignment}) = {result:.6f}")
# Expected: P(A=1, B=1, C=0, D=1) = P(A=1) * P(B=1|A=1) * P(C=0|A=1) * P(D=1|B=1,C=0)
# = 0.4 * 0.7 * 0.2 * 0.6 = 0.0336
