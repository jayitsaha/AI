Softmax: Multi-Class Output & Temperature Scaling

Turning raw logits into a probability distribution — and why dividing by T controls confidence
Intermediate Deep Learning Activation Functions O(n) per sample
1
Understanding Softmax
▼

What is it? Softmax is the standard output layer for multi-class classification. A network produces one raw, unbounded score (a logit) per class. Softmax turns that vector of arbitrary numbers into a proper probability distribution — every value between 0 and 1, and all values summing to exactly 1.

Analogy: Imagine five sports teams get raw "strength scores" from a computer model — numbers like 3.2, 1.1, 0.2, -1.5, 2.8 — which don't mean anything on their own (no fixed scale, can be negative). Softmax converts these scores into betting odds: the strongest team gets the biggest slice, the weakest gets a tiny slice, but every team gets a non-zero chance, and all the odds add up to 100%.

💡 If you remember one thing

Softmax exponentiates every logit (so relative differences become multiplicative, and everything turns positive), then normalizes by the sum: $$\sigma(z)_i = \frac{e^{z_i}}{\sum_{j=1}^n e^{z_j}}$$ A "temperature" \(T\) dividing the logits before this step controls how sharp or flat the resulting distribution is.

How Softmax Works Internally
▼

From Logits to Probabilities

A classifier's final linear layer outputs a raw score vector \(z \in \mathbb{R}^n\), one entry per class. These logits carry ranking information (higher = more likely) but are not probabilities: they can be negative, unbounded, and don't sum to 1. Softmax fixes both problems in two moves: exponentiate (forces positivity, amplifies the largest score exponentially more than the rest), then normalize (forces the sum to 1).

Numerical Stability: Subtract the Max First

Computed naively, \(e^{z_i}\) overflows for even moderately large logits (\(e^{1000}\) is infinity in float64). The fix exploits a shift-invariance property: subtracting any constant \(c\) from every logit before exponentiating leaves the output unchanged, because the constant factors out of both numerator and denominator and cancels:

$$\sigma(z)_i = \frac{e^{z_i - c}}{\sum_j e^{z_j - c}} = \frac{e^{z_i}}{\sum_j e^{z_j}}$$

Choosing \(c = \max_j z_j\) guarantees the largest exponent is \(e^0 = 1\) and every other term is \(\le 1\) — no overflow, and the smallest terms just underflow gracefully to 0 instead of blowing up.

Temperature Scaling

Dividing logits by a temperature \(T > 0\) before softmax rescales the gaps between them: \(\sigma(z/T)_i = e^{z_i/T} / \sum_j e^{z_j/T}\). Small \(T\) (e.g. 0.1) stretches the gaps apart, so the largest logit dominates and the distribution collapses toward a one-hot (as \(T \to 0\), softmax \(\to\) argmax). Large \(T\) (e.g. 10) compresses the gaps toward zero, so all exponentials approach \(e^0=1\) and the distribution flattens toward uniform (as \(T \to \infty\), softmax \(\to\) uniform \(1/n\)).

🔑 Key Property

Softmax is translation-invariant (adding a constant to every logit doesn't change the output) but not scale-invariant — multiplying logits by a factor (equivalently dividing by \(T\)) changes the sharpness of the distribution. This is exactly why temperature works.

Design Decision: Why Exponential, Not Linear Normalization?

You could normalize by dividing by the sum directly (\(z_i / \sum_j z_j\)), but that breaks for negative logits and doesn't amplify the winner. Exponentiation guarantees positivity for any real input and is monotonic, differentiable everywhere, and — critically — pairs perfectly with cross-entropy loss: the log in \(-\log \sigma(z)_y\) cancels the exp, giving clean, numerically stable gradients (the "log-sum-exp trick").

Why It Works — The Math
▼

The Jacobian of Softmax

Because every output \(\sigma_i\) depends on every input \(z_j\) (through the shared normalizer), softmax has a full \(n \times n\) Jacobian, not just a per-element derivative. Differentiate \(\sigma_i = e^{z_i}/S\) where \(S = \sum_k e^{z_k}\):

$$\frac{\partial \sigma_i}{\partial z_j} = \begin{cases} \sigma_i(1-\sigma_i) & i = j \\ -\sigma_i \sigma_j & i \neq j \end{cases} \;=\; \sigma_i(\delta_{ij} - \sigma_j)$$

Proof sketch (quotient rule): For \(i=j\): \(\partial_i(e^{z_i}/S) = (e^{z_i}S - e^{z_i}\cdot e^{z_i})/S^2 = \sigma_i - \sigma_i^2 = \sigma_i(1-\sigma_i)\). For \(i \neq j\): the numerator \(e^{z_i}\) doesn't depend on \(z_j\), so only the denominator changes: \(\partial_j(e^{z_i}/S) = -e^{z_i}\cdot e^{z_j}/S^2 = -\sigma_i\sigma_j\). Both cases combine into the Kronecker-delta form above.

In matrix form, the full Jacobian is:

$$J = \operatorname{diag}(\sigma) - \sigma\sigma^\top$$

This is a symmetric, negative-semidefinite-off-diagonal matrix: diagonal entries \(\sigma_i(1-\sigma_i) \ge 0\) (increasing \(z_i\) increases \(\sigma_i\)), off-diagonal entries \(-\sigma_i\sigma_j \le 0\) (increasing \(z_i\) must steal probability mass from every other class, since the row sums of \(J\) are always 0 — probabilities always sum to 1).

Link to Cross-Entropy

Softmax is almost always paired with cross-entropy loss \(L = -\log \sigma_y\) for true class \(y\). Composing the two, the gradient with respect to the logits collapses to a remarkably clean form:

$$\frac{\partial L}{\partial z_i} = \sigma_i - \mathbb{1}[i=y]$$

i.e. "predicted probability minus the one-hot target." This is why softmax + cross-entropy is the default classification head: the combined gradient is just the error vector, with no extra chain-rule terms from the Jacobian surviving.

⚠️ Common Misconception

"Softmax outputs are probabilities of correctness." Technically they're a distribution that sums to 1, but they are not calibrated unless the model was explicitly trained/calibrated for it. A softmax score of 0.9 does not mean a 90% chance the prediction is correct — modern deep networks are frequently overconfident (Guo et al. 2017), which is one motivation for using temperature scaling at inference time to calibrate outputs.

Key Takeaways
▼

When to use softmax:

  • Multi-class, single-label classification (exactly one correct class per example)
  • As the final layer paired with cross-entropy loss for training
  • Any time you need a proper probability distribution over discrete options (RL policy heads, attention weights, LLM next-token distributions)

When NOT to use:

  • Multi-label classification (multiple correct classes at once) — use independent sigmoids per class instead
  • Binary classification — a single sigmoid is equivalent and cheaper (softmax with 2 classes reduces to sigmoid)
  • When you need a genuinely calibrated confidence score without any temperature/Platt calibration step
💡 Mental Model

Softmax = "exponentiate to force positivity + amplify differences, then normalize to force a valid distribution." Temperature = "rescale the gaps between logits before that happens." Everything else (numerical stability, the Jacobian, the clean gradient with cross-entropy) follows directly from those two ideas.

Code Trace

import numpy as np
def softmax(z, T=1.0):
"""Numerically stable softmax with temperature."""
z_scaled = z / T # temperature scaling
z_shifted = z_scaled - np.max(z_scaled, axis=-1, keepdims=True) # stability
exp_z = np.exp(z_shifted) # exponentiate
return exp_z / np.sum(exp_z, axis=-1, keepdims=True) # normalize
z = np.array([3.2, 1.1, 0.2, -1.5, 2.8])
print(softmax(z)) # [0.540, 0.066, 0.027, 0.005, 0.362]
print(softmax(z, T=0.3)) # [0.791, 0.001, 0.000, 0.000, 0.208] — sharper
print(softmax(z, T=3.0)) # [0.339, 0.168, 0.125, 0.071, 0.297] — flatter
# Jacobian: d(softmax)/dz = diag(p) - outer(p, p)
def softmax_jacobian(p):
return np.diag(p) - np.outer(p, p)
# Softmax + cross-entropy gradient collapses to (p - one_hot(y))
def softmax_xent_grad(p, y_idx):
grad = p.copy()
grad[y_idx] -= 1.0
return grad # elegant: no Jacobian needed explicitly
