Strided Convolution as Alternative to Pooling

Learnable stride-2 downsampling vs fixed max/average pooling — the All-Convolutional Net idea
Intermediate CNN / Computer Vision Architecture O(k²·C) per output px
1
Understanding the Concept
▼

What is it? Every CNN needs to shrink its feature maps as it goes deeper — a 224×224 image can't stay 224×224 forever, or the network would be enormous and see nothing but tiny local patterns. The classic way to shrink is pooling: slide a window over the feature map and keep the max (or average) value, throwing everything else away. A strided convolution does the shrinking differently — it uses an ordinary learnable convolution, but moves the kernel by more than one pixel at a time (stride ≥ 2), so the output is smaller purely as a side effect of how far the kernel jumps.

Analogy: Pooling is like summarizing a paragraph by keeping only its loudest word — fast, cheap, and it never has to be told what "important" means. A strided convolution is like a trained editor reading the same paragraph and writing a shorter one that blends the ideas together in a way it learned works best. The editor costs more (has parameters to train) but can capture nuance the "loudest word" rule throws away.

💡 If you remember one thing

Pooling downsamples with a fixed, parameter-free rule (max or mean). A stride-2 convolution downsamples with a learned, weighted combination of the same window — same spatial shrinkage, but the network decides what to keep instead of a hard-coded max operator.

2
How It Works Internally
▼

Historical context

Early CNNs (LeNet, AlexNet, VGG) alternated conv layers with 2×2 max-pooling to downsample. Pooling was popular because it is cheap, adds zero parameters, and gives a small amount of translation invariance "for free." In 2014, Jost Tobias Springenberg et al. published "Striving for Simplicity: The All Convolutional Net" (ICLR 2015 workshop), showing that replacing every pooling layer with a stride-2 convolution matched or beat pooling-based architectures on CIFAR-10/100 and ImageNet, while simplifying the architecture to "just convolutions." This kicked off a trend — ResNet, and many modern CNNs, use strided convolutions (or strided conv + light pooling) rather than pooling-heavy designs.

The mechanism

A standard convolution slides a \(k \times k\) kernel over the input one pixel at a time (stride 1) and produces an output the same size (with padding). A strided convolution is the exact same operation, except the kernel jumps stride pixels between applications. With stride 2, the kernel visits roughly every other position, so the output height and width are roughly halved — precisely the same shrinkage factor a 2×2/stride-2 pooling layer gives.

Crucially, the kernel used for a strided convolution is trained by backpropagation like any other conv layer's weights. At every output position the network computes a weighted sum of the \(k \times k\) window (plus a bias), where the weights are learned to minimize the task loss — not fixed to "take the max" or "take the average."

Design decision: why not just downsample after a stride-1 conv?

You could run a normal stride-1 convolution and then max-pool the result — this is what classic CNNs did. A strided convolution fuses these two steps into one: the same learnable kernel both extracts features and reduces resolution in a single pass. This removes one layer, removes the pooling operator's fixed inductive bias, and lets every downsampling decision be shaped by gradient descent instead of a hand-picked reduction rule.

🔑 Key property

Pooling and strided convolution both map a \(k\times k\) window to one output value with stride \(s\). Pooling's reduction function is fixed (\(\max\) or \(\text{mean}\), 0 parameters); the strided conv's reduction function is a learned affine map \(\sum_{i,j} w_{ij}x_{ij} + b\) (\(k^2\!\cdot\! C_{in}\!\cdot\! C_{out}\) parameters), so it can represent max/average-like behavior as special cases but is not restricted to them.

3
Why It Works — The Math
▼

Output size — both operators shrink identically

For an input of size \(H \times W\), kernel size \(k\), padding \(p\), and stride \(s\), the output size of either a convolution or a pooling layer is given by the same formula:

$$H_{out} = \left\lfloor \frac{H + 2p - k}{s} \right\rfloor + 1$$

This is why the two are drop-in replacements for each other spatially: pick \(k=2,\,s=2,\,p=0\) for classic max-pool, or \(k=3,\,s=2,\,p=1\) for a common "replace the pool" strided conv — both roughly halve each spatial dimension.

What each operator computes at one output location

Let \(X\) be the \(k\times k\) window under the kernel at some output position. Max pooling computes:

$$y = \max_{i,j \in [1,k]} X_{ij} \qquad \frac{\partial y}{\partial X_{ij}} = \mathbb{1}[X_{ij} = \max(X)]$$

Gradients flow only through the single winning pixel — a hard, non-differentiable-almost-everywhere routing of gradient. A strided convolution instead computes a weighted sum:

$$y = \sum_{i=1}^{k}\sum_{j=1}^{k} w_{ij}\,X_{ij} + b \qquad \frac{\partial y}{\partial X_{ij}} = w_{ij}$$

Every pixel in the window contributes to both the forward value and the backward gradient, proportionally to its learned weight \(w_{ij}\). This is strictly more expressive: setting \(w_{ij}=1/k^2\) recovers average pooling; max pooling cannot be expressed exactly (it's non-linear), but the network can learn weights that approximate a "soft max" — sharply peaked weighting toward the strongest activation.

Parameter and compute cost

$$\text{params}_{pool} = 0 \qquad \text{params}_{conv} = (k^2 \cdot C_{in} + 1)\cdot C_{out}$$

Pooling is free in parameters and cheap in FLOPs (just comparisons). A strided conv with \(C_{in}=C_{out}=C\) channels costs \(k^2 C^2\) multiply-adds per output pixel — the same cost as any ordinary conv layer of that kernel size, since striding only changes how many output pixels are computed, not the cost of each one.

⚠️ Common misconception

"Strided convolution is pooling with extra steps." It is not — pooling's reduction is a fixed, non-parametric statistic (max/mean) applied identically at every layer and every training run. A strided conv's reduction is a learned, task-specific linear combination that changes as training progresses, and it can differ per output channel.

When to use strided convolution: deep architectures where you want every operation to be trainable end-to-end (all-convolutional nets, ResNets, GANs/diffusion U-Nets where pooling's information loss hurts pixel-level generation); when you can afford the extra parameters and compute; when downstream tasks are sensitive to fine detail that max-pooling would discard.

When to prefer pooling: very constrained parameter/compute budgets; when strong built-in translation invariance is valuable (e.g. classic image classification with limited data); as a cheap, zero-parameter regularizer late in training pipelines; global average pooling before a classifier head (parameter-free, hard to beat for that specific job).

💡 What Springenberg et al. (2014) actually found

Replacing every max-pool layer with a stride-2 conv matched or slightly improved accuracy on CIFAR-10/100 and ImageNet, with a simpler, more uniform architecture. It did not show strided conv is always strictly better — modern nets often mix both: strided convs inside the network, global average pooling at the very end.

Code Trace — PyTorch
▼
import torch, torch.nn as nn
# Classic block: conv (stride 1) + pooling downsamples
classic = nn.Sequential(
nn.Conv2d(C_in, C_out, kernel_size=3, stride=1, padding=1),
nn.ReLU(),
nn.MaxPool2d(kernel_size=2, stride=2) # 0 params, halves H,W
)
# All-convolutional block (Springenberg et al., 2014):
# fuse feature extraction + downsampling into ONE learned op
all_conv = nn.Sequential(
nn.Conv2d(C_in, C_out, kernel_size=3, stride=2, padding=1), # learns to downsample
nn.ReLU()
)
x = torch.randn(1, C_in, 6, 6)
print(classic(x).shape) # -> [1, C_out, 3, 3]
print(all_conv(x).shape) # -> [1, C_out, 3, 3] (same output size)
print(sum(p.numel() for p in classic[0].parameters())) # feature-extraction params only
print(sum(p.numel() for p in all_conv[0].parameters())) # extraction + downsampling fused
