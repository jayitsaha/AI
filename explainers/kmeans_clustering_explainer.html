Understanding K-Means
▼

What is it? K-Means is an unsupervised algorithm that partitions \(n\) data points into \(K\) groups (clusters) by alternately assigning points to their nearest center and recomputing each center as the mean of its group. It requires no labels — only the number of clusters \(K\).

Analogy: Imagine you have 100 city residents scattered on a map, and you need to place \(K\) fire stations to minimize total travel distance. You start with random locations, assign every resident to their nearest station, then move each station to the average location of the residents it serves. Repeat until nothing moves. That is Lloyd's algorithm.

If you remember one thing

K-Means minimizes within-cluster sum of squared Euclidean distances (inertia): $$\underset{\{C_k\},\{\mu_k\}}{\operatorname{argmin}} \sum_{k=1}^{K}\sum_{x_i \in C_k} \|x_i - \mu_k\|^2$$ Lloyd's algorithm is a coordinate-descent method on this objective — it never increases inertia and always converges.

Why it matters: K-Means is one of the most widely deployed algorithms in existence — used for customer segmentation, image compression, codebook learning, vector quantization, and as a component inside more complex pipelines (e.g., initializing GMMs, building cluster features, pre-training embeddings).

Common misconception

K-Means finds clusters that are convex and roughly equal in size. It will fail on non-convex shapes (moons, rings) and imbalanced clusters. The number of clusters \(K\) must be specified in advance.

How Lloyd's Algorithm Works Internally
▼

Lloyd's Algorithm — The Two-Step Loop

Lloyd's algorithm alternates between two steps until convergence:

Assign step: For each point \(x_i\), find the nearest centroid by Euclidean distance and assign it to that cluster:

$$c(i) = \underset{k \in \{1,\ldots,K\}}{\operatorname{argmin}}\; \|x_i - \mu_k\|^2$$

Update step: Move each centroid to the mean of the points currently assigned to it:

$$\mu_k \leftarrow \frac{1}{|C_k|}\sum_{x_i \in C_k} x_i$$

Each step is guaranteed to not increase the objective (inertia). Since the number of distinct partitions is finite, the algorithm converges in a finite number of steps — though not necessarily to the global minimum.

K-Means++ Smart Initialization

Random initialization often leads to suboptimal local minima (e.g., two centroids start inside the same true cluster). K-Means++ (Arthur & Vassilvitskii, 2007) uses a probabilistic seeding strategy:

  1. Choose the first centroid \(\mu_1\) uniformly at random from the data.
  2. For each subsequent centroid \(\mu_j\) \((j=2,\ldots,K)\): compute \(D(x)^2 = \min_{l

This spreads initial centroids far apart in a probabilistic sense, providing an \(O(\log K)\) approximation guarantee: the expected inertia of K-Means++ initialization is within \(O(\log K)\) of the optimal.

Design decision — why d² and not d?

Squaring the distance amplifies the penalty for very distant points, making it far more likely that the next centroid is placed in a genuinely far-away cluster rather than just slightly farther from existing centroids. This is the key to the approximation guarantee.

Mini-Batch K-Means

For large \(n\), full-batch Lloyd's is expensive (\(O(nKd)\) per iteration). Mini-Batch K-Means processes a random mini-batch \(B \subset \{1,\ldots,n\}\) per iteration and uses a per-centroid learning-rate update:

$$\mu_k \leftarrow (1 - \eta_k)\,\mu_k + \eta_k\,\bar{x}_k \qquad \eta_k = \frac{1}{\text{count}(k)}$$

This converges to a solution close to Lloyd's result but with \(O(|B| K d)\) per iteration — typically 10–100× faster on millions of points with negligible loss in quality.

The Math — Objective, Variants, K Selection
▼

Objective Function (Within-Cluster SSE / Inertia)

K-Means minimizes:

$$J = \sum_{k=1}^{K}\sum_{x_i \in C_k} \|x_i - \mu_k\|^2$$

This is NP-hard to optimize globally (the problem of optimal K-means partition is NP-hard in general \(d\)). Lloyd's algorithm finds a local minimum via coordinate descent.

Convergence Proof Sketch

Let \(J^{(t)}\) be the inertia at iteration \(t\).

Assign step: For each \(x_i\), choosing the nearest centroid gives the smallest \(\|x_i - \mu_k\|^2\) — so \(J^{(t+\frac{1}{2})} \le J^{(t)}\).

Update step: The centroid that minimizes \(\sum_{x_i \in C_k}\|x_i - c\|^2\) is the mean \(\mu_k = \frac{1}{|C_k|}\sum x_i\) (by differentiation and setting to zero). So \(J^{(t+1)} \le J^{(t+\frac{1}{2})}\). Since \(J \ge 0\) and the number of distinct partitions is finite, the sequence \(J^{(0)} \ge J^{(1)} \ge \ldots\) must converge. \(\square\)

Choosing K — Elbow Method

Plot inertia \(J\) vs \(K\). The "elbow" is where adding more clusters gives diminishing returns. On our dataset:

  • K=1: SSE = 151.5 (all points around one mean)
  • K=2: SSE = 67.8 (large drop)
  • K=3: SSE = 6.8 (massive drop — true structure recovered)
  • K=4: SSE = 5.8 (small improvement — over-splitting)

The elbow is clearly at K=3.

Choosing K — Silhouette Analysis

The silhouette coefficient for point \(x_i\) is:

$$s(i) = \frac{b(i) - a(i)}{\max\{a(i),\, b(i)\}}$$

where \(a(i)\) = mean distance to points in the same cluster (cohesion) and \(b(i)\) = mean distance to points in the nearest other cluster (separation). \(s(i) \in [-1, 1]\); values near +1 mean well-clustered. On our dataset, K=3 achieves silhouette = 0.799 — by far the highest, confirming the elbow choice.

K-Means++ Guarantee

Let \(J_{\text{opt}}\) be the optimal inertia and \(J_{\text{++}}\) be the expected inertia of the K-Means++ solution. Arthur & Vassilvitskii (2007) proved: \(\mathbb{E}[J_{\text{++}}] \le 8(\ln K + 2)\,J_{\text{opt}}\). In practice the gain is much larger — K-Means++ typically finds solutions 2–10× better than random init.

Key Takeaways
▼

When to use K-Means:

  • Data has roughly isotropic (spherical), similarly-sized clusters
  • You need fast, scalable clustering (\(n\) up to millions with mini-batch)
  • Cluster membership is hard (each point belongs to exactly one cluster)
  • As a preprocessing step: build cluster features, reduce search space

When NOT to use:

  • Clusters are non-convex (rings, moons) — use DBSCAN or spectral clustering
  • Clusters have very different densities or sizes — use GMM (soft assignment + covariance)
  • You do not know K — use DBSCAN (K-free) or sweep K with silhouette
  • Data has categorical features — Euclidean distance is meaningless; use K-Modes
Algorithm Hierarchy

K-Means (hard, spherical) ⊂ GMM (soft, elliptical) ⊂ DBSCAN (density, arbitrary shape). Each relaxes a constraint. K-Means is the fastest; DBSCAN the most flexible.

Code Trace
▼

From-scratch K-Means with K-Means++ init and mini-batch option:

import numpy as np
from sklearn.datasets import make_blobs
from sklearn.metrics import silhouette_score
def kmeans_plus_plus_init(X, k, rng):
"""K-Means++ seeding: O(n·K·d) initialization."""
n = len(X)
centroids = [X[rng.integers(n)]] # step 1: uniform random
for _ in range(1, k):
# D²(x) = min squared dist to any existing centroid
D2 = np.array([min(np.sum((x - c)**2) for c in centroids) for x in X])
probs = D2 / D2.sum() # normalize to probabilities
centroids.append(X[rng.choice(n, p=probs)]) # sample ∝ D²
return np.array(centroids)
def lloyd(X, k, init='k-means++', max_iter=300, tol=1e-4, seed=42):
"""Full Lloyd's algorithm with K-Means++ or random init."""
rng = np.random.default_rng(seed)
if init == 'k-means++':
centroids = kmeans_plus_plus_init(X, k, rng)
else:
centroids = X[rng.choice(len(X), k, replace=False)]
for iteration in range(max_iter):
# ── ASSIGN STEP ──
# dists[i,k] = ||x_i - μ_k||² shape (n, K)
dists = np.linalg.norm(X[:, None] - centroids[None, :], axis=2)
labels = np.argmin(dists, axis=1) # argmin over K
# ── UPDATE STEP ──
new_centroids = np.array(
[X[labels == k_].mean(axis=0) if (labels == k_).any()
else centroids[k_] # guard against empty cluster
for k_ in range(k)]
)
# Convergence: max centroid shift < tol
shift = np.max(np.linalg.norm(new_centroids - centroids, axis=1))
centroids = new_centroids
if shift < tol:
break
inertia = sum(np.sum((X[labels==k_] - centroids[k_])**2) for k_ in range(k))
return centroids, labels, inertia
# ── K selection ──
X, _ = make_blobs(n_samples=300, centers=3, cluster_std=0.8, random_state=42)
results = {}
for k in range(2, 8):
c, lbl, sse = lloyd(X, k, seed=0)
sil = silhouette_score(X, lbl)
results[k] = {'sse': sse, 'sil': sil}
print(f"K={k} SSE={sse:.1f} Silhouette={sil:.4f}")
# Production: sklearn with multiple restarts (n_init=10)
from sklearn.cluster import KMeans, MiniBatchKMeans
km = KMeans(n_clusters=3, init='k-means++', n_init=10, random_state=42)
km.fit(X)
print(km.inertia_, km.cluster_centers_)
# Mini-Batch for large datasets
mbkm = MiniBatchKMeans(n_clusters=3, batch_size=256, n_init=3, random_state=42)
mbkm.fit(X) # ~10-100x faster on millions of points
