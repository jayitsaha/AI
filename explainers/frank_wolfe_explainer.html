Understanding Frank-Wolfe
▼

What is it? The Frank-Wolfe algorithm (also called the conditional gradient method) solves constrained optimization problems without ever computing a projection onto the constraint set. Instead of the expensive "project back" step that Projected Gradient Descent requires, Frank-Wolfe asks a much simpler question at each iteration: "Which vertex of the constraint set does the gradient point toward?" It then moves toward that vertex.

Analogy: Imagine you are hiking downhill but must stay inside a fenced polygon. Projected Gradient Descent says: step in the steepest downhill direction, then if you fell outside the fence, snap back to the nearest point on the fence (expensive!). Frank-Wolfe says: look at the downhill direction, identify the fence corner that aligns best with it, then walk part-way toward that corner. You never leave the fence, no snapping needed — and each step only lands you at or between corners (sparse updates).

If you remember one thing

At each step, Frank-Wolfe solves a linear minimization oracle (LMO) over the feasible set \(\mathcal{C}\): find \(s_k = \underset{s \in \mathcal{C}}{\operatorname{argmin}}\; \nabla f(x_k)^\top s\). Then update \(x_{k+1} = x_k + \gamma_k(s_k - x_k)\). This is a convex combination — so \(x_{k+1} \in \mathcal{C}\) automatically. The FW gap \(g_k = \nabla f(x_k)^\top(x_k - s_k)\) serves as a convergence certificate.

How Frank-Wolfe Works Internally
▼

The Core Loop

Given a convex differentiable function \(f\) and a compact convex set \(\mathcal{C}\), each Frank-Wolfe iteration does exactly three things:

  1. Compute gradient \(\nabla f(x_k)\) at current point.
  2. Solve the LMO: Find \(s_k = \underset{s \in \mathcal{C}}{\operatorname{argmin}}\; \langle \nabla f(x_k),\, s \rangle\). This is a linear problem — always tractable, often analytical.
  3. Convex step: Move \(x_{k+1} = (1-\gamma_k) x_k + \gamma_k s_k\) with step size \(\gamma_k = \frac{2}{k+2}\).

Why Vertices? The Sparse Update Phenomenon

The LMO of a linear function over a polytope (e.g., simplex, \(\ell_1\)-ball, spectrahedron) always returns a vertex. Since \(x_{k+1}\) is a convex combination of \(x_k\) and a vertex \(s_k\), the iterates can be written as \(x_k = \sum_i \lambda_i^{(k)} v_i\) — a weighted sum of at most \(k+1\) vertices. This is the sparsity property: Frank-Wolfe naturally produces sparse solutions, making it ideal for matrix completion, LASSO-type problems, and sparse neural networks.

Step Size Strategies

Three common choices:

  • Decreasing: \(\gamma_k = \frac{2}{k+2}\) — simple, theory-backed \(O(1/k)\) rate.
  • Line search: \(\gamma_k = \underset{\gamma \in [0,1]}{\operatorname{argmin}}\; f(x_k + \gamma(s_k - x_k))\) — faster in practice.
  • Short step: \(\gamma_k = \min\!\left(1,\; \frac{g_k}{L \|s_k - x_k\|^2}\right)\) — uses local curvature \(L\).
Key Property — Projection-Free

Projected Gradient Descent requires computing \(\Pi_\mathcal{C}(x)\) — the Euclidean projection onto \(\mathcal{C}\). For complex sets (e.g., nuclear norm ball, positive semidefinite cone), this costs \(O(n^3)\) via SVD. The FW LMO for those same sets costs only \(O(n^2)\) — compute the top singular vector pair, not the full SVD. This difference is the main motivation for Frank-Wolfe in large-scale ML.

Why It Works — The Math
▼

Convergence Analysis via the Frank-Wolfe Gap

Assume \(f\) is convex and \(L\)-smooth: \(\|\nabla f(x) - \nabla f(y)\| \leq L\|x - y\|\) for all \(x,y \in \mathcal{C}\). Smoothness gives the quadratic upper bound:

$$f(y) \leq f(x) + \nabla f(x)^\top(y-x) + \frac{L}{2}\|y-x\|^2$$

Plugging in \(y = x_{k+1} = x_k + \gamma_k(s_k - x_k)\) and using \(d_k = s_k - x_k\):

$$f(x_{k+1}) \leq f(x_k) + \gamma_k \nabla f(x_k)^\top d_k + \frac{L\gamma_k^2}{2}\|d_k\|^2$$

Defining the Frank-Wolfe gap \(g_k = \nabla f(x_k)^\top(x_k - s_k) = -\nabla f(x_k)^\top d_k \geq 0\):

$$f(x_{k+1}) \leq f(x_k) - \gamma_k g_k + \frac{L\gamma_k^2}{2}D^2$$

where \(D = \max_{x,y \in \mathcal{C}}\|x-y\|\) is the diameter of \(\mathcal{C}\). Setting \(\gamma_k = \frac{2}{k+2}\) and telescoping gives the classical convergence rate:

$$f(x_k) - f^* \leq \frac{2LD^2}{k+2} = O\!\left(\frac{1}{k}\right)$$

The FW Gap as a Certificate

A critical feature: the FW gap \(g_k\) is computable and certifies suboptimality. Since \(\langle \nabla f(x), x^* - x \rangle \leq 0\) for optimal \(x^*\), we have \(g_k \geq f(x_k) - f^*\). Thus when \(g_k \leq \varepsilon\), you are guaranteed \(\varepsilon\)-optimal. This is unlike vanilla gradient methods where you must guess when to stop.

Comparison: Frank-Wolfe vs Projected Gradient Descent

Both achieve \(O(1/k)\) rate for smooth convex problems, but with different per-iteration costs. PGD's projection can be cheap for simple sets (box, simplex via sorting) but expensive for structured sets. FW's LMO is cheap for polytopes (linear programming) and structured sets (power iteration for nuclear norm ball), making FW preferable at scale.

Common Pitfall — O(1/k) is Optimal for FW (But PGD Can Achieve O(1/k²))

Using momentum (e.g., Nesterov acceleration), Projected Gradient Descent achieves \(O(1/k^2)\) for smooth convex problems. The classical Frank-Wolfe algorithm cannot be accelerated to \(O(1/k^2)\) in the same way because its updates are constrained to stay within \(\mathcal{C}\) via convex combinations — the geometry prevents the "overshooting" that acceleration requires. Variants like Away-Step FW and Pairwise FW improve convergence on polytopes.

Key Takeaways & When to Use
▼

Use Frank-Wolfe when:

  • Projection is expensive but the LMO is cheap (nuclear norm ball, spectrahedron, flow polytopes)
  • You need sparse solutions naturally (e.g., boosting, sparse recovery)
  • The feasible set is a polytope and vertices have semantic meaning (e.g., matchings, paths)
  • Memory is constrained — FW never needs to store a full projection computation

Do NOT use Frank-Wolfe when:

  • You need faster than \(O(1/k)\) — use PGD + Nesterov acceleration instead
  • The objective is non-smooth — FW requires \(\nabla f\) to exist
  • The constraint is a simple box or \(\ell_2\) ball — projection is trivial, PGD is preferred
  • Stochastic/online settings — FW's fixed-point analysis is harder to extend
FW in Modern ML

Frank-Wolfe underpins boosting (each boosting round adds a weak learner — a vertex of the prediction polytope), matrix completion (LMO = rank-1 update via power iteration), SVM training (the working set selection is an LMO over the dual simplex), and sparse attention mechanisms. The sparsity-inducing property makes it a natural fit for interpretable ML models.

Code Trace — From Scratch
▼
import numpy as np
def frank_wolfe(f, grad_f, lmo, x0, C, n_iters=50, tol=1e-6):
"""Frank-Wolfe / Conditional Gradient Method.
Args:
f : objective function (convex, smooth)
grad_f : gradient of f
lmo : linear minimization oracle — returns argmin_{s in C} g.dot(s)
x0 : starting point in C
n_iters: max iterations
tol : stop when FW gap < tol
"""
x = x0.copy()
history = [{'x': x.copy(), 'f': f(x)}]
for k in range(1, n_iters + 1):
g = grad_f(x) # gradient at current iterate
s = lmo(g) # solve linear oracle: argmin_{s in C} g.dot(s)
fw_gap = g.dot(x - s) # FW gap: certificate of suboptimality
if fw_gap <= tol: # converged! gap certifies optimality
break
gamma = 2.0 / (k + 2) # decreasing step size (classical schedule)
x = (1 - gamma) * x + gamma * s # convex combo — stays in C!
history.append({'x': x.copy(), 'fw_gap': fw_gap, 's': s.copy(), 'k': k})
return x, history
# Example: minimize 0.5||x-(2,2)||^2 over L1 ball
center = np.array([2.0, 2.0])
f = lambda x: 0.5 * np.sum((x - center)**2)
grad_f = lambda x: x - center
vertices = np.array([[1,0],[-1,0],[0,1],[0,-1]], dtype=float)
lmo = lambda g: vertices[np.argmin([g.dot(v) for v in vertices])]
x0 = np.zeros(2)
x_opt, hist = frank_wolfe(f, grad_f, lmo, x0, None, n_iters=20)
print(f"Optimal x: {x_opt}") # ≈ (0.5, 0.5)
print(f"f(x*): {f(x_opt):.4f}") # ≈ 2.25
