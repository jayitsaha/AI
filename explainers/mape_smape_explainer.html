Mean Absolute Percentage Error & Symmetric MAPE — scale-free regression metrics, their asymmetry problem, and the sMAPE fix

1
The 30-Second Version

Suppose you predict a product will sell 110 units but it actually sells 100. Your error is 10 units. But is that good or bad? Depends on scale — 10 units off on a product that sells 100 is very different from 10 units off on one that sells 1,000,000.

MAPE (Mean Absolute Percentage Error) expresses each error as a percentage of the actual value, then averages those percentages. This makes it scale-free: you can compare forecast quality across products, markets, and time horizons directly.

Real-World Analogy

Think of MAPE like a GPS accuracy rating in "percentage of journey length". A 1 km error on a 2 km trip (50%) is terrible. A 1 km error on a 10,000 km flight (0.01%) is negligible. The raw error (1 km) is meaningless without context — the percentage gives context.

💡 If You Remember One Thing

MAPE divides each absolute error by the actual value — making it scale-free but asymmetric (over-forecasts are capped at 100%, under-forecasts are unbounded) and undefined when any actual = 0. sMAPE replaces the denominator with the average of actual and forecast, gaining symmetry at the cost of a slightly different bias profile.

2
Formulas & Core Properties

Let \(y_i\) be the actual value and \(\hat{y}_i\) the forecast for observation \(i\), over \(n\) samples.

MAPE

$$\text{MAPE} = \frac{100\%}{n} \sum_{i=1}^{n} \left| \frac{y_i - \hat{y}_i}{y_i} \right|$$

Each term is the absolute percentage error (APE): \(\text{APE}_i = \left| \frac{y_i - \hat{y}_i}{y_i} \right| \times 100\%\). The denominator is the actual \(y_i\).

sMAPE (Makridakis 1993)

$$\text{sMAPE} = \frac{100\%}{n} \sum_{i=1}^{n} \frac{|y_i - \hat{y}_i|}{\tfrac{1}{2}(|y_i| + |\hat{y}_i|)}$$

The denominator is the average of |actual| and |forecast|, making it symmetric: swapping \(y_i\) and \(\hat{y}_i\) gives the same value. Range: \([0\%, 200\%]\).

⚠️ Key Asymmetry of MAPE

With MAPE, an over-forecast (predict 200, actual 100) gives APE = 100%. But an equal-magnitude under-forecast (predict 50, actual 100) gives APE = 50%. The denominator is always the actual, so the metric penalises under-forecasting less than over-forecasting for the same absolute deviation. sMAPE uses the symmetric denominator \(\tfrac{1}{2}(|y| + |\hat{y}|)\) to fix this.

The Blow-Up Near Zero & Why It Matters

The central technical problem with MAPE is that as the actual value \(y_i \to 0^+\), the APE \(\to \infty\) even for tiny absolute errors. This is not a rounding artefact — it's a structural property of dividing by a small denominator.

$$\text{APE}_i = \frac{|\hat{y}_i - y_i|}{y_i} \xrightarrow{y_i \to 0^+} \infty$$

Example: actual = 0.1, forecast = 0.2. Absolute error = 0.1 (tiny). But APE = 100%. Meanwhile actual = 1000, forecast = 1100. Absolute error = 100 (large). APE = 10%. MAPE would rank the first forecast as dramatically worse, even though the absolute deviation is 1000× smaller.

sMAPE mitigates this: with actual = 0.1 and forecast = 0.2, the denominator becomes \(\tfrac{1}{2}(0.1 + 0.2) = 0.15\), giving sMAPE = \(\frac{0.1}{0.15} \times 100\% \approx 66.7\%\). Still high, but bounded and symmetric.

🚨 Intermittent Demand Warning

In retail and supply chain, many SKUs have intermittent demand: weeks with zero sales. MAPE is undefined for those weeks. Practitioners either skip zero-actual periods (introducing bias) or switch to MASE (Mean Absolute Scaled Error), which uses a historical naive-forecast baseline in the denominator instead.

When to Use Each
MetricUse WhenAvoid When
MAPE Actuals always > 0; need intuitive % for business; comparing across different scales Intermittent / zero-actual data; under-forecast penalty should equal over-forecast
sMAPE Need symmetry; near-zero but nonzero actuals; M-competition benchmarking Actuals can be exactly 0 (undefined); when business stakeholders need intuitive %)
MASE Intermittent demand; exact zeros in data; competing with seasonal naive baseline Simple one-off forecasts where a naive baseline isn't meaningful
RMSE / MAE Scale matters; absolute units are meaningful; comparing models on the same dataset Cross-scale or cross-series comparisons
✅ Bottom Line

Use MAPE when actuals are safely above zero and you want business-readable percentages. Switch to sMAPE when you need symmetry or near-zero values are possible. Fall back to MASE when zeros appear. Always pair any relative metric with an absolute one (MAE/RMSE) so you don't lose sight of the actual error magnitude.
