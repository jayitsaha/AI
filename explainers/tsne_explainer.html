Understanding t-SNE
▼

What is it? t-SNE is a technique that takes data living in hundreds or thousands of dimensions (imagine a point cloud in 1000D space) and squashes it down to 2D — while trying to keep similar things close together. It's most famous for producing stunning cluster plots from image embeddings, word vectors, or gene expression data.

Analogy: Imagine you have a globe with cities clustered by region. You want to draw a flat map that keeps neighbors near each other. t-SNE is like a rubber-sheet that stretches and compresses, pulling similar groups together while pushing dissimilar groups apart — but unlike a flat map projection, it's free to distort distances however needed. The key trick: it uses a different shape of kernel in 2D than in high-D, so tightly packed neighborhoods in high-D "explode" into separated clusters in 2D.

💡 If you remember one thing

t-SNE converts similarities to probabilities — Gaussian in high-D, Student-t in low-D — then finds a 2D layout that minimizes KL divergence between them. The heavy-tailed Student-t in 2D lets clusters separate cleanly without crowding. But: distances and cluster sizes in the final plot are meaningless. Only neighborhood structure is preserved.

2
How t-SNE Works Internally
▼

Step 1 — High-D Affinities (Gaussian + Perplexity)

For each point \(x_i\) in \(\mathbb{R}^D\), compute a conditional probability \(p_{j|i}\) representing how likely \(x_j\) is to be a "neighbor" of \(x_i\):

$$p_{j|i} = \frac{\exp(-\|x_i - x_j\|^2 / 2\sigma_i^2)}{\sum_{k \neq i} \exp(-\|x_i - x_k\|^2 / 2\sigma_i^2)}$$

The bandwidth \(\sigma_i\) is chosen per-point via binary search so that the effective number of neighbors — the perplexity — matches a user-specified value. Perplexity \(\approx\) the number of meaningful neighbors (typically 5–50). Low perplexity: only the nearest few matter; high perplexity: broad, global structure matters more.

$$\text{Perplexity} = 2^{H(P_i)}, \quad H(P_i) = -\sum_j p_{j|i} \log_2 p_{j|i}$$

The conditional probabilities are symmetrized: \(p_{ij} = \frac{p_{j|i} + p_{i|j}}{2n}\), so the full high-D joint \(P\) is symmetric and sums to 1.

Step 2 — Low-D Affinities (Student-t, df=1)

In the 2D embedding, points \(y_i, y_j \in \mathbb{R}^2\) are compared using the Cauchy (Student-t with 1 degree of freedom) kernel:

$$q_{ij} = \frac{(1 + \|y_i - y_j\|^2)^{-1}}{\sum_{k \neq l}(1 + \|y_k - y_l\|^2)^{-1}}$$

Why Student-t and not Gaussian? The Gaussian in high-D creates a "crowding problem" — there's not enough room in 2D to place moderately-distant points correctly. The heavy tail of Student-t alleviates this: moderately-far points in 2D get lower \(q_{ij}\) than a Gaussian would give, so the optimizer pushes them far away, creating the characteristic separated clusters.

Step 3 — KL Divergence + Gradient Descent

Minimize KL divergence from high-D \(P\) to low-D \(Q\):

$$\mathcal{L} = KL(P \| Q) = \sum_{i \neq j} p_{ij} \log \frac{p_{ij}}{q_{ij}}$$

The gradient has a beautiful additive form — an attractive force for dissimilar \(q_{ij} > p_{ij}\) and repulsive for the rest — computed as:

$$\frac{\partial \mathcal{L}}{\partial y_i} = 4 \sum_j (p_{ij} - q_{ij})(y_i - y_j)(1 + \|y_i - y_j\|^2)^{-1}$$

Optimization runs with gradient descent + momentum for ~1000 iterations, with early exaggeration (multiply \(p_{ij} \times 4\) for the first 250 iterations) to form initial tight clusters.

🔑 Key Design Insight

The asymmetry between kernels is intentional: Gaussian in high-D faithfully captures local neighborhoods; Student-t in low-D prevents the crowding problem by giving more "room" for moderately-distant points to spread out. This mismatch is what creates the tight, well-separated clusters.

⚠️ Critical Limitations

Non-parametric: No explicit mapping \(f: \mathbb{R}^D \to \mathbb{R}^2\) — you cannot embed new points without re-running. Non-convex: Different random seeds give different results. Distances are meaningless: cluster A being 3× farther from cluster B than cluster C tells you nothing. Cluster sizes are meaningless: dense/sparse clusters in high-D may appear identically sized in 2D. Use only topology (who is near whom).

The Math — Barnes-Hut & Gradient Derivation
▼

Naïve t-SNE: O(n²) bottleneck

The numerator of \(q_{ij}\) requires computing all \(n(n-1)/2\) pairwise distances each gradient step — \(O(n^2)\) per iteration, infeasible for \(n > 10{,}000\).

Barnes-Hut Approximation: O(n log n)

Van der Maaten (2014) adapted the Barnes-Hut tree algorithm from n-body physics. The idea: if a cluster of points \(C\) is far enough from point \(y_i\), approximate the entire cluster's repulsive contribution as if it were a single point at the cluster centroid, weighted by cluster size:

$$\frac{\partial \mathcal{L}^{\text{rep}}}{\partial y_i} \approx \sum_{\text{cells}} |C| \cdot \tilde{q}_{iC} \cdot (y_i - \bar{y}_C)(1 + \|y_i - \bar{y}_C\|^2)^{-1}$$

A quad-tree (2D) or oct-tree (3D) partitions the embedding space. A cell \(C\) with side length \(r\) and centroid distance \(d\) is accepted if \(r/d < \theta\) (threshold, typically \(\theta = 0.5\)). This gives \(O(n \log n)\) complexity per gradient step.

The attractive forces (from \(p_{ij} > 0\) pairs only) remain exact — but since \(p_{ij}\) is sparse (only \(\approx 3k\) non-zero per row after perplexity normalization, where \(k\) = perplexity), this is also \(O(nk)\) = \(O(n)\).

Gradient Derivation (compact)

Starting from \(\mathcal{L} = \sum_{ij} p_{ij} \log p_{ij} - \sum_{ij} p_{ij} \log q_{ij}\), the first term is constant w.r.t. \(y\). Let \(Z = \sum_{kl}(1+\|y_k-y_l\|^2)^{-1}\). Then:

$$\frac{\partial \mathcal{L}}{\partial y_i} = 4\sum_j \underbrace{(p_{ij} - q_{ij})}_{\text{signed mismatch}} \underbrace{(y_i - y_j)}_{\text{direction}} \underbrace{(1 + \|y_i-y_j\|^2)^{-1}}_{\text{Student-t weight}}$$

When \(p_{ij} > q_{ij}\): neighbors in high-D aren't close enough in 2D → attractive force pulling \(y_i\) toward \(y_j\).
When \(p_{ij} < q_{ij}\): points too close in 2D that aren't neighbors in high-D → repulsive force.

📐 Perplexity Binary Search

For each \(x_i\), find \(\sigma_i\) such that \(H(P_i) = \log_2(\text{perplexity})\). Since \(H(P_i)\) is monotonically increasing in \(\sigma_i\), binary search converges in \(\sim 50\) iterations. This is the most expensive precomputation step: \(O(n^2)\) total if done naïvely, but only \(O(nk)\) if only \(k\)-nearest neighbors are considered (BH-t-SNE uses this).

Key Takeaways & When to Use t-SNE
▼

Use t-SNE when:

You want to visually explore cluster structure in high-D data (e.g., MNIST embeddings, BERT representations, single-cell RNA-seq). The goal is qualitative insight, not a deployable embedding.

Do NOT use t-SNE when:

You need to embed new points at inference time (use UMAP or a parametric encoder). You need distance-preserving 2D coordinates. You need deterministic, reproducible embeddings (fix random seed + be aware of non-convexity). You care about the global layout (UMAP preserves global structure better).

🚫 The Three Lies of t-SNE Plots

1. Distance is meaningless: "Cluster A is 5× farther from B than C" — not a real signal.
2. Cluster size is meaningless: A large-looking cluster isn't necessarily a denser or larger group in high-D.
3. Topology is only local: Whether cluster A is "between" B and C in 2D is an artifact of the random init + perplexity — not a structural fact.

Code Trace — t-SNE From Scratch
▼

The core t-SNE loop — each line synchronized with the visualization steps above.

import numpy as np
from scipy.spatial.distance import cdist
def compute_pij(X, perplexity=30, tol=1e-5):
n = X.shape[0]
D = cdist(X, X, 'sqeuclidean') # all pairwise sq distances
P = np.zeros((n, n))
log_perp = np.log2(perplexity) # target entropy
for i in range(n): # binary search sigma_i per point
sigma_lo, sigma_hi = 1e-20, 1e20
for _ in range(50): # 50 bisection steps
sigma = (sigma_lo + sigma_hi) / 2
p = np.exp(-D[i] / (2*sigma**2)); p[i] = 0
p /= p.sum(); H = -np.sum(p * np.log2(p + 1e-12))
if H > log_perp: sigma_hi = sigma # entropy too high
else: sigma_lo = sigma # entropy too low
P[i] = p
return (P + P.T) / (2*n) # symmetrize
def tsne_gradient(Y, P, exaggeration=1.0):
n = Y.shape[0]
D = 1 / (1 + cdist(Y, Y, 'sqeuclidean')) # Student-t kernel
np.fill_diagonal(D, 0)
Q = D / D.sum() # normalize → q_ij
PQ = exaggeration * P - Q # signed mismatch
grad = 4 * np.einsum('ij,ijk,ij->ik', PQ, Y[:,None]-Y[None,:], D)
return grad, -np.sum(P * np.log((P+1e-12)/(Q+1e-12))) # grad + KL

Multiplying \(p_{ij}\) by 4 for the first 250 iterations amplifies attractive forces — clusters form tight blobs fast. After iteration 250, exaggeration is removed (factor = 1), and the optimizer fine-tunes the layout. This prevents a local minimum where all points collapse to the center.
