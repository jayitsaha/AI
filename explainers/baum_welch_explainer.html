Baum-Welch Algorithm

An Expectation-Maximization (EM) algorithm for Hidden Markov Models
Foundational Machine Learning Probabilistic Models O(N²T)
1
Understanding Baum-Welch
▼

What is it? The Baum-Welch algorithm is a specific instance of the Expectation-Maximization (EM) algorithm used to find the unknown parameters of a Hidden Markov Model (HMM). An HMM describes a system where the observed data is generated by an underlying process whose states are hidden or unobserved. Baum-Welch allows us to learn the probabilities governing these hidden states and their emissions, given only a sequence of observations.

Analogy: Imagine you're a detective trying to understand a criminal's mood (happy, angry, neutral — the hidden states) based only on their daily actions (buying flowers, yelling at a clerk, sleeping in — the observations). You don't know how likely they are to start in a certain mood, how likely they are to switch between moods, or how likely each mood is to cause a specific action. Baum-Welch is your iterative process: you make an initial guess about these probabilities, then use those guesses to estimate the most likely mood sequence for each day. Then, you refine your initial probability guesses based on these estimated mood sequences, and repeat. Over time, your model of the criminal's mood-action relationship gets better and better.

💡 If you remember one thing

Baum-Welch is an iterative algorithm that uses the Forward-Backward procedure (E-step) to infer the expected frequencies of hidden states and transitions, and then uses these expected frequencies to update the HMM parameters (M-step). It aims to maximize the likelihood of the observed data, even though the hidden states are never directly seen.

2
How It Works Internally
▼

The Hidden Markov Model (HMM)

An HMM is defined by its parameters \(\lambda = (\pi, A, B)\):

  • \(\pi\): Initial state probabilities. \(\pi_i = P(q_1 = S_i)\) is the probability of starting in hidden state \(S_i\).
  • \(A\): Transition probability matrix. \(a_{ij} = P(q_{t+1} = S_j | q_t = S_i)\) is the probability of transitioning from state \(S_i\) to state \(S_j\).
  • \(B\): Emission probability matrix. \(b_j(k) = P(o_t = V_k | q_t = S_j)\) is the probability of observing symbol \(V_k\) while in state \(S_j\).

The goal of Baum-Welch is, given an observation sequence \(O = (o_1, o_2, \dots, o_T)\), to find the HMM parameters \(\lambda^*\) that maximize the probability \(P(O|\lambda)\).

The Expectation-Maximization (EM) Loop

Baum-Welch is an iterative algorithm, alternating between two steps:

  1. E-step (Expectation): Using the current HMM parameters \(\lambda^{(old)}\), calculate the expected counts of how often each state and state transition occurs, given the observed sequence \(O\). This involves computing auxiliary variables using the Forward-Backward algorithm:
    • \(\alpha_t(i)\): The probability of observing the partial sequence \(o_1 \dots o_t\) and being in state \(S_i\) at time \(t\).
    • \(\beta_t(i)\): The probability of observing the partial sequence \(o_{t+1} \dots o_T\) given being in state \(S_i\) at time \(t\).
    • \(\gamma_t(i)\): The probability of being in state \(S_i\) at time \(t\), given the entire observation sequence \(O\) and the current model.
    • \(\xi_t(i,j)\): The probability of being in state \(S_i\) at time \(t\) and state \(S_j\) at time \(t+1\), given the entire observation sequence \(O\) and the current model.
  2. M-step (Maximization): Use these expected counts (\(\gamma\) and \(\xi\)) to re-estimate the HMM parameters \(\lambda^{(new)}\). These new parameters are chosen to maximize the likelihood of the observed data, given the expected hidden state paths from the E-step.

These two steps are repeated until the parameters converge (i.e., the likelihood \(P(O|\lambda)\) stops increasing significantly between iterations).

Design Decision: Why EM?

Directly maximizing \(P(O|\lambda)\) is hard because the hidden state sequence is unknown. EM provides an elegant solution by introducing a "latent variable" (the hidden state sequence). The E-step essentially "fills in" these latent variables with their expected values, turning the intractable problem into a tractable one for the M-step. The M-step then finds the parameters that best explain these "completed" (expected) data points.

🔑 Key Property

Baum-Welch is guaranteed to converge to a local maximum of the likelihood function \(P(O|\lambda)\). It does not guarantee a global maximum, meaning the final parameters can depend on the initial random guess. Multiple restarts with different initial parameters are often used in practice.

3
Why It Works — The Math
▼

The Forward-Backward Algorithm: Computing Posteriors

The E-step relies on computing the forward probabilities \(\alpha_t(i)\) and backward probabilities \(\beta_t(i)\). These are typically scaled to prevent numerical underflow.

Forward Pass: \(\alpha_t(i) = P(o_1, \dots, o_t, q_t=S_i | \lambda)\)

$$\alpha_1(i) = \pi_i \cdot b_i(o_1) \quad \text{for } 1 \le i \le N$$ $$\alpha_t(j) = \left[ \sum_{i=1}^N \alpha_{t-1}(i) a_{ij} \right] b_j(o_t) \quad \text{for } 1 < t \le T, 1 \le j \le N$$

Backward Pass: \(\beta_t(i) = P(o_{t+1}, \dots, o_T | q_t=S_i, \lambda)\)

$$\beta_T(i) = 1 \quad \text{for } 1 \le i \le N$$ $$\beta_t(i) = \sum_{j=1}^N a_{ij} b_j(o_{t+1}) \beta_{t+1}(j) \quad \text{for } 1 \le t < T, 1 \le i \le N$$

From \(\alpha\) and \(\beta\), we can compute the posterior probabilities \(\gamma_t(i)\) and \(\xi_t(i,j)\):

$$\gamma_t(i) = P(q_t=S_i | O, \lambda) = \frac{\alpha_t(i) \beta_t(i)}{\sum_{j=1}^N \alpha_t(j) \beta_t(j)}$$ $$\xi_t(i,j) = P(q_t=S_i, q_{t+1}=S_j | O, \lambda) = \frac{\alpha_t(i) a_{ij} b_j(o_{t+1}) \beta_{t+1}(j)}{\sum_{i=1}^N \sum_{j=1}^N \alpha_t(i) a_{ij} b_j(o_{t+1}) \beta_{t+1}(j)}$$

Note that the denominator in \(\gamma_t(i)\) (and \(\xi_t(i,j)\)) is \(P(O|\lambda)\), the total likelihood of the observation sequence under the current model. These formulas are typically computed using log-probabilities or scaling factors to maintain numerical stability.

M-Step: Re-estimation Formulas

The re-estimation formulas for the HMM parameters are derived by maximizing the expected log-likelihood of the complete data (observations + hidden states). They are essentially smoothed frequency counts:

$$\pi_i^{new} = \gamma_1(i)$$ $$a_{ij}^{new} = \frac{\sum_{t=1}^{T-1} \xi_t(i,j)}{\sum_{t=1}^{T-1} \gamma_t(i)}$$ $$b_j^{new}(k) = \frac{\sum_{t=1}^{T} \mathbb{I}(o_t=V_k) \gamma_t(j)}{\sum_{t=1}^{T} \gamma_t(j)}$$

Here, \(\mathbb{I}(o_t=V_k)\) is an indicator function, equal to 1 if the observation at time \(t\) is \(V_k\), and 0 otherwise. These updates intuitively say: new initial state probability is the expected frequency of being in state \(S_i\) at time 1; new transition probability from \(S_i\) to \(S_j\) is the expected number of \(S_i \to S_j\) transitions divided by expected total transitions from \(S_i\); and new emission probability \(b_j(k)\) is the expected number of times observation \(V_k\) is emitted from state \(S_j\) divided by expected total times in state \(S_j\).

⚠️ Numerical Stability & Underflow

When dealing with long observation sequences, the product of many small probabilities in \(\alpha\) and \(\beta\) calculations can quickly underflow to zero, leading to incorrect results. Practical implementations use log-probabilities or scaling factors at each time step to keep values within a computable range. This explainer's visualization uses scaling for robustness.

Key Takeaways
▼

When to use Baum-Welch:

  • Unsupervised HMM Learning: When you have observation sequences but don't know the underlying hidden states or the HMM parameters. This is its primary use case.
  • Speech Recognition: Learning acoustic models, where observations are audio features and hidden states are phonemes or sub-phoneme units.
  • Bioinformatics: Gene finding, protein family modeling, sequence alignment, where observations are DNA/protein sequences and hidden states represent different biological regions (e.g., coding vs. non-coding).
  • Gesture Recognition: Modeling sequences of sensor data (e.g., accelerometer readings) to recognize different gestures, where the gestures themselves are hidden states.
  • Financial Modeling: Identifying hidden market regimes (e.g., bull, bear, stagnant) from observed stock prices or economic indicators.

When NOT to use Baum-Welch:

  • If Hidden States are Known: If you have labeled data (both observations and corresponding hidden states), you can directly compute MLE estimates for \(\pi, A, B\) using simple counting. Baum-Welch is for the unsupervised case.
  • Global Optima Concerns: As an EM algorithm, Baum-Welch is susceptible to local maxima. If the initial parameters are poor, it might converge to a suboptimal solution. For critical applications, multiple restarts with different random initializations are necessary.
  • Computational Cost for Very Long Sequences: The Forward-Backward algorithm has a time complexity of \(O(N^2 T)\), where \(N\) is the number of hidden states and \(T\) is the sequence length. For extremely long sequences or many states, this can be computationally expensive.
  • Small Datasets: Like all statistical learning methods, Baum-Welch requires sufficient data to reliably estimate parameters. With very sparse data, parameter estimates can be poor or lead to zero probabilities.
💡 Broader Context

Baum-Welch is a classic example of the power of the EM algorithm. It bridges the gap between a model's theoretical structure and its practical application when key variables are unobservable. Its principles extend to many other latent variable models in machine learning, such as Gaussian Mixture Models (GMMs).

Code Trace (Python-like Pseudocode)
▼
import numpy as np
def baum_welch(observations, num_states, num_emissions, max_iters=100, tol=1e-4):
T = len(observations)
N = num_states
M = num_emissions
# 1. Initialize HMM parameters (pi, A, B) randomly and normalize
pi = np.random.rand(N); pi /= np.sum(pi)
A = np.random.rand(N, N); A /= np.sum(A, axis=1, keepdims=True)
B = np.random.rand(N, M); B /= np.sum(B, axis=1, keepdims=True)
log_likelihood_prev = -np.inf
for iteration in range(max_iters):
# --- E-Step: Compute Forward-Backward probabilities ---
alpha = np.zeros((T, N)) # P(o_1..o_t, q_t=S_i)
beta = np.zeros((T, N)) # P(o_t+1..o_T | q_t=S_i)
scaling_factors = np.zeros(T) # For numerical stability
# Forward Pass (with scaling)
alpha[0, :] = pi * B[:, observations[0]]
scaling_factors[0] = np.sum(alpha[0, :])
alpha[0, :] /= scaling_factors[0]
for t in range(1, T):
alpha[t, :] = (alpha[t-1, :] @ A) * B[:, observations[t]]
scaling_factors[t] = np.sum(alpha[t, :])
alpha[t, :] /= scaling_factors[t]
# Backward Pass (with scaling)
beta[T-1, :] = 1 / scaling_factors[T-1] # Scaled beta_T is 1/c_T
for t in range(T-2, -1, -1):
beta[t, :] = (A @ (B[:, observations[t+1]] * beta[t+1, :])) / scaling_factors[t]
# Compute gamma (state posteriors) and xi (transition posteriors)
gamma = np.zeros((T, N))
xi = np.zeros((T-1, N, N))
for t in range(T-1):
denom = np.sum(alpha[t, :] * beta[t, :]) # P(O|lambda) * product of scaling factors
for i in range(N):
gamma[t, i] = alpha[t, i] * beta[t, i] / denom
for j in range(N):
num = alpha[t, i] * A[i, j] * B[j, observations[t+1]] * beta[t+1, j]
xi[t, i, j] = num / denom
gamma[T-1, :] = alpha[T-1, :] * beta[T-1, :] / np.sum(alpha[T-1, :] * beta[T-1, :])
# --- M-Step: Re-estimate HMM parameters ---
# Re-estimate pi
pi_new = gamma[0, :]
pi = pi_new / np.sum(pi_new) # Normalize
# Re-estimate A
A_new = np.zeros((N, N))
for i in range(N):
denom_A = np.sum(gamma[:T-1, i])
for j in range(N):
num_A = np.sum(xi[:T-1, i, j])
A_new[i, j] = num_A / denom_A
A = A_new / np.sum(A_new, axis=1, keepdims=True) # Normalize
# Re-estimate B
B_new = np.zeros((N, M))
for j in range(N):
denom_B = np.sum(gamma[:, j])
for k in range(M):
num_B = np.sum(gamma[observations == k, j])
B_new[j, k] = num_B / denom_B
B = B_new / np.sum(B_new, axis=1, keepdims=True) # Normalize
# Check for convergence
log_likelihood = -np.sum(np.log(scaling_factors)) # Log P(O|lambda)
if abs(log_likelihood - log_likelihood_prev) < tol:
break
log_likelihood_prev = log_likelihood
return pi, A, B, log_likelihood
