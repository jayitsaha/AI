Multi-Head Attention

Split d_model into h heads, each attending in its own subspace — then concat and project
Intermediate Transformers NLP O(h·n²·d_k)
1
Understanding Multi-Head Attention
▼

What is it? A single attention head computes exactly one weighted average over the sentence per query — it has to compromise if a word relates to other words in several different ways at once. Multi-head attention runs several small attention operations in parallel, each in its own low-dimensional subspace, so different heads can specialize in different kinds of relationships. Their outputs are then concatenated and mixed back together with one learned projection \(W^O\).

Analogy: Imagine reading a sentence with four colored highlighters at once. One highlighter tracks which word is right next to which (local structure). One always glances back at the first word for context (a "topic sentence" reflex). One skims everything evenly, staying open to anything relevant. One highlights words that are semantically similar in meaning. A single highlighter could only pick one strategy — four highlighters working together capture far more of the sentence's structure, and you merge their marks at the end.

💡 If you remember one thing

Multi-head attention doesn't add parameters over one big attention head — it redistributes the same budget across \(h\) independent, smaller attention distributions: $$\text{MultiHead}(Q,K,V) = \text{Concat}(\text{head}_1,\dots,\text{head}_h)\,W^O, \quad \text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)$$

How It Works Internally
▼

Step 1 — Project into h subspaces

Given token embeddings \(X \in \mathbb{R}^{n \times d_{model}}\), each head \(i\) has its own learned matrices \(W_i^Q, W_i^K \in \mathbb{R}^{d_{model}\times d_k}\) and \(W_i^V \in \mathbb{R}^{d_{model}\times d_v}\), producing \(Q_i = XW_i^Q\), \(K_i = XW_i^K\), \(V_i = XW_i^V\). Typically \(d_k = d_v = d_{model}/h\), so every head only ever "sees" a low-dimensional slice of the representation.

Step 2 — Attend independently per head

Each head runs its own scaled dot-product attention: \(\text{head}_i = \text{softmax}\!\left(\dfrac{Q_iK_i^\top}{\sqrt{d_k}}\right)V_i\). Because \(Q_i, K_i\) live in a different subspace for every head, the resulting \(n\times n\) attention matrix is different for every head — one head can look local, another can look global, another can fixate on one token.

Step 3 — Concatenate and mix

All \(h\) head outputs (each \(n \times d_v\)) are laid side by side into one \(n \times (h\cdot d_v) = n \times d_{model}\) matrix, then passed through a single learned output projection \(W^O \in \mathbb{R}^{d_{model}\times d_{model}}\). This is essential — without \(W^O\), the heads' information would just sit in separate blocks; the projection lets every output dimension mix information that came from every head.

Design decision: why split instead of one big head?

A single head with \(d_k=d_{model}\) produces exactly one softmax distribution per query — one weighted average, however the loss shapes it. Splitting into \(h\) heads of size \(d_{model}/h\) costs the same total number of parameters (see Card 3) but gives \(h\) independent softmax distributions per query, so the model can simultaneously track several different relations (e.g. "what's the subject of this verb" and "what word is right before me") instead of averaging them into one compromise distribution.

🔑 Key Property

Each head is a free, independent attention distribution over the sequence. Different heads reliably specialize — empirically, real trained transformers grow heads for positional/local patterns, "attention sinks" that anchor on the first token, broad context-gathering heads, and content/syntax-matching heads, closely mirroring the four heads visualized below.

Why It Works — The Math
▼

Full definition

$$\text{head}_i = \text{softmax}\!\left(\frac{(XW_i^Q)(XW_i^K)^\top}{\sqrt{d_k}}\right)(XW_i^V), \qquad i=1,\dots,h$$
$$\text{MultiHead}(X) = \big[\text{head}_1 \,\Vert\, \text{head}_2 \,\Vert\, \cdots \,\Vert\, \text{head}_h\big]\,W^O$$

where \(\Vert\) denotes concatenation along the feature axis, and \(W^O \in \mathbb{R}^{(h\cdot d_v)\times d_{model}}\) maps the concatenated heads back to model dimension.

Parameter-count invariant

With \(d_k = d_v = d_{model}/h\), one head's three projections cost \(3\,d_{model}\cdot d_k = 3\,d_{model}^2/h\) parameters. Summed over \(h\) heads: \(h \cdot 3\,d_{model}^2/h = 3\,d_{model}^2\) — exactly the cost of one single head with \(d_k = d_{model}\). \(W^O\) costs \(d_{model}^2\) either way. Multi-head attention is "free" in parameter count; the gain comes purely from having \(h\) independent softmax distributions instead of one.

Why \(1/\sqrt{d_k}\) matters more with many heads

If \(q,k \in \mathbb{R}^{d_k}\) have independent, zero-mean, unit-variance entries, then \(\text{Var}(q\cdot k) = d_k\). As \(d_k\) shrinks (more heads → smaller subspace), the raw dot products shrink too, so the scaling factor \(\sqrt{d_k}\) must shrink correspondingly to keep the softmax input variance at \(O(1)\) — otherwise scores would be too small and every head's attention would collapse toward uniform.

Gradient flow

Because each head's softmax is applied independently, gradients w.r.t. \(W_i^Q, W_i^K, W_i^V\) only depend on that head's own \(Q_i, K_i, V_i\) — heads do not interfere with each other's gradients during the attention step. They only interact downstream, through the shared \(W^O\), which mixes gradients back across heads on the backward pass.

⚠️ Common Misconception

"More heads always means more expressive power." Not necessarily — beyond a point, shrinking \(d_k\) too far limits how much any single head can represent (its subspace becomes too small to compute a meaningful similarity), and empirically many heads in trained models end up redundant or prunable. The right \(h\) is a capacity/diversity trade-off, not a free lunch.

Key Takeaways
▼

Why multi-head attention exists:

  • One attention head = one softmax = one weighted-average "compromise" per query
  • Splitting into \(h\) heads of size \(d_{model}/h\) is parameter-neutral vs. one big head
  • Different heads specialize: positional/local, "sink" (anchor on token 0), broad/diffuse, content-based
  • \(W^O\) is what actually lets information from different heads mix back together

Things to watch for:

  • Too many heads shrinks \(d_k\) until each head's subspace is too small to be useful
  • Many trained heads end up redundant — this motivates head-pruning research
  • Multi-Query / Grouped-Query Attention share \(K,V\) across heads to cut KV-cache memory at inference
💡 Mental Model

Single-head attention: one lens on the sentence. Multi-head attention: several lenses in parallel, each free to focus on something different, recombined by one shared projection at the end.

Code Trace
▼
import numpy as np
def softmax(z):
z = z - z.max(axis=-1, keepdims=True)
e = np.exp(z)
return e / e.sum(axis=-1, keepdims=True)
def attention(Q, K, V):
d_k = Q.shape[-1]
scores = Q @ K.T / np.sqrt(d_k) # (n, n)
weights = softmax(scores) # (n, n)
return weights @ V # (n, d_v)
def multi_head_attention(X, WQ, WK, WV, WO, h):
# X: (n, d_model); WQ/WK/WV: list of h matrices (d_model, d_k)
heads = []
for i in range(h):
Qi = X @ WQ[i]; Ki = X @ WK[i]; Vi = X @ WV[i]
heads.append(attention(Qi, Ki, Vi)) # each (n, d_v)
concat = np.concatenate(heads, axis=-1) # (n, h*d_v) = (n, d_model)
return concat @ WO # (n, d_model)
# n=5 tokens, d_model=8, h=4 heads, d_k=d_v=2
out = multi_head_attention(X, WQ, WK, WV, WO, h=4)
print(out.shape) # (5, 8) — same shape as the input
