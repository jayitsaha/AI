Why the diamond makes weights vanish and the circle only makes them shrink

1
Understanding L1 & L2 Regularization
▼

What is it? When a model has too much freedom, it memorizes noise instead of learning signal — large, wild weight values that overfit the training set. Regularization adds a penalty on the size of the weights to the loss function, discouraging the optimizer from choosing extreme values. L2 (Ridge) penalizes the sum of squared weights \(\sum_i w_i^2\); L1 (Lasso) penalizes the sum of absolute weights \(\sum_i |w_i|\). Same goal — smaller weights, simpler models — but geometrically very different outcomes.

Analogy: Imagine packing a suitcase (your weight budget) for a trip. L2 is a strict but fair packer — everything gets squeezed down proportionally, nothing is thrown out entirely. L1 is a ruthless minimalist — it decides some items just aren't worth taking at all and leaves them at zero, packing only the essentials. That's why L1 produces sparse models (many weights exactly zero, i.e. automatic feature selection) while L2 produces dense-but-small models (all weights shrink, none vanish).

💡 If you remember one thing

L1's constraint region is a diamond with sharp corners on the axes; L2's is a circle with no corners. The optimal point is where the loss contours first touch the constraint boundary — diamonds are touched at corners (a weight = 0) far more often than smooth circles are touched at an axis point. Sparsity is a geometric consequence, not a numerical accident.

How It Works Internally — Constrained Optimization Geometry
▼

Two Equivalent Views of Regularization

Regularized training is usually written as the Lagrangian (penalized) form:

$$\min_w \; L(w) + \lambda \, \Omega(w) \qquad \Omega(w) = \|w\|_2^2 \text{ (L2) or } \|w\|_1 \text{ (L1)}$$

By Lagrangian duality this is equivalent to the constrained (Ivanov) form: for every \(\lambda\) there is a budget \(t\) such that minimizing \(L(w)\) subject to \(\Omega(w) \le t\) gives the same solution. This constrained view is what makes the geometry visible: we are minimizing the loss \(L(w)\) inside (or on the boundary of) a fixed-size region.

The Shape of the Feasible Region

In 2D weight space \((w_1, w_2)\), the loss function's level sets (contours of equal loss) are ellipses centered at the unconstrained optimum \(w^{\star}\). The constraint region \(\{\Omega(w)\le t\}\) is:

  • L2: \(w_1^2 + w_2^2 \le t\) — a perfect circle (or hypersphere in higher dimensions). Smooth everywhere, no preferred direction.
  • L1: \(|w_1| + |w_2| \le t\) — a diamond (rotated square) whose four vertices sit exactly on the axes at \((\pm t, 0)\) and \((0,\pm t)\).

The regularized solution is found by inflating the loss ellipse outward from \(w^\star\) until it first touches the constraint boundary. That touching point is the answer.

Design Decision: Why Does Touching a Corner Zero Out a Weight?

A convex region's corners are points of non-differentiability — infinitely many possible "tangent lines" (subgradients) pass through a diamond's vertex, versus exactly one tangent line at any point on a smooth circle. This means an ellipse arriving from almost any angle can be tangent to the diamond precisely at a vertex, where one coordinate is exactly zero — a large fraction of the diamond's boundary. A circle has no such special points: it is generic, so the tangency point almost never lands exactly on an axis, and both coordinates stay nonzero (they merely shrink toward the origin).

🔑 Key Property

L1 sparsity is a corner-of-a-polytope phenomenon. It generalizes: in \(n\) dimensions the L1 ball is a cross-polytope with \(2n\) sharp vertices lying on the coordinate axes, while the L2 ball is a smooth hypersphere with zero vertices — which is exactly why only L1 induces exact zeros.

3
Why It Works — The Math (Soft-Thresholding & Weight Decay)
▼

L2: A Smooth Gradient, Proportional Shrinkage

For a per-coordinate quadratic loss \(L(w_i) = \tfrac{A_i}{2}(w_i - w_i^\star)^2\) plus an L2 penalty, the objective is differentiable everywhere:

$$\frac{\partial}{\partial w_i}\Big[\tfrac{A_i}{2}(w_i-w_i^\star)^2 + \lambda w_i^2\Big] = A_i(w_i - w_i^\star) + 2\lambda w_i = 0 \;\Longrightarrow\; \hat w_i = \frac{A_i}{A_i + 2\lambda}\,w_i^\star$$

Every weight is multiplied by a shrinkage factor \(\frac{A_i}{A_i+2\lambda} \in (0,1)\). As \(\lambda \to \infty\) this factor \(\to 0\), but for any finite \(\lambda\) it is strictly positive — \(\hat w_i\) can get arbitrarily close to zero but never exactly reaches it (except in the limit). This is why L2 shrinks but does not sparsify.

L1: A Kink at Zero, Soft-Thresholding

\(|w_i|\) is not differentiable at \(w_i=0\), so we use the subgradient optimality condition \(0 \in \partial\big[\tfrac{A_i}{2}(w_i-w_i^\star)^2 + \lambda|w_i|\big]\). Solving gives the closed-form soft-thresholding operator:

$$\hat w_i = \operatorname{sign}(w_i^\star)\,\max\!\Big(|w_i^\star| - \tfrac{\lambda}{A_i},\; 0\Big)$$

Whenever the penalty strength exceeds the coordinate's "pull" (\(\lambda \ge A_i|w_i^\star|\)), the max clips to exactly zero — a genuine dead weight, not just a small number. This is the algebraic fingerprint of the diamond's corner from Card 2.

Weight Decay vs. L2 — and Why AdamW Exists

For plain SGD, adding \(\lambda w^2\) to the loss produces the gradient step \(w \leftarrow w - \eta(\nabla L + 2\lambda w) = (1-2\eta\lambda)w - \eta\nabla L\) — this is identical to "weight decay," directly shrinking \(w\) by a factor each step. For SGD, L2-regularization and weight decay are the same thing.

For Adam, they are not. Adam divides the gradient by a per-parameter RMS of past gradients, so the L2 penalty term \(2\lambda w\) gets divided too — parameters with large historical gradients receive less effective decay, the opposite of the uniform shrinkage intended. AdamW (Loshchilov & Hutter, 2019) fixes this by decoupling: apply the adaptive update from the loss gradient only, then subtract \(\eta\lambda w\) directly, outside the adaptive machinery.

$$\text{Adam+L2: } w \leftarrow w - \eta\,\frac{\hat m}{\sqrt{\hat v}+\epsilon} \quad\text{where } \nabla L \text{ already includes } 2\lambda w \qquad\qquad \text{AdamW: } w \leftarrow w - \eta\Big(\frac{\hat m}{\sqrt{\hat v}+\epsilon} + \lambda w\Big)$$
⚠️ Common Misconception

"Adam's weight_decay argument is L2 regularization." Not in PyTorch's AdamW — the whole point of that optimizer is that it is not folded into the gradient before the adaptive scaling. Using plain Adam with weight_decay silently gives you the coupled (weaker, uneven) version; use AdamW when you actually want decoupled weight decay.

When to use L1: you suspect many features/weights are irrelevant and want automatic pruning or an interpretable sparse model.

When to use L2: you want smooth, stable shrinkage without discarding any input entirely — the default in almost all deep learning ("weight decay").

When NOT to regularize this way: if the model already underfits, adding L1/L2 will only hurt — check bias first, not just variance.

💡 Hierarchy

Both are special cases of the \(L_p\) ball \(\|w\|_p \le t\). As \(p \to 0\), the ball degenerates into the axes themselves (true sparsity, but non-convex/NP-hard to optimize). L1 (\(p=1\)) is the largest \(p\) for which the ball still has corners — the "tightest convex relaxation" of exact sparsity. L2 (\(p=2\)) is the smoothest common choice, and remains the standard for deep net weight decay because it interacts cleanly with gradient-based optimizers.

From Scratch — Soft-Thresholding (Proximal Gradient / ISTA) for L1

import numpy as np
# One proximal-gradient step for L1-regularized least squares:
# minimize 0.5 * ||y - Xw||^2 + lambda * ||w||_1
def soft_threshold(x, thresh):
# shrinks toward 0 and clips small values to EXACTLY 0
return np.sign(x) * np.maximum(np.abs(x) - thresh, 0.0)
def ista_step(w, X, y, lam, lr):
grad = -X.T @ (y - X @ w) # gradient of the smooth loss term
w_temp = w - lr * grad # ordinary gradient step
return soft_threshold(w_temp, lr * lam) # proximal (L1) step
# L2 (Ridge) closed form for comparison -- no thresholding needed:
def ridge_closed_form(X, y, lam):
n_features = X.shape[1]
return np.linalg.solve(X.T @ X + lam * np.eye(n_features), X.T @ y)

Production Usage — PyTorch: L2 vs. Weight Decay vs. AdamW

import torch
from torch.optim import SGD, Adam, AdamW
# Manual L1 penalty added to the loss (framework-agnostic):
l1_penalty = sum(p.abs().sum() for p in model.parameters())
loss = criterion(model(x), y) + lam_l1 * l1_penalty
# SGD: weight_decay == L2 regularization (mathematically identical)
opt = SGD(model.parameters(), lr=0.01, weight_decay=1e-4)
# Adam + weight_decay: L2 term gets divided by the adaptive v_hat --
# decay strength becomes UNEVEN across parameters (usually not intended)
opt = Adam(model.parameters(), lr=1e-3, weight_decay=1e-4) # coupled, be careful
# AdamW: decay is applied directly to weights, decoupled from adaptive scaling
opt = AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2) # preferred for transformers
⚠️ Gotcha

PyTorch has no built-in l1 penalty flag — you must add \(\lambda\|w\|_1\) to the loss manually (as above) since L1 is not equivalent to any optimizer's weight_decay argument.
