How model complexity drives the bias–variance tradeoff — and how regularization restores balance

1
Understanding Polynomial Features & Overfitting
▼

What is it? In real life, most relationships are not straight lines. Polynomial features let a linear model learn curved patterns by adding extra inputs like \(x^2, x^3, \ldots, x^d\). A degree-\(d\) polynomial fits a curve with up to \(d-1\) bends through the data.

The danger: overfitting. A very high-degree polynomial has enough flexibility to pass exactly through every training point — but then it wiggles wildly between them, giving terrible predictions on new data. This is overfitting: the model memorised the training set's noise rather than learning the underlying pattern.

Analogy. Imagine summarising a classroom's height by fitting a curve through each individual student. A straight line might miss the general trend (underfit). The true parabola captures it well. But a 30th-degree polynomial that snakes through every student's exact head will predict absurd heights for someone standing between two students — it's fit the wiggles of measurement noise, not the signal.

💡 If you remember one thing

As model complexity (polynomial degree \(d\)) increases: train error decreases monotonically, test error forms a U-shape. The sweet spot — the bottom of the U — is the generalisation-optimal degree. Too simple = high bias; too complex = high variance.

2
How Polynomial Regression Works Internally
▼

From Linear to Polynomial

Start with ordinary linear regression on scalar input \(x\): the model is \(\hat{y} = \beta_0 + \beta_1 x\). To fit curves, construct a feature vector \(\phi(x) = [1,\, x,\, x^2,\, \ldots,\, x^d]^\top\), then run linear regression on the extended design matrix \(\Phi\):

$$\hat{\beta} = (\Phi^\top \Phi)^{-1}\Phi^\top y, \qquad \hat{y}(x) = \hat{\beta}_0 + \hat{\beta}_1 x + \hat{\beta}_2 x^2 + \cdots + \hat{\beta}_d x^d$$

The model is still linear in the parameters \(\beta\), so ordinary least squares applies — only the feature construction changes.

What Happens as Degree Grows?

With \(n\) training points and degree \(d\):

  • \(d = 1\): straight line — captures linear trend only (high bias)
  • \(d = 2\): parabola — fits gentle curvature (often the sweet spot for smooth data)
  • \(d = n-1\): the polynomial passes through every single training point exactly (zero train error, zero bias — but explodes between points)
  • \(d \geq n\): system is under-determined; \(\Phi^\top\Phi\) becomes singular

Condition Number & Numerical Issues

As \(d\) grows, the columns of \(\Phi\) become nearly linearly dependent (all look like \(x^k\) for large \(k\)), making \(\Phi^\top\Phi\) ill-conditioned. Small perturbations in the data cause enormous swings in \(\hat{\beta}\). This is why high-degree polynomial coefficients are huge and the fitted curve oscillates — a phenomenon called Runge's phenomenon near the interval boundaries.

🔑 The Degrees of Freedom View

A degree-\(d\) polynomial has \(d+1\) free parameters. When \(d+1 \approx n\), the model uses all its degrees of freedom to fit the training points perfectly, leaving none to generalise. Effective complexity is controlled by \(d\) relative to \(n\).

3
The Bias–Variance Tradeoff — The Math
▼

Decomposing Expected Prediction Error

For a model \(\hat{f}\) trained on data \(\mathcal{D}\), evaluated at a new point \(x_0\) with true response \(y_0 = f(x_0) + \varepsilon\), the expected squared error decomposes as:

$$\mathbb{E}_{\mathcal{D},\varepsilon}\!\left[(y_0 - \hat{f}(x_0))^2\right] = \underbrace{\left(\mathbb{E}_\mathcal{D}[\hat{f}(x_0)] - f(x_0)\right)^2}_{\text{Bias}^2} + \underbrace{\operatorname{Var}_\mathcal{D}(\hat{f}(x_0))}_{\text{Variance}} + \underbrace{\sigma^2}_{\text{Irreducible noise}}$$
  • Bias\(^2\): how wrong the average prediction is. Low-degree polynomial = large bias (can't represent the true curve).
  • Variance: how much the prediction changes if we retrain on a different sample. High-degree polynomial = large variance (tiny data changes cause wild coefficient swings).
  • Irreducible noise \(\sigma^2\): inherent measurement noise — no model can eliminate this.

Ridge Regularization Tames Variance

Instead of OLS, Ridge regression minimizes a penalized objective:

$$\hat{\beta}_{\text{Ridge}} = \underset{\beta}{\operatorname{argmin}}\; \|y - \Phi\beta\|_2^2 + \lambda\|\beta\|_2^2$$

The closed-form solution is \(\hat{\beta}_{\text{Ridge}} = (\Phi^\top\Phi + \lambda I)^{-1}\Phi^\top y\). The \(\lambda I\) term regularises the ill-conditioned Gram matrix, shrinking large coefficients toward zero. This adds a controlled amount of bias but dramatically reduces variance — often moving the operating point to the bottom of the U-curve.

⚠️ Common Misconception

Low training error does NOT imply a good model. A degree-9 polynomial on 10 points achieves near-zero train MSE but high test MSE. Always evaluate on held-out data or use cross-validation to select degree and \(\lambda\).

∑ Effective Degrees of Freedom

Ridge has effective degrees of freedom \(\text{df}(\lambda) = \operatorname{tr}(\Phi(\Phi^\top\Phi + \lambda I)^{-1}\Phi^\top) = \sum_j \frac{\sigma_j^2}{\sigma_j^2 + \lambda}\), where \(\sigma_j\) are singular values of \(\Phi\). At \(\lambda=0\) this equals \(d+1\); as \(\lambda \to \infty\) it approaches 0.

Key Takeaways & Practical Rules
▼

Rules of thumb for polynomial regression:

  • Start with the lowest degree that captures the expected shape (domain knowledge first)
  • Use cross-validation to select degree — never trust training error alone
  • If using high degree, always apply Ridge or Lasso regularization
  • Normalise inputs before computing powers — \(x^9\) for \(x \sim 10\) creates values \(\sim 10^9\)
  • For multi-dimensional inputs, use sklearn.preprocessing.PolynomialFeatures(interaction_only=True) to avoid combinatorial explosion

When polynomial features are the right tool: smooth, continuous relationships; physical models (kinematics, optics) where curvature has scientific meaning; small datasets where neural networks would overfit worse.

When they are NOT the right tool: high-dimensional inputs (feature explosion from \(p^d\) terms); discontinuous or piecewise relationships (use splines or tree models); production systems needing interpretability beyond linear effects.

💡 The Practitioner's Checklist

1) Plot your data first. 2) Fit degree 1, 2, 3 and compare cross-validated errors. 3) If degree >3 helps, add Ridge regularization. 4) Report test MSE, not train MSE. 5) Visualise the fitted curve — a suspicious wiggle is a red flag.

import numpy as np
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import Ridge
from sklearn.model_selection import cross_val_score
# 1. Build polynomial feature matrix
poly = PolynomialFeatures(degree=d, include_bias=True)
Phi_train = poly.fit_transform(X_train) # shape: (n, d+1)
Phi_test = poly.transform(X_test)
# 2. OLS fit (no regularization)
beta = np.linalg.lstsq(Phi_train, y_train, rcond=None)[0]
train_mse = np.mean((y_train - Phi_train @ beta)**2)
test_mse = np.mean((y_test - Phi_test @ beta)**2)
# 3. Ridge (regularized) fit — tames high-degree variance
ridge = Ridge(alpha=lam, fit_intercept=False)
ridge.fit(Phi_train, y_train)
ridge_test_mse = np.mean((y_test - ridge.predict(Phi_test))**2)
# 4. Select degree + lambda by cross-validation
cv_score = cross_val_score(
Ridge(alpha=lam), Phi_train, y_train,
cv=5, scoring='neg_mean_squared_error'
)
best_val_mse = -cv_score.mean()
