Multi-scale Detection: FPN, PANet, BiFPN, NAS-FPN

Architectures for robustly detecting objects across varying sizes
Foundational Deep Learning Computer Vision O(N) detection
1
Understanding Multi-scale Detection
▼

What is it? Object detection models face a fundamental challenge: objects in images can appear at vastly different scales (e.g., a tiny bird vs. a large elephant). Deep Convolutional Neural Networks (CNNs) naturally produce feature maps at different spatial resolutions. Shallow layers retain high resolution and fine spatial details but lack semantic context. Deep layers have rich semantic information but low resolution, making them poor at localizing small objects.

Multi-scale detection architectures, starting with the Feature Pyramid Network (FPN), address this by building feature pyramids that combine both high-level semantic information (from deep layers) and high-resolution spatial information (from shallow layers) across all levels of the pyramid. This allows detectors to operate effectively on objects of all sizes.

Analogy: Imagine you're a detective looking for clues. To find a tiny fingerprint, you need a high-resolution magnifying glass (shallow features). To understand the overall crime scene, you need a wide-angle view and context (deep features). Multi-scale detection is like having a set of specialized tools (feature maps) at different magnifications, each enriched with context, so you can find both the small fingerprint and the large getaway car with equal precision.

💡 If you remember one thing

FPN is the foundational idea for modern multi-scale object detection. It creates a feature pyramid where each level has both strong semantic information (from deep layers) and strong spatial information (from shallow layers), enabling robust detection across all object scales.

2
How It Works Internally
▼

1. CNN Backbone: The Feature Extractor

The process begins with a standard CNN backbone (e.g., ResNet, EfficientNet) that extracts features. It produces a hierarchy of feature maps at different scales: \(C_2, C_3, C_4, C_5\). \(C_2\) is the highest resolution (e.g., 1/4th of input image size) but has low-level features. \(C_5\) is the lowest resolution (e.g., 1/32nd) but contains rich, high-level semantic information.

2. Feature Pyramid Network (FPN)

FPN (Lin et al., 2017) builds a top-down pathway with lateral connections:

  • Top-down pathway: Starting from the deepest feature map (\(C_5\)), it's progressively upsampled. The upsampled feature map is then fused with the corresponding backbone feature map from the previous level (e.g., \(C_4\)).
  • Lateral connections: Before fusion, a 1x1 convolution is applied to the backbone feature maps (\(C_i\)) to reduce their channel dimensions and align them with the upsampled features.
  • Fusion: The upsampled feature map and the corresponding 1x1 convolved backbone feature map are element-wise added. Another 3x3 convolution is often applied to the fused result to smooth the feature map and reduce aliasing effects from upsampling.
  • Output: A new set of feature maps \(P_2, P_3, P_4, P_5\) (and often \(P_6\) from max-pooling \(P_5\)) are generated, each having strong semantics and fine localization details.

3. Path Aggregation Network (PANet)

PANet (Liu et al., 2018) extends FPN by adding a bottom-up pathway. While FPN effectively propagates semantic information top-down, PANet introduces an additional path to propagate strong localization signals from lower (higher-resolution) levels upwards. This helps in more precise localization of objects.

  • It takes the FPN output features (\(P_2, P_3, P_4, P_5\)) and builds a new pyramid (\(N_2, N_3, N_4, N_5\)) by propagating information from high-resolution features to low-resolution features.
  • This second pathway ensures that both rich semantic context and accurate spatial information are available at all scales.

4. Bi-directional Feature Pyramid Network (BiFPN)

BiFPN (Tan et al., 2019), introduced in EfficientDet, improves upon FPN by proposing a more efficient and effective weighted bi-directional cross-scale connection. It addresses the limitation that FPN and PANet treat all input features equally during fusion.

  • Weighted Feature Fusion: BiFPN introduces learnable weights for each input feature map when combining them. This allows the network to learn the importance of different scale features, rather than simply summing them.
  • Simplified and Optimized Connections: It removes nodes that only have one input edge (less contribution to feature fusion) and adds an extra edge between original input and output nodes if they are at the same scale.
  • The entire structure is a repeated block of these bi-directional connections.

5. NAS-FPN (Neural Architecture Search FPN)

NAS-FPN (Ghiasi et al., 2019) uses Neural Architecture Search (NAS) to automatically discover novel FPN structures. Instead of hand-designing the connections and operations, a reinforcement learning controller searches for optimal cross-scale connections and feature fusion methods. This often results in highly irregular, complex, but extremely performant pyramid structures, albeit with significant computational cost for the search itself.

🔑 Key Property

All these methods aim to fuse features from different backbone layers to create a multi-scale pyramid where each level is rich in both semantic and spatial information, crucial for detecting objects of varying sizes.

3
Why It Works — The Math
▼

1. FPN: Top-Down Fusion

The core operation in FPN's top-down pathway is the fusion of an upsampled, semantically rich feature map from a deeper layer with a spatially precise feature map from a shallower layer. For a pyramid level \(P_i\), formed from backbone feature \(C_i\) and the deeper pyramid feature \(P_{i+1}\):

$$P_i = \text{Conv}_{3\times3}(\text{Conv}_{1\times1}(C_i) + \text{Upsample}(P_{i+1}))$$

Here, \(\text{Conv}_{1\times1}(C_i)\) adjusts the channel dimension of \(C_i\), \(\text{Upsample}(P_{i+1})\) matches its spatial resolution to \(C_i\), and \(\text{Conv}_{3\times3}\) is a smoothing operation after element-wise addition.

2. PANet: Bottom-Up Path Augmentation

PANet adds a bottom-up path to FPN. For a feature map \(N_i\) in this new path, it combines information from the FPN feature \(P_i\) and a downsampled feature from the shallower path \(N_{i-1}\):

$$N_i = \text{Conv}_{3\times3}(\text{Conv}_{1\times1}(P_i) + \text{Downsample}(N_{i-1}))$$

This structure ensures that precise localization signals, which might be diluted in the FPN's top-down path, are explicitly propagated upwards through the pyramid, further enriching the features at each scale.

3. BiFPN: Weighted Feature Fusion

BiFPN's key innovation is its weighted fusion. For an intermediate feature \(P_{i}^{\text{td}}\) (top-down path) and \(P_{i}^{\text{out}}\) (output node), it combines multiple inputs with learnable weights. A common form of weighted fusion is:

$$P_{i}^{\text{out}} = \text{Conv}\left(\sum_k \frac{w_k}{\sum_j w_j + \epsilon} \cdot I_k\right)$$

where \(I_k\) are the input features (e.g., \(C_i\), \(\text{Upsample}(P_{i+1})\), \(\text{Downsample}(N_{i-1})\)), \(w_k \ge 0\) are learnable weights (often initialized to 1), and \(\epsilon\) is a small value (e.g., 0.0001) for numerical stability. The weights \(w_k\) are typically learned as scalars for each connection, often using a simple activation like ReLU to ensure non-negativity. This allows the network to dynamically adjust the contribution of each input feature, leading to more effective and efficient fusion.

⚠️ Design Considerations

The choice of fusion operation (sum, concatenation, weighted sum) and the specific connections (top-down, bottom-up, skip) significantly impact performance. More complex connections (like BiFPN or NAS-FPN) often yield better results but increase architectural complexity and sometimes training difficulty.

Key Takeaways
▼

When to use multi-scale detection architectures:

  • Any object detection task, especially when objects of widely varying sizes are present.
  • Instance segmentation, where precise pixel-level localization is critical.
  • Other dense prediction tasks (e.g., semantic segmentation) that benefit from multi-resolution feature fusion.
  • When using deep backbones where small object information might be lost.

Key differences & trade-offs:

  • FPN: The standard. Simple, effective, and widely adopted. Provides strong semantic features at all scales.
  • PANet: Improves FPN by adding a bottom-up path, enhancing localization accuracy, particularly for small objects. Slightly more complex than FPN.
  • BiFPN: Focuses on efficient and effective weighted feature fusion. Learnable weights allow the network to prioritize important features, leading to higher performance with fewer parameters and FLOPs than other complex FPNs.
  • NAS-FPN: Achieves state-of-the-art performance by automatically discovering optimal (often irregular) architectures. However, the search process is computationally very expensive, making it less practical for general use unless you have vast compute resources.
💡 Practical Advice

For most applications, FPN or PANet is an excellent starting point. For higher performance and efficiency, especially with EfficientNet backbones, BiFPN is a strong choice. NAS-FPN is typically for pushing state-of-the-art boundaries.

Code Trace (Core Components)
▼
import torch
import torch.nn as nn
import torch.nn.functional as F
class FPN(nn.Module):
def __init__(self, in_channels_list, out_channels):
super().__init__()
self.lateral_convs = nn.ModuleList()
self.fpn_convs = nn.ModuleList()
for in_channels in in_channels_list:
self.lateral_convs.append(nn.Conv2d(in_channels, out_channels, 1))
self.fpn_convs.append(nn.Conv2d(out_channels, out_channels, 3, padding=1))
def forward(self, features): # features = [C2, C3, C4, C5]
# build lateral connections
laterals = [lateral_conv(f) for lateral_conv, f in zip(self.lateral_convs, features)]
# build top-down path
for i in range(len(laterals) - 2, -1, -1): # From P4 to P2
upsampled = F.interpolate(laterals[i+1], scale_factor=2, mode='nearest')
laterals[i] = laterals[i] + upsampled # Element-wise addition
# build final FPN outputs
fpn_outputs = [fpn_conv(l) for fpn_conv, l in zip(self.fpn_convs, laterals)]
return fpn_outputs # P2, P3, P4, P5
class BiFPNNode(nn.Module):
def __init__(self, in_channels, out_channels):
super().__init__()
# For simplicity, assume two inputs for a node (e.g., from top-down and bottom-up)
self.w1 = nn.Parameter(torch.ones(1, dtype=torch.float32)) # Learnable weight 1
self.w2 = nn.Parameter(torch.ones(1, dtype=torch.float32)) # Learnable weight 2
self.relu = nn.ReLU() # Ensure weights are non-negative
self.conv = nn.Conv2d(in_channels, out_channels, 3, padding=1)
def forward(self, input1, input2):
w1 = self.relu(self.w1)
w2 = self.relu(self.w2)
# Normalized weighted sum: I = (w1*I1 + w2*I2) / (w1 + w2 + epsilon)
epsilon = 1e-4
combined_feature = (w1 * input1 + w2 * input2) / (w1 + w2 + epsilon)
return self.conv(combined_feature)
