Understanding the Estimator API
▼

What is it? Scikit-learn is Python's go-to library for classical machine learning. Its genius is a single Estimator API: every algorithm — whether a scaler, a feature extractor, or a classifier — follows the same interface. Once you know how to call fit and predict, you know how to use any of the 100+ algorithms.

Analogy: Think of all kitchen appliances sharing the same plug shape. A toaster, a blender, and a microwave all plug into the same wall socket — you don't need a different outlet for each. In sklearn, fit(X, y) is the socket: every algorithm plugs in.

The Three Estimator Roles

  • Transformer — has fit and transform (and fit_transform). Examples: StandardScaler, PCA, OneHotEncoder.
  • Predictor — has fit and predict. Examples: LogisticRegression, RandomForestClassifier.
  • Scorer — has score. Most predictors also implement this (returns accuracy for classifiers, R² for regressors).

The API Contract

Every estimator: (1) stores all hyperparameters in __init__, (2) fit(X[, y]) learns parameters from data and returns self, (3) learned parameters are stored as attributes ending in _ (e.g., scaler.mean_, lr.coef_). This convention makes introspection, cloning, and serialization trivial.

💡 If you remember one thing

Preprocessing must be fit on training data only. Never call fit on the full dataset before splitting — that's data leakage. Pipeline enforces this automatically: during cross-validation, the scaler fits only on each training fold and transforms the test fold with the training statistics.

Custom Transformers

Extend BaseEstimator and TransformerMixin. Implement fit(self, X, y=None) (store learned state, return self) and transform(self, X) (apply transformation). TransformerMixin gives fit_transform for free. Tag with set_output(transform="pandas") (sklearn ≥ 1.2) to preserve DataFrame column names through the pipeline.

🔑 API Invariants

(1) fit always returns self — enabling method chaining.
(2) transform must not change the number of rows.
(3) Parameters set in __init__ must be re-accessible via get_params() — this is how GridSearchCV clones and configures estimators.
(4) Learned attributes end in _; hyperparameters do not.

Pipeline Chaining & ColumnTransformer
▼

Why Pipeline?

Without Pipeline, a common mistake is to call scaler.fit_transform(X_all) before splitting, leaking test-set statistics into the scaler's mean/std. Pipeline wraps N-1 transformers + 1 final estimator. During cross_validate, sklearn calls pipe.fit(X_train_fold) which triggers each transformer's fit on the fold's training portion only, then transforms both parts.

$$\text{Pipeline}: X \xrightarrow{\text{Scaler.fit\_transform}} \tilde{X} \xrightarrow{\text{PCA.fit\_transform}} \hat{X} \xrightarrow{\text{LR.fit}} \hat{y}$$

The key insight: pipe.fit(X_train, y_train) calls fit_transform on each intermediate step, then fit on the final estimator. pipe.predict(X_test) calls transform (NOT fit_transform) on each intermediate step, preventing leakage.

ColumnTransformer — Routing by Column Type

Real datasets have mixed types: age and income are numeric (scale them); city and job_title are categorical (one-hot encode). ColumnTransformer applies different transformers to different column subsets, then concatenates the results horizontally:

from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.pipeline import Pipeline
num_pipe = Pipeline([('scaler', StandardScaler())])
cat_pipe = Pipeline([('ohe', OneHotEncoder(handle_unknown='ignore'))])
preprocess = ColumnTransformer([
('num', num_pipe, ['age', 'income', 'score']), # 3 numeric cols
('cat', cat_pipe, ['city', 'job_title']), # 2 categorical cols
], remainder='drop') # drop any leftover
full_pipe = Pipeline([
('preprocess', preprocess),
('clf', LogisticRegression(C=1.0, max_iter=500))
])

After transformation: 3 numeric features (scaled) + k one-hot columns from city + m from job_title, all concatenated into a single matrix. The ColumnTransformer remembers which columns it saw during fit and applies the same mapping at transform time.

⚠️ Gotcha: Column Order vs. Column Names

If you pass a NumPy array, ColumnTransformer uses integer positions. If you pass a DataFrame, use column names (strings). In sklearn ≥ 1.2, add set_output(transform="pandas") to propagate column names through the whole pipeline — critical for interpretability and SHAP analysis.

Cross-Validation Strategies
▼

Why Cross-Validate?

A single train/test split gives a high-variance estimate of generalization error: lucky or unlucky random splits change the score significantly. k-fold CV uses all data for both training and evaluation by rotating which fold is held out. The mean CV score is lower-variance; the std across folds measures estimate stability.

$$\text{CV score} = \frac{1}{k} \sum_{i=1}^{k} \text{score}\!\left(f_{-i}(X_{-i},y_{-i}),\; X_i,\; y_i\right)$$

where \(f_{-i}\) denotes the model trained on all folds except fold \(i\), and \((X_i, y_i)\) is the held-out test fold.

CV Strategies

  • KFold(n_splits=k) — shuffles rows, splits into k equal folds. Default choice for regression.
  • StratifiedKFold — preserves class proportions in each fold. Always use for classification (imbalanced or not).
  • GroupKFold — ensures samples from the same group never appear in both train and test. Critical for patient data, temporal groups, etc.
  • TimeSeriesSplit — expanding window: fold i trains on [0..i-1], tests on i. Never shuffles — respects temporal ordering.
  • RepeatedStratifiedKFold — repeats StratifiedKFold n_repeats times with different random seeds. Lowers variance further at computational cost.
  • LeaveOneOut (LOO) — k = n. Unbiased but high variance and expensive. Only for tiny datasets (<50 samples).
$$\text{Standard Error of CV score} = \frac{\text{std}(s_1,\ldots,s_k)}{\sqrt{k}}$$

The Nadeau-Bengio correction adjusts for the fact that CV folds share training data and are therefore not independent, giving a conservative (wider) confidence interval.

💡 The Leakage Invariant

When using cross_validate(pipe, X, y, cv=5), sklearn does: for each fold, (1) deep-copy the pipeline, (2) call pipe.fit(X_train_fold, y_train_fold) — which fits the scaler on fold's training rows only, (3) call pipe.score(X_test_fold, y_test_fold) — which transforms test rows using training statistics. The scaler never sees the test fold's values during fitting.

Choosing k

k=5 or k=10 are standard. Large k: less bias (train sets closer to full n), more variance, more computation. k=n (LOO): minimum bias, maximum variance. For most datasets with n ≥ 1000, k=5 is sufficient. For small datasets (n < 200), use k=10 or even LOO with caution.

🔴 Critical Error: Fitting Before CV

scaler.fit(X) # WRONG: sees all X including test folds
cross_val_score(clf, scaler.transform(X), y) — this contaminates every fold's test set with global statistics. The test accuracy will be optimistically biased. Always wrap preprocessing in a Pipeline and pass the raw X to cross_validate.

Hyperparameter Search Strategies
▼

GridSearchCV

GridSearchCV(estimator, param_grid, cv=5, scoring='accuracy') exhaustively tries every combination of hyperparameters, refitting each configuration with k-fold CV. For a grid of m parameters with \(v_i\) values each and k-fold CV, total fits = \(k \cdot \prod_i v_i\). With 3 parameters × 5 values × 5-fold = 375 fits.

$$\text{GridSearchCV total fits} = k \cdot \prod_{i=1}^{m} |V_i|$$

RandomizedSearchCV

RandomizedSearchCV(estimator, param_distributions, n_iter=100, cv=5) samples n_iter random combinations from the hyperparameter distributions. Key insight from Bergstra & Bengio (2012): if only a few parameters truly matter, random search finds good values much faster than grid search because it explores those important dimensions more densely.

$$\text{RandomSearchCV total fits} = k \cdot n\_\text{iter}$$
  • When grid search wins: ≤ 3 hyperparameters, coarse grid, need exhaustive coverage for reproducibility.
  • When random search wins: ≥ 4 hyperparameters, continuous ranges, or budget-constrained. Supports scipy.stats distributions (e.g., loguniform(1e-4, 1e2)).
  • HalvingGridSearchCV / HalvingRandomSearchCV (sklearn ≥ 0.24): successive halving cuts bad configurations early, reducing compute by ~10×.
  • BayesSearchCV (scikit-optimize): builds a surrogate model of the loss surface, proposes next configuration to evaluate. Best for expensive-to-fit models.

Pipeline + GridSearch Integration

When the estimator is a Pipeline, use double-underscore notation to access nested parameters:

param_grid = {
'preprocess__num__scaler__with_std': [True, False],
'clf__C': [0.1, 1.0, 10.0],
'clf__penalty': ['l1', 'l2'],
}
gs = GridSearchCV(full_pipe, param_grid, cv=StratifiedKFold(5),
scoring='roc_auc', n_jobs=-1, refit=True)
gs.fit(X_train, y_train)
print(gs.best_params_, gs.best_score_)
# After GridSearch: gs.best_estimator_ is refit on full training set
y_pred = gs.predict(X_test) # uses best_estimator_
⚠️ The Two-Level CV Mistake

GridSearchCV internally does CV to select hyperparameters. This inner CV's best_score_ is optimistic (you peeked at it to choose). To get an unbiased estimate of final performance, wrap GridSearchCV in an outer cross_val_score: cross_val_score(GridSearchCV(...), X, y, cv=5). This is nested cross-validation.

Custom Transformer Recipe

from sklearn.base import BaseEstimator, TransformerMixin
import numpy as np
class LogTransformer(BaseEstimator, TransformerMixin):
"""Log-transform skewed features. Hyperparameter: shift."""
def __init__(self, shift=1.0): # ALL hyperparams in __init__
self.shift = shift
def fit(self, X, y=None): # learn nothing, return self
self.n_features_in_ = X.shape[1] # sklearn convention
return self
def transform(self, X): # apply transformation
return np.log(X + self.shift)
# fit_transform is inherited from TransformerMixin

When to Use What

  • Few hyperparams, need exhaustive coverage → GridSearchCV
  • Many hyperparams, continuous ranges → RandomizedSearchCV with distributions
  • Very expensive model (deep learning, XGBoost on big data) → BayesSearchCV or Optuna
  • Small n, few folds available → LeaveOneOut or RepeatedKFold
  • Time series → always TimeSeriesSplit, never shuffle
  • Grouped data (patient IDs, store IDs) → GroupKFold or GroupShuffleSplit
