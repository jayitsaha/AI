Gradient Clipping

By Value vs By Global Norm — taming exploding gradients
Foundational Optimization / Training Stability O(n)
1
Understanding the Concept
▾

What is this? During training, a neural network's gradient tells it how much and in which direction to adjust each weight. Sometimes — especially early in training, in RNNs unrolled over many steps, or in transformers with unstable loss spikes — that gradient becomes enormous. A single giant update can throw the weights into a bad region (or straight to NaN). Gradient clipping is a safety valve: before the optimizer applies the update, we cap the gradient so it can never be "too big."

Analogy: Think of steering a car. Normally you make small, proportional corrections. But if you yank the wheel with full force because of a sudden bump, you'll spin out. Gradient clipping is like a mechanical limiter on the steering wheel — it still lets you turn in the right direction, but it stops you from over-rotating and losing control.

There are two dominant ways to build that limiter. Clip-by-value clamps each individual gradient component independently into a fixed range \([-v, v]\) — simple, but it can distort the direction of the overall gradient vector. Clip-by-global-norm looks at the entire gradient vector (across all parameters) at once, and if its length (norm) exceeds a threshold, rescales the whole vector down uniformly — shrinking magnitude while preserving direction exactly.

If you remember one thing
Clip-by-value reshapes the gradient (changes its direction); clip-by-global-norm only rescales it (keeps the direction, shrinks the length). That's why global-norm clipping is the default in RNNs and transformers — it prevents explosions without corrupting the descent direction.
2
How It Works Internally
▾

Clip-by-value

For every parameter gradient component \(g_i\), independently apply:

$$g_i \leftarrow \max(-v,\ \min(v,\ g_i))$$

This is a per-coordinate clamp. It's cheap (\(O(n)\), no reduction needed) and can be applied per-tensor with no communication across parameters. But because each component is clipped on its own, the ratios between components change — the clipped vector can point in a completely different direction than the original gradient.

Clip-by-global-norm

First compute the L2 norm of the entire gradient — concatenating every parameter's gradient into one giant vector \(g\) (this requires a reduction across all tensors/devices):

$$\|g\|_2 = \sqrt{\textstyle\sum_i g_i^2}$$

If \(\|g\|_2\) exceeds a threshold \(\tau\), rescale the whole vector by the same scalar factor:

$$g \leftarrow g \cdot \frac{\tau}{\|g\|_2} \quad \text{only if } \|g\|_2 > \tau$$

Every component is multiplied by the identical scalar \(\tau / \|g\|_2\), so the direction of \(g\) is untouched — only its magnitude is capped at exactly \(\tau\). Geometrically, this projects any gradient that falls outside the norm-ball of radius \(\tau\) straight back onto the ball's surface, along the ray from the origin.

Design decision: why not just clip-by-value everywhere?
Value clipping treats each parameter independently, so a gradient vector like \((10, 0.01)\) with \(v=1\) becomes \((1, 0.01)\) — the second component barely moves while the first is slashed 10×. The resulting direction is wildly different from the true gradient, which can bias the optimization trajectory. Global-norm clipping instead treats the gradient as one geometric object, so \((10, 0.01)\) with a norm threshold just shrinks uniformly, preserving the descent direction learned by backprop.

Where it fits in the training loop

Clipping happens after loss.backward() computes gradients, and before optimizer.step() applies them:

loss.backward()                                   # gradients populated in .grad
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)   # in-place rescale
optimizer.step()                                  # update uses the clipped gradient

Why It Works
▾

Exploding gradients occur most often when a network is deep or recurrent: through the chain rule, gradients get multiplied by the same Jacobian repeatedly. If the largest singular value of that Jacobian is \(> 1\), gradient magnitude grows geometrically with depth/sequence length:

$$\left\|\frac{\partial L}{\partial h_0}\right\| \approx \left(\prod_{t=1}^{T} \left\|\frac{\partial h_t}{\partial h_{t-1}}\right\|\right) \left\|\frac{\partial L}{\partial h_T}\right\|$$

A single unstable batch can then produce a gradient hundreds or thousands of times larger than normal — the SGD/Adam update step becomes \(\theta \leftarrow \theta - \eta g\), and a huge \(g\) launches the weights far outside the region where the loss surface is locally well-approximated by that gradient, often causing loss to spike or the run to NaN out entirely.

The core guarantee
After global-norm clipping, \(\|g'\|_2 = \min(\|g\|_2, \tau)\) — the update magnitude is bounded by \(\tau\) for every single step, no matter how bad the local curvature is. This gives you an explicit Lipschitz-style bound on how far a single step can move the parameters, which is exactly what makes RNN/Transformer training numerically stable.

Proof sketch (direction preservation): for global-norm clipping, \(g' = c \cdot g\) where \(c = \tau/\|g\|_2 > 0\) is a positive scalar. Since \(g'\) is a positive scalar multiple of \(g\), the cosine similarity between \(g\) and \(g'\) is exactly 1 — the update still points along the true (negative) gradient direction, so it remains a valid descent direction for the loss. Value clipping offers no such guarantee: \(g'_i = \text{clamp}(g_i)\) is a nonlinear, per-coordinate operation, so \(g'\) is generally NOT a scalar multiple of \(g\), and can even point in a direction with positive dot-product deviation large enough to no longer locally decrease the loss.

Key Takeaways & When to Use Which
▾
DimensionClip by ValueClip by Global Norm
OperationPer-component clamp \([-v,v]\)Uniform rescale by \(\tau/\|g\|_2\)
Direction preserved?No — can rotate the vector arbitrarilyYes — always a positive scalar multiple of g
Needs cross-parameter reduction?No, purely localYes, needs global \(\|g\|_2\) across all tensors
CostO(n), trivially parallelO(n) + one global reduction (all-reduce in distributed training)
Typical useRare; simple RL / debugging safety netDefault for RNNs, LSTMs, Transformers (GPT, BERT training all use this)
Common thresholdv ≈ 0.1 – 5, very task-specificτ ≈ 0.5 – 5.0 (τ=1.0 is a very common transformer default)
Decision rule
Default to clip-by-global-norm — it's what PyTorch's clip_grad_norm_, TensorFlow's clip_by_global_norm, and virtually every modern RNN/Transformer training recipe use, because it bounds the update size without biasing the descent direction. Reach for clip-by-value only when you specifically want to bound individual weight updates (e.g. some RL policy-gradient setups) regardless of the resulting direction, or as an extra hard safety cap layered on top of norm clipping.
