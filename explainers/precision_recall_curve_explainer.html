Precision-Recall Curve & AUC-PR

Why PR curves tell the truth that ROC curves hide — especially when positives are rare.

Intermediate Classical ML Evaluation Imbalanced Data
1
Understanding the Concept

Imagine you built a fraud-detection model. Out of 10,000 transactions, only 100 are fraudulent (1% positive rate). Your model flags 50 transactions as fraud. Of those 50 flags, only 40 are actually fraudulent. Of the 100 real frauds, your model caught 40.

Two Questions Every Classifier Must Answer

When your model shouts "Fraud!" — how often is it right? Precision \(= \frac{TP}{TP+FP}\). How many real frauds did it catch? Recall \(= \frac{TP}{TP+FN}\). These two are in tension: raising the alarm more often boosts recall but tanks precision.

A binary classifier doesn't just output "yes/no" — it outputs a score (probability). You pick a threshold \(\tau\): scores above \(\tau\) → predicted positive, below → predicted negative. As you sweep \(\tau\) from 1 → 0, you collect (Precision, Recall) pairs. Plot them: that's the Precision-Recall curve.

The One Thing to Remember

The PR curve lives in (Recall, Precision) space. A random classifier's baseline is a horizontal line at y = class prevalence \(\pi\) — if positives are 1% of data, a random model gives AP ≈ 0.01. A perfect classifier has AP = 1.0. Unlike ROC, there is no free gift for predicting the majority class.

AUC-PR (Area Under the PR Curve), also called Average Precision (AP), summarises the curve in a single number. Higher is always better, and the scale is anchored to how hard the task is.

2
Why PR Beats ROC Under Heavy Imbalance

The ROC curve plots True Positive Rate (Recall) on the y-axis versus False Positive Rate \(\left(= \frac{FP}{FP+TN}\right)\) on the x-axis. Both axes are normalised by their respective class sizes.

The ROC Optimism Trap

When negatives vastly outnumber positives, the FPR denominator \((FP + TN)\) is enormous. A model can make many absolute false positives while keeping FPR small — making ROC look great. PR curves use precision, which directly counts false positives in its numerator: you cannot hide FPs in a PR curve.

Concrete example (1% prevalence, 10,000 samples → 100 positives, 9,900 negatives):

  • Model catches 80/100 positives (TPR = 0.80) but also flags 990 negatives as positive (FPR = 990/9900 = 0.10). ROC point: (0.10, 0.80) — looks impressive.
  • Precision = 80/(80+990) = 80/1070 ≈ 0.075 — 92.5% of flags are wrong. PR curve reveals this brutally.
  • A random model gets AUC-ROC ≈ 0.50 but AUC-PR ≈ 0.01 (= prevalence). The gap between models is much more visible in PR space.
Average Precision Formula

$$\text{AP} = \sum_{k=1}^{n} \bigl(R_k - R_{k-1}\bigr) \cdot P_k$$

where \(P_k\) and \(R_k\) are precision and recall at the \(k\)-th threshold. This is the area under the step-function PR curve, computed by summing trapezoids (left-Riemann sum variant).

The interpolated AP used in PASCAL VOC 2010+ evaluates at 101 recall points \(\{0, 0.01, \ldots, 1.0\}\) and takes the max precision to the right: \(\text{AP} = \frac{1}{101}\sum_{r\in\mathcal{R}} p_{\text{interp}}(r)\) where \(p_{\text{interp}}(r) = \max_{\tilde{r}\geq r} p(\tilde{r})\).

Key Takeaways
When to Choose PR over ROC
  • Class imbalance is severe (positives < 10% of data)
  • False positives have real cost (fraud, medical screening, spam)
  • You care about performance on the positive class only
  • Tasks: information retrieval, object detection (PASCAL VOC mAP), medical diagnosis
Random Baseline

A random classifier traces a horizontal line at \(y = \pi\) (the class prevalence) in PR space. So AUC-PR for a useless model = prevalence \(\approx 0.01\) for 1% data. This makes improvements clearly visible.

AUC-PR Is Not Always Comparable Across Datasets

Because the baseline shifts with prevalence, AUC-PR = 0.60 on a 1%-positive dataset is far harder than 0.60 on a 30%-positive dataset. Always report prevalence alongside AUC-PR.
