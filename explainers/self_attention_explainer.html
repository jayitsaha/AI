Self-Attention (Scaled Dot-Product)

How a sequence looks at itself — turning every token into a Query, a Key, and a Value, then letting each word decide, with real numbers, how much of every other word to absorb.

Intermediate NLP / Transformers O(n²·d)
1
Understanding the Concept
▾

What is this? Self-attention is a way for a model to let every word in a sentence "look at" every other word and decide how relevant each one is, before deciding what that word actually means in context. It's "self" because the sentence attends to itself — not to some other sentence.

Analogy: Imagine a group discussion where each person (token) asks a question ("what am I looking for?") — the Query — while simultaneously wearing a name tag describing what they offer ("here's what I'm about") — the Key. Everyone compares their question against everyone else's tag; the better the match, the more attention they pay to that person's actual contribution to the conversation — the Value. The word "bank" pays close attention to "river" nearby and barely any to "loan" — its final representation blends in mostly river-flavored meaning.

One-sentence summary: Self-attention computes, for every token, a weighted average of every other token's Value vector, where the weights come from how well that token's Query matches each Key.

💡 If you remember one thing

\(Q\), \(K\), \(V\) are just three different linear projections of the same input sequence — self-attention is "compare queries to keys, turn the comparison into a probability distribution, use it to blend values."

2
How It Works Internally
▾

Given an input sequence packed into a matrix \(X \in \mathbb{R}^{n \times d_{model}}\) (one row per token), self-attention learns three weight matrices \(W_Q, W_K, W_V\) and projects the same \(X\) through each of them:

$$Q = XW_Q \qquad K = XW_K \qquad V = XW_V$$

Every token now has a Query row, a Key row, and a Value row. To find out how much token \(i\) should attend to token \(j\), we take the dot product \(q_i \cdot k_j\) — a large positive value means "well aligned," near zero means "unrelated." Stacking every pairwise dot product gives the raw score matrix \(S = QK^\top \in \mathbb{R}^{n \times n}\).

Raw dot products of high-dimensional vectors can get huge, which pushes softmax into regions with near-zero gradients (one weight ≈ 1, the rest ≈ 0). So the scores are divided by \(\sqrt{d_k}\) before the softmax — this keeps the variance of the scores roughly constant regardless of dimensionality, so training stays stable. Row-wise softmax then turns each row of scaled scores into a probability distribution that sums to 1 — this is the attention matrix \(A\). Finally, each token's new representation is a weighted sum of every Value row, weighted by its own row of \(A\): \(Z = AV\).

🔑 Design decision: why three separate projections?

Using \(X\) directly as Query, Key, and Value would force one vector to simultaneously play "what I'm searching for," "how I advertise myself," and "what I actually contribute" — three conflicting jobs. Separate learned projections let the model specialize each role, and because they're just matrix multiplies, the whole operation is a single fused, parallelizable computation across all tokens at once.

3
Why It Works — The Math
▾

The complete scaled dot-product attention formula, from the "Attention Is All You Need" paper (Vaswani et al., 2017):

$$\operatorname{Attention}(Q,K,V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Why divide by \(\sqrt{d_k}\) specifically? Assume each component of \(q\) and \(k\) is drawn independently with mean 0 and variance 1. The dot product \(q\cdot k=\sum_{i=1}^{d_k} q_ik_i\) is a sum of \(d_k\) independent, roughly-zero-mean terms, so by linearity of variance:

$$\operatorname{Var}(q \cdot k) = \sum_{i=1}^{d_k}\operatorname{Var}(q_ik_i) = d_k$$

So the raw score's standard deviation grows like \(\sqrt{d_k}\). Dividing by \(\sqrt{d_k}\) rescales the score back to unit variance regardless of dimensionality — that's exactly why the divisor is a square root, not \(d_k\) itself. Without it, larger head dimensions produce sharper, saturated softmax outputs and vanishing gradients.

⚠️ Common misconception

"Attention weights are how important a token is, period." Not quite — a row of \(A\) is query-conditioned: it says how relevant every other token is to this specific token's query. The same token can receive very different attention from different queries in the same sentence.

Gradient flow: because \(\operatorname{softmax}\) and matrix multiplies are smooth, differentiable operations, gradients flow from the loss straight back through \(Z=AV\), through \(A=\operatorname{softmax}(S/\sqrt{d_k})\), through \(S=QK^\top\), and into \(W_Q, W_K, W_V\) — the whole block is trained end-to-end with ordinary backprop, no special machinery required.

Key Takeaways
▾
AlternativeHow it mixes contextTrade-off vs self-attention
RNN / LSTMSequential hidden state carried token-by-tokenCan't parallelize; long-range deps decay
1D ConvolutionFixed local receptive field, stacked for rangeNeeds many layers for long-range context
Cross-attentionQ from one sequence, K/V from anotherSame math, different source — used in encoder-decoder
Self-attentionQ, K, V all from the same sequenceO(n²) memory/compute, but fully parallel + direct long-range links

Use self-attention when you need every position to directly reach every other position regardless of distance and you can afford \(O(n^2)\) compute (typical sequence lengths in NLP/vision-patch settings). For very long sequences, look at sparse/linear attention variants that approximate the same idea sub-quadratically.

💡 Takeaway

Self-attention is nothing more than learned, content-based soft lookup: build a query, compare it to every key with a dot product, scale to keep gradients healthy, normalize with softmax, and blend the corresponding values. Multi-head attention just runs several of these lookups in parallel with different \(W_Q,W_K,W_V\) so different heads can specialize in different relationships.

6
Code Trace (from scratch)
▾

Exactly what the visualization above computes, in plain NumPy:

import numpy as np def self_attention(X, Wq, Wk, Wv): Q, K, V = X @ Wq, X @ Wk, X @ Wv # (1) linear projections d_k = K.shape[-1] scores = Q @ K.T / np.sqrt(d_k) # (2) scaled dot-product scores -= scores.max(axis=-1, keepdims=True) # numerical stability weights = np.exp(scores) weights /= weights.sum(axis=-1, keepdims=True) # (3) row-wise softmax return weights @ V, weights # (4) weighted sum of values
⚠️ Gotcha

Forgetting axis=-1 on the softmax normalizes down the wrong axis (across tokens instead of across each token's own distribution) — the rows of the attention matrix silently stop summing to 1, and results look "almost right" but are subtly broken.
