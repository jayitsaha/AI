Annoy Library

Approximate Nearest Neighbors Oh Yeah — Spotify's memory-mapped forest of random-projection binary trees

Intermediate Classical ML ANN / Vector Search Index: O(n log n) · Query: O(log n × trees)
1
Understanding the Concept

Annoy (Approximate Nearest Neighbors Oh Yeah) is a C++ library with Python bindings, built at Spotify, that finds the k vectors closest to a query — fast — by trading a little accuracy for a lot of speed and memory efficiency.

Real-World Analogy

Think of a large library with millions of books. Finding the book most similar to yours by reading every book would take forever. Instead, Annoy is like organising the library into a binary decision tree: "Is this book more about science or humanities?" — left or right. Repeat for many random questions, build many such trees, then at query time walk down each tree and combine the candidate lists. You won't read every book, but you'll find the right neighbourhood extremely quickly.

Key Invariant

Annoy builds a static, memory-mapped index of random-projection binary trees. Each tree partitions the space with random hyperplanes; queries descend all trees, merge candidates into a priority queue, and return the best \(k\). Once built, the index is read-only and maps directly into RAM — no Python object overhead.

💡 If You Remember One Thing

Annoy = random hyperplane forests. Every split picks a random hyperplane through two random points; query time is \(O(\text{trees} \times \log n)\); accuracy improves linearly with more trees at the cost of linear memory and query time.

2
How It Works Internally

Index Build Phase

Given \(n\) vectors in \(\mathbb{R}^d\):

  1. Pick two random points \(p, q\) from the current node's set.
  2. Compute the splitting hyperplane: the perpendicular bisector of the segment \(pq\). Its normal is \(\mathbf{v} = p - q\), midpoint \(\mathbf{m} = \frac{p+q}{2}\). A point \(x\) goes left if \(\mathbf{v} \cdot (x - \mathbf{m}) < 0\), else right.
  3. Recurse until a node has \(\leq K\) items (leaf size, default 10–50).
  4. Repeat to build \(T\) independent trees.
$$\text{split}(\mathbf{x}) = \text{sign}\!\left((\mathbf{p} - \mathbf{q})^\top \!\left(\mathbf{x} - \tfrac{\mathbf{p}+\mathbf{q}}{2}\right)\right)$$

Query Phase

For a query \(\mathbf{q}\):

  1. Maintain a max-priority queue of (node, distance-to-hyperplane) pairs, initialised with all tree roots.
  2. Pop the best node, traverse its subtree while also adding the other child to the priority queue (so close hyperplanes are explored).
  3. Accumulate candidate items into a set; once search_k candidates are gathered, compute exact distances to all candidates and return the top \(k\).
Numerical Trace (d=2, n=8 points)

Suppose we have 8 2-D points. Build 2 trees with leaf size 4. Tree 1 picks random pair \((p_3, p_7)\); hyperplane normal \(\mathbf{v} = [1.2, -0.8]\). Points with \(\mathbf{v} \cdot (\mathbf{x} - \mathbf{m}) < 0\) go left (4 pts), rest right (4 pts). Each child is a leaf. Tree 2 picks a different random pair, generating a different partition. Query \(\mathbf{q} = [0.5, 0.3]\) descends both trees, collects up to \(2 \times 4 = 8\) candidates (all points here), computes exact L2 distances, returns top \(k=3\).

Memory Layout

The entire forest is serialised to disk as a flat binary file. At query time, Annoy calls mmap() — the OS maps the file directly into the process address space. This means multiple processes share one file with zero copy overhead, making it ideal for serving at scale.

3
The Mathematics

Hyperplane Splitting

For two randomly chosen points \(\mathbf{p}, \mathbf{q} \in \mathbb{R}^d\), the splitting hyperplane is:

$$\mathcal{H} = \left\{ \mathbf{x} \in \mathbb{R}^d \;\middle|\; (\mathbf{p} - \mathbf{q})^\top \!\left(\mathbf{x} - \frac{\mathbf{p}+\mathbf{q}}{2}\right) = 0 \right\}$$

Recall vs Trees Trade-off

With \(T\) trees, each with leaf size \(K\), the expected number of candidates examined is \(T \cdot K\). Recall (fraction of true nearest neighbors found) grows with \(T\). Empirically:

$$\text{Recall} \approx 1 - \left(1 - \frac{1}{\text{effective partitions}}\right)^T$$

This means doubling trees roughly halves the miss probability, but at the cost of \(2\times\) query time and index size.

Distance Metrics Supported

Annoy natively supports:

  • Euclidean: \(\|\mathbf{x} - \mathbf{y}\|_2 = \sqrt{\sum_i (x_i - y_i)^2}\)
  • Cosine (Angular): \(1 - \frac{\mathbf{x}^\top \mathbf{y}}{\|\mathbf{x}\|_2 \|\mathbf{y}\|_2}\) — internally normalises vectors
  • Manhattan: \(\|\mathbf{x} - \mathbf{y}\|_1 = \sum_i |x_i - y_i|\)
  • Dot product: \(-\mathbf{x}^\top \mathbf{y}\) (maximisation)
  • Hamming: fraction of bits differing
⚠️ Common Misconception

Annoy does not guarantee finding the true nearest neighbor. It is approximate. With angular distance, Annoy pre-normalises all vectors, so the splitting hyperplane passes through the origin — this is equivalent to cosine similarity search. The guarantee is probabilistic: higher \(T\) raises recall but never reaches 100% deterministically.

Index Build Complexity

$$\text{Build time: } O(T \cdot n \log n), \quad \text{Index size: } O(T \cdot n)$$

Query time: \(O(T \cdot \log n + \text{search\_k})\) where search_k is the candidate set size (default \(T \cdot K\)).

Key Takeaways & When to Use

✅ Use Annoy When

  • Index is static (no incremental adds after build)
  • Multiple processes need to share the same index (mmap advantage)
  • You want a simple, dependency-light solution (single C++ file)
  • Vectors are dense and moderate dimension (d ≤ ~500)
  • You use cosine similarity (Spotify recommendation use case)

❌ Do NOT Use Annoy When

  • You need real-time insertions — use HNSW (Hnswlib/FAISS)
  • You need exact nearest neighbors — use brute-force or KD-tree
  • Dimensionality is very high (>1000) — curse of dimensionality hurts all tree methods
  • You need GPU acceleration — use FAISS with CUDA

From Scratch: Random Projection Tree (NumPy)

import numpy as np
from collections import defaultdict
class RPTree:
"""Single random-projection binary tree (simplified Annoy tree)."""
def __init__(self, leaf_size=10):
self.leaf_size = leaf_size
self.nodes = [] # list of (normal, offset, left_idx, right_idx, items)
def build(self, X, indices=None):
if indices is None: indices = list(range(len(X)))
node_id = len(self.nodes)
self.nodes.append(None) # placeholder
if len(indices) <= self.leaf_size:
self.nodes[node_id] = ('leaf', indices) # LEAF
return node_id
# Pick 2 random points → hyperplane normal & offset
i, j = np.random.choice(indices, 2, replace=False)
normal = X[i] - X[j] # perpendicular bisector normal
mid = (X[i] + X[j]) / 2.0 # midpoint
# Partition: dot(normal, x - mid) < 0 → left
dots = (X[indices] - mid) @ normal # shape: (len(indices),)
left = [idx for idx, d in zip(indices, dots) if d < 0]
right = [idx for idx, d in zip(indices, dots) if d >= 0]
# Avoid degenerate splits (all same side)
if not left or not right:
self.nodes[node_id] = ('leaf', indices); return node_id
left_id = self.build(X, left)
right_id = self.build(X, right)
self.nodes[node_id] = ('split', normal, mid, left_id, right_id)
return node_id
def get_candidates(self, X, query, node_id=0, k=50):
node = self.nodes[node_id]
if node[0] == 'leaf': return set(node[1])
_, normal, mid, left_id, right_id = node
margin = normal @ (query - mid)
primary = left_id if margin < 0 else right_id
secondary = right_id if margin < 0 else left_id
candidates = self.get_candidates(X, query, primary)
# Explore other side if close to hyperplane
if abs(margin) < 0.5 * np.linalg.norm(normal):
candidates |= self.get_candidates(X, query, secondary)
return candidates
