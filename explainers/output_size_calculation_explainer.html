Output Size Calculation

How convolution, pooling, and padding determine spatial dimensions in neural networks
Foundational Deep Learning CNNs Beginner–Intermediate O(1) formula
1
Understanding Output Size
▼

What is it? Every convolutional or pooling layer in a neural network takes a spatial input (an image, a feature map) and produces a spatial output. The output's height and width depend on four parameters: the input size, the kernel size, the padding, and the stride. Getting this wrong causes shape mismatches — one of the most common errors when building CNNs.

Why does it matter? Before you can stack layers, connect a fully-connected head, or design a U-Net skip connection, you must know exactly how large each feature map is. Miscalculate by even one pixel and PyTorch or TensorFlow will throw a runtime error deep inside your training loop.

Analogy: Imagine sliding a magnifying glass (the kernel) across a photograph (the input). How many positions can you place the glass? That count is the output size. If you add a border of blank pixels (padding), you get more positions. If you move the glass two steps at a time instead of one (stride > 1), you get fewer positions. Dilation stretches the glass's effective reach without adding parameters.

💡 If you remember one thing

The master formula for a 1-D convolution output size is: $$\text{out} = \left\lfloor \frac{\text{in} + 2p - d(k-1) - 1}{s} \right\rfloor + 1$$ where \(p\) = padding, \(k\) = kernel size, \(s\) = stride, \(d\) = dilation. For 2-D, apply the formula independently to height and width.

This formula generalises all common cases: standard convolution (\(d=1\)), dilated/atrous convolution (\(d>1\)), max-pooling (treat as convolution with no learnable weights), and transposed convolution (which increases spatial size — a separate formula).

How Output Size Is Computed Internally
▼

Step 1 — Effective Kernel Size

Before anything else, dilation expands the kernel's receptive field without adding weights. A kernel of size \(k\) with dilation \(d\) spans \(k_{\text{eff}} = d(k-1)+1\) pixels. With \(k=3, d=1\): \(k_{\text{eff}}=3\). With \(k=3, d=2\): \(k_{\text{eff}}=5\). The kernel still has only \(k^2\) weights, but it "sees" a larger region by skipping pixels.

Step 2 — Padded Input Size

Padding adds \(p\) zeros on each side of the input. A 1-D input of size \(W\) becomes \(W' = W + 2p\). Common choices: valid padding (\(p=0\), output shrinks), same padding (choose \(p\) so output = input when \(s=1\)), and full padding (\(p = k-1\), output grows).

Step 3 — Count Valid Positions

The kernel can be placed at positions \(0, s, 2s, \ldots\) as long as it fits entirely within the padded input. The last valid start position is \(W' - k_{\text{eff}}\). The number of positions is therefore \(\lfloor (W' - k_{\text{eff}}) / s \rfloor + 1\), which expands to the master formula.

Step 4 — 2-D Extension

For images, height and width are independent. Apply the formula once for \(H\) and once for \(W\). The output has shape \((\text{out}_H, \text{out}_W, C_{\text{out}})\) where \(C_{\text{out}}\) is the number of filters (does not affect spatial size).

🔑 Same Padding Rule

To keep output size equal to input size with stride 1 and dilation 1, set \(p = \lfloor k/2 \rfloor\). For odd kernels (1, 3, 5, …) this is exact. For even kernels, PyTorch and TensorFlow handle the asymmetry differently — prefer odd kernels to avoid surprises.

⚠️ Floor vs Round

The formula uses floor division. If the kernel doesn't fit exactly, the rightmost/bottom pixels are simply dropped. This is the default in PyTorch (ceil_mode=False). Setting ceil_mode=True in pooling layers uses ceiling instead, keeping one extra position by zero-padding.

3
The Math — Full Derivation
▼

Setup

Let the input have spatial size \(W\) (1-D for clarity). We slide a kernel of size \(k\) with dilation \(d\), padding \(p\), and stride \(s\). Define the effective kernel size:

$$k_{\text{eff}} = d(k - 1) + 1$$

The padded input has size \(W + 2p\). The kernel must fit entirely within this padded input, so valid start indices \(i\) satisfy:

$$0 \le i \le (W + 2p) - k_{\text{eff}}$$

With stride \(s\), the valid start positions are \(i = 0, s, 2s, \ldots\) The number of such positions (and hence the output size) is:

$$\text{out} = \left\lfloor \frac{W + 2p - k_{\text{eff}}}{s} \right\rfloor + 1 = \left\lfloor \frac{W + 2p - d(k-1) - 1}{s} \right\rfloor + 1$$

Special Cases

Standard convolution (\(d=1, p=0, s=1\)): \(\text{out} = W - k + 1\). A \(5\times5\) input with a \(3\times3\) kernel gives \(5-3+1=3\).

Same padding (\(s=1, d=1\)): Set \(p = \lfloor k/2 \rfloor\) so \(\text{out} = W\).

Strided convolution (\(p=0, d=1\)): \(\text{out} = \lfloor (W-k)/s \rfloor + 1\). Halving: \(k=3, s=2\) on \(W=7\) gives \(\lfloor 4/2 \rfloor+1=3\).

Transposed Convolution (Upsampling)

Transposed convolution reverses the spatial relationship. The output size is:

$$\text{out}_{\text{T}} = (W - 1) \cdot s - 2p + d(k-1) + 1 + \text{output\_padding}$$

where output_padding \(\in \{0, 1, \ldots, s-1\}\) resolves the ambiguity that multiple input sizes can map to the same output size under regular convolution.

Parameter Count (bonus)

The output size formula tells us spatial dimensions, but the total number of learnable parameters in a conv layer is independent of spatial size:

$$\text{params} = C_{\text{out}} \times (C_{\text{in}} \times k_H \times k_W + \mathbf{1}_{\text{bias}})$$

This is why convolutional layers are parameter-efficient: the same \(k \times k\) filter is shared across all spatial positions regardless of input size.

📐 Receptive Field

The receptive field of a neuron in layer \(l\) (how many input pixels it "sees") grows as layers stack. For \(L\) layers each with kernel \(k\) and stride \(s\): \(RF_L = 1 + \sum_{l=1}^{L}(k_l - 1)\prod_{i=1}^{l-1}s_i\). Dilated convolutions grow the receptive field rapidly without increasing parameters or losing resolution.

Key Takeaways
▼

The four knobs and their effects:

  • Kernel size \(k\): Larger kernels shrink the output more (valid padding). They also increase the receptive field and parameter count quadratically.
  • Padding \(p\): Increases output size. "Same" padding (\(p=\lfloor k/2\rfloor\), \(s=1\)) preserves spatial size — essential for residual connections.
  • Stride \(s\): Reduces output size by roughly a factor of \(s\). Strided convolutions replace pooling in modern architectures (e.g., ResNet, EfficientNet).
  • Dilation \(d\): Expands receptive field without reducing output size (when combined with appropriate padding). Used in DeepLab, WaveNet, and temporal CNNs.

Common architecture patterns:

  • Encoder: stride-2 convolutions or max-pooling halve spatial size at each stage.
  • Decoder / U-Net: transposed convolutions double spatial size, skip connections require exact size matching.
  • Fully convolutional networks: output size scales with input — no fixed spatial size required.
💡 Quick Mental Check

For a standard conv with no padding and stride 1: output shrinks by \(k-1\) in each spatial dimension. A stack of \(L\) such layers shrinks by \(L(k-1)\) total. With \(k=3\) and 5 layers: shrinkage = 10 pixels per side. Always verify your input is large enough!

⚠️ Asymmetric Padding

When stride > 1 and you want "same"-like behavior, the required padding may be asymmetric (more on one side). PyTorch's Conv2d only supports symmetric padding; use nn.ZeroPad2d manually or switch to padding='same' (PyTorch ≥ 1.9) which handles this automatically.

Code Trace
▼
import torch
import torch.nn as nn
import math
# ── Pure formula (no tensors needed) ──────────────────────────────
def conv_output_size(W, k, p=0, s=1, d=1):
"""1-D output size for conv / pooling."""
k_eff = d * (k - 1) + 1 # effective kernel size
return math.floor((W + 2*p - k_eff) / s) + 1
def conv2d_output_size(H, W, k, p=0, s=1, d=1):
"""2-D output size — apply formula independently to H and W."""
out_H = conv_output_size(H, k, p, s, d)
out_W = conv_output_size(W, k, p, s, d)
return out_H, out_W
# ── Verify with PyTorch ───────────────────────────────────────────
H, W = 7, 7
k, p, s, d = 3, 0, 1, 1
conv = nn.Conv2d(1, 1, kernel_size=k, padding=p, stride=s, dilation=d)
x = torch.zeros(1, 1, H, W) # batch=1, C=1, H, W
out = conv(x)
print(out.shape) # torch.Size([1, 1, 5, 5])
formula_H, formula_W = conv2d_output_size(H, W, k, p, s, d)
print(formula_H, formula_W) # 5 5 ✓
# ── Transposed convolution (upsampling) ──────────────────────────
def transposed_conv_output(W, k, p=0, s=1, d=1, op=0):
return (W - 1) * s - 2*p + d*(k-1) + 1 + op
print(transposed_conv_output(5, 3, p=0, s=2)) # 11
# ── "Same" padding helper ─────────────────────────────────────────
def same_padding(k, d=1):
"""Padding for output == input when s=1."""
return (d * (k - 1)) // 2
print(same_padding(3)) # 1
print(same_padding(5)) # 2
print(same_padding(3, d=2)) # 2 (dilated same)
