1
Understanding Matrix Multiplication
▼

What is it? Matrix multiplication is the operation that combines two grids of numbers \(A\) and \(B\) into a result matrix \(C\). Every deep learning forward pass, every linear transformation in a neural network, every PCA computation, boils down to matrix multiplication. It is the fundamental primitive of numerical computing.

Analogy: Imagine a factory network. Matrix \(A\) describes how each source factory distributes goods to each warehouse. Matrix \(B\) describes how each warehouse distributes to each city. Multiplying them tells you how goods flow directly from source factories to cities, skipping warehouses. Each entry \(C_{ij}\) = total goods from factory \(i\) to city \(j\), summed across all possible warehouses.

Why complexity matters: For an \(n \times n\) matrix, the naive algorithm does \(n^3\) scalar multiplications. For \(n = 1024\) (typical in ML), that's over a billion operations. Reducing the exponent by even 0.2 yields 30–40% fewer operations at \(n = 4096\). This is why Strassen's 1969 discovery was revolutionary — it proved the naive algorithm is not optimal.

💡 If you remember one thing

The naive algorithm computes \(C_{ij} = \sum_{k=1}^n A_{ik} B_{kj}\) using \(n^3\) multiplications. Strassen recurses on \(2\times 2\) blocks using only 7 multiplications (not 8), giving \(T(n) = 7\,T(n/2) + O(n^2)\), which by the Master Theorem resolves to \(O(n^{\log_2 7}) = O(n^{2.807})\).

2
How It Works Internally
▼

The Naive Algorithm: Row × Column Dot Products

Given \(A \in \mathbb{R}^{m \times k}\) and \(B \in \mathbb{R}^{k \times n}\), their product \(C = AB \in \mathbb{R}^{m \times n}\) is defined entry-by-entry:

$$C_{ij} = \sum_{p=1}^{k} A_{ip} \cdot B_{pj}, \quad i=1,\ldots,m,\; j=1,\ldots,n$$

Computing one entry requires \(k\) multiplications and \(k-1\) additions. For square \(n\times n\) matrices: \(n^2\) entries, each requiring \(n\) multiplications → \(O(n^3)\) total multiplications.

Strassen's Algorithm: Divide and Conquer on 2×2 Blocks

Partition \(A\), \(B\), and \(C\) into \(2 \times 2\) blocks, each of size \((n/2) \times (n/2)\). The naive approach to compute the 4 blocks of \(C\) would require 8 recursive multiplications. Strassen's insight: define 7 auxiliary products \(M_1, \ldots, M_7\) using only additions and subtractions of blocks, then combine them to recover all 4 blocks of \(C\):

The 7 Products

M₁ = (A₁₁ + A₂₂)(B₁₁ + B₂₂)
M₂ = (A₂₁ + A₂₂) B₁₁
M₃ = A₁₁ (B₁₂ − B₂₂)
M₄ = A₂₂ (B₂₁ − B₁₁)
M₅ = (A₁₁ + A₁₂) B₂₂
M₆ = (A₂₁ − A₁₁)(B₁₁ + B₁₂)
M₇ = (A₁₂ − A₂₂)(B₂₁ + B₂₂)

Reconstructed C Blocks

C₁₁ = M₁ + M₄ − M₅ + M₇
C₁₂ = M₃ + M₅
C₂₁ = M₂ + M₄
C₂₂ = M₁ − M₂ + M₃ + M₆

Verify: each C block uses only additions of M's — no extra multiplications.

🔑 Key Property

Strassen replaces 8 recursive multiplications with 7, at the cost of 18 additions/subtractions (instead of 4). Since multiplication is asymptotically more expensive than addition for large blocks, this tradeoff pays off. Recursing: \(T(n) = 7\,T(n/2) + \Theta(n^2)\), giving \(T(n) = \Theta(n^{\log_2 7}) \approx \Theta(n^{2.807})\).

Design Decision: Why Does 7 vs 8 Matter?

With 8 multiplications: \(T(n) = 8\,T(n/2) + O(n^2)\) → \(O(n^{\log_2 8}) = O(n^3)\) — no gain. The Master Theorem's "multiplication count" is the base of the recurrence; shaving it from 8 to 7 changes the exponent from 3 to 2.807. Every improvement since (Coppersmith–Winograd, Virginia Vassilevska Williams, 2024's \(\omega < 2.371866\)) follows the same principle: reduce the base of the recursion.

3
Why It Works — The Math
▼

Complexity of Naive Algorithm

For square \(n\times n\) matrices, the triple nested loop performs:

$$T_{\text{naive}}(n) = \sum_{i=1}^n \sum_{j=1}^n \sum_{k=1}^n 1 = n^3 \text{ multiplications}$$

This is tight: every entry must receive contributions from every row-column pair.

Master Theorem Applied to Strassen

Strassen's recurrence on \(n = 2^s\) (padded if necessary):

$$T(n) = 7\,T\!\left(\frac{n}{2}\right) + \Theta(n^2)$$

Master Theorem form: \(T(n) = a\,T(n/b) + f(n)\) with \(a=7\), \(b=2\), \(f(n) = \Theta(n^2)\).

Compare \(f(n)\) to \(n^{\log_b a} = n^{\log_2 7} \approx n^{2.807}\). Since \(2 < 2.807\), we are in Case 1 of the Master Theorem:

$$T(n) = \Theta\!\left(n^{\log_2 7}\right) = \Theta\!\left(n^{2.807\ldots}\right)$$

Exact Value

$$\log_2 7 = \frac{\ln 7}{\ln 2} = \frac{1.94591\ldots}{0.69315\ldots} = 2.80735\ldots$$

Strassen Correctness on 2×2 Numerical Trace

Let \(A = \begin{bmatrix}1&2\\3&4\end{bmatrix}\), \(B = \begin{bmatrix}5&6\\7&8\end{bmatrix}\). Naive gives \(C = \begin{bmatrix}19&22\\43&50\end{bmatrix}\). Now verify with Strassen's \(M_i\):

  • \(M_1 = (1+4)(5+8) = 5 \cdot 13 = 65\)
  • \(M_2 = (3+4)\cdot 5 = 7 \cdot 5 = 35\)
  • \(M_3 = 1\cdot(6-8) = 1 \cdot (-2) = -2\)
  • \(M_4 = 4\cdot(7-5) = 4 \cdot 2 = 8\)
  • \(M_5 = (1+2)\cdot 8 = 3 \cdot 8 = 24\)
  • \(M_6 = (3-1)(5+6) = 2 \cdot 11 = 22\)
  • \(M_7 = (2-4)(7+8) = (-2) \cdot 15 = -30\)

Reconstruct: \(C_{11} = 65 + 8 - 24 + (-30) = 19\) ✓, \(C_{12} = -2 + 24 = 22\) ✓, \(C_{21} = 35 + 8 = 43\) ✓, \(C_{22} = 65 - 35 + (-2) + 22 = 50\) ✓

⚠️ Common Pitfall

Strassen has a large constant hidden in \(\Theta(\cdot)\): at small \(n\), the overhead of additions and recursive call setup makes it slower than naive. In practice, hybrid algorithms switch to naive (or BLAS-tuned) below a crossover point (often \(n \approx 64\)–\(128\)). For dense ML workloads on modern GPUs, highly-optimized BLAS (cuBLAS) outperforms Strassen due to cache and memory bandwidth benefits.

Key Takeaways & When to Use
▼

Complexity hierarchy (square \(n\times n\)):

  • Naive: \(O(n^3)\) — three nested loops, every introductory course
  • Strassen: \(O(n^{2.807})\) — first sub-cubic algorithm, 1969
  • Coppersmith–Winograd: \(O(n^{2.376})\) — 1987, impractical constant
  • Vassilevska Williams et al. (2024): \(O(n^{2.3713})\) — theoretical frontier

When to use Strassen in practice: Very large dense matrices (\(n \gg 1000\)) where memory bandwidth is not the bottleneck. CPU implementations exist in LAPACK-adjacent libraries; GPU implementations are rare because modern GPU memory hierarchies favor BLAS-tuned tiling over Strassen's recursive structure.

Why this matters for ML: Transformer attention is \(O(n^2 d)\) partly because matrix multiplication of \(Q K^\top \in \mathbb{R}^{n\times n}\) costs \(O(n^2 d)\) — improving the matmul exponent directly reduces attention complexity. Flash Attention's approach (tiling for cache efficiency) is an orthogonal improvement that leverages hardware rather than algebraic tricks.

💡 The Big Picture

Matrix multiplication complexity is one of the deepest open problems in theoretical computer science. The "true" exponent \(\omega\) (the infimum of achievable exponents) is believed to be 2, but no algorithm has achieved it. Current best: \(\omega < 2.3713\).

Code Implementations
▼

Naive Algorithm (Python / NumPy from scratch)

# Pure Python — educational, O(n^3)
def matmul_naive(A, B):
    m, k = len(A), len(A[0])
    k2, n = len(B), len(B[0])
    assert k == k2, "Inner dims must match"
    C = [[0.0] * n for _ in range(m)]
    for i in range(m):           # rows of A
        for j in range(n):       # cols of B
            s = 0.0
            for p in range(k):   # dot product
                s += A[i][p] * B[p][j]
            C[i][j] = s
    return C

# NumPy production usage (uses optimized BLAS)
import numpy as np
A = np.random.randn(1024, 1024).astype(np.float32)
B = np.random.randn(1024, 1024).astype(np.float32)
C = A @ B  # or np.matmul(A, B)

Strassen 2×2 (Python)

def strassen_2x2(A, B):
    """Strassen on 2x2 scalar matrices — 7 multiplications."""
    a11,a12,a21,a22 = A[0][0],A[0][1],A[1][0],A[1][1]
    b11,b12,b21,b22 = B[0][0],B[0][1],B[1][0],B[1][1]

    M1 = (a11+a22)*(b11+b22)  # 1 mult
    M2 = (a21+a22)*b11        # 1 mult
    M3 = a11*(b12-b22)        # 1 mult
    M4 = a22*(b21-b11)        # 1 mult
    M5 = (a11+a12)*b22        # 1 mult
    M6 = (a21-a11)*(b11+b12)  # 1 mult
    M7 = (a12-a22)*(b21+b22)  # 1 mult
    # Total: exactly 7 multiplications

    C11 = M1 + M4 - M5 + M7
    C12 = M3 + M5
    C21 = M2 + M4
    C22 = M1 - M2 + M3 + M6
    return [[C11,C12],[C21,C22]]

# Verify:
A = [[1,2],[3,4]]; B = [[5,6],[7,8]]
C = strassen_2x2(A,B)
# C = [[19,22],[43,50]] ✓
⚠️ Production Gotcha

In PyTorch / TensorFlow, A @ B dispatches to cuBLAS on GPU, which uses highly-tuned GEMM kernels. These are faster than Strassen for typical ML workloads (\(n \leq 8192\)) due to cache-friendly tiling and tensor core utilization. Use Strassen only when theoretical complexity dominates hardware effects.
