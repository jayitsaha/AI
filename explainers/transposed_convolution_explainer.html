Understanding Transposed Convolution
▼

What is it? A transposed convolution (also called a fractionally-strided convolution or — misleadingly — a "deconvolution") is a learnable operation that increases the spatial resolution of a feature map. It is the backbone of decoder networks in architectures like U-Net, DCGAN, and segmentation models, where you need to go from a compact latent representation back to full-resolution output.

Why not just upsample then convolve? You could bilinearly upsample and then apply a regular convolution. Transposed convolution does this in one step with learned weights, allowing the network to decide the best way to fill in the missing spatial information. The filter weights are trained by backpropagation just like any other layer.

Analogy: Imagine a regular convolution as pressing a stamp onto paper — you collapse a patch of pixels into one number. A transposed convolution is like taking one number and spreading it back out through the stamp, then summing all the overlapping stamp impressions. Each input pixel "broadcasts" a scaled copy of the kernel into the output, and wherever kernels overlap, the values are added together.

💡 If you remember one thing

A transposed convolution with kernel size \(k\), stride \(s\), and padding \(p\) maps an input of size \(H_{in}\) to an output of size \(H_{out} = s(H_{in}-1) + k - 2p\). With \(s=2, k=2, p=0\) this exactly doubles the spatial dimensions, which is the most common use case in decoder networks.

The name confusion: "Deconvolution" is a misnomer — the operation does not mathematically invert a convolution (that would require knowing the original input). The correct term is transposed convolution because its matrix representation is the transpose of the forward convolution matrix. The gradient of a convolution with respect to its input IS a transposed convolution — so backprop through a conv layer literally performs this operation.

How Transposed Convolution Works Internally
▼

Step 1: Insert Zeros (Fractional Striding)

For stride \(s > 1\), the input is first "dilated" by inserting \(s-1\) zeros between every pair of adjacent input values. A \(2 \times 2\) input with stride 2 becomes a \(3 \times 3\) dilated input (one zero between each pair). This is why the operation is also called a fractionally-strided convolution — the effective stride is \(1/s\).

Step 2: Pad the Dilated Input

The dilated input is then padded with \(k-1-p\) zeros on all sides, where \(k\) is the kernel size and \(p\) is the desired output padding. For the common case \(k=3, s=2, p=1\), this means padding the dilated input with 2 zeros on each side.

Step 3: Apply a Standard Convolution with Stride 1

A regular convolution with stride 1 is applied to the padded, dilated input. The kernel is the same size as in the forward pass. The result is the upsampled output.

🔑 The "Scatter-and-Sum" View

Equivalently (and more intuitively): for each input position \((i,j)\) with value \(x_{ij}\), place a copy of the kernel scaled by \(x_{ij}\) at the corresponding output location. Where kernel footprints overlap, sum the contributions. This is the view shown in the interactive diagram.

Checkerboard Artifacts

A notorious failure mode: when the kernel size is not divisible by the stride, some output positions receive contributions from more input pixels than others. This creates a regular "checkerboard" pattern of high and low activations. The fix is to use kernel sizes divisible by stride (e.g., \(k=4, s=2\)) or to use bilinear upsample + conv instead.

⚠️ Checkerboard Artifacts

With \(k=3, s=2\): kernel size (3) is not divisible by stride (2). Output pixels at even positions receive 4 kernel contributions; odd positions receive only 2. This uneven overlap creates visible grid artifacts in generated images. Use \(k=4, s=2\) or \(k=2, s=2\) to avoid this.

Relationship to the Forward Convolution Matrix

Every convolution can be written as a matrix multiplication \(y = Cx\), where \(C\) is a sparse Toeplitz matrix. The transposed convolution computes \(x' = C^\top y'\). This is exactly the operation performed during backpropagation when computing \(\partial \mathcal{L}/\partial x\) in a conv layer — which is why the gradient of a conv IS a transposed conv.

3
The Math — Why It Works
▼

Output Size Formula

For a 1D transposed convolution with input size \(L_{in}\), kernel size \(k\), stride \(s\), padding \(p\), and output padding \(p_{out}\):

$$L_{out} = (L_{in} - 1) \cdot s - 2p + k + p_{out}$$

In 2D (the standard case), this applies independently to height and width. The most common configuration for 2× upsampling is \(k=2, s=2, p=0\), giving \(L_{out} = 2L_{in}\).

Matrix Formulation

Consider a 1D input \(\mathbf{x} \in \mathbb{R}^{n}\) and a convolution matrix \(C \in \mathbb{R}^{m \times n}\) (with \(m < n\) for downsampling). The forward convolution is:

$$\mathbf{y} = C\mathbf{x}, \quad C \in \mathbb{R}^{m \times n}, \quad \mathbf{y} \in \mathbb{R}^m$$

The transposed convolution uses \(C^\top\) to map back from the smaller space to the larger one:

$$\mathbf{x}' = C^\top \mathbf{y}', \quad C^\top \in \mathbb{R}^{n \times m}, \quad \mathbf{x}' \in \mathbb{R}^n$$

For example, with input size 4, kernel size 3, stride 1, the convolution matrix is:

$$C = \begin{pmatrix} k_1 & k_2 & k_3 & 0 \\ 0 & k_1 & k_2 & k_3 \end{pmatrix} \in \mathbb{R}^{2 \times 4}$$

and \(C^\top \in \mathbb{R}^{4 \times 2}\) maps 2 values back to 4. The kernel weights \(k_1, k_2, k_3\) are shared — the same kernel appears in both the forward and transposed pass, just transposed in arrangement.

Gradient Connection

During backpropagation through a conv layer, the gradient with respect to the input is:

$$\frac{\partial \mathcal{L}}{\partial \mathbf{x}} = C^\top \frac{\partial \mathcal{L}}{\partial \mathbf{y}}$$

This is precisely a transposed convolution applied to the upstream gradient. So every time you train a CNN, transposed convolutions are computed implicitly in the backward pass.

📐 Inner Product Duality

The transposed conv is the adjoint of the forward conv: \(\langle C\mathbf{x}, \mathbf{y} \rangle = \langle \mathbf{x}, C^\top \mathbf{y} \rangle\). This duality means the transposed conv preserves the "information geometry" of the forward pass — it maps gradients back through the same learned filter bank.

Key Takeaways
▼

When to use transposed convolution:

  • Decoder/upsampling path of encoder-decoder architectures (U-Net, SegNet)
  • Generator networks in GANs (DCGAN, StyleGAN) — learned upsampling is crucial for quality
  • Super-resolution networks where learned spatial upsampling outperforms bicubic interpolation
  • Any task requiring spatial resolution recovery: depth estimation, optical flow, image generation

When NOT to use (or be careful):

  • When checkerboard artifacts are unacceptable — prefer bilinear upsample + conv (e.g., in medical imaging)
  • When memory is very tight — transposed conv uses the same memory as a forward conv of the output size
  • When you need exact inversion of a conv — transposed conv does NOT invert; use proper deconvolution algorithms
💡 Architecture Hierarchy

Nearest-neighbor upsample (no params) ⊂ Bilinear upsample (no params) ⊂ Bilinear + Conv (params, no artifacts) ⊂ Transposed Conv (params, possible artifacts, more expressive). Each step adds expressiveness at a cost.

Output size formula quick reference: For 2× upsampling use \(k=2, s=2, p=0\) → \(H_{out} = 2H_{in}\). For 2× with same-style padding use \(k=4, s=2, p=1\) → \(H_{out} = 2H_{in}\). The second avoids checkerboard artifacts.

🔑 The Backprop Connection

The gradient of a convolution with respect to its input is a transposed convolution. This means every CNN you train already computes transposed convolutions during the backward pass — the transposed conv layer simply exposes this operation as a learnable forward-pass primitive.

Code Trace
▼

From-scratch NumPy implementation of 1D transposed convolution using the scatter-and-sum approach, then verified against PyTorch.

import numpy as np
import torch, torch.nn as nn
# ── 1D Transposed Convolution from scratch ──────────────────────
def transposed_conv1d(x, kernel, stride=1, padding=0):
"""
x : input array, shape (L_in,)
kernel : 1D kernel, shape (k,)
stride : upsampling factor
"""
L_in = len(x)
k = len(kernel)
# Output size formula: (L_in - 1)*stride + k - 2*padding
L_out = (L_in - 1) * stride + k - 2 * padding
output = np.zeros(L_out)
# Scatter-and-sum: each input pixel broadcasts a scaled kernel
for i, val in enumerate(x):
start = i * stride - padding
for j, w in enumerate(kernel):
out_idx = start + j
if 0 <= out_idx < L_out:
output[out_idx] += val * w # accumulate overlap
return output
# ── Example ─────────────────────────────────────────────────────
x = np.array([2.0, 3.0])
kernel = np.array([1.0, 2.0, 1.0])
out = transposed_conv1d(x, kernel, stride=2)
print("Scratch:", out) # [2. 4. 7. 6. 3.]
# ── Verify with PyTorch ──────────────────────────────────────────
layer = nn.ConvTranspose1d(1, 1, kernel_size=3, stride=2, bias=False)
layer.weight.data = torch.tensor([[kernel]]).float()
x_t = torch.tensor([[[2.0, 3.0]]]) # (batch, channels, length)
out_t = layer(x_t)
print("PyTorch:", out_t.detach().numpy()) # matches scratch
# ── 2D version (used in image decoders) ─────────────────────────
layer2d = nn.ConvTranspose2d(
in_channels=64, # e.g. bottleneck feature map
out_channels=32,
kernel_size=4, # divisible by stride → no checkerboard
stride=2,
padding=1 # (k - s) / 2 = 1 for exact 2x upsample
)
# Input: (batch, 64, H, W) → Output: (batch, 32, 2H, 2W)
