1
Understanding the Chain Rule on a Graph
▼

What is it? Any function built from simple operations — add, multiply, sin, exp — can be drawn as a computational graph: a DAG where leaf nodes are inputs, internal nodes are primitive operations, and edges carry values forward. The multivariable chain rule tells you exactly how to compute the derivative of the output with respect to any node, just by walking the graph.

Analogy: Think of a company's profit as the final node in an org chart. A change in a junior engineer's output ripples upward through their team lead, then their director, then the VP, each link scaling the effect by "how much I amplify what's below me." If that engineer's work also feeds a second team (a second path to the top), their total influence on profit is the sum of their influence through both routes — not just one.

💡 If you remember one thing

Backpropagation is nothing but the multivariable chain rule applied node-by-node in reverse: $$\frac{\partial f}{\partial x} = \sum_{\text{paths } p:\, x \to f} \ \prod_{(u \to v) \in p} \frac{\partial v}{\partial u}$$ Each node only ever needs to know its own local derivative — the graph structure handles composing them correctly.

2
How Backprop Works Internally
▼

Building the Graph: Decompose Into Primitives

Take \(f = (a \cdot b + c)\cdot\sin(a+d)\). We factor it into primitive operations, each becoming one node: \(e = a\cdot b\), \(s = a+d\), \(g = e + c\), \(h = \sin(s)\), \(f = g \cdot h\). Notice a appears in two primitives (\(e\) and \(s\)) — it has two distinct paths to the output. This is the case the naive single-variable chain rule can't handle, but the graph handles automatically.

Forward Pass: Evaluate Bottom-Up

With \(a=2, b=3, c=1, d=0.5\): compute every node in topological order, caching each intermediate value. This gives us \(f(a,b,c,d) = 4.1893\), but also — crucially — every local derivative becomes cheap to evaluate once we know the inputs at each node (e.g. \(\partial e/\partial a = b\) is just "whatever \(b\) currently is").

Backward Pass: Reverse Accumulation

Starting from \(\partial f/\partial f = 1\), we walk the graph in reverse topological order. At each node \(v\), once ALL of \(v\)'s consumers have reported their gradient contribution, we multiply by \(v\)'s local derivative and push the result to \(v\)'s parents (inputs). A node with multiple consumers — like a — simply sums every contribution it receives before it's considered "done."

Design Decision: Why Reverse-Mode, Not Forward-Mode?

Forward-mode autodiff propagates \(\partial(\cdot)/\partial x\) for one input \(x\) at a time — you'd need 4 forward passes to get all of \(\partial f/\partial a, \partial f/\partial b, \partial f/\partial c, \partial f/\partial d\). Reverse-mode computes gradients for all inputs with respect to a single output in one backward pass. Since neural nets have millions of inputs (parameters) and one scalar loss, reverse-mode (what PyTorch/TensorFlow call "backprop" or "autograd") is astronomically cheaper.

🔑 Key Property

Every node's job is purely local: know your inputs, know your own derivative formula, and sum whatever gradient signal arrives from your consumers. Global correctness (the exact multivariable chain rule) emerges from this simple local rule applied everywhere in the graph.

3
Why It Works — The Math
▼

Single-Variable Chain Rule (the building block)

If \(z = z(u)\) and \(u = u(x)\), the familiar chain rule says:

$$\frac{dz}{dx} = \frac{dz}{du}\cdot\frac{du}{dx}$$

This is exactly one edge of the graph: multiply the gradient arriving from above by the local derivative of that edge.

Multivariable Chain Rule (the total derivative)

Now suppose \(z\) depends on \(x\) through several intermediate variables \(u_1,\dots,u_k\), each of which depends on \(x\). The total derivative theorem says the effects add:

$$\frac{\partial z}{\partial x} = \sum_{i=1}^{k} \frac{\partial z}{\partial u_i}\cdot\frac{\partial u_i}{\partial x}$$

In our graph, \(x=a\) reaches \(f\) via \(u_1=e\) and \(u_2=s\), so \(\partial f/\partial a = (\partial f/\partial e)(\partial e/\partial a) + (\partial f/\partial s)(\partial s/\partial a)\). Expanding recursively — since \(\partial f/\partial e\) and \(\partial f/\partial s\) are themselves sums of products along the paths from \(e\) and \(s\) to \(f\) — gives the general path-sum formula:

$$\frac{\partial f}{\partial x} = \sum_{\text{paths } p:\, x \to f} \ \prod_{(u \to v) \in p} \frac{\partial v}{\partial u}$$

Proof sketch (induction on graph depth): Base case — if \(x\) is a direct input to \(f\), the formula reduces to the single local derivative, which is trivially "the product along the one edge." Inductive step — assume the formula holds for every child \(u_i\) of \(x\) (i.e. \(\partial f/\partial u_i\) already correctly sums products over all paths \(u_i \to f\)). Then by the single-variable chain rule applied at the edge \(x \to u_i\), each term \((\partial f/\partial u_i)(\partial u_i/\partial x)\) itself expands into "local derivative times a sum of path-products" — distributing the multiplication over the sum reproduces exactly the path-sum formula for \(x\). Summing over all children \(u_i\) of \(x\) sums over all paths from \(x\) to \(f\).

⚠️ Common Misconception

"Just multiply the local derivatives along the path from \(f\) back to \(x\)." This is only correct if there is exactly one path. The moment a variable is reused (weight sharing, residual connections, an input feeding two branches), you must sum the products over every path — forgetting to accumulate is exactly the class of bug that silently produces wrong gradients in hand-rolled autodiff code (it's why frameworks explicitly zero_grad() and then accumulate into .grad, never overwrite it).

Key Takeaways
▼

This is exactly what deep learning frameworks do:

  • PyTorch's autograd and TensorFlow's GradientTape build this graph implicitly as you run forward operations (a "tape"), then walk it backward calling each op's backward() with the incoming gradient.
  • Shared weights (e.g. an embedding matrix used at every timestep of an RNN, or tied encoder/decoder weights) are the "variable used twice" case — gradients from every use are summed automatically.
  • Residual/skip connections (ResNets, Transformers) create exactly this multi-path structure — the identity path contributes a clean "+1" term to the sum, which is precisely why they fight vanishing gradients.

When you need to think about this explicitly: writing a custom autograd Function, debugging exploding/vanishing/NaN gradients, or reasoning about why gradient accumulation across micro-batches requires summing (not averaging) before the optimizer step.

💡 Forward-mode vs Reverse-mode

Forward-mode propagates \(\partial(\cdot)/\partial x_{\text{fixed}}\) — cheap when #inputs \(\ll\) #outputs (e.g. sensitivity analysis). Reverse-mode propagates \(\partial f_{\text{fixed}}/\partial(\cdot)\) — cheap when #outputs \(\ll\) #inputs. Neural net training has millions of inputs (weights) and one scalar loss, so reverse-mode (backprop) wins by a landslide.

Code Trace — Mini Autodiff Engine
▼

A ~20-line reverse-mode autodiff engine. Every op stores its local derivatives; backward() walks the graph in reverse and accumulates (+=) into .grad — the line that makes the multivariable chain rule correct for reused variables.

import math
class Value:
def __init__(self, data, parents=(), local_grads=()):
self.data = data
self.grad = 0.0
self.parents = parents # inputs that built this node
self.local_grads = local_grads # d(self)/d(parent) for each
def mul(x, y): return Value(x.data*y.data, (x,y), (y.data, x.data))
def add(x, y): return Value(x.data+y.data, (x,y), (1.0, 1.0))
def sin_(x): return Value(math.sin(x.data), (x,), (math.cos(x.data),))
a, b, c, d = Value(2), Value(3), Value(1), Value(0.5)
e = mul(a, b) # e = a*b
s = add(a, d) # s = a+d <-- 'a' reused: 2nd path!
g = add(e, c) # g = e+c
h = sin_(s) # h = sin(s)
f = mul(g, h) # f = g*h (output, f = 4.1893)
def backward(root):
order = topo_sort(root) # reverse topological order
root.grad = 1.0 # seed: df/df = 1
for node in reversed(order):
for p, local in zip(node.parents, node.local_grads):
p.grad += node.grad * local # SUM contributions!
backward(f)
print(a.grad) # -3.8126 = 1.7954 (via e) + -5.6080 (via s)
print(b.grad) # 1.1969
print(c.grad) # 0.5985
print(d.grad) # -5.6080
