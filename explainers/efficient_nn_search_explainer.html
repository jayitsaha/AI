Efficient Nearest-Neighbour Search

KD-Trees, Ball Trees & Locality-Sensitive Hashing — beyond brute force
Advanced Classical ML KNN / Search O(log n) avg · O(n) worst
1
Understanding the Problem
▼

What is Nearest-Neighbour (NN) search? Given a dataset of \(n\) points in \(d\)-dimensional space and a query point \(\mathbf{q}\), find the point \(\mathbf{x}^*\) that minimises \(\|\mathbf{q} - \mathbf{x}^*\|_2\). This is the core computation in KNN classification, retrieval systems, recommendation, and vector databases.

The brute-force problem: Scanning all \(n\) points and computing distance to \(\mathbf{q}\) costs \(\mathcal{O}(nd)\) per query. With \(n=10^9\) documents and \(d=768\) (BERT embedding), that is ~768 billion multiply-adds per query — completely impractical.

Analogy: Finding the nearest library in a city. Brute-force checks every building. A KD-tree is like using a street grid — "I'm north of Main St., so skip the south half." A ball tree uses circular zones. LSH is like a city-district postal code: points in the same zone are approximately close, so only check your zone.

💡 If you remember one thing

Brute force is \(\mathcal{O}(nd)\). KD-trees reduce this to \(\mathcal{O}(d \log n)\) in low dimensions but degrade to \(\mathcal{O}(nd)\) for \(d \gtrsim 20\). Ball trees handle moderate \(d\) better. LSH gives approximate results in \(\mathcal{O}(n^\rho d)\) with \(\rho < 1\), sub-linear in \(n\) — trading exactness for speed.

2
How the Three Structures Work
▼

KD-Tree — Axis-Aligned Binary Space Partitioning

A KD-tree recursively splits the dataset by alternating axes. At depth \(k\), split on dimension \(k \bmod d\) at the median value. Each internal node stores a split hyperplane; leaves store points. Build time: \(\mathcal{O}(dn \log n)\). Query time: \(\mathcal{O}(d \log n)\) average, but degrades exponentially in \(d\) because the branch-and-bound pruning fails — every hypersphere in high-D intersects many cells.

Branch-and-bound NN query: Descend to the leaf containing \(\mathbf{q}\), record the nearest point found as \(r^*\). Then backtrack: prune a sibling subtree if the distance from \(\mathbf{q}\) to its bounding hyperplane exceeds \(r^*\). For the 6-point 2D dataset with \(\mathbf{q}=(9,2)\), best distance is \(\sqrt{2}\approx 1.414\) to \((8,1)\). The split plane at \(x=5\) is distance \(|9-5|=4 > 1.414\), so the entire left subtree is pruned.

Ball Tree — Nested Hyperspheres

Instead of axis-aligned rectangles, a ball tree encloses each node's subset in the smallest enclosing ball \(\mathcal{B}(\mathbf{c}, r)\). Pruning condition: if \(\|\mathbf{q} - \mathbf{c}\| - r > r^*_{\text{current}}\), the entire subtree is skipped. Ball trees are more expensive to build (\(\mathcal{O}(dn \log n)\) with tighter constants) but their spherical bounds are much tighter in moderate dimensions (\(d \sim 20\text{–}100\)), reducing unnecessary expansions.

$$\text{prune ball} \iff \underbrace{\|\mathbf{q} - \mathbf{c}\|_2}_{\text{dist to ball center}} - \underbrace{r}_{\text{ball radius}} > r^*$$

Locality-Sensitive Hashing (LSH) — Approximate Sub-linear Search

LSH uses a family of random hash functions \(\mathcal{H}\) such that nearby points collide (same bucket) with high probability, and far points rarely collide. For \(\ell_2\) distance, Random Projection LSH (RPLSH) defines:

$$h_{\mathbf{r}}(\mathbf{x}) = \left\lfloor \frac{\mathbf{r} \cdot \mathbf{x} + b}{w} \right\rfloor, \quad \mathbf{r} \sim \mathcal{N}(\mathbf{0}, I),\ b \sim \text{Uniform}(0, w)$$

Using \(L\) independent hash tables, each with \(K\) concatenated hash bits, the query retrieves candidates from matching buckets and does exact distance computation only on those. Expected query time: \(\mathcal{O}(n^\rho dL)\) where \(\rho = \frac{1}{c^2} < 1\) for \((c,r)\)-approximate NN. The trade-off: recall can be less than 100% — this is approximate NN (ANN).

🔑 Key Invariant: Collision Probability

For RPLSH, \(\Pr[h(\mathbf{x}) = h(\mathbf{y})] = 1 - \frac{\|\mathbf{x}-\mathbf{y}\|}{w}\) (decreasing in distance). Near points collide often; far points rarely share a bucket. By amplifying with \(K\)-bit concatenation and \(L\) tables: true NN is returned with probability \(\geq 1-(1-p_1^K)^L\).

⚠️ The Curse of Dimensionality

KD-trees become brute-force for \(d \gtrsim 20\): the search ball intersects \(2^d\) cells, so no subtrees are pruned. Ball trees survive to \(d \sim 50\text{–}100\). LSH gives sub-linear query time even in \(d=10{,}000\) by accepting approximate answers. For modern embeddings (\(d=768\text{+}\)), use HNSW or product quantization instead.

3
The Math — Complexity & Collision Probability
▼

KD-Tree Build & Query Complexity

Building a balanced KD-tree with \(n\) points in \(\mathbb{R}^d\): at each level, finding the median costs \(\mathcal{O}(n)\) (median-of-medians). There are \(\log n\) levels, yielding build time \(\mathcal{O}(dn\log n)\). The tree has \(\mathcal{O}(n)\) nodes.

Query time: In the best case (low \(d\)), we descend \(\mathcal{O}(\log n)\) levels and prune most subtrees, giving \(\mathcal{O}(d \log n)\). However, the number of cells intersected by the search ball of radius \(r^*\) grows as \(\mathcal{O}(r^{*d})\). In high \(d\), \(r^*\) becomes comparable to the data diameter (concentration of measure), so essentially all cells are visited: \(\mathcal{O}(nd)\).

Ball Tree Pruning Guarantee

For a ball node with center \(\mathbf{c}\) and radius \(r_\text{ball}\), the minimum possible distance from any point inside the ball to \(\mathbf{q}\) is:

$$d_{\min}(\mathbf{q}, \mathcal{B}) = \max(0,\ \|\mathbf{q} - \mathbf{c}\| - r_{\text{ball}})$$

If \(d_{\min} > r^*_{\text{current}}\), the entire subtree is skipped. Because spheres are rotationally symmetric, this bound is tighter than the KD-tree's axis-aligned bounding box in all directions simultaneously, giving better pruning in moderate \(d\).

LSH Collision Probability Derivation

For random projection \(\mathbf{r} \sim \mathcal{N}(\mathbf{0},I)\) and bucket width \(w\):

$$p(t) = \Pr[h(\mathbf{x}) = h(\mathbf{y})] = \int_0^w \frac{1}{t}\,f\!\left(\frac{u}{t}\right)\left(1 - \frac{u}{w}\right)du$$

where \(t = \|\mathbf{x}-\mathbf{y}\|\) and \(f\) is the half-normal PDF. This is a decreasing function of \(t\). For the \((r_1, r_2, p_1, p_2)\)-sensitive family: for points at distance \(\leq r_1\), collision probability is \(\geq p_1\); for distance \(\geq r_2 = cr_1\), collision probability is \(\leq p_2\).

Amplification — Multiple Tables

A single hash function has weak separation. Use \(K\)-bit concatenation (AND construction) and \(L\) tables (OR construction):

$$\Pr[\text{NN found}] \geq 1 - \left(1 - p_1^K\right)^L$$

AND reduces false-positive rate (far points collide on all \(K\) bits only with prob \(p_2^K\)). OR increases recall (at least one of \(L\) tables finds the true NN). Choosing \(K = \log_{1/p_2}(n)\) and \(L = n^\rho\) where \(\rho = \frac{\log p_1}{\log p_2}\) gives the \(\mathcal{O}(n^\rho)\) sub-linear guarantee.

📐 Key Complexity Summary

Brute force: query \(\mathcal{O}(nd)\) · KD-tree: build \(\mathcal{O}(dn\log n)\), query \(\mathcal{O}(d\log n)\) in low-\(d\) · Ball tree: same complexity, better pruning for moderate \(d\) · LSH: build \(\mathcal{O}(nLK)\), query \(\mathcal{O}(n^\rho dL)\) with \(\rho < 1\)

\(n < 10{,}000\) or \(d \leq 10\): KD-tree (sklearn default).
\(10 < d \leq 50\), tabular data: Ball-tree.

Key Takeaways & Code Sketch
▼

Core Insight

All three structures exploit the same idea: avoid computing distances to most points. KD/Ball trees do this exactly via geometric pruning; LSH does it approximately via hashing. The right choice depends on \(d\), \(n\), and whether you can tolerate approximate results.

From-Scratch KD-tree (Python/NumPy)

import numpy as np
class KDNode:
def __init__(self, point, axis, left=None, right=None):
self.point = point # split point (median along axis)
self.axis = axis # split axis (0..d-1)
self.left = left # left subtree (< median)
self.right = right # right subtree (>= median)
def build_kd(pts, depth=0):
if len(pts) == 0: return None
axis = depth % pts.shape[1] # cycle through dimensions
pts = pts[pts[:, axis].argsort()] # sort along split axis
med = len(pts) // 2 # median index
return KDNode(
point = pts[med],
axis = axis,
left = build_kd(pts[:med], depth+1),
right = build_kd(pts[med+1:], depth+1))
def nn_search(node, query, best=[None, float('inf')]):
if node is None: return best
d = np.linalg.norm(query - node.point) # distance to split point
if d < best[1]: best = [node.point, d] # update best if closer
ax = node.axis
# descend into the half containing the query
near, far = (node.left, node.right) if query[ax] < node.point[ax] else (node.right, node.left)
best = nn_search(near, query, best)
# only search far subtree if split-plane distance < current best
if abs(query[ax] - node.point[ax]) < best[1]:
best = nn_search(far, query, best)
return best

Production: sklearn & FAISS

# sklearn — exact KNN with auto tree selection
from sklearn.neighbors import NearestNeighbors
nn = NearestNeighbors(n_neighbors=5, algorithm='auto') # picks kd_tree/ball_tree/brute
nn.fit(X_train)
dists, idxs = nn.kneighbors(X_query)
# FAISS — approximate NN at billion scale
import faiss
d = X_train.shape[1] # embedding dimension
index = faiss.IndexHNSWFlat(d, 32) # HNSW graph, M=32
index.add(X_train.astype('float32'))
D, I = index.search(X_query.astype('float32'), k=5)
