1
Understanding the Concept

SVMs need an optimizer to find the maximum-margin hyperplane. Two open-source libraries dominate practice: libSVM (Chih-Chung Chang & Chih-Jen Lin, 2001–2011) and LIBLINEAR (Fan et al., 2008). They share a goal but diverge sharply on algorithm and applicable problem class.

Key Distinction
libSVM implements SMO (Sequential Minimal Optimization) and supports any Mercer kernel — enabling non-linear decision boundaries at the cost of \(O(n^2)\)–\(O(n^3)\) training. LIBLINEAR uses coordinate descent / dual CD and supports only linear kernels, achieving near-linear \(O(n)\) time and scaling to millions of samples.
Analogy
Think of libSVM as a bespoke tailor who can craft any silhouette (kernel boundary) but must measure every pair of customers against each other — quadratic effort. LIBLINEAR is a factory line: it only makes straight-cut suits but finishes a million in the time libSVM does a thousand.

One-liner: Use libSVM when you need kernels or have \(n < 100\text{k}\); switch to LIBLINEAR when \(n > 100\text{k}\) and a linear boundary suffices.

2
How They Work Internally

libSVM — Sequential Minimal Optimization (SMO)

The SVM dual is a Quadratic Program (QP) over \(n\) dual variables \(\alpha_i\). Full QP solvers are \(O(n^3)\). Platt's SMO (1998) decomposes it into the smallest non-trivial subproblem: optimize exactly two \(\alpha_i, \alpha_j\) at a time while holding others fixed. The two-variable sub-QP has a closed-form solution.

$$\alpha_j^{\text{new,clipped}} = \alpha_j^{\text{old}} + \frac{y_j(E_i - E_j)}{\eta}, \qquad \eta = K_{ii} + K_{jj} - 2K_{ij}$$

where \(E_i = f(x_i) - y_i\) is the prediction error and \(K_{ij} = k(x_i, x_j)\) is the kernel matrix element. libSVM adds a working-set selection heuristic (maximal violating pair) and caching of kernel columns (default 200 MB) to reduce re-computation. Complexity: O(n² · d) per pass; overall \(O(n^2)\)–\(O(n^3)\).

LIBLINEAR — Coordinate Descent on the Dual (or Primal)

For linear kernels \(k(x_i, x_j) = x_i^\top x_j\), the weight vector \(w \in \mathbb{R}^d\) can be maintained explicitly. LIBLINEAR cycles through dual variables one at a time and updates \(w\) cheaply without materializing the kernel matrix.

$$\Delta\alpha_i = \frac{y_i - w^\top x_i}{\|x_i\|^2 + \frac{1}{2C}}, \qquad w \leftarrow w + \Delta\alpha_i\, y_i\, x_i$$

Each coordinate step costs \(O(d)\) (sparse data: \(O(\text{nnz}_i)\)). One full pass over \(n\) samples is \(O(n \cdot d)\). The number of passes to \(\epsilon\)-accuracy is essentially constant (empirically 10–50 passes regardless of \(n\)). Overall: O(n · d) — linear in the dataset size.

Why LIBLINEAR Cannot Use Kernels
Kernelized coordinate descent requires storing or recomputing \(K_{ij} = k(x_i, x_j)\) every update, making each step \(O(n)\) instead of \(O(d)\). The advantage evaporates. For non-linear boundaries you must use libSVM (or kernel approximations like RFF + LIBLINEAR).
3
The Mathematics

Shared Primal Problem (soft-margin SVM)

$$\min_{w, b, \xi} \;\frac{1}{2}\|w\|^2 + C\sum_{i=1}^n \xi_i \quad \text{s.t.}\quad y_i(w^\top\phi(x_i)+b) \ge 1 - \xi_i,\; \xi_i \ge 0$$

Dual (both solvers work here)

$$\max_\alpha \sum_i \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_i y_j K_{ij} \quad \text{s.t.}\quad 0 \le \alpha_i \le C,\; \sum_i \alpha_i y_i = 0$$

libSVM — Two-Variable Sub-QP (analytic solution)

Fix all \(\alpha\) except \((\alpha_i, \alpha_j)\). The constraint \(\alpha_i y_i + \alpha_j y_j = \text{const}\) reduces to a 1-D clipped update:

$$\alpha_j^* = \alpha_j + \frac{y_j(E_i - E_j)}{\eta}, \quad \text{clipped to } [L, H]$$

where \(L, H\) depend on \(y_i = y_j\) or \(y_i \ne y_j\) (box constraints), and \(\eta = K_{ii}+K_{jj}-2K_{ij} \ge 0\) by PSD of kernel (Mercer). If \(\eta = 0\), the objective is non-positive definite and libSVM takes the boundary giving maximum objective gain.

LIBLINEAR — Dual Coordinate Descent Step (L2-SVM)

$$U = \frac{y_i - w^\top x_i}{\|x_i\|^2 + \frac{1}{2C}}, \quad \Delta\alpha_i = \min\!\left(\max\!\left(U,\, -\alpha_i\right),\, C - \alpha_i\right)$$

The clipping ensures \(0 \le \alpha_i \le C\). After update, \(w \leftarrow w + \Delta\alpha_i y_i x_i\) in \(O(d)\). Convergence is linear-rate (R-linear) guaranteed for strongly convex objectives (L2 regularization).

Complexity Summary

libSVM: \(O(n^2)\) memory for kernel cache (or \(O(n \cdot \text{cache})\)), \(O(n^2)\)–\(O(n^3)\) time.
LIBLINEAR: \(O(n \cdot d)\) time, \(O(d)\) memory (no kernel matrix). Scales to \(n = 10^6, d = 10^6\).

6
Key Takeaways
  • libSVM / SVC implements SMO — optimal for kernelized SVMs, quadratic scaling limits it to tens of thousands of samples.
  • LIBLINEAR / LinearSVC implements dual coordinate descent — linear-time, linear-only, millions of samples no problem.
  • The \(\eta = K_{ii}+K_{jj}-2K_{ij}\) denominator in SMO is always \(\ge 0\) by Mercer's theorem (PSD kernels), ensuring a valid update.
  • For \(n \gg 100\text{k}\) with non-linear needs: approximate kernels (Nyström, RFF) + LIBLINEAR is often better than libSVM.
  • Both libraries are column-sparse-aware; LIBLINEAR explicitly exploits sparse features (NLP bag-of-words).
Common Mistake
Calling SVC(kernel='linear') on 1 M samples — this uses libSVM's SMO which is \(O(n^2)\). Use LinearSVC (LIBLINEAR) instead; it will be 100×–1000× faster for the same linear model.
