Multi-class SVM

Extending binary SVMs to K classes via One-vs-Rest (OvR) and One-vs-One (OvO)
Intermediate Classical ML · SVM O(K·n) training
1
Understanding the Concept
▾

SVMs are inherently binary: the classic formulation finds a single hyperplane that separates two classes. Real problems (digit recognition, sentiment with many labels, medical diagnosis) require distinguishing K ≥ 3 classes. Two strategies adapt SVMs to this: One-vs-Rest (OvR) and One-vs-One (OvO).

💡 Core Insight

OvR trains K binary classifiers: class \(k\) against all others combined. Prediction picks whichever classifier fires most confidently (argmax of raw scores).
OvO trains \(\tfrac{K(K-1)}{2}\) binary classifiers: one per pair of classes. Prediction uses a majority vote — the class that wins the most head-to-head duels wins overall.

Everyday Analogy

Imagine a talent show with 5 contestants. OvR = ask 5 judges, each thinking "is contestant A the winner vs everyone else?" The contestant with the most confident yes wins. OvO = run a round-robin tournament: every pair of contestants competes head-to-head, and whoever wins the most matchups advances. OvR is faster (fewer judges); OvO is fairer (smaller, balanced contests).

Key Concept

Both strategies reduce a K-class problem to multiple binary SVMs. OvR: K classifiers, each trained on all \(n\) samples (imbalanced labels).   OvO: \(\tfrac{K(K-1)}{2}\) classifiers, each trained on only 2 classes' samples (smaller, balanced).

How It Works Internally
▾

One-vs-Rest (OvR / One-vs-All, OvA)

For K classes, train K binary SVMs. For classifier \(k\), label all samples of class \(k\) as \(+1\) and every other sample as \(-1\). The decision function is \(f_k(\mathbf{x}) = \mathbf{w}_k^\top \mathbf{x} + b_k\).

Training: Solve K independent SVM optimisation problems, each on the full dataset of \(n\) samples.

Prediction: Run all K classifiers. Assign the test point to the class whose classifier returns the highest score (argmax of raw signed distances to the hyperplane):

$$\hat{y} = \underset{k \in \{1,\dots,K\}}{\operatorname{argmax}}\; f_k(\mathbf{x})$$
⚠️ OvR Imbalance Problem

If \(K=10\) with balanced classes, each classifier's training set is ~10% positive and ~90% negative. This class imbalance can bias the learned hyperplane. Class-weight regularisation (sklearn's class_weight='balanced') mitigates this.

One-vs-One (OvO)

Train one binary SVM for every pair \((i, j)\), \(i < j\). Each classifier uses only samples from those two classes (balanced by definition). For K classes there are \(\tfrac{K(K-1)}{2}\) classifiers.

Training: Solve \(\tfrac{K(K-1)}{2}\) SVM problems, each on \(\approx \tfrac{2n}{K}\) samples.

Prediction (majority vote): Each of the \(\tfrac{K(K-1)}{2}\) classifiers casts one vote for the class it predicts. The class with the most votes wins:

$$\hat{y} = \underset{k}{\operatorname{argmax}}\sum_{j \ne k} \mathbf{1}\bigl[h_{kj}(\mathbf{x}) = k\bigr]$$

where \(h_{kj}\) is the binary classifier trained on classes \(k\) and \(j\).

Numerical Trace (K = 3, test point \(\mathbf{x} = [1.8,\; 2.5]^\top\))

OvR scores (raw decision values \(\mathbf{w}_k^\top\mathbf{x} + b_k\)):

$$f_1 = 2.70, \quad f_2 = -1.49, \quad f_3 = -3.89 \;\Rightarrow\; \hat{y} = 1 \; (\text{argmax})$$

OvO votes (\(\tfrac{3\cdot2}{2}=3\) classifiers):

$$d_{12} = 2.95 > 0 \;\to\; \text{vote class 1}, \quad d_{13} = 4.30 > 0 \;\to\; \text{vote class 1}, \quad d_{23} = -0.60 < 0 \;\to\; \text{vote class 3}$$
$$\text{Tally: class 1 = 2 votes, class 3 = 1 vote} \;\Rightarrow\; \hat{y} = 1$$

Ambiguous Regions

OvR ambiguity: Multiple classifiers can output \(f_k > 0\) simultaneously, or all output \(f_k < 0\) (no class is confident). The argmax resolution is a heuristic, not a calibrated probability.

OvO ties: Two or more classes can receive equal vote counts. Tie-breaking is implementation-defined (often lexicographic or by total decision-function sum). LibSVM uses a more sophisticated vote-weighting scheme.

3
The Math Behind It
▾

Binary SVM Recap

A binary SVM with data \(\{(\mathbf{x}_i, y_i)\}_{i=1}^n\), \(y_i \in \{-1,+1\}\), solves:

$$\min_{\mathbf{w},b,\boldsymbol{\xi}} \frac{1}{2}\|\mathbf{w}\|^2 + C\sum_{i=1}^n \xi_i \quad\text{s.t.}\quad y_i(\mathbf{w}^\top\mathbf{x}_i + b) \ge 1-\xi_i,\;\; \xi_i \ge 0$$

The dual form introduces support vectors \(\alpha_i \ge 0\) and allows the kernel trick: \(f(\mathbf{x}) = \sum_i \alpha_i y_i K(\mathbf{x}_i,\mathbf{x}) + b\).

OvR Formalisation (K classifiers)

For each class \(k = 1,\dots,K\), define relabelled targets \(\tilde{y}_i^{(k)} = +1\) if \(y_i = k\), else \(-1\). Solve:

$$\min_{\mathbf{w}_k,b_k,\boldsymbol{\xi}^{(k)}} \frac{1}{2}\|\mathbf{w}_k\|^2 + C\sum_{i=1}^n \xi_i^{(k)} \quad\text{s.t.}\quad \tilde{y}_i^{(k)}\!\left(\mathbf{w}_k^\top\mathbf{x}_i + b_k\right) \ge 1-\xi_i^{(k)},\;\;\xi_i^{(k)}\ge 0$$

Prediction: \(\hat{y} = \operatorname{argmax}_k \;(\mathbf{w}_k^\top\mathbf{x} + b_k)\).

OvO Formalisation (\(\tfrac{K(K-1)}{2}\) classifiers)

For each ordered pair \((j,k)\), \(j < k\), define the restricted dataset \(\mathcal{D}_{jk} = \{(\mathbf{x}_i,y_i) : y_i \in \{j,k\}\}\). Solve the standard binary SVM on \(\mathcal{D}_{jk}\) with relabelled targets \(+1\) for class \(j\), \(-1\) for class \(k\). Get classifier \(h_{jk}\).

Prediction by majority vote:

$$\text{votes}[k] = \sum_{j \ne k} \mathbf{1}\!\left[h_{jk}(\mathbf{x}) = k\right], \qquad \hat{y} = \operatorname{argmax}_k\;\text{votes}[k]$$

📐 Weston–Watkins Multiclass SVM (Alternative)

A native multiclass SVM solves a single joint optimisation. The Weston–Watkins formulation penalises all incorrect classes simultaneously: \(\min_{\mathbf{W}} \frac{1}{2}\|\mathbf{W}\|_F^2 + C\sum_i\sum_{k \ne y_i}\max(0,\,1 - f_{y_i}(\mathbf{x}_i) + f_k(\mathbf{x}_i))\). This is theoretically tighter but computationally heavier; OvR/OvO remain dominant in practice.

🎯 Decision Guide

Use OvR when: K is large (K ≥ 10) and training data is abundant; tune class_weight='balanced' to combat imbalance.
Use OvO when: K is small-to-moderate and class balance is critical; LibSVM defaults to OvO.
Use logistic regression / softmax: When you need calibrated probabilities and training speed is paramount.

Advantages of OvR

• Simple to implement and parallelisable (K independent problems).
• Fewer total SVMs; each trained on the full dataset (good for generalisation).
• Decision scores are directly comparable across classes (argmax is well-defined).

Disadvantages of OvR

• Severe class imbalance (1 positive class vs K−1 negatives) can bias the classifier.
• Overlapping positive scores from multiple classifiers create genuinely ambiguous regions with no principled resolution.
• Calibrated probabilities require an extra Platt scaling step.

Advantages of OvO

• Each sub-problem is balanced and simpler (only 2 classes).
• LibSVM's default — benefits from faster convergence per classifier.
• Majority voting is robust to individual classifier errors.

Disadvantages of OvO

• \(O(K^2)\) classifiers: for K=100 that's 4 950 SVMs.
• Vote ties require secondary heuristics.
• Pairwise classifiers may not generalise well when trained on small subsets for large K.

Key Takeaways & Code Trace
▾
✅ Key Takeaways

1. SVMs are binary; OvR and OvO are the two canonical decomposition strategies.
2. OvR: K classifiers, argmax of scores → fast training, prone to imbalance.
3. OvO: K(K−1)/2 classifiers, majority vote → balanced, expensive for large K.
4. sklearn's SVC defaults to OvO internally (LibSVM backend); it exposes OvR scores via decision_function_shape='ovr'.
5. Neither strategy directly extends the SVM margin guarantee to K classes — only native multiclass SVMs do.

sklearn — Production Code

from sklearn.svm import SVC
from sklearn.datasets import make_classification
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
X, y = make_classification(n_samples=500, n_classes=4,
n_informative=4, n_redundant=0, random_state=42)
# OvR — K=4 binary SVMs, argmax of scores
ovr_clf = Pipeline([
('scaler', StandardScaler()), # SVM is not scale-invariant!
('svm', SVC(kernel='rbf', C=1.0,
decision_function_shape='ovr', # shape: (n_samples, K)
class_weight='balanced')) # mitigate OvR imbalance
])
ovr_clf.fit(X, y)
# OvO — K(K-1)/2=6 binary SVMs, majority vote (LibSVM default)
ovo_clf = Pipeline([
('scaler', StandardScaler()),
('svm', SVC(kernel='rbf', C=1.0,
decision_function_shape='ovo')) # shape: (n_samples, K*(K-1)/2)
])
ovo_clf.fit(X, y)
# ⚠️ Always scale! SVM loss is sensitive to feature magnitudes.
# ⚠️ For probability estimates use probability=True + Platt scaling (slow).

From-Scratch OvR Predict (NumPy)

import numpy as np
def ovr_predict(W, b, X):
"""OvR prediction. W: (K, d), b: (K,), X: (n, d)"""
scores = X @ W.T + b # (n, K) — decision values per classifier
return np.argmax(scores, axis=1) # class index with highest score
def ovo_predict(classifiers, K, X):
"""OvO majority vote. classifiers: list of (w,b,c_pos,c_neg) tuples."""
n = X.shape[0]
votes = np.zeros((n, K), dtype=int)
for w, b, c_pos, c_neg in classifiers:
d = X @ w + b # (n,) signed distance
predicted = np.where(d > 0, c_pos, c_neg)
for i, cls in enumerate(predicted):
votes[i, cls] += 1
return np.argmax(votes, axis=1) # majority-vote winner
