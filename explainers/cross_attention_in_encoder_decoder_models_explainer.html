Cross-Attention in Encoder–Decoder Models

How the decoder learns to look back at the source — Queries from the decoder, Keys & Values from the encoder

Understanding Cross-Attention
▼

What is it? When a human translator writes the English sentence "The black cat sleeps peacefully," they don't just remember the French source once and forget it — for every single word they write, they glance back at the source sentence to check which part of it they're currently rendering. Cross-attention is exactly this mechanism inside an encoder–decoder Transformer: at every decoding step, the decoder issues a Query asking "which source tokens are relevant to what I'm producing right now?", and the encoder's finished representations answer via Keys and Values.

The translator analogy: The encoder reads the whole source sentence once and produces a rich set of notes (one note per source word) — this happens a single time, up front. Then, as the decoder writes the output word by word, for each word it re-reads those notes and decides how much attention each one deserves. Writing "black" makes it focus heavily on the note for "noir"; writing "cat" makes it focus on "chat" — even though the words appear in a different order in each language.

  • Query (\(Q\)): comes from the decoder's current hidden state — "what am I trying to generate right now?"
  • Key (\(K\)): comes from the encoder's final output — "what does each source token represent?"
  • Value (\(V\)): also comes from the encoder's final output — "what content should be pulled in if this source token is relevant?"

This is the crucial structural difference from self-attention: in self-attention \(Q\), \(K\), and \(V\) all come from the same sequence. In cross-attention, \(Q\) comes from one sequence (decoder/target) while \(K\) and \(V\) come from a different sequence (encoder/source) — it is the bridge that links generation to the source.

💡 Core Intuition

Cross-attention lets a decoder of length \(N\) dynamically pull information from an encoder of length \(M\), forming an \(N \times M\) alignment matrix — a soft, learned, differentiable version of the hard word-alignment tables used in old statistical machine translation systems.

How It Works Internally
▼

The Two Halves of the Stack

An encoder–decoder Transformer (original Transformer, T5, BART, mT5, Marian, Whisper's decoder, ...) has two towers. The encoder runs self-attention over the source sequence \(X_{src} \in \mathbb{R}^{M \times d}\) through several layers and produces a final contextualized representation \(H_{enc} \in \mathbb{R}^{M \times d}\). Crucially, this happens once, regardless of how many tokens the decoder will eventually generate.

The decoder generates the target sequence autoregressively. At each layer, a decoder block does two attention operations in sequence: first masked self-attention over the target tokens generated so far (causal — it cannot see the future), producing a hidden state \(h_{dec,t}\) for the current step \(t\); then cross-attention, where that hidden state becomes the Query against the encoder's cached \(K\) and \(V\).

The Projections

  • Query: \(q_t = h_{dec,t} W_Q \quad (W_Q \in \mathbb{R}^{d \times d_k})\) — recomputed at every decoder layer, every generation step.
  • Keys: \(K = H_{enc} W_K \quad (W_K \in \mathbb{R}^{d \times d_k})\) — computed once per encoder layer, then cached and reused for every single decoding step.
  • Values: \(V = H_{enc} W_V \quad (W_V \in \mathbb{R}^{d \times d_v})\) — same caching story as \(K\).

Why Cache K and V?

Because \(H_{enc}\) never changes while decoding a single example, \(K\) and \(V\) are identical at every decoder timestep. Production systems compute them exactly once after encoding and reuse them for the entire generation loop — this is one of the biggest practical efficiency wins of the encoder-decoder split, distinct from the (growing) self-attention KV-cache on the decoder side.

🔑 Cross-Attention Pipeline (per decoder step \(t\))

1. Query from decoder: \(q_t = h_{dec,t} W_Q\)
2. Keys/Values from encoder (cached): \(K = H_{enc}W_K,\ V = H_{enc}W_V\)
3. Compatibility: \(s_t = q_t K^\top\)
4. Scale & normalize: \(a_t = \operatorname{softmax}(s_t/\sqrt{d_k})\)
5. Context vector: \(c_t = a_t V\) — fused back into the decoder stream

Why It Works — The Math
▼

The Complete Formula

Cross-attention uses exactly the scaled dot-product attention formula from self-attention — only the source of each matrix differs:

$$\operatorname{CrossAttn}(H_{dec}, H_{enc}) = \operatorname{softmax}\!\left(\frac{(H_{dec}W_Q)(H_{enc}W_K)^\top}{\sqrt{d_k}}\right)(H_{enc}W_V)$$

For a single decoding step \(t\), with query \(q_t = h_{dec,t}W_Q \in \mathbb{R}^{d_k}\) and the full encoder Key/Value matrices \(K, V \in \mathbb{R}^{M \times d_k}\):

$$a_t = \operatorname{softmax}\!\left(\frac{q_t K^\top}{\sqrt{d_k}}\right) \in \mathbb{R}^{M}, \qquad c_t = a_t V \in \mathbb{R}^{d_v}$$

Shapes Tell the Story

Let \(N\) be the target (decoder) length and \(M\) the source (encoder) length. Self-attention inside the decoder produces an \(N \times N\) attention matrix (query and key both range over target positions). Cross-attention produces an \(N \times M\) matrix — rectangular, not square — because the query ranges over target positions while the key ranges over source positions. Row \(t\) of that matrix is exactly the vector \(a_t\) above: a probability distribution over the \(M\) source tokens for the token being generated at step \(t\).

Why the Same \(\sqrt{d_k}\) Scaling Applies

The variance argument from self-attention carries over unchanged, since it only depends on the dimensionality of the projected vectors, not on which sequence they came from. If \(q_i, k_i\) are independent, zero-mean, unit-variance, then \(\operatorname{Var}(q\cdot k) = \sum_{i=1}^{d_k}\operatorname{Var}(q_ik_i) = d_k\); dividing the raw score by \(\sqrt{d_k}\) restores unit variance and keeps softmax out of its saturated, low-gradient regime — regardless of whether \(K\) came from the same sequence as \(Q\) or a different one.

Gradient Flow

Gradients from the cross-attention output \(c_t\) flow two ways: back through \(W_Q\) into the decoder's self-attention stack (shaping how the decoder forms queries), and back through \(W_K, W_V\) into the encoder stack — meaning the encoder's representations are trained not just to reconstruct/understand the source, but specifically to be useful lookup targets for whatever the decoder will eventually need.

⚠️ Common Misconception

Cross-attention is not masked/causal — every decoder step is allowed to see the entire source sequence, including "future" source tokens relative to word order. Only the decoder's self-attention is causally masked, because only the target sequence is being generated autoregressively; the full source is already known.

Key Takeaways
▼

Where You'll See It

Cross-attention is the defining feature of encoder–decoder ("sequence-to-sequence") Transformers: the original Vaswani et al. Transformer for machine translation, T5/mT5, BART, Marian-NMT, and the encoder-decoder speech models like Whisper (audio encoder → text decoder). Multi-head cross-attention is standard — each head can learn a different kind of alignment (e.g., one head tracks nouns, another tracks verb tense agreement).

Not Every Architecture Has It

Decoder-only LLMs (GPT-family, LLaMA, Mistral) have no separate encoder and therefore no cross-attention at all — everything is self-attention over one growing sequence. Encoder-only models (BERT) never generate, so they have no decoder and no cross-attention either. Cross-attention is unique to the two-tower generation setup — and it reappears outside NLP too, e.g. as the mechanism that lets a diffusion U-Net attend over CLIP text-embedding tokens (K/V) while the image latent supplies the Query.

Computational Cost

Cross-attention costs \(O(N \cdot M \cdot d)\) — linear in target length for a fixed, already-encoded source, versus the decoder's own self-attention which costs \(O(N^2 \cdot d)\) and grows quadratically with the output it has produced so far.

💡 Summary of Dimensions

• \(H_{enc} \in \mathbb{R}^{M \times d}\) (source, computed once)  •  \(h_{dec,t} \in \mathbb{R}^{d}\) (target step \(t\))
• \(K, V \in \mathbb{R}^{M \times d_k}\) (cached, reused every step)  •  \(q_t \in \mathbb{R}^{d_k}\) (fresh each step)
• \(a_t = \operatorname{softmax}(q_t K^\top/\sqrt{d_k}) \in \mathbb{R}^{M}\)  •  \(c_t = a_t V \in \mathbb{R}^{d_v}\)
• Full attention map across generation: \(N \times M\), one row per decoder step

Code Trace

import numpy as np
# M=5 source tokens (encoder), d=4 features -- computed ONCE
H_enc = np.array([...]) # shape (5, 4), from encoder self-attention stack
# N=5 target tokens (decoder), each h_dec_t built causally, one at a time
H_dec = np.array([...]) # shape (5, 4), from decoder masked self-attention
# Projection weights
W_q = np.eye(4) # decoder-side projection
W_k = np.eye(4) # encoder-side projection (shared across all steps)
W_v = np.array([...]) # shape (4, 4)
# Encoder K, V: compute ONCE, cache, reuse for every decoding step
K = H_enc @ W_k # shape (5, 4)
V = H_enc @ W_v # shape (5, 4)
def cross_attention_step(h_dec_t, K, V, d_k):
q_t = h_dec_t @ W_q # (4,) -- fresh query this step
scores = q_t @ K.T # (5,) -- compat. with every source tok
scaled = scores / np.sqrt(d_k)
exp_s = np.exp(scaled - np.max(scaled))
weights = exp_s / exp_s.sum() # (5,) attention over SOURCE positions
context = weights @ V # (4,) weighted sum of source Values
return context, weights
# Autoregressive loop: K, V reused every step; only q_t changes
for t in range(H_dec.shape[0]):
c_t, a_t = cross_attention_step(H_dec[t], K, V, d_k=4)
fused = H_dec[t] + c_t # residual fuse, then feed to output projection
print(f"step {t}: attends most to source idx {a_t.argmax()}")
