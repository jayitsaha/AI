Understanding GBM
▼

What is it? Gradient Boosting Machines build a powerful prediction model by combining many weak models (usually shallow decision trees) one at a time. Each new tree is trained to fix the mistakes of the current ensemble. The result is an additive model that gets progressively better, like a team of specialists where each person corrects the errors of the person before them.

Analogy: Imagine you're estimating the height of a building. Your first guess is the average height of all buildings in the city. You notice you're too short for tall skyscrapers and too tall for small cottages. So you ask a second estimator to focus only on your errors. Then a third corrects what remains, and so on. Each corrector makes smaller and smaller adjustments. GBM does exactly this, but the "corrector" is a decision tree and the "errors" are the negative gradient of the loss function.

💡 If you remember one thing

GBM performs gradient descent in function space. Instead of updating model parameters, it adds a new tree \(h_t\) that points in the direction of steepest descent of the loss: $$F_t(x) = F_{t-1}(x) + \nu \cdot h_t(x)$$ where \(h_t\) is fit to the pseudo-residuals \(r_i = -\frac{\partial L(y_i, F)}{\partial F}\), and \(\nu\) is the learning rate (shrinkage).

2
Functional Gradient Descent — The Core Mechanism
▼

Why "Gradient Descent in Function Space"?

Standard gradient descent updates parameters: \(\theta \leftarrow \theta - \eta \nabla_\theta L\). GBM does something deeper — it descends in the space of functions. At each step, the negative gradient evaluated at each training point \(r_i = -\frac{\partial L(y_i, F(x_i))}{\partial F(x_i)}\) gives the direction the function needs to move to reduce loss. A tree is fit to these "pseudo-residuals", effectively approximating the gradient in function space.

For MSE Loss: Residuals ARE the Negative Gradient

With loss \(L(y,F) = \frac{1}{2}(y-F)^2\), the negative gradient is simply: \(-\frac{\partial L}{\partial F} = y - F\). So for MSE, pseudo-residuals equal actual residuals — every tree simply fits what the current ensemble got wrong. This connection breaks down for other losses (log-loss, absolute error, Huber), where the pseudo-residuals are more complex.

Shrinkage \(\nu\) — The Learning Rate

The update rule \(F_t = F_{t-1} + \nu \cdot h_t\) scales each tree's contribution by \(\nu \in (0,1]\). Small \(\nu\) prevents any single tree from dominating (regularisation), requires more trees, but generalises better. Friedman (2001) proved empirically and theoretically that shrinkage + many weak learners beats fewer strong learners without shrinkage.

Stochastic Subsampling

At each stage, GBM can sample a fraction \(\eta\) of training rows (row subsampling) and/or a fraction of features (column subsampling) before fitting the tree. This: (1) injects randomness that reduces correlation between trees; (2) speeds up training; (3) provides an out-of-bag estimate for early stopping. Friedman called this "stochastic gradient boosting" — it is the same idea as mini-batch SGD applied to boosting.

🔑 Key Property — Stagewise Additive Modelling

GBM is greedy and stagewise: once tree \(h_t\) is added, its contribution is never revised. This is different from bagging (parallel), random forests (parallel), or neural networks (all parameters updated jointly). The greedy stagewise approach enables the gradient interpretation and allows arbitrary differentiable loss functions.

3
The Math — Derivation & Regularisation
▼

The Algorithm (Friedman 2001)

Given: data \(\{(x_i, y_i)\}_{i=1}^n\), differentiable loss \(L(y, F)\), and number of trees \(T\):

$$F_0(x) = \underset{\gamma}{\operatorname{argmin}} \sum_{i=1}^n L(y_i, \gamma) \quad \text{(best constant)}$$

For \(t = 1, \ldots, T\):

$$r_{it} = -\left[\frac{\partial L(y_i, F(x_i))}{\partial F(x_i)}\right]_{F=F_{t-1}} \quad \text{(pseudo-residuals = neg. gradient)}$$
$$h_t = \underset{h \in \mathcal{H}}{\operatorname{argmin}} \sum_{i=1}^n \bigl(r_{it} - h(x_i)\bigr)^2 \quad \text{(fit tree to residuals)}$$
$$\rho_t = \underset{\rho}{\operatorname{argmin}} \sum_{i=1}^n L(y_i,\, F_{t-1}(x_i) + \rho \cdot h_t(x_i)) \quad \text{(line search for step size)}$$
$$F_t(x) = F_{t-1}(x) + \nu \cdot \rho_t \cdot h_t(x) \quad \text{(shrinkage update)}$$

Why Trees? The Connection to Functional Space

A tree partitions \(\mathcal{X}\) into \(J\) disjoint regions \(R_{jt}\). Within each region, it outputs a constant \(\gamma_{jt}\). The update becomes: $$F_t(x) = F_{t-1}(x) + \nu \sum_{j=1}^J \gamma_{jt} \cdot \mathbf{1}[x \in R_{jt}]$$ This is a piecewise-constant step in function space. Trees are chosen because they are computationally cheap to fit, naturally handle mixed variable types, and the resulting model is a piecewise-constant function composition.

Regularisation Mechanisms

GBM has three complementary regularisers:

1. Shrinkage \(\nu\): Scales the contribution of each tree. Lower \(\nu\) → more trees needed, but lower variance.

2. Subsampling \(\eta\): At each iteration, sample \(\lfloor \eta n \rfloor\) rows without replacement. The expected gradient is unbiased, but the added noise regularises.

3. Tree complexity: Limit tree depth (max leaves \(J\), max depth \(d\)). Shallow trees (stumps: \(J=2\)) are weak learners with high bias — the boosting process reduces bias while shrinkage controls variance.

⚠️ Common Misconception

GBM is NOT fitting trees to the raw errors \(y_i - \hat{y}_i\) in general. It fits the negative gradient of the loss. For MSE these coincide, but for other losses (e.g., log-loss, MAE, quantile), the pseudo-residuals \(r_i\) are different from the raw residuals and must be recomputed at each stage.

Bias-Variance Decomposition

Each individual tree has high bias (it is a stump fitting noisy pseudo-residuals). The ensemble reduces bias stagewise. Shrinkage and subsampling control variance. The overall MSE decomposes as: $$\mathbb{E}[(F_T(x) - f^*(x))^2] = \operatorname{Bias}^2 + \operatorname{Var} + \sigma^2$$ Increasing \(T\) (more trees) reduces Bias; decreasing \(\nu\) reduces Var at the cost of needing larger \(T\).

def gradient_boost(X, y, T=6, nu=0.4):
F = np.full(len(X), y.mean()) # F₀ = mean(y)
for t in range(T):
r = y - F # pseudo-residuals (neg. gradient MSE)
h = fit_stump(X, r) # tree fits residuals
F = F + nu * h(X) # shrinkage update
return F

Key Takeaways & When to Use GBM
▼

When to use GBM:

  • Tabular/structured data with mixed types — GBM is typically state-of-the-art here
  • You need calibrated probability estimates (with appropriate loss like log-loss)
  • Feature interactions are important but unknown a priori
  • You can afford tuning (n_estimators, max_depth, learning_rate, subsample)

When NOT to use:

  • Raw image/audio/text data — use CNNs, Transformers instead
  • Real-time serving with very low latency requirements (XGBoost is fast but still sequential trees)
  • Very small datasets — risk of overfitting even with shrinkage
  • When interpretability via linear coefficients is required — use logistic regression
💡 GBM vs Random Forest

Random Forest: parallel bagging, high variance models, averaging reduces variance. GBM: sequential boosting, low-variance models (stumps), additive stages reduce bias. GBM typically outperforms RF on tabular data; RF is faster to train and more robust to hyperparameters. Modern implementations: XGBoost, LightGBM (histogram-based, much faster), CatBoost (categorical features natively).

Key papers: Friedman (2001) "Greedy function approximation: a gradient boosting machine." · Chen & Guestrin (2016) "XGBoost" · Ke et al. (2017) "LightGBM."
