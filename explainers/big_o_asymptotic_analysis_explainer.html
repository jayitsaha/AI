1
Understanding Big-O
▼

What is it? Big-O notation is a mathematical shorthand for describing how an algorithm's resource usage (time or memory) grows as the input size \(n\) increases. It captures the dominant growth pattern — ignoring constants and slower-growing terms — so we can compare algorithms on a universal scale independent of hardware.

Analogy: Think of a road trip. You don't care that your car takes 30 seconds to start — you care that a 1000 km trip takes roughly 10× longer than a 100 km trip. That "roughly proportional to distance" observation is linear: \(O(n)\). If traffic jams mean every km you travel, you wait proportionally more, that's \(O(n^2)\). Big-O describes the shape of scaling, not the exact time.

If you remember one thing

Big-O answers: "As \(n \to \infty\), which term dominates?" Drop constants and lower-order terms — \(5n^2 + 3n + 100\) is \(O(n^2)\) because \(n^2\) overwhelms everything else for large \(n\). The three bounds: \(O\) (upper — at most this fast), \(\Omega\) (lower — at least this fast), \(\Theta\) (tight — exactly this class).

The Three Asymptotic Notations

\(O\) (Big-O, upper bound): \(f(n) = O(g(n))\) means \(f\) grows no faster than \(g\). "At worst, it takes this long." This is the most common in interviews.

\(\Omega\) (Big-Omega, lower bound): \(f(n) = \Omega(g(n))\) means \(f\) grows at least as fast as \(g\). "It cannot be faster than this." Used to prove a problem is inherently hard — e.g., any comparison sort needs \(\Omega(n \log n)\).

\(\Theta\) (Big-Theta, tight bound): \(f(n) = \Theta(g(n))\) means both \(f = O(g)\) and \(f = \Omega(g)\). The algorithm is exactly this complexity class. Merge sort is \(\Theta(n \log n)\) — it is both upper- and lower-bounded by \(n \log n\).

2
Reading Complexity from Code
▼

Pattern Recognition Shortcuts

You don't need to solve recurrences for every loop. Recognise these structural patterns:

  • Single loop over \(n\) elements → \(O(n)\) (linear scan, sum, max)
  • Nested loops over \(n\) → \(O(n^2)\) (bubble sort, naive all-pairs)
  • Halving the input each iteration → \(O(\log n)\) (binary search, balanced BST lookup)
  • Loop + halving (e.g., merge sort) → \(O(n \log n)\) — \(n\) work at each of \(\log n\) levels
  • Generating all subsets → \(O(2^n)\) (power set, subset sum brute force)
  • Fixed constant work regardless of \(n\) → \(O(1)\) (hash map lookup, array index)

Dropping Constants and Lower Terms

Consider \(T(n) = 4n^2 + 200n + 10{,}000\). As \(n \to \infty\):

$$\lim_{n\to\infty} \frac{4n^2 + 200n + 10000}{n^2} = 4$$

The ratio approaches a constant, so \(T(n) = O(n^2)\). The constant 4 and the \(200n\) term vanish asymptotically — they describe hardware speed, not algorithmic scaling. In Big-O we write just \(O(n^2)\).

Common Mistake

Saying two algorithms are "equally fast" because both are \(O(n \log n)\) is wrong in practice — constants matter enormously at real-world sizes. Big-O tells you scaling class, not wall-clock speed. An \(O(n^2)\) algorithm with a tiny constant can beat an \(O(n \log n)\) one for small \(n\) (e.g., insertion sort beats merge sort for \(n < 20\)).

Key Insight — Dominant Term

When you have \(O(n^2 + n \log n)\), keep only the dominant term: \(O(n^2)\). The hierarchy is: \(O(1) \subset O(\log n) \subset O(n) \subset O(n \log n) \subset O(n^2) \subset O(2^n) \subset O(n!)\). Each class grows infinitely faster than the previous for large \(n\).

3
Formal Definitions — The Math
▼

Big-O (Upper Bound)

We say \(f(n) = O(g(n))\) if there exist positive constants \(c\) and \(n_0\) such that:

$$f(n) \leq c \cdot g(n) \quad \text{for all } n \geq n_0$$

Example: Prove \(2n + 5 = O(n)\). Choose \(c = 3, n_0 = 5\). For all \(n \geq 5\): \(2n + 5 \leq 2n + n = 3n\). The bound holds from \(n_0 = 5\) onwards. ✓

Big-Omega (Lower Bound)

We say \(f(n) = \Omega(g(n))\) if there exist positive constants \(c\) and \(n_0\) such that:

$$f(n) \geq c \cdot g(n) \quad \text{for all } n \geq n_0$$

Example: \(n^2 / 2 - n = \Omega(n^2)\). Choose \(c = 1/4, n_0 = 4\). For \(n \geq 4\): \(n^2/2 - n \geq n^2/4\) because \(n \leq n^2/4\) when \(n \geq 4\). ✓

Big-Theta (Tight Bound)

We say \(f(n) = \Theta(g(n))\) if \(f = O(g)\) AND \(f = \Omega(g)\) — equivalently, there exist positive constants \(c_1, c_2, n_0\) such that:

$$c_1 \cdot g(n) \leq f(n) \leq c_2 \cdot g(n) \quad \text{for all } n \geq n_0$$

Example: \(\frac{n^2}{2} - 3n = \Theta(n^2)\) with \(c_1 = 1/4, c_2 = 1, n_0 = 7\). The function is sandwiched between two multiples of \(n^2\) for large enough \(n\).

Limit Definition (Equivalent)

Equivalently using limits: \(f = O(g) \iff \limsup_{n\to\infty} f(n)/g(n) < \infty\). And \(f = \Theta(g) \iff \lim_{n\to\infty} f(n)/g(n) = L\) for some \(0 < L < \infty\). This makes checking asymptotic class as easy as computing a limit.

Little-o and Little-omega (Strict Bounds)

Little-\(o\): \(f(n) = o(g(n))\) means \(f\) grows strictly slower than \(g\): \(\lim_{n\to\infty} f(n)/g(n) = 0\). For example, \(n = o(n^2)\).

Little-\(\omega\): \(f(n) = \omega(g(n))\) means \(f\) grows strictly faster than \(g\): \(\lim_{n\to\infty} g(n)/f(n) = 0\). For example, \(n^2 = \omega(n \log n)\).

Key Takeaways & Interview Tips
▼

When Each Bound Is Used

  • O (upper): What you report in interviews for time/space complexity. "This runs in \(O(n \log n)\)."
  • \(\Omega\) (lower): Proving a problem is inherently hard. "No comparison sort can beat \(\Omega(n \log n)\) in the worst case." Also used in algorithm analysis to show a bound is tight.
  • \(\Theta\) (tight): When you've proven both upper and lower match. Heap sort is \(\Theta(n \log n)\) worst-case — not just "at most \(n \log n\)" but exactly that class.

Interview Checklist

  • Always state worst-case unless asked otherwise. Average-case and amortized analysis are separate.
  • Nested loops: multiply complexity. Sequential blocks: add, then keep dominant term.
  • Recursive algorithms: set up a recurrence. \(T(n) = 2T(n/2) + O(n)\) → Master Theorem → \(\Theta(n \log n)\).
  • Space complexity counts auxiliary memory (not the input). Recursive depth counts as stack space: a recursive DFS on \(n\) nodes uses \(O(n)\) space.
The Practical Threshold

For \(n \leq 10^4\): \(O(n^2)\) may be fine. For \(n \leq 10^6\): need \(O(n \log n)\) or better. For \(n \leq 10^8\): need \(O(n)\) or \(O(\log n)\). Exponential \(O(2^n)\) is only feasible for \(n \leq 25\text{–}30\).

# O(1) — constant time: single operation, no loop
def get_first(arr): return arr[0]
# O(log n) — halve the search space each step
def binary_search(arr, target): # n=1024 → ~10 iterations
lo, hi = 0, len(arr) - 1
while lo <= hi:
mid = (lo + hi) // 2
if arr[mid] == target: return mid
elif arr[mid] < target: lo = mid + 1
else: hi = mid - 1
# O(n) — single pass
def find_max(arr): # visits every element once
return max(arr)
# O(n log n) — divide & conquer
def merge_sort(arr): # log n levels, O(n) merge each
if len(arr) <= 1: return arr
mid = len(arr) // 2
return merge(merge_sort(arr[:mid]), merge_sort(arr[mid:]))
# O(n²) — nested loops
def bubble_sort(arr): # n iterations × n comparisons
for i in range(len(arr)):
for j in range(len(arr)-i-1):
if arr[j] > arr[j+1]: arr[j], arr[j+1] = arr[j+1], arr[j]
# O(2ⁿ) — enumerate all subsets
def all_subsets(arr): # 2^n subsets total
if not arr: return [[]]
rest = all_subsets(arr[1:])
return rest + [[arr[0]] + s for s in rest]
