Convergence Rates: \(O(1/k)\) vs \(O(1/k^2)\)

Sublinear, accelerated, and linear convergence — how fast optimizers actually reach a solution
Intermediate Optimization Math Foundations Calculus & Analysis
1
Understanding Convergence Rates
▼

What is a convergence rate? When an optimizer iterates toward a minimum, the convergence rate describes how quickly the error \(f(x_k) - f^*\) shrinks with iteration count \(k\). Knowing the rate tells you exactly how many iterations you need to reach a target precision \(\varepsilon\).

Analogy: Imagine draining a bathtub. \(O(1/k)\) is like the drain getting progressively slower — at step 100 it drains 100× slower than step 1, so the last bit of water takes forever. \(O(1/k^2)\) is a better drain that loses relatively less efficiency each step, reaching empty much sooner. Linear convergence is like opening a bigger valve — the fraction of remaining water removed each second is constant, so the tub empties exponentially fast.

If you remember one thing

To reduce error by a factor of 100: \(O(1/k)\) needs 100× more iterations; \(O(1/k^2)\) needs only 10×; linear convergence needs a fixed additive constant in \(k\) regardless of the target. The gap is algorithmic — not about hardware.

Key definition

We say an algorithm has convergence rate \(r(k)\) if there exists a constant \(C > 0\) such that after \(k\) iterations, \(f(x_k) - f^* \leq C \cdot r(k)\). The three canonical rates are: \(r(k) = 1/k\) (sublinear), \(r(k) = 1/k^2\) (accelerated sublinear), and \(r(k) = \rho^k\) with \(\rho \in (0,1)\) (linear/geometric).

2
The Three Convergence Regimes
▼

Regime 1: \(O(1/k)\) — Plain Gradient Descent on Smooth Convex Problems

For a \(L\)-smooth convex function \(f\), gradient descent with step size \(\alpha = 1/L\) satisfies:

$$f(x_k) - f^* \;\leq\; \frac{L\,\|x_0 - x^*\|^2}{2k}$$

This is sublinear: to halve the error, you must double the iterations. To reach \(\varepsilon\) precision, you need \(k = O(1/\varepsilon)\) iterations. This rate is tight — GD cannot do better on the class of all smooth convex functions without additional structure.

Regime 2: \(O(1/k^2)\) — Nesterov Accelerated Gradient (NAG)

Nesterov's 1983 method adds a momentum look-ahead step. For the same smooth convex setting:

$$f(x_k) - f^* \;\leq\; \frac{2L\,\|x_0 - x^*\|^2}{(k+1)^2}$$

Now you need only \(k = O(1/\sqrt{\varepsilon})\) iterations. This is the optimal first-order rate — no algorithm that only uses gradients can do better on smooth convex problems (Nesterov's lower bound).

Regime 3: \(\rho^k\) — Linear/Geometric Convergence (Strongly Convex)

If \(f\) is also \(\mu\)-strongly convex (curvature bounded below), GD with \(\alpha = 2/(\mu + L)\) achieves:

$$f(x_k) - f^* \;\leq\; \left(\frac{\kappa - 1}{\kappa + 1}\right)^{2k} \cdot (f(x_0) - f^*)$$

where \(\kappa = L/\mu\) is the condition number. Each iteration multiplies the error by a constant \(\rho = \left(\tfrac{\kappa-1}{\kappa+1}\right)^2 < 1\). This requires only \(k = O(\kappa \log(1/\varepsilon))\) iterations — logarithmic in \(\varepsilon\).

Common confusion

"Linear convergence" does NOT mean the error decreases linearly (that would be \(O(1/k)\)). It means on a log scale the error decreases linearly — i.e., the error is an exponentially decaying geometric sequence. The name comes from \(\log(f(x_k) - f^*)\) being linear in \(k\).

3
Why the Rates Differ — The Math
▼

Why Nesterov is Faster: The Momentum Insight

Plain GD updates: \(x_{k+1} = x_k - \alpha \nabla f(x_k)\). Nesterov introduces a momentum point \(y_k\):

$$y_{k+1} = x_k - \alpha \nabla f(x_k)$$
$$x_{k+1} = y_{k+1} + \frac{k-1}{k+2}(y_{k+1} - y_k)$$

The extra term \(\frac{k-1}{k+2}(y_{k+1} - y_k)\) is a momentum step — it "overshoots" in the direction of previous progress. Intuitively, this lets the sequence accumulate information about the gradient over time, not just at the current point.

Why the Momentum Coefficient Matters

The coefficient \(\frac{k-1}{k+2}\) is carefully chosen. It is not an arbitrary hyperparameter — it is the specific sequence derived from the Lyapunov analysis. Changing it (e.g., using a constant momentum) can destroy the \(O(1/k^2)\) rate. The proof constructs an energy function \(E_k = k^2(f(x_k)-f^*) + \frac{1}{2\alpha}\|z_k - x^*\|^2\) and shows \(E_k\) is non-increasing, from which the rate follows.

Sketch: bounding O(1/k²)

Let \(E_k = k^2[f(x_k) - f^*] + \frac{1}{2\alpha}\|z_k - x^*\|^2\) where \(z_k\) is an auxiliary sequence. The Lyapunov descent inequality gives \(E_{k+1} \leq E_k\), so \(k^2[f(x_k)-f^*] \leq E_k \leq E_0 = \frac{1}{2\alpha}\|x_0-x^*\|^2\). Dividing both sides: \(f(x_k)-f^* \leq \frac{\|x_0-x^*\|^2}{2\alpha k^2} = \frac{L\|x_0-x^*\|^2}{2k^2}\).

Why Linear Convergence Requires Strong Convexity

Strong convexity with parameter \(\mu > 0\) means:

$$f(y) \geq f(x) + \nabla f(x)^\top(y-x) + \frac{\mu}{2}\|y-x\|^2 \quad \forall x, y$$

This gives the iterates a "restoring force" toward \(x^*\). Combined with \(L\)-smoothness, each GD step satisfies \(\|x_{k+1} - x^*\|^2 \leq \left(1 - \frac{\mu}{L}\right)\|x_k - x^*\|^2 = \frac{\kappa-1}{\kappa}\|x_k - x^*\|^2\). Iterating gives \(\|x_k - x^*\|^2 \leq \left(\frac{\kappa-1}{\kappa}\right)^k \|x_0 - x^*\|^2\), and the function value gap follows by \(\mu\)-strong convexity.

Critical subtlety: the constant C matters

The \(O(\cdot)\) notation hides the constant \(C\). For plain GD: \(C = L\|x_0-x^*\|^2/2\). For Nesterov: \(C = 2L\|x_0-x^*\|^2\) — so Nesterov's constant is 4× larger! This means for very small \(k\) (early iterations), GD can temporarily outperform Nesterov. The acceleration only dominates asymptotically.

5
Key Takeaways & When to Use
▼

Choose your method based on problem structure:

  • Smooth convex only (no strong convexity): Use Nesterov acceleration — it doubles the convergence exponent at zero extra cost per iteration
  • Strongly convex (know \(\mu\) and \(L\)): Use gradient descent with optimal step — you get linear convergence automatically; Nesterov's accelerated variant gives \(\rho = 1 - 1/\sqrt{\kappa}\) vs GD's \(\rho = 1 - 1/\kappa\), crucial when \(\kappa\) is large
  • Deep learning in practice: Loss surfaces are non-convex; Adam/SGD don't have clean theoretical rates, but the intuition still applies — momentum-based methods tend to escape saddle points and flat regions faster
The practical hierarchy

Linear \(\rho^k\) (strongly convex) \(\gg\) Accelerated \(O(1/k^2)\) (smooth convex + Nesterov) \(\gg\) Sublinear \(O(1/k)\) (smooth convex, plain GD). Each tier requires stronger assumptions. You can't get linear convergence on a function that isn't strongly convex — the geometry doesn't support it.

When acceleration can hurt

On non-smooth problems (e.g., \(\ell_1\) regularization), vanilla Nesterov can diverge. Use proximal variants (FISTA) instead. Also, Nesterov's constant \(C\) is 4× larger than GD's, so if you only run a handful of iterations, GD may be more practical.

6
Code Trace — GD vs Nesterov
▼

Both methods applied to \(f(x) = x^2/2\) (optimal: \(x^* = 0\), \(f^* = 0\), \(L = 1\), \(\mu = 1\)).

import numpy as np
# Objective: f(x) = x^2/2, f* = 0, L = 1 (Lipschitz constant of grad)
f = lambda x: x**2 / 2
grad = lambda x: x
L = 1.0; alpha = 1.0 / L
# ── Plain Gradient Descent: O(1/k) rate ──
x_gd = 1.0
for k in range(1, 101):
x_gd = x_gd - alpha * grad(x_gd) # = x_gd * (1 - alpha)
# f(x_gd) ≈ L*||x0||^2 / (2k) = 0.5/k → O(1/k)
# ── Nesterov Accelerated GD: O(1/k^2) rate ──
x_nes, y_nes = 1.0, 1.0
for k in range(1, 101):
y_new = x_nes - alpha * grad(x_nes) # gradient step
x_nes = y_new + (k-1)/(k+2) * (y_new - y_nes) # momentum
y_nes = y_new
# f(x_nes) ≈ 2*L*||x0||^2 / (k+1)^2 → O(1/k^2)
# ── Strongly Convex GD: linear rate ──
# mu = L = 1 here (kappa=1), so convergence is exact in 1 step.
# For a harder example, use f(x) = x1^2/2 + 50*x2^2/2 (kappa=50)
mu, L_hard = 1.0, 50.0
alpha_opt = 2.0 / (mu + L_hard) # optimal step for strongly convex
rho = (L_hard - mu) / (L_hard + mu) # contraction factor per iter
print(f"Linear rate rho = {rho:.4f} (kappa={L_hard/mu:.0f})")
# At k=100: error ≤ rho^100 * initial = {rho**100:.2e}
