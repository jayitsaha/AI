Projected Gradient Descent
Step-then-project optimization for constrained problems — the workhorse of constrained ML
Advanced Optimization Theory Non-Smooth & Constrained Part I · §5.6
1
Understanding the Concept
▾

Imagine you are hiking downhill in fog, trying to reach the lowest valley — but you are only allowed to stay inside a fenced park. Ordinary gradient descent says "take a step in the steepest downward direction." But what if that step lands you outside the fence? Projected Gradient Descent (PGD) fixes this with a simple two-move rule:

  1. Gradient step — move in the unconstrained steepest descent direction.
  2. Project — snap the new point back to the nearest legal position inside the constraint set \(\mathcal{C}\).

Formally, the update is:

$$x^{(t+1)} = \Pi_{\mathcal{C}}\!\left(x^{(t)} - \eta\,\nabla f(x^{(t)})\right)$$

where \(\Pi_{\mathcal{C}}\) denotes the orthogonal projection onto \(\mathcal{C}\) and \(\eta > 0\) is the step size (learning rate).

If you remember one thing
PGD = gradient descent + a projection step. The projection is the Euclidean nearest point in the feasible set, and it is always non-expansive (it can only decrease distances). This single property drives all convergence guarantees.

Real-World Uses

  • Adversarial attacks (PGD-attack) — Madry et al. (2018) perturb inputs within an \(\ell_\infty\)-ball to maximise loss.
  • Non-negative matrix factorisation — factor matrices must stay \(\geq 0\); project onto the non-negative orthant after each step.
  • Portfolio optimisation — weights live on the probability simplex; project after each gradient step.
  • Federated learning clipping — gradient norms clipped to an \(\ell_2\)-ball (DP-SGD).
2
How It Works — The Algorithm
▾

The PGD Algorithm (General Form)

$$x^{(t+1)} = \Pi_{\mathcal{C}}\!\left(x^{(t)} - \eta_t\,\nabla f(x^{(t)})\right), \quad t = 0,1,2,\ldots$$

Three constraint sets cover virtually all practical cases:

1. Box Constraint \(\mathcal{C} = \{x : l \leq x \leq u\}\)

The projection is coordinate-wise clipping — the cheapest possible operation:

$$\bigl[\Pi_{\text{box}}(v)\bigr]_i = \max\!\left(l_i,\, \min\!\left(u_i,\, v_i\right)\right)$$

2. \(\ell_2\)-Ball \(\mathcal{C} = \{x : \|x\|_2 \leq r\}\)

If the gradient step lands inside the ball, no projection is needed. Otherwise, rescale to the boundary:

$$\Pi_{\text{ball}}(v) = \begin{cases} v & \text{if } \|v\|_2 \leq r \\ r\,v/\|v\|_2 & \text{otherwise} \end{cases}$$

3. Probability Simplex \(\mathcal{C} = \Delta_n = \{x \geq 0 : \mathbf{1}^\top x = 1\}\)

Duchi et al.'s \(O(n \log n)\) algorithm: sort descending, find the threshold \(\rho\), then soft-threshold:

$$\theta = \frac{1}{\rho+1}\!\left(\sum_{j=1}^{\rho+1} u_j - 1\right), \quad \Pi_{\Delta}(v)_i = \max(v_i - \theta,\,0)$$

where \(u = \mathrm{sort}(v, \text{descending})\) and \(\rho = \max\!\left\{j : u_j - \frac{1}{j}\!\left(\textstyle\sum_{k\leq j}u_k - 1\right) > 0\right\}\).

Connection to Proximal Gradient

Projection is a special case of the proximal operator. For the indicator function \(\delta_{\mathcal{C}}\) (zero inside \(\mathcal{C}\), \(+\infty\) outside):

$$\operatorname{prox}_{\eta\,\delta_{\mathcal{C}}}(v) = \underset{x \in \mathcal{C}}{\operatorname{argmin}}\,\tfrac{1}{2}\|x - v\|^2 = \Pi_{\mathcal{C}}(v)$$

This means PGD is just proximal gradient descent with \(g = \delta_{\mathcal{C}}\). The full proximal gradient method handles any closed convex \(g\) — LASSO (\(g=\lambda\|x\|_1\) → soft-thresholding) or nuclear norm for matrix completion.

Common Mistake
Projecting before the gradient step is wrong. The gradient must be computed at \(x^{(t)}\) (the current feasible point), and the unconstrained step \(x^{(t)} - \eta\nabla f\) is formed first, then projected. Swapping the order destroys convergence guarantees.
3
The Mathematics — Projections & Convergence
▾

Non-Expansiveness of Projection

The projection map \(\Pi_{\mathcal{C}}\) onto any closed convex set is non-expansive (firmly non-expansive, in fact):

$$\|\Pi_{\mathcal{C}}(u) - \Pi_{\mathcal{C}}(v)\|_2 \leq \|u - v\|_2 \quad \forall\, u,v$$

Even stronger — the firm non-expansiveness inequality:

$$\|\Pi_{\mathcal{C}}(u) - \Pi_{\mathcal{C}}(v)\|^2 \leq \langle u - v,\, \Pi_{\mathcal{C}}(u) - \Pi_{\mathcal{C}}(v)\rangle$$

Convergence — Convex \(f\), Lipschitz Gradient

Assume \(f\) is convex with \(L\)-Lipschitz gradient. With fixed step size \(\eta = 1/L\), after \(T\) steps:

$$f(x^{(T)}) - f^* \leq \frac{L\,\|x^{(0)} - x^*\|^2}{2T}$$

This is the same \(O(1/T)\) rate as unconstrained gradient descent — the projection does not cost anything in the convergence rate.

Convergence — Strongly Convex \(f\)

If \(f\) is also \(\mu\)-strongly convex, PGD enjoys linear (geometric) convergence:

$$\|x^{(T)} - x^*\|^2 \leq \left(1 - \frac{\mu}{L}\right)^T \|x^{(0)} - x^*\|^2$$

The contraction factor \(\kappa^{-1} = \mu/L\) is the reciprocal condition number — identical to unconstrained gradient descent on strongly convex functions.

Key Lemma — Descent with Projection

The crux of the proof uses the variational characterisation: \(z = \Pi_{\mathcal{C}}(v)\) iff

$$\langle v - z,\, y - z\rangle \leq 0 \quad \forall y \in \mathcal{C}$$

Applying this with \(v = x - \eta\nabla f(x)\), \(z = x^+\) (next iterate), and \(y = x^*\) yields the descent lemma that bounds \(f(x^+) - f^*\).

Key Invariant
Because \(\Pi_{\mathcal{C}}\) is non-expansive, every iterate stays within distance \(\|x^{(0)} - x^*\|\) of the optimum, and the analysis reduces to bounding how much each gradient step decreases the objective — exactly as in unconstrained GD.

Code Trace — From Scratch in NumPy
▾

Every line below traces the PGD update on \(f(x)=\|x - [2,1.5]^\top\|^2\) with a box constraint \(\mathcal{C}=[-1,1]^2\). Click a line to highlight the matching canvas step above.

import numpy as np
def proj_box(x, lo=-1, hi=1):
return np.clip(x, lo, hi) # coordinate-wise clamp
def pgd(x0, target, eta=0.38, T=5):
x = x0.copy()
for t in range(T):
grad = 2 * (x - target) # ∇f(x) = 2(x - x*)
x_gd = x - eta * grad # unconstrained gradient step
x = proj_box(x_gd) # project back onto C
print(f"t={t+1}: x={x.round(3)}")
return x
# Trace (verified numerically):
# t=1: x-η∇f=[1.6, 1.2] → proj=[ 1.0, 1.0] ← hits box boundary
# t=2: x-η∇f=[1.8, 1.4] → proj=[ 1.0, 1.0] ← optimum IS corner
# t≥2: converged to constrained optimum [1.0, 1.0]
x_opt = pgd(np.array([-0.6, -0.8]), np.array([2.0, 1.5]))
Why clipping IS the box projection
For a box \([l,u]^n\), the Euclidean nearest point to \(v\) with \(v_i \in [l_i, u_i]\) is just \(\mathrm{clip}(v_i, l_i, u_i)\) — a one-liner. This is why PGD with box constraints is almost as cheap as unconstrained GD.

When to Use PGD

  • The feasible set \(\mathcal{C}\) has a cheap, closed-form projection (box, ball, simplex).
  • Adversarial robustness — PGD-attack is the standard strong attack.
  • Large-scale problems where barrier/interior-point methods are too slow.
  • Non-negative matrix factorisation, federated DP-SGD gradient clipping.

When NOT to Use PGD

  • Projection itself is expensive (e.g., general semidefinite constraints — use Frank-Wolfe or interior-point instead).
  • Highly non-convex landscapes — convergence to a stationary point but not global minimum.
  • When you need exact constraint satisfaction at every intermediate step (e.g., safety-critical control) — consider ADMM.
Connecting PGD to Proximal Gradient
PGD with constraint \(\mathcal{C}\) \(=\) Proximal GD with \(g = \delta_{\mathcal{C}}\) (indicator function). Soft-thresholding for LASSO (\(g = \lambda\|\cdot\|_1\)) is the same idea with a different proximal operator. All share the \(O(1/T)\) convergence rate for convex \(f\).
