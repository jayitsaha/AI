Underfitting vs Overfitting

Learning Curves & Validation Curves — Diagnosing Bias and Variance
Intermediate Classical ML Model Selection Must Know
1
Understanding the Concept
▾

What is this? Imagine you're studying for an exam. If you study too little, you fail because you don't know enough — that's underfitting (high bias). If you memorize every past exam question word-for-word without understanding the subject, you fail on new questions — that's overfitting (high variance). The sweet spot is a model that generalizes: it learned the real patterns, not the noise.

💡 If you remember one thing

Bias-variance tradeoff: a model too simple cannot capture the signal (high bias), a model too complex captures noise as signal (high variance). Learning curves and validation curves are X-ray machines that reveal which problem you have.

The Two Diagnostic Tools

  • Learning curve — plots train error and validation error as a function of number of training samples. Reveals whether more data helps.
  • Validation curve — plots train error and validation error as a function of a hyperparameter (e.g., model complexity). Reveals the sweet-spot complexity.
Key Concept — Bias-Variance Decomposition

For squared error loss, the expected test error decomposes as:
\(\mathbb{E}[(y - \hat{f}(x))^2] = \underbrace{\text{Bias}^2[\hat{f}(x)]}_{\text{underfitting}} + \underbrace{\text{Var}[\hat{f}(x)]}_{\text{overfitting}} + \underbrace{\sigma^2_\varepsilon}_{\text{irreducible noise}}\)

Reading the Curves at a Glance

Symptom on Learning CurveDiagnosisFix
Both train & val error high, small gapHigh Bias (Underfitting)More complex model, better features
Train error low, val error high, large gapHigh Variance (Overfitting)More data, regularization, simpler model
Both low, convergingGood fitDeploy!

How the Curves Work Internally
▾

Learning Curve Construction

Given a dataset \(\mathcal{D} = \{(x_i, y_i)\}_{i=1}^N\), hold out a fixed validation set \(\mathcal{D}_{val}\). Then for each training size \(m \in \{m_1, m_2, \ldots, N_{train}\}\):

  1. Sample \(m\) points from \(\mathcal{D}_{train}\) (or use first \(m\) after shuffle)
  2. Fit model \(\hat{f}_m\) on those \(m\) points
  3. Record \(\text{Err}_{train}(m) = \frac{1}{m}\sum_{i=1}^m \ell(y_i, \hat{f}_m(x_i))\)
  4. Record \(\text{Err}_{val}(m) = \frac{1}{|\mathcal{D}_{val}|}\sum_{(x,y)\in\mathcal{D}_{val}} \ell(y, \hat{f}_m(x))\)
  5. Repeat steps 1–4 for robustness (average over multiple random splits)
$$\text{Learning Curve}: \quad m \mapsto \bigl(\text{Err}_{train}(m),\; \text{Err}_{val}(m)\bigr)$$

Why Train Error Rises with More Data

With 1 sample a polynomial can fit perfectly (zero train error). As \(m\) grows, the model cannot memorize all points simultaneously — train error increases and converges to the Bayes error from above. Validation error starts high (few training points → poor generalization) and decreases, converging to Bayes error from below. They meet at the irreducible noise floor \(\sigma^2_\varepsilon\).

Validation Curve Construction

Fix a hyperparameter \(\lambda\) (e.g., polynomial degree \(d\), regularization strength \(\alpha\), or tree depth). For each candidate value:

$$\text{Validation Curve}: \quad \lambda \mapsto \bigl(\text{Err}_{train}(\lambda),\; \text{Err}_{val}(\lambda)\bigr)$$

The optimal \(\lambda^*\) minimizes validation error. Left of \(\lambda^*\): underfitting (both errors high). Right: overfitting (train low, val high, large gap).

⚠️ Common Mistake

Never select \(\lambda^*\) using the test set. Use k-fold cross-validation on \(\mathcal{D}_{train}\) for the validation curve, then evaluate once on the held-out test set.

The Math Behind It
▾

Bias-Variance Decomposition (Full Derivation)

Let \(y = f(x) + \varepsilon\) where \(\varepsilon \sim \mathcal{N}(0, \sigma^2)\) is irreducible noise. The model trained on dataset \(\mathcal{D}\) produces \(\hat{f}_\mathcal{D}(x)\). The expected MSE at a fixed test point \(x\):

$$\mathbb{E}_\mathcal{D}[(y - \hat{f}_\mathcal{D}(x))^2]$$

Expand by adding and subtracting \(\bar{f}(x) = \mathbb{E}_\mathcal{D}[\hat{f}_\mathcal{D}(x)]\):

$$= \mathbb{E}_\mathcal{D}\bigl[(\hat{f}_\mathcal{D}(x) - \bar{f}(x))^2\bigr] + (\bar{f}(x) - f(x))^2 + \sigma^2$$
$$= \underbrace{\operatorname{Var}[\hat{f}_\mathcal{D}(x)]}_{\text{variance}} + \underbrace{\operatorname{Bias}^2[\hat{f}_\mathcal{D}(x)]}_{\text{bias}^2} + \underbrace{\sigma^2}_{\text{noise}}$$

Cross terms vanish because \(\mathbb{E}_\mathcal{D}[\hat{f}_\mathcal{D}(x) - \bar{f}(x)] = 0\) by definition of \(\bar{f}\), and \(\varepsilon\) is independent of \(\mathcal{D}\).

Asymptotic Behaviour of Learning Curves

As \(m \to \infty\):

  • \(\operatorname{Var}[\hat{f}_m(x)] \to 0\) for any fixed-capacity model (more data reduces estimation noise)
  • \(\operatorname{Bias}^2[\hat{f}_m(x)] \to c > 0\) for a misspecified model (structural underfitting persists)

Therefore for a high-bias model, both curves plateau far above \(\sigma^2\), and adding data does not help. For a high-variance model with finite \(m\), the gap \(\text{Err}_{val}(m) - \text{Err}_{train}(m) \approx \operatorname{Var}[\hat{f}_m]\) closes as \(m\) grows.

$$\text{Gap}(m) \approx \frac{2}{m} \cdot \text{model complexity} \quad \text{(heuristic, VC-theory)}$$
Math — VC Bound on Generalisation Gap

With probability \(\geq 1-\delta\), for a hypothesis class of VC-dimension \(h\):

\(\text{Err}_{val} \leq \text{Err}_{train} + \sqrt{\frac{h(\ln(2m/h)+1) - \ln(\delta/4)}{m}}\)

The gap shrinks as \(\mathcal{O}(\sqrt{h/m})\) — more data or lower capacity reduces it.

Code — Plotting with scikit-learn
▾

Learning Curve — from scratch

import numpy as np import matplotlib.pyplot as plt from sklearn.pipeline import make_pipeline from sklearn.preprocessing import PolynomialFeatures from sklearn.linear_model import Ridge # --- Generate synthetic data: y = sin(2πx) + noise --- rng = np.random.default_rng(42) N = 200 X = rng.uniform(0, 1, N).reshape(-1, 1) y = np.sin(2 * np.pi * X.ravel()) + rng.normal(0, 0.15, N) # Hold out 20% as fixed validation set val_mask = rng.random(N) < 0.2 X_train, y_train = X[~val_mask], y[~val_mask] X_val, y_val = X[val_mask], y[val_mask] # Model: degree-9 polynomial ridge regression (high-variance) model = make_pipeline(PolynomialFeatures(9), Ridge(alpha=1e-4)) train_sizes = np.arange(10, len(X_train)+1, 5) train_errs, val_errs = [], [] for m in train_sizes: model.fit(X_train[:m], y_train[:m]) # MSE train_errs.append(np.mean((model.predict(X_train[:m]) - y_train[:m])**2)) val_errs.append(np.mean((model.predict(X_val) - y_val)**2)) plt.figure(figsize=(8, 5)) plt.plot(train_sizes, train_errs, 'r-o', ms=4, label='Train Error') plt.plot(train_sizes, val_errs, 'b-s', ms=4, label='Validation Error') plt.axhline(0.0225, color='gray', linestyle='--', label='Bayes Error ≈ σ²') plt.xlabel('Training Set Size (m)') plt.ylabel('MSE') plt.title('Learning Curve — High-Variance Model (degree-9 poly)') plt.legend(); plt.tight_layout(); plt.show()

Validation Curve — sklearn helper

from sklearn.model_selection import validation_curve degrees = np.arange(1, 16) # validation_curve handles cross-validation internally train_scores, val_scores = validation_curve( make_pipeline(PolynomialFeatures(), Ridge(alpha=1e-3)), X, y, param_name="polynomialfeatures__degree", param_range=degrees, cv=5, scoring="neg_mean_squared_error" ) # Flip sign (neg → pos MSE) train_mse = -train_scores.mean(axis=1) val_mse = -val_scores.mean(axis=1) plt.figure(figsize=(8, 5)) plt.plot(degrees, train_mse, 'r-o', label='Train MSE') plt.plot(degrees, val_mse, 'b-s', label='Val MSE (CV)') plt.axvline(degrees[val_mse.argmin()], color='green', linestyle='--', label=f'Optimal degree={degrees[val_mse.argmin()]}') plt.xlabel('Polynomial Degree (model complexity)') plt.ylabel('MSE') plt.title('Validation Curve') plt.legend(); plt.tight_layout(); plt.show() # ⚠️ Gotcha: param_range must match the *exact* parameter name in the pipeline # Use get_params() to discover it: make_pipeline(...).get_params()

Key Takeaways & Decision Guide
▾

Diagnosis Cheat-Sheet

ObservationDiagnosisRemedy
High train error + high val error + small gapHigh BiasMore features, higher-capacity model, lower regularization
Low train error + high val error + large gapHigh VarianceMore data, stronger regularization, simpler model, dropout
Val error plateau despite more dataHigh Bias (structural)Different model family entirely
Gap closes but both highHigh Bias + noisy dataBetter features & noise filtering
Decision Rule

Learning curve gap is large? → Overfitting → add data or regularize.
Both errors high, gap small? → Underfitting → increase capacity.
Validation curve: left of optimal? → Underfitting → increase \(\lambda\) (complexity).
Validation curve: right of optimal? → Overfitting → decrease \(\lambda\).
