Causal Masking / Autoregressive Mask

How self-attention is forced to only look backward in time
Intermediate Transformers NLP / LLMs O(n²) mask, O(n) per decode step
1
Understanding Causal Masking
▼

What is it? In self-attention, every token normally gets to look at every other token — including ones that come after it. Causal masking (also called an autoregressive mask, or a "look-ahead mask") forbids that: token i may only attend to tokens at positions 0…i, never to positions i+1…n-1. It is what turns bidirectional self-attention (BERT-style) into the decoder-only attention used by GPT-style language models.

Analogy: Imagine taking a fill-in-the-blank exam where you can see every word in the passage, including the answer itself, sitting right there in plain sight — that's unmasked attention, and it's cheating. Causal masking is like covering the rest of the page with a sheet of paper as you read left to right: at each word, you can only see what came before it. That's the only way "predict the next word" is actually a fair, learnable task.

💡 If you remember one thing

Causal masking sets every "future" entry of the raw attention-score matrix to \(-\infty\) before the softmax, so that after softmax those positions receive exactly zero attention weight: $$\text{score}_{ij} = \begin{cases} \dfrac{q_i \cdot k_j}{\sqrt{d_k}} & j \le i \\ -\infty & j > i \end{cases}$$

How It Works Internally
▼

The Problem Without a Mask

Self-attention computes \(Q = XW_Q\), \(K = XW_K\), \(V = XW_V\) and then the raw score matrix \(S = QK^\top / \sqrt{d_k} \in \mathbb{R}^{n\times n}\). If you softmax \(S\) row-wise and multiply by \(V\) with no restriction, token \(i\)'s output is a blend of every token in the sequence, including tokens \(i+1, i+2, \dots\) that haven't "happened" yet. During training on next-token prediction, the model would be allowed to peek at the very word it's supposed to predict — the loss would collapse to zero while learning nothing useful, and at actual generation time those future tokens don't even exist yet, so the trained behavior would be undefined.

The Fix: Mask Before Softmax, Not After

The mask is applied as an additive bias before the softmax, not as a multiplicative zeroing-out after it. Define a mask matrix \(M\) with \(M_{ij}=0\) for \(j\le i\) and \(M_{ij}=-\infty\) for \(j>i\) (implemented in practice as a large negative number like -1e9 or torch's actual \(-\infty\) via masked_fill). The masked score matrix is \(S' = S + M\), and only then does softmax run: \(A = \text{softmax}(S')\). Because \(e^{-\infty}=0\), every forbidden position gets attention weight exactly 0, and because softmax renormalizes over the row, the surviving (allowed) weights still sum to 1 — nothing is "wasted" probability mass.

Design Decision: Why Additive Masking Before Softmax?

You could imagine zeroing out attention weights after softmax instead. That fails: softmax would have already spread nonzero probability mass onto the future positions, so zeroing them out afterward leaves the remaining weights not summing to 1 — you'd need to renormalize manually, and gradients would still flow through the forbidden dot products during backprop, letting the model exploit them indirectly. Additive \(-\infty\) masking before softmax is mathematically clean: it is equivalent to deleting those edges from the attention graph entirely, and it composes trivially with other additive biases (relative position bias, ALiBi, padding masks) via simple matrix addition.

Why It Works — The Math
▼

Full Masked Attention Formula

For queries \(Q\), keys \(K\), values \(V \in \mathbb{R}^{n\times d}\), and mask \(M \in \{0,-\infty\}^{n\times n}\):

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V$$

Row \(i\) of the output is \(o_i = \sum_{j=1}^{n} A_{ij}v_j\), and because \(A_{ij}=0\) for \(j>i\), this is really \(o_i = \sum_{j=1}^{i} A_{ij}v_j\) — a weighted average over only the past. Gradients respect this too: \(\partial \mathcal{L}/\partial (q_i\cdot k_j)\) is exactly zero for \(j>i\) because \(A_{ij}\) (and hence its dependence on that dot product) is identically zero — masking blocks both the forward information flow and the corresponding backward gradient path.

Softmax With -∞ Entries

For a row with allowed set \(\mathcal{A}=\{j: j\le i\}\) and forbidden set \(j > i\):

$$A_{ij} = \frac{e^{S_{ij}+M_{ij}}}{\sum_{k=1}^n e^{S_{ik}+M_{ik}}} = \begin{cases}\dfrac{e^{S_{ij}}}{\sum_{k\in\mathcal{A}} e^{S_{ik}}} & j \in \mathcal{A} \\[6pt] 0 & j \notin \mathcal{A}\end{cases}$$

because \(e^{S_{ij}+(-\infty)} = e^{-\infty} = 0\). This is exactly softmax computed over the restricted set \(\mathcal{A}\) — masking is mathematically identical to running softmax on a shorter, position-dependent vector, just implemented efficiently as one dense \(n\times n\) operation.

Numerical Trace (token "sat", position \(i=2\), in "The cat sat on the mat")

Suppose raw scores for row \(i=2\) are \(S_{2,:} = [1.1,\,0.4,\,0.9,\,1.6,\,0.8,\,-0.3]\). After adding \(M_{2,:} = [0,0,0,-\infty,-\infty,-\infty]\): \(S'_{2,:} = [1.1,0.4,0.9,-\infty,-\infty,-\infty]\). Exponentiating and normalizing over just the first 3 entries gives, e.g., \(A_{2,:} \approx [0.45,\,0.22,\,0.33,\,0,\,0,\,0]\) — weight is redistributed entirely among "The", "cat", "sat" and the model never sees the score 1.6 that "on" would have received, even though it was numerically the largest.

⚠️ Common Pitfall

Using a literal float('-inf') in float16/bfloat16 training can produce NaN gradients if an entire row becomes all \(-\infty\) (e.g. from combining with a padding mask). Frameworks typically use a large finite negative number (like -1e9 or the dtype's min value) instead of true \(-\infty\), and always leave the diagonal (\(j=i\)) unmasked so every row has at least one valid entry to soften into.

Key Takeaways
▼

When causal masking is used:

  • Decoder-only LLMs (GPT-family, LLaMA, Mistral, Claude's underlying architecture class) — always, every layer
  • The decoder self-attention block of encoder-decoder models (original Transformer, T5) — masked self-attention, but cross-attention to the encoder stays unmasked
  • Any model trained with a next-token / autoregressive objective

When it is NOT used:

  • Encoder self-attention (BERT, ViT, encoder half of T5) — every token should see the full context, so attention is fully bidirectional
  • Cross-attention from decoder to encoder outputs — the encoder sequence is fully known, no ordering constraint applies
  • Non-causal tasks like masked language modeling (which uses a different mask: random token masking, not positional)
💡 Inference-time payoff: KV-caching

Because token \(i\) never attends forward, its key/value vectors never change once computed. During generation you compute \(K,V\) for each new token once, cache them, and each new step only needs one new row of the score matrix — turning a naive \(O(n^2)\) per-step recomputation into \(O(n)\) work per generated token (still \(O(n^2)\) total across a full generation, but incrementally, not redundantly).

Code Trace
▼
import torch, math
import torch.nn.functional as F
def causal_self_attention(x, Wq, Wk, Wv):
n, d = x.shape
Q, K, V = x @ Wq, x @ Wk, x @ Wv # (n, d_k) each
scores = Q @ K.T / math.sqrt(K.shape[-1]) # (n, n) raw scores
# Build the causal mask once: True = allowed (j <= i)
allowed = torch.tril(torch.ones(n, n, dtype=torch.bool))
scores = scores.masked_fill(~allowed, float('-inf'))
attn = F.softmax(scores, dim=-1) # rows re-normalize over allowed only
out = attn @ V # (n, d_v) — weighted, causal output
return out, attn
# ⚠️ Gotcha: if a padding mask is combined with the causal mask and an
# entire row ends up all -inf, softmax produces NaN. Guard by always
# leaving the diagonal (self) position unmasked.
# Inference-time incremental decoding reuses cached K, V:
def decode_step(x_new, kv_cache, Wq, Wk, Wv):
q_new = x_new @ Wq # (1, d_k) — only ONE new query
k_new, v_new = x_new @ Wk, x_new @ Wv
kv_cache.K = torch.cat([kv_cache.K, k_new]) # append, never recompute past
kv_cache.V = torch.cat([kv_cache.V, v_new])
scores = q_new @ kv_cache.K.T / math.sqrt(k_new.shape[-1]) # (1, n) — no mask needed!
attn = F.softmax(scores, dim=-1) # all n cached keys are already "past"
return attn @ kv_cache.V
