1
Understanding Anchor-free Detection
▼

What is it? Object detection models like R-CNN, Faster R-CNN, YOLO, and SSD rely on "anchor boxes" — a predefined set of bounding box proposals with various scales and aspect ratios. Anchor-free detectors, like FCOS (Fully Convolutional One-Stage Object Detector) and CenterPoint, ditch this concept. Instead of guessing where objects might be, they directly predict object properties (like bounding box coordinates) from specific locations on a feature map, often a pixel or a keypoint.

Analogy: Imagine you're trying to find misplaced keys. An "anchor-based" approach is like having a list of 100 common places keys might be (on the desk, under the couch, by the door, etc.), then checking each spot and adjusting your search if you find something close. An "anchor-free" approach is like directly scanning the room, identifying "key-like" features, and then from those features, pinpointing the exact location and size of the keys. It's more direct, often simpler, and avoids the hassle of tuning those 100 predefined spots.

💡 If you remember one thing

Anchor-free detectors simplify object detection by eliminating the need for predefined anchor boxes. They directly predict bounding box parameters (and other attributes) from individual spatial locations (pixels in 2D, points in 3D) on a feature map, making them more flexible and easier to tune.

How FCOS Works Internally (2D Example)
▼

FCOS: Fully Convolutional One-Stage Object Detector

FCOS treats object detection as a per-pixel prediction problem, similar to semantic segmentation. For each pixel \((x,y)\) on a feature map, if it falls within a ground truth bounding box, it's considered a positive sample. The network then predicts three things for that pixel:

  1. Classification Score: A probability distribution over object classes (e.g., car, person, dog).
  2. Regression Distances: Four values representing the distances from the current pixel to the four sides of the bounding box: left (\(l\)), top (\(t\)), right (\(r\)), and bottom (\(b\)). This directly defines the bounding box \((x-l, y-t, x+r, y+b)\).
  3. Center-ness Score: A scalar value (between 0 and 1) indicating how close the current pixel is to the center of its assigned ground truth bounding box. This is crucial for suppressing low-quality bounding boxes predicted by pixels far from the object's true center.

FCOS leverages a Feature Pyramid Network (FPN) to handle objects of different scales. Each level of the FPN is responsible for detecting objects within a specific size range, avoiding the need for multi-scale anchor boxes. This "pixel-by-pixel" approach naturally handles varying object shapes and sizes without explicit anchor box design.

From 2D Pixels to 3D Points: CenterPoint

CenterPoint extends the anchor-free paradigm to 3D object detection, primarily using LiDAR point clouds. Instead of pixels, it detects 3D object centers (keypoints) in a bird's-eye view (BEV) feature map. For each detected center, it regresses attributes like 3D bounding box size, orientation, velocity, and height. The core idea is the same: directly predict object properties from a central keypoint, rather than refining predefined 3D anchor boxes.

🔑 Key Property

Anchor-free detectors frame object detection as a dense prediction task, where each spatial location (pixel or point) directly regresses bounding box parameters. The "center-ness" score is vital for filtering out ambiguous predictions and maintaining high precision, especially for 2D methods like FCOS.

3
Why It Works — The Math
▼

Loss Functions for FCOS

FCOS uses a multi-task loss function combining classification, regression, and center-ness:

$$L = L_{cls} + L_{reg} + L_{center-ness}$$

where \(L_{cls}\) is typically Focal Loss to handle class imbalance, \(L_{reg}\) is an IoU-based loss (like GIoU or DIoU Loss) for bounding box regression, and \(L_{center-ness}\) is Binary Cross-Entropy (BCE) for the center-ness score.

Regression Targets

For a pixel \((x,y)\) within a ground truth box \((x_0, y_0, x_1, y_1)\), the regression targets are simply the distances to the box boundaries:

$$l^* = x - x_0, \quad t^* = y - y_0, \quad r^* = x_1 - x, \quad b^* = y_1 - y$$

The network learns to predict these four distances, \((l, t, r, b)\). During inference, a predicted bounding box for pixel \((x,y)\) is \((x-l, y-t, x+r, y+b)\).

The Center-ness Score

The center-ness score \(C\) is a crucial component. For a pixel \((x,y)\) inside a ground truth box, its target center-ness score \(C^*\) is defined as:

$$C^* = \sqrt{\frac{\min(l^*,r^*)}{\max(l^*,r^*)} \times \frac{\min(t^*,b^*)}{\max(t^*,b^*)}}$$

This formulation ensures that \(C^*\) is 1 if the pixel is exactly at the center of the bounding box and approaches 0 as the pixel moves towards the edges. During inference, the final score for a predicted box is \(S = \sqrt{P_{cls} \times C}\), where \(P_{cls}\) is the classification probability. This combined score is then used for Non-Maximum Suppression (NMS), effectively down-weighting low-quality boxes far from the object's center.

📐 Why it works

The center-ness score directly addresses a key challenge of anchor-free methods: pixels far from an object's center can still predict a reasonable bounding box, but these predictions are often noisy. By multiplying the classification score with center-ness, these low-quality predictions are naturally suppressed during NMS, leading to higher precision without complex post-processing.

Key Takeaways
▼

When to use Anchor-free Detectors:

  • When you want to simplify the object detection pipeline by removing anchor box design heuristics.
  • For datasets with highly diverse object scales and aspect ratios, where designing effective anchor boxes is challenging.
  • For dense prediction tasks where per-pixel or per-point reasoning is natural (e.g., semantic segmentation, 3D point cloud processing).
  • When computational efficiency during inference is a priority, as they often have fewer parameters and simpler structures than multi-stage anchor-based methods.

When NOT to use / Considerations:

  • For very small objects, where a single pixel's receptive field might not contain enough information, careful FPN design is still crucial.
  • Initial anchor-free methods sometimes suffered from higher false positives due to redundant predictions from nearby pixels, which the center-ness score and NMS mitigate.
  • The performance can be sensitive to the choice of NMS threshold and the center-ness threshold, requiring careful tuning.
  • For highly occluded objects or crowded scenes, accurately identifying distinct object centers can be challenging.
💡 Paradigm Shift

Anchor-free detection represents a significant paradigm shift from "refining proposals" to "directly predicting from keypoints." This leads to more elegant, end-to-end differentiable architectures that are often more robust to varying object characteristics and easier to adapt to new domains (like 3D detection).

Code Trace (Simplified FCOS Head)
▼
import torch
import torch.nn as nn
class FCOSHead(nn.Module):
def __init__(self, in_channels, num_classes):
super().__init__()
# Shared convolutional layers for classification and regression
self.cls_convs = nn.Sequential(
*[nn.Conv2d(in_channels, in_channels, 3, padding=1, bias=True), nn.ReLU()] * 4
)
self.reg_convs = nn.Sequential(
*[nn.Conv2d(in_channels, in_channels, 3, padding=1, bias=True), nn.ReLU()] * 4
)
# Output heads
self.cls_head = nn.Conv2d(in_channels, num_classes, 3, padding=1)
self.reg_head = nn.Conv2d(in_channels, 4, 3, padding=1) # 4 for (l, t, r, b)
self.centerness_head = nn.Conv2d(in_channels, 1, 3, padding=1)
def forward(self, x):
cls_feat = self.cls_convs(x)
reg_feat = self.reg_convs(x)
cls_logits = self.cls_head(cls_feat) # (N, num_classes, H, W)
reg_preds = torch.exp(self.reg_head(reg_feat)) # (N, 4, H, W), apply exp for positive distances
centerness_logits = self.centerness_head(reg_feat) # (N, 1, H, W)
return cls_logits, reg_preds, centerness_logits
