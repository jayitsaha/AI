Understanding ndarray — The Core Data Structure
▼

A NumPy ndarray is not just a Python list of numbers. It is a view into a raw contiguous block of memory described by three pieces of metadata: shape (logical dimensions), strides (bytes to skip per axis step), and dtype (element type). Every operation — slicing, transposing, reshaping — almost never copies data; it returns a new view with adjusted metadata pointing at the same buffer.

$$\text{element}(i,\,j) = \text{buffer}\!\left[\text{offset} + i \cdot s_0 + j \cdot s_1\right]$$

where \(s_0,\,s_1\) are strides in bytes. For a 2×3 float64 array in C order: \(s_0 = 24\) bytes (3 cols × 8 bytes), \(s_1 = 8\) bytes (one float64).

Key Concept

ndarray = data buffer (raw bytes) + shape (tuple) + strides (byte offsets per axis) + dtype. Reshape, transpose and most slices cost O(1) — they adjust metadata, never copy bytes.

Numerical Trace — Creating a 2×3 float64 array

import numpy as np
a = np.array([[1,2,3],[4,5,6]], dtype=np.float64)
a.shape # (2, 3)
a.strides # (24, 8) ← 3 cols x 8 bytes/row, 8 bytes/col
a.itemsize # 8 ← bytes per element (float64)
a.nbytes # 48 ← 2 x 3 x 8 = 48 bytes total
# element [1,2] = buf[0 + 1*24 + 2*8] = buf[40] = 6.0
If You Remember One Thing

NumPy's speed comes from operating on a raw memory buffer with BLAS/LAPACK routines, bypassing Python's interpreter loop entirely. That's why a + b is 100× faster than [x+y for x,y in zip(a,b)].

Memory Layout: C Order vs Fortran Order
▼

C order (row-major, default) stores data row by row. Fortran order (column-major) stores data column by column. The difference determines which index varies fastest in the underlying buffer — the last index in C, the first in Fortran.

$$\text{C: } \text{buf}[i \cdot n_{\text{cols}} + j] \;\;\;\; \text{F: } \text{buf}[j \cdot n_{\text{rows}} + i]$$

Strides reveal layout

a = np.array([[1,2,3],[4,5,6]], dtype=np.int32) # 4-byte elements
a.strides # (12, 4) ← C: 3 cols*4 per row, 4 per col
b = np.asfortranarray(a)
b.strides # (4, 8) ← F: 4 per row-step, 2 rows*4 per col-step
c = a.T # shape (3,2) strides (4, 12) ← zero copy!
np.shares_memory(a, c) # True — same buffer, flipped strides
Performance Impact

Cache performance depends on access order. Iterating C-order row-by-row is fast (sequential). Column-wise access causes cache misses every step. LAPACK (used by np.linalg) expects Fortran order — NumPy silently copies if input layout doesn't match.

Zero-copy reshape

Reshape works without a copy when the array is contiguous and the new shape is compatible. If the array is non-contiguous (e.g., strided slice), NumPy must make a copy first.

a = np.arange(12, dtype=np.float64) # 1D, strides (8,)
b = a.reshape(3, 4) # strides (32, 8) — zero copy
np.shares_memory(a, b) # True
s = a[::2] # strides (16,) — non-contiguous
s.reshape(3, 1) # ValueError or forced copy

Broadcasting, Vectorization & Universal Functions
▼

Broadcasting is NumPy's rule for operating on arrays with different shapes without copying data. Arrays are compared dimension-by-dimension from the right; a dimension of size 1 is virtually stretched to match. No physical copy is made — NumPy uses internal zero-strides.

$$\text{shape }(3,1) + \text{shape }(1,4) \xrightarrow{\text{broadcast}} \text{result }(3,4)$$

Broadcasting rules (right-to-left)

  1. Prepend 1s to the shorter shape until ranks match.
  2. Each dimension pair must be equal, or one must be 1.
  3. Output shape = element-wise max of each pair.
x = np.array([[1],[2],[3]]) # shape (3,1)
y = np.array([[10,20,30,40]]) # shape (1,4)
z = x + y # result shape (3,4), no data copied
# [[11,21,31,41],
# [12,22,32,42],
# [13,23,33,43]]

Universal Functions (ufuncs)

A ufunc is a compiled C-level function operating element-wise on ndarrays. It dispatches natively, supports broadcasting, can write to pre-allocated output buffers, and skips Python's interpreter entirely.

a = np.arange(1, 6, dtype=np.float64) # [1., 2., 3., 4., 5.]
np.sqrt(a) # [1.0, 1.414, 1.732, 2.0, 2.236] — C SIMD loop
np.square(a) # [1., 4., 9., 16., 25.]
# Python loop equivalent (100x slower for large N):
# [x**0.5 for x in a.tolist()]
Vectorization = Loop in C, Not Python

Each Python loop iteration pays ~100 ns for type-check + reference count. NumPy skips all that. For N=10&sup6;: ufunc≈1 ms vs Python loop≈100 ms. Use np.vectorize only as a convenience wrapper — it does NOT produce a true ufunc and has similar speed to a Python loop.

Advanced Indexing & Structured Arrays
▼

NumPy has three indexing modes. Basic indexing (slices, single integers) returns views. Fancy (integer array) indexing and boolean indexing always return copies — they gather non-contiguous elements that cannot be represented by strides.

Fancy Indexing

arr = np.array([[10,20,30],[40,50,60],[70,80,90]])
idx = np.array([0, 2]) # select rows 0 and 2
arr[idx] # COPY: [[10,20,30],
# [70,80,90]]

Boolean Indexing

mask = arr > 40 # [[F,F,F],[F,T,T],[T,T,T]]
arr[mask] # [50, 60, 70, 80, 90] ← 1D, always a copy
View vs Copy Trap

Basic slices return views — modifying them mutates the original. Fancy/boolean indexing returns copies — mutations do NOT propagate. Use np.shares_memory(a, b) to check. Common bug: a[a > 0] = 0 works (in-place scatter) but tmp = a[a > 0]; tmp *= 2 has no effect on a.

Structured Arrays

A structured array stores heterogeneous fields (like a C struct) in a single ndarray. Each element has named fields of different types, enabling column-wise access with zero extra memory.

dt = np.dtype([('name','U10'),('age',np.int32),('score',np.float64)])
people = np.array([('Alice',30,9.2),('Bob',25,8.7)], dtype=dt)
people['name'] # view: ['Alice', 'Bob']
people['score'] # view: [9.2, 8.7]
people[people['score'] > 9.0]['name'] # ['Alice']

Decision Guide
  • Use ndarray for numerical pipelines, linear algebra, image data, simulations.
  • Prefer C order for row-wise iteration; F order for column-wise LAPACK calls.
  • Use broadcasting over explicit loops — 10–100× faster.
  • Know your view vs copy semantics: slices are views; fancy/boolean are copies.
  • Use structured arrays for heterogeneous tabular data at scale (avoids Pandas overhead).
