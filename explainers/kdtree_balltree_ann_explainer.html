KD-Tree & Ball-Tree for Approximate Nearest Neighbor

Spatial data structures that speed up nearest-neighbour search from \(O(n)\) brute-force to \(O(\log n)\) average
Intermediate Classical ML KNN Build O(n log n) · Query O(log n)–O(n)
1
Understanding the Concept

What is this? When a KNN classifier asks "find the 5 closest training points to this new point," the naïve answer is to measure the distance to every training point — that's \(O(n)\) work per query. For large \(n\) or real-time inference this is too slow. KD-trees and Ball-trees are pre-built index structures that let you skip the vast majority of those distance calculations at query time.

Analogy. Imagine searching for the nearest coffee shop in a city. You don't check every café — you first narrow down to your borough, then your street. KD-trees divide space with axis-aligned walls (like a city grid). Ball-trees wrap groups of points in spheres (like neighbourhoods with an irregular shape). Either way, if the nearest point found so far is closer than the entire sphere/cell, you skip it entirely — this is branch-and-bound pruning.

💡 If you remember one thing
Both structures trade \(O(n\log n)\) build time for \(O(\log n)\) expected query time by organising points so you can prune entire subtrees. KD-trees win in low \(d\); Ball-trees win in high \(d\); both degrade to \(O(n)\) in very high dimensions (the curse of dimensionality).
2
How Each Structure Works Internally

KD-Tree — Axis-Aligned Binary Space Partition

Build: At each node, choose a split axis (usually the dimension with greatest spread) and split on the median value. All points with coordinate \(x_i^{(d)} \le m\) go left; the rest go right. Repeat recursively until each leaf holds ≤ leaf_size points.

$$\text{Split axis } d^* = \arg\max_d \operatorname{Var}(\{x_i^{(d)}\}), \quad m = \operatorname{median}_i x_i^{(d^*)}$$

Query — branch-and-bound: Traverse to the leaf containing the query \(q\). Track best distance \(r^*\). On the way back up, prune sibling subtrees whose axis-aligned bounding box is farther than \(r^*\) from \(q\).

⚠ Curse of Dimensionality
In \(d\) dimensions the bounding boxes become very large relative to distances between points. The pruning condition \(\|q - \text{bbox}\| > r^*\) is almost never satisfied for \(d \gtrsim 20\), so nearly all nodes are visited — the tree degenerates to brute force. KD-trees are practical only for \(d \lesssim 10{-}15\).

Ball-Tree — Nested Hyperspheres

Build: At each node, enclose all points in the node in a minimal bounding ball \(\mathcal{B}(c, r)\) with centroid \(c\) and radius \(r\). Pick two "pivot" points (far apart), assign each remaining point to its closer pivot, and recurse. Common strategies: median-of-mass or k-d slice heuristics.

$$\mathcal{B}(c, r) = \{x \mid \|x - c\|_2 \le r\}, \quad c = \frac{1}{|S|}\sum_{x \in S} x$$

Query — sphere pruning: The key inequality: if

$$\|q - c\|_2 - r > r^*$$

then no point inside the ball can be closer than \(r^*\) to \(q\), so skip the entire subtree. This works in any dimension because sphere–point distance is a tight lower bound.

🔑 Key Invariant
Both structures maintain: if the minimum possible distance from \(q\) to any point in a subtree is ≥ current best \(r^*\), the subtree is pruned. KD-trees compute this minimum distance to an axis-aligned box; Ball-trees compute it to a bounding sphere.
3
The Math — Pruning Conditions & Complexity

KD-tree box–point distance (lower bound on distances inside a node):

$$d_{\min}(\text{box}, q) = \sqrt{\sum_{d=1}^D \left(\max(0,\, l_d - q_d,\, q_d - u_d)\right)^2}$$

where \([l_d, u_d]\) is the node's bounding interval in dimension \(d\). If \(d_{\min} \ge r^*\), skip.

Ball-tree sphere–point distance:

$$d_{\min}(\mathcal{B}(c,r), q) = \max(0,\; \|q - c\|_2 - r)$$

This is always a valid lower bound because all points lie within radius \(r\) of \(c\).

🎯 Decision Rule
Start with algorithm='auto' in sklearn (it picks KD-tree for \(d \le 20\), Ball-tree otherwise, brute force for tiny \(n\)). For \(d > 50\) consider approximate methods (FAISS, HNSW, Annoy) — exact ANN trees degrade regardless of variant.
