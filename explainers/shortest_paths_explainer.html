Understanding Shortest Paths
▼

What is it? Given a weighted graph — a collection of cities (nodes) connected by roads with distances (edge weights) — the shortest-path problem asks: "What is the minimum total weight to travel from a source node to every other node?" Two classical algorithms answer this: Dijkstra's algorithm and Bellman-Ford. They differ in what types of graphs they handle and how efficiently they do it.

Analogy. Imagine you're a GPS app routing a driver through a city map. Dijkstra is like a greedy explorer who always expands whichever nearby city is currently cheapest to reach — it works perfectly because road distances are always positive. Bellman-Ford is like a cautious accountant who methodically checks every single road \(V-1\) times — slower, but it can handle roads with "negative tolls" (negative weights) and even detect if someone has set up a money-printing loop (a negative-weight cycle).

💡 If you remember one thing

Dijkstra greedily finalizes distances using a min-heap — \(O((V+E)\log V)\), non-negative weights only. Bellman-Ford relaxes every edge \(V-1\) times — \(O(VE)\), handles negative weights and detects negative cycles. Choose Dijkstra for speed; choose Bellman-Ford for correctness on graphs with negative edges.

How They Work Internally
▼

Dijkstra's Algorithm — Greedy + Priority Queue

Dijkstra maintains a set of finalized nodes (shortest distance confirmed) and a min-priority queue of tentative distances. At each step it extracts the node with the globally minimum tentative distance, marks it as finalized, and relaxes all outgoing edges. Because all weights are non-negative, once a node is extracted its distance cannot improve — this is the key greedy invariant.

Relaxation: For edge \((u, v, w)\), if \(d[u] + w < d[v]\), update \(d[v] \leftarrow d[u] + w\) and push \((d[v], v)\) onto the heap. This propagates improvements "outward" from finalized nodes.

🔑 Greedy Invariant

When Dijkstra extracts node \(u\) from the heap with distance \(d[u]\), that distance is already optimal. Proof: any alternative path to \(u\) must pass through some node \(x\) not yet finalized, but \(d[x] \geq d[u]\) (since \(u\) was extracted first) and all subsequent edge weights are \(\geq 0\), so no shorter path exists.

Bellman-Ford — V−1 Rounds of Edge Relaxation

Bellman-Ford repeatedly iterates over all edges, relaxing each one. After \(k\) rounds, the algorithm has correctly computed shortest paths using at most \(k\) edges. Since any simple (no-repeated-node) shortest path in a graph of \(V\) nodes uses at most \(V-1\) edges, running \(V-1\) rounds guarantees correctness for all reachable nodes.

Negative cycle detection: After \(V-1\) rounds, run one more round. If any distance still improves, a negative cycle is reachable — because only infinitely looping around a negative cycle could keep improving distances.

⚠️ Why Dijkstra Fails with Negative Weights

If edge weights can be negative, a node extracted from the min-heap might later be improved via a negative edge from a node finalized after it. The greedy invariant breaks: Dijkstra may output incorrect distances. Bellman-Ford does not rely on this invariant — it checks all edges every round, so negative edges are handled correctly.

Why They Work — The Math
▼

Formal Problem Statement

Given a directed weighted graph \(G = (V, E, w)\) where \(w: E \to \mathbb{R}\) and a source \(s \in V\), compute for every \(v \in V\):

$$\delta(s, v) = \min_{\text{paths } P: s \leadsto v} \sum_{(u,u') \in P} w(u, u')$$

where the minimum is over all simple paths from \(s\) to \(v\) (or \(+\infty\) if \(v\) is unreachable).

Dijkstra Correctness (Proof Sketch)

Let \(S\) be the finalized set and \(d[v]\) be current distances. Invariant: \(\forall v \in S,\; d[v] = \delta(s,v)\). When extracting \(u = \arg\min_{v \notin S} d[v]\):

  • Any path \(s \to u\) outside \(S\) must pass through some vertex \(x \notin S\) before reaching \(u\).
  • By invariant, \(d[x] = \delta(s,x)\) if \(x\) was in \(S\), and \(d[x] \geq d[u]\) since \(u\) was the minimum.
  • Since \(w \geq 0\), the sub-path from \(x\) to \(u\) has non-negative total weight, so no path via \(x\) can improve on \(d[u]\). Hence \(d[u] = \delta(s,u)\).

Bellman-Ford Correctness — Optimal Substructure

Define \(d_k[v]\) = shortest path distance from \(s\) to \(v\) using at most \(k\) edges. Then:

$$d_k[v] = \min\!\Bigl(d_{k-1}[v],\; \min_{(u,v) \in E}\bigl(d_{k-1}[u] + w(u,v)\bigr)\Bigr)$$

Base case: \(d_0[s] = 0\), \(d_0[v] = +\infty\) for \(v \neq s\). After \(V-1\) rounds, \(d_{V-1}[v] = \delta(s,v)\) for all \(v\) (since optimal simple paths have \(\leq V-1\) edges). This recurrence is exactly what the edge-relaxation loop computes.

Complexity Analysis

$$T_{\text{Dijkstra}} = O\!\bigl((V + E)\log V\bigr) \quad \text{(binary heap)} \qquad T_{\text{Bellman-Ford}} = O(VE)$$

Dijkstra with a Fibonacci heap achieves \(O(E + V\log V)\). In dense graphs (\(E \approx V^2\)), Dijkstra still wins; Bellman-Ford's \(O(V^3)\) becomes prohibitive.

📐 The Triangle Inequality for Shortest Paths

Shortest-path distances satisfy \(\delta(s,v) \leq \delta(s,u) + w(u,v)\) for every edge \((u,v)\). This is the relaxation condition: if equality doesn't hold, we can improve our estimate of \(d[v]\). Both algorithms terminate when no more relaxations are possible.

When to use Dijkstra

  • All edge weights are non-negative (roads, latencies, costs)
  • You need the fastest shortest-path algorithm
  • SSSP (single-source) in sparse graphs: \(E \ll V^2\)

When to use Bellman-Ford

  • Graph has negative edge weights (e.g., profit/loss in financial graphs)
  • You need to detect negative cycles (arbitrage detection)
  • Distributed shortest-path (each node only knows its neighbors)
💡 The Hierarchy

BFS (unweighted) ⊂ Dijkstra (non-negative weights) ⊂ Bellman-Ford (any real weights + cycle detection) ⊂ Floyd-Warshall (all-pairs). Each generalizes the previous by relaxing assumptions on edge weights or number of sources.

import heapq
def dijkstra(graph, source): # graph: {u: [(v,w), ...]}
dist = {v: float('inf') for v in graph} # initialize all ∞
dist[source] = 0 # source = 0
heap = [(0, source)] # (distance, node)
finalized = set()
while heap:
d, u = heapq.heappop(heap) # extract minimum
if u in finalized: continue # skip stale entries
finalized.add(u) # u is now settled
for v, w in graph[u]: # relax neighbors
if dist[u] + w < dist[v]: # can we improve?
dist[v] = dist[u] + w
heapq.heappush(heap, (dist[v], v))
return dist
def bellman_ford(edges, n, source): # edges: [(u, v, w)]
dist = [float('inf')] * n
dist[source] = 0
for _ in range(n - 1): # V-1 rounds
for u, v, w in edges: # scan all edges
if dist[u] + w < dist[v]: # relax
dist[v] = dist[u] + w
# Negative cycle check
for u, v, w in edges:
if dist[u] + w < dist[v]:
raise ValueError("Negative cycle detected")
return dist
