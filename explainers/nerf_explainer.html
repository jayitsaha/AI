Novel view synthesis and 3D-aware generation from a neural representation
Foundational Computer Vision Generative AI O(N_samples) per pixel
1
Understanding NeRF
▼

What is it? NeRF (Neural Radiance Fields) is a technique that uses a small neural network to represent a 3D scene. Instead of storing explicit geometry (like meshes or point clouds) or textures, NeRF learns a continuous volumetric function that maps any 5D coordinate (3D position \((x, y, z)\) and 2D viewing direction \(( \theta, \phi)\)) to an emitted color (RGB) and a volume density \(\sigma\).

Once trained on a set of input images and their corresponding camera poses, this neural network can render photorealistic novel views of the scene from any arbitrary viewpoint. It implicitly captures complex light transport effects like reflections and transparency, leading to remarkably high-quality results.

Analogy: Imagine you want to describe a complex 3D object to someone who can only see 2D pictures. Instead of giving them a blueprint (a mesh) or a list of points (a point cloud), you give them a magical, tiny artist. This artist, when given any 3D location and a direction to look from, can instantly tell you the color and how "solid" that spot is. To see a full picture, you ask the artist about millions of points along imaginary light rays, and then you combine their answers to paint the final image. That magical artist is the NeRF neural network.

💡 If you remember one thing

NeRF represents a 3D scene as a continuous function (a neural network) that outputs color and density for any point in space. It then uses a classic volume rendering technique to synthesize images from this function, allowing for novel view generation.

2
How It Works Internally
▼

The Core Idea: A 5D Implicit Function

At its heart, a NeRF models a scene as a function \(F: (\mathbf{x}, \mathbf{d}) \to (\mathbf{c}, \sigma)\), where:

  • \(\mathbf{x} = (x, y, z)\) is a 3D point in space.
  • \(\mathbf{d} = (\theta, \phi)\) is the 2D viewing direction (azimuth and elevation).
  • \(\mathbf{c} = (R, G, B)\) is the emitted color at that point when viewed from direction \(\mathbf{d}\).
  • \(\sigma\) is the volume density at that point, representing the probability of a ray terminating at \(\mathbf{x}\).

This function \(F\) is implemented by a Multi-Layer Perceptron (MLP).

The Pipeline: From Camera Ray to Pixel Color

  1. Ray Casting: For each pixel in a target image, a ray \(\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}\) is cast from the camera origin \(\mathbf{o}\) through that pixel into the scene.
  2. Sampling Points: Along each ray, a set of 3D points \(\mathbf{x}_i\) are sampled. To capture both coarse and fine details, NeRF uses a hierarchical sampling strategy (coarse then fine).
  3. Positional Encoding: The 3D coordinates \(\mathbf{x}_i\) and viewing directions \(\mathbf{d}\) are transformed using a high-frequency positional encoding. This helps the MLP learn high-frequency details, which are crucial for photorealistic rendering.
  4. MLP Query: Each encoded point \(\gamma(\mathbf{x}_i)\) is fed into the MLP to predict its density \(\sigma_i\). This density output is then concatenated with the encoded viewing direction \(\gamma(\mathbf{d})\) and fed into the *latter* layers of the MLP to predict the view-dependent color \(\mathbf{c}_i\).
  5. Volume Rendering: The predicted colors and densities for all sampled points along a ray are combined using classical volume rendering techniques to produce a single, final color for the pixel. This process is fully differentiable.

Design Decision: Why View-Dependent Color and Density?

Density \(\sigma\) is independent of viewing direction because an object's solidity doesn't change based on how you look at it. However, color \(\mathbf{c}\) *is* view-dependent. This allows NeRF to model complex visual effects like specular reflections (shiny surfaces look different from different angles) and translucency, which are critical for photorealism and impossible with view-independent texture maps.

🔑 Key Property

NeRF's power comes from combining a continuous neural representation with differentiable volume rendering. This allows it to be trained end-to-end using standard gradient descent, optimizing the MLP weights to accurately reconstruct the input images.

3
Why It Works — The Math
▼

Positional Encoding

To enable the MLP to represent high-frequency functions (necessary for sharp details), NeRF applies a positional encoding function \(\gamma(\cdot)\) to its input coordinates. For each coordinate \(p\) (e.g., \(x, y, z, \theta, \phi\)), it maps it to a higher-dimensional vector:

$$\gamma(p) = (\sin(2^0 \pi p), \cos(2^0 \pi p), \dots, \sin(2^{L-1} \pi p), \cos(2^{L-1} \pi p))$$

where \(L\) is the number of frequency bands. This transformation makes the input to the MLP more "oscillatory," allowing it to learn rapidly changing functions that correspond to fine geometric and textural details.

Differentiable Volume Rendering

The core of NeRF's rendering process is the classical volume rendering equation, adapted for discrete samples along a ray. For a ray \(\mathbf{r}(t)\) with sampled points \(t_1, \dots, t_N\) and corresponding interval lengths \(\delta_i = t_{i+1} - t_i\), the expected color \(C(\mathbf{r})\) of a pixel is given by:

$$C(\mathbf{r}) = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i$$

where \(\mathbf{c}_i\) and \(\sigma_i\) are the color and density predicted by the MLP for point \(\mathbf{r}(t_i)\) and direction \(\mathbf{d}\). The term \(T_i\) represents the accumulated transmittance along the ray from \(t_1\) to \(t_i\), i.e., the probability that the ray travels unobstructed to point \(i\):

$$T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$$

This formulation is fully differentiable with respect to \(\sigma_i\) and \(\mathbf{c}_i\), which in turn depend on the MLP's weights. This allows gradients to flow back through the rendering process to update the neural network during training.

⚠️ Common Pitfall: Computational Cost

A naive NeRF is computationally expensive. Each pixel requires querying an MLP hundreds of times (for all sampled points along its ray). This makes training and rendering slow. Subsequent works (e.g., Mip-NeRF, Instant-NGP, Plenoxels) have introduced various optimizations like anti-aliasing, hash grids, and explicit voxel grids to drastically speed up training and inference, making NeRF more practical.

Key Takeaways
▼

When to use NeRF:

  • Novel View Synthesis: Generating photorealistic images of a static scene from viewpoints not seen during training. This is NeRF's primary strength.
  • 3D Reconstruction: Creating a dense, continuous 3D model of a scene from 2D images, useful for virtual reality, augmented reality, or digital twins.
  • Scene Editing: With extensions, NeRFs can enable semantic editing of scenes (e.g., changing object colors, removing objects) by manipulating the underlying implicit representation.
  • Robotics and Simulation: Providing realistic synthetic data for training robots or for complex simulations where real-world data is hard to acquire.

When NOT to use:

  • Real-time Applications (Vanilla NeRF): The original NeRF is too slow for interactive frame rates without significant optimizations or specialized hardware.
  • Dynamic Scenes: Vanilla NeRF assumes a static scene. Modeling moving objects or changing lighting requires advanced extensions (e.g., D-NeRF, Nerfies).
  • Sparse Training Data: NeRF requires a good number of input images (typically 50-100+) with accurate camera poses to learn a robust representation. Very sparse data can lead to artifacts.
  • Simple Geometry/Textures: For scenes with simple geometry and diffuse textures, traditional mesh-based methods might be more efficient and easier to control.
💡 The Future of 3D Representation

NeRF represents a paradigm shift from explicit 3D representations (meshes, point clouds) to implicit neural representations. This allows for unprecedented photorealism and detail, opening doors to new applications in computer graphics, vision, and beyond.

Code Trace (Conceptual PyTorch-like)
▼
import torch
import torch.nn as nn
# Positional Encoding function
def positional_encode(x, L_freq=10):
# x: (..., N_dims) e.g., (N_rays, N_samples, 3) for xyz
freq_bands = 2.**torch.arange(L_freq, device=x.device) * torch.pi
# (1, 1, L_freq) for broadcasting
expanded_x = x[..., None] * freq_bands # (..., N_dims, L_freq)
# (..., N_dims * L_freq * 2)
return torch.cat([torch.sin(expanded_x), torch.cos(expanded_x)], dim=-1)
# NeRF MLP Architecture
class NeRF(nn.Module):
def __init__(self, L_xyz=10, L_dir=4):
super().__init__()
self.L_xyz = L_xyz; self.L_dir = L_dir
input_dim_xyz = 3 + 3*2*L_xyz # (x,y,z) + sin/cos for each component
input_dim_dir = 3 + 3*2*L_dir # (dx,dy,dz) + sin/cos for each component
self.block1 = nn.Sequential(
nn.Linear(input_dim_xyz, 256), nn.ReLU(),
nn.Linear(256, 256), nn.ReLU(),
# ... 6 more layers ...
nn.Linear(256, 256), nn.ReLU()
)
self.sigma_out = nn.Linear(256, 1) # Density output
self.color_branch = nn.Sequential(
nn.Linear(256 + input_dim_dir, 128), nn.ReLU(), # Concat with view_dir
nn.Linear(128, 3), nn.Sigmoid() # RGB color output
)
def forward(self, xyz, view_dir):
xyz_encoded = positional_encode(xyz, self.L_xyz)
view_dir_encoded = positional_encode(view_dir, self.L_dir)
feature = self.block1(xyz_encoded)
sigma = self.sigma_out(feature) # Predict density
# Concat feature with view_dir for color prediction
color_input = torch.cat([feature, view_dir_encoded], dim=-1)
color = self.color_branch(color_input) # Predict color
return color, sigma
# Simplified Volume Rendering (for a single ray)
def render_ray(colors, densities, dists):
# colors: (N_samples, 3), densities: (N_samples, 1), dists: (N_samples,)
alpha = 1.0 - torch.exp(-densities * dists[..., None]) # (N_samples, 1)
# T_i = exp(-sum_{j=1}^{i-1} sigma_j * delta_j)
# Cumulative product of (1 - alpha) is transmittance
transmittance = torch.cumprod(1.0 - alpha + 1e-10, dim=0) # Add epsilon for stability
transmittance = torch.cat([torch.ones_like(transmittance[:1]), transmittance[:-1]], dim=0)
weights = alpha * transmittance # (N_samples, 1)
rendered_color = (weights * colors).sum(dim=0) # (3,)
return rendered_color
