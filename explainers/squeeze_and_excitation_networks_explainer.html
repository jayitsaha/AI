Understanding SE Blocks
▼

What is it? A Squeeze-and-Excitation (SE) block is a tiny plug-in module you drop after any convolutional layer. It looks at the whole feature map, decides which channels (feature detectors) are actually useful for the current input, and turns those channels up while turning the less useful ones down — before passing the result to the next layer. It adds almost no compute, yet SE-ResNet won ILSVRC 2017 by the largest margin in the competition's history.

Analogy: Think of a sound mixing console with dozens of tracks (channels) — drums, bass, vocals, strings — all recorded from the same performance. A fixed mixer plays every track at the same volume regardless of the song. A smart mixer first listens to the whole section (squeeze), decides "the bass and vocals matter most right here" (excitation), and nudges those faders up while quietly dimming the rest (scale) — automatically, and differently for every new song.

One-sentence summary: SE blocks let a CNN learn per-channel attention weights from global context, so it can emphasize informative feature channels and suppress noisy ones, at almost zero extra cost.

💡 If you remember one thing

SE block = squeeze (global average pool each channel → one number per channel) → excitation (2 tiny FC layers + ReLU + sigmoid → a gate value in \((0,1)\) per channel) → scale (multiply each channel's feature map by its gate). $$\tilde{u}_c = s_c \cdot u_c, \qquad s = \sigma\big(W_2\,\delta(W_1 z)\big)$$

How SE Blocks Work Internally
▼

The Problem: Convolutions Are Locally Blind to Channel Importance

A convolution kernel only looks at a small spatial neighborhood, and every output channel is produced by the same fixed weights regardless of what the image actually contains. The network has no built-in mechanism to say "for THIS input, channel 37 (a texture detector) matters a lot, but channel 12 (a color-fringe detector) is irrelevant noise." All channels are treated with equal importance by default — SE fixes exactly this.

Step 1 — Squeeze: Global Average Pooling

For a feature map \(U \in \mathbb{R}^{H\times W\times C}\), squeeze collapses each channel's \(H \times W\) spatial grid into a single scalar via global average pooling:

$$z_c = \frac{1}{H \times W}\sum_{i=1}^{H}\sum_{j=1}^{W} u_c(i,j)$$

This produces a compact channel descriptor \(z \in \mathbb{R}^C\) that summarizes "how active is this channel, on average, across the whole image" — giving the module access to the network's global receptive field, something individual conv filters never see.

Step 2 — Excitation: Two FC Layers Learn Channel Dependencies

\(z\) passes through a small bottleneck: a dimensionality-reducing FC layer \(W_1 \in \mathbb{R}^{(C/r)\times C}\), a ReLU, an expanding FC layer \(W_2 \in \mathbb{R}^{C\times(C/r)}\), and a sigmoid:

$$s = \sigma\big(W_2\,\delta(W_1 z)\big), \qquad \delta = \text{ReLU}$$

The reduction ratio \(r\) (typically 16) controls the bottleneck width \(C/r\), trading capacity for parameter/compute cost. The bottleneck forces the module to learn a compressed, nonlinear model of how channels co-depend on one another, rather than a single linear re-weighting.

Step 3 — Scale: Channel-wise Recalibration

Each gate value \(s_c \in (0,1)\) rescales its entire channel map by simple broadcast multiplication:

$$\tilde{u}_c(i,j) = s_c \cdot u_c(i,j) \quad \text{for all } (i,j)$$

Channels the network deems useful for this specific input get amplified toward their original strength (\(s_c \to 1\)); channels it deems irrelevant get squashed toward zero (\(s_c \to 0\)) — a form of self-gated, input-conditioned channel attention.

Numerical Trace (toy, \(C=4\), \(r=2\))

Say the squeezed descriptor is \(z = [0.8,\ 0.1,\ 0.6,\ 0.3]\) (channel 1 and 3 are highly active on average; channel 2 barely fires). After \(W_1\)+ReLU we might get bottleneck \(h=[0.55,\ 0.0]\), and after \(W_2\) the raw excitation is \([1.2,\ -0.3,\ 0.9,\ -1.5]\). Sigmoid turns this into gates \(s=[0.77,\ 0.43,\ 0.71,\ 0.18]\): channels 1 and 3 (already active) get boosted toward 1, while channel 4 (weakest activity) is suppressed toward 0. 🔑 Design Decision: Why Sigmoid, Not Softmax?

Softmax forces channels to compete — the gates sum to 1, so boosting one channel necessarily suppresses others. That's right for mutually-exclusive classification, but wrong here: an image can legitimately need multiple channels active simultaneously (e.g. both "fur texture" and "eye shape" detectors for a cat). Sigmoid gives each channel an independent, non-mutually-exclusive gate in \((0,1)\), which is the correct inductive bias for feature recalibration.

Why It Works — The Math
▼

Full Pipeline as One Composition

An SE block is a differentiable function \(F_{tr}\) composed of three stages applied to the output \(U\) of any transformation (a conv layer, a residual block, etc.):

$$z_c = F_{sq}(u_c) = \frac{1}{HW}\sum_{i,j} u_c(i,j) \quad\Longrightarrow\quad s = F_{ex}(z, W) = \sigma\big(W_2\,\delta(W_1 z)\big) \quad\Longrightarrow\quad \tilde{u}_c = F_{scale}(u_c, s_c) = s_c \cdot u_c$$

Every operator here — mean, matrix multiply, ReLU, sigmoid, elementwise multiply — is differentiable, so the whole block trains end-to-end with ordinary backpropagation; no auxiliary loss or special optimizer is needed.

Gradient Flow

Because \(\tilde{u}_c = s_c(z) \cdot u_c\) and \(z\) is itself a function of \(u\), the gradient with respect to \(u_c\) has two paths — direct (through the scale) and indirect (through the squeeze → excitation → gate):

$$\frac{\partial \mathcal{L}}{\partial u_c} = s_c \cdot \frac{\partial \mathcal{L}}{\partial \tilde{u}_c} \;+\; u_c \cdot \frac{\partial \mathcal{L}}{\partial s_c}\cdot\frac{\partial s_c}{\partial z_c}\cdot\frac{\partial z_c}{\partial u_c}$$

The first term is a simple rescaled gradient (like a learned per-channel learning-rate multiplier); the second term lets the loss actively push the gate itself to open or close for that channel. Sigmoid's derivative \(\sigma'(x)=\sigma(x)(1-\sigma(x))\) keeps this second path well-behaved and bounded.

Parameter & Compute Cost

Each SE block adds \(W_1\) and \(W_2\), giving parameter count:

$$\Delta\text{params} = 2 \cdot \frac{C^2}{r}$$

For SE-ResNet-50 with \(r=16\), this is roughly a 10% increase in total parameters — but because squeeze/excitation only ever operates on a length-\(C\) vector (not the full \(H\times W\times C\) tensor), the added compute is under 1% extra GFLOPs. That asymmetry — cheap in FLOPs, a bit heavier in params — is exactly why SE blocks are such a popular "free lunch" add-on.

⚠️ Common Misconception

"SE blocks are a form of spatial attention." No. \(s_c\) is a single scalar per channel, broadcast identically over every spatial location \((i,j)\). SE tells the network which channels to trust, never where in the image to look. Mixing in spatial attention (e.g. a per-pixel gate) is a different mechanism — that's what CBAM adds on top of SE-style channel attention.

Key Takeaways
▼

When to use SE blocks:

  • Drop-in add-on to almost any CNN backbone (ResNet, Inception, MobileNet, ResNeXt) — SE-ResNet-50 roughly matches ResNet-101 accuracy at ResNet-50 compute
  • Fine-grained recognition where some feature channels are far more diagnostic than others for a given input
  • Resource-constrained deployment: mobile SE variants (e.g. MobileNetV3) get a meaningful accuracy bump for <1% extra FLOPs

When NOT to use / limitations:

  • It cannot fix a fundamentally under-capacity or poorly-designed backbone — it only recalibrates existing channels, it can't invent new features
  • No spatial selectivity — if the task needs "look here, not there" reasoning, pair it with (or replace it by) a spatial/self-attention mechanism
  • Parameter overhead (~10%) matters more than FLOPs overhead on extremely parameter-constrained edge devices — ECA-Net is a lighter alternative

💡 Decision Rule

Need a near-free accuracy boost on any existing CNN → SE. Need it even cheaper in parameters → ECA-Net. Need spatial "where to look" reasoning too → CBAM or a self-attention layer. SE was the first to show that channel attention alone, done cheaply, is worth a Pareto-improving amount of accuracy.

Code Trace
▼
import torch, torch.nn as nn
class SEBlock(nn.Module):
def __init__(self, channels, r=16):
super().__init__()
self.pool = nn.AdaptiveAvgPool2d(1) # squeeze: (B,C,H,W) -> (B,C,1,1)
self.fc1 = nn.Linear(channels, channels // r, bias=False) # W1
self.relu = nn.ReLU(inplace=True) # delta
self.fc2 = nn.Linear(channels // r, channels, bias=False) # W2
self.sig = nn.Sigmoid()
def forward(self, u):
b, c, h, w = u.shape
z = self.pool(u).view(b, c) # squeeze -> (B, C)
h1 = self.relu(self.fc1(z)) # excitation FC1 + ReLU -> (B, C/r)
raw = self.fc2(h1) # excitation FC2 -> (B, C)
s = self.sig(raw).view(b, c, 1, 1) # gate in (0,1) -> (B, C, 1, 1)
return u * s # scale: channel-wise recalibration
# Drop-in usage after any conv layer / residual block:
out = conv(x)
out = SEBlock(channels=out.shape[1])(out) # recalibrate channels, then continue
