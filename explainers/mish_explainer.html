Mish

A smooth, non-monotonic, self-regularizing activation function
Intermediate Deep Learning Activation Functions O(n) elementwise
1
Understanding Mish
▼

What is it? Mish is a smooth activation function used in place of ReLU in neural networks. Instead of a hard cutoff at zero, it lets small negative values pass through as a small negative signal and only gently saturates for very negative inputs. It never has a sharp corner anywhere.

Analogy: ReLU is a bouncer who slams the door shut the instant a value dips below zero — no negotiation. Mish is more like a bouncer who eases the door closed slowly, letting a little bit of "maybe" through before finally saying no. That gentle, non-abrupt gradient turns out to help gradients flow better during training.

💡 If you remember one thing

Mish is built by composing two known functions: $$\text{Mish}(x) = x \cdot \tanh(\text{softplus}(x)) = x \cdot \tanh(\ln(1+e^x))$$ It is smooth everywhere (infinitely differentiable), unbounded above, bounded below (≈ −0.31), and slightly non-monotonic — it dips just below zero for small negative \(x\) before flattening out.

2
How Mish Works Internally
▼

Three Stages of Composition

Mish is built as a pipeline of three simple stages applied to the raw pre-activation \(x\):

1️⃣ Softplus — \(sp(x) = \ln(1+e^x)\), a smooth version of ReLU that is always positive and grows like \(x\) for large \(x\).
2️⃣ Tanh-squash — \(\tanh(sp(x))\), which compresses softplus's unbounded output into the range \((-1, 1)\). Since \(sp(x) \ge 0\) always, this stage's output actually lives in \([0, 1)\).
3️⃣ Self-gate — multiply the squashed value back by the original input \(x\). This is the same "self-gating" idea Swish uses (\(x \cdot \sigma(x)\)), except Mish's gate is \(\tanh(\text{softplus}(x))\) instead of the sigmoid \(\sigma(x)\).

Why This Shape Matters

For large positive \(x\), \(sp(x) \to x\), so \(\tanh(sp(x)) \to 1\) and \(\text{Mish}(x) \to x\) — it behaves like the identity, exactly like ReLU does for positive inputs. For large negative \(x\), \(sp(x) \to 0^+\), so \(\tanh(sp(x)) \to 0^+\) and \(\text{Mish}(x) \to 0^-\) — but it approaches zero from below, not along the axis. That's what makes it non-monotonic: right around \(x \approx -1.2\) the function dips to a minimum of about \(-0.31\) before curving back up toward 0.

Design Decision: Why tanh(softplus(x)) and not sigmoid(x)?

Swish/SiLU gates with \(\sigma(x)\), which saturates faster and more symmetrically. Mish's gate \(\tanh(\text{softplus}(x))\) preserves a small amount of negative signal further into the negative region and produces a slightly smoother, wider "bump" of negative gradient near the origin. Empirically (Misra, 2019) this small change improved accuracy on image classification/detection benchmarks over both ReLU and Swish, at the cost of roughly 2 extra transcendental function calls (softplus + tanh) per activation.

🔑 Key Property

Mish is \(C^\infty\) (infinitely differentiable) everywhere — no kinks like ReLU/Leaky ReLU. It is unbounded above (avoiding vanishing-gradient saturation for large activations, like ReLU) but bounded below at \(\approx -0.3084\) (providing implicit, "self-regularizing" bias toward small negative values instead of a hard zero).

3
Why It Works — The Math
▼

Setting Up the Derivative

Let \(sp(x) = \ln(1+e^x)\) and \(\Delta(x) = \tanh(sp(x))\), so \(\text{Mish}(x) = x\cdot\Delta(x)\). By the product rule:

$$\text{Mish}'(x) = \Delta(x) + x\cdot\Delta'(x)$$

Since \(\Delta(x)=\tanh(sp(x))\), the chain rule gives \(\Delta'(x) = \text{sech}^2(sp(x))\cdot sp'(x)\). And \(sp'(x) = \sigma(x) = \frac{1}{1+e^{-x}}\) (the sigmoid — softplus's derivative is exactly the sigmoid). Substituting:

$$\text{Mish}'(x) = \tanh(sp(x)) + x\cdot\sigma(x)\cdot\left[1-\tanh^2(sp(x))\right]$$

This is often written compactly using \(\omega(x) = 4(x+1) + 4e^{2x} + e^{3x} + e^x(4x+6)\) and \(\delta(x) = 2e^x+e^{2x}+2\), giving the numerically stable closed form \(\text{Mish}'(x) = \dfrac{e^x\,\omega(x)}{\delta(x)^2}\) — this is the version used in fast CUDA kernels.

Non-Monotonicity from the Derivative

Because \(\text{Mish}'(x)\) is negative for \(x\) in roughly \((-2.5, 0)\) before turning positive again, the function is provably non-monotonic there — it decreases then increases, producing the dip visible in the plot. This "preserves small negative gradients" instead of hard-zeroing them the way ReLU's derivative (0 or 1) does.

⚠️ Common Misconception

"Non-monotonic activations can't work because they're not convex/order-preserving." In practice, non-monotonicity near zero is exactly what helps: it acts like a small learned "dead-zone recovery" — units that would be permanently zeroed by ReLU can still receive a (small, non-zero) gradient signal and recover during training.

Key Takeaways
▼

When to use Mish:

  • Deep CNN backbones for detection/classification where a small accuracy gain is worth extra compute — it's the default activation in YOLOv4's CSPDarknet53 backbone
  • Training regimes where dying ReLU units are a concern — Mish's small negative gradient helps units recover
  • Research/benchmark settings where you can afford ~10–20% slower activations for a modest quality bump

When NOT to use:

  • Extreme latency-sensitive inference (mobile/edge) — ReLU/Hard-Swish are far cheaper and usually close enough
  • Very large-scale LLM/Transformer pretraining — GELU and SwiGLU dominate that space, not Mish
  • When you lack a fused/optimized kernel — naive softplus+tanh can overflow for large \(|x|\) without care
💡 Hierarchy

ReLU (hard, monotonic) → Swish/SiLU (\(x\sigma(x)\), smooth, self-gated) → Mish (\(x\tanh(sp(x))\), smoother, slightly better empirically, more compute) → GELU (\(x\Phi(x)\), the Transformer-era default, similar smoothness profile to Mish/Swish).

Code Trace
▼
import numpy as np
def softplus(x):
# numerically stable: ln(1+e^x)
return np.logaddexp(0.0, x)
def mish(x):
return x * np.tanh(softplus(x))
def mish_grad(x):
sp = softplus(x)
delta = np.tanh(sp) # tanh(softplus(x))
sig = 1.0 / (1.0 + np.exp(-x)) # sigmoid(x) = softplus'(x)
return delta + x * sig * (1 - delta**2)
# --- Production usage: PyTorch ---
import torch, torch.nn as nn
act = nn.Mish() # built-in since torch >= 1.9
y = act(torch.randn(4, 64)) # drop-in replacement for nn.ReLU()
# Gotcha: naive exp(x) in softplus overflows for x > ~709 in fp64
# -- always use logaddexp / F.softplus, never ln(1+exp(x)) directly
