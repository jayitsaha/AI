1
Understanding Distance Metrics
▼

What is it? A distance metric is a function that takes two points and returns a non-negative number representing how "far apart" they are. In machine learning, the choice of metric determines which examples are considered "similar" — and therefore which class a new point belongs to in K-Nearest Neighbours (KNN), which cluster a point joins, and how outliers are detected.

Analogy: Imagine you're in Manhattan and want to know how far you are from a coffee shop. You could measure the straight-line (Euclidean) distance — but that's useless if you can't fly through buildings. The actual travel distance follows city blocks (Manhattan distance). On a chessboard, the king can move diagonally, so "distance" is the max of horizontal and vertical steps (Chebyshev). Each notion of "distance" is adapted to the geometry of the space.

The critical insight: Different metrics define different "unit balls" — the set of all points exactly distance 1 from the origin. An L1 ball is a diamond, an L2 ball is a circle, an L∞ ball is a square. The shape of the unit ball tells you everything about which direction the metric "rewards" proximity in, and this directly changes which neighbour is "nearest."

If you remember one thing

The nearest neighbour of a query point can change when you switch from one metric to another. There is no universally "correct" metric — it is a modelling assumption about the geometry of your data. Euclidean treats all directions equally; Manhattan penalises diagonal shortcuts; cosine ignores magnitude; Mahalanobis accounts for feature covariance.

2
The Five Metrics — Definitions & Geometry
▼

L1 — Manhattan Distance

$$d_{L_1}(\mathbf{x}, \mathbf{y}) = \sum_{i=1}^d |x_i - y_i|$$

Travel distance along axis-aligned paths. Named for Manhattan's street grid. Unit ball = diamond (axis-aligned square rotated 45°). Robust to outliers in individual features. Favoured in high-dimensional spaces (less curse of dimensionality than L2).

L2 — Euclidean Distance

$$d_{L_2}(\mathbf{x}, \mathbf{y}) = \sqrt{\sum_{i=1}^d (x_i - y_i)^2}$$

Straight-line distance. Unit ball = circle (sphere in higher dimensions). The most common choice. Sensitive to large differences in any single coordinate. Assumes all features are on the same scale.

Lp — Minkowski Distance (generalization)

$$d_{L_p}(\mathbf{x}, \mathbf{y}) = \left(\sum_{i=1}^d |x_i - y_i|^p\right)^{1/p}, \quad p \geq 1$$

A family parameterized by \(p\). L1 and L2 are special cases (\(p=1\) and \(p=2\)). As \(p \to \infty\): \(d_{L_\infty}(\mathbf{x},\mathbf{y}) = \max_i |x_i - y_i|\) — the Chebyshev distance, with unit ball a square. The unit ball transitions smoothly: diamond (\(p=1\)) → circle (\(p=2\)) → square (\(p\to\infty\)).

Cosine Similarity & Cosine Distance

$$\text{cos\_sim}(\mathbf{x}, \mathbf{y}) = \frac{\mathbf{x} \cdot \mathbf{y}}{\|\mathbf{x}\| \|\mathbf{y}\|}, \qquad d_{\cos}(\mathbf{x}, \mathbf{y}) = 1 - \text{cos\_sim}(\mathbf{x}, \mathbf{y})$$

Measures the angle between two vectors, ignoring their magnitude. Scale-invariant: \(\text{cos\_sim}(\mathbf{x}, 100\mathbf{x}) = 1\). Used heavily in NLP (document similarity, word embeddings) and recommendation systems. Note: cosine distance is not a proper metric in the mathematical sense (violates triangle inequality).

Mahalanobis Distance

$$d_M(\mathbf{x}, \mathbf{y}) = \sqrt{(\mathbf{x}-\mathbf{y})^\top \Sigma^{-1} (\mathbf{x}-\mathbf{y})}$$

Accounts for the covariance structure \(\Sigma\) of the data. Equivalent to Euclidean distance in the whitened (decorrelated, unit-variance) space \(\Sigma^{-1/2}\mathbf{x}\). Unit ball = an axis-aligned ellipse aligned with the eigenvectors of \(\Sigma\). When \(\Sigma = I\), reduces to L2. Essential when features have different scales or are correlated.

Key Property — Metric Axioms

A proper metric must satisfy: (1) non-negativity \(d(x,y)\geq 0\), (2) identity \(d(x,y)=0 \Leftrightarrow x=y\), (3) symmetry \(d(x,y)=d(y,x)\), (4) triangle inequality \(d(x,z)\leq d(x,y)+d(y,z)\). All five above satisfy (1)–(3); cosine distance only approximately satisfies (4). Violation can cause issues in metric-learning algorithms.

3
Why the Choice of Metric Matters
▼

The Unit Ball Determines "Shape of Space"

The unit ball \(B_p = \{\mathbf{x} : \|\mathbf{x}\|_p \leq 1\}\) is the key geometric object. It tells you: how large can a vector be in various directions while remaining within distance 1 of the origin? Under L1, the ball extends only to (\(\pm 1, 0\)) and \((0, \pm 1\)) — diagonal points like \((0.5, 0.5)\) also have norm 1. Under L∞, the ball extends to the full square \([-1,1]^2\).

Query at origin. Two candidates: A = (1.5, 1.5) and B = (2.5, 0.1).

L2 rewards the diagonal shortcut that L1 does not (L1 must "pay" for both coordinates separately). L∞ only cares about the largest component. Cosine ignores the fact that B is far away — it only cares that B points almost exactly along the x-axis. Mahalanobis, knowing data is correlated along x≈y, treats A as naturally "inside" the data cloud.

Warning — Curse of Dimensionality

In high dimensions (d ≫ 10), all pairwise L2 distances concentrate: the ratio of the max to min distance tends to 1. This makes KNN poorly discriminating under L2. L1 is often preferred in high-d because it grows more slowly with d, and distances remain more distinguishable. Cosine similarity is especially effective in sparse, high-dimensional text spaces.

Key Takeaways & When to Use Each Metric
▼

Choose by data geometry:

  • L2 (Euclidean) — Default. Works when features are on the same scale, no strong correlations, and magnitude matters. Always normalise features first.
  • L1 (Manhattan) — High-dimensional data, robust to outliers, when only a subset of features are relevant per query. Good for text/image features.
  • Lp / L∞ — L∞ (Chebyshev) for board games, manufacturing tolerances (pass if ALL dimensions are within spec). Fractional \(p\) for sparse feature spaces.
  • Cosine similarity — NLP / IR: document similarity, word embeddings, TF-IDF vectors. When magnitude is irrelevant (long vs. short document about the same topic).
  • Mahalanobis — Anomaly detection, when features have different variances and correlations. Equivalent to whitening + Euclidean. Requires estimating \(\Sigma\) — needs enough data.
Decision Rule

Start with L2 + feature standardisation. If features are sparse/high-d: try L1. If direction matters more than magnitude: cosine. If features are correlated with different scales: Mahalanobis. In practice, cross-validate the metric choice alongside \(k\) in KNN — it can dominate the performance.

Related Concepts

Distance metrics are the core of: KNN classification/regression, K-means clustering, DBSCAN, nearest-centroid classifier, metric learning (LMNN, triplet loss), anomaly detection (Mahalanobis-based), and approximate nearest neighbour search (FAISS, HNSW).

import numpy as np
from scipy.spatial.distance import cdist
# Two candidate points vs. query at origin
query = np.array([[0.0, 0.0]])
A = np.array([[1.5, 1.5]]) # diagonal
B = np.array([[2.5, 0.1]]) # near x-axis
# L1 (Manhattan) — sum of absolute differences
l1_A = np.sum(np.abs(A - query)) # = |1.5| + |1.5| = 3.000
l1_B = np.sum(np.abs(B - query)) # = |2.5| + |0.1| = 2.600 ← NEAREST
# L2 (Euclidean) — sqrt of sum of squares
l2_A = np.linalg.norm(A - query) # = sqrt(1.5²+1.5²) = 2.121 ← NEAREST
l2_B = np.linalg.norm(B - query) # = sqrt(2.5²+0.1²) = 2.502
# L_inf (Chebyshev) — maximum component
linf_A = np.max(np.abs(A - query)) # = max(1.5, 1.5) = 1.500 ← NEAREST
linf_B = np.max(np.abs(B - query)) # = max(2.5, 0.1) = 2.500
# Cosine similarity — angle between vectors
cos_A = np.dot(A.flatten(), [1,0]) / np.linalg.norm(A) # angle to x-axis
cos_B = np.dot(B.flatten(), [1,0]) / np.linalg.norm(B) # closer to x-axis
# Mahalanobis — accounts for covariance
Sigma = np.array([[4.0, 2.0],[2.0, 2.0]])
VI = np.linalg.inv(Sigma) # precision matrix
d_mahal = lambda x: np.sqrt(x @ VI @ x)
mA = d_mahal(A.flatten()) # 1.061 ← NEAREST
mB = d_mahal(B.flatten()) # 1.699
