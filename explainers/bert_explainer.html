Understanding BERT
▼

What is it? BERT is a language model that reads a sentence in both directions at once — left-to-right and right-to-left simultaneously — instead of predicting the next word from only the words before it (like GPT). To learn this, it is trained on a fill-in-the-blank game: hide 15% of the words in a sentence and force the model to guess them using all the surrounding words, on both sides.

Analogy: Imagine doing a crossword puzzle versus writing a story word-by-word. Writing a story, you only know what you've already written (unidirectional, like GPT). Solving a crossword clue, you can see the letters that come both before and after the blank — full context. BERT is trained like a crossword solver: "The cat sat on the ___ mat" — it uses "sat on the" (left) AND "mat" (right, after the blank) to guess "soft" or "warm."

💡 If you remember one thing

BERT is an encoder-only Transformer pretrained with two auxiliary tasks — Masked Language Modeling (predict randomly hidden tokens using bidirectional context) and Next Sentence Prediction (does sentence B follow sentence A?) — then fine-tuned on downstream tasks by swapping the output head while keeping the pretrained encoder.

How BERT Works Internally
▼

Input Representation

Every input starts with [CLS] (a summary token used for classification) and sentences are separated by [SEP]. Each token's input vector is the sum of three embeddings: (1) the token embedding (what word it is), (2) the segment embedding (sentence A or sentence B), and (3) the position embedding (where it sits in the sequence). This lets a single stack of Transformer encoder layers see identity, membership, and order all at once.

Masked Language Modeling (MLM) — the 80/10/10 rule

15% of tokens are randomly selected for prediction. Of those: 80% are replaced with [MASK], 10% are replaced with a random word, and 10% are left unchanged. Why not always use [MASK]? Because [MASK] never appears at fine-tuning time — if the model only ever saw [MASK] during pretraining, it would learn a representation that's useless once [MASK] disappears. Mixing in random/unchanged tokens forces the model to build a genuinely contextual representation for every token, not just the masked ones.

Bidirectional Self-Attention

Every encoder layer lets every token attend to every other token — no causal mask, unlike GPT. For the masked position, this means the query vector for [MASK] computes attention scores against keys from words before and after it (and even across the [SEP] boundary into sentence B). The attention-weighted sum of value vectors becomes the new, context-aware representation of that position. Stacking 12 (BERT-base) or 24 (BERT-large) of these layers lets information mix across the whole sequence repeatedly, building progressively richer contextual features.

Next Sentence Prediction (NSP)

50% of training pairs are true consecutive sentences (A, B); 50% pair A with a random sentence from elsewhere in the corpus. The final hidden state of [CLS] is fed to a binary classifier: IsNext or NotNext. The idea is to give the model a sense of discourse-level, cross-sentence coherence — useful for tasks like question answering and natural language inference. (Later work, e.g. RoBERTa, found NSP contributes little and drops it in favor of just packing more contiguous text.)

Design Decision: Why not just use GPT's left-to-right objective?

A left-to-right LM literally cannot see future tokens without cheating (each word would trivially "see itself" through the layers). MLM sidesteps this by hiding tokens rather than restricting attention direction, so the encoder is free to use full bidirectional context — richer representations for understanding tasks (classification, NER, QA) at the cost of not being naturally suited to free-form generation.

🔑 Key Property

BERT is pretrained once, fine-tuned many times. The 12/24-layer bidirectional encoder is reused as-is; only a small task-specific head (a linear layer, usually) is added and the whole network is fine-tuned end-to-end on labeled data — this transfer-learning pattern is what made BERT the default starting point for NLP tasks from 2018 onward.

Why It Works — The Math
▼

Input Embedding

For token \(i\) with word \(w_i\), segment \(s_i \in \{0,1\}\), and position \(i\):

$$x_i = E_{\text{tok}}(w_i) + E_{\text{seg}}(s_i) + E_{\text{pos}}(i)$$

Scaled Dot-Product Self-Attention

Each layer projects the sequence \(X \in \mathbb{R}^{n \times d}\) into queries, keys, and values:

$$Q = XW^Q,\quad K = XW^K,\quad V = XW^V$$

Attention weights are a softmax over scaled dot products — every position \(j\) is visible to every query \(i\), which is exactly what makes this bidirectional:

$$\text{Attention}(Q,K,V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Contrast with GPT's causal self-attention, which adds a mask \(M\) where \(M_{ij} = -\infty\) for \(j > i\) before the softmax — forcing position \(i\) to ignore all future tokens. BERT uses no such mask (aside from padding), so \(\sqrt{d_k}\) scaling and softmax normalization are applied over the full row.

Masked LM Loss

Let \(\mathcal{M}\) be the set of masked positions. The final hidden state \(h_i\) at each masked position is projected to vocabulary logits and a cross-entropy loss is computed only over \(\mathcal{M}\):

$$\mathcal{L}_{\text{MLM}} = -\sum_{i \in \mathcal{M}} \log P(w_i \mid h_i) = -\sum_{i \in \mathcal{M}} \log \frac{\exp(h_i \cdot e_{w_i})}{\sum_{v \in V} \exp(h_i \cdot e_v)}$$

Next Sentence Prediction Loss

Using the pooled \([CLS]\) representation \(h_{\text{CLS}}\) and a learned weight vector \(W_{\text{NSP}}\):

$$\mathcal{L}_{\text{NSP}} = -\log P(y \mid h_{\text{CLS}}) = -\log \operatorname{softmax}(W_{\text{NSP}} h_{\text{CLS}})_y,\quad y \in \{\text{IsNext}, \text{NotNext}\}$$

Total Pretraining Objective

$$\mathcal{L} = \mathcal{L}_{\text{MLM}} + \mathcal{L}_{\text{NSP}}$$

Both terms are summed and backpropagated jointly through the shared encoder — every parameter in the 12/24 Transformer layers receives gradient signal from both objectives simultaneously.

⚠️ Common Misconception

"BERT predicts the masked word using only its neighbors' raw embeddings." Not quite — by the time the masked position reaches the prediction head, its representation \(h_i\) has passed through every layer, mixing information from the entire sequence multiple times via self-attention. It's not a local n-gram lookup; it's a deeply contextualized, iteratively refined vector.

Key Takeaways
▼

Natural strengthFree-form generationUnderstanding / classification / extraction
Typical fine-tune useChat, completionClassification, NER, QA (span extraction)

When to use BERT-style encoders:

  • Sentence/document classification (sentiment, topic, intent)
  • Token-level tagging — named entity recognition, POS tagging
  • Extractive question answering (predict answer span start/end)
  • Sentence-pair tasks — natural language inference, semantic similarity

When NOT to use it:

  • Open-ended text generation — BERT has no autoregressive decoding mechanism
  • Very long documents beyond its max position embeddings (512 tokens for original BERT) without chunking
  • Low-latency edge deployment without distillation (DistilBERT, TinyBERT, MobileBERT exist for this)
💡 Legacy

BERT (Devlin et al., 2018) established the "pretrain on unlabeled text, fine-tune on labeled task" paradigm for NLP. Its descendants — RoBERTa (drops NSP, trains longer), ALBERT (parameter sharing), DeBERTa (disentangled attention), and DistilBERT (distillation) — all keep the bidirectional MLM core while refining training details.

Code Trace — Fine-Tuning BERT
▼
from transformers import BertTokenizer, BertForSequenceClassification
# Load a pretrained (MLM + NSP) encoder, add a classification head
tokenizer = BertTokenizer.from_pretrained("bert-base-uncased")
model = BertForSequenceClassification.from_pretrained(
"bert-base-uncased", num_labels=2) # new head, random init
# [CLS] the movie was great [SEP]
inputs = tokenizer("the movie was great", return_tensors="pt")
labels = torch.tensor([1]) # 1 = positive
# Forward pass: encoder (pretrained) -> pooled [CLS] -> head (new)
outputs = model(**inputs, labels=labels)
loss = outputs.loss
logits = outputs.logits # shape (1, 2)
# Backprop updates BOTH the encoder and the new head
loss.backward()
optimizer.step() # small LR (e.g. 2e-5) — don't destroy pretraining
