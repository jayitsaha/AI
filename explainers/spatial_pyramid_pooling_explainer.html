Spatial Pyramid Pooling (SPPNet)

Fixed-length feature vectors from any input size — the precursor to RoI Pooling
Intermediate CNN / Computer Vision He et al. 2015
1
Understanding SPP
▼

What is it? Classic CNNs (AlexNet, VGG) require every input image to be forced to one fixed size — usually by cropping or warping — because the fully-connected (FC) layers at the end need a fixed number of inputs. Spatial Pyramid Pooling (SPP) removes this constraint. It lets the convolutional layers run on an image of ANY size, then pools the resulting feature map at several fixed grid resolutions (e.g. 4×4, 2×2, 1×1) so the pooled output always has the same length — no matter how big the input feature map was.

Analogy: Imagine grading how salty a pot of soup is. You take one big spoonful from the whole pot (1 reading), then one spoonful from each of 4 quadrants (4 readings), then one spoonful from each of 16 small sections (16 readings). No matter how large or small the pot is, you always walk away with exactly 1+4+16 = 21 taste readings. SPP does exactly this to a convolutional feature map — it "tastes" it at 3 resolutions and always returns the same number of numbers.

💡 If you remember one thing

The number of pooling bins is fixed by design (e.g. 16+4+1 = 21 per channel); only the size of each bin adapts to the input. Bin boundaries are computed as \(\lfloor i \cdot s/n \rfloor\) to \(\lceil (i{+}1)\cdot s/n \rceil\), which always yields exactly \(n\) bins regardless of the feature-map size \(s\).

How SPP Works Internally
▼

Architecture / Data Flow

Input image (any \(H \times W\)) → stack of conv + pooling layers, fully convolutional, shared weights regardless of input size → feature map of shape \((C, H', W')\), where \(H', W'\) scale with the input's size → SPP layer with pyramid levels \(n \in \{4, 2, 1\}\) → for each level, divide the \(H' \times W'\) map into an \(n \times n\) grid of bins and max-pool each bin → produces \(n^2\) values per channel per level → concatenate every level and every channel → one fixed-length vector of size \(C \cdot \sum_l n_l^2\) (e.g. \(C \cdot 21\)) → feed into the FC layers exactly as before.

The Bin Formula

For pyramid level \(n\) and feature-map size \(s\) along one axis, bin index \(i = 0, \dots, n-1\) covers positions \([\lfloor i \cdot s/n \rfloor,\ \lceil (i{+}1)\cdot s/n \rceil)\). This guarantees two things: (a) the bins tile the entire map (with at most 1-pixel overlap from rounding), and (b) there are always exactly \(n\) bins, whatever \(s\) is. Because \(n\) is a fixed hyperparameter chosen at design time, the pooled output size \(n^2\) is fixed too — it is the input size \(s\) that gets absorbed into the (variable) bin width, never into the bin count.

Design Decision: Why Not Just Crop or Warp?

AlexNet/VGG-style pipelines force every image to, say, 224×224 by cropping (losing content outside the box) or warping (distorting the aspect ratio) — both hurt recognition accuracy, especially for objects at unusual scales. SPP instead lets the network see the full image at its native resolution and aspect ratio, and defers the "fit-to-fixed-size" step to right before the FC layers, where it is nearly free: pooling naturally summarizes a region into one number without needing to synthesize new pixels the way resizing does. This is also why SPPNet was ~24-102× faster than R-CNN at test time — it runs the (expensive) convolutions ONCE on the full image instead of once per region proposal.

🔑 Key Property

SPP is input-size agnostic pooling with a fixed output cardinality. It generalizes ordinary max pooling (a single bin count) to a multi-resolution pyramid, giving both a fixed-length descriptor AND multi-scale spatial information (coarse global context from 1×1, fine local detail from 4×4) in a single feature vector.

3
Why It Works — The Math
▼

Bin Boundaries

For a pyramid level with \(n\) bins along an axis of size \(s\), bin \(i\) spans:

$$\text{bin}_i^{(n,s)} = \Big[\ \lfloor i \cdot s/n \rfloor,\ \ \lceil (i+1)\cdot s/n \rceil\ \Big), \qquad i = 0, \dots, n-1$$

Pooling Within Each Bin

For channel \(c\), row-bin \(i\), col-bin \(j\), the pooled value is the max activation over the corresponding rectangle of the feature map \(F\):

$$\text{out}_{n}(c,i,j) = \max_{(p,q)\ \in\ \text{bin}_i^{(n,H')} \times \text{bin}_j^{(n,W')}} F(c,p,q)$$

Concatenation Into a Fixed-Length Vector

The final descriptor stacks every level's pooled grid, flattened, across all channels:

$$v = \Big[\ \text{out}_{4\times4}\ \Vert\ \text{out}_{2\times2}\ \Vert\ \text{out}_{1\times1}\ \Big] \in \mathbb{R}^{\,C\cdot(16+4+1)}$$

Proof Sketch: Why the Length Is Constant

The number of bins produced by level \(n\) is exactly \(n^2\) for any \(s \ge n\) — the formula above always emits \(i = 0,\dots,n-1\), i.e. \(n\) intervals, since \(s\) only changes the interval widths, never the interval count. Summing over the fixed set of levels \(\{4,2,1\}\) gives a total bin count of \(16+4+1=21\) that never depends on \(H'\) or \(W'\). Multiplying by the (fixed) channel count \(C\) gives a provably constant vector length \(21C\), regardless of the original image's dimensions. \(\blacksquare\)

⚠️ Common Misconception

"SPP resizes the feature map." It does not resize or interpolate — no new pixel values are synthesized. It changes the bin width used for max pooling (a form of adaptive/data-dependent pooling), aggregating existing activations rather than manufacturing new ones the way image resizing (bilinear/bicubic) would.

Key Takeaways
▼

When SPP shines:

  • Variable-size / variable-aspect-ratio inputs where cropping or warping would destroy information (e.g. object detection region proposals, wide panoramas, document images)
  • You want multi-scale context (coarse + fine) fused into one descriptor for free
  • You need to avoid re-running expensive convolutions per crop (SPPNet's original motivation over R-CNN)

When NOT to use / limitations:

  • SPP itself is not (sub-)differentiable-friendly for end-to-end multi-region training the way RoI Pooling / RoI Align are — SPPNet in practice froze the conv layers during fine-tuning
  • If all inputs are naturally fixed-size (e.g. small fixed thumbnails), a plain global pool or flatten is simpler and just as effective
  • For precise localization (segmentation, keypoints) prefer RoI Align, which fixes SPP/RoI Pooling's quantization misalignment via bilinear interpolation

💡 Lineage

SPP (2015) generalized max pooling to multiple resolutions for whole-image, variable-size inputs. Its single-level special case (one \(n\times n\) grid applied per region proposal) became RoI Pooling in Fast R-CNN, which was later refined into RoI Align in Mask R-CNN to remove quantization artifacts. Today, nn.AdaptiveMaxPool2d / nn.AdaptiveAvgPool2d in PyTorch implement the same bin-formula idea as a one-line building block.

Code Trace — From Scratch
▼
import numpy as np
# feature_map: shape (C, H, W) — output of the last conv layer,
# H and W can be ANY size, they vary with input image size
def spp_bins(n, s):
"""Bin boundaries for n bins over an axis of length s (He et al. 2015)."""
return [(int(np.floor(i*s/n)), int(np.ceil((i+1)*s/n))) for i in range(n)]
def spatial_pyramid_pool(feature_map, levels=(4, 2, 1)):
C, H, W = feature_map.shape
pooled_chunks = []
for n in levels:
row_bins = spp_bins(n, H)
col_bins = spp_bins(n, W)
level_out = np.zeros((C, n, n))
for i, (r0, r1) in enumerate(row_bins):
for j, (c0, c1) in enumerate(col_bins):
region = feature_map[:, r0:r1, c0:c1] # (C, bin_h, bin_w)
level_out[:, i, j] = region.max(axis=(1, 2)) # max pool
pooled_chunks.append(level_out.reshape(C, -1)) # (C, n*n)
return np.concatenate(pooled_chunks, axis=1).reshape(-1) # length C*sum(n^2)
# Works identically whether the conv backbone produced a 9x13 or 14x20 map:
fmap_a = np.random.rand(256, 9, 13) # image A -> feature map (256, 9, 13)
fmap_b = np.random.rand(256, 14, 20) # image B, different size -> (256, 14, 20)
vec_a = spatial_pyramid_pool(fmap_a) # shape (256*21,) = (5376,)
vec_b = spatial_pyramid_pool(fmap_b) # shape (256*21,) = (5376,) -- SAME length!
assert vec_a.shape == vec_b.shape
# Production: PyTorch's adaptive pooling implements the same bin formula
import torch, torch.nn as nn
pools = [nn.AdaptiveMaxPool2d(n) for n in (4, 2, 1)]
x = torch.rand(1, 256, 9, 13) # (batch, C, H, W) -- any H, W
v = torch.cat([p(x).flatten(1) for p in pools], dim=1) # (1, 256*21)
# Gotcha: AdaptiveMaxPool2d(n) means OUTPUT size n x n, not a divisor of input!
