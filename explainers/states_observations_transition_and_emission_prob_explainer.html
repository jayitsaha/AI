Understanding Hidden Markov Models
▼

What is it? A Hidden Markov Model (HMM) is a statistical model used to describe a system that transitions between a set of unobserved (hidden) states, and at each state, it emits an observable symbol. The key idea is that you don't directly see the states, but you can infer them from the sequence of observations.

Analogy: Imagine you have a friend whose mood (Happy or Sad) is a hidden state you cannot directly observe. However, you can see their daily activities (Shopping, Reading, Gaming). If your friend is Happy, they might go Shopping more often. If Sad, they might prefer Reading or Gaming. An HMM allows you to model these relationships: how their mood changes from day to day (transitions) and how their mood influences their activity choices (emissions). From a sequence of observed activities, you can then infer the most likely sequence of moods.

💡 If you remember one thing

HMMs are powerful for modeling sequential data where the underlying generative process is a Markov chain, but its states are hidden. We only see the probabilistic "evidence" (observations) produced by these hidden states.

2
How HMMs Work Internally
▼

The Core Assumptions

HMMs rely on two fundamental assumptions that simplify their mathematical tractability:

  1. Markov Property (for states): The probability of transitioning to the next hidden state depends only on the current hidden state, not on any previous states. This is a "memoryless" property: \(P(q_t | q_{t-1}, q_{t-2}, \dots, q_1) = P(q_t | q_{t-1})\).
  2. Output Independence (for observations): The probability of an observation at a given time depends only on the hidden state at that same time, and is independent of all other observations and hidden states. \(P(o_t | q_T, \dots, q_1, o_{T-1}, \dots, o_1) = P(o_t | q_t)\).

The Five Components of an HMM

An HMM is completely defined by its parameters, often denoted collectively as \(\lambda = (A, B, \pi)\):

  • \(N\): The number of possible hidden states. (e.g., Happy, Sad)
  • \(M\): The number of possible observation symbols. (e.g., Shopping, Reading, Gaming)
  • \(A\): The state transition probability matrix, an \(N \times N\) matrix where \(A_{ij} = P(q_{t+1}=j | q_t=i)\). This governs how the hidden state evolves over time. Each row sums to 1.
  • \(B\): The observation (or emission) probability matrix, an \(N \times M\) matrix where \(B_{jk} = P(o_t=k | q_t=j)\). This describes the probability of observing a particular symbol from a given hidden state. Each row sums to 1.
  • \(\pi\): The initial state distribution, an \(N\)-dimensional vector where \(\pi_i = P(q_1=i)\). This specifies the probability of starting in each hidden state. The elements sum to 1.

Design Decision: Why these assumptions?

These assumptions simplify the model structure, making it possible to develop efficient dynamic programming algorithms (like the Forward-Backward algorithm for evaluation, and Viterbi for decoding) that would be intractable for arbitrary probabilistic graphical models. While strong, they are surprisingly effective for many real-world sequence modeling tasks like speech recognition and bioinformatics.

🔑 Key Property

The "hidden" aspect is crucial. If the states were directly observable, it would simply be a standard Markov chain. The HMM's power lies in its ability to infer unobserved states from indirect, noisy observations.

3
Why It Works — The Math
▼

Joint Probability of State and Observation Sequences

Given an HMM \(\lambda = (A, B, \pi)\), a sequence of hidden states \(Q = (q_1, q_2, \dots, q_T)\), and a sequence of observations \(O = (o_1, o_2, \dots, o_T)\), the joint probability \(P(O, Q | \lambda)\) can be expressed as:

$$P(O, Q | \lambda) = P(q_1 | \pi) \cdot P(o_1 | q_1, B) \cdot \prod_{t=2}^T P(q_t | q_{t-1}, A) \cdot P(o_t | q_t, B)$$

Substituting the specific notation for \(\pi, A, B\):

$$P(O, Q | \lambda) = \pi_{q_1} \cdot b_{q_1}(o_1) \cdot \prod_{t=2}^T a_{q_{t-1}q_t} \cdot b_{q_t}(o_t)$$

This formula allows us to calculate the probability of a specific hidden state sequence *and* observation sequence occurring together. However, typically we are interested in \(P(O | \lambda)\), which requires summing over all possible hidden state sequences \(Q\):

$$P(O | \lambda) = \sum_Q P(O, Q | \lambda) = \sum_{q_1, \dots, q_T} \pi_{q_1} b_{q_1}(o_1) \prod_{t=2}^T a_{q_{t-1}q_t} b_{q_t}(o_t)$$

Directly summing over all \(N^T\) possible hidden state sequences is computationally intractable for long sequences. This is where dynamic programming algorithms like the Forward algorithm come in, allowing us to compute \(P(O | \lambda)\) efficiently in \(O(T \cdot N^2)\) time.

The Three Fundamental Problems

The core applications of HMMs revolve around solving three problems:

  1. Evaluation: Given an HMM \(\lambda\) and an observation sequence \(O\), what is the probability \(P(O | \lambda)\)? (Solved by the Forward-Backward algorithm)
  2. Decoding: Given an HMM \(\lambda\) and an observation sequence \(O\), what is the most likely hidden state sequence \(Q^*\) that produced \(O\)? (Solved by the Viterbi algorithm)
  3. Learning: Given an observation sequence \(O\) (and possibly other sequences), how do we adjust the HMM parameters \(\lambda = (A, B, \pi)\) to maximize \(P(O | \lambda)\)? (Solved by the Baum-Welch algorithm, a form of Expectation-Maximization)
⚠️ Common Pitfall

The learning problem (Baum-Welch) is complex because the states are hidden. It's an iterative algorithm that finds a locally optimal set of parameters, not necessarily a globally optimal one. Initializing the HMM parameters well is often crucial for good performance.

Key Takeaways
▼

When to use HMMs:

  • Speech Recognition: Hidden states are phonemes or sub-phoneme units; observations are acoustic features.
  • Bioinformatics: Hidden states are regions in a DNA sequence (e.g., gene, intergenic); observations are DNA bases.
  • Natural Language Processing: Part-of-Speech (POS) tagging where hidden states are POS tags and observations are words.
  • Time Series Analysis: Modeling sequences where the underlying process is not directly observable but influences what you see.

When NOT to use:

  • Long-Range Dependencies: HMMs struggle with dependencies that span many time steps, as the Markov property limits memory to the immediate past. Recurrent Neural Networks (RNNs) or Transformers are better suited.
  • Directly Observable States: If the states are fully known, a simpler Markov chain or other models might be more appropriate.
  • Non-Sequential Data: HMMs are inherently designed for sequences.
  • Complex Relationships: If observations depend on multiple hidden states simultaneously, or states depend on more than just the previous state, HMMs may be too restrictive.
💡 Modern Context

While foundational, HMMs have largely been supplanted by deep learning models (RNNs, LSTMs, Transformers) for many tasks like speech and NLP due to their ability to capture complex, long-range dependencies and learn features directly from raw data. However, HMMs remain important for understanding sequence modeling basics and for specific applications where their assumptions hold well or data is scarce.

import numpy as np
# Define HMM parameters for the "friend's mood" example
states = ['Happy', 'Sad']
observations = ['Shopping', 'Reading', 'Gaming']
# Initial state probabilities (pi)
# P(Happy), P(Sad)
pi = np.array([0.6, 0.4])
# Transition matrix (A)
# A[i, j] = P(state_t+1=j | state_t=i)
# Rows: current state (Happy, Sad)
# Cols: next state (Happy, Sad)
A = np.array([
[0.7, 0.3], # From Happy: P(H->H), P(H->S)
[0.4, 0.6] # From Sad: P(S->H), P(S->S)
])
# Emission matrix (B)
# B[j, k] = P(obs_t=k | state_t=j)
# Rows: hidden state (Happy, Sad)
# Cols: observation (Shopping, Reading, Gaming)
B = np.array([
[0.5, 0.3, 0.2], # From Happy: P(Shop|H), P(Read|H), P(Game|H)
[0.1, 0.4, 0.5] # From Sad: P(Shop|S), P(Read|S), P(Game|S)
])
def generate_sequence(length, pi_vec, A_mat, B_mat, state_names, obs_names):
hidden_seq = []
obs_seq = []
# Choose initial state
current_state_idx = np.random.choice(len(state_names), p=pi_vec)
hidden_seq.append(state_names[current_state_idx])
# Emit first observation
current_obs_idx = np.random.choice(len(obs_names), p=B_mat[current_state_idx])
obs_seq.append(obs_names[current_obs_idx])
# Generate subsequent states and observations
for _ in range(1, length):
# Transition to next state
current_state_idx = np.random.choice(len(state_names), p=A_mat[current_state_idx])
hidden_seq.append(state_names[current_state_idx])
# Emit observation from new state
current_obs_idx = np.random.choice(len(obs_names), p=B_mat[current_state_idx])
obs_seq.append(obs_names[current_obs_idx])
return hidden_seq, obs_seq
