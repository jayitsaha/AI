Binary Encoding & Hash Encoding

Compact representations for high-cardinality categorical features
Intermediate Feature Engineering Classical ML Part III · Section 1.3.3
1
Understanding the Concept

Categorical variables — city names, product IDs, browser types — must be converted to numbers before a ML model can use them. Two compact encoding strategies shine when there are many categories (high cardinality).

Binary Encoding

Assign each category an integer ID (0, 1, 2, …), then convert that integer to its binary (base-2) representation. Split the bits into separate columns. With \(K\) categories you need exactly \(\lceil \log_2 K \rceil\) columns instead of the \(K\) columns one-hot encoding would require. A colour palette with 256 shades needs 8 columns; one-hot would need 256.

💡 Key Insight

Binary encoding maps \(K\) categories → \(\lceil \log_2 K \rceil\) columns, an exponential compression over one-hot's \(K\) columns. For 1024 cities, that is 10 columns instead of 1024.

Hash Encoding (the Hashing Trick)

Apply a deterministic hash function to the category string and map it to one of \(B\) fixed buckets (columns). No vocabulary is needed — the bucketing is computed on-the-fly. Unknown categories at inference time land in some bucket automatically. The trade-off: two different categories may hash to the same bucket (a collision), blending their signals.

⚠ Trade-off

More buckets (\(B\)) → fewer collisions but more columns. Fewer buckets → more collisions but smaller feature space. Set \(B\) so the expected collision rate is acceptable for your task.

2
How It Works Internally

Binary Encoding — Exact Steps

  1. Ordinal-encode: map each unique category to an integer (0-indexed).
  2. Convert each integer to its binary representation, zero-padded to \(\lceil \log_2 K \rceil\) bits.
  3. Write each bit as a separate column \(b_0, b_1, \ldots, b_{w-1}\) (MSB first).
$$\text{id}(c) \in \{0,\ldots,K{-}1\} \;\longrightarrow\; \bigl(b_{w-1},\, b_{w-2},\, \ldots,\, b_0\bigr), \quad w = \lceil \log_2 K \rceil$$

The resulting matrix has \(n\) rows and \(w\) binary columns. Each row is a unique bit-pattern; no two categories share the same pattern (unlike hash encoding).

Hash Encoding — Exact Steps

  1. Choose bucket count \(B\) and a hash function \(h\) (e.g. MurmurHash, MD5).
  2. For category string \(c\): compute \(j = h(c) \bmod B\).
  3. Set column \(j\) to 1 (or increment for count-based hashing); all others stay 0.
$$j = h(c) \bmod B, \quad \mathbf{x}^{(c)} = \mathbf{e}_j \in \{0,1\}^B$$
🔑 Key Property

Hash encoding requires no pre-fit vocabulary. It handles novel categories at inference time without retraining — ideal for streaming and online learning settings.

3
The Math Behind It

Column Count

$$w_{\text{binary}} = \lceil \log_2 K \rceil \qquad w_{\text{one-hot}} = K$$

Savings factor: \(K / \lceil \log_2 K \rceil\). For \(K = 2^{20} \approx 10^6\) categories, binary encoding uses 20 columns vs 1 million.

Expected Collisions in Hash Encoding

With \(K\) categories mapped uniformly into \(B\) buckets, the expected number of collisions follows the birthday problem. For a given bucket \(j\), the expected number of categories is \(K/B\). The probability two specific categories collide is \(1/B\).

$$P(\text{collision}) \approx 1 - e^{-K(K-1)/(2B)} \approx \frac{K^2}{2B} \quad\text{(for }K \ll B\text{)}$$

Practical rule: set \(B \geq K / 10\) to keep collision rate below 10%, or \(B = 2^{\lceil \log_2 K \rceil + 2}\) for near-zero collisions.

Sign Trick (Weinberger et al., 2009)

Use a second hash \(s(c) \in \{+1, -1\}\) as the feature value instead of 1. Colliding categories are assigned opposite signs with equal probability, making the expected dot-product between colliding features zero — eliminating bias from collisions.

$$\phi(c)_j = s(c) \cdot \mathbf{1}[h(c) = j]$$

When to Choose

Binary encoding: tree-based models (XGBoost, LightGBM), medium cardinality (K = 10–10,000), when you need lossless encoding with far fewer columns than one-hot.  |  Hash encoding: very high cardinality (K > 100,000), online/streaming data, NLP bag-of-words, when novel categories appear at inference time.
